# Schema 语义评估

**核心原则：评估 LLM 仅凭输入契约理解作者意图并生成正确 JSON 的准确性，要求对可评估的输入语义全覆盖。** 通过 Zod 只证明结构合法，不证明符合题意；离线覆盖不代表模型正确率。LLM 是被测对象，脚本负责确定性评分。诊断兼顾契约可理解性与描述成本，不以模型排名为目标。

## 范围与接入

- 以完整命名 schema 为评估单元，如 `NodeSchema`、`PathSchema`、`ScatterChartSchema`；属性路径、分支和跨字段关系是评分与归因粒度，不把完整对象拆成脱离上下文的单字段问答
- 用例数量由覆盖矩阵决定：盘点全部可达属性、相关描述的独立语义、主要 union 分支与跨字段关系，并映射到用例及可执行断言；仅出现在输入、答案或提示中不算覆盖。递归、开放结构及转换缺口按 reference 明确边界，不以固定题数截断覆盖
- 仅为拥有作者输入或配置生成契约、且存在语义选择的包接入；依赖 Zod 本身不构成接入理由。Kernel 当前优先 Core，Foundation 原子在实际消费场景中覆盖；其他包及 Inspect 简单配置不要求机械建立 evals
- Zod 是唯一契约真源，模型读取由其导出的完整 JSON Schema，输出由原始 Zod 与用例判分器校验；不另写一套面向 LLM 的 IR 或字段定义
- 包内 `evals/` 与 `tests/`、`benchmarks/` 同级，用例使用 `*.eval.ts`；保留这三个目录的语义名，不统一添加 `_`。没有用例的包不创建占位目录
- 每个 schema 使用 `evals/<schema>/`：`cases/*.eval.ts` 按语义分类存放题库，`checks/*.check.ts` 按离线自检职责组织，两者不要求一一对应；`suite.ts` 负责用例汇总与接入，`projection.ts` 按需承载领域等价规则，不创建占位文件
- 通用类型、判分、提示、覆盖和报告复用根目录 [scripts/evals](../../../scripts/evals)，领域规则留在所属 schema 目录；功能测试发现范围不得收录 evals，离线自检与模型采样的配置和命令明确分离
- [现有评测应用](../../../apps/eval/README.md) 的提示组装、重复执行和报告仅作参考；它的整体 IR 生成与编译打分不作为本流程的默认评估粒度

## 执行前

1. 读取根与目标包 `AGENTS.md`、公开 schema、实际消费者和已有用例；契约与命名设计读取 [schema 规范](../standard-structure/references/schema.md) 与 [standard-name](../standard-name/SKILL.md)
2. 编写、审查用例前读 [用例与契约设计](references/evaluation-design.md)；运行、解释报告或优化前读 [报告与优化](references/report-and-optimization.md)
3. 调用前给出简要执行说明并获用户确认：包/schema、用例与变体、具体模型 ID 及思考程度、按题目/采样划分的 agent 粒度、agent 初始量与上限、并发方式、动态采样档及回答总量上限、预算边界、报告位置及是否自动优化；确认后连续执行，范围或参数变化再确认
4. 运行需有当前对话针对 LLM 评估范围及模型调用的明确授权；开发、功能验证、全量验证或本 skill 的编写不自动授权付费调用、subagent 或外部模型执行
5. 报告默认包含归因分析和优化建议，无需另行授权；自动实施优化默认关闭

## 隔离与快照

- eval 用例实现、真实采样和优化实验使用任务专用隔离 worktree；有效快照重建、保留实验分支、最终人工确认合回和清理沿用 [性能测试的隔离与合回规则](../test-performance/SKILL.md#worktree-隔离与合回)。仅编辑本 skill/reference 不创建实验 worktree，不运行基准或 eval
- 开始前记录原分支、HEAD 和相关 dirty/untracked 内容；隔离副本须包含本任务需要的真实依赖快照。不能用 HEAD 代替有效工作区，也不能覆盖并发改动
- 已确认的用例、判分器与配置属于正式资产；导出的 JSON Schema、原始回答、报告和候选对比写入已有 ignored `notes/reports/`、`notes/plans/` 或就近 `_notes/reports/`、`_notes/plans/`，不覆盖历史基线
- 自动优化开启后，在 ignored plan 的 `TASK_STATE.md` 记录授权、问题清单及依赖分组、候选起点、逐问题逐阶段尝试次数、预算消耗、保留/撤回/待确认状态和恢复入口；恢复或切换方案不重置同一问题的次数，不推定旧结果仍有效

## 模型与采样执行

- 默认直接使用当前订阅（plan）的 subagent 通道；仅在用户另行选择时接入 API，不将额外 API 凭据作为默认前提
- 完整评估固定使用 Terra（`gpt-6.1-terra`，reasoning effort `high`）和 Luna（`gpt-6-luna`，reasoning effort `high`）。指定单模型复测时只运行该模型，仍使用固定配置。调用前核对可用性；不可用时报告缺口，不替换版本或降低推理强度。
- 评估模型不是开发 worker/reviewer；运行前固定其他生成参数，各描述变体及前后版本保持一致，记录实际生效值
- 每个“模型 × 用例 × 契约变体 × 采样序号”单独创建不继承主会话的 fresh subagent，不跨题或采样复用 agent/上下文。不同样本按确认的并发上限调度
- 被测 agent 只允许读取统一指令、完整 JSON Schema 和题目，并写入自己负责的原始结果；禁止读取源码、JSDoc、文档、参考答案、其他样本输出或评分反馈，禁止浏览和调度其他 agent。信息输入与判分资产分开存放
- 每次采样都重新生成并保留原始回答，不用脚本复制、回放或重复已有答案充数；报告记录实际上下文隔离粒度与恢复边界，同题复用 agent 时不将重复回答视为独立无历史请求
- 主评估采用固定提示下的单次自由 JSON 生成，不使用 provider 原生 schema 强制约束、自动修复或多轮纠错。真实工具调用/结构化输出接入可另设获批评估，分别报告，不与主评估混算
- 两个模型共享评估 agent 并发上限 4；实际取 4、已确认上限和可用 worker 槽位的最小值，主 agent 占槽时须扣除并报告实际并发。空槽及时补入可执行的下一样本；同一用例须完成当前档评分后才决定是否追加，不预先启动未触发的档位。重试、限流和恢复预算预先固定，不以跑到足够成功为止代替停止规则

## 动态采样档

次数按每个“模型 × 用例 × 契约变体”独立累计，无预热，不是优化轮次：

| 档位         | 初始采样 | 首次出现失败后补至 | 累计至少两次失败后补至 | 用途                        |
| ------------ | -------: | -----------------: | ---------------------: | --------------------------- |
| 中间分析     |     1 次 |               3 次 |                   5 次 | 初始摸底与失败定位          |
| 完整报告     |     3 次 |               5 次 |                  10 次 | 最终保留/撤回判断与基线候选 |
| 描述调整验证 |     3 次 |               5 次 |                      — | describe 调整、消融及其对照 |

- 完成初始采样后，全部联合成功即通过本档筛选并进入下一用例，不代表已正式达标；累计至少 1 次联合失败时补足第二档。设有第三档时，第二档完成后累计至少 2 次联合失败才补足第三档，否则结束；达到本模式上限即停止
- `describe` 补充、精简或删除后的验证及消融对照统一采用 3→5 次，优先于通用采样档：先测 3 次，有至少 1 次联合失败才补 2 次，上限 5 次。基线与候选使用相同模式，不以单次成功判定调整有效，也不自动追加至 10 次
- 疑似退化的对照核查须在执行计划中预设；可在获批范围内将相关对照补至同档，上限仍为 5 次，单列核查样本及触发原因。未获批或证据仍不足时标记待确认，不自动加样本或判定候选无效
- 数字表示累计总次数，追加只生成差额，不重新开始或重复计入历史回答；例如中间分析首次失败后补 2 次，若这两次均成功则以失败率 33.3%（n=3）结束，不追加到 5 次。追加不能消除已发生的失败；保留全部样本，按预设目标裁决，不用最后一次成功或多数票改判全通过
- 最终统计、用例比较与失败排序使用联合失败率（联合失败次数 ÷ 该题实际采样次数），同时标明样本数；失败绝对数仅用于追加门槛与原始记录。每个变体先算逐题失败率，再按用例等权汇总，不按回答数给追加题加权；初始阶段与追加阶段分开报告
- 调用故障按既定重试与预算规则处理，不冒充语义失败触发追加；未取得计划内所需答案时标记不完整。中间分析不更新正式基线；完整报告也不自动证明稳定，不把重复回答当成不同语义用例
- 首次调用前按模型列出用例数、变体数、初始与最大回答数，并汇总本轮回答预算；最大量按全部用例达到所选模式上限计算，实际只执行触发的追加。订阅模式固定 agent 和并发上限，平台未提供的 token/额度记为未知；API 模式另定 token/费用预算。扩大范围、增加变体或超预算先回到授权边界
- 基线与候选使用相同用例、模型参数、提示、动态采样档和停止规则，分别保留原始结果及实际样本数；模型、输入模式、判分或采样规则变化时建立独立比较组。动态追加偏向失败用例，原始汇总成功频率不视为无偏总体准确率或直接与固定采样成绩比较

## 报告后的闭环

及格线、局部筛选与退化核查见 [门槛与可比性](references/report-and-optimization.md#门槛与可比性)；3→5 次不证明稳定达标，总体通过不豁免已确认的关键语义退化。

1. 无论通过或失败都保存中文 Markdown 与原始 JSON；按 reference 分开报告结构合法、字段选择、赋值与联合成功，不只报告汇总分
2. 主 agent 根据报告同时评估属性名、数据结构、约束、描述、导出完整性及用例/判分器；失败项检查语义缺口，高成功率项检查 `describe` 能否精简或省略以降低输入成本。报告须给出候选或保留理由，不仅诊断失败；高分不直接证明描述冗余
3. 默认按实际错法给出有证据的归因、优化建议或不改理由；未经授权不修改、不追加采样。已获优化授权时，先核准题意、合法等价与判分，再按“未及格补齐 → 未优秀补齐 → describe 精简”逐问题记录假设、验证范围与保留条件
4. 各阶段按独立语义问题推进，每个问题在当前阶段最多 3 次“候选修改 → 功能验证 → 同条件 eval → 裁决”；共享 schema 且影响不可分离的内容合组。独立保留通过项，失败项进入下一次尝试，三次失败只撤回对应问题；同一未解决失败不换阶段重置次数。总调用预算仍统一约束，阶段可部分完成，最后验证累计改动，细则见 reference
5. 名称、数据结构、值域、默认或行为改变属于公开契约设计，按根规则重新确认；自动优化不扩大原授权，不自动改变验收目标、判分规则、基线、Git 或 agent 权限

## 完成检查

- 完整输入契约、独立答案来源与覆盖矩阵已核对；新增/修改属性或描述须同步断言映射，报告未覆盖项、转换缺口和覆盖边界，不用总体成功率代替完整覆盖
- 已阅读逐样本原始结果、调用失败与各被测模型的独立报告，区分实测、推测、未验证项及不完整结果
- 保留候选经过受影响范围的格式化、lint、类型检查和必要功能验证；schema 语义变化按现有规则同步文档与设计
- 最终结果按声明的采样与裁决规则核验，并与优化前同条件基线比较；逐问题区分通过筛选、正式达标、已确认退化、待确认、耗尽尝试或设计待批，不以小样本全对证明已优秀或跳过其他问题
- 交付报告、实际改动、基线建议及合回待确认项；仅新增本 skill 时只汇报规则与文档校验，不声称 runner、用例或评估已实现
