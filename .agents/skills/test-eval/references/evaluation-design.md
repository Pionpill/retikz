# 用例与契约设计

用于编写或审查 schema 语义 eval、设计名称/结构/描述对照及核对模型可见输入；运行授权、隔离与采样档见 [技能入口](../SKILL.md)。

## 契约投影

- 使用实际命名 Zod schema，按 `io: 'input'` 导出 JSON Schema，保持作者输入的 optional/default 语义，包含全部必要 `$ref`/`$defs`；不得用解析后物化默认的对象代替输入契约
- 模型侧使用 JSON Schema，不发送原始 TypeScript、import、helper 实现或 JSDoc。框架接受 Zod 是开发者接口，实际模型协议通常转换为 JSON Schema；框架转换与本地导出有差异时记录实际发送契约
- 保留属性名、类型、discriminator、union、结构约束、默认值和 `.describe()` 元数据；不在提示中额外解释某个字段、示范答案或补全未写入契约的语义
- 在调用模型前核对转换损失：自定义 refinement、transform、开放扩展和递归引用等不能因导出成功就视为完整。发现缺口须记录不可见规则与受影响用例；不以 `unrepresentable: 'any'` 静默抹平，影响目标评分时先解决或明确标记未覆盖
- 领域规则无法结构化表达时，由权威 schema 的简短描述补充稳定语义；不把任意校验函数实现或平行手写 JSON Schema 当补丁
- 公共入口触发的递归装配与注册必须与真实消费一致；不为导出便利改公开 API、绕过 owner 或维护第二套 IR

## 用例单元与信息隔离

主 agent 根据真实契约和消费者写题及确定性判分器；每个完整 schema 配置多条自然语言任务，标明目标属性路径、分支、关系与独立失效模式。标记和标准答案仅对判分侧可见。

- 每次采样由独立 fresh subagent 处理，输入文件仅含完整 schema 与当前题目，不提供其他题目、历史采样或模型结果；原始答案按模型、轮次、用例分别保存，评分在主 agent 侧执行且不回传
- 输入覆盖完整 schema；题目不提示“本题考 opacity”，不通过只展示目标字段泄露选择。请求可自然包含数值或业务名称，但不能只把字段名和枚举值抄成题目
- 预期从当前真实功能契约、已知答案和必要源码/文档核对得到，不从被测 `describe` 自己生成并自证。描述与行为冲突时报告契约问题，不改答案迁就描述
- 覆盖普通表达、同义改写、易混淆字段、单位/方向、零值/边界、嵌套选择、缺省/省略及跨字段关系；使用代表性等价类，不为每个 Zod 原生约束机械穷举
- 简单字段允许依靠通用知识与结构约束；自定义语义必须在模型可见契约中找到依据，不能要求模型凭隐藏实现猜测
- 接受事先明确的等价合法表达；同时列出必须出现、不应出现、允许省略的字段及数值容差。浮点、单位或结构等价只按被测契约处理，不用任意宽松匹配掩盖错误
- 采样前用合法等价答案与反例审查题意和判分，核对作用域、继承及实际 provider 上下文；参考答案通过 Zod 不代表判分完备。存在多种合理解释或等价依赖未固定宿主时，先澄清或列为诊断题，再冻结评分
- 优化集用于分析与改写，独立留出集用于最终验收；按语义情景分组，近重复改写不跨集合泄漏。不得反复读留出失败再把同一集合继续称为盲测；需要调整时版本化并另保留验收集
- 名称或结构候选需要更新答案路径时，先固定同一语义任务与等价映射；新旧结构分别用其权威 schema 校验，映射变化与判分修复均留痕

例如“整体保持不透明，只将填充设为半透明”应面对含整体、填充、描边配置的完整 `NodeSchema`。判分检查目标填充因子、整体语义和误改描边，而不是只检查某处出现 `0.5`。

## 按错法拆题与去重

- 先写出本题要区分的作者意图和典型错答，再设计提示与断言。全覆盖针对可观察的语义区别，不按字段数、枚举值数或宿主题数配额；属性矩阵无缺口不能替代语义审阅。
- 两种意图都常见时，固定背景与数值，只改变决定答案的条件，交换答案须通过 Zod 但双向判错。例如用长度不等的两段路径区分按段与按累计长度采样。只有一侧值得实测时，另一侧只作离线反例。
- 共享结构在代表性宿主测全；换宿主时专测归属、继承、优先级、禁用或省略语义的变化，不铺“资源 × 宿主”的全排列。区分不创建、启用但继承、显式覆盖；题意不要求保留某种写法时接受合法等价解。
- 辨析题聚焦一个可归因的问题，允许多个必要字段联动；集成题只组合实际相互影响的行为，并按关系分别判分。
- 合并或删题前，核对剩余断言仍覆盖原有分支、宿主差异，并能拒绝该题独有或历史实测的错答。未验证的冗余只列候选；保留稳定题号，不将改题后的成绩直接并入旧基线。

## 全量属性与描述覆盖

- 从实际完整 schema 及模型可见投影生成清单：记录属性路径、引用/变体上下文、描述位置与文本、独立语义规则、关联用例和断言、证据来源及未覆盖原因。覆盖矩阵驱动题数，不先固定题数再删减属性
- 每个可达属性至少有字段选择与赋值断言；描述拆为可观察语义，如单位、方向、默认/省略、优先级、继承和适用范围，分别安排能区分正确与错误理解的情景。字段出现、答案通过 Zod 或描述被发送给模型均不能单独证明语义覆盖
- 共享 schema 可复用基础语义用例，但继承、消费位置或覆盖描述不同的上下文必须另测；主要 union/discriminator 分支、易混淆邻项与跨字段关系不得因共享类型而去重。组合采用代表性等价类，不要求字段笛卡尔积穷举
- 递归按循环引用登记并选择代表性嵌套；数组按元素/顺序/边界场景，开放 JSON 与扩展参数按通配路径、保真及可见约束覆盖。明确有限覆盖边界，不声称穷举任意深度、长度、键或注册扩展
- 无法从模型可见契约获知的规则、不可观察的行为及转换损失列为阻断或显式缺口，不要求模型猜测，也不虚构断言。覆盖率分别报告属性、分支、语义规则和上下文关系的已覆盖/总数及排除原因
- 断言须能拒绝对应的代表性错误答案；用例/判分器实现后以删除、错层、错值或关系错误等反例验证。schema 或 describe 变化时重新生成清单并检查覆盖差异；设计草案的人工断言不标为已执行覆盖

## 优化维度

生成报告后逐项评估，不把描述长度当作契约质量：

| 维度       | 检查内容                                            | 典型诊断                                         |
| ---------- | --------------------------------------------------- | ------------------------------------------------ |
| 属性名     | 同概念同名、常用词、领域区分、缩写与歧义            | 模型稳定误选相邻字段或编造常见替代字段           |
| 数据结构   | 层级、分组、discriminator、union 与字段关系         | 值正确却放错层；可选分支或相似对象持续混淆       |
| 约束与默认 | 类型、值域、互斥关系、缺省及结构可表达性            | 多种冲突解释都通过 schema；导出缺少关键限制      |
| describe   | 稳定领域含义、单位、方向、作用对象、继承/组合与边界 | 字段合法但单位、方向、应用范围或关系错误         |
| 转换与评估 | 契约损失、题目歧义、答案遗漏、评分过严或泄题        | 多个模型在同一可疑断言失败，或合法等价答案被拒绝 |

`describe` 不复述类型、必填、范围等已完整结构化的约束；通用属性能由名称、约束和通用知识正确理解时，可通过实验省略。不能由结构推导的单位、坐标方向、继承、乘法关系、特定变体限制仍需准确表达。

## 对照与消融

- 描述实验至少区分当前描述、精简描述和无描述；按目标决定是否只干预目标字段或整个 schema，并记录父对象及引用处仍可见的描述，避免“无描述”实际仍从别处读到相同信息
- describe 调整与各对照统一按入口的 3→5 次模式验证，每题每模型至少 3 次；出现至少 1 次失败才补至 5 次，不使用 1 次摸底结果判定候选有效
- 对比描述时固定名称和结构；名称、结构、约束实验分别作为候选，不同时改多项再声称找到单因素原因。确需组合修改时只报告组合效果
- 候选按独立语义问题划分，记录改动假设、影响路径、相关用例及依赖；共享 schema 的不可分离影响合组，模型仍读取完整 schema。先验证目标和必要邻项，各问题分别裁决，最后验证累计保留改动
- 高成功率项也须检查上下文成本，优先审视重复结构约束、通用常识和冗长表述；精简或删除必须比较实际候选，不能因当前分数高就直接删除。记录描述及完整输入的长度变化，优先保证 各被测模型的总体正确性及关键反例不退化；输入缩短不直接等于实测费用下降
- 变化前固定用例、生成参数、任务顺序、上下文模式、采样档、评分和验收规则；候选与基线使用分别新建的模型 agent 重新生成，不把历史回答回放冒充新契约效果
- 主评估不使用自动修复与 schema 强制解码；真实接入模式单独配置并保持前后一致，注明其结构保证，不与自由生成结果混算

## 参考方法

借鉴方法，不照搬外部阈值或结论：

- [BFCL](https://gorilla.cs.berkeley.edu/blogs/8_berkeley_function_calling_leaderboard.html)：参数选择、类型、值及不存在参数的确定性检查
- [JSONSchemaBench](https://github.com/epfl-dlab/jsonschemabench)：区分结构符合性与任务质量
- [元数据控制变量研究](https://arxiv.org/abs/2610.14334)：分别干预名称、描述和参数结构；该预印本主要测工具选择，不等同属性赋值
- [描述优化研究](https://arxiv.org/abs/2606.30775)：利用误选/漏选与留出集检查描述优化；技能路由实验不提供 Retikz 的通用收益保证
- [Zod JSON Schema](https://zod.dev/json-schema)、[LangChain 转换](https://reference.langchain.com/javascript/langchain-core/utils/function_calling/convertToOpenAITool)、[AI SDK 转换](https://ai-sdk.dev/docs/reference/ai-sdk-core/zod-schema)：实际接入时核对安装版本和传输契约，不把“可传 Zod”理解为模型读取源码
