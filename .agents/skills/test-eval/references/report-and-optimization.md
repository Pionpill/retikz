# 报告、诊断与优化

用于执行前冻结评分与门槛、解释结果及开展获准优化；用例与转换规则见 [用例设计](evaluation-design.md)，采样与授权见 [技能入口](../SKILL.md)。

## 确定性评分

保留原始回答，依次完成 JSON 解析、原始字段检查、原始 Zod 输入校验和语义判分。字段存在性、误填和省略意图按原始 JSON 判断，不让 parse 补默认值或 transform 隐藏错误；需要消费解析结果时另记录它与原输入的区别。

| 指标            | 定义                                                                 |
| --------------- | -------------------------------------------------------------------- |
| JSON/结构合法率 | 能解析 JSON、通过完整权威 Zod schema 的输出占比，分别列出            |
| 字段选择正确率  | 必选字段、所属层级/分支与不应填写字段均满足用例要求                  |
| 赋值正确率      | 目标值、单位、方向及关系符合预设判分器；选错字段不能靠别处同值算正确 |
| 联合失败率      | 未同时满足结构、字段选择和全部目标语义断言的回答占比；作为主指标     |
| 联合成功率      | 1 − 联合失败率，保留用于既定成功目标及历史结果对照                   |
| 调用完整性      | 请求次数、完成次数、可评样本数、基础设施失败、重试与预算消耗         |

- 所有指标写明分母；语义评分不只统计通过 Zod 的幸存样本。非法 JSON、schema 失败、拒答、截断或无答案均记对应失败，联合成功为零
- 网络、认证、限流等执行故障与模型答案失败分开；不静默从分母移除。报告实际可评样本和缺口，未达到正式采样配置时标记不完整，不宣称达标
- 最终统计与失败排序使用联合失败率，不按失败绝对数衡量问题程度；逐题以联合失败次数除以实际采样次数，并附样本数。未取得答案时不填 0% 或视为成功。次数保留在原始记录并用于追加门槛，不用多数投票或“至少对一次”替代失败比例
- 按契约变体与采样档分别汇总：先计算逐题失败率，再按用例等权平均；不将全部失败次数除以全部回答数作为最终总分，避免追加题获得更大权重。初始阶段和全部样本分别统计，分项失败率采用同样口径；条件赋值率等辅助指标单独命名
- 按 schema、属性/关系、用例、模型、契约变体展开；先按预设规则形成属性指标，再对属性做宏平均，避免大量简单用例掩盖困难关系。包级均值不能替代关键属性验收
- 给出样本量、逐用例与轮次波动，注明按题目或按采样隔离 agent；同题复用上下文时不直接套用独立样本置信区间。重复采样及近重复用例的相关性须纳入不确定性说明，不能视为独立新语义任务。参考 [Inspect 的 epochs、分组统计与区间](https://inspect.aisi.org.uk/metrics.html)
- 动态采样分开列出每题初始阶段与追加阶段的次数、失败数、触发依据和停止原因；初始阶段用于同范围比较，全部样本用于失败诊断。失败题被追加采样，不能将混合后的频率或属性宏平均解释为无偏总体准确率

## 门槛与可比性

Terra 与 Luna 分开报告，不合并样本。每个模型按 schema 与契约变体分别计算逐题等权联合失败率，成功率为 1 − 失败率。Terra 的及格线为成功率 ≥98%（失败率 ≤2%），优化目标为 ≥99%（失败率 ≤1%）。

- 首次调用前固定本次采用的门槛、关键语义用例和允许退化范围。优化目标不作为及格条件，也不自动授权追加采样或启动优化
- 及格与退化分开判断：候选仍及格但较同条件基线下降时，不因越过及格线就判为优化成功；按预设退化范围及关键用例裁决。方向、单位、继承等关键语义持续失败须单列处理，不能由总体达标掩盖
- 达到优化目标或局部用例持续高成功率时，须诊断对应 `describe` 能否精简或省略，列出冗余候选及预期输入成本变化，或说明保留理由。高分仅触发候选分析，不证明描述冗余；保留精简须以真实消融、独立留出集及各被测模型总体及关键用例无不可接受退化举证
- 模型未达标时先检查失败内容、等价答案、信息缺口和参数差异，不直接判定描述有问题
- 阈值、基线和 CI 阻断是不同决策；不按本次成绩倒推保证通过的门槛，不用局部提升抵消关键语义退化
- 比较前核对模型版本、生成参数、schema/依赖内容、导出配置、提示、用例与判分器快照。条件不同的结果分组保存，不宣称单项优化收益
- 固定采样与动态采样另建基线，不直接混比；历史成绩可作参考，不用新门槛或新采样规则改写历史运行配置及裁决
- 正式达标以适用的采样模式及声明的目标/不确定性规则为准；通用评估采用完整报告档，describe 调整及其对照采用专用 3→5 次模式。达到停止条件即完成该题采样，不要求补齐上限；样本不足以支持稳定率或候选收益结论时标记证据不足，不自行追加调用
- 区分逐样本失败、候选筛选和正式达标：3→5 次用于局部筛选与诊断，不能精确区分 98%/99% 或以 3/3 证明已优秀。调用前固定局部保留条件、关键错误定义、退化核查及不确定性处理，不将小样本错误率直接当作稳定率门槛
- 基线无错、候选有错先记疑似退化；核对题意、等价、受影响路径和原始回答，再按获批规则补充同条件对照。证据确认契约错误或关键退化后撤回对应候选；证据不足则待确认，不判成功，也不直接宣称改动导致失败。对照核查与候选重试均受原采样上限和总预算约束

## 报告契约

每次运行写入新的 ignored 报告目录，保留中文 Markdown 与原始 JSON，失败也保存；不把原始回答或报告提交到正式 eval 用例目录。

报告至少包含：

1. **身份与范围**：包、完整 schema、属性/关系、用例集版本、源码及实际传输契约快照；HEAD 之外标明相关 dirty/untracked 和依赖来源
2. **实际执行**：准确模型 ID、订阅/API 通道、reasoning effort 等生效参数、agent 数与并发方式、模型内任务顺序与上下文/恢复边界、提示/转换/判分器版本、动态采样档及停止规则、初始/最大/实际回答量、生成与重试次数、可观测 token/额度或费用及运行错误；不可观测计量记为未知，不保存密钥或认证头
3. **结果矩阵**：schema → 属性/关系 → 用例 → 模型 → 契约变体，列实际样本数、各分项率、联合失败率、门槛、状态及不确定性；总览使用逐题等权失败率，联合成功率按需展示。原始 JSON 保留逐样本答案与断言结果。附属性、分支、描述语义与上下文关系的覆盖矩阵、分母和缺口；字段存在率不冒充描述语义覆盖
4. **失败归因**：错误字段/分支、层级、值、单位/方向、默认/省略、误填、转换损失及用例/判分疑点；每项附可复核样本和预期，不能只列模型分数
5. **候选与收益**：名称、结构、约束和描述分别给出诊断与证据，同时列出失败项改进及高成功率项精简机会。对描述候选记录描述与完整模型输入的前后长度、相对节省、总体与关键用例退化；token 不可测时用字符数并注明口径，不换算为实测费用。不把预期节省或推测写成已验证收益
6. **最终裁决**：逐问题列起点、依赖、尝试次数、通过筛选/正式达标/弃用/待确认/设计待批及证据；汇总阶段完成或部分完成状态、累计保留改动验证、未解决项、基线建议和停止原因

运行身份字段与派生展示分开；只保存可复核事实，分数、分组与展示由报告工具计算，不在多个源模型手工维护同一份统计。

## 报告后的诊断流程

报告默认附归因与优化建议：对照原始回答、题意、模型可见契约与判分，按错法区分题目歧义、等价判分遗漏、契约表达缺口和模型误读；同题可有多因，证据不足标待验证。指出优先改哪一层或为何不改；不把建议视为修改或追加采样的授权。

先复核真实需求、题目与标准答案、合法等价、评分、导出损失和模型隔离；评估设计缺陷先解决或标为诊断，冻结后再开始优化，修正留痕并重建受影响基线。之后按问题清单依次执行三阶段；优秀即上述优化目标，局部小样本只作声明的候选筛选。

| 阶段            | 工作                                                  | 单轮成功条件                                                       |        上限 |
| --------------- | ----------------------------------------------------- | ------------------------------------------------------------------ | ----------: |
| ① 未及格补齐    | 逐问题优化名称、结构、约束或 describe，向及格目标推进 | 满足该问题预设筛选/验收条件，无已确认的不可接受关键退化            | 每问题 3 次 |
| ② 未优秀补齐    | 对已及格内容继续优化，向优秀目标推进                  | 满足该问题预设条件，保留前阶段成果，无已确认的不可接受退化         | 每问题 3 次 |
| ③ describe 精简 | 逐问题精简或删除冗余描述，降低完整输入成本            | 完整输入缩短，满足预设条件，各被测模型总体及相关关键语义无确认退化 | 每问题 3 次 |

阶段目标、问题清单及验证范围在实验前固定；每项记录失败证据、改动假设、影响路径与依赖、相关用例、保留条件和状态。名称、结构、约束与 describe 均形成裁决；需要公开契约变更时给出具体方案并标待确认，不以仅允许改 describe 为由结束诊断。跳过须逐项给出依据，部分题目未复现不能替代整阶段处理。

名称、结构、约束候选已在本次获批设计与执行计划中明确时，可在批准范围内实施；未批准时只完成优化评估与方案，不因“自动优化”获得公开 API 改动权限。语义等价 describe 调整可在既有优化授权内实施；其候选及对照统一按 3→5 次模式验证。

## 属性命名诊断

- 对照相关 schema 中的同名属性：同名应尽量同义；若它们要求作者选择不同概念，优先按实际含义重命名，复用同义字段的已有名称，不靠 `describe` 消除歧义

## describe 精简候选

- 判别字段的名称与 literal 已表达其作用和取值时，优先将重复说明列为删除候选；不只因字段名常见就删除描述
- 导出的输入契约已列出枚举值或值域约束时，`describe` 不重复罗列；保留结构未表达的参照方向、取值含义或选择条件。仅在 Zod 中校验的规则，先核对模型能否从导出契约读到
- 导出契约的 `required` 已标明必填时，字段描述可省去“必填”，保留结构未表达的约定，如引用名的唯一性
- 字段名和对象上下文已说明用途、导出的 union 分支已说明各自写法时，省略仅复述用途或枚举分支的 `describe`；字段层只补充分支未表达的共同约定或选择条件
- 结构无法表达的领域语义保留在对应字段或对象层级；对象级描述已解释的实体含义，不在判别字段上重复
- 多个字段共同决定一个结果时，在对象级集中说明映射与取值优先级；消费方若只展开 `.shape`，核对其导出契约仍保留这条规则
- 比例字段已有值域约束时，描述优先说明起点、递增方向和省略时的含义
- 同名样式字段跨层生效时，保留取值顺序：省略时取哪一层、显式值替代哪一层，以及最终还与哪一层组合
- 默认值按是否影响填写决策取舍：保留从字段名和结构推不出的隐式来源（如文字颜色回退到 `currentColor`）；省略符合惯例且无需显式填写的值（如透明度乘数为 1）。若实际默认偏离惯例或省略与显式填写不等价，说明差异
- 属性或 schema 含义相近、容易混淆时，优先说明何时选用哪个、选错会产生什么不同结果，不把共有用途写成区别；差异来自隐式逻辑时，只说明影响选择或结果的规则
- 名称引用含有保留值或可匹配多类定义时，说明保留值指向什么、同名时哪个定义生效；无需描述注册表的查找步骤
- 结构分析只支持精简假设，不等于 LLM 验证通过；未采样的修改标为待验证，要求验证时按同条件真实消融比较

## 优化轮次、保留与停止

- 保留、尝试和回滚单位是独立语义问题；共享 schema 且影响无法分离的内容合组验证。不相关问题分别裁决，任一难点失败不清空其他通过项
- 每个问题在当前阶段最多 3 次候选尝试；各问题独立计数，同一问题换字段、换方案或恢复上下文不重置，未解决失败不换阶段重新计数。总调用量始终受统一预算约束，不按问题扩增预算；基线、纯诊断和单题采样不算候选尝试
- 每次先记录有效起点、改动假设与预期可观察改进，再做最小修改、功能验证和相关用例的同条件评估。describe 仍用 3→5 次，模型仍读取完整 schema；先验证目标及必要邻项，避免为尚未通过筛选的候选铺满无关采样
- 满足该问题预设条件即独立保留，记录仅通过筛选还是正式达标，停止该问题当前阶段尝试；其余失败项继续下一次尝试。若 A 通过、独立的 B 失败，仅修订或撤回 B；共享影响未分离时不声称 A 已独立通过
- 三次尝试均失败，只撤回该问题候选到相应起点，保留其他已验证成果并记录未解决项。疑似退化先按门槛节核查；证据不足标待确认，未满足保留条件的候选不计为交付成果，已发生尝试仍计数
- 阶段可部分完成；逐项报告通过、耗尽尝试、无合理候选、证据不足或设计待批。没有合理新候选时说明理由后停止该项，不凑满次数，不以少数用例通过跳过其他问题，也不把局部通过冒充整个 schema 达标
- 最后验证累计保留改动相对原始同条件基线的总体、各属性/关系、必要组合及独立留出集；累计退化核查后定位并撤回对应候选或依赖组，不直接清空整个阶段。仅在正确性符合预设条件时比较精简收益，留出结果暴露后不得据此调参再称盲测
- 各问题均有裁决或明确阻塞状态后结束流程；高成功率项仍须精简诊断。总预算耗尽、无法隔离信息、契约转换缺口阻断、需扩大范围或改变未获批公开契约时交付证据与具体方案并停止，不自行放宽目标或追加采样
- 基线更新须人工选择确认；历史基线与报告不覆盖。未解决项逐一说明继续优化价值、成本、风险与下一步，明确建议和实际执行的区别
- 最终合回沿用入口的人工确认边界；保留实验 worktree 与 ignored 证据，用户确认并核对最终有效快照后再合回和清理，不自动 stage/commit/push
