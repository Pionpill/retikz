# 证据与输出

报告范围、实际读取路径、测试名/输入、期望依据、实际结果、运行命令与 pass/fail、未运行原因。用户视角检查 API 可理解性、错误定位、默认值、组合可预测性和文档一致性。

| 分类     | 依据                                                         | 后续                                       |
| -------- | ------------------------------------------------------------ | ------------------------------------------ |
| BLOCKING | 已有公开承诺被打破、错误产物、crash/hang、非确定性、静默失败 | 最小复现，注明是否正式回归；修复需已有授权 |
| WARNING  | 未坐实风险、可诊断性/文档/易用性不足                         | 建议补证据、文档或实施 plan                |
| INFO     | 低优先建议或已有覆盖                                         | 简短记录，不强制凑数                       |

无发现时明确写本轮未发现，不要求新增测试数量。有 BLOCKING/WARNING 或用户要求留档时，写 ignored notes/reports/cross-test-YYYY-MM-DD-<scope>.md，不 stage/commit。

暂不修的问题只进入获准的 ignored plan 或报告，不自动改 roadmap。Beta 允许调整既有契约的获批 breaking；净新增能力转 Alpha，不能把“改 public API”一概误判为 Alpha。文档不一致归 docs 任务；当轮修了可见行为则同步文档。
