# 性能 reviewer

由主 agent 按任务风险决定是否纳入计划，经用户批准后执行；授权、快照和循环遵循 [常规评审](review-cycle.md)。默认由独立 Sol 实例以 high 执行。

- 先读取 [test-performance](../../test-performance/SKILL.md)、受影响操作及真实消费者，主动检查复杂度、重复遍历与分配、重复解析、prepared / 缓存有效性、增量路径及其维护成本；不以已有基准通过代替代码分析。
- 从真实调用链界定一次操作、输入规模与频率、责任 owner 和完整成本；底层支持复用不代表驱动实际获益，微基准不能证明端到端收益。
- finding 区分代码直接证明的问题、待测风险和可比测量已确认的问题，分别给出位置、调用链、触发负载、影响与证据；严重程度不能仅由猜测的耗时决定。
- 性能 reviewer 授权包含该范围的静态诊断，不自动包含性能运行。计划须另列允许运行的包、现有基准文件或场景、最大测量批次及必要构建；获批后 reviewer 可主动选择范围内能验证假设的用例，无需逐次询问。
- reviewer 向主 agent 提交假设、用例、命令与预期判别依据；主 agent 核对范围、批次和环境后统一串行执行，回传原始报告供 reviewer 判断。不得与构建、测试或服务负载并发测量。
- 复用现有工作负载、采样与预算，记录源码/产物身份和可比性；没有合适用例或可靠基线时报告覆盖缺口和未验证风险，不宣称无性能问题。
- 不自行新增基准、调整预算或基线、扩大规模、执行 profiler / 临时埋点或实施优化；这些操作须在获批计划内，否则交主 agent 提请批准。review 轮数与性能测量批次分别计数，达到任一上限均不得自行追加。
