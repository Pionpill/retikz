# 公开 JSDoc 与 API 参考

用于公开声明的 JSDoc 编写与审查；没有文档页的公开符号同样适用。生成展示另读 [API 投影](api.md)。

## 范围与真源

- 从 package `exports` 的根入口、子路径与公开 barrel 建清单，跟随 re-export 到声明真源；包含公开成员、嵌套配置、回调、重载和继承契约，不把内部 `export` 当成公共 API
- 包参考覆盖其声明的入口；组件参考是明确列出范围的局部视图。按物理声明去重审查，保留每个公开入口的可达关系；未生成页面的公开符号仍检查 JSDoc
- 先核对签名、实际消费者、默认值应用处与相关测试，再下语义结论；不能从名称、旧文案或可选标记猜行为。只读审查不自动授权改源码、生成产物或公开面
- 纯 `ValueOf` / `z.infer` 别名及收窄 re-export 可沿用根规范的注释豁免；品牌字段、第三方继承字段和类型推导结果需单独判断，缺注释计数不等于缺陷数

## 从调用者写起

- 首句说明用途或可观察结果，脱离源码也能读懂。避免“某某配置”“某某 registry”式同义复述，或以内部处理链、包间所有权作为主要摘要
- 注释正文使用中文；保留准确的 API 名、字面量及通用技术名。必要领域词首次出现时就近解释或链接，不用中英术语拼接替代功能说明。Zod `.describe()` 的英文契约不纳入此中文要求
- 字段说明就近解释它影响什么、何时生效；按实际需要交代单位、坐标系、取值边界、缺省/空值、优先级、互斥和继承。不把复杂字段说明全部堆在类型摘要
- 函数说明补足签名不能表达的输入条件与输出语义；有实际影响时说明修改输入、返回原对象、异步完成/取消、回调时机、订阅释放和错误后的状态
- 公共扩展作者也是读者：Definition、registry、编译回调可保留必要阶段术语，但要说明调用时机、输入保证及输出责任，不写实现流水账
- 简单且自明的 API 可用一两句。复杂度决定说明深度，不要求每个符号凑齐标签或附教程

## 标签分工

| 内容                   | 放置与要求                                                                                                       |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------- |
| 摘要 / `@description`  | 首句给独立摘要；复杂主语义、启用条件、跨字段关系放 `@description`，不重复摘要                                    |
| `@param` / `@template` | 补充参数含义、单位、边界及泛型关联；泛型统一使用标准 JSDoc `@template`，参数名与声明一致，不重复 TypeScript 类型 |
| `@returns`             | 说明结果含义、空结果、顺序、引用/所有权及 Promise 完成语义；不要只写“返回结果”                                   |
| `@throws`              | 写调用者会遇到的触发条件与实际错误；区分抛出、Promise rejection、诊断回调和空结果，不编造异常                    |
| `@default`             | 对有默认值或明确缺省行为的配置字段逐项标注；新写统一用此标签，读取兼容已有 `@defaultValue`                       |
| `@example`             | 复杂组合、易混分支、扩展注册或生命周期用最小例子解释；展示实际公开导入、调用及有意义的结果                       |
| `@remarks`             | 只放非主路径补充或有助使用的设计理由；正确调用必需条件不能藏在这里                                               |

`@since` / `@deprecated` 仅在有真实依据时使用；不要为标签齐全制造版本、兼容承诺或已移除 API。自然语言中的包名、CSS 指令等含 `@` 文本要检查解析结果，避免误切为标签而丢失后续正文。

- JSDoc 不使用 `@see` / `{@link}`，功能与关键约束就地说明，相关符号用普通文字或行内代码。API 参考不生成延伸阅读或链接展示；已有 `@see` 不投影，已有行内链接只保留文字。文档导航放在 docs 正文维护，不写进包源码

### 泛型参数

- 公开声明的每个泛型参数必须用 `@template` 说明用途及与输入、输出或成员的关联；默认类型有语义影响时一并解释
- 生成参考前逐项核对泛型说明；缺失时先在声明真源补齐 JSDoc，再同步英文翻译并重新生成，确认类型参数表不再以 `—` 代替说明

### 默认值

- 区分固定值、上下文继承、按内容计算与没有默认值；动态缺省在字段说明中解释，`@default` 标可定位的来源，不伪装成固定常量；必填项不填假值
- `@default` 的值只能是可定位的代码字面量、常量、上下文或解析入口（如 `BUILTIN_ARROWS`、`ThemeStylesContext`）；禁止填入自然语言转述，语义解释留在字段说明
- 说明生效顺序及条件，例如先采用显式值、再继承、最后采用内置值；与 schema `.default()`、解构默认、resolve 和宿主配置的实际行为一致
- 生成 API 参考前，逐项回查 schema、解构、resolve、上下文合并和宿主逻辑中的缺省行为；存在固定值或可说明的动态缺省而字段未写 `@default` 时，先补齐 JSDoc 再生成，不以表格中的 `—` 代替核对
- 函数参数的缺省行为写在对应 `@param`，options 对象的默认写在字段上；不在函数顶层用一个 `@default` 含糊指代多个参数
- 可选不等于有默认，生成表中的 `—` 不证明运行时没有默认；常量声明的值也不自动代表消费者的缺省行为

### 示例

- 围绕一个容易误用的行为，展示最少前置配置；异步、资源释放或互斥选择属于该例正确使用的一部分时必须保留
- 对有关键分支的 API，按需要补一个对照结果或边界例子；简单字段不机械添加 `@example`
- 使用真实公开入口与现有符号，不用内部 deep import、强转或虚构参数让例子成立。示例代码与相关最小验证一致，不能只靠生成成功证明可运行
- 包内示例不得依赖文档站私有文件或未随包发布的 demo；必要定义就地给出，调用方提供的前置对象须明确类型与来源
- 使用当前解析/渲染器支持的代码围栏；核对 TS / TSX 高亮、缩进与示例外说明，不能假定 TypeDoc 支持的形态自定义生成器也完整支持

## API 参考的投影

按 [API 生成与翻译](api.md) 检查声明、字段、默认、重载与示例是否完整投影。区分源码缺说明、提取丢信息、翻译失真与页面难查询；不手改 generated include，不为展示增加公共导出。

## 中文与英文

- 中文 JSDoc 是说明真源；英文通过受审阅的翻译产物生成，遵守现有缺译失败机制，不在浏览器翻译或静默回退中文
- 核对摘要、详情、字段、参数、默认行为、返回、异常、备注、链接标签及示例说明的逐项对应；英文没有汉字不等于翻译完整，更不等于契约准确
- 保留标识符、类型、参数名、枚举值、导入路径和影响行为的字符串。示例中的说明性注释与面向读者的展示文案需要英文对照；中文测试数据或语法演示字面量可保留，但不能用“代码块豁免”掩盖漏译
- 对照检查否定、条件、单位、优先级、可选性和时序，禁止翻译新增保证或把“可能”变成“总是”。只有摘要译完不能判整页完成
- 当前工具若未投影某字段/标签或未本地化默认值、示例，明确报告限制；既不声称英文已完整，也不擅自扩大为生成器改造

## 审查与验证

1. 明确页面/包/全仓范围与授权动作，列出公开入口、声明真源、页面和翻译来源
2. 机械检查清单覆盖、缺注释、全英文说明、标签与缺译；随后从调用者视角核对功能语义、示例必要性与默认值。自动筛选只生成候选，不作缺陷定论
3. 报告覆盖层级：全量机械扫描、语义审查范围、实际页面验证分别说明；抽样不能表述为逐项语义通过。问题附符号、源码/页面位置、读者影响和修订建议，不用总分掩盖关键遗漏
4. 按实际改动验证：skill-only 校验 frontmatter、引用、规则冲突与任务分流；改 JSDoc/翻译则重新生成受影响双语参考并检查 diff、类型和关键示例；改展示时在浏览器检查 zh/en 的字段、默认、示例、锚点与可读性。命令与 Docs 提交检查沿用 docs-doc-principle，不因全量审查自动重写全仓
