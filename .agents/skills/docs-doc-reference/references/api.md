# API 生成与翻译

先核对 `apps/docs/scripts/generate-api-references.ts` 与对应 `scripts/api-reference/` 配置；沿用现有生成命令与英文翻译产物，不直接手改生成 include。

生成 API 时必须同步执行 [JSDoc 完整性检查](jsdoc.md)：逐项核对本次收录的公开声明、类字段、构造函数、方法及各重载的摘要、参数、泛型、返回值、异常与真实缺省语义，按适用性补齐声明真源和英文翻译后重新生成。逐项解释产物中空白或 `—` 是不适用、无默认值还是注释 / 投影遗漏；不得以生成成功代替完整性审阅，不为填表虚构默认值或无意义标签。签名上的注释也须投影，不能只读取成员节点注释。

API Reference 只收录从 package `exports` 可达的真实公共标识符；入口、子路径、re-export 和 JSDoc 必须由 TypeScript 分析产物确定，不扫描任意内部源码文件。中文说明以中文 JSDoc 为源；英文说明由受审查的翻译产物生成，代码标识符、签名、枚举值、示例执行语义和 JSDoc 机器语义不翻译；示例中的读者说明按 [JSDoc](jsdoc.md) 核对。不得在浏览器运行时调用 LLM 翻译，也不得把未经审查的机翻作为契约真源。

每次 API Reference 变更先运行生成脚本，再由 LLM 翻译新增的中文读者说明并写回生成器的英文翻译产物；随后审阅术语、代码标识符和 Markdown / MDX 结构，重新生成英文 include。缺少翻译必须让生成失败；英文 include 不得遗留未翻译的读者说明，代码块内按说明与语义字面量区分检查。LLM 只参与生成时的翻译与审阅，不参与浏览器运行时。

API Reference 的目标投影契约如下：首段 summary 生成名称下的职责摘要；`@description` 生成主体说明；`@remarks` 生成备注；字段 `@default` / `@defaultValue` 生成默认值列；`@param` 与 `@typeParam` 生成同表参数与泛型行；`@returns` / `@return`、`@throws` / `@exception` 生成同表返回值与错误行，`@example` 生成用法代码块；`@since`、`@deprecated` 生成版本和弃用元数据；`@see` 不投影，`{@link}` 只保留文字，不生成链接。可见性标签和 `@inheritDoc` 按当前 TypeDoc 配置核验，不能覆盖 package exports 的真实公开面。未使用的标签不制造空章节；不从源码签名或实现猜测缺失说明。

`ZodInfer<typeof XxxSchema>` 等 Schema 推导对象的属性表以公开 Schema 字段为说明真源：英文取 `.describe()`，中文复用对应 Schema Reference 的人工翻译，缺译时阻止生成；默认值只取字段 Schema `.default()` 解析后实际物化的值，不把继承或编译缺省写成 Schema 默认。字段类型由 TypeScript 解析，超过表格长度限制时显示指向该字段 Schema 的类型表达式；其他对象类型超限时显示命名类型的字段索引，禁止用省略号替代。原始声明仍放「类型定义」，生成脚本不得在页面中复制一份 Schema 字段定义。

## 实际能力核验

目标契约不代表每种声明结构都已支持。修改前核对 `tex.ts` 的对象、Schema、重载与渲染逻辑；遇到缺口按源码、投影、翻译分别记录，不手改 include 或把未展示内容视为已完成。

- 对象展开一级，映射与继承成员取 TypeScript 解析结果；字段投影 summary/description/default，可选性与只读性按解析结果，索引签名并入成员表。默认显示「属性」，完整原声明放「类型定义」；分组配置只组织字段
- Schema 继承沿别名、交叉类型、工具类型及字段索引追溯；`Extract` / `NonNullable` 与嵌套字段路径仅在能唯一定位对象分支时复用公开 Schema 及既有翻译。直接重声明字段使用自身 JSDoc；来源歧义或缺译不得猜测。`.describe()` 中的缺省说明不等于 `.default()`
- 函数重载完整保留各签名、参数、泛型及已有说明；可调用类型别名也要追踪调用签名，不只读取首签名。公开声明缺少 JSDoc 时不擅自借用私有实现注释
- 有摘要时以摘要链接源码，无摘要时保留独立「查看源码 / View source」入口
- 函数、可调用类型与类同样使用单层「属性 / Members」「类型定义 / Type definition」页签，默认属性；属性页展示成员或参数、泛型、返回值和异常说明，类型定义页展示完整公开声明，不在页签外重复，不嵌套 Tab；源码链接仍指向实现，不将类型定义命名为源码
- 未确定字段的泛型、条件类型及超限结构保留原声明与源码入口；示例目前统一包成 ts 围栏且未独立翻译，不能声称已完整支持

### 属性页签单表

- 每个 API 的属性页签只用一张表承载泛型、成员、调用参数、返回值、错误与索引签名；不在页签内外另拆这些子小节或附加表。联合分支和显式重载页签各自一表，重载契约必须逐项对应，不混合不同签名的参数与返回值
- 对象与类沿用成员表，不因泛型或调用信息增加分组列；泛型置于字段前，名称旁标注“泛型 / Type parameter”，调用参数标注“参数 / Parameter”，返回值、错误和索引签名直接作为行名。补充行不参与字段用途分组；无默认值写 `—`
- 独立函数使用“类别 / 名称 / 类型或签名 / 说明”，依次列泛型、参数、返回值、错误，同类别只在首行写类别；无对应契约则省略。泛型约束、默认类型及返回类型取公开声明，不猜测缺失说明或错误
- 摘要与主体说明置于表前；示例保留代码块，备注与版本信息保留正常排版，使用行内标签而非四级小标题。“类型定义”保留完整公开声明

### 函数与构造函数重载

- 不拆“重载 1 / 2 / 3”标题或小节；「类型定义」按源码顺序将全部签名合并为一个代码块。未配置独立重载页签时，调用契约集中在一张属性表，重载编号仅在该重载首行显示；重载摘要与主体说明并入对应首行说明，参数与返回值保持逐项对应
- 表格中的函数、方法与构造函数重载按源码顺序各占一行，签名与对应重载的说明逐行匹配；相同成员名只在首行书写，后续行留空，不把多个签名或说明拼进一个单元格
- 构造函数的表格签名只保留参数列表，不重复所属类的泛型约束、默认类型和返回实例类型；参数中的泛型引用仍保留，泛型含义见同表泛型行，完整声明保留在「类型定义」。普通函数与方法保留自身泛型和返回类型，不用省略号截断契约
- 仅含构造函数或方法的成员表使用「成员 / 签名 / 说明」，省略不适用的默认值列；混合数据属性的表保留默认值列，无默认值或不适用时写 `—`。独立函数的参数、返回值等说明仍按重载对应，不将参数表误作成员表

### 联合分支

TypeScript 解析后全为对象、分支不超过 8 个且各分支字段数之和不超过 40 时，用单层 `DocTabs > DocTab` 并列展示「属性 · 分支名 / Members · Branch label」与末尾的「类型定义 / Type definition」，默认选中首个分支；不再嵌套「属性」页签。每个分支独立投影字段说明与默认值，保留判别字段和互斥约束，类型定义保留完整联合声明。普通对象仍使用「属性 / 类型定义」。

分支名由 LLM 阅读源码后按语义确定，禁止「分支 1 / 分支 2」等序号名称。将双语 label、稳定 value 和判别字段类型写入 `apps/docs/scripts/api-reference/branch-labels.ts`，以 `包名#符号名` 定位；按判别字段匹配，不依赖分支数组顺序或在生成器内写组件特判。缺失、过期、歧义或重复映射阻止生成；zh/en 使用相同 value。

不满足分支表条件时，沿用受限“展开类型”：仅展开原声明隐藏的命名分支，最多 8 分支、40 行、500 字符；直接可读的对象、字面量、关键字、Readonly、数组或元组分支不重复展开。展开含未解析工具类型、`import(...)`、`$Zod` 或超限时保留原声明。

具备有效展开类型且未使用属性表时，以单层「展开类型 / Expanded type」「类型定义 / Type definition」页签展示，默认选中展开类型；原始声明只放类型定义，不在页签外重复展示。没有有效展开时沿用原始声明展示。

## 属性表分组

新增或优化对象类型的「属性」页签时，字段超过 12 项且能按用途形成有意义的多个分组，才在同一表格首列显示「分组 / Group」；每组只有首行写组名，其余行留空。语义单一或字段不超过 12 项时沿用四列表，不为凑数量强行分组。组间按读者查找任务排序，组内保留 TypeDoc 提取的字段相对顺序；每个字段恰好归属一组，zh/en 的分组与字段顺序一致。「类型定义」仍展示原始声明，不受分组影响。不得根据字段名自动猜测分组。

先运行生成脚本，读取未分组的字段表及源码类型、JSDoc，LLM 再逐项判断用途，将 `包名#符号名`、组顺序和字段归属写入 `apps/docs/scripts/api-reference/member-groups.ts`；不要在各页面配置中写符号或 owner 特判。重新生成双语 include，脚本必须拒绝字段遗漏、未知字段、重复或空组、组顺序遗漏。分类结果随生成器保存和审阅；生成时只读取已保存的分类，不调用 LLM，也不直接手改 generated MDX。已有显式 `DocSteps` 分组保持原状，迁移时先删除旧配置再使用集中分类。

分组名只从下表选择，英文词同时作为稳定键；每页按实际职责选用，不强制出现全部分组。`Main / 主要` 只放标识、内容与关键调用字段，不用作未分类字段的兜底。

| English    | 中文   | 适用字段                 |
| ---------- | ------ | ------------------------ |
| Main       | 主要   | 标识、内容、关键调用字段 |
| Input      | 输入   | 传入数据与配置           |
| Output     | 输出   | 结果、产物、结果通知     |
| Data       | 数据   | 数据内容与映射           |
| Geometry   | 几何   | 位置、形状、边界、变换   |
| Layout     | 布局   | 排列、尺寸、间距         |
| Style      | 样式   | 外观、主题、层级         |
| Rendering  | 渲染   | 渲染器、宿主、视框       |
| Callbacks  | 回调   | 事件处理函数与回调       |
| Animation  | 动画   | 时间轴、播放、采样       |
| Runtime    | 运行时 | 执行模式与运行载荷       |
| Extensions | 扩展   | 能力注册与注入           |

轻量 Props 包装由脚本自动识别：顶层 `Omit` / `Pick` 与交叉组合中，直接声明字段不超过 3 个、而解析字段超过 12 个或字段文本超过 500 字符时，不渲染继承字段的大表。默认页签改为“直接属性 / Direct members”，仅列新增字段并说明继承类型和被移除字段；完整组合仍在“类型定义”。

字段表中的枚举值不展开为字面量联合或 const object；能唯一对应公开常量时，用 `ApiValues` 显示常量名并提供取值提示。开放字符串须同时保留可自定义的类型语义；无法确认对应常量时保留真实类型，不猜测名称。

字段表中的索引类型引用也要核对实际类型；若能用简短、等价且公开的类型表达，优先展示该类型，例如 `Array<IRAnimationTrack>`，不因推断展开文本很长就机械保留 `InputEntity['animations']`。复杂结构仍保留具名引用，不在单元格展开大对象。

生成后，LLM 须独立复核公开对象与 Props 的展开 / 收起结果，判断脚本选择是否方便读者查字段、是否造成过宽或重复的表格。若建议与脚本不同，以“符号｜脚本结果｜建议｜理由与读者影响”表格告知用户；用户决策后才调整展示配置并对该项下最终结论。

长任务先沿用脚本结果继续执行，不为展示建议中断；收尾时用同样的表格集中说明推荐调整方案。用户决策前不改这些展示配置，也不把脚本结果表述为最终阅读结论。
