# 参考页结构

## 分工与唯一真源

本地化翻译分组名及 JSDoc、describe 等说明文字；变量、函数、类型、枚举、属性和 Schema 等代码成员保留源码原名，成员标题不翻译或省略后缀。标题中的名称使用 `ApiSourceLink` 指向各自真实声明；字段类型中的 Schema 引用只显示原名。公开枚举使用现有 `ApiValues` 展示取值，不扩展为对象或 Schema 详情浮层。

| 参考内容 | 契约真源                                              | 查询职责                                         |
| -------- | ----------------------------------------------------- | ------------------------------------------------ |
| API 参考 | package exports、公开 barrel、TypeScript 签名与 JSDoc | 完整公开标识符、签名、参数、默认、返回与错误说明 |
| Schema   | 公开 Zod schema 与 describe                           | 持久化 IR / 配置字段、类型、必填、默认和校验结构 |

两类内容合为“API 参考 / API Reference”，独立页路径为 `<owner-path>/reference`，不设阅读难度。开篇说明收录范围、公开入口并链接基础用法；主体按能力组织；需要时以延伸阅读收尾。不添加安装教程或内部执行章节。未公开的内部类型不得为生成参考而额外 export。

包参考拥有完整查询真源；组件参考可提供同一生成来源的局部视图。Schema 推导类型依据真实声明与 Schema 配对，标题如 `IRDataTransform / TransformSchema`；两者名称分别链接自身声明。在同一层 DocTabs 中并列「属性 / Members」「类型定义 / Type definition」「Schema」，联合分支页签也保持同层，不嵌套。只展示实际存在的页签，无属性表时保留类型定义与 Schema；无对应 Schema 的 API、无配对类型的 Schema 独立成单元，不造占位或平行 schema。

独立页按能力设 H2，如“变换声明”“行选择”“统计归约”，不以包名或类型名代替能力分组；成员统一使用 H4，右侧 TOC 只收录能力分组。包名及实际导入子路径放入口说明或正文标签。嵌入非独立参考页时，以 H2“API 参考”收录合并内容，分组改用正文标签，成员仍用 H4，不增加 H3。zh/en 分组与成员顺序一致；生成配置须拒绝遗漏、未知或重复成员。

同一入口及其专属 Props / Input 类型合并为一个参考单元，标题使用 `入口名 / 类型名`，如 `ListItem / ListItemProps`、`list / InputList`，各名称分别链接源码。移除独立摘要链接行，保留详细契约说明；入口签名与类型定义放在同一个代码块，属性表和必要的类型展开放在该标题下，不再按标识符拆节。共享类型或可独立使用的类型仍单独收录，不因名称相近而合并；配对依据实际契约，定义与说明仍从源码生成，zh/en 同步。

入口与 Props / Input 合并展示后，若参数表仅重复已有签名及该输入类型、没有额外说明，省略“参数”标题与表格；存在其他参数或独立调用约束时保留必要说明，不丢失源码契约。

组件 Schema 参考只收录主 schema、组件所有的直接子 schema，以及该页面承担的专属配置通道输入 schema。共享的 geometry、style、entity、default 等 schema 即使被主 schema 字段引用，也只在类型列保留名称，交给所属参考页说明；不要以“高度相关”为由递归展开。排除内部组合辅助、解析态、编译输出与运行时 schema，不因属于同一包而全量展开。具体边界见 [Schema 参考](schema.md)。

配置参考在字段表前交代启用条件、默认值应用时机及省略值与显式值的区别；只描述该配置实际存在的语义。
