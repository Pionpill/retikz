# 固定采样轮次

先按运行目的选择采样档，不因中间过程需要保存报告就升级为正式采样：

| 档位                         |  预热 |   测量 | 用途                                                                                     |
| ---------------------------- | ----: | -----: | ---------------------------------------------------------------------------------------- |
| 中间分析档                   |  0 轮 |  10 轮 | 中途观察优化效果、插桩诊断、定位与筛选候选方案                                           |
| 正式常规档，包括业务重点规模 | 10 轮 | 100 轮 | 用户明确要求生成性能报告、正式性能比较，或最终结果报告；P50 为对比基准，均值仅作辅助统计 |
| 百万等超业务规模参考档       |  0 轮 |   3 轮 | 大致耗时与可完成性，不作为稳定分位数或门槛依据                                           |

中间过程分析默认简化，最终报告使用完整采样。10轮无预热的结果须标记为中间诊断，不用于宣称最终达标或更新基线；正式结论另用同条件完整采样核验，不将两档结果直接混比。“完整”指已授权场景的采样协议，不自动扩大到全仓或全量用例；用户另有明确轮次时优先遵循，超规模参考档仍保留3次上限。

Vitest / Tinybench 配置意图：

```ts
// 中间分析档：关闭预热，仅测量10轮
{ time: 0, iterations: 10, warmup: false, warmupTime: 0, warmupIterations: 0 }

// 正式常规档：关闭时间驱动，固定预热与正式轮次
{ time: 0, iterations: 100, warmup: true, warmupTime: 0, warmupIterations: 10 }

// 参考档：实际算法计算总次数不得超过 3 次
{ time: 0, iterations: 3, warmup: false, warmupTime: 0, warmupIterations: 0 }
```

- `time > 0` 与 `iterations` 通常是共同满足的最低条件，不能把 iterations 当成上限；短算法可能因此产生数百万样本
- 对同步算法显式设置注册选项 `async: false`，避免自动探测额外执行。参考档不得在计时前另算一次完整规模“预期结果”；包括探测、预热、校验在内的实际计算总数必须受限
- 核对安装版本与共享 helper 的真实行为，以计数器和保留样本验证：中间分析档样本与总调用都为10；正式常规档样本100、总调用110；参考档样本与总调用都为3。计数用于验证测量协议，不替代算法正确性断言
- 正式常规档 100 次是默认起点，不保证测量稳定；P50 使用中位数，偶数样本取中间两个排序值的平均（100 个样本取第 50、51 个值的平均）。中间分析档仅 10 次，不用于正式验收；更换统计指标不消除运行间漂移，不擅自扩大采样
- 固定预热 10 次不保证 JIT 已稳定；有重复运行漂移证据时再调整具体场景，并记录实际配置
- 优化改变前序场景的执行路径时，对异常退化做隔离复测，区分执行历史影响；隔离结果不替换原场景集合的整体对照
- 接入时检查 [sampling.ts](../../../../scripts/benchmarks/sampling.ts) 是否符合上述约定；发现差异应在获授权的实现任务中修正并验证，不能把 skill 中的目标配置当作已运行事实
