# 报告后的 AI 诊断

1. **授权分流**：核对报告后，已开启自动优化的直接执行下述阶段；未开启的询问是否进行 AI 诊断，说明包、重点用例、插桩与重跑范围，获准才诊断，交付方案后仍需确认实施。仅批准诊断不等于开启自动优化；后续明确开启时沿用前置授权，不重复审批
2. **测试用例复核**：先不看算法实现，从重点结果中的错误、警告入手，结合用例、预算依据和已知消费需求检查上限、输入规模、形态及调用频率是否合理。区分真实需求、假设场景和不符合实际消费方式的负载；只有需求或测量边界的证据表明原预算不合理时才建议调整，保留原预算、调整理由与证据，否则按性能问题继续分析。不能仅凭耗时高或暂未找到消费者就认定场景不成立，也不能为消除红黄标记放宽标准
3. **三阶段依次执行**：只将仍不满足标准的目标推进到下一阶段；没有可行优化点时记录依据后推进，不为凑轮次改代码。初始结果或任一步骤完成后，若全部目标已按正式采样确认达到预设性能标准、正确性通过且无不可接受退化，则停止并生成最终报告，不继续插桩或另造机制方案

| 阶段             | 工作与依据                                                                                                                          | 自动优化开启时的决策边界                                                                           |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| ① 源码诊断与优化 | LLM 根据结果、源码及调用链识别重复计算、分配、算法和局部逻辑优化点；按需读 [通用优化原则](optimization-patterns.md)，实施候选并验证 | LLM 自行选择、实现、比较及保留/撤回，不要求人工批准具体候选                                        |
| ② 插桩定位与优化 | 仍未达标时用临时插桩拆分真实瓶颈，依据分阶段耗时与占比优化；记录插桩开销，移除探针后再比较收益                                      | LLM 自行设计插桩、诊断、实现与判定，不能仅凭源码推测替代该阶段测量                                 |
| ③ 机制与目标复审 | 仍未达标时跳出具体算法/逻辑，从调用机制、行为必要性、职责归属及相关 ADR 目标寻找替代方案；核对成熟方案、适用边界和目标一致性        | 生成含证据、预期收益、行为/契约差异、风险和验证计划的新方案，交人工决定；不自行实施或修改 ADR 目标 |

插桩与中间对比使用 **0 预热 + 10 测量**，同条件串行运行；原始基准与插桩结果分开保存，不擅自扩大规模或混比。达标停止及最终保留/撤回结论使用 **10 预热 + 100 测量**核验，参考档沿用其上限。临时探针不得作为生产优化保留；每阶段的证据、候选与决策写入 plans，正式报告区分实测、推测、未验证项及人工决策项

## 获准优化后的闭环

- 性能优化相关代码段须就近补充带 `⚡` 的中文注释或 JSDoc，说明具体优化手段，例如 `// ⚡按变换类型直接累计矩阵，减少中间矩阵分配`
- 前两阶段合计最多 **3 轮**优化；一轮指“实施或替换方案 → 功能验证 → 同条件性能对比 → 判定”，首次优化计第 1 轮，初始基线和纯诊断不计轮次。为插桩阶段至少预留一轮，阶段不等于轮次，不因换方案或上下文恢复重置；未达标则进入第三阶段出方案，不自动追加第 4 轮。机制方案获批后的实施轮次另行明确
- 中间候选筛选和效果观察默认采用10轮无预热，不逐方案套用10+100；最终保留/撤回结论及正式报告采用完整采样核验。保存中间对比记录不构成升级采样的理由
- 每轮由 AI 逐方案判定：正确性通过、达到预设预算且没有不可接受的退化才算通过；有收益但仍超限的保留有效改动并继续优化；无收益、退化或正确性失败的修正或撤回本轮对应改动，换方案继续，不影响用户既有工作。测量不可比或波动不足以支持结论时不得判通过
- 多轮结束时必须复核累计改动相对优化前同条件基线的 P50，不能只比较最后一轮或挑选改善场景。逐场景列出 P50；模块整体对比按运行前固定的场景集合与权重汇总各场景 P50，明确这是 P50 加权汇总而非混合样本的 P50，不事后删选或改权。若整体 P50 汇总不降反升，撤回对应范围的累计性能优化改动（包括前轮保留项），保留用户其它工作并验证撤回结果；不能用局部提速抵消整体退化。基线不可比时先补齐对照证据，不宣称有收益
- 在已授权范围内自动推进未解决项，不逐轮请求确认，也不以“已有提速”提前结束。预算与测量条件保持可比，不以放宽阈值消除问题；涉及公开契约变化、范围扩大或外部阻塞时仍按仓库规则交人工
- 每轮保存对比证据及通过、保留、替换的理由并更新长任务状态。全部目标达标时收尾；前两阶段结束仍未达标时完成第三阶段方案并停在人工决策点。报告列出各阶段/轮方案、前后耗时、预算状态、正确性与退化、剩余问题及停止原因，不以已有收益代替达标

## 停止与最终评估

- 前两阶段结束后，未达标项进入机制方案评审；提前全部解决时直接收尾。列出方案失败、超预算、契约阻塞和证据不足项，按真实消费频率、绝对耗时及预算缺口、累计 P50 收益、风险与维护成本提出继续、暂缓或停止建议；第三阶段的选择和实施由人工决定，不因超限自动追加实现轮次
- 评估是否更新回归基线：仅将最终保留且正确性验证通过、测量条件可比、重复测量足以支持稳定性的快照列为候选；记录保留旧基线、建议更新或暂缓及理由。条件变化须新建独立基线，不覆盖旧证据；更新基线不调整消费预算、不消除未解决项，实际更新仍由人工选择确认
- 最终结果报告必须包含失败/未解决清单、各项继续优化必要性与优先级、保留/撤回结论及 P50 证据、基线评估与实际更新状态。区分建议和已执行动作，不只汇报测试通过或耗时变化
- 流程结束时，若同条件实测有性能收益，将有效做法提炼为可复用原则并注明适用边界，对照[通用优化原则](optimization-patterns.md)说明已有覆盖或建议补充之处；需要补充时由用户决定是否写入，不自动修改 skill
- 按计时边界分别报告预算状态与最近测量版本；流程级达标不消除单元级未解决项。候选撤回只否定当前方案的保留依据，不证明模块没有优化空间；后续诊断应说明需要补充的调用链或成本证据
