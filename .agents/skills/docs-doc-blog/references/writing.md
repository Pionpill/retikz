# 博客写作

面向熟悉 React/TypeScript 的程序员，解释设计为什么成立、实际开发经验与版本演进，不替代 API 参考。

## 作者与 AI

作者提供主线、观点、经历和偏好的例子；AI 组织表达、核对技术事实与补齐必要上下文。默认先对齐大纲再逐节整理；用户已指定范围与结构时直接执行。保留作者指定的外链、术语和 demo，发现失效或不准确时说明证据再调整，不擅自换掉观点。

结构调整服务主题内聚性，不以阅读分钟数、H2 数量或屏幕行数强行拆篇。段落围绕一个观点；列表用于并列或步骤，表格用于重复比较，连续推理保留段落。

## 表达与示例

- 先交代当时的问题、约束与选择，再写结论和术语；不要以全知复盘口吻省略理由。
- 允许主观判断与客观比较，不虚构竞品缺陷或优越性。
- 代码来自真实源码/历史记录，假设示例明确标“仅作示意”；代码围栏带语言。
- retikz 效果使用 ComponentPreview，前后解释观察重点；新 demo 文件与 i18n 遵循公共预览契约，不能继续创建旧双语副本。
- 叙述图遵循公共插图规范，不用截图、GIF、视频、Mermaid 代替。ZodSchema 和 ExamplePrompt 不用于博客。
- 标题简洁，正文脱离站点 UI 仍能理解；不要把“点击右上角”当成完整解释。

## 检查

技术结论有依据，作者经历未被编造，术语一致；去掉互动组件后周围文字仍说明例子的作用。实际验证按总则，不以长度或固定段落形式判定文章质量。
