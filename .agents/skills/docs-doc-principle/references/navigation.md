# 文档导航与路由

先读 docs-doc-principle 与其 [页型词典](page-contract.md)。本文件负责页面放在哪里；正文由对应主写作 skill 负责。

## 导航单位

区分模块（kernel、library、schematic、viz）、拥有独立阅读界面的解决方案（如 Kernel、Standard、Plot）、发布包与组件家族。一个解决方案可包含多个包；React / Vanilla adapter 共用解决方案入口，不复制整套导航。根据当前 data、路由和侧栏实现确定真实路径，不假定方案名等于顶层 moduleId。

## 默认入口与三类侧栏分区

简介、快速开始、更新日志固定按此顺序直接显示在侧栏顶部，不加“快捷访问”等分组标题，也不包进可折叠分组；它们是所有读者的默认入口。

其后按以下顺序组织；分区是展示职责，不强制成为 URL 段：

| 分区                              | 固定内容                                                         |
| --------------------------------- | ---------------------------------------------------------------- |
| 概念 / Concepts                   | 基础概念 basic、核心概念 core、设计理念 design；无内容的组不显示 |
| 组件 / Components，或领域专用名称 | 可直接调用的主要能力；普通方案按组件家族，Plot 可按图形语法阶段  |
| 进阶 / Internals                  | 跨能力扩展、测量、编译、运行机制与底层诊断；难度按页型确定       |

跨能力扩展入口（如 Kernel 复合组件）归进阶区；组件局部的自定义、实现原理与参考留在所属 owner 下，不因难度移动到远处的进阶区。API / Schema 参考不声明难度，也不自动归底层。画廊与博客保留已有独立用途；不为凑分区把成品展示放进概念或底层区。

分组主体承担总纲，children 依次为基础用法、具体专题、自定义用法、实现原理、API 参考、Schema 参考。只创建确有内容的页面，不要求每个 owner 凑齐六种。包可以在总纲提供安装与最小接入；复杂使用另设 usage，避免两页复制同一教程。

## 命名与归属

- 统一名称和尾段按页型词典，专题名说明真实任务。旧路由不规范时允许在获准重构范围内改名，不以保留历史拼法阻止规范化
- 每个公共 API / schema 有唯一权威参考入口；局部页面链接或使用同一生成产物的定向视图，不复制完整字段词典
- 共享概念归其语义 owner；其他解决方案解释自身差异并链接权威页，不复制全套概念
- 分组根页有正文，不额外设 overview，也不默认为首个 child 的重定向

## 改路由时

1. 阅读当前 data、contents、i18n、路由解析、文档加载与 manifest，列出旧路径到新路径的映射
2. 校验嵌套深度：data 可递归不代表路由、面包屑、加载器或静态检查支持任意层。需要改站点代码时先确认该范围已获准；不要生成不可访问的深层页
3. 同步正文目录、data id、双语标签、站内链接、LinkedSections、模块快捷入口、schema registry、API 生成配置与源码锚点引用；检查脚本中的固定路径
4. 删除被替代的旧路径；不新增旧名别名、兼容重定向或双份正文。迁移范围外的旧页只修指向被迁移页的链接
5. 用实际路由验证页面和锚点，按 docs 的受影响范围门禁检查

pageType 必须表达阅读任务，不按 components / packages 等目录猜测。入口或概念页迁入其他 section 后，核对 manifest 实际产出的 pageType 与 audience，不能仅凭侧栏位置或 difficulty 判定分类正确。固定 segment 可复用统一推导，自由专题按已有 meta.pageType 明确分类。现有 union 或推断器不支持新语义时报告需要站点任务，不在只改 skill 或单篇正文优化任务中擅自扩大为站点改造。
