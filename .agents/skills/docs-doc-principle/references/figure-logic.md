# 实现逻辑图

先读 [插图契约](figure-contract.md)。每张图先确定要解释的结论、职责边界、必要角色及角色间的关系；只画本小节所需内容。全局管线链接权威页，不在每个组件重复。

## 按关系选择图型

| 关系                | 画法                                         |
| ------------------- | -------------------------------------------- |
| 真实执行或数据先后  | 一条主流程，辅助输入从侧边进入具体阶段       |
| 信号到 owner / 结果 | 平行成对映射，文件位置放角色次行             |
| 包、层与职责依赖    | 分组与依赖边，不制造伪执行顺序               |
| 内置与自定义汇聚    | 同级入口进入 resolver，诊断从实际决策点分离  |
| 前后状态、不同模式  | 对照排列，不变量与比较尺度一致               |
| 缺省回退、优先级    | 编号候选或优先级栈，写明“仅当前项缺省时继续” |

只解释抽象关系时使用简洁无框图；需要具体 owner、输入输出、注册或诊断语境时用有框图和必要分组。两张图必须解释不同问题，不能仅换样式重复。

## 复用站点词汇

真实流程使用 `@retikz/diagram-react/flow` 的 FlowDiagram、FlowLayout、FlowEntities、FlowRelations；非流程关系、架构图使用 `@/modules/docs/components/logic-figure` 的 LogicFigure / LogicFigureRelation。先核对实际公开 API。

Flow 可用 `logicFigureGraphProps()` 注入站点 Entity definitions 与规则：

| kind                     | role                               | 用途                               |
| ------------------------ | ---------------------------------- | ---------------------------------- |
| 省略                     | 实际角色                           | 普通主链节点                       |
| docs.logic.important     | participant / activity / concept   | 重要逻辑，dodgerblue               |
| docs.logic.importantData | event / state / gateway / resource | 重要数据契约，darkorange           |
| docs.logic.secondary     | 全部                               | 相对本图主线的辅助、背景、派生内容 |
| docs.logic.algorithm     | activity                           | 算法或性能机制，darkviolet         |

Secondary 复用主题提供的无描边中性底色与弱化文字，不逐图写颜色；主链输入、校验、输出不自动算辅助。关闭、错误、成功使用 status，不用 Secondary 代替。event 仅在短标签需要表达瞬时事件时使用，避免长文字撑大圆形。

主流程关系省略 kind，采用默认灰色实线；真实次要依赖使用 relation kind `docs.logic.secondary`。LogicFigure 自动注册；Flow 实际使用该 kind 时传 `relationKinds={logicFigureRelationKinds}`。

多条必须区分的并行链路可对各自 Entity / Relation 使用同一 group，由 Graph 色板统一着色。group 不是职责容器、类别或布局分组；普通串行主链不加它。语义容器在 Flow 内用 FlowGroup，非 Flow 图用 LogicFigureFrame，外观遵循插图契约。

## Entity 粒度

- 减少 role、形状或颜色种类不等于减少 Entity。按读者要追踪的动作、判断、独立输入与关键中间结果拆节点，不以节点越少越好为目标。
- 只合并没有独立依赖、分支或观察价值的细节；需要看清来源、先后、转换或汇合的内容保留独立节点，不把它们全部挤进动作副标题。
- role 表达实际语义，不为统一矩形把数据或状态改成 activity；通过分组、对齐、默认间距和一致文字层级整理多个节点。

## 布局与文字

- 先确定主线、分支和辅助输入的区域；不同读写操作分区，平行方案逐列对齐。不要把所有机制套成同一种散点网格，也不为少量节点强加阶段容器。
- 主控制流围绕动作、条件组织；仅作说明的坐标、参数和函数名放次行，需要独立追踪的输入与结果按 Entity 粒度规则保留。
- 优化已有流程图时继续使用 Flow 的布局、分组与连线能力，不因减少 role 或改善对齐改成 Core 手工流程图；独立数据结构示意不替代原有执行流程。
- 普通 Flow 图默认横向展开：串行主线从左到右，并行分支横向排列。只有内容特别大、压缩后横向仍重叠或文字不可读时才改为纵向；不以固定节点数量决定图型。
- 角色名可搜索，内部成员准确拼写；职责、路径放次行。新节点必须代表独立角色或状态，不能只因实现里多调用一次就加一个阶段。
- 主链使用默认实线与颜色，辅助依赖虚线接到真实目标；下方输入与内部目标对齐，反馈沿外侧绕行。装饰边和无语义箭头删除。
- 分组外入口与出口贴近边界，同组节点聚集；有标签的边留足空间，无标签边收紧到清晰可辨。
- 标签写关系名或实际转换，不写整段解释。源码导览可用真实函数名加简短作用；放不下移正文，不发明简称。
- controls 仅用于比较同结构下的真实语义分支，不给每张图加任意颜色、线型编辑器。

## 连续状态实例

讲解多阶段变换或状态演进时，Flow 图之外还要就近展示同一具体对象的初始、关键中间态与最终态，用箭头标实际操作。跟踪一个代表性点或字段，使用真实计算结果；保持对象身份、颜色和尺度一致，标明固定参照。

图前说明输入，图后把变化对应回 Flow 阶段。几何快照用 Scope 与基础图元，数据快照用实际结构，不强塞进 Flow Entity。只展示理解结论必需的变化。

## 数据结构图

解释收集、存储、引用或作用域时，画出承载行为的数据结构及具体条目，不用“收集 → 处理 → 输出”文字框代替。结构采用语义抽象，不模拟未证实的内存布局；只展开本节需要的字段，其余用省略号。

### 提炼与展示

- 先核对源码中的结构类型、持有者、写入时机、读取方式与生命周期；用一组具体数据展示，不只列类型名或完整接口。
- 从外层容器逐层展开到条目与必要字段，例如数组槽位 → Map 的 key/value → value 对应的记录；引用线从真实字段出发，不把展开画成对象复制或额外执行阶段。
- 明确每处展示的是完整条目、字段摘录还是计算结果；Definition 等复杂对象只标职责或身份，不伪装成原始字符串值。

| 结构         | 画法                                                                                                       |
| ------------ | ---------------------------------------------------------------------------------------------------------- |
| Array / 队列 | 连续等规格槽位，标索引或先后；元素身份保持一致。队列标入队端与消费方向，槽位间不自动加箭头                 |
| Map          | key / value 成对行，查询箭头落到具体 key，值为复杂对象时用引用线连接记录；排布不暗示排序、哈希桶或内存地址 |
| 栈           | 层叠 frame，标栈顶与栈底；push / pop 落到栈顶，查找方向独立标注，不混同数组索引方向                        |
| 记录 / 对象  | 字段名与值对齐，引用字段连接被引用对象；区分原始输入、已解析结果与生命周期状态                             |

- 写入、查找、覆盖、出栈等操作标在所作用的槽位、条目或 frame 上；数据流、对象引用与作用域边界分别说明，虚线和淡化不能无图例地兼指未命中、删除或辅助关系。
- 用同一具体例子贯穿写入和消费，保留未变化条目的身份与位置；对比图只突出变化部分，并写出查询结果或可观察输出。
- 数据结构图以组织、嵌套、引用与读写为主；流程图以执行步骤和分支为主，通用几何与空间解释使用示意图。带操作箭头不自动成为流程图。
- 分面仅在比较不同模式或状态时可选；核心是结构、操作和结果可读，不强制多面板、矩形步骤框或固定子图数量。

### 组件与配置

- Array、List、队列、栈用 `@retikz/standard-react` 的 List；Map、记录与对象用 Map。索引仅在解释机制需要时展示；普通对象的键值表示不等同于 JavaScript Map，正文应区分。
- 嵌套数据优先通过 `data` 输入；需要单格 id、样式或连线时使用 `items` / `entries`。保持真实嵌套关系，不把对象字段平铺成字符串。
- 标题直接使用 List / Map 的 `label`，不另造标题 Node、FlexLayout 或 NamespaceTable 等薄封装。多个内容确需排列时使用局部 FlexLayout，各结构块独立定位，不强迫全图进入一个布局。
- 普通实体与处理对象使用 Node；数据容器复用现有组件，算法控制流仍用 Flow。默认 gap、distance、颜色与位置不重复填写，只保留语义与布局需要的覆盖。

### 绘制风格

- 数据单元格用 `fill` 深浅区分且无描边：Map 的键、记录的字段名用深色，值用浅色；Array / 队列槽位统一浅色。已有组件默认满足时不重复配置；使用基础图元补充结构时也遵循此规则。
- 默认中性填色；强调具体条目时，键和值采用同一强调色的深浅配对，跨图保持对象身份一致。只调整 `fillOpacity`，文字保持 `currentColor` 和完整不透明度。
- 单元格等高、列宽按内容统一，槽位与行列用细留白分隔，不另加网格描边；标题放结构外，操作说明放连线旁，不压住数据、箭头或预览工具栏。
- 优先沿用 List / Map 的直角、无描边和键深值浅默认样式；普通实体 Node 用淡色填充与小圆角区分，不为区分数据结构额外加边框。同一对象与其记录共享强调色，不为每步单独配色。
- 容器 label 使用 12px、继承文字颜色及 `opacity: 0.8`；边标签与辅助说明使用 12px gray。透明度仅作用于标签或填充，不降低整个容器与数据文字的透明度。
- 检查明暗主题下的填色层级、文字对比和细留白，不能只在亮色背景可辨。

### 连接与顺序

- 用稳定 id 连接实际对象、槽位或字段，不连接标题。能直连时优先 `horizontalTo` / `verticalTo`；需要转折再用 `|-`、`-|` 或多段正交线。
- 普通 Draw 沿用默认线色；关系文字使用 Path / Draw 的 label。先调整结构块位置与路径，再处理标签重叠，仅在默认间距不足时覆盖 distance。
- 真实操作顺序使用 `1. / 2. / 3.`，静态引用关系不强加编号；箭头表示引用或读写时应就近说明，不把对象展开误画为复制。

## 检查

逐条核对关系是否真实、回退是否误画为顺序、主线与辅助是否混淆；检查正文是否解释每个必要角色和可观察变化。视觉与测量统一按插图契约，不再维护另一套尺寸或配色清单。
