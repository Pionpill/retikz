# 单元测试编写与 Review 规范

适用于新增、修改、审查和收敛功能性单元测试；临时验证也遵循本文件的生命周期规则。运行范围与性能、压力测试授权遵循根 [AGENTS.md](../../../../AGENTS.md)

## 正式测试的准入

新增前先检索已有覆盖，明确生产入口、可观察结果和新增的独立失效模式：哪种真实功能错误发生后，这条测试会失败？已有 case 能保护同一规则时优先复用或加强，不按每次改动追加测试

正式测试保护功能语义、必要边界或已确认回归；测试数量、覆盖率、流程要求先写和运行通过均不构成长期保留理由。小任务在对话或测试名称中说明即可，不强制另建矩阵

“简单”按语义判断，不按实现行数：常量搬运、原样返回通常不单独测试；优先级、单位、坐标方向、零值、继承和事务即使只有一行，也可能需要守卫

## 收敛判定表

| 类别                 | 默认动作                                                                                | 保留边界                                                                         |
| -------------------- | --------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| 第三方声明复述       | 不逐字段测试 Zod 的类型、必填、optional、enum、strict、上下界、tuple 长度及原生错误路径 | 保留项目自定义逻辑、组合接线风险或真实回归；不为所有 schema 再建同义遍历测试     |
| 简单逻辑与常量抄写   | 不为无独立功能的赋值、透传、原样返回、枚举整表复制新增 case                             | 值参与持久化、调度、几何等行为时在实际消费处验证，不以“公开导出”自动取得测试资格 |
| 存在性或不报错 smoke | 已有实际调用和结果断言时删除重复的导出存在、方法为函数、输入能 parse 等 case            | 存在、不抛错或缺省本身是独立可观察契约时，断言其具体效果                         |
| fixture 自测         | 不测试用例自己定义的回调、算式或假实现；不以它证明产品功能                              | 让 fixture 经真实注册、解析、编译等生产入口，验证接入行为                        |
| 普通 JSON 往返       | 不为每种普通对象重复证明 JSON 或 schema 原样保留输入                                    | 保留转换、递归接线、稀疏默认意图或持久化语义可能丢失的代表性场景                 |
| 跨字段、跨层重复     | 相同失效模式在契约 owner 的最低必要层保留，包装层不重跑底层算法全套输入                 | 上层只补接入、参数转换、上下文差异、错误归属及必要闭环                           |
| 历史迁移护栏         | 删除只拒绝旧名、旧目录、旧结构或锁定已删除实现的 case                                   | 当前负向业务契约和真实缺陷的唯一回归守卫仍保留                                   |
| 实现细节与对象身份   | 不锁定私有源码、调用形式、无语义的创建次数、每次新对象或偶然文案                        | 对外不可变、变异隔离、引用身份或资源生命周期确有契约时保留行为证据               |
| 仅服务本轮流程       | 作为临时测试运行后清理，不因写过或跑绿而转正                                            | 发现独立长期契约或真实回归后，按下文条件重写为最小正式 case                      |

例如 `number().positive()` 不配套枚举零、负数、NaN、Infinity 的库行为测试；`index < period`、索引唯一性和自定义诊断路径属于项目逻辑，应有针对性反例

schema 是声明真源，不代表不会误改；普通声明不另建单测的风险由 schema review 承担。不能仅因测试在 schemas 目录就整批删除，或把一次真实修复降为“只是改了声明”而移除守卫

## 必须区分的语义

- 自定义 refine / superRefine / preprocess / transform、正则或解析器按项目逻辑测试；不因借用 Zod API 而当成第三方行为
- schema 组合只测能区分错误接线的递归、变体差异和约束遗漏；默认值与继承优先级、显式 `0` / `false` / `undefined` 的语义在真正消费的一层验证，不逐字段复测 `.default()`
- TypeScript 已保证的可赋值性、互斥 union、必填字段和封闭判别分支交给生产声明与 `tsc --noEmit`；不编写独立类型测试，也不靠强转、`expectTypeOf` 或 `@ts-expect-error` 伪造 runtime 输入，不迁移到 scratch
- 颜色、坐标或特殊输入仅在区分功能、边界或真实回归时保留；颜色透传、覆盖优先级、退化几何和失败事务不是偶然展示值
- 每个等价类选代表性成功输入、关键边界和必要错误分支；参数化不用于穷举无新增失效模式的组合。性质测试须限定输入域和运行预算并保留可复现反例，不替代具名回归或绕过测试类别授权
- 断言实际结果，优先输入、输出、错误、Scene 或 DOM 可观察行为。源码生成器产物可属于公开输出；静态结构约束由相应 lint / integrity 工具统一负责
- Snapshot 小而聚焦且逐项 review；不以自动更新快照或剩余测试全绿证明删除安全

## 临时测试生命周期

1. **创建前分流**：保护明确长期行为的 case 可直接写正式测试；仅为本轮 TDD 探索、排查、重构对照、canary 或流程验收存在的 case 默认放受影响 workspace 的 `tests/_scratch/`。流程要求先写测试，不改变其保留资格
2. **按真实环境运行**：先用 `git check-ignore <repository-relative-path>` 确认忽略命中，再用下列命令。`--file` 指定单个具体文件，不传通配符；仅人工明确要求时使用 `--keep`

   ```bash
   pnpm temp:test -- --workspace <workspace-directory> --file tests/_scratch/<case>.test.ts
   ```

   runner 在执行成功或失败后清理文件和空目录；强制终止可能跳过清理，收尾仍需检查本轮残留。不得强制跟踪 scratch，也不为一次性验证另建临时 runner 或默认进入 CI 的脚本

3. **转正前说明价值**：指出仍有效的契约或已确认缺陷、独立失效模式及既有覆盖缺口。复用或加强现有 case，必要时重写最小具名正式测试，删除探索脚手架与重复输入；发现 bug 时保留修复前失败证据，不弱化原断言
4. **收尾明确去向**：本轮 case 分别保留、合并或删除，核对 scratch 残留与暂存 diff。按本轮文件范围清理，不删除其他会话用例；`canary`、`debug`、`cross-test` 等名称仅为线索，按实际语义判断临时性

## Review 与删除证据

- 按独立 case 或断言分类，不因同文件含库级校验而连同自定义逻辑删除
- 每项删除或合并建议说明当前目的、无效或重复依据、替代 case 与最小保留断言；无替代时明确是声明 / 类型 / 静态检查承担，还是尚未覆盖的功能风险
- 库级重复与 fixture 自测不要求为删除补写等量替代测试；真实功能风险也不能靠删掉失败 case 消除
- 核对真实入口、数据来源和下游消费，不能只看标题、代码短、当前全绿或覆盖率决定去留
- 分别记录目录盘点、测试块审查与实现核对范围；未逐项核对的候选不标记为已确认可删
