# 文档审查

## 依次检查

1. **任务与结构**：开篇说明问题和结果；主线符合页型；前置知识就近给出。独立基础、专题、扩展和自定义页不漏相关属性，API/Schema/实现原理不额外套用该节。组件合页按页型词典检查固定顺序，不另加相关属性；实现原理位于 API 前，节首 Tip 明确可跳过，必要调用约束不藏在原理中。
2. **读者理解**：按首次阅读顺序找未定义或解释过晚的概念、逻辑跳跃和术语堆叠。即便术语已定义，也要判断是否把简单问题讲复杂；指出首次困难位置和准确替代表达。
3. **契约事实**：从公开入口追到声明与实际默认值、优先级、错误分支；内部机制标识符仅作源码锚点。区分源码错误、生成丢失、翻译失真与陈旧正文。
4. **示例覆盖**：默认场景能看出目标能力；代码可复制；参数变化可用 controls，结构/错误差异独立解释。代表性操作、极值与 Reset 按 controls 契约实测。
5. **图文关系**：图前说明观察点，图后解释变化；不能以抽象框图替代必要的具体实例。关系、回退、顺序与分组语义准确。
6. **维护一致性**：contents/data/i18n、双语、生成配置和引用同步；核对易过时的包、依赖、宿主与预览能力，不把旧文案当依据。
7. **链接和布局**：机械完整性脚本先检查可自动判断的部分，再核对目标语义、源码支撑和真实页面。浏览器检查中英文的遮挡、裁切、滚动与交互，不凭源码宣布视觉通过。

## 输出

先列问题：严重度 + 文件/行号或页面小节 + 问题 + 读者影响 + 建议。再说明已检查范围、实际执行的机械/页面验证与未验证项。无问题时直接说明，不凑 INFO、赞扬清单或总分。

- BLOCKING：公开契约失真、必要解释缺失导致无法使用/理解、双语缺漏、引用失效、核心 demo 不可读或交互不可达。
- WARNING：仍可理解但表达、章节衔接、层级或布局影响阅读效率。
- 风格偏好不单独升级为 BLOCKING；不为主观微调扩大获准范围。

读者评审只能指出正文与图中实际的信息缺口，不能靠源码或作者背景替文档补齐推理。原理页可依赖明确链接的前置知识，不必重写入门教程。
