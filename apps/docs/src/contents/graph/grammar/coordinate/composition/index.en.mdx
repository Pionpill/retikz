---
title: Coordinate Composition
description: composition lets one Plot express dual axes, facets, and shared tracks.
---

When a chart has one projection, `coordinate` is enough. When the same Plot needs several coordinate regions, panels, or aligned tracks, the result still uses the same `composition` model, but everyday JSX does not need a hand-written `composition` object: dual axes use `Axis id` plus `yAxisId`, facets use `<Facet>` plus `facetId`, and shared tracks use `<Scaffold>` / `<Track>` plus `trackId` / `scaffoldId`.

`composition` organizes coordinate regions; it is not a new mark type. Marks are still `PathMark`, `PointMark`, and `IntervalMark`; scales still come from fields and explicit `<Scale>` children; guides are still declared with `<Axis>`.

## Dual Axes

Dual-axis charts are the most common multi-scope case: x positions are shared, while two y-axes represent different units. The default y-axis does not need a name; extra y-axes use `Axis id`, and marks select them with `yAxisId`.

<ComponentPreview name="coordinate-composition-scopes" sourceFiles={['coordinate-composition-scopes.data.ts']} size="md" />

In this example, `temperature` uses the default y-axis, while `rainfall` is the id of an extra y-axis. The temperature line omits `yAxisId`; the rainfall line and points use `yAxisId="rainfall"` to choose the right-side axis. A mark that omits `yAxisId`, or sets `yAxisId="default"`, enters the default y scope.

| JSX | Role |
| --- | --- |
| `<Axis dimension="y">` | Declare the default y-axis; marks use it when `yAxisId` is omitted |
| `<Axis id="rainfall" dimension="y">` | Declare an extra y-axis whose `id` can be referenced by marks |
| `yAxisId` | Let a mark choose a y-axis; omitted or `default` uses the default y-axis |
| `placement={{ kind: 'side', side: 'right' }}` | Put an extra y-axis on the right; x bottom and y left can be omitted |

## Facets

A facet splits one chart into panels from data fields. The common JSX form declares one `<Facet>`, then points marks and axes at it with `facetId`; each panel receives the rows that match its row / column value.

<ComponentPreview name="coordinate-composition-facet" sourceFiles={['coordinate-composition-facet.data.ts']} size="lg" />

The chart above splits columns by `region` and rows by `channel`. Facets share coordinate-role domains by default and collapse shared axes to the outside; each grid is still declared by its `<Axis grid>`, and the default placement projects that grid into each panel's own plot area.

| JSX | Role |
| --- | --- |
| `<Facet id>` | Binding identity for this facet |
| `row` / `column` | Field used to split panels, plus optional display order |
| `facetId` | Bind a mark or axis to this facet |
| `empty` | Whether empty panels are dropped or kept |
| `scales.roles` | Choose whether x / y roles share a domain or compute it per panel |

## Shared Scaffold And Tracks

A shared scaffold uses one coordinate frame to manage several tracks. The common case is aligned small tracks: shared x, separate y bands, useful for timelines, monitoring panels, or event + load views. The common JSX form wraps several `<Track>` declarations in one `<Scaffold>`; marks choose a track with `trackId`, while axes that span the aligned scaffold choose it with `scaffoldId`.

<ComponentPreview name="coordinate-composition-tracks" sourceFiles={['coordinate-composition-tracks.data.ts']} size="md" />

Here both tracks share the `week` x position. `incidents` and `load` each occupy a y band inside the scaffold, so they align horizontally while keeping separate vertical space. The x-axis enables `grid`; shared scaffold defaults project the same x ticks into every shared track. `trackGap` opens space between bands.

| JSX | Role |
| --- | --- |
| `<Scaffold id>` | Binding identity for the shared scaffold |
| `sharedRoles` | Roles managed by the scaffold, such as shared `x` |
| `<Track id>` | Binding identity for one track |
| `tracks[].band` | Fractional interval occupied by a track on the non-shared role |
| `trackId` / `scaffoldId` | Bind a mark or axis to a track or the whole scaffold |

## layout And guidePolicy

`layout` only controls spacing inside the composition. It does not change data, scale domains, or mark semantics.

| Field | Controls |
| --- | --- |
| `panelGap` | Gap between facet panels |
| `trackGap` | Gap between shared scaffold tracks |
| `axisGap` | Outward offset between axes on the same side |
| `labelGap` | Distance from axis titles, facet labels, and track labels to the plot area |
| `padding` | Extra padding around the composition frame |

`guidePolicy` decides where axes, grids, and labels are placed in multi-region charts. When omitted, defaults are chosen by composition type: facets use outer shared axes plus local panel grids; shared scaffolds project shared-role grids into every track; plain overlay scopes keep their own axes and grids.

| Field | Values | Use it when |
| --- | --- | --- |
| `axes` | `perScope` / `outerShared` | Facets or tracks share scales and only need one outer axis |
| `gridPlacement` | `self` / `sharedRole` | Default projection target for `Axis grid`; whether a grid exists is still decided by each axis |
| `facetLabels` | `none` / `rowColumn` | Render row / column panel labels |
| `trackLabels` | `none` / `inline` | Render labels inside tracks |

## Choosing A Shape

| Situation | Recommended structure |
| --- | --- |
| One line plus one bar layer, shared x but different y units | Dual axes |
| Split by region / category into rows or columns | Facet |
| Several metrics aligned along one time axis | Shared scaffold + tracks |
| Several independent charts placed on one large canvas | Multiple `<Plot>` panels inside a parent `<Layout>`; no composition needed |
