---
title: Coordinate Composition
description: composition lets one Plot express dual axes, facets, and shared tracks.
---

When a chart has one projection, `coordinate` is enough. When the same Plot needs several coordinate regions, panels, or aligned tracks, the result still uses the same `composition` model, but everyday JSX does not need a hand-written `composition` object: dual axes use `Axis id` plus `xAxisId` / `yAxisId`, while facets and shared tracks place axes and marks inside the matching container.

`composition` organizes coordinate regions; it is not a new mark type. Marks are still `PathMark`, `PointMark`, and `IntervalMark`; scales still come from fields and explicit `<Scale>` children; guides are still declared with `<Axis>`.

## Dual Axes

Dual-axis charts are the most common multi-scope case: one side is shared, while the other side has two sets of ticks. The axis-id shortcut currently targets `cartesian2D`, the usual x / y Cartesian coordinate system.

Each dimension starts with one default axis. An `<Axis dimension="x">` or `<Axis dimension="y">` without an `id` belongs to that dimension's default axis; when a mark omits `xAxisId` / `yAxisId`, it also uses the default axis for that dimension. Only extra axes need explicit ids, then marks select them with `xAxisId` or `yAxisId`.

### Multiple Y-Axes

Multiple y-axes fit charts where x positions are shared but y units differ. In the weather example below, temperature uses the default y-axis and rainfall binds to the right-side y-axis.

<ComponentPreview name="coordinate-composition-scopes" sourceFiles={['coordinate-composition-scopes.data.ts']} size="md" />

`rainfall` is the id of the extra y-axis. The temperature line omits `yAxisId`; the rainfall line and points use `yAxisId="rainfall"` to choose the right-side axis.

| JSX | Role |
| --- | --- |
| `<Axis id="rainfall" dimension="y">` | Declare the extra rainfall y-axis |
| `yAxisId="rainfall"` | Make a mark use the rainfall axis |
| `placement={{ kind: 'side', side: 'right' }}` | Place the extra y-axis on the right |

### Multiple X-Axes

Multiple x-axes fit charts where the y metric is shared but horizontal positions have two interpretations. The example below shows elapsed release day at the bottom and calendar day at the top; both lines share the y-axis.

<ComponentPreview name="coordinate-composition-x-axis" sourceFiles={['coordinate-composition-x-axis.data.ts']} size="md" />

`calendar` is the id of the extra x-axis. The completed line uses the default x-axis; the forecast line and points use `xAxisId="calendar"` to choose the top axis.

| JSX | Role |
| --- | --- |
| `<Axis id="calendar" dimension="x">` | Declare the extra calendar-day x-axis |
| `xAxisId="calendar"` | Make a mark use the calendar-day axis |
| `placement={{ kind: 'side', side: 'top' }}` | Place the extra x-axis on top |

## Facets

A facet splits one chart into panels from data fields. The common JSX form places axes and marks inside `<Facet>`; each panel receives the rows that match its row / column value.

### Basic Column Facet

Passing only `column` creates one row of panels. This example splits the chart into three `segment` columns; by default every panel shares the x / y domains, so line heights can be compared across panels.

<ComponentPreview name="coordinate-composition-facet-basic" sourceFiles={['coordinate-composition-facet-basic.data.ts']} size="md" />

This demo has a single `<Facet column="segment">`. `Axis`, `PathMark`, and `PointMark` are written inside `<Facet>`, so they automatically enter every segment panel without a `facetId`.

### Row And Column Grid

Passing both `row` and `column` creates a two-dimensional grid. The chart below splits columns by `region` and rows by `channel`; `Axis grid` is still declared by the axis itself, and facet defaults draw that grid inside every panel.

<ComponentPreview name="coordinate-composition-facet" sourceFiles={['coordinate-composition-facet.data.ts']} size="lg" />

Here `<Facet row="channel" column="region">` defines the panel matrix. `grid` still belongs on `<Axis dimension="x">` / `<Axis dimension="y">`; the facet only projects those guides into each panel.

### Empty Panels And Independent Scales

Empty panels are dropped by default, and scale domains are shared across panels by default. The next example keeps empty panels and computes the y-axis independently inside each panel, which helps when groups differ by order of magnitude.

<ComponentPreview name="coordinate-composition-facet-independent" sourceFiles={['coordinate-composition-facet-independent.data.ts']} size="lg" />

`empty="show"` keeps panels listed by the order even when no rows match them. `scales={{ roles: { y: 'independent' } }}` computes a separate y domain per panel, while the x-axis stays shared for month alignment.

### API

`FacetValue` in the table means `string | number | boolean | null`.

| Property | Type | Default | Description |
| --- | --- | --- | --- |
| `id` | `string` | Required | Facet identity referenced by `facetId` |
| `row` | `string`<br />`{ field: string; order?: FacetValue[] }` | Omitted | Row split field |
| `column` | `string`<br />`{ field: string; order?: FacetValue[] }` | Omitted | Column split field |
| `row.order`<br />`column.order` | `FacetValue[]` | First-seen order | Panel order; unlisted values append by first sight |
| `facetId` | `string` | Omitted | Explicitly bind a mark or axis outside the container to facet panels |
| `empty` | `'drop' \| 'show'` | `'drop'` | Drop or keep empty panels |
| `scales.roles` | `Record<string, 'shared' \| 'independent'>` | Unlisted roles are `'shared'` | Whether each coordinate role shares its domain across panels |
| `layout.panelGap` | `number` | `0` | Panel gap in user units |
| `guidePolicy.axes` | `'perScope' \| 'outerShared'` | `'outerShared'` | Render axes per panel or collapse them to the outside |
| `guidePolicy.gridPlacement` | `'self' \| 'sharedRole'` | `'self'` | Default target for `Axis grid`; every facet panel receives it |

## Shared Tracks

Shared tracks use one coordinate scaffold to manage several tracks. The common case is a set of aligned small plots: one role is shared, while the other role is split into multiple bands. The common JSX form wraps several `<Track>` declarations in one `<Scaffold>`: shared axes live in `<Scaffold>`, while local axes and marks live in the matching `<Track>`.

### Cartesian Tracks

<ComponentPreview name="coordinate-composition-tracks" sourceFiles={['coordinate-composition-tracks.data.ts']} size="lg" />

Here all three tracks share the `trading day` x position. The shared x-axis is written directly in `<Scaffold>`; `trend` draws a line, `drawdown` uses baseline closure as an area, and `signal` draws a line with points.

Each track keeps its own y-axis and marks inside its own `<Track>`, so the tracks align horizontally while keeping separate vertical space. The x-axis enables `grid`; shared-track defaults project the same x ticks into every shared track.

### Polar Tracks

<ComponentPreview name="coordinate-composition-tracks-polar" sourceFiles={['coordinate-composition-tracks-polar.data.ts']} size="lg" />

Shared tracks also work under `polar2D`. Here the coordinate system interprets `x` as the angular role and `y` as the radial role. `sharedRoles={['x']}` lets several radial tracks share the same angular ticks while each track keeps its own radius band.

The JSX shape is still `<Scaffold>` containing `<Track>`: the angular axis lives at scaffold level, the `signal` and `capacity` radial lines live in inner tracks, and the outermost `sector` track uses `IntervalMark` to draw a ring of sectors. Changing the coordinate system changes how roles are interpreted, not the container binding rule.

### API

| Property | Type | Default | Description |
| --- | --- | --- | --- |
| `Scaffold.id` | `string` | Required | Scaffold identity referenced by explicit `scaffoldId` and generated track scopes |
| `Scaffold.sharedRoles` | `Array<string>` | Required | Coordinate roles managed by the scaffold, such as shared `x` |
| `Scaffold.coordinate` | `CoordinateOperation` | Inherits `<Plot coordinate>` | Coordinate system used by the scaffold |
| `Scaffold.frame` | `'shared' \| 'independent'` | `'shared'` | Whether tracks share the scaffold frame |
| `Track.id` | `string` | Required | Track identity referenced by `trackId` |
| `Track.band` | `{ role: string; start: number; end: number }` | Required | Fractional interval occupied by the track on the non-shared role; `start` / `end` are between `0` and `1` |
| `Track.order` | `number` | Declaration order | Optional ordering hint for tracks |
| `trackId` | `string` | Omitted | Explicitly place a mark or axis outside the container in one track |
| `scaffoldId` | `string` | Omitted | Explicitly bind an axis outside the container to the whole scaffold, usually for a shared axis |
| `layout.trackGap` | `number` | `0` | Gap between tracks in user units |
| `guidePolicy.axes` | `'perScope' \| 'outerShared'` | `'outerShared'` | Render axes per track or collapse them to the outside |
| `guidePolicy.gridPlacement` | `'self' \| 'sharedRole'` | `'sharedRole'` | Default target for `Axis grid`; shared tracks project it to tracks with the same role |

## Choosing A Shape

| Situation | Recommended structure |
| --- | --- |
| One line plus one bar layer, shared x but different y units | Dual axes |
| Split by region / category into rows or columns | Facet |
| Several metrics aligned along one time axis | Shared tracks |
| Several independent charts placed on one large canvas | Multiple `<Plot>` panels inside a parent `<Layout>`; no composition needed |
