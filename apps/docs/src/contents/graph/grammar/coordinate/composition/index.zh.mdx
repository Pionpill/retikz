---
title: 坐标组合
description: composition 在一张 Plot 内注册多个坐标 scope，让 overlay、facet 和 shared track 共用同一套坐标组织模型。
---

当一张图只有一个投影方式时，用 `coordinate` 就够了。需要把同一份数据放进多个坐标区域、多个面板或上下轨道时，仍然会落到同一套 `composition` 模型，但日常写法不必手写 `composition` 对象：双轴用 `Axis id` + `yAxisId`，分面用 `<Facet>` + `facetId`，共享轨道用 `<Scaffold>` / `<Track>` + `trackId` / `scaffoldId`。adapter 会把这些声明展开成 coordinate scope、facet、scaffold 和 guide placement。

`composition` 解决的是“坐标区域怎么组织”，不是新的图元类型。mark 仍然是 `PathMark`、`PointMark`、`IntervalMark`；scale 仍然由字段和显式 `<Scale>` 推断；guide 仍然用 `<Axis>` 声明。

## 多坐标 scope

scope 是 composition 的最小单元。`defaultScope` 是省略 `coordinateScope` 时使用的作用域；其它 scope 可以叠在它上面。双轴图一般不需要手写这些字段，默认 y 轴对应 `default` scope，额外 y 轴用 `Axis id` 命名，再让 mark 用 `yAxisId` 绑定对应轴即可。

<ComponentPreview name="coordinate-composition-scopes" sourceFiles={['coordinate-composition.data.ts']} size="md" />

这个例子里，`temperature` 使用默认 y 轴，`rainfall` 是额外 y 轴的 `id`。temperature 折线省略 `yAxisId`，rainfall 折线和点用 `yAxisId="rainfall"` 选择右侧轴；adapter 会生成 `default` scope，并把 `rainfall` 作为 overlay scope 叠在它上面。省略 `yAxisId` 或写 `yAxisId="default"` 的 mark 会进入默认 y scope。用户不需要手写 `__x`、`__y.default` 或 `coordinateScope`，但底层 PlotSpec 仍然是 composition。

| 字段 | 作用 |
| --- | --- |
| `Axis id` | 给 y 轴一个可被 mark 引用的绑定身份 |
| `yAxisId` | 让 mark 绑定到指定 y 轴，并展开成 `coordinateScope`；省略或写 `default` 时进入默认 y scope |
| `defaultScope` | mark / axis 未声明 `coordinateScope` 时的目标；双轴 sugar 固定生成 `default` |
| `scopes[].id` | 被 mark / guide 引用的稳定 scope id |
| `scopes[].coordinate` | 该 scope 使用的坐标系配置 |
| `placement.kind: 'overlay'` | 把当前 scope 叠到另一个 scope 的 plot area |

## 分面

facet 会按数据字段派生多个 panel scope。常规写法是声明一个 `<Facet>`，然后让 mark 和 axis 用 `facetId` 指向它；adapter 会生成基础 scope 和 facet 规则，lowering 再按 row / column 值生成面板、路由每个面板的数据，并把 mark 放进对应 panel。

<ComponentPreview name="coordinate-composition-facet" sourceFiles={['coordinate-composition.data.ts']} size="xl" />

上面的图按 `region` 拆成三列、按 `channel` 拆成两行。`scales.roles.y: 'shared'` 表示所有面板共用 y domain；`guidePolicy.axes: 'outerShared'` 让共享轴只在外侧输出一次；`Axis grid` 仍由轴自己声明，`gridPlacement: 'self'` 让这根轴的网格投放到每个面板自己的 plot area。

| 字段 | 作用 |
| --- | --- |
| `<Facet id>` | facet 身份，也会进入 provenance / locator 上下文 |
| `row` / `column` | 按哪个字段拆面板，以及可选显示顺序 |
| `facetId` | 让 mark / axis 绑定到这个 facet |
| `empty` | 空面板是丢弃还是保留 |
| `scales.roles` | 指定每个坐标 role 是 `shared` 还是 `independent` |

## 共享 scaffold 与 track

shared scaffold 用一套坐标骨架管理多个 track。常见用途是多条上下对齐的小轨道：共享 x 轴，y 方向各自占一段 band，适合时间线、监控指标、事件 + 负载这类图。常规写法是用 `<Scaffold>` 包住多个 `<Track>`，mark 用 `trackId` 选择轨道，跨轨道共享的轴用 `scaffoldId` 选择整套 scaffold。

<ComponentPreview name="coordinate-composition-tracks" sourceFiles={['coordinate-composition.data.ts']} size="md" />

这个例子里两个 track 共用 `week` 的 x 位置。`incidents` 和 `load` 各自占用 scaffold 的 y band，所以它们能上下对齐但保持自己的垂直空间。x 轴的 `grid` 由 `<Axis>` 开启，`gridPlacement: 'sharedRole'` 把同一组 x 刻度投放到共享 scaffold 的所有 track。`trackGap` 打开轨道之间的空隙，`trackLabels: 'inline'` 会给 track 输出内联标签。

| 字段 | 作用 |
| --- | --- |
| `<Scaffold id>` | scaffold 的绑定身份 |
| `sharedRoles` | 由 scaffold 统一管理的 role，例如共享 `x` |
| `<Track id>` | track 的绑定身份 |
| `tracks[].band` | 某个 track 在非共享 role 上占用的比例区间 |
| `trackId` / `scaffoldId` | 让 mark / axis 绑定到某条 track 或整个 scaffold |

## layout 与 guidePolicy

`layout` 只管 composition 内部的间距；它不改变数据、scale domain 或 mark 语义。

| 字段 | 控制 |
| --- | --- |
| `panelGap` | facet 面板之间的间距 |
| `trackGap` | shared scaffold track 之间的间距 |
| `axisGap` | 同侧多根 axis 向外错开的距离 |
| `labelGap` | axis title、facet label、track label 与绘图区的距离 |
| `padding` | composition 外框四周额外留白 |

`guidePolicy` 决定 guide 在多 scope 场景中的默认投放方式。省略时偏向保守：axis 和 grid 都留在自己的 scope。

| 字段 | 可选值 | 何时用 |
| --- | --- | --- |
| `axes` | `perScope` / `outerShared` | facet 或 track 共用 scale 时，外侧只保留一份轴 |
| `gridPlacement` | `self` / `sharedRole` | `Axis grid` 的默认投放目标；是否画网格仍由每根 `<Axis grid>` 决定 |
| `facetLabels` | `none` / `rowColumn` | 是否输出 row / column 面板标签 |
| `trackLabels` | `none` / `inline` | 是否在 track 内输出标签 |

## 怎么选择

| 场景 | 推荐结构 |
| --- | --- |
| 一条折线 + 一组柱，共享 x 但 y 单位不同 | overlay scope |
| 按地区 / 类别拆成多列或多行 | facet |
| 几个指标沿同一时间轴上下对齐 | shared scaffold + track |
| 几张图只是摆在同一个大画布里 | 父级 `<Layout>` 里放多个 `<Plot>`，不用 composition |
