---
title: 坐标组合
description: composition 让一张 Plot 同时表达双轴、分面和共享轨道这类多区域图。
---

当一张图只有一个投影方式时，用 `coordinate` 就够了。需要把同一份数据放进多个坐标区域、多个面板或上下轨道时，仍然会落到同一套 `composition` 模型，但日常写法不必手写 `composition` 对象：双轴用 `Axis id` + `yAxisId`，分面用 `<Facet>` + `facetId`，共享轨道用 `<Scaffold>` / `<Track>` + `trackId` / `scaffoldId`。

`composition` 解决的是“坐标区域怎么组织”，不是新的图元类型。mark 仍然是 `PathMark`、`PointMark`、`IntervalMark`；scale 仍然由字段和显式 `<Scale>` 推断；guide 仍然用 `<Axis>` 声明。

## 双轴

双轴图是最常见的多坐标场景：x 位置共享，两个 y 轴各自负责不同单位。默认 y 轴不需要命名；额外 y 轴用 `Axis id` 命名，mark 用 `yAxisId` 选择它。

<ComponentPreview name="coordinate-composition-scopes" sourceFiles={['coordinate-composition-scopes.data.ts']} size="md" />

这个例子里，`temperature` 使用默认 y 轴，`rainfall` 是额外 y 轴的 `id`。temperature 折线省略 `yAxisId`，rainfall 折线和点用 `yAxisId="rainfall"` 选择右侧轴；省略 `yAxisId` 或写 `yAxisId="default"` 的 mark 会进入默认 y scope。

| 写法 | 作用 |
| --- | --- |
| `<Axis dimension="y">` | 声明默认 y 轴；mark 省略 `yAxisId` 时使用它 |
| `<Axis id="rainfall" dimension="y">` | 声明一根额外 y 轴，`id` 供 mark 引用 |
| `yAxisId` | 让 mark 选择指定 y 轴；省略或写 `default` 时使用默认 y 轴 |
| `placement={{ kind: 'side', side: 'right' }}` | 把额外 y 轴放到右侧；x 轴 bottom、y 轴 left 可省略 |

## 分面

facet 会按数据字段把一张图拆成多个面板。常规写法是声明一个 `<Facet>`，然后让 mark 和 axis 用 `facetId` 指向它；每个面板会拿到自己对应的数据行。

<ComponentPreview name="coordinate-composition-facet" sourceFiles={['coordinate-composition-facet.data.ts']} size="lg" />

上面的图按 `region` 拆成三列、按 `channel` 拆成两行。facet 默认共享坐标 role 的 domain，并把共享轴收敛到外侧；`Axis grid` 仍由轴自己声明，默认投放到每个面板自己的 plot area。

| 写法 | 作用 |
| --- | --- |
| `<Facet id>` | 分面的绑定身份 |
| `row` / `column` | 按哪个字段拆面板，以及可选显示顺序 |
| `facetId` | 让 mark / axis 绑定到这个 facet |
| `empty` | 空面板是丢弃还是保留 |
| `scales.roles` | 指定 x / y 等坐标角色共享 domain，还是各面板独立计算 |

## 共享 scaffold 与 track

shared scaffold 用一套坐标骨架管理多个 track。常见用途是多条上下对齐的小轨道：共享 x 轴，y 方向各自占一段 band，适合时间线、监控指标、事件 + 负载这类图。常规写法是用 `<Scaffold>` 包住多个 `<Track>`，mark 用 `trackId` 选择轨道，跨轨道共享的轴用 `scaffoldId` 选择整套 scaffold。

<ComponentPreview name="coordinate-composition-tracks" sourceFiles={['coordinate-composition-tracks.data.ts']} size="md" />

这个例子里两个 track 共用 `week` 的 x 位置。`incidents` 和 `load` 各自占用 scaffold 的 y band，所以它们能上下对齐但保持自己的垂直空间。x 轴的 `grid` 由 `<Axis>` 开启；shared scaffold 默认把同一组 x 刻度投放到所有共享 track。`trackGap` 打开轨道之间的空隙。

| 写法 | 作用 |
| --- | --- |
| `<Scaffold id>` | scaffold 的绑定身份 |
| `sharedRoles` | 由 scaffold 统一管理的 role，例如共享 `x` |
| `<Track id>` | track 的绑定身份 |
| `tracks[].band` | 某个 track 在非共享 role 上占用的比例区间 |
| `trackId` / `scaffoldId` | 让 mark / axis 绑定到某条 track 或整个 scaffold |

## layout 与 guidePolicy

`layout` 只管 composition 内部的间距；它不改变数据、scale domain 或 mark 语义。

| 字段 | 控制 |
| --- | --- |
| `panelGap` | facet 面板之间的间距 |
| `trackGap` | shared scaffold track 之间的间距 |
| `axisGap` | 同侧多根 axis 向外错开的距离 |
| `labelGap` | axis title、facet label、track label 与绘图区的距离 |
| `padding` | composition 外框四周额外留白 |

`guidePolicy` 决定轴、网格和标签在多区域图中的投放方式。省略时会按 composition 类型选择常用默认：facet 默认外侧共享轴 + 面板内网格；shared scaffold 默认把共享 role 的网格投放到所有 track；普通 overlay scope 保持各自轴和网格。

| 字段 | 可选值 | 何时用 |
| --- | --- | --- |
| `axes` | `perScope` / `outerShared` | facet 或 track 共用 scale 时，外侧只保留一份轴 |
| `gridPlacement` | `self` / `sharedRole` | `Axis grid` 的默认投放目标；是否画网格仍由每根 `<Axis grid>` 决定 |
| `facetLabels` | `none` / `rowColumn` | 是否输出 row / column 面板标签 |
| `trackLabels` | `none` / `inline` | 是否在 track 内输出标签 |

## 怎么选择

| 场景 | 推荐结构 |
| --- | --- |
| 一条折线 + 一组柱，共享 x 但 y 单位不同 | 双轴 |
| 按地区 / 类别拆成多列或多行 | 分面 |
| 几个指标沿同一时间轴上下对齐 | 共享 scaffold + track |
| 几张图只是摆在同一个大画布里 | 父级 `<Layout>` 里放多个 `<Plot>`，不用 composition |
