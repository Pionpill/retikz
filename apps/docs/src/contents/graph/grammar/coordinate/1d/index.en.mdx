Sometimes data has only one positional dimension: a list of samples, event times within a day, or a distribution along one axis. A 2D chart wastes one axis; a 1D coordinate binds one position channel and collapses the other screen dimension to a baseline or wraps it into a circle.

## Two Forms

| coordinate | Shape | Binding | Typical use |
| --- | --- | --- | --- |
| `"cartesian1D"` | Line | binds `x` only | rug ticks, timeline, 1D strip |
| `"polar1D"` | Circle | binds `x` only (as the angle) | 24-hour clock, weekday wheel, cyclic data |

1D coordinates are scale-agnostic: like a 2D axis they accept linear / log / time. Below, left is a `cartesian1D` rug, and right is `polar1D` wrapping a day of event times into a circle.

## Options

`cartesian1D` can use the object form to control orientation:

```tsx
<Plot coordinate={{ type: 'cartesian1D', orientation: 'horizontal' }}>
```

`polar1D` can control the circle radius fraction and angular range:

```tsx
<Plot coordinate={{ type: 'polar1D', radius: 0.8, startAngle: 180, endAngle: 360 }}>
```

| Coordinate | Field | Description |
| --- | --- | --- |
| `cartesian1D` | `orientation` | `'horizontal'` or `'vertical'`, choosing how the 1D axis is placed |
| `polar1D` | `radius` | Circle radius as a fraction of the plot radius |
| `polar1D` | `startAngle` / `endAngle` | Angular range in degrees |

## Limits

This round, 1D coordinates support `<PointMark>` only, for rug ticks, timeline points, or circular event points. Bars, sectors, areas, and other marks that need a 2D cell or region have no 1D geometry and fail loudly instead of drawing a misleading chart.
