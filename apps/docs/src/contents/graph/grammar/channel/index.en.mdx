A channel answers "where does this attribute read its value from?" The data layer first normalizes external rows into canonical rows, then channels pass fields or constants to coordinates, mark lowering, core scopes, core nodes, core paths, and legends. `x` / `y` / `color` / `size` / `text` share one binding model, while later stages consume them differently.

## Mental Model

A channel is not the final rendered property. It is a binding: first exposed as a short name in the DSL, then stored as a field or constant in PlotSpec, then consumed by one part of the grammar of graphics.

<ComponentPreview name="channel-flow" size="md" hideCode />

| Layer      | Surface                                                          | Role                                                                       |
| ---------- | ---------------------------------------------------------------- | -------------------------------------------------------------------------- |
| React DSL  | Props such as `<PointMark x="gdp" color="region" />`             | Gives users short names for the fields a mark binds                        |
| PlotSpec   | `encoding.x = { field: 'gdp' }` or `encoding.channels.intensity` | Stores JSON-safe field / constant bindings                                 |
| Definition | `ChannelDefinitionKind.Position / Mark / Scope / Node / Path`    | Declares who consumes the channel, how values resolve, and where they land |

From a user-facing view, a channel supported by a mark is usually a prop on that mark component. Common built-in channels get named props; custom channels start in `encoding.channels.<name>` and receive runtime behavior through `channelDefinitions`.

## Who Consumes Channels

In Plot's GoG layer, marks are not the only channel consumers. Several stages read channels, but each one asks a different question:

| Consumer   | Reads                                                                  | Purpose                                                                          |
| ---------- | ---------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| data model | all field-bound channels                                               | Infers field types for scales and diagnostics                                    |
| transform  | fields such as `x` / `y` / `series` / `order`                          | stack, dodge, sort, and bin steps need grouping, ordering, or value sources      |
| scale      | fields bound to position / color / size / opacity and similar channels | Collects domains and maps raw values into coordinates, colors, radii, or opacity |
| coordinate | position channels: `x` / `y` / `z` / custom roles                      | Decides how positional components project onto the canvas                        |
| mark       | resolved mark / scope / node / path channels                           | Chooses the graphic shape and applies style to the right core surface            |
| guide      | channel descriptors                                                    | Builds axes / legends that explain a channel's scale                             |

So a channel does three jobs: it names which value to read, gives scale / coordinate / guide a shared field source, and lets marks apply the resolved value to the correct visual surface.

## Responsibilities

| Topic             | Responsibility                                                                                                                                                       | Reach for it when                                                        |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| Channel binding   | How fields / constants appear in mark props or `encoding`                                                                                                            | You want to confirm what `x="date"`, `color="region"`, or `y={80}` means |
| Built-in channels | Who consumes position / mark / scope / node / path channels                                                                                                          | You want to decide where `color`, `size`, or `strokeWidth` belongs       |
| Custom channels   | Declare runtime definitions with `defineScopeChannel` / `defineNodeChannel` / `definePathChannel` / `defineChannel`, then register them through `channelDefinitions` | Your spec needs `encoding.channels.<name>`                               |

Position channels are reinterpreted by coordinates: the same `x` / `y` means horizontal / vertical under `cartesian2D`, but angle / radius under `polar2D`. `color` is a mark channel because different marks land it on node fill, text color, path stroke, or path fill. `size` and `shape` are node channels; shared styles such as `opacity` and `strokeWidth` land on scope / node / path according to the mark's consumption surface.
