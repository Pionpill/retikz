title: Extending
description: Extend the graphics grammar by registering long-tail field parsing, channels, transforms, scales, coordinates, and marks into the same plot lowering flow.

This group covers how to **extend** Plot's graphics grammar. The built-ins cover common charts; when you need a new field format, channel, statistical step, scale, coordinate projection, or mark, runtime-injected definitions reuse the same parsing, validation, and lowering flow as built-in capabilities.

> Extension definitions are host capabilities and do not enter Plot IR directly. The IR stores only serializable types, names, field bindings, and JSON config; functions, projections, evaluators, and lowerers are injected through `<Plot>` props or vanilla options.

## What each part covers

| Topic              | Extends                                                   | Reach for it when                                                                                     |
| ------------------ | --------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| Custom Data        | Field formats and field parsing functions                 | Your source has values like `1.2万`, percentages, nested fields, or one-off parsing logic             |
| Custom Channels    | Position / mark / scope / node / path channel definitions | You need a new `encoding.channels.<name>` that lands data on a custom visual surface                  |
| Custom Transforms  | Transform, reducer, and selector definitions              | You need special statistics, row derivation, representative row selection, or cross-source processing |
| Custom Marks       | Mark definitions                                          | You need a new geometry layer that projects rows through the frame and assembles core IR              |
| Custom Scales      | Scale definitions and named color schemes                 | You need brand ramps, domain mappings, or value mappings beyond the built-in scales                   |
| Custom Coordinates | Coordinate definitions                                    | You need new position roles, projections, custom axes, or special spaces                              |

## Three Boundaries

- **Data stays separate from IR**: real rows, parser functions, and evaluators do not enter IR; PlotSpec only records field contracts and serializable config.
- **Built-ins and custom definitions share one mechanism**: custom definitions do not use private patch points; they register, parse, validate, and consume through the same path as built-ins.
- **Lowering still returns to core**: custom coordinates and marks can decide how geometry is generated, but the final output should still be core Node / Path / Coordinate / Scope primitives.
