Data is the primary member of the graphics grammar: what marks draw, how scales map, and how coordinates interpret all ultimately resolve against rows of data. The data layer aligns external datasets with the **field model** Plot can consume — declaring field names and types, parsing and normalizing real values, then handing the result to channels.

Data itself **does not enter IR**. The grammar only describes which fields to read, what types they have, and how to parse them; the actual rows arrive only at compile time (lowering), and only field contracts like `model` and `format` persist with the PlotSpec. That keeps one grammar reusable across data sources, and easy to serialize and AI-generate.

## Pipeline

During compilation, Plot first collects the fields actually referenced by the current configuration, then normalizes external rows into canonical rows (the standardized row after field mapping, parsing, and type coercion, written back under logical field names). Transforms, scales, marks, and locators all read that normalized result instead of repeatedly reading raw input rows.

| Step | What Happens | Main Configuration |
| --- | --- | --- |
| Data reference | Select the external dataset for this plot; rows themselves stay out of IR | `<Plot data>` / `data.reference` |
| Field contract | Decide logical field names, types, category order, and declarative formats; otherwise infer from samples | `model` |
| Source alignment | Map logical fields to physical data paths, including renamed fields and nested paths | `fieldMap` / `fieldMaps` |
| Parse and normalize | Parse values with `resolveField`, `format`, or built-in coercion, then write canonical values back under logical names | `resolveField` / `format` / field type |
| Validation | Sample-check or fully check participating fields, and decide whether invalid values skip or throw | `validateData` / `invalid` |
| Channel consumption | Mark channels such as `x`, `y`, `color`, `size`, and `text` read canonical values | mark props / `encoding` |

`model` and `format` are persisted with the PlotSpec. `fieldMap` is a serializable lowering option injected by dataset reference. Function options such as `resolveField` participate only at runtime and do not enter IR. See [Custom Data](/graph/grammar/extend/data) when you need custom field formats or field parsing.

## Channel Consumption

The data layer only turns external rows into canonical rows. How a field or constant enters `x` / `y` / `color` / `size` / `text` lives in the separate [Channels](/graph/grammar/channel) group.
