一张图有两类输入：**配置**（画什么——mark / 坐标系 / 比例尺）和**数据**（画哪些值）。retikz 把两者分开：数据**不进**图的配置（IR），而是在编译时单独传入。这让同一份配置可以复用到不同数据上。

<ComponentAlert title="为什么数据不进 IR？" description="数据通常比图表配置大得多；把每行数据塞进 IR 会让 JSON 与持久化内容迅速膨胀，难以 diff、复用和维护。配置与数据也天然解耦：IR 只描述图怎么画，数据在编译时按 model 接入；只要字段契约能对应，同一份配置就可以切换到另一份数据源。" />

最简单的用法：把数据行数组交给 `<Plot data>`，mark 用字段名引用列。

```tsx
<Plot data={rows}>
  <PathMark x="month" y="revenue" order="month" />
</Plot>
```

字段名是**路径**，所以嵌套数据（如 MongoDB 文档 / 接口返回的 JSON）也能直接用：`x="user.address.city"` 会逐级取到叶子值。叶子必须是标量（字符串 / 数字 / 布尔 / 时间），不能是对象或数组。

字段解析会先查整段字段名是否是行上的直接 key，再按 `.` 下钻。因此 `user.age` 既可以指嵌套路径，也可以作为规范化后的逻辑字段名存在。编译准备阶段会把字段解析成 canonical 值（规范化值：解析、归一后写回逻辑字段名的标准值）并写回逻辑字段名，后续 transform、scale、mark 都读取这份结果。

## 声明字段类型

字段类型通过 `<Plot model>` 声明。`model` 是字段契约：`month` 是时间还是普通字符串、`revenue` 是连续数值还是分类，都会影响比例尺选择、坐标轴格式、图例派生和数据校验。未声明 `model` 时，retikz 会按数据样本**自动推断字段类型**。

字段类型与默认推断：

| 类型 | 含义 | 例子 | 默认推断与显式声明场景 |
| --- | --- | --- | --- |
| `continuous` | 连续可度量数值 | 销量、价格、温度 | 默认：样本值是有限 number 或 bigint<br />显式：数字串、数值枚举、编号、状态码要改成连续或分类 |
| `temporal` | 日期 / 时间 | 日期、时间戳 | 默认：`Date` 或无歧义 ISO 日期 / 时间字符串<br />显式：非默认日期格式、无时区时间 |
| `categorical` | 离散类别 | 国家、颜色名、评级 | 默认：其余字符串、布尔值、混合类型或无法判断字段<br />显式：需要固定分类顺序或控制轴与图例顺序 |

想覆盖默认推断、解析非默认格式，或让配置脱离数据也能自描述时，就自定义 `model`。每个字段声明可以包含这些配置：

| 字段 | 作用 |
| --- | --- |
| `name` | 逻辑字段名，也是 mark / transform 引用的名字 |
| `type` | 测量类型；省略时从数据推断 |
| `format` | 声明式解析格式，如 `slashDate` / `percent`；详见[数据处理](/graph/grammar/data/processing) |
| `order` | 分类字段的类别顺序；只对 `categorical` 有效 |

<ComponentPreview name="data-model-custom" sourceFiles={['data-model-custom.data.ts']} />

**声明 model = 严格模式**：mark / transform 引用的每个数据字段都必须在 model 里列出，拼错字段名会**立刻报错**，而不是画出一张空图。这里的引用不只包括 `x` / `y` / `z`，也包括 `color`、`series`、mark 的 `order`、点图的 `size` / `opacity` / `shape`，以及 transform 输入字段。model 中字段名不能重复，重复声明同样会报错。

不声明 `model` 时，字段类型走上面的默认推断，适合快速试画。

**`type` 可选——部分声明**：字段类型可省略，只写 `{ name }`。这样该字段仍然进入严格模式，也保留可移植的字段契约；只有类型留给数据推断。适合「大部分字段一目了然、只有少数要点名」的场景：数值枚举写 `type`，非默认日期 / 百分比写 `format`，其余留空。

```tsx
<Plot data={sales} model={[
  { name: 'createdAt',  format: 'slashDate' }, // '2024/01/01' → temporal
  { name: 'statusCode', type: 'categorical' }, // 数值枚举，点名为分类
  { name: 'revenue' },                         // 仅 name → 推断 continuous
]}>
  {/* … */}
</Plot>
```

省略 `type` 的字段要到 lowering 时看数据才能定类型；写了 `format` 的字段由格式蕴含类型，例如 `format: 'percent'` 会把字段当作 `continuous`。如果要让 spec 不看数据也完全自描述（LLM 友好 / 完全可移植），就把 `type` 或 `format` 填清楚。

<ComponentAlert title="推断是尽力而为，model 才是契约" description="不声明 model（或字段省略 type / format）时类型靠抽样猜测：时间只认无歧义的 ISO 格式（YYYY-MM-DD、带时区的 ISO datetime，含空格分隔的 SQL 时间戳如 '2024-01-01 12:00:00Z'），'2024/01/01'、无时区时间不会被当成时间；裸数字串也不会被自动当成 continuous。bigint 会推断为 continuous，但只有安全整数能归一化。要精确、要校验、要让 LLM 不看数据就懂字段，就声明 model；非默认存储格式再加 format 或 resolveField。" />

## 类型驱动的比例尺

声明了字段类型后，位置通道（x / y，以及 ternary 的 x / y / z）**不必再手写比例尺**：retikz 按类型自动选，`continuous`→线性、`temporal`→时间轴、`categorical`→分类带。颜色通道同样受字段类型影响：连续 / 时间字段派生连续色阶，分类字段派生离散颜色。详细映射与覆盖规则见[比例尺](/graph/grammar/scale)。

## 分类顺序

`categorical` 字段默认按**数据出现顺序**排类别，轴和图例都会跟着这个顺序。想控制顺序——比如尺码该按 `S → M → L → XL`，而不是数据里碰巧出现的次序——给字段一个 `order`：

下面两张图使用同一份尺码数据：左图按数据出现序显示，右图通过 `order` 固定为业务顺序 `S → M → L → XL`。

<ComponentPreview name="data-model-order" sourceFiles={['data-model-order.data.ts']} />

这里的 `order` 排的是**分类域**：轴刻度、图例和分类颜色会按它走；它不会重排数据行，也不会改变折线连接顺序。要重排行，用[行级变换里的排序](/graph/grammar/transform/row#排序-sort)。

| `order` | 效果 |
| --- | --- |
| 不写 / `'data'` | 按数据出现序（默认） |
| `'ascending'` / `'descending'` | 对类别排序：全数值按数值比，否则按字符串 |
| `Array`（如 `['S','M','L']`） | 以数组为顺序；数据里有、数组没有的类别追加到末尾 |

规则：

- **挂在字段上，位置与颜色同序**：同一字段既作 x 轴（band）又作颜色（ordinal）时，两处类别顺序一致。
- **只对 categorical 有效**：给 `continuous` / `temporal` 字段写 `order` 会**报错**（顺序对连续值 / 时间没有意义）。
- **显式比例尺 domain 优先**：若比例尺自己写了 `domain`，以它为准，`order` 被忽略。
- 写了**非默认** `order`（排序或显式数组）就表示「这个分类有序」——retikz 三类字段里没有「有序类别」专门类型，有序性靠这个参数表达。

## 技术原理

`model` 只保存字段契约、不保存数据行。lowering 前，Plot 把配置里实际引用的字段**收集、校验、定类型**，整理成一份字段元信息，供比例尺、坐标轴、图例和校验共用。

<ComponentPreview name="data-model-pipeline" size="sm" hideCode />

确定类型的优先级是「显式 `type` > `format` 蕴含 > 数据推断」，`categorical` 的 `order` 一并存进元信息。真实数据仍在编译时传入、不写进 IR——这也是同一份配置能换数据源复用的基础。

### 自动推断字段类型

字段既没写 `type` 也没写 `format` 时，retikz 按数据样本推断，分两步。

**第一步，逐值判类**：扫描该字段的样本值，每个值先单独定一个类型。

| 样本值 | 判为 |
| --- | --- |
| `Date` 实例 | `temporal` |
| ISO 日期 / 时间字符串 | `temporal` |
| 有限 `number`、`bigint` | `continuous` |
| 其它字符串、布尔值 | `categorical` |
| `null` / `undefined`、`NaN` / `Infinity`、对象 / 数组 | 跳过，不计入样本 |

ISO 只认无歧义格式：`YYYY-MM-DD`，以及带时区的日期时间（`T` 或空格分隔、且必须带 `Z` 或 `±HH:MM`，如 `2024-01-01 12:00:00Z`）。`2024/01/01`、无时区时间、裸数字串都不算。

**第二步，整字段归类**：最多扫描前 1000 行、取前 100 个有效样本，再按样本汇总定字段类型。

- 样本**全部**是 temporal → 字段为 `temporal`
- 样本**全部**是 continuous → 字段为 `continuous`
- 否则（类型混合、全是 categorical、或没有有效样本）→ `categorical`

也就是说：只要有一个值不是时间 / 数值，整个字段就退回 `categorical`；空字段或全是空值的字段也默认 `categorical`。声明 `model` 的字段优先用 `type`，其次由 `format` 蕴含类型，最后才轮到这套推断。

### 类型派生 scale

字段类型确定后，**省略 scale 配置**的通道按类型派生默认比例尺。

**位置通道**（x / y / z，坐标系没给该通道显式 scale 时）：

| 字段类型 | 派生 scale |
| --- | --- |
| `continuous` | `linear` |
| `temporal` | `time` |
| `categorical` | `band` |
| 无字段绑定（如全常量通道） | `linear`（兜底） |

同一位置通道绑定的字段类型必须一致；省略 scale 又混用了多种类型会报错，提示显式声明 scale。若字段带非默认 `order` 且派生出 `band` / `point`，分类域按 `order` 排。

**颜色通道**：分类字段缺省时合成 `ordinal`（离散、一类一色）；连续 / 时间字段不自动派生，须显式引用 `sequential` / `diverging` / `quantize` / `threshold` / `quantile` 色阶，且只用于按 datum 取色的图元（散点 / 柱 / 扇形），line / area 会报错。完整颜色派生与配色见[比例尺](/graph/grammar/scale)。
