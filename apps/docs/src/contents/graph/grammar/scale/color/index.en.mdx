title: Color scales
description: Color scales map a data value to a color — one color per category (ordinal), a continuous band for continuous values (sequential / diverging), or binned coloring (quantize / threshold / quantile).
---

Color scales map a data value to a color, consumed by the `color` channel. By input field there are three routes: a categorical field takes one color per category (`ordinal`), a continuous / temporal field maps to a continuous band (`sequential` / `diverging`), or a continuous quantity is cut into a few discrete bins, one color each (`quantize` / `threshold` / `quantile`). Explaining a color scale to the reader is the job of the [legend](/graph/grammar/guide/legend).

## ordinal: discrete coloring

Bind `color` to a categorical field and `<Plot>` derives `ordinal` — one discrete color per category. It is also how multi-series coloring works: without an explicit series, a categorical color field implicitly splits the data into multiple series.

| Type      | For               | Output                                                               |
| --------- | ----------------- | -------------------------------------------------------------------- |
| `ordinal` | Categorical field | One discrete color per category (multi-series, categorical coloring) |

ordinal is **discrete** coloring — one color per category, no gradient between them. Continuous / temporal fields want a continuous band, so use `sequential` below — don't put it on a categorical field.

## Continuous coloring: sequential / diverging

Bind `color` to a continuous numeric (or temporal) field and `<Plot>` derives `sequential` (viridis by default) — color along one gradient.

| Type         | For                                 | Output                                                                                   |
| ------------ | ----------------------------------- | ---------------------------------------------------------------------------------------- |
| `sequential` | Continuous / temporal field         | A one-directional band: low→high along one gradient (the workhorse for continuous color) |
| `diverging`  | Quantity with a meaningful midpoint | Two-sided hues, pale center: profit/loss, deviation from mean                            |

Sequential and diverging color comes from a **named scheme** — a preset set of color band names that is serializable and AI-generatable. Sequential schemes include `viridis` (default), `blues`, `greens`, `magma`; diverging schemes include `rdbu` (default), `brbg`, `spectral`. Use `range` to override a scheme with custom endpoint colors.

Continuous color encoding works only on per-datum marks (point / bar / sector); a line or area colors the whole path at once, so its color is not constant along the path and binding a continuous `color` errors.

## Discretization / binning

A sequential scale is a **continuous** band (smooth gradient). But many cases want a continuous quantity cut into **a few discrete bins, one color each** — graded maps, threshold alerts, skew-resistant binning. These three needs map to three discretization scales, differing only in **how the bins are cut**:

| Type        | Cut by                                             | For                                                                   |
| ----------- | -------------------------------------------------- | --------------------------------------------------------------------- |
| `quantize`  | domain split into `count` equal-width bins         | choropleth / evenly-distributed continuous values                     |
| `threshold` | user-given breakpoints (`breakpoints`)             | business thresholds / alerts (`<60` red, `60–80` yellow, `≥80` green) |
| `quantile`  | data quantiles, roughly equal sample count per bin | skewed data / outlier resistance                                      |

Each bin's color reuses the named schemes above — N discrete colors are sampled at evenly spaced points along one continuous band (e.g. `scheme: 'blues'` sampled into 5 bins); or give a `range` array to override the scheme, where the array length is the bin count.

A few constraints to keep in mind:

- **threshold breakpoints must be strictly ascending**; bin count = breakpoints + 1, so a `range` must have length `breakpoints.length + 1` (e.g. `[60, 80]` pairs with 3 colors).
- **`count` defaults to 5** for quantize / quantile; giving only a `range` (omitting `count`) makes the bin count the range length; giving both `count` and `range` with mismatched lengths errors.
- **quantile reads no explicit numeric domain** — the bin boundaries come purely from the data, so a `domain`, if written, is silently ignored (no error).
- Like continuous color, discretized color works **only on per-datum marks** (point / bar / sector); a line or area colors the whole path at once, so binding a discretization color errors.
