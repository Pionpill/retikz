---
title: Statistic Operations
description: Reducers and selectors are the shared statistical primitives behind transforms: they compute statistic values, choose representative rows, and power extensible structures such as parameterized quantile bands.
---

Statistic operations are not a new pipeline stage. They live inside existing transforms: reducers compute statistic values, while selectors choose representative rows. That lets `summarize`, `annotate`, `bin`, `select`, and `relate` reuse one statistical layer instead of baking special fields into each chart shape.

| Operation | Returns | Reused by | Good for |
| --- | --- | --- | --- |
| reducer | Field fragment | `bin` / `summarize` / `annotate` | Counts, means, quantile bands, risk scores |
| selector | Source rows | `select` / `annotate` / `relate` | Extremes, top-N, outliers, relation endpoints |

## Reducers

A reducer receives a group of rows and returns the fields to write onto a summary row or annotation row. It answers “what statistic does this group have?” without deciding whether the outer transform preserves rows or emits new rows.

| op | Input | Output | Notes |
| --- | --- | --- | --- |
| `count` | Row group | `as` | Number of rows |
| `sum` / `mean` | `field` | `as` | Sum or average |
| `median` | `field` | `as` | Median value |
| `min` / `max` | `field` | `as` | Finite numeric extrema |
| `extent` | `field` | `as` | `[min, max]` |
| `quantile` | `field` / `p` | `as` | One quantile point |
| `quantile-band` | `field` / `lowerP` / `upperP` | `outputs` | Parameterized quantile interval |

The same reducer can appear in several transforms. In `summarize.metrics`, it collapses each group into one row. In `annotate.metrics`, it broadcasts the statistic back to every row in the group. In `bin.metrics`, it reduces each bin independently.

## Selectors

A selector receives a group of rows and returns selected source rows plus an optional rank. Use it when the output still needs original ids, labels, or anchor fields, because the result row is copied from source data rather than synthesized as a statistic object.

| op | Input | Output | Notes |
| --- | --- | --- | --- |
| `min` / `max` | `by` | Source row | Row with smallest or largest numeric value |
| `first` / `last` | `orderBy?` | Source row | First or last row in current or sorted order |
| `top` / `bottom` | `by` / `n` | Source rows | Top or bottom N rows |
| `nth` | `orderBy` / `index` | Source row | Zero-based row after ordering |
| `outside-quantile-band` | `field` / `lowerP` / `upperP` | Source rows | Rows outside a quantile interval |

`select` emits the selected rows directly. `annotate.selectors` broadcasts representative values back onto detail rows. `relate` runs source and target selectors, then projects endpoint fields into relation rows.

## Quantile Bands

`quantile-band` uses `lowerP` and `upperP` to define any quantile interval; it is not fixed to `q1` / `q3`. `outputs` explicitly names every derived field, so the same reducer can express box plots, central 80% bands, outlier fences, business bands, or other summaries.

```tsx
<Transform
  kind="summarize"
  groupBy={['group']}
  metrics={[
    {
      op: 'quantile-band',
      field: 'value',
      lowerP: 0.1,
      upperP: 0.9,
      outputs: {
        lower: 'p10',
        upper: 'p90',
        points: [{ p: 0.5, as: 'p50' }],
        spread: 'p80Spread',
      },
    },
  ]}
/>
```

`whisker` is an optional strategy, not the interval itself. `{ kind: 'minMax' }` emits finite min/max values. `{ kind: 'spread', factor: 1.5 }` derives fences from `(upper - lower) * factor`, then emits the whiskers inside those fences.

| outputs field | Role |
| --- | --- |
| `lower` / `upper` | Required interval boundaries |
| `points` | Optional extra quantile points, such as median or p95 |
| `spread` | Optional `upper - lower` |
| `lowerFence` / `upperFence` | Optional fences from spread whiskers |
| `whiskerMin` / `whiskerMax` | Optional min/max or in-fence whiskers |
| `min` / `max` / `count` | Optional finite extrema and count |

## Outside Selection

`outside-quantile-band` is a selector, so it emits source rows. `boundary: { kind: 'band' }` selects rows below `lowerP` or above `upperP`; `boundary: { kind: 'spread', factor }` first derives fences from the interval spread, then selects rows outside those fences.

```tsx
<Transform
  kind="select"
  groupBy={['group']}
  selector={{
    op: 'outside-quantile-band',
    field: 'value',
    lowerP: 0.25,
    upperP: 0.75,
    boundary: { kind: 'spread', factor: 1.5 },
  }}
  rankAs="outlierRank"
/>
```

For drawing outlier points, prefer the selector: selected rows keep their original coordinates, labels, and datum provenance. For drawing a statistical band, prefer the `quantile-band` reducer: it emits group-level interval fields.

## Extensions

When adding a new statistic value, prefer `defineStatisticsReducer`. When adding a new representative-row rule, prefer `defineRowSelector`. Register a full `defineTransform` only when the input/output row shape does not fit an existing transform.

Definitions do not enter JSON IR. The IR only stores `{ op, ...config }`; runtime definitions are injected through `<Plot statisticsReducerDefinitions={...}>` or `<Plot rowSelectorDefinitions={...}>`.

| definition | Declares | In IR |
| --- | --- | --- |
| `schema` | Validates `{ op, ...config }` and extracts the registry key | No |
| `inputFields` | Source fields read by strict model validation | No |
| `outputFields` | Derived fields excluded from strict model validation | No |
| `reduce` / `select` | Runtime calculation | No |

See [Custom Transforms](/graph/grammar/transform/custom) for extension examples.
