`transform` 是图形语法的统计层：在数据整理成 canonical 行（规范化行）之后、比例尺和图元之前，把数据重写成图元更容易消费的形态。它不关心最后画成柱、线还是点，只负责改写行。

变换在管线里上接[数据层](/graph/grammar/data)产出的 canonical 行，下接 scale 推断、mark lowering 和 locator。多个 `<Transform>` 按声明顺序折叠成一条管线：前一个变换的输出行就是后一个变换的输入行。

## 职责一览

| 分类       | 成员                                                  | 行数       | 底层能力                               | 适合场景                          |
| ---------- | ----------------------------------------------------- | ---------- | -------------------------------------- | --------------------------------- |
| 保行重写   | `sort` / `derive-interval` / `jitter`                 | N → N      | row rewrite                            | 排序、单行区间、确定性抖点        |
| 保行标注   | `stack` / `normalize` / `annotate`                    | N → N      | reducer / row context                  | 堆叠区间、占比、组均值回填        |
| 规约与选择 | `bin` / `summarize` / `select` / `density` / `smooth` | N → M/K    | reducer / selector / sampled transform | 直方图、箱线图、密度面积、趋势线  |
| 行配对     | `relate`                                              | N → P      | selector / projection                  | 从 source / target 行生成关系字段 |
| 扩展能力   | custom transform / reducer / selector                 | 取决于定义 | definition registry                    | 自定义数据处理或统计子算子        |

这张表按“输出行长什么样”分组。`summarize` 和 `annotate` 都用 reducer，但前者把多行压成统计行，后者把统计值回填给原行；`select` 和 `relate` 都用 selector，但前者输出代表原始行，后者输出 source/target 配对行。

## 声明方式

用 `<Transform kind="...">` 声明 plot 级变换，`kind` 判别类型，其它 props 对应该变换字段。多个 `<Transform>` 按声明顺序折叠成管线：

```tsx
<Plot data={rows} model={model}>
  <Transform kind="summarize" groupBy={['region']} metrics={[{ op: 'sum', field: 'revenue', as: 'total' }]} />
  <IntervalMark x="region" y="total" />
</Plot>
```

同样的 transform 数组也可以写到任意 mark 上，让这一层图元拿到自己的局部数据视图：

```tsx
<Plot data={rows} model={model}>
  <PointMark x="region" y="raw" />
  <IntervalMark
    x="region"
    y="total"
    transform={[{ kind: 'summarize', groupBy: ['region'], metrics: [{ op: 'sum', field: 'raw', as: 'total' }] }]}
  />
</Plot>
```

变换产生的字段是派生字段，例如 `binStart` / `binEnd` / `binCount`、`total`、`sourceId` / `targetId`、`y0` / `y1`。它们由 transform 生成，不需要写进 `model`；被 transform 消费的输入字段仍然要走 model 和数据校验。

程序化构造时，也可以用 `<Plot dataTransforms={[...]}>` 直传 transform 数组。它和 `<Transform>` 子组件共用同一管线；直传数组排在子组件之前。

> 用 `dataTransforms` 而不是 `transforms`，是为了和 core 容器的几何 `transforms`（平移 / 旋转）区分。

React DSL 里的高级快捷写法也会落成普通 transform。例如 `IntervalMark` 的 `angle` / `stack` / `percent` 会生成 `stack` 或 `normalize + stack`；自定义创作层语法可以通过 `markTransformShortcuts` 生成同样的 transform operation。快捷入口不引入新的数据语义，只是少写样板。

## 技术原理

lowering 时，Plot 先收集 transform 读取的源字段，同时登记 transform 派生出来的输出字段。这样 strict model 只校验真实输入字段，不要求你把派生字段提前声明。

`bin`、`summarize` 和 `annotate` 复用 [reducer / selector 统计子算子](/graph/grammar/transform/statistics)，例如 `count` / `sum` / `mean` / `median` / `quantile-band`。`select` 和 `relate` 复用 selector，例如 `min` / `max` / `first` / `last` / `top`。`density` 与 `smooth` 会生成采样行，再交给 `PathMark` 画密度面积或趋势线。自定义长尾统计可以继续用 `defineTransform`，也可以通过 reducer / selector definition 嵌入这些通用 transform。

plot 级 transform 会影响整张图的 scale、guide 和所有 mark。mark-local transform 只影响当前图元看到的 rows，适合派生局部统计层或 relation 行。

`relate` 常放在 `RelationMark.transform` 里，但它不是 RelationMark 私有能力。它输出的 `sourceId` / `targetId` / `delta` 也是普通字段，可以继续被 PointMark、ReferenceMark 或自定义 mark 消费。
