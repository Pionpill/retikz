`<IntervalMark>` is not a "bar mark"; it is the interval mark. It builds intervals across one or more position roles for each datum, then lets the coordinate system project them: rectangles under cartesian coordinates, radial bars or sectors under polar coordinates.

With plain `x` / `y`, `x` is a band interval and `y` spans from baseline `0` to the value. With explicit `bounds`, each role can be declared as `band` / `span` / `extent` / `proportional` / `full`. In the tables below, `FieldName` means a data field name or field path, such as `quarter` / `sales.revenue`.

## Usage

```tsx
import { IntervalMark, Plot } from '@retikz/plot-react';
```

```tsx
<Plot data={revenue}>
  <IntervalMark x="quarter" y="value" />
</Plot>
```

A basic bar only needs `x` / `y`. Variable-width bars use `width` for proportional intervals; histograms use `x0` / `x1` for continuous intervals; heatmaps use `bounds` for double-band cells; pies and donuts use `angle` so the React DSL can accumulate angular extents.

## Presentation Layer

IntervalMark is the low-level cell mark: it turns each data row into an orthogonal interval cell, then the coordinate system projects that cell into a rectangle, sector, or contour. Bars, histograms, heatmaps, radial bars, pies, and donuts are not separate low-level marks; they are presentation forms of the same IntervalMark under different `bounds`, `series`, `stack`, and `coordinate` settings.

| Form | Key props | Meaning |
| --- | --- | --- |
| Bar | `x` / `y` | `x` provides the category slot; `y` spans from `0` to the value |
| Horizontal bar | `direction="horizontal"` | `x` becomes the numeric length; `y` becomes the categorical band |
| Variable-width bar | `x` / `width` | `width` accumulates contiguous proportional intervals; `x` supplies axis labels |
| Grouped bar | `arrangement="dodge"` / `group` | Split one category slot into sub-bands by group |
| Stacked bar | `arrangement="stack"` / `group` | A stack transform produces `y0` / `y1`; the value role becomes an extent |
| Normalized stacked bar | `arrangement="normalize-stack"` / `group` | Normalize each category to percentages, then stack |
| Histogram | `x0` / `x1` / `y` | `x0` / `x1` provide a continuous x interval; `y` provides the height |
| Heatmap / grid | `bounds` | Both `bounds.x` and `bounds.y` are declared as `band` |
| Pie / donut | `angle` / `coordinate` | `angle` accumulates into angular extents; the radial role uses full |

## Examples

### Position Props

`x` / `y` are the smallest bar form: `x` binds a categorical field, and `y` binds a numeric field. The coordinate system interprets the categorical field as a band and the numeric field as a span from `0` to the value.

`direction="horizontal"` swaps the bar roles: `x` still binds the numeric field, but it is interpreted as the length from `0` to the value; `y` binds the categorical field and is inferred as a band. Multi-series horizontal arrangement is handled by the arrangement API.
`width` is the proportional-width shortcut: it accumulates a non-negative numeric field into contiguous intervals on the band role, so the bar width can represent another measure while `y` still controls height. When `x` is also provided, that field labels the center of each proportional interval on the axis.

### Continuous Intervals

`x0` / `x1` are the continuous-interval form. The left histogram below first lets the bin transform produce `binStart` / `binEnd`, then IntervalMark uses them as `bounds.x=extent(x0,x1)`; the right example uses `width` to allocate bar width proportionally by GDP and `x` to show country labels.

### Bounds Prop

`bounds` overrides the default inference. A heatmap needs both directions to be bands, so it explicitly writes `bounds={{ x: { kind: 'band' }, y: { kind: 'band' } }}`.

Without `color`, the same double-band interval draws a fixed grid. It is still IntervalMark; it just does not map a cell value to fill color.

<ComponentPreview name="rect-bounds" sourceFiles={['rect-heatmap.data.ts', 'rect-grid.data.ts']} interactive />

### Series Props

`arrangement` controls how multiple interval segments share one category slot: `dodge` places them side by side, `stack` accumulates them, and `normalize-stack` builds a percentage stack. `group` is the arrangement field used for sub-bands or stack segments; `color` is the visual color field and can be the same field or a separate one. `series` remains as a compatibility shortcut: when `group` / `color` are omitted, it acts as the default arrangement and color field.
`arrangement="stack"` can use `stackOffset`: `zero` accumulates from 0, `normalize` scales each stack to 0..1, `diverging` separates positive and negative values, `center` centers the full stack, and `overlap` draws every segment from 0. For percentage stacks, use `percent` or `arrangement="normalize-stack"`; that path normalizes values within each category to 0..100 before stacking.

The same `x` / `y` interval under `coordinate="polar2D"` maps the `x` band to an angular band and the `y` span to radial length.

IntervalMark visual styles lower onto the core `Node` for each cell. Common entries include `cornerRadius`, `stroke`, `strokeWidth`, `fillOpacity`, `shadow`, and label styling; polar sectors can also use `padAngle` for a real angular gap and `pull` to move along the sector midline. ## How It Works

`IntervalMark` is a built-in registered mark. The React `<IntervalMark>` does not render DOM by itself; `<Plot>` collects it into a `type: 'interval'` mark IR while filling in `bounds`, automatic stack transforms, and color scales from the shortcut props.

At compile time, `lowerMark` looks up `MARK_REGISTRY` by `mark.type`. `IntervalMark` hits the `PlotMark.Interval` entry and calls `lowerIntervalLayer`; that function requires the current coordinate frame to provide `projectCell`, then calls `markCell` and the frame's `projectCell` for each row. cartesian2D / polar2D also build an `IntervalContext` for bands, grouped sub-bands, and proportional intervals; a custom coordinate that wants interval support must provide both `roleScales` and `projectCell` on its frame. The coordinate frame decides whether the cell becomes a rectangle, sector, or contour; IntervalMark only applies sector-only visual parameters such as `padAngle` / `pull`, and runtime locating reuses the same geometry helper.

The important registration line and lowering excerpt are:

```ts
[PlotMark.Interval]: { type: PlotMark.Interval, buildCell: (mark, row, frame, ctx) => markCell(mark, row, frame, ctx), lower: lowerIntervalLayer },

const lowerIntervalLayer = (mark: Mark, rows: Array<ExternalRow>, frame: CoordinateFrame, channels: MarkChannels, markProvenance: MarkProvenance | undefined): IRChild | null => {
  if (mark.type !== PlotMark.Interval) return null;
  if (!hasProjectCell(frame)) {
    throw new Error(failLoudMessage(mark.type, frame.type));
  }
  const ctx = buildIntervalContext(mark, frame, rows);
  const layer = lowerCells(mark, rows, frame, ctx, channels.colorOf, channels.defaultColor, markProvenance, channels.labelOf);
  return layer === null ? null : attachMarkLayer(layer, mark, markProvenance);
};

const intervalCellGeometry = (mark: IntervalMark, row: ExternalRow, frame: CoordinateFrame, ctx: IntervalContext | undefined): CellGeometry | null => {
  if (!hasProjectCell(frame)) return null;
  const cell = markCell(mark, row, frame, ctx);
  return cell === null ? null : applyIntervalCellVisualParams(frame.projectCell(cell), mark, row);
};

const lowerCells = (...): IRScope | null => {
  const placed: Array<{ color: string | undefined; node: IRNode }> = [];
  let kind: CellGeometry['kind'] | undefined;
  for (let transformedIndex = 0; transformedIndex < rows.length; transformedIndex++) {
    const row = rows[transformedIndex];
    const geometry = intervalCellGeometry(mark, row, frame, ctx);
    if (!geometry) continue;
    if (!isRenderableCellGeometry(geometry)) continue;
    kind = geometry.kind;
    const node = attachDatumLabel(
      decorateDatum(cellGeometryNode(geometry), row, transformedIndex, mark.type, markProvenance, cellSeriesValue(mark, row)),
      mark,
      row,
      labelOf,
    );
    placed.push({ color: colorOf?.(row), node });
  }
  return placed.length === 0 || kind === undefined ? null : cellLayer(placed, kind, colorOf, defaultColor);
};
```

| Step | Meaning |
| --- | --- |
| Coordinate guard | IntervalMark needs the coordinate frame to provide `projectCell`; frames without cell projection fail loudly |
| Interval construction | `markCell` builds the logical cell from `bounds`, position channels, `series`, and stack-derived fields; custom frames also need `roleScales` |
| Projection | `frame.projectCell` projects the logical cell into `rect`, `sector`, or `contour` geometry |
| Sector visual parameters | `padAngle` shrinks sector angles; `pull` moves the sector center along the final mid angle; locators read the same geometry |
| Core lowering | `cellGeometryNode` turns renderable geometry into a core Node, skips empty contours, and groups color channels upward into Scopes |

## API

`IntervalMark` props are grouped as Position, Specific, Node, Label, General, and Custom: position fields define cell role values, specific fields build intervals and series relationships, and node fields lower onto core `Node`. `FieldName` means a data field name or field path, such as `quarter` / `sales.revenue`.

| Category | Prop | Type | Default | Description |
| --- | --- | --- | --- | --- |
| Position | `x` / `y` / `z` | `FieldName?` | — | Coordinate role fields; cartesian2D / polar2D use `x` / `y`, ternary2D also needs `z` |
| Specific | `color` | `FieldName?` | `series` | Color field; field bindings create a color channel and legend |
|  | `x0` / `x1` | `FieldName?` | — | Lower / upper x interval fields; component props create `bounds.x = extent(x0, x1)` |
|  | `width` | `FieldName?` | — | Proportional-width field; component props create `bounds.<bandRole> = proportional(width)`; the same-role `x` / `y` field can label axis ticks |
|  | `direction` | `'vertical' \| 'horizontal'` | `vertical` | Ordinary bar direction; `horizontal` uses an x value span and y categorical band |
|  | `angle` | `FieldName?` | — | Pie / donut shortcut: share field accumulated into angular intervals |
|  | `padAngle` | `number?` | — | Angular gap in degrees for polar sectors; each sector shrinks by half the gap on each side |
|  | `pull` | `MarkValueProp<number>`<br />`PointNonnegativeNumberStyle` | `0` | Static radial offset for polar sectors; numbers are constants, strings bind fields, and only sector geometry supports it |
|  | `bounds` | `IntervalBounds?` | inferred by role | Explicit band / span / extent / proportional / full source for each role |
|  | `group` | `FieldName?` | `series` | Arrangement grouping field; dodge cuts sub-bands by it, stack uses it for segments |
|  | `arrangement` | `'dodge' \| 'stack' \| 'normalize-stack'` | inferred from `group` / `series` / `stack` | Multi-segment interval arrangement |
|  | `stackOffset` | `'zero' \| 'normalize' \| 'diverging' \| 'center' \| 'overlap'` | `zero` | Baseline offset passed to the stack transform; only applies directly to `arrangement="stack"` |
|  | `percent` | `boolean?` | `false` | Percentage-stack shortcut; equivalent to `arrangement="normalize-stack"` |
|  | `series` | `FieldName?` | — | Compatibility shortcut; used as the default arrangement and color field when `group` / `color` are omitted |
|  | `stack` | `boolean?` | `false` | Compatibility shortcut; `true` is equivalent to `arrangement="stack"` |
| Node | `fill` / `stroke` | `FieldName`<br />`IRPaintSpec`<br />`PointFillStyle?` / `PointStrokeStyle?` | `currentColor` / — | Cell Node fill and stroke paint |
|  | `opacity` / `fillOpacity` | `PointOpacityStyle?` | — | Cell Node whole and fill opacity |
|  | `strokeWidth` | `PointNonnegativeNumberStyle?` | — | Cell Node stroke width |
|  | `padding` / `minimumSize` | `MarkValueProp<number>`<br />`PointNonnegativeNumberStyle` | — | Cell Node padding and minimum visual size |
|  | `minimumWidth` / `minimumHeight` | `MarkValueProp<number>`<br />`PointNonnegativeNumberStyle` | — | Minimum visual width / height |
|  | `align`<br />`lineHeight` / `maxTextWidth` | `MarkValueProp<NodeTextAlignValue>`<br />`NodeTextAlignStyle`<br />`MarkValueProp<number>`<br />`NodePositiveNumberStyle` | —<br />— | Text layout channels |
|  | `cornerRadius`<br />`scale` / `xScale` / `yScale` | `MarkValueProp<number>`<br />`PointNonnegativeNumberStyle`<br />`MarkValueProp<number>`<br />`NodePositiveNumberStyle` | —<br />— | Cell Node corner radius and scaling |
|  | `innerXSep` / `innerYSep`<br />`outerSep` / `margin` | `MarkValueProp<number>`<br />`PointNonnegativeNumberStyle` | — | Cell Node spacing channels |
|  | `dashed` / `dotted`<br />`dashPattern` | `MarkValueProp<boolean>`<br />`NodeBooleanStyle`<br />`MarkValueProp<Array<number>>`<br />`NodeDashPatternStyle` | —<br />— | Cell Node stroke dash channels |
|  | `font`<br />`boundary`<br />`shadow`<br />`blendMode` | `NodeFontStyle?`<br />`NodeBoundaryStyle?`<br />`ShadowStyle?`<br />`BlendModeStyle?` | —<br />—<br />—<br />— | Font, boundary, shadow, and blend mode |
| Label | `label` / `labelDisplayFormat` | `FieldName?`<br />`string?` | —<br />— | Attach datum labels to each cell |
|  | `labelPosition`<br />`labelDistance`<br />`labelPin` | `string / number`<br />`number`<br />`boolean / LabelPin` | `above`<br />`12`<br />`false` | Label side, spacing, and leader line |
| General | `id` | `string?` | — | Optional mark handle for layer ids / runtime label resolution |
|  | `transform` | `Array<Transform>?` | — | Mark-local data transform; runs after the plot-level transform and only changes the rows seen by this layer |
| Custom | `channels` | `Record<string, Channel>` | — | Custom channel bindings; resolved by registered channel definitions |
