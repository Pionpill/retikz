Beyond the 6 built-in marks, define your own glyph with `defineMark`. It follows the same paradigm as `defineCoordinate`, `defineScale`, and `defineTransform`: the spec still stores only a JSON operation, such as `{ type: 'diamond', encoding: { x: { field: 'month' }, y: { field: 'sales' } } }`; the field collection and lowering function live in a runtime definition injected through `<Plot markDefinitions={[...]}>`.

A custom mark's `type` is any non-built-in discriminator; its `encoding` reuses the same channel shape as built-in marks. Common coordinates use `x` / `y` / `color`, and custom coordinates may declare their own position roles. Position channels feed scale inference, so the custom mark shares the same coordinate system and scales as built-in marks.

## Diamond glyph

The `diamond` mark below projects each row into a diamond. It is registered in `markDefinitions`; a custom mark has **no dedicated React component**, so it is authored via the `<Plot spec={...}>` entry — write `{ type: 'diamond', ... }` directly in the `marks` array.

The third argument to `lower` is the coordinate `frame`. It projects each row's `x` / `y` through `frame.projectRoles` into a screen point, then assembles a core `Node` (`shape: 'diamond'`). The `frame` hides cartesian / polar differences: the mark just asks for a projected point; how the coordinate system interprets `x` / `y` is decided by the coordinate layer.

## Definition contract

| Field | Required | Purpose |
| --- | --- | --- |
| `type` | required | Registration key = IR discriminator; must be a non-built-in identifier (no collision with `point` / `path` / `region` / `interval` / `link` / `reference`) |
| `lower` | required | Lowers the mark + data rows + `frame` + channel resolvers into core IR; returns `null` when nothing is drawable |
| `collectFields` | optional | Registers the source fields this mark reads; strict model validation uses it so fields are not flagged as missing |
| `buildCell` | optional | Per-row cell builder for interval-like marks (built-in `interval` uses this; plain glyphs do not) |

Use `defineMark<MyMark>` to specify your own operation type, so `lower` / `collectFields` receive the precise `mark` shape (defaults to the built-in `Mark`).

## Three-layer boundary

A mark spans three layers, with the same boundary as built-in marks:

| Layer | Holds | In IR | Responsibility |
| --- | --- | --- | --- |
| schema | `type`, `encoding`, and other serializable fields | yes | validation, persistence, AI generation, cross-runtime transfer |
| authoring | built-in via React components; custom via the spec entry | no | assemble user input into JSON-safe mark IR |
| registry | `lower(mark, rows, frame, channels)` behavior | no | lower into core IR at compile time |

Built-in and custom marks dispatch through the same `resolveMarkRegistry`: built-in marks go through the strict discriminated union, custom marks through `type` passthrough, and lowering uses an `isBuiltinMark` guard to separate built-in-specific geometry (interval bounds, link endpoints, …) from the generic position channels.
