`<IntervalMark>` is not a "bar mark"; it is the interval mark. It builds intervals across one or more position roles for each datum, then lets the coordinate system project them: rectangles under cartesian coordinates, radial bars or sectors under polar coordinates.

With plain `x` / `y`, `x` is a band interval and `y` spans from baseline `0` to the value. With explicit `bounds`, each role can be declared as `band` / `span` / `extent` / `full`. In the tables below, `FieldName` means a data field name or field path, such as `quarter` / `sales.revenue`.

## Usage

```tsx
import { IntervalMark, Plot } from '@retikz/plot-react';
```

```tsx
<Plot data={revenue}>
  <IntervalMark x="quarter" y="value" />
</Plot>
```

A basic bar only needs `x` / `y`. Histograms use `x0` / `x1` for continuous intervals; heatmaps use `bounds` for double-band cells; pies and donuts use `angle` so the React DSL can accumulate angular extents.

## Presentation Layer

IntervalMark is the low-level cell mark: it turns each data row into an orthogonal interval cell, then the coordinate system projects that cell into a rectangle, sector, or contour. Bars, histograms, heatmaps, radial bars, pies, and donuts are not separate low-level marks; they are presentation forms of the same IntervalMark under different `bounds`, `series`, `stack`, and `coordinate` settings.

| Form | Key props | Meaning |
| --- | --- | --- |
| Bar | `x` / `y` | `x` provides the category slot; `y` spans from `0` to the value |
| Grouped bar | `series` | Split one category slot into sub-bands by series |
| Stacked bar | `series` / `stack` | A stack transform produces `y0` / `y1`; `bounds.y` becomes an extent |
| Histogram | `x0` / `x1` / `y` | `x0` / `x1` provide a continuous x interval; `y` provides the height |
| Heatmap / grid | `bounds` | Both `bounds.x` and `bounds.y` are declared as `band` |
| Pie / donut | `angle` / `coordinate` | `angle` accumulates into angular extents; the radial role uses full |

## How It Works

`IntervalMark` is a built-in registered mark. The React `<IntervalMark>` does not render DOM by itself; `<Plot>` collects it into a `type: 'interval'` mark IR while filling in `bounds`, automatic stack transforms, and color scales from the shortcut props.

At compile time, `lowerMark` looks up `MARK_REGISTRY` by `mark.type`. `IntervalMark` hits the `PlotMark.Interval` entry and calls `lowerIntervalLayer`; that function requires the current coordinate frame to provide `projectCell`, then calls `markCell` and the frame's `projectCell` for each row. cartesian2D / polar2D also build an `IntervalContext` for bands and grouped sub-bands; a custom coordinate that wants interval support must provide both `roleScales` and `projectCell` on its frame. The coordinate frame decides whether the cell becomes a rectangle, sector, or contour; IntervalMark itself does not branch by chart form.

The important registration line and lowering excerpt are:

```ts
[PlotMark.Interval]: { type: PlotMark.Interval, buildCell: (mark, row, frame, ctx) => markCell(mark, row, frame, ctx), lower: lowerIntervalLayer },

const lowerIntervalLayer = (mark: Mark, rows: Array<ExternalRow>, frame: CoordinateFrame, channels: MarkChannels, markProvenance: MarkProvenance | undefined): IRChild | null => {
  if (mark.type !== PlotMark.Interval) return null;
  if (!hasProjectCell(frame)) {
    throw new Error(failLoudMessage(mark.type, frame.type));
  }
  const ctx = isCartesianCoordinateFrame(frame) || isPolarCoordinateFrame(frame) ? buildIntervalContext(mark, frame, rows) : isGenericCoordinateFrame(frame) ? buildGenericIntervalContext(mark, frame, rows) : undefined;
  const layer = lowerCells(mark, rows, frame, frame.projectCell, ctx, channels.colorOf, channels.defaultColor, markProvenance, channels.labelOf);
  return layer === null ? null : attachMarkLayer(layer, mark, markProvenance);
};

const lowerCells = (
  mark: Mark,
  rows: Array<ExternalRow>,
  frame: CoordinateFrame,
  projectCell: (cell: Cell) => CellGeometry,
  ctx: IntervalContext | undefined,
  colorOf: ColorOf | undefined,
  defaultColor: string | undefined,
  markProvenance: MarkProvenance | undefined,
  labelOf: LabelOf | undefined,
): IRScope | null => {
  const placed: Array<{ color: string | undefined; node: IRNode }> = [];
  let kind: CellGeometry['kind'] | undefined;
  for (let transformedIndex = 0; transformedIndex < rows.length; transformedIndex++) {
    const row = rows[transformedIndex];
    const cell = markCell(mark, row, frame, ctx);
    if (!cell) continue;
    const geometry = projectCell(cell);
    if (!isRenderableCellGeometry(geometry)) continue;
    kind = geometry.kind;
    const node = attachDatumLabel(
      decorateDatum(cellGeometryNode(geometry), row, transformedIndex, mark.type, markProvenance, cellSeriesValue(mark, row)),
      mark,
      row,
      labelOf,
    );
    placed.push({ color: colorOf?.(row), node });
  }
  return placed.length === 0 || kind === undefined ? null : cellLayer(placed, kind, colorOf, defaultColor);
};
```

| Step | Meaning |
| --- | --- |
| Coordinate guard | IntervalMark needs the coordinate frame to provide `projectCell`; frames without cell projection fail loudly |
| Interval construction | `markCell` builds the logical cell from `bounds`, position channels, `series`, and stack-derived fields; custom frames also need `roleScales` |
| Projection | `frame.projectCell` projects the logical cell into `rect`, `sector`, or `contour` geometry |
| Core lowering | `cellGeometryNode` turns renderable geometry into a core Node, skips empty contours, and groups color channels upward into Scopes |

## API

Most `IntervalMark` props are data channels. `FieldName` means a data field name or field path, such as `quarter` / `sales.revenue`.

| Category | Prop | Type | Default | Description |
| --- | --- | --- | --- | --- |
| Position | `x` | `FieldName?` | — | x position field; used by bars, heatmaps, and radial bars |
| | `y` | `FieldName?` | — | y position field; used by bars, heatmaps, and radial bars |
| | `x0` / `x1` | `FieldName?` | — | Continuous x interval bounds; used by histograms and other explicit intervals |
| | `angle` | `FieldName?` | — | Pie / donut shortcut: share-value field, accumulated into angular extents |
| Bounds | `bounds` | `IntervalBounds?` | inferred from scales | Advanced interval source; heatmaps use `{ x: { kind: 'band' }, y: { kind: 'band' } }` |
| Series | `series` | `FieldName?` | — | Series field; split into multiple interval series |
| | `stack` | `boolean?` | `false` | Stack multiple series; omit for side-by-side grouping |
| Style Channel | `color` | `FieldName?` | `series` | Color field; falls back to `series` |
| Label | `label` | `FieldName?` | — | Host datum-label field |
| | `labelDisplayFormat` | `string?` | — | Label display format string |
| | `labelPosition` | `CompassAnchor \| number?` | `above` | Label position relative to the host Node |
| | `labelDistance` | `number?` | `12` | Distance from the host border to the label |
| | `labelPin` | `boolean?` | `false` | Whether to draw a leader from the host border to the label |
| | `resolveLabel` | `(row) => string?` | — | Runtime label resolver; not stored in IR, requires `id` |
| Common | `id` | `string?` | — | Optional handle |
