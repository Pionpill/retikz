title: LinkMark
description: LinkMark expresses relational geometry: each row connects a source and target into a fillable band whose width can be encoded.
---

`<LinkMark>` describes the relation between two projected endpoint tuples. Each row curves from a source endpoint (`sourceX` / `sourceY`) to a target endpoint (`targetX` / `targetY`), with two cubic-curve long edges and straight end caps enclosing a fillable region.

`value` is the width channel, mapped through a built-in linear width scale to the source-end band width; `endWidth` can provide an independent target-end width. Sankey and alluvial flow diagrams are common presentation forms, but LinkMark itself only consumes already-computed endpoint positions and width fields.

## Usage

```tsx
import { LinkMark, Plot } from '@retikz/plot-react';
```

```tsx
<Plot data={flows}>
  <LinkMark sourceX="sourceX" sourceY="sourceY" targetX="targetX" targetY="targetY" value="value" color="channel" />
</Plot>
```

Endpoints must be field pairs in the same coordinate system. LinkMark currently supports `cartesian2D` only; named-node links across facet / inset / scope are a later capability.

## Presentation Layer

LinkMark is a low-level relation mark: it only lowers each row into one fillable curved band. What the presentation layer calls a sankey, alluvial, or flow migration diagram is not a new low-level mark; it is the same LinkMark after external layout and grouping.

The band defaults to `orientation="horizontal"`: entry / exit tangents run along the horizontal axis and half-width runs along the vertical axis, giving left-to-right flow with vertical end caps. Set `orientation="vertical"` for top-to-bottom flow with half-width along the horizontal axis. Width can gradually change from source to target.

| Presentation form | Key props | Description |
| --- | --- | --- |
| Equal-width band | `sourceX` / `sourceY` / `targetX` / `targetY` / `value` | Each row connects one endpoint pair, with equal source and target widths |
| Flared band | `value` / `endWidth` | Source and target widths differ, with a smooth transition along the band |
| Grouped band | `color` | Group by field for fill color; geometry stays unchanged |

### Geometry Props

`curvature` tunes the S-shape tension of the two cubic long edges. It ranges from `0..1` and defaults to `0.5`. `orientation` chooses the main axis: `horizontal` flows left-to-right, while `vertical` flows top-to-bottom.

The example above reuses the flared band: `curvature={0.6}` makes the bend more visible. `orientation` does not require new data; it changes the half-width direction and control-point direction for the same endpoint fields.

## How It Works

`LinkMark` is a built-in registered mark. The React `<LinkMark>` component does not render DOM; `<Plot>` assembles the flat props into mark IR with `type: 'link'`, turns `sourceX` / `sourceY` and `targetX` / `targetY` into nested `source` / `target` field pairs, and keeps `value` / `endWidth` / `curvature` / `orientation` on the mark itself.

At compile time, `lowerMark` looks up `MARK_REGISTRY` by `mark.type`. `LinkMark` resolves to the `PlotMark.Link` entry, which calls `lowerLinkLayer`. `lowerLinkLayer` accepts only cartesian2D, then calls `lowerLink`: it projects source and target endpoints for each row, computes source / target half-widths, and emits one closed cubic core `Path`.

For registration, focus on the `LinkMark` registry entry and the `lowerLinkLayer` / `lowerLink` functions that perform the lowering:

```ts
[PlotMark.Link]: { type: PlotMark.Link, lower: lowerLinkLayer },

const lowerLinkLayer = (mark: Mark, rows: Array<ExternalRow>, frame: CoordinateFrame, channels: MarkChannels, markProvenance: MarkProvenance | undefined): IRChild | null => {
  if (mark.type !== PlotMark.Link) return null;
  if (frame.type !== PlotCoordinate.Cartesian2D) {
    throw new Error(failLoudMessage(mark.type, frame.type));
  }
  const layer = lowerLink(mark, rows, frame, channels.colorOf, channels.defaultColor);
  return layer === null ? null : attachMarkLayer(layer, mark, markProvenance);
};

const lowerLink = (mark: LinkMark, rows: Array<ExternalRow>, frame: CoordinateFrame, colorOf: ColorOf | undefined, defaultColor: string | undefined): IRScope | null => {
  const halfWidthOf = linkHalfWidthOf(mark, rows);
  const curvature = mark.curvature ?? LINK_DEFAULT_CURVATURE;
  const placed: Array<{ color: string | undefined; steps: Array<IRStep> }> = [];
  for (const row of rows) {
    const value = linkValueOf(row, mark.value);
    if (value === null) continue;
    const endValue = mark.endWidth !== undefined ? linkValueOf(row, mark.endWidth) : value;
    if (endValue === null) continue;
    const halfSource = halfWidthOf(value);
    const halfTarget = halfWidthOf(endValue);
    const endpoints = linkEndpoints(mark, row, frame);
    if (endpoints === null) continue;
    const geometry = linkBandGeometry(endpoints.source, endpoints.target, halfSource, halfTarget, curvature, mark.orientation ?? 'horizontal');
    if (geometry === null) continue;
    placed.push({
      color: colorOf?.(row),
      steps: [
        { type: 'step', kind: 'move', to: geometry.sourceTop },
        { type: 'step', kind: 'cubic', to: geometry.targetTop, control1: geometry.topControl1, control2: geometry.topControl2 },
        { type: 'step', kind: 'line', to: geometry.targetBottom },
        { type: 'step', kind: 'cubic', to: geometry.sourceBottom, control1: geometry.bottomControl1, control2: geometry.bottomControl2 },
        { type: 'step', kind: 'cycle' },
      ],
    });
  }
  // no color channel: one scope; color channel: group paths by fill
};
```

The logic breaks down into four steps:

| Step | Description |
| --- | --- |
| Coordinate check | This round lowers only under cartesian2D; other coordinate systems fail loud |
| Width mapping | `linkHalfWidthOf` synthesizes a linear width mapping from the maximum `value` / `endWidth` |
| Endpoint projection | `linkEndpoints` projects source / target field pairs into screen points |
| Core lowering | `linkBandGeometry` computes corners and control points, then lowers the band into a closed core `Path` |

## API

LinkMark props are grouped as Position, Specific, Path, General, and Custom: endpoint fields define the source / target positions, specific fields describe width and geometry, and path fields lower onto core `Path`. `FieldName` means a field name or field path, such as `source.x` / `amount`; `curvature` / `orientation` are constant geometry settings.

| Category | Prop | Type | Default | Description |
| --- | --- | --- | --- | --- |
| Position | `sourceX` / `sourceY` | `FieldName` | — | Source endpoint field pair; currently projected only under cartesian2D |
|  | `targetX` / `targetY` | `FieldName` | — | Target endpoint field pair; currently projected only under cartesian2D |
| Specific | `value` | `FieldName` | — | Source-end flow field, mapped through a synthesized linear scale to band width |
|  | `endWidth` | `FieldName?` | `value` | Target-end width field; omitted means equal target and source widths |
|  | `curvature` | `number?` | `0.5` | Cubic control-point extrapolation ratio along the main axis, range `0..1` |
|  | `orientation` | `'horizontal' / 'vertical'?` | `'horizontal'` | Main-axis orientation: horizontal left-right flow or vertical top-bottom flow |
|  | `color` | `FieldName?` | default layer color | Field bound to color; groups fills by field value |
| Path | `opacity` / `fillOpacity`<br />`drawOpacity` | `PointOpacityStyle?`<br />`PointOpacityStyle?` | —<br />— | Whole-band, fill, and stroke opacity |
|  | `zIndex` / `rotate` | `PointZIndexStyle?`<br />`PointNumberStyle?` | —<br />— | Draw order and rotation |
|  | `scale`<br />`fillRule` / `thickness` | `PathScaleStyle?`<br />`PathFillRuleStyle?`<br />`PathThicknessStyle?` | —<br />—<br />— | Path scaling, fill rule, and thickness preset |
|  | `arrow` / `arrowDetail` | `PathArrowStyle?`<br />`PathArrowDetailStyle?` | —<br />— | Arrow direction and details |
|  | `dashPattern`<br />`shadow` / `blendMode` | `NodeDashPatternStyle?`<br />`ShadowStyle?`<br />`BlendModeStyle?` | —<br />—<br />— | Dash pattern, shadow, and blend mode |
| General | `id` | `string?` | — | Optional mark handle for layer ids |
| Custom | `channels` | `Record<string, Channel>` | — | Custom channel bindings; resolved by registered channel definitions |
