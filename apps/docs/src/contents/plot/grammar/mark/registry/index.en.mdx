The mark registry answers one question: how does a mark enter the plot compilation pipeline? The IR schema only describes serializable fields; the React / Vanilla declaration layer only assembles user syntax into IR; the registry lowering function turns data rows, scales, and coordinates into core `Scope` / `Node` / `Path` primitives.

The built-in `PointMark` / `PathMark` / `RegionMark` / `IntervalMark` / `ReferenceMark` / `LinkMark` are all entries in this mechanism. A custom mark follows the same line: define a stable `type` and field contract first, then put behavior in a runtime registry entry instead of putting functions into JSON.

## Usage

For users, the registered mechanism still appears as ordinary mark components:

```tsx
import { Plot, PointMark } from '@retikz/plot-react';

<Plot data={rows}>
  <PointMark x="x" y="value" />
</Plot>;
```

After adding a source-level mark, the declaration layer should keep that shape. The `CrossMark` below is a mechanism example: it declares field channels under `<Plot>`, while the matching registry lowering entry performs the drawing.

```tsx
<Plot data={rows}>
  <CrossMark x="x" y="value" size={10} />
</Plot>
```

The React component itself does not draw DOM. `<Plot>` collects it into mark IR such as `type: 'cross'`, and compilation looks up the registry by `type`.

## Mechanism

A mark is split across three layers:

| Layer | Contains | Enters IR | Responsibility |
| --- | --- | --- | --- |
| schema | fields such as `type`, `encoding`, `bounds`, `series` | yes | validation, persistence, AI generation, cross-runtime transport |
| declaration | React props / Vanilla builder | no | assemble user syntax into JSON-safe mark IR |
| registry | behavior such as `lower(mark, rows, frame, channels)` | no | compile-time lowering into core IR |

That boundary matters. IR cannot store functions, so the schema only keeps fields that reconstruct the mark semantics; the lowering function lives only in the runtime registry. Built-in marks are not special branches: they are built-in registry entries.

The current built-in registry entry shape can be read as:

```ts
type MarkDefinition<T extends Mark = Mark> = {
  type: PlotMarkValue;
  requiredRoles?: (frame: CoordinateFrame) => ReadonlyArray<DimensionRole>;
  buildCell?: (mark: T, row: ExternalRow, frame: CoordinateFrame, ctx?: IntervalContext) => Cell | null;
  lower: (mark: T, rows: Array<ExternalRow>, frame: CoordinateFrame, channels: MarkChannels, prov?: MarkProvenance) => IRChild | null;
};
```

`lowerMark` no longer owns a long `if (mark.type === ...)` chain. It looks up `MARK_REGISTRY` by `mark.type`, then calls the matching `lower`. Adding a built-in mark keeps dispatch stable and adds schema, declaration, and registry pieces.

## Custom Steps

Design a new mark in this order:

1. Pick an abstract semantic, not a chart name. Prefer "projected interval", "relational band", or "axis constraint" over "pie chart" or "heatmap".
2. Define a JSON-safe schema: the `type` discriminator, field channels, defaults, and fail-loud rules must all be serializable.
3. Implement the lowering entry: read `rows`, `frame`, and channel resolvers, return a core `Scope`, and return `null` when there is nothing drawable.
4. If the mark depends on intervals or grids, convert each row into a `Cell` first, then call `frame.projectCell`. Cartesian coordinates can produce rectangles, polar coordinates can produce sectors, and curved coordinates can return contours.
5. Add the React / Vanilla declaration layer. The component or builder only assembles IR; drawing behavior still belongs to registry lowering.

## Example

This demo shows a source-level `CrossMark`: each row projects to one point, then two crossing line segments are drawn at that point. Open the source and you can see that the demo does place `CrossMark` under `<Plot>`, keeping the same declaration shape as a built-in mark.

The public API cannot register marks dynamically yet, so this demo only simulates the result after a source extension is wired in. The page-local `CrossMark` is an empty declaration component; a transparent `PointMark` makes the plot establish scales; core `Draw` overlays the two lines that `lowerCross` would emit. That compromise is only for the documentation preview. In real source wiring, `buildPlotSpec` would collect `CrossMark` and hand it to registry lowering.

First extend the IR schema. `type` is the discriminator, `encoding` still describes field-to-channel bindings, and `size` is a JSON-safe drawing parameter:

```ts
export const PlotMark = {
  // ...
  Cross: 'cross',
} as const;

export const CrossMarkSchema = z.object({
  type: z.literal(PlotMark.Cross),
  encoding: EncodingSchema,
  size: z.number().positive().optional(),
});

export const MarkSchema = z.discriminatedUnion('type', [
  PointMarkSchema,
  PathMarkSchema,
  RegionMarkSchema,
  IntervalMarkSchema,
  ReferenceMarkSchema,
  LinkMarkSchema,
  CrossMarkSchema,
]);
```

Then implement lowering. It consumes data rows and the coordinate frame, returns a core `Path` layer, and returns `null` when no point can be projected:

```ts
const lowerCross = (mark: CrossMark, rows: Array<ExternalRow>, frame: CoordinateFrame): IRChild | null => {
  const size = mark.size ?? 6;
  const children: Array<IRChild> = [];

  for (const row of rows) {
    const point = frame.projectRoles([channelValue(mark.encoding.x, row), channelValue(mark.encoding.y, row)]);
    if (!point) continue;

    const [x, y] = point;
    children.push({
      type: 'path',
      children: [
        { action: 'move', to: [x - size, y - size] },
        { action: 'line', to: [x + size, y + size] },
        { action: 'move', to: [x - size, y + size] },
        { action: 'line', to: [x + size, y - size] },
      ],
    });
  }

  return children.length === 0 ? null : { type: 'scope', children };
};
```

Finally register it and add a React declaration component that only assembles IR:

```ts
export const MARK_REGISTRY = {
  // ...
  [PlotMark.Cross]: { type: PlotMark.Cross, lower: lowerCross },
};

export type CrossMarkProps = {
  x: string;
  y: string;
  size?: number;
  id?: string;
};

export const CrossMark: FC<CrossMarkProps> = () => null;
```

`CrossMark` does not need to know whether the current coordinate is cartesian or polar. It asks `frame.projectRoles` for the projected point; the coordinate layer decides how to interpret `x` / `y`.

## Interface

| Interface point | Required | Description |
| --- | --- | --- |
| `type` | yes | Registry key; must match the IR schema discriminator |
| `lower` | yes | Lowers the current mark and data rows into core IR; returns `null` when empty |
| `requiredRoles` | optional | Declares which position roles are required for the current coordinate; omitted entries fail loud inside lowering |
| `buildCell` | optional | Per-row cell construction for interval-like marks, mainly used by marks such as `IntervalMark` |

Declaration props are not the registry interface. Props face users and are usually flat field names; schema faces IR and must stay JSON-safe; registry faces compilation and receives normalized marks, data rows, channel resolvers, and the coordinate frame.

## Current Boundary

<ComponentAlert type="warn" title="Runtime registration is not public yet" description="The built-in marks already use a registry table, but this version does not expose a registerMark API or a dynamic MarkSchema registry. This differs from custom coordinates. A coordinate projection can be injected through `<Plot coordinates>` because the IR only stores `{ type: <customType>, ...config }`, while roles and functions live in the `defineCoordinate` definition. A mark `type` must also enter the `MarkSchema` discriminated union, so public runtime registration needs schema extension, React / Vanilla assembly, and lowering dispatch to be solved together.

## Built-Ins

| Mark | Registered behavior |
| --- | --- |
| `PointMark` | Lowers each row to a glyph or text Node |
| `PathMark` | Lowers ordered points into a core Path |
| `RegionMark` | Fills the area enclosed by an outline and baseline |
| `IntervalMark` | Builds a Cell first, then projects it into a rectangle, sector, or contour |
| `ReferenceMark` | Lowers an axis constant into a line or band |
| `LinkMark` | Lowers source / target endpoints into a fillable cubic band |

Chart forms are just results of these registered marks under different coordinates, scales, and transforms. Before adding a new mark, first check whether the existing marks already express the geometry.
