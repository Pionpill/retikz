A heatmap is `<IntervalMark>` with a double band: it draws one rectangular cell per data row, `x` and `y` **both bind categorical fields**, and `bounds={{ x: { kind: 'band' }, y: { kind: 'band' } }}` explicitly declares both dimensions as band, sizing each cell `bandwidth_x × bandwidth_y`. The data value does not drive position — instead it maps through the `color` channel to the cell's fill. This is the basis for heatmaps, confusion matrices, and calendar heatmaps.

## Difference from ordinary interval bars

A heatmap and a bar differ in "what the second dimension is":

- **Bar** (`<IntervalMark x y>`): `x` comes from a band scale (its `bandwidth` is the bar width), `y` is a **continuous value** — the bar height scales with the data, so the cell is "one band × one continuous interval".
- **Rect** (`<IntervalMark>` double band): `bounds` declares `x` **and** `y` **both as band scales**, so the cell is a fixed `bandwidth_x × bandwidth_y` grid; the value maps through the `color` channel to the fill, not to position.

Because of this, the double-band `<IntervalMark>` forces **both** the x and y axes to be band scales — declaring a continuous `<Scale dimension="y">` that conflicts with it raises an error.

## Without color: a plain grid

Omit `color` and each cell falls back to a single default fill — a plain grid with no value mapping, useful as a backdrop you then layer `<PointMark>` / text on top of:

## API

| prop | type | description |
| --- | --- | --- |
| `x` | `string` | Field path for the x channel (categorical, auto band scale, sizes the cell width) |
| `y` | `string` | Field path for the y channel (categorical, auto band scale, sizes the cell height) |
| `bounds` | `IntervalBounds?` | Explicit interval-bounds escape hatch; for a double-band heatmap write `{ x: { kind: 'band' }, y: { kind: 'band' } }` to force both dimensions to band |
| `color` | `string?` | Color field: maps the value to the cell fill. A continuous field needs a `model` declaration → auto sequential color scale (viridis), colored per datum; omit for a plain grid (single default fill) |
| `id` | `string?` | Optional handle (reserved, not yet resolved) |
