---
title: Ternary Coordinates
description: ternary2D normalizes a / b / c continuous components and projects them into an equilateral triangle for compositions and three-way trade-offs.
---

`coordinate="ternary2D"` projects three components satisfying `a + b + c = constant` into an equilateral triangle. Each vertex represents one component at 100%; the closer a point is to a vertex, the larger that component's share is.

## Field Binding

Ternary coordinates do not use `x` / `y`; they bind three channels: `a` / `b` / `c`. Each row is normalized automatically, so you can feed any positive triple directly, such as sand 60, silt 30, clay 10. Negative values or a sum of zero fail loudly.

## Axes And Dimensions

Add `<Axis dimension="a" />` / `"b"` / `"c"` to draw tick axes along the three edges; all three together form the full triangle outline. Ternary coordinates this round are `<PointMark>`-first, for scatter points inside the triangle.

<ComponentAlert type="tip" title="Guide dimensions must match the coordinate" description="Each coordinate system accepts only its own dimensions: cartesian uses x / y, polar uses angle / radius, ternary uses a / b / c. A wrong dimension, such as <Axis dimension='angle'> under cartesian, fails loudly instead of silently drawing an empty axis." />

## Good Fits

Ternary coordinates fit data where three parts share a fixed total and trade off against each other: soil composition, three-way vote shares, or recipe ratios. They are not ordinary 3D data: `a` / `b` / `c` are not independent spatial axes, but components of one position inside a triangle.
