---
title: Channels
description: Channels connect fields or constants to mark attributes: position chooses coordinate roles, while mark / scope / node / path channels decide how visible attributes are consumed.
---

A channel answers "where does this attribute read its value from?" The data layer first normalizes external rows into canonical rows, then channels pass fields or constants to coordinates, mark lowering, core nodes, core paths, and legends. `x` / `y` / `color` / `size` / `text` share one binding model, while later stages consume them differently.

## Responsibilities

| Topic | Responsibility | Reach for it when |
| --- | --- | --- |
| Channel binding | How fields / constants appear in mark props or `encoding` | You want to confirm what `x="date"`, `color="region"`, or `y={80}` means |
| Channel groups | Who consumes position / mark / scope / node / path channels | You want to decide where `color`, `size`, or `strokeWidth` belongs |
| Custom channels | Declare runtime definitions with `defineScopeChannel` / `defineNodeChannel` / `definePathChannel` / `defineChannel`, then register them through `channelDefinitions` | Your spec needs `encoding.channels.<name>` |

Position channels are reinterpreted by coordinates: the same `x` / `y` means horizontal / vertical under `cartesian2D`, but angle / radius under `polar2D`. `color` is a mark channel because different marks land it on node fill, text color, path stroke, or path fill. `size`, `shape`, and `opacity` are node channels because they write core `IRNode` properties directly.
