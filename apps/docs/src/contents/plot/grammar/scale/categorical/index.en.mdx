---
title: Categorical scales
description: Positional scales for categorical fields (band for bars, point for dots) and the color scale (ordinal, one color per category).
---

A categorical field (`categorical`) has no continuous numeric order; the scale's job is to spread a finite set of categories **evenly across position or color**. Position defaults to `band` (bars), lines use `point`; color goes through `ordinal`, one discrete color per category.

## band and point

| Type | Placement | For |
| --- | --- | --- |
| `band` | Each category gets an equal-width slot; marks sit in the center and can fill the slot width | Bar charts (default) |
| `point` | Each category lands on an evenly-spaced point, no slot width | Categorical lines, categorical scatter |

Declare the field as `categorical` and the positional channel defaults to `band`: each category gets an equal slot, with the bar centered in it.

Lines and scatter want points, not slots — there is no "width" between categories, so switch to `point` explicitly to land each category on an evenly-spaced point:

```tsx
<Plot data={rows} model={[{ name: 'segment', type: 'categorical' }]}>
  <PathMark x="segment" y="revenue" order="segment" />
  <Scale dimension="x" type="point" />
  <Axis dimension="x" />
</Plot>
```

## ordinal coloring

Bind `color` to a categorical field and `<Plot>` derives `ordinal` — one discrete color per category. It is also how multi-series coloring works: without an explicit series, a categorical color field implicitly splits the data into multiple series.

| Type | For | Output |
| --- | --- | --- |
| `ordinal` | Categorical field | One discrete color per category (multi-series, categorical coloring) |

ordinal is **discrete** coloring — one color per category, no gradient between them. Continuous / temporal fields want a continuous band, so use [`sequential`](/plot/grammar/scale/continuous#mapping-continuous-values-to-color) instead — don't put it on a categorical field.
