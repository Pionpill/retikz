title: Custom Transforms
description: Custom transforms keep the executor at runtime: the IR stores only a custom kind and JSON config, while field collection and apply live in defineTransform.
---

Beyond the built-in transforms, register your own data processor with `defineTransform`. It is the same pattern as `defineCoordinate` for coordinates and `defineScale` for scales: the spec still stores only the JSON operation, such as `{ kind: 'double-x', field: 'x', as: 'x2' }`; the schema, field collection, and runtime function live in the definition, injected through `<Plot transformDefinitions={[...]}>`.

The custom operation stays plain JSON — serializable and AI-generatable; functions like `inputFields` / `outputFields` / `apply` participate only at runtime and never enter the IR.

## Doubling x

The `double-x` transform below doubles `field` into `as`. It is registered in `transformDefinitions`, and the spec references it with `<Transform kind="double-x" field="x" as="x2" />`.

`x2` is not declared in `model`, because it is derived by `double-x`. `outputFields` registers it as a transform output, so strict model validation checks only the real input fields `x` and `y`.

## Definition contract

| Field | Purpose |
| --- | --- |
| `schema` | Validates the `{ kind, ...config }` operation. `kind` must be a non-built-in `z.literal(...)`; all other fields must stay JSON-serializable. |
| `inputFields` | Returns the source fields read by the transform; these fields enter model validation and field resolution. |
| `outputFields` | Returns derived fields produced by the transform; downstream marks or transforms can consume them without declaring them in `model`. |
| `apply` | Runs the transform in pipeline order and returns the next row set; it must be deterministic so rendering and locators stay aligned. |

The third `apply` argument is a transform context. Row-preserving transforms usually keep row provenance by returning `{ ...row, newField }`; when a row-count-changing transform emits one row for a group of source rows, it must call `context.groupProvenance(out, members)` to attach `sourceIndices`. If a transform generates rows with no source rows, provenance naturally degrades to `transformedIndex` only.
