---
title: Data Labels
description: Add text labels to a chart: bar-top values and scatter category names go on the host mark's label; free-floating text uses <TextMark>.
---

There are two ways to write data values or arbitrary text onto a chart. To label **another mark's datum** (a bar-top value, a scatter category name) prefer giving that mark a `label`; to place **free-floating text with no host** (annotations, notes) use a standalone `<TextMark>`. Both project exactly like a point and are coordinate-system agnostic.

## Bar-top value labels

Give `<BarMark>` (or `<PointMark>` / `<LineMark>` / `<AreaMark>`) a `label` field and the label sits above each bar's border, placed by `labelPosition` / `labelDistance` — no second mark needed. `labelFormat` formats the value (thousands separator, decimals, etc.).

`label` takes a field name at the top level (resolved as a field by default). Placement mirrors the node-label semantics: `labelPosition` is an 8-direction enum (`above` / `right` / `above-left` …) or a numeric angle, and `labelDistance` is the gap from the border.

## Free text

For floating text with no host, use `<TextMark>`: it creates a text-bearing node at the projected point, with geometry identical to a scatter point. `dx` / `dy` are pixel-level offsets from the anchor.

## Custom content

Label content has four priority tiers, highest first:

| Source | In IR | Notes |
| --- | --- | --- |
| `resolveLabel` | No | Runtime function for fully custom templates; highest priority |
| `labelFormat` / `format` | Yes | Format string applied to the field value (number / time) |
| `label` / `text` field | Yes | Stringify that row's field value |
| Constant string | Yes | One label for every row |

`resolveLabel` is the runtime escape hatch: use it for concatenation that `field` / `format` cannot express (e.g. `month: revenue`). It is a function, never enters the IR, and needs the mark to carry an `id` so it can be injected at runtime.

## API

Host label (set on `<BarMark>` / `<PointMark>` / `<LineMark>` / `<AreaMark>`):

| prop | type | notes |
| --- | --- | --- |
| `label` | `string?` | Label content field (resolved as a field by default); omit for no label |
| `labelFormat` | `string?` | Number / time format string; only used with `label` |
| `labelPosition` | `8-dir \| number?` | Border direction or numeric angle; default `above` |
| `labelDistance` | `number?` | Gap from the border (user units); default 12 |
| `labelPin` | `boolean?` | Draw a leader line from the border to the label; default false |
| `resolveLabel` | `(row) => string?` | Runtime template escape hatch (not in IR, needs `id`); overrides `label` / `labelFormat` |

Standalone `<TextMark>` (free text):

| prop | type | notes |
| --- | --- | --- |
| `x` / `y` | `string?` | Position fields (project like a point; under polar reinterpreted as angle / radius) |
| `a` / `b` / `c` | `string?` | ternary2D component fields |
| `text` | `string` | Text content field (required) |
| `format` | `string?` | Number / time format string; only used with the `text` field |
| `color` | `string?` | Text color field (colored by category, applied to node text color) |
| `dx` / `dy` | `number?` | Pixel-level fine-tuning from the anchor; prefer the host label's position / distance |
| `resolveLabel` | `(row) => string?` | Runtime template escape hatch (not in IR, needs `id`); overrides `text` / `format` |
| `id` | `string?` | Optional handle; `resolveLabel` injection matches on this id |
