---

`<Plot>` 是 plot 体系的容器组件：它接收 `data`（裸数据行数组）和显示尺寸，收集内部的 `<LineMark>` / `<BarMark>` / `<SectorMark>` / `<Axis>` / `<Scale>` 等子组件，编译期再装配成 PlotSpec 并下沉到 core。数据不写进 IR，只在 lowering 时注入。`<Plot>` 自己不画坐标轴、网格或图例；这些 guide 由你显式声明，scale 会自动推断，也可以用 `<Scale>` 覆盖；坐标系默认 `cartesian2D`，可用 `coordinate` 切换。

## 用法

```tsx
import { Axis, BarMark, Plot } from '@retikz/plot-react';
```

```tsx
<Plot data={revenue} width={360} height={220}>
  <BarMark x="quarter" y="value" />
  <Axis dimension="x" />
  <Axis dimension="y" grid />
</Plot>
```

`width × height` 是整张图的外框，包含绘图区、坐标轴和刻度标签。子组件只声明字段映射与 guide，不写像素坐标；如果只想画数据层，可以省略 `<Axis>` / `<Legend>` 这类 guide 子组件。

## 例子

### 坐标系

`coordinate` 决定单张 `<Plot>` 内部怎么投影数据。缺省是 `cartesian2D`；同一份数据也可以切到 `polar2D`，在另一套坐标系下解释同样的字段映射。

<ComponentPreview name="plot-coordinate" sourceFiles={['plot-cartesian.data.ts']} size="md" />

<p className="text-sm text-muted-foreground">左：cartesian 柱图；右：同一份数据切成 polar2D 径向柱图。</p>

`coordinate` 支持字符串简写和对象两种形态，覆盖坐标系族：

```tsx
<Plot coordinate="polar2D">                                    {/* 极坐标（饼 / 雷达 / 径向柱） */}
<Plot coordinate={{ type: 'polar2D', innerRadius: 0.5 }}>      {/* 挖中心成环图 */}
<Plot coordinate="cartesian1D">                                {/* 一维直线（rug / timeline） */}
<Plot coordinate="polar1D">                                    {/* 一维圆周（周期数据） */}
<Plot coordinate="ternary2D">                                  {/* 三元（重心坐标） */}
```

各坐标系的几何配置（polar 的 `innerRadius` / `startAngle` / `endAngle`、cartesian1D 的 `orientation`、polar1D 的 `radius` 等）与适用的 mark / 通道见 [坐标系](/plot/grammar/coordinate)。

### 比例尺

默认 scale 来自字段值和 mark 类型：数字走连续轴，普通字符串走分类位置，ISO 日期走时间轴。需要对数轴、平方根轴或手动 domain 时，在 `<Plot>` 里写 `<Scale>` 子组件覆盖对应维度。

### 颜色系

`colors` 控制整张 `<Plot>` 的默认颜色数组。省略时使用 d3 的 `schemeCategory10`；传入自己的数组后，分类 `color` 通道会把它作为 range，没有 `color` 编码的 mark 也会按图层顺序取色，超过数组长度后循环。数组里写 `'currentColor'` 表示该层保持 core 继承色。

### 数据模型

真实数据的字段名经常和图表里的逻辑字段名不同。`model` 声明图表需要的逻辑字段及类型，`fieldMap` 再把这些逻辑字段映射到真实数据路径；mark 始终引用逻辑名。

### 面板组合

同一个父级 `<Layout>` 可以放多张 `<Plot>`。每张图用自己的 `width` / `height` 决定外框，再用 `x` / `y` 或 `transforms` 在父画布中摆位；父级只负责承载和组合，不参与子图的 scale 推断。

<ComponentPreview name="plot-panels" sourceFiles={['plot-cartesian.data.ts']} size="md" />

<p className="text-sm text-muted-foreground">左：cartesian 折线图；右：同一个 Layout 里的 cartesian 柱状图。</p>

`width` / `height` 仍是每张图自己的外框尺寸；父级 `<Layout>` 的尺寸只决定整张组合图的画布。

### 入口形态

`<Plot>` 有两条入口，按是否传 `spec` 分流：

| 入口 | 必填 | 适用 |
| --- | --- | --- |
| 组合 DSL | `data`（裸数组）+ `children` | 手写 JSX 声明 mark / guide / scale（最常用） |
| spec 入口 | `spec`（已构造 PlotSpec）+ `data`（数据集表） | 持久化 / 外部生成的完整 spec 直喂 |

当图表配置来自持久化 JSON 或外部生成结果时，可以直接传 `spec`。数据仍然单独通过 `data` 表注入，不写进 PlotSpec。

## 技术原理

> 上手阶段可跳过本节；想理解 `<Plot>` 怎么被编译，或要直接写 / 生成底层 IR 时再回来读。

`<Plot>` 自己不画任何图元。组合入口会先把 children（mark / guide / scale / coordinate）装配成一棵 **PlotSpec**——Tier 2 的高层 IR（全 JSON 可序列化，数据不在其中）；编译期再经 **lowering** 把 PlotSpec 下沉成 `@retikz/core` 的 Tier 1 IR（`<Scope>` / `<Node>` / `<Path>`），最后由 core 编译成 Scene 交给 renderer。spec 入口跳过装配，直接喂 PlotSpec。

下沉不是 `<Plot>` 私有逻辑，而是注册进 core 编译管线的一个 **composite**：core 见到 PlotSpec 节点就调用它的展开函数，与 core 处理任何高层节点同源——上层不另造平行渲染。

### 下沉每一步

数据与 PlotSpec 一起进入下沉，按下表逐步变成 Tier 1：

| 步骤 | 输入 | 产物 |
| --- | --- | --- |
| 解析数据 | `data.reference` 取数据集 + `model` / `fieldMap` | 归一化数据行（类型推断、改名、transform） |
| 推断 scale | 各通道绑定字段 + 坐标系 | band / linear / time / log… scale 与投影帧 |
| 逐 mark 成层 | 每个 `<LineMark>` / `<BarMark>` … | 一个 core `<Scope>` 图层（内含 `<Node>` / `<Path>`） |
| 轴 / 网格 / 图例成层 | 显式 `<Axis>` / `<Legend>` | 网格层、轴层、图例层（各是 `<Scope>`） |
| 编排 z-order | 上面所有层 | 网格垫底 → mark → 轴 → 图例 |

所有层包进一个隔离命名空间的 `<Scope>`，每张图的内部 id（datum / series）互不串扰。

### 可组合的面板

当 PlotSpec 带 `id`（spec 入口或生成的 IR）时，下沉额外包一层**外部可见**的面板 `<Scope>`：面板 bbox 用 `<plotId>` 注册、绘图区用 `<plotId>.plotArea` 注册，二者都落在隔离命名空间之外。同级节点能锚到它们连线 / 标注，从而把多张图组合进一张大图。

## API

| 属性 | 类型 | 默认值 | 描述 |
| --- | --- | --- | --- |
| `data` | `Array<Row>` | — | 裸数据行数组（组合 DSL 入口）；数据不进 IR |
| `children` | `ReactNode` | — | mark / guide / scale 子组件（组合 DSL 入口） |
| `model` | `DataModel` | — | 数据模型（字段名 + 类型）：声明则启用 strict 校验与 type-driven scale / guide 派生；详见[数据模型](/plot/data/model) |
| `fieldMap` | `Record<string, string>` | — | 逻辑字段名 → 数据里的实际路径（需配合 `model`）；只改名、不变换值；详见[数据处理](/plot/data/processing) |
| `coordinate` | 见[坐标系](/plot/grammar/coordinate) | cartesian2D | 坐标系：`"polar2D"` / `"cartesian1D"` / `"polar1D"` / `"ternary2D"` 简写或对应对象配置；缺省平面直角 |
| `colors` | `Array<string>` | `schemeCategory10` | 默认调色板。分类颜色 scale 会把它作为 range；没有颜色编码的 mark 按图层顺序取色，超过后循环。写 `'currentColor'` 表示保持 core 继承色 |
| `id` | `string` | — | 面板 id：写入 PlotSpec.id，作为外部 anchor 句柄；嵌入态未显式 `dataRef` 时也作为默认数据集引用 |
| `dataRef` | `string` | — | DSL 入口的数据集引用名；多张 Plot 共享同一数据源时可显式设为同名 |
| `width` | `number` | — | 外框宽度（含轴与标签）；也写入 PlotSpec 自描述尺寸 |
| `height` | `number` | — | 外框高度（含轴与标签）；也写入 PlotSpec 自描述尺寸 |
| `x` / `y` | `number` | — | 父级 `<Layout>` 内的面板左上角位置；会转成外层 `translate` |
| `transforms` | `Array<IRTransform>` | — | 面板级变换；与 `x` / `y` 可叠加，常用于更细摆位 |
| `zIndex` | `number` | `0` | 面板在父级层级中的绘制顺序 |
| `clip` | `IRClipSpec` | — | 面板级裁剪区域 |
| `fontSize` | `number?` | — | 刻度标签字号 |
| `margin` | `{ top?; right?; bottom?; left? }` | — | 覆盖四周留白 |
| `spec` | `PlotSpec` | — | spec 入口：已构造好的 Plot IR 根（与 `children` 二选一） |

此外 `renderer` / `className` / `style` 透传给底层 `<Layout>`，分别选渲染后端、附加类名、内联样式。
