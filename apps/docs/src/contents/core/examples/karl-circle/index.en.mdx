## Introduction

This is the final figure from the [TikZ tutorial](https://tikz.dev/tutorial) — "Karl teaching his daughter trigonometry": a unit circle plus the sin / cos / tan geometry around a 30° angle.

The page breaks it into 7 accumulative steps. From a single naked circle each step adds one visible element and one retikz capability — by the end you have the full figure and have also seen the three most beginner-friendly sugars: [Circle](/core/components/shapes/circle-ellipse) / [Grid](/core/components/helpers/grid) / [Sector](/core/components/shapes/arc-sector). They shorten the hand-written Path / Step pieces, while [Draw](/core/components/draw/overview) / [Coordinate](/core/components/node/coordinate) / [Node](/core/components/node/overview) keep building the full figure, plus polar positions, multi-Draw coordination, and multi-line / multi-color Node text.

<ComponentPreview name="karl-circle-07-info" size="lg" interactive />

If you are coming from TikZ, watch five differences in this page: retikz coordinates grow downward on y; circle / grid / sector now have dedicated sugar; projections / intersections are currently hand-computed or named with Coordinate; `foreach`-style repeated primitives are usually generated with React `.map()`; and formulas are no longer plain-text fallbacks but LaTeX written with [@retikz/tex](/core/packages/tex)'s `<TexNode>` (standalone / framed math is supported; inline text+math mixing is still pending).

## Steps

### Step 1 — Unit circle

Minimal start — one circle centered at the origin. Use [Circle](/core/components/shapes/circle-ellipse) here: `center + radius` keeps the first step short, and it still expands to the same underlying Path / Step shape, but the code reads like “this is a circle” at a glance. `lineCap="round"` softens the line endpoints.

<ComponentPreview name="karl-circle-01-circle" size="lg" />

### Step 2 — Axes + endpoint labels + named anchors

x and y axes use [Draw](/core/components/draw/overview) with `arrow="->"` to get arrow-tipped segments. The `x` / `y` labels at the axis ends are now [@retikz/tex](/core/packages/tex) [`<TexNode>`](/core/packages/tex)s rendering math-italic letters (`stroke="none"` hides the default border), placed just past each axis. This is the first formula on the page, so **from this step on every demo calls `useLowerTex()` to start MathJax and injects `<Layout lowerTex>`**; without it, nodes carrying tex degrade silently (no formula) instead of crashing. [Coordinate](/core/components/node/coordinate) names the two endpoints (`x-axis` / `y-axis`) so later steps could reference them by id string — this example doesn't end up using them, but we keep them for fidelity to TikZ's `coordinate(x axis)` idiom.

<ComponentPreview name="karl-circle-02-axes" diffFrom="karl-circle-01-circle" size="lg" interactive />

### Step 3 — Grid + ticks

The background grid now uses [Grid](/core/components/helpers/grid) sugar, which expands to many lines for you. Ticks are also array-driven: a short segment plus a transparent [`<TexNode>`](/core/packages/tex) per tick; `−1/2` / `1/2` are no longer the plain string `-1/2` but real fractions rendered from `-\frac{1}{2}`. The label sits **slightly offset** from its tick (x-axis labels nudged 10px left, y-axis labels 10px down) so they don't clash with the circle or axis lines, and the step reads like “give me a grid” instead of “assemble 10 lines.” 
retikz coordinates are SVG pixels with y pointing downward — so "1 unit up" is written as `[0, -100]` (this example uses 100px = unit-circle radius as the length basis). The top-level `<Layout>` has no picture-level scale or y-flip, so math coordinates from the TikZ tutorial need their y manually negated.

<ComponentPreview name="karl-circle-03-ticks" diffFrom="karl-circle-02-axes" size="lg" interactive />

### Step 4 — 30° wedge + α label

The wedge is the trickiest step. Use [Sector](/core/components/shapes/arc-sector) here: it starts from the center, draws the arc, and closes back to the center, so the intent reads more directly than a hand-written `arc` + `line` path, and it is easier for a first-time reader to remember as one clear API.

The α label is a [`<TexNode>`](/core/packages/tex) writing `\alpha` (a real Greek letter) at a polar position (`{ angle, radius }`) — `{ angle: -15, radius: 22 }` places it visually centered in the wedge (a negative angle points toward the top of the screen). Its color comes from `textColor` (one TexNode renders in a single color — see Step 7).

<ComponentPreview name="karl-circle-04-wedge" diffFrom="karl-circle-03-ticks" size="lg" interactive />

### Step 5 — sin α red line + cos α dodgerblue line

`sin` drops from (30°, 100px) vertically to the x-axis; `cos` goes from that foot back to the origin. Both use [Draw](/core/components/draw/overview), with a `{ label: { text, side } }` operator threaded into the `way` array to attach an edge label. `thickness="thick"` is a semantic stroke preset — saves having to pick a numeric width.

Note: the original TikZ uses `(30:1cm |- x axis)` to express "horizontal projection of (30°, 1cm) onto the x-axis" directly. retikz has no projection target yet — geometrically that equals (cos30°, 0), so we hand-compute the coordinate.

<ComponentPreview name="karl-circle-05-sin-cos" diffFrom="karl-circle-04-wedge" size="lg" interactive />

### Step 6 — tan α darkorange line + auxiliary ray

The tan line goes from (1, 0) up to (1, tan30°). The original uses TikZ's `name path` + `name intersections` to compute "intersection of x=1 vertical and 30° ray from origin"; retikz has no such constructs, so we hand-compute (1, tan30°) and name it `t` via [Coordinate](/core/components/node/coordinate). The auxiliary ray from the origin through `t` then just references the id.

The pattern here — multiple [Draw](/core/components/draw/overview)s coordinating through shared named anchors — is retikz's standard way to wire up a multi-segment figure.

<ComponentPreview name="karl-circle-06-tan" diffFrom="karl-circle-05-sin-cos" size="lg" interactive />

### Step 7 — Right-hand multi-color info box

Finally, a colored legend on the right. We want the four values as real formulas (`\frac{\sqrt{3}}{2}` / `\frac{1}{\sqrt{3}}` / `\frac{\pi}{6}`), but two tex constraints bite: **one [`<TexNode>`](/core/packages/tex) renders in a single color** — `\color{}` is not honored by the current lowering, so the whole glyph block takes `textColor` — and **MathJax's `\text{}` tends to tofu out on CJK**. So the legend can't be one multi-color / CJK-annotated formula block; instead **each row is its own `<TexNode displayMode>` with its own color** (green / red / dodgerblue / darkorange, one per function line), and the old "(red segment length)" caption rows are dropped — the colors already tie each value back to its line.

The frame is a separate rectangle [Node](/core/components/node/overview) (`dashed` + `stroke="lightgray"` + `cornerRadius`, no fill, visible in both themes) sitting underneath; the four formula rows stack on top in source order, and the frame reserves space via `minimumWidth` / `minimumHeight`. Putting colored formulas and CJK captions on the same line needs inline text+math mixing (see Limitations).

## Limitations

| Capability | Plan | Status / fallback |
| --- | --- | --- |
| Math y-up axis | 🚧 Planned | scaling itself works via a Scope `scale` transform, but there's no `<Layout>`-level y-up switch yet (a negative `y` scale flips text too); the example writes pixel coordinates with manual y negation |
| Projection target (`(A \|- B)`) | 🚧 Planned | hand-compute `[cos30 * 100, 0]` |
| Named path + intersection target | 🚧 Planned | hand-compute `[100, -tan30 * 100]` |
| In-line spans inside LineSpec | 🚧 Planned | color switches only at line granularity; `spans` field planned |
| Standalone / framed LaTeX math | ✅ Supported | this example uses [@retikz/tex](/core/packages/tex)'s `<TexNode>` for x / y, tick fractions, α, and the right-hand legend formulas |
| Multi-color inside one TexNode (`\color{}`) | ❌ Not supported | a TexNode is single-color as a whole; split into per-row TexNodes with their own `textColor` for multiple colors |
| Inline text+math mixing (edge labels / formula inside a text line + CJK) | 🚧 Planned (ADR-03 deferred) | edge labels (`sin α` …) and mixed caption rows stay plain text; standalone / framed formulas use TexNode |
