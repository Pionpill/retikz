title: Ribbon
description: Kernel band path — generate a fillable variable-width area from an open centerline, for Sankey and alluvial ribbons.
---

`<Ribbon>` draws an area, not a variable `strokeWidth`. Like `<Path>`, it uses `<Step>` children for the centerline, but compile offsets both sides of that line by `width`, closes the outline, and fills the resulting Path primitive.

This gives plot-level Sankey charts, alluvial diagrams, and any “wide at the source, narrow at the target” link a core capability. SVG / Canvas renderers still receive an ordinary closed path.

## Usage

```tsx
import { Ribbon, Step } from '@retikz/react';
```

```tsx
<Ribbon start={{ width: 32 }} end={{ width: 12 }} fill="#60a5fa">
  <Step kind="move" to="source" />
  <Step kind="cubic" control1={[80, 0]} control2={[160, 80]} to="target" />
</Ribbon>
```

Use `<Draw>` / `<Path>` for a line, arrow, dash, or path label. Use `<Ribbon>` when the visible object is a filled band and its width needs to change along the centerline.

## Composition

`<Ribbon>` requires `<Step>` children, and those steps must form one open centerline. `cycle`, multiple `move` subpaths, and zero-length centerlines fail during compile.

```tsx
<Ribbon width={24}>
  <Step kind="move" to={[-120, 0]} />
  <Step kind="line" to={[120, 0]} />
</Ribbon>
```

The centerline is only used to build the ribbon outline. `stroke` / `strokeWidth` outline the ribbon polygon; they do not stroke the centerline.

When a layout algorithm already computed both sides, use `kind="boundary"` and place the two open boundaries in `<Ribbon.Upper>` and `<Ribbon.Lower>`. This mode does not use `width`.

```tsx
<Ribbon kind="boundary" fill="#bfdbfe">
  <Ribbon.Upper>
    <Step kind="move" to={[-120, -20]} />
    <Step kind="curve" control={[0, -40]} to={[120, -10]} />
  </Ribbon.Upper>
  <Ribbon.Lower>
    <Step kind="move" to={[-120, 20]} />
    <Step kind="curve" control={[0, 48]} to={[120, 34]} />
  </Ribbon.Lower>
</Ribbon>
```

### Alignment And Caps

`align` places the centerline at the middle, left boundary, or right boundary. `start.cap` / `end.cap` control how the two ends close.

<ComponentPreview name="ribbon-align-cap" size="md" />

| cap type | Effect | Common use |
| --- | --- | --- |
| `butt` | Connects both ribbon sides directly without extending the endpoint. | Default flat end; bands that meet rectangular node edges. |
| `round` | Draws an automatic semicircle using the midpoint between both sides as the center. | Standard rounded end without choosing a center manually. |
| `square` | Extends along the endpoint tangent before closing with a straight edge. | Ends that should project past the centerline, similar to a square line cap. |
| `{ type: 'arc' }` | Closes the endpoint with an arc from explicit `center` and `radius`; `sweep` chooses short or long arc. | Sankey bands that meet circular or curved node boundaries, or any cap that needs a custom center. |

## How it works

> Optional for everyday use; revisit when you hit edge cases or want to understand why Ribbon has no arrows or dashes.

### Lowering to a Closed Path

The compiler first resolves the `<Step>` sequence into one open centerline. When `samples` is omitted, fixed-width ribbons and `start.width` / `end.width` endpoint tapers are lowered to structured Path commands first: the generated boundaries still use `line` / `quad` / `cubic`, so SVG and Canvas can use their native path APIs directly.

When `samples` / `sampling` is provided, or when the ribbon uses along-path width rules such as `width.kind="stops"` or registered profiles, the compiler switches to cross-section sampling. At each sample it computes the tangent, derives a normal, asks either `start.width` / `end.width` or top-level `width` for the local width, offsets left and right by half that width, and closes the resulting polyline outline. Sampling is also useful for tight curves or arc / ellipseArc segments that are not yet lowered as exact path offsets.

The renderer still sees a normal closed path: `fill` paints the band area, and `stroke` outlines the boundary. The first Ribbon version does not support arrow, dash, marks, or path labels because those belong to centerline stroke semantics.

### Custom Width Profiles

IR cannot store functions. Custom rules use `width={{ kind: 'profile', name, params }}` to reference a runtime registry. The host registers `defineRibbonWidthProfile(...)` through `<Layout ribbonWidthProfiles={...}>` or compile options, and compile calls `widthAt` for each normalized offset.

## API Reference

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `kind` | `'centerline' \| 'boundary'` | `'centerline'` | Construction mode; the default derives an area from a centerline and `width`, while `boundary` uses explicit upper and lower sides. |
| `start` | `{ width?, direction?, cap?: 'butt' \| 'round' \| 'square' \| { type: 'arc', center, radius, sweep? } }` | — | Start endpoint configuration: endpoint width, tangent direction, and cap. |
| `end` | `{ width?, direction?, cap?: 'butt' \| 'round' \| 'square' \| { type: 'arc', center, radius, sweep? } }` | — | End endpoint configuration: endpoint width, tangent direction, and cap. |
| `interpolation` | `'linear' \| 'smooth'` | `'linear'` | Transition curve between `start.width` and `end.width`; only used for endpoint taper. |
| `width` | `number \| { kind: 'stops', stops, interpolation? } \| { kind: 'profile', name, params? }` | — | Whole-centerline width rule. Use it for fixed width or custom mid-width profiles; do not combine it with `start.width` / `end.width`. |
| `align` | `'center' \| 'left' \| 'right'` | `'center'` | Where the centerline sits relative to the band; `left` / `right` makes it one boundary. |
| `samples` | `boolean \| number` | automatic | Sampling override; `true` uses 64 cross-sections, a number uses that fixed count in `2..512`. Omitted means structured path lowering is tried first, while `stops` / profile width rules auto-sample. |
| `sampling` | `{ kind: 'fixed', samples } \| { kind: 'adaptive', tolerance, maxSamples? }` | — | Explicit sampling strategy. Cannot be combined with `samples`. |
| `fill` | `string \| PaintSpec` | `currentColor` | Fill for the ribbon area: solid color, gradient, pattern, or image. |
| `fillOpacity` | `number` | — | Opacity for fill only. |
| `stroke` | `string \| PaintSpec` | — | Optional outline stroke paint; omitted means no outline. |
| `strokeWidth` | `number` | — | Optional outline stroke width; if set alone, outline color is `currentColor`. |
| `drawOpacity` | `number` | — | Opacity for the outline stroke. |
| `opacity` | `number` | — | Whole-ribbon opacity. |
| `shadow` | `ShadowPreset \| DropShadow` | — | Shadow applied to the emitted closed path. |
| `blendMode` | `BlendMode` | — | Blend mode applied to the emitted closed path. |
| `zIndex` | `number` | — | Explicit stacking order among sibling children. |
| `children` | `Array<Step>` | — | Open centerline step sequence for centerline mode, at least 2 steps. |
| `upper` / `lower` | `Array<Step>` | — | Open upper and lower boundaries for `boundary` mode; React DSL uses `<Ribbon.Upper>` / `<Ribbon.Lower>`. |
