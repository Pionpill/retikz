这一分组讲怎么**扩展** retikz：内置组件覆盖不到的能力，通过运行时注入的扩展点补上。读者是发第三方包、做宿主集成、或给 retikz 加新基元的人——日常画图从 [组件](/kernel/components/layout) 开始即可。

> 扩展点都是**宿主 / 编译期能力，不写进 IR**——IR 始终是可序列化的纯数据（LLM / 持久化友好），扩展定义经 `CompileOptions` / 组件 props 在运行时注入。

## 职责一览

| 主题 | 扩展什么 | 何时用 |
| --- | --- | --- |
| 自定义形状 | 注册新的节点形状（`ShapeDefinition` + `CompileOptions.shapes`）| 内置 6 注册形状 + 2 preset 之外要 cylinder / cloud 等（hexagon 已可用内置 `polygon{ sides:6 }` 表达） |
| 自定义箭头 | 注册新的箭头样式（`defineArrow` / `ArrowDefinition` + `CompileOptions.arrows`） | 需要 bracket / 业务箭头等新端点样式 |
| 自定义图案 | 注册新的填充图案（`definePattern` / `PatternDefinition` + `CompileOptions.patterns`） | 需要 cross / 条纹 / 特殊 motif |
| 自定义路径 | 注册新的 Path kind（`definePathKind` / `PathKindDefinition` + `CompileOptions.pathKinds`） | 需要把整条 Path 当作高亮、双线、业务关系或其它关系形态处理 |
| 路径生成器 | 注册新的曲线生成器（`PathGeneratorDefinition` + `CompileOptions.pathGenerators`） | 需要 parabola / 波形 / 自定义曲线 |
| 复合（Tier 2） | 注册 Tier 2 高层节点（`CompositeDefinition` + `CompileOptions.composites`） | domain 包把高层节点 lowering 成 Tier 1 基础图元，详见 [复合](/kernel/reference/composites) |
| 自定义缓动 | 注册新的缓动曲线（`EasingRegistry` + `<Layout easings>`） | 需要 spring 等内置之外的缓动曲线 |
| 自定义动画属性 | 注册新的动画属性通道（`AnimationPropertyDefinition` + `<Layout animationProperties>`） | 需要 blur 等内置之外的动画属性 |

## 三类扩展模型

扩展点按机制分三类；判断一个能力属于哪类，就知道它怎么定义、何时生效：

- **Definition 扩展**（形状 / 箭头 / 图案 / 自定义路径 / 路径生成器 / 复合）：用 `xxxDefinition` 定义，经 `CompileOptions` / `<Layout>` 注入，编译期生效，IR 里只留名字。形状 / 箭头 / 图案 / 自定义路径 / 路径生成器按名注入（`Record<string, …>`，内置同名被覆盖或替换）；复合是 `Array<CompositeDefinition>`，按 `namespace` + `type` 判别，重名直接报错。
- **Registry 扩展**（缓动 / 动画属性）：注入面是 `<Layout>` 的轻量 registry，运行时在渲染器内生效，不进 compile。缓动没有 `EasingDefinition`——值就是 cubic-bezier 元组或函数；动画属性要同时定义插值与后端落地，才用 `AnimationPropertyDefinition`。
- **Host lowerer**（TeX 公式）：`CompileOptions.lowerTex` 是可选宿主能力，把公式在编译期降成基础 path，不属于通用图元扩展；缺失时可诊断降级。
