A `path` is the outer container for a drawn line. Its `children` field is an ordered array of `Step` actions; the renderer walks them sequentially to produce SVG path commands. Each step's destination is a `Target`.

## DrawableStyle

`DrawableStyleSchema` is the shared geometry-style field set for Path kinds. The default `stroke` kind maps `color` to stroke; the built-in `ribbon` kind maps `color` to fill. `pathDefault` also uses this subset when it styles path-like drawables.

<ZodSchema name="DrawableStyleSchema" />

## DrawableMeta

`DrawableMetaSchema` groups shared identity, provenance, animation, and stacking fields for Path. `id` / `meta` / `animations` are instance metadata and do not enter `pathDefault`; `zIndex` participates in sibling ordering but is not inherited as a default style.

<ZodSchema name="DrawableMetaSchema" />

## PathRibbonOptions

`PathRibbonOptionsSchema` configures the built-in `kind: 'ribbon'` path provider. Centerline mode reads normal Path children; boundary mode reads `upper` / `lower` step arrays from this object and does not use `children`.

## GeometryLabel

`GeometryLabelSchema` is the shared label contract for path-like hosts. `StepLabelSchema` is an alias of this schema; drawn steps and centerline ribbon labels reuse the same fields.
It describes label text, normalized position along the host segment or centerline, and tangent / normal-side placement.

<ZodSchema name="GeometryLabelSchema" />

## Target

`TargetSchema` is the union for path endpoints: Cartesian / polar / node target object `{ id, anchor?, offset?, boundary? }` / offset placement `{ of, offset }` / proportional placement `{ between, t }` / relative offsets (relative / relativeAccumulate). In the node target object, `boundary?` overrides the connection surface this single endpoint clips to (defaults to the node's own `boundary`, i.e. `shape`); `anchor?` auto-clips to the boundary when omitted. Node id strings are React DSL shorthand and are parsed into objects before reaching the IR:

<ZodSchema name="TargetSchema" />

For the endpoint rules of proportional placement, see [Placement](/kernel/reference/schema/placement#betweenposition): `between` endpoints must be self-contained and do not accept path-relative targets.
