`<Path>` `kind` is an **open string**: beyond the built-in `stroke` and `ribbon` kinds, you can register your own path kind. Custom paths are for cases where the whole Path needs a different Scene output, such as highlight underlays, double-line relations, domain-specific relation lines, wide arrows, or future path forms.

Registration goes through `CompileOptions.pathKinds` (in React, `<Layout pathKinds={...}>`): the IR only stores `kind` plus JSON-only `kindOptions`; the provider function is injected by the host at runtime and never enters the IR.

## API

| Field | Type | Description |
| --- | --- | --- |
| `kind` | `string` | Registry name; `Path.kind` uses it to find the provider |
| `optionsSchema` | `ZodType<IRJsonObject>` | Optional; validates `kindOptions`, whose output still must be JSON-safe |
| `compile` | `(context) => PathKindCompileResult \| null` | Compiles the whole Path into Scene primitives and sampled points; `null` means no output |

The `PathKindCompileContext` passed to `compile`:

| Field | Type | Description |
| --- | --- | --- |
| `path` | `IRPathBase` | Full IR data for the current Path |
| `options` | `TOptions` | `kindOptions` after `optionsSchema` validation |
| `emitStroke` | `(path?) => PathKindCompileResult \| null` | Reuse the built-in stroke lowerer, optionally with a patched Path |
| `emitRibbon` | `(path?) => PathKindCompileResult \| null` | Reuse the built-in ribbon lowerer, optionally with a patched Path |

## Difference from path generators

A custom path owns the **whole Path**: it decides what primitives that Path emits, so it is the right place to change relation form or reuse a built-in lowerer and rewrite the result.

A path generator owns only **one `generator` step**: it converts a curve segment into low-level `PathCommand[]`, then the current Path kind still compiles the whole Path. Use [Path Generators](/kernel/reference/extending/path-generator) for new curve segments; use custom paths for new whole-path providers.
