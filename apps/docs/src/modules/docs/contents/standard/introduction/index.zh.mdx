标准库（Library）组承载不应进入最小 Core、但适合跨领域复用的官方绘图能力。Grid、Axes、Frame 与 Legend 等呈现组件用紧凑配置下沉为 Core 图元；FlexLayout、GridLayout 与 OverlayLayout 则在 Core layout-aware composite 契约上提供通用布局容器。Standard Logic 增加领域无关的 `LogicBlockBase`、语义单元、`Connector` 与 `Callout` 词汇。

## 与 Core 的边界

标准库是 Core 的横向扩展，不是新的绘图内核。每项 Tier 2 能力拥有 JSON-safe schema 和 lowering，但不另造基础 IR、几何底座或 renderer 语义。

这意味着：

- 不使用标准库时，Kernel 的安装、编译和渲染路径保持不变。
- 能力按图加载，Definition 不做全局注册，也不会写入持久化 JSON。
- Standard IR 下沉后仍由 Core compile，并交给既有 SVG、Canvas 等 renderer。

## 三个发布包

| 包                         | 负责什么                                    | 什么时候使用                          |
| -------------------------- | ------------------------------------------- | ------------------------------------- |
| `@retikz/standard`         | schema、factory、Definition 与 lowering     | 校验或持久化 IR，直接接入 Core 编译   |
| `@retikz/standard-react`   | 呈现组件与 `<FlexLayout>` 等 React DSL      | 在 `@retikz/react` 的 `Layout` 中使用 |
| `@retikz/standard-vanilla` | plain spec helper 与 Vanilla Tier 2 adapter | 无 React 的浏览器或脚本入口           |

三个包共享 `@retikz/standard` 中的同一套 schema 与 lowering。React 和 Vanilla 只负责把各自的作者输入接到这套能力上，不复制语义。

## 加载方式

| 场景      | 加载方式                                                                                         |
| --------- | ------------------------------------------------------------------------------------------------ |
| React     | 组件在当前 `Layout` 局部贡献对应 Definition；`ir` 模式显式传 `composites`                        |
| Vanilla   | helper 生成 embed，宿主传入部分 adapter 或 `StandardVanillaAdapters`；直接 IR 显式传 definitions |
| 持久化 IR | schema 校验 JSON，宿主通过 `CompileOptions.composites` 选择并注入 definitions                    |

从 [快速开始](/standard/get-start) 查看三条完整路径，从 [展现](/standard/composite) 或[布局容器](/standard/layout)选择能力，在 [Legend](/standard/composite/legend) 中组合已解析样本与含义，或在[Definition 接入](/standard/extension/capability-loading)中了解如何将当前图所需能力传给 Core。

从[逻辑组件](/standard/logic)了解逻辑家族。它拥有 authored target 契约、显式路由与相对 target 的放置，但不拥有 `GraphModel`、自动布局、自动避障或交互。
