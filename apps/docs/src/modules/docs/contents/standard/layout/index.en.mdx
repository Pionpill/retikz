title: Layout containers
description: Replace hand-authored coordinates with FlexLayout, GridLayout, and OverlayLayout to compose reusable graphical layouts.

Standard layout containers extract child arrangement from hand-authored coordinates. They cover linear distribution, two-dimensional tracks, and stacking within one region, and they compose recursively. Domain packages such as Plot, Table, and future Gantt packages can reuse them internally while retaining ownership of domain semantics.

Given the same available space and child measurement, layout solving is deterministic and independent of a specific renderer. Text dimensions still depend on the host measurer, fonts, and font-loading state.

The example below uses Flex for lines, Grid for columns, and Overlay for a badge in the right-hand cell to show how all three containers compose as ordinary children.

This example enables layout guides for the whole figure with `<Layout inspect={{ layout: true }}>`. Use a container's own `inspect` prop for one occurrence, or declare `<Scope inspect={{ layout: true }}>` to affect one authored subtree.

## Responsibilities

| Component       | Core model                     | Best suited for                                |
| --------------- | ------------------------------ | ---------------------------------------------- |
| `FlexLayout`    | One axis, grow/shrink, wrap    | Legend entries, label strips, toolbars         |
| `GridLayout`    | 2D tracks, spans, auto placing | Panels, matrices, guide regions, structured UI |
| `OverlayLayout` | Alignment or local positioning | Badges, overlays, annotations, stacked marks   |

Containers own generic size distribution, spacing, alignment, overflow, and observable results. Data channels, chart semantics, table rules, and algorithmic layout remain with their domain packages.
