布局 schema 只保存容器与子项配置；Definition、Core 编译上下文和适配器属于运行时。Standard 负责通用布局求解，Core 负责对子图形提出双轴空间条件、隔离测量候选、回放最终候选并发布类型化产物。

> 这里解释 Definition 接入与执行逻辑，不重复 schema 字段。持久化配置见[输入契约](/standard/layout/reference/contract-input)，求解结果见[产物契约](/standard/layout/reference/contract-artifact)。

## 如何接入 Definition

| 粒度     | 公开入口                                                                  | 用途                                              |
| -------- | ------------------------------------------------------------------------- | ------------------------------------------------- |
| 单一定义 | `FlexLayoutDefinition`、`GridLayoutDefinition`、`OverlayLayoutDefinition` | 只向 Core 注册一个布局复合组件                    |
| React    | `FlexLayout`、`GridLayout`、`OverlayLayout`、`LayoutItem`                 | 从组件树生成规范 IR，并向外层 `<Layout>` 贡献定义 |
| Vanilla  | `StandardLayoutVanillaAdapters`                                           | 让 Figure、挂载与 SSR 入口识别三种布局嵌入项      |

将一个或多个布局 Definition 直接放入 `CompileOptions.composites`。React 与 Vanilla 适配器生成相同的 Standard IR，并贡献所需的 Definition；adapter 便利数组不成为 Standard compile preset

## 一次布局事务

布局容器是 Core 的布局感知复合组件。一次编译会按确定顺序完成以下阶段：

1. **解析输入**：Core 按 `namespace` 与 `type` 找到 Definition，并使用对应 schema 校验规范 IR。
2. **测量子图形**：容器通过 `layoutChild` 请求子图形的最小、自然、范围或精确尺寸候选。候选携带父级求值后的 `slotSize`、真实 `allocationBounds`、`visualBounds` 和可用对齐参考线。
3. **求解容器**：Standard 的纯求解器根据容器规则、可用空间和候选测量结果决定轨道、布局行、分配区域与平移。
4. **回放最终候选**：每个子图形只回放被选中的候选；未选候选不会发布图元、资源、命名空间或产物。
5. **发布结果**：Core 把 Standard 返回的值封装为带 occurrence 的复合组件产物，与最终 Scene 一起返回。

固定几何可以拒绝过小的分配区域，因此 `slotSize` 与真实 `allocationBounds` 必须分开观察。容器不会因为拒绝而重新猜测主轴尺寸；可确定的尺寸不足通过溢出状态和可见边界表达，无效或无法求解的配置则直接报错。

嵌套布局仍属于同一次 Core 编译。内层容器作为普通子图形接受外层空间提案，每次复合组件出现（occurrence）分别发布本地 key 空间中的产物，不依赖公开 id 选择实例。

## 直接使用 Core

```ts
import { compileToScene } from '@retikz/core';
import {
  FlexLayoutArtifactSchema,
  FlexLayoutDefinition,
  GridLayoutDefinition,
  OverlayLayoutDefinition,
} from '@retikz/standard';

const output = compileToScene(scene, {
  composites: [FlexLayoutDefinition, GridLayoutDefinition, OverlayLayoutDefinition],
});
const envelope = output.artifacts.find(
  artifact => artifact.kind === 'composite' && artifact.namespace === 'standard' && artifact.type === 'flexLayout',
);
const artifact = FlexLayoutArtifactSchema.parse(envelope?.value);
```

如果宿主只使用单一容器，可以只把对应 Definition 放入 `compile.composites`；图中使用完整布局家族时再加入其它 Definition。产物信封中的 `occurrence.sourcePath` 与 `occurrence.expansionPath` 用于区分嵌套或重复实例，`value` 再由对应的 `XxxLayoutArtifactSchema` 精确解析

## React

`@retikz/standard-react` 的三个容器都是可嵌入 Tier 2 组件。容器直属 children 必须是匹配 `kind` 的 `LayoutItem`；Fragment 和数组会透明展开，但普通 JSX 节点不能绕过子项语义。

每个 `LayoutItem` 必须在 `children` 与 `ir` 中二选一，并最终生成恰好一个 `IRChild`。React 的 `itemKey` 会写入规范 JSON 的 `key`；它不读取 React 保留的 `key`。嵌套 Standard 布局可以继续贡献同一布局家族，外部数据集或其它 Tier 2 运行时贡献则应由外层宿主负责。

React 容器本身不启动局部编译，也不测量 DOM。它们把 IR 与 Definition 贡献给外层 `<Layout>`，由宿主统一编译和渲染；需要读取产物时使用外层的产物观察入口。

## Vanilla

`flexLayout()`、`gridLayout()` 与 `overlayLayout()` 返回 `VanillaEmbedSpec`。Figure、挂载或 SSR 宿主需要传入对应适配器；完整布局家族使用 `StandardLayoutVanillaAdapters`。

每个适配器调用与 React 相同的 `createXxxLayout()` 工厂生成规范 IR，并贡献该布局家族所需的 Definition。Vanilla 因而与直接 Core 编译、React 入口共享同一套 schema、Definition、求解器和产物语义

## 布局检查器

布局检查器（Layout Inspector）是运行时开发辅助层，不进入 Standard IR，也不修改类型化布局产物。SVG 把它绘制在主图之后的 `pointer-events="none"` 分组中；Canvas 在主图之后单独绘制，但不把辅助图元加入命中测试。两种后端都只用主 Scene 决定 viewBox、资源、动画和正常交互。

### 颜色、纹理与线型

辅助层用三条正交通道表达不同信息，不再用一种颜色同时暗示边界类别与嵌套层级：

| 通道 | 表达内容            | 规则                                                                                                                                 |
| ---- | ------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 颜色 | 最终布局 occurrence | Core 按最终 entry 顺序分配 `colorScope`；Render 在九色数组中循环取色，warning 始终为红色                                             |
| 纹理 | 空间语义            | margin 与固定 gap 为 `/`，padding 为反向 `\`；三者只绘斜线、不铺底色；distributed space 不使用纹理或背景色；斜线间距为 12 user units |
| 线型 | 几何类别            | 容器、内容、item box、Flex line、Grid track/cell/span、Overlay placement 与 alignment guide 统一使用虚线；anchor crosshair 使用实线  |

同一个 occurrence 的普通辅助图元共享颜色；嵌套容器按各自最终 occurrence 取得颜色。颜色数组在第十个 occurrence 开始循环，因此颜色只用于快速归属，精确身份仍由 occurrence locator 表达。

绘制顺序固定为 spacing hatch / boundary underlay → family structure → box outline → overflow warning → guide/anchor → label。`bounds.content` 与 `bounds.slot` 只控制对应 outline；`spacing.padding` 与 `spacing.margin` 独立控制两种纹理和边界。margin、padding 与固定 gap 使用独立 dashed line 表达边界；ring 只描内外周长，不描四块纹理分片之间的接缝。`distributedSpace` 只显示未占用 content 的 dashed perimeter，内部保持透明留白。若 spacing boundary 已被 content/slot outline 或 Flex line / Grid track 完整覆盖，同一线段只绘制一次；单独开启任一类别时仍保留其完整可见边界。

### 三种开启范围

| 范围          | React                                 | Vanilla                            | 级联语义                                      |
| ------------- | ------------------------------------- | ---------------------------------- | --------------------------------------------- |
| 整张图        | `<Layout inspect={{ layout: true }}>` | mount / SSR options 的 `inspect`   | 作用于所有已注册且带检查器的布局 occurrence   |
| authored 子树 | `<Scope inspect={{ layout: true }}>`  | `VanillaScopeSpec.inspect`         | 只作用于该 Scope 的 authored 后代             |
| 单个容器      | `<FlexLayout inspect>` 等             | `flexLayout('id', input, true)` 等 | 只作用于当前 occurrence，不自动传播到嵌套布局 |

策略按 Layout → 最近的 Scope → 当前组件逐字段合并。`bounds` 与 `spacing` 的对象形式逐项合并，boolean 与对象互换时由后写值替换整组。`layout: false` 只把当前级联值覆盖为关闭，更深的 Scope 或组件仍可重新开启；`enabled: false` 才是后代不能越过的子树硬屏障。组件自身的 `inspect={false}` 只关闭当前 occurrence。省略所有 `inspect` 时不运行检查器，`CompileResult.inspection` 为 `null`。

`layout: true` 使用唯一完整轮廓：`container`、`content`、`slot`、`allocation`、padding、margin、`overflow` 与 `alignmentGuides` 开启，`visual` 与 `labels` 关闭。对象形式只覆盖显式字段；例如 `{ layout: { spacing: { padding: false } } }` 只关闭 padding 纹理。

文档 playground 的“推荐”不是完整轮廓：Flex 显示 content outline、Flex 行区域与固定 gap，Grid 显示 content outline、轨道边界与固定 gap，Overlay 只显示 content outline。选择“全部”会打开每个细节；“关闭”只关闭总开关；Reset 回到推荐值。

`inspect` 只接受稀疏 authoring 值；未知字段或错误类型会 fail-loud。编译完成后，Core 才把级联策略求值为完整默认轮廓，并让 Standard 检查器只读取同次 compile 的类型化 artifact。切换 retained view 的检查选项会原子提交主图、产物和辅助层；失败时不会发布半帧。
