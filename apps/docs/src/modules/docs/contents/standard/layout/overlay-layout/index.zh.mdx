---
title: 叠加布局
description: 在同一区域内混合对齐与局部定位，并独立控制尺寸参与和稳定叠放顺序。
---

`OverlayLayout` 让多个子图形共享同一区域。对齐子项跟随容器对齐；定位子项用局部 `at` 和 `anchor` 放置徽标、标注框等浮层。`sizeParticipation` 决定子项是否影响容器尺寸，`zIndex` 只决定稳定绘制层级。

## 用法

```tsx
import { Layout, Node } from '@retikz/react';
import { LayoutItem, OverlayLayout } from '@retikz/standard-react';
```

```tsx
<Layout width={360} height={180}>
  <OverlayLayout size={{ x: { kind: 'fixed', value: 280 }, y: { kind: 'fixed', value: 120 } }}>
    <LayoutItem kind="overlay" itemKey="base">
      <Node position={[0, 0]} text="Base" />
    </LayoutItem>
    <LayoutItem
      kind="overlay"
      itemKey="badge"
      placement={{ kind: 'positioned', at: { x: 270, y: 10 }, anchor: { x: 1, y: 0 } }}
      sizeParticipation="exclude"
      zIndex={1}
    >
      <Node position={[0, 0]} text="3" shape="circle" />
    </LayoutItem>
  </OverlayLayout>
</Layout>
```

JSON/IR 路径使用 `createOverlayLayout()` 与 `OverlayLayoutDefinition`；Vanilla 使用 `overlayLayout()` 与 `OverlayLayoutVanillaAdapter`。

| 场景        | 公开入口                                                                                               |
| ----------- | ------------------------------------------------------------------------------------------------------ |
| React       | `OverlayLayout`、`LayoutItem`（`@retikz/standard-react`）                                              |
| Vanilla     | `overlayLayout`、`OverlayLayoutVanillaAdapter`（`@retikz/standard-vanilla`）                           |
| 可选检查    | `InspectOverlayLayout`（`@retikz/standard-react/inspect`）、`inspectOverlayLayout`（Vanilla）          |
| IR / 持久化 | `OverlayLayoutSchema`、`createOverlayLayout`、`IROverlayLayout`、`OverlayLayoutDefinition`（Standard） |

### 对齐与定位

| 模式         | 分配区域来源                                             | 常见用途                     |
| ------------ | -------------------------------------------------------- | ---------------------------- |
| `aligned`    | 内容区域扣除外边距后按对齐方式分配                       | 背景、居中内容、底部说明文字 |
| `positioned` | `at` 决定目标点，`anchor` 决定分配区域的哪一点贴到目标点 | 徽标、标注框、局部注释       |

## 技术原理

<ComponentAlert
  type="tip"
  title="上手阶段可跳过本节"
  description="只有在排查基线、结构尺寸参与或稳定绘制顺序时，才需要理解这些约束。"
/>

`offset` 在放置后平移。按基线对齐的子项，其纵向偏移必须为零；定位子项必须采用边缘对齐，避免把局部点定位和跨子项基线求解混为一件事。

`sizeParticipation="exclude"` 只排除最小和自然尺寸轮廓，不隐藏子项、不跳过回放，也不改变绘制顺序。即使子项位于容器分配区域外，类型化产物仍保留其父级分配区域、真实占用、视觉边界和可见边界。

## API 参考

### 可选 React 检查组件

| 属性       | 类型                                               | 默认值 | 描述                                                                      |
| ---------- | -------------------------------------------------- | ------ | ------------------------------------------------------------------------- |
| `inspect?` | `false` \| `true` \| `OverlayLayoutInspectOptions` | `true` | `InspectOverlayLayout` 为当前 occurrence 声明请求；`false` 只取消当前实例 |

基础 `OverlayLayout` 没有 `inspect` 属性。可选的 `InspectOverlayLayout` 对象形式可分别控制 `placements`、`anchors` 与 `stacking`，并复用通用边界与盒模型间距开关。完整字段和宿主 / Scope 规则见[运行时参考](/standard/layout/reference/runtime#布局检查器)。

### `OverlayLayoutInput`

| 属性            | 类型                                        | 默认值      | 描述                                |
| --------------- | ------------------------------------------- | ----------- | ----------------------------------- |
| `size?`         | `LayoutSizeInput`                           | 内容 / 内容 | 双轴分配策略                        |
| `padding?`      | `number` \| `IRBoxSpacing`                  | `0`         | 从分配区域到内容区域的内边距        |
| `overflow?`     | <ApiValues name="LayoutOverflow" />         | `'visible'` | 是否在容器分配区域上裁切视觉输出    |
| `justifyItems?` | `'start' \| 'center' \| 'end' \| 'stretch'` | `'center'`  | 默认水平对齐                        |
| `alignItems?`   | <ApiValues name="LayoutAlignment" />        | `'center'`  | 默认垂直对齐                        |
| `children?`     | `Array<OverlayLayoutItemInput>`             | `[]`        | 作者声明的子项；本地 `key` 必须唯一 |

### `OverlayLayoutItemInput`

| 属性                 | 类型                                         | 默认值      | 描述                                 |
| -------------------- | -------------------------------------------- | ----------- | ------------------------------------ |
| `kind`               | `'overlay'`                                  | —           | 叠加布局子项判别字段                 |
| `key`                | `string`                                     | —           | 当前容器内由作者声明的标识           |
| `child`              | `IRChild`                                    | —           | 任意可 JSON 序列化的 Core 子图形     |
| `placement?`         | `OverlayPlacementInput`                      | `aligned`   | 对齐或内容区域局部定位               |
| `offset?`            | `{ x: number, y: number }`                   | `{0, 0}`    | 放置后的偏移                         |
| `margin?`            | `number` \| `IRBoxSpacing`                   | `0`         | 对齐或定位分配区域的外边距           |
| `justifySelf?`       | `'start' \| 'center' \| 'end' \| 'stretch'`  | 容器值      | 覆盖水平对齐                         |
| `alignSelf?`         | <ApiValues name="LayoutAlignment" />         | 容器值      | 覆盖垂直对齐                         |
| `sizeParticipation?` | <ApiValues name="LayoutSizeParticipation" /> | `'include'` | 是否参与固有尺寸轮廓计算             |
| `zIndex?`            | `number`                                     | `0`         | 整数绘制层级；相同值保持作者声明顺序 |

### `OverlayPlacementInput`

| `kind`       | 字段                                 | 语义                                 |
| ------------ | ------------------------------------ | ------------------------------------ |
| `aligned`    | 无                                   | 使用容器与子项对齐                   |
| `positioned` | `at`、`anchor?`、`width?`、`height?` | 内容区域局部目标点与可选精确分配尺寸 |

React 中把 `key` 写成 `itemKey`，并用一个可绘制子元素或 `ir` 提供 `child`。
