title: Axes
description: Preserve origin, direction, arrows, ticks, and text for number lines or reference axes as JSON-safe Axes IR that lowers to Core Paths and Nodes.

`<Axes>` is a Standard Tier 2 component for static mathematical illustrations. It preserves a number line or Cartesian reference axes as one persistable configuration, then deterministically lowers that configuration to Core `Path` and `Node` primitives.

## Usage

```tsx
import { Layout } from '@retikz/react';
import { Axes } from '@retikz/standard-react';
```

```tsx
<Layout width={280} height={170}>
  <Axes origin={[140, 90]} extent={{ x: 110, y: 60 }} />
</Layout>
```

The React entry contributes `AxesDefinition` locally to the current `Layout`. For persistence or non-React use, create complete IR through `@retikz/standard` and explicitly provide the definition to Core compile options.

| Scenario         | Public entry point                                                       |
| ---------------- | ------------------------------------------------------------------------ |
| React            | `Axes` from `@retikz/standard-react`                                     |
| Vanilla          | `axes` and `AxesVanillaAdapter` from `@retikz/standard-vanilla`          |
| IR / persistence | `AxesSchema`, `createAxes`, and `AxesDefinition` from `@retikz/standard` |

See [Get Started](/standard/get-start) for complete Vanilla mounting and persistence flows. Use [Plot axis](/viz/grammar/guide/axis) instead when the task includes a data domain, scale, automatic ticks, formatters, or label collision handling.

## Examples

### Basic axes

`extent` is the only required semantic field. It determines how far each axis extends from the origin in its positive and negative directions:

- A number shorthand uses the same length on both sides, such as `x: 110`
- `{ negative, positive }` configures each side separately and allows either side to be `0`
- Positive x points visually right and positive y points visually up; this direction mapping only affects primitives generated by Axes

The canonical example below combines an asymmetric y extent, ticks on both x half-axes, positive-only y ticks, static numeric text, and a lightweight grid.

<ComponentPreview files="axes-basic" size="sm" />

Optional configuration answers four separate questions: `x` / `y` control each line, its ticks, and its label; `grid` adds lightweight regular lines; `originLabel` emits one text item at the intersection; and `origin` moves the complete reference axes.

### Common variants

These four side-by-side cases compare positive-only half-axes, a two-ended number line whose ticks extend upward only, asymmetric extents, and several ticks that remain after hiding the baseline. Use `x: false` or `y: false` for a single axis; `line: false` hides only that axis baseline.

<ComponentPreview files="axes-variants" size="sm" />

Axis labels, tick labels, and the origin label all accept Core `IRTextBlock`. Plain strings work directly. Formula strings such as `'$x_1$'` or `'$\\pi/2$'` require the host to inject [TeX support](/kernel/packages/tex) through `lowerTex`.

## How it works

<ComponentAlert
  type="tip"
  title="Optional for everyday use"
  description="You only need this lowering model when reading Axes IR directly, aligning other Core primitives, or debugging compile diagnostics."
/>

Axes IR never becomes a renderer-specific primitive. Once the current figure loads `AxesDefinition`, lowering normalizes positive and negative extents, maps the y direction, enumerates grid lines and ticks, and assembles ordinary Core IR in a fixed order.

The figure shows only the transformation owned by Axes. Its responsibility ends once the output reaches `Core IR[]`.

<ComponentPreview files="axes-lowering" hideCode size="xs" />

The y-axis path always runs from its negative endpoint to its positive endpoint. A positive value `v` maps to screen position `originY - v`, so the default positive arrow consistently points up. This does not create a new global coordinate system: adjacent `<Node position>` and `<Step to>` values still use Core y-down coordinates.

Axes `grid` only emits ordinary lines clipped to the same `origin` and `extent`; `offset` shifts the lattice origin in mathematical x/y directions, while dashes and other appearance fields reuse Path style. It does not depend on `GridDefinition`. Use standalone [Grid](/standard/composite/grid) for major lines, borders, and direction visibility.

A handwritten `IRAxes` without a loaded definition is never silently interpreted: Core emits `COMPOSITE_NOT_REGISTERED` and skips it. Renderers only receive the lowered `Path` and text `Node` primitives, so they never need to recognize Axes.

## API Reference

### Axes

| Prop          | Type                                                                                                                                                                                                              | Default                          | Description                                                 |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------- | ----------------------------------------------------------- |
| `origin`      | `Position`                                                                                                                                                                                                        | `[0, 0]`                         | Shared screen-space origin for axes, grid, ticks, text      |
| `extent`      | `{ x: number \| { negative: number; positive: number };`<br />`y: number \| { negative: number; positive: number } }`                                                                                             | —                                | Positive and negative drawing lengths for both axes         |
| `grid`        | `{ spacing: number \| { x: number; y: number };`<br />`offset?: Position;`<br />`style?: IRStandardPathStrokeStyle;`<br />`vertical?: IRStandardPathStrokeStyle;`<br />`horizontal?: IRStandardPathStrokeStyle }` | —                                | Lightweight regular grid with a configurable lattice origin |
| `x`           | `false \| { line?; ticks?; label? }`                                                                                                                                                                              | enabled, positive arrow, label x | Horizontal axis; `false` removes all of its artifacts       |
| `y`           | `false \| { line?; ticks?; label? }`                                                                                                                                                                              | enabled, positive arrow, label y | Vertical axis; positive values point visually up            |
| `originLabel` | `false \| IRTextBlock \| { text: IRTextBlock; offset?: number; style?: IRLabelVisualStyle }`                                                                                                                      | `false`                          | One static label placed down-left from the origin           |

### Nested fields

The table below summarizes the object fields of `AxesInput`; the complete JSON shapes for `source` and `labels` are listed in their following rows.

| Prop                         | Type                                                                                                                                 | Default           | Description                                                             |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ | ----------------- | ----------------------------------------------------------------------- |
| `extent.x` / `extent.y`      | `number \| { negative: number; positive: number }`                                                                                   | —                 | A number is symmetric; an object may set one direction to `0`           |
| `grid.offset`                | `Position`                                                                                                                           | `[0, 0]`          | Axis-local mathematical offset for lattice alignment                    |
| `grid.style`                 | `IRStandardPathStrokeStyle`                                                                                                          | —                 | Color, width, dash, dash offset, line cap, and opacity                  |
| `x.line` / `y.line`          | `false \| { arrows?: 'none' \| 'positive' \| 'negative' \| 'both'; arrowDetail?: IRArrowDetail; style?: IRStandardPathStrokeStyle }` | positive arrow    | `false` hides the baseline without removing ticks or text               |
| `line.arrowDetail`           | `IRArrowDetail`                                                                                                                      | —                 | Core arrow appearance; `start` / `end` map to negative / positive ends  |
| `x.ticks` / `y.ticks`        | `false \| { source; side?; endpointGap?: number; length?: number; style?: IRStandardPathStrokeStyle; labels? }`                      | —                 | Ticks and optional static text for this axis                            |
| `ticks.source` (spacing)     | `{ kind: 'spacing'; spacing: number; extent?: 'positive' \| 'negative' \| 'both' }`                                                  | `extent='both'`   | Enumerates positive spacing from the origin on selected sides           |
| `ticks.source` (values)      | `{ kind: 'values'; values: Array<number> }`                                                                                          | —                 | Strictly increasing nonzero signed values inside the extent             |
| `ticks.side`                 | `'positive' \| 'negative' \| 'both'`                                                                                                 | `'both'`          | Perpendicular extension side; x positive is above, y positive is right  |
| `ticks.endpointGap`          | `number`                                                                                                                             | `6`               | Omits ticks closer than this to either endpoint; `0` disables filtering |
| `ticks.length`               | `number`                                                                                                                             | `6`               | Total tick-segment length distributed across the selected side          |
| `ticks.labels`               | `false \| { entries: Array<{ value: number; text: IRTextBlock }>; offset?: number; style?: IRLabelVisualStyle }`                     | `offset: 4`       | Labels emitted ticks only; formatter functions are not accepted         |
| `x.label` / `y.label`        | `false \| IRTextBlock \| { text: IRTextBlock; end?: 'positive' \| 'negative'; offset?: number; style?: IRLabelVisualStyle }`         | x or y            | Axis text, endpoint, outward offset, and text style                     |
| `label.end` / `label.offset` | `'positive' \| 'negative'`<br />`number`                                                                                             | positive<br />`8` | Label endpoint and distance from that endpoint                          |
| `originLabel.offset`         | `number`                                                                                                                             | `10`              | Distance that moves the origin label down-left                          |
