`<Legend>` 是领域无关的呈现组件：调用方先把颜色、线型、符号或连续变化解析成可绘制样本，再交给 Legend 排列样本、标签和标题。它不读取 Plot scale、Table cell 或逻辑关系模型，也不保存筛选、选择和点击状态。

Legend 有两种内容形态。`items` 保存稳定顺序的离散“样本 + 标签”，`ramp` 保存一个连续样本和沿主轴归一化到 `0..1` 的刻度。样本、标签与标题都接受任意 JSON-safe `IRChild`，因此 Core 图元和已注册的其它 Tier 2 composite 可以走同一条编译链路。

## 用法

```tsx
import { Layout } from '@retikz/react';
import { Legend } from '@retikz/standard-react';
```

```tsx
<Layout width={320} height={160}>
  <Legend
    content={{
      kind: 'items',
      items: [
        {
          key: 'primary',
          sample: { type: 'node', position: [0, 0], text: '', fill: 'dodgerblue' },
          label: { type: 'node', position: [0, 0], text: '主要' },
        },
      ],
    }}
  />
</Layout>
```

React 接收 plain-data props，不提供 `children` 模板入口。React 与 Vanilla authoring 复用 `LegendInput`，并经 `createLegend()` 生成 `IRLegend`；直接 IR / 持久化使用完整的 `IRLegend`。三条路径最终都由 `LegendSchema` 校验，并交给 `LegendDefinition` 编译。

| 场景        | 公开入口                                                                                   |
| ----------- | ------------------------------------------------------------------------------------------ |
| React       | `Legend`（`@retikz/standard-react`）                                                       |
| Vanilla     | `legend()`、`LegendVanillaAdapter`（`@retikz/standard-vanilla`）                           |
| IR / 持久化 | `LegendSchema`、`createLegend()`、`LegendDefinition`、`LegendModule`（`@retikz/standard`） |

完整的挂载、`StandardBundle` 和持久化加载流程见[快速开始](/standard/get-start)。领域包负责生成已经解析好的样本；Standard Legend 只拥有通用呈现、布局与类型化产物。

## 例子

### 离散样本

`key` 是当前 Legend 内稳定且唯一的身份。下面用真实 Path 样本表达逻辑图中的直接、间接与参考关系；实线、虚线、点线的含义来自调用方，Legend 不为线型硬编码领域解释。

### 连续样本

`ramp` 保留一个连续 Core child，并把每个 `offset` 映射到样本物理主轴。端点标签可以超出样本 slot，类型化产物会同时记录真实 allocation、visual 与 visible bounds。

<ComponentPreview files="legend-ramp" size="xs" />

### 控制面板

固定容器分配与 viewBox 后，可以比较内容区域对齐、方向、换行、样本对齐、间距、内边距和溢出策略。`contentAlign` 分别按标题与主体自身的结构宽度，在 Legend 内容框内沿 x 轴对齐；它不是标题内部文字对齐，也不是 Legend 在父容器中的位置。标题输入支持换行，标题对齐只控制多行文字块内各行的位置；单行标题按文字自然宽度参与布局，不会为对齐预留额外空间。`wrap` 只在约束使条目需要额外行或列时改变结构。

## 技术原理

<ComponentAlert
  type="tip"
  title="日常使用可以跳过本节"

### 从 Legend IR 到 Core 输出

`LegendDefinition` 由 Core composite registry 消费。它先对标题、样本和标签执行 minimum / natural probe，求出结构轮廓。内容宽度确定后，标题按 x 轴 range 与 y 轴 natural 再 probe；样本和标签则按最终 slot 执行 exact probe。编译只 replay 被选中的结果，被丢弃的 probe 不发布图元、资源或产物。

<ComponentPreview files="legend-pipeline" hideCode size="xs" />

`LegendDefinition` 返回普通 Core IR children，并在同次编译并列返回 `LegendArtifact`。Core 随后把这些 children 编译进 Scene，而 artifact 保持为独立产物；SVG 与 Canvas renderer 不认识 `standard.legend`，也不提供专属分支。

### 嵌套能力与失败

Core `Node`、`Path`、`Scope` 等图元可以直接作为 `IRChild`。内嵌 Tier 2 composite 仍需在同一 compile options 中注册自己的 Definition；`LegendModule` 只贡献 `LegendDefinition`，不会猜测或全局安装样本依赖。

未注册 Legend 会产生 `COMPOSITE_NOT_REGISTERED`。内嵌 composite 的 probe 失败会保留原始 occurrence 并终止当前 Legend，而不是用空样本继续。重复 `items[].key` / `ticks[].key`、纯空白 key、越界或逆序 tick offset 会在 schema 边界 fail-loud。

### 类型化产物

`LegendArtifact` 是 `items | ramp` 的严格判别联合。两种分支都记录容器、标题和主体边界；离散分支按编写顺序记录每个 key、sourceIndex、样本与标签 placement，连续分支记录样本 placement 以及每个 tick 的物理 anchor。所有坐标都处于 Legend allocation coordinate，领域 owner 可以用稳定 key 与自己的 locator 连接，而不把 provenance 写入 Standard IR。

## API 参考

### 公开入口

| API                    | 包                         | 职责                                                            | 默认值 |
| ---------------------- | -------------------------- | --------------------------------------------------------------- | ------ |
| `Legend`               | `@retikz/standard-react`   | 把 `LegendProps` 贡献为当前 Layout 的 `IRLegend` 与 Definition  | —      |
| `legend(id, input)`    | `@retikz/standard-vanilla` | 创建由 `LegendVanillaAdapter` 消费的 Vanilla embed              | —      |
| `LegendVanillaAdapter` | `@retikz/standard-vanilla` | 经 `createLegend()` 下沉 embed，并向当前 Figure 贡献 Definition | —      |
| `createLegend(input)`  | `@retikz/standard`         | 校验 input、应用默认值并补固定 discriminator                    | —      |
| `LegendModule`         | `@retikz/standard`         | 按需贡献 `LegendDefinition` 的 capability module                | —      |
| `LegendDefinition`     | `@retikz/standard`         | Core layout-aware composite definition                          | —      |

`@retikz/standard` 还公开导出 `LegendContentKind`、`LegendDirection`、`LegendWrap` 与 `LegendSampleAlignment` 闭合集合；具体取值由下方 `LegendSchema` 展示。

### React 与 Vanilla

| 属性 / 参数 | 类型          | 默认值 | 描述                                                                 |
| ----------- | ------------- | ------ | -------------------------------------------------------------------- |
| `props`     | `LegendProps` | —      | 等同于 `LegendInput`；不接收 `children` 或 ReactNode callback        |
| `id`        | `string`      | —      | `legend()` 的 embed 身份，不写入 `IRLegend`                          |
| `input`     | `LegendInput` | —      | `legend()` 的 JSON-safe 输入；由 adapter 调用同一个 `createLegend()` |

`LegendInput` 省略固定的 `namespace` 与 `type`。常用默认值为：`titleGap: 8`、`contentAlign: 'start'`、内容尺寸、`padding: 0`、`overflow: 'visible'`；离散内容默认 `direction: 'vertical'`、`wrap: 'nowrap'`、`columnGap / rowGap / sampleGap: 8`、`sampleAlign: 'center'`。
