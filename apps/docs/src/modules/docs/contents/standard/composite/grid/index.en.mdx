`<Grid>` is an optional Standard Tier 2 component. It retains bounds, spacing, alignment, major lines, and borders as compact JSON fields; it lowers to Core `Path` only when the current figure loads `GridDefinition`.

## Usage

```tsx
import { Layout } from '@retikz/react';
import { Grid } from '@retikz/standard-react';
```

```tsx
<Layout width={280} height={170}>
  <Grid bounds={{ min: [20, 20], max: [260, 150] }} spacing={20} lines={{ style: { stroke: 'lightgray' } }} />
</Layout>
```

The React entry contributes `GridDefinition` locally to the current `Layout`. For persistence or non-React use, create IR through `createGrid` from `@retikz/standard` and explicitly provide `GridDefinition` to Core compile options.

| Scenario         | Public entry point                                                       |
| ---------------- | ------------------------------------------------------------------------ |
| React            | `Grid` from `@retikz/standard-react`                                     |
| Vanilla          | `grid` and `GridVanillaAdapter` from `@retikz/standard-vanilla`          |
| IR / persistence | `GridSchema`, `createGrid`, and `GridDefinition` from `@retikz/standard` |

See [Get Started](/standard/get-start) for complete Vanilla mounting and persistence flows. This page focuses on Grid-specific fields and semantics.

## Examples

### Basic grid

You only need two required props to define a grid:

- `bounds` uses `min` and `max` corners to limit the rectangular area covered by the grid. `min` must be less than `max` on both axes; grid lines normally extend only within this area
- `spacing` sets the distance between adjacent lines. A number uses one distance for both directions; `{ x, y }` uses `x` between vertical lines and `y` between horizontal lines

The grid below covers `[20, 20]` through `[260, 150]` and emits a line every 20 user units in both directions.

<ComponentPreview files="grid-basic" size="sm" />

Optional props then answer four kinds of decisions:

- `origin` moves the lattice alignment base and the starting point for major-line counting
- `lines` selects vertical lines, horizontal lines, range boundaries, and ordinary-line style
- `major` emphasizes every Nth lattice line and overrides selected ordinary-line style fields
- `border` adds an independent outer frame and controls padding, drawing order, and whether lines reach that frame

## How it works

<ComponentAlert
  type="tip"
  title="Optional for everyday use"
  description="You only need this lowering model when working with Grid IR directly or debugging compile diagnostics."
/>

Grid IR does not become a renderer primitive. Lowering first normalizes bounds, origin, and spacing, enumerates lattice points for the x and y directions, identifies major lines by their `origin`-relative indices, and assembles ordinary Core `Path` nodes in border order.

The figure follows this deterministic transformation from left to right. Grid's responsibility ends once the output reaches `Core Path[]`.

<ComponentPreview files="grid-lowering" hideCode size="xs" />

Each grid line becomes a `move + line` path, while the border becomes a closed path. Core's existing compiler and renderers consume the result, so renderers never need to recognize Grid.

A handwritten `IRGrid` without a loaded definition is never silently interpreted: Core emits `COMPOSITE_NOT_REGISTERED` and skips it. Standard therefore remains dynamically loaded by capability without changing compilation for other figures.

## API Reference

`GridProps` is a public alias of `GridInput`, and the Vanilla adapter accepts that same `GridInput`. `createGrid` validates it and returns `IRGrid` with schema defaults applied. `Position` in the table below comes from `@retikz/math`.
