`<Grid>` is an optional Standard Tier 2 component. It retains bounds, spacing, alignment, and styles as compact JSON fields; it lowers to Core `Path` nodes or a center-translating `Scope` when the current figure loads `GridDefinition`.

## Usage

```tsx
import { Layout } from '@retikz/react';
import { Grid } from '@retikz/standard-react';
```

```tsx
<Layout width={280} height={170}>
  <Grid bounds={{ start: [20, 20], end: [260, 150] }} spacing={20} lines={{ style: { stroke: 'lightgray' } }} />
</Layout>
```

The React entry contributes `GridDefinition` locally to the current `Layout`. For persistence or non-React use, create IR through `createGrid` from `@retikz/standard` and explicitly provide `GridDefinition` to Core compile options.

| Scenario         | Public entry point                                                       |
| ---------------- | ------------------------------------------------------------------------ |
| React            | `Grid` from `@retikz/standard-react`                                     |
| Vanilla          | `grid` and `GridVanillaAdapter` from `@retikz/standard-vanilla`          |
| IR / persistence | `GridSchema`, `createGrid`, and `GridDefinition` from `@retikz/standard` |

See [Get Started](/standard/get-start) for complete Vanilla mounting and persistence flows. This page focuses on Grid-specific fields and semantics.

## Examples

### Basic grid

You define a grid with `bounds` and `spacing`; line directions and styles are configured through `lines`, and major lines through `major`:

- `bounds` accepts unordered `start` and `end` Cartesian corners, or a center `position` with `width` and `height`
- `start` and `end` are sorted independently on x and y during lowering, so reversed and equal coordinates are valid; corner positions must be Cartesian `Position` values
- centered `position` is the geometric center and accepts `Position` or `PolarPosition`; Core resolves PolarPosition, while the grid itself remains Cartesian
- `spacing` is required and accepts one positive number or independent x/y values
- `origin` is an optional Cartesian `Position`: corner bounds use scene coordinates, while centered bounds use center-local coordinates
- `lines` independently enables `vertical` and `horizontal` lines and configures `includeBoundary` and ordinary-line `style`; both directions are enabled by default and boundary insertion is off
- `major` configures periodic major lines by integer indices relative to `origin`; its style shallowly overrides the ordinary-line style
- `border` can be configured independently, so the border may remain when either line direction is disabled

The grid below covers `[20, 20]` through `[260, 150]` and emits a line every 20 user units in both directions.

<ComponentPreview files="grid-basic" size="sm" />

`origin` follows the bounds form. Corner bounds use scene coordinates and default to the normalized start; centered bounds use center-local coordinates and default to `[-width / 2, -height / 2]`. Set `origin: [0, 0]` in a centered configuration to align the lattice through the geometric center. `origin` accepts only Cartesian `Position`; Core resolves the center `PolarPosition`.

## How it works

<ComponentAlert
  type="tip"
  title="Optional for everyday use"
  description="You only need this lowering model when working with Grid IR directly or debugging compile diagnostics."
/>

Grid IR does not become a renderer primitive. Corner bounds are normalized independently on both axes; centered bounds are expanded in a center-local rectangle. Standard enumerates lattice points from the top-level `spacing`, `origin`, `lines`, and `major` fields before assembling Core `Path` nodes in border order.

Centered bounds additionally use an existing Core `Scope` to carry the center translation. Cartesian Position, recursive PolarPosition, and node references are therefore resolved by Core Scene compilation; Standard does not add a second position resolver, and this is not a polar grid.

The figure follows this deterministic transformation from left to right. Grid's responsibility ends once the output reaches `Core Path[]` or a positioned `Scope`.

<ComponentPreview files="grid-lowering" hideCode size="xs" />

Each grid line becomes a `move + line` path, while the border becomes a closed path. Core's existing compiler and renderers consume the result, so renderers never need to recognize Grid.

A handwritten `IRGrid` without a loaded definition is never silently interpreted: Core emits `COMPOSITE_NOT_REGISTERED` and skips it. Standard therefore remains dynamically loaded by capability without changing compilation for other figures.

## API Reference

`GridProps` is a public alias of `GridInput`, and the Vanilla adapter accepts that same `GridInput`. `createGrid` validates it and returns `IRGrid` with schema defaults applied. `Position` and `PolarPosition` in the table below come from Core's positioning contract.

| `origin?` | `Position`                                                                                                                                                                      | Depends on the `bounds` form                                                                                       | Lattice alignment and major-line index base; corner bounds use scene coordinates and default to the normalized start, while centered bounds use center-local coordinates and default to `[-width / 2, -height / 2]`                                          |
