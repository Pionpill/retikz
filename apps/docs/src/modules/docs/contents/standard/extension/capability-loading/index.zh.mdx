直接编译持久化 Standard IR 时，先组合当前任务需要的 module，再把 bundle 的编译片段交给 Core：

```ts
import { compileToScene } from '@retikz/core';
import { createStandardBundle, FrameModule, GridModule } from '@retikz/standard';

const drawingBundle = createStandardBundle([GridModule, FrameModule]);
const scene = compileToScene(persistedIR, drawingBundle.compile);
```

module 和 bundle 都是运行时配置；它们包含 definition 函数，不能写入 JSON IR。

## 适用边界

使用 bundle 的场景包括服务端编译、文件恢复、LLM 生成 IR 和需要稳定能力目录的工具链。仅使用 React JSX 时，组件静态 adapter 已按当前图贡献 definition，不需要额外 preset。

bundle 只组合 `CompositeDefinition`。它不合并 renderer、布局策略、warning handler、React Context 或 Vanilla 生命周期，也不会在 import 时修改全局状态。

## 定义能力

Standard 内置 module 包括 `GridModule`、`AxesModule`、`FrameModule`、`FlexLayoutModule`、`GridLayoutModule`、`OverlayLayoutModule` 与 `LegendModule`。第三方 composite 仍以 Core `defineComposite()` 为真源；需要和官方能力一起组合时，可用普通结构化 module 分组：

```ts
import { CompositeBaseSchema, defineComposite } from '@retikz/core';
import type { StandardCapabilityModule } from '@retikz/standard';
import { z } from 'zod';

const BadgeDefinition = defineComposite({
  namespace: 'example',
  type: 'badge',
  schema: CompositeBaseSchema.extend({
    namespace: z.literal('example'),
    type: z.literal('badge'),
    text: z.string(),
  }),
  expand: (node, _context) => ({ type: 'node', position: [0, 0], text: node.text }),
});

const BadgeModule = {
  name: 'example.badge',
  composites: [BadgeDefinition],
} satisfies StandardCapabilityModule;
```

`name` 只用于 bundle 级异对象冲突诊断；真正的 composite lookup 仍读取 definition 的 `namespace` 与 `type`。同一 module 对象引用重复出现时幂等汇合并保留首次位置；不同对象即使结构相同，也不能共享 `name`。

## 注入宿主

### 直接 IR 与 React IR 模式

Core、React 的 `ir` prop 和 Vanilla 的直接 IR 路径都消费同一组 definitions：

```tsx
import { Layout } from '@retikz/react';
import { StandardAllPreset } from '@retikz/standard';

<Layout ir={persistedIR} composites={StandardAllPreset.compile.composites} />;
```

`StandardAllPreset` 包含当前版本发布的全部 Standard modules。需要更小集合时，使用 `createStandardBundle([GridModule, FrameModule])`。

只需要布局家族时使用 `StandardLayoutPreset`。它按 FlexLayout、GridLayout、OverlayLayout 顺序提供三项 definitions。

### React JSX

`<Grid>`、`<Axes>`、`<Frame>`、`<Legend>` 与三种布局容器继续通过组件静态 adapter 贡献 definition。嵌套布局共享 `standard.layout` namespace 与 maker，只向最外层 `Layout` 贡献一次家族 definitions。宿主组合这些贡献时仍以 definition 对象与 Core provider key 为准，不建立另一套覆盖优先级。

### Vanilla

Vanilla embed 由 adapter 做 authoring 下沉。部分加载显式传所需 adapters；需要当前完整目录时使用浅冻结数组 `StandardVanillaAdapters`：

```ts
import { StandardVanillaAdapters } from '@retikz/standard-vanilla';
import { mountSvg } from '@retikz/vanilla';

mountSvg(container, figure, { adapters: StandardVanillaAdapters });
```

直接传 Standard IR 时不读取 adapters，只需把 `bundle.compile` 放进 runtime 的 `compile` 选项。

只需要布局 embeds 时使用 `StandardLayoutVanillaAdapters`；完整 `StandardVanillaAdapters` 按 Grid、Axes、Frame、三种布局、Legend 的顺序提供当前目录。

静态 adapter 与显式 bundle 是同一 capability 的两种装载来源，不是相互去重的层。若 JSX / embed 已贡献某个 definition，宿主又通过 bundle 注入相同 provider key，Core 会 fail-loud 报 `duplicate composite registration`。

## 执行机制

1. capability module 按声明顺序提供 Core definitions。
2. `createStandardBundle()` 先按 module 对象 identity 幂等汇合，再拒绝同名异对象，复制名称与 definition 引用并浅冻结返回容器。
3. 宿主把 `bundle.compile.composites` 交给 Core composite registry。
4. Core 按 definition 的 provider key 查找、校验并展开 Standard IR。

## 错误与限制

| 情况                             | 结果                                                                 |
| -------------------------------- | -------------------------------------------------------------------- |
| module 名为空或只含空白          | `createStandardBundle()` 立即抛错                                    |
| 同一 module 对象重复出现         | 幂等汇合，保留首次位置，只贡献一次 definitions                       |
| 不同 module 对象使用同一 name    | Standard 立即抛错，不按 name 或结构静默覆盖                          |
| 不同 module 的 provider key 重复 | Core 报 `duplicate composite registration`                           |
| JSX / embed 与 bundle 重复注入   | Core 报 `duplicate composite registration`，不会按来源自动去重       |
| IR 引用未选择的 composite        | Core 产生 `COMPOSITE_NOT_REGISTERED`，跳过该节点并继续处理其它 child |

module、bundle 与 adapter 都不能进入持久化 IR。`StandardAllPreset` 与 `StandardVanillaAdapters` 会随 Standard 版本增加已发布能力，不是跨版本固定目录。

## API 参考

| 导出                            | 所属包                     | 职责                                      |
| ------------------------------- | -------------------------- | ----------------------------------------- |
| `StandardCapabilityModule`      | `@retikz/standard`         | 用稳定名称分组 Core composite definitions |
| `StandardBundle`                | `@retikz/standard`         | 保存 module 名称和必填 compile 片段       |
| `createStandardBundle()`        | `@retikz/standard`         | 校验、组合并冻结选定 modules              |
| `GridModule`                    | `@retikz/standard`         | Grid 的官方 module                        |
| `AxesModule`                    | `@retikz/standard`         | Axes 的官方 module                        |
| `FrameModule`                   | `@retikz/standard`         | Frame 的官方 module                       |
| `LegendModule`                  | `@retikz/standard`         | Legend 的官方 module                      |
| `FlexLayoutModule`              | `@retikz/standard`         | FlexLayout 的官方 module                  |
| `GridLayoutModule`              | `@retikz/standard`         | GridLayout 的官方 module                  |
| `OverlayLayoutModule`           | `@retikz/standard`         | OverlayLayout 的官方 module               |
| `StandardLayoutPreset`          | `@retikz/standard`         | 三种布局 definitions 的 bundle            |
| `StandardAllPreset`             | `@retikz/standard`         | 当前版本全部 Standard modules 的 bundle   |
| `StandardLayoutVanillaAdapters` | `@retikz/standard-vanilla` | 三种布局 Vanilla adapters                 |
| `StandardVanillaAdapters`       | `@retikz/standard-vanilla` | 当前版本全部 Standard Vanilla adapters    |

`StandardCapabilityModule` 包含 `name: string` 与 `composites: ReadonlyArray<CompositeDefinition>`。`StandardBundle` 包含 `modules: ReadonlyArray<string>` 和必填的 `compile.composites`；空 bundle 也返回空数组，无需空值分支。

三个包都只公开根 package entry。所有能力是根入口 named export；不会为每个组件维护 `/grid`、`/axes` 等 package subpath。
