`Surface` 为一个子图添加内边距、背景、边框和圆角，并可裁剪内容溢出。子图可以是一个 Node，也可以是包含多个图元的 Scope 或已注册的复合组件。

## 接入方式

完成[安装与首次渲染](/library/standard/get-start)后，从 `/presentation` 导入。下面四种方式绘制相同的单节点表面。

## 基础用法

### 基础表面

`Surface` 只要求一个可转换为 IR 的直接 child；child 本身可以是容纳多个图元的 Core `Scope`。padding 参与布局，背景、内容与边框按固定层次绘制。

<ComponentPreview files="surface-basic" size="sm" />

`padding` 默认 `0`，`cornerRadius` 默认 `0`；背景与边框默认不生成。padding 参与空间分配，背景与边框围绕完整的 allocation box 绘制。`style` 和其它 Scope 属性作用于整个外层分组，不能替代独立的 `background` 或 `border`。

## 扩展用法

### Overflow 与圆角裁剪

`overflow="visible"` 保留 child 的视觉溢出；`overflow="clip"` 只裁剪内容层，不裁剪背景或边框。圆角同时作用于边界 Path 和内容 clip，半径会限制到短边的一半。

<ComponentPreview files="surface-overflow" size="sm" />

## 错误与限制

归一化后必须恰好有一个 child。padding 和圆角半径不能为负；父容器在某轴提供的有限范围或精确尺寸小于该轴 padding 总和时，会在探测 child 前失败。直接 IR 使用 `overflow: 'clip'` 时还需注册 `PathClipDefinition`；React 与 Vanilla adapter 自动贡献该依赖。

## 实现原理

<ComponentAlert type="tip">

本节解释内部布局与下沉，仅使用组件时可跳到 API 参考。

</ComponentAlert>

`SurfaceDefinition` 先根据 parent proposal 和 padding 探测唯一 child，再回放 child 并输出背景 Path、内容 Scope 和边框 Path。`overflow="clip"` 的 clip 只挂在内容 Scope；Surface 自身的 Core `clip` 仍作用于完整外层。

```text
standard.surface → SurfaceDefinition → Core Scope(Path + child replay + Path)
```

未注入 `SurfaceDefinition` 的手写 `standard.surface` 会得到 `COMPOSITE_NOT_REGISTERED` 诊断。React 与 Vanilla adapter 会贡献 `SurfaceProvider → PathClipProvider` 的完整依赖链；嵌套 Tier 2 child 的 provider 依赖按 authored order 一并进入 Core resolver。直接调用 `compileToScene` 时，如果使用 `overflow: 'clip'`，除了 `SurfaceDefinition` 还需通过 `clips` 传入完整的 `PathClipDefinition`。

Surface 还在 authored 外层 Scope 发布 id 为 `surface` 的 qualified spatial handle。handle 继承最终 placement 与 transform；child 自己的 handle 保持原 id、role、tags 与 payload，只增加真实 owner path。
