`Axes` 为数学插图提供数轴或笛卡尔参考轴，支持静态刻度、文字、箭头和网格。它只改变自身生成图元的方向，不改变整张图的坐标系。

## 接入方式

[安装与首次渲染](/library/standard/get-start)后，从 `/presentation` 子入口导入。下面四种接入方式绘制相同的图形；直接使用 IR 时显式注册 Definition。

## 基础用法

### 基础坐标轴

`x` 与 `y` 是必填的轴对象；每条轴同时拥有自己的 `extent`、`grid`、基线、刻度和轴名：

- 数字 `extent` 表示两侧等长，例如 `x: { extent: 110 }`
- `{ negative, positive }` 分别设置两侧长度，并允许其中一侧为 `0`
- x 正值视觉向右，y 正值视觉向上；这套方向换算只作用于 Axes 自己生成的图元
- `x.grid` 生成竖直格线，`y.grid` 生成水平格线，因此两条轴可以独立设置间距、偏移和样式

下面的 canonical 示例使用非对称 y 范围、双向 x 刻度、仅正向 y 刻度、静态数字文字和两组独立网格。

<ComponentPreview files="axes-basic" size="sm" />

`origin` 统一承载共同的屏幕位置和原点文字。若只隐藏一条轴的某类产物，在对应轴对象中将 `line`、`ticks`、`grid` 或 `label` 设为 `false`；轴对象仍需保留 `extent`。

## 扩展用法

### 单轴、非对称范围与隐藏轴线

四个并列场景展示仅正半轴、只保留水平数轴、非对称范围，以及隐藏轴线但保留多组刻度和文字。隐藏整条轴时仍使用完整的 `x` / `y` 对象，并关闭该对象的各类产物。

<ComponentPreview files="axes-variants" size="sm" />

轴名、刻度文字和原点文字都接受 Core `IRTextBlock`。普通字符串可直接使用；`'$x_1$'`、`'$\\pi/2$'` 等公式写法需要宿主通过 `lowerTex` 注入 [TeX 能力](/kernel/packages/tex)。

### 配置刻度和静态文字

刻度使用 `source` 选择等间距或显式值。下面在 x 轴每隔 20 个单位生成刻度，并只为其中的 `20` 标注文字：

```tsx
<Axes
  x={{
    extent: 80,
    ticks: { source: { kind: 'spacing', spacing: 20 }, labels: { entries: [{ value: 20, text: '20' }] } },
  }}
  y={{ extent: 50 }}
/>
```

显式值使用 `{ kind: 'values', values: [-40, -20, 20, 40] }`。值必须严格递增、非零且落在轴范围内；文字只能引用最终实际生成的刻度。`endpointGap` 默认 `6`，过于靠近端点的刻度会被过滤，因此给端点标注前要同时检查这个间距。

### 调整网格与刻度方向

面板覆盖 Axes 的坐标原点、两条轴各自的范围和网格、轴线、箭头、刻度、刻度文字、轴名和原点文字，并可分别调整 x/y 网格与刻度的偏移。预览视野保持固定。

## 错误与限制

`x`、`y` 都必须提供 `extent`，每条轴至少有一侧长度为正。格距与刻度步长必须为正。隐藏轴线不会自动隐藏该轴的网格或文字。数据 domain、scale、自动刻度与标签避让请使用 [Plot axis](/viz/plot/guide/axis)。

## 实现原理

<ComponentAlert
  type="tip"
  title="上手阶段可跳过本节"
  description="只有在直接读写 Axes IR、对齐其它 Core 图元或排查编译诊断时才需要理解 lowering。"
/>

Axes IR 不会成为 renderer 专有图元。当前图加载 `AxesDefinition` 后，lowering 才会规范化正负范围、换算 y 方向、枚举网格与刻度，并按固定顺序组装普通 Core IR。

下图只展示 Axes 自己负责的转换链。输出到达 `Core IR[]` 后，它的职责就结束了。

<ComponentPreview files="axes-lowering" hideCode size="xs" />

y 轴路径始终从负端走向正端；正值 `v` 映射到屏幕位置 `originY - v`，所以默认正向箭头稳定朝上。这不是新的全局坐标系，旁边的 `<Node position>` 与 `<Step to>` 仍使用 Core 的 y-down 坐标。

Axes 的 `x.grid` 与 `y.grid` 只生成裁切在各自轴范围内的普通格线：前者沿 x 轴枚举并投影为竖直线，后者沿 y 轴枚举并投影为水平线。两者都复用 Path style，不依赖 `GridDefinition`；主线、边框和更完整的网格能力继续使用单独的 [Grid](/library/standard/presentation/grid)。

未加载 definition 的手写 `IRAxes` 不会被静默解释：Core 会发出 `COMPOSITE_NOT_REGISTERED` 并跳过它。renderer 只看到 lowering 后的 `Path` 与文字 `Node`，不需要识别 Axes。
