title: Frame · 分组框

`Frame` 为一组 Node 添加随内容边界变化的外框，并在上方排布可选的标题和说明。它不重新排列内容节点，适合已有位置关系的语义分组。

## 接入方式

完成[安装与首次渲染](/library/standard/get-start)后，从 `/presentation` 子入口选择宿主。四种方式绘制同一个带标题分组。

`FrameTitle`、`FrameDescription` 必须是 Frame 的直接子项，各最多一个；内容区至少有一个直接 Node。数组和 Fragment 可以透明包裹这些子项。

```text
Frame
├─ FrameTitle?
├─ FrameDescription?
└─ Node (1..n)
```

```tsx
import { Layout, Node } from '@retikz/react';
import { Frame, FrameTitle } from '@retikz/standard-react/presentation';

export const Example = () => (
  <Layout>
    <Frame>
      <FrameTitle text="Group" />
      <Node position={[0, 0]} text="A" />
    </Frame>
  </Layout>
);
```

## 基础用法

### 基础分组

显式 `id` 可以提供稳定标识；省略时 Frame 与内部排版 Scope 都保持匿名。直接 `Node` children 决定内容区边界，`FrameTitle` 与 `FrameDescription` 都是可选的。下面的最小组合使用默认边框、`padding: 8` 与 `gap: 4`。

<ComponentPreview files="frame-basic" size="sm" />

### 标题与说明组合

Frame 可以只围合内容区，也可以组合 Title 与 Description。两者默认在内容区上方横向排列并对齐底部；设置 `headerDirection="vertical"` 后按 Title、Description、内容区纵向排列。省略任一组成部分都不会产生占位。

## 扩展用法

### 调整标题样式与边框

固定内容区位置后，可集中探索标题区方向、边框内边距和类 Node 标题样式，也可以编辑 A / B 内容并开关它们之间的真实连接。改变标题字号、内边距或说明透明度时，Frame 会重新按最终 Node 边界围合内容。

<ComponentPreview
  files="frame-playground"
  size="md"
  caption="A / B 始终是 Frame 的直接 Node；灰色连接线是 Frame 外部的 sibling Draw，可独立开关。"
/>

标题与说明沿用 Node 的 `style`、`layout` 和文字语义，但位置由 Frame 排布。`border.style` 只控制边框；根级 `style`、`defaults`、`clip`、`transforms` 与 `placement` 作用于整个 Scope。标题默认字体为 sm/600，说明为 xs 且透明度 0.7；两者默认无填充、无描边、Node padding 为 0，显式值可以覆盖。

## 错误与限制

内容区只接受非空的直接 Core Node，不接受 Path、Scope 或其它复合组件。连接线应作为 Frame 外部的同级元素；需要装饰任意单个子图时使用 [Surface](/library/standard/presentation/surface)。标题和说明各最多一个，必须得到合法 Node text；它们及内容节点的 id 不能与 Frame 的显式根 id 冲突。padding 与 gap 不得为负。

## 实现原理

### 从 Frame IR 到 Core IR

Frame 的 JSON IR 不会成为新的 renderer 图元。`FrameDefinition` 先校验并匹配 `standard.frame`，随后 lowering 只输出 Core 已认识的 `Scope`、`Path` 与 `Node`。

<ComponentPreview files="frame-lowering" hideCode size="xs" />

输出到达 Core IR 后，Frame 的职责就结束了。未注入 `FrameDefinition` 的手写 `IRFrame` 会得到 `COMPOSITE_NOT_REGISTERED` 诊断并被跳过，而不是被 renderer 静默猜测。

### 边界、标题排布与可选 id

lowering 使用 occurrence-local 的匿名 Scope probe 测量内容区，并只 replay 最终选中的结果，不生成公开内容区 id。默认横向模式先把 Title 的左下 anchor 对齐到内容区左上方，再把 Description 的左下 anchor 接到 Title 的右下 anchor；纵向模式则先排 Description，再把 Title 放到其上方，从视觉上形成 Title、Description、内容区的顺序。只有一个标题区组成部分时，它会直接对齐内容区。Core 会先完成 Node 的文字、shape、padding、margin、scale 与 rotate 布局，再执行这些 anchor 对齐。

边框是外层 Scope 内部的 rectangle Path，并按 `padding` 扩张标题区与内容区的最终边界。`border.style` 只作用于这个 Path，`border.cornerRadius` 由 Core rectangle step 消费；省略或设为 `0` 时保持直角，正值由 Core 限制到短边的一半。边框、内容区与标题区的内部 `zIndex` 默认分别为 `-1`、`0` 与 `1`；显式标题区或 `border.style.zIndex` 仍会保留，Frame 自身的 `zIndex` 则作用于整个外层 Scope。

省略 Frame、Title 或 Description 的 id 时，它们都保持匿名；显式 id 会原样进入对应 Core Scope 或 Node。Frame 有显式根 id 时，直接 body Node、Title 或 Description 不能占用同一个 id；其它重复显式 id 继续使用 Core 的诊断规则。
