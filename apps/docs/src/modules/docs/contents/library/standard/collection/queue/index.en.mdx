`Queue` displays a snapshot ordered from front to back. The first item is the front and the last is the back; the default direction is rightward. Use it for task queues, algorithm illustrations and before/after states.

## Getting started

## Basic usage

### Choose an input form

Choose one of items, data or skeleton. Strings in items are literal text; explicit cells use `{ content?, id?, style?, layout? }`. data accepts a JSON array: strings keep their quotes, and nested objects and arrays expand to Map/Array by default. dataExpand only applies to data; false disables expansion and a map/array list selects which structures expand.

| Skeleton form                           | Result                                         |
| --------------------------------------- | ---------------------------------------------- |
| `skeleton={{ count: 3 }}`               | Three contentless cells                        |
| `skeleton={{ labels: ['A', '', 'C'] }}` | Three symbolic cells with an empty middle cell |

An empty array or zero count means an empty queue. Its default open container is 16×16, with no placeholder cell or operation arrows. Zero padding makes its natural size zero. Skeleton cells are drawing content, not capacity slots.

### Arrange cells and border

layout.direction supports up, down, left and right. Both ends stay open. Changing direction preserves input order. layout.width/height always mean physical cell dimensions. Cells retain their main-axis sizes; auto cells fill the largest cross-axis demand, while smaller fixed cells are centered without stretching.

layout.gap defaults to 8, larger than the nested Array/Map default of 2 so outer items remain visually distinct. layout.padding controls cell padding; root padding controls container padding, both defaulting to 8. border draws two independent sides: top and bottom for horizontal layouts, left and right for vertical layouts. Use `border={{ style: { stroke: 'dodgerblue', dashPattern: [4, 3] } }}` to configure the outline. false hides only the border and preserves padding. Root frame retains the general container decoration contract independently.

arrow defaults to false. Set it to true to enable both arrows, or configure input and output independently with an object; omitted sides stay hidden. A queue accepts input at the back and emits output at the front, using straight arrows. Each accepts true, false, or an appearance object. style controls color, width and dashes; arrowDetail controls the arrow-tip shape, size and color. Arrows do not change cell or container allocation and are hidden when empty. label remains the overall text label.

The example below enables both incoming and outgoing arrows by default; use the switches to hide them independently.

```tsx
<Queue
  items={['A', 'B', 'C']}
  arrow={{
    input: { style: { stroke: 'dodgerblue', dashPattern: [4, 3] }, arrowDetail: { shape: 'openStealth' } },
    output: { style: { stroke: 'darkorange', strokeWidth: 2 } },
  }}
/>
```

## Extended usage

### Nest content and reference a cell

Use this React hierarchy. Vanilla items.content accepts the corresponding drawing input; IR accepts one serializable child.

```text
Queue
├── QueueItem
└── QueueItem
    └── Matrix
```

QueueItem accepts either text or one drawable child; omitting both creates an empty cell. Nested collections omit the outer cell fill and padding by default, while ordinary text retains its light gray background. Cell style and layout override overall defaults, including dashes, no fill and dimensions. Fixed dimensions clip content by default; explicit overflow overrides that behavior.

Set a cell id to reference its actual border from an external Draw. Queue does not generate index ids, maintain enqueue/dequeue state or route complex connections. Compose additional operation annotations, curves and multiple snapshots with existing drawing and layout features. This example names the back cell selected and connects to it externally.
