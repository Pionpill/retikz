`Frame` surrounds a group of Nodes with a border that follows their bounds and arranges optional title and description nodes above it. It preserves the positions of body nodes.

## Using this topic

After [installation and first rendering](/library/standard/get-start), choose a host from `/presentation`. These four forms draw the same titled group.

## Basic usage

### Basic group

An explicit `id` provides stable identity; when omitted, Frame and its internal layout Scope remain anonymous. Direct `Node` children determine the body bounds, and `FrameTitle` and `FrameDescription` are both optional. This minimal composition uses the default border, `padding: 8`, and `gap: 4`.

<ComponentPreview files="frame-basic" size="sm" />

### Header compositions

A Frame may enclose only its body or combine a Title and Description. By default the two parts form a bottom-aligned row above the body; `headerDirection="vertical"` arranges Title, Description, and body vertically. Omitting either part does not create a placeholder.

## Extended usage

### Adjust header styles and borders

With body positions fixed, use the panel to explore header direction, border padding, and Node-like header styles. You can also edit A / B and toggle the real connection between them. Changing title size, padding, or description opacity makes Frame recompute the boundary from final Node bounds.

<ComponentPreview
  files={['frame-playground', 'frame-playground.preview.tsx']}
  size="md"
  caption="A and B remain direct Frame Nodes. The gray connection is a sibling Draw outside Frame and can be toggled independently."
  defaultSourceFile="frame-playground.preview.tsx"
/>

Title and description use Node style, layout, and text semantics, while Frame controls their positions. border.style affects only the border; root style, defaults, clip, transforms, and placement affect the whole Scope. The title defaults to sm/600 text; the description to xs text with 0.7 opacity. Both default to no fill, no stroke, and zero Node padding; explicit values override these defaults.

## Errors and limitations

The body accepts only a nonempty set of direct Core Nodes, not Paths, Scopes, or other composites. Put connecting paths outside Frame as siblings; use [Surface](/library/standard/presentation/surface) to decorate an arbitrary child drawing. Title and description must each be unique and produce valid Node text. Their ids and body ids cannot equal the explicit Frame root id. Padding and gap must be nonnegative.

## Implementation

### From Frame IR to Core IR

Frame JSON IR does not become a new renderer primitive. `FrameDefinition` validates and matches `standard.frame`, then lowering emits only the `Scope`, `Path`, and `Node` types already understood by Core.

<ComponentPreview files="frame-lowering" hideCode size="xs" />

Frame's responsibility ends at Core IR. A hand-authored `IRFrame` without `FrameDefinition` produces `COMPOSITE_NOT_REGISTERED` and is skipped instead of being guessed by a renderer.

### Bounds, headers, and optional ids

Lowering measures the body through an occurrence-local anonymous Scope probe and replays only the selected result, without generating a public body id. Horizontal mode aligns the Title's bottom-left anchor above the body's top-left, then attaches the Description's bottom-left to the Title's bottom-right. Vertical mode lowers Description first and places Title above it, producing the visual Title, Description, body sequence. A single header part aligns directly to the body. Core resolves these anchors after Node text, shape, padding, margin, scale, and rotate layout.

The border is a rectangle Path inside the outer Scope and expands the final header and body bounds by `padding`. `border.style` applies only to that Path, while `border.cornerRadius` is consumed by the Core rectangle step; omitting it or setting it to `0` keeps sharp corners, while Core clamps positive values to half the shorter side. Border, body, and headers default to internal `zIndex` values of `-1`, `0`, and `1`; explicit header or `border.style.zIndex` values are preserved, while Frame's own `zIndex` applies to the complete outer Scope.

Omitted Frame, Title, and Description ids all remain anonymous; explicit ids pass through to the matching Core Scope or Node. When Frame has an explicit root id, a direct body Node, Title, or Description cannot occupy the same id. Other duplicate explicit ids continue to use Core diagnostics.
