用 Standard 的 Circle / Ellipse 保留形状与尺寸意图，编译时生成一条 Core Path。适合已知几何参数的独立轮廓；需要节点文字占位与连接边界时，使用[节点形状](/library/standard/shape)。

## 接入方式

形状家族统一从三个包的 `/shape` 子入口导入，根入口不重复导出。节点形状扩展使用 `@retikz/standard/node-shape`。

React 组件通过同名 Vanilla adapter 局部贡献所需 Definition。Vanilla 使用 `shape.xxx(id, input)`，显式 id 同时标识 embed 和最终路径；React 省略 id 时不会持久化自动 occurrence id。直接编译 JSON 时，在 `composites` 中显式传入对应 Definition。三种入口共享下列几何契约。

| 入口    | 公开 API                                                                                        |
| ------- | ----------------------------------------------------------------------------------------------- |
| React   | `Circle, Ellipse` — `@retikz/standard-react/shape`                                              |
| Vanilla | `shape.circle, shape.ellipse` — `@retikz/standard-vanilla/shape`                                |
| JSON    | `CircleSchema / CircleDefinition, EllipseSchema / EllipseDefinition` — `@retikz/standard/shape` |

## 用法

`<Circle>` / `<Ellipse>` 在指定位置画一条圆 / 椭圆轮廓，展开成底层 `<Path>`。适合「我知道中心和半径」「我只有一个包围盒」这类场景。

```tsx
import { Circle, Ellipse } from '@retikz/standard-react/shape';
```

```tsx
<Circle center={[0, 0]} radius={32} style={{ fill: "none" }} />
<Ellipse center={[0, 0]} radius={{ x: 48, y: 28 }} style={{ fill: "none" }} />
```

最常见的是 `center + radius`。如果手上是一个矩形范围，也可以直接用 `corner1 + corner2` 或 `box`。

| 写法                         | 适合                                              |
| ---------------------------- | ------------------------------------------------- |
| `{ center, radius }`         | 已知圆心和半径                                    |
| `{ center, diameter }`       | 已知直径                                          |
| `{ from, to }`               | 直径两端点                                        |
| `{ corner1, corner2 }`       | 放进一个包围盒                                    |
| `{ box }`                    | 用 `x/y/origin + width + height` 直接描述矩形范围 |
| + `fit="contain" \| "cover"` | 让圆取范围短边之半（内切）或长边之半              |
| + `inset` / `outset`         | 在原范围基础上先收缩或扩展再绘制                  |
| + angles + `closed="sector"` | 画 1/4 圆、30° 圆这类连回圆心的残缺圆             |

<ComponentPreview files="circle-basic" size="sm" />

椭圆和圆很像，只是半径拆成了 `radius: { x, y }`。它也支持 `corner1 + corner2` 和 `box`。

| 写法                               | 适合                                              |
| ---------------------------------- | ------------------------------------------------- |
| `{ center, radius }`               | 已知中心和两个半轴                                |
| `{ center, diameterX, diameterY }` | 已知两个直径                                      |
| `{ corner1, corner2 }`             | 放进一个包围盒                                    |
| `{ box }`                          | 用 `x/y/origin + width + height` 直接描述矩形范围 |
| + `inset` / `outset`               | 先收缩或扩展范围再画椭圆                          |
| + angles + `closed="sector"`       | 画连回中心的部分椭圆                              |

## 输入约束

只选择一套几何描述；半径、直径、边长和尺寸必须为有限非负数。盒调整后的宽高必须大于零。局部圆弧恰好提供 startAngle、endAngle、sweepAngle 中的两个，保留 sweep 的方向和圈数。

## 编译过程

Standard 的 schema 负责互斥输入和尺寸关系；Definition 在编译时把形状意图展开为 Path steps，Core 再解析 Target、生成几何并渲染。不会添加 Node 或额外 Scope。除正多边形和星形将 rotate 烘焙进顶点外，其余旋转与缩放使用 Path 规则。

### 圆与椭圆的路径展开

图中上路保留 `Circle center` 的 target 引用，节点 id、极坐标或 `[x, y]` 会留到 Path 编译时解析；下路必须先在 Standard lowering 计算中心和半径，因此只接受字面量 `[x, y]` 几何：

<ComponentPreview files="circle-ellipse-lowering-flow" size="md" hideCode type="illustration" />

`Circle` 的 `from` / corners / box 与 `Ellipse` 的 corners / box 写法走下路；Ellipse 的 center 形式同样保留 Target 引用。两路最终都展开成等价的 `<Path>` + `circlePath` / `ellipsePath` Step；给角度后，`closed` 再决定弧端是连弦（`chord`，默认）、连回中心（`sector`）还是保持开放（`open`）。
