`Surface` adds padding, a background, a border, and rounded corners to one child drawing, with optional overflow clipping. The child can be a Node, a Scope containing multiple primitives, or a registered composite.

## Using this topic

After [installation and first rendering](/library/standard/get-start), import from `/presentation`. All four forms draw the same surface around one node.

## Basic usage

### Basic surface

`Surface` accepts exactly one direct child that lowers to IR. That child may be a Core `Scope` containing several primitives. Padding participates in layout, while background, content, and border use fixed layers.

<ComponentPreview files="surface-basic" size="sm" />

Padding and cornerRadius default to 0; background and border are absent by default. Padding participates in space allocation, and appearance follows the complete allocation box. Style and other Scope props affect the whole outer group rather than replacing background or border.

## Extended usage

### Overflow and rounded clipping

`overflow="visible"` preserves visual overflow; `overflow="clip"` clips only the content layer, not the background or border. The radius drives both the boundary Path and content clip and is clamped to half the shorter side.

<ComponentPreview files="surface-overflow" size="sm" />

## Errors and limitations

Normalization must produce exactly one child. Padding and radius must be nonnegative. If a finite range or exact parent size is smaller than total padding on that axis, Surface fails before probing the child. Direct IR with overflow: 'clip' also requires PathClipDefinition; React and Vanilla adapters contribute it automatically.

## Implementation

<ComponentAlert type="tip">

This section explains internal layout and lowering. Skip to the API reference if you only need to use the component.

</ComponentAlert>

`SurfaceDefinition` translates the parent proposal for the padded content, probes the single child, replays it, and emits a background Path, content Scope, and border Path. The overflow clip belongs only to the content Scope; an authored Core `clip` on Surface still covers the complete outer group.

```text
standard.surface → SurfaceDefinition → Core Scope(Path + child replay + Path)
```

Persisted `standard.surface` IR without `SurfaceDefinition` produces `COMPOSITE_NOT_REGISTERED`. React and Vanilla contribute the complete `SurfaceProvider → PathClipProvider` dependency chain; nested Tier 2 providers follow it in authored order and enter the same Core resolver. With a direct `compileToScene` call, `overflow: 'clip'` requires the complete `PathClipDefinition` through `clips`, alongside `SurfaceDefinition`.

The authored outer Scope also publishes a qualified handle whose id is `surface`. It inherits settled placement and transforms. Descendant handles preserve their id, role, tags, and payload and only gain the real owner path.
