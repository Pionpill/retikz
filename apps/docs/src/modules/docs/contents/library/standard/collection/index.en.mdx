Collection components draw a snapshot of a data structure. Show ordered items, key-value records, or a grid, and use connections to express operations, branches, or parent-child relationships. They suit algorithm explanations, structural diagrams, and state comparisons. Your application supplies changes; the components draw each state.

## How to choose

Start with the structure you want to emphasize: Array for order, Map for key-value pairs, and Matrix for rows and columns. Use Stack or Queue to highlight operation ends, Chain for branches and joins, and Tree for parent-child hierarchy.

| Collection                                    | When to use it                             | What the diagram emphasizes                    |
| --------------------------------------------- | ------------------------------------------ | ---------------------------------------------- |
| [Array](/library/standard/collection/array)   | Show ordered items or indexed positions    | One-dimensional cells                          |
| [Map](/library/standard/collection/map)       | Show records, properties, or configuration | Paired keys and values                         |
| [Matrix](/library/standard/collection/matrix) | Show two-dimensional arrays or matrices    | Shared row and column tracks                   |
| [Stack](/library/standard/collection/stack)   | Show a last-in, first-out state            | Stack top, open border, and operation arrows   |
| [Queue](/library/standard/collection/queue)   | Show a first-in, first-out state           | Queue front, rear, and operation arrows        |
| [Chain](/library/standard/collection/chain)   | Show a sequence with branches and joins    | Cells with sequential and parallel connections |
| [Tree](/library/standard/collection/tree)     | Show parent-child hierarchy                | Text nodes and ordered subtrees                |

## Combine collections

A cell can contain another collection. This example uses Array to establish item order and places a Map inside one cell to show record fields. The outer collection arranges items; the inner one owns its key-value structure. A nested collection adds no outer Cell background or padding by default.

## Inputs and boundaries

Array, Map, Matrix, Chain, Stack, and Queue accept explicit content, JSON data, or a schematic skeleton, with fields and shapes appropriate to each structure. Explicit content supports per-item styles, identity, and drawable composition; data displays existing values; skeleton describes schematic cells. These inputs are mutually exclusive. See each page for its syntax.

Tree uses a single root input. Nodes may be strings or objects with children, styles, and connection settings. It draws text nodes rather than arbitrary drawable content.

These components do not perform push, dequeue, search, or balancing operations. Use [Layout](/library/layout) to arrange arbitrary drawings and [presentation components](/library/standard/presentation) to wrap content in a background or border. New users can start with [installation and first render](/library/standard/get-start).
