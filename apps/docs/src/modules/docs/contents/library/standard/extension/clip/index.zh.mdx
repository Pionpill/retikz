Core 只保留最常用的矩形裁剪；其余五种官方裁剪由 Standard 沿与第三方相同的两级扩展链提供：

| 包名            | 提供内容                                                                                    |
| --------------- | ------------------------------------------------------------------------------------------- |
| `core`          | `rect` — 矩形                                                                               |
| `standard/clip` | `circle` — 圆形、`ellipse` — 椭圆、`polygon` — 多边形、`path` — 路径、`compound` — 组合裁剪 |

## 用法

本页支持两种导入方式：

- 按需导入同 kind 的 operation 与 shape Definition，例如 `CircleClipDefinition` + `CircleClipShapeDefinition`
- 整体使用 `StandardClipDefinitions` + `StandardClipShapeDefinitions`；组装 provider graph 时使用同时包含两级 provider 的 `StandardClipProviders`

两种方式都只是当前图的显式装配，不会因为 import 自动全局注册裁剪。

### React 用法

从 `@retikz/standard/clip` 导入所需的 clip Definition，传给 React `Layout` 的 `clips` 属性，再在 `Scope` 上写入裁剪 spec。

```tsx
import { Layout, Node, Scope } from '@retikz/react';
import {
  CircleClipDefinition,
  CircleClipShapeDefinition,
  CompoundClipDefinition,
  CompoundClipShapeDefinition,
} from '@retikz/standard/clip';

<Layout
  clips={[CompoundClipDefinition, CircleClipDefinition]}
  clipShapes={[CompoundClipShapeDefinition, CircleClipShapeDefinition]}
>
  <Scope
    clip={{
      kind: 'compound',
      fillRule: 'nonzero',
      children: [
        { kind: 'circle', cx: -32, cy: 0, r: 56 },
        { kind: 'circle', cx: 32, cy: 0, r: 56 },
      ],
    }}
  >
    <Node position={[0, 0]} minimumSize={{ width: 180, height: 110 }} />
  </Scope>
</Layout>;
```

### Vanilla 用法

在 `@retikz/vanilla` 中，把 Definition 放进 `compile.clips`。`input` 可以是已有的 Core IR 或 Vanilla plain spec；`mount` 使用完全相同的 `compile` 配置。

```ts
import { renderToSvgString } from '@retikz/vanilla';
import {
  CircleClipDefinition,
  CircleClipShapeDefinition,
  CompoundClipDefinition,
  CompoundClipShapeDefinition,
} from '@retikz/standard/clip';

const svg = renderToSvgString(input, {
  compile: {
    clips: [CompoundClipDefinition, CircleClipDefinition],
    clipShapes: [CompoundClipShapeDefinition, CircleClipShapeDefinition],
  },
});
```

Definition 只在当前 Core registry assembly 中有效，不进入 IR JSON，也不会通过 import 写入全局状态。缺 operation Definition 时 Core 提示 `clips`；operation 已解析但缺 shape Definition 时提示 `clipShapes`。两级都注入后，Standard schema 校验 spec 与 shape，Core 再统一生成 canonical path。

### 组合裁剪

`compound` 通过 `children` 递归组合其他已注册的裁剪 spec。上面的例子展示两个可独立切换类型的子区域，适合需要将基础裁剪组合为一个区域的场景。

该子入口提供五种 schema、`IRXxxClip`、`XxxClipShape`、两级 Definition / provider，以及三个完整集合；`@retikz/standard` 根入口不转发它们。

#### API

`compound` 使用 `IRCompoundClip`。它与每个实际 child 都需要 operation / shape 两级 Definition：

| 字段        | 类型                     | 说明                                                                                    |
| ----------- | ------------------------ | --------------------------------------------------------------------------------------- |
| `kind`      | `'compound'`             | 递归组合裁剪的判别字段                                                                  |
| `children`  | `Array<IRClip>`          | 至少一个子 operation；每项都回到当前 Core Clip registry，可来自 Core、Standard 或第三方 |
| `fillRule?` | `'nonzero' \| 'evenodd'` | 统一解释累积后的全部 child commands；省略为 `nonzero`，不是逐 child 几何交集            |

直接编译可按需传入对应 `XxxClipDefinition` 与 `XxxClipShapeDefinition`；provider graph 则以 operation provider 为 root，并在 catalog 中提供其 shape dependency。`StandardClipProviders` 是 catalog，不会因为传入完整数组就自动安装所有 clip，resolver 只物化 root 可达闭包。
