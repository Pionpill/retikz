Core 只保留最常用的矩形裁剪；Standard 沿与第三方相同的完整 `ClipDefinition` 契约提供其余五种官方实现：

| 包名            | 提供内容                                                                                    |
| --------------- | ------------------------------------------------------------------------------------------- |
| `core`          | `rect` — 矩形                                                                               |
| `standard/clip` | `circle` — 圆形、`ellipse` — 椭圆、`polygon` — 多边形、`path` — 路径、`compound` — 组合裁剪 |

下面横向展示两个内容区域如何使用基础裁剪，并由 `compound` 承载。控制项可以切换左右区域的裁剪类型和位置。

## 适用边界

- 当前图只用少量裁剪时，按需导入对应的 `XxxClipDefinition`
- 希望一次装配全部官方裁剪时，使用 `StandardClipDefinitions`
- adapter 或 Tier 2 组装 provider graph 时，使用 `StandardClipProviders` 作为 catalog

以上方式都只影响当前编译，不会因为 import 自动注册全局能力。自定义新的 clip kind 请参阅 [自定义裁剪区](/kernel/components/layout/custom-clip)。

## 定义能力

每个 Standard definition 同时拥有 spec schema、JSON-safe shape schema、`resolve` 与 `lower`。例如 `CircleClipDefinition` 的 authored spec、resolved shape 与 registry key 都使用 `kind: 'circle'`。

五种 definitions 都从 `@retikz/standard/clip` 导出：

- `CircleClipDefinition`
- `EllipseClipDefinition`
- `PolygonClipDefinition`
- `PathClipDefinition`
- `CompoundClipDefinition`

`StandardClipDefinitions` 按以上顺序包含完整集合；`@retikz/standard` 根入口不转发这些可选能力。

## 注入宿主

### React 用法

```tsx
import { Layout, Node, Scope } from '@retikz/react';
import { CircleClipDefinition, CompoundClipDefinition } from '@retikz/standard/clip';

<Layout clips={[CompoundClipDefinition, CircleClipDefinition]}>
  <Scope
    clip={{
      kind: 'compound',
      fillRule: 'nonzero',
      children: [
        { kind: 'circle', cx: -32, cy: 0, r: 56 },
        { kind: 'circle', cx: 32, cy: 0, r: 56 },
      ],
    }}
  >
    <Node position={[0, 0]} minimumSize={{ width: 180, height: 110 }} />
  </Scope>
</Layout>;
```

### Vanilla 用法

```ts
import { renderToSvgString } from '@retikz/vanilla';
import { CircleClipDefinition, CompoundClipDefinition } from '@retikz/standard/clip';

const svg = renderToSvgString(input, {
  compile: {
    clips: [CompoundClipDefinition, CircleClipDefinition],
  },
});
```

Definition 只存在于当前 Core registry assembly，不进入 IR JSON，也不写全局状态。缺少实际 kind 时，Core 统一提示通过 `clips` 注入。

## 执行机制

Standard definitions 与自定义 definitions 进入同一个 Core Clip registry。Core 依次执行 spec schema、`resolve`、shape schema、`lower` 与 canonical path 校验；renderer 只看到 `SceneClipPath`。

provider graph 中，每个 `XxxClipProvider` 都是无依赖的完整 clip provider。`StandardClipProviders` 只是 catalog；resolver 仍只物化 roots 可达的 definitions，不会自动安装全部裁剪。`compound` 的实际 child kinds 仍需由调用方作为 roots/catalog 显式贡献。

## 错误与限制

| 情况                            | 结果                                                   |
| ------------------------------- | ------------------------------------------------------ |
| 未注入当前 kind                 | Core 报未知 clip，并提示 `options.clips`               |
| 重复注册同 kind                 | registry fail-loud，不覆盖已有 definition              |
| 非法 spec 或 shape              | 同一个 definition 在对应 schema 阶段报告 provider 诊断 |
| `compound` 缺少 child kind      | child 回到当前 Clip registry 时失败                    |
| 非法 commands、cycle 或深度超限 | Core canonical path / traversal 边界 fail-loud         |

`compound` 按 authored order 累积 child commands，并由外层 `fillRule` 统一解释单一组合路径；它不是逐 child 几何交集。几何交集使用嵌套 `<Scope clip>`。

## API 参考

### 导出概览

- schema / IR：五种 `XxxClipSchema`、`IRXxxClip` 与 `XxxClipShape`
- definitions：五个 `XxxClipDefinition`、`StandardClipDefinitions`
- providers：五个 `XxxClipProvider`、`StandardClipProviders`

### IRCompoundClip

| 字段        | 类型                       | 说明                                                                            |
| ----------- | -------------------------- | ------------------------------------------------------------------------------- |
| `kind`      | `'compound'`               | 递归组合裁剪的判别字段                                                          |
| `children`  | `Array<IRClip>`            | 至少一个 child；每项回到当前 Core Clip registry，可来自 Core、Standard 或第三方 |
| `fillRule?` | `'nonzero'` \| `'evenodd'` | 统一解释累积后的全部 child commands；省略为 `nonzero`，不是逐 child 几何交集    |
