`Grid` 在指定范围内绘制规则参考线，可分别设置两个方向的间距、周期主线和外框。

## 接入方式

[安装与首次渲染](/library/standard/get-start)后，从 `/presentation` 子入口导入。下面四种接入方式绘制相同的图形；直接使用 IR 时显式注册 Definition。

## 基础用法

### 基础网格

定义网格需要 `bounds` 和 `line`；间距、对齐、样式和主线都配置在这一个属性中：

- `bounds` 可以是无序的 `start`、`end` 笛卡尔角点，也可以是中心 `position` 加 `width`、`height`
- `start`、`end` 会在 lowering 时按 x、y 分别排序，因此允许反向或相等坐标；角点只能使用笛卡尔 `Position`
- 中心形式的 `position` 是几何中心，支持 `Position` 或 `PolarPosition`；`width`、`height` 必须为非负数，PolarPosition 由 Core 解析，网格本身仍是笛卡尔网格
- `line` 省略或设为 `true` 时启用两个方向，默认格距为 `10`；设为 `false` 时关闭全部格线，但仍可独立保留 `border`
- 共享的 `line` 对象会同时配置两个方向；`{ vertical, horizontal }` 形式可以分别配置两个方向
- 每个 `GridLineInput` 可以配置正数 `spacing`、可选的数值 `origin`、`includeBoundary`、普通线 `style` 和周期性的 `major`
- 角点形式的 `origin` 使用场景坐标，中心形式使用中心局部坐标
- `border` 可独立配置，即使 `line` 为 `false` 也仍然有效

下面的网格覆盖 `[20, 20]` 到 `[260, 150]`，两个方向每隔 20 个用户单位生成一条线

`line.origin` 的坐标系取决于 `bounds` 形式：角点形式使用场景坐标，省略时取排序后的起点；中心形式使用中心局部坐标，省略时取 `[-width / 2, -height / 2]`。中心形式传 `line: { origin: 0 }` 即可让两个方向的格点穿过几何中心。使用方向对象时，可以为两个方向设置不同的数值 origin。中心的 `PolarPosition` 由 Core 解析

## 错误与限制

`spacing` 必须为正数，`major.every` 必须为正整数；尺寸与外框 padding 不能为负。角点范围允许反向或重合，中心形式只定位笛卡尔网格，不生成极坐标网格。直接 IR 未注册 `GridDefinition` 时会报告 `COMPOSITE_NOT_REGISTERED`。

## 实现原理

<ComponentAlert
  type="tip"
  title="上手阶段可跳过本节"
  description="只有在直接读写 Grid IR 或排查编译诊断时才需要理解 lowering。"
/>

Grid 的 IR 不直接成为新的渲染图元。角点形式先按两个轴独立规范化；中心形式先在中心局部矩形中生成格线。Standard 会先规范化共享或方向独立的 `line`，再枚举两个格点序列、应用普通线和主线样式，并按边框顺序组装 Core `Path`

中心形式额外使用既有 Core `Scope` 保存 `position` 的平移。这样 Cartesian Position、递归 PolarPosition 和节点引用都由 Core Scene compile 解析；Standard 不实现第二套位置解析器，也不会把它当成极坐标网格

下图从左到右展示这条确定性转换链。输出到达 `Core Path[]` 或带定位的 `Scope` 后，Grid 的职责就结束了

<ComponentPreview files="grid-lowering" hideCode size="xs" />

每条网格线都会成为一条 `move + line` 路径，边框则成为闭合路径。后续仍由 Core 的既有 compile 与 renderer 消费，因此 renderer 不需要识别 Grid

未加载 definition 的手写 `IRGrid` 不会被静默解释：Core 会给出 `COMPOSITE_NOT_REGISTERED` 诊断并跳过它。这样 Standard 仍保持按能力动态加载，同时不会改变其它图的编译行为
