`Chain` 将内容单元串联，允许分叉、嵌套分叉并重新汇合。单元可以是文字、空格或已有绘图组件，适合处理链、算法示意和论文插图。

## 接入方式

[安装与首次渲染](/library/standard/get-start)后，从 collection 入口导入。最小链只需提供 items。

## 基础用法

### 选择输入方式

items、data、skeleton 三选一。items 的字符串原样显示，显式单元用 `{ kind: 'cell', content?, id?, style?, layout? }`。data 中每个 JSON 值形成线性单元，嵌套对象或数组不会被猜测为分支；dataExpand 默认 true，可用 false 或 map/array 数组控制展开。

| 骨架形式                                                         | 效果                         |
| ---------------------------------------------------------------- | ---------------------------- |
| `skeleton={{ count: 4 }}`                                        | 四个线性空单元               |
| `skeleton={{ labels: ['A', '', 'C'] }}`                          | 线性符号，空字符串保留空单元 |
| `skeleton={{ items: ['A', { branches: [['B'], ['C']] }, 'D'] }}` | 分叉后汇合，可递归嵌套       |

骨架的三个形式互斥。

**分支骨架**使用 `skeleton.items` 描述串行与分叉结构，只含符号，不携带图形、id 或局部样式。需要这些配置时，显式分叉用 `{ kind: 'parallel', branches: [{ items: [...] }, ...] }`，可配置局部 layout 与 connection。

嵌套集合默认不增加外层 Cell 背景和 padding，普通文本仍保留浅灰背景与默认内边距。JSON 自动展开与手动嵌套行为一致；显式设置的 style.fill、layout.padding（含继承配置）仍然优先。

每个分叉至少两条非空支路，前后必须有普通单元，支路首尾也必须是普通单元。空字符串或空 cell 是单元，空数组不是直通支路。根空序列无连线，单单元不会自连。

### 对齐分支与步骤

根 layout.direction 默认 right，也支持 down。gap 和 branchGap 分别控制主轴与支路间距，均为正数，默认 24。

branchAlign 决定整个分支包围盒相对前一个单元的位置：start、center、end 或 `{ branch: 0 }`。默认 center；指定分支时，其主干与父链保持直线。横向链的起端／末端为上／下，纵向链为左／右。

spacing 默认 steps，直属项共享步骤轨道；independent 让各支路独立排布。justify 用 start、center、end 控制短支路的位置，默认 start。嵌套分叉整体占父级一步；中心对齐遇到奇数空轨道时，多余空位放在末端，不生成虚假节点。

## 扩展用法

### 组合图形内容

JSX 的结构关系为：

```text
Chain
├── ChainCell
├── ChainParallel
│   ├── ChainBranch → ChainCell / ChainParallel
│   └── ChainBranch → ChainCell / ChainParallel
└── ChainCell
```

ChainCell 的 text 与唯一图形 children 互斥，都省略表示空单元。ChainBranch 只分组，不绘制边框。items 属性用于文字，复杂图形使用 children；Vanilla 的 items.content 则接受 drawable 输入。

### 连接、标签与引用

`connection.route` 默认 `auto`：在分流、汇合处按分支包围盒预留通道，横向用 `-|-`，纵向用 `|-|`；短支路也沿公共通道汇合。普通串行项直接连接。具体折线由 Core Path 生成。

| route      | 连接方式               |
| ---------- | ---------------------- |
| `auto`     | 自动选择直线或分支通道 |
| `straight` | 起终点直连             |
| `\|-`      | 先纵后横               |
| `-\|`      | 先横后纵               |
| `-\|-`     | 横—纵—横               |
| `\|-\|`    | 纵—横—纵               |

连接引用整个单元，不固定左右或上下锚点；路径根据出入方向在单元边界处裁切。显式路由的横纵方向以绘图坐标为准，不随 Chain 排列方向交换，也不自动避让其它内容。三段折线使用 `connection.fraction` 指定中段在两单元中心之间的位置，范围为 0–1，缺省为 0.5；`fraction` 只能与显式 `-|-` 或 `|-|` 一起提供，其它路由或省略路由时均不允许携带。局部仅覆盖样式时继承原路由；指定相同路由时可继承或覆盖比例，切换路由时使用新路由自己的参数与默认值。`auto` 的通道位置由布局计算。

示例将连接设为蓝色。React／Vanilla 的 connection.path.arrow 支持 none、单向或双向箭头，通过现有路径归一化转换成 Source marks；IR 用 marks，空数组关闭默认末端箭头。路径标签字段是 label。path 配置不能改写路径的身份、类型或步骤。

显式 cell id 可用于外部路径引用：React／Vanilla 使用 `target.right`，Source IR 使用 `{ id: 'target', anchor: 'right' }`，指向单元实际边框，而非内部内容或整条支路。根 label 附着在整个 Chain 上；分支配置逐字段继承，显式 marks 数组替换继承的标记列表。

## 错误与限制

输入混用、空支路、没有前后单元的分叉、非法主干下标、非正间距会失败并提供结构位置。父级空间不足不会压缩单元或 gap。Chain 不支持任意跨支路边、回边、闭合链或自动避障；图式关系使用 Graph。

### 分支合并与轨道对齐

布局需要跟踪三个对象：

- **布局块**：一个单元、一段序列或一组并行分支的整体尺寸与内部位置。
- **基线**：块内用于与前后序列对齐的主轴位置，以距块顶边的偏移表示。
- **入口与出口**：允许前后块连接的单元格布局对象引用，不是固定锚点或坐标快照。

下图使用同一组内容，较长的 Bbbbbbbb 让两种居中的区别可见。观察下方 E 与上方 C 的位置：两图都使用 `justify="center"` 和 `branchAlign="center"`。

<ComponentPreview files="branch-layout-figure" size="sm" hideCode type="illustration" />

- `independent` 先按各格尺寸独立排布，再将较短支路放到最大支路宽度的中央；E 不必对齐 C。
- `steps` 先按步骤序号汇总各支路的最大尺寸，形成共享轨道，再把各块居中放入对应轨道。上方有三个步骤、下方只有一个时，E 使用第二条轨道，因此与 C 对齐；只有两个步骤时，居中取前一条轨道，剩余空轨道留在末端。轨道分配不会强行拉宽单元格本身。

布局从内向外递归合并。串行块按基线对齐，入口取第一块、出口取最后一块；并行块纵向叠放支路，汇总各支路入口与出口。图中并行块的入口是 Bbbbbbbb、E，出口是 D、E。`branchAlign` 决定这个整体与 A、F 对齐的位置：`center` 使用块的交叉轴中点，指定支路时则使用该支路的基线。计算始终使用主轴与交叉轴，向下排列时在最终输出前交换坐标与尺寸。

### 连接关系与路径生成

布局阶段把前一块的每个出口与后一块的每个入口配对。它只记录两端单元格的引用、连接配置及必要的自动通道比例；块继续平移时，端点仍引用同一布局对象，不维护随位置变化的折线点列。下图沿用 A 进入两条分支的例子：

<ComponentPreview files="connection-compile-figure" size="xs" hideCode type="flow" />

所有位置确定后，编译入口用单元格的最终分配边界创建私有矩形引用节点，再将每条连接转为普通 Core Path。节点与路径位于独立命名空间内，路径通过 id 引用整个矩形，因此未显式提供 cell id 也能连接，不会固定某一侧的 anchor。内部内容比单元格窄时，连接仍以分配边界为准。

`auto` 在普通相邻单元之间生成直线，在分叉和汇合处使用块间空隙的中线作为通道；比例相对两端中心计算，整体平移不改变它。向右排列使用横—纵—横，向下排列使用纵—横—纵。显式路由则保持绘图坐标中的横纵含义。后续节点边界裁切、折点落在节点内时的可见路径处理，以及箭头和标签均交由 Core 完成；这不包含其它节点的自动避障。
