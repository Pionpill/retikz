Standard Rectangle preserves shape and sizing intent and compiles to one Core Path. For content sizing and connection boundaries, use [node shapes](/library/extension/shape).

## Entry points

Import this family from the `/shape` subpaths of the three packages; the root entries do not re-export it. Node shape extensions use `@retikz/extension`.

React components contribute the required Definition through the matching Vanilla adapter. Vanilla uses `shape.xxx({ id, ...input })` with the same explicit identity for the embed and its final path. Neither Vanilla nor React generates a persistent graphic id when id is omitted. Direct JSON compilation requires the corresponding Definition in `composites`. All three entry points share the geometry contract below.

| Entry   | Public API                                                         |
| ------- | ------------------------------------------------------------------ |
| React   | `Rectangle` — `@retikz/standard-react/shape`                       |
| Vanilla | `shape.rectangle` — `@retikz/standard-vanilla/shape`               |
| JSON    | `RectangleSchema / RectangleDefinition` — `@retikz/standard/shape` |

## Usage

`<Rectangle>` draws a rectangle at a position, expanding to an underlying `<Path>`. It fits cases where you know two corners, a center plus size, or one corner plus size.

```tsx
import { Rectangle } from '@retikz/standard-react/shape';
```

```tsx
<Rectangle corner1={[-40, -20]} corner2={[40, 20]} cornerRadius={6} />
```

`<Rectangle>` can use two corners, or derive the corners from a center and size. Use `cornerRadius` for rounded rectangles.

| Form                         | Best for               |
| ---------------------------- | ---------------------- |
| `{ corner1, corner2 }`       | Known opposite corners |
| `{ center, width, height }`  | Known center and size  |
| `{ center, side }`           | Square                 |
| `{ corner1, width, height }` | Expand from one corner |

## Input constraints

Choose exactly one geometry description. Width, height and side length must be finite and nonnegative. Opposite corners accept Core Targets; forms that calculate coordinates require literal coordinates.

## Compilation

The Standard schema validates exclusive geometry inputs and dimensional relations. Its Definition expands the shape into Path steps during compilation; Core then resolves Targets and generates geometry. No Node or extra Scope is added. RegularPolygon and Star bake rotate into vertices once; other rotations and all scaling use Path semantics.

### Rectangle path expansion

`<Rectangle>` first converges its four prop forms on two opposite corners, `from` and `to`. The upper route in the figure passes through Targets (resolvable points, including coordinates and node ids); the lower route computes the corners from dimensions in the React layer:

<ComponentPreview files="rectangle-lowering-flow" size="lg" hideCode type="illustration" />

Only `corner1 + corner2` passes both Targets through unchanged, so it can reference node ids. Forms such as `center + width + height` need arithmetic first and accept only literal `[x, y]` coordinates. The `rectangle` step then resolves both corners and emits an independent closed subpath; `cornerRadius` replaces each corner with an arc and is clamped to half the shorter side.

If either node reference cannot be resolved, the whole Path is skipped with a warning instead of leaving a partial rectangle.
