`Rectangle` draws a rectangle from opposite corners, a center and size, or one corner and size. Use it for panel outlines, borders, and rounded backgrounds.

## Using this topic

After [installation and first rendering](/library/standard/get-start), choose a host from the three `/shape` subpaths. All four forms draw the same minimal shape. React and Vanilla adapters supply the required definitions; direct IR requires explicit Definition injection.

## Basic usage

`<Rectangle>` draws a rectangle at a position, expanding to an underlying `<Path>`. It fits cases where you know two corners, a center plus size, or one corner plus size.

```tsx
import { Rectangle } from '@retikz/standard-react/shape';
```

```tsx
<Rectangle corner1={[-40, -20]} corner2={[40, 20]} cornerRadius={6} />
```

`<Rectangle>` can use two corners, or derive the corners from a center and size. Use `cornerRadius` for rounded rectangles.

| Form                         | Best for               |
| ---------------------------- | ---------------------- |
| `{ corner1, corner2 }`       | Known opposite corners |
| `{ center, width, height }`  | Known center and size  |
| `{ center, side }`           | Square                 |
| `{ corner1, width, height }` | Expand from one corner |

## Errors and limitations

Choose exactly one geometry description. Width, height and side length must be finite and nonnegative. Opposite corners accept Core Targets; forms that calculate coordinates require literal coordinates.

### Rectangle path expansion

`<Rectangle>` first converges its four prop forms on two opposite corners, `from` and `to`. The upper route in the figure passes through Targets (resolvable points, including coordinates and node ids); the lower route computes the corners from dimensions during Standard lowering:

<ComponentPreview files="rectangle-lowering-flow" size="lg" hideCode type="illustration" />

Only `corner1 + corner2` passes both Targets through unchanged, so it can reference node ids. Forms such as `center + width + height` need arithmetic first and accept only literal `[x, y]` coordinates. The `rectangle` step then resolves both corners and emits an independent closed subpath; `cornerRadius` replaces each corner with an arc and is clamped to half the shorter side.

If either node reference cannot be resolved, the whole Path is skipped with a warning instead of leaving a partial rectangle.
