Persisted Standard IR contains only JSON-safe data. Definitions contain functions, so they must be assembled before compilation. Reusable authoring modules contribute rooted providers; direct-IR hosts that already own a complete Definition set continue using Core's `CompileOptions.composites`:

```ts
import { compileToScene } from '@retikz/core';
import { FrameDefinition, GridDefinition } from '@retikz/standard';

const scene = compileToScene(persistedIR, {
  composites: [GridDefinition, FrameDefinition],
});
```

Standard provides no bundle, preset, global registry, or built-in allowlist. `GridProvider`, `AxesProvider`, `FrameProvider`, `SurfaceProvider`, and `LegendProvider` each generate one exact-key Definition. The Core resolver computes the transitive closure from actual roots, and the result still enters Core's single composite registry

## Scope

The provider path serves React / Vanilla adapters, cross-namespace third-party composites, and toolchains that reuse dependency assembly. The direct-Definition path serves server-side compilation, file restoration, LLM-generated IR, and hosts that already know the complete dependency set. Both answer which Definitions are available during compilation; neither provides dynamic import, runtime package splitting, renderer settings, layout policy, or host lifecycle state

React JSX and Vanilla embeds remain authoring surfaces owned by their adapters. They contribute equivalent `CompositeDependencyContribution` values, while direct-IR hosts provide complete `composites` explicitly without dependency guessing

## Define a capability

Each Standard composite owner directly exports its Definition, factory, schema, artifact, and lowering:

```ts
import { createGrid, GridDefinition, GridSchema } from '@retikz/standard';

const grid = GridSchema.parse(createGrid({ bounds: { start: [20, 20], end: [260, 150] }, line: { spacing: 20 } }));
const compileOptions = { composites: [GridDefinition] };
```

Third-party composites use Core's `defineComposite()` in the same way, then declare required Standard provider keys in their own provider:

```ts
import type { CompositeDependencyProvider } from '@retikz/core';

import { resolveCompositeDependencies } from '@retikz/core';
import { FrameProvider } from '@retikz/standard';

const CardProvider = {
  key: { namespace: 'third', type: 'card' },
  dependencies: [FrameProvider.key],
  datasets: {},
  makeDefinition: () => CardDefinition,
} satisfies CompositeDependencyProvider;

const composites = resolveCompositeDependencies({
  contributions: [{ roots: [CardProvider.key], providers: [CardProvider, FrameProvider] }],
});
```

`namespace` and `type` form the Core lookup key; persisted JSON contains the discriminator and data, not the Definition. Providers do not perform dynamic imports, so callers still import and carry every required provider explicitly

## Inject into a host

### Direct IR and React `ir` mode

```tsx
import { Layout } from '@retikz/react';
import { FrameDefinition, GridDefinition } from '@retikz/standard';

<Layout ir={persistedIR} composites={[GridDefinition, FrameDefinition]} />;
```

If a Definition is missing, Core retains its `COMPOSITE_NOT_REGISTERED` diagnostic. Core-native children and other registered composites continue according to Core semantics

### React JSX

`<Grid>`, `<Axes>`, `<Frame>`, `<Surface>`, and `<Legend>` set their own provider as a root through static InputEmbed adapters. `<Surface>` then appends the contribution of its one Tier 2 child, preserving authored provider order. Layout containers create InputEmbed values from `@retikz/layout-react`; `<Layout>` hands them to Vanilla processing for the single Core resolver path and creates no second registry

### Vanilla

Vanilla Scenes use InputEmbed adapters for authoring. Pass only the adapters used by the current Scene, or use `StandardInputEmbedAdapters` as the convenience array. The adapters contribute a rooted provider graph that Vanilla processing sends through the single Core resolver:

```ts
import { GridDefinition } from '@retikz/standard';
import { renderToSvgString } from '@retikz/vanilla';

const svg = renderToSvgString(persistedIR, {
  compile: { composites: [GridDefinition] },
});
```

`StandardInputEmbedAdapters` is an authoring convenience from `@retikz/standard-vanilla`, not a Standard compile preset. Layout authoring uses `LayoutInputEmbedAdapters` from `@retikz/layout-vanilla`

## Execution model

1. An adapter or toolchain roots the provider key for the authored capability and carries available providers
2. The Core resolver preflights missing dependencies, cycles, and maker / dependency / dataset identity conflicts
3. The resolver emits Definitions in dependency-first order, followed by host-authored explicit `composites`
4. Core builds the single composite registry for this compilation from `namespace` and `type`
5. Core validates IR, expands Definitions, and produces Scene, diagnostics, and applicable typed artifacts

## Errors and limits

| Situation                                                              | Result                                                                    |
| ---------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| A root or transitive dependency has no provider                        | The resolver reports the complete dependency chain before maker / compile |
| One provider key has different makers or ordered dependencies          | The resolver fails loudly; there is no first- or last-wins policy         |
| One provider key repeats a dataset reference with a different identity | Only `Object.is`-identical values deduplicate; otherwise resolution fails |
| A provider result and explicit `composites` use the same key           | The same Definition object deduplicates; a different object fails loudly  |
| Direct IR omits a required Standard Definition                         | Core emits `COMPOSITE_NOT_REGISTERED` with an explicit diagnostic         |
| A Definition is placed in persisted JSON                               | Not allowed; JSON contains schema-defined data only                       |

## API reference

| Export                                                                                         | Package                    | Responsibility                                              |
| ---------------------------------------------------------------------------------------------- | -------------------------- | ----------------------------------------------------------- |
| `GridProvider`, `AxesProvider`, `FrameProvider`, `SurfaceProvider`, `LegendProvider`           | `@retikz/standard`         | Rooted providers shared by React, Vanilla, and toolchains   |
| `GridDefinition`, `AxesDefinition`, `FrameDefinition`, `SurfaceDefinition`, `LegendDefinition` | `@retikz/standard`         | Final Core Definitions for direct-IR hosts                  |
| `GridSchema`, `createGrid()`, and peers                                                        | `@retikz/standard`         | Validate and construct JSON-safe Standard input             |
| `StandardInputEmbedAdapters`                                                                   | `@retikz/standard-vanilla` | Convenience array for the current Standard Vanilla adapters |

All three Standard packages still expose only their root entry. Providers and Definitions are named exports, so consumers' bundlers can tree-shake by reference. On-demand use means the reachable closure of current contributions; it is not runtime dynamic loading
