---
title: Capability Loading
description: Assemble optional Standard capabilities through direct CompileOptions injection or an adapter provider graph while always reusing Core's registry and compile path.
---

Persisted IR contains JSON-safe data only. Definitions contain runtime logic and must be assembled before compilation. This page separates two explicit paths: direct-IR hosts provide a complete Definition set, while React, Vanilla, and Tier 2 authoring declare provider contributions that Core resolves for the current invocation.

Standard provides no global registration, preset, bundle, or implicit full set. Optional shapes, arrows, clips, and path generators are imported only from their `@retikz/standard/<capability>` subpaths; the `@retikz/standard` root keeps composites only and does not aggregate these Definitions.

## Direct Definition injection

Hosts that compile directly, restore persisted IR, or already know the complete dependency set place each Definition in its matching Core compile option:

```ts
import { compileToScene } from '@retikz/core';
import { DiamondArrowDefinition } from '@retikz/standard/arrow';
import { CompoundClipDefinition } from '@retikz/standard/clip';
import { ParabolaPathGeneratorDefinition } from '@retikz/standard/path-generator';
import { CrossShapeDefinition } from '@retikz/standard/shape';

const result = compileToScene(scene, {
  shapes: [CrossShapeDefinition],
  arrows: [DiamondArrowDefinition],
  clips: [CompoundClipDefinition],
  pathGenerators: [ParabolaPathGeneratorDefinition],
});
```

React's `<Layout>` exposes the same `shapes`, `arrows`, `clips`, and `pathGenerators` entry points. Provide only what the current figure uses; this is neither a dynamic import nor a change to another compilation's registry.

## Adapter provider graph

React, Vanilla, and first-party Tier 2 packages can declare `CoreProviderContribution` during authoring. A contribution contains the required roots and its statically carried providers. A regular provider key uses `capability + name`; a composite key uses `namespace + type`.

Core's `resolveCoreProviderDependencies()` handles roots, transitive dependencies, and merging with explicit definitions, then produces ordinary compile options such as `shapes`, `arrows`, `clips`, `pathGenerators`, and `composites`. A Standard subpath supplies only static Definitions or providers; it does not implement merging, deduplication, lookup, or a second registry.

## Execution and persistence boundary

1. A direct host supplies Definitions, or an adapter declares contributions for authored capabilities
2. Before compilation, Core resolves the dependency-first closure of the current roots and checks missing entries, cycles, and conflicts
3. Core merges the result and the host's explicit Definitions into their matching compile options
4. Core uses one registry to validate IR, find Definitions, and produce Scene output and diagnostics

Providers, makers, and datasets exist only during authoring and compile assembly. They must not enter IR, Scene, artifacts, manifests, or persisted JSON.

## Errors and limits

| Situation                                                          | Result                                                                          |
| ------------------------------------------------------------------ | ------------------------------------------------------------------------------- |
| A root or transitive dependency lacks a provider                   | The Core resolver reports the complete dependency chain before maker or compile |
| The same provider key has different makers or ordered dependencies | The Core resolver fails explicitly; there is no first-wins or last-wins rule    |
| A provider result and explicit Definition use the same key         | The same Definition object deduplicates; different objects fail explicitly      |
| IR refers to an unassembled optional capability                    | Its Core registry lookup fails explicitly and reports available entries         |
| A Definition or provider is placed in persisted JSON               | Not allowed; JSON contains schema-defined data only                             |
