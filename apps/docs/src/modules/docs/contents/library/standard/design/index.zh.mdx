---
title: 设计理念
description: 理解 Standard 如何把基础绘图能力组合成常见组件，以及它负责的绘图任务。
---

画一个圆、排列一组条目、给内容加上边框，都是常见的绘图任务。Standard 为这些任务提供可以直接使用的组件：作者描述要画的对象，组件处理轮廓、内容排布或外围样式。

## 把常见任务写成组件

Standard 基于 Kernel 的节点、路径和容器能力，保留“圆”“列表”“图例”等容易理解的对象名称。你可以从任务选择组件，而不必每次从基础图元重新组合。

| 想表达什么             | 可用组件          | 组件负责什么                       |
| ---------------------- | ----------------- | ---------------------------------- |
| 已知尺寸的圆或矩形     | Circle、Rectangle | 根据几何参数生成轮廓               |
| 有顺序或键值的可见内容 | List、Map         | 组织条目、单元格和它们的边界       |
| 内容的背景或符号说明   | Surface、Legend   | 根据内容形成外围区域或展示说明条目 |

例如，List 中的条目可以继续包含 Map。作者声明嵌套关系，组件根据内容安排单元格；不需要为每个单元格维护一组坐标。

## 与基础图元一起使用

Standard 组件最终仍使用 Kernel 的绘图能力，能和普通 Node（节点）、Path（路径）出现在同一张图中。形状组件生成可绘制的轮廓；需要包裹内容的组件根据内部内容安排位置和边界。它们共用图形的输出方式，因此可以逐步加入现有图形。

Standard 增加的是**通用绘图对象的表达方式**，不解释业务数据。List 表达可见的条目结构，不负责运行时集合操作；Legend 展示作者提供的说明，不从数据自动推断图例。

## 把不同问题留给对应能力

| 需要解决的问题               | 选择      |
| ---------------------------- | --------- |
| 直接使用常见形状、集合或说明 | Standard  |
| 为已有节点或路径增加可选画法 | Extension |
| 根据子图尺寸安排它们的位置   | Layout    |
| 根据数据生成刻度和视觉映射   | Plot      |

这样的分工让 Standard 保持通用：绘图作者可以独立使用它，领域包也可以复用同一组件，而不用把数据或领域规则写进 Standard。
