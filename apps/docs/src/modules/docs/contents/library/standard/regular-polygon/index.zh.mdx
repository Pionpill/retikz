用 Standard 的 RegularPolygon 保留形状与尺寸意图，编译时生成一条 Core Path。适合已知几何参数的独立轮廓；需要节点文字占位与连接边界时，使用[节点形状](/library/extension/shape)。

## 接入方式

形状家族统一从三个包的 `/shape` 子入口导入，根入口不重复导出。节点形状扩展使用 `@retikz/extension`。

React 组件通过同名 Vanilla adapter 局部贡献所需 Definition。Vanilla 使用 `shape.xxx({ id, ...input })`，显式 id 同时标识 embed 和最终路径；Vanilla 与 React 省略 id 时均不生成持久化图元 id。直接编译 JSON 时，在 `composites` 中显式传入对应 Definition。三种入口共享下列几何契约。

| 入口    | 公开 API                                                                     |
| ------- | ---------------------------------------------------------------------------- |
| React   | `RegularPolygon` — `@retikz/standard-react/shape`                            |
| Vanilla | `shape.regularPolygon` — `@retikz/standard-vanilla/shape`                    |
| JSON    | `RegularPolygonSchema / RegularPolygonDefinition` — `@retikz/standard/shape` |

## 用法

`<RegularPolygon>` 在指定位置画一个等边多边形，展开成底层 `<Path>`。

```tsx
import { RegularPolygon } from '@retikz/standard-react/shape';
```

```tsx
<RegularPolygon center={[0, 0]} radius={36} sides={6} />
```

`<RegularPolygon>` 用外接半径或边长确定大小。`sides` 至少为 `3`，`rotate` 可以调整整体朝向。

| 写法                            | 适合         |
| ------------------------------- | ------------ |
| `{ center, radius, sides }`     | 已知外接半径 |
| `{ center, sideLength, sides }` | 已知边长     |

## 输入约束

在 radius 与 sideLength 中选择一个，数值必须有限且非负。sides 必须为至少 3 的整数，center 使用字面坐标。rotate 默认 −90°，只在生成顶点时应用一次。

## 编译过程

Standard 的 schema 负责互斥输入和尺寸关系；Definition 在编译时把形状意图展开为 Path steps，Core 再解析 Target、生成几何并渲染。不会添加 Node 或额外 Scope。除正多边形和星形将 rotate 烘焙进顶点外，其余旋转与缩放使用 Path 规则。

### 正多边形的顶点展开

图中的半径与边长输入先收敛为同一个顶点环，再由唯一的主链展开成 Path：

<ComponentPreview files="polygon-lowering-flow" size="md" hideCode type="illustration" />

`radius` 可以直接作为外接半径；`sideLength` 则先通过 `R = sideLength / (2·sin(π/sides))` 换算到同一半径。随后第 `k` 个顶点取 `rotate + k·360/sides` 的方向，`rotate` 直接烘焙进顶点坐标，不会再作为底层 Path 的 transform 透传。

因此输出拓扑始终是一次 `move`、`sides - 1` 次 `line` 和一次 `cycle`。`center` 不是字面 `[x, y]`，或 `sides` 不是至少为 3 的整数时，会在生成顶点环之前报错。
