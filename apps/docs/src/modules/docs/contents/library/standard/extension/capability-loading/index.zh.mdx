持久化 Standard IR 只保存 JSON-safe 数据，Definition 中的函数必须在编译前装配。可复用 authoring 模块贡献 rooted providers；已经拥有完整 Definition 集合的直接 IR 宿主继续使用 Core `CompileOptions.composites`：

```ts
import { compileToScene } from '@retikz/core';
import { FrameDefinition, GridDefinition } from '@retikz/standard';

const scene = compileToScene(persistedIR, {
  composites: [GridDefinition, FrameDefinition],
});
```

Standard 不提供 bundle、preset、全局 registry 或内置白名单。`GridProvider`、`AxesProvider`、`FrameProvider`、`SurfaceProvider` 与 `LegendProvider` 各自只生成一个 exact-key Definition；Core resolver 从实际 roots 计算传递闭包，最终仍进入 Core 唯一 composite registry

## 适用边界

Provider 路径适用于 React / Vanilla adapter、跨 namespace 的第三方 composite，以及需要复用依赖装配的工具链。直接 Definition 路径适用于服务端编译、文件恢复、LLM 生成 IR 和已经掌握完整依赖集合的宿主。两条路径只解决“编译时使用哪些 Definition”，不负责动态 import、运行时包分割、renderer 配置、布局策略或宿主生命周期

React JSX 和 Vanilla embed 由各自 adapter 负责 authoring，并贡献相同的 `CompositeDependencyContribution`。直接 IR 不猜测依赖，仍由宿主显式传入完整 `composites`

## 定义能力

每个 Standard composite owner 直接导出自己的 Definition、factory、schema、artifact 和 lowering：

```ts
import { GridDefinition, createGrid, GridSchema } from '@retikz/standard';

const grid = GridSchema.parse(createGrid({ bounds: { start: [20, 20], end: [260, 150] }, line: { spacing: 20 } }));
const compileOptions = { composites: [GridDefinition] };
```

第三方 composite 同样使用 Core 的 `defineComposite()` 产生 Definition，并用一个 provider 声明所需 Standard provider 的 key：

```ts
import type { CompositeDependencyProvider } from '@retikz/core';

import { resolveCompositeDependencies } from '@retikz/core';
import { FrameProvider } from '@retikz/standard';

const CardProvider = {
  key: { namespace: 'third', type: 'card' },
  dependencies: [FrameProvider.key],
  datasets: {},
  makeDefinition: () => CardDefinition,
} satisfies CompositeDependencyProvider;

const composites = resolveCompositeDependencies({
  contributions: [{ roots: [CardProvider.key], providers: [CardProvider, FrameProvider] }],
});
```

Definition 的 `namespace` 与 `type` 是 Core lookup key；JSON IR 只保存对应 discriminator 和数据。Provider 不做动态 import，调用方仍要正常导入并显式携带需要的 provider

## 注入宿主

### 直接 IR 与 React `ir` 模式

```tsx
import { Layout } from '@retikz/react';
import { FrameDefinition, GridDefinition } from '@retikz/standard';

<Layout ir={persistedIR} composites={[GridDefinition, FrameDefinition]} />;
```

缺少某个 Definition 时，Core 保留 `COMPOSITE_NOT_REGISTERED` 诊断。Core 原生 child 和其它已注册 composite 仍按 Core 规则处理

### React JSX

`<Grid>`、`<Axes>`、`<Frame>`、`<Surface>` 与 `<Legend>` 通过静态 InputEmbed adapter 把各自 provider 设为 root。`<Surface>` 还把唯一 Tier 2 child 的 contribution 接在自身之后，保持 authored provider 顺序。布局容器由 `@retikz/layout-react` 生成 InputEmbed；`<Layout>` 把 Input 交给 Vanilla processing 统一解析 contributions，不创建第二套 registry

### Vanilla

Vanilla Scene 使用 InputEmbed adapter 做 authoring；当前使用的 adapter 可以按需传入，也可以使用 `StandardInputEmbedAdapters` 这一便利数组。adapter 贡献 rooted provider graph，并由 Vanilla processing 统一交给 Core resolver：

```ts
import { GridDefinition } from '@retikz/standard';
import { renderToSvgString } from '@retikz/vanilla';

const svg = renderToSvgString(persistedIR, {
  compile: { composites: [GridDefinition] },
});
```

`StandardInputEmbedAdapters` 属于 `@retikz/standard-vanilla` 的 authoring 便利入口，不是 Standard 的 compile preset。布局 authoring 使用 `@retikz/layout-vanilla` 的 `LayoutInputEmbedAdapters`

## 执行机制

1. adapter 或工具链把 authored capability 的 provider key 设为 root，并携带可用 providers
2. Core resolver 预检缺失依赖、cycle、maker / dependency / dataset identity 冲突
3. resolver 按 dependency-first 顺序生成 Definition，并在其后追加宿主显式 `composites`
4. Core 按 `namespace` / `type` 建立本次编译的唯一 composite registry
5. Core 校验 IR、展开 Definition，并产生 Scene、diagnostic 和适用的 typed artifact

## 错误与限制

| 情况                                              | 结果                                               |
| ------------------------------------------------- | -------------------------------------------------- |
| root 或传递依赖缺少 provider                      | resolver 在 maker / compile 前报告完整依赖链       |
| 同 provider key 的 maker 或有序 dependencies 不同 | resolver fail-loud，不采用 first / last wins       |
| 同 provider key、同 dataset reference 的值不同源  | 只有 `Object.is` 同源可去重，否则 fail-loud        |
| provider 结果与显式 `composites` 使用同 key       | 同一个 Definition 对象去重；不同对象 fail-loud     |
| 直接 IR 缺少需要的 Standard Definition            | Core 产生 `COMPOSITE_NOT_REGISTERED`，保持明确诊断 |
| Definition 进入持久化 JSON                        | 不允许；JSON 只保存 schema 定义的数据              |

## API 参考

| 导出                                                                                           | 所属包                     | 职责                                           |
| ---------------------------------------------------------------------------------------------- | -------------------------- | ---------------------------------------------- |
| `GridProvider`、`AxesProvider`、`FrameProvider`、`SurfaceProvider`、`LegendProvider`           | `@retikz/standard`         | React / Vanilla / 工具链共用的 rooted provider |
| `GridDefinition`、`AxesDefinition`、`FrameDefinition`、`SurfaceDefinition`、`LegendDefinition` | `@retikz/standard`         | 直接 IR 宿主使用的最终 Core Definition         |
| `GridSchema`、`createGrid()` 等                                                                | `@retikz/standard`         | 校验和构造 JSON-safe Standard 输入             |
| `StandardInputEmbedAdapters`                                                                   | `@retikz/standard-vanilla` | 当前 Standard Vanilla adapter 便利数组         |

三个 Standard 包仍只发布根入口；Provider 与 Definition 都是 named export，消费方 bundler 可按引用 tree-shaking。按需使用指当前 contributions 的可达闭包，不等同于运行时动态加载
