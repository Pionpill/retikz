`Map` draws ordered key/value pairs in two aligned columns, suitable for object fields and records. It handles presentation, not dictionary lookup or deduplication.

## Using this topic

After [installation](/library/standard/get-start), choose one of the four entry points. JSX and Vanilla adapters collect required definitions; direct IR supplies the component definition explicitly. Cell clipping additionally requires `PathClipDefinition` from `@retikz/extension`.

## Basic usage

### Choose an input form

The four input forms are mutually exclusive. Choose based on whether you need cell-specific styling, identities, or drawable content.

| Input          | Use it for                                           |
| -------------- | ---------------------------------------------------- |
| `skeleton`     | Symbolic keys and empty value cells without data     |
| `entries`      | Explicit text, cell styles, and ids                  |
| `data`         | Recursively displaying a JSON object                 |
| JSX `children` | Composing drawings with MapEntry / MapKey / MapValue |

`entries` preserves array order. Each entry has a `key` and a `value`, both accepting a string or `{ content?, id?, style?, layout? }`. Displayed keys may repeat; strings do not automatically become cell ids.

### Draw a schematic skeleton

Use `skeleton: { keys: ['k₁', 'k₂', 'kₙ'] }` to illustrate a key/value structure without real values. Components, Vanilla `map()`, and IR share this configuration. Do not combine it with data, entries, or JSX children.

The key array determines row count. Keys appear as plain text and value cells have no content. Order, repeated keys, and empty strings are preserved, with no JSON quoting or inferred identities. `keys: []` creates an empty collection without row gaps.

Empty value cells retain shared and role styles, dimensions, and padding. Use entries for per-cell ids, styles, or drawings. Both key and value roles remain required, but content is optional, as in `{ key: 'k₁', value: {} }`. JSX allows empty MapKey / MapValue components, but neither role can be omitted. Explicit `content: ''` remains empty text, distinct from absent content.

### Style and dimensions

Style precedence is **structural defaults → overall style → style.key / style.value → cell style**. Keys and values can have distinct appearances.

Font fields merge individually. `fillOpacity` affects only the background; `opacity` affects the whole cell. Use `fill: 'none'` to hide the background or `stroke: 'none'` to hide the border. Defaults are no border or rounding, gray / 0.14 backgrounds, and gray / 0.4 for Map keys.

<ComponentPreview files="map-styles" size="sm" />

`layout.width` / `height` set the cell border-box dimensions, including padding; zero is valid. Omit them or use `'auto'` for natural sizing. Cell-level values take precedence, and explicit `'auto'` clears an inherited fixed dimension. `layout.padding` defaults to 8 and `layout.gap` to 2. Content is centered inside the padded area.

Layout precedence is **overall layout → layout.key / layout.value → cell layout**. Each column uses its largest width requirement and each row its tallest cell. Fixed dimensions are not stretched; smaller cells align to the track start, so borders in one column or row may differ in size. `layout.gap` accepts a number or `{ row, column }`.

### Container labels

`label` adds text to the whole container. It accepts one object or an array, with position, distance, rotation, and pin options. Labels do not enlarge the layout allocation but do contribute to the final drawing bounds, including on empty containers.

```tsx
<Map entries={[{ key: 'a', value: '1' }]} label={{ text: 'record', position: 'top' }} />
```

Overall font, text color, and `defaults.label` supply label defaults, overridden by the label itself. Key/value roles and cell styles do not affect container labels, and nested containers created by `data` do not inherit the root label.

## Extended usage

### Compose drawable content

Each `MapEntry` must contain exactly one `MapKey` and one `MapValue`. Each cell accepts either `text` or exactly one drawable child, never both. Omitting both preserves an empty cell.

```text
Map
└── MapEntry
    ├── MapKey
    └── MapValue
        └── List
```

`MapEntry` represents one record; `MapKey` and `MapValue` occupy its key and value columns. These markers declare content and cannot render independently outside this parent-child structure.

Wrap multiple drawings in one `Scope` before putting them in a cell. React data arrays contain text configurations, not JSX. Vanilla cell `content` accepts text or one authoring child; direct IR `content` accepts text or one serializable drawable.

### Display JSON data directly

`data` accepts a JSON object. `dataExpand` controls nested objects and arrays and defaults to `true`. It preserves the outer Map structure and applies only to `data`, not explicit cells or JSX composition.

| Setting                               | Nested objects | Nested arrays |
| ------------------------------------- | -------------- | ------------- |
| `true` (default) or `['map', 'list']` | Map            | List          |
| `false` or `[]`                       | JSON text      | JSON text     |
| `['map']`                             | Map            | JSON text     |
| `['list']`                            | JSON text      | List          |

Generated components recursively use the same selection. A structure displayed as text retains its entire subtree as compact JSON and stops expanding. Empty objects and arrays always appear as `{}` and `[]`. Selection order and duplicates do not affect the result. The example starts with arrays only; switch between the four modes.

<ComponentPreview files={['map-data', 'map-data.preview.tsx']} defaultSourceFile="map-data.preview.tsx" />

Object keys are displayed as plain text; string values use quoted, escaped JSON literals, distinguishing `"null"` from `null`. Numbers, booleans, and null retain their literal forms. Nested empty objects and arrays appear as `{}` and `[]`; an empty root has zero natural size. Objects follow own enumerable string-key order, with integer-index keys first. Use Map `entries` for custom ordering or repeated keys.

Data never generates cell ids, so repeated values and empty strings are valid. Fields named `id`, `style`, or `type` remain ordinary data. For connections or per-cell customization, use explicit cells containing a nested component with `data`. Overall style / layout affects the current level only; nested structures use their own defaults, with font and text color inherited through content. Fixed sizes clip the nested drawing as a whole instead of resizing every descendant cell.

React / Vanilla assemble nested dependencies automatically. For direct IR with `data`, register `ListDefinition` and `MapDefinition` in `composites` and `PathClipDefinition` from `@retikz/extension` in `clips`. Source IR preserves the original data, not JSX or functions.

### Reference cells and control overflow

Set a cell `id` to reference it from a path endpoint, for example `to={{ id: 'selected', anchor: 'right' }}`. The reference uses the cell border rectangle, excluding gaps, indices, and visual overflow. Hiding the background does not change it. An id on the content references its own geometry. Cells without ids do not acquire identities from array indices.

Automatic cells default to `overflow: 'visible'`; fixing either axis changes the default to `'clip'`. Set `layout.overflow` explicitly to override it; cell-level settings win. Clipping neither scales content nor automatically wraps it to fit a slot. Direct IR using clipping must register `PathClipDefinition` in `clips`. Container transforms and clipping also affect labels, but cell clipping does not clip container labels.

## Errors and limitations

- Do not mix input forms. Explicit cell ids must be unique within the container; configure repeated text separately from identity.
- Composition markers must be direct children of their required parents, with empty cells allowed and exactly one drawable when provided. Invalid JSX composition raises an error.
- `data` accepts JSON value trees only, not functions, runtime instances, cycles, or sparse arrays. Project data before rendering when needed.
- A fixed cell may be smaller than its content, but compilation fails if the parent allocation cannot fit all cells and gaps. Extra parent space remains at the end rather than stretching cells.
- These components draw data structures; they do not process data or implement arbitrary matrices or merged cells.
