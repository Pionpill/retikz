Core keeps only the most common rectangular clip. Standard supplies the other five official clips through the same two-stage extension chain used by third parties:

| Package         | Provided content                                       |
| --------------- | ------------------------------------------------------ |
| `core`          | `rect`                                                 |
| `standard/clip` | `circle`, `ellipse`, `polygon`, `path`, and `compound` |

## Usage

This page supports two import styles:

- Import the operation and shape Definition for one kind, such as `CircleClipDefinition` plus `CircleClipShapeDefinition`
- Use `StandardClipDefinitions` plus `StandardClipShapeDefinitions` for the complete set; use `StandardClipProviders`, which contains both provider levels, when assembling a provider graph

Both styles explicitly assemble capabilities for the current figure. Importing the package does not register clips globally.

### React usage

Import the clip Definitions you need from `@retikz/standard/clip`, pass them to the React `Layout` `clips` prop, and place the clip spec on a `Scope`.

```tsx
import { Layout, Node, Scope } from '@retikz/react';
import {
  CircleClipDefinition,
  CircleClipShapeDefinition,
  CompoundClipDefinition,
  CompoundClipShapeDefinition,
} from '@retikz/standard/clip';

<Layout
  clips={[CompoundClipDefinition, CircleClipDefinition]}
  clipShapes={[CompoundClipShapeDefinition, CircleClipShapeDefinition]}
>
  <Scope
    clip={{
      kind: 'compound',
      fillRule: 'nonzero',
      children: [
        { kind: 'circle', cx: -32, cy: 0, r: 56 },
        { kind: 'circle', cx: 32, cy: 0, r: 56 },
      ],
    }}
  >
    <Node position={[0, 0]} minimumSize={{ width: 180, height: 110 }} />
  </Scope>
</Layout>;
```

### Vanilla usage

With `@retikz/vanilla`, put the Definition in `compile.clips`. `input` can be an existing Core IR or Vanilla plain spec; `mount` accepts the same `compile` configuration.

```ts
import { renderToSvgString } from '@retikz/vanilla';
import {
  CircleClipDefinition,
  CircleClipShapeDefinition,
  CompoundClipDefinition,
  CompoundClipShapeDefinition,
} from '@retikz/standard/clip';

const svg = renderToSvgString(input, {
  compile: {
    clips: [CompoundClipDefinition, CircleClipDefinition],
    clipShapes: [CompoundClipShapeDefinition, CircleClipShapeDefinition],
  },
});
```

Definitions exist only for the current Core registry assembly; they do not enter IR JSON or write global state as an import side effect. A missing operation Definition points to `clips`; a resolved operation with no shape Definition points to `clipShapes`. With both present, Standard validates the spec and shape before Core emits one canonical path.

### Compound clipping

`compound` recursively combines other registered clip specs through `children`. The example above uses two independently selectable child regions and suits cases where basic clips need to form one combined region.

This subpath provides five schemas, `IRXxxClip` and `XxxClipShape` types, both Definition/provider levels, and three complete collections. The `@retikz/standard` root does not forward them.

#### API

`compound` uses `IRCompoundClip`. It and every actual child require both operation and shape Definitions:

| Field       | Type                     | Description                                                                                                                    |
| ----------- | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| `kind`      | `'compound'`             | Discriminator for recursive compound clipping                                                                                  |
| `children`  | `Array<IRClip>`          | At least one child operation; each returns to the active Core Clip registry and may come from Core, Standard, or a third party |
| `fillRule?` | `'nonzero' \| 'evenodd'` | Applies once to all accumulated child commands; defaults to `nonzero` and is not per-child geometric intersection              |

Direct compilation passes the matching `XxxClipDefinition` and `XxxClipShapeDefinition` on demand. A provider graph uses the operation provider as a root and includes its shape dependency in the catalog. `StandardClipProviders` is a catalog, not an auto-install bundle: the resolver materializes only the root-reachable closure.
