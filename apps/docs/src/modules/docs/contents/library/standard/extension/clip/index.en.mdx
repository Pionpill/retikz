Clip extensions build on Core's basic clips and add more optional content:

| Package         | Provided content              |
| --------------- | ----------------------------- |
| `core`          | `rect`, `circle`, `ellipse`   |
| `standard/clip` | `polygon`, `path`, `compound` |

## Usage

This page supports two import styles:

- Import specific Definitions on demand, such as `CompoundClipDefinition`, and pass only the official extensions used by the figure to `Layout` or `compile`
- Use the complete official extension set through `StandardClipDefinitions`, which includes every Standard Definition from this subpath; use `StandardClipProviders` when assembling a provider graph

Both styles explicitly assemble capabilities for the current figure. Importing the package does not register clips globally.

### React usage

Import the clip Definitions you need from `@retikz/standard/clip`, pass them to the React `Layout` `clips` prop, and place the clip spec on a `Scope`.

```tsx
import { Layout, Node, Scope } from '@retikz/react';
import { CompoundClipDefinition, PathClipDefinition, PolygonClipDefinition } from '@retikz/standard/clip';

<Layout clips={[CompoundClipDefinition, PolygonClipDefinition, PathClipDefinition]}>
  <Scope
    clip={{
      kind: 'compound',
      fillRule: 'nonzero',
      children: [
        { kind: 'circle', cx: -32, cy: 0, r: 56 },
        { kind: 'circle', cx: 32, cy: 0, r: 56 },
      ],
    }}
  >
    <Node position={[0, 0]} minimumSize={{ width: 180, height: 110 }} />
  </Scope>
</Layout>;
```

### Vanilla usage

With `@retikz/vanilla`, put the Definition in `compile.clips`. `input` can be an existing Core IR or Vanilla plain spec; `mount` accepts the same `compile` configuration.

```ts
import { renderToSvgString } from '@retikz/vanilla';
import { CompoundClipDefinition, PathClipDefinition, PolygonClipDefinition } from '@retikz/standard/clip';

const svg = renderToSvgString(input, {
  compile: {
    clips: [CompoundClipDefinition, PolygonClipDefinition, PathClipDefinition],
  },
});
```

The Definition exists only for the current Core registry assembly; it does not enter IR JSON or write global state as an import side effect. If IR uses `polygon`, `path`, or `compound` without injecting the corresponding Definition, Core reports an unregistered clip; after injection it validates the data through that Definition's schema.

### Compound clipping

`compound` recursively combines other registered clip specs through `children`. The example above uses two independently selectable child regions and suits cases where basic clips need to form one combined region.

This subpath provides the individual Definitions, `StandardClipDefinitions`, `StandardClipProviders`, and their parameter types; the `@retikz/standard` root does not forward them.

#### API

`compound` uses `CompoundClip` and requires `CompoundClipDefinition` during compilation:

| Field       | Type                                    | Description                                                                                      |
| ----------- | --------------------------------------- | ------------------------------------------------------------------------------------------------ |
| `kind`      | `'compound'`                            | Discriminator for recursive compound clipping                                                    |
| `children`  | `Array<IRClip \| CompoundClip>` | At least one child; each child can nest another `compound` or reference a Core / registered clip |
| `fillRule?` | `'nonzero' \| 'evenodd'`                | Fill rule for the combined path; omitted values follow Core's default handling                   |
