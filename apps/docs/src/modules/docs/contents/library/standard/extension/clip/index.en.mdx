Clip Extensions add optional regions on top of Core's rectangular clip:

| Package         | Provided content                                       |
| --------------- | ------------------------------------------------------ |
| `core`          | `rect`                                                 |
| `standard/clip` | `circle`, `ellipse`, `polygon`, `path`, and `compound` |

## Usage

This page supports two import styles:

- Import an individual Definition such as `CircleClipDefinition` and pass only what the current figure needs to `Layout` or `compile`
- Use `StandardClipDefinitions` to include every Standard Definition from this subpath; use `StandardClipProviders` when assembling a provider graph

Both styles assemble only the current figure. Importing the module never registers clips globally.

### React usage

Import the Definition used by the current figure from `@retikz/standard/clip` and pass it to the React `Layout` through `clips`. A `Scope` clip stores only its `kind` and JSON-safe parameters.

```tsx
import { Layout, Node, Scope } from '@retikz/react';
import { CircleClipDefinition } from '@retikz/standard/clip';

<Layout clips={[CircleClipDefinition]}>
  <Scope clip={{ kind: 'circle', cx: 0, cy: 0, r: 56 }}>
    <Node position={[0, 0]} minimumSize={{ width: 160, height: 120 }} />
  </Scope>
</Layout>;
```

Core's `rect` needs no extra injection. A Standard Definition applies only to the current `Layout`.

### Vanilla usage

With `@retikz/vanilla`, pass the same Definition through `compile.clips`. `input` may be existing Core IR or a Vanilla plain spec; `mount` uses the same `compile` configuration.

```ts
import { renderToSvgString } from '@retikz/vanilla';
import { CircleClipDefinition } from '@retikz/standard/clip';

const svg = renderToSvgString(input, {
  compile: {
    clips: [CircleClipDefinition],
  },
});
```

If a clip `kind` is neither a Core default nor registered through the current `clips`, Core reports the missing entry and points to the injection option. It never substitutes a rectangle or another nearby region.

## Examples

Each example below keeps the current section's clip `kind` fixed. Its controls change only parameters owned by that clip type.

### Circles and ellipses

`circle` uses one radius, while `ellipse` controls the horizontal and vertical radii independently. They work well for avatars, badges, spotlights, and rounded content windows.

<ComponentPreview
  files="circle-ellipse-clip"
  size="sm"
  caption="The dashed rectangles mark the source bounds. The left and right regions stay circle and ellipse while their radii change."
/>

| Type            | Required fields            | Description                                       |
| --------------- | -------------------------- | ------------------------------------------------- |
| `IRCircleClip`  | `cx`, `cy`, and `r`        | Center and a positive radius                      |
| `IREllipseClip` | `cx`, `cy`, `rx`, and `ry` | Center and positive horizontal and vertical radii |

Inject `CircleClipDefinition` or `EllipseClipDefinition`, respectively.

### Polygons

`polygon` joins at least three vertices in authored order and closes the region automatically. It covers regular and irregular straight-edged clips.

<ComponentPreview
  files="polygon-clip"
  size="sm"
  caption="The clip kind stays polygon; the three point controls write directly to points in order."
/>

| Field    | Type                      | Description                                          |
| -------- | ------------------------- | ---------------------------------------------------- |
| `points` | `Array<[number, number]>` | At least three user-space vertices in authored order |

Inject `PolygonClipDefinition` when using it.

### Paths

`path` accepts Core structured path commands directly. It covers curves and compound outlines that circles, ellipses, and polygons cannot express. The commands must form a valid fillable region.

<ComponentPreview
  files="path-clip"
  size="md"
  caption="The command structure stays fixed. Controls change only command coordinates and fillRule."
/>

| Field       | Type                       | Description                          |
| ----------- | -------------------------- | ------------------------------------ |
| `commands`  | `Array<PathCommand>`       | At least one structured path command |
| `fillRule?` | `'nonzero'` \| `'evenodd'` | Fill rule; defaults to `nonzero`     |

Inject `PathClipDefinition`. See [Custom Paths](/kernel/components/draw/custom-path) for structured command authoring.

### Compound clips

`compound` appends child path commands in input order, then applies one `fillRule` to the final region. It combines outlines into one clip path but does not compute a geometric intersection between children.

<ComponentPreview
  files="compound-clip"
  size="sm"
  caption="The children remain two circles. Change their radius, center distance, and fillRule to inspect the combined region."
/>

| Field       | Type                       | Description                                                                       |
| ----------- | -------------------------- | --------------------------------------------------------------------------------- |
| `children`  | `Array<IRClip>`            | At least one child; every child Definition must also be available through `clips` |
| `fillRule?` | `'nonzero'` \| `'evenodd'` | Fill rule for the final combined path; defaults to `nonzero`                      |

Inject `CompoundClipDefinition` together with the Definitions used by its children. Use nested `<Scope clip>` elements when you need geometric intersections.
