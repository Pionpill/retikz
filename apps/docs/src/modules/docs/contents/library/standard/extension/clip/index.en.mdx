Core keeps only the common rectangular clip. Standard supplies the other five official implementations through the same complete `ClipDefinition` contract used by third parties:

| Package         | Provided content                                       |
| --------------- | ------------------------------------------------------ |
| `core`          | `rect`                                                 |
| `standard/clip` | `circle`, `ellipse`, `polygon`, `path`, and `compound` |

The preview lays out two content regions horizontally. Controls switch each region's clip type and position while `compound` carries the selected child.

## Applicability Boundary

- Import an individual `XxxClipDefinition` when a figure uses only selected clips
- Use `StandardClipDefinitions` when the figure can assemble the complete official set
- Use `StandardClipProviders` as a catalog when an adapter or Tier 2 package builds a provider graph

These styles affect only the current compile and never register global capabilities as an import side effect. See [Custom Clips](/kernel/components/layout/custom-clip) to author a new clip kind.

## Define the Capability

Each Standard definition owns its spec schema, JSON-safe shape schema, `resolve`, and `lower`. For example, `CircleClipDefinition` uses `kind: 'circle'` for the authored spec, resolved shape, and registry key.

`@retikz/standard/clip` exports five definitions:

- `CircleClipDefinition`
- `EllipseClipDefinition`
- `PolygonClipDefinition`
- `PathClipDefinition`
- `CompoundClipDefinition`

`StandardClipDefinitions` contains the complete set in that order. The `@retikz/standard` root does not forward these optional capabilities.

## Inject the Host

### React usage

```tsx
import { Layout, Node, Scope } from '@retikz/react';
import { CircleClipDefinition, CompoundClipDefinition } from '@retikz/standard/clip';

<Layout clips={[CompoundClipDefinition, CircleClipDefinition]}>
  <Scope
    clip={{
      kind: 'compound',
      fillRule: 'nonzero',
      children: [
        { kind: 'circle', cx: -32, cy: 0, r: 56 },
        { kind: 'circle', cx: 32, cy: 0, r: 56 },
      ],
    }}
  >
    <Node position={[0, 0]} minimumSize={{ width: 180, height: 110 }} />
  </Scope>
</Layout>;
```

### Vanilla usage

```ts
import { renderToSvgString } from '@retikz/vanilla';
import { CircleClipDefinition, CompoundClipDefinition } from '@retikz/standard/clip';

const svg = renderToSvgString(input, {
  compile: {
    clips: [CompoundClipDefinition, CircleClipDefinition],
  },
});
```

Definitions exist only in the current Core registry assembly. They never enter IR JSON or write global state. A missing kind consistently points to `clips`.

## Execution Path

Standard and custom definitions enter the same Core Clip registry. Core runs the spec schema, `resolve`, shape schema, `lower`, and canonical path validation in order; renderers see only `SceneClipPath`.

Every `XxxClipProvider` is a dependency-free complete clip provider. `StandardClipProviders` remains a catalog, so the resolver materializes only root-reachable definitions and never installs every clip automatically. Callers still contribute the actual child kinds used by `compound` as explicit roots and catalog entries.

## Errors and Limits

| Case                                       | Result                                                      |
| ------------------------------------------ | ----------------------------------------------------------- |
| Current kind is not injected               | Core reports an unknown clip and suggests `options.clips`   |
| Duplicate kind                             | Registry fails loudly and never overwrites a definition     |
| Invalid spec or shape                      | The same definition reports the matching schema stage       |
| `compound` child kind is missing           | The child fails when it returns to the active Clip registry |
| Invalid commands, cycle, or depth overflow | Core canonical path or traversal validation fails loudly    |

`compound` appends child commands in authored order and applies its outer `fillRule` to one combined path. It is not a per-child geometric intersection. Use nested `<Scope clip>` elements for intersections.

## API Reference

### Export Overview

- schemas and IR: five `XxxClipSchema`, `IRXxxClip`, and `XxxClipShape` exports
- definitions: five `XxxClipDefinition` values and `StandardClipDefinitions`
- providers: five `XxxClipProvider` values and `StandardClipProviders`

### IRCompoundClip

| Field       | Type                       | Description                                                                                                          |
| ----------- | -------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `kind`      | `'compound'`               | Discriminator for recursive compound clipping                                                                        |
| `children`  | `Array<IRClip>`            | At least one child; each returns to the active Core Clip registry and may come from Core, Standard, or a third party |
| `fillRule?` | `'nonzero'` \| `'evenodd'` | Applies once to all accumulated child commands; defaults to `nonzero` and is not a per-child geometric intersection  |
