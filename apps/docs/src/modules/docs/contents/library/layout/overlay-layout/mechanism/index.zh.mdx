## 尺寸参与和最终放置是两条规则

所有子项都需要测量，但只有 `include` 子项贡献容器的最小与自然尺寸轮廓。容器尺寸确定后，`exclude` 子项仍获得最终约束、被放置并进入输出。固定尺寸策略则由作者提供分配范围，而不是要求所有图形都改变尺寸。

## 局部目标点如何确定槽位

`at` 从内容区左上角计算；`anchor` 取槽位的归一化位置。图中内容区为 200 × 100，目标点为 `(150,20)`，槽位为 40 × 20，锚点 `(1,0)` 选择右上角。槽位左上角因此为 `(150−40,20)=(110,20)`。

一般关系如下，其中 $\odot$ 表示按 x / y 分量相乘：

$$
\mathbf{o}_{slot} = \mathbf{o}_{content} + \mathbf{at} - \mathbf{anchor} \odot \mathbf{size}_{slot} + \mathbf{offset}
$$

锚点不取自视觉包络；改变描边或标签不会改变这个坐标定义。

## 槽位、真实占用和可见区域如何衔接

`aligned` 以内容区作为对齐参照；`positioned` 先求局部锚定槽位。之后根据对齐策略把子图形真实占用放进去，再叠加 `offset`。固定几何可以拒绝拉伸，因此槽位大小不等于最终图形大小。

回放时才应用容器裁切。基线对齐需要共享纵向参照，所以采用基线的对齐子项不允许非零纵向偏移；定位子项必须选择边缘对齐。输入约束保证两种放置模型不会混用。

## 为什么绘制顺序不改写子项身份

绘制前按 `zIndex` 升序排列，同层级按 `sourceIndex` 保持作者顺序。图中的 First、Second、Third 层级分别为 2、0、2，因此先绘制 Second，再绘制 First，最后绘制 Third。尺寸参与方式不参与排序。

`OverlayLayoutArtifact.items` 仍按作者顺序保存；`paintOrder` 单独给出绘制顺序。两者拥有不同用途：前者用于回查输入身份，后者用于解释重叠结果。
