`FlexLayout` arranges arbitrary graphical children along one main axis. It distributes free space, shrinks or wraps when space is tight, keeps fixed geometry at its real size, and lets text reflow against its allocated width.

## Using this topic

The container's `children` are layout items, each carrying a graphic through `child`. React expresses items with `FlexLayoutItem`; Vanilla and IR use `{ kind: 'flex', child: ... }`. The preview shows space allocation in action; the four integration examples start with two content-sized items to explain the minimal composition.

<DocTab value="react-jsx" label="React + JSX">

In React + JSX, direct children of `FlexLayout` use `FlexLayoutItem`. Each item carries one drawable child:

```text
FlexLayout
└── FlexLayoutItem
    └── Node / FlexLayout
```

```tsx
import { Layout, Node } from '@retikz/react';
import { FlexLayout, FlexLayoutItem } from '@retikz/layout-react';

export const Example = () => (
  <Layout>
    <FlexLayout gap={12}>
      <FlexLayoutItem>
        <Node text="A" />
      </FlexLayoutItem>
      <FlexLayoutItem>
        <Node text="B" />
      </FlexLayoutItem>
    </FlexLayout>
  </Layout>
);
```

`itemKey` may be omitted. Layout creates a container-local effective key internally without writing it back to Source IR. Pass `itemKey` only when identity must remain stable across reordering; it never reads React's reserved `key`. Each `FlexLayoutItem` accepts exactly one drawable child or one explicit `IRChild` through `ir`.

## Setting direction, size, and spacing

Direction chooses a horizontal or vertical arrangement, size determines the available space, and padding and gaps provide spacing. These are container properties.

| Property          | Available values                                                      | Explanation                                                                                          |
| ----------------- | --------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `direction`       | `row`, `row-reverse`, `column`, `column-reverse`                      | Choose a horizontal or vertical main axis; reverse modes change placement, not paint order           |
| `size.x / size.y` | `{ kind: "content" }`, `{ kind: "fixed", value }`, `{ kind: "fill" }` | Physical container width and height: size to content, use a fixed value, or fill finite parent space |
| `padding`         | Non-negative number, or an object with `x` / `y` / per-side values    | Inset the container on each side to form the content box                                             |
| `gap`             | Non-negative number, or `{ column, row }` with non-negative values    | Fixed spacing between adjacent items, deducted before distributing free space                        |

In the demo, switch direction and size policy, then adjust padding and gaps. `size.x` / `size.y` always mean physical width and height, so a vertical arrangement needs space on the y axis. Start with content sizing on both axes, or fix only x for a specific row width. `fill` requires finite parent space.

## Allocating item space

Items start from a base size, then grow or shrink to fit the container. Set these properties on each item.

| Property | Available values                   | Explanation                                                                                            |
| -------- | ---------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `basis`  | `content` or a non-negative number | Item main-axis starting size; `content` uses intrinsic measurement                                     |
| `grow`   | Non-negative number                | Item weight for extra space; `0` disables growth. This is not a final size ratio                       |
| `shrink` | Non-negative number                | Item shrink weight; `0` disables shrinking. Effective weight also includes the unconstrained base size |
| `size.x` | `{ kind: "fixed", value }`         | Fixed container width; `value` is non-negative                                                         |

The demo gives all three items the same base size and a minimum allocation of 32. Reduce the base size and adjust the first item’s `grow` to compare extra space; then increase the base size or narrow the container and adjust the second item’s `shrink`. The third item keeps `grow=1` and `shrink=1` as a reference. Fixed geometry does not automatically scale to its slot.

## Aligning the container and items

Alignment determines where free space goes and where items sit on the other axis. An item can override the container default.

| Property         | Available values                                                                 | Explanation                                                                                     |
| ---------------- | -------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `justifyContent` | `start`, `center`, `end`, `space-between`, `space-around`, `space-evenly`        | Container property: distribute remaining space on each line’s main axis                         |
| `alignItems`     | `start`, `center`, `end`, `stretch`, `first-baseline`, `last-baseline`           | Container property: default cross-axis alignment; baseline modes require a horizontal main axis |
| `alignSelf`      | `start`, `center`, `end`, `stretch`, `first-baseline`, `last-baseline`; optional | Item property: override `alignItems`, or inherit it when omitted                                |

The demo uses a horizontal arrangement with growth disabled. Change main-axis distribution, switch default cross-axis alignment from center to start, then override the second item. `gap` remains fixed; distribution may have no visible effect if growth has consumed all free space. `stretch` supplies a size constraint but does not guarantee that fixed geometry deforms.
