## 先决定占位，再建立轨道

轨道尺寸求解前，先确定每个子项占据哪些格子。完整显式位置先占位；其余子项按作者顺序和 `autoFlow` 搜索可用区域。搜索结果超出显式行列时，再按隐式定义补齐轨道。因此隐式轨道不是视觉补线，而是参与后续测量的真实轨道。

## 为什么列宽先于行高

文字的可用宽度会改变折行高度。GridLayout 固定采用物理 x→y 顺序：先测量横向最小与自然贡献并求列宽，再把列区域作为约束重测子项，最后求行高。`autoFlow` 控制搜索方向，不会反转这个依赖。

内容贡献、轨道份额和上下界共同参与求解。固定列直接给出尺寸；内容列读取子项贡献；份额列在有限空间中分配剩余。最小贡献与边界可能限制份额比例，不能简单按总宽度乘以 `fr` 比例推算所有情况。

## 跨度怎样变成连续槽位

两列分别宽 100 与 140，中间间距 12，跨两列的槽位宽度为 `100 + 12 + 140 = 252`。子项跨过的是已有轨道组成的连续区域；下一行仍保留原来的两条列边界。求内容贡献时会扣除内部间距，避免把间距再作为轨道需求重复计入。

外边距随后缩小可用区域，对齐再把实际占用放入其中。槽位、真实占用和视觉边界必须分别记录：Node 的描边范围不能替代列区域。

## 最终候选如何成为输出

轨道确定后，布局依据子项对齐策略发送精确或有界尺寸约束。测量返回的候选携带自己的结果，最终只回放选中的候选，再应用平移与裁切。试测不会把未选中的图元混入 Scene。

`GridLayoutArtifact` 保存容器、物理行列、隐式标记和子项最终跨度。嵌套布局的局部 key 由 occurrence 区分，不能只凭相同 key 合并结果。
