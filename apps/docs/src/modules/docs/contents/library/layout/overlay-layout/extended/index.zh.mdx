本页在[基础用法](/library/layout/overlay-layout/usage)之上组合约束、观察边界并检查布局结果。先调整一个变量，再对照分配区域和真实占用。

## 把徽标贴到局部目标点

positioned 的 at 相对内容区域左上角，anchor 取子项 slot 的归一化位置。例如 slot 为 40×20，at=(150,20)、anchor=(1,0)，slot 左上角就是 (110,20)。offset 在放置完成后再平移，不改变 at 的坐标原点。

width / height 可显式提出精确分配尺寸；固定几何仍可能超出分配区域。若需要让徽标不撑大内容自适应容器，设置 sizeParticipation="exclude"，而不是给它负尺寸或隐藏它。

## 尺寸参与与叠放互相独立

include / exclude 只控制最小和自然尺寸贡献。exclude 的子项依然测量、放置、回放并出现在产物中。zIndex 只决定绘制顺序；同一 zIndex 按 sourceIndex 保持稳定。无法用层级修复错误的尺寸参与策略。

## 交互比较

切换共享对齐，并移动定位徽标的目标点、锚点和 `zIndex`。预览中的三个子项发生重叠，因而层级变化会直接反映到绘制结果。

基础 `OverlayLayout` 没有 `inspect` 属性。可选的 `InspectOverlayLayout` 对象形式可分别控制 `placements`、`anchors` 与 `stacking`，并复用通用边界与盒模型间距开关。完整字段和宿主 / Scope 规则见[检查器说明](/library/layout/flex-layout/extended#检查器的宿主与范围)。

```tsx
import { Layout, Node } from '@retikz/react';
import { LayoutItem } from '@retikz/layout-react';
import { LayoutInspectLayout, InspectOverlayLayout } from '@retikz/layout-react/inspect';
export const Inspected = () => (
  <Layout>
    <LayoutInspectLayout>
      <InspectOverlayLayout
        size={{ x: { kind: 'fixed', value: 100 }, y: { kind: 'fixed', value: 60 } }}
        inspect={{ bounds: { content: true, slot: true } }}
      >
        <LayoutItem kind="overlay">
          <Node position={[0, 0]} text="A" />
        </LayoutItem>
      </InspectOverlayLayout>
    </LayoutInspectLayout>
  </Layout>
);
```

## 读取布局结果

编译结果通过 occurrence 标识具体容器实例；不要只用公开 id 区分嵌套实例。先定位产物信封，再用对应 Schema 校验 value。下面只检查同次编译的结果，不重新求解。

```ts
import { compileToScene } from '@retikz/core';
import { OverlayLayoutDefinition, OverlayLayoutArtifactSchema, createOverlayLayout } from '@retikz/layout';
const output = compileToScene(
  { type: 'scene', version: 1, children: [createOverlayLayout({ children: [] })] },
  { composites: [OverlayLayoutDefinition] },
);
const envelope = output.artifacts.find(
  item => item.kind === 'composite' && item.namespace === 'layout' && item.type === 'overlayLayout',
);
if (envelope) {
  const result = OverlayLayoutArtifactSchema.parse(envelope.value);
  console.log(result.container, result.items);
}
```

`items[]` 增加 `placement`、`sizeParticipation`、`zIndex` 与可选 `position`。只有 `positioned` 子项必须提供 `position.target` 和 `position.slotAnchor`；两点都使用容器分配坐标，并在数值容差内重合。`aligned` 子项不得携带该字段。`paintOrder` 必须是所有子项 key 的完整排列：先按 `zIndex` 升序，再按 `sourceIndex` 保持稳定顺序。

## 共同边界与检查规则

三种布局使用相同的 slot、真实占用与视觉包络语义。读取结果前参阅[产物边界](/library/layout/flex-layout/extended#理解产物边界)；检查宿主、子树范围和屏障见[检查器的宿主与范围](/library/layout/flex-layout/extended#检查器的宿主与范围)。
