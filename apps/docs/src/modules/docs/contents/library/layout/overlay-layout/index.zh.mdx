---
title: overlay · 叠加布局
description: 在共享区域内对齐或定位图形，并独立控制尺寸参与与绘制层级
---

`OverlayLayout` 让多个子图形共享同一个内容区域，适合卡片与角标、主体与浮层说明等叠加场景。子项可以跟随容器对齐，也可以把自身锚点放到容器内的指定位置。

你分别声明放在哪里、是否影响容器尺寸、先画还是后画。叠加不需要为每个子项预留独占的行列空间，也不会自动把相互覆盖的图形推开。

## 职责一览

布局以可序列化的 IR 描述容器、子项规则和图形内容。三者分别保存不同的事实：

| IR 层次                         | 描述内容                             | 作用范围                       |
| ------------------------------- | ------------------------------------ | ------------------------------ |
| 布局容器                        | 共享区域、内边距与默认对齐           | 决定整组内容的空间组织         |
| 子项配置（`children` 中的条目） | 对齐或定位、偏移、尺寸参与与绘制层级 | 决定单个子图形如何参与布局     |
| 子图形（条目的 `child`）        | 节点、路径或嵌套图形的内容与几何声明 | 决定实际绘制的内容及其测量依据 |

容器的 `children` 保存子项配置，每个条目的 `child` 保存子图形 IR。布局规则与图形内容因此可以分别调整：修改子项的分配或放置规则，不必重写图形本身。

React 通过 JSX 组合、Vanilla 通过函数与对象编写这些声明，也可以直接提供 IR。各入口最终表达同一份布局契约；具体写法在基础用法中对照，总览按这份共同契约解释行为。

## 将徽标叠加到内容卡片

下面的卡片跟随容器居中对齐，徽标则独立定位在卡片右上方。二者共享同一内容区域；徽标的 `zIndex` 更高，因此在卡片之后绘制。

<ComponentPreview files="entry" hideCode size="sm" />

徽标用 `at` 指定相对内容区域起点的位置，再用 `anchor` 选择自身槽位的对齐点。这里 `anchor` 为 `{ x: 0.5, y: 0.5 }`，表示把徽标槽位的中心放到指定位置。

这个示例中的徽标位置是显式坐标，并不是自动绑定到卡片角点。卡片尺寸或容器尺寸变化后，需要重新选择定位规则；容器对齐和局部定位承担不同任务。

徽标设置 `sizeParticipation="exclude"`，表示它不参与容器的固有尺寸计算；它仍然会被放置和绘制。示例采用固定容器尺寸，因此这个选项不会改变当前容器的宽高。`zIndex` 只控制绘制顺序，不改变位置，也不替代尺寸参与规则。

<Comparison target="css" title="与 CSS 定位和层叠的对应关系">

CSS 没有名为 Overlay 的独立布局模式。理解 OverlayLayout 时，可以分别类比同一网格区域内的对齐、绝对定位和 `z-index`，而不是把整个布局等同于 `position: absolute`。

| CSS 中的做法                         | OverlayLayout IR                                | 对应语义                                               |
| ------------------------------------ | ----------------------------------------------- | ------------------------------------------------------ |
| 多个 Grid 项目放入同一网格区域并对齐 | `placement: { kind: 'aligned' }` 与容器对齐规则 | 子项共享内容区域，默认居中                             |
| `left` / `top` 配合定位参照          | `placement: { kind: 'positioned', at, anchor }` | 将子项槽位的指定锚点放到内容区域内的局部坐标           |
| 定位后再作平移                       | `offset`                                        | 在放置结果上增加物理横纵偏移                           |
| `z-index`                            | `zIndex`                                        | 控制兄弟子项的绘制先后                                 |
| 绝对定位元素不参与常规流尺寸         | `sizeParticipation: 'exclude'`                  | 不贡献容器固有尺寸；这是独立选项，不由定位方式自动决定 |

本页卡片使用默认对齐，徽标使用局部定位。徽标的中心锚点可类比 CSS 中用 `left` / `top` 定位后再作 `translate(-50%, -50%)`，但参照区域不同：这里的 `at` 明确从容器内容区域起点计算，`anchor` 的 0 到 1 表示子项槽位上的相对位置，不是容器百分比坐标。

OverlayLayout 的定位子项默认仍参与尺寸计算，只有显式设置 `sizeParticipation: 'exclude'` 才排除；它不是 CSS 脱离文档流规则的自动复刻。被排除的子项仍然绘制，也不因此被裁剪。

`zIndex` 越大越晚绘制，同值保留声明顺序。这里说明的是当前布局内的顺序，不是浏览器由定位、透明度和 transform 等共同建立的 stacking context。数值使用绘图坐标单位，不接受 CSS 长度字符串；布局也不会自动避让重叠内容。

## 选择与边界

| 排列目标                               | 选择                                      |
| -------------------------------------- | ----------------------------------------- |
| 主体与角标、浮层共享区域，需要覆盖关系 | `OverlayLayout`                           |
| 子项依次排列，需要伸缩或换行           | [FlexLayout](/library/layout/flex-layout) |
| 子项占据不同的行列区域，需要跨行或跨列 | [GridLayout](/library/layout/grid-layout) |

OverlayLayout 允许重叠，不提供自动避让。它负责放置，不会自动为主体生成背景或边框；只需按内容范围添加装饰外观时，可选择标准包的 [Surface](/library/standard/presentation/surface)。

从基础用法学习对齐和定位；需要组合偏移、尺寸参与与层级规则时阅读扩展用法。API、Schema 参考用于查询字段，实现原理解释尺寸计算、定位与绘制顺序之间的关系。
