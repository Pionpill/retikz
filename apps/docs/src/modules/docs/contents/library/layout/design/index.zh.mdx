---
title: 设计理念
description: 理解 Layout 如何根据内容占用的空间排列图形，减少手动维护位置。
---

直接排列多个 Kernel Node 时，作者通常用 `position` 指定各自位置。画一两个独立对象很直观；但若标签变长、条目增多或容器变窄，后续对象的坐标也要跟着修改。Layout 用容器描述排列关系，让位置随内容重新计算。

## 从逐个定位到声明排列

在 Layout 中，作者把图元或嵌套布局放进布局子项，再声明间距、对齐或尺寸约束。每个子项是一块待排列的内容，内部仍使用自己的局部坐标；容器负责决定整个子项在图中的最终位置。布局内的 Node 可以省略 `position`，默认从局部 `[0, 0]` 开始。

| 直接放置图元                | 使用 Layout 容器                 |
| --------------------------- | -------------------------------- |
| 为每个 Node 维护 `position` | 声明子项顺序、间距与排列约束     |
| 内容尺寸变化后调整后续坐标  | 根据测量尺寸重新分配空间与位置   |
| 适合已知的独立位置          | 适合多个内容之间有排列关系的图形 |

Layout 解决的是“这些内容怎样排在一起”，而不是改变 Node、Path 本身的绘图含义。

## 让内容尺寸参与排版

Layout 复用 Kernel 的测量能力，取得每块内容占用的宽、高，再根据可用空间和子项约束安排它们。例如一个标签文字变长时，后面的条目可以随之移动；作者只需维护标签内容和容器间距，不必重新计算每个 `position`。

| 容器          | 排列关系                 | 常见用途             |
| ------------- | ------------------------ | -------------------- |
| FlexLayout    | 沿一个方向排列、分配空间 | 标签带、图例条目     |
| GridLayout    | 按行列轨道安排内容       | 面板、矩阵           |
| OverlayLayout | 在同一区域内对齐和叠放   | 徽标、局部注释、浮层 |

三种容器都可以包含普通图元或其它布局容器，因此可以先安排整体区域，再排布区域内的内容。

## 布局的职责边界

Layout 依据内容尺寸和作者给出的排列约束求位置，不判断图元代表什么，也不从节点关系自动生成整张流程图。需要固定位置时仍可直接使用 Node 的 `position`；需要关系驱动的自动布局时，选择相应的结构图能力。
