Building on [Basic usage](/library/layout/flex-layout/usage), this page covers insufficient space, multiple lines, and result inspection. Each section follows a cooperating API group: establish size constraints, choose wrapping and alignment, then inspect the actual allocation.

## Combining flex allocation with size limits

Flex weights determine how space is shared, while size limits bound each item’s allocation. Once an item reaches a limit, other flexible items absorb the remaining adjustment.

| Property          | Available values                                                      | Explanation                                                                                            |
| ----------------- | --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `size.x / size.y` | `{ kind: "content" }`, `{ kind: "fixed", value }`, `{ kind: "fill" }` | Physical container width and height: size to content, use a fixed value, or fill finite parent space   |
| `basis`           | `content` or a non-negative number                                    | Item main-axis starting size; `content` uses intrinsic measurement                                     |
| `grow`            | Non-negative number                                                   | Item weight for extra space; `0` disables growth. This is not a final size ratio                       |
| `shrink`          | Non-negative number                                                   | Item shrink weight; `0` disables shrinking. Effective weight also includes the unconstrained base size |
| `min / max`       | Optional non-negative numbers, `min ≤ max`                            | Hard lower and upper limits for the item’s main-axis slot; they do not force fixed geometry to shrink  |

The demo changes only the first item’s flex settings and limits; the second stays flexible. Increase `grow`, then lower `max` to see where growth stops. Narrow the container and adjust `min` to see where shrinking stops. Content can still overflow after a minimum is reached.

## Wrapping and aligning multiple lines

Wrapping moves items that do not fit onto additional layout lines. Alignment within each line and distribution of the lines are separate controls.

| Property         | Available values                                                                     | Explanation                                                                                    |
| ---------------- | ------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------- |
| `wrap`           | `nowrap`, `wrap`, `wrap-reverse`                                                     | Keep one line, wrap, or reverse line placement without changing authored item order            |
| `basis`          | `content` or a non-negative number                                                   | Item main-axis starting size; `content` uses intrinsic measurement                             |
| `justifyContent` | `start`, `center`, `end`, `space-between`, `space-around`, `space-evenly`            | Distribute remaining main-axis space within each line                                          |
| `alignContent`   | `start`, `center`, `end`, `stretch`, `space-between`, `space-around`, `space-evenly` | Distribute lines across the cross axis; requires multiple lines and available cross-axis space |
| `size.x`         | `{ kind: "fixed", value }`                                                           | Set horizontal space, affecting how many items fit on a line                                   |

The demo keeps a horizontal main axis. Switch wrapping and adjust the base size or container width until at least two lines appear. Change `alignContent` and `justifyContent` separately to compare spacing between lines and between items. `wrap-reverse` reverses line placement on the cross axis; `direction` controls main-axis reversal.

## Aligning baselines

Centering borders does not necessarily align text with different font sizes or line counts. Baseline alignment lines up the first or last text baseline instead.

| Property               | Available values                                                  | Explanation                                                                                        |
| ---------------------- | ----------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `alignItems`           | This section compares `center`, `first-baseline`, `last-baseline` | Default container alignment; first and last baseline modes require a horizontal main axis          |
| `alignSelf`            | Omit, or use an alignment value                                   | Override one item, or inherit the container when omitted                                           |
| `alignmentGuides`      | `true`, `false`                                                   | Inspection option: show the alignment guides actually used                                         |
| `Node.style.font.size` | `number`                                                          | Node font size, controlled separately for each item to compare baselines at different text heights |

The first item has two explicit lines; the second wraps to its available width. Change both font sizes and compare center, first-baseline, and last-baseline alignment. The second item inherits the default only when its override is unset. A child without the requested guide falls back to edge alignment. Use ordinary edge alignment for a vertical main axis.

## Handling overflow and clipping

When content does not fit, it can remain visible or be clipped. Clipping affects visibility without changing space allocation.

| Property                        | Available values           | Explanation                                                                                             |
| ------------------------------- | -------------------------- | ------------------------------------------------------------------------------------------------------- |
| `overflow`                      | `visible`, `clip`          | Keep overflow visible or clip to the container allocation; neither option reruns layout                 |
| `size.x`                        | `{ kind: "fixed", value }` | Fixed container width, which determines the clipping region width                                       |
| `basis / min / max`             | `number`                   | Item base size and limits; one control sets all three to the same non-negative value, fixing slot width |
| `Node.layout.minimumSize.width` | `number`                   | The node’s own non-negative minimum width, which can exceed its slot                                    |

Narrow the container or increase the node minimum width until it extends beyond the boundary, then switch between `visible` and `clip`. Changing the base size changes slot width without forcing the node to shrink. To make content fit, adjust sizing, wrapping, or item constraints; choose clipping when the external portion should be hidden.

## Inspecting and reading layout results

Inspection layers distinguish assigned space from actual allocation, while the result table reads data from the same compilation. Inspection options only affect overlays and are not stored in layout IR.

| Property            | Available values                                                      | Explanation                                                                                          |
| ------------------- | --------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `size.x / size.y`   | `{ kind: "content" }`, `{ kind: "fixed", value }`, `{ kind: "fill" }` | Physical container width and height: size to content, use a fixed value, or fill finite parent space |
| `basis`             | `content` or a non-negative number                                    | Item main-axis starting size; `content` uses intrinsic measurement                                   |
| `wrap`              | `nowrap`, `wrap`, `wrap-reverse`                                      | Keep one line, wrap, or reverse line placement without changing authored item order                  |
| `bounds.slot`       | `true`, `false`                                                       | Inspection option: show or hide the slot assigned by the parent                                      |
| `bounds.allocation` | `true`, `false`                                                       | Inspection option: show or hide the allocation actually accepted by the child                        |
| `gaps`              | `true`, `false`                                                       | Inspection option: show fixed gaps                                                                   |

Change container width, base size, and wrapping, then compare the line, slot width, and actual width in the result table. Toggle slots, allocations, and gaps separately to identify each overlay. Inspection toggles do not change the table values.

### Inspector hosts and scopes

- React: use `LayoutInspectLayout` + `InspectFlexLayout`, with `inspect` configuring the current container.
- Vanilla: declare requests with `inspectFlexLayout` and pass the driver created by `createLayoutInspectionVanillaDriver` as the render / mount `compileDriver`.
- IR: keep the original layout input and select targets through the inspection driver’s runtime `selection`; do not add inspection fields to IR.

Start with `bounds.slot` and `bounds.allocation` to compare assigned slots with actual occupancy. Add `gaps` and `distributedSpace` to distinguish fixed gaps from distributed free space. The panel's recommended preset selects details useful for this explanation; it is not the complete default inspect configuration.

A container request does not automatically propagate to nested layouts. React can select the scene through the host's `request` or a subtree through `LayoutInspectScope`; Vanilla can use `createInspectionVanillaAuthoring` on the scene or a Scope. To block an entire subtree, use `LayoutInspectScope request={false}` or `createLayoutInspectionBarrier()`. Setting one request to `false` disables selection at that level but allows deeper requests to enable it again.

See [API reference](/library/layout/flex-layout/api-reference) for full entry points and option types, and [Schema reference](/library/layout/flex-layout/schema-reference) for layout input fields.

### Reading results from the same compilation

A compilation can contain multiple layout instances; a public id alone is insufficient to identify nested instances. This example takes the first Flex artifact to demonstrate reading it. For multiple instances, also use the artifact's occurrence to locate the intended target.

```ts
import { compileToScene } from '@retikz/core';
import { FlexLayoutDefinition, FlexLayoutArtifactSchema, createFlexLayout } from '@retikz/layout';

const output = compileToScene(
  { type: 'scene', version: 1, children: [createFlexLayout({ children: [] })] },
  { composites: [FlexLayoutDefinition] },
);

const envelope = output.artifacts.find(
  item => item.kind === 'composite' && item.namespace === 'layout' && item.type === 'flexLayout',
);

if (envelope) {
  const result = FlexLayoutArtifactSchema.parse(envelope.value);
  console.log(result.container, result.items);
}
```

### Understanding artifact bounds

Distinguish three quantities: `slotBounds` is the parent-assigned slot, `allocationBounds` is the layout space actually accepted by the child, and `visualBounds` includes visual effects such as strokes and labels. Fixed geometry may exceed its slot; `visibleBounds` separately describes visibility after clipping.

Flex artifact `items` retain declaration order, `lines` describe the final grouping, and `spacing` distinguishes fixed gaps from distributed free space. Use them to answer questions such as which line an item belongs to or where overflow occurs, without rerunning allocation. See [API reference](/library/layout/flex-layout/api-reference) for all artifact members and [Implementation](/library/layout/flex-layout/mechanism) for the solving process.
