本页承接[基础用法](/library/layout/flex-layout/usage)，处理空间不足、多行排列和结果检查。每节围绕一组配合使用的 API：先确定尺寸约束，再选择换行与对齐，最后用 inspect 验证实际分配。

## 组合伸缩与尺寸边界

伸缩决定空间如何分配，尺寸边界决定每个子项最多和最少拿到多少空间。达到边界后，剩余调整由其他可伸缩子项承担。

| 属性              | 可用值                                                                | 解释                                                       |
| ----------------- | --------------------------------------------------------------------- | ---------------------------------------------------------- |
| `size.x / size.y` | `{ kind: "content" }`, `{ kind: "fixed", value }`, `{ kind: "fill" }` | 容器的物理宽、高：按内容求尺寸、固定尺寸或接收父级有限空间 |
| `basis`           | `content` 或非负数                                                    | 子项的主轴基础尺寸；`content` 从内容测量取得               |
| `grow`            | 非负数                                                                | 子项分配剩余空间的权重；`0` 不参与伸展，不表示最终尺寸比例 |
| `shrink`          | 非负数                                                                | 子项收缩权重；`0` 不收缩，实际权重还要乘以未约束基础尺寸   |
| `min / max`       | 可省略的非负数，`min ≤ max`                                           | 子项主轴槽位的硬下限与上限；不强迫固定图形缩小             |

demo 只调整第一项的伸缩和边界，第二项保持可伸缩。增大第一项的 `grow` 后降低 `max`，观察它何时停止增长；再缩小容器并调整 `min`，观察下限如何限制收缩。达到下限后，内容仍可能溢出。

## 换行与多行对齐

换行把放不下的子项分到多条布局行。每行内部的排列与多行整体的排列分别控制。

| 属性             | 可用值                                                                               | 解释                                             |
| ---------------- | ------------------------------------------------------------------------------------ | ------------------------------------------------ |
| `wrap`           | `nowrap`, `wrap`, `wrap-reverse`                                                     | 不换行、换行或反向排列布局行；不改写子项声明顺序 |
| `basis`          | `content` 或非负数                                                                   | 子项的主轴基础尺寸；`content` 从内容测量取得     |
| `justifyContent` | `start`, `center`, `end`, `space-between`, `space-around`, `space-evenly`            | 分配每一行主轴上的剩余空间                       |
| `alignContent`   | `start`, `center`, `end`, `stretch`, `space-between`, `space-around`, `space-evenly` | 分布多行整体的交叉轴空间；需要多行且交叉轴有余量 |
| `size.x`         | `{ kind: "fixed", value }`                                                           | 控制横向可用空间，影响一行能容纳多少子项         |

demo 固定横向主轴。切换换行方式并调整基础尺寸或容器宽度，先形成至少两行；再分别改变 `alignContent` 和 `justifyContent`，比较行与行之间、每行子项之间的变化。`wrap-reverse` 反转行的交叉轴放置方向，主轴反向则由 `direction` 决定。

## 基线对齐

字号或行数不同时，边框居中不一定能让文字排齐。基线对齐让子项按首行或末行文字的参考线对齐。

| 属性                   | 可用值                                               | 解释                                                     |
| ---------------------- | ---------------------------------------------------- | -------------------------------------------------------- |
| `alignItems`           | 本节比较 `center`, `first-baseline`, `last-baseline` | 容器的默认对齐；首基线或末基线模式仅用于横向主轴         |
| `alignSelf`            | 省略，或同类对齐值                                   | 覆盖单个子项的对齐；省略时跟随容器                       |
| `alignmentGuides`      | `true`, `false`                                      | 检查选项：显示实际采用的对齐参考线                       |
| `Node.style.font.size` | `number`                                             | 节点字号，本例分别控制两项，用于比较不同文字高度下的基线 |

demo 的第一项显式分成两行，第二项随宽度排版。调整两项字号，比较居中、首基线与末基线；第二项选择跟随容器时才继承默认对齐。没有提供对应参考线的子图形会回退到边缘对齐。纵向主轴应使用普通边缘对齐。

## 处理溢出与裁切

内容放不下时，可以保留超出的部分，也可以将它隐藏。裁切只影响可见内容，不改变空间分配。

| 属性                            | 可用值                     | 解释                                                             |
| ------------------------------- | -------------------------- | ---------------------------------------------------------------- |
| `overflow`                      | `visible`, `clip`          | 保留超出容器的内容，或在容器分配区域裁切；不重新求解布局         |
| `size.x`                        | `{ kind: "fixed", value }` | 容器固定宽度，决定裁切区域的宽度                                 |
| `basis / min / max`             | `number`                   | 子项基础尺寸和边界；本例由同一控件设置为相同非负值，固定槽位宽度 |
| `Node.layout.minimumSize.width` | `number`                   | 节点自身的最小宽度，可大于槽位；非负数                           |

在 demo 中缩小容器或增大节点最小宽度，让节点超出边界；再切换 `visible` 与 `clip`，比较可见部分。调整基础尺寸时，槽位宽度会变化，但不强迫节点缩小。若希望内容真正放得下，应调整尺寸、换行或子项约束；只在需要隐藏外部内容时使用裁切。

## 检查与读取布局结果

检查图层用来区分分配空间与实际占用，结果表用来读取同一次编译的数据。检查选项只改变辅助显示，不写入布局 IR。

| 属性                | 可用值                                                                | 解释                                                       |
| ------------------- | --------------------------------------------------------------------- | ---------------------------------------------------------- |
| `size.x / size.y`   | `{ kind: "content" }`, `{ kind: "fixed", value }`, `{ kind: "fill" }` | 容器的物理宽、高：按内容求尺寸、固定尺寸或接收父级有限空间 |
| `basis`             | `content` 或非负数                                                    | 子项的主轴基础尺寸；`content` 从内容测量取得               |
| `wrap`              | `nowrap`, `wrap`, `wrap-reverse`                                      | 不换行、换行或反向排列布局行；不改写子项声明顺序           |
| `bounds.slot`       | `true`, `false`                                                       | 检查选项：显示或隐藏父级分给子项的槽位                     |
| `bounds.allocation` | `true`, `false`                                                       | 检查选项：显示或隐藏子图形实际接受的布局占用               |
| `gaps`              | `true`, `false`                                                       | 检查选项：显示固定间距                                     |

调整容器宽度、基础尺寸和换行方式，观察结果表中的所属行、槽位宽度与实际宽度。分别关闭槽位、占用和间距辅助层，核对图中各区域；开关检查层不会改变结果表数值。

### 检查器的宿主与范围

- React：通过 `LayoutInspectLayout` + `InspectFlexLayout` 接入，用 `inspect` 配置当前容器。
- Vanilla：用 `inspectFlexLayout` 声明请求，将 `createLayoutInspectionVanillaDriver` 创建的驱动传给 render / mount 的 `compileDriver`。
- IR：保留原始布局输入，通过检查驱动的运行时 `selection` 选择目标，不向 IR 添加检查字段。

查看布局分配时，优先打开 `bounds.slot` 与 `bounds.allocation` 比较槽位和真实占用；需要分辨固定间隔与分布自由空间时，再打开 `gaps` 与 `distributedSpace`。面板的“推荐”仅选择当前讲解需要的辅助层，不等于 inspect 的完整默认配置。

单个容器的请求不自动传播到嵌套布局。React 可通过宿主的 `request` 选择整图，通过 `LayoutInspectScope` 选择子树；Vanilla 可在 scene / Scope 上使用 `createInspectionVanillaAuthoring`。需要屏蔽整个子树时，使用 `LayoutInspectScope request={false}` 或 `createLayoutInspectionBarrier()`；单个请求的 `false` 只关闭当前层选择，更深的请求仍可开启。

完整入口与选项类型见 [API 参考](/library/layout/flex-layout/api-reference)。布局输入字段见 [Schema 参考](/library/layout/flex-layout/schema-reference)。

### 读取同次编译的结果

编译结果可能包含多个布局实例，不能仅用一个公开 id 判断嵌套实例。下面只取第一个 Flex 产物演示读取流程；处理多个实例时，应进一步结合产物的 occurrence 定位目标。

```ts
import { compileToScene } from '@retikz/core';
import { FlexLayoutDefinition, FlexLayoutArtifactSchema, createFlexLayout } from '@retikz/layout';

const output = compileToScene(
  { type: 'scene', version: 1, children: [createFlexLayout({ children: [] })] },
  { composites: [FlexLayoutDefinition] },
);

const envelope = output.artifacts.find(
  item => item.kind === 'composite' && item.namespace === 'layout' && item.type === 'flexLayout',
);

if (envelope) {
  const result = FlexLayoutArtifactSchema.parse(envelope.value);
  console.log(result.container, result.items);
}
```

### 理解产物边界

读取结果时，先区分三个量：`slotBounds` 是父级分配的槽位，`allocationBounds` 是子图形实际接受的布局占用，`visualBounds` 还包含描边、标签等视觉范围。固定几何可能超出槽位；裁切后的可见范围另由 `visibleBounds` 表达。

Flex 产物的 `items` 保持声明顺序，`lines` 表达最终分行，`spacing` 区分固定间距与分布自由空间。用它们回答“属于哪一行”“哪里发生溢出”等问题即可，不需要在读取时重新执行分配算法。完整产物成员查询 [API 参考](/library/layout/flex-layout/api-reference)，求解过程见[实现原理](/library/layout/flex-layout/mechanism)。
