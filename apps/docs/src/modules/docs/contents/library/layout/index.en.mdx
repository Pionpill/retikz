title: Layout

Layout extracts child arrangement from hand-authored coordinates. Flex, Grid, and Overlay cover linear distribution, two-dimensional tracks, and stacking within one region, and they compose recursively. Higher-level packages such as Standard, Graph, and Plot can reuse them while retaining ownership of their domain semantics.

Start with the [introduction](/library/layout/introduction) and [quick start](/library/layout/get-start); see the [changelog](/library/layout/changelog) for version changes.

Given the same available space and child measurement, layout solving is deterministic and independent of a specific renderer. Text dimensions still depend on the host measurer, fonts, and font-loading state.

This example uses `LayoutInspectLayout` from `@retikz/layout-react/inspect` to install the layout Inspectors, then selects individual occurrences with `InspectFlexLayout`, `InspectGridLayout`, and `InspectOverlayLayout`. Use `LayoutInspectScope request={false}` as a hard barrier when one authored subtree must not inherit inspection requests. The Layout root does not statically load the optional inspection capability.

## Responsibilities

| Component       | Core model                     | Best suited for                                |
| --------------- | ------------------------------ | ---------------------------------------------- |
| `FlexLayout`    | One axis, grow/shrink, wrap    | Legend entries, label strips, toolbars         |
| `GridLayout`    | 2D tracks, spans, auto placing | Panels, matrices, guide regions, structured UI |
| `OverlayLayout` | Alignment or local positioning | Badges, overlays, annotations, stacked marks   |

Containers own generic size distribution, spacing, alignment, overflow, and observable results. Data channels, chart semantics, table rules, and algorithmic layout remain with their domain packages.

## Three packages

| Package                  | Responsibility                             | Use it when                                        |
| ------------------------ | ------------------------------------------ | -------------------------------------------------- |
| `@retikz/layout`         | Schemas, factories, Definitions, and solve | Validating or persisting IR and compiling directly |
| `@retikz/layout-react`   | React DSL for layout containers            | Authoring inside a React `Layout`                  |
| `@retikz/layout-vanilla` | Plain-spec helpers and adapters            | Authoring in browsers or scripts without React     |

For React authoring, compose `FlexLayout`, `GridLayout`, or `OverlayLayout` inside the `Layout` from `@retikz/react`. For Vanilla, combine the helpers and adapters from `@retikz/layout-vanilla`. When loading persisted JSON, validate complete layout IR with `@retikz/layout` and pass the required Definitions to the Core compiler.
