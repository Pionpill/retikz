Choose the host used by your project and run its example below. Packages use ES modules and require Node.js 24 or later in Node environments.

## Three packages

| Package                  | Responsibility                             | Use it when                                        |
| ------------------------ | ------------------------------------------ | -------------------------------------------------- |
| `@retikz/layout`         | Schemas, factories, Definitions, and solve | Validating or persisting IR and compiling directly |
| `@retikz/layout-react`   | React DSL for layout containers            | Authoring inside a React `Layout`                  |
| `@retikz/layout-vanilla` | Plain-spec helpers and adapters            | Authoring in browsers or scripts without React     |

For React authoring, compose `FlexLayout`, `GridLayout`, or `OverlayLayout` inside the `Layout` from `@retikz/react`. For Vanilla, combine the helpers and adapters from `@retikz/layout-vanilla`. When loading persisted JSON, validate complete layout IR with `@retikz/layout` and pass the required Definitions to the Core compiler.

## React

<PackageManagerInstall packages="@retikz/layout-react @retikz/react react react-dom" />

Render the following `Example` component in an existing React app. The host peers `react` and `react-dom` require version 18 or later.

```tsx
import type { FC } from 'react';
import { Layout, Node } from '@retikz/react';
import { FlexLayout, LayoutItem } from '@retikz/layout-react';

export const Example: FC = () => (
  <Layout>
    <FlexLayout gap={{ column: 12, row: 0 }}>
      <LayoutItem kind="flex">
        <Node shape="circle" position={[0, 0]} layout={{ minimumSize: 32 }} />
      </LayoutItem>
      <LayoutItem kind="flex">
        <Node position={[0, 0]} layout={{ minimumSize: 32 }} />
      </LayoutItem>
    </FlexLayout>
  </Layout>
);
```

The result is a circle and a rectangle arranged horizontally with a 12-unit gap. Each `LayoutItem` contains one graphic. Both start at local `[0, 0]`; the Flex container assigns their final positions.

Save the component above as `Example.tsx` and mount it from an existing React app entry (provide `<div id="root"></div>` in HTML):

```tsx
import { createRoot } from 'react-dom/client';
import { Example } from './Example';

const root = document.getElementById('root');
if (root) createRoot(root).render(<Example />);
```

The root `Layout` outputs SVG by default; this example needs no renderer configuration. Sizes and gaps use the same graphic units. At the default natural display size, one unit equals one CSS pixel.

## Vanilla

<PackageManagerInstall packages="@retikz/layout-vanilla @retikz/vanilla" />

```ts
import { flexLayout, FlexLayoutInputEmbedAdapter } from '@retikz/layout-vanilla';
import { node, renderToSvgString, scene } from '@retikz/vanilla';

const input = scene({
  children: [
    flexLayout({
      gap: { column: 12, row: 0 },
      children: [
        {
          kind: 'flex',
          child: node({ id: 'circle', shape: 'circle', position: [0, 0], layout: { minimumSize: 32 } }),
        },
        {
          kind: 'flex',
          child: node({ id: 'box', position: [0, 0], layout: { minimumSize: 32 } }),
        },
      ],
    }),
  ],
});
const svg = renderToSvgString(input, { adapters: [FlexLayoutInputEmbedAdapter] });
console.log(svg);
```

`svg` is a complete SVG string that can be saved as a `.svg` file or displayed by a page host. The helper creates ordinary input; `adapters` lets Vanilla recognize the embed and collect its capability dependencies. Omitting the adapter leaves the embed unresolved.

Both hosts default to horizontal rows (`direction: 'row'`). `LayoutItem kind="flex"` selects Flex item constraints and holds one drawable child. `minimumSize: 32` sets both minimum width and minimum height. A Node without `shape` defaults to a rectangle.

## How hosts recognize layouts

| Granularity    | Public entry                                                              | Purpose                                                   |
| -------------- | ------------------------------------------------------------------------- | --------------------------------------------------------- |
| One definition | `FlexLayoutDefinition`, `GridLayoutDefinition`, `OverlayLayoutDefinition` | Register one layout composite with Core                   |
| React          | `FlexLayout`, `GridLayout`, `OverlayLayout`, `LayoutItem`                 | Build canonical IR and contribute definitions to `Layout` |
| Vanilla        | `LayoutInputEmbedAdapters`                                                | Recognize all three embeds in Scene, mount, or SSR hosts  |

Pass one or more of the three layout Definitions directly in `CompileOptions.composites`. React and Vanilla adapters produce the same Layout IR and contribute the same Definitions; their adapter convenience arrays do not become Core compile presets.

### React

The three `@retikz/layout-react` containers are embeddable Tier 2 components. Their direct children must be `LayoutItem` elements with the matching `kind`. Fragments and arrays flatten transparently, but ordinary JSX nodes cannot bypass item semantics.

Every `LayoutItem` requires exactly one of `children` or `ir` and must produce exactly one `IRChild`. Optional React `itemKey` becomes canonical JSON `key`. When omitted, Source IR has no `key`, and Layout generates a container-local effective key from the source index before solving. It never reads React's reserved `key`. Nested Layout containers may contribute the same family, while external datasets or foreign Tier 2 runtime contributions remain the outer host's responsibility.

React containers start no local compilation and perform no DOM measurement. They contribute IR and definitions to the outer `Layout`, which compiles and renders the complete tree. Observe artifacts through the outer host.

### Vanilla

`flexLayout()`, `gridLayout()`, and `overlayLayout()` return `InputEmbed` values. Scene, mount, or SSR hosts need the matching adapter; use `LayoutInputEmbedAdapters` for the complete family.

Each adapter calls the same `createXxxLayout()` factory as direct authoring and contributes the layout Definitions required by its family. Vanilla therefore shares schemas, definitions, solvers, and artifact semantics with direct Core compilation and React.

## Further reading

Change `gap.column` to adjust spacing. To distribute remaining space, assign a size to the container and set `grow` on an item. Continue with [Flex layout](/library/layout/flex-layout). Use [Grid layout](/library/layout/grid-layout) for two-dimensional regions or [Overlay layout](/library/layout/overlay-layout) for stacking.

See version changes in the [changelog](/library/layout/changelog).
