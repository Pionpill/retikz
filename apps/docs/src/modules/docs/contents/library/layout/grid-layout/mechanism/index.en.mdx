## Resolve occupancy before materializing tracks

Before sizing tracks, placement determines which cells each item occupies. Fully explicit positions reserve areas first; remaining items search in authored order using `autoFlow`. Implicit definitions materialize tracks beyond the explicit lists. These are real tracks used by measurement, not decorative grid lines.

## Why columns are solved before rows

Available text width affects wrapped height. GridLayout always solves physical x before y: measure horizontal minimum and natural contributions, resolve columns, remeasure children under column constraints, then resolve rows. `autoFlow` changes search order without reversing this dependency.

Contributions, weights, and bounds all affect sizing. Fixed columns supply a size; intrinsic columns read child contributions; fractional columns distribute finite remaining space. Minimum contributions and bounds may constrain the ratio, so multiplying total width by a fraction is not a general solution.

## How spans become continuous slots

Columns of 100 and 140 with a gap of 12 yield a spanning slot of `100 + 12 + 140 = 252`. The item occupies a continuous area across existing tracks; the next row retains both column boundaries. Contribution constraints subtract internal gaps to avoid counting them again as track demand.

Margins reduce available space, and alignment places the actual allocation inside it. Slots, allocations, and visual bounds remain distinct: Node stroke bounds cannot stand in for the track area.

## How the final candidate becomes output

After tracks are resolved, alignment determines exact or bounded proposals. Each measured candidate carries its result; only selected candidates are replayed with translation and clipping. Rejected probes do not leak drawing primitives into the Scene.

`GridLayoutArtifact` records the container, physical tracks, implicit flags, and final item spans. Occurrences distinguish local keys in nested layouts; equal keys alone do not identify the same item.
