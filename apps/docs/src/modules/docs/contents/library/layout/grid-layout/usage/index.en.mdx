`GridLayout` divides its content box into physical column and row tracks. Tracks may be fixed, use minimum or natural content contributions, absorb finite free space by fractions, or combine bounds with `minmax`. Items may declare continuous spans or follow `autoFlow` into the next available area.

## Using this topic

See [Quick start](/library/layout/get-start) for installation. Direct children must use LayoutItem with a matching kind; each item owns one drawable child.

```text
GridLayout
└── LayoutItem (kind="grid")
    └── Node / GridLayout
```

Use `createGridLayout()` with `GridLayoutDefinition` for JSON/IR, or `gridLayout()` with `GridLayoutInputEmbedAdapter` for Vanilla. For the complete family, pass the three layout Definitions in `composites`, or use `LayoutInputEmbedAdapters` for Vanilla embeds.

| Scenario         | Public entry                                                                                      |
| ---------------- | ------------------------------------------------------------------------------------------------- |
| React            | `GridLayout`, `LayoutItem` (`@retikz/layout-react`)                                               |
| Vanilla          | `gridLayout`, `GridLayoutInputEmbedAdapter` (`@retikz/layout-vanilla`)                            |
| Optional inspect | `InspectGridLayout` (`@retikz/layout-react/inspect`), `inspectGridLayout` (Vanilla)               |
| IR / persistence | `GridLayoutSchema`, `createGridLayout`, `IRGridLayout`, `GridLayoutDefinition` (`@retikz/layout`) |

## Tracks and placement

The example combines fixed, `1fr`, and `2fr` tracks, an explicit span, and items without coordinates. Auto placement advances in canonical authored order and does not implement browser-style dense backfilling.

## Container allocation and alignment

Declare at least one `columns` track; omitted rows are sized from content. `justifyItems` / `alignItems` align items inside cells, while `justifyContent` / `alignContent` position the complete track group.

## Choosing track types

| Form     | Key fields                     | Meaning                                       |
| -------- | ------------------------------ | --------------------------------------------- |
| fixed    | `{ kind: 'fixed', value }`     | Fixed non-negative size                       |
| content  | `{ kind: 'content', mode }`    | Child minimum or natural contribution         |
| fraction | `{ kind: 'fraction', factor }` | Positive fraction weight in finite space      |
| minmax   | `{ kind: 'minmax', min, max }` | Non-fraction lower and fixed/content/fr upper |

## Item constraints

Each item owns one `child`; its container assigns space and position. `margin` stays outside the slot. Item alignment overrides apply only to that item and otherwise inherit from the container.

In React, write optional `key` as `itemKey` and provide `child` through one drawable child or `ir`. When `itemKey` is omitted, the generated identity exists only in internal artifacts and is not written back to Source IR.
