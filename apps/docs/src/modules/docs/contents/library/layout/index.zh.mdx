Layout 把“如何排布子图形”从手写坐标中提取出来。Flex、Grid 与 Overlay 分别处理线性分配、二维轨道和同一区域叠放，并能递归组合；Standard、Graph、Plot 等上层包可以复用这些能力，同时继续拥有自己的领域语义。

给定相同的可用空间与子图形测量结果，布局求解是确定的，并且不依赖具体渲染后端。文字尺寸仍取决于宿主提供的测量器、字体和字体加载状态。

下面先用弹性布局分行、网格布局分列，再在右侧单元内用叠加布局放置徽标，展示三种容器如何作为普通子图形递归组合。

这个示例使用 `@retikz/layout-react/inspect` 的 `LayoutInspectLayout` 装配布局检查器，再用 `InspectFlexLayout`、`InspectGridLayout` 与 `InspectOverlayLayout` 选择具体实例。需要阻止某段 authored 子树继承检查请求时，用 `LayoutInspectScope request={false}` 建立硬屏障。Layout 根入口不静态加载可选检查能力。

## 职责一览

| 组件            | 核心模型                   | 适合解决的问题                     |
| --------------- | -------------------------- | ---------------------------------- |
| `FlexLayout`    | 单主轴、伸展/收缩、换行    | 图例条目、标签带、工具条、线性注释 |
| `GridLayout`    | 二维轨道、跨轨道、自动放置 | 面板、矩阵、刻度区、结构化图形区域 |
| `OverlayLayout` | 同一区域内对齐或局部定位   | 徽标、浮层、注释、叠放图形         |

容器负责通用尺寸分配、间距、对齐、溢出和可观察结果；数据通道、图表语义、表格规则与算法布局仍由对应领域包负责。

## 三个发布包

| 包                       | 负责什么                           | 什么时候使用                        |
| ------------------------ | ---------------------------------- | ----------------------------------- |
| `@retikz/layout`         | schema、factory、Definition 与求解 | 校验或持久化 IR，直接接入 Core 编译 |
| `@retikz/layout-react`   | 布局容器的 React DSL               | 在 React `Layout` 中创作            |
| `@retikz/layout-vanilla` | Input helper 与 InputEmbedAdapter  | 无 React 的浏览器或脚本入口         |

使用 React 创作时，在 `@retikz/react` 的 `Layout` 中组合 `FlexLayout`、`GridLayout` 或 `OverlayLayout`；使用 Vanilla 时，通过 `@retikz/layout-vanilla` 的 helper 与 adapter 接入；读取持久化 JSON 时，则用 `@retikz/layout` 校验完整布局 IR，并把所需 Definition 传给 Core 编译器。
