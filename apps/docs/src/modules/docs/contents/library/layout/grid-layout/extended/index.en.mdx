## Combine intrinsic sizing and track bounds

Content tracks size to the space required by text or drawings, while bounded tracks limit how much their width can change. Both can be used in one container.

| Property                        | Available values                                                      | Explanation                                                                                                                    |
| ------------------------------- | --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `columns[].kind`                | `fixed`, `content`, `fraction`, `minmax`                              | Select the sizing strategy; this demo uses `content` for the first column and `minmax` for the second                          |
| `columns[].mode`                | `minimum`, `natural`                                                  | The content track’s `mode`: use minimum or natural intrinsic contributions                                                     |
| `columns[].min`                 | `fixed` or `content` breadth                                          | The bounded track’s `min`: lower bound; fractions are not accepted                                                             |
| `columns[].max`                 | `fixed`, `content`, or `fraction` breadth                             | The bounded track’s `max`: upper bound or fractional growth policy; a fixed upper bound must be at least the fixed lower bound |
| `size.x / size.y`               | `{ kind: "content" }`, `{ kind: "fixed", value }`, `{ kind: "fill" }` | Physical container width and height: size to content, use a fixed value, or fill finite parent space                           |
| `Node.layout.minimumSize.width` | Non-negative number                                                   | Node minimum width, independent of track bounds; compare wide and narrow content                                               |

Switch the content mode to compare the first column’s minimum and natural width. The orange node in the second column defaults to a minimum width of 220, while the upper bound ranges from 110 to 250. Raise the upper bound from 110 to 220 to see the dashed column boundary and the node below move. Increasing it further to 250 leaves the track at the required width of 220; an upper bound does not force the track to fill it. The orange node retains its own minimum width: the bound limits the track, not the child’s geometry. To explore the lower bound, reduce Node minimum width to 40, then increase the second column’s minimum and watch short content receive a wider track.

## Combine explicit spans and implicit tracks

When an item targets a position beyond the explicit rows or columns, the container adds the required tracks. Implicit track settings determine their sizes.

| Property                       | Available values                                  | Explanation                                                                       |
| ------------------------------ | ------------------------------------------------- | --------------------------------------------------------------------------------- |
| `row.start / column.start`     | Optional non-negative integer                     | Zero-based item start; tracks are added when the start exceeds the explicit range |
| `row.span / column.span`       | Positive integer, default 1                       | Number of consecutive rows or columns to span                                     |
| `implicitRow / implicitColumn` | `fixed`, `content`, `fraction`, or `minmax` track | Sizing policy for added rows and columns; defaults to natural content sizing      |
| `autoFlow`                     | `row`, `column`                                   | Auto-placement direction; does not swap physical row and column meanings          |

The first demo item spans two columns. Change its starting row to reveal the intervening tracks, then adjust implicit row height to compare empty and occupied rows. Switching auto-placement direction changes automatic placement only: sizing still follows physical x→y, and row and column gaps do not swap.

## Handle overlap and visual overflow explicitly

Items sharing a grid area overlap; drawings extending beyond the container overflow. Different properties control these behaviors.

| Property       | Available values    | Explanation                                                                                                             |
| -------------- | ------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `overlap`      | `reject`, `allow`   | Container property: allow or reject overlap between fully explicit placements; automatic free-space search is unchanged |
| `column / row` | `{ start?, span? }` | Item properties: define the occupied area; the demo’s overlap toggle also changes the second item’s placement           |
| `overflow`     | `visible`, `clip`   | Keep overflow visible or clip to the container allocation; neither option reruns layout                                 |

With overlap disabled, the second demo item occupies the adjacent column. Enabling overlap sets `allow` and moves it into the first item’s area, so each control state is valid. The container is deliberately narrower than the two fixed columns. Switch clipping to compare visibility without changing tracks or placement.
