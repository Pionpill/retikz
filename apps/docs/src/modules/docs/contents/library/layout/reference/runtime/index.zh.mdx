description: 查询 Layout 布局 Definition、Core 测量与回放，以及 React 和 Vanilla 适配器如何汇入同一次编译。
---

布局 schema 只保存容器与子项配置；Definition、Core 编译上下文和适配器属于运行时。Layout 负责通用布局求解，Core 负责对子图形提出双轴空间条件、隔离测量候选、回放最终候选并发布类型化产物。

> 这里解释 Definition 接入与执行逻辑，不重复 schema 字段。持久化配置见[输入契约](/library/layout/reference/contract-input)，求解结果见[产物契约](/library/layout/reference/contract-artifact)。

## 如何接入 Definition

| 粒度     | 公开入口                                                                  | 用途                                              |
| -------- | ------------------------------------------------------------------------- | ------------------------------------------------- |
| 单一定义 | `FlexLayoutDefinition`、`GridLayoutDefinition`、`OverlayLayoutDefinition` | 只向 Core 注册一个布局复合组件                    |
| React    | `FlexLayout`、`GridLayout`、`OverlayLayout`、`LayoutItem`                 | 从组件树生成规范 IR，并向外层 `<Layout>` 贡献定义 |
| Vanilla  | `LayoutInputEmbedAdapters`                                                | 让 Scene、挂载与 SSR 入口识别三种布局嵌入项       |

将一个或多个布局 Definition 直接放入 `CompileOptions.composites`。React 与 Vanilla 适配器生成相同的 Layout IR，并贡献所需的 Definition；adapter 便利数组不成为 Core compile preset

## 一次布局事务

布局容器是 Core 的布局感知复合组件。一次编译会按确定顺序完成以下阶段：

1. **解析输入**：Core 按 `namespace` 与 `type` 找到 Definition，并使用对应 schema 校验规范 IR。
2. **测量子图形**：容器通过 `layoutChild` 请求子图形的最小、自然、范围或精确尺寸候选。候选携带父级求值后的 `slotSize`、真实 `allocationBounds`、`visualBounds` 和可用对齐参考线。
3. **求解容器**：Layout 的纯求解器根据容器规则、可用空间和候选测量结果决定轨道、布局行、分配区域与平移。
4. **回放最终候选**：每个子图形只回放被选中的候选；未选候选不会发布图元、资源、命名空间或产物。
5. **发布结果**：Core 把 Layout 返回的值封装为带 occurrence 的复合组件产物，与最终 Scene 一起返回。

固定几何可以拒绝过小的分配区域，因此 `slotSize` 与真实 `allocationBounds` 必须分开观察。容器不会因为拒绝而重新猜测主轴尺寸；可确定的尺寸不足通过溢出状态和可见边界表达，无效或无法求解的配置则直接报错。

嵌套布局仍属于同一次 Core 编译。内层容器作为普通子图形接受外层空间提案，每次复合组件出现（occurrence）分别发布本地 key 空间中的产物，不依赖公开 id 选择实例。

## 直接使用 Core

```ts
import { compileToScene } from '@retikz/core';
import {
  FlexLayoutArtifactSchema,
  FlexLayoutDefinition,
  GridLayoutDefinition,
  OverlayLayoutDefinition,
} from '@retikz/layout';

const output = compileToScene(scene, {
  composites: [FlexLayoutDefinition, GridLayoutDefinition, OverlayLayoutDefinition],
});
const envelope = output.artifacts.find(
  artifact => artifact.kind === 'composite' && artifact.namespace === 'layout' && artifact.type === 'flexLayout',
);
const artifact = FlexLayoutArtifactSchema.parse(envelope?.value);
```

如果宿主只使用单一容器，可以只把对应 Definition 放入 `compile.composites`；图中使用完整布局家族时再加入其它 Definition。产物信封中的 `occurrence.sourcePath` 与 `occurrence.expansionPath` 用于区分嵌套或重复实例，`value` 再由对应的 `XxxLayoutArtifactSchema` 精确解析

## React

`@retikz/layout-react` 的三个容器都是可嵌入 Tier 2 组件。容器直属 children 必须是匹配 `kind` 的 `LayoutItem`；Fragment 和数组会透明展开，但普通 JSX 节点不能绕过子项语义。

每个 `LayoutItem` 必须在 `children` 与 `ir` 中二选一，并最终生成恰好一个 `IRChild`。React 的 `itemKey` 会写入规范 JSON 的 `key`；它不读取 React 保留的 `key`。嵌套 Layout 布局可以继续贡献同一布局家族，外部数据集或其它 Tier 2 运行时贡献则应由外层宿主负责。

React 容器本身不启动局部编译，也不测量 DOM。它们把 IR 与 Definition 贡献给外层 `<Layout>`，由宿主统一编译和渲染；需要读取产物时使用外层的产物观察入口。

## Vanilla

`flexLayout()`、`gridLayout()` 与 `overlayLayout()` 返回 `InputEmbed`。Scene、挂载或 SSR 宿主需要传入对应 adapter；完整布局家族使用 `LayoutInputEmbedAdapters`。

每个适配器调用与 React 相同的 `createXxxLayout()` 工厂生成规范 IR，并贡献该布局家族所需的 Definition。Vanilla 因而与直接 Core 编译、React 入口共享同一套 schema、Definition、求解器和产物语义

## 布局检查器

布局检查器是可选的运行时开发辅助能力，不进入 Layout IR，也不修改类型化布局产物。`@retikz/layout/inspect` 拥有三种 Inspector Definition、选项 schema 与预设；`@retikz/layout-react/inspect` 和 `@retikz/layout-vanilla/inspect` 负责宿主接线。Layout 根入口不依赖 `@retikz/inspect`。

Flex、Grid 与 Overlay Inspector 读取 Core 观测到的最终类型化 artifact，返回普通 Core Path、Node 与 pattern paint。`@retikz/inspect` 用隔离片段编译这些内容，再转换为 Render 的普通只读图层。SVG 在主图之后绘制 `pointer-events="none"` 分组；Canvas 在主图之后单独绘制，但不把辅助图元加入命中测试。viewBox、主资源、动画和正常交互始终只由主 Scene 决定。

### 颜色、纹理与线型

辅助层用三条正交通道表达不同信息，不再用一种颜色同时暗示边界类别与嵌套层级：

| 通道 | 表达内容            | 规则                                                                                                                                                                                                                           |
| ---- | ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 颜色 | 最终布局 occurrence | Inspect 按最终请求顺序分配 `colorScope`；常规 occurrence 颜色来自当前 Core Theme 的 categorical palette，guide / anchor 使用 `semantic.guide`，溢出 warning 使用 `semantic.warning`，并通过 `InspectionAppearanceContext` 暴露 |
| 纹理 | 空间语义            | Layout 用普通 `lines` pattern paint 表达：margin 与固定 gap 为 `-45°` 的 `/`，padding 为 `45°` 的 `\`；size 为 12、lineWidth 为 1，三者不铺底色                                                                                |
| 线型 | 几何类别            | 容器、内容、item box、Flex line、Grid track/cell/span、Overlay placement 与 alignment guide 统一使用虚线；anchor crosshair 使用实线                                                                                            |

同一个 occurrence 的普通辅助图元共享颜色；嵌套容器按各自最终 occurrence 取得 categorical 颜色。颜色数组循环使用，因此颜色只用于快速归属，精确身份仍由 occurrence locator 表达。guide / anchor 使用低强调的 Theme semantic 颜色，溢出警告是普通半透明 fill，辅助标签也是普通 Node。

绘制顺序固定为 spacing hatch / boundary underlay → family structure → box outline → overflow warning → guide/anchor → label。`bounds.content` 与 `bounds.slot` 只控制对应 outline；`spacing.padding` 与 `spacing.margin` 独立控制两种纹理和边界。margin、padding 与固定 gap 使用独立 dashed line 表达边界；ring 只描内外周长，不描四块纹理分片之间的接缝。`distributedSpace` 只显示未占用 content 的 dashed perimeter，内部保持透明留白。若 spacing boundary 已被 content/slot outline 或 Flex line / Grid track 完整覆盖，同一线段只绘制一次；单独开启任一类别时仍保留其完整可见边界。

### 三种选择范围

| 范围          | React                                                              | Vanilla                                                                  | 语义                                        |
| ------------- | ------------------------------------------------------------------ | ------------------------------------------------------------------------ | ------------------------------------------- |
| 整张图        | `LayoutInspectLayout request={...}`                                | figure 的 `createInspectionVanillaAuthoring(...)`                        | 按 Inspector key 选择全部匹配 occurrence    |
| authored 子树 | `LayoutInspectScope request={...}`                                 | Scope 的 `createInspectionVanillaAuthoring(...)`                         | 只选择该 Scope 的 authored 后代             |
| 单个容器      | `InspectFlexLayout` / `InspectGridLayout` / `InspectOverlayLayout` | `inspectFlexLayout()` / `inspectGridLayout()` / `inspectOverlayLayout()` | 只选择当前 occurrence，不自动传播到嵌套布局 |

React 必须由 `LayoutInspectLayout` 提供预注册三种 Definition 的检查宿主；Vanilla 必须把 `createLayoutInspectionVanillaDriver()` 传给 render / mount 的 `compileDriver`。`LayoutInspectScope request={false}` 与 `createLayoutInspectionBarrier()` 都建立后代不能越过的硬屏障。

同一个 Inspector 的 scene → 外层 subtree → 内层 subtree → self 请求按范围与声明顺序求值。`bounds` 与 `spacing` 的对象形式逐项合并，boolean 与对象互换时由后写值替换整组；请求值 `false` 关闭当前层选择，但更深请求仍可重新开启。省略全部请求时 observer 不捕获布局产物，也不会产生只读图层。

请求值 `true` 使用完整默认轮廓：`container`、`content`、`slot`、`allocation`、padding、margin、`overflow` 与 `alignmentGuides` 开启，`visual` 与 `labels` 关闭。对象形式只覆盖显式字段；例如 `{ spacing: { padding: false } }` 只关闭 padding 纹理。

文档 playground 的“推荐”不是完整轮廓：Flex 显示 content outline、Flex 行区域与固定 gap，Grid 显示 content outline、轨道边界与固定 gap，Overlay 只显示 content outline。选择“全部”会打开每个细节；“关闭”只关闭总开关；Reset 回到推荐值。

每个 `InspectXxxLayout` 的 `inspect` 只接受 `false`、`true` 或对应的稀疏选项；未知字段和错误类型会直接报错。Inspect 在 Core traversal 前校验选择与选项输入，最终 occurrence 确定后再合并并解析完整选项。Layout Inspector 只读取同次 compile 的类型化 artifact，并返回普通 Core 子元素。Retained 更新会原子提交主图、产物和只读图层；失败时不发布半帧。
