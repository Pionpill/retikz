`OverlayLayout` lets several graphical children share one region. Aligned items follow container alignment, while positioned items use local `at` and `anchor` values for badges, callouts, and similar overlays. `sizeParticipation` controls container sizing, while `zIndex` controls only stable paint layers.

## Using this topic

See [Quick start](/library/layout/get-start) for installation. Direct children must use LayoutItem with a matching kind; each item owns one drawable child.

```text
OverlayLayout
└── LayoutItem (kind="overlay")
    └── Node / OverlayLayout
```

Use `createOverlayLayout()` with `OverlayLayoutDefinition` for JSON/IR, or `overlayLayout()` with `OverlayLayoutInputEmbedAdapter` for Vanilla.

| Scenario         | Public entry                                                                                                  |
| ---------------- | ------------------------------------------------------------------------------------------------------------- |
| React            | `OverlayLayout`, `LayoutItem` (`@retikz/layout-react`)                                                        |
| Vanilla          | `overlayLayout`, `OverlayLayoutInputEmbedAdapter` (`@retikz/layout-vanilla`)                                  |
| Optional inspect | `InspectOverlayLayout` (`@retikz/layout-react/inspect`), `inspectOverlayLayout` (Vanilla)                     |
| IR / persistence | `OverlayLayoutSchema`, `createOverlayLayout`, `IROverlayLayout`, `OverlayLayoutDefinition` (`@retikz/layout`) |

The structural layer contributes intrinsic size. The top-right badge uses positioned placement and excludes its size contribution. The caption remains aligned. Paint order sorts by ascending `zIndex`, preserving authored `sourceIndex` within one layer.

## Aligned and positioned

| Mode         | Slot source                                                     | Typical use                             |
| ------------ | --------------------------------------------------------------- | --------------------------------------- |
| `aligned`    | Content box after margins, resolved by alignment                | Backgrounds, centered content, captions |
| `positioned` | `at` selects a target; `anchor` selects the slot point attached | Badges, callouts, local annotations     |

## Container allocation and alignment

All items share one content region. Use container alignment for ordinary layers and item overrides or a local target point for exceptions. Position and paint order are independent choices.

## Item constraints

Each item owns one `child`; its container assigns space and position. `margin` stays outside the slot. Item alignment overrides apply only to that item and otherwise inherit from the container.

## Placement forms

| kind         | Fields                                   | Meaning                                      |
| ------------ | ---------------------------------------- | -------------------------------------------- |
| `aligned`    | none                                     | Uses container and item alignment            |
| `positioned` | `at`, `anchor?`, `width?`, and `height?` | Content-local target and optional exact slot |

In React, write optional `key` as `itemKey` and provide `child` through one drawable child or `ir`. When `itemKey` is omitted, the generated identity exists only in internal artifacts and is not written back to Source IR.
