`OverlayLayout` lets several graphical children share one region. Aligned items follow container alignment, while positioned items use local `at` and `anchor` values for badges, callouts, and similar overlays. `sizeParticipation` controls container sizing, while `zIndex` controls only stable paint layers.

<DocTab value="react-jsx" label="React + JSX">

In React + JSX, direct children of `OverlayLayout` use `OverlayLayoutItem`. Each item carries one drawable child:

```text
OverlayLayout
└── OverlayLayoutItem
    └── Node / OverlayLayout
```

```tsx
import { Layout, Node } from '@retikz/react';
import { OverlayLayout, OverlayLayoutItem } from '@retikz/layout-react';

export const Example = () => (
  <Layout>
    <OverlayLayout size={{ x: { kind: 'fixed', value: 100 }, y: { kind: 'fixed', value: 60 } }}>
      <OverlayLayoutItem>
        <Node text="A" />
      </OverlayLayoutItem>
      <OverlayLayoutItem offset={{ x: 30, y: 20 }}>
        <Node text="B" />
      </OverlayLayoutItem>
    </OverlayLayout>
  </Layout>
);
```

In React, write optional `key` as `itemKey` and provide `child` through one drawable child or `ir`. When `itemKey` is omitted, the generated identity exists only in internal artifacts and is not written back to Source IR.

        { kind: 'overlay', child: { type: 'node', text: 'A' } },

## Define the shared content box

All items share one content box instead of consuming space in sequence. Container size and padding define that common reference area.

| Property          | Available values                                                      | Explanation                                                                                          |
| ----------------- | --------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `size.x / size.y` | `{ kind: "content" }`, `{ kind: "fixed", value }`, `{ kind: "fill" }` | Physical container width and height: size to content, use a fixed value, or fill finite parent space |
| `padding`         | Non-negative number, or an object with `x` / `y` / per-side values    | Inset the container on each side to form the content box                                             |

The demo places items at the top-left and bottom-right. Adjust width, height, and padding to see both follow the same reference box. Omitted sizes use content sizing; `fill` requires finite parent space. The fixed demo height illustrates the shared area and does not require equal node heights.

## Set alignment and item overrides

The container provides default alignment, while an item can choose its own. This demo compares horizontal alignment only: the blue node always inherits the container, and the orange node can switch between inheritance and an item override.

| Property       | Available values                             | Explanation                                                                 |
| -------------- | -------------------------------------------- | --------------------------------------------------------------------------- |
| `justifyItems` | `start`, `center`, `end`, `stretch`          | Default container horizontal alignment, affecting items without an override |
| `justifySelf`  | Omit, or `start`, `center`, `end`, `stretch` | Item horizontal alignment; selecting Inherit omits this property            |

Both nodes initially inherit the container. Change Container horizontal alignment to move them together. Set Orange node alignment to End, then change the container alignment again: only the blue node follows it. Select Inherit to restore shared movement. Fixed `alignSelf` values place the items at the top and bottom so they remain distinguishable; this vertical separation is only a comparison aid. This example focuses on start, center, and end positioning.

## Offset an aligned result

An offset moves an item after alignment. It is useful for nudging badges or overlays without changing the content-box origin.

| Property              | Available values                                                                 | Explanation                                                                                    |
| --------------------- | -------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `offset.x / offset.y` | Finite number, default 0                                                         | Signed horizontal and vertical offsets after placement; y must be 0 for baseline-aligned items |
| `alignSelf`           | `start`, `center`, `end`, `stretch`, `first-baseline`, `last-baseline`; optional | Vertical alignment before applying the offset; inherits the container when omitted             |

The first demo item stays fixed. Switch the second item’s vertical alignment, then adjust its x / y offsets to move it from that aligned position. To place a particular corner at a specific coordinate, use `positioned` from extended usage instead of treating offsets as absolute coordinates.
