自定义 width profile 将 JSON-safe 参数与运行时宽度采样函数关联，再把生成的 Definition 注入当前图。先阅读[基础用法](/library/extension/ribbon/usage)，确认中心线 Ribbon 的常用写法。

## 适用边界

内置固定宽度、端点插值、stops 与 `bulge` 已足够时，直接使用[基础用法](/library/extension/ribbon/usage)。只有业务需要自己的宽度函数时，才定义新的 profile。输入仍保存 profile 名称和 JSON 参数；函数与 Definition 仅存在于运行时。

## 定义能力

需要业务宽度曲线时，用 `defineRibbonWidthProfile` 创建一个 profile，再用 `createRibbonPathKindDefinition` 创建包含该 profile 的唯一 Ribbon definition。自定义 definition 必须和内置 definition 走同一 `RibbonPathSchema`、profile registry 与几何编译路径。

将以下共享定义保存为 `pulse-profile.ts`，供不同 API 的消费示例复用：

```ts
import { createRibbonPathKindDefinition, defineRibbonWidthProfile } from '@retikz/extension';
import { z } from 'zod';

export const pulseProfile = defineRibbonWidthProfile({
  name: 'pulse',
  paramsSchema: z.strictObject({
    base: z.number().nonnegative(),
    peak: z.number().nonnegative(),
  }),
  widthAt: ({ offset, params }) => params.base + (params.peak - params.base) * Math.sin(Math.PI * offset),
});

export const pulseRibbonDefinition = createRibbonPathKindDefinition({ profiles: [pulseProfile] });
```

`params` 必须保持 JSON-safe，并由 profile 的 `paramsSchema` 在采样前校验。`widthAt` 只能返回有限的非负 user-unit 宽度。

以下写法复用上方的 `pulseRibbonDefinition`，绘制同一条 `pulse` 流带。Definition 在渲染或编译入口装配，路径通过 `width.name` 引用它的 profile；仅 import 不会自动注册。

      kind="ribbon"

    >

  </Layout>

### 组装 provider graph

需要由 adapter 或工具链在编译前汇总 runtime datasets 时，使用 `createRibbonProviderContribution`。它把官方 `bulge` 和调用方 profiles 合并到同一个 `pathKind/ribbon` provider，再交给 Core 的通用 resolver：

```ts
import { compileToScene, resolveCoreProviderDependencies } from '@retikz/core';
import { createRibbonProviderContribution } from '@retikz/extension';

import { pulseProfile } from './pulse-profile';
import { ir } from './ribbon-ir';

const compileOptions = resolveCoreProviderDependencies({
  contributions: [createRibbonProviderContribution({ profiles: [pulseProfile] })],
});

const result = compileToScene(ir, compileOptions);
```

Provider 只负责把 Definition 和 runtime profile dataset 装配成普通 Core compile options；它不改变 `Path` 的 IR 结构，也不建立第二套 Ribbon lookup。直接 `pathKinds` 注入与 provider graph 共享同一套 `createRibbonPathKindDefinition` 构造路径、schema 和 compile 实现。

## 错误与限制

- profile 的 `name` 不能为空；同名但不同 identity 的 profile 在装配时会报冲突，不会按顺序覆盖
- `paramsSchema` 若存在，会在宽度采样前校验 JSON 参数；未知 profile、非法参数及非有限或负数的 `widthAt` 结果都会使编译失败
- 同一图只装配一个 `ribbon` Path kind Definition；不要同时传官方 Definition 与自定义 Definition

## 自定义端帽

用 `defineRibbonCap` 定义参数 schema 和 `resolve`，再通过 `createRibbonPathKindDefinition({ caps })` 注入，最后在 `start.cap` 或 `end.cap` 中按 name 引用。回调接收端面中点、向外方向、端面轴和宽度；命令位于 Path 局部坐标，首尾接点必须闭合。end 从左到右，start 从右到左，宿主负责最终 close。
