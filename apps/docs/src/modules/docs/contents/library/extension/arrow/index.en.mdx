These arrow Definitions add six optional geometries to path endpoints. After choosing filled, hollow, or open-line shapes, use path `arrowDetail` to adjust size and color.

## Using this topic

Import Definitions such as `DiamondArrowDefinition` on demand from `@retikz/extension`, or use `ExtensionArrowDefinitions` for the full family. Imports do not register endpoints globally. React uses `Layout.extensions.arrows`; Vanilla uses `compile.arrows`.

<DocTab value="react-jsx" label="React + JSX">

```tsx
import { DiamondArrowDefinition } from '@retikz/extension';
import { Draw, Layout } from '@retikz/react';

export const Example = () => (
  <Layout extensions={{ arrows: [DiamondArrowDefinition] }}>
    <Draw
      way={[
        [0, 0],
        [160, 0],
      ]}
      arrow="->"
      arrowDetail={{ end: { shape: 'diamond' } }}
    />
  </Layout>
);
```

## Diamond arrows

`diamond` and `openDiamond` are filled and hollow symmetric diamonds. Both default to 11 × 6; the hollow form is stroke-only.

/>

<DocTabs defaultValue="api">
<DocTab value="api" label="API reference">

#### DiamondArrowDefinition / OpenDiamondArrowDefinition

Pass these Definitions to `Layout.extensions.arrows` or `compile.arrows` and select an endpoint with `arrowDetail.end.shape`:

| Definition                   | `shape`       | Default length × width |
| ---------------------------- | ------------- | ---------------------- |
| `DiamondArrowDefinition`     | `diamond`     | 11 × 6                 |
| `OpenDiamondArrowDefinition` | `openDiamond` | 11 × 6                 |

#### IRArrowEndDetail

| Field        | Type               | Description                                                       |
| ------------ | ------------------ | ----------------------------------------------------------------- |
| `shape`      | `string`           | One of the endpoint names above                                   |
| `length?`    | `number`           | Nonnegative length along the path                                 |
| `width?`     | `number`           | Nonnegative width across the path                                 |
| `color?`     | `string \| number` | Marker color; inherits the path stroke when omitted               |
| `lineWidth?` | `number`           | Stroke width for hollow or open contours; ignored by solid shapes |

</DocTab>
</DocTabs>

Change color, scale, and hollow stroke width to compare their paint.

## Square arrows

`square` and `openSquare` default to 8 × 8. The hollow contour is inset before stroking so a heavy stroke stays within marker bounds.

## Bar endpoint

`bar` draws an open line perpendicular to the path at its endpoint. It defaults to 8 × 8 and has no fixed domain meaning.

<DocTab value="api" label="API reference">

#### BarArrowDefinition

Pass these Definitions to `Layout.extensions.arrows` or `compile.arrows` and select an endpoint with `arrowDetail.end.shape`:

| Definition           | `shape` | Default length × width |
| -------------------- | ------- | ---------------------- |
| `BarArrowDefinition` | `bar`   | 8 × 8                  |

#### IRArrowEndDetail

| Field        | Type               | Description                                                       |
| ------------ | ------------------ | ----------------------------------------------------------------- |
| `shape`      | `string`           | One of the endpoint names above                                   |
| `length?`    | `number`           | Nonnegative length along the path                                 |
| `width?`     | `number`           | Nonnegative width across the path                                 |
| `color?`     | `string \| number` | Marker color; inherits the path stroke when omitted               |
| `lineWidth?` | `number`           | Stroke width for hollow or open contours; ignored by solid shapes |

</DocTab>

Length sets the span along the path, width sets the bar span, and line width affects only the marker.

## Crow-foot endpoint

`crowFoot` draws three open rays from the path contact point and defaults to 8 × 8. Relationship diagrams can use it for multiplicity, but the geometry has no fixed domain meaning.
