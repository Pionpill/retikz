---
title: 设计理念
description: 理解 Extension 如何沿用 Kernel 的自定义协议，按需提供常见绘图元素。
---

同一个节点可以画成矩形或十字形，同一条路径可以使用不同的箭头。Extension 为这些常见变化提供现成的绘图定义，作者只需选择当前图需要的部分。

## 沿用已有的扩展协议

Kernel 提供定义和使用自定义画法的公开协议。绘图定义是一份与名称对应的绘制规则。Extension 使用这套协议实现官方的节点形状、箭头、裁剪和流带；它与作者自行编写的定义使用相同的装载方式。

| 已有绘图对象 | Extension 提供的选择 | 对象仍然是什么 |
| ------------ | -------------------- | -------------- |
| Node         | 十字形、圆柱等轮廓   | 节点           |
| Path         | 菱形等端点箭头       | 路径           |
| 绘图内容     | 圆形、路径等裁剪区域 | 原有内容       |
| Path         | 有宽度的流带画法     | 路径           |

这些选择增加可用的几何形态和绘制方式，但不赋予对象新的业务角色。例如十字形节点仍是 Node；它是否表示“医院”，由使用这张图的领域决定。

## 只为当前图装入所需定义

Extension 不会因安装或导入而自动启用所有能力。作者选择一个定义，再把它传入当前图的配置。例如快速开始中，`shape="cross"` 选择十字形；传入 `CrossShapeDefinition` 后，这个名称才能找到对应的绘制规则。

按需装入让不同图形可以选择不同的形状、箭头和裁剪规则，也让这些官方实现与自定义实现保持同一使用方式。绘图作者可以直接使用这些元素，上层组件也可以复用它们来丰富 Retikz 生态。

## 与 Standard 的分工

Extension 丰富**已有图元可以怎样画**；Standard 封装**可以直接使用的通用绘图对象**。需要给 Node 换一种轮廓时选择 Extension；需要声明 List、Surface 或 Legend 这样的完整对象时选择 Standard。两者都复用基础绘图能力，不另建一套场景或渲染方式。
