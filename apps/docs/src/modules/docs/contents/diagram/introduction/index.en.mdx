The Diagram group owns domain capabilities for what appears in a diagram and what each element means. The current Notation package family provides independently drawable elements. Future Graph capabilities can compose those elements when a figure needs global nodes, edges, topology, or automatic layout without changing their drawing contracts.

## Start with Notation

The first Notation set includes `LogicFrame`, Terminal, Stage, Decision, Junction, and Connector. They reuse Core Node, Path, target, and Scene contracts plus Layout's generic containers. Notation does not copy geometry, renderer, or layout algorithms.

| Package                    | Responsibility                                    | Use it when                                    |
| -------------------------- | ------------------------------------------------- | ---------------------------------------------- |
| `@retikz/notation`         | Schemas, factories, Definitions, lowering, and IR | Validating or persisting JSON and using Core   |
| `@retikz/notation-react`   | React JSX authoring                               | Authoring inside `@retikz/react` `Layout`      |
| `@retikz/notation-vanilla` | Builders, adapters, SSR, and mount authoring      | Authoring in browsers or scripts without React |

All three packages produce the same canonical IR. React and Vanilla provide authoring surfaces without duplicating schemas, defaults, or lowering.

## Capability boundary

Notation owns the meaning, visual defaults, and lowering path of each diagram element. It does not own:

- A global `GraphModel`, node and edge collections, or topology constraints
- Automatic layout, routing, obstacle avoidance, or collision search
- Editor state such as selection, viewport, or history
- Execution models for UML or state machines

You can therefore draw local logical structure with Notation today and reuse the same elements inside a future Graph capability.
