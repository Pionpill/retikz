title: Logic Node
description: Terminal, Stage, Decision, and Junction retain Notation semantics and lower lightly to Core Nodes.

Logic nodes are lightweight semantic IR values that retain the `notation` namespace. Terminal, Stage, Decision, and Junction remain distinguishable in persisted data for tools, LLMs, and future Graph presentations. At compile time, each unit uses its own Definition to lower one-to-one into a same-id Core `Node`

## Usage

```tsx
import { Layout, Text } from '@retikz/react';
import { Decision, Junction, Stage, Terminal } from '@retikz/notation-react';
```

```tsx
<Layout width={440} height={180}>
  <Terminal id="start" position={[20, 70]}>
    Start
  </Terminal>
  <Stage id="step" position={[130, 70]}>
    Process
  </Stage>
  <Decision id="check" position={[250, 70]}>
    <Text>Ready?</Text>
  </Decision>
  <Junction id="join" position={[380, 80]} />
</Layout>
```

String children become Node text, and `<Text>` works as it does with Core `Node`. Applicable Node props such as `color`, `fill`, `padding`, `minimumSize`, and `position` pass through, while the unit owns its `namespace`, semantic `type`, and fixed `shape`

| Unit       | Fixed shape                    | Logic responsibility               | Geometry defaults                            |
| ---------- | ------------------------------ | ---------------------------------- | -------------------------------------------- |
| `Terminal` | Capsule (rounded rectangle)    | Start or end of a flow             | minimum `48 × 24`, padding `{ x: 12, y: 6 }` |
| `Stage`    | Rounded rectangle, radius `8`  | Process or action in a flow        | padding `8`                                  |
| `Decision` | Flattened diamond, ratio `1.8` | Condition or branch                | padding `{ x: 3, y: 2 }`                     |
| `Junction` | Circle                         | Fork, merge, or continuation point | minimum `8 × 8`, padding `0`                 |

## Examples

### LogicNodeVariant

Logic nodes use the five-value Notation-owned `LogicNodeVariant` vocabulary rather than Core or Viz global Theme Styles. `variant` is the explicit baseline for one logic node; when omitted, the nearest `LogicFrame.logicNodeVariant` applies, then `default`

| variant     | Text           | Border           | Fill                         |
| ----------- | -------------- | ---------------- | ---------------------------- |
| `default`   | `currentColor` | `currentColor`   | `none`                       |
| `primary`   | `contrast`     | `currentColor`   | `currentColor`               |
| `secondary` | `currentColor` | `none`           | 10% precomposed primary tint |
| `outline`   | `currentColor` | 60% primary tint | `none`                       |
| `vibrant`   | `currentColor` | `currentColor`   | 15% precomposed primary tint |

`secondary` has no border. The 10% / 15% / 60% values are precomposed against `#ffffff` in Light mode or `#000000` in Dark mode; they do not create renderer opacity. `primary` uses Core `contrast` text, selecting black or white from the fill. A logic node's `color` is its primary color; omission uses `#000000` in Light and `#ffffff` in Dark

Explicit `textColor`, `stroke`, and `fill` override the variant baseline independently. Explicit `opacity`, `fillOpacity`, and `strokeOpacity` also pass through unchanged. A variant that needs tinting or contrast fails loudly when its primary color cannot be statically resolved. Notation does not read the Core categorical palette and does not put a variant discriminator into Core Scene or renderer output

### LogicFrame inheritance

`LogicFrame.logicNodeVariant` provides a default for logic nodes in its header, sections, nested `LogicFrame`, and Core `Scope` descendants. A nested Frame creates a new scope, an explicit unit `variant` wins, and `variant="default"` resets an outer value. The Frame shell, divider, Connector, and sibling branches are unaffected

```tsx
import { LogicFrame, LogicFrameSection, Stage } from '@retikz/notation-react';

<LogicFrame id="order" logicNodeVariant="secondary">
  <LogicFrameSection sectionKey="input">
    <Stage id="load" position={[0, 0]} />
  </LogicFrameSection>
  <LogicFrameSection sectionKey="important">
    <Stage id="validate" position={[0, 0]} variant="primary" />
  </LogicFrameSection>
</LogicFrame>;
```

### Direct, React, and Vanilla wiring

All three entry points share the same Notation IR and variant lowering path. Direct IR uses package assembly; React and Vanilla adapters do not accept ThemeStyle configuration or a separate variant registry

```ts
import { compileToScene } from '@retikz/core';
import { createNotationDefinitions, createStage } from '@retikz/notation';

const stage = createStage({
  id: 'step',
  position: [0, 0],
  text: 'Process',
  color: '#2563eb',
  variant: 'primary',
});
const scene = compileToScene(
  { version: 1, type: 'scene', children: [stage] },
  { composites: createNotationDefinitions() },
);
```

## How it works

<ComponentAlert
  type="tip"
  title="Optional for everyday use"
  description="Revisit this section when you need to understand the lowering boundary or diagnose paint behavior."
/>

Logic nodes own their persisted notation identity, fixed shape, primary-color interpretation, and `LogicNodeVariant`. They do not own a graph store, automatic layout, obstacle avoidance, interaction, or domain recipes. Core owns Node layout, targets, compilation, and Scene output; Notation only projects the effective variant into ordinary Node paints during lowering

## API Reference

| API                                        | Package                    | Purpose                                                                                  |
| ------------------------------------------ | -------------------------- | ---------------------------------------------------------------------------------------- |
| `variant?: LogicNodeVariantValue`          | All four logic nodes       | Selects one unit's visual variant; omission inherits the Frame default or uses `default` |
| `logicNodeVariant?: LogicNodeVariantValue` | `LogicFrame`               | Sets the default variant for descendant logic nodes; nested Frames create a new scope    |
| `color?: string`                           | All four logic nodes       | Sets the primary color; omission uses `#000000` in Light and `#ffffff` in Dark           |
| `createNotationDefinitions()`              | `@retikz/notation`         | Creates the complete Notation Definition set for direct IR                               |
| `createNotationReactAdapters()`            | `@retikz/notation-react`   | Creates six adapters for React InputScene normalization                                  |
| `createNotationVanillaAdapters()`          | `@retikz/notation-vanilla` | Creates six adapters for Vanilla runtime normalization                                   |
