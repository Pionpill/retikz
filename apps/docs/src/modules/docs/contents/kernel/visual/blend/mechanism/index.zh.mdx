## 混合的背景不是指定的另一个节点

混合发生在实际绘制时：

- **前景**是当前准备绘制的图元。
- **背景**是当前位置在本次绘制前已经积累的结果。
- **混合函数**根据前景色与背景色计算混合颜色，再结合透明度合成到目标。

blendMode 不建立节点间引用。背景可能由多个先前图元组成，也可能受 SVG 宿主背景影响。声明顺序与 zIndex 影响绘制先后，空间重叠本身不能决定谁是背景。

## 混合颜色与透明度是两个步骤

先考虑不透明背景。背景通道 b、前景通道 s 都归一化到 0 到 1。multiply 的结果是 $b \times s$，screen 则是 $1 - (1 - b) \times (1 - s)$，所以前者通常变暗，后者通常变亮。

若 b = 0.8、s = 0.4，multiply 得到 0.32。前景只有 50% 不透明度时，最终通道不是 0.32，而是 $0.5 \times 0.32 + 0.5 \times 0.8 = 0.56$。这组数字解释单个通道，不是图中命名色的数值。

## Scope 默认样式分别作用于后代图元

默认样式决定每个后代的配置；隔离组需要独立的合成背景，让内部图元先彼此混合，再把整组结果放回外部背景。

下图左侧是当前逐图元路径；右侧表示隔离组所需的额外中间结果，只用于说明区别，**不是当前 blendMode 提供的能力**。

<ComponentPreview files="blend-boundary" size="md" hideCode type="flow" />

主几何携带 blendMode；文字、标签、引脚独立输出，不会自动成为一个统一混合图层。Scope 默认样式不创建离屏缓冲区，也不建立隔离边界。“所有子节点设置同一模式”不等于“整个组只混合一次”。

## 后端在图元绘制范围内应用混合状态

SVG 将模式写为几何元素的 `mix-blend-mode` 样式，省略或 normal 不增加该样式。实际背景由浏览器 SVG/CSS 合成环境决定，透明 SVG 与宿主背景需要一起考虑。

Canvas 先 save，再设置 `globalCompositeOperation`，绘制后 restore。它恢复进入作用域前的状态，避免模式泄漏到后续图元；省略或 normal 直接走普通绘制路径。

比较两端时需要保持背景、颜色、透明度与顺序一致。相同模式名称不保证逐像素相同，透明画布、宿主背景、滤镜与抗锯齿仍会影响结果。
