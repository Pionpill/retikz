[Basic usage](/kernel/visual/blend/usage) shows the modes. This page explains where the backdrop comes from and why drawing order changes the image.

## The backdrop is not a designated second node

Blending happens during drawing:

- **The source** is the primitive about to be drawn.
- **The backdrop** is the accumulated result at that location before this draw.
- **The blend function** computes a color from source and backdrop, then transparency determines compositing.

BlendMode does not reference another node. The backdrop may include several previous primitives and may depend on the SVG host background. Declaration order and zIndex affect drawing order; overlap alone does not determine the backdrop.

A below is an orange rectangle using normal; B is blue using multiply. The left draws A, the middle adds B, and the right draws B before A. Positions and individual modes are unchanged.

In the middle, B blends with the existing A. On the right, A covers the overlap using normal. Although multiply's color formula is commutative, these draws do not merely swap its arguments: the last draw uses a different mode.

## Blending color and compositing alpha are separate

Start with an opaque backdrop. Channel values b for backdrop and s for source are normalized to 0–1. Multiply gives $b \times s$; screen gives $1 - (1 - b) \times (1 - s)$. The former tends to darken, the latter to lighten.

For b = 0.8 and s = 0.4, multiply gives 0.32. With source opacity 50%, the final channel is $0.5 \times 0.32 + 0.5 \times 0.8 = 0.56$, not 0.32. These numbers illustrate a channel, not the named colors in the figure.

The flow separates the steps. The existing backdrop feeds color blending and alpha compositing. The final result becomes the next primitive's backdrop.

This simplified equation assumes an opaque backdrop. Transparent backgrounds require coverage and alpha calculations too; multiplying RGB alone does not produce the final pixel. Retikz delegates to native SVG or Canvas compositing rather than maintaining a pixel blender in Core.

## Scope defaults configure individual descendants

Defaults configure individual descendants. An isolated group needs its own backdrop: children first blend internally, then the group result is composited onto the outside backdrop.

The left shows the current primitive path. The right illustrates the extra intermediate result needed for isolation. It is a comparison, **not a capability of the current blendMode contract**.

<ComponentPreview files="blend-boundary" size="md" hideCode type="flow" />

Primary geometry carries blendMode. Text, labels, and pins are separate outputs and do not automatically become one blended layer. Scope defaults create neither an offscreen buffer nor an isolation boundary. Giving each child the same mode does not blend the group once.

## Backends apply blending state within primitive drawing

SVG writes `mix-blend-mode` on geometry elements. Normal or an omitted mode adds no style. The browser SVG/CSS environment determines the backdrop, including the interaction between a transparent SVG and its host background.

Canvas saves context, sets `globalCompositeOperation`, draws, and restores the previous state. This prevents the mode from leaking to later primitives. Normal or an omitted mode follows the ordinary drawing path.

Compare backends with matching backgrounds, colors, opacity, and order. Matching mode names do not guarantee pixel equality: transparent canvases, host backgrounds, filters, and antialiasing still affect results.
