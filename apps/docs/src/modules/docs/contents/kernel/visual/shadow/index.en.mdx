Shadows emphasize card-like nodes and path outlines, helping separate foreground from background. Node and Path supply the primary geometry; shadow styles specify offset, blur, and color. Scope can provide shared defaults for its children.

## The overall picture

Scope supplies separate shadow defaults for Node and Path below. The left node and middle path use those defaults; the right node disables its shadow with `shadow: 'none'`. Observe each shadow relative to its outline, rather than treating the entire subgraph as one image casting a shared shadow.

<ComponentPreview files="/kernel/visual/shadow/integration/shadow-integration" size="sm" />

The configuration is shared, but each element casts its own shadow. Scope does not accept `style.shadow`, and node text and attached labels do not automatically become part of the primary geometry's shadow.

## Choosing an approach and its boundaries

Use presets for common depth effects. Configure offset and blur when you need a specific direction or a hard edge. Children can override defaults or use `none` to disable an inherited shadow.

Shadows do not change layout, anchors, or connection geometry. Adjust position or layout to change actual spacing; use [blend modes](/kernel/visual/blend/usage) to control overlapping colors. SVG and Canvas use their own rendering mechanisms, so blurred edges are not guaranteed to match pixel for pixel.
