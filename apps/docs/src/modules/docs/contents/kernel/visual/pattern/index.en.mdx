title: Patterns
description: Fill shapes and stroke regions with repeating lines, dots, grids, or custom textures

Patterns distinguish regions through texture, such as hatched nodes in a flowchart or a grid inside a geometric region. A pattern is a fill or stroke style: Node and Path define the outline, while the pattern defines the texture repeated within it.

## The overall picture

This example supplies a shared pattern through Scope. Compare the repeating texture in the node and path region with the child that overrides its inherited fill. Elements can share a pattern while retaining their own outlines.

<ComponentPreview files="/kernel/visual/pattern/integration/pattern-integration" size="sm" />

Scope passes styles to its children and can paint an independent envelope through `frame`. Node applies the pattern to its shape, while Path applies it to the region formed by its geometry. Patterns can also paint stroke regions. The texture tile repeats, not the node or path itself.

## Choosing an approach and its boundaries

Start with built-in `lines`, `dots`, or `grid`, adjusting color, spacing, and rotation for common textures. Define a custom pattern when you need a different repeating tile. Built-in and custom patterns use the same fill and stroke entries.

Patterns do not change geometry, layout, or hit regions. To change a node outline, see [Node shapes](/kernel/components/node/shape); to draw a new region, use [Path](/kernel/components/path/usage). A two-point line has no visible fill area, so apply its pattern to the stroke instead.
