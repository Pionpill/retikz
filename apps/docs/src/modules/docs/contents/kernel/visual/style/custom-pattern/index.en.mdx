## Define and register

Import definePattern from `@retikz/core`. Supply a name, optional defaultSize, and emit. Emit receives resolved size, color, and line styles and returns ScenePrimitive geometry in tile-local coordinates.

`defaultSize` must be a finite positive number. `definePattern` checks it when the definition is created and throws immediately for invalid values. When supplying a definition object directly, the author is responsible for meeting the same constraint.

This example defines cross, registers it through Layout.extensions.patterns, and references the same name in fill.shape.

<ComponentPreview files="custom-pattern-basic" size="sm" />

React uses `extensions={{ patterns: [cross] }}`. Vanilla supplies `compile: { patterns: [cross] }` to mount / renderToSvgString. Core uses CompileOptions.patterns. Definitions belong to host configuration; emit functions cannot enter IR.

## Control the period

Returning a geometry iterable keeps context.size as the period. Return `{ tileSize, motif }` when final period differs from base spacing; tileSize must be finite and positive. Use context.round for consistent precision.

## Errors and limitations

Names must exist in the active compile registry. Tiles use the full ScenePrimitive contract, including measured text, clipping, animation, and finite nested content. DOM objects, functions, and unmeasured text are not valid primitives. References use the owning Scene resource namespace; missing, wrong-kind, or cyclic references fail. Typed definition authors are responsible for the primitive contract, and emit failures preserve their original cause.

Resource animations share the scene clock with independent playback origins per host. Tiles within one host share playback state. Local ids do not create independent update nodes, and tiles do not create separate hit targets. Custom definitions consume background, directional styles, and cycles explicitly; receiving these fields does not make the compiler draw them automatically.
