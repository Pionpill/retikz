retikz 把用户写下的 DSL（React 组件或 Vanilla JS 写法）先转成 IR，再编译成 Scene。DSL 负责书写体验，IR 保留“你想画什么”，Scene 只保留“渲染器应该画什么”。

## 三层模型

| 层    | 作用                                                                       | 面向谁                    |
| ----- | -------------------------------------------------------------------------- | ------------------------- |
| DSL   | React 组件或 Vanilla JS 写法，分为 Kernel 与 Sugar                         | 日常作者                  |
| IR    | JSON 可序列化的声明结构，保留 Node / Path / Step / Coordinate / Scope 语义 | 用户、LLM、持久化、转换器 |
| Scene | 渲染目标无关的 primitive、layout bounds、资源表与根动画                    | renderer                  |

IR 是公开契约；Scene 是 renderer 输入。正常写图时不需要手写 Scene。

为什么用户需要知道这三层：日常写图看 DSL；要把图存进数据库、发给 LLM 修改、做 JSON Patch 或跨端渲染时看 IR；只有写 renderer / 调试测量结果时才看 Scene。

## Kernel 与 Sugar

| 层     | 例子                                                                                                        | 是否直接进 IR | 说明                      |
| ------ | ----------------------------------------------------------------------------------------------------------- | ------------- | ------------------------- |
| Kernel | `<Layout>` / `<Scope>` / `<Node>` / `<Coordinate>` / `<Path>` / `<Step>`                                    | 是            | 与 IR 节点一一对应        |
| Sugar  | `<Draw way={...}>`、`DrawWay.Cycle`、相对坐标字符串、<br />`<Circle>` / `<Rectangle>` / `<Star>` 等形状组件 | 否            | adapter 同步展开为 Kernel |

Sugar 不引入新能力。能用 `<Draw>` 画出来的图，也能用 `<Path>` + `<Step>` 手写出来。下面两段编译结果完全一致：

```tsx
// Sugar：一行 way 数组
<Draw way={['a', 'b']} arrow="->" />
```

```tsx
// Kernel：way 的第一个目标展开成 move，其余展开成 line
<Path arrow="->">
  <Step kind="move" to="a" />
  <Step to="b" />
</Path>
```

`<Scope>` 也属于 Kernel：它在 IR 中保留分组语义，编译到 Scene 时下沉为 `group`，并承载局部 transform、clip、样式默认值、动画和 `zIndex` 等组级行为。

## 编译链路

```tsx
<Layout>
  <Node id="a" position={[0, 0]}>
    A
  </Node>
  <Draw way={['a', [80, 0]]} />
</Layout>
```

这段 JSX 会被 adapter 收集成 IR，`@retikz/core` 再负责解析 position、计算 anchor、展开路径与边界，最后输出 Scene。上例中的 `<Draw>` 会在 IR 中成为普通 `path` 节点。

`@retikz/core` 在一次递归遍历中分阶段编排布局与路径，再收尾输出 Scene。下图按依赖顺序展开这三个阶段，不表示对整棵 IR 做三次独立遍历：

<ComponentPreview files="layers-compile" size="xs" hideCode />

- **layout nodes**：遍历遇到 node / coordinate 时立即解析坐标、度量文字、计算包围盒，并登记进当前命名空间。
- **resolve paths**：path 先留下占位；当前 scope 子树或 root 遍历完成后，再从已登记的布局查端点并 flush 成路径图元。这正是箭头上 `anchors` 代表的依赖。
- **fit bounds**：合并所有图元的包围盒，加 padding 并按精度 round，得到 viewBox。

如果 IR 里有 Tier 2 的 composite 节点（如 plot 的高层组件），编译会先把它们下沉成 Kernel，再进入上面的分阶段遍历；细节见[复合](/kernel/concepts/design/composite)。

## 选择建议

| 场景                                     | 推荐                |
| ---------------------------------------- | ------------------- |
| 普通连线、流程图边、带箭头路径           | `<Draw>`            |
| 需要逐段控制 move / line / cycle / curve | `<Path>` + `<Step>` |
| 需要最接近 IR 的测试或转换器输出         | Kernel              |
| 需要持久化、AI 生成或局部修改图          | IR                  |

Sugar 的展开逻辑由 builder 同步调用，不能依赖 React hooks 或异步状态。完整 IR schema 从 [结构参考](/kernel/reference/schema) 进入；IR 根见 [Scene](/kernel/reference/schema/scene)，字段细分见 Entity / Path / Placement。

## 包结构

Kernel 组由 `packages/kernel` 下六个同步发版的 npm 包组成。图中箭头从能力提供方指向使用方：实线串起主要构建链，灰色虚线补充跨层的直接依赖。`@retikz/math` 是零依赖计算底座，`@retikz/core` 在其上定义 IR 与编译语义，其余包按职责接入 core。

<ComponentPreview files="layers-packages" size="sm" hideCode />

| 包                | 职责                                           | Kernel 组依赖 |
| ----------------- | ---------------------------------------------- | ------------- |
| `@retikz/math`    | 零依赖的几何、矩阵与数值计算                   | —             |
| `@retikz/core`    | IR / Scene / schema / geometry / parser        | math          |
| `@retikz/render`  | Scene 渲染：SVG / Canvas、hydration、animation | math + core   |
| `@retikz/react`   | Kernel / Sugar JSX 组件，内置 SVG / Canvas     | core + render |
| `@retikz/vanilla` | 框架无关运行时：mount / hydrate / 动画 / SSR   | core + render |
| `@retikz/tex`     | 可选的 LaTeX 公式解析与图元下沉                | core          |

react / vanilla 只做 adapter：把 DSL 收集成 IR、把渲染交给 render；tex 把 LaTeX 公式下沉为 core 可编译的图元。上层包不另造平行 IR、渲染语义或几何底座。

普通用户装 `@retikz/react`（或 `@retikz/vanilla`）即可，它会自动带上 core 与 render；只有写自定义渲染器或直接读写 IR 时，才单独依赖 `@retikz/core`。
