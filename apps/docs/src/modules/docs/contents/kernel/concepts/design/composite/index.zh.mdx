retikz 的 IR 子节点分两层：**Tier 1** 是 core 内置的 `node` / `path` / `coordinate` / `scope`；**Tier 2 composite** 是 domain 包提供的高层节点，例如 `@retikz/plot` 的整张统计图 spec。

Tier 2 节点用 `namespace + type` 判别，拥有完整 schema，并由同一套 composite registry 在 compile 中处理。只需结构变换时使用 `expand`；需要真实子内容反馈布局时使用布局感知的 `compile`。两条路径最终都产出 Tier 1，布局、anchor、zIndex 与 renderer 继续复用 core 能力；core 不需要认识 table、chart、tree 等领域语义。

## 为什么需要 composite

直接保存几十个矩形和连线，会丢失“这是一张图表 / 一棵树”的高层意图。composite 把领域字段保留在可序列化 IR 中，再把具体几何延迟到 compile 期生成：

<ComponentPreview files="composite-pipeline" size="xs" hideCode />

图中的 `lower` 是关键边界：上游仍能存储、传输、diff 或由 AI 生成高层节点；下游只接收统一的 Tier 1，因此所有 renderer 共享同一次 Core compile 的结果。

适合 composite 的能力通常同时满足三点：

- 一个高层节点会按数据或算法生成数量不固定的 Tier 1 图元；
- 领域 schema 比展开后的几何更能表达用户意图；
- 展开结果应被 React、Vanilla、SVG、Canvas 等入口共同复用。

## 两种互斥分支

`defineComposite` 把 schema 与一个处理分支注册为同一项。definition 必须且只能提供 `expand` 或 `compile`；`schema` 可以是单个 object，也可以是共享同一 `namespace` / `type` literal 的直接 object union。每个 schema 分支的 literal 都必须与 definition key 一致，union 中出现非 object 分支、空 literal 或混合 key 时会立即报错。

Core 只按顶层 `namespace + type` 路由 composite，不读取领域 schema 内部的判别字段。例如 Table 可以在同一个 `table.table` composite 下定义多种 spec 分支，但 `structure.kind` 的解释与缩窄仍由 Table 包负责。

<ComponentPreview files="composite-basic" size="sm" />

| 字段             | 职责                                   | 约束                                  |
| ---------------- | -------------------------------------- | ------------------------------------- |
| `namespace`      | 划分 domain                            | 与 schema literal 一致                |
| `type`           | 标识 domain 内的节点类型               | 与 schema literal 一致                |
| `schema`         | 校验完整高层节点并填充默认值           | object 或共享 key 的直接 object union |
| `expand`         | 无上下文生成一个或多个 Tier 1 / Tier 2 | 与 `compile` 互斥，最终收敛到 Tier 1  |
| `compile`        | 在完整编译环境中测量、约束并放置子内容 | 与 `expand` 互斥                      |
| `artifactSchema` | 校验 `compile` 同次返回的领域 artifact | 有 artifact 类型时必填                |

编译器按 `${namespace}.${type}` 查注册表，校验节点后调用对应分支。嵌套 composite 会继续处理，直到最终输出只含 Tier 1 与已提交 replay。未注册节点产生 warning 并跳过，循环或超过深度限制则报错。完整字段、诊断与独立 lowering 入口见[编译](/kernel/reference/runtime/compile)。

## 布局感知编译

`CompositeDefinition.expand()` 拿不到文字测量、provider、引用环境或父级约束，因此不能表达“先看真实子内容，再求解父布局”的反馈过程。`compile(node, context)` 为这类 Tier 2 组件提供通用闭环：

每次 `layoutChild` 都把子布局拆成四个彼此独立的结果：

| 结果               | 含义                                                   |
| ------------------ | ------------------------------------------------------ |
| `allocationBounds` | 约束后 child 的真实局部占用，不伪装成目标 slot         |
| `slotSize`         | 父级按双轴约束分配的 `width` / `height`，不包含 x / y  |
| `visualBounds`     | 包含描边、marker、shadow、clip 与 transform 的静态包络 |
| `replay`           | 只允许一次原子提交的 opaque token                      |

<ComponentPreview files="layout-aware-compile" size="xl" hideCode />

图中的两次 probe 都返回 allocation bounds、slot size、visual bounds 与 replay，但不会立即发布结果。自然尺寸 probe 的 replay A 只参与求解；父 composite 选定双轴约束后，只有 replay B 沿最后一条边进入单次提交，并与领域 artifact 一起汇入同一个 `CompileResult`。

1. `layoutChild(child, { kind:'intrinsic' })` 测量子内容的自然尺寸；
2. 父 composite 据 allocation bounds 求解列、行和目标 slot；
3. 用 `constrained.width` / `constrained.height` 分别传入 `bounded` 或 `exact` 轴约束；
4. 用 `context.replay(result, { transforms, clip })` 放置并裁剪选中结果；需要 identity 或嵌套结构时，再用 `context.scope(props, children)` 递归组合。

省略某一轴表示 indefinite；`bounded` 把真实占用 clamp 到有限 `min` / `max` 后生成 slot，`exact` 直接给定 slot 尺寸。两者都不会缩放 child 几何，因此父 solver 仍负责对齐位置与 overflow 策略。

`compile` 还可以返回显式 `allocationBounds`，把它作为 composite 自身的 container box。它让空容器拥有尺寸，也允许后代溢出而不反向撑大父容器；省略时才继续合并最终 children 的 allocation。`context.replay()` 把选中结果转为 output child；replay 只在创建它的同一次 compile、同一个 composite callback 中可用一次，最终发出保存的 primitive、资源、引用、warning 与 artifact，不会第三次展开或布局。

### 编译期局部包装树

布局求解完成后，父 composite 往往还要放置、裁剪或标记 replay。单个 replay 的数值变换与 clip 直接放在 replay wrapper；需要 identity、local namespace、metadata、zIndex 或递归结构时，再用 `context.scope()` 建立 runtime Scope tree。Scope children 可以混合普通 `IRChild`、`context.replay()` 和其它 `context.scope()` 结果：

```ts
compile: (node, context) => {
  const constrained = context.layoutChild(node.child, {
    kind: 'constrained',
    width: { kind: 'exact', size: node.width },
    height: { kind: 'bounded', max: node.height },
  });

  const placed = context.replay(constrained, {
    transforms: [{ kind: 'translate', x: 12, y: 8 }],
    clip: { kind: 'rect', x: 0, y: 0, width: node.width, height: node.height },
  });

  return {
    allocationBounds: { x: 0, y: 0, width: node.width, height: node.height },
    children: [
      context.scope(
        {
          id: 'cell',
          meta: { role: 'cell' },
        },
        [placed],
      ),
    ],
  };
};
```

replay wrapper 的 clip 先在 child 局部坐标中生效，再按 `transforms` 投影；clip 不改变 allocation，只收紧最终提交后 Scene 的 compile visual bounds，不回写此前取得的 `LayoutChildResult.visualBounds`。builder 返回的是不可读取、不可伪造或序列化的 opaque handle；它只存在于当前 `compileToScene()` 的内存 session 中。跨 compile、跨 callback、重复 replay 或伪造 handle 都会报错。Core 最终仍输出既有 Tier 1 Scene、resource 与 occurrence；wrapper 不新增 IR、Scene 或 renderer 合同。

任何需要“测量子内容 → 求解父布局 → 约束子内容 → 放置最终结果”的 Tier 2 composite 都可以复用它。

### 同次类型化产物

布局感知定义可以声明 `artifactSchema` 并从 `compile` 返回 JSON-safe `artifact`。Core 在 `CompileResult.artifacts` 中用 `namespace`、`type` 和 occurrence locator 封装它；locator 由原始 `sourcePath` 与结构化 expansion / output / replay 路径组成，不依赖全局 Map、回调捕获或第二次遍历。宿主因而能从同一次 compile 同时得到 Scene 与领域产物。

`lowerIRToKernel()` 只支持可独立执行的 `expand` 分支。它遇到布局感知 composite 会明确报错，因为正确结果依赖完整 compile 环境。

## 与 Sugar 的区别

|          | Sugar（如 `<Draw>`） | Tier 2 composite                                |
| -------- | -------------------- | ----------------------------------------------- |
| IR 中    | 构建期已展平         | 保留高层节点                                    |
| 下沉时机 | adapter 构建期       | core compile 期                                 |
| 适合     | 可直接映射的便捷写法 | 结构生成，或依赖真实子内容反馈的布局 / 聚合算法 |

## 在 React `<Layout>` 中使用

普通用户只需要把支持嵌入的 domain 组件放进 `<Layout>`。组件所属包负责贡献高层节点与 composite definition，`<Layout>` 再把它们交给同一条 core lowering 管线；core 仍不依赖具体 domain。

如果你在实现 domain adapter、注入 `composites` / `embeddables`，或排查 datasets 汇总与宿主行为，请直接查 [Layout 高级能力与宿主接入](/kernel/components/layout/overview#高级能力与宿主接入)和[扩展运行时](/kernel/reference/runtime/extensions)，概念页不展开 React 静态遍历与聚合细节。
