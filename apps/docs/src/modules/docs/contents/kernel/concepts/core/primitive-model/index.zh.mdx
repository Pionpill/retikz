图元（primitive）是 retikz 里可被绘制和引用的最小单位。**图元模型**描述一个图元在几何上如何被搭起来——从内容、内框、shape，到外接框、boundary 与 anchor——使它能被测量、布局、连接和引用。它是一层抽象概念，不绑定某个具体组件。

Node 是这套图元模型最常用的具体实现。你可以把它想成一个“会被连线识别的盒模型”：`position` 给出节点的语义参考点，文本测量与 `padding` 先形成内框，shape 据此算出视觉外接框，`minimumSize` 再给外接框设下限，boundary 和 anchor 决定路径从哪里接上来。

图里从内到外是这套 Node 的分层：最内是内容盒，往外依次是内框、shape 视觉轮廓、外接框、boundary，最外是 anchor。实际渲染时你通常只会看到橙色 shape；其余几层是编译与连线阶段使用的几何信息。

| 层                       | 由什么决定                                     | 影响什么                                                |
| ------------------------ | ---------------------------------------------- | ------------------------------------------------------- |
| 内容盒<br />content box  | `text` / children / font                       | 文本测量的基础尺寸                                      |
| 内框<br />inner frame    | 文本测量 + `padding`                           | 传给 shape 的基础半轴                                   |
| 形状<br />shape          | `shape.circumscribe` 与 `shape.emit`           | 节点真正画出来的轮廓                                    |
| 外接框<br />bounding box | shape 包围内框后再受 `minimumSize` 约束        | 渲染裁剪的基础；+`margin` 后即布局占位 / viewBox        |
| 连接面<br />boundary     | `boundary`，默认跟随 shape                     | border 锚点（自动连线 / 命名方位 / 角度）贴的连接面形状 |
| 锚点<br />anchor         | Web 方位 / angle / shape-specific / edge point | 精确引用节点上的点                                      |

外接框不含 `margin`。编译器总会用 `margin` 扩大布局 / viewBox 占位，但连接点是否随之外移取决于选中的 boundary 如何解析：rect 驱动的边界会消费扩大的外接框；star / sector 等参数驱动 shape 的默认边界仍按 params 重建真实轮廓。

## 盒模型

一个 Node 像 CSS 盒模型一样，由三层从内到外嵌套的框组成。

- **内容盒**：由 `text` / children 和 `font` 决定，是文本测量出的基础尺寸。
- **内框**：在内容盒外加上 `padding`，得到传给 shape 的基础半轴——对矩形节点来说，它就是 shape 尺寸的起点。
- **外接框下限**：shape 先用 `circumscribe` 包围内框，`minimumSize` 再与这个结果取较大者。它约束的是外接框，不会反向参与 `circumscribe`。
- **外框**：在外接框外再加 `margin`。它不改变视觉 shape，并始终计入布局 / viewBox；连接点是否落在这一圈上由 boundary / anchor 的解析方式决定。

<ComponentPreview files="node-frames" size="md" hideCode />

最内灰块是内容盒，中间虚线是内框（矩形节点的 shape 起点），最外虚线是外框。图中是 rect 驱动的矩形 boundary，因此 `margin` 同时扩大连接面与布局占位；参数驱动 shape 的例外见下文。

内框是后续几何的起点：shape 先拿它计算外接框，再由 `minimumSize` 对结果设下限。空文本节点仍可由 padding 提供内框；需要保证最终占位尺寸时再设置 `minimumSize`。

| 属性      | 改的是                | 结果                                                              |
| --------- | --------------------- | ----------------------------------------------------------------- |
| `padding` | 内容盒到 shape 的距离 | shape 变大，外接框也变大                                          |
| `margin`  | 外接框外的布局留白    | shape 不变；布局占位始终扩大，连接点按 boundary / anchor 路径决定 |

padding 在 `circumscribe` 前扩大内框；`minimumSize` 在其后约束外接框；margin 不动 shape，只扩布局外框，并把使用 rect 几何的连接点外推。三者缺省都不额外改变几何。

## 形状 Shape

shape 不是简单的 CSS border-radius。它是一套几何定义：给定内框半轴和参数后，shape 会回答“我要多大的外接框才能装下自己”，并负责画出最终的视觉轮廓。

| shape 类型   | 尺寸来源                         | 例子                                         |
| ------------ | -------------------------------- | -------------------------------------------- |
| 文本容器形状 | 文字 + padding，经外接框下限约束 | rectangle、circle、ellipse、polygon、diamond |
| 参数驱动形状 | shape params 自己决定几何        | sector、star                                 |

<ComponentPreview files="shapes" size="md" hideCode />

灰块是内容盒、虚线是内框，这五个文本容器形状共享同一个内框，shape 以内框为准画出不同轮廓：rectangle 即内框，其余把它包得更大（circle / diamond 分别是 ellipse / polygon 的 preset）。参数驱动形状（sector / star）的几何来自 params，不走这套内框逻辑；Sector 的等半径状态可以表达开放弧。

文本容器形状更像按钮或 DOM 盒子：文字变长，节点会变大。参数驱动形状更像一个几何 glyph：半径、角度、尖角数量已经定义了大小，文本只是附着在它上面。

用 `defineShape` 扩展 shape 时，要补齐 shape 的几何回答——外接框怎么包住自己、射线打到哪、具名 anchor 在哪、如何 emit 成基础图元——让 Node 在可测量、可连接、可引用、可渲染上和内置 shape 一样。实现细节见 [自定义形状](/kernel/components/shapes/custom-shape)。

## 外层边界 Boundary

外接框（bounding box）和连接面（boundary）都是 shape 之外的一层包围面，但分工不同：外接框管布局与渲染占位，连接面管自动连线贴到哪。默认两者都跟随 shape，只有显式改 `boundary` 时才分开。

<ComponentPreview files="bbox-boundary" size="sm" hideCode />

两个节点是同一个 polygon shape（六边形）、同一个内框（最内虚线）和外接框（灰色虚线矩形），两侧完全相同。左边 `boundary="shape"`（默认），自动连线贴到多边形边缘；右边 `boundary="circle"`，连线改贴到蓝色虚线圆——注意这个圆可以伸出外接框。改 boundary 只挪 border 锚点贴的连接面，不动 shape、内框、外接框，也不动布局占位。

**外接框**不是视觉轮廓本身，而是能包住视觉轮廓的矩形。复杂形状也会先被归约到这个矩形里，后续的 viewBox、布局和渲染裁剪都可以用统一模型处理。少数形状还会提供 `circumscribeOffset`，让 `position` 这个语义参考点和外接框中心分离，例如扇形以圆心定位，但外接框中心偏在扇形一侧。

**连接面**只回答一个问题：路径自动连接到这个 Node 时，端点应该贴到哪一层表面。默认 `boundary="shape"`，自动路径端点会贴到视觉 shape 的边上。你也可以把五角星的连接面改成圆或椭圆，让连线看起来更规整，但这不会改变星形本身，也不会改变它的外接框。

内置的 circle / ellipse boundary 支持两种拟合策略：默认 `fit: 'tight'` 读取视觉 shape 提供的安全连接包络，尽量贴合真实轮廓；`fit: 'bounds'` 则从视觉外接框构造能包住四角的规则连接面。两者都在拟合后应用 `gap`，只改变连接面，不参与布局占位。

这里的 `tight` 不是简单取外接框长半轴：star / polygon 等 shape 会按真实顶点给出安全包络。只有借用未注册为 boundary provider 的普通 shape 名时，才直接把它套在当前视觉外接框上，而不会再次调用它的 `circumscribe`。

| 设置                | 改变什么                                                | 不改变什么                 |
| ------------------- | ------------------------------------------------------- | -------------------------- |
| `shape`             | 视觉轮廓、外接框、shape anchor                          | 节点中心语义               |
| `boundary`          | border 锚点（自动连线 / 命名方位 / 角度）贴的连接面形状 | 节点视觉、外接框、布局占位 |
| 单条边覆盖 boundary | 当前路径端点                                            | 节点默认设置               |

因此，外接框是“渲染 / 视觉包围矩形”（再加 `margin` 即布局占位），连接面更接近“连接用的 hit surface”——都不是“画出来的外壳”。

boundary 决定连接面的形状；`margin` 总是扩大传给连接解析的外接矩形。circle / rectangle 等 rect 驱动 boundary 会随之向外扩，star / sector 等参数驱动 shape 的默认边界则仍按 params 计算。因此 `margin` 是稳定的布局留白，但只有 boundary 消费 rect 尺寸时才同时成为连接留白。

<ComponentPreview files="margin-boundary-gap" size="md" hideCode />

每列从内到外三层：最内灰块是文本区，currentColor 实线是矩形 shape，虚线是连接面，灰点是命名方位锚点。这里的 shape / boundary 都由 rect 驱动，所以 `margin` 会把连接面与锚点推开；右列借用 circle 后只是把连接面改成圆。参数驱动形状与完整 boundary 选项见 [Node 几何](/kernel/components/node/overview)。

## 锚点 Anchor

Anchor 是 Node 暴露给其它图元引用的点。路径、定位和标签都可以通过 anchor 找到节点上的稳定位置。

| anchor 类型  | 例子                                 | 适合用途                 |
| ------------ | ------------------------------------ | ------------------------ |
| 中心点       | `center`                             | 对齐、旋转、放射关系     |
| 方位点       | `top`、`right`、`bottom-left`        | 常规连线和布局           |
| 角度点       | `'A.35'` / `{ id: 'A', anchor: 35 }` | 沿射线找边界交点         |
| shape 专属点 | star 的尖角、sector 的圆弧端点       | 复杂形状的语义连接       |
| 边比例点     | `{ side: 'top', fraction: 0.25 }`    | 表格、泳道、框图边缘定位 |

<ComponentPreview files="anchors" size="lg" hideCode />

上排用矩形说明标准方位、角度与边比例 anchor；下排说明复杂 shape 还可以提供自己的语义点。这里的重点是区分几何所有者，不在概念页枚举每种 shape 的全部名称：

| anchor 家族          | 几何所有者                 | 权威入口                                            |
| -------------------- | -------------------------- | --------------------------------------------------- |
| `center` / 标准方位  | Node 的 shape / boundary   | [Node 几何](/kernel/components/node/overview)       |
| 数字角度             | 选定的 connection boundary | [Path target](/kernel/reference/schema/path#目标点) |
| shape 专属名称       | 对应 shape                 | [Shapes](/kernel/components/shapes)                 |
| `{ side, fraction }` | 视觉 shape 的真实边        | [Node 几何](/kernel/components/node/overview)       |

IR / schema 的标准方位只保留 `top` / `right` / `bottom` / `left` 与四个角点，`center` 独立存在。命名方位优先让 shape / boundary 自己解析，缺失时回退到 AABB；数字角度沿射线命中选定 boundary；shape 专属名称和边比例点始终由视觉 shape 负责。

<Comparison target="tikz" title="锚点命名">

TikZ 使用 `north` / `south` / `east` / `west` 这类 compass 名称。retikz 的 IR / schema 只保存 `top` / `right` / `bottom` / `left` 这套 canonical 名称；如果某个 sugar 支持 TikZ 风格输入，也会先归一后再进入 IR。

</Comparison>

完整命名、各 shape 的专属点和 boundary 例外由 Node / Shapes 页面维护；自定义几何见[自定义形状](/kernel/components/shapes/custom-shape)。这些点如何被另一个图元引用、端点如何在 auto / 锁定间解析，继续看[图元关系](/kernel/concepts/core/primitive-relations)。

## 动手试一试

先编辑内容并输入换行，再切换 rectangle、circle、ellipse、diamond、polygon、star 与 sector，观察同一个 Node 如何更换视觉 shape。前五类会让内容与内边框参与外形尺寸计算；star、sector 则使用演示中预设的几何参数，文字叠加在既定外形上。后两种是 Standard 可选 shape，演示已通过 `<Layout shapes>` 显式注入；普通使用同样需要从 `@retikz/standard/shape` 导入对应 Definition。Sector 将等内外半径解释为开放弧。

接着在 `shape`、`circle`、`rectangle`、`ellipse` 四种 boundary 间切换：circle / ellipse 还可比较 `fit: 'tight'` 与 `fit: 'bounds'`，三种规则连接面都可调整 `gap`。再改变来源角度，观察真实连线落点。最后的 `fill`、`stroke`、`strokeWidth` 只提供最小样式反馈；完整的[文本](/kernel/components/node/text)、[Node](/kernel/components/node/overview)与[Shapes](/kernel/components/shapes) API 继续查对应组件页。
