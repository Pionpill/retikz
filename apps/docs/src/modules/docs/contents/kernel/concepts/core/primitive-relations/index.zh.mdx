[图元模型](/kernel/concepts/core/primitive-model) 负责单个图元的内容、shape、boundary 与 anchor。本页只讨论图元之间的关系：path 引用目标时，端点如何选择，以及多个目标如何组成一条可维护的路线。

## 动态贴边与显式位置

同一条关系可以让端点根据布局自动变化，也可以把端点锁在一个稳定位置：

<ComponentPreview files="relation-dynamic-vs-locked" size="sm" hideCode />

| 模式     | 写法                         | 行为                     |
| -------- | ---------------------------- | ------------------------ |
| 动态贴边 | `'T'` / `{ id: 'T' }`        | 朝相邻 step 自动命中边界 |
| 显式位置 | `'T.top'` / `{ id, anchor }` | 固定到指定 anchor        |

默认优先动态贴边，让流程图、DAG 等关系线随布局变化；只有固定出线侧、对齐或复刻既有版式时才指定 anchor。

### 动态贴边

目标只给 id 时，编译器先看相邻 step 的方向，再从目标中心朝该方向命中 connection boundary。所以下图中同一个目标会按来源位置选择不同端点：

<ComponentPreview files="anchors-auto-attach" size="sm" hideCode />

boundary 决定“线停在哪一层表面”，`margin` 与 shape 如何影响这层几何由[图元模型 · 外层边界](/kernel/concepts/core/primitive-model#外层边界-boundary)统一解释；本页不重复维护盒模型例外。

### 显式位置

指定 anchor 后，端点不再读取相邻 step 的方向。矩形、椭圆使用通用标准 anchor，复杂 shape 还可以提供自己的语义点：

<ComponentPreview files="anchors-explicit" size="sm" hideCode />

概念上只需记住“省略 anchor 是动态，提供 anchor 是固定”。完整 target union、`offset`、角度与边比例写法见 [Path schema · 目标点](/kernel/reference/schema/path#目标点)；标准 anchor、boundary 与各 shape 专属名称见 [Node 几何](/kernel/components/node/overview)和 [Shapes](/kernel/components/shapes)。

## 连线与路由

端点模式决定“连到哪里”，path step 决定“中间怎么走”。下面用同一对端点比较直线、曲线与折线：

<ComponentPreview files="connection-styles" size="xs" hideCode />

| 路线     | 常用写法                 | 适合                   |
| -------- | ------------------------ | ---------------------- |
| 直线     | `['a', 'b']`             | 默认关系线             |
| 正交折线 | `'-\|'` / `'\|-'`        | 流程图、结构图         |
| 曲线     | `{ bend }` / `{ curve }` | 避让、双向边、平滑关系 |

完整 step 与 path kind 参数属于 [Draw](/kernel/components/draw/overview)和 [Path schema](/kernel/reference/schema/path)。关系页只给选择思路，不复制 API 字典。

路径内部可以相对上一段终点移动：`{ relative }` 临时偏移但不推进累计基准，`{ relativeAccumulate }` 偏移后把新终点作为下一段基准。React Sugar 也支持 `'+dx,dy'` / `'++dx,dy'`：

<ComponentPreview files="connection-relative" size="xs" hideCode />

需要稳定路由点时，用 `<Coordinate>` 声明一个可引用但不渲染的位置，再让 path 经过它：

<ComponentPreview files="connection-coordinate" size="xs" hideCode />

实体位置、偏移、between 与 path-relative 的适用范围集中在[定位](/kernel/concepts/basic/position)。

## 分组连接

`<Scope id="cluster">` 会把子树外接框注册为可引用的组边界。外部 path 可以用 `'cluster'` 动态贴边，也可以用 `'cluster.top'` 锁定位置：

<ComponentPreview files="relation-scope" size="sm" hideCode />

图中的淡灰虚线是 cluster 的合成外接框。分组连接仍复用与 Node 相同的 auto / explicit 选择；命名空间、bbox 模式与 transform 行为见 [Scope](/kernel/components/layout/scope)。

## 动手试一试

目标 Node 的视觉 shape 是椭圆，默认 boundary 是矩形。先保持 `anchor="auto"`，拖动来源角度：端点会持续朝来源方向命中目标 boundary。再锁定 `top` / `right` 或数字角度，来源继续移动而目标端点保持不变。`boundary` 选项只覆盖这条边的目标端点；切回“继承矩形”不会修改目标 Node 自己的默认设置。
