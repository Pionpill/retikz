---
title: 定位
description: retikz 用节点引用、相对、偏移、比例与路径相对 target 表达实体之间的位置关系，并规定实体位置和路径目标的引用时序。
---

retikz 使用一组统一的位置表达来描述实体放置与路径目标解析。`<Node>.position` / `<Coordinate>.position` 确定图元中心或引用点；`<Step>.to` / `<Draw>.way` 确定路径连接或经过的目标。

笛卡尔、极坐标、user units 与 viewBox 的完整模型集中在[坐标系](/kernel/concepts/basic/coordinate-system)。本页从“一个位置如何依赖另一个实体”开始，只讲关系型定位与路径 target。

| 任务         | 典型写法                                  | 可用位置                     |
| ------------ | ----------------------------------------- | ---------------------------- |
| 绝对位置     | `[x, y]` / `{ angle, radius }`            | 实体位置、路径目标           |
| 引用图元     | `{ id, anchor? }`                         | 路径目标                     |
| 方向 / 偏移  | `{ direction, of }` / `{ of, offset }`    | 实体位置；偏移也可作路径目标 |
| 两点之间     | `{ between: [A, B], fraction }`           | 实体位置、路径目标           |
| 路径相对移动 | `{ relative }` / `{ relativeAccumulate }` | 仅路径目标                   |

## 节点 id 引用

`<Step>` / `<Draw>` 的 target 还接受**字符串**，表示引用同一 `<Layout>` 内的节点 id。这是 React DSL 的便捷写法；需要指定 anchor、偏移或连接面时，用对象形式 `{ id, anchor?, offset?, boundary? }`：

<ComponentPreview files="positioning-id-ref" size="xs" />

线段的实际起止点由 retikz 自动算——见 [图元关系](/kernel/concepts/core/primitive-relations)。

`<Node>` / `<Coordinate>` 不能直接把 `position` 写成节点 id，因为"把一个实体放在另一个实体中心"通常不是最有用的默认。要表达节点之间的关系，用 `{ direction, of, distance? }`；要表达任意二维偏移，用 `{ of, offset }`。这两种写法把布局意图留在文档里，比提前算好每个绝对坐标更容易维护。

## 相对定位

相对定位用 `{ direction, of, distance? }` 描述"把当前实体放到另一个实体的某个方向"。它适合流程图、概念图、局部排版：读代码时能直接看出 A 在 B 的上方 / 右侧，而不是反推两个绝对坐标的差值。

```tsx
<Node id="a" position={[0, 0]}>A</Node>
<Node id="b" position={{ direction: 'right', of: 'a', distance: 80 }}>B</Node>
```

<ComponentPreview files="positioning-relative" size="md" />

`direction` 接 8 个视觉方向：`top` / `bottom` / `left` / `right` / `top-left` / `top-right` / `bottom-left` / `bottom-right`。省略 `distance` 时走 `<Layout nodeDistance>`，再回退到 `24`。

## 偏移定位

偏移定位用 `{ of, offset }` 表示"先解析一个基准点，再加 `[dx, dy]`"。`of` 可写节点 id、笛卡尔坐标或极坐标；`offset` 永远是二维用户单位偏移。

```tsx
<Node id="a" position={[0, 0]}>A</Node>
<Node id="note" position={{ of: 'a', offset: [40, -24] }}>note</Node>
```

<ComponentPreview files="positioning-offset" size="sm" />

它比相对定位更自由：当你要表达"A 右边 40、上方 24"这类非 8 方向关系时，用偏移定位更直接。

## 比例定位

比例定位取 A 到 B 连线上的比例点：`t = 0` 是 A，`t = 1` 是 B，`t = 0.5` 是中点。它适合在线段中点放标签、把辅助点放在两节点之间，或给 path 的某个 step 直接走到比例点。

```tsx
<Node id="a" position={[0, 0]}>A</Node>
<Node id="b" position={[120, 0]}>B</Node>
<Coordinate id="mid" position={{ between: [{ id: 'a' }, { id: 'b' }], fraction: 0.5 }} />
```

<ComponentPreview files="positioning-between" size="xs" />

`between` 的两个端点是自包含的 absolute target：可用笛卡尔、极坐标、节点 / Coordinate 引用对象（`{ id: 'a' }`）、偏移定位，或继续嵌套 `{ between, fraction }`。它不接受 path-relative target（`relative` / `relativeAccumulate`），因为比例定位必须能独立解析。

## 路径相对 target

路径内部还支持只给 `<Step>.to` / `<Draw>.way` 使用的相对 target：`{ relative: [dx, dy] }` 从上一段终点临时偏移，但不更新累计基准；`{ relativeAccumulate: [dx, dy] }` 偏移后把新终点作为下一段基准。React sugar 里也可写 `'+10,0'` / `'++10,0'`。

```tsx
<Draw way={[[0, 0], { relativeAccumulate: [40, 0] }, { relativeAccumulate: [0, 30] }]} />
```

<ComponentPreview files="positioning-path-relative" size="sm" />

它们只属于 path target，不用于 `<Node>.position` / `<Coordinate>.position`。如果要摆放实体，请用笛卡尔、极坐标、相对定位、偏移定位或比例定位。

## 引用顺序

实体位置与路径目标的解析时机不同：

- `<Node>.position` / `<Coordinate>.position` 中的 `origin`、`of` 和 `between` 会按 IR children 顺序解析，因此被引用实体必须先定义。
- `<Step>.to` / `<Draw>.way` 中的节点或 Coordinate 引用会延迟到当前命名空间的实体完成注册后解析，因此可以引用同一可解析作用域内稍后定义的实体。

实体位置引用无法解析时，编译会报错；路径目标最终仍找不到对应实体时，该路径无法正常输出，并会产生诊断。

```tsx
// ✅ b 引用 a，a 在前
<Node id="a" position={[0, 0]}>A</Node>
<Node id="b" position={{ origin: 'a', angle: 0, radius: 50 }}>B</Node>

// ❌ a 引用 b，b 在 a 之后
<Node id="a" position={{ origin: 'b', angle: 0, radius: 50 }}>A</Node>
<Node id="b" position={[0, 0]}>B</Node>
```

路径引用则可以前置：

```tsx
<Draw way={['a', 'b']} />
<Node id="a" position={[0, 0]}>A</Node>
<Node id="b" position={[120, 0]}>B</Node>
```
