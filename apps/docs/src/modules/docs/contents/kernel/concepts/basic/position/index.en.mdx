title: Positioning
description: retikz expresses relationships through node references, relative, offset, proportional, and path-relative targets, with distinct reference timing for entity positions and paths.
---

retikz uses one set of position expressions for entity placement and path target resolution. `<Node>.position` / `<Coordinate>.position` determine an entity center or reference point; `<Step>.to` / `<Draw>.way` determine where a path connects or passes.

The full model for Cartesian, polar, user units, and viewBox lives in [Coordinate System](/kernel/concepts/basic/coordinate-system). This page starts where one position depends on another entity: relational placement and path targets.

| Task             | Typical form                              | Valid in                                            |
| ---------------- | ----------------------------------------- | --------------------------------------------------- |
| Absolute point   | `[x, y]` / `{ angle, radius }`            | Entity position, path target                        |
| Reference entity | `{ id, anchor? }`                         | Path target                                         |
| Direction/offset | `{ direction, of }` / `{ of, offset }`    | Entity position; offset also works as a path target |
| Between points   | `{ between: [A, B], fraction }`           | Entity position, path target                        |
| Path-relative    | `{ relative }` / `{ relativeAccumulate }` | Path target only                                    |

## Node id reference

`<Step>` / `<Draw>` targets also accept a **string** to reference a node id inside the same `<Layout>`. This is React DSL shorthand; use the object form `{ id, anchor?, offset?, boundary? }` when you need an anchor, offset, or connection-surface override:

<ComponentPreview files="positioning-id-ref" size="xs" />

The actual line endpoints are computed by retikz automatically — see [Primitive Relations](/kernel/concepts/core/primitive-relations).

`<Node>` / `<Coordinate>` do not accept a bare node id as `position`, because "place this entity at another entity's center" is rarely the useful default. Use `{ direction, of, distance? }` for relational placement, or `{ of, offset }` for arbitrary 2D offsets. Both keep layout intent in the document instead of baking every coordinate up front.

## Relative Placement

Relative placement uses `{ direction, of, distance? }` to say "place this entity in a direction from another entity." It is useful for flowcharts, concept maps, and local layout because the code states that B is to the right of A instead of making readers infer it from two absolute coordinates.

```tsx
<Node id="a" position={[0, 0]}>A</Node>
<Node id="b" position={{ direction: 'right', of: 'a', distance: 80 }}>B</Node>
```

<ComponentPreview files="positioning-relative" size="md" />

`direction` accepts 8 visual directions: `top` / `bottom` / `left` / `right` / `top-left` / `top-right` / `bottom-left` / `bottom-right`. When `distance` is omitted, retikz uses `<Layout nodeDistance>`, then falls back to `24`.

## Offset Placement

Offset placement uses `{ of, offset }`: resolve a base point first, then add `[dx, dy]`. `of` may be a node id, Cartesian point, or polar position; `offset` is always a 2D user-unit offset.

```tsx
<Node id="a" position={[0, 0]}>A</Node>
<Node id="note" position={{ of: 'a', offset: [40, -24] }}>note</Node>
```

<ComponentPreview files="positioning-offset" size="sm" />

It is more flexible than directional placement. When you want "40 units right and 24 units up from A" rather than one of the 8 named directions, offset placement is the direct form.

## Proportional Placement

Proportional placement takes a point along A → B: `t = 0` is A, `t = 1` is B, and `t = 0.5` is the midpoint. Use it for mid-line labels, helper points between two nodes, or a path step that should land at a proportional point.

```tsx
<Node id="a" position={[0, 0]}>A</Node>
<Node id="b" position={[120, 0]}>B</Node>
<Coordinate id="mid" position={{ between: [{ id: 'a' }, { id: 'b' }], fraction: 0.5 }} />
```

<ComponentPreview files="positioning-between" size="xs" />

The two `between` endpoints are self-contained absolute targets: Cartesian, polar, node / Coordinate reference objects (`{ id: 'a' }`), offset placement, or nested `{ between, fraction }`. They do not accept path-relative targets (`relative` / `relativeAccumulate`) because proportional placement must resolve independently.

## Path-Relative Targets

Paths also support relative targets that are only valid in `<Step>.to` / `<Draw>.way`: `{ relative: [dx, dy] }` offsets from the previous segment endpoint without updating the accumulated base; `{ relativeAccumulate: [dx, dy] }` offsets and then uses the new endpoint as the next base. React sugar may also use `'+10,0'` / `'++10,0'`.

```tsx
<Draw way={[[0, 0], { relativeAccumulate: [40, 0] }, { relativeAccumulate: [0, 30] }]} />
```

<ComponentPreview files="positioning-path-relative" size="sm" />

These forms are path targets only; they are not valid for `<Node>.position` / `<Coordinate>.position`. For entity placement, use Cartesian, polar, relative placement, offset placement, or proportional placement.

## Reference order

Entity positions and path targets resolve at different times:

- `origin`, `of`, and `between` inside `<Node>.position` / `<Coordinate>.position` resolve in IR children order, so the referenced entity must be defined first.
- Node or Coordinate references inside `<Step>.to` / `<Draw>.way` are deferred until entities in the current namespace have been registered, so they may reference an entity defined later in the same resolvable scope.

Compilation fails when an entity position reference cannot resolve. If a path target still cannot find its entity during deferred resolution, that path cannot be emitted normally and produces a diagnostic.

```tsx
// ✅ b references a, a defined first
<Node id="a" position={[0, 0]}>A</Node>
<Node id="b" position={{ origin: 'a', angle: 0, radius: 50 }}>B</Node>

// ❌ a references b, but b is after a
<Node id="a" position={{ origin: 'b', angle: 0, radius: 50 }}>A</Node>
<Node id="b" position={[0, 0]}>B</Node>
```

A path reference may appear first:

```tsx
<Draw way={['a', 'b']} />
<Node id="a" position={[0, 0]}>A</Node>
<Node id="b" position={[120, 0]}>B</Node>
```
