Circles and ellipses are retikz geometric shapes with two faces: draw an outline with `<Circle>` / `<Ellipse>` (sugar), or bound a node with `shape="circle"` / `"ellipse"`. See [Shapes](/kernel/components/shapes) for the full definition. Reach for sugar to draw a line, and for `<Node shape>` to get a connectable, labelable node.

## As a Path shape (sugar)

`<Circle>` / `<Ellipse>` draw a circle / ellipse outline at a position, expanding to an underlying `<Path>`. They fit cases where you know the center and radius, or only have a box.

### Usage

```tsx
import { Circle, Ellipse } from '@retikz/react';
```

```tsx
<Circle center={[0, 0]} radius={32} fill="none" />
<Ellipse center={[0, 0]} radius={{ x: 48, y: 28 }} fill="none" />
```

### Examples

The common form is `center + radius`. If you already have a rectangular area, you can also use `corner1 + corner2` or `box`.

| Form                         | Best for                                                   |
| ---------------------------- | ---------------------------------------------------------- |
| `{ center, radius }`         | Known center and radius                                    |
| `{ center, diameter }`       | Known diameter                                             |
| `{ from, to }`               | Diameter endpoints                                         |
| `{ corner1, corner2 }`       | Fit inside a box                                           |
| `{ box }`                    | Describe the box with `x/y/origin + width + height`        |
| + `fit="contain" \| "cover"` | Fit the circle inside or outside the box                   |
| + `inset` / `outset`         | Shrink or expand the box before fitting                    |
| + angles + `closed="sector"` | Draw a partial circle whose arc ends connect to the center |

Ellipse works like Circle, but the radius is split into `radius: { x, y }`. It also supports `corner1 + corner2` and `box`.

| Form                               | Best for                                                    |
| ---------------------------------- | ----------------------------------------------------------- |
| `{ center, radius }`               | Known center and radii                                      |
| `{ center, diameterX, diameterY }` | Known diameters                                             |
| `{ corner1, corner2 }`             | Fit inside a box                                            |
| `{ box }`                          | Describe the box with `x/y/origin + width + height`         |
| + `inset` / `outset`               | Shrink or expand the box before fitting                     |
| + angles + `closed="sector"`       | Draw a partial ellipse whose arc ends connect to the center |

### API Reference

| Component   | Combination                                                              | Meaning                                                       |
| ----------- | ------------------------------------------------------------------------ | ------------------------------------------------------------- |
| `<Circle>`  | `center` + `radius`                                                      | Circle from center and radius                                 |
|             | `center` + `diameter`                                                    | Circle from center and diameter                               |
|             | `from` + `to`                                                            | Circle from two points (diameter endpoints)                   |
|             | `corner1` + `corner2`                                                    | Largest circle inscribed in the box                           |
|             | `box`                                                                    | Circle from a box, with `fit` / `inset` / `outset`            |
|             | + `fit?`                                                                 | `contain` uses the shorter side, `cover` uses the longer side |
|             | + `inset?` / `outset?`                                                   | Shrink or expand the box before fitting                       |
|             | + angles (`startAngle` / `endAngle` / `sweepAngle`, any two) + `closed?` | Partial circle: `chord` / `sector` / `open`                   |
| `<Ellipse>` | `center` + `radius`                                                      | Ellipse from center and two radii                             |
|             | `center` + `diameterX` + `diameterY`                                     | Ellipse from center and two diameters                         |
|             | `corner1` + `corner2`                                                    | Ellipse inscribed in the box                                  |
|             | `box`                                                                    | Ellipse from a box, with `inset` / `outset`                   |
|             | + `inset?` / `outset?`                                                   | Shrink or expand the box before fitting                       |
|             | + angles + `closed?`                                                     | Partial ellipse: `chord` / `sector` / `open`                  |

These shape sugars also forward the shared Path props, including `stroke`, `fill`, `opacity`, `animations`, and `onClick`. See [Path](/kernel/components/draw/path) for the full list and [Hydration](/kernel/packages/render/render-hydration) for how events are attached after rendering.

## As a node shape

When you need a circular / elliptical node rather than a line (to hold text, to be referenced by a connection), set `shape` on `<Node>`.

### Usage

```tsx
import { Node } from '@retikz/react';
```

```tsx
<Node shape="circle">label</Node>
<Node shape="ellipse">label</Node>
```

### Examples

Switch between `circle` and `ellipse` in the playground: the former is the isotropic `circumscribe:'equal'` preset, while the latter defaults to circumscribing "text + padding" by scaling each axis by √2. Adjust the orbit angle and distance to move the source; keep automatic clipping or choose a named or numeric anchor to compare endpoint placement on both boundaries.

<ComponentPreview files="node-connection-playground" size="sm" />

The center and 8 directional anchors (`center` / `top` …) still apply. See [Node](/kernel/components/node/overview) for shared props such as `position` / `fill` / `padding` / `label`.

### API Reference

| `shape`                                     | Boundary                                                                          | Parameters                                                                                                                |
| ------------------------------------------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `"circle"`                                  | Circle circumscribing the text (= the `circumscribe:'equal'` preset of `ellipse`) | None                                                                                                                      |
| `"ellipse"` or `{ type:'ellipse', params }` | Circumscribed ellipse                                                             | `circumscribe?`: `'proportional'` (default, each axis × √2) / `'equal'` (isotropic, radius = half the inner box diagonal) |

### How sugar becomes a Path

The upper route preserves a `Circle center` target, so a node id, polar point, or `[x, y]` coordinate can resolve later during Path compilation. The lower route must compute a center and radii in the React adapter first, so it accepts literal `[x, y]` geometry only:

<ComponentPreview files="circle-ellipse-sugar-flow" size="md" hideCode />

`Circle` from / corner / box forms and every `Ellipse` form take the lower route. Both routes expand to an equivalent `<Path>` plus a `circlePath` / `ellipsePath` Step. With angles present, `closed` then chooses a chord (`chord`, the default), a return to the center (`sector`), or an open arc (`open`).

### How Node gets its connection boundary

`<Node>` combines measured text and `padding` into a content box, then asks the shape definition to compute a visible boundary around that inner box. Both panels below start with the same content box and change only the circumscription policy:

<ComponentPreview files="circle-ellipse-circumscription" size="md" hideCode />

The default `ellipse` multiplies each half-axis by √2. During compilation, `circle` resolves to `ellipse + circumscribe:'equal'`, using the content-box half-diagonal as one shared radius. The same resolved geometry emits the visible ellipse primitive and provides anchors plus the connection boundary, so `<Draw>` / `<Path>` endpoints snap to the outer contour.
