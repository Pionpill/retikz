---

接着[分层](/kernel/components/design/layers)，这里区分“写得更方便”和“增加新的绘图能力”。语法糖（Sugar）改变书写方式，展开后仍使用同一套基础模型。

语法糖是一种通用设计，不是 Kernel 独有的层级；上层包也有简化自身模型写法的语法糖。它可以展开为所属包的领域 IR，不必直接展开为 Kernel 图元。本文以 Kernel 为例，讨论这种设计的等价性与边界。

广义上，语法糖也包括更方便的值表达：字号档位 `sm`、`base`、`lg` 最终求值为数值字号，极坐标最终转换为笛卡尔坐标。相对于最终绘制所需的基础值，它们同样简化了作者的表达。

但“最终会转换”不等于“不是 IR 的一等公民”：字号档位和极坐标都是 Core IR 正式支持、可持久化的表示，在编译时求值。下文的 Kernel / Sugar 对照与展开图特指构建 IR 时消除的组件糖和作者侧简写，不涵盖所有广义语法糖。

## Kernel 与 Sugar

| 层     | 例子                                                                     | 是否直接进 IR | 说明                      |
| ------ | ------------------------------------------------------------------------ | ------------- | ------------------------- |
| Kernel | `<Layout>` / `<Scope>` / `<Node>` / `<Coordinate>` / `<Path>` / `<Step>` | 是            | 与 IR 节点一一对应        |
| Sugar  | `<Draw way={...}>`、`DrawWay.Cycle`、相对坐标字符串                      | 否            | adapter 同步展开为 Kernel |

Sugar 不引入新能力。能用 `<Draw>` 画出来的图，也能用 `<Path>` + `<Step>` 手写出来。下面两段编译结果完全一致：

```tsx
// Sugar：一行 way 数组
<Draw way={['a', 'b']} arrow="->" />
```

```tsx
// Kernel：先移动，再连线
<Path arrow="->">
  <Step kind="move" to="a" />
  <Step to="b" />
</Path>
```

## 选择建议

| 场景                                     | 推荐                |
| ---------------------------------------- | ------------------- |
| 普通连线、流程图边、带箭头路径           | `<Draw>`            |
| 需要逐段控制 move / line / cycle / curve | `<Path>` + `<Step>` |
| 需要最接近 IR 的测试或转换器输出         | Kernel              |
| 需要持久化、AI 生成或局部修改图          | IR                  |

Sugar 的展开逻辑由 builder 同步调用，不能依赖 React hooks 或异步状态。完整 IR schema 从 [结构参考](/kernel/reference/schema) 进入；根声明的字段见 [IRScene](/kernel/reference/schema/scene)；它不是编译后的 Scene。

## 与复合的区别

Composite 的高层节点保留在编译前的 IR 中，可以随 IR 一起持久化；编译时才展开为基础实体。保存高层意图指保存这份输入 IR，而不是把编译后的 Scene 当作原始模型。

React 组件不一定是语法糖；Scope 也不是语法糖，因为它在 IR 中保留分组。判断依据不是写成了什么组件，而是构建后是否仍有独立的高层节点。

| 区别     | 语法糖       | Composite    |
| -------- | ------------ | ------------ |
| 保存结果 | 基础表达     | 高层意图     |
| 展开时机 | 构建 IR 时   | 编译 IR 时   |
| 适用任务 | 简化已有写法 | 生成领域结构 |

需要把“这是一张图表”作为数据保存时，使用[复合](/kernel/components/design/composite)；只是把路径写短时，使用语法糖。二者最终都复用基础几何与渲染能力，不另造后端语义。

## Kernel 语法糖列表

Kernel 通过 `@retikz/react` 提供以下语法糖组件；这里只列用途，具体写法见对应组件页。

| 组件                                                | 用途                               |
| --------------------------------------------------- | ---------------------------------- |
| [Draw](/kernel/components/path/usage)               | 将简写路径展开为 Path 与 Step      |
| [EdgeLabel](/kernel/components/path/step)           | 将子元素写法转换为 Step 的标签配置 |
| [Circle、Ellipse](/library/standard/circle-ellipse) | 圆与椭圆路径                       |
| [Arc、Sector](/library/standard/circle-ellipse)     | 圆弧、椭圆弧与扇形路径             |

Circle、Ellipse 等形状已属于 [Standard composite](/library/standard/circle-ellipse)，在 IR 中保留形状意图。`DrawWay.Cycle`、相对坐标字符串仍属于 Kernel 作者简写。
