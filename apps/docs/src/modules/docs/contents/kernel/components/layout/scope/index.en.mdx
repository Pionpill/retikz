## Usage

```tsx
import { Scope } from '@retikz/react';
```

```tsx
<Scope transforms={[{ kind: 'translate', x: 50, y: 0 }]}>{/* Node / Path / Coordinate / nested Scope */}</Scope>
```

If the scope subtree produces any primitive, or the scope carries one of `transforms` / `id` / `clip` → a `GroupPrim` is emitted; otherwise (no subtree output and none of those three) it is pruned and emits no Scene primitive, with no empty-container overhead. A scope that only sets style defaults / `meta` but whose subtree produces nothing is pruned too.

### When to use Scope

When your design has a "grouping" concept — a set of nodes / paths that conceptually belong to the same sub-diagram, need to be transformed as a unit, or need to be referenced / positioned as a whole from outside via `scope.id`.

On a first read, remember three common jobs:

| Goal                                               | Use                                                                       |
| -------------------------------------------------- | ------------------------------------------------------------------------- |
| Move / rotate / scale a group of primitives        | `transforms`                                                              |
| Give a group shared default styling                | `color` / `nodeDefault` / `pathDefault` / `labelDefault` / `arrowDefault` |
| Let external paths connect to the group's boundary | `id`                                                                      |

## Composition

`<Scope>` children can be `<Node>`, `<Coordinate>`, `<Path>`, or nested `<Scope>`. Scope does not draw a shape by itself; it becomes a Scene group when its subtree produces any primitive, or when it carries one of `transforms` / `id` / `clip` (a scope with only style defaults / `meta` and no subtree output is pruned).

Think of Scope as a "subdiagram container", not a plain div. Use it for geometry, local coordinates, and whole-group references; if you only want cleaner JSX, split the code with ordinary React components first.

### The 7 transform variants

The 5 translate variants mirror the 5 `<Node position>` shapes (Cartesian / polar / direction-relative / offset / proportional between two endpoints) one-to-one.

| kind                | Fields                         | Semantics                                                                                                                          |
| ------------------- | ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------- |
| `translate`         | `{ x, y }`                     | Cartesian translation in user units                                                                                                |
| `polar-translate`   | `{ origin?, angle, radius }`   | Polar translation; `origin` accepts `id` / `[x, y]` / `PolarPosition`; defaults to origin point                                    |
| `at-translate`      | `{ direction, of, distance? }` | Place scope at `distance` from referent node along `direction`; `distance` defaults to `<Layout nodeDistance>`                     |
| `offset-translate`  | `{ of, offset? }`              | Scope origin = referent global position + `[dx, dy]`; `offset` defaults to `[0, 0]`                                                |
| `between-translate` | `{ between, fraction }`        | Scope origin = proportional point between two endpoints; endpoints support coordinates / node references / offset / nested between |
| `rotate`            | `{ degrees, cx?, cy? }`        | Rotate by degrees; `cx/cy` default to scope local origin                                                                           |
| `scale`             | `{ x, y? }`                    | Scale; `y` defaults to `x` (uniform)                                                                                               |

Array order is application order — the 0-th entry is the outermost (applied last to the local point) and the last entry is the innermost (applied first), matching SVG transform-list semantics. `transforms: [translate, rotate]` is equivalent to SVG `transform="translate(...) rotate(...)"`: rotate applies first, translate last; see [How transforms and relative positions reach global space](#how-transforms-and-relative-positions-reach-global-space) for compile flattening and lowering.

<Comparison target="tikz" title="Scope mapping">

`<Scope transforms={[{ kind: 'translate', x: 50, y: 0 }]}>...</Scope>` maps to TikZ `\begin{scope}[shift={(50,0)}] ... \end{scope}`: a local transform is pushed at the start of the subdiagram and popped at the end. TikZ stacks CM in the order options appear; retikz applies `transforms` in array index order, reusing the SVG / Scene convention.

</Comparison>

#### Recipe: orbit + self-rotation facing the center

A bare `polar-translate` only moves the scope's origin — it does **not** rotate the local frame, so animating its angle keeps the scope content's orientation fixed ("like a satellite drifting along the orbit"). To make the scope also self-rotate so its front always faces the center ("tidal lock"), chain a `rotate(angle + 180)`:

<ComponentPreview files="scope-orbit-facing-hub" size="md" />

Chain application order: in `[t0, t1]` the **last** element is applied first (innermost), so `rotate` runs first to align local +x toward hub, then `polar-translate` pushes the origin to the orbital position. The `+ 180` flips scope's +x from "pointing outward" to "pointing at hub"; drop it to face outward (front away from center).

Append `.<anchor>` / `.<deg>` to the id for the node's visual border point (computed on the global rect with accumulated rotate / scale):

<ComponentPreview files="scope-anchor-cross" size="sm" />

Note that Web anchors (`top` / `bottom-left`, the 8 directions) resolve on the node's **bounding box (AABB)** by default, not the shape outline — so on the circular `hub`, `bottom-left` lands at the bounding box's bottom-left corner, **outside** the circle; only the 4 edge midpoints (`top` / `right` / `bottom` / `left`) actually sit on the circle. Compass names such as `north` / `south-west` remain accepted input aliases.

### Style inheritance

A scope doubles as a style-default anchor, exposing three style surfaces to its children: a **master color `color`** plus shared sub-fields that cascade to every element; **four typed defaults** `nodeDefault` / `pathDefault` / `labelDefault` / `arrowDefault` dispatched by element type, flat and independent; and **`resetStyle`** to cut outer inheritance.

#### Master color cascade

`<Scope color>` cascades the current color to every inner element — node border / text, path stroke / arrow / edge label all default to it; individual fields (`stroke` / `fill` / `textColor`) override the master when set explicitly:

<ComponentPreview files="scope-style-cascade" size="xs" />

The master color also tints node `fill`; the anchor nodes top set `fill="white"` to cut that fill so their text stays readable. What follows the color is the **master `color`**, not `stroke` — `<Path color>` colors the label / arrow too, while `<Path stroke>` only paints the line and leaves the label unchanged.

#### Typed defaults

`nodeDefault` / `pathDefault` / `labelDefault` / `arrowDefault` each attach defaults to one element family, flat and independent. `nodeDefault` carries node-only fields like shape / spacing (a bare `color` can't reach `shape` — use `nodeDefault`); `pathDefault` applies to Path and passes its shared geometry style fields to Ribbon; arrows go through the separate `arrowDefault`, so `pathDefault` excludes them:

<ComponentPreview files="scope-style-typed-defaults" size="xs" />

#### resetStyle inheritance barrier

`resetStyle` cuts the outer scope's inheritance (master-color cascade + typed defaults) back to the built-in baseline; the scope's own values and inner scopes still apply. `true` cuts all; pass a channel array (`['node' | 'path' | 'label' | 'arrow']`) to cut per type:

<ComponentPreview files="scope-style-reset" size="xs" />

`resetStyle` only cuts the scope inheritance, **not the structural relation between an element and its host** — labels / arrows still follow their owning path / node's resolved color: `resetStyle={['label']}` only ignores the outer `labelDefault`, the label still follows its line. See [How styles resolve field by field](#how-styles-resolve-field-by-field) for per-field priority, presence-based fallback, and inheritance barriers.

<Comparison target="tikz" title="Style inheritance mapping">

The master `color` maps to TikZ `color=` (sets the current color; draw / fill / text follow); `nodeDefault` / `pathDefault` / `labelDefault` / `arrowDefault` map to `every node` / `every path` etc. `.style`. Difference: retikz nesting is **per-field merge** (≈ TikZ `.append style`), not a literal `.style=` whole replacement.

</Comparison>

### Stacking order (zIndex)

`zIndex` positions the **whole scope** (the `GroupPrim` it compiles to) among its siblings in the parent layer; it **does not affect the relative stacking of children inside the scope**. The two node clusters bottom overlap and are declared A-then-B (group B on top by default); setting `zIndex={1}` on the earlier A group lifts the entire group top B:

<ComponentPreview files="scope-z-index" size="sm" />

### Scope boundary polymorphism

`boundingShape` makes the scope.id handle take an envelope of the given shape instead of the default axis-aligned rectangle (AABB). Omitted / `'rectangle'` is unchanged; `'circle'` takes the **minimal enclosing circle** of the subtree point set — `cluster.<anchor>` / `cluster.<deg>` and connecting endpoints all land on the **circle**, which suits round / polar panels:

<ComponentPreview files="scope-bounding-shape" size="sm" />

`boundingShape` is a controlled enum: only `'rectangle'` (default) and `'circle'` are accepted — the schema rejects any other value at parse time. `'polygon'` / `'ellipse'` are deferred because each needs its own minimal-enclosing algorithm; this is intentionally a closed set rather than the open shape reference Node `shape` / `boundary` use.

### Clipping

`<Scope clip={...}>` clips every child of the scope to a region — inside is visible, outside is cut away. Built-in clips support `rect` / `circle` / `ellipse` / `polygon` / `path` / `compound`, and [Custom Clips](/kernel/components/extend/clip-registry) can register additional `kind` values. Coordinates are scope-local:

```tsx
<Scope clip={{ kind: 'circle', cx: 0, cy: 0, r: 60 }}>{/* children */}</Scope>
```

### How transforms and relative positions reach global space

The upper row reduces 7 IR transform variants to renderer-ready `translate` / `rotate` / `scale`. The lower row shows relative positioning using that same scope chain to travel between global and local space.

<ComponentPreview files="scope-coordinate-flow" size="sm" hideCode />

The `transforms` list follows SVG ordering. Relative positioning follows `global referent → inverse into the current local frame → add the relative part → project back to global`. Rotate / scale therefore changes the relative part's visual direction or length, while translation alone does not.

Inside a transformed scope, path endpoints are already global before emit, so the path is hoisted to the top level to avoid applying the transform twice. Consequently, cross-frame z-order cannot fully preserve IR order, and the scope's clip does not affect that path.

### How namespaces and id conflicts are handled

`localNamespace` decides whether a frame is added. Lookup always starts at the current frame and proceeds outward only after a miss. Register writes only to the current frame and takes the warning branch when that frame already contains the id.

<ComponentPreview files="scope-namespace-resolution" size="md" hideCode />

By default, a scope adds no boundary, so child ids enter the existing frame. With `localNamespace`, inner code can still see outer ids; a same-named inner id shadows without warning, and the outer id becomes visible again after the frame is popped.

Duplicate ids in one frame emit `DUPLICATE_NODE_ID` for each overwrite; compile continues and keeps the later definition. `scope.id` is registered in the parent before the child frame is pushed, so it always remains the scope's externally visible handle.

### How styles resolve field by field

Left to right is the fallback order for one style field: resolution continues only when the current source does not provide a value. Within one source, an explicit field wins over that source's expanded `color`.

<ComponentPreview files="scope-style-resolution" size="xs" hideCode />

Resolution checks field presence, so explicit `none` / `0` / `false` all stop fallback at the current layer. `resetStyle` cuts only outer-scope inheritance for the selected channels; the current scope, explicit element values, and built-in defaults still participate.

Labels and arrows retain the host color axis. For example, after resetting arrow defaults, an arrow can still follow its resolved path color instead of becoming an isolated style island.

### How scope.id bounds and clip enter Scene

The upper row turns the scope subtree into a referenceable synthetic layout. The lower row turns renderer-agnostic clip IR into a Scene resource plus a group reference. Both chains stop at compile's boundary; adapters perform the actual drawing.

<ComponentPreview files="scope-boundary-clip" size="xs" hideCode />

`scope.id` collects node, coordinate, and nested-scope layouts, but not path routing. By default, global corners produce an axis-aligned AABB; `boundingShape="circle"` uses a minimal enclosing circle; an empty scope becomes a 0×0 handle at the projected local origin.

The clip provider first resolves a JSON-serializable `ClipShape`; the registry then deduplicates shapes and assigns a stable `clipRef`. SVG materializes `<clipPath>`, while Canvas clips from the same Scene resource. The hoisted path described earlier is outside the group's children and therefore outside that group's clip.

## API Reference

| Prop         | Type                         | Default | Description                                                                                                                                                                                                                                                                                 |
| ------------ | ---------------------------- | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `transforms` | `Array<Transform>`           | —       | Local transform list, 7 variants; applied in array order (0-th outermost, last innermost, matching SVG transform-list); see [How transforms and relative positions reach global space](#how-transforms-and-relative-positions-reach-global-space) for flattening and lowering               |
| `children`   | `ReactNode`                  | —       | Scope children: `<Node>` / `<Path>` / `<Coordinate>` / nested `<Scope>`                                                                                                                                                                                                                     |
| `meta`       | `Record<string, JSON value>` | —       | Provenance metadata, passed through verbatim onto the `GroupPrim` this scope emits; ignored by renderers, never part of layout, and **not propagated to children**. Typically injected by a higher-level lowering (e.g. plot) to tag the series / layer. Must be a JSON-serializable object |
| `animations` | `Array<AnimationTrack>`      | —       | Timeline animation tracks applied to the scope as a whole (its GroupPrim); not propagated to children, not part of layout. See [Animation](/kernel/components/effects/animation)                                                                                                            |

### References and positioning

| Prop             | Type      | Default | Description                                                                                                                                                                                                                                                                                                                                                             |
| ---------------- | --------- | ------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`             | `string`  | —       | Optional scope reference id; when set, the **axis-aligned global bounding box** of all child layouts is registered as a synthetic rectangle layout into the **parent frame**; external code can reference it as `'X'` / `'X.<anchor>'` / `'X.<deg>'`; see [How scope.id bounds and clip enter Scene](#how-scopeid-bounds-and-clip-enter-scene) for envelope computation |
| `localNamespace` | `boolean` | `false` | Whether to create a local namespace: `true` pushes a child frame and isolates child ids from the outside; see [How namespaces and id conflicts are handled](#how-namespaces-and-id-conflicts-are-handled)                                                                                                                                                               |

See [Scope clipping](/kernel/components/layout/scope) for the `scope.id` envelope and `boundingShape`.
