---
title: Scope
description: "Scope is Kernel's local-context container: a group shares coordinate transforms, style defaults, namespaces, group references, and clipping without gaining drawing or automatic-layout behavior."
---

`<Scope>` places a group of children in one local context. It does not draw a new primitive or calculate plot / table layout; it controls how the group transforms, aligns by its own envelope, can be referenced, and enters Scene.

Treat Scope as a _sub-figure boundary_. Use it only when the group genuinely shares geometry or runtime semantics. For JSX organization alone, extract an ordinary React component.

## Usage

```tsx
import { Scope } from '@retikz/react';
```

```tsx
<Scope id="cluster" transforms={[{ kind: 'translate', x: 80, y: 0 }]}>
  {/* Node / Path / Coordinate / nested Scope */}
</Scope>
```

### When to use Scope

| Task                        | Entry point            | Scope stops at                    |
| --------------------------- | ---------------------- | --------------------------------- |
| Transform a subfigure       | `transforms`           | It does not place raw children    |
| Align a subfigure           | `placement`            | Only completed targets are seen   |
| Reference a group           | `id` + `boundingShape` | Path routes do not enter bounds   |
| Isolate reusable ids        | `localNamespace`       | `scope.id` stays in the parent    |
| Switch a local domain theme | `theme`                | Core primitives are not recolored |
| Share defaults              | `color` / `*Default`   | Explicit element values win       |
| Limit visibility            | `clip`                 | No renderer-specific semantics    |
| Move a whole stack          | `zIndex`               | Child order stays unchanged       |

### Transform inputs

Five translation forms mirror Node's relative-position model; `rotate` and `scale` set the local axes and scale. Array order follows an SVG transform list, so the last item acts on a local point first.

| kind                | Key fields                     | Effect                            |
| ------------------- | ------------------------------ | --------------------------------- |
| `translate`         | `x`, `y`                       | Fixed Cartesian translation       |
| `polar-translate`   | `origin?`, `angle`, `radius`   | Polar placement from an origin    |
| `at-translate`      | `direction`, `of`, `distance?` | Place in a referent direction     |
| `offset-translate`  | `of`, `offset?`                | Add a local offset to a referent  |
| `between-translate` | `between`, `fraction`          | Interpolate between two endpoints |
| `rotate`            | `degrees`, `pivot?`            | Rotate around a Scope self point  |
| `scale`             | `x`, `y?`, `pivot?`            | Scale around a Scope self point   |

## Examples

### Local coordinates

`O` / `T` are fixed referents outside the Scope, while `q` provides its intrinsic envelope. The panel selects one of seven transforms and independently toggles `placement` in every mode; `placement` is not a transform kind, but the outer placement applied after transforms.

<ComponentPreview

  caption="Square q is the only envelope subject; the small dot only marks the local origin. Self placement is off by default. When enabled, choose O or T as the placement target; selfAnchor locks the square's selected anchor to it. Final placement then cancels the five translate-only transforms, so the panel hides their ineffective transform referent."
/>

`placement.target` accepts only a parent-frame `[x, y]` or a previously completed `{ id, anchor?, offset? }`. `selfAnchor` defaults to `center` and also accepts standard anchors, numeric angles, `{ side, fraction }`, `origin`, or an explicit local point.

`rotate.pivot` and `scale.pivot` use the same self-point vocabulary and default to `origin`. A pivot reads the intrinsic envelope before placement, so moving a Scope cannot feed back into its rotation or scale center. Other relative directions remain local: rotating Scope also rotates the visual direction of `right` with the axes.

### Local Theme

`<Scope theme>` writes sparse `style` / `mode` selectors to `IRScope.theme` and affects descendant composites only. Fields inherit independently: `{ mode: ThemeMode.Dark }` changes the light/dark environment while retaining the outer `style`. During compilation, Core regenerates shared colors through the current style registry; an unregistered style fails immediately. See [Layout: Inherited Theme](/kernel/components/layout/overview#inherited-theme) for the complete example.

Theme and style defaults are independent channels. `resetStyle` does not reset Theme, and Theme does not fill Node or Path colors. Omitting `style` uses the owning package's default baseline; within a nested `Scope`, omitting `style` inherits the outer style and cannot reset to that baseline.

### Style defaults

Scope also exposes `color`, shared graphic state, and `nodeDefault` / `pathDefault` / `labelDefault` / `arrowDefault`. Values cascade per field, explicit element values win, and `resetStyle` cuts only selected outer channels.

Style is a supporting responsibility and does not alter local coordinates, references, or clipping. Consult the API below for color, stroke, and opacity fields rather than creating extra Scopes for visual variants.

<ComponentAlert
  type="tip"
  title="Shared defaults also reduce configuration size"
  description="Putting genuinely shared local styles on Scope avoids repeating the same fields on every child, often reducing both configuration objects and persisted JSON substantially. Tier 2 packages such as Plot also centralize series or layer styles as Scope defaults during lowering to keep generated IR compact."
/>

## How it works

  type="tip"
  title="Optional for everyday use"
  description="Return when you hit transform projection, id conflicts, envelope, or clipping edge cases."
/>

This section covers only Scope behavior visible to users. See [Architecture](/kernel/concepts/design/principles) for the complete JSX → IR → Scene pipeline.

### Transforms and relative positions

Scope first completes intrinsic child layout and its rectangle / circle envelope, resolves pivots on that envelope, lowers transforms, and finally computes the outermost `placement` translation. Index 0 is the outer transform and the last item acts first; placement is prepended at index 0 and therefore acts last.

<ComponentPreview files="scope-coordinate-flow" size="sm" hideCode />

Existing transforms that do not depend on the envelope retain the global referent → inverse-project → add relative value → project-to-global behavior. Anchor pivots resolve only after the intrinsic envelope is complete. One final chain drives Group output, namespace layouts, layout observers, and automatic viewBox geometry without baking own transforms into children twice.

A zero scale remains legal as a purely visual transform. Any operation that must inverse-project across that chain throws `non-invertible scope transform`. A Scope-placement NodeTarget sees only completed Nodes, Coordinates, or Scopes before the current traversal point; forward, self, descendant, and unresolved Scope-placeholder references fail loudly.

### Namespaces and id conflicts

A default Scope reuses the current namespace frame. Only `localNamespace` creates a frame; lookup returns the first inside-out match, while registration writes only to the current frame.

<ComponentPreview files="scope-namespace-resolution" size="md" hideCode />

Equal ids in different frames are valid shadowing. A duplicate in one frame emits `DUPLICATE_NODE_ID` and keeps the later definition. `scope.id` registers in the parent before the child frame is entered, so the group handle remains externally visible.

### Group handles and Scene output

`scope.id` and `clip` follow separate paths: one summarizes child layouts as a reference handle, while the other resolves a JSON clip spec into a Scene resource. Both stop at the Core compile boundary.

<ComponentPreview files="scope-boundary-clip" size="sm" hideCode />

The Scope envelope collects node, coordinate, and nested-Scope layouts, not path routes. The default is a global AABB; circle mode computes a minimum enclosing circle. A `GroupPrim` is emitted when the subtree has output or Scope carries `transforms` / `id` / `clip`; an empty Scope without those semantics is pruned.

## API Reference

### Context and output

| Prop             | Type                                    | Default       | Description                                                                                                               |
| ---------------- | --------------------------------------- | ------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `children`       | `ReactNode`                             | —             | Node / Path / Coordinate / nested Scope                                                                                   |
| `theme`          | `IRTheme`                               | Inherited     | Per-field Theme override for descendant composites; does not style Core primitives                                        |
| `transforms`     | `Array<InputTransform>`                 | —             | Seven local transforms; the last acts first                                                                               |
| `placement`      | `IRScopePlacement`                      | —             | Align transformed `selfAnchor` (center by default) with a target in the parent frame                                      |
| `id`             | `string`                                | —             | Register the Scope envelope as a group handle                                                                             |
| `localNamespace` | `boolean`                               | `false`       | Isolate child ids; `scope.id` remains visible                                                                             |
| `boundingShape`  | <ApiValues name="ScopeBoundingShape" /> | `'rectangle'` | Rectangle or circle envelope for `scope.id`                                                                               |
| `clip`           | `IRClip`                                | —             | Built-in or custom clip in local coordinates                                                                              |
| `zIndex`         | `number` (integer)                      | `0`           | Stable sibling order for the whole Scope                                                                                  |
| `meta`           | `Record<string, JSON value>`            | —             | Forwarded to GroupPrim, not layout or cascade                                                                             |
| `animations`     | `Array<IRAnimationTrack>`               | —             | Group animation, not inherited by children                                                                                |
| `on<Event>`      | `ScopeProps['onClick']`                 | —             | Uses the `onClick` signature and requires `id`; see [Hydration](/kernel/packages/render/render-hydration) for every event |

Inspection support comes from `LayoutInspectScope` in `@retikz/layout-react/inspect`. Its `request` accepts one or more Inspector requests; `request={false}` is the hard barrier descendants cannot cross. This runtime marker never enters `IRScope`. If a nested Scope contribution cannot be located precisely, inspection compilation fails loudly instead of attributing guides to the outer Scope. See [Layout Inspector](/library/layout/reference/runtime#layout-inspector) for the complete rules.

### Style defaults

| Prop                                                            | Type                               | Default | Description                               |
| --------------------------------------------------------------- | ---------------------------------- | ------- | ----------------------------------------- |
| `color`                                                         | `string`                           | —       | Primary color cascaded across elements    |
| `stroke` / `fill`                                               | `string` \| `IRPaint`              | —       | Per-field stroke and fill cascade         |
| `strokeWidth` / opacity fields                                  | `number`                           | —       | Stroke width and per-field opacity        |
| `nodeDefault` / `pathDefault` / `labelDefault` / `arrowDefault` | default objects                    | —       | Four independent element-default channels |
| `resetStyle`                                                    | `boolean` \| `Array<StyleChannel>` | `false` | Cut all or selected outer Scope channels  |
