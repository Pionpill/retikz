Use Scope to move a group, share defaults, or clip children. Place it inside Layout or another Scope; each Scope affects only its own subtree.

`defaults.style` can share `lineCap`, `lineJoin`, `shadow`, and `blendMode` across descendant nodes and paths. Shadows and blend modes apply to each descendant’s primary geometry; they do not composite the Scope as a single layer.

## Using this topic

Choose a host and input format: React accepts JSX or an `ir` prop; Vanilla accepts builder output or IR directly. All four variants keep the left `x = 0` reference and move A and B inside Scope 80 units to the right.

Import components from `@retikz/react` and declare Scope with its child subtree directly.

```tsx
import { Draw, Layout, Node, Scope } from '@retikz/react';
import type { FC } from 'react';

const Demo: FC = () => (
  <Layout>
    <Node id="origin" position={[0, 0]}>
      x = 0
    </Node>
    <Scope position={[80, 0]}>
      <Node id="A" position={[0, 0]}>
        A
      </Node>
      <Node id="B" position={[100, 0]}>
        B
      </Node>
      <Draw way={['A', 'B']} arrow="->" />
    </Scope>
  </Layout>
);

export default Demo;
```

Import the IR type from `@retikz/core` and pass the Scope subtree to `<Layout ir>`, without JSX children.

```tsx
import type { IRScene } from '@retikz/core';

  version: 1,
  type: 'scene',
  children: [
    { type: 'node', id: 'origin', position: [0, 0], text: 'x = 0' },
    {
      type: 'scope',
      position: [80, 0],
      children: [
        { type: 'node', id: 'A', position: [0, 0], text: 'A' },
        { type: 'node', id: 'B', position: [100, 0], text: 'B' },
        {
          type: 'path',
          arrow: { end: {} },
          children: [
            { type: 'step', kind: 'move', to: { id: 'A' } },
            { type: 'step', kind: 'line', to: { id: 'B' } },

    },
  ],
};

const Demo: FC = () => <Layout ir={ir} />;
```

Build Scope with `@retikz/vanilla`, then mount it into an existing `diagram` container using the `/dom` entry.

```ts
import { node, path, scene, scope } from '@retikz/vanilla';
import { mount } from '@retikz/vanilla/dom';

const input = scene({
  children: [
    node({ id: 'origin', position: [0, 0], text: 'x = 0' }),
    scope({ position: [80, 0] }, [
      node({ id: 'A', position: [0, 0], text: 'A' }),
      node({ id: 'B', position: [100, 0], text: 'B' }),
      path({ way: ['A', 'B'], arrow: { end: {} } }),
    ]),
  ],
});

const view = mount(document.getElementById('diagram')!, input);
```

Call `view.dispose()` before removing the container to release mounted resources.

Descendants cannot use named references to the center, anchors, or boundary of any ancestor Scope. This applies to nested Nodes, Coordinates, Scopes, and Paths, including Paths evaluated after the envelope is complete, and throws an error. External Paths can still connect to the Scope; the Scope can still position itself relative to a valid external Node and use its own envelope for pivot or selfAnchor. Namespace shadowing remains valid: a local node is not forbidden merely because it shares an ancestor Scope name.

## When to use Scope

| Category        | Property               | Effect                                                                    |
| --------------- | ---------------------- | ------------------------------------------------------------------------- |
| Group target    | `position`             | Set the parent-frame origin position or align the group by its own anchor |
|                 | `id` + `boundingShape` | Make the group referenceable externally; path routes stay out of bounds   |
| Subtree context | `transforms`           | Transform the whole subfigure; does not place raw children                |
|                 | `localNamespace`       | Isolate reusable child ids; `scope.id` stays in the parent                |
|                 | `theme`                | Switch a local domain theme; Core primitives are not recolored            |
|                 | `defaults`             | Share defaults; explicit element values win                               |
|                 | `clip`                 | Limit the subtree's visible area; no renderer-specific semantics          |
|                 | `zIndex`               | Move the group among parent-level content; child order stays unchanged    |

## Transform inputs

Five translation forms mirror Node's relative-position model; `rotate` and `scale` set the local axes and scale. Array order follows an SVG transform list, so the last item acts on a local point first.

| kind                | Key fields                     | Effect                                            |
| ------------------- | ------------------------------ | ------------------------------------------------- |
| `translate`         | `x`, `y`                       | Fixed Cartesian translation                       |
| `polar-translate`   | `origin?`, `angle`, `radius`   | Polar position from an origin or reference target |
| `at-translate`      | `direction`, `of`, `distance?` | Place in a reference target's direction           |
| `offset-translate`  | `of`, `offset?`                | Add a local offset to a reference target          |
| `between-translate` | `between`, `fraction`          | Interpolate between two endpoints                 |
| `rotate`            | `degrees`, `pivot?`            | Rotate around a Scope self point                  |
| `scale`             | `x`, `y?`, `pivot?`            | Scale around a Scope self point                   |

## Local coordinates

`position` has two forms; `transforms` always describes additional local transforms:

| Form             | Example                                                                   | Result                                                                                                     |
| ---------------- | ------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| Origin position  | `position={[100, 50]}`                                                    | Places the local origin in parent coordinates; local rotation and scaling do not change this base position |
| Anchor alignment | `position={{ kind: 'anchor', target: { id: 'T' }, selfAnchor: 'right' }}` | Aligns the transformed right anchor exactly with T                                                         |

Omitting position gives the same geometry as `[0, 0]`. With position `[100, 50]` and local `translate(10, 0)`, the origin ends at `[110, 50]`. Anchor alignment can cancel that translation; move target or target.offset to offset the alignment.

`O` / `T` are fixed referents, while `q` provides the intrinsic envelope. Change the origin position and local transform, or enable anchor alignment, to compare the two forms.

In the anchor form, `position.target` accepts only a parent-frame `[x, y]` or a previously completed `{ id, anchor?, offset? }`. `selfAnchor` defaults to `center` and also accepts standard anchors, numeric angles, `{ side, fraction }`, `origin`, or an explicit local point.

`rotate.pivot` and `scale.pivot` use the same self-point vocabulary and default to `origin`. A pivot reads the intrinsic envelope before position, so moving a Scope cannot feed back into its rotation or scale center. Other relative directions remain local: rotating Scope also rotates the visual direction of `right` with the axes.

## Clipping and stacking

All clips use `{ kind, params }`: `kind` selects the clip definition, and the required `params` object holds its parameters, for example `{ kind: 'rect', params: { x: 0, y: 0, width: 100, height: 80 } }`.

`clip` uses Scope-local coordinates and becomes a renderer-agnostic Scene resource downstream. The panel shows Core's `rect` plus `circle` / `ellipse` / `polygon` / `path` / `compound` provided by Standard and injected into the drawing. Register a [Custom Clip](/kernel/components/scope/custom) when a domain needs another operation or geometry kind.

## Additional notes

**Local Theme.** `<Scope theme>` writes sparse `name` / `mode` selectors to `IRScope.theme` and affects descendant composites only. Fields inherit independently: `{ mode: ThemeMode.Dark }` changes the light/dark environment while retaining the outer `name`. During compilation, Core regenerates shared colors through the current theme registry; an unregistered theme fails immediately. See [Layout: Inherited Theme](/kernel/components/layout/extend#theme-configuration) for the complete example.

Theme and style defaults are independent channels. `defaults.reset` does not reset Theme, and Theme does not fill Node or Path colors. Omitting `name` uses the owning package's default baseline; within a nested `Scope`, omitting `name` inherits the outer name and cannot reset to that baseline.

**Style defaults.** Scope also exposes `defaults.style.color`, shared visual properties, and `defaults.node` / `defaults.path`. Values cascade per field, explicit element values win, and `defaults.reset` cuts only selected outer channels.

Decoration defaults belong to their hosts. `defaults.node.label` configures existing node labels, including attachment, alignment, distance, rotation, leader lines, and appearance. `defaults.path.label` configures existing path and step labels, including position, slope, interruption, and appearance. `defaults.path.arrow` configures existing arrow marks and endpoint overrides. These fragments contain no label text and create neither labels nor arrows.

Font fields inherit independently across nested Scopes and instances: changing size retains the family and weight. `reset: ['node']` clears inherited node and node-label defaults; `reset: ['path']` clears path, label, and arrow defaults. `true` clears both host channels; declarations on the current Scope still apply.

Shared stroke fields include `stroke`, `strokeWidth`, `dashPattern`, and `dashOffset`. For example, `defaults: { style: { dashPattern: [6, 2], dashOffset: -2 } }` affects both descendant Node borders and Paths. Current-scope channel defaults override shared defaults, and explicit element styles override channel defaults. Dash arrays replace the entire inherited array; `dashOffset: 0` overrides an inherited phase. Omitted fields inherit. Use `defaults: { reset: ['node'] }` to cut off inherited Node dashes while retaining Path defaults; empty dash arrays are invalid.

Style is a supporting responsibility and does not alter local coordinates, references, or clipping. Consult the [API reference](/kernel/components/scope/reference) for color, stroke, and opacity fields rather than creating extra Scopes for visual variants.

## Visible containers

Scope retains its content envelope and references but draws no frame. Use [Surface](/library/standard/presentation/surface) for backgrounds, borders, and padding, or [Frame](/library/standard/presentation/frame) for a titled container.

## Errors and limitations

- Anchor-form `position` can reference only completed targets, never self, descendants, or unfinished Scopes.
- Zero scaling is valid visually, but inverse coordinate projection across it fails.
- Duplicate ids in one namespace warn and use the later definition. Use `localNamespace` to isolate reusable child ids.
- Base Scope has no layout-inspection props; use the Layout package’s `LayoutInspectScope` for subtree inspection.

## Set label and arrow defaults by host

Configure node and path labels separately. The labels below provide content while their placement, spacing, fonts, and arrow appearance inherit from host defaults. Elements without a label or arrow do not gain decorations.

```tsx
<Scope
  defaults={{
    node: { label: { position: 'bottom', distance: 12, font: { size: 14 } } },
    path: {
      label: { side: 'top', distance: 8, sloped: true },
      arrow: { length: 10 },
    },
  }}
>
  <Node id="a" position={[0, 0]} label={{ text: 'A' }} />
  <Node id="b" position={[100, 0]} label={{ text: 'B' }} />
  <Draw way={['a', 'b']} arrow="->" label={{ text: 'A → B' }} />
</Scope>
```
