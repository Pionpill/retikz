title: Way
description: Look up how a Draw way array expresses targets, folds, closure, and relative coordinates, and how they expand into ordered Steps.
---

`way` is the core of `<Draw>`: targets decide where the path goes, fold and curve operators decide how neighboring targets connect, `DrawWay.Cycle` closes the path, and relative coordinates change the target's evaluation base.

Think of `way` as a tiny path language: targets produce points, `'-|'` / `'|-'` rewrite the segment between neighboring points, `{ label }` decorates the next segment, `{ curve }` / `{ cubic }` / `{ bend }` consume the next item to make a curve, and `{ arc }` / `{ circle }` / `{ ellipse }` draw around the previous point without consuming the next item.

## Usage

```tsx
import { DrawWay } from '@retikz/core';
import { Draw } from '@retikz/react';
```

```tsx
<Draw way={['a', DrawWay.Hv, 'b']} />
```

### Single-axis connections

`{ horizontalTo }` connects only to the target x, while `{ verticalTo }` connects only to the target y. Each emits one `axis-line` Step, unlike the two segments produced by `-\|` / `\|-`. Directions use the current Scope's local axes.

The operator value accepts only Cartesian coordinates, NodeTarget, or their string shorthand. `parseWay` rejects relative, polar, offset, and between targets, as well as objects containing multiple Way operators.

Switch among four fold directions and watch the blue path pass through one or two orthogonal corners. In `-\|-` / `\|-\|` modes, `fraction` moves the middle leg through `0..1` and defaults to `0.5`; the gray dotted line only marks the direct endpoint connection.

<Comparison target="tikz" title="Fold Syntax">

### How a WayItem becomes a Step

`<Draw>` scans `way` from left to right. The first item must be a target and always emits `move`; every later item is classified by role, then emits an equivalent Step according to its consumption rule. “Consume” means which array items the current rule takes.

<ComponentPreview files="way-parser-flow" size="sm" hideCode />

| Category                         | Scan advance              | Output                          |
| -------------------------------- | ------------------------- | ------------------------------- |
| target                           | Current item              | First `move`, then `line`       |
| horizontalTo / verticalTo        | Current item              | One `axis-line` Step            |
| `-\|` / `\|-`, curve / bend etc. | Operator + next target    | One matching fold or curve Step |
| arc / circle / ellipse           | Current operator only     | One shape Step; next item stays |
| `{ label }`                      | Hold for the next segment | No Step of its own              |
| `DrawWay.Cycle`                  | Current item              | `cycle`, with no label          |

That is why a fold or curve operator must be followed immediately by a target, while a shape operator leaves the next item available to the scan. `{ label }` enters a pending state that the next segment-producing item consumes, so place it before the target or segment operator. Consecutive labels, trailing labels, and labels attached to cycle are rejected.

Finally, `<Draw>` expands the Step sequence into `<Step>` children of `<Path>` and passes stroke, fill, arrow, and related visual props to `<Path>`. It is compact sugar rather than a second path model.

### Relative coordinates resolve during Path compilation

`parseWay` only normalizes `'+10,0'` / `'++10,0'` and their object forms into `relative` / `relativeAccumulate` targets. It does not precompute an absolute point. As Path compilation visits each Step, both forms use the previous effective endpoint, `prevEnd`, as their base; the first item falls back to `[0, 0]` when no base exists.

`Relative` borrows `prevEnd` for this endpoint without replacing the base. `Accumulate` writes its result back to `prevEnd`, so the next relative item continues from the new position. Inside a transformed [Scope](/kernel/components/layout/scope), the offset is added in that Scope's local coordinates before being projected back to global coordinates.

## API Reference

### WayItem

| Form                    | Example                                                                                         | Meaning                                                                                  |
| ----------------------- | ----------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| Node id                 | `'a'`                                                                                           | Reference a Node in the same diagram; endpoint auto-attaches to border                   |
| Explicit anchor         | `{ id: 'a', anchor: 'top' }` or `'a.top'`                                                       | Lock to a named anchor / angle / edge proportional point; object form is the IR contract |
| Cartesian               | `[120, 0]`                                                                                      | Literal coordinate                                                                       |
| Polar                   | `{ origin: 'a', angle: 60, radius: 80 }`                                                        | Polar coordinate; see [Positioning](/kernel/concepts/basic/position)                     |
| Offset placement        | `{ of: 'a', offset: [10, 5] }`                                                                  | Base + `(dx, dy)`, same offset form as `<Node position>`                                 |
| Proportional placement  | `{ between: [{ id: 'a' }, { id: 'b' }], fraction: 0.5 }`                                        | Proportional point along A → B                                                           |
| Relative                | `{ position: [10, 0], type: DrawWay.Relative }` or `'+10,0'`                                    | Offset from the previous step endpoint without updating prevEnd                          |
| Accumulate              | `{ position: [10, 0], type: DrawWay.Accumulate }` or `'++10,0'`                                 | Offset from the previous step endpoint and update prevEnd                                |
| Single-axis operator    | `{ horizontalTo: 'a' }` / `{ verticalTo: [120, 0] }`                                            | Connect to the target along one local host axis                                          |
| Two-leg fold operator   | `'-\|'` / `'\|-'`                                                                               | Turn previous-to-next into a two-leg fold                                                |
| Three-leg fold operator | `'-\|-'` / `'\|-\|'` / `{ via: '-\|-', fraction: 0.3 }`                                         | Three-leg orthogonal connector; object form is strict and fraction is in `0..1`          |
| Cycle                   | `DrawWay.Cycle`                                                                                 | Close back to the way start                                                              |
| Curve / shape / label   | `{ curve }` / `{ cubic }` / `{ bend }` / `{ arc }` / `{ circle }` / `{ ellipse }` / `{ label }` | Covered by [Draw](/kernel/components/draw/overview)                                      |

### DrawWay

| Constant             | Raw literal | Meaning                                        |
| -------------------- | ----------- | ---------------------------------------------- |
| `DrawWay.Cycle`      | const-only  | Close keyword; avoids collisions with node ids |
| `DrawWay.Hv`         | `'-\|'`     | Horizontal then vertical                       |
| `DrawWay.Vh`         | `'\|-'`     | Vertical then horizontal                       |
| `DrawWay.Hvh`        | `'-\|-'`    | Horizontal → vertical → horizontal             |
| `DrawWay.Vhv`        | `'\|-\|'`   | Vertical → horizontal → vertical               |
| `DrawWay.Relative`   | const-only  | Non-accumulating relative offset               |
| `DrawWay.Accumulate` | const-only  | Accumulating relative offset                   |
