Register a custom repeating pattern when the built-in lines, dots, and grid cannot express the texture you need. The `cross` definition below draws one cross in each tile and then works like any other `fill`.

## Boundaries

Keep a [built-in pattern](/kernel/components/effects/pattern) when you only need to change density, color, background, line width, or rotation. Create a `PatternDefinition` only when the tile geometry itself must change.

Primitive data stores only serializable configuration such as `{ kind: 'pattern', shape: 'cross' }`. The `emit` function stays in the host-injected definition and never enters the IR (intermediate representation).

## Define the capability

Use `definePattern()` to create a named definition. `emit` receives the resolved size and color, then returns structured primitives in tile-local `0..size` coordinates.

```tsx
import { definePattern } from '@retikz/core';

const cross = definePattern({
  name: 'cross',
  defaultSize: 12,
  emit: ({ size, color }) => {
    const center = size / 2;
    return [
      {
        type: 'path',
        commands: [
          { kind: 'move', to: [center, 2] },
          { kind: 'line', to: [center, size - 2] },
        ],
        stroke: color,
      },
      {
        type: 'path',
        commands: [
          { kind: 'move', to: [2, center] },
          { kind: 'line', to: [size - 2, center] },
        ],
        stroke: color,
      },
    ];
  },
});
```

Built-in and custom patterns implement the same `PatternDefinition` and enter the same registry. `definePattern()` only checks the definition shape in TypeScript; it does not put functions into primitive data.

## Inject the host

Pass the definition to `<Layout patterns>`, then reference its `name` from a Node or Path `fill`:

```tsx
<Layout patterns={[cross]}>
  <Node fill={{ kind: 'pattern', shape: 'cross', color: 'darkorange' }} />
</Layout>
```

When calling `compileToScene()` directly, use `CompileOptions.patterns`. Definitions belong to the current compile host, so the same IR can receive different pattern sets in different hosts.

`pattern.size` overrides the definition's `defaultSize`. These two nodes reuse the same complete definition: the left stays at `size: 6` as a reference, while the right starts at `size: 16` and lets you tune period, rotation, color, and backdrop.

## Execution

At compile time, built-in and custom definitions merge into one registry. The compiler looks up `shape`, calls `emit`, and writes a resolved pattern resource into the Scene. SVG and Canvas materialize that resource without seeing the definition function.

| Stage    | Input                    | Output                    |
| -------- | ------------------------ | ------------------------- |
| Register | Built-ins + `patterns`   | One name-indexed registry |
| Resolve  | `shape`, size, and color | Tile-local primitives     |
| Emit     | Resolved tile            | Scene pattern resource    |
| Render   | Scene pattern resource   | SVG or Canvas pattern     |

Built-in and custom patterns therefore share name conflicts, lookup, validation, and rendering semantics.

## Errors and limits

| Case                            | Result                           | Fix                                  |
| ------------------------------- | -------------------------------- | ------------------------------------ |
| Empty or duplicate name         | Registration throws              | Use a non-empty unique `name`        |
| Unregistered `shape`            | Compile lists available names    | Inject or correct the definition     |
| Invalid `size` / `lineWidth`    | Compile throws                   | Pass a finite positive number        |
| Non-finite `rotation`           | Compile throws                   | Pass a finite angle                  |
| `emit` throws                   | Compile reports the pattern name | Fix the definition logic             |
| Invalid primitive or coordinate | Compile validation fails         | Return supported structured geometry |

Tile output accepts only JSON-safe structured geometry. Do not return functions, DOM nodes, text, external resource references, or non-finite coordinates.

## API Reference

### PatternDefinition

| Prop          | Type                                 | Default | Description                                         |
| ------------- | ------------------------------------ | ------- | --------------------------------------------------- |
| `name`        | `string`                             | —       | Registry name used by `pattern.shape`               |
| `defaultSize` | `number?`                            | `8`     | Optional period used when `pattern.size` is omitted |
| `emit`        | `(ctx) => Iterable<MarkerPrimitive>` | —       | Produces tile-local geometry                        |

### PatternEmitContext

| Prop         | Type            | Default        | Description                      |
| ------------ | --------------- | -------------- | -------------------------------- |
| `size`       | `number`        | resolved       | Tile period                      |
| `color`      | `string`        | `currentColor` | Primary motif color              |
| `background` | `string?`       | —              | Omitted means a transparent tile |
| `lineWidth`  | `number?`       | —              | Omitted lets the motif choose    |
| `round`      | `(n) => number` | —              | Applies compile precision        |
