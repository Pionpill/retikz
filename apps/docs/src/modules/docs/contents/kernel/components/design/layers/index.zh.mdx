retikz 把用户写下的 DSL（React 组件或 Vanilla JS 写法）先转成 IR，再编译成 Scene。DSL 负责书写体验，IR 保留“你想画什么”，Scene 只保留“渲染器应该画什么”。

## 三层模型

| 层    | 作用                                                                       | 面向谁                    |
| ----- | -------------------------------------------------------------------------- | ------------------------- |
| DSL   | React 组件或 Vanilla JS 写法，分为 Kernel 与 Sugar                         | 日常作者                  |
| IR    | JSON 可序列化的声明结构，保留 Node / Path / Step / Coordinate / Scope 语义 | 用户、LLM、持久化、转换器 |
| Scene | 渲染目标无关的 primitive、layout bounds、资源表与根动画                    | renderer                  |

IR 是公开契约；Scene 是 renderer 输入。正常写图时不需要手写 Scene。

为什么用户需要知道这三层：日常写图看 DSL；要把图存进数据库、发给 LLM 修改、做 JSON Patch 或跨端渲染时看 IR；只有写 renderer / 调试测量结果时才看 Scene。

## Kernel 与 Sugar

Kernel 保留基础绘图语义，Sugar 在构建 IR 时展开为这些基础表达。等价示例、展开约束与选择建议见[语法糖](/kernel/components/design/sugar)。

## 包结构

Kernel 当前包含九个同步发版的包。按使用任务选择入口；依赖由包管理器安装，不需要手动安装整组。

| 包                   | 职责                      |
| -------------------- | ------------------------- |
| `@retikz/foundation` | 跨包原子契约与基础 schema |
| `@retikz/math`       | 零依赖几何与数值计算      |
| `@retikz/runtime`    | 增量执行与事务            |
| `@retikz/core`       | 共享 IR、Scene 与编译     |
| `@retikz/inspect`    | 诊断观察与辅助图形        |
| `@retikz/render`     | SVG / Canvas 后端输出     |
| `@retikz/vanilla`    | 框架无关输入与宿主接入    |
| `@retikz/react`      | React 组件与生命周期接线  |
| `@retikz/tex`        | 可选 LaTeX 公式接入       |

浏览器应用通常从 React 或 Vanilla 开始；查看各包的独立文档再决定是否直接依赖其他包。
