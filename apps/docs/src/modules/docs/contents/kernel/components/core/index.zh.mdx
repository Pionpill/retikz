节点和连线不仅是画面上的矩形与线条。节点提供可被测量、放置和引用的几何信息，连线使用这些信息选择端点。核心概念从“一个对象怎样组成”走向“多个对象怎样连接”，帮助你在文字、形状或位置改变后仍保持图形关系。

## 职责一览

| 章节     | 职责                       | 何时阅读                 |
| -------- | -------------------------- | ------------------------ |
| 图元模型 | 定义内容、形状、边界与锚点 | 理解单个图元的几何结构   |
| 图元关系 | 用引用与连接规则确定端点   | 选择自动贴边或固定连接点 |

## 对象与连接怎样配合

以带文字的 Node 为例：文字占据内容区域，padding 为内容留出空隙，shape 决定可见形状。连线还需要知道可以接到哪里：boundary 是连接所用的边界，anchor 是边界或图元上的命名位置，例如顶部中点。

可见轮廓、外接矩形与连接边界用途不同，不必永远重合。理解这些区别，才能判断一处变化应该修改文字间距、形状大小，还是连线的连接位置，而不是用偏移量反复补偿。

## 同一节点的两种连接

下图左右各有一个 T 节点，以及来自 a、b 的连线。左侧只引用 T，端点随来线方向贴到相应边界；右侧指定 `T.top`，两条线都连接到顶部中点。

<ComponentPreview files="/kernel/components/core/primitive-relations/relation-dynamic-vs-locked" size="sm" hideCode />

两组节点的位置相同，差异来自连接规则。默认贴边适合让关系线随布局变化；指定 anchor 适合固定出线位置。节点模型定义“有哪些可用几何信息”，图元关系决定“这次连接如何使用它们”。

## 从现象定位问题

| 看到的现象                   | 先检查什么               |
| ---------------------------- | ------------------------ |
| 文字离边框太近               | 内容区域与 padding       |
| 连线接到了不想要的一侧       | 动态贴边还是显式 anchor  |
| 形状变了，连线位置不符合预期 | 可见形状与连接边界的关系 |

这些判断先帮助你找到概念，再到组件文档查询具体写法。这里不要求阅读完整字段表，也不展开编译器怎样测量和解析每一步。

## 阅读顺序与边界

先读图元模型，认识单个节点的结构，再读图元关系，理解路径如何引用它。还不熟悉坐标方向或相对位置时，先回到[基础概念](/kernel/components/basic)；需要实际配置时，再进入 Node、Draw 或 Layout 的对应文档。
