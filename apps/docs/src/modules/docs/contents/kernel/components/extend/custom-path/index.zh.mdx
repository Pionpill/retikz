`<Path>` 的 `kind` 是**开放字符串**：内置 `stroke` 和 `ribbon` 之外，可以注册自己的路径 kind。自定义路径适合“整条 Path 应该如何产出 Scene primitive”的场景，例如高亮底线、双线关系、业务关系线、宽箭头或后续的领域路径。

注册面是 `CompileOptions.pathKinds`（React 里是 `<Layout pathKinds={...}>`）：IR 只保存 `kind` 与 JSON-only 的 `kindOptions`，provider 函数在宿主运行时注入，不进入 IR。

## API

| 字段            | 类型                                         | 说明                                                                        |
| --------------- | -------------------------------------------- | --------------------------------------------------------------------------- |
| `kind`          | `string`                                     | 注册名；`Path.kind` 用它查找 provider                                       |
| `optionsSchema` | `ZodType<IRJsonObject>`                      | 可选；校验 `kindOptions`，输出仍必须是 JSON-safe                            |
| `compile`       | `(context) => PathKindCompileResult \| null` | 编译整条 Path，返回 Scene primitives 与 `boundsPoints`；`null` 表示无法产出 |

`compile` 拿到的 `PathKindCompileContext`：

| 字段         | 类型                                       | 说明                                          |
| ------------ | ------------------------------------------ | --------------------------------------------- |
| `path`       | `IRPathBase`                               | 当前 Path 的完整 IR 数据                      |
| `options`    | `TOptions`                                 | `kindOptions` 经 `optionsSchema` 校验后的结果 |
| `emitStroke` | `(path?) => PathKindCompileResult \| null` | 复用内置 stroke lowerer，可传入改写后的 Path  |
| `emitRibbon` | `(path?) => PathKindCompileResult \| null` | 复用内置 ribbon lowerer，可传入改写后的 Path  |

## 与路径生成器的区别

自定义路径接管**整条 Path**：它决定这条路径最终产出什么 primitive，适合改变关系形态或复用内置 lowerer 后再改写结果。

路径生成器只接管 **一个 `generator` step**：它把某一段曲线转换成低层 `PathCommand[]`，之后仍交给当前 Path kind 继续编译。需要新增曲线段时用 [路径生成器](/kernel/components/extend/path-generator)，需要新增整条路径的 provider 时用自定义路径。
