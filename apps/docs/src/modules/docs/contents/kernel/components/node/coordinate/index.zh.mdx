---
title: Coordinate
description: Coordinate 命名一个不渲染的几何点，供路径端点和其它节点按 id 定位。
---

`<Coordinate>` 给位置一个稳定的 `id`，但不画形状或文字。路径可以把它当端点，其它节点也能通过相对、偏移、比例或锚点定位引用它。

## 用法

```tsx
import { Coordinate } from '@retikz/react';
```

```tsx
<Coordinate id="hub" position={[0, 0]} />
```

`Coordinate.position` 接受五种中心 / 点定位形态：笛卡尔 `[x, y]` / 极坐标 `{ angle, radius, origin? }` / 相对定位 `{ direction, of, distance? }` / 偏移定位 `{ of, offset }` / 比例定位 `{ between, fraction }`。Node 额外支持依赖自身真实尺寸的 `{ kind: 'anchor', target, selfAnchor? }`；Coordinate 可以作为它的 target，但自身没有 `selfAnchor` 定位。

### 何时使用

需要汇合点、辅助定位或不可见锚点时使用 Coordinate；需要形状、文字或方向性边界时使用 Node。不要用透明 Node 模拟坐标点：它仍有尺寸和 padding，会扩大布局范围。

| 目标                   | 选择           |
| ---------------------- | -------------- |
| 只命名位置             | `<Coordinate>` |
| 显示圆点或其它标记     | `<Node>`       |
| 显示文字或 label       | `<Node>`       |
| 使用不同方向的真实锚点 | `<Node>`       |

Coordinate 的方向与角度 anchor 都退化到中心；它也不提供文字字段。零尺寸语义见[技术原理](#技术原理)。

### 先登记，再引用

图的主链表示编译器遍历到 Coordinate 时发生的动作；下方两条分支展示定位引用与 path 端点读取同一登记结果的不同时机。

<ComponentPreview files="coordinate-resolution-flow" size="sm" hideCode />

Coordinate 的 `position` 会立即解析。若它依赖另一个 id，该 id 必须已经在当前可见命名空间中登记；引用同一层里后定义的 Node / Coordinate 会直接报错。位置解析成功后，编译器把结果投影到全局坐标，保存成一条只有中心坐标的零尺寸几何记录，再按 `id` 登记。

Node / Coordinate 的定位引用同样在遍历时解析，因此只看得到已登记的 id。Path 则先排队，等当前 Scope 的 children 完成登记后再解析端点，所以同一作用域里的 path 可以引用写在它后面的 Coordinate。`localNamespace` 带来的可见范围仍遵循 [Scope 的命名空间规则](/kernel/components/layout/scope#命名空间与-id-冲突)。

### 零尺寸记录如何影响输出

这里的“零尺寸”表示记录的宽为 0、高为 0，因此也常简写为 **0×0**。它只保存 Coordinate 的中心坐标，没有面积或可见内容，边界也退化到中心；这是一条供编译器定位和连线引用的内部几何记录，不是 Scene 图元。这样既能复用 Node 的 id 查询与 anchor 解析机制，又不会让纯引用点进入渲染输出或自动画布范围。

- **不画任何图元**——没有形状、没有文字，渲染产物里完全不出现。
- **不撑大画布**——远处的 coordinate 不会让最终 viewBox 自动变大；必须有实际 `<Node>` / `<Path>` 落在那片区域，画布才覆盖过去（调试定位时常踩这点）。
- **命名 / 角度 anchor 退化为中心**——因为宽和高都是 0，各方向的边界都和中心重合，所以 `hub.top` / `hub.bottom` / `hub.30` 都等于中心点；需要方向 anchor 就改用 `<Node>`。
- **边上比例点会报错**——`{ anchor: { side, fraction } }` 需要一条真实边，而零尺寸记录只有中心点，没有可取样的边。

## API 参考

| 属性       | 类型                                                                                                 | 默认值 | 描述                                                                                                                         |
| ---------- | ---------------------------------------------------------------------------------------------------- | ------ | ---------------------------------------------------------------------------------------------------------------------------- |
| `id`       | `string`                                                                                             | —      | **必填**——占位的全部意义就在于被 id 引用                                                                                     |
| `position` | `[x, y] \| PolarPosition \| { direction, of, distance? } \| { of, offset } \| { between, fraction }` | —      | 零尺寸占位点的五种位置形态；不接受 Node-only `IRAnchorPosition`。其中 id 依赖必须先登记，解析时序见[技术原理](#先登记再引用) |
