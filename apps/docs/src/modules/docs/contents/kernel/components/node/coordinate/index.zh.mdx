---
title: Coordinate
description: 占位节点——命名一个点不画任何图形，给 path 和 node 相对定位（`{ of }`）引用。
---

`<Coordinate>` 用来在 IR 中登记一个可命名的引用点。它和 `<Node>` 一样可以被路径与相对定位引用，但不会在画面上渲染形状或文字；编译时会解析它的位置并登记 `id`，供 `<Path>` 端点和 `<Node position>` 的相对 / 偏移定位（`{ of }`）引用。

## 用法

```tsx
import { Coordinate } from '@retikz/react';
```

```tsx
<Coordinate id="hub" position={[0, 0]} />
```

`position` 接受 `<Node>` 完全相同的五种形态：笛卡尔 `[x, y]` / 极坐标 `{ angle, radius, origin? }` / 相对定位 `{ direction, of, distance? }` / 偏移定位 `{ of, offset }` / 比例定位 `{ between, fraction }`。

### 为什么需要它

要在某处放一个引用点，最朴素的做法是 fake 一个 `stroke="transparent" fill="transparent"` 的空 `<Node>`——但空 Node 仍会按 padding 占一块不可见的方块、把外框撑大，AI / 序列化往返时也分不清它是真节点还是占位。

`<Coordinate>` 把"命名点"做成一等概念：字段最少（只有 `id` + `position`）、不画任何东西、也不会撑大画布。背后的占位语义见 [技术原理](#技术原理)。

<Comparison target="tikz" title="Coordinate 对照">

`<Coordinate id="hub" position={[0, 0]} />` 对应 TikZ 的 `\coordinate (hub) at (0,0);`：只命名一个点，不渲染形状。

`{ between: [A, B], fraction }` 对应 TikZ `($(A)!t!(B)$)`，都表示在两个端点之间按比例取点。

`{ between: [A, B], fraction }` 在 A、B 两端点的连线上按 `fraction`（0..1）取点——`lerp(A, B, fraction)`。放"连线中点 / 1/3 处"的点比手算坐标更省、且随 A、B 移动自动保持比例。端点是**自包含 AbsoluteTarget**（笛卡尔 / 极坐标 / 节点引用 `{ id, anchor? }` / `{ of, offset }` / 嵌套 between，**不含** path-relative）。同一形态可用于 `<Coordinate position>` / `<Node position>` / `<Step to>`：

### 先登记，再引用

图的主链表示编译器遍历到 Coordinate 时发生的动作；下方两条分支展示定位引用与 path 端点读取同一登记结果的不同时机。

<ComponentPreview files="coordinate-resolution-flow" size="sm" hideCode />

Coordinate 的 `position` 会立即解析。若它依赖另一个 id，该 id 必须已经在当前可见命名空间中登记；引用同一层里后定义的 Node / Coordinate 会直接报错。位置解析成功后，编译器把结果投影到全局坐标，保存成一条只有中心坐标的零尺寸几何记录，再按 `id` 登记。

Node / Coordinate 的定位引用同样在遍历时解析，因此只看得到已登记的 id。Path 则先排队，等当前 Scope 的 children 完成登记后再解析端点，所以同一作用域里的 path 可以引用写在它后面的 Coordinate。`localNamespace` 带来的可见范围仍遵循 [Scope 的命名空间规则](/kernel/components/layout/scope#命名空间与-id-冲突如何处理)。

### 零尺寸记录如何影响输出

这里的“零尺寸”表示记录的宽为 0、高为 0，因此也常简写为 **0×0**。它只保存 Coordinate 的中心坐标，没有面积或可见内容，边界也退化到中心；这是一条供编译器定位和连线引用的内部几何记录，不是 Scene 图元。这样既能复用 Node 的 id 查询与 anchor 解析机制，又不会让纯引用点进入渲染输出或自动画布范围。

- **不画任何图元**——没有形状、没有文字，渲染产物里完全不出现。
- **不撑大画布**——远处的 coordinate 不会让最终 viewBox 自动变大；必须有实际 `<Node>` / `<Path>` 落在那片区域，画布才覆盖过去（调试定位时常踩这点）。
- **命名 / 角度 anchor 退化为中心**——因为宽和高都是 0，各方向的边界都和中心重合，所以 `hub.top` / `hub.bottom` / `hub.30` 都等于中心点；需要方向 anchor 就改用 `<Node>`。
- **边上比例点会报错**——`{ anchor: { side, fraction } }` 需要一条真实边，而零尺寸记录只有中心点，没有可取样的边。

## API 参考

| 属性       | 类型                                                                                                 | 默认值 | 描述                                                                                                   |
| ---------- | ---------------------------------------------------------------------------------------------------- | ------ | ------------------------------------------------------------------------------------------------------ |
| `id`       | `string`                                                                                             | —      | **必填**——占位的全部意义就在于被 id 引用                                                               |
| `position` | `[x, y] \| PolarPosition \| { direction, of, distance? } \| { of, offset } \| { between, fraction }` | —      | 占位点位置；与 `<Node position>` 完全一致；其中 id 依赖必须先登记，解析时序见[技术原理](#先登记再引用) |

## 相关

### 与 `<Node>` / `<Path>` 的关系

|                                 | `<Coordinate>` | `<Node>`       |
| ------------------------------- | -------------- | -------------- |
| 渲染图形                        | ❌             | ✅（按 shape） |
| 参与 layout bounds              | ❌             | ✅             |
| 进 nodeIndex                    | ✅             | ✅             |
| path target 引用                | ✅             | ✅             |
| 相对 / 偏移定位（`{ of }`）引用 | ✅             | ✅             |
| 必须有 `id`                     | ✅             | 可选           |

简单原则：需要画形状 + 文字 → `<Node>`；只要一个引用点 → `<Coordinate>`。

### 不适用场景

- **要给点配文字标签** → 用 `<Node>` 加 `label?`，coordinate 不带文字字段
- **要画一个圆点 / 标记位置** → 用 `<Node shape="circle">` + 小尺寸；coordinate 永远不画
- **anchor 指向**（`hub.top`）→ coordinate 的命名 / 角度 anchor 都退化为中心，要方向 anchor 用 `<Node>`

- [Node](/kernel/components/node/overview)：有形状和文字的节点
- [Draw](/kernel/components/draw/overview)：引用 coordinate id 的日常连线写法
