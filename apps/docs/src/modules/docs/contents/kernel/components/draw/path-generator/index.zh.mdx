路径生成器扩展的是**一段路径动作**。`<Step kind="generator">` 只保存生成器名称与 JSON 参数；宿主注入 `PathGeneratorDefinition` 后，core 再把这一段转换成普通路径命令，交回当前 Path kind 继续处理。

## 适用边界

当现有 `line`、`curve`、`cubic`、`bend`、`smooth` 与 `arc` 不能表达一种可复用的参数化曲线段时，再定义路径生成器。

| 需求                        | 选择                                              |
| --------------------------- | ------------------------------------------------- |
| 一次性二次或三次贝塞尔      | 现有 `curve` / `cubic`                            |
| 穿过一组点的平滑曲线        | 现有 `smooth`                                     |
| 新增可复用的参数化曲线段    | 路径生成器                                        |
| 改变整条 Path 的 Scene 输出 | [自定义路径](/kernel/components/draw/custom-path) |

生成器不拥有整条 Path 的描边、箭头、流带或变换；这些仍由宿主 Path 与当前 Path kind 负责。

## 定义能力

用 `definePathGenerator` 声明四件事：稳定名称、参数 schema、可选目标参数，以及如何从当前游标生成 `PathCommand[]`。

```tsx
const wave = definePathGenerator({
  name: 'wave',
  paramsSchema: z.strictObject({ amplitude: z.number().positive() }),
  generate: ({ from, to, params }) => {
    // 返回使用当前 Path 局部坐标的 move / line / quad / cubic / arc 等命令
  },
});
```

definition 是运行时能力，不进入 IR。IR 只保留 `name`、可选 `to` 与 JSON-safe `params`，因此图形数据仍可序列化、持久化和跨 adapter 传递。

## 注入宿主

React 通过 `<Layout pathGenerators>` 注入；直接调用 core 时使用 `CompileOptions.pathGenerators`。生成器名称随后写在 generator Step 上。

```tsx
<Layout pathGenerators={[wave]}>
  <Path>
    <Step kind="move" to="A" />
    <Step kind="generator" name="wave" to="B" params={{ amplitude: 12 }} />
  </Path>
</Layout>
```

## 执行机制

Core 默认不携带路径生成器。宿主注入的自定义生成器进入 registry，再按 Step 的 `name` 查找。compile 依次校验参数、解析声明过的目标字段、调用 `generate`，最后检查每条输出命令是否完整且坐标有限。

| 阶段     | 输入                        | 结果                            |
| -------- | --------------------------- | ------------------------------- |
| 合并     | 宿主注入的 definitions      | 统一名称 registry               |
| 校验     | `params` + `paramsSchema`   | JSON-safe 参数对象              |
| 解析目标 | `targetParams` 顶层字段     | 当前 Path 局部坐标              |
| 生成     | `from` / `to` / 参数 / 目标 | `PathCommand[]`                 |
| 回接     | 生成的命令                  | 当前 Path kind 继续编译整条路径 |

`targetParams` 只接受顶层 key。列入其中的字符串按节点 id 解析；嵌套对象或数组中的 Target 不会递归查找。生成器位于变换后的 Scope 中时，输入与输出仍使用当前 Path 的局部坐标，外层变换由 Scene 分组统一应用。

## 错误与限制

| 情况                            | 结果                                                      |
| ------------------------------- | --------------------------------------------------------- |
| 名称为空                        | `definePathGenerator` 立即拒绝                            |
| 与另一已注册项重名              | registry 合并时报重复注册                                 |
| Step 引用未注册名称             | 编译报错，并列出可用名称与注入入口                        |
| `paramsSchema` 拒绝参数         | 错误包含生成器名与对应 IR 路径                            |
| 参数解析后含函数、`NaN` 等      | JSON-safe 护栏拒绝                                        |
| `targetParams` 值不是 Target    | 编译指出具体字段                                          |
| `targetParams` 指向不存在的节点 | 对应 key 不写入 `resolvedTargets`；由 `generate` 处理缺省 |
| `generate` 抛错                 | 错误包装生成器名称并保留原始原因                          |
| 返回非数组、未知命令或无限坐标  | 输出校验拒绝，不让坏几何进入 Scene                        |

生成器可以返回 `move` 创建子路径，但不能直接返回 Scene primitive，也不能绕开当前 Path kind 的样式与装饰流程。

## API 参考

### PathGeneratorDefinition

| 字段           | 类型                          | 默认值 | 描述                                       |
| -------------- | ----------------------------- | ------ | ------------------------------------------ |
| `name`         | `string`                      | —      | registry key，也是 generator Step 的引用名 |
| `paramsSchema` | `ZodType<IRJsonObject>`       | —      | 校验实例参数；输出必须仍是 JSON 对象       |
| `targetParams` | `Array<string>`               | `[]`   | 需要预先解析为局部坐标的顶层参数 key       |
| `generate`     | `(ctx) => Array<PathCommand>` | —      | 根据局部上下文生成路径命令                 |

### generate 上下文

| 字段              | 类型                                     | 默认值 | 描述                                     |
| ----------------- | ---------------------------------------- | ------ | ---------------------------------------- |
| `from`            | `Position`                               | —      | 当前游标的局部坐标                       |
| `to`              | `Position`                               | —      | Step 的可选终点解析结果                  |
| `params`          | `PathGeneratorGenerateContext['params']` | —      | 经 schema 校验的参数                     |
| `resolvedTargets` | `Record<string, Position>`               | `{}`   | 成功解析的 `targetParams` key 与局部坐标 |
| `round`           | `(number) => number`                     | —      | 与 compile / render 一致的精度取整函数   |

### generator Step

| 属性     | 类型                        | 默认值 | 描述                          |
| -------- | --------------------------- | ------ | ----------------------------- |
| `kind`   | `'generator'`               | —      | 选择 generator Step           |
| `name`   | `string`                    | —      | 生成器 registry key           |
| `to`     | `IRGeneratorStep['to']`     | —      | 可选终点，解析后传给 `ctx.to` |
| `params` | `IRGeneratorStep['params']` | —      | 可序列化的实例参数            |
| `label`  | `IRGeneratorStep['label']`  | —      | 生成段的可选边标注            |
