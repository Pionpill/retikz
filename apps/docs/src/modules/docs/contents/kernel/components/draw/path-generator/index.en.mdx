A path generator extends **one path action**. `<Step kind="generator">` stores only a provider name and JSON parameters. After the host injects a `PathGeneratorDefinition`, core converts that segment into ordinary path commands and returns them to the current Path kind.

The runnable example below keeps the `sin` definition, `<Layout pathGenerators>` injection, and generator Step together. Open the code view to copy the complete loop.

## Applicability

Define a generator when the existing `line`, `curve`, `cubic`, `bend`, `smooth`, and `arc` actions cannot express a reusable parameterized segment.

| Need                                      | Choose                                              |
| ----------------------------------------- | --------------------------------------------------- |
| One quadratic or cubic Bezier             | Existing `curve` / `cubic`                          |
| A smooth curve through several points     | Existing `smooth`                                   |
| A reusable parameterized curve segment    | Path generator                                      |
| Different Scene output for the whole Path | [Custom Paths](/kernel/components/draw/custom-path) |

A generator does not own whole-path stroke, arrows, ribbons, or transforms. The host Path and its selected Path kind still own those concerns.

## Define the capability

Use `definePathGenerator` to declare a stable name, a parameter schema, optional target parameters, and a function that generates `PathCommand[]` from the current cursor.

```tsx
const wave = definePathGenerator({
  name: 'wave',
  paramsSchema: z.strictObject({ amplitude: z.number().positive() }),
  generate: ({ from, to, params }) => {
    // Return move / line / quad / cubic / arc commands in Path-local coordinates.
  },
});
```

The definition is runtime capability and never enters IR. IR keeps only `name`, optional `to`, and JSON-safe `params`, so diagram data remains serializable, persistable, and portable across adapters.

## Inject into the host

React injects definitions through `<Layout pathGenerators>`; direct core calls use `CompileOptions.pathGenerators`. A generator Step then references the registered name.

```tsx
<Layout pathGenerators={[wave]}>
  <Path>
    <Step kind="move" to="A" />
    <Step kind="generator" name="wave" to="B" params={{ amplitude: 12 }} />
  </Path>
</Layout>
```

`parabola` is an optional generator supplied by Standard. It resolves `params.control` as a target and emits one quadratic Bezier command. Import its Definition from `@retikz/standard/path-generator` and pass it to the current `<Layout>`:

```tsx
import { ParabolaPathGeneratorDefinition } from '@retikz/standard/path-generator';

<Layout pathGenerators={[ParabolaPathGeneratorDefinition]}>{/* generator Step */}</Layout>;
```

## Execution

Core carries no default path generators. Standard and custom definitions injected by the host enter one registry before lookup by the Step `name`. Compilation validates parameters, resolves declared target fields, invokes `generate`, and checks every output command for a complete shape and finite coordinates.

| Stage           | Input                            | Result                                        |
| --------------- | -------------------------------- | --------------------------------------------- |
| Merge           | Host-injected definitions        | One name registry                             |
| Validate        | `params` + `paramsSchema`        | JSON-safe parameter object                    |
| Resolve targets | Top-level `targetParams` keys    | Current Path-local coordinates                |
| Generate        | `from` / `to` / params / targets | `PathCommand[]`                               |
| Rejoin          | Generated commands               | The current Path kind compiles the whole path |

`targetParams` accepts top-level keys only. A listed string is resolved as a node id; Targets nested inside objects or arrays are not searched recursively. Inside a transformed Scope, inputs and outputs still use Path-local coordinates, while the outer Scene group applies the transform.

## Errors and limits

| Case                                     | Result                                                                    |
| ---------------------------------------- | ------------------------------------------------------------------------- |
| Empty name                               | `definePathGenerator` rejects it immediately                              |
| Duplicate registered name                | Registry merge reports a duplicate registration                           |
| Step references an unknown name          | Compile lists available names and the injection option                    |
| `paramsSchema` rejects input             | Error includes provider name and the relevant IR path                     |
| Parsed params contain functions/`NaN`    | The JSON-safe guard rejects them                                          |
| A `targetParams` value is not a Target   | Compile identifies the offending key                                      |
| A `targetParams` node id cannot resolve  | Its key is omitted from `resolvedTargets`; `generate` handles the absence |
| `generate` throws                        | Error wraps the generator name and preserves the cause                    |
| Non-array, unknown, or non-finite output | Output validation prevents invalid geometry entering Scene                |

A generator may return `move` commands to create subpaths, but it cannot return Scene primitives or bypass the current Path kind's style and decoration pipeline.

## API Reference

### PathGeneratorDefinition

| Field          | Type                          | Default | Description                                            |
| -------------- | ----------------------------- | ------- | ------------------------------------------------------ |
| `name`         | `string`                      | —       | Registry key and generator Step reference              |
| `paramsSchema` | `ZodType<IRJsonObject>`       | —       | Validates instance parameters; output must remain JSON |
| `targetParams` | `Array<string>`               | `[]`    | Top-level parameter keys resolved to local coordinates |
| `generate`     | `(ctx) => Array<PathCommand>` | —       | Generates commands from the local context              |

### Generate context

| Field             | Type                                     | Default | Description                                                     |
| ----------------- | ---------------------------------------- | ------- | --------------------------------------------------------------- |
| `from`            | `Position`                               | —       | Current cursor in Path-local coordinates                        |
| `to`              | `Position`                               | —       | Optional resolved Step endpoint                                 |
| `params`          | `PathGeneratorGenerateContext['params']` | —       | Schema-validated parameters                                     |
| `resolvedTargets` | `Record<string, Position>`               | `{}`    | Successfully resolved `targetParams` keys and local coordinates |
| `round`           | `(number) => number`                     | —       | Compile/render precision rounding function                      |

### Generator Step

| Prop     | Type                        | Default | Description                                |
| -------- | --------------------------- | ------- | ------------------------------------------ |
| `kind`   | `'generator'`               | —       | Selects the generator action               |
| `name`   | `string`                    | —       | Generator registry key                     |
| `to`     | `IRGeneratorStep['to']`     | —       | Optional endpoint passed as `ctx.to`       |
| `params` | `IRGeneratorStep['params']` | —       | Serializable instance parameters           |
| `label`  | `IRGeneratorStep['label']`  | —       | Optional edge label for the generated span |
