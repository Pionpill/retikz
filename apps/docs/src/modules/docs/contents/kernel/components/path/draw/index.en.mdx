`way` is the core of `<Draw>`: targets decide where the path goes, fold and curve operators decide how neighboring targets connect, `DrawWay.Cycle` closes the path, and relative coordinates change the target's evaluation base.

Think of `way` as a tiny path language: targets produce points, `'-|'` / `'|-'` rewrite the segment between neighboring points, `{ label }` decorates the next segment, `{ curve }` / `{ cubic }` / `{ bend }` consume the next item to make a curve, and `{ arc }` / `{ circle }` / `{ ellipse }` draw around the previous point without consuming the next item.

## Target Forms

One `way` can mix target forms. Choose one based on where the position comes from:

- **Node reference**: `'a'` points to an existing node. The line follows the node and attaches to its boundary.
- **Cartesian coordinate**: `[120, 0]` gives a fixed position that does not depend on another node.
- **Polar coordinate**: `{ origin: 'a', angle: 60, radius: 80 }` places a point by angle and distance from an origin, which is useful for arranging points around a node.
- **Structured target**: `{ id: 'a', anchor: 'top' }` selects a node anchor or a boundary position when the line needs a precise landing point.

## Single-axis connections

`{ horizontalTo }` connects only to the target x, while `{ verticalTo }` connects only to the target y. Each emits one `axis-line` Step, unlike the two segments produced by `-\|` / `\|-`. Directions use the current Scope's local axes.

```tsx
<Draw way={[[0, 0], { horizontalTo: [100, 60] }]} />
<Draw way={[[0, 0], { verticalTo: [100, 60] }]} />
```

<ComponentPreview files="axis-line" size="sm" />

The operator value accepts only Cartesian coordinates, NodeTarget, or their string shorthand. `parseWay` rejects relative, polar, offset, and between targets, as well as objects containing multiple Way operators.

## Folds

Switch among four fold directions and watch the blue path pass through one or two orthogonal corners. In `-\|-` / `\|-\|` modes, `fraction` moves the middle leg through `0..1` and defaults to `0.5`; the gray dotted line only marks the direct endpoint connection.

<Comparison target="tikz" title="Fold Syntax">

`'-|'` / `'|-'` follow the two-leg TikZ path syntax `(A) -| (B)` / `(A) |- (B)`. `'-|-'` / `'|-|'` add the common three-leg flowchart form. Bare tokens use the midpoint; `{ via: '-|-', fraction: 0.3 }` positions the middle leg explicitly.

## Relative coordinates

Both paths first move right by `[60, 0]`, then use the control-panel offset `[x, y]` for the second segment. The difference is not where the first segment is drawn, but whether its endpoint becomes the internal cursor:

- **Blue `+`**: The first segment is drawn, but the cursor stays at the start. The second segment is still calculated from the `+` box, so its endpoint is “start + `[x, y]`” without adding the earlier `[60, 0]`.
- **Orange `++`**: The first segment moves the cursor to the hollow dot. The second segment continues from that dot, so its endpoint is “start + `[60, 0]` + `[x, y]`”.
- The gray dotted right-angle guides show the base for the second calculation: the upper one starts at the `+` box, and the lower one starts at the orange hollow dot. Solid dots are the final endpoints.
