Start with [Basic usage](/kernel/components/layout/usage). Use the options below when you need themes for composites, custom shapes, geometry results outside the figure, or control over updates. These examples focus on React `<Layout>` props and callbacks.

## Theme configuration

`theme` selects the theme for descendant Composites (compound components); it does not automatically style ordinary Node / Path primitives. Use each primitive's `style` and `rootScope` for figure-wide defaults. Switch the theme and color mode in the panel to observe color changes on the same card; its position and dimensions stay fixed.

## Capability injection

Pass extension definitions by capability through `Layout.extensions`. `shapes` is one category: the `ShapeDefinition` below supplies the folded file's footprint, connection boundary, and emitted primitives, then registers through `extensions={{ shapes: [fileShape] }}`. Both Nodes reference the registered `drawio-file` name, and the connector ends on the custom outline.

<ComponentPreview files={['layout-shape-injection', 'layout-file-shape.ts']} size="sm" />

`extensions` also supports connection boundaries (`boundaries`), clipping regions (`clips`), arrows (`arrows`), patterns (`patterns`), path definitions (`paths`), composites (`composites`), and themes (`themeDefinitions`). These definitions enter their respective registries through `extensions` and are consumed during compilation.

This section demonstrates shape injection only; later custom-usage guides for each topic explain how to define and use the other capabilities. See the [API reference](/kernel/components/layout/reference) for the complete fields.

## Reading compile artifacts

Use `onArtifacts` to read domain artifacts returned by composites, such as the container and item layout of FlexLayout. Artifacts are collected automatically. The callback runs after React commits, and later updates leave previous snapshots unchanged.

<ComponentPreview files="layout-artifacts" size="xs" />

The example displays the artifact count and the FlexLayout domain value outside the drawing. Each component defines its fields and coordinate semantics; ordinary nodes do not produce separate layout artifacts.

## Execution modes and update strategies

Layout passes `reconciler` to Vanilla. The default `full` mode does not retain an incremental cache; `incremental` retains the cache and supports batch update strategies. In either mode, new JSX or complete IR goes through `replace` and is compiled in full. Layout does not infer a batch from changed props.

```tsx
<Layout />
<Layout reconciler={{ mode: 'incremental', updateStrategy: 'auto' }} />
<Layout onDiagnostic={diagnostic => console.warn(diagnostic.message)} />
```

If replacing the input fails, the last successful result stays visible. Both modes deliver structured diagnostics through `onDiagnostic`.

## Additional notes

- **Root Scope**: Omitting `rootScope.defaults` leaves the children unwrapped. Passing even an empty defaults object creates a root Scope.
- **Host styles**: `Layout.style` always means host CSS. See [Basic usage](/kernel/components/layout/usage#whole-figure-defaults) for whole-figure primitive defaults.
