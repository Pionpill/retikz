## 用法

```tsx
import { Node } from '@retikz/react';
```

```tsx
<Node id="a" position={[0, 0]}>
  Label
</Node>
```

需要可见主体、文字或真实边界时使用 Node；只需要一个不可见引用点时使用 [Coordinate](/kernel/components/node/coordinate)。

## 例子

### 基础

<ComponentPreview files="node-basic" size="xs" />

一个 Node 把位置、内容与形状边界收在同一声明里。流程图节点通常只需默认矩形；纯文字可去掉 `stroke` / `fill`；需要稳定尺寸时再加 `minimumSize`。

### 定位

`position` 的五种中心 / 点定位写法包括笛卡尔、极坐标、方向相对、引用点偏移和两点比例位置。用面板切换输入形态并调整参数，观察同一个 `q` 如何围绕固定参照节点 `a` / `b` 移动。

<ComponentPreview files="node-position" size="md" />

引用 id 必须先声明；方向定位的默认距离来自 `<Layout nodeDistance>`，`between` 的 `fraction: 0.5` 表示中点。完整输入类型见下方 [API 参考](#定位)，需要不可见辅助点时使用 [Coordinate](/kernel/components/node/coordinate)。

Node 还支持第六种、依赖自身真实尺寸的锚点对齐。用面板切换双方标准 anchor，并调整 offset、目标 margin、两端 rotate 与当前 Node scale；非对称 padding 和这些几何参数都会先参与布局。

`target.anchor` 与 `selfAnchor` 都省略时默认为 `center`。target 只能引用已完成布局的 Node、Coordinate 或 Scope；未定义、后定义、自引用和仍在布局中的祖先 Scope 会直接报错。

### 形状

节点的视觉轮廓和连线端点分三层控制：`shape` 选择画出来的形状，`boundary` 选择自动贴边使用的连接面，path 端点的 `anchor` 则指定一个命名连接点。分别修改 A / B，观察同一条边如何落到两端。

<ComponentPreview files={['node-shape-connection', 'node-shape-connection-boundary.ts']} size="md" />

`anchor` 省略时，连线朝另一个端点自动贴边；标准命名 anchor（如 `top` / `right`）按 `boundary` 解析。`center` 会直接连到节点中心。形状专属 anchor 仍属于视觉 `shape`，具体名称见对应形状页。

`shape` 有两种写法：无必填参数的形状可用裸字符串；`polygon` / `sector` / `star` 等带参形状必须写成 `{ type, params }`。Core 默认提供 `rectangle` / `ellipse` / `polygon`，并把 `circle` / `diamond` 作为基础 preset；`sector` / `star` 等可选 Node shape 需先通过 `<Layout shapes>` 或 `CompileOptions.shapes` 注入。按尺寸来源，它们又分为包住「文字 + padding」的文本容器形状，以及由半径 / 角度决定尺寸的几何形状。Sector 的 `innerRadius === outerRadius` 状态就是开放弧。

每种形状的参数和专属 anchor 见对应页面：

| shape             | 写法                                       | 文档                                                         |
| ----------------- | ------------------------------------------ | ------------------------------------------------------------ |
| rectangle         | 默认 / `'rectangle'`                       | [Rectangle](/kernel/components/shapes/rectangle)             |
| circle / ellipse  | `'circle'` / `'ellipse'`                   | [Circle / Ellipse](/kernel/components/shapes/circle-ellipse) |
| sector            | `{ type:'sector', params }`                | [Arc / Sector](/kernel/components/shapes/arc-sector)         |
| polygon / diamond | `{ type:'polygon', params }` / `'diamond'` | [Polygon](/kernel/components/shapes/polygon)                 |
| star              | `{ type:'star', params }`                  | [Star](/kernel/components/shapes/star)                       |

`shape` 也接受经 `<Layout shapes>` / `CompileOptions.shapes` 注册的名称，带参注册形状继续用 `{ type, params }`。详情见 [自定义形状](/kernel/components/shapes/custom-shape)。

`boundary` 默认为 `'shape'`，也可选 `'circle'` / `'rectangle'` / `'ellipse'` 或注册的连接面。它只改变自动端点与标准 anchor 的解析，不改节点占位和视觉轮廓。三个内置替代面都支持 `{ fit, gap }`：`fit: 'tight'`（默认）按视觉形状提供的安全包络尽量贴近，`fit: 'bounds'` 则包住视觉 AABB；`gap` 再向外（正数）或向内（负数）调整半径 / 半轴。矩形的两种 `fit` 结果相同。

在 playground 中切换 A / B 的 `fit` 并拖动 `gap`，浅色点状轮廓就是实际连接面。负 `gap` 允许穿过视觉形状，但通常会让连线盖住节点，不推荐；若它把任一有效半轴压到 0 或以下，编译会直接报错。单条边也可在端点对象中覆盖节点默认值，注册方式见 [自定义连接面](/kernel/components/node/custom-boundary)，端点写法见 [Path](/kernel/components/draw/path)。

### 尺寸与变换

尺寸与变换采用同一套节点几何：padding 撑开内容盒，minimumSize 设置下限，scale / rotate 再改变最终边界；margin 不改节点外观，只让连线提前停下。用面板调整同一个 `q`，连接线提供边界参照。

- 内边距：`padding={N}` 或 `padding={{ default, x, y, left, right, top, bottom }}`
- 外边距：`margin={N}` 或 `margin={{ default, x, y, left, right, top, bottom }}`
- `cornerRadius`——圆角半径。`rectangle` / `polygon` / `star` / `sector` 支持圆角（`ellipse` 等不支持），写在形状 params 里：`shape={{ type:'polygon', params:{ sides:6, cornerRadius:8 } }}`、`star` / `sector` / `rectangle` 同理。顶层 `cornerRadius` 只对 `rectangle` 形状生效（默认或显式 `'rectangle'` 都算），且仅在 params 未显式给 `cornerRadius` 时合入；两者并存时 params 优先
- `minimumSize`——撑开 bbox（不缩水 text 自然宽度）
- `scale`——均匀 / 分轴缩放，影响 bbox + 字号 + padding + 路径附着点
- `rotate`——绕节点中心旋转，连线跟随旋转后的边界贴附

### 文本

在面板里直接输入多行内容；换行符形成硬分行，第 1、2、3 行及以后可分别调整颜色、强调方式与透明度。`shape`、`align`、`lineHeight` 和 `maxTextWidth` 也在同一场景比较，节点位置与取景保持不变。

<ComponentPreview files="node-text" size="lg" />

- `text` 接字符串或 LineSpec 数组；字符串里的 `'\n'` 是硬换行，数组则让每行拥有独立样式
- `align` 控制多行块内的水平对齐，`lineHeight` 控制行距；两者都是块级属性
- `maxTextWidth` 是折行阈值，不是固定段落宽；西文按词、CJK 按字折行，不可断长词会整体溢出
- 每行可覆盖 `fill` / `opacity` / `font`，也可以用 [`<Text>` 子元素](/kernel/components/node/text)表达相同结构
- 多行内容换到不同 `shape` 后，外接边界继续遵循各形状自己的外接规则

`text` prop 优先于 `children`；二者同时提供时使用 `text`。块级 `font` 是 `{ family?, size?, weight?, style? }`，其它通用视觉属性可在本页末尾的[样式 playground](#样式)调整。

#### 自动黑白对比色

把 `textColor` 设为 `NodeTextColor.Contrast`，Core 会根据 Node 最终的静态不透明 `fill` 选择对比度更高的纯黑或纯白。关键字在样式级联后按每个 Node 独立解析，因此也可以放进 `Scope.nodeDefault`。

<ComponentPreview files="node-auto-contrast" size="sm" />

```tsx
import { NodeTextColor } from '@retikz/core';

<Node fill="#1e293b" textColor={NodeTextColor.Contrast}>
  Status
</Node>;
```

- Core 静态支持 CSS named color、3/4/6/8 位 hex，以及 legacy / modern `rgb()`、`hsl()`；不读取 DOM、主题变量或页面像素
- 透明 / 缺省 fill、`fillOpacity < 1`、gradient、pattern、image、`var()`、`currentColor` 等无法闭合求值的背景使用固定 `currentColor` fallback，并发出 `TEXT_AUTO_CONTRAST_UNRESOLVED`
- 行 / run 的 `fill`、label 的显式颜色和 `labelDefault` 仍优先；关键字只影响最终继承 Node 文字颜色的正文、label 与 pin

### 节点标签

`label` 在节点边界附加额外文字。单对象或数组形态；`position` 接 8 方向枚举（缺省 `'top'`）、`'center'`、数字角度，或 `{ boundary, fraction }` 这种边界比例点；`placement` 控制标签在附着点外侧还是内侧，默认 `'outside'`；`'center'` 会把 label 直接画在节点中心，不做重叠避让；`font` / `textColor` 缺省时从 node 继承，`opacity` 可单独控制标签透明度（0~1，与 node `opacity` 相乘）。

下面的 playground 聚焦一个标签，统一尝试命名方位、数字角度、边界比例、内外侧、朝向、文字样式与引线。

<ComponentPreview files="node-label" size="md" />

需要同时附加多个标签时，把同一份对象写法放进数组：

```tsx
<Node
  label={[
    { text: 'status', position: 'top' },
    { text: 'owner', position: 'bottom' },
  ]}
/>
```

`distance` 是节点边界与**旋转后标签视觉框**之间沿摆放方向的净距，省略时默认为 `12`；写 `0` 时视觉框恰好贴住边界。`placement: 'inside'` 会把方向转向节点内部，并在边界内侧保留同样的净距；矩形节点还可以写 `position: { boundary, fraction }`，把标签附着到某条边界的比例位置上。`position: 'center'` 始终使用最终节点矩形中心，会忽略 `placement` 与 `distance`。

- `boundary` 接 `'top'` / `'right'` / `'bottom'` / `'left'`
- `fraction` 是边界上的 0..1 比例位置，缺省 `0.5`
- `placement: 'inside'` 不能和 `pin` 同时使用；需要引线时请保持外侧标签

`label.rotate` 让标签文字绕**自身中心**自旋：`'radial'` 沿 `position` 定义的方向，边界比例位置使用所选边的外法向；`'tangent'` 取其切向（radial + 90°），数字为显式角度（度）。`placement: 'inside'` 只反转标签偏移，不反转该朝向；`keepUpright` 在文字会倒置时翻 180° 保持可读。旋转会改变视觉框沿摆放方向的投影，所以编译器会相应移动标签中心，保证 `distance` 仍是同一个净距。

`label.pin` 给标签加一条**引线**连回节点边界：`pin: true` 是默认细实线（继承标签色）；`pin: { stroke, strokeWidth, dashPattern, dashOffset }` 自定义引线样式；不写 / `false` 则无引线。引线终点是摆放射线与旋转后视觉框的精确交点，没有额外隐藏留白；标签摆放仍只由前述盒几何决定。

### 从属性到可引用节点

编译器先把样式继承后的 `position`、内容与几何 props 收敛成一份 Node 布局。它同时服务两条输出：形状、文字与标签变成 Scene 图元；`id`、锚点和连接面变成 `<Path>` / `<Draw>` 可以查询的命名几何。

<ComponentPreview files="node-layout-flow" size="md" hideCode />

节点尺寸按固定顺序收敛：文本先测量与折行，`padding` 再形成内容内框，shape definition 根据内框与 params 算出视觉外接盒，`minimumSize` 只负责托底。`scale` 从前面开始同步影响字体、间距和形状参数，`rotate` 最后附着到几何结果。

锚点对齐在这份 provisional 布局完成后才计算目标与自身 anchor，再整体平移 Node。opt-in `nodeLayout` artifact、id 注册、Scene 输出、Scope bbox 与自动 viewBox 都只会看到平移后的最终几何。

`label` 不参与视觉形状尺寸计算，而是作为附属图元单独布局；它不会撑大节点边框，但会与 `margin`、阴影一起进入自动 viewBox 的内容范围。编译器先在一个测量阶段收敛标签视觉框，再用最终节点矩形、标签旋转视觉框与 `distance` 求中心偏移，不会因矩形完成而重新测量；同一份盒几何同时决定文字基线、pin 终点与 viewBox。`Node.scale` 不缩放 `distance` 这个用户单位值，外层 `Scope` transform 则会连同节点、标签与间距一起变换。

### 视觉形状与连接几何

`shape` 决定画出来的轮廓，也拥有形状专属锚点；`boundary` 则只在解析自动连线端点、标准方位锚点和数字角度锚点时参与。`boundary` 省略或写成 `'shape'` 时，两条几何路径才重合。

| 引用方式                        | 实际采用的几何              |
| ------------------------------- | --------------------------- |
| 自动连线、`.top`、`.30`         | `boundary`，再外扩 `margin` |
| 形状专属锚点（如 `tip-0`）      | 视觉 `shape`                |
| `{ side, fraction }` 边上比例点 | 视觉 `shape`                |

因此，`margin` 会外推连接端点与标准 border anchor，并扩大节点布局占位，却不会重画视觉形状。形状专属锚点与边上比例点保持在原轮廓上；某个 shape 没实现标准方位锚点时，core 会回退到它的外接矩形。

规则连接面先按 `fit` 求矩形，再应用 `gap`；自动端点、数字角度和标准命名 anchor 会共享这一结果。Core 的 ellipse / polygon，以及已注入的 star / contour，都会提供 shape-aware `tight` 包络；rectangle 的 `tight` 与 `bounds` 一致，已注入的 Sector 按 bounds 处理。自定义 shape 若未实现 `connectionEnvelope`，`tight` 会安全回退到 bounds，并产生一次结构化 warning。

### 命名引用为何受顺序影响

Node 定位是在遍历到该节点时立即解析的：编译器先查询当前命名空间，得到布局后才注册这个节点的 `id`。所以 `position` 引用同一作用域里后声明的 Node / Coordinate / Scope 会失败，循环定位也无法成立。锚点定位可以引用前面已闭合的 Scope；若在 Scope 子树里引用仍在计算 bbox 的祖先 Scope，则会被识别为未完成布局并直接报错。已闭合的空 Scope 虽然是 0×0，仍是合法 target。

Path / Draw 的端点采用另一种时机。路径先保留绘制顺序占位，等当前作用域的 Node 与 Coordinate 都注册完成后再统一解析，因此路径端点可以引用后声明的同级节点。

### 定位

| 属性       | 类型                    | 默认值 | 描述                                                                                                                             |
| ---------- | ----------------------- | ------ | -------------------------------------------------------------------------------------------------------------------------------- |
| `position` | `NodeProps['position']` | —      | 前五种直接确定中心 / 点位置；`IRAnchorPosition` 在自身布局完成后把 `selfAnchor` 对齐到已完成 target 的 anchor，双方默认 `center` |

| 属性           | 类型                                                                                                                                                                                       | 默认值        | 描述                                                                                                                                                                                                                                                                                                                                                                                       |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `shape`        | <ApiValues name="BuiltinShape" /> \| `string` \| `IRShapeRef`                                                                                                                              | `'rectangle'` | 节点形状：Core 内置值是 `rectangle` / `circle` / `ellipse` / `diamond`，其中后两者分别是 ellipse / polygon 的 preset；`polygon` 或任意带必填参数的已注册形状（如 Standard `sector` / `star`）必须用 `{ type, params }`（裸字符串会编译期抛错）。可选与自定义形状经 `<Layout shapes>` / `CompileOptions.shapes` 注册                                                                        |
| `boundary`     | `IRBoundary`                                                                                                                                                                               | `'shape'`     | 连接面：边在此节点如何贴边、标准方位锚点如何解析，独立于视觉 `shape`。内置规则面参数为 `{ fit?: 'tight' \| 'bounds', gap?: number }`，默认 `{ fit:'tight', gap:0 }`；`gap` 有符号且必须有限，负值允许穿过视觉形状但不推荐，最终半轴必须大于 0。其它值先查自定义连接面，再 fallback 到已注册 shape 边界。不改节点占位；形状专属锚点与边上比例点仍走视觉形状。单条边可用端点 `boundary` 覆盖 |

| `margin`       | `number` \| `IRBoxSpacing`<br />- `default?: number`<br />- `x?: number`<br />- `y?: number`<br />- `left?: number`<br />- `right?: number`<br />- `top?: number`<br />- `bottom?: number` | `0`           | 边框外推距离<br />- 四边 fallback<br />- 左右 fallback<br />- 上下 fallback<br />- 左边<br />- 右边<br />- 上边<br />- 下边；边字段优先于轴字段，再优先于 `default`；作用于**所有 border 锚点**并计入布局占位 / viewBox                                                                                                                                                                    |

### margin 与 padding 的区别

|           | 影响什么             | 视觉表现                                                                 |
| --------- | -------------------- | ------------------------------------------------------------------------ |
| `padding` | 文字到 border 的距离 | 视觉形状变大                                                             |
| `margin`  | 连接面外的外偏移     | 视觉形状不变；所有 border 锚点与连线端点外移 margin，节点占位也含 margin |

`padding` 撑大节点本身；`margin` 不动视觉形状，而是把节点的连接/引用边界外推（含显式 `.top` 这类锚点），并让节点在布局里多占 margin 的空间。`margin` 缺省 0，不设则零影响。
