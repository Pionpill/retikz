把节点 A 从橙色改成蓝色，哪些工作需要重做？本文沿 Vanilla DOM 的 retained 更新追踪：Vanilla 准备输入，Reconciler 会话调用 Core 编译，Render 准备并提交画面，成功后才发布新结果。React 订阅处理结果后显示它，拥有不同的宿主提交边界。

阅读前先了解[渲染链路](/kernel/components/runtime-mechanics/rendering-pipeline)中的 IR、Scene 与包职责。单次编译见 [Core 编译流程](/kernel/packages/core/compilation)。

## 整体流程

本例包含具有唯一 id 的两个根节点 A、B。第二次输入只改变 A 的 `style.fill`，但仍提交包含 A、B 的完整文档。下面的布局仅用于并列比较改色前后的画面。

<ComponentPreview files="update-example" size="md" hideCode type="illustration" />

普通 React／Vanilla 输入更新走完整替换；Reconciler 的批次入口需要调用方提供当前基础元素树上的明确操作。两者都返回完整编译结果。是否复用元素编译状态、是否局部修改宿主，由不同层决定。

## 输入准备

React 将组件声明转换为 `InputScene`，Vanilla 再归一化为 `IRScene`；已有 IR 直接进入处理流程。`prepareProcessingInput` 同时整理编译配置和 Composite 输入。控制器持有 `ReconcilerSession`，初始化调用 `mount`，普通后续输入调用 `replace`。

这条链路不经过通用 Runtime 包的 Source／Computation 注册图。`replace` 显式重建编译结果，没有基于文档内容相等而跳过编译的保证。仅修改渲染配置时，控制器可调用 `updateTarget` 复用已有编译结果。

## 编译与复用

完整替换根据输入选择编译入口：基础元素构建 Weave 树，由 Core 单元素能力完成计算；含 Composite 的文档走 Core 完整准备路径，保留 probe、实例输入、artifacts 与空间句柄。

<ComponentPreview files="update-reuse" size="md" hideCode type="flow" />

Weave 保存输入、上下文、编译状态和依赖。`ReconcilerSession.update(batch, expected)` 可在已有基础元素树上应用 `WeaveBatch`；`expected` 必须是当前会话结果，旧结果会被拒绝。Composite 场景不支持该批次入口，空批次保留当前结果。

批次更新按最终输入重算受影响元素，复用仍有效的产物。上下文沿声明结构传递，失效沿依赖传播；Scope 变化可能使整个子树重算。名称索引和输出组装仍可能遍历整树，因此局部编译不等于整次更新只有局部成本。普通 React／Vanilla 输入更新尚未接入此批次入口。

## 宿主提交

Vanilla DOM 通过 `createRetainedRenderTarget` 把 renderer 接入会话输出目标，并将 `ProcessingResult` 的发布与宿主提交组合起来。目标准备新的 frame 和配置；编译结果变化时生成 `replaceScene`，仅配置更新时生成空操作 Patch。当前接线不会从完整结果差异自动生成逐图元 Patch。

Scene 快照根据编译 provenance 记录图元身份、owner 与拓扑，供 Render 验证和水合使用。这些身份不等于 Weave 批次中的节点地址，也不保证宿主进行局部更新。

React Layout 先订阅成功发布的 `ProcessingResult`，再构建宿主输出。Reconciler 输出目标的回滚保证不覆盖 React 自身的提交周期。

## 失败处理

准备阶段保留旧结果。会话先准备输出目标，再提交候选 Weave 状态和目标；两者成功后才发布新结果。完整替换使用新树，发布成功前不会替换旧树。

<ComponentPreview files="update-commit" size="lg" hideCode type="flow" />

提交失败时，会话先回滚目标，再恢复候选 Weave 状态。恢复成功后仍可读取旧结果；恢复失败则进入 broken 状态并禁止正常读写，需要释放会话。准备函数尚未返回提交 token 就失败时，由该函数负责清理自身已取得的资源。

发布后的告警回调、trace 或提交 token 清理失败记录为诊断，不撤销已发布版本。Vanilla 只通知成功发布的处理结果；React 更新失败时保留最后一次成功结果。
