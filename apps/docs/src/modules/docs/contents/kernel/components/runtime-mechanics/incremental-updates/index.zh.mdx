把节点 A 从橙色改成蓝色，哪些工作需要重做？本文沿 Vanilla DOM 的 retained 更新追踪：Vanilla 准备输入，Reconciler 会话组合 Core 原子阶段，Render 准备并提交画面，成功后才发布新结果。React 订阅处理结果后显示它，拥有不同的宿主提交边界。

阅读前先了解[渲染链路](/kernel/components/runtime-mechanics/rendering-pipeline)中的 IR、Scene 与包职责。单次编译见 [Core 编译流程](/kernel/packages/core/compilation)。

## 整体流程

本例包含具有唯一 id 的两个根节点 A、B。第二次输入只改变 A 的 `style.fill`，但仍提交包含 A、B 的完整文档。下面的布局仅用于并列比较改色前后的画面。

<ComponentPreview files="update-example" size="md" hideCode type="illustration" />

普通 React／Vanilla 输入更新走完整替换；Reconciler 的批次入口需要调用方提供当前基础元素树上的明确操作。两者都返回完整编译结果。是否复用元素编译状态、是否局部修改宿主，由不同层决定。

## 输入准备

React 将组件声明转换为 `InputScene`，Vanilla 再归一化为 `IRScene`；已有 IR 直接进入处理流程。`prepareProcessingInput` 同时整理编译配置和 Composite 输入。控制器持有 `SceneReconciler`，初始化调用 `mount`，普通后续输入调用 `replace`。

这条链路不经过通用 Runtime 包的 Source／Computation 注册图。`replace` 显式重建编译结果，没有基于文档内容相等而跳过编译的保证。仅修改渲染配置时，控制器可调用 `updateTarget` 复用已有编译结果。

## 编译与复用

一次性编译和完整替换由 Reconciler 的完整构建入口执行；批次更新由 Weave 选择需要计算的元素，再调用共享的 Core 阶段与输出组装能力。`incremental` 默认为 `true`，保留作者 Weave 树和实际阶段产物；设为 `false` 时不保留缓存，只允许 mount / replace，调用 update 会报错。配置类型以 `incremental` 为判别字段，`updateStrategy` 仅在增量模式下可配置，非法组合由 TypeScript 拒绝。`@retikz/reconciler` 同时导出 `FullSceneReconcilerOptions` 和 `IncrementalSceneReconcilerOptions`，可分别声明两种模式的配置。probe、实例输入和 artifacts 在两种模式下保持相同语义。

<ComponentPreview files="update-reuse" size="md" hideCode type="flow" />

Weave 保存输入、上下文、编译状态和依赖。`SceneReconciler.update(batch, expected)` 可在已有基础元素树上应用 `WeaveBatch`；`expected` 必须是当前会话结果，旧结果会被拒绝。含 Composite 的场景可以更新作者基础元素；生成节点不可寻址，修改 Composite 作者输入需 replace。auto 策略下空批次保留当前结果；full 策略强制重新计算，包括空批次。

会话结果只返回版本和编译产物。批次需要的作用域标识通过 `session.getScopeId(path, expected)` 查询：省略路径或传入 `[]` 获取根标识，`[1, 0]` 表示依次选择根的第二个子元素、该 Scope 的第一个子元素，每一步都必须是作者声明的 Scope。查询返回字符串，可用于 `scope`、`id`、`child` 三种目标的 `scopeId`，也可用于插入操作的 `parentId`。

查询仅允许在已挂载、空闲的增量会话中进行；`expected` 默认为当前结果，传入旧结果或其它会话的结果会报错。路径按当前已发布结构解释，不进入 Composite 生成内容。Scope 存续期间标识稳定，插入兄弟元素可能改变查询路径；删除 Scope 或完整替换场景后，旧标识失效。失败事务成功回滚后，原标识仍可使用。

生命周期由 `ReconcilerLifecyclePhase` 定义，包含挂载、更新和卸载；一批内容变化发生在更新阶段，其中 `WeaveOperationKind.Insert`、`Update` 和 `Remove` 分别表示插入、修改和删除。两个常量均可从 `@retikz/reconciler` 导入，内容操作的 payload 保持原有契约。

通过 `SceneReconciler` 的 `trace` 选项可观察这些阶段：首次成功发布结果报告 `mount`，包括直接调用 `replace()` 建立会话；已有结果后的完整替换、非空批次和强制全量更新报告 `update`。编译工作量仍按 `element-compile` 或 `scene-compile` 计数，auto 策略的空批次与仅更新输出目标不报告编译记录。已挂载会话成功清理后报告一次 `unmount`，使用 `ReconcilerTraceUnit.Session`（`session`）和 `outcome: 'dispose'`，计数为 `visited: 1`、`reused: 0`、`changed: 1`。清理失败时不报告成功，重试成功后补报；重复清理和未挂载会话的清理不报告卸载记录。trace 回调异常记录为诊断，不影响已完成的发布或清理。

批次更新从直接变化进入 Weave 的同步队列。计算完成后先比较实际产物，再通知直接消费者；消费者按自己读取的位置、锚点或边界确认是否需要重算。例如，节点改色不会使只读取连接几何的路径重算；文字改变但连接几何相同时，也能停止这条依赖分支。需要计算时，Weave 将仍有效的 Core 局部产物通过 prepared 传入，保留正文测量等独立结果。

内部的 <ApiSourceLink path="packages/kernel/reconciler/src/weave/schedule/queue.ts">`WeaveTaskQueue`</ApiSourceLink> 按稳定元素身份和就绪阶段合并任务。执行环境从候选节点及父 Scope 的准备结果取得，不靠遍历作者子树捕获。读取点需要生产者时，先完成其候选阶段，再继续消费者。Node、Coordinate 保留声明时的名称可见性，Path 使用所属环境闭合时的名称；调度顺序不会放宽前向引用。

Scope 先准备继承环境，再从子布局计算包络和最终投影，最后组装路径与分组输出。Composite 保留现有生成子树与隔离试算，生成名称先就绪，延迟 Path 随后完成。未变化元素复用输出贡献，Scope 不另存完整后代输出。名称索引和完整输出组装仍可扫描整树，因此局部计算不代表整次更新只有局部成本。普通 React／Vanilla 输入更新尚未接入此批次入口。

## 宿主提交

Vanilla DOM 通过 `createRetainedRenderTarget` 把 renderer 接入会话输出目标，并将 `ProcessingResult` 的发布与宿主提交组合起来。目标准备新的 frame 和配置；编译结果变化时生成 `replaceScene`，仅配置更新时生成空操作 Patch。当前接线不会从完整结果差异自动生成逐图元 Patch。

Scene 快照根据编译 provenance 记录图元身份、owner 与拓扑，供 Render 验证和水合使用。这些身份不等于 Weave 批次中的节点地址，也不保证宿主进行局部更新。

React Layout 先订阅成功发布的 `ProcessingResult`，再构建宿主输出。Reconciler 输出目标的回滚保证不覆盖 React 自身的提交周期。

## 失败处理

准备阶段保留旧结果。会话先准备输出目标，再提交候选 Weave 状态和目标；两者成功后才发布新结果。完整替换使用新树，发布成功前不会替换旧树。

<ComponentPreview files="update-commit" size="lg" hideCode type="flow" />

提交失败时，会话先回滚目标，再恢复候选 Weave 状态。恢复成功后仍可读取旧结果；恢复失败则进入 broken 状态并禁止正常读写，需要释放会话。准备函数尚未返回提交 token 就失败时，由该函数负责清理自身已取得的资源。

发布后的告警回调、trace 或提交 token 清理失败记录为诊断，不撤销已发布版本。Vanilla 只通知成功发布的处理结果；React 更新失败时保留最后一次成功结果。
