One drawing can be authored with React components, saved as JSON, and displayed by different backends. Design Philosophy explains why these entry points can cooperate and how new capabilities remain consistent. Familiarity with Basic Concepts and Core Concepts is enough for this overview; source folders and compiler functions are not prerequisites.

## Notation, declarations, and results

Node and Path are primitives. A composite retains high-level data and expands into primitives. Here, “object” is a general term for an entity in a drawing declaration, not another primitive type.

DSL means the notation used to author a drawing, such as JSX components or Vanilla function calls. IR is the savable declaration of objects, positions, and relationships. Scene is the compiled drawing result. A renderer executes that result to produce SVG or Canvas output.

Focus on IR and Scene in the figure: IR supports saving and editing, while Scene connects to rendering backends. Different authoring forms share these boundaries and therefore do not need separate geometry rules.

## Design choices in a bar chart

Suppose you want to save a bar chart. You could save the primitive for every bar, or retain a data array and chart settings that generate bars during compilation. The latter preserves the high-level intent that this object is a chart. It is a composite model that still reuses primitive layout and rendering.

If you only shorten a common path expression without retaining a new high-level object, that is Sugar. Both approaches can simplify authoring, but they retain different declarations; shorter code alone does not tell you which model applies.

Theme answers another question: how components share a style and color environment. Components that consume the theme translate it into primitive styles. Explicit Node / Path styles are not automatically replaced merely because a theme exists.

## Choose an entry for your design question

Start with Layers to understand shared data boundaries, then decide whether your question concerns authoring convenience, a high-level model, or shared styling. Architecture connects those choices to package responsibilities and helps identify which layer should implement them.

These pages explain why responsibilities are divided this way. Continue to [Internal mechanisms](/kernel/components/internals) when tracing a call, investigating measurements, or studying theme inheritance execution. Internal execution order is not a prerequisite for ordinary drawing.
