title: 自定义裁剪区
description: 为 Scope 定义新的 JSON-safe 裁剪形状，并在 React 或 Vanilla 宿主中注册后使用
---

当内置 `rect` 和 Standard 的 circle / ellipse / polygon / path / compound 都不满足需求时，用一个 `ClipDefinition` 定义新的裁剪形状。Definition 不进入 IR；IR 只保存 `kind` 和可序列化参数，渲染、可视边界与命中测试共享同一份 lowering 结果。

## 适用边界

前提是已会 [Scope 的基础裁剪用法](/kernel/components/scope/usage#裁剪与层级)。先判断现有能力能否表达需求：

| 需求                             | 选择                                                   |
| -------------------------------- | ------------------------------------------------------ |
| 一次性矩形                       | 直接写 Core 内置 `rect` clip spec                      |
| 圆、椭圆、多边形、路径或组合区域 | 从 [裁剪扩展](/library/standard/clip) 注入 Definition  |
| 新的静态二维裁剪                 | 定义一个完整 `ClipDefinition` 并降低为 `SceneClipPath` |
| renderer 专属 mask / filter 行为 | 不属于 Clip；另建明确的后端能力                        |

## 定义能力

将 Definition 放在可复用模块中，例如 `rounded-rect-clip.ts`。当 spec 本身已是完整 shape 时，只写 `schema` 与 `lower`：`defineClip` 会派生 `resolve: spec => spec`，并复用该 schema 作为 `shapeSchema`。需要将简写、引用或配置解析为另一种 shape 时，才显式提供 `resolve` 与 `shapeSchema`。`lower` 返回结构化路径，而不是 SVG 字符串或 Canvas callback。

```ts
import type { PathCommand } from '@retikz/core';
import { defineClip } from '@retikz/core';
import { z } from 'zod';

const roundedRectClipSchema = z.strictObject({
  kind: z.literal('rounded-rect'),
  x: z.number(),
  y: z.number(),
  width: z.number().positive(),
  height: z.number().positive(),
  radius: z.number().nonnegative(),
});
export const roundedRectClip = defineClip({
  kind: 'rounded-rect',
  schema: roundedRectClipSchema,
  lower: shape => {
    const right = shape.x + shape.width;
    const bottom = shape.y + shape.height;
    const radius = Math.min(shape.radius, shape.width / 2, shape.height / 2);
    const commands: Array<PathCommand> = [
      { kind: 'move', to: [shape.x + radius, shape.y] },
      { kind: 'line', to: [right - radius, shape.y] },
      { kind: 'quad', control: [right, shape.y], to: [right, shape.y + radius] },
      { kind: 'line', to: [right, bottom - radius] },
      { kind: 'quad', control: [right, bottom], to: [right - radius, bottom] },
      { kind: 'line', to: [shape.x + radius, bottom] },
      { kind: 'quad', control: [shape.x, bottom], to: [shape.x, bottom - radius] },
      { kind: 'line', to: [shape.x, shape.y + radius] },
      { kind: 'quad', control: [shape.x, shape.y], to: [shape.x + radius, shape.y] },
      { kind: 'close' },
    ];
    return { commands, fillRule: 'nonzero' };
  },
});
```

## 注入与使用

Definition 是 React 与 Vanilla 共用的运行时对象，不会写进保存的场景数据。选择宿主后，把它注册到 `clips`，再由 `Scope.clip.kind` 引用。

通过 `Layout.extensions.clips` 注册 Definition；`Scope` 只写可保存的 `kind` 和参数。

```tsx
import { Layout, Node, Scope } from '@retikz/react';
import { roundedRectClip } from './rounded-rect-clip';

const Demo = () => (
  <Layout extensions={{ clips: [roundedRectClip] }}>
    <Scope clip={{ kind: 'rounded-rect', x: -150, y: -72, width: 300, height: 144, radius: 36 }}>
      <Node
        position={[-88, -8]}
        shape="circle"
        style={{ fill: 'skyblue', stroke: 'none' }}
        layout={{ minimumSize: { width: 160, height: 160 } }}
      />
      <Node
        position={[84, 8]}
        shape="circle"
        style={{ fill: 'darkorange', stroke: 'none' }}
        layout={{ minimumSize: { width: 170, height: 170 } }}
      />
      <Node
        position={[0, 0]}
        text="custom clip"
        style={{ fill: 'dodgerblue', stroke: 'dodgerblue', strokeWidth: 2, textColor: 'contrast' }}
        layout={{ minimumSize: { width: 132, height: 42 } }}
      />
    </Scope>
    <Node
      position={[0, 80]}
      text="rounded-rect provider"
      style={{ fill: 'none', stroke: 'none', textColor: 'dodgerblue' }}
    />
  </Layout>
);
```

IR 面板中的 JSON 可直接作为 `ir` 传给 Core；仍要在编译时传入 Definition：

```ts
import { compileToScene } from '@retikz/core';
import { roundedRectClip } from './rounded-rect-clip';

const { scene } = compileToScene(ir, { clips: [roundedRectClip] });
```

provider graph 中的 `{ capability: 'clip', name: kind }` provider 同样产出完整 Definition，并与显式 `clips` 参与相同的冲突检查。

## 错误与限制

| 情况                                  | 结果                                                                                               |
| ------------------------------------- | -------------------------------------------------------------------------------------------------- |
| 重复 kind                             | registry 报 definition conflict，不覆盖已有项                                                      |
| 未注册的 `clip.kind`                  | 报 kind，并提示通过 Core `options.clips`、React `extensions.clips` 或 Vanilla `compile.clips` 注入 |
| definition / spec / shape kind 不一致 | 在 `lower` 前作为 provider contract violation 失败                                                 |
| spec 或 shape 不符合 schema           | 报 provider key、对应 schema 阶段与校验 cause                                                      |
| 递归超过 `maxClipDepth`               | 失败；resolve / lower 默认共享 32 条边预算                                                         |

复合 shape 会按 authored order 累积 child commands，并应用外层 `fillRule`；它不是几何交集。需要交集时使用嵌套 `<Scope clip>`。

完整的 registry 解析、shape snapshot、路径 canonicalization 与资源去重见 [Scope 实现原理](/kernel/components/scope/mechanism)。
