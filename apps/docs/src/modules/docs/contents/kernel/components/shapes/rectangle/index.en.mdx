The rectangle is the most common shape in retikz, with two faces: draw a rectangle outline with `<Rectangle>` (sugar), or just use `<Node>` — **a node is a rectangle by default**. See [Shapes](/kernel/components/shapes) for the full definition. Reach for sugar to draw a rectangle outline, and for `<Node>` to get a rectangular node (to hold text, to connect).

## As a Path shape (sugar)

`<Rectangle>` draws a rectangle at a position, expanding to an underlying `<Path>`. It fits cases where you know two corners, a center plus size, or one corner plus size.

### Usage

```tsx
import { Rectangle } from '@retikz/react';
```

```tsx
<Rectangle corner1={[-40, -20]} corner2={[40, 20]} cornerRadius={6} />
```

### Examples

`<Rectangle>` can use two corners, or derive the corners from a center and size. Use `cornerRadius` for rounded rectangles.

| Form                         | Best for               |
| ---------------------------- | ---------------------- |
| `{ corner1, corner2 }`       | Known opposite corners |
| `{ center, width, height }`  | Known center and size  |
| `{ center, side }`           | Square                 |
| `{ corner1, width, height }` | Expand from one corner |

Use the playground to vary width, height, and corner radius continuously. The gray dimension lines stay attached to the current boundary, making it clear when rounding starts to dominate the short side.

### API Reference

| Component     | Combination                    | Meaning                                              |
| ------------- | ------------------------------ | ---------------------------------------------------- |
| `<Rectangle>` | `corner1` + `corner2`          | Rectangle from two opposite corners                  |
|               | `center` + `width` + `height`  | Rectangle from center and size                       |
|               | `center` + `side`              | Square from center and side                          |
|               | `corner1` + `width` + `height` | Rectangle from one corner and size                   |
|               | + `cornerRadius?`              | Rounded rectangle (clamped to half the smaller side) |

This shape sugar also forwards the shared Path props, including `stroke`, `fill`, `opacity`, `animations`, and `onClick`. See [Path](/kernel/components/draw/path) for the full list and [Hydration](/kernel/packages/render/hydration) for how events are attached after rendering.

## As a node shape

A `<Node>` without a `shape` is a rectangle: the boundary wraps "text + padding" and is sized by the text content. Almost every flowchart node is this form.

### Usage

```tsx
import { Node } from '@retikz/react';
```

```tsx
<Node>label</Node>
<Node shape={{ type: 'rectangle', params: { cornerRadius: 10 } }}>rounded</Node>
```

### Examples

The playground fixes the target rectangle at the origin. Adjust `cornerRadius` to compare sharp and rounded boundaries, then move the source with the orbit angle and distance; automatic clipping lands on the real boundary, while named and numeric anchors provide stable explicit positions.

<ComponentPreview files="node-connection-playground" size="sm" />

Round corners with the top-level `cornerRadius`, or with `shape={{ type:'rectangle', params:{ cornerRadius } }}` (params win when both are present). See [Node geometry](/kernel/components/node/overview) for shared sizing, boundary, and anchor behavior.

### API Reference

| `shape`                 | Boundary                            | Parameters                      |
| ----------------------- | ----------------------------------- | ------------------------------- |
| omitted / `"rectangle"` | Inner box wrapping "text + padding" | `cornerRadius?` (corner radius) |

This section covers only how Rectangle produces a Path and how a rectangular Node gets a connectable boundary. See [Architecture Principles](/kernel/concepts/design/principles) for the complete JSX → IR → Scene pipeline.

### How sugar converges on a closed Path

`<Rectangle>` first converges its four prop forms on two opposite corners, `from` and `to`. The upper route in the figure passes through Targets (resolvable points, including coordinates and node ids); the lower route computes the corners from dimensions in the React layer:

<ComponentPreview files="rectangle-sugar-flow" size="lg" hideCode />

Only `corner1 + corner2` passes both Targets through unchanged, so it can reference node ids. Forms such as `center + width + height` need arithmetic first and accept only literal `[x, y]` coordinates. The `rectangle` step then resolves both corners and emits an independent closed subpath; `cornerRadius` replaces each corner with an arc and is clamped to half the shorter side.

If either node reference cannot be resolved, the whole Path is skipped with a warning instead of leaving a partial rectangle.

### How Node gets a connectable boundary

When `<Node>` omits `shape`, it selects `rectangle`. Text measurement and `padding` first form the inner content box, which the rectangle shape uses to produce both the visible outline and connection geometry:

<ComponentPreview files="rectangle-node-boundary" size="lg" hideCode />

A rectangle does not enlarge the half-axes when circumscribing the content, so its boundary wraps exactly around “text + padding.” The same `cornerRadius` participates in both drawing the rectangle and finding a boundary point toward a target. That is why a connection to a rounded node lands on the fillet arc rather than on the sharp corner that was rounded away.

The result of `<Rectangle>` is pure Path geometry. A rectangular `<Node>` retains its id, directional anchors, and boundary-intersection behavior; use `<Node>` when the rectangle needs to hold text and connect.
