## 用法

```tsx
import { Path, Step } from '@retikz/react';
```

```tsx
<Path stroke="currentColor">
  <Step kind="move" to="a" />
  <Step kind="line" to="b" />
</Path>
```

`<Draw>` 编译后就是 `<Path>`，覆盖日常连线的 step / 折角 / 曲线 / 弧形需求；但 `<Path>` 还多出 `color` / `rotate` / `scale` / `marks` / `id` / `meta` / `animations` 等元素级能力，`<Draw>` 不暴露这些。日常连线用 `<Draw>` 一行 way 数组更省，需要显式 Step 序列、多次 `move`、逐段混用 `kind` / label / 控制点，或要用上述 Path 专属能力时用 `<Path>`：

|                                                                       | `<Draw>`      | `<Path>` + `<Step>`        |
| --------------------------------------------------------------------- | ------------- | -------------------------- |
| 写法                                                                  | 一行 way 数组 | 容器 + 子节点              |
| step / 曲线 / 折角 / 弧形                                             | 支持          | 支持                       |
| `color` / `rotate` / `scale` / `marks` / `id` / `meta` / `animations` | 不暴露        | 支持                       |
| 适用                                                                  | 90% 连线场景  | 显式 Step 序列、元素级能力 |

### Path 与 Step

`<Path>` 必须搭配 `<Step>` 子节点（至少 2 个）；首个非 `move` 时编译器会强制改成 `move`：

```tsx
<Path>
  <Step kind="move" to={...} />     {/* 第 1 个：必为 move */}
  <Step kind="line" to={...} />     {/* 之后任意多个 line / move / step */}
  ...
</Path>
```

`<Step>` 支持 13 种 kind——`move` / `line` 处理直线，`fold` 走直角折角，`cycle` 闭合回起点，`curve` / `cubic` 画贝塞尔曲线，`bend` 是弧形简记（可带 out/in 角与自环），`smooth` 画穿过点列的平滑曲线，`generator` 调用内置或自定义路径生成器，`arc` / `circlePath` / `ellipsePath` 以游标为圆心画弧 / 整圆 / 整椭圆，`rectangle` 画对角矩形，详见 [Step](/kernel/components/draw/step) 与 [路径生成器](/kernel/components/draw/path-generator)。

## 例子

### 基础结构

在一个面板中比较折线、多子路径与闭合填充三种 Path 组合。多次 `move` 会抬笔并从新位置开始独立子路径；填充示例用 `cycle` 对应的 `Z` 闭合轮廓。折角与单独的闭合操作见 [Way](/kernel/components/draw/way)，本面板只承担 Path 容器层的结构差异。

### 端点与连接

#### 箭头

`arrow` 控制方向（`'->'` / `'<-'` / `'<->'` / `'none'`），`arrowDetail` 一个对象统管全部视觉规格（shape / scale / length / width / color / fill / opacity / lineWidth）+ 可选 `start` / `end` 起末分别配置。详细规则、8 种内置 shape、起末 merge、颜色 / 缩放 / 半透明配置以及完整 API 参考见 **[Arrow](/kernel/components/draw/arrow)** 专页。

#### 端点连接面

端点引用节点时（`{ id }` 对象形态，或 way 里的 id），可加 `boundary` 字段，**只对这一个端点**覆盖目标节点的 [`boundary`](/kernel/components/node/overview#视觉形状与连接几何)（连接面）。取值与节点 `boundary` 同形：`'shape'`（视觉形状自身）/ `'circle'`（真圆）/ 任意注册 shape 名 / `{ type, params }`。

```tsx
<Path arrow="->">
  <Step kind="move" to="a" />
  <Step kind="line" to={{ id: 'star', boundary: { type: 'circle', params: { fit: 'tight', gap: 8 } } }} />
</Path>
```

`circle` / `rectangle` / `ellipse` 共用 `fit: 'tight' | 'bounds'` 与有符号 `gap`；默认是贴合形状的 `tight` 与 `gap: 0`。`rectangle` 的两种 fit 结果一致；负 gap 可向内收缩，但可能穿过视觉形状。

`boundary` 只在"连接面有意义"的地方生效：端点自动贴边（未显式给 `anchor`）以及该端点的标准方位 / 角度锚点。在没有方向引用的场合——`between` 端点、`offset` 的 `of`、节点中心——它是 no-op。节点默认连接面写在 [`<Node boundary>`](/kernel/components/node/overview#视觉形状与连接几何)，端点 `boundary` 是单边覆盖。

下例的五角星未设置节点 `boundary`。面板默认展示圆形连接面，可直接比较 `tight` / `bounds` 并调整 `gap`；切回星形轮廓可对照真实形状连接面。浅灰虚点线是当前圆形连接面，会与真实端点一起更新。

### 样式

`strokeWidth` 可直接给数值；`thickness` 则提供 `ultraThin` 到 `ultraThick` 的语义档位，且显式 `strokeWidth` 优先。`dashOffset` 只移动虚线节奏的起点。`lineCap` / `lineJoin` 分别控制端点与拐点，`opacity` / `fillOpacity` / `strokeOpacity` 是可叠加的三个透明度通道。

<ComponentPreview files="path-style" size="sm" />

#### 渐变描边

`stroke` 除纯色字符串外还接 `IRPaintSpec`。线性 / 径向渐变、pattern、image 会进入同一份 paint 资源表；`dashPattern`、`dashOffset`、`lineCap`、`strokeOpacity` 等描边样式照常作用在这条线本身。用面板调整线性渐变角度与三个色标，可直接观察同一条路径上的颜色分布。

<ComponentPreview files="path-stroke-paint" size="sm" />

带箭头的路径如果用渐变描边，需要给 `arrowDetail.color` 或端点 `color` 一个显式纯色；箭头 marker 不能继承资源型描边。

#### 栈序（zIndex）

默认层叠 = 声明顺序。`zIndex` 显式覆盖：大者在上、缺省 0、同值保持声明顺序；只在同层（同 scope / 顶层）子节点间生效。下面两个填充矩形声明顺序蓝先红后，拖动面板中的蓝色 `zIndex`，可比较负值、0 与正值对重叠顺序的影响。

<ComponentPreview files="path-z-index" size="sm" />

### 曲线与变换

#### 出 / 入射角与自环

`<Step kind="bend">` 除对称的 `bendDirection` + `bendAngle` 外，还可用 `outAngle` / `inAngle` 指定起点出射角与终点入射角，画非对称曲线；`looseness` 调控制点距离（松紧，缺省 ≈1）。**out/in 给定时优先于 `bendDirection`**。当 `from == to`（同节点 / 同坐标）时退化为**自环**——这是 out/in 最大价值场景（状态机自跳转），对称 bend 画不出。面板可在自环与双端点连接间切换，并配合虚点线方向参考调整出入射角与松紧度。

<ComponentPreview files="path-outin-loop" size="md" />

#### 整体变换（rotate / scale）

`rotate`（度）/ `scale`（数字等比，或 `{ x, y }` 非等比）把整条 path 绕**包围盒中心**变换，免去为单条 path 包一层 `<Scope transforms>`。变换顺序有硬契约：path 端点先 resolve、箭头 shrink 在**未变换的几何**上算，最后整体包进 group——故箭头方向随变换正确、不错位。虚点线路径保留原始几何，面板中的旋转与二维缩放只作用于实线路径，便于对照。

<ComponentPreview files="path-transform" size="sm" />

#### 中段标记（marks）

`marks` 沿路径放方向标记：每项 `{ pos, mark }`，`pos ∈ [0, 1]`（越界 schema 拒），`mark` 首批为 `{ kind: 'arrow', shape, ... }`（复用已注册箭头名 + 视觉子集，见 [自定义箭头](/kernel/components/draw/custom-arrow)），**朝向由该点切线决定**（不是固定方向）。直线 / 贝塞尔 / 弧段都按切线定向。尺寸与端点箭头同口径**随 `strokeWidth` 缩放**：线越粗、标记越大。拖动面板中的两个位置值，可观察标记沿路径移动时如何持续跟随局部切线。

<ComponentPreview files="path-marks" size="xs" />

#### 折线圆角（roundedCorners）

`roundedCorners` 给整条 path 的每个 **line↔line 内拐角**倒一个半径相同的圆角弧——画流程图、布线、折线连接时把硬尖角磨圆。缺省 / 省略 = 全尖角（行为不变）。首点 / 末点保持尖；接缝一侧是曲线 / 弧 / 贝塞尔 / 折角（`fold`）时该接缝也保持尖。半径过大时按相邻段长**逐拐角夹紧**到可行最大值。`cycle` 闭合后，闭合接缝也参与倒圆。

<ComponentPreview files="path-rounded-corners" size="sm" />

`roundedCorners` 改的是**路径几何**——它把拐角顶点回退并插入一段相切圆弧，因此影响包围盒、弧长、路径级 `marks` 的归一化定位和连接点解析。这和 `lineJoin` 是两码事：`lineJoin` 只改**描边视觉**，路径中心线仍是尖折。面板上方展示 `lineJoin`，下方展示几何圆角，可直接拖动半径比较。（注：step 边标注 `label` 当前仍定位在该 step 自身线段上，不随接缝倒角缩短重算。）

<Comparison target="tikz" title="Path 写法映射">

| ---------------------------- | ---------------------------- |
| `lineCap` / `lineJoin`       | `line cap` / `line join`     |

### 端点引用为什么支持后定义

编译器遍历到 `<Path>` 时不会立刻生成图元，而是加入待处理队列；需要保持当前输出层级时，还会留下绘制顺序占位。它继续注册当前 scope 内的 `<Node>` 与 `<Coordinate>`，待该 scope 扫描完成后再统一解析 `Step.to`、控制点和连接面。普通 scope 会把图元回填到占位处；带变换 scope 的全局投影规则见 [`<Scope>` 技术原理](/kernel/components/layout/scope#技术原理)。

因此 path 端点可以引用同一 scope 内稍后声明的 id，同时仍保持原来的绘制顺序。这个能力只属于延迟生成的 path；`Node.position` 与 scope transform 仍在遍历到自身时解析，不能据此假设所有 id 引用都支持后定义。

### kind 如何选择整条路径的输出

`kind` 不是 renderer 的绘制开关，而是整条 Path 的编译 provider（处理器）名称，缺省为 `stroke`。编译器从统一注册表找到 definition；如果该 provider 声明了 `optionsSchema`，就先校验 `kindOptions`，否则保留原始 JSON 对象。随后由 provider 决定复用标准描边、复用标准 Ribbon，还是直接生成自定义 Scene 图元。

下图在 Path 的职责边界停止：输入仍是一条 `<Path>`，provider 分派后只输出与 renderer 无关的 Scene 图元。

<ComponentPreview files="path-kind-pipeline" size="sm" hideCode />

内置 `stroke` / [`ribbon`](/kernel/components/draw/ribbon) 与外部 kind 走同一套注册和冲突规则；renderer 不需要认识自定义 kind。要接管整条路径时见[自定义路径](/kernel/components/draw/custom-path)，只扩展某一个 step 时则使用[路径生成器](/kernel/components/draw/path-generator)。

### 描边如何物化几何

默认描边会先把 relative、节点引用和 generator 解析成路径命令（`PathCommand`，即物化后的 move / line / arc 等几何）。`roundedCorners` 随后改写命令，再计算路径标记与端点箭头收缩；`rotate` / `scale` 最后把主路径、标签和标记包装成同一个 group。于是标记会跟随倒圆后的弧长与切线，整体变换也不会让装饰脱离路径。
