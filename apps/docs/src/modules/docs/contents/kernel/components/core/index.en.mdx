Nodes and connections are more than rectangles and lines on a screen. Nodes provide geometry that can be measured, positioned, and referenced; connections use that geometry to choose endpoints. Core Concepts moves from how one object is formed to how several objects connect, so relationships remain meaningful when text, shapes, or positions change.

## Responsibilities at a glance

| ------------------- | ---------------------------------------- | ------------------------------------ |
| Primitive Model     | Content, shapes, boundaries, and anchors | Understand one primitive’s geometry  |
| Primitive Relations | References and endpoint attachment       | Choose automatic or fixed attachment |

## How objects and connections cooperate

For a text Node, text occupies the content region, padding adds space, and shape determines the visible form. A connection also needs attachment geometry: a boundary is the surface used for connections, while an anchor names a position such as the top midpoint.

A visible outline, bounding rectangle, and connection boundary serve different purposes and need not coincide. Distinguishing them helps you decide whether to change text spacing, shape size, or attachment rules instead of repeatedly compensating with offsets.

The node arrangements are identical; the connection rule differs. Automatic attachment suits relationships that follow layout changes, while an explicit anchor fixes the attachment position. The primitive model defines available geometry; primitive relations decide how a particular connection uses it.

## Diagnose a visible problem

| What you see                                | What to check first                            |
| ------------------------------------------- | ---------------------------------------------- |
| Text too close to its border                | Content region and padding                     |
| A line attaches on the wrong side           | Automatic attachment versus an explicit anchor |
| A shape change gives unexpected attachments | Visible shape versus connection boundary       |

Use these questions to find the relevant concept, then consult component documentation for syntax. This overview does not require a complete field dictionary or explain every compiler measurement step.

## Reading order and boundaries

Read Primitive Model for a node's structure, then Primitive Relations for how paths reference it. Revisit [Basic Concepts](/kernel/components/basic) if coordinate directions or relative positions are unfamiliar. For actual configuration, continue with the relevant Node, Draw, or Layout documentation.
