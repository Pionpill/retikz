title: Layout
description: The React drawing entry that connects JSX or Core IR to a retained Runtime Session and incrementally updates a stable SVG or Canvas host.
---

`<Layout>` is the top-level runtime entry for a React drawing tree. Every Kernel / Sugar component enters the same graphics pipeline through it.

It converges two input modes: children are converted to Core IR by the React adapter, while `ir` adopts an existing IR. A retained Runtime Session then lets `@retikz/core` publish Scene Snapshots / Patches and `@retikz/render` update SVG or Canvas.

`<Layout>` owns React-side construction, capability injection, and host wiring. It does not own IR / Scene semantics, geometry rules, or automatic layout algorithms. Core expresses generic positioning and constraints; plot and table layouts belong to their respective higher-level capabilities.

`width` / `height` only control the rendered output's displayed size in the page; internal coordinates stay in retikz user units, and the visible range is auto-computed from layout bounds at compile time.

## Usage

```tsx
import { Draw, Layout, Node } from '@retikz/react';
```

```tsx
<Layout width={300} height={80}>
  <Node id="A" position={[0, 0]}>
    A
  </Node>
  <Node id="B" position={[120, 0]}>
    B
  </Node>
  <Draw way={['A', 'B']} arrow="->" />
</Layout>
```

Place Kernel / Sugar components directly in children; there is no additional fixed composition protocol.

### IR Input

`<Layout>` accepts an `ir` prop — feed a persisted IR JSON directly and get a rendered image, **no JSX children needed**. Source can be anything: LLM-generated, a JSON editor, URL deserialization, or database storage.

<ComponentPreview files="layout-from-ir" size="sm" />

`ir` and `children` are two entry modes; if both are present, `ir` is used. For IR generation, persistence, and conversion, continue with [Architecture](/kernel/concepts/design/principles) and [Composite](/kernel/concepts/design/composite).

### Reading Compile Artifacts

DTO means Data Transfer Object here: `CompiledNodeLayout` is a detached, frozen snapshot produced after Core finishes laying out a Node. It records the Node id, content-box center / size / global bounds, frame position / size / rotation, line count, and whether the content contains TeX; the artifact envelope's `occurrence` separately identifies where that Node came from in the current compile.

It is not IR, a Scene primitive, or a live DOM measurement object, and it exposes no mutable compiler state. Opt into these snapshots with `artifacts={{ nodeLayouts: true }}`, then read the same compile's result from `onArtifacts` after the React commit. The callback below displays the real Node count and content width outside the figure.

This section zooms in on React wiring, viewport, and host-policy decisions owned by `<Layout>`. See [Architecture Principles](/kernel/concepts/design/principles) for package-level responsibilities.

### How Responsibilities Close the Loop

`<Layout>` converts JSX children to Core IR or adopts the `ir` prop, while definitions and runtime options enter through the same boundary. Whenever `ir` or Core options change, the render phase performs one complete compile for an SSR-safe Scene seed. After React commits, a Core Program and retained Render participant process the same input in a Runtime Session. Input and renderer configuration commit in one transaction, then publish Scene, DOM / bitmap, events, animation handles, and artifacts together.

<ComponentPreview files="layout-input-flow" size="sm" hideCode />

Semantic ownership does not drift with the entry point: React declares only a stable `<svg>` / `<canvas>` host shell, while the Render participant exclusively owns SVG descendants or the Canvas bitmap. Core does not own DOM or Canvas instances, and render does not define graphics semantics in reverse. A failed transaction publishes no new revision and attempts rollback. The old host remains usable when rollback succeeds; if rollback itself fails, the Session becomes broken and the caller must unmount and mount again.

### How the viewport is chosen

The upper track resolves the internal coordinate range: an explicit `viewBox` prop wins, then an IR-owned `viewBox`, then content bounds plus padding. The lower `width` / `height` track controls only the CSS display size and never participates in the internal coordinate calculation.

<ComponentPreview files="layout-viewbox-resolution" size="sm" hideCode />

If a figure is clipped or has too much empty space, inspect **View Code → IR** first. An explicit viewBox may be smaller than visible primitives, while automatic layout may be expanded by visible bounds far from the subject. A coordinate without a visible boundary does not extend the automatic range by itself.

### Advanced Host Policies

Ordinary pages can use `renderer`, `animate`, and `snapshotAt` directly. Editors and test harnesses only need Providers when they must control an entire subtree; the figure separates renderer fallback from animation host-policy overrides.

<ComponentPreview files="layout-runtime-priority" size="md" hideCode />

The renderer Provider fills only an omitted renderer, so an explicit descendant prop still wins. The animation Provider intentionally controls the entire subtree and overrides descendant `animate` props; its `system` mode follows the system preference directly. `snapshotAt` is not part of that fallback chain: once present, both SVG and Canvas emit only the static frame at that time.

## API Reference

### Input and Viewport

| Prop       | Type                 | Default | Description                                       |
| ---------- | -------------------- | ------- | ------------------------------------------------- |
| `children` | `ReactNode`          | —       | Kernel / Sugar tree, used when `ir` is omitted    |
| `ir`       | `IRScene`            | —       | Pre-built Core IR; wins when children also exist  |
| `width`    | `number` \| `string` | —       | SVG / Canvas display width                        |
| `height`   | `number` \| `string` | —       | SVG / Canvas display height                       |
| `viewBox`  | `IRViewBox`          | —       | Internal range; overrides IR and automatic layout |

### Compile Basics

These props enter `CompileOptions` together. See each extension guide for definition, registration, and error contracts.

| Prop           | Type                                                         | Default | Description                                                                         |
| -------------- | ------------------------------------------------------------ | ------- | ----------------------------------------------------------------------------------- |
| `nodeDistance` | `number`                                                     | `24`    | Default relative-position distance; the node's own value wins                       |
| `fontSize`     | `number`                                                     | `16`    | Default font size and root size for presets and `rem`                               |
| `artifacts`    | `CompileArtifactOptions`                                     | `{}`    | Requests opt-in outputs; `nodeLayouts:true` includes `CompiledNodeLayout` snapshots |
| `onArtifacts`  | `(artifacts:`<br />`ReadonlyArray<CompileArtifact>) => void` | —       | Reports same-compile immutable artifacts after React commit                         |

### Primitive and Resource Injection

| Prop         | Type                                        | Default | Description                                                                         |
| ------------ | ------------------------------------------- | ------- | ----------------------------------------------------------------------------------- |
| `shapes`     | `ReadonlyArray`<br />`<ShapeDefinition>`    | —       | Inject shapes; see [Custom Shapes](/kernel/components/shapes/custom-shape)          |
| `boundaries` | `ReadonlyArray`<br />`<BoundaryDefinition>` | —       | Inject boundaries; see [Custom Boundaries](/kernel/components/node/custom-boundary) |
| `clips`      | `ReadonlyArray`<br />`<ClipDefinition>`     | —       | Inject clips; see [Custom Clips](/kernel/components/layout/custom-clip)             |
| `arrows`     | `ReadonlyArray`<br />`<ArrowDefinition>`    | —       | Inject arrows; see [Custom Arrows](/kernel/components/draw/custom-arrow)            |
| `patterns`   | `ReadonlyArray`<br />`<PatternDefinition>`  | —       | Inject patterns; see [Custom Patterns](/kernel/components/effects/custom-pattern)   |

### Higher-Level Capabilities and Host Integration

| Prop                  | Type                                                  | Default | Description                                                                                     |
| --------------------- | ----------------------------------------------------- | ------- | ----------------------------------------------------------------------------------------------- |

### Whole-Figure Defaults

These props reuse the [`<Scope>`](/kernel/components/layout/scope) cascade contract rather than defining another style system. In children mode, values synthesize a root Scope; direct `ir` input ignores them with a development warning.

| Prop                                                                                      | Type              | Default | Description                          |
| ----------------------------------------------------------------------------------------- | ----------------- | ------- | ------------------------------------ |
| `color` / `stroke` / `fill` / `strokeWidth` / `opacity` / `fillOpacity` / `strokeOpacity` | same as `<Scope>` | —       | Whole-figure graphic-state defaults  |
| `nodeDefault` / `pathDefault` / `labelDefault` / `arrowDefault`                           | same as `<Scope>` | —       | Node / path / label / arrow defaults |

### Rendering and Host Runtime

| Prop        | Type                      | Default | Description                                                                      |
| ----------- | ------------------------- | ------- | -------------------------------------------------------------------------------- |
| `renderer`  | `'svg'` \| `'canvas'`     | `'svg'` | Output backend; falls back to the nearest `RendererModeProvider`                 |
| `className` | `string`                  | —       | Forwarded to the SVG / Canvas root                                               |
| `style`     | `CSSProperties`           | —       | Forwarded to the SVG / Canvas root                                               |
| `idPrefix`  | `string`                  | —       | Overrides resource ids for multi-instance or SSR hydration stability             |
| `handlers`  | `LayoutProps['handlers']` | —       | Event registry for `ir` mode; see [Hydration](/kernel/packages/render/hydration) |
| `runtime`   | `LayoutRuntimeOptions`    | `{}`    | Retained renderer factory and Runtime diagnostic outlet                          |

`runtime.rendererFactory` can inject a third-party backend that implements the same retained renderer contract; omitting it selects the built-in SVG / Canvas factory. `runtime.onDiagnostic` receives diagnostics for successful commits and failed transactions in Runtime queue order. Callback exceptions are isolated and do not change the Runtime commit or failure result.

### React host exports

- `RendererModeProvider` / `RendererModeProviderProps`: supplies a default `mode: 'svg' | 'canvas'` to a subtree; `useRendererMode` reads the nearest value, while `RendererModeContext` is the low-level bridge
- `AnimationModeProvider` / `AnimationModeProviderProps`: controls a subtree with `mode: 'system' | 'enabled' | 'disabled'`; `useAnimationMode` reads the nearest value, while `AnimationModeContext` is the low-level bridge
- `collectHydrationHandlers(children, embeddables?)`: collects `on<Event>` handlers by element `id`; ordinary `<Layout>` children mode calls it automatically, so only custom hydration hosts need it directly

### Animation

| Prop                  | Type                                 | Default | Description                                                                        |
| --------------------- | ------------------------------------ | ------- | ---------------------------------------------------------------------------------- |
| `animate`             | `boolean`                            | system  | Playback switch; see [Animation](/kernel/components/effects/animation)             |
| `snapshotAt`          | `number`                             | —       | Static snapshot time; overrides `animate`                                          |
| `animations`          | `Array<IRAnimationTrack>`            | —       | Scene-root tracks such as viewBox camera animation                                 |
| `animationRef`        | `LayoutProps['animationRef']`        | —       | Imperative `play` / `pause` / `seek` handle                                        |
| `easings`             | `LayoutProps['easings']`             | —       | Custom easing; see [Custom Animation](/kernel/components/effects/custom-animation) |
| `animationProperties` | `LayoutProps['animationProperties']` | —       | Custom animation-property interpolation; Canvas only for now                       |
