---
title: Layout
description: Top-level container — accepts a component tree or IR, compiles to Scene, and produces rendered output.
---

`<Layout>` is retikz's only required top-level wrapper. Every Kernel / Sugar component must live inside a `<Layout>`.

It is the entry point between the DSL and the renderer: with children it converts the component tree into IR; with `ir` it uses that pre-built IR directly. It then compiles the IR into a Scene and hands it to the current renderer.

`width` / `height` only control the rendered output's displayed size in the page; internal coordinates stay in retikz user units, and the visible range is auto-computed from layout bounds at compile time.

## Usage

```tsx
import { Layout } from '@retikz/react';
```

```tsx
<Layout width={300} height={80}>
  {/* Kernel / Sugar children */}
</Layout>
```

## Composition

`<Layout>` is a container; children are any Kernel / Sugar component tree:

```tsx
<Layout>
  <Node id="..." position={...}>label</Node>
  <Path>
    <Step kind="move" to="..." />
    <Step kind="line" to="..." />
  </Path>
  <Draw way={[...]} />
</Layout>
```

### Whole-figure Default Style

`<Layout>` directly accepts the same cascade style subset as [`<Scope>`](/kernel/components/layout/scope) (`color` / `stroke` / `fill` / `strokeWidth` / `opacity` / `fillOpacity` / `strokeOpacity` + `nodeDefault` / `pathDefault` / `labelDefault` / `arrowDefault`). When any style prop is set, Layout wraps its children in an **implicit root `<Scope>`**, removing the boilerplate of nesting one root `<Scope>` on every figure. Inner `<Scope>` and explicit primitive props still cascade over it as usual.

<ComponentPreview files="layout-scope-style" size="sm" />

```tsx
// Set defaults for the whole figure — no nested <Scope> needed
<Layout stroke="gray" nodeDefault={{ shape: 'circle', fill: 'white', dashed: true }} pathDefault={{ lineCap: 'round' }}>
  <Node id="A" position={[0, 0]}>A</Node>
  <Draw way={['A', 'B']} arrow="->" />
</Layout>

// Equivalent to hand-writing one root <Scope>
<Layout>
  <Scope stroke="gray" nodeDefault={{ shape: 'circle', fill: 'white', dashed: true }} pathDefault={{ lineCap: 'round' }}>
    {/* ... */}
  </Scope>
</Layout>
```

The exact wrapping condition, and what happens when combined with the `ir` prop, are covered in How it works bottom.

### Render from IR

`<Layout>` accepts an `ir` prop — feed a persisted IR JSON directly and get a rendered image, **no JSX children needed**. Source can be anything: LLM-generated, a JSON editor, URL deserialization, or database storage.

<ComponentPreview files="layout-from-ir" size="xs" />

When you need to convert between the DSL and IR, pair `convertReactNodeToIR` with `convertIRToReactNode`. Tier 1 IR stays structurally equivalent across the roundtrip. Tier 2 composites are first expanded with the supplied `composites` definitions, so the result is semantically equivalent to the lowered Kernel IR rather than the original custom component:

```tsx
import { Layout, Node, convertIRToReactNode, convertReactNodeToIR } from '@retikz/react';

const ir = convertReactNodeToIR(
  <Node id="a" position={[0, 0]}>
    A
  </Node>,
);
// Serialize, send to LLM, store in DB...
<Layout ir={ir} width={200} height={80} />;

const kernelChildren = convertIRToReactNode(tier2IR, {
  composites: [panelDefinition],
});
```

If a Tier 2 definition is missing, its payload is invalid, or recursive expansion exceeds the depth limit, `convertIRToReactNode` throws with the composite key and IR path instead of silently dropping the node.

`ir` and `children` are mutually exclusive; if both are supplied, `ir` wins.

### Custom viewBox

By default the `viewBox` is auto-computed from content (AABB + padding). Pass `viewBox={{ x, y, width, height }}` to pin it explicitly — for fixed size, deliberate clipping, multi-figure alignment, or excluding overflow. When set it overrides the auto computation and ignores padding; `width` / `height` must be > 0.

<ComponentPreview files="layout-viewbox" size="md" />

### Render Backend (SVG / Canvas)

`renderer` selects the output backend: `'svg'` by default, or `'canvas'` to draw the same Scene onto a `<canvas>`.

When the `renderer` prop is omitted, `<Layout>` falls back to the nearest `RendererModeProvider`. This fits the case where an outer layer wants to switch a whole subtree it can't reach into per-`<Layout>` — e.g. toggling an interactive (hooks / async) subtree between svg / canvas: you can't edit its inner `<Layout renderer>`, but wrapping it in the Provider does it:

```tsx
import { Layout, RendererModeProvider } from '@retikz/react';

// Inner <Layout>s without an explicit renderer follow the Provider; those with one are unaffected
<RendererModeProvider mode="canvas">
  <SomeInteractiveChart />
</RendererModeProvider>;
```

### Control animation for a whole subtree

Normally, each `<Layout>` should express its own animation intent through `animate`. An editor, docs preview, or test harness that needs one policy for an entire component tree can wrap it in `AnimationModeProvider`:

```tsx
import { AnimationModeProvider } from '@retikz/react';

<AnimationModeProvider mode="enabled">
  <SomeInteractiveChart />
</AnimationModeProvider>;
```

| `mode`       | Behavior                                              |
| ------------ | ----------------------------------------------------- |
| `'system'`   | The whole subtree follows the reduced-motion setting  |
| `'enabled'`  | The whole subtree is forced to play animations        |
| `'disabled'` | The whole subtree is forced to show the static result |

The animation Provider is a host-level override: the nearest `AnimationModeProvider` wins over descendant `<Layout animate>` props, including an explicit opposite value. Without a Provider, `animate` keeps its existing tri-state behavior. `snapshotAt` always wins and produces a static frame.

### How the two inputs converge

Both `children` and `ir` end as the same JSON IR before core compiles them. Only the work before IR differs: the JSX branch walks the component tree, while the `ir` branch adopts an existing contract directly.

<ComponentPreview files="layout-input-flow" size="md" hideCode />

The JSX branch adds a root `<Scope>` only when a style prop carries a real directive; empty defaults leave the IR unchanged. With direct `ir` input, figure-level style props are ignored and produce a development warning because the IR already owns its complete root semantics.

### How the viewport is chosen

The upper track resolves the internal coordinate range: an explicit `viewBox` prop wins, then an IR-owned `viewBox`, then content bounds plus padding. The lower `width` / `height` track controls only the CSS display size and never participates in the internal coordinate calculation.

<ComponentPreview files="layout-viewbox-resolution" size="sm" hideCode />

If a figure is clipped or has too much empty space, inspect **View Code → IR** first. An explicit viewBox may be smaller than visible primitives, while automatic layout may be expanded by visible bounds far from the subject. A coordinate without a visible boundary does not extend the automatic range by itself.

### How host policies fall back

The numbers show lookup order. Resolution moves downward only when the current item is absent and stops at the first effective value. The left column is **`renderer` prop > nearest `RendererModeProvider` > `'svg'`**; the right column is **`snapshotAt` > nearest `AnimationModeProvider` > `animate` > system preference**.

<ComponentPreview files="layout-runtime-priority" size="lg" hideCode />

The renderer Provider fills only an omitted renderer, so an explicit descendant prop still wins. The animation Provider intentionally controls the entire subtree and overrides descendant `animate` props. Once `snapshotAt` is present, both SVG and Canvas emit only the static frame at that time.
