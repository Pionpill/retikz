title: 复合
description: 高层对象保留领域意图，编译时展开为共享基础图元。
---

复合（composite）把一组基础图元表达成一个有意义的对象。例如，保存柱状图的数据比保存几十个矩形更便于继续编辑。Kernel 的基础层称为 Tier 1，高层对象称为 Tier 2；编译时，高层对象展开为基础图元，共用同一套布局和渲染能力。

例如，柱状图保存“数据 `[4, 7]`”这个高层节点（Tier 2），展开后得到两根表示柱子的矩形 Node（Tier 1）。这种从高层声明到基础图元的转换称为下沉（lowering）；随后编译生成渲染结果 Scene，由 SVG / Canvas 后端显示。可保存的图形声明称为 IR。

## 为什么需要 composite

直接保存几十个矩形和连线，会丢失“这是一张图表 / 一棵树”的高层意图。composite 把领域字段保留在可序列化 IR 中，再把具体几何延迟到 compile 期生成：

<ComponentPreview files="composite-pipeline" size="xs" hideCode />

图中的 `lower` 是关键边界：上游仍能存储、传输、diff 或由 AI 生成高层节点；下游只接收统一的 Tier 1，因此所有 renderer 共享同一次 Core compile 的结果。

适合 composite 的能力通常同时满足三点：

- 一个高层节点会按数据或算法生成数量不固定的 Tier 1 图元；
- 领域 schema 比展开后的几何更能表达用户意图；
- 展开结果应被 React、Vanilla、SVG、Canvas 等入口共同复用。

## 与 Sugar 的区别

|          | Sugar（如 `<Draw>`） | Tier 2 composite                                |
| -------- | -------------------- | ----------------------------------------------- |
| IR 中    | 构建期已展平         | 保留高层节点                                    |
| 下沉时机 | adapter 构建期       | core compile 期                                 |
| 适合     | 可直接映射的便捷写法 | 结构生成，或依赖真实子内容反馈的布局 / 聚合算法 |

<Comparison target="tikz" title="Tier 2 与 PGFPlots">

PGFPlots 位于 TikZ 基础图元之上；同样地，`@retikz/plot` 通过 composite 把 grammar-of-graphics spec 下沉为 core 图元。区别在于 retikz 把高层节点保留为可校验、可序列化的 IR，并让 lowering 成为所有后端共享的 compile 步骤。

## 选择展开方式

只需从数据生成图元时，使用 `expand`；需要先测量子内容再分配空间时，使用 `compile`。这两个名称是复合定义中的互斥回调，不是要求用户连续调用的两个步骤。普通使用者调用领域组件即可，扩展作者才需要实现这些回调。
