---
title: 复合组件
description: 将一组基础图元封装成可复用的高层能力。
---

当一组图形需要保留自己的数据与参数时，可以把它表达为复合组件。例如，柱状图的输入是数值数组，输出是多个矩形；用户修改数据，组件负责重新组织图形。这里介绍怎样把这种能力接入 Kernel，而不是只把一段 JSX 包成函数。

## 数据怎样变成图形

下图从一个高层声明开始：composite IR 保存有领域含义的数据，下沉过程把它转换成 Kernel 基础图元；随后编译为 Scene，再交给 SVG 或 Canvas 后端。IR 是可保存声明，Scene 是已确定位置与样式的绘制结果。

以六个数值生成六根柱子为例，保存数据数组比保存每个矩形的坐标更便于继续编辑。生成图形的函数保留在程序中，数据则可以保存和传输。两者通过注册到宿主的组件名称对应，由宿主查找相应 Definition，不把函数塞进 JSON。

## 定义与接入怎样配合

Definition 是描述能力的定义对象：说明它叫什么、接受什么数据、怎样生成图元。schema 校验输入数据；处理函数根据通过校验的数据产生图形。

“注入”是把 Definition 传给宿主的 `composites` 选项，让编译器能按名称找到它。React 与 Vanilla 使用同一份定义和可保存声明，分别完成各自的界面接入；不需要为两个宿主实现两套柱高计算。

## 先选择最简单的处理方式

如果输入数据已经足够确定所有图元，可以直接展开。例如数值决定柱高，固定间距决定横向位置。只有需要先测量子内容、再决定给它多大空间时，才需要布局反馈，例如根据文字实际宽度安排卡片。

教程先用直接展开完成最小闭环。实现原理再解释布局试算、选择结果与提交，适合已经会定义能力、需要处理复杂组合的读者。不要一开始就把完整布局机制当作必填配置。

## 适用边界

只想重复一段固定绘图结构时，普通组件组合通常已经够用；需要保留高层数据与可校验参数时，再考虑复合模型。判断模型本身是否合适可先读[复合概念](/kernel/components/design/composite)，下面两篇则分别解决“怎样接入”和“内部怎样执行”。
