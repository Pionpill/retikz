A star alternates points between an outer and an inner radius, with two faces: draw an outline with `<Star>` (sugar), or bound a node with `shape={{ type:'star', params }}`. See [Shapes](/kernel/components/shapes) for the full definition. Reach for sugar to draw a star outline, and for `<Node shape>` to get a connectable star element.

## As a Path shape (sugar)

`<Star>` alternates points on an outer and inner radius, connects them into a closed path, and expands to an underlying `<Path>`. Useful for rating stars, emphasis marks, and decorative multi-point shapes.

### Usage

```tsx
import { Star } from '@retikz/react';
```

```tsx
<Star center={[0, 0]} outerRadius={36} innerRadius={16} points={5} />
```

### Examples

`points` is the number of star points. Give `innerRadius` directly, or use `innerRatio` to derive it from the outer radius.

| Form                                           | Best for                         |
| ---------------------------------------------- | -------------------------------- |
| `{ center, outerRadius, innerRadius, points }` | Control both radii               |
| `{ center, outerRadius, points, innerRatio? }` | Derive inner radius from a ratio |

The two dashed circles in the playground are the inner and outer radii. Adjust the point count, `innerRatio`, and start angle to see how notch depth and orientation shape the contour together.

### API Reference

| Prop          | Type               | Default | Description                                                            |
| ------------- | ------------------ | ------- | ---------------------------------------------------------------------- |
| `center`      | `[number, number]` | —       | Star center                                                            |
| `outerRadius` | `number`           | —       | Outer radius                                                           |
| `innerRadius` | `number`           | —       | Inner radius; wins when provided                                       |
| `innerRatio`  | `number`           | `0.5`   | Inner radius as a ratio of `outerRadius` when `innerRadius` is omitted |
| `points`      | `number`           | —       | Number of star points                                                  |
| `rotate`      | `number`           | `-90`   | Starting angle                                                         |

This shape sugar also forwards the shared Path props, including `stroke`, `fill`, `opacity`, `animations`, and `onClick`. See [Path](/kernel/components/draw/path) for the full list and [Hydration](/kernel/packages/render/render-hydration) for how events are attached after rendering.

## As a node shape

When you need a star **node** (referenceable by a connection, usable as an icon glyph) rather than a line, set `shape={{ type:'star', params }}` on `<Node>`. It is sized by the radius parameters, **independent of any text content**. The Node variant is an optional Standard shape, while sugar `<Star>` remains a Kernel React component. Inject `StarShapeDefinition` into the current `<Layout>` before using the Node variant.

### Usage

```tsx
import { Layout, Node } from '@retikz/react';
import { StarShapeDefinition } from '@retikz/standard/shape';
```

```tsx
<Layout shapes={[StarShapeDefinition]}>
  <Node shape={{ type: 'star', params: { points: 5, innerRadius: 16, outerRadius: 40 } }} />
</Layout>
```

### Examples

| shape | params                                          | Notes                                     |
| ----- | ----------------------------------------------- | ----------------------------------------- |
| star  | `{ points, innerRadius, outerRadius, rotate? }` | Star with alternating inner / outer radii |

> Node `star` constraints: `points` is an integer ≥ 3, and `outerRadius` must be > `innerRadius` (a compile-time refine throws otherwise). Note the minimums differ from the Sugar `<Star>`, which allows `points ≥ 2`.

The playground fixes the target star at the origin. Adjusting `cornerRadius` rounds outer tips and inner notches together; automatic clipping moves with the contour, while `tip-0` / `notch-0` stay at the original logical vertices. Directional and numeric anchors can also be compared while the orbit angle and distance move the source.

<ComponentPreview files="node-connection-playground" size="md" />

The complete named-anchor forms are `tip-N` (the Nth tip) and `notch-N` (the Nth notch). See [Node geometry](/kernel/components/node/overview) for shared sizing, boundary, and anchor behavior.

### API Reference

| `shape`                    | params                                                                 | Boundary / use         |
| -------------------------- | ---------------------------------------------------------------------- | ---------------------- |
| `{ type: 'star', params }` | `points` / `innerRadius` / `outerRadius` / `rotate?` / `cornerRadius?` | Connectable star glyph |

`cornerRadius` (user units) rounds both tips and notches; omitted / `0` = sharp corners, clamped per corner.

### Alternating between the two radii (both)

Let `p = points`. The orange tips lie on the outer circle `R`, while the blue notches lie on the inner circle `r`; the two kinds alternate by vertex index.

<ComponentPreview files="star-vertex-construction" size="sm" hideCode />

The contour has `2p` vertices, with an angular step of `180° / p` between neighbors. Sugar uses an explicit `innerRadius` when present, otherwise it derives one as `outerRadius × innerRatio`; Node star requires both radii. `rotate` changes only the first tip's starting direction, and every later vertex continues at the same step.

### One contour, two consumers (both)

Both entry points first produce the same alternating-vertex contour. Their responsibilities diverge from there: Sugar turns it into a drawable Path, while the Node shape turns it into named geometry that can be laid out and connected.

<ComponentPreview files="star-output-flow" size="sm" hideCode />

Sugar bakes `rotate` directly into the vertex coordinates, then emits `move + line × (2p - 1) + cycle`. The underlying Path carries no `rotate`, avoiding a second rotation around its bounding-box center. Node star derives its circumscribed box from the vertices and reuses the contour for auto-clipping, `tip-N` / `notch-N` anchors, and the Scene path. `cornerRadius` changes the rounded contour and auto-clipped endpoints, but named anchors stay at the original logical vertices.

The left side of the figure also shows the two rotation baselines: Sugar `rotate:-90` and Node star `rotate:0` both point the first tip upward. To keep explicit values visually aligned, set the Node value `90°` higher than the Sugar value. Sugar also allows `points ≥ 2`, while Node star requires `points ≥ 3`.
