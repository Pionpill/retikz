先完成[基础用法](/kernel/components/layout/usage)中的绘图接入。需要为复合组件选择主题、接入自定义形状、在图外读取几何结果或调整更新方式时，再使用下面的配置。示例聚焦 React `<Layout>` 的属性与回调。

## 主题配置

`theme` 为后代 Composite（复合组件）选择主题；它不会自动设置普通 Node / Path 的颜色。普通图元使用自身的 `style`，全图图元默认值使用 `rootScope`。在面板中切换主题风格与明暗模式，观察同一卡片的颜色变化；卡片的位置和尺寸保持不变。

`theme` 的显式字段覆盖已有 IR 的根主题；未声明字段保留原值。完整继承规则见[主题](/kernel/components/design/theme)。

## 编译配置

`compile` 接受 Vanilla 完整的编译配置，既可以设置布局参数，也可以注册扩展。例如：`<Layout ir={sceneIR} compile={{ padding: 12, precision: 3 }} />`。

通过 `Layout.compile` 按能力类别传入扩展定义。`shapes` 只是其中的形状扩展：下面的 `ShapeDefinition` 定义折角文件的占位、连接边界与输出图元，再通过 `compile={{ shapes: [fileShape] }}` 注册。两个 Node 引用注册名 `drawio-file`，连线端点停在自定义轮廓上。

<ComponentPreview files={['layout-shape-injection', 'layout-file-shape.ts']} size="sm" />

`compile` 还支持连接边界（`boundaries`）、裁剪区（`clips`）、箭头（`arrows`）、图案（`patterns`）、路径类型（`paths`）、复合组件（`composites`）和主题风格（`themeDefinitions`）。这些定义统一通过 `compile` 进入对应注册表，由编译过程消费。

本节只展示形状扩展的接入方式；其他能力的定义与使用将在后续对应主题的自定义指南中分别说明。完整字段见 [API 参考](/kernel/components/layout/reference)。

## 读取编译产物

通过 `onArtifacts` 读取 Composite 返回的领域产物，例如 FlexLayout 的容器与子项布局。产物随编译自动收集，回调在 React commit 后通知同次结果；后续更新不会改变此前收到的快照。

更换 `onArtifacts` 或 `onCompileResult` 回调时，新回调会收到当前结果，不会因此重新编译。若不希望父组件重渲染时重复通知，请传入稳定的函数引用。

示例在图外显示 Composite 产物数量和 FlexLayout 的领域值。字段及坐标语义由对应组件定义；普通 Node 不提供独立布局产物。

## 执行模式与更新策略

`reconciler` 直接透传给 Vanilla。默认的 `full` 不保留增量缓存；`incremental` 保留缓存并支持协调器的批次更新策略。两种模式下，Layout 收到新的 JSX 或完整 IR 都调用 `replace` 完整编译，不会把 props 变化推断成增量批次。

```tsx
<Layout><Node /></Layout>
<Layout ir={sceneIR} reconciler={{ mode: 'incremental', updateStrategy: 'auto' }} />
<Layout ir={sceneIR} onDiagnostic={diagnostic => console.warn(diagnostic.message)} />
```

后续输入替换失败时，Layout 继续显示上一次成功结果。两种模式均可通过 `onDiagnostic` 接收结构化诊断。

## 补充说明

- **根 Scope**：未设置 `rootScope.defaults` 时不包装；显式传入 `{}` 也会创建根 Scope。
- **宿主样式**：`Layout.style` 始终是宿主 CSS；全图图元默认值的设置见[基础用法](/kernel/components/layout/usage#全图默认值)。
