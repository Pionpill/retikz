Node combines position, text, and shape in one declaration. An `id` lets other nodes reference its position and paths connect to its border.

## Using this topic

All four forms draw the same Hello node at the origin. React examples export a component; Vanilla examples require an existing `<div id="diagram"></div>`.

## Naming and connecting

A Node needs an `id` to be registered for later references. Coordinate also registers its `id`; `Draw`, relative placement, and anchors can use these named objects. An unnamed Node still draws, but it ends with that drawing pass and leaves no node information for later connections or positioning. `position` sets each center; paths stop at the border by default.

<ComponentPreview files="node-connection" size="xs" />

Here Draw resolves both ends through the `a` and `b` IDs. See [Extended usage](/kernel/components/node/extend) for relative placement and connection surfaces.

`<Draw>` corresponds to IR `type: 'path'`; see [Path](/kernel/components/path/usage) for endpoint and `way` rules. Node / Coordinate positioning can reference only objects whose layout and registration have completed (usually earlier siblings). Path / Draw endpoints may reference later siblings; see [reference timing](/kernel/components/node/mechanism#named-references-and-registration-order).

## Choosing a shape

An omitted `shape` inherits `Scope.defaults.node.shape`, falling back to a rectangle when no inherited value exists. This panel uses only Core shapes: switch presets, or choose polygon and adjust its side count. Use `text` or children for body text and `label` for annotations; see [Node text](/kernel/components/node/text) and [Node labels](/kernel/components/node/labels).

| Input                                    | Core resolution                                              |
| ---------------------------------------- | ------------------------------------------------------------ |
| omitted                                  | Inherit the Scope default shape, then fall back to rectangle |
| `rectangle`                              | rectangle provider                                           |
| `ellipse`                                | ellipse provider                                             |
| `{ type: 'polygon', params: { sides } }` | polygon provider, with `sides` selecting the count           |
| `circle`                                 | preset resolving to an equally circumscribed ellipse         |
| `diamond`                                | preset resolving to a four-sided polygon                     |

<ComponentPreview files="node-shape" size="sm" />

For more shapes, import the Extension package from [Extension Shape](/library/extension/shape) and register it through `Layout.extensions.shapes`.

## Size and transforms

Adjust the same q in the panel to compare text spacing, border size, and rotation. The connection is a fixed reference showing how its endpoint follows the geometry.

| Goal               | Common configuration                                   | Result                                                          |
| ------------------ | ------------------------------------------------------ | --------------------------------------------------------------- |
| Space around text  | `layout={{ padding: 12 }}`                             | Add inner spacing around the text                               |
| Minimum dimensions | `layout={{ minimumSize: { width: 100, height: 48 } }}` | Enforce a size floor; more content can enlarge it               |
| Outer spacing      | `layout={{ margin: 8 }}`                               | Expand layout and connection bounds without changing appearance |
| Rectangle corners  | `cornerRadius={8}`                                     | Round the rectangle corners                                     |
| Scale or rotate    | `scale={1.5}` / `rotate={30}`                          | Transform the node geometry and update attached connections     |

`padding` / `margin` can also control individual sides. See [node shapes](/kernel/components/node/shape) for corner parameters and precedence, and [extended usage](/kernel/components/node/extend#shapes-and-connection-surfaces) for margin versus connection surfaces.

### Fixed width, minimum width, and wrapping

Each column uses one width setting: short text above and the same longer sentence below. Compare whether the borders keep the same width and whether the text wraps.

| Setting                    | Controls                                        | When content changes                                                                     |
| -------------------------- | ----------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `layout.width`             | Unscaled visible border width, excluding margin | Keeps the width fixed and reflows plain text into the available space                    |
| `layout.minimumSize.width` | A lower bound on visible border width           | Expands short text to the minimum; longer text can enlarge the border                    |
| `layout.maxTextWidth`      | A plain-text wrapping threshold                 | Wraps long text without stretching short text; padding and shape still affect the border |

<ComponentPreview files="node-width-comparison" size="md" />

A fixed width must accommodate the effective minimum size, padding, and shape geometry. If an unbreakable word or mixed content still cannot fit, compilation fails rather than clipping it or shrinking its font. See [text](/kernel/components/node/text#multiple-lines-and-wrapping) for multiline and mixed-run limits.

## Additional notes

Put visual properties in `style`, and size and text layout in `layout`. [Scope](/kernel/components/scope/usage) supplies shared defaults.

<ComponentPreview files="node-styled" size="md" />

- **Stacking**: `zIndex` compares siblings only; higher values draw on top and ties preserve declaration order.
- **Color**: `style.color` is the base color; numeric `fill` and `stroke` values derive colors from it, rather than setting opacity.
- **Pattern fills**: `style.fill` also accepts pattern objects such as `{ kind: 'pattern', shape: 'lines' }` to fill a node with lines, dots, or a grid. See [Patterns](/kernel/visual/style/pattern).
- **Text and points**: a borderless Node still has text dimensions. Use Coordinate for an invisible reference point.
- **Effects**: see [Shadow](/kernel/visual/style/shadow) and [Animation](/kernel/visual/animation/usage).
