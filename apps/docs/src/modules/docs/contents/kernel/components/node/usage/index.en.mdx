Node combines position, text, and shape in one declaration. An `id` lets other nodes reference its position and paths connect to its border.

## Using this topic

All four forms draw the same Hello node at the origin. React examples export a component; Vanilla examples require an existing `<div id="diagram"></div>`.

## Naming and connecting

A Node needs an `id` to be registered for later references. Coordinate also registers its `id`; `Draw`, relative placement, and anchors can use these named objects. An unnamed Node still draws, but it ends with that drawing pass and leaves no node information for later connections or positioning. `position` sets each center; paths stop at the border by default.

<ComponentPreview files="node-connection" size="xs" />

Here Draw resolves both ends through the `a` and `b` IDs. See [Extended usage](/kernel/components/node/extend) for relative placement and connection surfaces.

`<Draw>` corresponds to IR `type: 'path'`; see [Path](/kernel/components/path/usage) for endpoint and `way` rules. Node / Coordinate positioning can reference only objects whose layout and registration have completed (usually earlier siblings). Path / Draw endpoints may reference later siblings; see [reference timing](/kernel/components/node/mechanism#why-named-positioning-is-order-sensitive).

## Choosing a shape

An omitted `shape` inherits `Scope.defaults.node.shape`, falling back to a rectangle when no inherited value exists. This panel uses only Core shapes: switch presets, or choose polygon and adjust its side count. Use `text` or children for body text and `label` for annotations; see [Node text](/kernel/components/node/text) and [Node labels](/kernel/components/node/labels).

| Input                                    | Core resolution                                              |
| ---------------------------------------- | ------------------------------------------------------------ |
| omitted                                  | Inherit the Scope default shape, then fall back to rectangle |
| `rectangle`                              | rectangle provider                                           |
| `ellipse`                                | ellipse provider                                             |
| `{ type: 'polygon', params: { sides } }` | polygon provider, with `sides` selecting the count           |
| `circle`                                 | preset resolving to an equally circumscribed ellipse         |
| `diamond`                                | preset resolving to a four-sided polygon                     |

<ComponentPreview files="node-shape" size="sm" />

For more shapes, import the Standard extension package from [Standard Shape](/library/standard/shape) and register it through `Layout.extensions.shapes`.

## Size and transforms

`layout.margin` expands the node's layout footprint. A boundary's `gap` changes only connection geometry, leaving the visual shape and layout footprint unchanged.

Size and transforms share one node geometry: padding expands the content box, minimumSize sets a floor, and scale / rotate alter the final border. Margin leaves the node appearance unchanged and pushes automatic endpoints and standard anchors outward. Shape-specific anchors and side-fraction points stay on the visible contour. Adjust the same `q` while the edge provides a border reference.

- Inner: `layout={{ padding: N }}` or `layout={{ padding: { default, x, y, left, right, top, bottom } }}`
- Outer: `layout={{ margin: N }}` or `layout={{ margin: { default, x, y, left, right, top, bottom } }}`
- `cornerRadius` — corner radius. `rectangle` / `polygon` / `star` / `sector` support rounding (`ellipse` and the like do not) via their params: `shape={{ type:'polygon', params:{ sides:6, cornerRadius:8 } }}`, and likewise for `star` / `sector` / `rectangle`. The top-level `cornerRadius` only affects the `rectangle` shape (default or explicit `'rectangle'`), and only merges when params don't already set `cornerRadius` (params wins when both are set)
- `minimumSize` — floor the bbox without shrinking natural text width
- `scale` — uniform / per-axis scale; affects bbox, font size, padding, and path attachment
- `rotate` — rotate around the node center; attached paths follow the rotated border

`layout.width` sets the unscaled visible border width, excluding margin, and cannot be smaller than the effective minimum width. It is distinct from the wrapping threshold `layout.maxTextWidth`.

## Additional notes

Put visual properties in `style`, and size and text layout in `layout`. [Scope](/kernel/components/scope/usage) supplies shared defaults.

<ComponentPreview files="node-styled" size="md" />

- **Stacking**: `zIndex` compares siblings only; higher values draw on top and ties preserve declaration order.
- **Color**: `style.color` is the base color; numeric `fill` and `stroke` values derive colors from it, rather than setting opacity.
- **Pattern fills**: `style.fill` also accepts pattern objects such as `{ kind: 'pattern', shape: 'lines' }` to fill a node with lines, dots, or a grid. See [Patterns](/kernel/components/effects/pattern).
- **Text and points**: a borderless Node still has text dimensions. Use Coordinate for an invisible reference point.
- **Effects**: see [Visual effects](/kernel/components/effects) for shadows and animation.
