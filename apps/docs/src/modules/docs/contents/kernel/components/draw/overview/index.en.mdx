---
title: Draw
description: Declare everyday links, folds, curves, cycles, and edge labels in one way array that expands to equivalent Path and Step actions.
---

`<Draw>` is the default entry point for most connections. It accepts a `way` array and expands targets, folds, cycles, curves, shapes, and edge labels into Kernel `<Path>` + `<Step>`. Stroke, fill, arrow, and opacity props match `<Path>`.

Choosing rule: use `<Draw>` for ordinary relationship lines, flowchart edges, and arrowed connections; switch to `<Path>` + `<Step>` when you need multiple `move`s, precise per-segment `kind` control, or IR-close debugging; use the **shape sugar** below to draw a single geometric shape (circle / rectangle / sector, etc.). Work with IR directly only at AI / persistence boundaries.

## Usage

```tsx
import { Draw } from '@retikz/react';
```

```tsx
<Draw way={['a', 'b']} />
```

### Orthogonal connections

Draw provides three orthogonal connection choices in `way`. Single-axis forms project to only one target coordinate and do not necessarily reach the target; fold forms connect to it completely.

<ComponentPreview
  files="draw-orthogonal"
  size="sm"
  caption="Switch connection types and follow the blue path; the gray dotted line only hints at the direct direction between the nodes."
/>

| Need                | `way` form                                                              | Behavior                                                        |
| ------------------- | ----------------------------------------------------------------------- | --------------------------------------------------------------- |
| Single-axis project | `{ horizontalTo: 'b' }`<br />`{ verticalTo: 'b' }`                      | Take only target x or y along the current Scope's local axes    |
| One corner          | `'-\|'`<br />`'\|-'`                                                    | Reach the next target through one orthogonal corner             |
| Middle leg          | `{ via: '-\|-', fraction: 0.5 }`<br />`{ via: '\|-\|', fraction: 0.5 }` | Use two orthogonal corners; `fraction` positions the middle leg |

See [Way](/kernel/components/draw/way#single-axis-connections) for syntax constraints and interactive examples, and [Step](/kernel/components/draw/step#orthogonal-connections) for the underlying path actions.

### Curves

Draw has two curve families: `curve` / `cubic` / `bend` connect the previous target to the next target, while `arc` draws a circular arc around the previous point. In Bezier curves, control points are not necessarily points the curve passes through; they are handles that pull the curve's direction and amount of bend.

| Form        | Mental model                                                     | Good for                                         |
| ----------- | ---------------------------------------------------------------- | ------------------------------------------------ |
| `{ curve }` | One control point pulls a simple bend                            | Ordinary single-arc connectors                   |
| `{ cubic }` | Two control points shape the start and end directions separately | S-curves, complex connectors, precise tangents   |
| `{ bend }`  | Direction + angle shorthand; control points are computed for you | Quick curved links between two nodes             |
| `{ arc }`   | Circular arc around the previous point by angles and radius      | Angle marks, circle fragments, geometry diagrams |

Use the panel to switch among quadratic / cubic Bezier, bend, arc, circle, and ellipse. Bezier control points are edited as `[x, y]` pairs and move the dashed handles on the canvas; other kinds expose only the angles or radii they actually use. Connection operations consume the targets on both sides; arc / circle / ellipse use the previous item as their center and do not consume a next target.

<ComponentPreview files="draw-curve" size="sm" />

A smooth curve through points is a `<Step kind="smooth">`-only capability rather than a `way` operation because it consumes a point list at once. See [Step curves](/kernel/components/draw/step#geometry-and-curves).

### Edge Labels

`{ label }` decorates the next produced segment through `step.label`; it does not produce a segment itself. Switch between a line and the two fold operators, drag `position`, then adjust side, sloped, and text color. A fold divides t evenly across its two legs, so `0.5` always lands on the corner.

<ComponentPreview files="draw-label" size="sm" />

For the seven position keywords and t semantics on curves and arcs, see [Step edge labels](/kernel/components/draw/step#edge-label).

#### Fill and stacking

After `DrawWay.Cycle` closes the region, `fill` and `fillOpacity` control its appearance, while `fillRule` handles nested sub-paths. `zIndex` overrides declaration order among siblings at the same level. The blue Draw in the panel is declared before the red one: red stays on top while blue has `zIndex` 0, and blue moves above it at 1.

## How it works

<ComponentAlert
  type="tip"
  title="Optional for everyday use"
  description="Revisit this section when you need to inspect way expansion or diagnose structural errors."
/>

`<Draw>` only turns the author-friendly `way` syntax into a Kernel subtree. This section stops at the `<Path>` + `<Step>` boundary; see [Architecture Principles](/kernel/concepts/design/principles) for the complete JSX → IR → Scene pipeline.

### From way syntax to a Step sequence

The `way` array is scanned from left to right. Its first item must be a target and always becomes `move`; later items either produce path actions or decorate the action that follows them.

| Input role                        | Normalized result                       | Scan behavior                     |
| --------------------------------- | --------------------------------------- | --------------------------------- |
| First target                      | `move` step                             | Consumes the current item         |
| Ordinary / relative target        | `line` step                             | Consumes the current item         |
| Fold / `curve` / `cubic` / `bend` | Matching `fold` / curve step            | Consumes the following target too |
| `arc` / `circle` / `ellipse`      | `arc` / `circlePath` / `ellipsePath`    | Does not consume a later target   |
| `label`                           | Sets the next `step.label`; no own step | Waits for and decorates next step |
| `cycle`                           | `cycle` step                            | Closes the current subpath        |

The same scan validates structure. A `way` with fewer than two items, a non-target first item, an infix operator without a following target, consecutive labels, or a trailing label fails while Draw expands instead of producing an ambiguous Kernel subtree.

### Equivalent expansion

For example, this Sugar:

```tsx
<Draw way={['a', { label: 'ok' }, '-|', 'b']} arrow="->" />
```

expands to the equivalent Kernel component tree:

```tsx
<Path arrow="->">
  <Step kind="move" to="a" />
  <Step kind="fold" via="-|" to="b" label={{ text: 'ok' }} />
</Path>
```

Draw forwards whole-path properties such as stroke, fill, arrows, and stacking to `<Path>`, then maps every normalized action to a `<Step>`. Both forms therefore enter the same Kernel semantics and downstream geometry pipeline. Switching from Draw to an explicit Path + Step tree changes authoring granularity, not path behavior.

## API Reference

### Props

| Prop             | Type                                                | Default        | Description                                                                                                                                                                                 |
| ---------------- | --------------------------------------------------- | -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `way`            | `Array<WayItem>`                                    | —              | At least 2 items; first is always `move`, rest become `line` / `fold` / `cycle` and related actions based on item form                                                                      |
| `stroke`         | `string` \| `IRPaintSpec`                           | `currentColor` | Stroke paint: CSS color or IRPaintSpec (gradient / pattern / image); when using IRPaintSpec, set an explicit CSS color for arrows                                                           |
| `strokeWidth`    | `number`                                            | `1`            | Stroke width                                                                                                                                                                                |
| `dashPattern`    | `Array<number>`                                     | —              | Dash / gap length sequence, for example `[4, 2]`                                                                                                                                            |
| `dashOffset`     | `number`                                            | —              | Dash start offset in path user units                                                                                                                                                        |
| `lineCap`        | <ApiValues name="PathLineCap" />                    | `'butt'`       | Stroke endpoint shape                                                                                                                                                                       |
| `lineJoin`       | <ApiValues name="PathLineJoin" />                   | `'miter'`      | Stroke corner shape (visual only, geometry unchanged)                                                                                                                                       |
| `roundedCorners` | `number`                                            | —              | **Geometric** corner radius for line-to-line joints; changes the path geometry, unlike `lineJoin`. See [Path §Rounded corners](/kernel/components/draw/path#rounded-corners-roundedcorners) |
| `thickness`      | <ApiValues name="PathThickness" />                  | —              | Semantic stroke preset; explicit `strokeWidth` wins                                                                                                                                         |
| `arrow`          | `'none'` \| `'->'` \| `'<-'` \| `'<->'`             | —              | Path-level arrow direction                                                                                                                                                                  |
| `arrowDetail`    | `IRArrowDetail`                                     | —              | Detailed arrow configuration; see [Arrow](/kernel/components/draw/arrow)                                                                                                                    |
| `fill`           | `string` \| `IRPaintSpec`                           | `'none'`       | Fill for closed regions: plain color or IRPaintSpec (gradient / pattern / image)                                                                                                            |
| `fillRule`       | <ApiValues name="PathFillRule" />                   | `'nonzero'`    | Fill rule                                                                                                                                                                                   |
| `opacity`        | `number`                                            | —              | Whole-path opacity, 0..1                                                                                                                                                                    |
| `fillOpacity`    | `number`                                            | —              | Fill-only opacity, 0..1                                                                                                                                                                     |
| `strokeOpacity`  | `number`                                            | —              | Stroke-only opacity, 0..1                                                                                                                                                                   |
| `shadow`         | <ApiValues name="ShadowPreset" /> \| `IRDropShadow` | —              | Drop shadow on the main path; endpoint arrows cast a shadow with it. See [Visual Effects](/kernel/components/effects)                                                                       |
| `blendMode`      | <ApiValues name="BlendMode" />                      | `'normal'`     | How the main path blends with content beneath it; endpoint arrows blend with it. See [Visual Effects](/kernel/components/effects)                                                           |
| `zIndex`         | `number` (integer)                                  | `0`            | Explicit stacking order: higher draws on top; ties keep declaration order; effective only among siblings at the same level (forwarded to the underlying `<Path>`)                           |

<Comparison target="tikz" title="Style Naming">

`lineCap` / `lineJoin` map to TikZ `line cap` / `line join`, and `roundedCorners` maps to `rounded corners=`; `strokeOpacity` is stroke-only opacity; `thickness` presets reuse semantic stroke-width names from `ultra thin` through `ultra thick`.

</Comparison>

### Curve / Shape / Label Way Items

| Way item          | Parameters                         | Consumes next item | Equivalent Step      | Description                                                    |
| ----------------- | ---------------------------------- | ------------------ | -------------------- | -------------------------------------------------------------- |
| `{ curve }`       | `[cx, cy]`                         | Yes                | `kind="curve"`       | Quadratic Bezier control point                                 |
| `{ cubic }`       | `[[c1x, c1y], [c2x, c2y]]`         | Yes                | `kind="cubic"`       | Two cubic Bezier control points                                |
| `{ bend }`        | <ApiValues name="BendDirection" /> | Yes                | `kind="bend"`        | Bend direction, default angle 30                               |
| `{ bend, angle }` | `number`                           | Yes                | `kind="bend"`        | Override the bend angle                                        |
| `{ arc }`         | `WayArcOp['arc']`                  | No                 | `kind="arc"`         | Draw an arc around the current point                           |
| `{ circle }`      | `WayCircleOp['circle']`            | No                 | `kind="circlePath"`  | Draw a full circle around the current point                    |
| `{ ellipse }`     | `WayEllipseOp['ellipse']`          | No                 | `kind="ellipsePath"` | Draw a full ellipse centered on the current point              |
| `{ label }`       | `string` \| `IRStepLabel`          | Yes                | `step.label`         | Decorates the next segment; string shorthand equals `{ text }` |

### StepLabel

| Field       | Type                                                   | Default    | Description                                                                                                                                                                            |
| ----------- | ------------------------------------------------------ | ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `text`      | `string`                                               | —          | Label text (single line)                                                                                                                                                               |
| `position`  | <ApiValues name="GeometryLabelPosition" /> \| `number` | `'midway'` | Normalized position t along the segment; keywords are sugar for t (at-start=0 / very-near-start=0.125 / near-start=0.25 / midway=0.5 / near-end=0.75 / very-near-end=0.875 / at-end=1) |
| `side`      | <ApiValues name="Side" />                              | `'top'`    | Edge-label side relative to segment direction. Compass aliases `north` / `south` / `east` / `west` are accepted                                                                        |
| `sloped`    | `boolean`                                              | `false`    | Whether to rotate along the segment tangent                                                                                                                                            |
| `textColor` | `string`                                               | —          | Label text color; falls back to scope `labelDefault` → host path master color → currentColor                                                                                           |
| `opacity`   | `number`                                               | —          | Label-only opacity 0..1; multiplied with the owning path opacity                                                                                                                       |
| `font`      | `IRFont`                                               | —          | Label font overrides (family / size / weight / style)                                                                                                                                  |
