自定义 Path kind 扩展的是**整条路径如何输出**。IR 只保存开放的 `kind` 与 JSON-safe `kindOptions`；宿主注入 `PathKindDefinition` 后，core 从统一 registry 找到 provider，并由它生成 Scene 图元。

下面的 `highlight` kind 复用 Core 描边编译器，只改写线宽。definition、`<Layout pathKinds>` 注入和使用方式都包含在同一个示例中。

## 适用边界

先判断扩展发生在“一个段”还是“整条路径”：

| 需求                                 | 选择                                                 |
| ------------------------------------ | ---------------------------------------------------- |
| 新增一种参数化曲线段                 | [路径生成器](/kernel/components/draw/path-generator) |
| 改变整条 Path 的图元、轮廓或组合方式 | 自定义 Path kind                                     |
| 只增加新的端点造型                   | [自定义箭头](/kernel/components/draw/custom-arrow)   |

如果只是换描边色、线宽、虚线或箭头，直接使用现有 Path props；不要为样式组合创建新的 kind。需要填充式 Ribbon 路径时，见可选的 [Standard Ribbon](/library/standard/extension/ribbon) definition。

## 定义能力

用 `definePathKind` 声明一个显式 registry key、完整 Path subject schema，以及整条路径的 compile 函数。schema 应在开放的 `PathSchema` 上组合该 kind 的 literal 与 `kindOptions`，从而让 definition 自己拥有完整的 payload 约束。

```tsx
const HighlightOptionsSchema = z.strictObject({
  strokeWidth: z.number().positive(),
});
const HighlightPathSchema = PathSchema.extend({
  kind: z.literal('highlight'),
  kindOptions: HighlightOptionsSchema,
});
type HighlightPath = z.infer<typeof HighlightPathSchema>;

const highlight = definePathKind<HighlightPath>({
  name: 'highlight',
  schema: HighlightPathSchema,
  compile: context => {
    const { kindOptions, ...strokePath } = context.path;
    return context.emitStroke({
      ...strokePath,
      kind: 'stroke',
      strokeWidth: kindOptions.strokeWidth,
    });
  },
});
```

`name` 是 registry key，不从 Zod schema 的内部结构推导。`schema` 是该 kind 的完整 source subject schema：Core 的开放 `PathSchema` 先接受共享 host 字段，解析阶段找到 definition 后，再由这个 schema 校验 `kind`、`kindOptions` 与其它跨字段约束。definition 与 compile 函数只存在于运行时，不进入 IR。

### 可选 Inspector

需要为当前 Path kind 提供开发辅助内容时，Path kind 只声明带 schema 的 `ownerOutput`，Inspector 则在 `@retikz/inspect` 中独立定义和注册。下面复用标准描边编译，按需发布最终 commands，并让外部 Inspector 返回普通 Node。

```tsx
const InspectInputSchema = z.strictObject({ summary: z.boolean().optional() });
const InspectOptionsSchema = InspectInputSchema.transform(value => ({
  summary: value.summary ?? true,
}));

const highlightInspector = defineInspector({
  namespace: 'demo',
  name: 'highlight-summary',
  owner: { kind: 'pathKind', name: 'highlight' },
  subjectSchema: StrokePathOwnerOutputSchema,
  optionsInputSchema: InspectInputSchema,
  optionsSchema: InspectOptionsSchema,
  inspect: (subject: StrokePathOwnerOutput, context) =>
    context.options.summary
      ? {
          type: 'node',
          position: [0, 0],
          text: `${subject.commands.length} commands`,
          textColor: context.appearance.scopeColor,
        }
      : [],
});

const highlight = definePathKind({
  name: 'highlight',
  schema: HighlightPathSchema,
  ownerOutput: { schema: StrokePathOwnerOutputSchema },
  compile: context =>
    context.ownerOutput.requested
      ? context.emitStroke(context.path, { captureOwnerOutput: context.ownerOutput.publish })
      : context.emitStroke(context.path),
});

const registry = createInspectorRegistry([highlightInspector]);
```

只有观察者选择当前 owner 时，`ownerOutput.requested` 才为 `true`。非空结果必须恰好发布一次符合 schema 的值；返回 `null` 时不得发布。Inspector 的 `subjectSchema` 再校验一次外部约定，`inspect()` 返回 `IRChild | ReadonlyArray<IRChild>`，没有 `outputSchema`。完整注册、选择与宿主接线见 [`@retikz/inspect`](/kernel/packages/extension/inspect)。

## 注入宿主

React 通过 `<Layout pathKinds>` 注入；直接调用 core 时使用 `CompileOptions.pathKinds`。Path 只引用注册名与实例配置。

```tsx
<Layout pathKinds={[highlight]}>
  <Path kind="highlight" kindOptions={{ strokeWidth: 12 }}>
    <Step kind="move" to="A" />
    <Step kind="line" to="B" />
  </Path>
</Layout>
```

## 执行机制

Core 内置的 `stroke` 与自定义 kind 先合并到同一个 registry。可选的 Standard Ribbon 也只是通过 `pathKinds` 装载的普通 definition，不会改变 Core 的内置集合。编译 Path 时，Core 按 `kind` 查找 definition，再用 definition 的完整 schema 校验 subject，随后把编译上下文交给 provider。

provider 可以完全创建新的 Scene primitive，也可以调用 `emitStroke` 复用现有端点解析、路径命令和箭头逻辑。`materializePath` 提供不带描边装饰的确定性路径命令；`emitHostLabels` 负责共享宿主标签；`appearance` 与 `round` 提供已解析的外观和同次编译精度；`ownerOutput` 只在被观测时发布所属者产物。返回的 `primitives` 与 `boundsPoints` 都使用当前 Path 的局部坐标，外层 Scope 变换随后统一应用。

## 错误与限制

| 情况                                            | 结果                                            |
| ----------------------------------------------- | ----------------------------------------------- |
| definition `name` 为空或不是字符串              | `definePathKind` 立即拒绝                       |
| 与 `stroke` 或自定义项重名                      | registry 合并时报重复注册                       |
| Path 引用未注册 kind                            | 编译列出可用名称与 `options.pathKinds` 注入提示 |
| 选定 definition schema 拒绝 Path                | 错误包含 kind 名和对应 IR 路径                  |
| provider 返回 `null`                            | 该 Path 不产生图元                              |
| 已请求的非空结果未发布 owner output             | Core 观测契约 fail-loud                         |
| owner output 或 Inspector subject 不符合 schema | 对应校验阶段 fail-loud                          |
| Inspector 返回非法 Core child                   | 错误携 owner、occurrence 与 output index        |
| `boundsPoints` 不覆盖真实输出边界               | 自动布局与 Path 级 rotate / scale 依据会失真    |

自定义 kind 返回的是后端中立 Scene primitive，不能把 SVG element、Canvas 实例、ReactNode 或函数塞进结果，也不能要求 renderer 识别自定义 `kind`。

## API 参考

### PathKindDefinition

| 字段          | 类型                            | 默认值 | 描述                                        |
| ------------- | ------------------------------- | ------ | ------------------------------------------- |
| `name`        | `string`                        | —      | 非空 registry key，由 `Path.kind` 引用      |
| `schema`      | `PathKindDefinition['schema']`  | —      | 校验当前 definition 对应的完整 Path subject |
| `compile`     | `PathKindDefinition['compile']` | —      | 为整条 Path 生成 Scene 图元与边界依据       |
| `ownerOutput` | `CompileOwnerOutputDefinition`  | —      | 声明可按需发布的最终所属者产物 schema       |

### InspectorDefinition

| 字段                 | 类型                             | 默认值 | 描述                                          |
| -------------------- | -------------------------------- | ------ | --------------------------------------------- |
| `namespace`          | `string`                         | —      | 与 `name` 组成独立注册键                      |
| `name`               | `string`                         | —      | 与 `namespace` 组成独立注册键                 |
| `owner`              | `CompileObservationOwner`        | —      | 指向被观察的 Path kind                        |
| `subjectSchema`      | `ZodType<JsonValue>`             | —      | 校验 owner output 与 Inspector 的外部约定     |
| `optionsInputSchema` | strict `ZodObject`               | —      | 校验可为空的 runtime 稀疏输入                 |
| `optionsSchema`      | `ZodType<IRJsonObject>`          | —      | 把稀疏输入解析为完整 JSON-safe options        |
| `inspect`            | `InspectorDefinition['inspect']` | —      | 返回一个普通 Core child 或稠密只读 child 数组 |

### compile 上下文

| 字段              | 类型                                       | 默认值    | 描述                                        |
| ----------------- | ------------------------------------------ | --------- | ------------------------------------------- |
| `path`            | `IRPathBase`                               | —         | definition schema 解析后的完整 Path subject |
| `ownerOutput`     | `CompileOwnerOutputPublisher`              | —         | 按需发布带 schema 的最终所属者产物          |
| `materializePath` | `(input?) => MaterializedPath`             | 当前 Path | 物化选定 step，不应用描边装饰               |
| `emitStroke`      | `PathKindCompileContext['emitStroke']`     | 当前 Path | 复用 Core 标准描边编译                      |
| `emitHostLabels`  | `PathKindCompileContext['emitHostLabels']` | —         | 用已定位几何编译共享宿主标签                |
| `appearance`      | `ResolvedPathKindAppearance`               | —         | 提供已解析的、与 renderer 无关的宿主外观    |
| `round`           | `(value: number) => number`                | —         | 使用本次 compile 的取整精度                 |

### PathKindCompileResult

| 字段           | 类型                    | 默认值 | 描述                                   |
| -------------- | ----------------------- | ------ | -------------------------------------- |
| `primitives`   | `Array<ScenePrimitive>` | —      | 当前 Path 局部坐标中的实际输出         |
| `boundsPoints` | `Array<Position>`       | —      | 自动布局与 Path 级变换使用的关键边界点 |
