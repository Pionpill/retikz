Choose the form by the role in the diagram: flowchart nodes usually use the default rectangle + `padding`; plain text labels use `stroke="none"` / `fill="none"`; button-like nodes add `cornerRadius` + `minimumSize`; annotation cards fit multi-line `text` + `align="left"`; and if you only need a reference point with no visible shape, use [Coordinate](/kernel/components/node/coordinate) instead.

### Positioning

#### Relative positioning

In addition to Cartesian / polar, `position` accepts **`{ direction, of, distance? }`**. No more hand-computing absolute coordinates; describe node relationships instead.

- `direction`: 8 directions — `top` / `bottom` / `left` / `right` / `top-left` / `top-right` / `bottom-left` / `bottom-right`
- `of`: id of the referenced node / coordinate (must be defined earlier in the IR; forward references rejected)
- `distance`: falls back to `<Layout nodeDistance>` then to 24 when omitted

<ComponentPreview files="node-at-relative" size="sm" />

#### Offset positioning

`position` also accepts **`{ of, offset }`** — an arbitrary `(dx, dy)` offset from a base point. Use offset whenever the 8-direction + scalar-distance relative form can't express what you want (e.g. "A right 30 down 10").

- `of` is the base point in three shapes (matching `PolarPosition.origin`):
  - string id — references a named node / coordinate (forward references rejected)
  - `[x, y]` Cartesian literal — direct coordinate base, no node definition needed
  - `PolarPosition` (`{ angle, radius, origin? }`) — polar expression as base, recursively resolved
- `offset` is a `[dx, dy]` tuple in user units

<ComponentPreview files="node-offset-position" size="sm" />

#### Proportional positioning

`position` also accepts **`{ between, fraction }`**: place the node at a proportional point between two endpoints, with `fraction: 0.5` as the midpoint. Endpoints may be node ids, coordinates, polar positions, offsets, or nested between positions; see [Coordinate](/kernel/components/node/coordinate) for a fuller midpoint-helper example.

<Comparison target="tikz" title="Node Positioning Syntax">

| retikz                                        | TikZ mapping                          |
| --------------------------------------------- | ------------------------------------- |
| `{ direction: 'top', of: 'a', distance: 20 }` | positioning-library `[above=20 of a]` |
| `<Layout nodeDistance={...}>`                 | global `node distance`                |
| `{ of: 'a', offset: [10, 5] }`                | calc-library `($(a) + (10,5)$)`       |

Directional positioning also accepts compass names such as `north` and legacy aliases such as `above`.

</Comparison>

### Shapes

A node's geometric shape drives its visual look and how edges clip to it.

#### Shape polymorphism

Shapes have two faces in retikz — drawn as a Path with sugar, or used as a Node boundary; see [Shapes](/kernel/components/shapes) for the full definition. This section covers the Node-shape side.

`shape` picks the visual shape in two forms:

- **Bare string** (parameterless shapes): `'rectangle'` (default) / `'circle'` / `'ellipse'` / `'diamond'`, or a custom name with no required params registered via `<Layout shapes>` / `CompileOptions.shapes`.
- **`{ type, params }` object** (parametric shapes): when a shape needs extra geometry (sides / inner & outer radii / start & end angles…), pick it with `type` and pass the params. `polygon` / `sector` / `arc` / `star` have required params and **must** use `{ type, params }` — a bare string like `shape="polygon"` throws at compile time because the param validation fails.

Either way, the node works as an attachable target — connecting lines clip to that shape's boundary automatically.

Shapes split into two families by where their size comes from: **text-container shapes** (rectangle / circle / ellipse / polygon / diamond) wrap "text + padding" and are sized by the text; **params-driven geometric shapes** (sector / arc / star) are sized by radii / angles, independent of the text, and work as attachable graphic glyphs.

<ComponentPreview files="node-shape-params" size="md" />

For each shape's parameters, anchors, and examples, see its shape page:

| shape             | form                                       | docs                                                         |
| ----------------- | ------------------------------------------ | ------------------------------------------------------------ |
| rectangle         | default / `'rectangle'`                    | [Rectangle](/kernel/components/shapes/rectangle)             |
| circle / ellipse  | `'circle'` / `'ellipse'`                   | [Circle / Ellipse](/kernel/components/shapes/circle-ellipse) |
| sector / arc      | `{ type:'sector' \| 'arc', params }`       | [Arc / Sector](/kernel/components/shapes/arc-sector)         |
| polygon / diamond | `{ type:'polygon', params }` / `'diamond'` | [Polygon](/kernel/components/shapes/polygon)                 |
| star              | `{ type:'star', params }`                  | [Star](/kernel/components/shapes/star)                       |

`shape` also accepts registered names beyond the built-ins (hexagon / cylinder / cloud…) — any string passes schema validation, the definition is injected via `CompileOptions.shapes` / `<Layout shapes>`, and unregistered names throw at compile time. Parametric registered shapes pass their params through `{ type, params }`. See [Custom Shapes](/kernel/components/shapes/custom-shape).

#### Connection surface (boundary)

By default, edges clip against the node's visual shape boundary. When you want edges to meet a different shape without changing the node's real footprint, set `boundary` to pick an independent "connection surface". The common case is concave shapes like stars and polygons — you keep the spiky look but want edges to arrive evenly as if meeting a circle, instead of diving into the notches.

`boundary` takes the same forms as `shape`. The four parameter-free values below are the common ones; other names first check [Custom Boundaries](/kernel/components/node/custom-boundary), then fall back to any registered shape:

| Value                                                    | Connection surface                                               | Effect                                                                                                    |
| -------------------------------------------------------- | ---------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| `'shape'` (default)                                      | The visual shape itself                                          | Edges clip to the real outline — stars / polygons land on tips or dive into notches                       |
| `'circle'`                                               | A true circle, radius = the node's larger bounding-box half-axis | Edges meet it evenly all around, unaffected by notches / rotation                                         |
| `'rectangle'`                                            | The bounding box (AABB)                                          | Edges clip to the horizontal / vertical box sides                                                         |
| `'ellipse'`                                              | An ellipse matching the AABB aspect ratio                        | Edges clip to the ellipse, stretched with the aspect ratio                                                |
| Custom boundary or registered shape / `{ type, params }` | Boundary provider first; shape fallback second                   | Parametric providers need explicit params; auto-fitting a borrowed shape size to the AABB is out of scope |

The same five-point star set to four surfaces, each with one edge clipping in from the lower-left at 45° — `shape` lands on the real star outline (innermost), `rectangle` reaches the bounding-box corner (outermost), and `circle` / `ellipse` sit in between (close together for a near-square node). A diagonal is needed to tell them apart: on a vertical / horizontal axis an inscribed ellipse always meets the rectangle at the same point and the circle takes the larger half-axis, so the three coincide there:

<ComponentPreview files="node-boundary-surfaces" size="sm" />

The connection surface **never changes the node footprint**: bounding box, visual shape, and layout position stay the same — it only changes where edges clip and how standard direction anchors resolve. Shape-specific anchors (such as a star's `tip-0`) and edge proportional points always resolve against the visual shape, regardless of `boundary`.

In the example below the five-point star has `boundary="circle"`: the solid edge clips to the circumscribing circle by default, while the dashed edge with `boundary="shape"` on its endpoint clips to the real tip instead.

<ComponentPreview files="node-boundary" size="sm" />

To override a target node's `boundary` for a single edge, set `boundary` on the path endpoint object — it affects only that one endpoint and takes the same values as the node's `boundary`. See the endpoint `boundary` notes on [Path](/kernel/components/draw/path).

### Size & transforms

#### Padding / margin

Spacing uses a CSS-like nested object: side fields win, then `x` / `y`, then `default` and system defaults.

- Inner: `padding={N}` or `padding={{ default, x, y, left, right, top, bottom }}`
- Outer: `margin={N}` or `margin={{ default, x, y, left, right, top, bottom }}`

Most nodes only need `padding={N}`. Use `padding={{ x, y }}` when horizontal and vertical spacing need different values; use `left` / `right` / `top` / `bottom` only when one side needs a special value.

<ComponentPreview files="node-sep" size="xs" />

#### Size constraints + scale

- `cornerRadius` — corner radius. `rectangle` / `polygon` / `star` / `sector` support rounding (`ellipse` and the like do not) via their params: `shape={{ type:'polygon', params:{ sides:6, cornerRadius:8 } }}`, and likewise for `star` / `sector` / `rectangle`. The top-level `cornerRadius` only affects the `rectangle` shape (default or explicit `'rectangle'`), and only merges when params don't already set `cornerRadius` (params wins when both are set)
- `minimumSize` — floor the bbox without shrinking natural text width
- `scale` — uniform / per-axis scale; affects bbox, font size, padding, and path attachment

<ComponentPreview files="node-size-constraints" size="xs" />

### Text

#### Font

`font` is a nested object `{ family?, size?, weight?, style? }` — bold / italic / family all live in one prop:

<ComponentPreview files="node-font" size="xs" />

#### Multi-line text

`text` accepts a string or an array of strings (one line each). A `'\n'` inside a string is a hard line break, so a single string can render as multiple lines. `align` controls horizontal alignment within the text block (`'start'` / `'middle'` (default) / `'end'`), and `lineHeight` controls vertical spacing between lines, defaulting to `font.size × 1.2`.

<ComponentPreview files="node-multiline" size="xs" />

> Arrays beat `'\n'`-delimited strings: JSON-friendly (no escape headaches), and leaves room for per-line attributes later.

You can also pass the text as `children` — pick whichever form reads best:

```tsx
{
  /* string with \n */
}
<Node>{'Line 1\nLine 2'}</Node>;

{
  /* template literal (real newlines) */
}
<Node>{`Line 1
Line 2`}</Node>;

{
  /* array */
}
<Node>{['Line 1', 'Line 2']}</Node>;
```

`text` wins over `children` whenever both are supplied.

#### Auto-wrap

`maxTextWidth` sets a **wrap threshold** (user units): text wraps past the threshold (Western on word boundaries, CJK per character), and short text shrinks the box to its actual content instead of filling the width. It is **not a fixed paragraph width**.

<ComponentPreview files="node-max-text-width" size="sm" />

> An unbreakable long token (a long run with no whitespace) that exceeds the threshold overflows as a whole rather than being hard-cut.

#### Per-line styling

Each line can override `fill` / `opacity` / `font` (any subset of family / size / weight / style); unset fields inherit block defaults. Two equivalent paths:

1. **Mix LineSpec objects into the `text` array** — JSON / AI-friendly, schema-expressible
2. **`<Text>` child elements** — natural JSX; see the [Text page](/kernel/components/node/text) for the dedicated docs

<ComponentPreview files="node-styled-lines" size="xs" />

> Block-level `align` / `lineHeight` cannot be overridden per line — they apply to the whole multi-line block.

Multi-line text combined with each shape — outer boundary follows the shape-specific circumscription (circle / ellipse / polygon):

<ComponentPreview files="node-multiline-shapes" size="xs" />

### Node labels

`label` attaches extra text to the node border. Single object or array form; `position` accepts the 8-direction enum (default `'top'`), `'center'`, a numeric angle, or a `{ boundary, fraction }` proportional boundary point; `placement` chooses whether the label is offset outside or inside the attachment point and defaults to `'outside'`; `'center'` draws the label directly at the node center with no collision avoidance; `font` / `textColor` inherit from the node when omitted, and `opacity` controls the label's own opacity (0..1, multiplied with the node `opacity`).

<ComponentPreview files="node-label-basic" size="xs" />

`distance` controls how far the label is pushed outward from the node border, still in retikz user units. It defaults to `12`; for example, `position: 'top', distance: 20` places the label further above the node's top border.

<ComponentPreview files="node-label-distance" size="xs" />

#### Inside and Boundary Positions

`placement: 'inside'` offsets the label from its attachment point toward the node interior, with `distance` still controlling the offset length. Direction and numeric-angle positions support inside placement; rectangle nodes can also use `position: { boundary, fraction }` to attach to a proportional point on a specific box side.

- `boundary` accepts `'top'` / `'right'` / `'bottom'` / `'left'`
- `fraction` is the 0..1 proportional position on that side and defaults to `0.5`
- `placement: 'inside'` cannot be combined with `pin`; keep labels outside when a leader line is needed

<ComponentPreview files="node-label-inside" size="sm" />

#### Orientation

`label.rotate` spins the label text around **its own center**: `'radial'` along the node-center → label-center direction, `'tangent'` is its tangent (radial + 90°), a number is an explicit angle (degrees); `keepUpright` flips it 180° when it would otherwise read upside-down. `rotate` only changes orientation, not the placement determined by `position` / `distance`.

<ComponentPreview files="node-label-rotate" size="sm" />

#### Pin

`label.pin` adds a **leader line** from the node border to the label: `pin: true` is a default thin solid line (inherits the label color); `pin: { stroke, strokeWidth, dashPattern, dashOffset }` customizes it; omitted / `false` = no leader. The label is still placed by `position` / `distance` — pin only adds the leader.

<ComponentPreview files="node-pin" size="md" />

### Stacking order (zIndex)

By default stacking = declaration order (SVG only honors paint order). `zIndex` overrides it explicitly: higher draws on top, omitted = 0, ties keep declaration order; effective only among siblings at the same level (same scope / top level). For example, lift a highlighted node with `zIndex={10}` above all connecting paths without moving it to the end of the JSX. `<Path>` / `<Scope>` support `zIndex` too (a scope's `zIndex` positions the whole group among its siblings without affecting the relative stacking inside it).

#### Colors / opacity

- `textColor` — text color (block default; per-line `LineSpec.fill` still overrides)
- `opacity` — whole-node 0..1 (applies to shape + text)
- `fillOpacity` / `strokeOpacity` — fill-only / stroke-only opacity

<ComponentPreview files="node-color-opacity" size="xs" />

#### Gradient fill and stroke

Besides a plain color string, `fill` / `stroke` accept a **PaintSpec object** — linear / radial / conic gradient, pattern, or image. Identical PaintSpecs are deduplicated automatically and rendered as a paint server inside SVG `<defs>`. `<Path fill>` / `<Path stroke>` support it too.

- Linear: `{ kind: 'linearGradient', angle?, stops }` — `angle` in degrees (0 = left→right, 90 = top→bottom)
- Radial: `{ kind: 'radialGradient', center?, radius?, stops }` — `center` / `radius` in 0..1 relative units
- Conic: `{ kind: 'conicGradient', center?, angle?, stops }` — angular interpolation around `center`, useful for polar / sector color ramps
- `stops`: array of `{ offset (0..1), color, opacity? }`, at least 2; `color` may be `currentColor`

<ComponentPreview files="node-paint" size="sm" />

A node border can use gradient stroke as well; `strokeWidth`, `strokeOpacity`, `dashPattern`, `dashOffset`, and other stroke styles keep applying:

<ComponentPreview files="node-stroke-paint" size="sm" />

A stop's `opacity` gives a "solid → transparent" fade; `color` set to `currentColor` makes the gradient follow the element's `color` and react to theme changes:

<ComponentPreview files="node-paint-stops" size="sm" />

`fill` also accepts **pattern** and **image**:

- Pattern: `{ kind:'pattern', shape:'lines'|'dots'|'grid', color?, background?, size?, lineWidth?, rotation? }` — `color` defaults to `currentColor`, `size` is the tile period, `rotation` rotates the whole pattern
- Image: `{ kind:'image', href, fit? }` — `href` is a URL (incl. data URI), `fit`: `cover` (default) / `contain` / `fill`

<ComponentPreview files="node-pattern-image" size="sm" />

`href` takes any external image URL (http(s)) or a data URI; `fit` controls how the image maps into the shape box — the same external landscape image (`picsum.photos`, 320×200) under all three fits in a square box:

<ComponentPreview files="node-image-fit" size="sm" />

> `fit` is computed against the normalized shape box: it matches CSS `object-fit` for square boxes; for strongly non-square boxes cover/contain are approximate (against the normalized square, not the true aspect ratio). When the source and box share a shape (both square / both landscape) the three fits look identical.
>
> Image fill renders via a runtime `<image href>`, so external URLs load on the browser side; inlining for SSR / PNG export is deferred.

### From props to a referenceable node

The compiler first resolves the style-inherited `position`, content, and geometry props into one Node layout. That layout serves two outputs: shape, text, and labels become Scene primitives, while `id`, anchors, and the connection boundary become named geometry that `<Path>` / `<Draw>` can query.

<ComponentPreview files="node-layout-flow" size="md" hideCode />

Node sizing converges in a fixed order: text is measured and wrapped first; `padding` forms the content box; the shape definition computes a visual circumscribed box from that box and its params; then `minimumSize` applies a floor. `scale` affects fonts, spacing, and shape params from the start, while `rotate` is attached to the resolved geometry.

`label` does not participate in visual shape sizing. Labels are laid out as separate attached primitives, so they do not enlarge the node border, but their extents join `margin` and shadow when the automatic viewBox is collected.

### Visual shape vs connection geometry

`shape` owns the rendered contour and shape-specific anchors. `boundary` participates only when resolving automatic path endpoints, standard directional anchors, and numeric-angle anchors. The two geometry paths coincide only when `boundary` is omitted or set to `'shape'`.

| Reference form                        | Geometry used                    |
| ------------------------------------- | -------------------------------- |
| Automatic endpoint, `.top`, or `.30`  | `boundary`, expanded by `margin` |
| Shape-specific anchor such as `tip-0` | Visual `shape`                   |
| `{ side, fraction }` edge point       | Visual `shape`                   |

As a result, `margin` pushes connection endpoints and standard border anchors outward and expands the node's layout footprint, but never redraws the visual shape. Shape-specific anchors and edge points stay on the original contour. If a shape does not implement a standard directional anchor, core falls back to its bounding rectangle.

### Why named positioning is order-sensitive

Node positioning resolves immediately when traversal reaches that node: the compiler queries the current namespace first, then registers the node's `id` only after its layout is known. A `position` that refers to a later Node / Coordinate in the same scope therefore fails, and cyclic positioning cannot resolve.

Path / Draw endpoints use a different phase. A path first reserves its drawing-order slot, then resolves only after every Node and Coordinate in the current scope has registered. Path endpoints can therefore refer to later sibling nodes.

### margin vs padding

|           | Affects                                     | Visual effect                                                                                                                 |
| --------- | ------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `padding` | Distance from text to border                | Visible shape grows                                                                                                           |
| `margin`  | Outer offset around the connection boundary | Visible shape unchanged; all border anchors and path endpoints move out by `margin`, and the node footprint includes `margin` |

`padding` grows the node itself; `margin` leaves the visible shape untouched but pushes the node's connection/reference boundary outward (including explicit anchors like `.top`) and reserves that much extra space in layout. `margin` defaults to 0, so unset means zero effect.

| `children` / `text` | `string \| Array<string \| LineSpec>` | —                 | Visible label; `'\n'` in a string is a hard line break, array = one element per line; array elements may mix `LineSpec` objects (`{ text, fill?, opacity?, font? }`) for per-line overrides; `text` wins over `children`                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `align`             | `'start' \| 'middle' \| 'end'`        | `'middle'`        | Horizontal alignment of lines within the multi-line text block                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `lineHeight`        | `number`                              | `font.size × 1.2` | Line height of the multi-line block (user units)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `maxTextWidth`      | `number`                              | —                 | Wrap threshold (user units); text wraps past it (Western per word / CJK per char) and the box shrinks for short text; not a fixed paragraph width                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `font`              | `{ family?, size?, weight?, style? }` | —                 | Font spec; nested object, all fields optional                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `textColor`         | `string`                              | `currentColor`    | Text color (block default; per-line override via `LineSpec.fill`)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `label`             | `NodeLabel \| Array<NodeLabel>`       | —                 | Extra label(s) attached to the node border; single object or array; `position` accepts the 8-direction enum (default `'top'`), `'center'`, a numeric angle, or `{ boundary, fraction }` on a rectangle boundary; `placement` defaults to `'outside'` and can be `'inside'`; `distance` defaults to 12, `font` / `textColor` inherit from the node, `opacity` controls the label's own opacity 0..1; `rotate` (`'none'` / `'radial'` / `'tangent'` / a number of degrees) + `keepUpright` control label spin; `pin` (`true` default line / `{ stroke, strokeWidth, dashPattern, dashOffset }` styled / omitted = none) draws a leader and is only supported for outside labels |
