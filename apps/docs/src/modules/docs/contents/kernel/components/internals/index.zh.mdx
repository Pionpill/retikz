有时图形的声明看起来正确，但你仍想知道位置怎样算出来、主题在哪里生效，或输出为什么与预期不同。内部机制从这些问题出发，追踪输入怎样变成结果。日常画图不必先读这些专题，本总览只帮助你判断何时需要深入。

## 职责一览

| 章节     | 职责                          | 何时阅读                 |
| -------- | ----------------------------- | ------------------------ |
| 编译流程 | 追踪声明到布局及 Scene 的过程 | 分析位置、端点或编译结果 |
| 主题解析 | 追踪主题继承、颜色与结果复用  | 分析组件实际消费的主题   |

## 从声明到可见结果

IR 是描述对象与关系的可保存声明；Scene 是已经确定位置与样式、可交给渲染器执行的结果。编译负责连接这两者。主题在其中提供共享的风格与颜色环境，由使用它的组件转换成明确样式。

下图展示复合组件消费主题的一条路径：主题给出环境，复合组件解释环境，基础图元保留具体画法。其他消费主题的能力也可以解释环境，并不必须经过复合组件。看到颜色不符合预期时，先判断问题发生在哪个角色，而不是直接从最终 SVG 开始查找。

## 用一个问题串起两个专题

假设一个带文字的复合组件放进深色分组。你想确认文字怎样参与布局，以及它为什么选择了当前颜色。这涉及同一次编译中的两个问题：编译流程决定对象如何布局并形成输出，主题解析决定组件读取到什么风格和颜色环境。

布局问题追踪测量与编译，颜色问题追踪主题解析；颜色本身不改变布局，只有影响文本度量的样式才可能同时影响测量结果。两个专题相互配合，但不能互相替代。改变主题不等于改变位置表达；输出一个 Scene 也不意味着渲染器还会重新解释主题。先定位职责，再深入对应执行过程，通常比从所有函数中寻找答案更直接。

## 带着观察结果阅读

| 要确认的问题                 | 先准备的信息                     |
| ---------------------------- | -------------------------------- |
| 节点位置或连接端点不符合预期 | 最小图形声明、对象名称与期望位置 |
| 组件没有使用预期的明暗风格   | 外层和局部主题选择、具体消费组件 |
| 想跟踪一次调用产生什么       | 输入声明、编译选项与最终结果     |

专题会从这些输入出发说明阶段、产物与源码位置，不要求你预先记住内部函数名称。尽量使用一个能复现现象的小例子，避免把整张业务图的所有因素同时带入。

## 阅读前提与边界
