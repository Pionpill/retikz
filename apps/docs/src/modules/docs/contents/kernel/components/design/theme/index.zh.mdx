一组图形需要保持共同风格时，可以传递主题环境，而不必在每个对象上重复指定颜色。Theme 描述环境，图元样式描述最终画法；两者不是同一条通道。

## 主题与样式

下图中的组合负责读取主题，把它转换成节点、路径等基础图元的明确样式。渲染器只执行结果，不重新解释主题。

<ComponentPreview files="theme-flow" size="xs" hideCode />

| 内容     | 职责               | 消费者     |
| -------- | ------------------ | ---------- |
| style    | 选择视觉风格       | 主题解析器 |
| mode     | 选择浅色或深色环境 | 主题解析器 |
| colors   | 共享语义色与分类色 | Composite  |
| 图元样式 | 明确填充、描边等   | renderer   |

因此，切换主题不保证手写 Node、Path 自动换色。它们的显式样式仍然有效；只有消费主题的组合才会把环境变成可见差异。

## 公共主题

Kernel 通过 Core 提供默认中性配色，支持 `light` 与 `dark` 两种模式。没有继承或显式选择风格时使用这套基线；根环境默认是 `light`，不需要填写 `style: 'neutral'`。

| 公共内容           | 作用                   |
| ------------------ | ---------------------- |
| `semantic.error`   | 错误                   |
| `semantic.success` | 成功                   |
| `semantic.warning` | 警告                   |
| `semantic.guide`   | 低强调辅助内容         |
| `categorical`      | 区分不同类别的非空色板 |

默认分类色板有 16 色，明暗模式保持类别索引与色相顺序一致，调整明度与饱和度。它只提供可复用的颜色，不规定图表、表格或流程图如何分配这些颜色。

## 数据结构

主题分为两份不同用途的数据：`IRTheme` 保存作者选择，`ResolvedTheme` 是编译当前位置供组合读取的有效环境。

| 数据                  | 字段                       | 含义                       |
| --------------------- | -------------------------- | -------------------------- |
| `IRTheme`             | `style?`、`mode?`          | 稀疏选择，省略字段沿用外层 |
| `ResolvedTheme`       | `style?`、`mode`、`colors` | 继承和风格解析后的只读结果 |
| `ResolvedThemeColors` | `semantic`、`categorical`  | 共享语义色与当前分类色板   |

下面只展示数据形状；`Color` 代表 CSS 颜色字符串，不是新增的公开类型：

```text
IRTheme
  style?: string
  mode?: 'light' | 'dark'

ResolvedTheme
  style?: string
  mode: 'light' | 'dark'
  colors
    semantic: { error: Color, success: Color, warning: Color, guide: Color }
    categorical: 非空 Color 数组
```

`colors` 不写入 `IRTheme`，而是由当前模式和风格解析器生成。自定义风格可逐项覆盖语义色；显式提供分类色板时整体替换默认色板，不要求仍为 16 色。风格定义中的 `resolve` 函数属于运行环境，不进入可持久化 IR。

## 继承

IRScene 是可保存的根绘图声明，Scope 是其中的局部分组；编译后的 Scene 才是渲染器消费的结果。主题按字段从外向内继承：内层只指定 mode 时，仍沿用外层 style；只指定 style 时，仍沿用外层 mode。

例如，根环境是“学术／浅色”，一个子组只改为“深色”，它得到的仍是“学术／深色”，不会重置成另一种风格。主题的继承也不等于节点样式默认值的继承。

主题可以随图形声明保存，自定义风格的实现仍需由运行环境提供。只有确实消费该风格的组件才会改变外观；缺少所需风格实现会报告错误。
