Use `arrow.start` / `arrow.end` for endpoint arrows and `marks` for content along a path. Both can coexist. Start with [Basic usage](/kernel/components/path/usage) if you are new to paths.

## Endpoint arrows

React, Vanilla, and JSON IR share the same object structure. Declare only the endpoints you need. An empty endpoint object creates the default `stealth` arrow; an omitted endpoint creates nothing.

React and Vanilla also accept direction shorthands: `arrow="->"` equals `{ end: {} }`, `arrow="<-"` equals `{ start: {} }`, and `arrow="<->"` equals `{ start: {}, end: {} }`. Vanilla normalizes these into endpoint objects; JSON IR uses the object form. Use endpoint objects to configure shape, dimensions, or overlap.

```tsx
<Draw way={['A', 'B']} arrow="->" />
```

<ComponentPreview files="arrow-basic" size="xs" />

```tsx
import { Draw, Layout } from '@retikz/react';

export default () => (
  <Layout>
    <Draw
      way={[
        [0, 0],
        [120, 0],
      ]}
      arrow={{ start: { shape: 'circle' }, end: { shape: 'stealth', scale: 1.5 } }}
    />
  </Layout>
);
```

Vanilla `path({ way, arrow })` and IR `{ type: 'path', children, arrow }` accept the same `arrow` object. Each endpoint independently configures `shape`, `color`, `fill`, `stroke`, `length`, `width`, `scale`, `opacity`, and outline fields. Use object spread to reuse shared settings.

## Appearance and defaults

Core provides `normal`, `open`, `stealth`, `openStealth`, `circle`, and `openCircle`. Register additional Extension arrows through `Layout.extensions.arrows` or `CompileOptions.arrows`. Custom names use the same registry; see [Custom arrows](/kernel/components/path/custom-arrow).

<ComponentPreview files="arrow-appearance" size="sm" />

Length and width default to 8. Final dimensions also multiply the arrow's `scale` and the host stroke width. Master color, explicit fill, and stroke follow arrow style rules. Host opacity multiplies arrow opacity, preserving an explicit `0`. Outline `lineWidth` uses arrow-local coordinates.

`defaults.path.arrow` supplies shared appearance and `start` / `end` defaults. Shared appearance applies to endpoint arrows and arrow-shaped marks; endpoint branches apply only to the corresponding endpoint arrows. Defaults never create arrows or marks.

## Endpoint overlap

`arrow.start.endpointOverlap` / `arrow.end.endpointOverlap` controls how far an arrow crosses its logical endpoint. At `0`, the tip is at the endpoint; at `1`, the final visual back aligns with it; `0.5` is halfway between. This does not change NodeTarget resolution, boundary clipping, or logical mark sampling.

<ComponentPreview files="arrow-endpoint-overlap" size="sm" />

```tsx
<Draw way={['A', 'B']} arrow={{ start: { endpointOverlap: 0 }, end: { shape: 'openCircle', endpointOverlap: 0.5 } }} />
```

Endpoint arrows shorten the main stroke according to their contact geometry so it does not cross hollow content. Visibility inside a node still follows drawing order and `zIndex`; overlap does not create clipping or change node fills. `endpointOverlap` applies only to endpoint arrows on the built-in Stroke Path.

## Marks along a path

Use [mark · Marks](/kernel/components/path/mark) to place primitives at any position along a path. Marks can reuse registered arrows without shortening the path. See [Custom marks](/kernel/components/path/custom-mark) for new ordinary mark shapes.
