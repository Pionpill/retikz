title: arrow · Arrows and marks
description: Configure endpoint arrows and place marks at arbitrary arc-length positions
---

Use `arrow.start` / `arrow.end` for endpoint arrows and `marks` for content along a path. Both can coexist. Start with [Basic usage](/kernel/components/path/usage) if you are new to paths.

## Endpoint arrows

React, Vanilla, and JSON IR share the same object structure. Declare only the endpoints you need. An empty endpoint object creates the default `stealth` arrow; an omitted endpoint creates nothing.

React and Vanilla also accept direction shorthands: `arrow="->"` equals `{ end: {} }`, `arrow="<-"` equals `{ start: {} }`, and `arrow="<->"` equals `{ start: {}, end: {} }`. Vanilla normalizes these into endpoint objects; JSON IR uses the object form. Use endpoint objects to configure shape, dimensions, or overlap.

```tsx
<Draw way={['A', 'B']} arrow="->" />
```

<ComponentPreview files="arrow-basic" size="xs" />

```tsx
import { Draw, Layout } from '@retikz/react';

export default () => (
  <Layout>
    <Draw
      way={[
        [0, 0],
        [120, 0],
      ]}
      arrow={{ start: { shape: 'circle' }, end: { shape: 'stealth', scale: 1.5 } }}
    />
  </Layout>
);
```

Vanilla `path({ way, arrow })` and IR `{ type: 'path', children, arrow }` accept the same `arrow` object. Each endpoint independently configures `shape`, `color`, `fill`, `stroke`, `length`, `width`, `scale`, `opacity`, and outline fields. Use object spread to reuse shared settings.

## Appearance and defaults

Core provides `normal`, `open`, `stealth`, `openStealth`, `circle`, and `openCircle`. Register additional Extension arrows through `Layout.extensions.arrows` or `CompileOptions.arrows`. Custom names use the same registry; see [Custom arrows](/kernel/components/path/custom-arrow).

<ComponentPreview files="arrow-appearance" size="sm" />

Length and width default to 8. Final dimensions also multiply the arrow's `scale` and the host stroke width. Master color, explicit fill, and stroke follow arrow style rules. Host opacity multiplies arrow opacity, preserving an explicit `0`. Outline `lineWidth` uses arrow-local coordinates.

`defaults.path.arrow` supplies shared appearance and `start` / `end` defaults. Shared appearance applies to endpoint arrows and arrow-shaped marks; endpoint branches apply only to the corresponding endpoint arrows. Defaults never create arrows or marks.

## Endpoint overlap

`arrow.start.endpointOverlap` / `arrow.end.endpointOverlap` controls how far an arrow crosses its logical endpoint. At `0`, the tip is at the endpoint; at `1`, the final visual back aligns with it; `0.5` is halfway between. This does not change NodeTarget resolution, boundary clipping, or logical mark sampling.

<ComponentPreview files="arrow-endpoint-overlap" size="sm" />

```tsx
<Draw way={['A', 'B']} arrow={{ start: { endpointOverlap: 0 }, end: { shape: 'openCircle', endpointOverlap: 0.5 } }} />
```

Endpoint arrows shorten the main stroke according to their contact geometry so it does not cross hollow content. Visibility inside a node still follows drawing order and `zIndex`; overlap does not create clipping or change node fills. `endpointOverlap` applies only to endpoint arrows on the built-in Stroke Path.

## Marks along a path

Each `marks` entry contains `pos`, optional `rotate` / `scale`, and `mark`. `pos` is a fraction of the entire path's accumulated arc length, from 0 to 1. Sampling follows routing, node-boundary clipping, and geometric corner rounding, before endpoint shortening, label interruptions, and whole-path transforms.

```tsx
<Draw
  way={[
    [0, 0],
    [30, 0],
    [120, 60],
  ]}
  arrow="->"
  marks={[
    { pos: 0, mark: { kind: 'arrow', shape: 'circle' } },
    { pos: 0.5, rotate: 'auto', mark: { kind: 'arrow', shape: 'stealth' } },
    { pos: 1, rotate: 30, scale: 1.5, mark: { kind: 'arrow', shape: 'open' } },
  ]}
/>
```

Marks only place primitives. They do not shorten strokes, cut holes, or avoid labels, even at `pos: 0` or `pos: 1`. Arrow-shaped marks reuse registered arrow definitions directly, anchor at the tip, and retain arrow sizing rules. They cannot specify `endpointOverlap`.

Omitted `rotate` or `'auto'` follows the path tangent. A number specifies a fixed angle in path-local coordinates. `scale` adds a placement scale, defaulting to 1. Moves contribute no length; closing segments do. At a segment boundary the next nonzero segment supplies the direction; the final endpoint uses the incoming direction. A nonempty mark list on a wholly zero-length path fails.

The main stroke and endpoint arrows paint first, marks paint in list order, and path labels paint last. Full mark content contributes to visual bounds and follows whole-path transforms.

## Custom marks

An ordinary mark emits basic Scene primitives with the local origin as its anchor. Its dimensions use user units and do not scale with host stroke width. Definitions stay outside JSON IR, which stores only a name and JSON parameters.

```tsx
import { defineMark } from '@retikz/core';
import { Draw, Layout } from '@retikz/react';

const dot = defineMark({
  name: 'dot',
  emit: (_params, { stroke }) => [{ type: 'ellipse', cx: 0, cy: 0, rx: 4, ry: 4, fill: stroke }],
});

export default () => (
  <Layout extensions={{ marks: [dot] }}>
    <Draw
      way={[
        [0, 0],
        [120, 0],
      ]}
      marks={[{ pos: 0.5, mark: { kind: 'custom', name: 'dot', params: {} } }]}
    />
  </Layout>
);
```

Register directly with `compileToScene(ir, { marks: [dot] })`. `emit(params, context)` returns `Iterable<ScenePrimitive>`; context supplies the host `stroke` and precision function `round`. Each definition interprets its own parameters. Fixed styles remain intact. Existing Scene resource references are supported, but their resources must exist.

Mark hits belong to the host Path. `pointerEvents: 'none'` excludes content, and internal primitives do not become independent authoring nodes. Animation and nested content follow Scene contracts; reused definitions produce independent primitive instances. Unknown definitions, missing resources, and emission failures produce errors.

## API reference

See [Path API reference](/kernel/components/path/reference) for complete fields. Endpoints use `PathArrowSchema`, placements use `PathMarkPlacementSchema`, and ordinary definitions use `MarkDefinition`.
