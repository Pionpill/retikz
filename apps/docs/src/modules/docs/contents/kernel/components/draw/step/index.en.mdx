## Usage

```tsx
import { Path, Step } from '@retikz/react';
```

```tsx
<Path>
  <Step kind="move" to="a" />
  <Step kind="line" to="b" />
</Path>
```

Use `<Step>` when you need exact control over Kernel path actions: multiple `move`s, mixed straight / folded / curved / arc segments, or debugging the structure produced by `<Draw>`. For everyday connections, prefer [Draw](/kernel/components/draw/overview).

## Examples

### Basic actions

Switch between `line`, repeated `move`s, `fold`, `cycle`, and `rectangle` in one panel. Repeated `move`s begin independent subpaths inside one `<Path>`; `fold` exposes its corner direction, `rectangle` exposes its corner radius, and `cycle` closes back to the most recent `move` target.

<ComponentPreview files="step-actions" size="md" />

### Target positioning

Besides absolute coordinates, `to` accepts `{ of, offset }`, `{ relative }`, and `{ relativeAccumulate }`. Switch modes and adjust x / y in the panel to see how their anchors differ:

- `offset`: offset from a node, coordinate, or PolarPosition base
- `relative`: resolve from the previous endpoint without advancing `prevEnd`
- `relativeAccumulate`: resolve from the previous endpoint and advance `prevEnd`

Relative targets also have the sugar strings `'+dx,dy'` / `'++dx,dy'`.

<ComponentPreview files="step-targeting" size="md" />

### Geometry and curves

Switch among `curve`, `cubic`, `bend`, `smooth`, `arc`, `circlePath`, and `ellipsePath` in the panel below. Bezier control points are edited as `[x, y]` pairs and appear as dashed handles on the canvas; other kinds reveal only their bend angle, tension, angles, or radii so you can compare how they advance the cursor and produce geometry.

### Edge label

Attach `label` to a `<Step>` to place text at any normalized position along that segment. The prop form `<Step label={{...}} />` and sugar form `<Step><EdgeLabel>...</EdgeLabel></Step>` provide equivalent basic placement fields; the prop wins when both are present.

<ComponentPreview files="step-label" />

The panel adjusts `position`, `side`, `sloped`, and text color together. `position` accepts seven keywords or a numeric t in `[0, 1]`; the keyword mapping and complete fields live in the [edge-label API table](#edge-labels) below instead of being repeated in the examples.

### Styling

`<Step>` itself has no stroke-related visual props. Stroke, dashes, rounded geometry, fill, and stacking all belong to the parent `<Path>`; adjust them in the [Path style controls](/kernel/components/draw/path#styling) instead of repeating the same static path here.

<Comparison target="tikz" title="Basic Step Path Syntax">

| retikz                                    | TikZ mapping                       |
| ----------------------------------------- | ---------------------------------- |
| `kind="fold"` + `via="-\|"` / `"\|-"`     | `(A) -\| (B)` / `(A) \|- (B)`      |
| `kind="cycle"`                            | `cycle`                            |
| `{ of, offset }` target                   | calc-library `($(of) + (dx, dy)$)` |
| `{ relative }` / `{ relativeAccumulate }` | `(+x, +y)` / `(++x, ++y)`          |
| `kind="rectangle"`                        | `(a) rectangle (b)`                |

</Comparison>

### From markers to an ordered Step sequence

`<Step>` is a marker component that returns `null`; it creates no DOM or graphic by itself. Its parent `<Path>` collects these markers in JSX order and normalizes string targets, a missing `kind`, and `<EdgeLabel>` children into serializable `IRStep` values. An explicit `label` prop wins over the child form.

Except for a single self-contained `rectangle`, a Path needs at least two Steps. If the first Step is not `move`, the React adapter converts it to `move`: it keeps `to` when available and falls back to `[0, 0]` otherwise. A leading `line` therefore positions the cursor instead of drawing that line.

### Cursor-driven geometry compilation

Once core compilation begins for the default `kind="stroke"`, Steps do not render independently. The compiler first normalizes relative targets into the current scope coordinates, then advances the cursor in declaration order, resolves node references and boundary connections, and finally lowers each `kind` into shared path commands and edge-label geometry:

<ComponentPreview files="step-compile-flow" size="xs" hideCode />

| Step family                                                      | Compile behavior                                                                   | Observable result                                                                                  |
| ---------------------------------------------------------------- | ---------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `move` / `cycle`                                                 | Maintain the cursor and latest subpath start                                       | `move` draws nothing; `cycle` closes to the latest `move`                                          |
| `line` / `curve` / `cubic`<br />`fold` / `bend`                  | Resolve both targets, clip node boundaries,<br />then emit line or Bezier commands | Node ids attach to their borders; `fold` / `bend` still become ordinary path segments              |
| `smooth` / `generator`<br />`arc` / `circlePath` / `ellipsePath` | Generate path commands and record the actual pen position afterward                | The next segment continues from the generated result; full circles / ellipses return to the center |
| `rectangle`                                                      | Resolve `from` / `to` independently of a preceding cursor                          | It may be the only Step in a Path                                                                  |

This ordering lets JSX, direct IR, and `<Draw>` sugar reuse the same geometry compiler. A renderer consumes the lowered commands and does not need to understand all thirteen Step forms.

### Geometric meaning of t per step kind

`label.position` first maps to a `0..1` parameter t. The compiler then asks the current kind's geometry sampler for a point and tangent: `side` offsets from that point, while `sloped` rotates by the tangent. Consequently, t means “progress through this kind's parametrization,” which is not always visual arc-length progress.

| Step kind             | Parametrization of t                                                           | Meaning of `t=0.5`                                                    |
| --------------------- | ------------------------------------------------------------------------------ | --------------------------------------------------------------------- |
| `'line'`              | Normalized arc length                                                          | Straight-line midpoint                                                |
| `'fold'`              | Each of the two legs gets half of `t`, regardless of leg length                | The corner at `t=0.5`                                                 |
| `'curve'` / `'cubic'` | Bezier parameter, **not arc length**                                           | Usually not the visual midpoint                                       |
| `'bend'`              | Bezier parameter after lowering to cubic                                       | Same as cubic                                                         |
| `'smooth'`            | Generated cubic segments split t evenly;<br />each interval then uses Bezier t | Depends on segment count, not full-curve arc length                   |
| `'generator'`         | Linear interpolation from the cursor on entry to the final pen position        | Midpoint of those endpoints; it does not follow intermediate commands |
| `'arc'`               | Linear interpolation across `startAngle..endAngle`                             | Mid angle                                                             |
| `'circlePath'`        | Full-circle angle 0→360, with 0 at +x                                          | 180° (−x)                                                             |
| `'ellipsePath'`       | Same as circlePath; parameter angle rather than uniform arc-length sampling    | 180° (−x); arbitrary `t` is not uniformly distributed by arc length   |

Circle and ellipse angles increase in screen coordinates, so 90° is visually downward.

## API Reference

| Prop           | Type                                                                                                                                                        | Default  | Description                                                                                                                                                                                                                                                                                                                                                                               |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `kind`         | `'move' \| 'line' \| 'fold' \| 'cycle' \| 'curve' \| 'cubic' \| 'bend' \| 'smooth' \| 'generator' \| 'arc' \| 'circlePath' \| 'ellipsePath' \| 'rectangle'` | `'line'` | See the "Thirteen kinds" table above                                                                                                                                                                                                                                                                                                                                                      |
| `via`          | `'-\|' \| '\|-'`                                                                                                                                            | —        | Required for `kind="fold"`: `-\|` horizontal-then-vertical; `\|-` vertical-then-horizontal                                                                                                                                                                                                                                                                                                |
| `from`         | `IRTarget`                                                                                                                                                  | —        | Required only for `kind="rectangle"`: one rectangle corner                                                                                                                                                                                                                                                                                                                                |
| `to`           | `IRTarget`                                                                                                                                                  | —        | Not used for `kind="cycle"` / `'arc'` / `'circlePath'` / `'ellipsePath'`; required for `kind="rectangle"` and other cursor-advancing kinds. Target: node id, Cartesian `[x, y]`, polar object, offset object `{ of, offset }`, proportional placement `{ between, fraction }`, relative-offset object `{ relative }` / `{ relativeAccumulate }`, or sugar string `'+dx,dy'` / `'++dx,dy'` |
| `name`         | `string`                                                                                                                                                    | —        | Required only for `kind="generator"`: the built-in or `<Layout pathGenerators>`-registered path generator name                                                                                                                                                                                                                                                                            |
| `params`       | `IRJsonObject`                                                                                                                                              | —        | Required only for `kind="generator"`: JSON-safe params passed to the path generator; the built-in `parabola` uses `{ control }`                                                                                                                                                                                                                                                           |
| `cornerRadius` | `number`                                                                                                                                                    | —        | Optional for `kind="rectangle"`: corner radius                                                                                                                                                                                                                                                                                                                                            |

### Thirteen kinds

| kind            | Behavior                                                         | Path analogue                 |
| --------------- | ---------------------------------------------------------------- | ----------------------------- |
| `'move'`        | Move cursor, **no draw**                                         | path "M"                      |
| `'line'`        | Straight line from cursor to target                              | path "L"                      |
| `'fold'`        | Right-angle fold through one corner                              | two path "L" segments         |
| `'cycle'`       | Close back to most recent `move` (no `to`)                       | path "Z"                      |
| `'curve'`       | Quadratic Bezier (one control point)                             | path "Q"                      |
| `'cubic'`       | Cubic Bezier (two control points)                                | path "C"                      |
| `'bend'`        | Arc shorthand (direction + angle), lowered to cubic              | path "C"                      |
| `'smooth'`      | Smooth curve through cursor + `points`, lowered to a cubic chain | path "C"×N                    |
| `'generator'`   | Invoke a built-in or registered path generator                   | provider commands             |
| `'arc'`         | Cursor as center; arc by start / end angle + radius              | path "A"                      |
| `'circlePath'`  | Cursor as center; full circle, pen returns to center             | path "A"×2                    |
| `'ellipsePath'` | Cursor as center; full ellipse, pen returns to center            | path "A"×2                    |
| `'rectangle'`   | Draw a rectangle using `from` and `to` as opposite corners       | independent rectangle subpath |

### Two via values

Only meaningful when `kind="fold"`. Given cursor `(px, py)` and target `(tx, ty)`:

| via     | Corner     | Path                                      |
| ------- | ---------- | ----------------------------------------- |
| `'-\|'` | `(tx, py)` | Horizontal to `tx`, then vertical to `ty` |
| `'\|-'` | `(px, ty)` | Vertical to `ty`, then horizontal to `tx` |

### Forms of `to`

| Form                                     | Example                                                                                   | Behavior                                                                                                                                                                 |
| ---------------------------------------- | ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Node id                                  | `'a'`                                                                                     | Auto-attaches to Node border (see [Primitive Relations](/kernel/concepts/core/primitive-relations))                                                                      |
| Node + connection surface                | `{ id: 'a', boundary: 'circle' }`                                                         | Per-edge override of the target node's [connection surface](/kernel/components/node/overview#connection-surface-boundary) (clip shape); never changes the node footprint |
| Cartesian                                | `[60, 0]`                                                                                 | Literal `[x, y]`                                                                                                                                                         |
| Polar                                    | `{ origin: 'a', angle: 30, radius: 50 }`                                                  | Polar (see [Positioning](/kernel/concepts/basic/position))                                                                                                               |
| Offset                                   | `{ of: 'a', offset: [10, 5] }`                                                            | Base + `(dx, dy)`; `of` accepts node id, Cartesian literal, or PolarPosition                                                                                             |
| Proportional placement                   | `{ between: [{ id: 'a' }, { id: 'b' }], fraction: 0.5 }`                                  | Proportional point along A → B; endpoints must be independently resolvable absolute targets (`{ id, anchor? }` form, or Cartesian / polar)                               |
| Proportional placement (explicit anchor) | `{ between: [{ id: 'a', anchor: 'right' }, { id: 'b', anchor: 'left' }], fraction: 0.5 }` | Endpoints may carry an explicit `anchor`, resolved from that anchor instead of auto-attaching to the border                                                              |
| Relative (relative)                      | `{ relative: [10, 0] }` or `'+10,0'`                                                      | Previous step's endpoint + `[dx, dy]`; does **not** update prevEnd                                                                                                       |
| Relative (relativeAccumulate)            | `{ relativeAccumulate: [10, 0] }` or `'++10,0'`                                           | Previous step's endpoint + `[dx, dy]`; **updates** prevEnd                                                                                                               |

### Curves and arcs

| Prop            | Type                                                                                                                                                        | Default   | Description                                                                                                                                                                                                                                                                             |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- | --------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `kind`          | `'move' \| 'line' \| 'fold' \| 'cycle' \| 'curve' \| 'cubic' \| 'bend' \| 'smooth' \| 'generator' \| 'arc' \| 'circlePath' \| 'ellipsePath' \| 'rectangle'` | `'line'`  | See the "Thirteen kinds" table above                                                                                                                                                                                                                                                    |
| `control`       | `[number, number]`                                                                                                                                          | —         | Required for `kind="curve"`: single control point of the quadratic Bezier                                                                                                                                                                                                               |
| `control1`      | `[number, number]`                                                                                                                                          | —         | Required for `kind="cubic"`: first control point (shapes start tangent)                                                                                                                                                                                                                 |
| `control2`      | `[number, number]`                                                                                                                                          | —         | Required for `kind="cubic"`: second control point (shapes end tangent)                                                                                                                                                                                                                  |
| `points`        | `Array<IRTarget>` (≥1)                                                                                                                                      | —         | Required for `kind="smooth"`: the points the curve passes through after the cursor, in order. The cursor is the implicit first knot; a single point = one segment; the cursor ends at the last point. Element form is the same as `to`                                                  |
| `tension`       | `number` (>0)                                                                                                                                               | `1`       | Optional for `kind="smooth"`: tangent-length multiplier; default 1 (standard centripetal Catmull-Rom), `<1` tauter, `>1` loopier                                                                                                                                                        |
| `bendDirection` | `'left' \| 'right'`                                                                                                                                         | —         | Optional for `kind="bend"`: visual left / right relative to from→to direction; pairs with `bendAngle` for a symmetric bend. **`outAngle` / `inAngle` take precedence** and this is ignored when they are given                                                                          |
| `bendAngle`     | `number`                                                                                                                                                    | `30`      | Optional for `kind="bend"`: bend angle in degrees, restricted to (-180, 180)                                                                                                                                                                                                            |
| `outAngle`      | `number`                                                                                                                                                    | —         | Optional for `kind="bend"`: out-angle at the start (degrees); pairs with `inAngle` for an asymmetric curve / self-loop, taking precedence over `bendDirection` / `bendAngle`                                                                                                            |
| `inAngle`       | `number`                                                                                                                                                    | —         | Optional for `kind="bend"`: in-angle at the end (degrees); pairs with `outAngle`                                                                                                                                                                                                        |
| `looseness`     | `number`                                                                                                                                                    | `≈1`      | Optional for `kind="bend"`: control-point distance factor; larger = slacker curve; also scales the default self-loop size when `from == to`                                                                                                                                             |
| `startAngle`    | `number`                                                                                                                                                    | —         | Required for `kind="arc"`; optional for `'circlePath'` / `'ellipsePath'` (pair with `endAngle` for a partial circle / ellipse): start angle in degrees (0° → +x, 90° → visually down)                                                                                                   |
| `endAngle`      | `number`                                                                                                                                                    | —         | Required for `kind="arc"`; optional for `'circlePath'` / `'ellipsePath'`: end angle in degrees; sweep direction inferred from start vs end                                                                                                                                              |
| `radius`        | `number \| { x: number; y: number }`                                                                                                                        | —         | Given for `kind="arc"` (circular) / `'circlePath'`: radius of the circle / arc. On arc, `radius` and `radius: { x, y }` are **mutually exclusive** (one or the other); required on circlePath                                                                                           |
| `center`        | `IRTarget`                                                                                                                                                  | cursor    | Optional for `kind="arc"`: explicit arc center, defaults to the cursor (previous step endpoint); set it to anchor the arc independently of the cursor (used by `<Sector>` to draw a correct wedge)                                                                                      |
| `closed`        | `'closed' \| 'chord' \| 'open' \| 'sector'`                                                                                                                 | see below | Optional for `kind="circlePath"` / `'ellipsePath'`: closing mode. Without angles `'closed'` (full circle / ellipse, default); with angles `'chord'` (chord between the two arc ends, default) / `'sector'` (connect both ends to the center, then close) / `'open'` (pure unclosed arc) |

### Edge labels

| Prop    | Type          | Default | Description                                                                                                                                                                                                                        |
| ------- | ------------- | ------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `label` | `IRStepLabel` | —       | Edge label (works on every kind except `'move'` / `'cycle'` / `'rectangle'`): `{ text, position?, side?, textColor?, opacity?, font? }`; `<EdgeLabel>` sugar covers text / position / side / sloped, and the prop wins on conflict |

### Fields of `label`

`label` is a single object, applied uniformly across all kinds that accept it:

| Field       | Type                                     | Default    | Description                                                                                                                                                                                                                                 |
| ----------- | ---------------------------------------- | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `text`      | `string`                                 | —          | Required label text (single line)                                                                                                                                                                                                           |
| `position`  | one of 7 keywords or `number` (0..1)     | `'midway'` | Normalized position t along the segment — keywords are sugar for t (at-start=0 / very-near-start=0.125 / near-start=0.25 / midway=0.5 / near-end=0.75 / very-near-end=0.875 / at-end=1); values outside `[0, 1]` are rejected by the schema |
| `side`      | `'top' \| 'bottom' \| 'left' \| 'right'` | `'top'`    | Edge-label side relative to the segment. Compass aliases `north` / `south` / `east` / `west` are accepted                                                                                                                                   |
| `sloped`    | `boolean`                                | `false`    | Whether to rotate along the segment tangent; can still be combined with `side` for placement                                                                                                                                                |
| `textColor` | `string`                                 | —          | Label text color; falls back to scope `labelDefault` → host path master `color` → currentColor (follows the master color, not stroke)                                                                                                       |
| `opacity`   | `number`                                 | —          | Label-only opacity 0..1; multiplied with the owning path opacity (does not compound across scopes)                                                                                                                                          |
| `font`      | `object`                                 | —          | Label font overrides (family / size / weight / style); per-field fallback to `labelDefault` → renderer default                                                                                                                              |

The geometric meaning of t per step kind, including the `smooth` / `generator` boundaries, is in the "[Geometric meaning of t per step kind](#geometric-meaning-of-t-per-step-kind)" table above.
