矩形是 retikz 里最常用的形状，有两副面孔：用 `<Rectangle>` 画一个矩形轮廓（Sugar），或直接用 `<Node>`——**节点默认就是矩形边界**。完整定义见 [形状](/kernel/components/shapes)。要画一个矩形框，用 Sugar；要一个矩形节点（装文字、连线），直接用 `<Node>`。

## 作为 Path 图形（Sugar）

`<Rectangle>` 在指定位置画一个矩形，展开成底层 `<Path>`。适合已知两个角、中心尺寸或从一个角向外展开的场景。

### 用法

```tsx
import { Rectangle } from '@retikz/react';
```

```tsx
<Rectangle corner1={[-40, -20]} corner2={[40, 20]} cornerRadius={6} />
```

### 例子

`<Rectangle>` 可以直接给两个角，也可以从中心和尺寸算出四个角。`cornerRadius` 用来画圆角。

| 写法                         | 适合               |
| ---------------------------- | ------------------ |
| `{ corner1, corner2 }`       | 已知两个对角       |
| `{ center, width, height }`  | 已知中心和尺寸     |
| `{ center, side }`           | 正方形             |
| `{ corner1, width, height }` | 从一个角向右下展开 |

<ComponentPreview files="rectangle-basic" size="sm" />

### API 参考

| 组件          | 组合                           | 含义                               |
| ------------- | ------------------------------ | ---------------------------------- |
| `<Rectangle>` | `corner1` + `corner2`          | 通过两个对角确定矩形               |
|               | `center` + `width` + `height`  | 通过中心和宽高确定矩形             |
|               | `center` + `side`              | 通过中心和边长确定正方形           |
|               | `corner1` + `width` + `height` | 通过一个角和宽高确定矩形           |
|               | + `cornerRadius?`              | 圆角矩形（会限制到边长的一半以内） |

这个形状 Sugar 也会透传共享的 Path 属性，例如 `stroke`、`fill`、`opacity`、`animations` 和 `onClick`。完整列表见 [Path](/kernel/components/draw/path)；事件如何在渲染后绑定，见 [Hydration](/kernel/packages/render/hydration)。

## 作为 Node 形状

`<Node>` 不写 `shape` 时就是矩形，边界包住「文字 + padding」、尺寸由文字内容驱动。流程图节点几乎都是这种。

### 用法

```tsx
import { Node } from '@retikz/react';
```

```tsx
<Node>label</Node>
<Node shape={{ type: 'rectangle', params: { cornerRadius: 10 } }}>rounded</Node>
```

### 例子

圆角既可以用顶层 `cornerRadius`，也可以写成 `shape={{ type:'rectangle', params:{ cornerRadius } }}`（两者并存时 params 优先）。倒角是连接感知的：连线端点会落在圆角弧上，而不是已被磨掉的尖角。

<ComponentPreview files="node-rectangle" size="sm" />

连线端点贴矩形边，节点的中心与 8 个方位 anchor（`center` / `top` …）照常可用。Node 的形状、尺寸、边界与 anchor 见 [Node 几何](/kernel/components/node/overview)。

### API 参考

| `shape`              | 边界                         | 参数                        |
| -------------------- | ---------------------------- | --------------------------- |
| 缺省 / `"rectangle"` | 包住「文字 + padding」的内框 | `cornerRadius?`（圆角半径） |

### Sugar 如何收敛为闭合 Path

`<Rectangle>` 先把四种 props 写法收敛成 `from` / `to` 两个对角。图中上路直接透传 Target（可解析点位，包括坐标与节点 id），下路先在 React 层根据尺寸计算对角：

<ComponentPreview files="rectangle-sugar-flow" size="lg" hideCode />

只有 `corner1 + corner2` 会原样透传两个 Target，因此可以引用节点 id；`center + width + height` 等写法需要先做算术，只接受 `[x, y]` 字面量坐标。随后 `rectangle` step 解析两个对角并生成独立的闭合子路径；`cornerRadius` 会把四角替换为圆弧，并限制在短边一半以内。

任一节点引用无法解析时，整条 Path 会被跳过并产生 warning，而不是留下半个矩形。

### Node 如何得到可连接边界

`<Node>` 省略 `shape` 时会选择 `rectangle`。文字测量结果与 `padding` 先组成内容内框，再交给矩形 shape 同时生成可见轮廓和连接几何：

<ComponentPreview files="rectangle-node-boundary" size="lg" hideCode />

矩形不会为了外接内容额外放大半轴，所以边界正好包住「文字 + padding」。同一份 `cornerRadius` 参数既参与矩形绘制，也参与朝目标方向求边界交点；这就是圆角节点的连线会落在圆弧上，而不是落在已被磨掉的尖角上的原因。

因此 `<Rectangle>` 的结果是纯 Path 图形；矩形 `<Node>` 则保留 id、方位 anchor 与边界求交能力。需要装文字并连接时，应选择 `<Node>`。
