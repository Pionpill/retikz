正多边形（等边等角）有两副面孔：用 `<RegularPolygon>` 画一个等边多边形轮廓（Sugar），或用 `shape={{ type:'polygon', params:{ sides } }}` 让节点带上正多边形边界。`diamond` 就是 `polygon{ sides:4, rotate:0 }` 的预设。完整定义见 [形状](/kernel/components/shapes)。要画一个多边形框，用 Sugar；要一个可连接、可标注的多边形节点，用 `<Node shape>`。

## 作为 Path 图形（Sugar）

`<RegularPolygon>` 在指定位置画一个等边多边形，展开成底层 `<Path>`。

### 用法

```tsx
import { RegularPolygon } from '@retikz/react';
```

```tsx
<RegularPolygon center={[0, 0]} radius={36} sides={6} />
```

### 例子

`<RegularPolygon>` 用外接半径或边长确定大小。`sides` 至少为 `3`，`rotate` 可以调整整体朝向。

| 写法                            | 适合         |
| ------------------------------- | ------------ |
| `{ center, radius, sides }`     | 已知外接半径 |
| `{ center, sideLength, sides }` | 已知边长     |

### API 参考

| 组件               | 组合                              | 含义                                   |
| ------------------ | --------------------------------- | -------------------------------------- |
| `<RegularPolygon>` | `center` + `radius` + `sides`     | 通过外接半径和边数确定正多边形         |
|                    | `center` + `sideLength` + `sides` | 通过边长和边数确定正多边形             |
|                    | + `rotate?`                       | 整体起始角；缺省 `-90`（一个顶点朝上） |

这个形状 Sugar 也会透传共享的 Path 属性，例如 `stroke`、`fill`、`opacity`、`animations` 和 `onClick`。完整列表见 [Path](/kernel/components/draw/path)；事件如何在渲染后绑定，见 [Hydration](/kernel/packages/render/hydration)。

## 作为 Node 形状

当你要的是一个多边形**节点**（装文字、被连线引用）而不是一条线时，给 `<Node>` 设 `shape={{ type:'polygon', params }}`。边界取能容纳「文字 + padding」的正多边形外接圆，尺寸由文字驱动。

### 用法

```tsx
import { Node } from '@retikz/react';
```

```tsx
<Node shape={{ type: 'polygon', params: { sides: 6 } }}>label</Node>
<Node shape="diamond">label</Node>
```

### 例子

playground 把六边形与 `diamond` 预设放在同一场景比较；`diamond` 等价于 `{ type:'polygon', params:{ sides:4, rotate:0 } }`，不接收额外参数。选择六边形时可调整 `cornerRadius`，再通过轨道角度与距离移动来源节点，观察自动贴边如何跟随尖角或圆角轮廓，并与命名 / 数字 anchor 对照。

<ComponentPreview files="node-connection-playground" size="md" />

Node 的通用尺寸、边界与 anchor 见 [Node 几何](/kernel/components/node/overview)。

### API 参考

| `shape`                       | 边界                                  | 参数                                        |
| ----------------------------- | ------------------------------------- | ------------------------------------------- |
| `{ type: 'polygon', params }` | 能容纳文字的正多边形外接圆            | `sides`（≥3） / `rotate?` / `cornerRadius?` |
| `"diamond"`                   | = `polygon{ sides:4, rotate:0 }` 预设 | 无                                          |

`cornerRadius`（用户单位）给每个顶点倒角，省略 / `0` = 直角，逐角夹紧到不自交的最大半径。

### 属性如何变成闭合 Path（Sugar）

图中三组输入先收敛为同一个顶点环，再由唯一的主链展开成 Path：

<ComponentPreview files="polygon-sugar-flow" size="md" hideCode />

`radius` 可以直接作为外接半径；`sideLength` 则先通过 `R = sideLength / (2·sin(π/sides))` 换算到同一半径。随后第 `k` 个顶点取 `rotate + k·360/sides` 的方向，`rotate` 直接烘焙进顶点坐标，不会再作为底层 Path 的 transform 透传。

因此输出拓扑始终是一次 `move`、`sides - 1` 次 `line` 和一次 `cycle`。`center` 不是字面 `[x, y]`，或 `sides` 不是至少为 3 的整数时，会在生成顶点环之前报错。

### 内框如何变成可连接轮廓（Node）

沿主链看，Node 的内容尺寸先决定多边形要包住什么，再由 shape 参数决定用什么正多边形去包；上下两条输出表示同一套轮廓规则同时服务渲染与自动连接：

<ComponentPreview files="polygon-node-flow" size="lg" hideCode />

文字与 `padding` 先形成内容内框；`polygon` 形状实现再根据 `sides` 与 `rotate` 求出能完整外接这个内框的最小外接圆半径。所有顶点仍落在同一个圆上，所以长文本只会把正多边形整体放大，不会把它拉伸成不规则多边形。

`cornerRadius` 不改变外接尺寸，而是在顶点环生成后应用倒角。同一套顶点与倒角规则既输出 Scene path，也用于从节点中心朝目标方向求边界交点，因此自动连接会落在圆角弧上。标准方位 anchor（`top`、`bottom` 等）仍取外接矩形；它们不等同于任意方向上的真实轮廓交点。

`shape="diamond"` 只改变入口写法：编译器会先把它归一为 `polygon{ sides:4, rotate:0 }`，再进入完全相同的 provider 主链。4 个顶点从 0° 开始按 90° 均布，因此落在右、下、左、上四个方向；要让四边形正置，可显式写 `rotate:45`。
