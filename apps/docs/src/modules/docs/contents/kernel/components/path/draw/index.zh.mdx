`way` 是 `<Draw>` 的路径简写：目标给出点，`-|` / `|-` 决定怎么转弯，`{ label }` 给下一段加文字，`DrawWay.Cycle` 把路径闭合。

目标可以是坐标，也可以引用节点：`'-|'` / `'|-'` 改写前后两个点之间的段，`{ label }` 修饰下一段，`{ curve }` / `{ cubic }` / `{ bend }` 消耗下一项生成曲线，`{ arc }` / `{ circle }` / `{ ellipse }` 围绕上一点画形状而不消耗下一项。

## 目标写法

同一条 `way` 可以混合不同的目标写法，按位置从哪里来选择：

- **节点引用**：`'a'` 指向已有节点，连线会随节点移动，并自动贴到节点边缘
- **笛卡尔坐标**：`[120, 0]` 直接给出固定位置，适合不依赖其他节点的点
- **极坐标**：`{ origin: 'a', angle: 60, radius: 80 }` 从原点按角度和距离取点，适合围绕节点排布
- **结构化目标**：`{ id: 'a', anchor: 'top' }` 可以指定节点锚点或边上的位置，适合精确控制连线落点

## 单轴连接

`{ horizontalTo }` 只连接到目标 x，`{ verticalTo }` 只连接到目标 y；两者各自产生一个 `axis-line` Step，不像 `-\|` / `\|-` 那样发出两段。方向按当前 Scope 的局部坐标轴解释。

```tsx
<Draw way={[[0, 0], { horizontalTo: [100, 60] }]} />
<Draw way={[[0, 0], { verticalTo: [100, 60] }]} />
```

<ComponentPreview files="axis-line" size="sm" />

算子值只接受笛卡尔坐标、NodeTarget 或对应字符串 shorthand。relative、polar、offset、between，以及同时含多个 Way operator 的对象会由 `parseWay` 直接拒绝。

## 折角

切换四种折角方向，观察蓝色路径经过一个或两个正交转折点。选择 `-\|-` / `\|-\|` 后可用 `fraction` 在 `0..1` 内移动中间腿，默认 `0.5`；灰色 dotted 直线只标出两个端点的直接连接。

<Comparison target="tikz" title="折角写法">

`'-|'` / `'|-'` 沿用 TikZ path 的 `(A) -| (B)` / `(A) |- (B)` 两段写法。`'-|-'` / `'|-|'` 是流程图常见的三段扩展；裸 token 使用中点，`{ via: '-|-', fraction: 0.3 }` 可配置中间腿位置。

## 相对坐标

两条线都会先向右偏移 `[60, 0]`，再使用面板中的二维偏移 `[x, y]` 画第二段。区别不在第一段画在哪里，而在第一段之后是否把内部游标移到终点：

- **蓝色 `+`**：第一段只画出来，游标仍停在起点。因此第二段仍从 `+` 方框的位置计算，终点是“起点 + `[x, y]`”，不会叠加前面的 `[60, 0]`
- **橙色 `++`**：第一段结束后，游标移到空心圆。因此第二段从空心圆继续计算，终点是“起点 + `[60, 0]` + `[x, y]`”
- 灰色 dotted 直角辅助线标出第二段的计算基准：上方从 `+` 方框开始，下方从橙色空心圆开始；实心圆是各自的最终终点
