`boundary` 决定连线接触节点的位置。通常它直接沿用视觉 `shape`；只有当“节点看起来是什么”和“线应该接在哪里”需要分离时，才注册自定义连接面。

下面的矩形仍按原形状绘制，但 `horizontal-ports` 让连线只接左右端口。展开源码可以看到定义、注入与消费的完整闭环。

## 适用边界

先判断现有写法能否解决问题：

| 需求                        | 选择                         |
| --------------------------- | ---------------------------- |
| 连线沿视觉轮廓贴边          | 省略 `boundary` 或写 `shape` |
| 改用圆、矩形或椭圆连接面    | 使用同名内置 boundary        |
| 借用已注册 shape 的连接几何 | 把 shape 名写进 `boundary`   |
| 固定方向端口或方位 anchor   | 注册 `BoundaryDefinition`    |

连接面只拥有“连线停在哪里”和“标准方位锚点在哪里”。它不计算节点尺寸，也不输出图元；视觉形状、占位和绘制仍由 `shape` 负责。若连接规则始终等同于新形状，应改写 [自定义形状](/kernel/components/shapes/custom-shape)，不要维护两份几何。形状专属自定义锚点仍属于视觉 shape，不由 boundary 扩展。

## 定义能力

用 `defineBoundary` 声明稳定的 registry key、参数 schema 和射线交点。无参数时仍提供 `z.strictObject({})`，让所有 payload 都经过同一校验路径。

```ts
import { defineBoundary } from '@retikz/core';
import { z } from 'zod';

export const horizontalPorts = defineBoundary({
  name: 'horizontal-ports',
  paramsSchema: z.strictObject({}),
  boundaryPoint: (rect, toward) =>
    toward[0] < rect.x ? [rect.x - rect.width / 2, rect.y] : [rect.x + rect.width / 2, rect.y],
  anchor: (rect, name) => {
    if (name === 'left') return [rect.x - rect.width / 2, rect.y];
    if (name === 'right') return [rect.x + rect.width / 2, rect.y];
    return undefined;
  },
});
```

`boundaryPoint` 收到的是该 boundary 最终解析出的 `rect`；未提供 `resolveRect` 时，它就是视觉 shape 已经算好的节点外接框。`toward` 是连线从节点中心指向的目标点。带参数的连接面把参数写进 `{ type, params }`，其中 `params` 必须是可 JSON 序列化的数据；函数只存在于 definition，不进入 IR（中间表示）。

需要在交点计算前调整连接面尺寸时，实现可选的 `resolveRect(context, params)`。`context.visualRect` 是视觉外接框，`context.connectionEnvelope(kind)` 则请求视觉 shape 对 circle / ellipse / rectangle 的安全规则包络；后者会复用同一节点内的缓存。返回矩形必须具有有限坐标和正宽高，否则编译会立即报错。

### 带参数的连接面

参数直接由 definition 的 schema 定义，并在回调第三个参数里获得推断类型。下面的 `bias` 把左右端口沿节点高度从顶部 `-1` 移到底部 `1`：

```ts
const biasedPorts = defineBoundary({
  name: 'biased-ports',
  paramsSchema: z.strictObject({ bias: z.number().min(-1).max(1) }),
  boundaryPoint: (rect, toward, { bias }) => [
    toward[0] < rect.x ? rect.x - rect.width / 2 : rect.x + rect.width / 2,
    rect.y + (rect.height / 2) * bias,
  ],
});
```

节点通过 JSON-safe 的 `{ type, params }` 选择该定义：

```tsx
<Node id="io" position={[0, 0]} boundary={{ type: 'biased-ports', params: { bias: 0.5 } }} />
```

## 注入宿主

React 宿主通过 `<Layout boundaries>` 注入定义，节点只保存 registry key：

```tsx
<Layout boundaries={[horizontalPorts]}>
  <Node id="io" position={[0, 0]} boundary="horizontal-ports">
    IO
  </Node>
</Layout>
```

直接使用 core 编译器时，把同一数组传给 `CompileOptions.boundaries`：

```ts
const { scene } = compileToScene(ir, { boundaries: [horizontalPorts] });
```

Definition 可以由应用代码持有，序列化的图只保留名字或参数对象。React 与直接编译因此复用同一套注册和解析语义。

## 执行机制

| 阶段 | 输入                      | 结果                                                                        |
| ---- | ------------------------- | --------------------------------------------------------------------------- |
| 合并 | 内置 + 自定义 definitions | 生成按 `name` 查询的 Boundary Registry                                      |
| 查找 | `boundary` 名字           | 先查 boundary；未命中再查 Shape Registry                                    |
| 校验 | `{ type, params }`        | 使用命中 definition 的 `paramsSchema` 解析参数                              |
| 消费 | 连线方向或标准方位 anchor | 可先调用 `resolveRect`，再调用 `boundaryPoint` / `anchor`，不改变视觉 shape |

`boundary="shape"` 是保留语义，始终复用节点自己的视觉形状。其它名字优先命中 Boundary Registry；同名 shape 只在 boundary 未注册时作为兼容回退。自定义 boundary 与 shape 同名时，boundary definition 优先，因此可以只替换连接规则。

## 错误与限制

- **重复 key**：自定义项不能覆盖内置项，同一注入数组里也不能重名；registry 会在编译开始时抛错。
- **空 key**：`name` 必须是非空字符串。
- **未知名字**：错误会同时列出已注册 boundaries 与 shapes，并提示检查 `boundaries` / `shapes` 注入。
- **非法参数**：`paramsSchema` 在调用几何函数前校验，失败时会带上对应的 `.boundary.params` IR 路径。
- **非法解析矩形**：`resolveRect` 返回非有限坐标、非正宽高或内部抛错时，错误会带 boundary 名和 Node IR 路径。
- **未知 anchor**：`anchor` 可省略或返回 `undefined`；标准方位会回退到外接矩形，形状专属名字仍交给视觉 shape 解析。
- **无绘制职责**：连接面不能改变节点尺寸、形状或内容；这些需求属于 Shape Definition 或 Node props。

两个常见失败入口会在编译期立即抛错：

```tsx
<Node id="io" position={[0, 0]} boundary={{ type: 'biased-ports', params: { bias: 2 } }} />
```

```ts
compileToScene(ir, { boundaries: [biasedPorts, biasedPorts] });
```

第一段违反 `paramsSchema`；第二段重复注册同一个 key。

## API 参考

### `BoundaryDefinitionInput<TParams>`

| 属性            | 类型                                 | 默认值       | 描述                                            |
| --------------- | ------------------------------------ | ------------ | ----------------------------------------------- |
| `name`          | `string`                             | —            | Registry key，由 Node `boundary` 引用           |
| `paramsSchema`  | `z.ZodType<TParams>`                 | —            | 校验 JSON-safe 的 `boundary.params`             |
| `resolveRect`   | `(context, params) => Rect`          | `visualRect` | 可选；从视觉矩形或 shape 安全包络解析连接面矩形 |
| `boundaryPoint` | `(rect, toward, params) => Position` | —            | 返回射线与连接面的交点                          |
| `anchor`        | `BoundaryDefinition['anchor']`       | —            | 可选标准方位锚点解析器                          |

`defineBoundary`、`BoundaryDefinition`、`BoundaryDefinitionInput` 与 `BUILTIN_BOUNDARIES` 从 `@retikz/core` 导入。`@retikz/react` 和 `@retikz/vanilla` 不重复导出作者侧定义。
