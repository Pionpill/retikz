A regular polygon (equal sides and angles) has two faces: draw an outline with `<RegularPolygon>` (sugar), or bound a node with `shape={{ type:'polygon', params:{ sides } }}`. `diamond` is the preset for `polygon{ sides:4, rotate:0 }`. See [Shapes](/kernel/components/shapes) for the full definition. Reach for sugar to draw a polygon outline, and for `<Node shape>` to get a connectable, labelable polygon node.

## As a Path shape (sugar)

`<RegularPolygon>` draws an equal-sided polygon at a position, expanding to an underlying `<Path>`.

### Usage

```tsx
import { RegularPolygon } from '@retikz/react';
```

```tsx
<RegularPolygon center={[0, 0]} radius={36} sides={6} />
```

### Examples

`<RegularPolygon>` uses either a circumradius or a side length. `sides` must be at least `3`, and `rotate` changes the overall orientation.

| Form                            | Best for           |
| ------------------------------- | ------------------ |
| `{ center, radius, sides }`     | Known circumradius |
| `{ center, sideLength, sides }` | Known side length  |

<ComponentPreview files="regular-polygon-basic" size="xs" />

### API Reference

| Component          | Combination                       | Meaning                                                   |
| ------------------ | --------------------------------- | --------------------------------------------------------- |
| `<RegularPolygon>` | `center` + `radius` + `sides`     | Polygon from circumradius and side count                  |
|                    | `center` + `sideLength` + `sides` | Polygon from side length and side count                   |
|                    | + `rotate?`                       | Overall start angle; default `-90` (one vertex points up) |

This shape sugar also forwards the shared Path props, including `stroke`, `fill`, `opacity`, `animations`, and `onClick`. See [Path](/kernel/components/draw/path) for the full list and [Hydration](/kernel/packages/render/hydration) for how events are attached after rendering.

## As a node shape

When you need a polygon **node** (to hold text, to be referenced by a connection) rather than a line, set `shape={{ type:'polygon', params }}` on `<Node>`. The boundary takes the regular polygon that circumscribes "text + padding", sized by the text.

### Usage

```tsx
import { Node } from '@retikz/react';
```

```tsx
<Node shape={{ type: 'polygon', params: { sides: 6 } }}>label</Node>
<Node shape="diamond">label</Node>
```

### Examples

`diamond` is the 4-side preset with vertices on the top / bottom / left / right axes, writable as the bare string `shape="diamond"`, equivalent to `{ type:'polygon', params:{ sides:4, rotate:0 } }`.

<ComponentPreview files="node-polygon" size="sm" />

Give `params.cornerRadius` a positive number to round every vertex; omitting it or `0` keeps sharp corners. The rounding is connection-aware: connection endpoints land on the fillet arc rather than the sharp corner that has been rounded away.

<ComponentPreview files="node-polygon-corner-radius" size="sm" />

Connection endpoints snap to the polygon edge, and the node's center plus 8 directional anchors (`center` / `top` …) still apply. See [Node geometry](/kernel/components/node/overview) for Node shapes, sizes, boundaries, and anchors.

### API Reference

| `shape`                       | Boundary                                | Parameters                                 |
| ----------------------------- | --------------------------------------- | ------------------------------------------ |
| `{ type: 'polygon', params }` | Regular polygon circumscribing the text | `sides` (≥3) / `rotate?` / `cornerRadius?` |
| `"diamond"`                   | = `polygon{ sides:4, rotate:0 }` preset | None                                       |

`cornerRadius` (user units) rounds every vertex; omitted / `0` = sharp corners, clamped per corner to the largest non-self-intersecting radius.

### Props become a closed Path (sugar)

The three input groups converge on one vertex ring before the single main path expands it into a Path:

<ComponentPreview files="polygon-sugar-flow" size="md" hideCode />

`radius` is already the circumradius. `sideLength` first converges on the same value through `R = sideLength / (2·sin(π/sides))`. Vertex `k` then uses the direction `rotate + k·360/sides`; `rotate` is baked into the vertex coordinates instead of being forwarded as a transform on the underlying Path.

The output topology is therefore always one `move`, `sides - 1` `line` steps, and one `cycle`. A non-literal `[x, y]` center, or a `sides` value that is not an integer of at least 3, fails before the vertex ring is produced.

### The inner box becomes a connectable contour (Node)

Along the main path, the Node content determines what the polygon must contain, then the shape parameters determine which regular polygon contains it. The two outputs show the same contour rules serving both rendering and automatic connections:

<ComponentPreview files="polygon-node-flow" size="lg" hideCode />

Text and `padding` first form the inner box. The polygon provider then derives the smallest circumradius that fully contains that box for the given `sides` and `rotate`. Every vertex still lies on one circle, so long text enlarges the regular polygon as a whole instead of stretching it into an irregular polygon.

`cornerRadius` does not change the circumscribed size; it is applied after the vertex ring is available. The same vertex and fillet rules emit the Scene path and intersect a ray from the node center toward an automatic connection target, so an endpoint lands on the rounded arc. Standard directional anchors (`top`, `bottom`, and so on) still come from the external bounding box; they are not arbitrary-direction contour intersections.

`shape="diamond"` changes only the entry form: the compiler first normalizes it to `polygon{ sides:4, rotate:0 }`, then sends it through the same provider path. Its four vertices start at 0° and advance by 90°, landing right, down, left, and up. Use an explicit `rotate:45` for an axis-aligned square.
