Start with [Basic usage](/kernel/components/path/usage). A label can belong to a whole Path or one Step. Choose that scope before setting its position.

## Using this topic

Path labels, Node labels, and Node body text share text capabilities. Set `textAlign`, `lineHeight`, and `maxTextWidth` directly on labels; body text uses the corresponding fields in `Node.layout`. Internal alignment defaults to `middle`, and line height defaults to 1.2 times the effective font size, expanding for taller content. Wrapping prefers word boundaries, splits oversized words at grapheme boundaries, and keeps formulas intact. Blank lines remain. Host, label, line, and segment opacity multiply; omitted factors are 1 and explicit 0 is preserved.

The four forms below attach the `status` label to the same segment; Vanilla needs an existing `<div id="diagram"></div>`.

## Choose the label scope

| Syntax               | Scope                        | When to use               |
| -------------------- | ---------------------------- | ------------------------- |
| `<Path label>`       | Whole path                   | Name a relationship       |
| `<Step label>`       | One step                     | Name a particular segment |
| `{ label }` in `way` | Following connection segment | Add a label in Draw       |

## Label a path

`{ label }` annotates the next connection segment without creating a segment itself. The panel supports a line, folds, a quadratic Bezier, and rounded line steps: adjust `position`, then `side`, `sloped`, and text color. In the default step mode, a fold allocates t evenly across its legs, so 0.5 lands at its corner; a curve samples at its Bezier parameter.

`position` accepts a number from 0 to 1: 0 is the start and 1 is the end. The keywords `at-start`, `very-near-start`, `near-start`, `midway`, `near-end`, `very-near-end`, and `at-end` map to 0, 0.125, 0.25, 0.5, 0.75, 0.875, and 1. `side` chooses a side of the line; `sloped: true` rotates text with the tangent. Use `side: 'center'` to center text on the path; `sloped` independently controls tangent rotation. Omitting `side` with `sloped: true` also defaults to center. Select Center in the example above and toggle Rotate along path to compare both orientations.

With Draw, put `{ label }` before the connection segment it annotates in `way`:

```tsx
<Draw way={['A', { label: { text: 'status', position: 0.5 } }, { curve: [180, -110] }, 'B']} />
```

With Path, pass the same object directly to the target `<Step>` through `label`:

```tsx
<Path>
  <Step kind="move" to="A" />
  <Step kind="curve" control={[180, -110]} to="B" label={{ text: 'status', position: 0.5 }} />
</Path>
```

Path and Step labels both default to `positionMode: 'step'`. With `'length'`, `position: 0.5` means half the accumulated length within the host: the entire path for Path labels, or the current step for Step labels.

`positionGeometry` independently selects `'original'` geometry before corner rounding or `'rounded'` geometry after it. When omitted, `step` uses original and `length` uses rounded. An explicitly inherited geometry remains effective when an instance changes only the mode. `step + rounded` preserves each original segment's parameter share and maps its vertex to the arc midpoint. In the playground above, choose “Rounded line steps” and move position to 1 to compare the first segment's original endpoint with the arc midpoint.

Move jumps and zero-length segments receive no share; nonzero closing segments participate. Positioning precedes arrow shortening, label interruption, and overall transforms. An original-geometry label on a portion removed by rounding stays at its original position and produces no stroke gap.

## Multiline text and stroke gaps

`<Path label>` belongs to the whole path, while `<Step label>` belongs only to its step. Observe how the same text block creates a gap: the text keeps its position and the stroke stops on either side of its bounds.

`label.text` reuses the same text-block input (TextBlock) as Node text: use one string (`\n` is a hard line break), or an array of lines with per-line `fill` / `font` / `opacity`. These overrides also apply to a single line, and its font size affects measurement and gap bounds. Line or segment opacity multiplies the label and Path opacity. All lines remain one label block with one anchor, `position`, `side`, `sloped`, and `interrupt`; a gap uses the whole block's visual bounds rather than treating lines as separate labels.

When `interrupt` is omitted, only that unfilled built-in Stroke + centered combination gets an automatic gap. `interrupt: false` forces a continuous stroke; `interrupt: true` can also gap a non-centered label. The gap extends by `4` user units beyond each side of the label's visual bounds by default; use `gap` to override it, and `gap: 0` for no extra clearance.

Any effective `fill` — including `style.fill: 'transparent'`, or setting fill and then `style.opacity.fill: 0` — disables the automatic gap, and `interrupt: true` then reports an error. Any explicit boolean on Ribbon, a custom Path, or another non-built-in Stroke host also reports an error. The gap does not move labels, marks, dash phase, or endpoint arrows, and does not avoid label / arrow or mark collisions.

Sampling a curve at a parameter, inverting distance, and taking a shape-preserving slice belong to the [`@retikz/math` curve-segment algorithms](/kernel/packages/math/algorithms#curve-slicing). They operate on plain geometry only; Core still decides label interruption, gap clearance, and Path output.
