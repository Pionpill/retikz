title: Coordinate
description: Placeholder node — names a point without drawing anything, so paths and relative positioning (`{ of }`) can reference it by id.
---

`<Coordinate>` registers a named reference point in IR. Like `<Node>`, it can be targeted by paths and relative positioning, but it renders no visible shape or text; compilation resolves its position and registers the `id` for `<Path>` endpoints and `<Node position>` relative / offset references (`{ of }`).

## Usage

```tsx
import { Coordinate } from '@retikz/react';
```

```tsx
<Coordinate id="hub" position={[0, 0]} />
```

`position` accepts the same five forms as `<Node>`: Cartesian `[x, y]` / polar `{ angle, radius, origin? }` / relative `{ direction, of, distance? }` / offset `{ of, offset }` / proportional `{ between, fraction }`.

### Why it exists

The plainest way to anchor "a named point" is to fake an empty `<Node>` with `stroke="transparent" fill="transparent"` — but an empty Node still takes up an invisible box sized by padding, enlarges the outer frame, and confuses AI / serialization round-trips ("real node or placeholder?").

`<Coordinate>` makes "named point" a first-class concept: the smallest possible shape (just `id` + `position`), draws nothing, and never enlarges the canvas. See [How it works](#how-it-works) for the placeholder semantics.

<Comparison target="tikz" title="Coordinate Mapping">

`<Coordinate id="hub" position={[0, 0]} />` maps to TikZ `\coordinate (hub) at (0,0);`: it names a point without rendering a shape.

`{ between: [A, B], fraction }` maps to TikZ `($(A)!t!(B)$)`; both take a proportional point between two endpoints.

### Proportional partway positioning

`{ between: [A, B], fraction }` takes a point along the A→B segment at proportion `fraction` (0..1) — `lerp(A, B, fraction)`. Placing a "midpoint / one-third" point this way beats hand-computing coordinates and keeps the proportion as A / B move. Endpoints are a self-contained **AbsoluteTarget** (Cartesian / polar / node reference `{ id, anchor? }` / `{ of, offset }` / nested between — **excluding** path-relative). The same shape works in `<Coordinate position>` / `<Node position>` / `<Step to>`:

<ComponentPreview files="coordinate-between" size="xs" />

> `fraction` is strict [0,1] (extrapolation not yet supported); when an endpoint references an undefined node, Coordinate / Node position resolution throws while a path `Step.to` warns and skips — the same as other positioning forms.

### Register first, then reference

The main chain shows what happens when the compiler reaches a Coordinate. The two lower branches show when position references and path endpoints read the same registered result.

<ComponentPreview files="coordinate-resolution-flow" size="sm" hideCode />

A Coordinate's `position` resolves immediately. If it depends on another id, that id must already be registered in the currently visible namespace; referencing a Node / Coordinate declared later at the same level throws. Once resolved, the compiler projects the result into global coordinates, stores it as a zero-size geometry record containing only the center coordinate, and registers it by `id`.

Node / Coordinate position references also resolve during traversal, so they see only ids registered so far. Paths are queued and resolve their endpoints after the current Scope's children have registered, so a path can target a Coordinate declared later in the same scope. Visibility introduced by `localNamespace` still follows [Scope namespace rules](/kernel/components/layout/scope#how-namespaces-and-id-conflicts-are-handled).

### How a zero-size record affects output

“Zero-size” means that the record has width 0 and height 0, commonly shortened to **0×0**. It stores only the Coordinate's center position, with no area or visible content; its boundary also collapses to the center. This is an internal geometry record used for positioning and path references, not a Scene primitive. That lets it reuse Node id lookup and anchor resolution while keeping pure reference points out of rendered output and automatic canvas bounds.

- **Draws no primitive** — no shape, no text; it never appears in the rendered output.
- **Never enlarges the canvas** — a far-away coordinate won't grow the final viewBox on its own; an actual `<Node>` / `<Path>` must land in that region for the canvas to cover it (a common gotcha when debugging placement).
- **Named / angular anchors collapse to the center** — because both dimensions are 0, every directional boundary coincides with the center, so `hub.top` / `hub.bottom` / `hub.30` all equal that point; use `<Node>` when you need directional anchors.
- **Side-fraction anchors throw** — `{ anchor: { side, fraction } }` needs a real edge to sample, while a zero-size record has only a center point and no edge.

## API Reference

| Prop       | Type                                                                                                 | Default | Description                                                                                                                                         |
| ---------- | ---------------------------------------------------------------------------------------------------- | ------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`       | `string`                                                                                             | —       | **Required** — a placeholder's entire purpose is to be referenced by id                                                                             |
| `position` | `[x, y] \| PolarPosition \| { direction, of, distance? } \| { of, offset } \| { between, fraction }` | —       | Placeholder position; same shapes as `<Node position>`; id dependencies must be registered first—see [How it works](#register-first-then-reference) |

## Related

### Relationship with `<Node>` / `<Path>`

|                                             | `<Coordinate>` | `<Node>`        |
| ------------------------------------------- | -------------- | --------------- |
| Renders shape                               | ❌             | ✅ (by `shape`) |
| Participates in layout bounds               | ❌             | ✅              |
| Registered in nodeIndex                     | ✅             | ✅              |
| Referenced as path target                   | ✅             | ✅              |
| Referenced via relative / offset (`{ of }`) | ✅             | ✅              |
| Required `id`                               | ✅             | optional        |

Rule of thumb: need a shape + text → `<Node>`; need only a reference point → `<Coordinate>`.

### When not to use

- **Need a labelled point** → use `<Node>` with `label?`; coordinate has no text field
- **Need a small visible dot** → use `<Node shape="circle">` with a small size; coordinate never draws
- **Direction anchors** (`hub.top`) → a coordinate's named / angular anchors collapse to the center; use `<Node>` for directional anchors
