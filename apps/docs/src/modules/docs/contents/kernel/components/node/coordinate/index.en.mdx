`<Coordinate>` gives a position a stable `id` without drawing shape or text. Paths can target it, and other nodes can reference it through relative, offset, proportional, or anchor placement.

Read [Basic usage](/kernel/components/node/usage) first, then use this page to organize helper positions.

## Using this topic

All four forms declare two invisible coordinates, then connect them with a path. Coordinate's real IR is `{ type: 'coordinate', id, position }`; it is not rendered, so the line that references the two ids is the only visible result. See [Coordinate System](/kernel/components/basic/coordinate-system) for the complete coordinate model. Vanilla needs an existing `<div id="diagram"></div>`.

`Coordinate.position` accepts five center/point forms: Cartesian `[x, y]` / polar `{ angle, radius, origin? }` / relative `{ direction, of, distance? }` / offset `{ of, offset }` / proportional `{ between, fraction }`. Node additionally supports `{ kind: 'anchor', target, selfAnchor? }`, which depends on its real measured size. A Coordinate may be that form's target, but Coordinate itself has no `selfAnchor` placement.

## When to use

Use Coordinate for junctions, helper positions, and invisible anchors; use Node when you need a shape, text, or directional boundary. Do not imitate a coordinate with a transparent Node: it still has size and padding and expands layout bounds.

| Goal                             | Choose         |
| -------------------------------- | -------------- |
| Name only a position             | `<Coordinate>` |
| Show a dot or another marker     | `<Node>`       |
| Show text or a label             | `<Node>`       |
| Use distinct directional anchors | `<Node>`       |

A Coordinate's directional and angular anchors all collapse to its center, and it has no text fields. See [Implementation](/kernel/components/node/mechanism) for its zero-size semantics.

<Comparison target="tikz" title="Coordinate Mapping">

`<Coordinate id="hub" position={[0, 0]} />` maps to TikZ `\coordinate (hub) at (0,0);`: it names a point without rendering a shape.

`{ between: [A, B], fraction }` maps to TikZ `($(A)!t!(B)$)`; both take a proportional point between two endpoints.

## Examples

### Named virtual anchor

Name a virtual center, then position multiple nodes around it and terminate multiple paths at it. The light axes stay fixed at the world origin; adjust the hub `position` and node `distance` to move hub against that reference and update every dependent object together.

<ComponentPreview files="coordinate-as-anchor" size="xl" />

The four nodes above all use `position={{ of: 'hub', ... }}` to reference the same hub; moving hub moves the whole arrangement.

### Named junction for path convergence

In flow charts, multiple paths can converge at a virtual point. Adjust the junction `position` and observe how all three paths keep passing through this Coordinate with no shape or text.

<ComponentPreview files="coordinate-fold-junction" size="md" />

### Offset positioning chain

Use `{ of, offset }` to derive one coordinate from another — drive the whole group from a single root, and moving the root drags everything along. The light axes stay fixed at the world origin; move the root or adjust the horizontal step to compare the group against that reference and watch the offset propagate through the chain:

<ComponentPreview files="coordinate-offset-chain" size="lg" />

### Proportional positioning

`{ between: [A, B], fraction }` takes a point between A and B at proportion `fraction` (0..1) — `lerp(A, B, fraction)`. The panel moves the invisible Coordinate Q; the orange q is only a visible marker that references Q. Q keeps the proportion when the endpoints move.

Each endpoint must resolve without using the current path position (`AbsoluteTarget`) (Cartesian / polar / node reference `{ id, anchor? }` / `{ of, offset }` / nested between — **excluding** path-relative). The same shape works in `<Coordinate position>` / `<Node position>` / `<Step to>`:

<ComponentPreview files="coordinate-between" size="xs" />

> `fraction` is strict [0,1] (extrapolation not yet supported); when an endpoint references an undefined node, Coordinate / Node position resolution throws while a path `Step.to` warns and skips — the same as other positioning forms.

## Errors and limitations

Position references must target objects whose layout and registration have completed (usually earlier siblings); path endpoints can reference later sibling Coordinates. Coordinate emits no primitive and does not enlarge the automatic viewBox. Named directional and angular anchors collapse to its center; side-fraction anchors require a real border and cannot target a Coordinate.

## Related props

Coordinate has only two public inputs: its name and placement. See the [API reference](/kernel/components/node/api-reference) for the complete field list and types.
