Supply node content through `text` or children; explicit `text` wins. Node owns the multi-line layout, while React `<Text>` styles one complete line. For several styles within a line, use `{ runs }`; Text is not an inline span.

Read [Basic usage](/kernel/components/node/usage) first, then use this page to organize node text.

## Using this topic

`<Text>` is a React JSX-only line marker inside Node. All four forms below produce the same two body-text lines: A is bold, while B inherits Node's block-level text style. Vanilla needs an existing `<div id="diagram"></div>`.

## Multiple lines and wrapping

The minimal example above establishes the line-level and block-level responsibilities. Now use the panel to compare multiline content: newlines create hard lines, while line 1, line 2, and line 3 onward can each change color, emphasis, and opacity. The same scene also compares `shape`, `align`, `lineHeight`, and `maxTextWidth` without moving the node or camera.

Select “Wrapping a long sentence”, then adjust `maxTextWidth` to compare the line count and node border.

<ComponentPreview files="node-text" size="md" />

- `text` accepts a string or a IRLine array; `'\n'` creates hard breaks, while the array form gives each line independent styles
- `layout.align` controls horizontal alignment within the block and `layout.lineHeight` controls spacing; both are block-level properties
- `layout.maxTextWidth` is a plain-text wrap threshold, not a fixed paragraph width; Western text wraps by word, CJK by character, and unbreakable tokens overflow as a whole
- Each line can override `fill` / `opacity` / `font`; [`<Text>` children](/kernel/components/node/text) express the same structure in JSX
- Changing `shape` keeps the shape-specific circumscription rules around the multiline content

`text` wins over `children` whenever both are supplied. Block-level `font` is `{ family?, size?, weight?, style? }`; the other shared visual properties remain in [Basic usage](/kernel/components/node/usage).

## Mixed runs within a line

Both runs below remain on one line. Vanilla API and IR use the same `text` data structure. If any line contains `{ runs }` or a resolved formula, the whole text block uses mixed layout and does not wrap automatically at `maxTextWidth`. Split the content into separate line-array items when a break is needed. For formulas, see [TeX](/kernel/packages/tex).

```tsx
<Node position={[0, 0]} text={[{ runs: [{ text: 'Status: ' }, { text: 'ready', fill: 'green' }] }]} />
```

## Automatic black-or-white contrast

Set `textColor` to `NodeTextColor.Contrast` and Core selects pure black or white, whichever has higher contrast against the Node's final static opaque `fill`. The keyword resolves after style cascading and independently for each Node, so it can also live in `Scope.defaults.node.style`.

<ComponentPreview files="node-auto-contrast" size="sm" />

```tsx
import { NodeTextColor } from '@retikz/core';

<Node position={[0, 0]} style={{ fill: '#1e293b', textColor: NodeTextColor.Contrast }}>
  Status
</Node>;
```

- Core statically supports CSS named colors, 3/4/6/8-digit hex, and legacy / modern `rgb()` and `hsl()`; it never reads DOM styles, theme variables, or page pixels
- Translucent / missing fills, `fillOpacity < 1`, gradients, patterns, images, `var()`, and `currentColor` use the fixed `currentColor` fallback and emit `TEXT_AUTO_CONTRAST_UNRESOLVED`
- Per-line / run `fill`, explicit label colors, and `defaults.label` still win. The keyword affects only body text, labels, and pins that ultimately inherit the Node text color

## Errors and limitations

Text only works inside Node and takes string or number children. Block alignment, line height, and wrapping width belong to `Node.layout.align`, `lineHeight`, and `maxTextWidth`; per-line fonts belong to Text `font`.

Automatic wrapping applies only to plain-text blocks; mixed runs and formulas do not wrap automatically. A fixed `layout.width` does not clip text: compilation fails if the content cannot fit.
