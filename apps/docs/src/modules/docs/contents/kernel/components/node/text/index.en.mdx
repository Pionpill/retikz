title: Text
description: Text declares one whole line inside Node and overrides that line's color, opacity, and font.

`<Text>` overrides text styling for one whole line inside `<Node>` and mixes with plain string children in JSX order. It is Sugar: the syntax exists only in the React DSL and then normalizes into one `IRLine` entry in `Node.text`.

It's an **equivalent** alternative to writing IRLine objects directly into the `text` prop:

| Path           | Form                                                | Strength                                      |
| -------------- | --------------------------------------------------- | --------------------------------------------- |
| `<Text>` Sugar | `<Node><Text fill="red">x</Text>...</Node>`         | Natural JSX, mixes well with string children  |
| `text` array   | `<Node text={[{ text: 'x', fill: 'red' }, ...]} />` | JSON-friendly; LLMs can emit IR JSON directly |

> Block-level props (`align` / `lineHeight`) go on `<Node>`; per-line overrides (`fill` / `opacity` / `font`) go on `<Text>`.

<ComponentAlert
  type="warn"
  title="A Text is one whole line, not an inline span"
  description="Text itself cannot express several styled runs on one line. For multi-color inline content, use a { runs } IRLine through the Node text prop; split into Text elements only when each segment should occupy its own line."
/>

## Usage

```tsx
import { Node, Text } from '@retikz/react';
```

```tsx
<Node>
  <Text fill="red" font={{ weight: 'bold' }}>
    Heading
  </Text>
  body line
</Node>
```

## How it works

### Line normalization and precedence

`<Text>` is a marker component that returns `null`; it creates no DOM or graphic by itself. It is recognized only while `<Node>` collects its children, where the React inputs converge on the same `Node.text` contract:

<ComponentPreview files="text-normalization" size="sm" hideCode />

An explicit `text` prop wins. When it is present, children do not participate in text collection. Without `text`, the adapter recursively reads strings, numbers, arrays, Fragments, and `<Text>` markers in JSX order:

| Input             | Normalization rule                                     | `Node.text` result   |
| ----------------- | ------------------------------------------------------ | -------------------- |
| String / number   | Adjacent content joins; Node text rules handle `\n`    | Plain string line    |
| Unstyled `<Text>` | Flush the current plain line, then add a separate line | Plain string line    |
| Styled `<Text>`   | Flush the current plain line and retain line overrides | IRLine object line |

This also explains both boundaries: `<Text>` only works inside `<Node>`, and it represents a whole line rather than an inline span.

### Line color resolution

After normalization, every line enters Core through the same color precedence. An explicit `<Text fill>` overrides the Node default; only lines without `fill` inherit `Node.textColor`:

<ComponentPreview files="text-contrast-flow" size="sm" hideCode />

When a Node uses `NodeTextColor.Contrast`, Core reads the final `fill` after style cascading. Only a static color with effective opacity 1 enters the WCAG relative-luminance comparison and resolves to `#000000` or `#ffffff`. Missing, translucent, gradient, `var()`, and other unresolved backgrounds use the fixed `currentColor` fallback and emit `TEXT_AUTO_CONTRAST_UNRESOLVED`. The Node's overall `opacity` does not participate in this background decision.

A per-line `font` still participates in that line's width measurement; wrapping, `align`, and `lineHeight` remain Node block-level responsibilities. Use a `{ runs }` IRLine through `text` when one line needs multiple styles.

## API Reference

| Prop       | Type                                                                                                                                                                                                                                | Default | Description                                                                                                                                                                                                                                   |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `children` | `string` \| `number`                                                                                                                                                                                                                | —       | Line content; a single string or number (numbers render as text); other child types are ignored                                                                                                                                               |
| `fill`     | `string`                                                                                                                                                                                                                            | —       | Per-line color override; falls back to Node `textColor` block default                                                                                                                                                                         |
| `opacity`  | `number`                                                                                                                                                                                                                            | —       | Per-line opacity 0..1                                                                                                                                                                                                                         |
| `font`     | `IRFont`<br />- `family?: string`<br />- `size?: number` \| <ApiValues name="WebFontSizePreset" /> \| `string`<br />- `weight?:` <ApiValues name="FontWeightKeyword" /> \| `number`<br />- `style?:` <ApiValues name="FontStyle" /> | —       | Per-line font override; missing fields inherit Node-level `font`<br />- CSS font family<br />- Font size; `WebFontSizePreset` provides presets, while `string` only accepts positive `em` / `rem` values<br />- Font weight<br />- Font style |

### Constraints

- **Must live inside `<Node>`**: a `<Text>` placed at the top level under `<Layout>` is silently ignored.
- **`children` must be a string or number**: nested elements or other types are not supported (numbers render as text). A line is a line.
- **Block-level props can't be overridden**: `align` / `lineHeight` only go on `<Node>`.
