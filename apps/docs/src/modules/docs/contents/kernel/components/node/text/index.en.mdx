title: Text
description: Per-line marker component inside <Node> — overrides fill / opacity / font for a single line; participates equally with string children in Node's multi-line layout.
---

`<Text>` overrides text styling for one whole line inside `<Node>` and mixes with plain string children in JSX order. It is Sugar: the syntax stays in the React layer and is normalized into one LineSpec inside `Node.text` before core receives it.

It's an **equivalent** alternative to writing LineSpec objects directly into the `text` prop:

| Path           | Form                                                | Strength                                      |
| -------------- | --------------------------------------------------- | --------------------------------------------- |
| `<Text>` Sugar | `<Node><Text fill="red">x</Text>...</Node>`         | Natural JSX, mixes well with string children  |
| `text` array   | `<Node text={[{ text: 'x', fill: 'red' }, ...]} />` | JSON-friendly; LLMs can emit IR JSON directly |

> Block-level props (`align` / `lineHeight`) go on `<Node>`; per-line overrides (`fill` / `opacity` / `font`) go on `<Text>`.

## Usage

```tsx
import { Node, Text } from '@retikz/react';
```

```tsx
<Node>
  <Text fill="red" font={{ weight: 'bold' }}>
    Heading
  </Text>
  body line
</Node>
```

## How it works

### Line normalization and precedence

`<Text>` is a marker component that returns `null`; it creates no DOM or graphic by itself. It is recognized only while `<Node>` collects its children, where the React inputs converge on the same `Node.text` contract:

<ComponentPreview files="text-normalization" size="sm" hideCode />

An explicit `text` prop wins. When it is present, children do not participate in text collection. Without `text`, the adapter recursively reads strings, numbers, arrays, Fragments, and `<Text>` markers in JSX order:

| Input             | Normalization rule                                     | `Node.text` result   |
| ----------------- | ------------------------------------------------------ | -------------------- |
| String / number   | Adjacent content joins; Node text rules handle `\n`    | Plain string line    |
| Unstyled `<Text>` | Flush the current plain line, then add a separate line | Plain string line    |
| Styled `<Text>`   | Flush the current plain line and retain line overrides | LineSpec object line |

This also explains both boundaries: `<Text>` only works inside `<Node>`, and it represents a whole line rather than an inline span.

### Styling and layout responsibilities

After normalization, the `<Text>` marker no longer exists; `<Node>` text layout handles every line uniformly. Missing `font` fields inherit the Node block font, while `fill` / `opacity` apply only to the current line. Measurement, wrapping, alignment, and line height remain block-level Node responsibilities.

That is why `<Text>` exposes only per-line visual fields. A per-line font participates in that line's width measurement, but `<Text>` cannot split the line into differently styled spans or override `align` or `lineHeight` by itself. Use a `{ runs }` LineSpec through `text` when one line needs multiple styles.

## API Reference

| Prop       | Type                                  | Default | Description                                                                                     |
| ---------- | ------------------------------------- | ------- | ----------------------------------------------------------------------------------------------- |
| `children` | `string \| number`                    | —       | Line content; a single string or number (numbers render as text); other child types are ignored |
| `fill`     | `string`                              | —       | Per-line color override; falls back to Node `textColor` block default                           |
| `opacity`  | `number`                              | —       | Per-line opacity 0..1                                                                           |
| `font`     | `{ family?, size?, weight?, style? }` | —       | Per-line font override; missing fields inherit Node block-level `font`                          |

### Constraints

- **Must live inside `<Node>`**: a `<Text>` placed at the top level under `<Layout>` is silently ignored.
- **`children` must be a string or number**: nested elements or other types are not supported (numbers render as text). A line is a line.
- **Block-level props can't be overridden**: `align` / `lineHeight` only go on `<Node>`.
