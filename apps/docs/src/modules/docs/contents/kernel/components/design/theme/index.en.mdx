When figures share a visual style, pass a theme environment instead of repeating colors on every object. Theme describes the environment; primitive styles describe the final drawing. They are separate channels.

## Theme and styles

In the figure, a composite reads the theme and converts it into explicit styles for basic nodes and paths. The renderer executes the result without interpreting the theme again.

<ComponentPreview files="theme-flow" size="xs" hideCode />

| Content          | Responsibility                         | Consumer       |
| ---------------- | -------------------------------------- | -------------- |
| style            | Select visual style                    | Theme resolver |
| mode             | Select light or dark mode              | Theme resolver |
| colors           | Shared semantic and categorical colors | Composite      |
| Primitive styles | Explicit fill, stroke, etc.            | Renderer       |

Changing a theme therefore does not guarantee that handwritten Node or Path elements change color. Their explicit styles remain in effect; composites that consume the theme turn it into visible differences.

## Shared Theme

Kernel provides a default neutral color baseline through Core, supporting `light` and `dark` modes. It applies when no style is inherited or explicitly selected. The root defaults to `light`; there is no need to specify `style: 'neutral'`.

| Shared content     | Purpose                                     |
| ------------------ | ------------------------------------------- |
| `semantic.error`   | Errors                                      |
| `semantic.success` | Success                                     |
| `semantic.warning` | Warnings                                    |
| `semantic.guide`   | Low-emphasis supporting content             |
| `categorical`      | A non-empty palette for distinct categories |

The default categorical palette contains 16 colors. Light and dark modes preserve category indices and hue order while adjusting lightness and saturation. It provides reusable colors without deciding how charts, tables, or flow diagrams assign them.

## Data Structure

Theme has two data representations with different purposes: `IRTheme` stores author selections, while `ResolvedTheme` is the effective environment available to composites at the current compilation location.

| Data                  | Fields                     | Meaning                                               |
| --------------------- | -------------------------- | ----------------------------------------------------- |
| `IRTheme`             | `style?`, `mode?`          | Sparse selections; omitted fields inherit             |
| `ResolvedTheme`       | `style?`, `mode`, `colors` | Read-only result of inheritance and style resolution  |
| `ResolvedThemeColors` | `semantic`, `categorical`  | Shared semantic colors and active categorical palette |

This outline shows only the data shape. `Color` means a CSS color string, not an additional public type:

```text
IRTheme
  style?: string
  mode?: 'light' | 'dark'

ResolvedTheme
  style?: string
  mode: 'light' | 'dark'
  colors
    semantic: { error: Color, success: Color, warning: Color, guide: Color }
    categorical: non-empty array of Color
```

`colors` is not stored in `IRTheme`; it is generated from the current mode and style resolver. Custom styles can override individual semantic colors. An explicit categorical palette replaces the default palette as a whole and need not contain 16 colors. A style definition's `resolve` function belongs to the runtime environment, not persistable IR.

## Inheritance

IRScene is the persistable root drawing declaration, and Scope is a local group within it; the compiled Scene is the result consumed by renderers. Theme inherits field by field: an inner mode override keeps the outer style, and an inner style override keeps the outer mode.

For example, if the root uses Academic/light and a child group only selects dark mode, that child gets Academic/dark rather than another style. Theme inheritance is distinct from inheritance of node style defaults.

Theme choices can be saved with drawing declarations, while custom style implementations must be supplied by the runtime environment. Only components that consume that style change appearance; missing required style implementations report an error.
