Use Kernel in an existing Vite or similar TypeScript project. Published packages use ES modules and require Node.js 22.12 or later; the React adapter requires React / React DOM 18 or later.

## Installation and usage

<DocTabs defaultValue="react">
<DocTab value="react" label="React">

<PackageManagerInstall packages="@retikz/react react react-dom" />

Put this in your TSX entry. In an existing React application, use the Layout subtree inside a component without calling createRoot again.

```tsx
import { Draw, Layout, Node } from '@retikz/react';
import { createRoot } from 'react-dom/client';

createRoot(document.getElementById('diagram')!).render(
  <Layout>
    <Node id="a" position={[0, 0]}>
      A
    </Node>
    <Node id="b" position={[100, 0]}>
      B
    </Node>
    <Node id="c" position={[200, 0]}>
      C
    </Node>
    <Draw way={['a', 'b']} arrow="->" />
    <Draw way={['b', 'c']} arrow="->" />
  </Layout>,
);
```

<DocTab value="vanilla" label="Vanilla">

<PackageManagerInstall packages="@retikz/vanilla" />

Put this in your TypeScript entry. The package root provides drawing constructors; the /dom entry mounts SVG in the browser.

```ts
import { layer, node, path, scene } from '@retikz/vanilla';
import { mount } from '@retikz/vanilla/dom';

const input = scene({
  id: 'first-diagram',
  layers: [
    layer('main', [
      node('a', { position: [0, 0], text: 'A' }),
      node('b', { position: [100, 0], text: 'B' }),
      node('c', { position: [200, 0], text: 'C' }),
      path('ab', { way: ['a', 'b'], marks: [{ pos: 1, mark: { kind: 'arrow' } }] }),
      path('bc', { way: ['b', 'c'], marks: [{ pos: 1, mark: { kind: 'arrow' } }] }),
    ]),
  ],
});

const view = mount(document.getElementById('diagram')!, input);
```

`scene` describes the drawing, and `layer` groups its `node` / `path` objects. Each node position places that node. `marks` adds markers to a path: `pos: 1` means the endpoint, and `kind: 'arrow'` selects an arrow.

Call `view.dispose()` before removing the container to release the mounted view.

## Step by Step

### 1. The container `<Layout />` + one `<Node />`

A minimal diagram starts with a container and a primitive. `<Layout>` holds the whole diagram, provides an SVG viewport and displays its primitives; the viewport is calculated from the content by default. `<Node>` draws a positioned, named element with visible text. This first step places one node to confirm both the canvas and the basic primitive are working.

<ComponentPreview files="get-start-step-1" size="xs" />

### 2. More `<Node />`s

Add more `<Node>`s to place the entities in the diagram before drawing relationships between them. Keep each `id` unique within the current namespace — as a beginner, you can treat the whole `<Layout>` as one namespace. `<Draw>` will find nodes by id later, and `position` is the node center in canvas coordinates.

| Prop       | Meaning                                                               |
| ---------- | --------------------------------------------------------------------- |
| `id`       | Identifier unique in its namespace, referenced by `<Path>` / `<Draw>` |
| `position` | `[x, y]` user-unit coordinates for the node center                    |
| children   | The node's visible content (label)                                    |

<ComponentPreview files="get-start-step-2" size="xs" />

### 3. Connect them with `<Draw />`

`<Draw>` draws connecting lines. The `way` array lists the node ids to pass through in order, and retikz attaches the line to node borders instead of text centers. `arrow="->"` adds an arrowhead at the end.

<ComponentPreview files="get-start-final" size="xs" />

Three nodes joined by two arrowed lines — the static structure now matches the example at the top.

Keep four rules in mind before moving on:

- Canvas coordinates grow right on x and down on y; `[0, 0]` is the origin in retikz user units
- `<Layout>` defaults to the natural content size at 1 user unit per CSS pixel; normally omit display dimensions and `viewBox`
- A node `id` is the name used by connections, and `<Draw way={['a', 'b']}>` targets node borders rather than text centers
- The preview source shows equivalent notation. IR is the savable drawing declaration; Scene is the compiled result
