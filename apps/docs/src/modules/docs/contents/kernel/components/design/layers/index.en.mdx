retikz turns the DSL (React components or Vanilla JS) into IR first, then compiles IR into Scene. The DSL optimizes authoring, IR preserves what you intend to draw, and Scene preserves what a renderer needs to draw.

## Three Layers

| Layer | Role                                                                                                 | Audience                             |
| ----- | ---------------------------------------------------------------------------------------------------- | ------------------------------------ |
| DSL   | React component or Vanilla JS syntax, split into Kernel and Sugar                                    | Everyday authors                     |
| IR    | JSON-serializable declaration model that preserves Node / Path / Step / Coordinate / Scope semantics | Users, LLMs, persistence, converters |
| Scene | Render-target-neutral primitives, layout bounds, resources, and root animations                      | Renderers                            |

IR is the public contract; Scene is renderer input. You normally do not write Scene by hand.

Why this matters in practice: use the DSL when authoring diagrams, use IR when saving diagrams, asking an LLM to edit them, applying JSON Patch, or rendering across targets, and only inspect Scene when building renderers or debugging measured output.

## Kernel and Sugar

Kernel preserves basic drawing semantics; Sugar expands into those expressions during IR construction. See [Sugar](/kernel/components/design/sugar) for equivalent examples, expansion constraints, and selection guidance.

## Packages

Kernel currently contains nine packages released together. Choose an entry for your task; the package manager installs its dependencies.

| Package              | Responsibility                                    |
| -------------------- | ------------------------------------------------- |
| `@retikz/foundation` | Shared atomic contracts and base schemas          |
| `@retikz/math`       | Dependency-free geometry and numerical algorithms |
| `@retikz/runtime`    | Incremental execution and transactions            |
| `@retikz/core`       | Shared IR, Scene, and compilation                 |
| `@retikz/inspect`    | Diagnostic observation and overlays               |
| `@retikz/render`     | SVG / Canvas output                               |
| `@retikz/vanilla`    | Framework-free input and host integration         |
| `@retikz/react`      | React components and lifecycle integration        |
| `@retikz/tex`        | Optional LaTeX formula integration                |

Browser applications usually start with React or Vanilla. Consult the package documentation before adding other direct dependencies.
