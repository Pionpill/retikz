title: Arrow
description: Choose start and end arrows for Draw or Path, then control shape, size, color, opacity, and per-end overrides in one model.

Arrows are driven by two independent props:

- **`arrow`** — direction enum: `'->'` end / `'<-'` start / `'<->'` both / `'none'` (default) = none
- **`arrowDetail`** — visual detail object, 8 top-level fields + optional `start` / `end` sub-objects. **Omit it for the default "stealth sharp barb inheriting the path stroke / opacity" behavior**

Both props sit on `<Draw>` and `<Path>` with identical syntax and effect — the examples bottom use `<Draw>`; the `<Path>` equivalent is the same.

The arrow tip stays at the resolved path start / end, and arrows are not repeated at intermediate nodes. Compile shortens the rendered stroke at the arrow contact point so the line does not pass through the tip. Very short segments, two-ended arrows, or large `length` / `width` values can still overlap visually; reduce the arrow size or create room with node `margin` / explicit coordinates.

## Usage

```tsx
import { Draw } from '@retikz/react';
```

```tsx
<Draw way={['a', 'b']} arrow="->" />
```

## Examples

### Direction, shape, and appearance

One panel combines the `arrow` direction, all eight built-in shapes, color, opacity, and size. Enable “Configure ends separately” to let `start` / `end` override the shared shape and color field by field; disable it to share the top-level values. Omitting `arrowDetail` uses a `stealth` tip that inherits the path color, with length and width both set to 6.

<ComponentPreview files="arrow-appearance" size="md" />

Built-in shapes come in solid and hollow pairs:

| Solid                      | Hollow                            | Typical use                         |
| -------------------------- | --------------------------------- | ----------------------------------- |
| `'normal'` filled triangle | `'open'` hollow triangle          | Basic triangle / UML generalization |
| `'stealth'` sharp barb     | `'openStealth'` hollow sharp barb | Default arrow, modern flow charts   |
| `'diamond'` filled diamond | `'openDiamond'` hollow diamond    | UML composition / aggregation       |
| `'circle'` filled dot      | `'openCircle'` hollow dot         | Connection dot / open endpoint      |

> Multi-node paths (e.g. a → b → c) clip per-segment, but the arrow only attaches to the overall **start** / **end** — never to intermediate nodes.

> **Merge semantics**: sub-object fields win first; fields not in the sub-object fall back to the top-level defaults; fields not at the top level fall back to the built-in defaults. Example: `arrowDetail={{ shape: 'stealth', start: { color: 'red' } }}` → both ends use stealth, start in red, end inherits the path stroke.

> **Hollow shapes silently ignore `fill`**: when `shape ∈ { open / openStealth / openDiamond / openCircle }`, the `fill` field is silently dropped. Hollow shapes are driven entirely by `color` (stroke) + `lineWidth` (stroke width); writing `fill='red'` will not render a red fill.

`scale` multiplies after `length` / `width`; for example, `length=10, scale=1.5` produces an effective length of 15.

### How direction and per-end styles resolve

`<Draw>` first expands to an equivalent `<Path>`. `arrow` chooses whether to create a start marker, an end marker, or both; each endpoint then merges the top-level `arrowDetail` fields with its matching `start` / `end` fields.

Solid lines show the main endpoint-arrow resolution path. Dashed lines show the two auxiliary inputs: style defaults and the arrow registry.

Explicit element fields win over the path master color and Scope arrow defaults. Any remaining size fields fall back to defaults from the selected arrow definition. `shape` looks up a built-in or custom `ArrowDefinition`, which compile materializes into renderer-agnostic marker geometry. An unregistered name fails explicitly instead of silently falling back to the default shape.

### Why the path body becomes shorter

The arrow tip remains at the original endpoint. The compiler uses the definition's tip and line-contact points to shorten the path body in the opposite direction, making the stroke stop at the arrow's tail. This prevents a line from crossing a hollow outline or showing through a solid or translucent arrow.

The shrink distance changes with `length × scale × strokeWidth`; hollow shapes also include `lineWidth` in the contact position. When an endpoint references a Node and is clipped to its boundary automatically, compile adds an outer-outline compensation so a hollow arrow does not press into the node boundary.

### Whole-path endpoints and the stroke-inheritance boundary

A multi-node path can become several subpaths during compile, but the start arrow belongs only to the first subpath and the end arrow only to the last. “Start” and “end” always refer to the whole `<Path>`, not every visual corner.

## API Reference

### arrow

| Property      | Type                                    | Default | Description                                                                                                           |
| ------------- | --------------------------------------- | ------- | --------------------------------------------------------------------------------------------------------------------- |
| `arrow`       | `'none'` \| `'->'` \| `'<-'` \| `'<->'` | —       | Path-level arrow direction                                                                                            |
| `arrowDetail` | `IRArrowDetail`                         | —       | Arrow visual config; 8 top-level fields all optional + optional `start` / `end` sub-objects that merge field-by-field |

### arrowDetail fields

`arrowDetail` carries 8 visual fields + optional `start` / `end` sub-objects. The `start` / `end` sub-objects use the same field set (non-recursive) and merge field-by-field into the top-level defaults:

| Field       | Type                                                    | Default                      | Description                                                                                                               |
| ----------- | ------------------------------------------------------- | ---------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `shape`     | <ApiValues name="BuiltinArrowShape" /> \| `string`      | `'stealth'`                  | Arrow tip shape; one of the 8 built-ins or a custom arrow name registered via `<Layout arrows>` / `CompileOptions.arrows` |
| `scale`     | `number > 0`                                            | `1`                          | Uniform scale factor; multiplied **after** `length` / `width` (`length=10, scale=1.5` → effective 15)                     |
| `length`    | `number ≥ 0`                                            | `6`                          | Arrow length along the path direction (user units)                                                                        |
| `width`     | `number ≥ 0`                                            | `6`                          | Arrow width perpendicular to the path (user units)                                                                        |
| `color`     | `string`                                                | —                            | Stroke color override; default inherits the path stroke color                                                             |
| `fill`      | `string`                                                | `color` or path stroke color | Fill color override; **silent no-op on hollow shapes** (written value is dropped)                                         |
| `opacity`   | `number ∈ [0, 1]`                                       | —                            | Arrow-only opacity; default inherits path opacity                                                                         |
| `lineWidth` | `number ≥ 0`                                            | `1.5`                        | Stroke width for hollow shapes; ignored on solid shapes                                                                   |
| `start`     | `IRArrowEndDetail` (same field set, no `start` / `end`) | —                            | Start-end override (only effective when `arrow` includes the start: `'<-'` / `'<->'`)                                     |
| `end`       | `IRArrowEndDetail` (same field set, no `start` / `end`) | —                            | End-end override (only effective when `arrow` includes the end: `'->'` / `'<->'`)                                         |
