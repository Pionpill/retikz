---
title: Arrow
description: Choose start and end arrows for Draw or Path, then control visual details, size, and endpoint overlap independently.
---

Arrows are driven by three independent props:

- **`arrow`** — direction enum: `'->'` end / `'<-'` start / `'<->'` both / `'none'` (default) = none
- **`arrowDetail`** — visual detail object, 8 top-level fields + optional `start` / `end` sub-objects. **Omit it for the default "stealth sharp barb inheriting the path stroke / opacity" behavior**
- **`arrowPlacement`** — endpoint-placement object whose normalized `overlap` moves an arrow across its logical endpoint, with optional `start` / `end` overrides

All three props sit on `<Draw>` and `<Path>` with identical syntax and effect — the examples below use `<Draw>`; the `<Path>` equivalent is the same.

By default, the arrow tip stays at the resolved path start / end, and arrows are not repeated at intermediate nodes. Use `arrowPlacement` when a hollow circle or another arrow should cross a Node boundary. It does not change the NodeTarget, anchor, boundary, or the logical path-sampling positions.

## Usage

```tsx
import { Draw } from '@retikz/react';
```

```tsx
<Draw way={['a', 'b']} arrow="->" />
```

## Examples

### Direction, shape, and appearance

One panel combines the `arrow` direction, six Core basic arrows, two optional Standard arrows, color, opacity, and size. Enable “Configure ends separately” to let `start` / `end` override the shared shape and color field by field; disable it to share the top-level values. The panel explicitly injects the Standard Definitions it uses. Omitting `arrowDetail` uses a `stealth` tip that inherits the path color, with length and width both set to 8.

<ComponentPreview files="arrow-appearance" size="md" />

Core provides six basic arrows by default, including hollow triangle, hollow stealth, and the circle pair. The remaining solid / hollow diamond pair comes from [`@retikz/standard/arrow`](/library/standard/extension/arrow); using a Standard name requires injecting its Definition through the current `<Layout arrows>` or `CompileOptions.arrows`:

| Solid                               | Hollow                                  | Typical use                         |
| ----------------------------------- | --------------------------------------- | ----------------------------------- |
| `'normal'` Core filled triangle     | `'open'` Core hollow triangle           | Basic triangle / UML generalization |
| `'stealth'` Core sharp barb         | `'openStealth'` Core hollow sharp barb  | Default arrow, modern flow charts   |
| `'diamond'` Standard filled diamond | `'openDiamond'` Standard hollow diamond | UML composition / aggregation       |
| `'circle'` Core filled dot          | `'openCircle'` Core hollow dot          | Connection dot / open endpoint      |

> Multi-node paths (e.g. a → b → c) clip per-segment, but the arrow only attaches to the overall **start** / **end** — never to intermediate nodes.

> **Merge semantics**: sub-object fields win first; fields not in the sub-object fall back to the top-level defaults; fields not at the top level fall back to the built-in defaults. Example: `arrowDetail={{ shape: 'stealth', start: { color: 'red' } }}` → both ends use stealth, start in red, end inherits the path stroke.

> **Hollow shapes silently ignore `fill`**: when `shape ∈ { open / openStealth / openDiamond / openCircle }`, the `fill` field is silently dropped. Hollow shapes are driven entirely by `color` (stroke) + `lineWidth` (stroke width); writing `fill='red'` will not render a red fill.

`scale` multiplies after `length` / `width`; for example, `length=10, scale=1.5` produces an effective length of 15.

### Endpoint overlap

`arrowPlacement.overlap` is normalized between two final placements: `0` preserves the existing default, `0.5` is the midpoint between the default and fully entered positions, and `1` aligns the final visual back with the logical endpoint. The back, path contact, and tip are separate geometry facts, so even a barbed `stealth` arrow is fully inside at `1`.

The calculation uses the resolved `length × scale`; hollow arrows also account for `lineWidth` and outer-outline compensation. After enlarging, shrinking, or overriding the length, `1` still means that the whole arrow's final visual back is aligned rather than a fixed user-unit offset.

The shared top-level `overlap` applies only to endpoints actually created by `arrow`. `start.overlap` / `end.overlap` override it per endpoint, and an explicit `0` is preserved. For example, `arrow="<->" arrowPlacement={{ overlap: 0.5, start: { overlap: 0 } }}` moves only the end halfway inside.

<ComponentAlert
  type="warn"
  title="Overlap does not change paint order"
  description="Whether an arrow remains visible after entering a node still follows the existing zIndex and declaration order. arrowPlacement does not add clipping, raise the arrow, or change node fill."
/>

`arrowPlacement` must correspond to a real endpoint arrow. No arrow, an endpoint object for an end that was not created, a direct-IR inline mark, a duplicate endpoint mark that was not selected, and `endpointOverlap` on a non-built-in Stroke Path all fail explicitly instead of becoming silent no-ops.

### How direction and per-end styles resolve

`<Draw>` first expands to an equivalent `<Path>`. `arrow` chooses whether to create a start marker, an end marker, or both; each endpoint then merges `arrowDetail` visual fields and `arrowPlacement` placement fields independently.

Solid lines show the main endpoint-arrow resolution path. Dashed lines show the two auxiliary inputs: style defaults and the arrow registry.

Any remaining size fields fall back to defaults from the selected arrow definition. `shape` looks up a Core basic, explicitly injected Standard, or custom `ArrowDefinition`, which compile materializes into renderer-agnostic marker geometry. An unregistered name fails explicitly instead of silently falling back to the default shape.

### Why the path body becomes shorter

By default, the arrow tip remains at the logical endpoint. The compiler uses the definition's tip and line-contact points to shorten the path body in the opposite direction, while letting the stroke overlap the contact edge by half of its own width before the marker paints over the joint. This removes antialiasing seams without letting the line cross a hollow outline or show through a solid or translucent arrow.

Core resolves the definition's `backX`, `lineContactX`, and `tipX` as the visual back, main-stroke contact, and tip, then interpolates `overlap` between the default shrink and the shrink required for back alignment. When an endpoint references a Node and is clipped automatically, outer-outline protection decays by `1 - overlap`; the default placement still keeps its half-line-width seam cover. Scene gains no placement field, so SVG and Canvas continue to execute the same final commands.

### Whole-path endpoints and the stroke-inheritance boundary

A multi-node path can become several subpaths during compile, but the start arrow belongs only to the first subpath and the end arrow only to the last. “Start” and “end” always refer to the whole `<Path>`, not every visual corner.

## API Reference

### arrow, arrowDetail, and arrowPlacement

| Property         | Type                                    | Default | Description                                                                                                           |
| ---------------- | --------------------------------------- | ------- | --------------------------------------------------------------------------------------------------------------------- |
| `arrow`          | `'none'` \| `'->'` \| `'<-'` \| `'<->'` | —       | Path-level arrow direction                                                                                            |
| `arrowDetail`    | `IRArrowDetail`                         | —       | Arrow visual config; 8 top-level fields all optional + optional `start` / `end` sub-objects that merge field-by-field |
| `arrowPlacement` | `InputPathArrowPlacement`               | —       | Endpoint placement; shared `overlap` plus `start` / `end` overrides, with every overlap constrained to `[0, 1]`       |

### arrowDetail fields

`arrowDetail` carries 8 visual fields + optional `start` / `end` sub-objects. The `start` / `end` sub-objects use the same field set (non-recursive) and merge field-by-field into the top-level defaults:

| Field       | Type                                                    | Default                      | Description                                                                                                                                                                                    |
| ----------- | ------------------------------------------------------- | ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `shape`     | <ApiValues name="BuiltinArrowShape" /> \| `string`      | `'stealth'`                  | Core basic arrows are `normal` / `open` / `stealth` / `openStealth` / `circle` / `openCircle`; optional Standard and custom names register through `<Layout arrows>` / `CompileOptions.arrows` |
| `scale`     | `number > 0`                                            | `1`                          | Uniform scale factor; multiplied **after** `length` / `width` (`length=10, scale=1.5` → effective 15)                                                                                          |
| `length`    | `number ≥ 0`                                            | Definition / `8`             | Arrow length along the path direction (user units); uses `8` when the Definition does not provide a value                                                                                      |
| `width`     | `number ≥ 0`                                            | Definition / `8`             | Arrow width perpendicular to the path (user units); uses `8` when the Definition does not provide a value                                                                                      |
| `color`     | `string`                                                | —                            | Stroke color override; default inherits the path stroke color                                                                                                                                  |
| `fill`      | `string`                                                | `color` or path stroke color | Fill color override; **silent no-op on hollow shapes** (written value is dropped)                                                                                                              |
| `opacity`   | `number ∈ [0, 1]`                                       | —                            | Arrow-only opacity; default inherits path opacity                                                                                                                                              |
| `lineWidth` | `number ≥ 0`                                            | `1.5`                        | Stroke width for hollow shapes; ignored on solid shapes                                                                                                                                        |
| `start`     | `IRArrowEndDetail` (same field set, no `start` / `end`) | —                            | Start-end override (only effective when `arrow` includes the start: `'<-'` / `'<->'`)                                                                                                          |
| `end`       | `IRArrowEndDetail` (same field set, no `start` / `end`) | —                            | End-end override (only effective when `arrow` includes the end: `'->'` / `'<->'`)                                                                                                              |

### arrowPlacement fields

| Field     | Type                            | Default | Description                                                    |
| --------- | ------------------------------- | ------- | -------------------------------------------------------------- |
| `overlap` | `number ∈ [0, 1]`               | `0`     | Shared ratio from the current default to visual-back alignment |
| `start`   | `{ overlap?: number ∈ [0, 1] }` | —       | Start override; valid only with `arrow="<-"` or `arrow="<->"`  |
| `end`     | `{ overlap?: number ∈ [0, 1] }` | —       | End override; valid only with `arrow="->"` or `arrow="<->"`    |
