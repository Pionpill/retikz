Animation transitions a static figure **from one look to another over time**: fade in, draw a line, scale up, spin, shift color, pan the camera. You don't hand-write keyframes — call a **preset factory** (`fadeIn()` / `spin()` …) to get an animation descriptor and attach it to an element's `animations` array.

## Usage

```tsx
import { fadeIn, scaleIn } from '@retikz/core';
import { Node } from '@retikz/react';
```

```tsx
<Node position={[0, 0]} animations={[fadeIn(), scaleIn()]}>
  hi
</Node>
```

## Examples

`animations` attaches to `<Node>` / `<Path>` / `<Scope>` (element animation) and `<Layout>` (camera). An element can carry several; they don't interfere. Apart from the `loop` wrapper and the `stagger` choreographer, every preset accepts the common options `{ duration, delay, easing, trigger }`; some add their own (`scaleIn.from` / `slideIn.axis,offset` / `growUp.origin` / `pulse.peak` …).

### All animations

| Animation    | Family       | Channel       | What it does                                      |
| ------------ | ------------ | ------------- | ------------------------------------------------- |
| `fadeIn`     | intro        | opacity       | fade in (0→1)                                     |
| `drawOn`     | intro        | pathDraw      | stroke draws along the path                       |
| `scaleIn`    | intro        | scale         | pop in from slightly small (0.8→1)                |
| `grow`       | intro        | scale         | grow from nothing (0→1)                           |
| `growUp`     | intro        | scaleY        | grow from baseline (bars)                         |
| `slideIn`    | intro        | translateX/Y  | slide in from an offset                           |
| `colorShift` | emphasis     | fill / stroke | color transition (oklch lerp)                     |
| `flash`      | emphasis     | opacity       | flash once (2× by default)                        |
| `blink`      | emphasis     | opacity       | continuous blink (infinite)                       |
| `wiggle`     | emphasis     | rotate        | rock left/right (3× by default)                   |
| `pulse`      | loop         | scale         | pulsing scale (infinite)                          |
| `spin`       | loop         | rotate        | steady rotation (infinite, loader)                |
| `loop`       | loop         | any           | turn any track into an infinite loop              |
| `cameraTo`   | camera       | viewBox       | pan / zoom the camera (on `<Layout>`)             |
| `stagger`    | choreography | —             | add increasing delay across a group               |
| `snapshot`   | control      | —             | `snapshotAt` bakes a static frame at a given time |

### Intro

Intro animations **play once on load**, bringing an element from a transparent / offset / shrunk state to its final look. They are element animations attached to a `<Node>` / `<Path>` / `<Scope>`'s `animations`.

| --------- | ------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `fadeIn`  | Opacity 0→1, the most common entrance                                                                   | — (common options only)                                                                                                                  |

| `grow`    | The `from: 0` alias of `scaleIn`, growing from nothing                                                  | `origin` (same as `scaleIn`)                                                                                                             |
| `growUp`  | `scaleY` 0→1 with the pivot at the bottom edge — bars growing from the baseline                         | `origin` (defaults to `'bottom'`, the bottom-edge midpoint; also accepts another canonical anchor or `[x, y]`)                           |
| `slideIn` | `translateX`/`translateY` `offset`→0, sliding back to place from an offset                              | `axis` (`'x'`→`translateX` / `'y'`→`translateY`, defaults to `'x'`), `offset` (starting shift, defaults to `-20`; last frame always `0`) |
| `drawOn`  | `pathDraw` 0→1, the stroke drawing progressively along the path; only for **stroked** `<Path>` / shapes | — (common options only)                                                                                                                  |

### Emphasis & Loop

Emphasis animations **draw attention** — shift color, flash, rock; loop animations **play continuously** — pulse, spin, or wrap any track into an infinite loop. They are element animations. Emphasis often uses three frames `0 → 0.5 → 1` (with the last frame back at base, so one pass leaves the element unchanged); `flash` repeats twice by default, `wiggle` three times, while `blink` / `pulse` / `spin` use `iterations: 'infinite'` to run forever.

| Animation    | What it does                                                                                                                                                        | Specific options                                                                                                                                         |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `colorShift` | Transitions `fill` / `stroke` in **oklch** space (perceptually even, no muddy band); targets the shape's own fill / stroke                                          | `from` / `to` (start / end color, **both required** — a pure factory can't read the base color), `channel` (`'fill'` / `'stroke'`, defaults to `'fill'`) |
| `flash`      | `opacity` 1→dim→1 flashed once, twice by default; the last frame returns to base                                                                                    | `dim` (trough opacity, defaults to `0`), `iterations` (flash count, defaults to `2`)                                                                     |
| `blink`      | The infinite version of `flash` (`opacity` blinking continuously)                                                                                                   | `dim` (trough opacity, defaults to `0`), `iterations` (defaults to `'infinite'`)                                                                         |
| `wiggle`     | `rotate` 0→+a→−a→+a→0 rocking emphasis, around the geometric center                                                                                                 | `angle` (rock amplitude in degrees, defaults to `5`), `iterations` (defaults to `3`), `origin` (rotation pivot, defaults to the geometric center)        |
| `pulse`      | `scale` 1→peak→1 infinite pulse (emphasis / heartbeat)                                                                                                              | `peak` (peak scale, defaults to `1.1`), `origin` (scale pivot, defaults to the geometric center)                                                         |
| `spin`       | `rotate` 0→360, infinite and linear, around the geometric center — a typical loader                                                                                 | `origin` (rotation pivot, defaults to the geometric center)                                                                                              |
| `loop`       | `loop(track, { direction })`: wraps any one-shot track into an infinite loop; produces no new track, layering `iterations` / `direction` onto the track you pass in | `iterations` (defaults to `'infinite'`), `direction` (e.g. `'alternate'`, play back and forth)                                                           |

### Camera & Stagger

Camera and stagger are the two animations that act **on the whole, not on a single element's look**: `cameraTo` animates the scene's viewbox, while `stagger` adjusts the start times of a group of animations.

`cameraTo({ from, to })`: animates the scene's viewbox `[x, y, w, h]` for pan / zoom. Attach it to `<Layout animations>` (the camera belongs to the scene root, not an element); both endpoints are explicit. It defaults to `duration` 800ms and `easing` `ease-in-out`, both overridable like the other common options. It expands to a single `viewBox`-channel track.

<ComponentPreview files="camera" size="md" />

<span style={{ color: '#888' }}>The camera pushes from the full view into the bottom-right corner.</span>

`stagger(tracks, stepMs, startMs = 0)`: **rewrites each track's `delay` to `startMs + i×stepMs`** (overriding any existing `delay`) for a one-by-one entrance. The third argument `startMs` defaults to 0 and is the group's start offset. It choreographs the start times of element animations; it doesn't change any single animation's shape.

### How a track reaches rendering

A preset and a hand-written track both end as the same `AnimationTrack`. A preset only supplies a common property channel, keyframes, and timing defaults; its result is still serializable JSON with no callbacks, DOM objects, or playback state.

After a track is attached to an element or `<Layout>`, compile only validates its responsibility boundary and preserves valid data: `viewBox` belongs to the Scene root as a camera track, while every other channel belongs to an element. An out-of-place track emits a warning and is dropped, so a renderer does not need to decide that ownership again.

The figure stays within the animation boundary: presets and hand-written data converge on one track, enter the renderer-agnostic Scene, then branch into live playback or a static snapshot.

<ComponentPreview files="animation-pipeline" size="lg" hideCode />

React DSL, direct IR, and Vanilla specs therefore share one animation model. A backend chooses how to play it; it does not reinterpret a preset as a second model.

### How time becomes a frame

A keyframe's `at` is a normalized position in `[0, 1]`; `duration` maps that position to milliseconds. At any instant, evaluation subtracts `delay`, selects the iteration and direction, applies `fill` outside the active interval, locates the neighboring keyframes, applies segment easing, and finally interpolates by value type.

The two renderers use different live carriers while consuming the same track:

- SVG expands `load` tracks into inline CSS `@keyframes`, so static HTML can autoplay with zero JavaScript; `visible`, `manual`, and event tracks become descriptors that the runtime connects to WAAPI
- Canvas advances one Scene-level rAF clock and calls the shared evaluator every frame, then applies the result to primitive properties or canvas transforms before redrawing
- `snapshotAt` starts no clock; it samples that same evaluator at one time and emits static attributes and transforms

### Triggers and control

`trigger` decides **when a track becomes active**; it does not change the keyframes or timing. The default is `load`:

| trigger                | Behavior                                | Backend support                                                        |
| ---------------------- | --------------------------------------- | ---------------------------------------------------------------------- |
| `load` (default)       | plays on render                         | SVG (inline CSS, zero-JS SSR) / Canvas (starts rAF)                    |
| `visible`              | plays when in viewport                  | SVG (IntersectionObserver); Canvas (id bbox intersecting the viewport) |
| `manual`               | no autoplay, driven by a runtime handle | SVG / Canvas                                                           |
| `{ onEvent: 'click' }` | plays when the event fires              | SVG / Canvas (hydration hit activates the id)                          |

Pass a ref to `<Layout animationRef={ref}>` and after mount you get `AnimationControls` (`play` / `pause` / `seek`) to drive playback from your own buttons outside the component (most useful with `trigger: 'manual'`):

```tsx
const ref = useRef<AnimationControls | null>(null);

<Layout animationRef={ref}>
  <Node position={[0, 0]} animations={[{ ...spin(), trigger: 'manual' }]} />
</Layout>
<button onClick={() => ref.current?.play()}>Play</button>
```

`animationRef` / vanilla `view.animation` is the Scene-level clock handle: SVG controls the diagram's interactive WAAPI handle, while Canvas controls the shared rAF clock. Inside a handler, use hydration's [`context.animation`](/kernel/packages/render/hydration#the-handler-context) to control the hit id; both backends expose per-id controls there.

The playback switch has three states. React and Vanilla use different shapes but the same priority:

| Intent        | React             | Vanilla                         |
| ------------- | ----------------- | ------------------------------- |
| Follow system | omit `animate`    | omit `animation.enabled`        |
| Force on      | `animate={true}`  | `animation: { enabled: true }`  |
| Force off     | `animate={false}` | `animation: { enabled: false }` |

### Static frames and fallback

Pass `<Layout snapshotAt={ms}>` (or `renderToSvgString(ir, { animation: { snapshotAt } })` / `mountSvg(…, { animation: { snapshotAt } })`) to render **one frame frozen at that time**. It starts no playback and emits no animation rules; it only bakes autoplay-track values into static attributes or transforms. This is useful for SSR poster frames, thumbnails, and social-card previews.

<ComponentPreview files="snapshot" size="xs" />

```tsx
// grow (0→1, 300ms) frozen at 150ms ≈ half size
<Layout snapshotAt={150}>
  <Node position={[0, 0]} animations={[grow({ duration: 300 })]}>
    150ms
  </Node>
</Layout>
```

`snapshotAt` has priority over the playback switch, but samples only `load` or omitted triggers. `manual`, `visible`, and event tracks stay at base because a poster represents "loaded, before any interaction." Without a snapshot, explicitly disabling animation, following a reduced-motion preference, or lacking backend animation support also renders the base figure without throwing or dropping it.

The default `fill="forwards"` keeps the last frame after playback. Built-in intro and return-to-base presets end at common base values, and `spin` at 360° is equivalent to 0°. `colorShift` and `cameraTo` cannot read an element or camera base, so you provide their destinations explicitly. `AnimationTrackSchema` documents "the last frame should be settled" as an authoring convention rather than comparing it against the base; hand-written tracks and explicit destinations must land on the intended resting state when they need graceful fallback.

## API Reference

### Component props

| Prop           | Type                             | Default     | Description                                               |
| -------------- | -------------------------------- | ----------- | --------------------------------------------------------- |
| `animations`   | `Array<IRAnimationTrack>`        | —           | Tracks attached to a Node, Path, Scope, or Layout         |
| `animate`      | `boolean`                        | `undefined` | Layout playback switch; omitted follows system preference |
| `snapshotAt`   | `number`                         | —           | Layout static-snapshot time in milliseconds               |
| `animationRef` | `Ref<AnimationControls \| null>` | —           | Layout's scene-level playback control handle              |

### AnimationTrack

| Prop         | Type                                                                 | Default        | Description                                            |
| ------------ | -------------------------------------------------------------------- | -------------- | ------------------------------------------------------ |
| `property`   | `string`                                                             | —              | Property channel; `viewBox` is Layout-only             |
| `keyframes`  | `Array<{ at, value, easing? }>`                                      | —              | Absolute-value keyframes sorted by `at`                |
| `duration`   | `number`                                                             | —              | Duration of one iteration in milliseconds              |
| `delay`      | `number`                                                             | `0`            | Delay before the first iteration in milliseconds       |
| `easing`     | `string \| [number, number, number, number]`                         | `'linear'`     | Track easing; a keyframe can override the next segment |
| `iterations` | `number \| 'infinite'`                                               | `1`            | Playback count                                         |
| `direction`  | `'normal' \| 'reverse' \| 'alternate'`<br />`\| 'alternate-reverse'` | `'normal'`     | Direction of each iteration                            |
| `fill`       | `'none' \| 'forwards' \| 'backwards' \| 'both'`                      | `'forwards'`   | Value used outside the active interval                 |
| `trigger`    | `'load' \| 'visible' \| 'manual'`<br />`\| { onEvent: string }`      | `'load'`       | Playback trigger                                       |
| `origin`     | `Anchor \| [number, number]`                                         | element center | Pivot for scale, scaleX/Y, and rotate                  |
