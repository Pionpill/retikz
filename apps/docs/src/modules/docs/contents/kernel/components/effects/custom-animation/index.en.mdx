Built-in animation covers common opacity, color, transform, stroke, and camera changes. Register an easing when you need a new motion curve, or register a property channel when animation must drive a new Canvas value.

This example gives `scaleIn()` a spring-like `spring` easing. The animation track still stores only the string name.

## Boundaries

First decide whether you are extending the timing curve or the property being changed:

| Need                    | Extension point       | Backend                     |
| ----------------------- | --------------------- | --------------------------- |
| Change motion timing    | `easings`             | SVG + Canvas (tuple)        |
| Use a JavaScript easing | `easings`             | Canvas live; both snapshots |
| Drive a new property    | `animationProperties` | Canvas                      |

If a built-in channel already represents the property, change its easing or write keyframes instead of adding another channel. Custom property channels depend on the Canvas 2D context and are not suitable when equivalent SVG output is required.

## Define the capability

### Easing curves

An easing registry value is either a cubic-bezier tuple or a `(t) => number` function, so it needs no wrapper definition:

```tsx
import type { EasingRegistry } from '@retikz/render/animation';

const easings = {
  spring: [0.34, 1.56, 0.64, 1],
} satisfies EasingRegistry;
```

A tuple works in SVG CSS and the shared evaluator. A function needs JavaScript: Canvas can play it live, and `snapshotAt` can evaluate it for both SVG and Canvas; live SVG cannot put the function into CSS. Tuple y values may leave `[0, 1]` for overshoot or spring-like motion.

### Property channels

A new channel uses `AnimationPropertyDefinition`. `interpolate` computes a value between neighboring keyframes, and `applyCanvas` applies that value while the primitive is being drawn.

```tsx
import type { AnimationPropertyDefinition } from '@retikz/render/animation';

const blur = {
  interpolate: (from, to, t) => Number(from) + (Number(to) - Number(from)) * t,
  applyCanvas: (ctx, _primitive, value) => {
    ctx.filter = `blur(${Number(value)}px)`;
  },
} satisfies AnimationPropertyDefinition;
```

This example registers `blur` and uses an ordinary `AnimationTrack` to move from blurred to sharp. You can tune the starting blur and duration while the complete property definition stays visible in the code:

## Inject the host

Both registries enter through `<Layout>`. Tracks reference registry entries by name, while functions and Canvas contexts stay outside the IR.

```tsx
<Layout renderer="canvas" easings={easings} animationProperties={{ blur }}>
  <Node animations={[scaleIn({ easing: 'spring' }), blurIn]} />
</Layout>
```

You do not need to force Canvas when registering only an easing. Cubic-bezier tuples play live in both SVG and Canvas. Function easings are limited only for live SVG; snapshots still use the shared JavaScript evaluator. `animationProperties` always depends on Canvas.

## Execution

Track `easing` and `property` values are both open strings, but they are resolved at different points:

| Extension | Lookup time                    | Consumption                      |
| --------- | ------------------------------ | -------------------------------- |
| easing    | Before each segment evaluates  | Maps time to eased progress      |
| property  | While Canvas draws a primitive | Interpolates and updates context |

Live SVG converts cubic-bezier values into CSS timing functions. A function cannot be serialized into CSS, so it warns and falls back to `linear`. `snapshotAt` emits no CSS and samples the shared evaluator, so static SVG frames can use function easings. A custom property has no generic SVG mapping, so SVG skips that track and keeps the primitive at rest.

Built-in easing names resolve before custom record entries, and built-in property channels are classified first, so custom entries cannot override built-in semantics. These extensions do not share one `defineXxx`: an easing value is already simple, while a property channel is a renderer-specific runtime definition.

## Errors and limits

| Case                           | SVG                  | Canvas                 |
| ------------------------------ | -------------------- | ---------------------- |
| Unregistered easing (live)     | Warns, uses `linear` | Silently uses `linear` |
| Function easing (live)         | Warns, uses `linear` | Evaluates normally     |
| Function easing (`snapshotAt`) | Evaluates normally   | Evaluates normally     |
| Unregistered property          | Warns, skips track   | Warns, skips track     |
| Registered custom property     | Warns, skips track   | Evaluates and applies  |

Skipping a track never drops the primitive; it renders at rest. Registry keys should be non-empty, stable strings that do not overlap built-in names. These lightweight record registries do not diagnose replacement by the same key.

## API Reference

### Layout registry props

| Prop                  | Type                        | Default | Description                       |
| --------------------- | --------------------------- | ------- | --------------------------------- |
| `easings`             | `EasingRegistry`            | —       | Maps names to tuples or functions |
| `animationProperties` | `AnimationPropertyRegistry` | —       | Maps names to Canvas definitions  |

### AnimationPropertyDefinition

| Prop          | Type                         | Default | Description                         |
| ------------- | ---------------------------- | ------- | ----------------------------------- |
| `interpolate` | `(from, to, t) => unknown`   | —       | Computes the current keyframe value |
| `applyCanvas` | `(ctx, prim, value) => void` | —       | Applies the value while drawing     |
