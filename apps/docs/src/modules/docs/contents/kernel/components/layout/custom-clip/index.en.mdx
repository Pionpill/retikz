When a domain needs a reusable named clipping primitive, define a `ClipDefinition` and inject it through `CompileOptions.clips` or `<Layout clips>`. The `rounded-rect` below is a complete runnable path from Definition and registration to `<Scope clip>`.

## Applicability Boundary

A custom clip solves “the existing `clip.kind` vocabulary cannot express this domain concept.” It is not the default form of every clip.

| Need                                           | Choose                       |
| ---------------------------------------------- | ---------------------------- |
| One-off rectangle, circle, ellipse, or polygon | Write a built-in clip spec   |
| A path or combined regions                     | Built-in `path` / `compound` |
| A reusable domain clipping primitive           | Register `ClipDefinition`    |
| Renderer-specific mask / filter behavior       | Outside the Clip Registry    |

IR stores only a JSON-safe spec with a `kind`. Functions, Zod schemas, and caches stay in the host-injected Definition. A custom provider must return a Scene-supported clip shape instead of creating a parallel rendering protocol.

## Define the Capability

`kind` is the stable registry key, `schema` validates the complete spec, and `resolve` converges valid input into a built-in `ClipShape`. Copy the full rounded-path command list from the demo source above.

```ts
const roundedRectClip = defineClip({
  kind: 'rounded-rect',
  schema: roundedRectClipSchema,
  resolve: spec => ({
    kind: 'path',
    commands: buildRoundedRectCommands(spec),
  }),
});
```

`resolve(spec, context)` can also use:

- `context.round(value)` to apply stable compile precision
- `context.resolve(otherSpec)` to send another clip spec through the same registry

## Inject the Host

Core and React are two injection entries for the same Definition:

```ts
const { scene } = compileToScene(ir, {
  clips: [roundedRectClip],
});
```

```tsx
<Layout clips={[roundedRectClip]}>
  <Scope
    clip={{
      kind: 'rounded-rect',
      x: -150,
      y: -72,
      width: 300,
      height: 144,
      radius: 36,
    }}
  >
    {/* clipped children */}
  </Scope>
</Layout>
```

`<Layout>` only forwards `clips` into Core compile options; the React adapter does not keep a second custom-clip table.

## Execution Path

Built-in and custom Definitions first merge into one registry. Every `clip.kind` then follows the same lookup, validation, and resolution path. Scene and renderer do not need to know where a Definition came from.

`compound.children` returns to this path through `context.resolve`, so one compound clip can mix built-in and custom kinds. The resolved shape is deduplicated into a stable `clipRef` referenced by Scope's `GroupPrim`.

## Errors and Limits

| Case                            | Result                                                       |
| ------------------------------- | ------------------------------------------------------------ |
| Empty key                       | Definition or registry rejects it immediately                |
| Same key as a built-in          | Duplicate clip registration error                            |
| Duplicate custom keys           | The same duplicate-registration error                        |
| Unknown `clip.kind`             | Compile error suggests injection through `options.clips`     |
| Spec fails `schema`             | Compile error preserves provider key, IR path, and Zod cause |
| `resolve` returns invalid shape | The Definition author violated the required Scene output     |

Custom clip parameters must be JSON-serializable. Do not put functions, ReactNode values, class instances, or renderer objects in a spec.

## API Reference

Except for the explicitly marked React injection prop, import every type, function, and constant in this section from `@retikz/core`.

### Export Overview

- `defineClip<TSpec>(definition)`: defines a custom clip, rejects an empty `kind`, and preserves concrete spec inference
- `ClipSpecLike`: the minimum custom clip spec shape, requiring only a string `kind`
- `ClipDefinitionInput<TSpec>`: the generic authoring contract that keeps `schema` and `resolve` on the same spec type
- `ClipDefinition`: the unified Definition shape stored and consumed by the registry after its concrete spec type is erased
- `ClipResolveContext`: runtime context passed to `resolve`, providing shared precision rounding and recursive clip resolution
- `BUILTIN_CLIPS`: Core's read-only Definition collection, both iterable and addressable through names such as `.rect`
- `BuiltinClipProviderName`: the union of every built-in clip key
- `resolveClipRegistry(clips?)`: merges built-in and custom Definitions and applies shared empty-key and duplicate checks; normal consumers do not call it directly
- `CompileOptions.clips`: injects custom Definitions through the Core compile entry
- `<Layout clips>` (`@retikz/react`): injects the same Definitions through the React host

### ClipDefinition

`ClipDefinitionInput<TSpec>` is the strongly typed authoring input. `defineClip` returns the unified `ClipDefinition` consumed by the registry. Both have the same fields:

| Field     | Type                                                      | Required | Description                                                                 |
| --------- | --------------------------------------------------------- | -------- | --------------------------------------------------------------------------- |
| `kind`    | `TSpec['kind']`                                           | Yes      | Non-empty registry key that must match the IR `clip.kind`                   |
| `schema`  | `ZodType<TSpec>`                                          | Yes      | Validates the complete JSON-safe spec and supplies valid input to `resolve` |
| `resolve` | `(spec: TSpec, context: ClipResolveContext) => ClipShape` | Yes      | Converges valid input into a Scene-supported shape, never a renderer object |

### BUILTIN_CLIPS

`BUILTIN_CLIPS` is not a string enum. It is a read-only `ClipDefinition` array with named indexes. Iterate it to inspect every Definition, or access one through `BUILTIN_CLIPS.rect`; IR still uses the corresponding `kind` string.

| Named index              | IR `kind`  | Spec fields                 | Meaning                                              |
| ------------------------ | ---------- | --------------------------- | ---------------------------------------------------- |
| `BUILTIN_CLIPS.rect`     | `rect`     | `x`, `y`, `width`, `height` | Axis-aligned rectangular clip region                 |
| `BUILTIN_CLIPS.circle`   | `circle`   | `cx`, `cy`, `r`             | Circular clip region                                 |
| `BUILTIN_CLIPS.ellipse`  | `ellipse`  | `cx`, `cy`, `rx`, `ry`      | Elliptical clip region                               |
| `BUILTIN_CLIPS.polygon`  | `polygon`  | `points`                    | Polygon clip region with at least three vertices     |
| `BUILTIN_CLIPS.path`     | `path`     | `commands`, `fillRule?`     | Structured path clip region                          |
| `BUILTIN_CLIPS.compound` | `compound` | `children`, `fillRule?`     | Recursively combines built-in or custom clip regions |
