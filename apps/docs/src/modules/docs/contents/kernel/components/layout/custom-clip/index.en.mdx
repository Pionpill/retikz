`ClipDefinition` owns both clip input and geometry lowering. The rounded rectangle below registers one definition, while SVG, Canvas, visual bounds, and hit testing all consume the same `SceneClipPath`.

## Applicability Boundary

| Need                                                | Choose                                                                       |
| --------------------------------------------------- | ---------------------------------------------------------------------------- |
| One-off rectangle                                   | Write the Core built-in `rect` clip spec                                     |
| Circle, ellipse, polygon, path, or combined regions | Inject a Definition from [Clip Extensions](/library/standard/extension/clip) |
| New static 2D clipping geometry                     | Define one complete `ClipDefinition` that lowers to `SceneClipPath`          |
| Renderer-specific mask / filter behavior            | Outside Clip; use an explicit backend capability                             |

IR stores only a JSON-safe clip spec with a `kind`. The `ClipShape` returned by `resolve` is also a JSON-safe snapshot. Zod schemas, callbacks, ReactNode values, Canvas objects, and SVG strings never enter IR or Scene.

## Define the Capability

One definition binds the spec schema, shape schema, resolution, and lowering under the same `kind`:

```ts
const roundedRectClip = defineClip<RoundedRectClip, RoundedRectClip>({
  kind: 'rounded-rect',
  schema: roundedRectClipSchema,
  resolve: spec => spec,
  shapeSchema: roundedRectClipSchema,
  lower: shape => ({
    commands: buildRoundedRectCommands(shape),
    fillRule: 'nonzero',
  }),
});
```

`resolve(spec, context)` can use `context.round(value)` for current compile precision or `context.resolve(otherSpec)` to resolve another clip recursively. `lower(shape, context)` receives the same rounding function and may compose shapes registered in the current registry through `context.lower(otherShape)`.

The definition, parsed spec, and parsed shape must all share one `kind`. Several kinds may reuse ordinary geometry helpers, but each independently assembled clip still owns a complete definition.

`lower` must return a structured path with at least one drawing segment. Core does not auto-close open paths and rejects raw SVG `d`, Canvas callbacks, and non-finite numbers.

## Inject the Host

Direct Core calls inject only `clips`:

```ts
const { scene } = compileToScene(ir, {
  clips: [roundedRectClip],
});
```

React `<Layout>` forwards the same Core option without an adapter-private registry:

```tsx
<Layout clips={[roundedRectClip]}>
  <Scope clip={{ kind: 'rounded-rect', x: -150, y: -72, width: 300, height: 144, radius: 36 }}>
    {/* clipped children */}
  </Scope>
</Layout>
```

In provider-graph assembly, one `{ capability: 'clip', name: kind }` provider creates the complete definition. Explicit `clips` remains the final Definition channel and participates in same-key conflict checks.

## Execution Path

Built-in, Standard, and third-party clips use the same registry:

<ComponentPreview files="clip-registry-flow" size="sm" hideCode />

1. `clip.kind` selects a complete definition in the Clip registry; `schema` validates the spec before `resolve` runs
2. Core copies the `resolve` output into a JSON snapshot and validates it with the same definition's `shapeSchema`
3. `lower` produces a structured path; Core canonicalizes field order, precision, `-0`, path grammar, and explicit `fillRule`
4. The canonical path is deduplicated into `{ kind: 'clip', id, path }`; `GroupPrim.clipRef` stores only the id

Renderers, visual bounds, and hit testing never interpret custom kinds or receive Definitions. Core keeps only the complete `rect` definition by default; Standard supplies the other five official implementations through `@retikz/standard/clip`.

## Errors and Limits

| Case                                                                   | Result                                                                 |
| ---------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| Empty key                                                              | `defineClip` rejects immediately                                       |
| Duplicate kind                                                         | Registry reports a definition conflict and never overwrites            |
| Unknown `clip.kind`                                                    | Reports the kind and suggests `options.clips`                          |
| Definition / spec / shape kind mismatch                                | Fails as a provider contract violation before `lower`                  |
| Spec or shape fails its schema                                         | Reports the provider key, schema stage, and validation cause           |
| Callback returns a function, cycle, invalid path, or non-finite number | Fails loudly; layout probes cannot silently discard it                 |
| Recursion exceeds `maxClipDepth`                                       | Fails; resolve/lower share 32 edges by default, and active cycles fail |

A compound shape appends child commands in authored order and applies the outer `fillRule` to the single combined path. It is not a geometric intersection of children. Use nested `<Scope clip>` elements for intersection.

## API Reference

Except for `<Layout>` props from `@retikz/react`, import every public type, function, and constant below from `@retikz/core`.

### Export Overview

- definition: `defineClip`, `ClipDefinitionInput`, `ClipDefinition`
- contexts: `ClipResolveContext`, `ClipLowerContext`
- data and output: `ClipShape`, `SceneClipPath`, `ClipResource`
- registry: `BUILTIN_CLIPS`, `resolveClipRegistry`
- injection: `CompileOptions.clips`, `<Layout clips>`

### ClipDefinition

| Field         | Type                                                          | Required | Description                                         |
| ------------- | ------------------------------------------------------------- | -------- | --------------------------------------------------- |
| `kind`        | `TClip['kind'] & TShape['kind']`                              | Yes      | One registry key shared by the spec and shape       |
| `schema`      | `ZodType<TClip>`                                              | Yes      | Validates the complete JSON-safe spec               |
| `resolve`     | `(clip: TClip, context: ClipResolveContext) => TShape`        | Yes      | Resolves a JSON-safe `ClipShape` with the same kind |
| `shapeSchema` | `ZodType<TShape>`                                             | Yes      | Validates the complete shape snapshot               |
| `lower`       | `(shape: TShape, context: ClipLowerContext) => SceneClipPath` | Yes      | Lowers to a backend-neutral structured path         |

### SceneClipPath

| Field      | Type                       | Required | Description                                          |
| ---------- | -------------------------- | -------- | ---------------------------------------------------- |
| `commands` | `Array<PathCommand>`       | Yes      | Non-empty structured commands with a drawing segment |
| `fillRule` | `'nonzero'` \| `'evenodd'` | Yes      | Always explicit in canonical output                  |
