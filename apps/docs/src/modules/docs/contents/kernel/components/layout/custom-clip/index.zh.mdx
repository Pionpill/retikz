description: 用 ClipDefinition 解析业务裁剪，再用 ClipShapeDefinition 将自定义几何降低为统一 SceneClipPath，并通过 Core 或 Layout 注入两级 registry。

自定义裁剪分为两层：`ClipDefinition` 解释 `Scope.clip.kind`，`ClipShapeDefinition` 决定解析后的几何如何降低为路径。下面的圆角矩形同时自定义 operation 与 shape，最终仍由 SVG、Canvas 和 hit-test 消费同一份 `SceneClipPath`。

## 适用边界

两级契约分别解决「怎么描述裁剪」与「这种几何怎么变成裁剪路径」。只有一层需要扩展时，可以复用另一层已有 Definition。

| 需求                             | 选择                                                           |
| -------------------------------- | -------------------------------------------------------------- |
| 一次性矩形、圆或椭圆             | 直接写 Core 内置 clip spec                                     |
| 多边形、路径或多个区域组合       | 从 [裁剪扩展](/library/standard/extension/clip) 装配 operation |
| 新业务参数，但可复用已有几何     | 只定义 `ClipDefinition`，返回已注册的 shape kind               |
| 新的静态二维裁剪几何             | 定义 `ClipShapeDefinition`，降低为 `SceneClipPath`             |
| renderer 专属 mask / filter 行为 | 不属于 ClipShape；另建明确的后端能力                           |

IR 只保存带 `kind` 的 JSON-safe clip spec。operation 解析出的 `ClipShape` 也必须是 JSON-safe snapshot；Zod schema、callback、ReactNode、Canvas 对象和 SVG 字符串都不能进入 IR 或 Scene。

## 定义能力

operation kind 与 shape kind 是两条独立身份。一个 operation 可以复用已有 shape，一个 shape 也可以被多个 operation 复用。

```ts
const roundedRectClip = defineClip<RoundedRectClip, RoundedRectShape>({
  kind: 'rounded-rect',
  schema: roundedRectClipSchema,
  resolve: spec => ({ ...spec, kind: 'rounded-rect-path' }),
});

const roundedRectShape = defineClipShape<RoundedRectShape>({
  kind: 'rounded-rect-path',
  schema: roundedRectShapeSchema,
  lower: shape => ({
    commands: buildRoundedRectCommands(shape),
    fillRule: 'nonzero',
  }),
});
```

`resolve(spec, context)` 可用 `context.round(value)` 采用当前编译精度，也可用 `context.resolve(otherSpec)` 递归解析另一段 operation。`lower(shape, context)` 可用相同的 `round`，或用 `context.lower(otherShape)` 组合已注册 shape。

`lower` 必须返回至少含一个绘制段的结构化路径。Core 不自动闭合开放路径，也不接受 raw SVG `d`、Canvas callback 或非有限数值。

## 注入宿主

直接调用 Core 时，分别注入两个 Definition 数组：

```ts
const { scene } = compileToScene(ir, {
  clips: [roundedRectClip],
  clipShapes: [roundedRectShape],
});
```

React `<Layout>` 转交相同的 Core options，不建立 adapter 私有 registry：

```tsx
<Layout clips={[roundedRectClip]} clipShapes={[roundedRectShape]}>
  <Scope clip={{ kind: 'rounded-rect', x: -150, y: -72, width: 300, height: 144, radius: 36 }}>
    {/* clipped children */}
  </Scope>
</Layout>
```

通过 provider graph 装配时，operation provider 应把它可能输出的非内置 shape 声明为 `clipShape` 静态依赖。缺少依赖会在 maker 执行前失败；显式 `clips` / `clipShapes` 仍作为最终 Definition 通道参与同 key 冲突检查。

## 执行机制

两级 registry 各自完成 lookup 与 schema 校验，最后在 Core 内收敛为 canonical path。内置与自定义项走完全相同的路径。

<ComponentPreview files="clip-registry-flow" size="sm" hideCode />

1. `clip.kind` 在 Clip registry 中找到 operation，校验 spec 后调用 `resolve`
2. 返回值复制为 JSON snapshot，再按 `ClipShape.kind` 查询 ClipShape registry
3. shape schema 通过后调用 `lower`，Core 规范字段顺序、精度、`-0`、path grammar 与显式 `fillRule`
4. canonical path 去重后写入 `{ kind: 'clip', id, path }`，`GroupPrim.clipRef` 只保存 id

renderer、visual bounds 和 hit-test 不再解释自定义 kind，也不接收 Definition。SVG 始终生成一个 `<path>`；Canvas 重放相同 commands 与 fill rule。

当前 Core operation 内置集合为 `rect`、`circle`、`ellipse`；Standard 提供 `polygon`、`path`、`compound` operation。对应六种 shape lowerer 当前都通过 Core 的 `BUILTIN_CLIP_SHAPES` 注册，第三方 shape 与它们共用同一 registry。

## 错误与限制

| 情况                                           | 结果                                                                      |
| ---------------------------------------------- | ------------------------------------------------------------------------- |
| 空字符串 key                                   | `defineClip` / `defineClipShape` 立即拒绝                                 |
| 同一 capability 内重复 key                     | registry 报 definition conflict，不覆盖已有项                             |
| 未注册的 `clip.kind`                           | 报 operation kind，并提示通过 `options.clips` 注入                        |
| operation 返回未注册的 shape kind              | 报 shape kind，并提示通过 `options.clipShapes` 注入                       |
| spec 或 shape 不符合各自 schema                | 报对应 capability、provider key 与校验 cause                              |
| callback 输出函数、cycle、非法 path 或非有限值 | 作为 provider contract violation 失败，不被 layout probe 静默吞掉         |
| operation / shape 递归超过 `maxClipDepth`      | 失败；默认共享 32 条 resolve/lower 边预算，active object cycle 也立即失败 |

复合 shape 将 child commands 按 authored order 累积成一个 path，并使用外层 `fillRule`；它不是逐 child 的几何交集。需要交集时使用嵌套 `<Scope clip>`。

## API 参考

除 `<Layout>` props 来自 `@retikz/react` 外，以下公开类型、函数和常量均从 `@retikz/core` 导入。

### 导出概览

- operation：`defineClip`、`ClipDefinitionInput`、`ClipDefinition`、`ClipResolveContext`
- shape：`defineClipShape`、`ClipShapeDefinitionInput`、`ClipShapeDefinition`、`AnyClipShapeDefinition`、`ClipShapeLowerContext`
- 输出：`SceneClipPath`、`ClipResource`
- registry：`BUILTIN_CLIPS`、`BUILTIN_CLIP_SHAPES`、`resolveClipRegistry`、`resolveClipShapeRegistry`
- 注入：`CompileOptions.clips`、`CompileOptions.clipShapes`、`<Layout clips>`、`<Layout clipShapes>`

### ClipDefinition

| 字段      | 类型                                                   | 必填 | 描述                                                   |
| --------- | ------------------------------------------------------ | ---- | ------------------------------------------------------ |
| `kind`    | `TClip['kind']`                                        | 是   | operation registry key，必须与输入 `clip.kind` 一致    |
| `schema`  | `ZodType<TClip>`                                       | 是   | 校验完整 JSON-safe spec                                |
| `resolve` | `(clip: TClip, context: ClipResolveContext) => TShape` | 是   | 返回开放 `ClipShape`；其 kind 可与 operation kind 不同 |

### ClipShapeDefinition

`defineClipShape` 返回精确的 `ClipShapeDefinition<TShape>`，因此 `schema` 与 `lower` 始终关联同一种 shape。`CompileOptions.clipShapes` 和 `<Layout clipShapes>` 在异构 registry 边界接收擦除后的 `AnyClipShapeDefinition`；通常直接传入 `defineClipShape` 的返回值，无需手动转换。

| 字段     | 类型                                                               | 必填 | 描述                                                   |
| -------- | ------------------------------------------------------------------ | ---- | ------------------------------------------------------ |
| `kind`   | `TShape['kind']`                                                   | 是   | shape registry key，必须与 shape snapshot 的 kind 一致 |
| `schema` | `ZodType<TShape>`                                                  | 是   | 校验完整 JSON-safe shape                               |
| `lower`  | `(shape: TShape, context: ClipShapeLowerContext) => SceneClipPath` | 是   | 降低为后端无关结构化路径                               |

### SceneClipPath

| 字段       | 类型                       | 必填 | 描述                                                   |
| ---------- | -------------------------- | ---- | ------------------------------------------------------ |
| `commands` | `Array<PathCommand>`       | 是   | 非空、有绘制段的结构化命令；合法开放路径保持开放       |
| `fillRule` | `'nonzero'` \| `'evenodd'` | 是   | canonical 输出始终显式存在；输入缺省时物化为 `nonzero` |
