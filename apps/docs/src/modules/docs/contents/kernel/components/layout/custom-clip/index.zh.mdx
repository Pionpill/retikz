`ClipDefinition` 同时拥有裁剪输入与几何 lowering。下面的圆角矩形只注册一个 definition，SVG、Canvas、visual bounds 与 hit-test 最终都消费同一份 `SceneClipPath`。

## 适用边界

| 需求                             | 选择                                                            |
| -------------------------------- | --------------------------------------------------------------- |
| 一次性矩形                       | 直接写 Core 内置 `rect` clip spec                               |
| 圆、椭圆、多边形、路径或组合区域 | 从 [裁剪扩展](/library/standard/extension/clip) 注入 Definition |
| 新的静态二维裁剪                 | 定义一个完整 `ClipDefinition` 并降低为 `SceneClipPath`          |
| renderer 专属 mask / filter 行为 | 不属于 Clip；另建明确的后端能力                                 |

IR 只保存带 `kind` 的 JSON-safe clip spec。`resolve` 产出的 `ClipShape` 也是 JSON-safe snapshot；Zod schema、callback、ReactNode、Canvas 对象和 SVG 字符串都不能进入 IR 或 Scene。

## 定义能力

一个 definition 使用同一个 `kind` 绑定 spec schema、shape schema、解析与 lowering：

```ts
const roundedRectClip = defineClip<RoundedRectClip, RoundedRectClip>({
  kind: 'rounded-rect',
  schema: roundedRectClipSchema,
  resolve: spec => spec,
  shapeSchema: roundedRectClipSchema,
  lower: shape => ({
    commands: buildRoundedRectCommands(shape),
    fillRule: 'nonzero',
  }),
});
```

`resolve(spec, context)` 可以用 `context.round(value)` 采用当前编译精度，也可以用 `context.resolve(otherSpec)` 递归解析另一段 clip。`lower(shape, context)` 可以使用相同的 `round`，或通过 `context.lower(otherShape)` 组合当前 registry 中已注册的 shape。

definition、spec schema 结果与 shape schema 结果的 `kind` 必须一致。若多个 kind 需要复用几何，可以共享普通 helper，但每个可独立装配的裁剪仍拥有自己的完整 definition。

`lower` 必须返回至少含一个绘制段的结构化路径。Core 不自动闭合开放路径，也不接受 raw SVG `d`、Canvas callback 或非有限数值。

## 注入宿主

直接调用 Core 时只注入 `clips`：

```ts
const { scene } = compileToScene(ir, {
  clips: [roundedRectClip],
});
```

React `<Layout>` 转交同一个 Core option，不建立 adapter 私有 registry：

```tsx
<Layout clips={[roundedRectClip]}>
  <Scope clip={{ kind: 'rounded-rect', x: -150, y: -72, width: 300, height: 144, radius: 36 }}>
    {/* clipped children */}
  </Scope>
</Layout>
```

通过 provider graph 装配时，一个 `{ capability: 'clip', name: kind }` provider 直接创建完整 definition。显式 `clips` 仍作为最终 Definition 通道参与同 key 冲突检查。

## 执行机制

内置、Standard 与第三方裁剪经过同一个 registry：

<ComponentPreview files="clip-registry-flow" size="sm" hideCode />

1. `clip.kind` 在 Clip registry 中找到完整 definition，`schema` 校验 spec 后调用 `resolve`
2. `resolve` 输出复制为 JSON snapshot，再由同一 definition 的 `shapeSchema` 校验
3. `lower` 产出结构化路径，Core 规范字段顺序、精度、`-0`、path grammar 与显式 `fillRule`
4. canonical path 去重后写入 `{ kind: 'clip', id, path }`，`GroupPrim.clipRef` 只保存 id

renderer、visual bounds 和 hit-test 不解释自定义 kind，也不接收 Definition。Core 默认只保留完整 `rect` definition；Standard 从 `@retikz/standard/clip` 提供其余五种官方实现。

## 错误与限制

| 情况                                           | 结果                                                                  |
| ---------------------------------------------- | --------------------------------------------------------------------- |
| 空字符串 key                                   | `defineClip` 立即拒绝                                                 |
| 重复 kind                                      | registry 报 definition conflict，不覆盖已有项                         |
| 未注册的 `clip.kind`                           | 报 kind，并提示通过 `options.clips` 注入                              |
| definition / spec / shape kind 不一致          | 在 `lower` 前作为 provider contract violation 失败                    |
| spec 或 shape 不符合 schema                    | 报 provider key、对应 schema 阶段与校验 cause                         |
| callback 输出函数、cycle、非法 path 或非有限值 | fail-loud，不被 layout probe 静默吞掉                                 |
| 递归超过 `maxClipDepth`                        | 失败；默认共享 32 条 resolve/lower 边预算，active object cycle 也失败 |

复合 shape 将 child commands 按 authored order 累积成一个 path，并使用外层 `fillRule`；它不是逐 child 的几何交集。需要交集时使用嵌套 `<Scope clip>`。

## API 参考

除 `<Layout>` props 来自 `@retikz/react` 外，以下公开类型、函数和常量均从 `@retikz/core` 导入。

### 导出概览

- definition：`defineClip`、`ClipDefinitionInput`、`ClipDefinition`
- context：`ClipResolveContext`、`ClipLowerContext`
- 数据与输出：`ClipShape`、`SceneClipPath`、`ClipResource`
- registry：`BUILTIN_CLIPS`、`resolveClipRegistry`
- 注入：`CompileOptions.clips`、`<Layout clips>`

### ClipDefinition

| 字段          | 类型                                                          | 必填 | 描述                                          |
| ------------- | ------------------------------------------------------------- | ---- | --------------------------------------------- |
| `kind`        | `TClip['kind'] & TShape['kind']`                              | 是   | 唯一 registry key，与 spec 和 shape kind 一致 |
| `schema`      | `ZodType<TClip>`                                              | 是   | 校验完整 JSON-safe spec                       |
| `resolve`     | `(clip: TClip, context: ClipResolveContext) => TShape`        | 是   | 解析为同 kind 的 JSON-safe `ClipShape`        |
| `shapeSchema` | `ZodType<TShape>`                                             | 是   | 校验完整 shape snapshot                       |
| `lower`       | `(shape: TShape, context: ClipLowerContext) => SceneClipPath` | 是   | 降低为后端无关结构化路径                      |

### SceneClipPath

| 字段       | 类型                       | 必填 | 描述                                             |
| ---------- | -------------------------- | ---- | ------------------------------------------------ |
| `commands` | `Array<PathCommand>`       | 是   | 非空、有绘制段的结构化命令；合法开放路径保持开放 |
| `fillRule` | `'nonzero'` \| `'evenodd'` | 是   | canonical 输出始终显式存在                       |
