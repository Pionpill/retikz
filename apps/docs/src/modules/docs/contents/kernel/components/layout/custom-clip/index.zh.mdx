当业务需要可复用的命名裁剪原语时，用 `ClipDefinition` 定义它，再通过 `CompileOptions.clips` 或 `<Layout clips>` 注入。下面的 `rounded-rect` 从 Definition、注册到 `<Scope clip>` 构成一条完整可运行链路。

## 适用边界

自定义 clip 解决「现有 `clip.kind` 无法表达业务词汇」的问题，不是所有裁剪的默认写法。

| 需求                             | 选择                                                                |
| -------------------------------- | ------------------------------------------------------------------- |
| 一次性矩形、圆或椭圆             | 直接写 Core 内置 clip spec                                          |
| 多边形或路径裁剪                 | 从 [裁剪扩展](/library/standard/extension/clip) 装配对应 Definition |
| 多个区域组合                     | 从 [裁剪扩展](/library/standard/extension/clip) 装配 `compound`     |
| 跨图复用的业务裁剪原语           | 注册自定义 `ClipDefinition`                                         |
| renderer 专属 mask / filter 行为 | 不属于 Clip Registry                                                |

IR 只保存带 `kind` 的 JSON-safe spec；函数、Zod schema 与缓存都留在宿主注入的 Definition 中。自定义 provider 的输出必须是 Scene 已支持的 clip shape，不能借此创建平行渲染协议。

## 定义能力

`kind` 是稳定 registry key，`schema` 校验完整 spec，`resolve` 把合法输入收敛为内置 `ClipShape`。完整圆角路径命令可在上方 demo 的源码视图中复制。

```ts
const roundedRectClip = defineClip({
  kind: 'rounded-rect',
  schema: roundedRectClipSchema,
  resolve: spec => ({
    kind: 'path',
    commands: buildRoundedRectCommands(spec),
  }),
});
```

`resolve(spec, context)` 还可使用：

- `context.round(value)`：按当前编译精度稳定舍入
- `context.resolve(otherSpec)`：让组合 provider 重新走同一 registry 解析另一段 clip spec

## 注入宿主

Core 与 React 只是两个注入入口，消费的是同一份 Definition：

```ts
const { scene } = compileToScene(ir, {
  clips: [roundedRectClip],
});
```

```tsx
<Layout clips={[roundedRectClip]}>
  <Scope
    clip={{
      kind: 'rounded-rect',
      x: -150,
      y: -72,
      width: 300,
      height: 144,
      radius: 36,
    }}
  >
    {/* clipped children */}
  </Scope>
</Layout>
```

`<Layout>` 只把 `clips` 转交给 Core compile options；它不在 React adapter 内维护另一份自定义 clip 表。

## 执行机制

内置与自定义 Definition 先合并为一个 registry，之后都按 `clip.kind` 查找、校验和解析。Scene 与 renderer 无需知道 Definition 来自内置包还是宿主。

<ComponentPreview files="clip-registry-flow" size="sm" hideCode />

装配 `CompoundClipDefinition` 后，`compound.children` 也通过 `context.resolve` 回到这条路径，因此一个 compound clip 可以混合 Core 内置、其他 Standard 或自定义 kind。解析后的 shape 会去重并注册成稳定 `clipRef`，由 Scope 的 `GroupPrim` 引用。

## 错误与限制

| 情况                                         | 结果                                                     |
| -------------------------------------------- | -------------------------------------------------------- |
| 空字符串 key                                 | Definition / registry 立即拒绝                           |
| 与已注册的 Core、Standard 或自定义 kind 重名 | 注册时报 duplicate clip registration                     |
| 自定义数组内重复 key                         | 注册时报同样的 duplicate 错误                            |
| 未注册的 `clip.kind`                         | 编译报错，并提示通过 `options.clips` 注入                |
| spec 不符合 `schema`                         | 编译报错，保留 provider key、IR path 与 Zod cause        |
| `resolve` 返回非法 shape                     | 后续 Scene 契约无法成立；Definition 作者必须返回合法形状 |

自定义 clip 的参数必须 JSON 可序列化。不要把函数、ReactNode、class 实例或 renderer 对象放进 spec。

## API 参考

除单独标注的 React 注入 prop 外，本节类型、函数与常量均从 `@retikz/core` 导入。

### 导出概览

- `defineClip<TSpec>(definition)`：定义自定义 clip，校验 `kind` 非空，并保留具体 spec 的类型推断
- `ClipSpecLike`：自定义 clip spec 的最小形态，只要求提供字符串 `kind`
- `ClipDefinitionInput<TSpec>`：Definition 作者侧的泛型输入契约，让 `schema` 与 `resolve` 使用同一种 spec
- `ClipDefinition`：registry 存储和消费的统一 Definition 形态，具体 spec 类型已擦除
- `ClipResolveContext`：传给 `resolve` 的运行时上下文，提供统一精度取整和递归 clip 解析
- `BUILTIN_CLIPS`：Core 自带的三项只读 Definition 集合，既可遍历，也可通过 `.rect` 等名称索引
- `BuiltinClipProviderName`：全部内置 clip key 的类型联合
- `resolveClipRegistry(clips?)`：合并内置与自定义 Definition，并统一检查空 key 和重复注册；普通使用无需直接调用
- `CompileOptions.clips`：从 Core 编译入口注入自定义 Definition
- `<Layout clips>`（`@retikz/react`）：从 React 宿主注入同一份 Definition

### ClipDefinition

`ClipDefinitionInput<TSpec>` 是作者侧的强类型输入；`defineClip` 返回的 `ClipDefinition` 是 registry 使用的统一形态。两者拥有相同字段：

| 字段      | 类型                                                      | 必填 | 描述                                                              |
| --------- | --------------------------------------------------------- | ---- | ----------------------------------------------------------------- |
| `kind`    | `TSpec['kind']`                                           | 是   | 非空 registry key，必须与 IR 中的 `clip.kind` 一致                |
| `schema`  | `ZodType<TSpec>`                                          | 是   | 校验完整的 JSON-safe spec，并为 `resolve` 提供合法输入            |
| `resolve` | `(spec: TSpec, context: ClipResolveContext) => ClipShape` | 是   | 把合法 spec 收敛为 Scene 已支持的裁剪形状，不得输出 renderer 对象 |

### BUILTIN_CLIPS

`BUILTIN_CLIPS` 不是字符串枚举，而是带名称索引的只读 `ClipDefinition` 数组。可以遍历全部 Definition，也可以用 `BUILTIN_CLIPS.rect` 直接取得某一项；IR 中仍写对应的 `kind` 字符串。

| 名称索引                | IR `kind` | spec 字段                   | 含义             |
| ----------------------- | --------- | --------------------------- | ---------------- |
| `BUILTIN_CLIPS.rect`    | `rect`    | `x`, `y`, `width`, `height` | 轴对齐矩形裁剪区 |
| `BUILTIN_CLIPS.circle`  | `circle`  | `cx`, `cy`, `r`             | 圆形裁剪区       |
| `BUILTIN_CLIPS.ellipse` | `ellipse` | `cx`, `cy`, `rx`, `ry`      | 椭圆裁剪区       |
