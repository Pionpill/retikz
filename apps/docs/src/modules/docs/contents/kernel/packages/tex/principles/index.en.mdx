`@retikz/tex` does not hand MathJax or SVG to a renderer. It first lowers a formula into glyph paths and metrics, then Core lays out and renders those paths as ordinary Scene paths. Core therefore does not depend on MathJax, and applications can replace the built-in engine.

## Implementation principles

### Why MathJax is built in

MathJax is selected here because it typesets TeX as SVG geometry instead of leaving a formula as host DOM text. The built-in engine uses MathJax's SVG output jax with `fontCache: 'none'`, so glyphs are inlined as paths in the returned SVG; the Tex package can then turn those outlines into renderer-neutral path data.

MathJax also provides package-composed TeX syntax, which maps directly to the public `profile` and `extensions` configuration. `mathjax-full` is an optional peer loaded through dynamic imports, so neither Core nor a renderer depends on or initializes it when formulas are unused.

This does not lock Retikz to MathJax: it is the built-in engine. Another engine can reuse the same SVG lowering path when it synchronously returns the SVG subset supported by this package.

### From TeX to a Scene primitive

The figure follows one conversion from “Core entry → Tex lowering → Core output.” Tex does not send SVG directly to a renderer: it translates SVG geometry into Core `PathCommand` values, then returns paths and formula metrics to Core:

<ComponentPreview files="tex-conversion-flow" size="sm" hideCode />

The figure connects adjacent stages in one layout row directly. Connections across layout rows—especially wider spans—use a three-leg `|-|` route so the main flow stays legible without crossing intervening content.

1. After the host injects `lowerTex`, Core recognizes `$...$` / `$$...$$` as math runs; without it, strings remain ordinary text
2. Core passes the TeX source, `displayMode`, font size, and color to `LowerTex`, then uses returned `height` / `depth` in inline layout
3. The built-in `MathJaxSvgEngine` produces an SVG string with inline glyph paths
4. Tex parses the supported SVG nodes, path data, paint, and transforms into structured `PathCommand` values and `LoweredTex.paths`
5. Core validates and freezes the lowering result, then includes its metrics in baseline layout; unsupported nodes, styles, or transforms reject the complete formula instead of returning partial paths
6. Core emits every `LoweredTexPath` as a standard `PathPrim`, positioned by a baseline-translated `GroupPrim`; renderers then consume ordinary Scene primitives and need no TeX, MathJax, or SVG knowledge

### Replaceable engine boundary

Core depends only on the synchronous `LowerTex` contract:

```ts
type LowerTex = (
  content: { tex: string; displayMode?: boolean },
  style: { fontSize: number; color?: string },
) => LoweredTex | null;
```

`LoweredTex` contains paths in draw order plus formula `width`, `height`, and `depth`. Each path carries fill / stroke, opacity, and path commands, so Core can continue layout and rendering. The minimal engine contract consumed by Tex is synchronous `MathJaxSvgEngine.convert(tex, { display }) => string`; a custom engine must return the SVG subset supported by this package.

This also keeps `mathjax-full` optional, so Core users who do not use formulas do not take on MathJax bundle size.

## Caching, failures, and retries

This figure combines the lowering cache with the React lifecycle for sharing engines, clearing an old lowerer, and discarding stale results:

<ComponentPreview files="tex-cache-lifecycle" size="xl" hideCode />

`createLowerTex` maintains an in-memory cache per lowerer. Its key contains TeX source, inline / display mode, font size, and host color. Successful results and deterministic MathJax / SVG failures are cached. An exception from `engine.convert` is transient and not cached, so the next call can retry. Every public failure calls the latest `onDiagnostic`.

`useLowerTex` shares an engine by effective extension set. A configuration change immediately enters `loading` and clears the old lowerer; an async result for an unmounted or stale request cannot write back. Initialization failure returns `error` and removes the failed shared item, allowing a later mount to retry.

| Scenario                                      | Observable result                                                                                                          |
| --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| String formula without an injected lowerer    | `$...$` / `$$...$$` remains ordinary text and does not enter formula parsing                                               |
| Explicit math run without an injected lowerer | The segment is skipped and reports `TEX_LOWERER_MISSING`; text runs on the same line continue rendering                    |
| MathJax returns an error node                 | The lowerer returns `null`, reports `mathjax-error`, then Core reports `TEX_INVALID`; this deterministic failure is cached |
| SVG is unsupported or malformed               | The full formula is rejected and reports `unsupported-svg` or `malformed-svg`, then Core `TEX_INVALID`; it is cached       |
| `engine.convert` throws                       | The lowerer returns `null`, reports `engine-error`, then Core `TEX_INVALID`; this transient failure is not cached          |
| `mathjax-full` is missing or startup fails    | The factory Promise rejects with install or startup details; React returns `error` and a later mount may retry             |

## API reference

| API                       | Description                                                                                                                                    |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `createMathJaxLowerTex`   | `(options?: MathJaxLowerTexOptions) => Promise<LowerTex>`. Creates the built-in MathJax engine and Core lowerer in one step                    |
| `createMathJaxEngine`     | `(options?: MathJaxEngineOptions) => Promise<MathJaxSvgEngine>`. Dynamically loads `mathjax-full` and creates a synchronous engine             |
| `createLowerTex`          | `(engine: MathJaxSvgEngine, options?: LowerTexOptions) => LowerTex`. Adapts a custom engine and owns SVG parsing, caching, diagnostics         |
| `MathJaxSvgEngine`        | `.convert(tex, { display }) => string`. A custom engine synchronously returns the supported SVG subset                                         |
| `LowerTexOptions`         | `.onDiagnostic?: (diagnostic: TexLoweringDiagnostic) => void`. Runs for every public lowering failure, including cached deterministic failures |
| `TexLoweringDiagnostic`   | `.kind` is `engine-error`, `mathjax-error`, `unsupported-svg`, or `malformed-svg`, with failed `source` and a diagnostic `message`             |
| `LowerTex`                | Core's synchronous injection point; returns `null` when lowering fails                                                                         |
| `LoweredTex`              | Paths in draw order plus `width`, `height`, and `depth`                                                                                        |
| `CompileOptions.lowerTex` | Formula capability injection point in the Vanilla / Core compile context                                                                       |
