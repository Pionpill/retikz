节点声明同时包含正文、形状、定位和样式意图。`resolveNode` 先确定这些意图，`compileNode` 再完成布局与绘制。Reconciler 提供测量、引用、资源和提案上下文，并把结果接回名称环境与子树输出。

## 整体流程

CanonicalNode 保存有效配置与能力绑定；CompiledNodeLayout 保存测量和定位结果；CompiledNode 将当前 Shape / Boundary 绑定与 layout、emit 产物关联。查询几何按需组合，绘制消费 emit.overall，不需要复制一份可持久化的“完整节点模型”。

## 解析后还剩下什么

语义解析已完成继承、默认、颜色与阴影展开，并把 Shape、Boundary 和参数绑定到定义。节点 scale 也已折入相应尺寸、字号与参数；编译不再重复乘一次。位置引用仍可能依赖当前几何，文字尺寸也取决于测量服务，因此 Canonical 不等于最终布局。

下面是贯穿示例中 A 的完整声明片段。普通文字 A 能放入给定最小尺寸；最终视觉矩形为 60 × 40，中心 [0, 0]，默认无额外旋转。

```ts
const node = {
  type: 'node',
  id: 'A',
  position: [0, 0],
  text: 'A',
  layout: { minimumSize: { width: 60, height: 40 }, padding: 0, margin: 0 },
} satisfies import('@retikz/core').IRNode;
```

## 内容测量与形状约束

Core 调用注入的 measureText，不读取 DOM。宽度、高度以及 ascent / descent 由宿主提供；缺少上下基线指标时，各取高度的一半。Reconciler 未收到宿主测量器时使用近似估算，同次执行的测量复用也由它负责。

普通文本保留显式换行，按预算折成物理行。混排片段在同一行共享基线；不可拆的公式超宽时可能溢出。正文盒加入 padding 后，交给 Shape 的 computeCircumscribedGeometry；最小尺寸和固定视觉宽度再参与最终尺寸选择。

下面三个节点使用同一句正文：收紧文字宽度会增加行数；增加外侧标签则不改变主体尺寸。

<ComponentPreview files="layout-example" size="md" hideCode type="illustration" />

| 约束         | 所属范围                             |
| ------------ | ------------------------------------ |
| maxTextWidth | 正文折行预算，不保证形状恰好等宽     |
| minimumSize  | 视觉外框下限，不压缩正文             |
| width        | 固定视觉宽度，仍放不下时失败         |
| 父级宽度提案 | 布局占位预算，需要考虑 margin 与旋转 |

`measureNodeBody` 在正文宽度与自定义形状尺寸之间执行有界反馈。父级提案不是保证能满足的硬裁剪；父级必须消费实际返回的布局贡献。固定 width 的语义与提案不同，不能用二者互相替换。

## 正文盒、视觉外框与布局占位

以下图为例，正文 40 × 24、padding 8 先得到 56 × 40；minimumSize 80 × 48 再扩大视觉外框；margin 6 使布局占位成为 92 × 60。margin 不会把可见矩形也画大，标签也不反向撑大形状。

<ComponentPreview files="layout-boxes" size="lg" hideCode type="illustration" />

不对称 padding 和形状 offset 可能使正文中心与视觉外框中心不同。布局分别保存它们；自身锚点定位还需要先做临时布局，求出自身锚点后再整体平移。

## 基线、标签与连接几何

行槽必须容纳实际 ascent + descent。行高 24、ascent 14、descent 4 时，上下各留 3，基线距槽顶 17。绘制沿用布局确定的基线，不重新猜测文字中心。

<ComponentPreview files="layout-baseline" size="lg" hideCode type="illustration" />

标签独立测量，依靠形状上的附着点和 direction / distance 等配置放置；最终视框包含标签，但连线不会自动连到标签边缘。Shape 是视觉轮廓，Boundary 是自动连接所用表面，二者可分别选择。

<ComponentPreview files="layout-boundaries" size="lg" hideCode type="illustration" />

标准方位与数字角度锚点使用连接面及 margin；形状专属锚点和边上比例点使用视觉形状。Reconciler 管理 boundaryStore，为当前绑定关联查询状态；Core 的节点阶段不创建跨节点 store。

## 图元与查询几何的交接

emitNode 分别处理 shape、content、label，并组装局部图元与边界贡献。文字节点或有旋转的节点使用 GroupPrimitive 统一承载元数据和变换；不能假定一个 Node 恰好对应一个矩形图元。

Reconciler 用 projectNodeGeometry 组合当前能力绑定与布局，按 Scope 变换投影后发布到名称环境；Scene 中的图元仍保留所属空间。prepared 可以提供完整或局部 layout / emit 产物，Core 只补缺项，跨次复用裁决由 Reconciler 完成。
