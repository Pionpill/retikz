`@retikz/tex` 是可选的公式能力包。你仍然在 `<Node>` 等文本入口中写 `$...$`、`$$...$$` 或显式 math run；编译时注入的 `lowerTex` 会把公式转换成 `@retikz/core` 能消费的字形路径。

它不提供新的公式组件，也不拥有文本 IR 或 renderer。MathJax 接入、SVG 字形解析、lowering 缓存和 React 初始化 hook 属于本包；文本布局与 Scene 契约属于 `@retikz/core`，最终路径执行属于 `@retikz/render`。

## 安装与使用

`mathjax-full` 是 optional peer dependency，由应用安装并控制版本：

```bash
pnpm add @retikz/tex mathjax-full
```

React 应用优先使用 `useLowerTex`。hook 异步启动共享的 MathJax engine，准备完成后返回可注入 `<Layout lowerTex>` 的同步 lowerer：

```tsx
import { Layout, Node } from '@retikz/react';
import { useLowerTex } from '@retikz/tex/react';

const Diagram = () => {
  const lowerTex = useLowerTex({ profile: 'math' });

  return (
    <Layout lowerTex={lowerTex}>
      <Node position={[0, 0]}>{'$\\frac{a}{b} = c$'}</Node>
    </Layout>
  );
};
```

`useLowerTex` 在 engine 就绪前返回 `undefined`，随后触发重新编译。React 通过 `<Layout lowerTex>` 注入；Vanilla 使用 `compile.lowerTex`。

## 为什么需要 @retikz/tex

### 让 Core 保持引擎无关

公式排版需要 MathJax 这类体积较大、启动方式也不同于普通文本测量的引擎。如果 Core 直接依赖 MathJax，所有用户和 renderer 都会被迫承担同一依赖与生命周期。

因此 Core 只定义 `LowerTex`：输入 TeX source、inline/display 模式和字号，输出普通的字形路径、宽高与基线深度。`@retikz/tex` 实现这个注入点，但只依赖最小的 `MathJaxSvgEngine.convert` 抽象；应用也可以提供满足该抽象的其它 engine。

### Scene 之后不再依赖 MathJax

| 阶段             | 所有者           | 产物                                             |
| ---------------- | ---------------- | ------------------------------------------------ |
| 公式写法         | Core 文本 IR     | 字符串 sugar 或 `{ tex, displayMode }` math run  |
| 公式降解         | `@retikz/tex`    | 带独立 fill / stroke 的 glyph paths 与度量       |
| 文本布局与 Scene | `@retikz/core`   | 按基线排版的 `PathPrim` / `GroupPrim`            |
| 后端输出         | `@retikz/render` | SVG、Canvas 或其它共享同一 Scene 语义的 renderer |

公式在进入 Scene 前已经是 Core 路径图元，SVG 与 Canvas 不需要各自理解 LaTeX，也不会出现一套 MathJax DOM 与一套 Canvas 公式语义。

`$...$` 使用 inline 度量并贴合文字基线；`$$...$$` 使用 display 度量，让分式、求和与积分获得更舒展的上下空间。多行 LaTeX 环境仍然属于一个 Node，只有一个 bbox 和连接目标；启用 `shape` 后，容器继续使用 Node 的常规 padding 与边界计算。

## 语法 profile

默认 `base` 只启用 MathJax 基础语法；`math` 在此基础上加载常用数学扩展。也可以通过 `extensions` 从闭合集合中按需追加单项：

| 配置   | 包含内容                              | 适用场景                                  |
| ------ | ------------------------------------- | ----------------------------------------- |
| `base` | MathJax base                          | 普通运算、分式、根式与上下标              |
| `math` | <ApiValues name="MathJaxExtension" /> | AMS、命令定义、括号、消去、分情况、颜色等 |

profile 取值由 <ApiValues name="MathJaxProfile" /> 提供。`cases` 会自动补齐内部 `empheq` 依赖；内部依赖不进入公开 extension 集合。

`upgreek`、`unicode` 与 `extpfeil` 不在支持范围：前两者会生成文字原子，后者依赖 nested SVG 裁剪。parser 遇到 `<text>`、`<foreignObject>` 或 nested `<svg>` 时会拒绝整段公式，不返回缺字或未裁剪的部分结果。

## 文字与公式混排

最自然的数学叙述是文字夹公式。直接在字符串里混写即可，公式和普通文字会在同一行按基线对齐：

```tsx
<Node>{'当 $v = d/t$ 时，位移 $s = v t$'}</Node>
```

需要逐段颜色、透明度或文字字体时，使用显式 `runs`。text run 可设置 `fill`、`opacity` 与 `font`；math run 可设置 `fill`、`opacity` 与 `displayMode`：

```tsx
<Node
  text={[
    {
      runs: [{ tex: '\\sin\\alpha = \\frac{1}{2}', fill: 'red' }, { text: '（红线长度）' }],
    },
  ]}
/>
```

## 注入方式

### React 注入

`useLowerTex` 复用一次共享的 engine 初始化，并在组件卸载后避免写回状态。大多数 React 应用只需要在最外层 `<Layout>` 注入一次，子级文本都会复用同一个 compile capability。

### 手动创建

非 React 初始化流程可以直接使用一步工厂：

```ts
import { createMathJaxLowerTex } from '@retikz/tex';

const lowerTex = await createMathJaxLowerTex({
  profile: 'math',
  extensions: ['color'],
  onDiagnostic: diagnostic => console.warn(diagnostic),
});
```

需要自定义 engine 时，先实现 `MathJaxSvgEngine`，再调用 `createLowerTex(engine, options)`。自定义 engine 与内置 profile 都进入同一个 Core `LowerTex` consumer。

### Vanilla 注入

Vanilla 把同一个 lowerer 放在 `compile.lowerTex`；InputScene、Core IR 与 Scene 仍沿用各自原有入口：

```ts
import { node, renderToSvgString, scene } from '@retikz/vanilla';
import { createLowerTex, createMathJaxEngine } from '@retikz/tex';

const lowerTex = createLowerTex(await createMathJaxEngine());
const spec = scene({
  children: [node('eq', { position: [0, 0], text: '$\\frac{a}{b} = c$' })],
});

const svg = renderToSvgString(spec, { compile: { lowerTex } });
```

## 失败与性能边界

| 情况                            | 可观察行为                                                                    |
| ------------------------------- | ----------------------------------------------------------------------------- |
| string sugar 未注入 `lowerTex`  | `$...$` / `$$...$$` 完整保留为普通文字，不解析公式                            |
| 显式 math run 未注入 `lowerTex` | 跳过公式 segment，并发出 `TEX_LOWERER_MISSING`；同一行的 text run 继续渲染    |
| 分隔符未闭合                    | 从未闭合 `$` 开始按字面保留，并发出 `TEXT_TEX_PARSE_ERROR`                    |
| engine 输出无效公式或转换抛错   | lowerer 返回 `null`，细分 diagnostic；Core 跳过该公式并发出一次 `TEX_INVALID` |
| SVG 含不支持的 element / style  | 返回 `unsupported-svg`，不允许部分成功                                        |
| `mathjax-full` 初始化失败       | `useLowerTex` 保持 `undefined` 并发出 `engine-error`；清除缓存以便后续重试    |

`createLowerTex` 按 TeX source、display 模式、字号与宿主颜色缓存成功结果和确定失败；每次失败调用仍会把 diagnostic 交给最新 callback。engine 抛错视为瞬态，不缓存，因此下一次调用可以重试。这个缓存只覆盖 TeX → glyph 的纯转换，不缓存 Core IR、Scene、Node 布局或 renderer 输出。

## 语法

| 写法              | 含义                                                   |
| ----------------- | ------------------------------------------------------ |
| `$...$`           | 行内公式（inline 度量，贴文字基线）                    |
| `$$...$$`         | display 公式（block 度量；独占一个 Node 时为独立公式） |
| `\$`              | 字面美元符号，不作为分隔符                             |
| `{ runs: [...] }` | 显式 run 序列，可分别设置普通文字与公式段              |

## API 参考

| API                                  | 类型                                                                                                                             | 描述                                                                                                  |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `useLowerTex`（`@retikz/tex/react`） | `(options?: MathJaxLowerTexOptions) => LowerTex \| undefined`                                                                    | 按 canonical profile 共享 engine；配置切换期间返回 `undefined`                                        |
| `createMathJaxLowerTex`              | `(options?: MathJaxLowerTexOptions) => Promise<LowerTex>`                                                                        | 一步创建内置 MathJax engine 与 lowerer                                                                |
| `createMathJaxEngine`                | `(options?: MathJaxEngineOptions) => Promise<MathJaxSvgEngine>`                                                                  | 创建同步 SVG engine；默认使用 `base`                                                                  |
| `createLowerTex`                     | `(engine: MathJaxSvgEngine, options?: LowerTexOptions) => LowerTex`                                                              | 适配自定义 engine，并执行结果缓存与诊断                                                               |
| `MathJaxEngineOptions`               | `MathJaxEngineOptions`<br />- `profile?:` <ApiValues name="MathJaxProfile" /><br />- `extensions?: Array<MathJaxExtensionValue>` | engine 配置<br />- 内置语法集合，默认 `base`<br />- 从 <ApiValues name="MathJaxExtension" /> 追加扩展 |
| `LowerTexOptions`                    | `LowerTexOptions`<br />- `onDiagnostic?: (diagnostic: TexLoweringDiagnostic) => void`                                            | lowerer 配置<br />- 接收 `engine-error`、`mathjax-error`、`unsupported-svg` 或 `malformed-svg`        |
| `MathJaxSvgEngine`                   | `MathJaxSvgEngine`                                                                                                               | 本包消费的最小同步 engine 抽象                                                                        |
| `LowerTex`（`@retikz/core`）         | `LowerTex`                                                                                                                       | Core 注入点；返回 renderer-agnostic 多路径与度量，失败返回 `null`                                     |
