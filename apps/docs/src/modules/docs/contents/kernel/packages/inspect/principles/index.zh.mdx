title: 解析原理
description: 理解 Inspect 如何复用 Core 最终观测、隔离编译辅助 IR，并在同次提交中交付只读图层
---

Inspect 是附加给 Core 编译的一项可选 observer，而不是第二套绘图或布局系统。没有 registry、request 或匹配 owner 时，普通 Core 编译不会创建辅助片段，也不需要加载 Inspect。

## Inspect 与 Core 的协作

Core 负责正常绘制主图，并在最终 occurrence 产生后提供 Inspect 所需的观测事实；Inspect 负责选择这些事实、生成辅助 IR，再复用 Core 编译它。Core 不认识任何 Inspector Definition、registry 或辅助层配色。

| Core 提供的内容                               | Inspect 如何使用                                                           |
| --------------------------------------------- | -------------------------------------------------------------------------- |
| `CompileObservation.owner` 与 `occurrence`    | 让 request 精确匹配 path kind 或 composite 的最终实例                      |
| `CompileObservation.value`                    | 作为 `subjectSchema` 校验的最终产物，供 `inspect()` 读取                   |
| `CompileObservationContext.theme`             | 为辅助内容分配与当前 occurrence 一致的主题与语义颜色                       |
| `CompileObservationContext.compileFragment()` | 在当前 Theme、Scope 样式和 provider 环境中隔离编译 Inspector 返回的普通 IR |

因此，若自定义 owner 没有在 Core 中发布最终产物，Inspector 无法仅凭作者输入推断出可观测事实；它必须先获得对应的 Core observation 能力。

## 辅助内容何时绘制

辅助内容不写入 Core 的主图绘制阶段。它在同一次 observed compile 的 observer `complete` 阶段，基于已经捕获的最终 occurrence 另行编译：

<ComponentPreview files="inspect-compile-flow.zh" size="md" hideCode />

1. 宿主把 registry 与运行时选择交给可选 compile driver，driver 注册一个 Core observer
2. Core 编译主图时，observer 按 owner 与来源路径选择可能匹配的站点
3. 每个选中的 owner 产生最终结果后，Core 调用 `observe()`，保存最终产物与当前 occurrence 的上下文
4. `complete()` 解析选择、合并 options、校验 `subjectSchema`，再调用对应 Definition 的 `inspect()`
5. `inspect()` 返回的普通 `IRChild` 逐项传给 `compileFragment()` 隔离编译，得到 InspectionPlane；公开身份、元数据和动画语义不会进入辅助 Scene
6. Render 把 InspectionPlane 转成不可命中的只读图层，主图与辅助图层只在同一 revision 一起成功提交

没有匹配结果或 callback 返回空内容时，InspectionPlane 为 `null`。额外成本只来自被选中 owner 的观测、Inspector callback 与非空辅助片段编译。

## 运行时选择

request 不是持久化图形数据，而是决定哪些最终 occurrence 交给 Inspector 的运行时规则。它可以来自整张图、一个 authored 子树或当前实例：

| 结构                              | 含义                                                      |
| --------------------------------- | --------------------------------------------------------- |
| `InspectionSelectionRule` request | 以 `inspector`、`target`、`options` 选择 Inspector 与范围 |
| `InspectionSelectionRule` barrier | 在整图或 authored 子树阻止后代重新开启 Inspector          |
| scene target                      | 匹配整张图中属于指定 owner 的最终实例                     |
| subtree target                    | 匹配一个 authored Scope 下的最终实例                      |
| self target                       | 按来源或 occurrence index 匹配当前对象                    |

同一位置可以请求多个不同 Inspector。同一 Inspector 的稀疏 options 从整图到子树再到当前实例合并；普通 `false` 只关闭当前位置的一个 Inspector，barrier 则阻止后代重新开启任何 Inspector。

合并使用作者传入的原始配置，随后由唯一的 `optionsSchema` 补默认值，再交给 `resolveOptions` 展开简写。例如父级 `labels: true`、子级 `{}` 会继续显示标签；子级显式 `labels: false` 才会关闭。每条启用规则仍会在准入时校验，即使未匹配或随后被覆盖也不能携带非法选项。

直接调用 `StrokePathInspectOptionsSchema.parse({})` 会得到包含 `labels: false` 的完整默认快照；再把它作为子级配置时，`false` 就是显式覆盖。保存原始配置才能保留省略意图；保存 parse 结果则保存已物化的默认值。

## 结果与错误

| 字段                                  | 含义                                          |
| ------------------------------------- | --------------------------------------------- |
| `InspectionCompileResult.primary`     | 未被辅助内容修改的普通 Core 编译结果          |
| `InspectionCompileResult.inspection`  | 有序辅助平面；所有 callback 无输出时为 `null` |
| `InspectionCompileResult.diagnostics` | 隔离片段产生的结构化警告列表                  |

`RetikzInspectError.details.origin.stage` 标明失败发生在选择、最终产物校验、`inspect` callback、输出规范化、辅助片段编译或最终组装。重复 registry key、未注册 request、owner 不匹配以及 schema 失败都会终止该次检查编译，不会交付部分辅助结果。
