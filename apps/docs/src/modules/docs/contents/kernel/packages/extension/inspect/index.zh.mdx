`@retikz/inspect` 是可选开发工具包。它读取 Core 发布的最终 occurrence 与所属者产物，再把 Inspector 返回的普通 Core 子元素编译成只读辅助图层；选择规则只存在于运行时，不进入 IR、Scene 或快照。

```bash
pnpm add @retikz/inspect
```

```tsx
import { createDefaultInspectorRegistry, STROKE_PATH_INSPECTOR_KEY } from '@retikz/inspect';
import { InspectLayout, InspectPath } from '@retikz/inspect/react';
import { Step } from '@retikz/react';

const registry = createDefaultInspectorRegistry();

<InspectLayout registry={registry}>
  <InspectPath
    request={{
      inspector: STROKE_PATH_INSPECTOR_KEY,
      value: { controlPoints: true, labels: true },
    }}
  >
    <Step kind="move" to={[0, 0]} />
    <Step kind="cubic" control1={[20, -30]} control2={[80, 30]} to={[100, 0]} />
  </InspectPath>
</InspectLayout>;
```

## 适用边界

使用 Inspector 查看最终编译结果中的控制点、边界、间距、对齐参考线或领域诊断。它不改变布局求解、主 Scene 边界、资源、命中测试和动画，也不把开发期选择持久化。

Core 只提供领域中立的所属者产物、最终 occurrence 观测和隔离片段编译。具体观察什么、如何选择以及如何绘制，都由本包或第三方 Inspector Definition 拥有。

## 定义能力

第三方 Inspector 使用 `defineInspector()` 声明注册键、目标 owner、subject schema、选项 schema 与输出函数。内置 stroke Path Inspector 也经过同一入口，不存在内置白名单。

```ts
import { defineInspector } from '@retikz/inspect';

const inspector = defineInspector({
  namespace: 'acme',
  name: 'bounds',
  owner,
  subjectSchema,
  optionsInputSchema,
  optionsSchema,
  inspect: (subject, context) => buildAuxiliaryChildren(subject, context.appearance),
});
```

`namespace + name` 在一个注册表中必须唯一；同一 owner 可以注册多个用途不同的 Inspector。subject 与选项都必须通过 schema，输出只能是普通 `IRChild` 或其只读数组。

## 注入宿主

根入口不加载 React、Vanilla 或 Render。按宿主显式导入子入口：

| 入口                      | 职责                                                             |
| ------------------------- | ---------------------------------------------------------------- |
| `@retikz/inspect`         | Definition、注册表、选择、诊断、编译驱动与内置 Path Inspector    |
| `@retikz/inspect/react`   | `InspectLayout`、`InspectPath`、`InspectScope` 与 React 编译驱动 |
| `@retikz/inspect/vanilla` | authoring 标记与 Vanilla 编译驱动                                |
| `@retikz/inspect/render`  | 把辅助平面一对一转换为普通只读图层                               |

Layout 布局使用 `@retikz/layout/inspect`、`@retikz/layout-react/inspect` 或 `@retikz/layout-vanilla/inspect`。这些入口显式依赖本包；Layout 根入口仍可在未安装 Inspector 时使用。

## 执行机制

1. 宿主收集运行时选择规则，并把 Inspector registry 交给可选编译驱动。
2. Core 只捕获被选择 owner 的最终产物，丢弃 probe 候选、失败分支和未采用 replay。
3. Inspect 按 occurrence 与 Inspector key 稳定排序，解析选项后调用 Definition。
4. 普通 IR 输出在当前主题、作用域样式和 provider 环境中隔离编译，并移除公共身份、元数据与动画语义。
5. Render 将结果作为 `pointer-events: none` 的只读图层提交；主图与辅助图层在同一 revision 成功或回滚。

## 错误与限制

- 重复注册键、无效 locator、越界 occurrence、owner 不匹配或 schema 失败会直接报错，不返回部分辅助结果。
- `barrier` 只能用于整图或 authored 子树，并阻止后代重新开启任何 Inspector。
- 贡献内部无法无歧义定位的嵌套 Scope 当前会明确拒绝；需要更精确的贡献内子树定位契约后才能支持。
- 普通 `compileToScene()` 不创建 Inspector session，也不产生额外辅助编译成本。

## API 参考

| 导出                                       | 职责                                          |
| ------------------------------------------ | --------------------------------------------- |
| `defineInspector()`、`InspectorDefinition` | 定义 owner、schema、选项合并和辅助输出        |
| `createInspectorRegistry()`                | 构造显式注册表并检查重复 key                  |
| `createDefaultInspectorRegistry()`         | 构造包含内置 stroke Path Inspector 的注册表   |
| `compileInspectionToScene()`               | 直接执行一次主图与辅助内容的原子编译          |
| `STROKE_PATH_INSPECTOR_KEY`                | 选择内置 stroke Path Inspector                |
| `InspectionSelection`                      | 描述 scene、subtree 或 self 的运行时规则      |
| `InspectionCompileResult`                  | 返回主编译结果、可选辅助平面与 Inspector 诊断 |
