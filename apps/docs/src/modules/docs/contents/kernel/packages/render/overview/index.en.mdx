> This is package documentation, not component docs; to draw, start from [Components](/kernel/components/layout).

This group covers how retikz actually paints a figure to the screen. Your figure is first compiled into a **renderer-agnostic Scene**, then handed to a backend: **SVG** emits a vector DOM where every primitive is a real, CSS-targetable element; **Canvas** paints the same Scene as a raster bitmap, suited to many primitives or frequent repaints. The backends share Scene semantics and align their output where each backend supports the required feature; check host capabilities and interaction needs before switching. **Hydration** is the mechanism both backends share: render statically first, then bind event handlers back to primitives by id on the client.

Import the `RenderMode` type from `@retikz/render/runtime` for backend selection. Both the Vanilla mount API and React Layout accept `svg` or `canvas` for `renderer`.

## Responsibilities

| Topic           | Responsibility                                                                               | Reach for it when                                                   |
| --------------- | -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| SVG             | Scene → vector DOM, or an SSR / build-time string                                            | The default: you want crisp vectors, CSS hit-testing, accessibility |
| Canvas          | Scene → raster bitmap, immediate-mode drawing + hit-testing                                  | Hundreds of primitives, frequent repaints, performance first        |
| Session commits | Prepare and commit Scenes and configuration in a Reconciler session                          | Stable host identity and incremental updates                        |
| Hydration       | Bind event handlers back to primitives by id after a static render (shared by both backends) | Adding click / hover interaction to a figure                        |

## Session commits

`createRenderTarget()` connects a Reconciler session to a renderer. Vanilla combines it with processing-result publication into one commit target: prepare the candidate frame and configuration, commit the host, then publish the session result. The first commit materializes a complete Scene. Changed compilation output produces `replaceScene`; a configuration-only update uses an empty-operation Patch and retains compilation output. Failed commits restore host and compilation state. Failed recovery puts the Reconciler session into the broken state, requiring disposal and recreation.

Final disposal performs reverse best-effort cleanup across hydration, animation, and the image loader. Once an SVG WAAPI binding or Canvas clock starts cleanup, public controls and event / visibility callbacks become inert immediately. Animations, observers, listeners, inline-style ownership, visibility listeners, and the clock are cleaned independently: successful items are not repeated, while failed items remain retryable by a later disposal call.

`InputRenderRuntimeConfig` is a closed transaction config. `handlerContributions` merge hydration handlers in registration order, `animation` controls playback, snapshots, and extension registries, `cachePolicy` preserves a hint for future layer invalidation optimization, and `canvas.width` / `canvas.height` declare Canvas CSS user-space dimensions. The SVG and Canvas renderers do not yet use `cachePolicy` to reuse layers. Render borrows the configuration without freezing caller-owned objects. It builds a separate ordered list only when handler registrations arrive out of order. Keep them and their members stable while the renderer uses them. For updates, supply new values rather than mutating data referenced by an earlier frame. Omitted Canvas dimensions derive from the committed Scene layout and are multiplied by the session-lifetime DPR. Size changes and bitmap painting commit atomically, while dirty reuse is allowed only when the target size is stable.

Import these session APIs from `@retikz/render/runtime`; they are not exported from the `@retikz/render` package root. A third-party backend uses `RendererFactory` to create a nominal SVG or Canvas renderer and declares `none`, `group`, or `entity` capability. The Render commit target validates Snapshot / Patch revisions and result consistency; invalid Patches are rejected. The current integration produces complete replacements for compilation changes. Backend capability declarations do not make the session generate fine-grained operations automatically.

### Scene snapshots

Render owns runtime Scene identities, topology, snapshots and Patch contracts. Import their types, including `SceneIdentity`, `SceneRuntimeSnapshot` and `ScenePatch`, from `@retikz/render/runtime`. Reconciler delivers the complete compilation result, provenance and candidate revision; the Render commit target uses them to build the rendering snapshot. Identity or topology construction failures are reported as `RetikzRenderError`.

A topology node’s sibling order comes from the final index in its `primitivePath`; the subtree root has the relative path `[]`. An update patch targets `subtree.root` without a separate `identity`. Move and remove operations still take an `identity`.

Static APIs consume a `Scene`. A custom renderer receives a `SceneRuntimeSnapshot` and returns it as `read().snapshot` after a successful commit.

Hosts can import `computeDisplaySize(scene.layout, width?, height?)` from `@retikz/render/runtime` to size an output element. Set only the width or height to preserve the scene’s aspect ratio without changing its viewBox.

### Static Scene APIs

| API                                       | Import path             | Result                                       |
| ----------------------------------------- | ----------------------- | -------------------------------------------- |
| `buildSvgDocument(scene, options)`        | `@retikz/render/svg`    | The SVG document tree                        |
| `renderToSvgString(scene, options)`       | `@retikz/render/svg`    | A complete SVG string for SSR                |
| `renderToCanvas(canvas, scene, options?)` | `@retikz/render/canvas` | Paints the target Canvas and returns nothing |
