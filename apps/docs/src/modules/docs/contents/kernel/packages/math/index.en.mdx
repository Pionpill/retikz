`@retikz/math` handles how geometry is computed, not how it is drawn. Use it to move a point, intersect two lines, compute a convex hull, or turn knots into a smooth curve over plain TypeScript data, then pass the result to `@retikz/core` or an adapter.

> To start drawing immediately, begin with [Components](/kernel/components/layout). Return here when you need to prepare geometry before drawing.

## Responsibilities

| Topic                                          | Problem it solves                                    | Reach for it when                                     |

| [Primitives](/kernel/packages/math/primitives) | Points, vectors, transforms, bounds, ellipses, arcs  | Constructing, transforming, or checking geometry data |
| [Algorithms](/kernel/packages/math/algorithms) | Intersections, enclosures, containment, hull, curves | Deriving new geometry from existing geometry          |

## Install and use

```bash
pnpm add @retikz/math
```

```ts
import { intersect, point, vector2 } from '@retikz/math';

const direction = vector2.fromAngleDegrees(-30);
const end = point.along([0, 0], direction, 120);
const hit = intersect.lineLine({
  a1: [0, 0],
  a2: end,
  b1: [20, -40],
  b2: [20, 40],
});
```

The package is ESM-only and requires Node.js 24 or newer.

## Why @retikz/math exists

Many drawing steps are deterministic numerical computations. Keeping them separate from IR, schemas, React, and renderers lets core, domain packages, server-side scripts, and tests share one geometry model. It also keeps the computations usable without a DOM or Canvas.

Its boundaries are explicit:

- Inputs and outputs are numbers, tuples, and plain objects; it produces no IR or Scene
- APIs are primarily pure functions that neither mutate point sets nor retain renderer state
- It has no runtime dependencies and does not own composition, compilation, measurement, or SVG / Canvas output

## Relationship to @retikz/core

`@retikz/math` relates to `@retikz/core` in two ways. Application code can use math to turn raw values into plain geometry before passing them to core. The core compiler also calls math directly for position resolution, path endpoints, bounds, and related computations. Math produces neither IR nor Scene; core still owns composition and Scene compilation.
