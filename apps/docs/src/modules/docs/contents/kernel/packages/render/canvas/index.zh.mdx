> 这里是 @retikz/render 包文档，不是组件教程；写图请从 [组件](/kernel/components/layout) 开始。

Canvas 后端把图画成像素位图，而不是 DOM。它和 SVG 消费同一份 Scene，并在支持范围内对齐绘制语义；区别在于整张图是一块画布而非一棵元素树。没有逐图元的 DOM 节点，因此图元成百上千、或要高频重绘 / 动画时，它通常比 SVG 更稳。代价是失去了逐元素 CSS 选择与原生无障碍语义；坐标命中查询只能补上交互定位，不能恢复 DOM 能力。

下面的预览与 [SVG 页面](/kernel/packages/render/svg) 共用同一份 IR，并固定通过 Canvas 输出。几何与样式来自同一 Scene，但最终产物是一块位图画布。

## 怎么用

**React**——给 `<Layout>` 显式传 `renderer="canvas"`：

```tsx
import { Layout, Node } from '@retikz/react';

<Layout renderer="canvas">
  <Node id="a">hello</Node>
</Layout>;
```

**Vanilla（浏览器）**——`mountCanvas` 把图挂成 `<canvas>`，返回的 view 包含 Canvas 侧的水合与坐标映射：

```ts
import { mountCanvas } from '@retikz/vanilla/dom';

const view = mountCanvas(container, ir);
// view.root 是 <canvas>；view.update(next) 走所选 static 或 retained processing；view.dispose() 卸载
```

两个入口的输入能力不同：

| 入口                  | 接收的输入                               | 输出       |
| --------------------- | ---------------------------------------- | ---------- |
| React `<Layout>`      | JSX `children`<br />或 `IRScene`         | `<canvas>` |
| Vanilla `mountCanvas` | `Scene` / `IRScene`<br />或 `InputScene` | `<canvas>` |

`devicePixelRatio` 缺省读取 `globalThis.devicePixelRatio`，再回退到 1，让高清屏保留足够的位图分辨率。

## 给 Canvas 图加交互

Canvas 没有 DOM 图元，定位靠**坐标命中查询**：把指针的 client 像素逆映射回 Scene 坐标，再做几何命中得到图元 `id`。这套定位封装在 `view.hydrate` 里，handler 注册表与 SVG 相同：

```ts
const view = mountCanvas(container, ir);
const handle = view.hydrate({
  handlers: { box: { click: event => toggle('box') } },
});
// handle.dispose() 解绑
```

同一张 `handlers` 表可用于 SVG 与 Canvas；定位实现和 `context.element` 等宿主字段仍有差异——详见 [水合](/kernel/packages/render/hydration)。

## 已知边界

Canvas 支持范围取决于宿主提供的 2D API 与资源加载能力。底层 `drawScene` 可用 `warnUnsupported` 接收诊断；未提供时，诊断写入 `console.warn`。

- 宿主没有 `createConicGradient` 时，圆锥渐变会跳过绘制并告警。
- image paint 需要 `getImage` 返回已解码图片。React `<Layout renderer="canvas">` 会自带 loader，并在图片就绪后重绘；v0.4 的 Vanilla `mountCanvas` 尚未暴露 `getImage`，因此 image paint 会跳过并告警。自定义宿主可给 `renderToCanvas` / `drawScene` 提供 loader，并在图片就绪后自行重绘。
- 直接调用 `drawScene` 时，pattern 和精确的非均匀 gradient stroke 依赖 `createOffscreen`；浏览器 `renderToCanvas` 会提供默认离屏 context，其他宿主需要自行注入。
- Scene 引用了缺失或当前不支持的 paint / clip 资源时，相应效果会跳过并告警。

## Node 图片导出

服务端或 CLI 里要直接生成 PNG / JPEG / WebP 时，使用独立入口 `@retikz/render/canvas-node`。它不会把 native canvas 打进浏览器包；调用前需要在应用侧安装可选 peer：

```bash
pnpm add @napi-rs/canvas
```

```ts
import { compileToScene } from '@retikz/core';
import { renderSceneToImage } from '@retikz/render/canvas-node';

const { scene } = compileToScene(ir);
const png = await renderSceneToImage(scene, {
  width: 960,
  height: 540,
  devicePixelRatio: 2,
  format: 'png',
  background: '#fff',
});
```

`renderSceneToImage` 消费已编译的 `Scene`，与浏览器 Canvas 一样走 `drawScene`。`width` / `height` 是 CSS 尺寸，实际位图尺寸为它们乘以 `devicePixelRatio`；具体效果仍受所用 native canvas 宿主能力约束。

## Canvas 还是 SVG

|              | Canvas                   | SVG            |
| ------------ | ------------------------ | -------------- |
| 输出         | 像素位图                 | 矢量 DOM 节点  |
| 大量图元     | 即时模式更稳             | 节点多时变慢   |
| 缩放         | 受分辨率限制             | 任意倍数清晰   |
| CSS / 选择器 | 整块画布                 | 每个图元可命中 |
| 默认         | 显式 `renderer="canvas"` | 是             |

图元成百上千或要高频重绘 / 动画时用 Canvas；图元不多、要清晰矢量、逐元素 CSS 或原生无障碍语义时用默认的 [SVG](/kernel/packages/render/svg)。两者共享 Scene 与 handler 注册语义，但切换前仍需核对上面的 Canvas 能力边界。
