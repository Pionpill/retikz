> 这里是包文档，不是组件教程；写图请从 [组件](/kernel/components/layout) 开始。

这一组讲 retikz 怎么把图真正画到屏幕上。你写的图会先被编译成一份**与渲染器无关的 Scene**，再交给某个后端落地：**SVG** 产出矢量 DOM，每个图元都是页面上能被 CSS 命中的真实元素；**Canvas** 把同一份 Scene 画成像素位图，适合图元很多或高频重绘的场景。两个后端共享 Scene 语义，在各自支持的能力范围内对齐输出；切换前仍需确认目标宿主和交互需求。**水合**是两个后端共用的机制：先静态出图，客户端再按 id 把事件 handler 绑回图元。

从 `@retikz/render/runtime` 导入 `RenderMode` 可为渲染后端选项标注类型。Vanilla 挂载和 React Layout 的 `renderer` 均接受 `svg` 或 `canvas`。

## 职责一览

| 主题         | 职责                                                  | 何时查阅                               |
| ------------ | ----------------------------------------------------- | -------------------------------------- |
| SVG          | Scene → 矢量 DOM，或 SSR / 构建期的字符串输出         | 默认选它：要清晰矢量、CSS 命中、无障碍 |
| Canvas       | Scene → 像素位图，即时模式绘制 + 命中查询             | 图元成百上千、高频重绘、性能优先       |
| Session 提交 | 在 Reconciler 会话中准备与提交 Scene 和配置           | 需要稳定宿主 identity 与增量更新       |
| 水合         | 静态出图后按 id 把事件 handler 绑回图元（两后端共用） | 给图加点击 / 悬停等交互                |

## Session 提交

`createRenderTarget()` 创建连接 Reconciler 会话与 renderer 的提交目标。Vanilla 将它与处理结果发布组合成一个目标：先准备候选帧与配置，再提交宿主，成功后才发布会话结果。首次提交物化完整 Scene；编译结果变化时生成 `replaceScene`，仅配置变化时使用空操作 Patch 并保留编译结果。提交失败时恢复宿主与编译状态；恢复失败会使 Reconciler 会话进入 broken 状态，需要释放后重新创建。

最终 dispose 会对 hydration、animation 与 image loader 做反向 best-effort cleanup。SVG WAAPI binding 或 Canvas clock 一旦开始清理，公开 controls 与事件 / 可见性回调立即失活；animation、observer、listener、inline style ownership、visibility listener 与 clock 分别清理，成功项不重复，失败项保留给后续 dispose 重试。

`InputRenderRuntimeConfig` 是 closed transaction config：`handlerContributions` 按注册序合并水合 handler，`animation` 控制播放、截帧与扩展 registry，`cachePolicy` 保留未来 layer 失效优化的 hint，`canvas.width` / `canvas.height` 声明 Canvas CSS user-space 尺寸。当前 SVG / Canvas renderer 尚不按 `cachePolicy` 复用图层。Render 借用配置，不冻结调用方的对象。只有 handler 注册项乱序时，才另外建立有序列表。渲染器使用这些值期间，请保持它们及其成员稳定；更新时传入新值，而不要原地修改旧帧引用的数据。Canvas 尺寸字段省略时从 committed Scene layout 推导，再乘 session-lifetime DPR 得到设备像素；尺寸更新与位图绘制原子 commit，dirty reuse 仅在目标尺寸稳定时成立。

这些 session API 从 `@retikz/render/runtime` 导入，不从 `@retikz/render` package root 导出。第三方后端通过 `RendererFactory` 创建 nominal SVG / Canvas renderer，并声明 `none` / `group` / `entity` capability。Render 提交目标校验 Snapshot / Patch 的版本与结果对应关系；无效 Patch 会被拒绝。当前接线对编译变化生成完整替换，后端能力声明不意味着会话自动产生细粒度操作。

### Scene 快照

运行时 Scene 身份、拓扑、快照和 Patch 契约由 Render 拥有，相关类型从 `@retikz/render/runtime` 导入，包括 `SceneIdentity`、`SceneRuntimeSnapshot` 和 `ScenePatch`。Reconciler 交付完整编译结果、来源信息和候选版本；Render 提交目标据此建立渲染快照。身份或拓扑构造失败使用 `RetikzRenderError` 报告。

拓扑节点在同级图元中的顺序由 `primitivePath` 的末尾索引决定，相对子树的根路径为 `[]`。构造 update patch 时，用 `subtree.root` 指定替换目标，不另传 `identity`；move 和 remove 仍通过 `identity` 指定目标。

静态 API 接收 `Scene`。自定义 renderer 接收 `SceneRuntimeSnapshot`，成功提交后通过 `read().snapshot` 返回该快照。

宿主可从 `@retikz/render/runtime` 导入 `computeDisplaySize(scene.layout, width?, height?)` 计算显示尺寸。只指定宽或高时，另一轴按场景比例补齐；这不会改变场景的取景范围。

### 静态 Scene API

| API                                       | 导入路径                | 产物                         |
| ----------------------------------------- | ----------------------- | ---------------------------- |
| `buildSvgDocument(scene, options)`        | `@retikz/render/svg`    | SVG 文档描述树               |
| `renderToSvgString(scene, options)`       | `@retikz/render/svg`    | 可用于 SSR 的完整 SVG 字符串 |
| `renderToCanvas(canvas, scene, options?)` | `@retikz/render/canvas` | 绘制到目标 Canvas，无返回值  |
