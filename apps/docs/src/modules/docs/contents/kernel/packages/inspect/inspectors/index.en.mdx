---
title: Custom Inspectors
description: Extend Inspectors through one Definition, registry, and selection path so third-party auxiliary content compiles in isolation like built-ins
---

When the built-in control-point Inspector cannot explain a domain result, define your own Inspector with `defineInspector()`. Built-in and third-party Definitions share the same registry, selection, validation, and auxiliary compilation path; there is no separate built-in allowlist.

## Scope

An Inspector reads final output published by an owner and returns ordinary `IRChild` content or a readonly array as auxiliary output. It cannot write to the primary Scene, mutate the primary figure, or bypass Core with parallel rendering semantics.

## Define and register

`InspectorKey.namespace` uses the stable short name of the package that owns the capability, not a shared `retikz` prefix: Core uses `core`, Layout uses `layout`, and third parties use their owning package short name. `type` is unique inside that namespace.

## Definition contract

| Field                | Responsibility                                                                  |
| -------------------- | ------------------------------------------------------------------------------- |
| `namespace`, `type`  | Form a stable compound key; namespace is the owning package short name          |
| `owner`              | Select the pathKind or composite owner to observe                               |
| `subjectSchema`      | Validate final output published by that owner                                   |
| `optionsInputSchema` | Validate sparse selection options at each level                                 |
| `optionsSchema`      | Resolve merged sparse input into canonical options                              |
| `mergeOptionsInput`  | Optionally merge sparse options across selection levels                         |
| `inspect`            | Convert the final subject and context into ordinary `IRChild` auxiliary content |

## Execution

Every inspection starts with an explicit registry. `createDefaultInspectorRegistry()` adds built-in Inspectors, then passes third-party Definitions through the same path. After selection resolves, only owners that can match are asked to publish observations. A duplicate `namespace + type` fails immediately.

## Errors and limits

A duplicate registry key or request for an unregistered Inspector throws `RetikzInspectError`; no partial result continues. Invalid final output, options, or auxiliary output also fails with its corresponding stage origin.

## API Reference

| API                                | Description                                                               |
| ---------------------------------- | ------------------------------------------------------------------------- |
| `defineInspector()`                | Validate and freeze one `InspectorDefinition`                             |
| `createInspectorRegistry()`        | Build a stateless registry from explicit Definitions; duplicate keys fail |
| `createDefaultInspectorRegistry()` | Build a registry with built-ins and optional third-party Definitions      |
| `STROKE_PATH_INSPECTOR_KEY`        | Compound key for the built-in `stroke` Path Inspector                     |
| `STROKE_PATH_INSPECTOR`            | Built-in `stroke` Path Inspector Definition                               |
