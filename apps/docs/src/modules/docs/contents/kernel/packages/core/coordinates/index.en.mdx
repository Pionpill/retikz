Semantic resolution can complete a position expression without knowing which geometry a name currently denotes. Core's resolvers retain intent; compile/reference evaluates it using naming and transform services supplied by the scheduler. Reconciler owns visibility and name lifetimes.

## Overall Flow

A local point belongs to the current Scope. A world point includes current and ancestor Scope transforms. Ordinary positions are computed locally and projected; named targets read published world geometry and convert it for local consumers. The spaces coincide without transforms.

## Expression Resolution and Geometric Evaluation

`resolvePosition` completes direction distance, polar origins and nested expressions without name lookup. For `{ of: 'A', direction: 'right' }`, it can determine distance but still needs readable A geometry to determine a point. Canonicalization does not discard references prematurely.

| Expression                                               | Evaluation                                                                                |
| -------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| [20, 10]                                                 | Current Scope local point                                                                 |
| `{ angle: 90, radius: 40 }`                              | From a local origin; positive screen-space angles turn downward                           |
| `{ of: 'A', direction: 'right', distance: 40 }`          | Convert A's center to local, then move in a local direction; distance is center-to-center |
| `{ of: 'A', offset: [40, 0] }`                           | Evaluate the local base, then add a local offset                                          |
| `{ between: [{ id: 'A' }, { id: 'B' }], fraction: 0.5 }` | Interpolate two world targets, then convert to local                                      |

These represent shared mechanisms, not a union accepted everywhere. Each consumer's Schema defines valid forms. Node supports self-anchor alignment; Scope placement involves its envelope; path-relative cursor expressions belong to path compilation.

## Local Offsets and Target Offsets

The offset in `{ of: 'A', offset: [40, 0] }` belongs to current local space. The offset in node target `{ id: 'A', offset: [40, 0] }` is added in world space. Scaling exposes the difference.

<ComponentPreview files="coordinate-spaces" size="lg" hideCode type="illustration" />

The base is world [100, 50] with Scope scale 2. A local offset of 40 gives world [180, 50]; a world target offset of 40 gives [140, 50]. This follows the two contracts' coordinate spaces.

## Names, Targets and Anchors

Lookup first returns a PositionReferenceView with geometry, state and source location. Anchor evaluation follows. Nodes and named Scopes provide boundary geometry; Coordinates provide only position and emit no visible primitive.

`evaluatePosition` returns localPoint / worldPoint. `evaluatePositionTargetWorld` returns referencePoint and retains a direct reference and optional boundary binding when appropriate. `evaluatePositionTarget` adds local point. An interpolated result is not presented as a direct node reference.

A position target without an anchor normally reads the center; path compilation may subsequently clip an endpoint to its boundary. Capabilities interpret standard and shape-specific anchors. Unknown anchors fail, and zero-size Coordinates cannot support proportional edge points requiring a real edge.

## Reference Timing

Node and Coordinate evaluate when visited and require readable targets. Node self-anchor alignment first needs provisional layout, then computes a world-space delta and projects it back to local space. Self-reference, undefined targets and a Scope still being laid out fail.

Paths have dedicated deferral: root paths wait for the root subtree, while Scope paths run when that Scope closes. Later siblings can become path targets, but this does not grant a Scope path access to external objects declared after the Scope.

A named Scope may initially publish a position placeholder. `scope-placeholder` differs from `resolved`; a position placeholder is not a ready envelope. Missing references yield null or an empty referencePoint at the evaluator boundary. Consumers then fail or diagnose according to their contract rather than inventing an origin.

## Complete Implementation Flow

A Coordinate goes through semantic resolution and local evaluation. Reconciler projects its world position, publishes its name and records its allocation. It emits no visible ScenePrimitive. Node and Path use the same position services while owning their final placement and endpoint handling.

<ComponentPreview files="coordinate-implementation" size="lg" hideCode type="flow" />

Core's createPositionEvaluateContext adapts geometry queries and coordinate conversion. Reconciler's createTreePositionContext supplies its name stack, Scope transforms and shared boundary state through this narrow interface, keeping Core independent of a particular tree or incremental engine.
