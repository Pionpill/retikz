`@retikz/core` defines the drawings retikz can express and the operations that produce their layout and drawing data. It provides serializable IR, capability extension contracts, and atomic stages for semantic resolution, coordinate evaluation, layout and primitive generation.

`@retikz/reconciler` schedules the compilation lifecycle: it accepts drawing declarations, maintains compilation context, calls Core stages as their dependencies become available, and assembles their products into a Scene. Reconciler also owns cache reuse and output transactions for subsequent updates. `@retikz/render` draws the Scene through SVG, Canvas and other backends.

This series is for developers who need to understand drawing semantics, implement extensions or integrate compilation. Everyday drawing can start with React or Vanilla, which use the same Core contracts.

## Responsibilities at a glance

IR is the data representation of a drawing declaration: a node's position, shape and text, for example, or the targets a path connects. Scene is the compiled drawing data, containing laid-out primitives and resources. The following parts supply the semantics and computation between them:

| Part                      | Responsibility                                                                                                             | When to read                                              |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| IR / Schema               | Define drawing declarations that can be stored and exchanged, including field meanings, constraints and defaults           | To understand what an author can express                  |
| Resolve                   | Use the current context to expand shorthand, apply inheritance and determine values and capabilities for downstream stages | To trace declarations into an internal, determined form   |
| Definition / registry     | Define extension capabilities and look up implementations by name; built-ins and custom implementations share contracts    | To understand how shapes, paths or composites participate |
| Atomic compilation stages | Compute layout and geometry, producing primitives and intermediate products                                                | To understand node, path and scope processing             |
| Scene / Primitive         | Define backend-independent scene, primitive and resource contracts                                                         | To understand what renderers consume                      |

A Definition describes an implementation contract, such as how a shape participates in sizing and drawing. A registry indexes definitions by name. IR stores serializable declarations; extension implementations are supplied through runtime wiring such as compilation options.

## Installation and usage

To declare IR and compile it directly, use Core's types and Reconciler's execution entry:

<PackageManagerInstall packages="@retikz/core @retikz/reconciler" />

Import `IRScene` from Core to declare the scene, and `SceneReconciler` from Reconciler to execute it. This example performs one full compilation, using `incremental: false` to disable state retention for later incremental updates. `mount(ir)` establishes the session's first result; `compilation.result.scene` is the Scene that can be passed to a renderer.

```ts
import type { IRScene } from '@retikz/core';
import { SceneReconciler } from '@retikz/reconciler';

const ir: IRScene = {
  type: 'scene',
  version: 1,
  children: [
    { type: 'node', id: 'A', position: [0, 0], text: 'A' },
    { type: 'node', id: 'B', position: [180, 0], text: 'B' },
    {
      type: 'path',
      children: [
        { type: 'step', kind: 'move', to: { id: 'A' } },
        { type: 'step', kind: 'line', to: { id: 'B' } },
      ],
    },
  ],
};

const reconciler = new SceneReconciler({}, { incremental: false });

try {
  const { compilation } = reconciler.mount(ir);
  console.log(compilation.result.scene);
} finally {
  reconciler.dispose();
}
```

This code logs drawing data; displaying it requires a renderer. The nodes use default layout, while the illustration above specifies minimum sizes.

External input such as JSON should first pass through the appropriate Schema validation. Typed TypeScript declarations can be passed directly. Compilation options supply capabilities such as text measurement and extension definitions. The semantic resolution part of this series explains field meanings and how declarations become internal, determined values.

## Package boundaries

Choose an extension point according to whether the change concerns drawing expression, execution or backend presentation:

| Concern                                                                                              | Owner                                                              |
| ---------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| IR fields, drawing semantics, capability definitions, layout and primitive computation               | Core                                                               |
| Full and incremental compilation, tree traversal, context lifecycle, caching and output transactions | Reconciler                                                         |
| SVG / Canvas drawing and backend resources                                                           | Render                                                             |
| React components or Vanilla authoring APIs, input assembly and host wiring                           | React / Vanilla                                                    |
| General computational geometry and basic mathematics                                                 | Math                                                               |
| Domain declarations and logic for Plot, Table and similar capabilities                               | The domain package, integrated through contracts such as Composite |

Each Core stage accepts the inputs and capability context needed for its operation and returns the corresponding products. Reconciler decides when to execute a stage, whether a product can be reused across updates, and when to commit to an output target.
