A drawing declaration can say “connect A to B”, while a renderer needs the exact start and end points. `@retikz/core` resolves these declarations, computes node layout, coordinates and paths, and assembles a renderer-independent Scene.

This package is for developers building domain components, extending drawing capabilities or integrating the compiler. Most drawing applications start with React or Vanilla, whose adapters prepare Core input and pass compiled results to a renderer.

## Responsibilities at a glance

Consider two nodes, A and B, joined by a line. The input records their positions, text and connection targets. Core computes node boundaries and connection endpoints, then emits drawable primitives.

| Object                | Responsibility                                                             | Two-node example                                                |
| --------------------- | -------------------------------------------------------------------------- | --------------------------------------------------------------- |
| IR                    | Store serializable drawing declarations                                    | Declare A, B and a path referencing them                        |
| Definition / registry | Define and bind shapes, path kinds, composites and other capabilities      | Look up the node shape and path processing capabilities         |
| Compiler              | Resolve configuration, layout, coordinates and paths                       | Determine endpoints from node boundaries                        |
| Scene                 | Store resolved primitives, resources, canvas and other drawing information | Drawing data for rectangles, text and the connecting line       |
| CompileResult         | Collect the Scene, artifacts and spatial handles                           | Deliver the Scene to a renderer and other data to its consumers |

IR describes what the author wants to draw; Scene records how to draw the compiled result. A Definition describes a capability, and a registry looks up definitions by name. Built-in and custom capabilities participate in compilation through their respective contracts.

Core resolves each node's style and shape, uses text metrics to determine its size, then resolves paths referencing the nodes. A path declared before its target nodes can have its endpoints filled in after node layout. SVG and Canvas renderers consume the same Scene contract.

## Installation and usage

<PackageManagerInstall packages="@retikz/core" />

Core provides a framework-independent TypeScript compilation API. This example uses the same A-to-B connection with default node layout:

```ts
import { compileToScene, type IRScene } from '@retikz/core';

const ir: IRScene = {
  type: 'scene',
  version: 1,
  children: [
    {
      type: 'path',
      children: [
        { type: 'step', kind: 'move', to: { id: 'A' } },
        { type: 'step', kind: 'line', to: { id: 'B' } },
      ],
    },
    { type: 'node', id: 'A', position: [0, 0], text: 'A' },
    { type: 'node', id: 'B', position: [180, 0], text: 'B' },
  ],
};

const result = compileToScene(ir);
console.log(result.scene);
```

`compileToScene` synchronously returns a `CompileResult`. Its `scene` can be passed to a renderer; `artifacts` and `spatialHandles` carry additional artifacts and spatial handles. See [Compilation Output](/kernel/packages/core/compilation-output) for details. This call compiles the drawing; Render or an adapter handles its display.

The entry accepts typed IR. External input such as JSON should first pass through the appropriate schema validation. Compile options can supply text measurement, formula handling and extension definitions.

## Package boundaries

| Core owns                                                          | Collaborators own                                                                        |
| ------------------------------------------------------------------ | ---------------------------------------------------------------------------------------- |
| Core IR, Definitions and extension contracts                       | React / Vanilla provide authoring APIs and prepare input                                 |
| Configuration resolution, node layout, coordinate and path solving | Math provides basic computation; the host supplies capabilities such as text measurement |
| Scene compilation, resource and output assembly                    | Render draws the Scene through SVG, Canvas and other backends                            |
| Drawing-state dependencies and incremental computation rules       | Runtime manages state, result lifetimes and consistent publication                       |
| Compilation observation outputs                                    | Inspect consumes observations and creates inspection helpers                             |

This series follows one compilation from input to final outputs. Subsequent updates across Runtime, Core and Render belong to the cross-package dynamic update topic. See [Incremental Execution](/kernel/packages/runtime) for Runtime state and transaction mechanisms.
