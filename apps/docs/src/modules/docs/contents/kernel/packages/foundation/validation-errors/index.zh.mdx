Foundation 将通用标量校验和错误形态放在一起：断言复用最小规则，错误类型则让每个包保留自己的错误语义。

## 基础用法

`RetikzErrorOptions`、`RetikzError` 与 `isRetikzError` 提供所有包共享的最小错误骨架。领域包（即拥有这次失败语义的 owner）应继承 `RetikzError` 并定义自己的错误码、详情和恢复语义；`RetikzFoundationError` 只承载 Foundation 自己拥有的原子失败。

```ts
import { assertPositiveNumber, RetikzError, type ValueOf } from '@retikz/foundation';

type Details = Readonly<{ source: string }>;

const RetikzDomainErrorCode = {
  Failed: 'DOMAIN_FAILED',
} as const;

type RetikzDomainErrorCodeValue = ValueOf<typeof RetikzDomainErrorCode>;

class RetikzDomainError extends RetikzError<RetikzDomainErrorCodeValue, Details> {
  constructor(details: Details, cause?: unknown) {
    super({ code: RetikzDomainErrorCode.Failed, message: 'Domain failed', details, cause });
  }
}
```

| 成员              | 类型                                       | 语义                                                       |
| ----------------- | ------------------------------------------ | ---------------------------------------------------------- |
| `code`            | `TCode`                                    | 结构化错误分类，由 owner 定义                              |
| `message`         | `string`                                   | 面向调用方的错误消息                                       |
| `details`         | `TDetails`                                 | owner 提供的结构化详情；保留对象身份，不自动深拷贝或冻结   |
| `cause`           | `unknown`，可选                            | 原始异常或值；省略时仍创建值为 `undefined` 的 own property |
| `isRetikzError()` | `(value: unknown) => value is RetikzError` | 判断值是否属于正常 `RetikzError` class hierarchy           |

## 标量断言

Foundation 内置少量用于基础契约失败的标量断言。它们只接收调用方已约束好 TypeScript 标量类型的值，成功时返回 `void`；未指定 owner 错误时，失败会抛出对应的 `RetikzFoundationError`。

### 内置断言

| 方法                                                    | 作用                                   | 默认错误码                             |
| ------------------------------------------------------- | -------------------------------------- | -------------------------------------- |
| `assertNonEmptyString(value, label, createOwnerError?)` | 拒绝空串和只包含运行时标准空白的字符串 | `FOUNDATION_NON_EMPTY_STRING_REQUIRED` |
| `assertPositiveNumber(value, label, createOwnerError?)` | 拒绝 `0`、负数和非有限数               | `FOUNDATION_POSITIVE_NUMBER_REQUIRED`  |

### 指定 owner 错误

第三个参数 `createOwnerError` 接收 `() => RetikzError` 工厂。校验成功时不调用；失败时调用一次并原样抛出返回的错误，保留其 `code`、`message`、`details` 与 `cause`。错误对象应在工厂内部创建，避免成功路径也承担构造成本。工厂自身抛出的异常也会原样传播。

```ts
const fontSize = 0;
assertPositiveNumber(fontSize, 'SVG font size', () => new RetikzDomainError({ source: 'svg' }));
// 抛出 RetikzDomainError，而不是 RetikzFoundationError
```

没有传入 `createOwnerError` 时，断言仍抛 `RetikzFoundationError`。字符串断言使用 `FOUNDATION_NON_EMPTY_STRING_REQUIRED`，正数断言使用 `FOUNDATION_POSITIVE_NUMBER_REQUIRED`，并在 `details` 与 `cause` 中保留原子失败信息。
