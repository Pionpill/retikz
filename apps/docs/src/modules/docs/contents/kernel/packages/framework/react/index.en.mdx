`@retikz/react` is the primary entry for React applications. You declare figures with JSX components such as `<Layout>`, `<Node>`, `<Path>`, `<Scope>`, and `<Draw>`; its collector turns props and children into an `@retikz/vanilla` `InputScene`, then `<Layout>` hosts the processed SVG or Canvas result.

It owns React authoring and result hosting rather than new drawing semantics. IR, schemas, geometry, and compilation belong to `@retikz/core`; Input normalization, composite dependency resolution, the Core Program, and retained processing state belong to `@retikz/vanilla`.

## Install and usage

`react` and `react-dom` are peer dependencies at version 18 or newer:

```bash
pnpm add @retikz/react react react-dom
```

```tsx
import { Draw, Layout, Node } from '@retikz/react';

export const Diagram = () => (
  <Layout>
    <Node id="source" position={[0, 0]}>
      Source
    </Node>
    <Node id="target" position={[160, 0]}>
      Target
    </Node>
    <Draw way={['source', 'target']} arrow="->" />
  </Layout>
);
```

`<Layout>` emits SVG by default; pass `renderer="canvas"` when you need a raster bitmap. Start with [Getting Started](/kernel/get-start), then see [Layout](/kernel/components/layout/overview) for the complete host options.

`<Layout theme>` writes the root `IRScene.theme`, while `<Scope theme>` writes a local `IRScope.theme`. Theme is a sparse `style / mode` override; `themeStyles` is the runtime-only compile option that registers custom Core styles defined with `defineThemeStyle`. When `ir` and an explicit `theme` are both present, the prop overrides `ir.theme` per field without mutating either input. See [Layout: Inherited Theme](/kernel/components/layout/overview#inherited-theme) for the complete example.

## Why @retikz/react exists

### JSX reduces authoring overhead

You can construct `@retikz/core` IR directly, but figures commonly contain nested, reusable, and compositional structures. JSX expresses those relationships as a component tree, keeping declarations such as `<Layout>`, `<Scope>`, `<Node>`, and `<Path>` close to the figure hierarchy while reducing the boilerplate of assembling authoring input by hand.

retikz treats React as its officially supported first-class framework: the component API, documentation, examples, and adapter behavior in `@retikz/react` are maintained alongside the Kernel. React is the authoring and result-host layer here; framework-neutral `@retikz/core` and shared `@retikz/vanilla` processing still own the data contract and compilation semantics.

### Why other adapters are not official packages

This does not mean Core can only integrate with React. Any framework can reuse the retikz Kernel by converting its component or template structure into the same `InputScene` and passing it to `@retikz/vanilla` processing.

`@retikz/react` also serves as the implementation reference for other framework adapters, demonstrating the complete boundaries for component-tree-to-`InputScene` conversion, host capability injection, and processing-result wiring. The official project focuses its maintenance resources on React and does not develop, release, or maintain packages for Vue, Svelte, or other frameworks; the community can implement those adapters independently against the same boundaries.

## Components do not render DOM directly

### Why marker components

Marker components are not used because React is incapable of drawing. They keep drawing semantics in one source of truth. If `<Node>` and `<Path>` each implemented their own DOM, browser layout, and geometry rules, the React DSL would gradually become a second system beside Core IR, and the same figure could produce different results in React, Vanilla, or another adapter.

JSX therefore organizes declarations while the collector converges them into a framework-neutral `InputScene`. The intermediate path creates no extra DOM and does not make CSS layout an implicit input to compilation. Shared processing then normalizes Input to Core IR that persistence, transport, and other framework adapters can reuse.

React still operates where it adds value. It subscribes to the read-only Vanilla processing result and connects React commit, refs, and unmounting to a stable `<svg>` / `<canvas>` host. The retained controller and static processing are managed by Vanilla; React only maps the completed Scene to that host. Drawing semantics are thin in this layer, not host integration.

Kernel components such as `<Node>`, `<Path>`, and `<Scope>` are **Input markers**, not DOM components. They return `null` and expose only a stable `displayName` that tells the React collector which primitive they represent. A `<Node>` therefore does not produce an intermediate `<div>` or acquire a second browser-layout model.

```tsx
export const Node: FC<NodeProps> = () => null;
Node.displayName = TIKZ_NODE;
```

Sugar components do not add another IR either. `<Draw>`, for example, parses `way` with Core's `parseWay`, then returns standard `<Path>` / `<Step>` Kernel JSX. This excerpt shows only the line branch; the source covers fold, curve, arc, cycle, and the other branches through the same mapping:

```tsx
const steps = parseWay(way);

return (
  <Path arrow={arrow}>
    {steps.map((step, index) => {
      if (step.kind === 'line') {
        return <Step key={index} kind="line" to={step.to} label={step.label} />;
      }
      return null;
    })}
  </Path>
);
```

`readSceneChildren` walks children synchronously: it recognizes Kernel markers, unwraps fragments, and directly invokes function Sugar before recursing into the result. This does not pass through the React DOM renderer, so Kernel and Sugar must be hook-free, side-effect-free function components. `createInputScene()` produces the single `InputScene` plus collected `InputEmbedAdapter` values for Vanilla normalization.

### Retained update boundaries

Marker components avoid intermediate DOM and duplicated drawing semantics, but JSX → Input still reruns when children references change. `<Layout>` prepares a static fallback during React render; after the client commit, the default retained mode creates a Vanilla processing controller and sends later Input or `ir` sources through it. The controller publishes only complete successful revisions, so React continues to host the prior successful result on failure.

Frequently updated large figures can keep stable IR, children, and Core options outside the component or in `useMemo`, avoiding needless Input or processing-controller recreation. Passing the IR prop skips the JSX collector but still uses Vanilla processing for the subsequent compile.

In retained mode, the Vanilla controller owns the Core Program, runtime session, and update strategy; static mode prepares one lifecycle-free processing result. React subscribes to the controller's read-only result, then uses `ProcessingResultHost` to present its same-revision Scene, artifacts, readonly layers, and event wiring.

Definition arrays are canonicalized by ordered element identity, so recreating an equivalent container such as `[shape]` does not rebuild the processing controller. Changing a Definition itself, the renderer backend, `idPrefix`, or processing options remounts it. Concurrent scheduling and progressive materialization remain outside the current public contract.

### Execution modes and update strategies

`<Layout>` uses two orthogonal `runtime` fields to select the host lifecycle and Program update behavior. Omitting the option means `retained + auto`:

```tsx
<Layout /> {/* retained + auto */}
<Layout runtime={{ mode: 'retained', updateStrategy: 'full' }} />
<Layout runtime={{ mode: 'static' }} />
```

| Configuration     | Update behavior                                           | Session, memory, and failure semantics                                                              |
| ----------------- | --------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `retained + auto` | Safe changes use local Patches; others fully fall back    | Keeps Snapshots, candidates, diagnostics, atomic commits, and rollback; this is the default         |
| `retained + full` | Skips Program `update()` for affected work and runs fully | Retains the same Runtime state and transaction guarantees as auto; it is not a low-memory mode      |
| `static`          | Fully compiles and directly materializes SVG / Canvas     | Creates no Session, Snapshot, diff, transaction, or rollback; less resident state, more update work |

`mode: 'static'` cannot be combined with `updateStrategy` or `onDiagnostic`. The `LayoutRuntimeOptions` TypeScript union rejects those combinations, and JavaScript calls fail before a host is created. If static compilation fails before host writes, no new picture is published. Errors after materialization, animation, or hydration begins propagate without a guarantee that the old host state is restored.

Changing `updateStrategy` between `auto` and `full` on a retained host disposes the old Session and creates a new one from the current complete input. The host element keeps its identity, while the revision restarts from initial. Changing `mode` releases and replaces the complete host. Choose `retained + full`, not `static`, when you want to keep transactions, diagnostics, and rollback while excluding incremental updates.

## From JSX to Scene

`<Layout>` first calls the React collector to adapt JSX into Vanilla Input. Whenever the input or Core options change, React only prepares a static fallback; after the client commit, Vanilla processing creates or updates the Core Program. In the figure, blue nodes belong to `@retikz/react` authoring / hosting, green nodes are shared `@retikz/vanilla` processing, and orange nodes are the data contracts and compiler owned by `@retikz/core`.

<ComponentPreview files="react-to-scene" size="xs" hideCode />

| Stage                | Owner             | Responsibility                                                                                 |
| -------------------- | ----------------- | ---------------------------------------------------------------------------------------------- |
| Kernel / Sugar JSX   | `@retikz/react`   | Collect props and children; expand Sugar into Kernel first                                     |
| `createInputScene()` | `@retikz/react`   | Walk the component tree, produce `InputScene`, and collect Tier 2 `InputEmbedAdapter`          |
| `normalizeScene()`   | `@retikz/vanilla` | Normalize typed Input to `IRScene`, lower embeds, and aggregate composite dependencies         |
| `IRScene`            | `@retikz/core`    | JSON-serializable drawing contract with no React element, hook, or DOM                         |
| `compileToScene`     | `@retikz/core`    | Process composites; resolve registries, references, geometry, layout, resources, and animation |
| `ProcessingResult`   | `@retikz/vanilla` | Return same-revision Scene, artifacts, readonly layers, and runtime metadata                   |

`Layout` injects host capabilities such as text measurement, Definition registries, and the TeX lowerer as processing compile options, but those options do not put React into IR or Scene. Passing the `ir` prop skips the JSX collector. The `artifacts` prop requests opt-in outputs, while `onArtifacts` receives immutable same-compile artifacts after the selected host publishes; notification does not trigger another compile.

The base package provides only a domain-neutral `VanillaCompileDriver` and opaque authoring sites. The default driver is run by Vanilla processing for an ordinary Core compile with no observers or readonly layers. Optional `@retikz/inspect/react` wrappers—`InspectLayout`, `InspectScope`, and `InspectPath`—interpret runtime selection and connect inspection observers to the same static or retained processing. Selection never enters `IRScene`, `IRScope`, or `IRPath`.

A `VanillaCompileDriver` may inject observers for the same compile, then resolve ordered readonly layers and extension diagnostics from the Core primary result and observer outputs. Static processing materializes the complete frame directly, while retained processing commits the primary figure and layers in one revision. The Inspect package wires into this general boundary; the base React package imports no Inspector definitions, palette, or selection logic. See [`@retikz/inspect`](/kernel/packages/extension/inspect) for the complete setup.

## After Scene

Scene no longer contains React component semantics. Vanilla processing obtains the result for a retained or static revision, while `@retikz/react` only subscribes to and hosts that result through React:

| Target | `@retikz/vanilla`                                                 | `@retikz/react`                                                 |
| ------ | ----------------------------------------------------------------- | --------------------------------------------------------------- |
| SVG    | Manages the processing controller, Core Program, and Scene result | Maps the result with `ProcessingResultHost` and binds hydration |
| Canvas | Manages the processing controller, Core Program, and Scene result | Maps the result with `ProcessingResultHost` to a Canvas host    |

Event handlers are functions and cannot enter JSON IR. In children mode, React separately runs `collectHydrationHandlers` to collect functions by primitive id, then binds them after rendering through SVG location or Canvas hit-testing. With the `ir` prop, the `handlers` prop supplies this runtime side channel instead.

## Responsibility boundaries

| Capability              | What `@retikz/react` owns                                             | Source of truth                    |
| ----------------------- | --------------------------------------------------------------------- | ---------------------------------- |
| JSX DSL                 | Kernel components construct Input; Sugar expands into Kernel          | `@retikz/vanilla` Input / Core IR  |
| Compilation host        | Collect children / IR, inject options, subscribe to processing result | `@retikz/vanilla` processing       |
| Rendering & interaction | Select SVG / Canvas, collect events, connect the React host           | `@retikz/render` output capability |

`@retikz/react` does not include framework-neutral Input helpers or DOM mounting. Use [`@retikz/vanilla`](/kernel/packages/framework/vanilla) outside React, for SSR strings, or for direct DOM mounting.
