这些工具不携带绘图领域语义，可被 Retikz 内部包和扩展按需复用。

## 基础用法

以下能力统一从包根入口导入：

```ts
import {
  createReadonlyMap,
  cloneAndFreezeJson,
  assertPlainDataContainers,
  parseStaticCssColor,
  compositeOpaqueColor,
} from '@retikz/foundation';

const color = compositeOpaqueColor('#336699', '#ffffff', 0.2); // '#d6e0eb'
```

## 只读集合快照

`createReadonlyMap(entries)` 将输入条目复制为独立的浅快照。结果保持原生 Map 的查询、迭代和插入顺序，但不暴露 `set`、`delete` 或 `clear`；entry value 保持原对象身份，不会被深拷贝或冻结。

```ts
const definition = { kind: 'point' };
const source = new Map([['point', definition]]);
const definitions = createReadonlyMap(source);

source.clear();
definitions.has('point'); // true
```

## JSON 数据快照

`cloneAndFreezeJson(value, path)` 校验 JSON-safe plain data，并返回与原输入脱离的深冻结副本。循环引用、访问器、symbol key、稀疏数组、数组额外属性、非有限数和 class 实例都会抛出 `RetikzFoundationError`。

```ts
const snapshot = cloneAndFreezeJson({ filters: [{ field: 'age', value: 18 }] });

Object.isFrozen(snapshot); // true
Object.isFrozen(snapshot.filters); // true
```

`assertPlainDataContainers(value, path)` 只检查容器结构，不复制数据，也不读取访问器。它用于没有持久化 schema、但仍需隔离 runtime Definition 容器的边界；已有 owner schema 的 Source 输入直接消费 Zod `parse()` 结果，不再把该断言作为通用前置校验。

## 静态 CSS 颜色

`parseStaticCssColor(input)` 把无需宿主环境即可确定的 CSS color 解析为归一化 sRGB 通道 `{ r, g, b, a }`；`compositeOpaqueColor(foreground, backdrop, weight)` 则按 `0..1` 权重把静态前景色预合成到不透明背景，并返回小写 `#rrggbb`。

```ts
parseStaticCssColor('darkorange');
compositeOpaqueColor('#336699', '#ffffff', 0.2); // '#d6e0eb'
```

正常路径按下面的顺序运行：先校验权重，再解析前景与背景色，确认背景不透明后，才以 `foreground.a × weight` 作为有效 alpha 做 source-over sRGB 预合成。任一校验或解析失败都会抛出 `RetikzFoundationError`。

## 属性浅合并

用 `mergeProperties(sources, options)` 合并多个优先级层：数组从左到右，后面的属性覆盖前面的属性。返回新对象，不修改输入，也不递归合并嵌套对象。

```ts
import { mergeProperties } from '@retikz/foundation';

const options = mergeProperties<{ color?: string | null; width?: number }>(
  [{ color: 'red', width: 1 }, { width: 2 }, { color: undefined, width: 0 }],
  { shouldOverride: value => value !== undefined },
);
// { color: 'red', width: 0 }
```

`shouldOverride(value, key)` 对首次写入和后续覆盖都生效；返回 `false` 只跳过当前属性，不删除已合并的值。若还要忽略 `null`，可写 `value => value !== undefined && value !== null`；不要用真假值判断，否则会丢失 `false`、`0` 和空字符串。

默认不设策略时，属性值 `undefined` 和 `null` 都会覆盖前值；源数组中的 `undefined` 则始终跳过。仅复制自身可枚举字符串和 symbol 属性，嵌套对象与数组保留引用。因为策略可以过滤任意字段，返回类型为 `Partial<T>`，必填字段由消费方补齐。属性读取或策略回调失败会抛出 `RetikzFoundationError`，原异常保留为 `cause`。
