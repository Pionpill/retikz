title: 编译观测 · inspect
description: 为已完成的编译按需添加观测与只读辅助图层，不改变主图的语义或结果
---

`@retikz/inspect` 为已经完成的 Core 编译提供可选观测：Inspector 读取最终实例与所属者产物，再生成独立的只读辅助内容。控制点、布局边界和对齐参考线都是这种观测的具体用法。

它只解释最终结果，不修正输入、不参与布局求解，也不改变主图。普通绘图、编译和渲染不需要安装本包；没有匹配的 Inspector 时也不会创建辅助片段。

<ComponentAlert
  title="可选的绘图辅助"
  description="@retikz/inspect 不是绘图或渲染的必需依赖。它只帮助理解已经完成的图和编译结果，适合开发、调试或教学场景；通常不建议作为生产环境的常规能力。"

## 观察什么

普通曲线是主图，点和虚线是独立的辅助层。改变主图控制点会改变曲线几何；关闭检查只隐藏辅助内容，不改变曲线。这一区别也适用于节点边界、裁切和层级观测。

## 安装与使用

注册表保存可用的观测器，请求选择目标和显示选项。先用默认注册表为一条曲线开启控制点。

<DocTab value="react" label="React">
<DocSteps>
<DocStep title="导入内容">

`@retikz/inspect` 导出默认注册表工厂 `createDefaultInspectorRegistry` 和路径观测标识 `PATH_INSPECTOR_KEY`；`@retikz/inspect/react` 导出 `InspectLayout` 和 `InspectPath`，分别接入注册表和附加路径观测请求。

```tsx
import { createDefaultInspectorRegistry, PATH_INSPECTOR_KEY } from '@retikz/inspect';
import { InspectLayout, InspectPath } from '@retikz/inspect/react';
```

</DocStep>
<DocStep title="接入渲染">

React 从 `@retikz/inspect/react` 导入包装组件。`InspectLayout` 接收 registry；`InspectPath`、`InspectNode`、`InspectScope` 和 `InspectCoordinate` 分别把 request 附加到当前 Path、Node、Scope 或 Coordinate：

```tsx
import { createDefaultInspectorRegistry, PATH_INSPECTOR_KEY } from '@retikz/inspect';
import { InspectLayout, InspectPath } from '@retikz/inspect/react';
import { Step } from '@retikz/react';

const registry = createDefaultInspectorRegistry();

export const InspectExample = () => (
  <InspectLayout registry={registry}>
    <InspectPath request={{ inspector: PATH_INSPECTOR_KEY, options: { controlPoints: true, labels: true } }}>
      <Step kind="move" to={[0, 0]} />
      <Step kind="cubic" control1={[20, -30]} control2={[80, 30]} to={[100, 0]} />
    </InspectPath>
  </InspectLayout>
);
```

`InspectLayout` 在普通 Layout 运行时接入可选 inspection compile driver；`InspectPath` 保持普通 Path 的内容写法，只把 request 转成 runtime-only authoring 标记。

</DocStep>

<DocStep title="保留普通 React 组件（可选）">

需要保留现有 `Layout` / `Path` 时，使用下面的等价接法；与上面的包装组件写法二选一。

这里的 `/vanilla` 子入口提供驱动与 authoring 标记 helper，普通 React 组件也能消费；仍然用 React 编写图形。Inspect 包装组件会代为接入这些 helper。

```tsx
import { createDefaultInspectorRegistry, PATH_INSPECTOR_KEY } from '@retikz/inspect';
import { createInspectionVanillaAuthoring, createInspectionVanillaDriver } from '@retikz/inspect/vanilla';
import { Layout, Path, Step } from '@retikz/react';

const registry = createDefaultInspectorRegistry();
const compileDriver = createInspectionVanillaDriver({ registry });
const pathInspection = createInspectionVanillaAuthoring({
  inspector: PATH_INSPECTOR_KEY,
  options: { controlPoints: true, labels: true },
});

export const ConfiguredInspectExample = () => (
  <Layout compileDriver={compileDriver}>
    <Path authoring={pathInspection}>
      <Step kind="move" to={[0, 0]} />
      <Step kind="cubic" control1={[20, -30]} control2={[80, 30]} to={[100, 0]} />
    </Path>
  </Layout>
);
```

两种写法在相同配置下生成相同的观测请求与结果；包装组件只是代为完成接线。这里的配置固定，因此驱动放在组件外；若依赖 React props 或状态，在组件内用 `useMemo` 创建驱动并声明对应依赖。基础组件没有 `inspect` 属性，`authoring` 也不会写入 Core IR。

</DocStep>
</DocSteps>

<DocStep title="导入内容">

`@retikz/inspect` 导出默认注册表工厂和路径观测标识；`@retikz/inspect/vanilla` 导出 `createInspectionVanillaAuthoring` 和 `createInspectionVanillaDriver`，分别创建观测标记和接入观测能力的编译驱动。

```ts
import { createDefaultInspectorRegistry, PATH_INSPECTOR_KEY } from '@retikz/inspect';
import { createInspectionVanillaAuthoring, createInspectionVanillaDriver } from '@retikz/inspect/vanilla';
```

</DocStep>
<DocStep title="接入渲染">

Vanilla 分别创建 authoring 标记和编译驱动：前者说明当前路径需要观测，后者在普通渲染入口接入 registry 与辅助图层：

`authoring` 只附加观测请求，不改变路径几何，也不会保存进 IR。

```ts
import { createDefaultInspectorRegistry, PATH_INSPECTOR_KEY } from '@retikz/inspect';
import { createInspectionVanillaAuthoring, createInspectionVanillaDriver } from '@retikz/inspect/vanilla';
import { path, renderToSvgString, scene } from '@retikz/vanilla';

const registry = createDefaultInspectorRegistry();
const input = scene({
  children: [
    path({
      id: 'curve',
      // 将当前 authored Path 标为要观测的目标；不会进入 Core IR
      authoring: createInspectionVanillaAuthoring({
        inspector: PATH_INSPECTOR_KEY,
        options: { controlPoints: true, labels: true },
      }),
      way: [
        [0, 0],
        {
          cubic: [
            [20, -30],
            [80, 30],
          ],
        },
        [100, 0],
      ],
    }),
  ],
});

const svg = renderToSvgString(input, { compileDriver: createInspectionVanillaDriver({ registry }) });
```

</DocStep>
