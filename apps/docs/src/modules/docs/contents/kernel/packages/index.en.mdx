The packages section helps when choosing an installation entry or understanding ownership. `@retikz/core` owns domain-neutral compilation; the other packages add optional observation, hosts, geometry, and rendering around the same Core contract.

## Responsibilities

| Package              | Responsibility                              | Reach for it when                                                    |
| -------------------- | ------------------------------------------- | -------------------------------------------------------------------- |
| `@retikz/foundation` | Cross-package types, assertions, errors     | Reusing primitives or migrating imports                              |
| `@retikz/inspect`    | Selection, auxiliary content, host wiring   | Showing path controls or layout overlays                             |
| `@retikz/runtime`    | Identity, ownership, execution tracing      | Defining state ownership across revisions                            |
| `@retikz/react`      | JSX components, IR adapter, React host      | Authoring and rendering figures in React                             |
| `@retikz/vanilla`    | InputScene, processing, browser mounts, SSR | Working without React, rendering strings, or implementing an adapter |
| `@retikz/tex`        | Lower formulas into glyph paths             | Rendering mathematics inside node text                               |
| `@retikz/math`       | Pure computational geometry                 | Reusing vectors, affine, arcs, and intersections                     |
| `@retikz/render`     | Scene to SVG / Canvas and hydration         | Integrating or choosing a render backend                             |
