`@retikz/core` 定义 retikz 能表达的图形，以及这些图形如何得到布局和绘制数据。它提供可序列化的 IR、能力扩展契约，以及语义解析、坐标求值、布局和图元生成等原子阶段。

整个编译生命周期由 `@retikz/reconciler` 调度：它接收图形声明，维护编译上下文，按依赖调用 Core 的阶段，再将产物组织成 Scene。后续更新中的缓存复用和输出事务也由 Reconciler 负责。`@retikz/render` 则将 Scene 绘制到 SVG、Canvas 等后端。

本系列面向需要理解图形语义、编写扩展或接入编译过程的开发者。日常绘图可以从 React 或 Vanilla 开始，使用同一套 Core 契约。

## 职责一览

IR 是图形声明的数据形式，例如节点的位置、形状与文字，以及一条路径要连接的目标。Scene 是编译后的绘制数据，包含已布局的图元与资源。两者之间的语义和计算由以下部分承接：

| 组成                  | 职责                                                       | 何时阅读                         |
| --------------------- | ---------------------------------------------------------- | -------------------------------- |
| IR / Schema           | 定义可保存、可交换的图形声明，说明字段含义、约束和默认值   | 理解作者可以表达什么             |
| Resolve               | 结合当前上下文，展开简写、处理继承并确定下游消费的值与能力 | 追踪声明如何变成内部确定形态     |
| Definition / registry | 定义扩展能力，并按名称找到对应实现；内置与自定义共用契约   | 理解形状、路径或复合组件如何接入 |
| 原子编译阶段          | 计算布局与几何，生成图元及供后续阶段消费的产物             | 理解节点、路径和作用域如何处理   |
| Scene / Primitive     | 定义后端中立的场景、图元与资源契约                         | 理解结果如何交给渲染器           |

Definition 描述一种能力的实现契约，例如形状如何参与尺寸计算和绘制；registry 保存按名称索引的定义。IR 中记录的是可序列化的声明，扩展实现则通过编译选项等运行时接线提供。

处理这张图时，Reconciler 根据依赖安排阶段执行。Core 解析节点配置，结合文字度量和形状定义计算布局；有了节点边界，路径阶段才能求出连接端点并生成绘制图元。图中指定了节点的最小尺寸，便于看清边界与连线的关系。

Reconciler 将这些产物组织成 Scene，Render 再消费 Scene。图元是结构化绘制数据，例如矩形、文字和路径命令；同一份 Scene 可以由不同渲染后端消费。完整的阶段衔接见[编译流程](/kernel/packages/core/compilation)。

## 安装与使用

若要直接声明 IR 并执行编译，需要 Core 的类型与 Reconciler 的执行入口：

<PackageManagerInstall packages="@retikz/core @retikz/reconciler" />

从 Core 导入 `IRScene` 声明场景，从 Reconciler 导入 `SceneReconciler` 执行。下面只进行一次完整编译，通过 `incremental: false` 关闭后续增量更新所需的状态保留。`mount(ir)` 建立会话的首次结果，`compilation.result.scene` 是可交给渲染器的 Scene。

```ts
import type { IRScene } from '@retikz/core';
import { SceneReconciler } from '@retikz/reconciler';

const ir: IRScene = {
  type: 'scene',
  version: 1,
  children: [
    { type: 'node', id: 'A', position: [0, 0], text: 'A' },
    { type: 'node', id: 'B', position: [180, 0], text: 'B' },
    {
      type: 'path',
      children: [
        { type: 'step', kind: 'move', to: { id: 'A' } },
        { type: 'step', kind: 'line', to: { id: 'B' } },
      ],
    },
  ],
};

const reconciler = new SceneReconciler({}, { incremental: false });

try {
  const { compilation } = reconciler.mount(ir);
  console.log(compilation.result.scene);
} finally {
  reconciler.dispose();
}
```

这段代码在控制台输出绘制数据；绘制画面还需要接入渲染器。示例中的节点采用默认布局，前面的插图则指定了最小尺寸。

来自 JSON 等外部输入的数据应先通过对应 Schema 校验。类型明确的 TypeScript 声明可以直接传入；文字测量和扩展定义等能力通过编译选项接入。有关字段含义与内部确定形态的说明，将沿着本系列的语义解析主线展开。

## 包边界

选择扩展位置时，先看需要改变的是绘图表达、执行过程还是后端呈现：

| 需要处理的问题                                         | 负责方                                |
| ------------------------------------------------------ | ------------------------------------- |
| IR 字段、绘图语义、能力定义、布局与图元计算            | Core                                  |
| 完整与增量编译、树遍历、上下文生命周期、缓存及输出事务 | Reconciler                            |
| SVG / Canvas 绘制及后端资源                            | Render                                |
| React 组件或 Vanilla 编写入口、输入组织与宿主接线      | React / Vanilla                       |
| 通用计算几何与基础数学                                 | Math                                  |
| Plot、Table 等领域声明与领域逻辑                       | 对应领域包，通过 Composite 等契约接入 |

Core 的阶段接收当前操作需要的输入与能力上下文，返回对应产物。何时执行阶段、某份产物是否可以跨次复用，以及何时向输出目标提交，由 Reconciler 决定。
