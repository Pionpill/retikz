图形声明可以写“连接 A 和 B”，但渲染器需要知道线段从哪里开始、在哪里结束。`@retikz/core` 负责解析这些声明，计算节点布局、坐标和路径，将结果组织成不绑定渲染后端的 Scene。

本包面向编写领域组件、扩展能力或接入编译器的开发者。普通绘图通常从 React 或 Vanilla 入口开始，由适配层组织 Core 输入，再将编译结果交给渲染器。

## 职责一览

以两个节点 A、B 和一条连线为例：输入保存节点的位置、文字及连线目标，Core 求出节点边界和连接端点，最终输出可绘制的图元。

| 对象                  | 职责                                     | 双节点示例                                   |
| --------------------- | ---------------------------------------- | -------------------------------------------- |
| IR                    | 保存可序列化的图形声明                   | 声明 A、B 及引用它们的路径                   |
| Definition / registry | 定义并绑定形状、路径种类、复合组件等能力 | 查找节点形状与路径处理能力                   |
| 编译器                | 解析配置、完成布局、求解坐标与路径       | 根据节点边界确定连线端点                     |
| Scene                 | 保存已确定的图元、资源与画布等绘制信息   | 矩形、文字和连接线的绘制数据                 |
| CompileResult         | 汇总场景、附加产物与空间句柄             | 向渲染器交付 Scene，向其他消费方提供所需数据 |

IR 描述作者希望画什么，Scene 保存编译后怎样绘制。Definition 是能力的定义，registry 负责按名称查找这些定义；内置能力与自定义能力通过对应契约参与编译。

Core 先解析节点的样式和形状，结合文字度量确定尺寸，再解析引用它们的路径。即使连线声明写在节点前面，也可以在节点布局完成后回填端点。编译完成后，SVG 与 Canvas 渲染器消费同一套 Scene 契约。

图中为节点指定了最小尺寸，便于观察连接边界；完整输入及处理顺序见[编译流程](/kernel/packages/core/compilation)。

## 安装与使用

<PackageManagerInstall packages="@retikz/core" />

声明图形时使用 Core 的 `IRScene` 等 IR 类型；处理编译后的路径命令时使用 Core 的 `PathCommand`。纯坐标和向量类型 `Position`、`Vector2` 从 `@retikz/math` 导入。

Core 提供无框架差异的 TypeScript 编译入口。下面使用同样的 A、B 连线关系，节点尺寸采用默认布局：

```ts
import { compileToScene, type IRScene } from '@retikz/core';

const ir: IRScene = {
  type: 'scene',
  version: 1,
  children: [
    {
      type: 'path',
      children: [
        { type: 'step', kind: 'move', to: { id: 'A' } },
        { type: 'step', kind: 'line', to: { id: 'B' } },
      ],
    },
    { type: 'node', id: 'A', position: [0, 0], text: 'A' },
    { type: 'node', id: 'B', position: [180, 0], text: 'B' },
  ],
};

const result = compileToScene(ir);
console.log(result.scene);
```

`compileToScene` 同步返回 `CompileResult`。其中 `scene` 可交给渲染器；`artifacts` 与 `spatialHandles` 分别承载附加产物和空间句柄，具体内容见[编译产物](/kernel/packages/core/compilation-output)。这次调用只完成编译，画面绘制由 Render 或适配层继续完成。

入口接收已类型化的 IR。来自 JSON 等外部输入的数据应先经过对应 schema 校验；文字测量、公式处理和扩展定义等能力可通过编译选项接入。

## 包边界

| Core 负责                          | 协作方负责                                          |
| ---------------------------------- | --------------------------------------------------- |
| 核心 IR、Definition 与扩展契约     | React / Vanilla 提供作者侧 API 并组织输入           |
| 配置解析、节点布局、坐标与路径求解 | Math 提供基础计算；宿主提供文字度量等能力           |
| 编译 Scene、汇总资源和其他产物     | Render 将 Scene 绘制为 SVG、Canvas 等输出           |
| 提供单次编译结果与可选来源信息     | Reconciler 负责增量复用，Runtime 管理事务与一致发布 |
| 提供编译观测输出                   | Inspect 消费观测并生成检查辅助图形                  |

本系列从一次编译的输入讲到最终产物。后续输入变化怎样经 Runtime、Reconciler、Core 和 Render 更新画面，属于跨包的动态更新专题；Runtime 的状态与事务机制见[增量执行](/kernel/packages/runtime)。
