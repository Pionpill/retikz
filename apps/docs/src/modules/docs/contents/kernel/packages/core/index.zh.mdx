`@retikz/core` 拥有 IR、Definition、registry、编译与 Scene 语义。`compileToScene()` 仍是无状态的完整编译入口；需要跨 revision 管理状态时，`CoreOwnerDefinition` 与 `createCoreProgram()` 把同一编译语义接入 `@retikz/runtime`。

## Theme 环境

Core 公开 `ThemeStyle`、`ThemeMode`、`ThemeSchema` 与 `ResolvedTheme`。`IRScene.theme` 和 `IRScope.theme` 是稀疏、JSON-safe 的覆盖；compile 从 `neutral + light` 开始按 Scene → Scope 逐字段继承，并把完整只读值传给 `CompositeDefinition.expand` 与布局感知 `compile`。

Theme 只是一条 Composite 环境通道。领域包和第三方 Composite 拥有自己的 token / palette 映射；Core primitive、最终 Scene 与 renderer 都不按 Theme 分支。契约和失败语义见[编译](/kernel/reference/runtime/compile#composite)，schema 见[场景](/kernel/reference/schema/scene#theme)。

## 完整 Snapshot 与 Core Program

调用方始终提交完整 IR Snapshot。Core owner 负责复制、冻结和比较文档；Core Program 读取 typed Snapshot，产生完整 `CompileResult`、`SceneRuntimeSnapshot` 与可选 `ScenePatch`，最后由 Runtime Session 原子发布。

Runtime 不解释 Node、Path、Scope、Composite 或 Scene。领域 identity、编译诊断和 full-fallback `replaceScene` Patch 都由 Core 决定；Runtime 只约束依赖顺序、candidate 隔离、revision 与发布。

## 基础接线

`CoreOwnerDefinition` 和 `createCoreProgram()` 都是普通 Runtime Definition，可以与其它领域 Owner / Program 注册到同一个 Session。初始 full run 的 `patch` 为 `undefined`，renderer 从完整 `snapshot` mount。

```ts
import { CORE_OWNER_KEY, CORE_PROGRAM_ID, CoreOwnerDefinition, createCoreProgram } from '@retikz/core';
import {
  createRuntimeOwnerInput,
  createRuntimeOwnerRegistry,
  createRuntimeProgramRegistry,
  createRuntimeSession,
} from '@retikz/runtime';

const ir = {
  version: 1,
  type: 'scene',
  children: [{ type: 'node', id: 'hello', position: [0, 0], text: 'Hello' }],
} as const;

const coreProgram = createCoreProgram({ padding: 16 });
const owners = createRuntimeOwnerRegistry({ builtins: [CoreOwnerDefinition] });
const programs = createRuntimeProgramRegistry({ owners, builtins: [coreProgram] });
const session = createRuntimeSession({
  owners,
  programs,
  initialSnapshots: [createRuntimeOwnerInput(CoreOwnerDefinition, ir)],
});

const { output, snapshot, patch } = session.artifact(coreProgram).value;
// output.result: 完整 CompileResult
// snapshot.revision: 0
// patch: undefined
```

固定 identity 为 `CORE_OWNER_KEY = '@retikz/core/document'` 与 `CORE_PROGRAM_ID = { owner: CORE_OWNER_KEY, key: 'compile' }`。调用方不应复制字符串另建平行 owner。

## Artifact 契约

| 字段                 | 作用                                                                                            |
| -------------------- | ----------------------------------------------------------------------------------------------- |
| `output.result`      | 与同一 IR/options 下 fresh `compileToScene()` 等价的 Scene、typed artifacts 与 inspection plane |
| `output.diagnostics` | canonical 顺序的 Core compile warnings；只在成功 commit 后派发给 `onWarn`                       |
| `snapshot`           | 当前 Session revision 的 deeply immutable Scene、document root identity 与 topology             |
| `patch`              | 相对 base revision 的原子 Scene Patch；initial full run 不提供                                  |

`CompileOptions.inspection` 是仅在运行时存在的 authored sidecar。Core 先用 locator 的 `target` 精确绑定 Composite 或 Path occurrence，再从对应 `CompositeDefinition` / `PathKindDefinition` 读取 Inspector；Inspector 仍依附原 Definition，不建立第二张注册表。生成的 `CompileResult.inspection` 与主 Scene 隔离，不进入 Snapshot identity、主资源、layout bounds 或 Patch diff。Program full fallback 时仍在同一 revision 重新生成主 Scene、artifacts 与 inspection plane。

Core 先稳定排序最终请求，再从 `0` 连续分配 `colorScope`，并通过 `InspectionAppearance` 把推荐的常规色与警告色传给 Inspector。被丢弃的 probe 不占号；已执行但返回空数组的请求占号但不形成 entry，因此后续 occurrence 的颜色不受前一项输出数量影响。

`InspectorDefinition.inspect()` 返回一个普通 `IRChild` 或稠密 `ReadonlyArray<IRChild>`，没有 `outputSchema`。Core 为每个 entry 在隔离环境中复用正常 child 编译流程、当前 Theme / Scope 样式和 provider definitions，再把结果封装为 occurrence-local 的静态 `scene`；seal 后不保留公共 `id`、`meta` 或动画，entry 内资源仍可正常引用。自定义 Composite 与 Path kind 因而可以使用 Node、Path、Coordinate、Scope 或已注册 Composite 表达辅助内容，Render 无需理解 Inspector 专用图元。

初始运行执行完整编译。update 无法安全局部证明时，Program 会 full fallback，并在 `patch.operations` 中发布唯一的 `replaceScene`；调用方仍只消费同一个 Snapshot / Patch envelope，不需要切换协议。

Core 会把可选 ChangeSet 与 previous / next 完整 Snapshot 交叉校验。Scene 根和 stable entity 的每一项自身 value 变化都必须由唯一 `update` hint 恰好覆盖；add/remove/move 必须完整解释所属 parent 的 next identity 集合与顺序，`parent` / `before` 指向 next 的最终位置。

document root 的 identity path 是 `['root']`。每个拥有唯一非空 `id` 的普通 child 追加 `[type, id]`；有 `id` 的 Scope 继续作为 parent boundary 递归索引后代，因此 Scope 内 Node 可以形成 `['root', 'scope', scopeId, 'node', nodeId]`。`localNamespace` 只改变引用 frame，不改变这条 identity path；实体跨 Scope 移动时旧、新 path 不同，使用 remove + add，而不是保留旧 identity 的 move。Scope add/remove 不级联，每个 stable descendant 都必须由自己的 hint 单独覆盖。

结构 hint 按集合校验，ChangeSet 数组顺序不是 Patch 执行顺序，每个 parent 内的 move 集合必须构成最小重排。anonymous、同 parent duplicate、Composite、漏报、多余 hint、错误 parent / before 或无法重建 next sibling order 都会被判定为不匹配。

当前局部增量路径先覆盖一个可证明安全的闭环：root 只含 unique-id、绝对 tuple position 的 Node，结构与顺序不变，只有一个 Node 的纯色 `fill` string 变化，并且没有自定义 shape、资源、artifact 或 compile warning。Program 只重编该 Node contribution，复用其它 committed root contribution，并以一个 emitted-subtree `update` operation 发布 Patch；输出仍与 fresh `compileToScene()` 等价。引用、资源、自定义 shape、Scope、Composite、多 owner 变化或其它无法局部证明的场景继续 full fallback。

不匹配时，`CORE_CHANGESET_MISMATCH` 只作为 Runtime diagnostic 在 fallback 成功 commit 后发布一次，不进入 `output.diagnostics` 或 `onWarn`。fallback compile 失败时不会发布该 diagnostic，也不会推进 revision 或替换 committed artifact。

Core Program 的 private read 保存下一次 update 使用的 immutable source Snapshot 与 stable identity index；已提交的完整 Scene Snapshot 同时作为安全子集的 contribution cache。dependency Program、participant 与 `session.artifact()` 只能看到上表中的 public read，不会取得 source/index 私有状态。

## 不可变 Program options

`createCoreProgram(options, runtimeOptions?)` 在 factory 调用时复制 option record、registry array 与 Definition record，并固定 callback reference。之后修改原数组或 Definition 字段不会改变已创建 Program。

普通 measurer、lowerer、provider callback 或 option 变化仍要求销毁旧 Session，再用新 options 创建 Program。若固定 Definition 的 callback 会读取一份可变外部状态，可把该状态建模成 Runtime owner，并通过 `runtimeOptions.invalidationOwners` 声明为额外失效依赖；owner value 只触发 Core Program 重算，不进入 IR 或 Scene。

`invalidationOwners` 不会替换固定 Definition topology，也不会自动更新 callback reference。新 Program 的第一轮总是 full run；`trace` 由 Runtime Program context 统一注入，因此不属于 `CoreProgramOptions`。

同一个失效 owner 必须同时进入 owner registry、Program runtime options、初始 Snapshot，以及状态变化时的 update transaction：

```ts
import { CoreOwnerDefinition, createCoreProgram } from '@retikz/core';
import {
  createRuntimeOwnerInput,
  createRuntimeOwnerRegistry,
  createRuntimeOwnerUpdate,
  createRuntimeProgramRegistry,
  createRuntimeSession,
  defineRuntimeOwner,
} from '@retikz/runtime';

const MeasureRevisionOwner = defineRuntimeOwner({
  key: 'app:measure-revision',
  value: {
    capture: value => value,
    read: value => value,
    equals: Object.is,
  },
});

const coreProgram = createCoreProgram({}, { invalidationOwners: [MeasureRevisionOwner] });
const owners = createRuntimeOwnerRegistry({ builtins: [CoreOwnerDefinition, MeasureRevisionOwner] });
const programs = createRuntimeProgramRegistry({ owners, builtins: [coreProgram] });
const session = createRuntimeSession({
  owners,
  programs,
  initialSnapshots: [
    createRuntimeOwnerInput(CoreOwnerDefinition, ir),
    createRuntimeOwnerInput(MeasureRevisionOwner, 0),
  ],
});

session.update({
  baseRevision: session.revision(),
  owners: [createRuntimeOwnerUpdate(MeasureRevisionOwner, 1)],
});
```

## 公开 API

| 导出                                                   | 作用                                                          |
| ------------------------------------------------------ | ------------------------------------------------------------- |
| `CORE_OWNER_KEY` / `CORE_PROGRAM_ID`                   | Core document owner 与 compile Program 的固定 identity        |
| `CoreOwnerDefinition`                                  | 完整 IR Snapshot 的 capture/read/equality Definition          |
| `ThemeStyle` / `ThemeMode` / `ThemeSchema`             | 闭合 Theme 词汇、严格 IR schema 与 Scene / Scope 继承入口     |
| `IRTheme` / `ResolvedTheme`                            | 稀疏持久化覆盖与 Composite 收到的完整只读环境                 |
| `createCoreProgram(options, runtimeOptions?)`          | 创建保留 composite artifact 泛型的 Runtime Program Definition |
| `CoreChange`                                           | `add` / `update` / `remove` / `move` change hint union        |
| `CoreProgramOptions<TComposites>`                      | `CompileOptions` 去掉 `trace` 后的 Program 生命周期配置       |
| `CoreProgramRuntimeOptions`                            | 声明只负责失效、不进入 IR / Scene 的额外 Runtime owners       |
| `CoreProgramOutput<TComposites>`                       | 完整 compile result 与 warnings                               |
| `CoreProgramPublicRead<TComposites>`                   | public `output` / `snapshot` / optional `patch`               |
| `CoreProgramDefinition<TComposites>`                   | 保留 artifact input、owned artifact、private/public read 泛型 |
| `RuntimeScene` / `SceneRuntimeSnapshot` / `ScenePatch` | deeply readonly Scene 与原子 Patch DTO                        |
| `InspectOptions` / `CompileInspectionOptions`          | Layout / Scope 级联策略与 compile authored sidecar            |
| `InspectionPlane` / `InspectionPlaneEntry`             | 与主 Scene 隔离、每项携带普通静态 `scene` 的辅助平面          |
| `InspectorDefinition` / `defineInspector`              | owner-neutral 的 Inspector 契约与定义 helper                  |
| `InspectorOutput` / `InspectorContext`                 | 普通 Core 子元素输出与 canonical options / appearance 上下文  |
| `InspectionAppearance` / `InspectionOwner`             | Core 解析的 occurrence 外观与 Definition owner 身份           |
| `PathInspectionAuthoring` / `PathInspectOptions`       | React / Vanilla Path 的 occurrence-local 运行时开启参数       |
