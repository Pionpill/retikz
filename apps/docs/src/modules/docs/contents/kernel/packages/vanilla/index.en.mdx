`@retikz/vanilla` is the framework-free entry. You can describe a figure with a plain spec, or pass Core IR or a compiled `Scene` directly, then produce output through SSR, the SVG DOM, or the Canvas runtime.

It owns plain-data authoring, input adaptation, and host lifecycles without inventing new drawing semantics. IR, schemas, geometry, and compilation belong to `@retikz/core`; backend execution belongs to `@retikz/render`.

## Installation & Usage

```bash
pnpm add @retikz/vanilla
```

```ts
import { figure, layer, mount, node, path, renderToSvgString } from '@retikz/vanilla';

const spec = figure({
  id: 'flow',
  layers: [
    layer('main', [
      node('a', { position: [0, 0], text: 'A' }),
      node('b', { position: [120, 0], text: 'B' }),
      path('edge', {
        way: ['a', 'b'],
        marks: [{ pos: 1, mark: { kind: 'arrow' } }],
      }),
    ]),
  ],
});

const svg = renderToSvgString(spec);
const view = mount(document.querySelector('#diagram')!, spec);
```

`renderToSvgString` does not depend on the DOM, so it works for SSR, build-time generation, or saving SVG. `mount` targets browser hosts, creates SVG by default, and can switch to Canvas with `renderer: 'canvas'`. The returned view owns later updates, interaction hydration, animation controls, and disposal.

## Why @retikz/vanilla Exists

### Authoring With Plain Data

Constructing `@retikz/core` IR directly is valid, but applications often also need layers, stable identities, Tier 2 embeds, and runtime metadata. `figure`, `layer`, `node`, `path`, `scope`, and `embed` express those structures with ordinary objects and functions, without JSX, a React runtime, or component lifecycles. This fits servers, build scripts, native DOM applications, and other non-React hosts.

These helpers only reduce construction overhead. `node`, `path`, and the other primitives still produce Core graphics, while a plain spec must normalize into the same Core IR. It is not a second IR parallel to Core. The final Core IR remains JSON-serializable; callers and adapters are responsible for keeping `embed.props` serializable when that property matters to their workflow.

### Why Specs And Runtime Stay Separate

A spec only describes what to draw. It does not retain a DOM node, Canvas, clock, or `update` method; `mount` returns a view that manages host state. The same spec can therefore produce an SSR string, mount in a browser, or pass through `normalizeFigureSpec` for inspection before rendering.

This separation keeps authoring data easy to generate, compare, and test while concentrating side effects at the runtime boundary. Vanilla is thin in graphics semantics, not in host wiring: it still owns DOM materialization, Canvas redraws, hydration, and animation lifecycles.

## From Spec To Scene

`@retikz/vanilla` accepts three input levels. Blue nodes in the figure belong to Vanilla authoring and adaptation; orange nodes are the data contract and compiler owned by Core. Concrete backends begin after `Scene`.

<ComponentPreview files="vanilla-pipeline" size="xs" hideCode />

| Input          | Owner             | Runtime handling                                                                  |
| -------------- | ----------------- | --------------------------------------------------------------------------------- |
| plain spec     | `@retikz/vanilla` | Normalize layers, embeds, and metadata, then compile/update in a retained Session |
| Core `IRScene` | `@retikz/core`    | Skip spec normalization, then compile/update in a retained Session                |
| `Scene`        | `@retikz/core`    | Skip normalization and compilation, creating a full-redraw static view            |

The plain-spec path first uses `normalizeFigureSpec` to produce Core IR. The Core Program then resolves composites, registries, references, geometry, layout, resources, and animation. `renderToSvgString` and static mounts of a precompiled `Scene` use `toSceneResult` for one-shot compilation / dispatch. Retained mounts of IR or a plain spec instead use `createVanillaRetainedSession → prepareRetainedInput` to create an updateable Core + Render Session. Both paths ultimately consume the same Core Scene and Render backends rather than defining parallel graphics semantics.

## Runtime & Performance Boundaries

| API                 | Purpose                                   | Returns                      |
| ------------------- | ----------------------------------------- | ---------------------------- |
| `renderToSvgString` | Produce an `<svg>` string for SSR         | `string`                     |
| `mount`             | Mount SVG or Canvas by `renderer`         | `VanillaView` / `CanvasView` |
| `mountSvg`          | Mount an SVG DOM explicitly               | `VanillaView`                |
| `mountCanvas`       | Mount a Canvas explicitly                 | `CanvasView`                 |
| `hydrate`           | Bind handlers to SSR / existing SVG roots | `HydrationHandle`            |

`mountSvg` / `mountCanvas` return a view discriminated by `mode` or `VanillaViewMode`. IR and plain specs create a `VanillaViewMode.Retained` view: `update(next, options?)` places the complete input and mutable renderer config in one transaction. Core publishes a Scene Patch or full fallback, and the Render participant atomically replaces DOM / bitmap, artifacts, runtime metadata, events, and animation handles only after success. A failed transaction publishes no new revision. The old view remains usable when rollback succeeds; if rollback itself fails, the Session becomes broken and must be disposed and remounted.

A precompiled `Scene` creates a `VanillaViewMode.Static` view. `update(nextScene)` preserves root identity but fully redraws the backend; there is no Core Program, Patch, Runtime diagnostics, or compile artifacts. Pass IR / a plain spec and enable `nodeLayouts` under `compile.artifacts` when Node layout outputs are needed.

When upgrading, keep `update(next)` for an IR / plain-spec view at the same IR or plain-spec input layer. To retain full-redraw `Scene → Scene` updates, mount a precompiled `Scene` to create a static view instead. Dispose and remount when changing DPR or compile topology.

`diagnostics()` on a retained view returns and drains Runtime diagnostics in queue order. `runtimeMeta` is a deeply immutable snapshot: layers, `childIds`, identity paths, and readonly indexes do not alias internal transaction state. `hydrate()` reads the latest committed Scene, so callers do not rebind after every update.

The SVG retained renderer preserves unchanged DOM identity. Canvas updates a dirty region for safe local changes and otherwise takes the full fallback. Concurrent scheduling and progressive materialization are not part of the current public contract.

## Options Shape

Render options are grouped by the stage that consumes them:

```ts
renderToSvgString(spec, {
  output: { width: 640, height: 360, idPrefix: 'flow' },
  compile: { composites, measureText },
  animation: { enabled: true },
});

mount(canvasRoot, spec, {
  renderer: 'canvas',
  output: { width: 640, height: 360 },
  canvas: { devicePixelRatio: 2 },
  runtime: { rendererFactory },
});
```

`figure()` only describes the figure. `output` controls display size and resource ids, `compile` injects Core compile capabilities, `animation` controls playback or snapshots, `canvas` is only for Canvas mounts, and `runtime.rendererFactory` replaces the built-in factory only for retained IR / plain-spec mounts. `RenderToStringOptions` has no `runtime` field, so SSR neither accepts nor silently ignores a retained renderer factory.

Omit `animation.enabled` to follow the system's reduced-motion preference. Explicit `true` forces playback on, and explicit `false` forces it off. `snapshotAt` still overrides playback and produces a static frame.

Retained `update()` accepts only backend-matched closed plain-data options. SVG `RetainedSvgUpdateOptions` contains only top-level `animation`; Canvas `RetainedCanvasUpdateOptions` additionally accepts `canvas.animationProperties`. `devicePixelRatio` is fixed at mount. Passing Canvas-only config to SVG, hot DPR changes, unknown fields, symbols, and accessors throw stable `RETAINED_RUNTIME_INPUT_INVALID`; dispose and remount to change DPR or compile capabilities.

## Layers And Embeds

`figure({ children })` creates a default layer. Use explicit `layers` when you need draw ordering, stable layer ids, or future invalidation hints. `zIndex` only orders the layer stack, with equal values retaining declaration order. `cache` only enters runtime metadata and does not enter Core IR. Alpha.2 folds it into a retained-config hint, but the SVG and Canvas renderers do not consume it yet and do not enable auto, static, or dynamic layer reuse from it.

Tier 2 capabilities enter through `embed(kind, id, props)`. Vanilla does not parse components or run hooks. It finds an injected adapter by `kind` and statically lowers props into a Core IR child, datasets, and composite definitions.

```ts
import type { VanillaTier2Adapter } from '@retikz/vanilla';
import { embed, figure, layer, node, renderToSvgString } from '@retikz/vanilla';

type BadgeProps = { label: string };

const badgeAdapter: VanillaTier2Adapter<BadgeProps> = {
  kind: 'badge',
  namespace: 'badge',
  lower: (props, context) => ({
    node: node(`${context.id}/label`, { position: [0, 0], text: props.label }),
    datasets: {},
    makeComposites: () => [],
  }),
};

const spec = figure({
  layers: [layer('content', [embed('badge', 'sales', { label: 'Sales' })])],
});

const svg = renderToSvgString(spec, { adapters: [badgeAdapter] });
```

`normalizeFigureSpec` is exported from the package root. `adapters` is a top-level render / mount option, not a field inside `compile`. To inspect normalization before rendering, call `normalizeFigureSpec(spec, { adapters })` directly and read its `ir`, `composites`, and `runtimeMeta` result.

A plain-spec retained update may replace the callback behind the same composite key, schema, and execution branch, committing or rolling it back with the Scene transaction. Definition count, order, key, schema, expand / compile branch, and artifact schema form fixed topology; dispose and remount to change them.

## Responsibility Boundaries

| Capability           | What `@retikz/vanilla` owns                                                    | Source of truth / boundary              |
| -------------------- | ------------------------------------------------------------------------------ | --------------------------------------- |
| Plain-data authoring | figure, layer, embed, Core primitive helpers, and spec normalization           | `@retikz/core` IR                       |
| Compile entry        | Accept spec / IR / Scene, aggregate adapter contributions, inject options      | `@retikz/core` compilation              |
| Host runtime         | SSR strings, DOM / Canvas mounting, update, hydration, and animation lifecycle | `@retikz/render` backend execution      |
| Tier 2 embeds        | Dispatch adapters by `kind` and aggregate lowering contributions               | Each domain package owns props/lowering |

Prefer [`@retikz/react`](/kernel/packages/react) for JSX authoring and React host lifecycles. Use this package for framework-free authoring, SSR strings, or direct DOM / Canvas mounting.

| `RetainedSvgUpdateOptions`    | type          | Animation config for SVG retained updates                           |
| `RetainedCanvasUpdateOptions` | type          | Animation and property config for Canvas retained updates           |
