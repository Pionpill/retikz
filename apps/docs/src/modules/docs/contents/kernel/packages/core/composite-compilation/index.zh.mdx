前面几篇介绍了坐标、节点、路径与 Scope 的编译。Composite 在这些能力之上接入领域声明：Definition 生成普通子项，或借助布局提案与试算选择布局结果，再接回同一编译链。本篇重点说明子项生成、布局协作和结果提交。

## 整体流程

领域声明先绑定定义并解析为 <ApiSourceLink label="CompositeResolution" path="packages/kernel/core/src/resolve/composite/types.ts" startLine={41}>`CompositeResolution`</ApiSourceLink>。回调返回 <ApiSourceLink label="CompositeEvaluationResult" path="packages/kernel/core/src/contract/composite/layout.ts" startLine={247}>`CompositeEvaluationResult`</ApiSourceLink>，完整布局的 <ApiSourceLink label="CompositeCompileResult" path="packages/kernel/core/src/contract/composite/layout.ts" startLine={309}>`CompositeCompileResult`</ApiSourceLink> 再交给子项编译或选中结果提交。

## 输入契约

Composite 的公共 IR 由 <ApiSourceLink label="CompositeNodeSchema" path="packages/kernel/core/src/schemas/scene/composite.ts" startLine={14}>`CompositeNodeSchema`</ApiSourceLink> 接收：`namespace` 与 `type` 都是非空字符串，其余字段必须是 JSON 值。选中定义后，再用 `CompositeDefinition.schema` 解释该领域的完整输入，所以输入形式由定义自身决定。

| 输入层      | 形式                                                                                                                                                                                    | 对后续处理的影响                                                    |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| 公共声明    | `{ namespace, type, ...领域字段 }`                                                                                                                                                      | 先按 namespace / type 查找定义，确定该用哪份 Schema 和 compile 回调 |
| 领域 Schema | 定义提供的对象、字段和分支                                                                                                                                                              | 解析默认值及领域参数，产物作为回调的首个参数                        |
| 运行时绑定  | <ApiSourceLink label="CompositeBoundChild" path="packages/kernel/core/src/contract/composite/input.ts" startLine={27}>`CompositeBoundChild`</ApiSourceLink> 与绑定输入契约              | 函数或宿主对象通过回调上下文传入，与持久化 JSON 声明分开            |
| 编译请求    | <ApiSourceLink label="CompositeEvaluation" path="packages/kernel/core/src/contract/composite/layout.ts" startLine={226}>`CompositeEvaluation`</ApiSourceLink> 的 layout 或 contribution | layout 请求完整子项；contribution 请求指定轴的布局尺寸              |

例如 pair 定义可接收 `{ namespace: 'example', type: 'pair', gap: 24 }`，Schema 给 `gap` 设置默认值后，回调用该值生成两个节点。需要先知道子项尺寸的定义则使用编译上下文提供的布局服务。

## 解析过程

函数 <ApiSourceLink label="bindComposite" path="packages/kernel/core/src/resolve/composite/resolve.ts" startLine={8}>`bindComposite`</ApiSourceLink> 按完整键选择定义，返回 <ApiSourceLink label="CompositeBinding" path="packages/kernel/core/src/resolve/composite/types.ts" startLine={8}>`CompositeBinding`</ApiSourceLink>。注册成功的分支交给 <ApiSourceLink label="resolveComposite" path="packages/kernel/core/src/resolve/composite/resolve.ts" startLine={30}>`resolveComposite`</ApiSourceLink>，用该定义的 Schema 解析 source，得到 <ApiSourceLink label="CompositeResolution" path="packages/kernel/core/src/resolve/composite/types.ts" startLine={41}>`CompositeResolution`</ApiSourceLink>。这是 Composite 在本阶段的真实产物名称；领域解析结果保存在 `node` 中。下面保留完整字段，省略源码注释。

```ts
export type CompositeBinding =
  | Readonly<{
      kind: 'unregistered';
      key: string;
    }>
  | Readonly<{
      kind: 'compile';
      key: string;
      namespace: string;
      type: string;
      source: IRComposite;
      schema: ZodType;
      compile: (node: unknown, context: CompositeCompileContext) => CompositeEvaluationResult<JsonValue>;
      artifactSchema?: ZodType<JsonValue>;
    }>;

export type RegisteredCompositeBinding = Exclude<CompositeBinding, { kind: 'unregistered' }>;

export type CompositeResolution<TBinding extends RegisteredCompositeBinding = RegisteredCompositeBinding> = TBinding &
  Readonly<{
    node: unknown;
  }>;
```

解析需要 <ApiSourceLink label="CompositeRegistry" path="packages/kernel/core/src/resolve/composite/types.ts" startLine={48}>`CompositeRegistry`</ApiSourceLink> 与当前 `irPath`，而领域输入的补全规则来自定义的 Schema。绑定保存 source、schema 与 compile 的对应关系，解析后将同一份领域值交给同一定义的回调。

未注册时，绑定结果是 `kind: 'unregistered'`；普通编译收集 warning 并跳过，隔离试算则将它作为可处理的布局失败。下图展示注册成功的解析主线。

## 编译过程

类型 <ApiSourceLink label="CompositeCompiler" path="packages/kernel/reconciler/src/compile/tree/composite/compile.ts" startLine={57}>`CompositeCompiler`</ApiSourceLink> 创建 <ApiSourceLink label="CompositeCompileContext" path="packages/kernel/core/src/contract/composite/layout.ts" startLine={252}>`CompositeCompileContext`</ApiSourceLink>，调用解析结果携带的 compile 回调。回调的真实返回类型是 <ApiSourceLink label="CompositeEvaluationResult" path="packages/kernel/core/src/contract/composite/layout.ts" startLine={247}>`CompositeEvaluationResult`</ApiSourceLink>：完整布局返回 <ApiSourceLink label="CompositeCompileResult" path="packages/kernel/core/src/contract/composite/layout.ts" startLine={309}>`CompositeCompileResult`</ApiSourceLink>，按轴测量可以返回 <ApiSourceLink label="CompositeContributionResult" path="packages/kernel/core/src/contract/composite/layout.ts" startLine={231}>`CompositeContributionResult`</ApiSourceLink>。其中普通 children 继续编译，运行时句柄交给预检与提交；领域 artifact 单独汇总。下面是完整字段，省略源码注释。

```ts
export type CompositeEvaluationResult<TArtifact extends JsonValue = never> =
  CompositeCompileResult<TArtifact> | CompositeContributionResult;

export type CompositeCompileResult<TArtifact extends JsonValue = never> = Readonly<{
  children: ReadonlyArray<IRChild | CompositeCompileChild | CompositeBoundChild>;
  allocationBounds?: Readonly<BoundsRect>;
  alignmentGuides?: ReadonlyArray<LayoutAlignmentGuide>;
}> &
  ([TArtifact] extends [never] ? { artifact?: never } : { artifact?: TArtifact });

export type CompositeContributionResult = Readonly<{
  kind: 'contribution';
  contribution: LayoutContribution;
}>;
```

| <ApiSourceLink label="CompositeCompileContext" path="packages/kernel/core/src/contract/composite/layout.ts" startLine={252}>`CompositeCompileContext`</ApiSourceLink> 成员 | 编译时提供什么                                               |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| `evaluation`、`proposal`                                                                                                                                                   | 当前是完整布局还是按轴测量，以及父级槽位要求                 |
| `measureChild`、`layoutChild`                                                                                                                                              | 查询子项尺寸，或获取完整隔离布局与可重放令牌                 |
| `replay`、`createScope`                                                                                                                                                    | 选中布局结果，或构造带完整 Scope 属性的输出子项              |
| `resolvePathTargets`                                                                                                                                                       | 在指定 child 环境中查询 source 与有序目标点                  |
| `theme`、`withTheme`                                                                                                                                                       | 当前有效主题及局部主题下的测量、查询上下文                   |
| `runtimeInput`、`selectSourceChild`、`bindChild`                                                                                                                           | 读取当前运行时输入，转交作者子项绑定，或为生成的子项提供绑定 |
| `warn`、`raise`                                                                                                                                                            | 报告诊断，或重新抛出无法采用的布局失败                       |

图中重点是回调产物的交接：返回子项和选中试算结果后，调度器才预检并形成最终绘图贡献。

### 布局提案表达父级需要什么

proposal 的 x / y 分别使用 intrinsic、range 或 exact。intrinsic 查询 minimum / natural，range 给出允许的槽位范围，exact 要求固定槽位。提案描述布局分配，不能把“分配了 60”理解成“所有可见几何都被缩成 60”。

<ComponentPreview files="composite-proposal" size="lg" hideCode type="illustration" />

图中固定路径的实际 allocationBounds.width 为 100。exact 60 可产生宽 60 的 slotSize，但路径几何仍为 100；父级需要自行处理溢出、裁剪或其他排布。子项没有可行布局时，试算也可能失败。

| 结果             | 用途                                   |
| ---------------- | -------------------------------------- |
| slotSize         | 提案作用后的布局槽位尺寸               |
| allocationBounds | 子项局部坐标中的实际布局占用，保留位置 |
| visualBounds     | 最终静态图元树的保守视觉包络           |
| alignmentGuides  | 基线等可选对齐参考                     |
| replay           | 当前回调中可选中一次的完整布局结果令牌 |

### 先测量，还是完成布局

`measureChild(child, proposal, axis)` 只查询所需轴的尺寸贡献，没有 replay。上下文 evaluation 指明当前请求完整 layout 还是某个轴的 contribution；能直接计算尺寸的 Composite 可返回对应 contribution，避免为纯查询生成完整子树。

`layoutChild(child, proposal)` 进行完整隔离布局，返回 resolved / failed。成功结果包含可重放的布局；失败句柄可用于舍弃方案或通过 raise 抛出。契约错误和执行不变量等致命错误仍直接传播，不是所有错误都能当作布局备选失败。

下面的定义试算一个真实节点，再把选中的结果平移 20。节点的定义、字体、继承和引用规则仍沿普通管线执行。

```ts
import { defineComposite } from '@retikz/core';
import { z } from 'zod';

const shiftedNode = defineComposite({
  namespace: 'example',
  type: 'shiftedNode',
  schema: z.strictObject({
    namespace: z.literal('example'),
    type: z.literal('shiftedNode'),
  }),
  compile: (_, context) => {
    const probe = context.layoutChild({ type: 'node', text: 'A' }, context.proposal);
    if (probe.kind === 'failed') return context.raise(probe.failure);
    return {
      children: [
        context.replay(probe.result, {
          transforms: [{ kind: 'translate', x: 20, y: 0 }],
        }),
      ],
    };
  },
});
```

### 隔离试算与选中重放

试算使用独立的名称写入、资源、图元和诊断工作区，不把候选绘图立即写进父输出。Reconciler 保存完整事务；回调只得到不透明令牌。未选中的方案不会发布图元、名称或 warning。

`replay` 将成功结果转成当前回调拥有的输出子项。令牌不能序列化、伪造、跨回调持有或放置两次；它不是可以存进 IR 的缓存。输出先做整体预检，再提交选中的资源、引用、图元和领域产物，避免提交一半后才发现重复句柄。

普通 children 会继续编译；重放子项消费已保存的事务。外层 replay wrapper 只接收已 lowering 的数值变换和裁剪。需要完整 authored Scope 语义时使用 `createScope(props, children)`，继续经过 Scope 调度。

### 目标查询、主题和运行时输入

`resolvePathTargets` 在隔离的真实 child 环境中解析 source 与有序 points，返回局部坐标。它不提交绘图，不执行最终路径边界裁剪或插值，也不修改作者点列，适合领域路径在 lowering 前读取既有引用能力。

`withTheme` 创建局部有效主题上下文，供测量和查询使用；最终 children 仍要通过 createScope 声明相同主题边界，不能只改试算环境却让正式输出继承另一套主题。

需要函数、宿主对象等运行时输入的领域能力使用绑定输入契约，而不是把它们塞进 JSON IR。<ApiSourceLink label="CompositeBoundChild" path="packages/kernel/core/src/contract/composite/input.ts" startLine={27}>`CompositeBoundChild`</ApiSourceLink> 和 replay / Scope 输出句柄是当前回调的运行时值，不是新的持久化实体类型。

### 领域产物与失败边界

有 artifact 时，Definition 必须声明 artifactSchema。当前 Reconciler 检查 artifactSchema 已声明，并检查产物的 JSON 可序列化形态后冻结；它不会调用 artifactSchema.parse 再校验值。产物和最终绘图分别返回；领域数据不应编码成隐藏图元让调用者反向读取。allocationBounds 和 alignmentGuides 也由输出契约明确提供，不替代 Scene 的视觉边界。

普通编译遇到未注册 Composite 会警告并跳过；隔离试算中则形成可处理的失败。超过展开深度、返回不合法数据、跨回调句柄或重复 replay 属于各自的契约 / 执行失败。
