Composite 让领域包拥有高层声明，同时复用 Core 的节点、路径、Scope 与坐标机制。它不是另一套 renderer：Definition 返回可继续执行的子项，Reconciler 将它们接入同一编译链。Core 拥有绑定、Schema 与布局协作契约，回调执行和结果提交由 Reconciler 调度。

## 整体流程

IRComposite 通过 namespace / type 匹配定义，Core 按该定义的 Schema 解析输入。Reconciler 创建受限上下文，调用 compile，预检返回值，再编译普通子项或提交选中的试算结果。领域 artifact 与图元分别汇总。

最简单的 Composite 直接返回 children，如[能力定义与注册](/kernel/packages/core/definitions)中的 pair。只有父布局需要知道子项真实尺寸时，才使用下面的布局服务，不必给每个组合添加试算。

## 布局提案表达父级需要什么

proposal 的 x / y 分别使用 intrinsic、range 或 exact。intrinsic 查询 minimum / natural，range 给出允许的槽位范围，exact 要求固定槽位。提案描述布局分配，不能把“分配了 60”理解成“所有可见几何都被缩成 60”。

<ComponentPreview files="composite-proposal" size="md" hideCode type="illustration" />

图中固定路径的实际 allocationBounds.width 为 100。exact 60 可产生宽 60 的 slotSize，但路径几何仍为 100；父级需要自行处理溢出、裁剪或其他排布。子项没有可行布局时，试算也可能失败。

| 结果             | 用途                                   |
| ---------------- | -------------------------------------- |
| slotSize         | 提案作用后的布局槽位尺寸               |
| allocationBounds | 子项局部坐标中的实际布局占用，保留位置 |
| visualBounds     | 最终静态图元树的保守视觉包络           |
| alignmentGuides  | 基线等可选对齐参考                     |
| replay           | 当前回调中可选中一次的完整布局结果令牌 |

## 先测量，还是完成布局

`measureChild(child, proposal, axis)` 只查询所需轴的尺寸贡献，没有 replay。上下文 evaluation 指明当前请求完整 layout 还是某个轴的 contribution；能直接计算尺寸的 Composite 可返回对应 contribution，避免为纯查询生成完整子树。

`layoutChild(child, proposal)` 进行完整隔离布局，返回 resolved / failed。成功结果包含可重放的布局；失败句柄可用于舍弃方案或通过 raise 抛出。契约错误和执行不变量等致命错误仍直接传播，不是所有错误都能当作布局备选失败。

下面的定义试算一个真实节点，再把选中的结果平移 20。节点的定义、字体、继承和引用规则仍沿普通管线执行。

```ts
import { defineComposite } from '@retikz/core';
import { z } from 'zod';

const shiftedNode = defineComposite({
  namespace: 'example',
  type: 'shiftedNode',
  schema: z.strictObject({
    namespace: z.literal('example'),
    type: z.literal('shiftedNode'),
  }),
  compile: (_, context) => {
    const probe = context.layoutChild({ type: 'node', text: 'A' }, context.proposal);
    if (probe.kind === 'failed') return context.raise(probe.failure);
    return {
      children: [
        context.replay(probe.result, {
          transforms: [{ kind: 'translate', x: 20, y: 0 }],
        }),
      ],
    };
  },
});
```

## 隔离试算与选中重放

试算使用独立的名称写入、资源、图元和诊断工作区，不把候选绘图立即写进父输出。Reconciler 保存完整事务；回调只得到不透明令牌。未选中的方案不会发布图元、名称或 warning。

`replay` 将成功结果转成当前回调拥有的输出子项。令牌不能序列化、伪造、跨回调持有或放置两次；它不是可以存进 IR 的缓存。输出先做整体预检，再提交选中的资源、引用、图元和领域产物，避免提交一半后才发现重复句柄。

普通 children 会继续编译；重放子项消费已保存的事务。外层 replay wrapper 只接收已 lowering 的数值变换和裁剪。需要完整 authored Scope 语义时使用 `createScope(props, children)`，继续经过 Scope 调度。

## 目标查询、主题和运行时输入

`resolvePathTargets` 在隔离的真实 child 环境中解析 source 与有序 points，返回局部坐标。它不提交绘图，不执行最终路径边界裁剪或插值，也不修改作者点列，适合领域路径在 lowering 前读取既有引用能力。

`withTheme` 创建局部有效主题上下文，供测量和查询使用；最终 children 仍要通过 createScope 声明相同主题边界，不能只改试算环境却让正式输出继承另一套主题。

需要函数、宿主对象等运行时输入的领域能力使用绑定输入契约，而不是把它们塞进 JSON IR。CompositeBoundChild 和 replay / Scope 输出句柄是当前回调的运行时值，不是新的持久化实体类型。

## 领域产物与失败边界

有 artifact 时，Definition 必须声明 artifactSchema。当前 Reconciler 检查 artifactSchema 已声明，并检查产物的 JSON 可序列化形态后冻结；它不会调用 artifactSchema.parse 再校验值。产物和最终绘图分别返回；领域数据不应编码成隐藏图元让调用者反向读取。allocationBounds 和 alignmentGuides 也由输出契约明确提供，不替代 Scene 的视觉边界。

普通编译遇到未注册 Composite 会警告并跳过；隔离试算中则形成可处理的失败。超过展开深度、返回不合法数据、跨回调句柄或重复 replay 属于各自的契约 / 执行失败，不能靠静默降级掩盖。
