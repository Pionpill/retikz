The preceding pages cover coordinate, node, path and Scope compilation. Composite builds on these capabilities to support domain declarations: a Definition generates ordinary children or uses layout proposals and probes to select a layout result, then joins the same compilation chain. This page focuses on child generation, layout collaboration and result submission. Core supplies binding, Schema and layout contracts; Reconciler invokes callbacks and commits results.

## Overall Flow

A domain declaration binds a definition and resolves to <ApiSourceLink label="CompositeResolution" path="packages/kernel/core/src/resolve/composite/types.ts" startLine={41}>`CompositeResolution`</ApiSourceLink>. Its callback returns <ApiSourceLink label="CompositeEvaluationResult" path="packages/kernel/core/src/contract/composite/layout.ts" startLine={247}>`CompositeEvaluationResult`</ApiSourceLink>; a full-layout <ApiSourceLink label="CompositeCompileResult" path="packages/kernel/core/src/contract/composite/layout.ts" startLine={309}>`CompositeCompileResult`</ApiSourceLink> then feeds child compilation or selected-result commit.

## Input Contract

The type <ApiSourceLink label="CompositeNodeSchema" path="packages/kernel/core/src/schemas/scene/composite.ts" startLine={14}>`CompositeNodeSchema`</ApiSourceLink> accepts the shared IR envelope: nonblank `namespace` and `type`, with JSON values for domain fields. The selected `CompositeDefinition.schema` then interprets the complete domain input, so each definition determines its supported forms.

| Input layer        | Form                                                                                                                                                                                    | Effect on later processing                                                                |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| Shared declaration | `{ namespace, type, ...domainFields }`                                                                                                                                                  | Selects the definition, schema and compile callback by namespace and type                 |
| Domain schema      | Definition-owned fields and branches                                                                                                                                                    | Resolves domain parameters and defaults; the result becomes the callback's first argument |
| Runtime binding    | <ApiSourceLink label="CompositeBoundChild" path="packages/kernel/core/src/contract/composite/input.ts" startLine={27}>`CompositeBoundChild`</ApiSourceLink> and its input contract      | Supplies functions or host objects through context, separately from persistent JSON       |
| Evaluation request | layout or contribution in <ApiSourceLink label="CompositeEvaluation" path="packages/kernel/core/src/contract/composite/layout.ts" startLine={226}>`CompositeEvaluation`</ApiSourceLink> | layout requests children; contribution requests sizes on selected axes                    |

For example, a pair definition can accept `{ namespace: 'example', type: 'pair', gap: 24 }`. Its schema supplies a default gap, which the callback uses when generating two nodes. Definitions that need child sizes use the layout services provided by the compile context.

## Resolution

The function <ApiSourceLink label="bindComposite" path="packages/kernel/core/src/resolve/composite/resolve.ts" startLine={8}>`bindComposite`</ApiSourceLink> selects a definition by its full key and returns <ApiSourceLink label="CompositeBinding" path="packages/kernel/core/src/resolve/composite/types.ts" startLine={8}>`CompositeBinding`</ApiSourceLink>. A registered binding goes to <ApiSourceLink label="resolveComposite" path="packages/kernel/core/src/resolve/composite/resolve.ts" startLine={30}>`resolveComposite`</ApiSourceLink>, which parses source with that definition's schema and produces <ApiSourceLink label="CompositeResolution" path="packages/kernel/core/src/resolve/composite/types.ts" startLine={41}>`CompositeResolution`</ApiSourceLink>. This is the actual resolution product: its `node` holds the parsed domain value. The full declarations follow, with source comments omitted.

```ts
export type CompositeBinding =
  | Readonly<{
      kind: 'unregistered';
      key: string;
    }>
  | Readonly<{
      kind: 'compile';
      key: string;
      namespace: string;
      type: string;
      source: IRComposite;
      schema: ZodType;
      compile: (node: unknown, context: CompositeCompileContext) => CompositeEvaluationResult<JsonValue>;
      artifactSchema?: ZodType<JsonValue>;
    }>;

export type RegisteredCompositeBinding = Exclude<CompositeBinding, { kind: 'unregistered' }>;

export type CompositeResolution<TBinding extends RegisteredCompositeBinding = RegisteredCompositeBinding> = TBinding &
  Readonly<{
    node: unknown;
  }>;
```

Resolution needs <ApiSourceLink label="CompositeRegistry" path="packages/kernel/core/src/resolve/composite/types.ts" startLine={48}>`CompositeRegistry`</ApiSourceLink> and the current `irPath`; the definition's schema owns domain defaults. Binding preserves the relationship between source, schema and compile, so the parsed value reaches the matching callback.

An unknown key produces `kind: 'unregistered'`. Normal compilation collects a warning and skips it; an isolated probe treats it as a recoverable layout failure. The diagram shows resolution for a registered definition.

## Compilation

The type <ApiSourceLink label="CompositeCompiler" path="packages/kernel/reconciler/src/compile/execution/composite/compile.ts" startLine={57}>`CompositeCompiler`</ApiSourceLink> creates <ApiSourceLink label="CompositeCompileContext" path="packages/kernel/core/src/contract/composite/layout.ts" startLine={252}>`CompositeCompileContext`</ApiSourceLink> and invokes the resolved compile callback. Its actual return type is <ApiSourceLink label="CompositeEvaluationResult" path="packages/kernel/core/src/contract/composite/layout.ts" startLine={247}>`CompositeEvaluationResult`</ApiSourceLink>: full layout returns <ApiSourceLink label="CompositeCompileResult" path="packages/kernel/core/src/contract/composite/layout.ts" startLine={309}>`CompositeCompileResult`</ApiSourceLink>, while axis measurement can return <ApiSourceLink label="CompositeContributionResult" path="packages/kernel/core/src/contract/composite/layout.ts" startLine={231}>`CompositeContributionResult`</ApiSourceLink>. ### Proposals Describe Parent Requirements

The x / y proposals independently use intrinsic, range or exact. Intrinsic queries minimum / natural size; range describes a slot interval; exact requests a fixed slot. Allocation does not imply scaling all visible geometry to that width.

<ComponentPreview files="composite-proposal" size="lg" hideCode type="illustration" />

The fixed path has allocationBounds.width 100. An exact 60 proposal can return a 60-wide slotSize while its geometry remains 100. The parent handles overflow, clipping or another arrangement. Some child layouts can fail under a proposal.

| Product          | Meaning                                                         |
| ---------------- | --------------------------------------------------------------- |
| slotSize         | Slot dimensions after applying the proposal                     |
| allocationBounds | Actual local allocation, retaining position                     |
| visualBounds     | Conservative visual envelope of the final static primitive tree |
| alignmentGuides  | Optional baseline and other alignment references                |
| replay           | Token for selecting one complete result in the current callback |

### Measurement or Complete Layout

`measureChild(child, proposal, axis)` queries only the requested size contribution and returns no replay token. Context evaluation distinguishes layout from an axis contribution request. A Composite that can compute that contribution directly may avoid generating a full subtree for measurement.

`layoutChild(child, proposal)` performs isolated complete layout and returns resolved / failed. Success carries a replayable result; a failure handle can be discarded with an alternative or raised. Fatal contract and execution-invariant errors still propagate directly; not every error is an ordinary failed candidate.

This definition lays out a real node and translates the selected result by 20. Definitions, fonts, inheritance and references still use ordinary compilation rules.

```ts
import { defineComposite } from '@retikz/core';
import { z } from 'zod';

const shiftedNode = defineComposite({
  namespace: 'example',
  type: 'shiftedNode',
  schema: z.strictObject({
    namespace: z.literal('example'),
    type: z.literal('shiftedNode'),
  }),
  compile: (_, context) => {
    const probe = context.layoutChild({ type: 'node', text: 'A' }, context.proposal);
    if (probe.kind === 'failed') return context.raise(probe.failure);
    return {
      children: [
        context.replay(probe.result, {
          transforms: [{ kind: 'translate', x: 20, y: 0 }],
        }),
      ],
    };
  },
});
```

### Isolation and Selected Replay

Probes use isolated name writes, resources, primitives and diagnostics. A candidate does not immediately draw into the parent. Reconciler stores the full transaction; the callback receives an opaque token. Unselected candidates publish no primitives, names or warnings.

`replay` turns a successful result into a callback-owned output child. Tokens cannot be serialized, forged, retained across callbacks or placed twice. They are not IR caches. Output is preflighted before committing selected resources, names, primitives and artifacts, so duplicate handles are detected before partial publication.

Ordinary children continue through compilation; replay children consume saved transactions. A replay wrapper accepts lowered numerical transforms and clipping. Use `createScope(props, children)` for full authored Scope semantics and ordinary Scope scheduling.

### Queries, Theme and Runtime Input

`resolvePathTargets` evaluates source and ordered points inside an isolated real child environment and returns local coordinates. It commits no drawing, performs no final endpoint clipping or interpolation, and does not mutate author points. Domain paths can use it before lowering.

`withTheme` creates effective local theme context for queries and measurements. Final children must still declare the matching theme boundary through createScope, so selected output does not accidentally inherit a different theme.

Domain capabilities requiring functions or host objects use runtime input bindings instead of inserting them into JSON IR. <ApiSourceLink label="CompositeBoundChild" path="packages/kernel/core/src/contract/composite/input.ts" startLine={27}>`CompositeBoundChild`</ApiSourceLink> and replay / Scope handles are callback-local runtime values, not new persistent entity types.

### Artifacts and Failure Boundaries

A Definition returning an artifact must declare artifactSchema. Reconciler currently checks that artifactSchema exists, then checks JSON serializability and freezes the value; it does not call artifactSchema.parse to validate the value. Artifacts are delivered separately from drawing. Domain data should not be hidden in primitives for consumers to reverse-engineer. Explicit allocationBounds and alignmentGuides also have their own output contracts rather than replacing visual bounds.

An unregistered Composite warns and is skipped in ordinary compilation; isolated probing returns a handleable failure. Excess expansion depth, invalid output, cross-callback handles and duplicate replay follow their contract or execution failure rules.
