Core 定义“一个对象怎样解析、布局和输出”；Reconciler 决定“何时执行它、哪些依赖已就绪、结果怎样汇总”。本页沿 A、B 两节点及连线追踪这条协作链，后续各篇再展开实体内部阶段。

## 整体流程

入口接收符合契约的 IRScene 与编译选项。Reconciler 装配运行环境、遍历子项，在需要的上下文就绪时调用 Core。最终收集 Scene、资源、领域产物与诊断。这里没有整棵树先统一变成 Canonical Scene 的前置 pass。

外部 JSON 应先在 Schema 入口解析。已类型化 IR 不在每个包边界重复整树 parse；需要 Definition、命名引用或布局结果才能判断的约束，在相应阶段检查。

```ts
import { SceneReconciler } from '@retikz/reconciler';
import type { IRScene } from '@retikz/core';

const ir: IRScene = {
  type: 'scene',
  version: 1,
  children: [
    {
      type: 'path',
      children: [
        { type: 'step', kind: 'move', to: { id: 'A' } },
        { type: 'step', kind: 'line', to: { id: 'B' } },
      ],
    },
    {
      type: 'node',
      id: 'A',
      position: [0, 0],
      text: 'A',
      layout: { minimumSize: { width: 60, height: 40 }, padding: 0, margin: 0 },
    },
    {
      type: 'node',
      id: 'B',
      position: [180, 0],
      text: 'B',
      layout: { minimumSize: { width: 60, height: 40 }, padding: 0, margin: 0 },
    },
  ],
};
const reconciler = new SceneReconciler({}, { incremental: false });
try {
  const result = reconciler.mount(ir).compilation.result;
  console.log(result.scene);
} finally {
  reconciler.dispose();
}
```

沿这份输入，节点先得到包含确定样式与能力绑定的 CanonicalNode，再得到几何与 emit 产物。路径暂存命名目标，等节点发布几何后，才选择边界交点并生成路径指令。IR 中的引用与作者顺序都不必被改写。

## 每种实体需要什么就绪条件

| 对象       | 进入 Core 前需要                   | 交回调度方的结果                 |
| ---------- | ---------------------------------- | -------------------------------- |
| Node       | 继承、定义、测量服务、定位引用     | 节点布局、查询几何、图元与边界   |
| Coordinate | 位置上下文与已可查引用             | 可发布的坐标几何，不绘制图元     |
| Scope      | 先确定继承；自身包络等待子布局     | 分组属性、包络与投影所需结果     |
| Path       | 命名目标与所属空间可查             | 路径输出、布局边界与共享资源引用 |
| Composite  | 已匹配的定义、提案与受限子布局服务 | 子项或布局贡献、可选领域产物     |

Scope 包含递归子树，所以这些阶段也会在局部出现。Composite 回调可以请求子布局试算；试算的隔离和选中结果的重放由 Reconciler 负责。不能把所有对象画成相同的“IR → Primitive”函数。

## 声明、求值与绘制顺序

Reconciler 按 children 声明顺序分派。遇到路径时保留原位置的输出槽位，节点和 Scope 等完成必要几何后再回填路径，因此“晚求值”不会自动变成“最后绘制”。最终同层输出按 zIndex 稳定排序；同值维持原有次序。

这个就绪机制不等于任意对象都支持前向引用。Node 定位和 Coordinate 在访问时求值，其目标应当可查；路径有专门的延迟机制。无法满足的引用、试算失败与诊断应按所属契约处理，不能用 [0, 0] 代替未知值。

## 环境与复用由谁持有

Reconciler 的共享环境按 registries、host、layout、limits 提供定义表、测量与 TeX 服务、有效数值配置及执行限制。每次执行还需要资源、命名、诊断与试算工作区。Core 只接收当前阶段必需的窄上下文，不拥有整个会话。

Core 的 prepared 参数允许消费调用方已确认有效的阶段产物，并补算缺项；它不自行判断跨次缓存是否仍有效。全量和增量执行都能调用这些原子阶段，依赖记录、复用裁决及输出事务由 Reconciler 管理。

## 完整实现流程

从 Reconciler 的 CompileManager 进入 SubtreeCompiler，再到各 visit / deferred 文件，才能看到 Core 阶段的真实调用点。根子树完成后，CompileManager 把图元、布局、资源和产物交给快照组装函数；renderer 在其后消费 Scene。
