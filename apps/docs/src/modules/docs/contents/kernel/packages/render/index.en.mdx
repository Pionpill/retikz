---
title: Rendering packages
description: Rendering packages materialize the shared Scene in SVG, Canvas, and hydration hosts while keeping backend semantics aligned.
---

Rendering packages answer the question, “How does a compiled Scene become a host artifact?” `@retikz/render` owns backend contracts for SVG, Canvas, events, and hydration. Its pages cover the shared rendering entry, concrete backends, and the client-side hydration boundary. It does not define upper-level components or domain IR.

## Responsibilities

| Page | Responsibility | Reach for it when |
| --- | --- | --- |
| `render` | Rendering entry points, Scene materialization, and shared runtime | Understanding backend contracts shared by all outputs |
| `render · SVG` | Scene to SVG DOM or SVG strings | Choosing the default vector backend |
| `render · Canvas` | Scene to bitmap Canvas and hit queries | Handling many primitives or frequent repaints |
| `render · Hydration` | Client-side events and host binding after static output | Adding interaction to a rendered figure |
