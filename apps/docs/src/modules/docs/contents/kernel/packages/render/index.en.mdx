> This is package documentation, not component docs; to draw, start from [Components](/kernel/components/layout).

This group covers how retikz actually paints a figure to the screen. Your figure is first compiled into a **renderer-agnostic Scene**, then handed to a backend: **SVG** emits a vector DOM where every primitive is a real, CSS-targetable element; **Canvas** paints the same Scene as a raster bitmap, suited to many primitives or frequent repaints. The backends share Scene semantics and align their output where each backend supports the required feature; check host capabilities and interaction needs before switching. **Hydration** is the mechanism both backends share: render statically first, then bind event handlers back to primitives by id on the client.

## Responsibilities

| Topic            | Responsibility                                                                               | Reach for it when                                                   |
| ---------------- | -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| SVG              | Scene → vector DOM, or an SSR / build-time string                                            | The default: you want crisp vectors, CSS hit-testing, accessibility |
| Canvas           | Scene → raster bitmap, immediate-mode drawing + hit-testing                                  | Hundreds of primitives, frequent repaints, performance first        |
| Retained Runtime | Prepare and commit Scene Patches inside a Runtime transaction                                | Stable host identity and incremental updates                        |
| Inspection       | Materialize an independent development overlay after the primary figure                      | Reading layout bounds, overflow, and alignment guides               |
| Hydration        | Bind event handlers back to primitives by id after a static render (shared by both backends) | Adding click / hover interaction to a figure                        |

## Retained Runtime

`createRetainedRenderParticipant()` connects a Core Program, `RenderRuntimeOwnerDefinition`, and one retained renderer to the same Runtime Session. The initial transaction materializes a complete Scene. Later transactions prepare a Scene Patch and renderer config together; DOM / bitmap state, events, animation controls, and the public read advance to one revision only after every participant commits. A failed transaction publishes no new revision and attempts rollback. The old host remains usable when rollback succeeds; if rollback itself fails, the Session becomes broken and must be disposed and recreated.

Final disposal performs reverse best-effort cleanup across hydration, animation, and the image loader. Once an SVG WAAPI binding or Canvas clock starts cleanup, public controls and event / visibility callbacks become inert immediately. Animations, observers, listeners, inline-style ownership, visibility listeners, and the clock are cleaned independently: successful items are not repeated, while failed items remain retryable by a later disposal call.

`RenderRuntimeConfigInput` is a closed transaction config. `handlerContributions` merge hydration handlers in registration order, `animation` controls playback, snapshots, and extension registries, `cachePolicy` preserves a hint for future layer invalidation optimization, and `canvas.width` / `canvas.height` declare Canvas CSS user-space dimensions. The alpha.2 SVG and Canvas renderers validate and freeze `cachePolicy` but do not yet enable auto, static, or dynamic layer reuse. Omitted Canvas dimensions derive from the committed Scene layout and are multiplied by the session-lifetime DPR. Size changes and bitmap painting commit atomically, while dirty reuse is allowed only when the target size is stable.

Import these retained APIs from `@retikz/render/runtime`; they are not exported from the `@retikz/render` package root. A third-party backend uses `RetainedRendererFactory` to create a nominal SVG or Canvas renderer and declares `none`, `group`, or `entity` capability. The Render participant validates Snapshot / Patch lineage. When a backend cannot interpret a Patch, it consistently falls back to a complete Scene replacement and publishes a diagnostic.

### Primary and inspection planes

Static APIs use `StaticRenderFrame { primary: Scene, inspection }`. Retained renderers use `RenderFrameSnapshot { primary: SceneRuntimeSnapshot, inspection }`. Both materialize the primary figure and complete inspection overlay as one frame, so a failed retained transaction cannot publish a new figure with an old overlay.

SVG appends a `pointer-events="none"` inspection group after the primary figure and assigns no hydration ids. Canvas draws inspection DTOs after the primary bitmap, while `hitTest` continues to read only the primary Scene. The overlay never determines viewBox, resources, animation, or primary identity. A third-party retained renderer must declare `inspectionCapability: 'supported' | 'unsupported'`; receiving a non-null overlay while unsupported fails loudly instead of silently dropping it.

The built-in SVG and Canvas backends share one nine-color occurrence palette, fixed red warning color, alpha rules, and hatch-segment generator. Regular color is `palette[colorScope % 9]`. A `solid` fill uses base alpha `0.14 × opacity`; diagonal and crosshatch patterns draw no base fill and use only `0.55 × opacity` hatch strokes.

`forward-diagonal` appears as `/` in screen coordinates, `backward-diagonal` as `\`, and `crosshatch` combines both. SVG emits only local `<path>` segments already clipped to the rectangle and creates no document-global pattern id. Canvas paints inside a `save → clip → hatch stroke → restore` lifecycle. The canonical pitch is 12 user units and scales with the figure transform. A pattern does not create an implicit border; an upstream inspector emits a separate outline or line primitive when a boundary is required.

### Static frame APIs

Import `StaticRenderFrame` from `@retikz/render/runtime`; import each materialization function from its SVG or Canvas backend subpath.

| API                                            | Import path             | Result                                                          |
| ---------------------------------------------- | ----------------------- | --------------------------------------------------------------- |
| `buildSvgFrameDocument(frame, options)`        | `@retikz/render/svg`    | An `SvgNode` containing the primary figure and inspection group |
| `renderFrameToSvgString(frame, options)`       | `@retikz/render/svg`    | A complete SVG string for SSR                                   |
| `renderFrameToCanvas(canvas, frame, options?)` | `@retikz/render/canvas` | Atomically paints the target Canvas and returns nothing         |
