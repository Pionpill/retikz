[配置解析](/kernel/packages/core/resolution)确定路径样式与 Definition，[坐标解析](/kernel/packages/core/coordinates)说明引用何时可见，[节点编译](/kernel/packages/core/node-compilation)提供连线需要的节点几何。本页沿一条普通描边路径，追踪目标绑定、路径段计算和最终图元输出。

## 整体流程

路径输入包含目标、步骤、样式和标签。Core 在所属 Scope 完成子树处理后解析这些声明，生成局部坐标下的几何命令，最后组合线条、箭头和文字，回填到 Scene 中原先预留的位置。

<ComponentPreview files="path-example" size="sm" hideCode type="illustration" />

本页以内置描边路径为主线。自定义 Path 通过自己的 Definition 输出图元。

`compileStrokePath` 组织布局与绘制：布局计算基础路径、标签和标记放置，再处理断口与端点接触；绘制生成或复用局部图元，最后应用宿主包装。只有存在标签断口时才生成切分片段。

目录按这些阶段组织：`geometry/` 管理基础几何和采样，`layout.ts` 协调布局，`emit.ts` 应用外观并协调图元输出，`decoration/` 计算标签与修饰，`body.ts` 生成可见路径，`output.ts` 包装最终输出。Definition 能力组装和通用标签回调分别保留在 `host/context.ts` 与 `label/callbacks.ts`。

## 目标绑定

遍历器遇到 Path 时先保存待处理记录，其中包含路径输入、当前变换、继承配置和图元占位。所属 Scope 的子树处理完成后，再解析路径目标并替换占位；根级路径在根子树完成后处理。这样既能引用本层后续节点，也能保留原始绘制顺序。跨 Scope 的可见性见[引用时机](/kernel/packages/core/coordinates#引用时机)。

<ComponentPreview files="path-timing" size="xl" hideCode type="illustration" />

第二列新增 B 的几何与图元，P 仍占据原来的数组位置；第三列将该占位替换为 Path P。为突出数组变化，这里用一条无标签直线表示 P，用 A、B 表示对应节点图元。

`bindPathTargets` 在编译阶段绑定目标，保留计算后的点并直接引用完整节点布局；引用来源与布局分别保存。后续通过 `PathTargetView` 查询局部参考点及边界交点。对 A 到 B 的连线，先取得两个参考点，再由连线方向求出实际端点。

## 游标与路径段

编译器按声明顺序消费步骤，并维护后续步骤需要的位置：

- 前驱目标：普通线段从哪里开始，以及该位置是否带有节点边界。
- 最近一次 `move` 的目标：供 `cycle` 闭合当前子路径。
- 特殊步骤留下的笔位：例如圆弧终点，供下一段接续。
- 相对坐标基准：用于计算 `relative` 与 `relativeAccumulate`。

下图两条路径都从 `[0, 0]` 开始，连续使用两次 `[60, 30]` 偏移。`relative` 保持基准不变，两次终点重合；`relativeAccumulate` 更新基准，第二段继续向前。

<ComponentPreview files="path-relative" size="md" hideCode type="illustration" />

能提前确定的相对目标在编译阶段绑定为局部坐标；依赖 axis-line 投影等运行结果的后续目标，在消费步骤时继续计算。`move` 开启新的笔位，普通直线、折线和曲线逐段转为命令；圆弧、闭合形状、平滑曲线由各自分支处理，并交接后续笔位。

| 输入步骤                                   | 几何变化                                             |
| ------------------------------------------ | ---------------------------------------------------- |
| line / axis-line                           | 生成直线；axis-line 先把目标投影到当前水平线或竖直线 |
| fold                                       | 根据方向生成正交折点，再连接成折线                   |
| curve / cubic / bend                       | 使用给定或计算得到的控制点，生成二次或三次贝塞尔曲线 |
| arc / circlePath / ellipsePath / rectangle | 生成对应形状命令，并维护后续笔位                     |
| smooth                                     | 生成过点平滑曲线                                     |
| cycle                                      | 回到最近一次 move 的目标，闭合当前子路径             |

## 边界交点

节点引用作为连线目标时，Core 先计算连接边界上的附着点，再用这些端点生成路径命令。以 A 到 B 的直线为例：

1. **取得参考点与节点几何**：从已绑定的目标读取 A、B 的参考点、形状与连接边界。
2. **确定连接方向**：计算 A 端时朝向 B 的参考点，计算 B 端时朝向 A 的参考点。
3. **查询边界交点**：将方向参考点转换到世界坐标，选用目标上的 `boundary`；未指定时使用节点的 `boundary`。Core 取得对应几何并应用节点 `margin`，再调用 Definition 的 `computeBoundaryPoint` 求附着点。
4. **生成局部路径命令**：将交点转换回当前 Scope 的局部坐标，以它们作为线段起终点。

开篇两个圆的中心分别为 `[0, 0]` 和 `[220, 0]`，半径为 24，margin 为 0。沿中心连线求得的附着点是 `[24, 0]` 和 `[196, 0]`，因此先生成这两个点之间的直线；箭头所需的端点缩短在后续阶段处理。连接面与 margin 的关系见[节点编译](/kernel/packages/core/node-compilation#连接边界)。

### 各类路径如何确定方向

| 路径段       | 边界计算方式                                                  |
| ------------ | ------------------------------------------------------------- |
| line         | 两端分别朝向对方参考点求交                                    |
| curve        | 两端分别朝向同一个二次贝塞尔控制点求交                        |
| cubic / bend | 起点朝向第一个控制点，终点朝向第二个控制点；bend 先计算控制点 |
| fold         | 先生成折点，再沿折线查找离开起点边界、进入终点边界的位置      |

贝塞尔曲线用控制点方向确定附着点，然后以新端点和控制点生成曲线。这里求的是方向射线上的边界点，并未求解整条贝塞尔曲线与形状的交点。

对于未指定 anchor 和 offset 的节点目标，折线会依次检查折点，找到第一个从边界内部走到外部的线段。在该线段上求出界点：从边界中心出发时直接查询 `computeBoundaryPoint`，其余情况用二分逼近内外分界。随后去掉节点内部的折线前缀，终点端反向执行同样的处理，以保留原折线的方向。

### 显式锚点与偏移

指定 `anchor` 时，Core 使用锚点位置作为附着点；`offset` 在附着点求出后叠加。仅指定 offset 时，仍会先按方向查询边界点。偏移在世界坐标中应用，再转换回当前 Scope 的局部坐标。

## 箭头与标签

标签根据路径上的采样点和方向定位，再经文字测量得到视觉范围。步骤标签使用所属段的采样规则；路径级标签沿组合后的采样区间定位。不同路径段的参数不一定与弧长成正比，具体 position 语义见 [Path 标签](/kernel/components/path/label)。

需要断线的标签会把视觉范围和 gap 转为路径上的留白区间，Core 据此拆分线条。箭头 Definition 提供端点装饰及所需缩短量，Core 再缩短首尾线段，并保护端点附近的箭头区域。

回看开篇右图：A、B 的连接边界决定两端接触点；标签在中间形成留白；箭头所需的缩短量作用于末段。添加标签不会改变原始目标引用。

### 端点如何缩短

默认端点箭头需要同时满足两个条件：**尖端落在目标点，尾部接到原曲线的断点**。Core 根据箭头几何与线宽得到接合长度，再从目标端沿原路径向内寻找断点，使断点到目标点的直线距离等于这个长度。

1. **保留目标**：先记录原路径起终点，标签断口仍按完整路径计算。
2. **寻找接合点**：在承载端点的片段内逐段向内搜索，再用二分细化曲线参数。需要时可跨过该连续片段中的多个命令。
3. **保形切片**：保留接合点以内的原曲线。贝塞尔曲线重新计算子曲线控制点；圆弧与椭圆弧调整起止角，保留中心、半径和旋转。
4. **定位箭头**：终点箭头沿“接合点 → 原目标点”定向，起点箭头反向处理。marker 内部变换校正宿主切线带来的旋转，SVG 与 Canvas 消费同一结果。

线条与箭头尾部保留半个线宽的重叠，避免抗锯齿产生细缝；这部分重叠只调整接触位置，尖端仍固定在目标。箭头方向是断点与目标的连线方向，曲率较大时会与断点处切线略有差别。

`endpointOverlap` 继续控制箭头进入目标的程度，自动节点边界还会应用空心箭头的外缘保护。短路径无法容纳原尺寸时，箭头会缩小以保持接合；无有效长度时不输出端点箭头。保形计算复用[曲线切片](/kernel/components/path/mechanism#为什么曲线也能截断)。

## 阶段复用

`compilePath(canon, context, prepared)` 返回目标绑定 `targets`、完整绘制结果 `emit`、当前阴影声明，以及本次实际使用的源路径描边产物 `stroke`。调用方从结果中选择仍有效的部分，通过 `PreparedPathCompilation` 传回；Core 只补算缺项，跨次有效性由调用方判断。

- `targets` 命中后跳过目标查询，将已转换的相对目标应用到当前步骤，同时保留当前样式和标签。有效性涉及步骤、目标、诊断字段路径、引用几何及坐标环境；空 Map 也是已计算结果。
- 顶层 `emit` 直接保存已校验、快照化的图元与边界点数组。命中后跳过目标绑定和 Definition 调用；`undefined` 表示缺项，`null` 表示合法空结果，空数组输出仍有独立语义。
- `stroke.layout` 和 `stroke.emit` 各自保留 `overall` 与已知局部产物。整体命中不会反推缺失局部结果；只传顶层 `emit` 也不会重建目标或描边产物。

描边缓存按实际计算边界划分：

| 产物                          | 可以复用的计算                                                            |
| ----------------------------- | ------------------------------------------------------------------------- |
| `layout.geometry` / `metrics` | 基础命令与原始参数模型；按需建立的逻辑路径度量                            |
| `layout.labels`               | 逐标签 `measurement` 与 `placement`，分别保存文字排版和路径放置、断线定位 |
| `layout.marks` / `body`       | 截断前的逐标记放置；标签断口与箭头接触截取后的可见主线                    |
| `emit.labels` / `marks`       | 逐项局部 `content` 与已放置 `overall`                                     |
| `emit.arrows` / `body`        | 首末端箭头局部 `content`；尚未绑定宿主身份与整体变换的主线图元            |

例如，路径位置变化而文字不变时，可回传标签的 `measurement` 和 `content`，重新计算放置与断口。只改绘制颜色时，可复用完整布局。标签内容已包含文字外观和宿主透明度，复用时也要保证这些依赖有效。步骤标签按 `children` 下标对齐，非标签步骤保留空槽；宿主标签和 marks 分别按声明顺序对齐。

自定义 kind 可以生成任意图元。宿主只将无参数 `emitStroke()` 对应的当前源路径产物交接给 `stroke`；显式传入其他路径的调用独立计算，多次无参数调用复用同次结果。几何缓存保存纯参数数据，当前标签仍从本轮声明读取，普通分段参数与圆角路径的弧长定位规则保持不变。

调用方负责恢复配套资源、重放诊断，并保证 Definition、输入与宿主环境有效。Core 为实际返回的缓存图元恢复本次宿主资源引用许可；放置、包装和 Definition 取得的可修改输出均不改写保留的缓存。

## 完整实现流程

从 `resolvePath` 读起，再进入 `compilePath` 查看目标绑定和 Definition 调用；内置描边经宿主进入 `compileStrokePath`。下图先沿左列向下，再沿右列向上：步骤消费产生几何命令，随后处理圆角、标签与装饰，再把路径主体和附属图元交给遍历器回填。

<ComponentPreview files="path-implementation" size="lg" hideCode type="flow" />

输出可能包含多段线条、标签文字和装饰图元，路径自己的旋转与缩放由输出分组承载。Scope 变换继续由外层分组表达，renderer 消费这些结构化结果。

普通目标未解析或缺少必要前驱时，相关分支会报告警告并跳过整条路径；部分无可绘制内容的步骤可以不产生命令。违反路径几何约束等错误会抛出异常，不能把所有失败都理解成跳过单段。
