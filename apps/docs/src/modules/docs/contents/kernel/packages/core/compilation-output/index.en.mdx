Core defines primitives, resources and bounds calculations. Reconciler collects subtree contributions, finishes deferred paths and sorting, assembles Scene and associated results, then publishes through the session commit protocol.

## Overall Flow

Drawing goes into Scene, domain results into artifacts, diagnostics into the compilation snapshot, and optional source information into provenance. These serve different consumers; renderers do not need Composite business input or layout algorithms.

## What Callers Receive

SceneReconciler returns revision and compilation. Drawing is at `output.compilation.result.scene`; artifacts are beside scene in result. Diagnostics belong to compilation.diagnostics rather than Scene.

```ts
import { SceneReconciler } from '@retikz/reconciler';

const reconciler = new SceneReconciler({}, { incremental: false });
try {
  const output = reconciler.mount({
    type: 'scene',
    version: 1,
    children: [{ type: 'node', text: 'A' }],
  });
  const { scene, artifacts } = output.compilation.result;
  const diagnostics = output.compilation.diagnostics;
  console.log(scene, artifacts, diagnostics);
} finally {
  reconciler.dispose();
}
```

This is Reconciler's public result. Vanilla convenience processing can manage an internal coordinator's lifetime. Read each entry's return value through its owning package contract.

## Scene Is Laid-Out, Backend-Neutral Drawing

Scene.primitives is ordered for drawing. Layout contains x / y / width / height; resources and root animations are optional. Renderers do not receive authored Nodes, Scopes or domain Composites for another semantic compilation pass.

| Primitive        | Determined content                                             |
| ---------------- | -------------------------------------------------------------- |
| RectPrimitive    | Rectangle geometry and appearance                              |
| EllipsePrimitive | Ellipse geometry and appearance                                |
| TextPrimitive    | Text, lines, baselines and fonts                               |
| PathPrimitive    | Structured commands, paint and decoration data                 |
| GroupPrimitive   | Children, shared transforms, clipping, identity and animations |

These contracts hold drawing semantics for multiple backends, not DOM, Canvas contexts or SVG-only callbacks. Structured marker data can still carry endpoint decoration.

## Group Coordinates and Query Geometry

Scene need not flatten all primitives into world coordinates. Scope and Node groups can retain transforms while children remain local. Renderers compose transforms; compilation projects query geometry as needed for cross-Scope references.

A local rectangle at x=0 inside a group translated by 20 has world x=20. Writing 20 into both would apply the translation twice. Artifact coordinate spaces likewise follow their domain contracts rather than automatically becoming world-space data.

## Shared Drawing Resources

Colors can appear directly on primitives. Gradients, patterns and images live in `Scene.resources.paints`, referenced by fill or stroke values. Clip paths live in `Scene.resources.clips`, referenced by a group's `clipRef`. Core paint / clip registries materialize backend-neutral resources and reuse content identities. Reconciler creates the workspace registries and preserves these categories through caching, replay and the final Scene.

When `resources` is present, both `paints` and `clips` are arrays; an unused category is empty. Compilation can omit the entire field when there are no resources, while Render runtime snapshots always include both collections. Resources and the primitives referencing them take effect in the same revision.

Pattern Definitions can emit tile primitives, not separate resource tables. Extension outputs can reference only resources permitted by their host. Resources from isolated probes enter the real workspace only through selected replay; copying primitives without their resources is incomplete.

Resource ids associate references and definitions in a Scene rather than providing business keys for callers to interpret. Backends materialize them separately; Core does not output DOM defs here.

## Layout and the Different Bounds

A Scope envelope serves connection and placement. Composite allocationBounds serves parent layout. VisualBounds conservatively encloses the static primitive tree. Scene.layout applies viewport policy to compilation output bounds.

Without viewBox, collected layout contributions are processed by Core bounds helpers, expanded by padding and rounded. Padding defaults to 10. No bounds produces the default canvas x=0, y=0, width=100, height=100. An explicit viewBox directly determines layout and must retain finite coordinates and positive dimensions after rounding.

The A/B example contributes x=-30 through 210 and y=-20 through 20. Default padding gives `{ x: -40, y: -30, width: 260, height: 60 }`. Labels, shadows and decorations can affect output contributions.

## Artifacts, Diagnostics and Provenance

A Composite artifact carries namespace, type, structured occurrence and JSON value. Occurrence distinguishes author source from expansion location; generated ownership should not be guessed from a path string. Artifacts are ordered by the final logical tree and delivered separately from drawing.

Diagnostics contain warnings that can be committed after successful compilation, including code, message and source data. Unselected probes do not leak warnings. Optional provenance links primitives to compilation sources and is not required by the renderer. Transaction rollback belongs to Reconciler rather than an individual Core emit function.

Readonly snapshot, result and artifacts / diagnostics array shells do not imply that all Scene data is recursively frozen at runtime. Consumers respect result ownership rather than mutating published output as a substitute for updating declarations.
