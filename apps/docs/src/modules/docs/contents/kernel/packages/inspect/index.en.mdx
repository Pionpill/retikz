title: Compilation Inspection · inspect
description: Add on-demand observation and readonly auxiliary layers to completed compilation without changing the primary figure
---

`@retikz/inspect` adds optional observation to a completed Core compile. An Inspector reads final occurrences and owner output, then produces independent readonly auxiliary content. Control points, layout bounds, and alignment guides are concrete uses of that observation.

It explains final results only: it does not repair input, participate in layout solving, or mutate the primary figure. Ordinary drawing, compilation, and rendering do not require this package, and no auxiliary fragment exists when no Inspector matches.

<ComponentAlert
  title="Optional drawing aid"
  description="@retikz/inspect is not required for drawing or rendering. It only helps interpret completed figures and compilation results, making it useful for development, debugging, or teaching rather than as a routine production capability."
/>

## What inspection shows

The ordinary curve is the primary figure; points and dashed lines form a separate auxiliary layer. Moving control points changes the curve, while disabling inspection only hides the auxiliary content. The same distinction applies to nodes, clipping, and scopes.

## Installation and usage

<PackageManagerInstall packages="@retikz/inspect" />

A registry stores available inspectors; a request chooses a target and displayed content. Start with the default registry and enable control points for one curve.

<DocTabs defaultValue="react">
<DocTab value="react" label="React">
<DocSteps>
<DocStep title="Imports">

`@retikz/inspect` exports the default registry factory `createDefaultInspectorRegistry` and path inspector key `PATH_INSPECTOR_KEY`. `@retikz/inspect/react` exports `InspectLayout` and `InspectPath` to connect the registry and attach path inspection requests.

```tsx
import { createDefaultInspectorRegistry, PATH_INSPECTOR_KEY } from '@retikz/inspect';
import { InspectLayout, InspectPath } from '@retikz/inspect/react';
```

</DocStep>
<DocStep title="Integrate and render">

React imports optional wrappers from `@retikz/inspect/react`. `InspectLayout` receives the registry; `InspectPath`, `InspectNode`, `InspectScope`, and `InspectCoordinate` attach requests to the current Path, Node, Scope, or Coordinate:

```tsx
import { createDefaultInspectorRegistry, PATH_INSPECTOR_KEY } from '@retikz/inspect';
import { InspectLayout, InspectPath } from '@retikz/inspect/react';
import { Step } from '@retikz/react';

const registry = createDefaultInspectorRegistry();

export const InspectExample = () => (
  <InspectLayout registry={registry}>
    <InspectPath request={{ inspector: PATH_INSPECTOR_KEY, options: { controlPoints: true, labels: true } }}>
      <Step kind="move" to={[0, 0]} />
      <Step kind="cubic" control1={[20, -30]} control2={[80, 30]} to={[100, 0]} />
    </InspectPath>
  </InspectLayout>
);
```

`InspectLayout` adds the optional inspection compile driver to the ordinary Layout runtime. `InspectPath` keeps ordinary Path authoring and turns its request into a runtime-only authoring marker.

</DocStep>

<DocStep title="Keep ordinary React components (optional)">

Use this equivalent approach when keeping existing `Layout` / `Path` components. Choose it instead of the wrapper example above.

The `/vanilla` subpath exposes driver and authoring-marker helpers that ordinary React components can also consume. The diagram is still authored in React; Inspect wrappers connect these helpers for you.

```tsx
import { createDefaultInspectorRegistry, PATH_INSPECTOR_KEY } from '@retikz/inspect';
import { createInspectionVanillaAuthoring, createInspectionVanillaDriver } from '@retikz/inspect/vanilla';
import { Layout, Path, Step } from '@retikz/react';

const registry = createDefaultInspectorRegistry();
const compileDriver = createInspectionVanillaDriver({ registry });
const pathInspection = createInspectionVanillaAuthoring({
  inspector: PATH_INSPECTOR_KEY,
  options: { controlPoints: true, labels: true },
});

export const ConfiguredInspectExample = () => (
  <Layout compileDriver={compileDriver}>
    <Path authoring={pathInspection}>
      <Step kind="move" to={[0, 0]} />
      <Step kind="cubic" control1={[20, -30]} control2={[80, 30]} to={[100, 0]} />
    </Path>
  </Layout>
);
```

Both forms produce the same inspection requests and results for the same configuration; the wrappers simply handle the wiring. This configuration is fixed, so the driver lives outside the component. If it depends on React props or state, create it with `useMemo` inside the component and list those dependencies. Base components have no `inspect` prop, and `authoring` never enters Core IR.

</DocStep>

<DocStep title="Imports">

`@retikz/inspect` exports the default registry factory and path inspector key. `@retikz/inspect/vanilla` exports `createInspectionVanillaAuthoring` and `createInspectionVanillaDriver` to create inspection markers and the compile driver that integrates inspection.

```ts
import { createDefaultInspectorRegistry, PATH_INSPECTOR_KEY } from '@retikz/inspect';
import { createInspectionVanillaAuthoring, createInspectionVanillaDriver } from '@retikz/inspect/vanilla';
```

</DocStep>
<DocStep title="Integrate and render">

Vanilla creates an authoring marker and a compile driver separately: the marker declares that a path needs observation, and the driver adds the registry and auxiliary layers at the ordinary render entry:

`authoring` attaches an inspection request without changing path geometry or becoming persistent IR.

```ts
import { createDefaultInspectorRegistry, PATH_INSPECTOR_KEY } from '@retikz/inspect';
import { createInspectionVanillaAuthoring, createInspectionVanillaDriver } from '@retikz/inspect/vanilla';
import { path, renderToSvgString, scene } from '@retikz/vanilla';

const registry = createDefaultInspectorRegistry();
const input = scene({
  children: [
    path('curve', {
      // Mark this authored Path for inspection; it never enters Core IR.
      authoring: createInspectionVanillaAuthoring({
        inspector: PATH_INSPECTOR_KEY,
        options: { controlPoints: true, labels: true },
      }),
      way: [
        [0, 0],
        {
          cubic: [
            [20, -30],
            [80, 30],
          ],
        },
        [100, 0],
      ],
    }),
  ],
});

const svg = renderToSvgString(input, { compileDriver: createInspectionVanillaDriver({ registry }) });
```

</DocStep>

The root entry owns Definitions, registries, selection, and auxiliary compilation. React and Vanilla adapters come from `/react` and `/vanilla`; rendering remains the responsibility of `@retikz/render`. Start with Built-in inspection, then continue to extension or inspection details as needed. Configuration fields are listed in the [Schema reference](/kernel/packages/inspect/schema-reference).
