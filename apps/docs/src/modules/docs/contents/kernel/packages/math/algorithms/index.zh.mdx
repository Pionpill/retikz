几何原语负责描述点、向量、圆和圆弧；几何算法则把这些已有数据组合起来，回答“它们在哪里相交”“哪些点能被一个圆覆盖”或“怎样得到一条平滑曲线”等问题。算法只处理数学与几何关系，不创建 IR，也不依赖 renderer。

## 基础用法

从根入口导入，返回普通数值或几何数据，不负责绘图。

```ts
import { intersect } from '@retikz/math';

const crossing = intersect.segmentSegment({
  a1: [0, 0],
  a2: [20, 20],
  b1: [0, 20],
  b2: [20, 0],
}); // [10, 10]
```

## 求交

求交用于找出两条直线、两条线段、直线与圆，或两个圆之间的交点。结果是坐标点；没有交点或输入退化时，函数会返回 `null` 或空数组。

用面板切换直线、线段、直线与圆、两个圆，并尝试相交、平行、相切和相离情况。选择“显示段外的直线交点”时，画面中的实线只是为了适配画布而截取的有限显示段，但 `lineLine` 仍按无限延长线计算，因此两段实线没有碰到时也会显示紫色交点；选择“不相交线段”可以对比 `segmentSegment` 的有限范围。

<ComponentPreview files="intersection-playground" size="lg" caption="切换几何关系，观察交点和退化结果" />

### 算法解析

直线和线段先都写成参数方程：$p=a_1+t\mathbf d_a$、$q=b_1+u\mathbf d_b$。令两式相等后，用二维叉积消去一个未知量：

$$
\det=\mathbf d_a\times\mathbf d_b,\qquad t=\frac{(b_1-a_1)\times\mathbf d_b}{\det}
$$

`det` 衡量两条方向是否平行：接近零时没有唯一交点。`lineLine` 只用 $t$ 取得无限直线的交点；`segmentSegment` 还会检查 $t$ 与 $u$ 是否都落在 $[0,1]$，这一步才把交点限制在两条有限线段上。

直线与圆把 $p=origin+s\,direction$ 代入圆方程，得到关于 $s$ 的一元二次方程。判别式小于零表示没有相交候选点；等于零时两个根重合。两个圆则先用圆心距离 $d$ 排除相离和内含情况，再用 $a$ 定位交点公共弦的中点，用垂直偏移 $h$ 得到中点两侧的交点；相切时 $h=0$，因此保留两个重合坐标。

## 射线与圆弧求交

射线与圆弧的输入包含圆弧的圆心、半径、起始角度和终止角度。`intersectRayWithArc` 返回射线参数 `s`，实际交点可按 `origin + s * direction` 得到；它只保留射线正方向上的交点。

<ComponentPreview files="ray-arc" size="sm" caption="圆弧与射线的交点以紫色点显示" />

### 算法解析

射线与圆弧不是直接解一个新方程。算法先把射线延长为直线，代入圆方程求两个候选参数 $s$；再按两个条件筛选：$s$ 必须大于容差，保证点在射线正方向；候选点相对圆心的 `atan2` 角度必须落在圆弧实际扫过的范围内。

因此返回的 $s$ 是在 `origin + s * direction` 中定位交点的参数，而不是几何距离：`direction` 没有单位化时，距离还要乘以它的长度。最后升序排序使第一个结果始终是射线首先遇到的圆弧交点。

## 圆与三角形

这一组算法从三角形或点集构造圆。通过“构造方式”切换只查看一种方案：外接圆经过三角形的三个顶点，内切圆与三条边相切，最小包围圆则覆盖给定点集。面板中的二维控制点就是算法输入，移动它们可以观察圆如何随几何关系变化；三点共线等退化情况返回 `null`。

下方示意只展示当前选中的圆构造方案，避免把不同问题的结果混在一起。

<ComponentPreview files="circle-constructions" size="md" caption="比较三角形外接圆、内切圆和点集最小包围圆" />

### 算法解析

外接圆先用三点的有向面积构成分母 $d$；$d$ 接近零说明三点共线，无法唯一决定一个圆。内切圆则用三条对边长度作为顶点权重得到圆心，再由 $r=\mathrm{area}/\mathrm{semiperimeter}$ 得到半径，所以它到三条边的距离相等。

最小包围圆从一个已覆盖此前点的当前圆开始。遇到落在圆外的新点 $i$ 时，$i$ 必须成为结果的边界点：先尝试 $i$ 与此前点 $j$ 的直径圆；如果某个 $k$ 仍在外部，结果就由 $i,j,k$ 三点共同决定，改用三点外接圆。三点共线时，退化为三组两点直径圆中半径最大的一个。

## 多边形与凸包

多边形包含判断回答一个点是否位于多边形内部，支持凹多边形和不同的顶点绕向。凸包则从一组点中筛出最外层的边界点，得到一个按逆时针排列的凸多边形。两者用途不同：包含判断保留原多边形形状，凸包会包住凹陷区域。

下方示意中，浅灰线是原多边形，橙色线是凸包。面板提供多个可移动测试点：点在多边形内部时显示为绿色，点在外部时显示为红色；默认点集同时展示普通内部点、外部点和凹陷区域外的点。

<ComponentPreview files="polygon-containment" size="lg" caption="同时观察多边形包含判断与凸包边界" />

`polygon.containsPoint` 的边界点结果未定义；如果边界归属会影响业务结果，应在调用方补充点在线段上的判断。`convexHull` 会去重并剔除共线的中间点，少于三个点或全部共线时返回排序后的端点集合。

### 算法解析

包含判断从测试点向右发出一条射线，逐边检查射线是否跨过边。每跨过一次就翻转 `inside`；全部边处理完后，奇数次表示在内，偶数次表示在外。这就是奇偶规则，顶点顺时针或逆时针排列不会改变结果。

凸包先按 $(x,y)$ 排序并去重，再分别从左到右、从右到左建立下链和上链。每加入一点时，若末两个边与新边的叉积不大于零，就移除中间点：它要么让路径向内转，要么只是共线中间点。两条链去掉重复端点后相接，便得到逆时针的最外层边界。

## 曲线切片

当一条路线不是直线时，常见需求是：在 40% 处放标签、箭头或动画对象，按已经走过的距离找到位置，或只取中间一段来高亮、留白或局部重绘。`CurveSegment` 为直线、二次 / 三次贝塞尔、圆弧和椭圆弧提供同一套取点、取方向和保形切片能力。

用面板切换曲线类型，再拖动采样位置和切片起止。浅灰是完整曲线，高亮黄部分来自 `curve.slice`；蓝色实点和短线分别表示当前位置与前进方向。无论选择哪一种曲线，切片都会保留原来的曲线类型，而不会降级成折线。

<ComponentPreview files="curve-segments" size="lg" caption="切换五种曲线段，观察参数采样、前进方向与保形切片" />

`sampleAt` 的参数范围是 `0–1`：`0` 是起点，`1` 是终点；它同时给出该位置的点和前进方向。`approximateLength` 用于回答“这条路线有多长”：直线和圆弧直接计算，贝塞尔和椭圆弧用固定数量的采样点近似。默认 `sampleCount` 为 32；提高它会更精确，也会更耗时。

`parameterAtDistance` 用于回答“走了这么远应到哪里”：贝塞尔和椭圆弧默认最多二分 32 次。若某个中点的近似已行进距离已在默认几何容差内，它会提前返回。若传入缓存的 `totalLength`，它必须与相同采样预算对应。

`slice` 也会限制并升序排列两个参数。二次 / 三次贝塞尔采用 De Casteljau 切分；圆弧和椭圆弧保留原来的有向扫描、圆心、半径与椭圆旋转。零长度或零导数段仍返回确定的点和 `[1, 0]` 切线，距离反解返回起始参数。

### 算法解析

先明确这里的 `t`：它是曲线内部的 $0–1$ 参数，`t=0` 选中起点，`t=1` 选中终点。它用来指定曲线定义中的位置，不是“已经走过多少 px”，通常也不是整条曲线的长度比例。只有直线和圆弧的行进速度均匀时，`t=0.5` 才恰好表示走完一半距离；贝塞尔和椭圆弧通常不成立。

想象一个箭头要沿曲线走 80px 后停下，或者要高亮从第 20px 到第 80px 的那一段。曲线本身只认识参数 $t$，不认识“走了多少 px”；更麻烦的是，贝塞尔曲线里相同的参数变化不一定对应相同的实际距离。

所以这组算法要完成三件相连的事：先估算从起点走到某个 $t$ 的距离；再把指定距离反查成对应的 $t$；最后按这两个参数从原曲线中切出一段。它不会把曲线结果变成折线，折线只用来帮助测量长度。

下图展示一次查找：先从当前区间取中点 $t$，估算走到该处的长度，再与目标距离比较。菱形没有通向“参数 $t$”的回路表示未命中：根据长度偏大或偏小收窄 $[lo,hi]$，再从新区间取中点；命中容差后才输出参数。

<ComponentPreview files="curve-distance-search-flow" size="sm" type="flow" hideCode />

从数学上看，每一小段参数变化带来的路程由曲线当时的速度决定。把所有小段路程累加，就是从起点走到 $t$ 的真实弧长：

$$
L(t)=\int_0^t\lVert p'(u)\rVert\,du
$$

直线和圆弧可以直接求出这个长度。贝塞尔和椭圆弧则把整段行程暂时看成 $m$ 个很短的直线步：逐段取点、计算相邻两点距离、再相加。这就是代码中对积分的离散近似：

$$
L(t)\approx\sum_{i=1}^{m}\left\lVert p\!\left(\frac{it}{m}\right)-p\!\left(\frac{(i-1)t}{m}\right)\right\rVert,\qquad m=\max(4,\lceil sampleCount\cdot t\rceil)
$$

这解释了 `sampleCount` 的取舍：步子越短，折线越贴近曲线，长度通常越准确，但要多计算一些点。`parameterAtDistance` 要回答的正是“走到第 80px 时参数是多少”：它在同一个近似长度函数上反复尝试中点 $t$，看已经累计的长度偏大还是偏小，再用二分缩小范围。直线和圆弧的长度均匀，可以直接按比例换算。

缓存 `totalLength` 时必须配合同一个 `sampleCount`，否则“总长度”和“走到这里的长度”来自两套近似，反查位置会不一致。要取“从 20px 到 80px”的一段时，先用 `parameterAtDistance` 得到两个参数，再交给 `slice`；贝塞尔随后通过 De Casteljau 保持原曲线形状，而不是输出用于测量的近似折线。

## 过点曲线

过点曲线把一组 knot 转换为连续的三次贝塞尔段。曲线会经过输入 knot，而不是只在它们附近平滑；`tension` 用来控制控制点距离和弯曲程度。这个算法也是 `<Step kind="smooth">` 的底层实现。

切换点集和张力，并移动面板中的控制点，观察点距不均、折返和重合点时的曲线变化。源码视图中的 `CubicSegment` 展示了每段三次贝塞尔曲线的两个控制点和终点。

<ComponentPreview files="curve-playground" size="md" caption="比较点集、张力与三次贝塞尔段" />

### 算法解析

内部采用 centripetal Catmull–Rom（$\alpha=0.5$）：每一段根据两端及其相邻 knot 计算局部切线，再转成两个贝塞尔控制点。参数间隔随点距变化，点距差异很大时能降低尖点或异常回环的风险。`tension` 只缩放控制柄长度，曲线仍严格经过每个 knot。

至少需要两个 knot；返回的段数为 `knots.length - 1`，每段终点严格命中下一个 knot。开放曲线两端复用端点形成单侧切线；重合 knot 用极小间隔避免除零，所以输出仍保持有限，但不保证任意输入下都没有自交。

## 错误与限制

- 过点曲线至少输入两个 knot，返回 `knots.length - 1` 段；重合点仍保持有限输出，但不保证任意点集没有自交。
- 曲线参数 `t` 通常不是弧长比例。需要按距离取点时，先用 `parameterAtDistance` 换算参数；其缓存长度须来自相同采样预算。
- 射线交点参数不是距离：方向未单位化时，距离还需乘以方向长度。
