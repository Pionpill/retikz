description: Understand how Inspect reuses final Core observations, compiles auxiliary IR in isolation, and delivers readonly layers in one commit

Inspect is an optional observer attached to a Core compile, not a second drawing or layout system. Ordinary Core compilation creates no auxiliary fragment and need not load Inspect when there is no registry, request, or matching owner.

## How Inspect cooperates with Core

Core draws the primary figure normally and provides the observation facts Inspect needs after a final occurrence exists. Inspect selects those facts, produces auxiliary IR, and asks Core to compile it. Core knows no Inspector Definitions, registries, or auxiliary-layer palette.

| What Core provides                            | How Inspect uses it                                                                                       |
| --------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| `CompileObservation.owner` and `occurrence`   | Matches a request to a final path-kind or composite occurrence                                            |
| `CompileObservation.value`                    | Validates final output with `subjectSchema` and supplies it to `inspect()`                                |
| `CompileObservationContext.theme`             | Gives auxiliary content the current occurrence's theme and semantic colors                                |
| `CompileObservationContext.compileFragment()` | Compiles ordinary IR returned by an Inspector in the current Theme, Scope-style, and provider environment |

An owner that does not publish final output from Core cannot gain observable facts by inspecting authored input alone; it must first provide the matching Core observation capability.

## When auxiliary content is drawn

Auxiliary content is not written during Core's primary drawing stage. In the observer `complete` stage of the same observed compile, it is compiled separately from final occurrences Core has already captured:

<ComponentPreview files="inspect-compile-flow.en" size="md" hideCode />

1. The host gives a registry and runtime selection to an optional compile driver, which registers one Core observer
2. While Core compiles the primary figure, the observer selects candidate sites by owner and source path
3. After each selected owner has produced final output, Core calls `observe()` with that output and the current occurrence context
4. `complete()` resolves selection, merges options, validates `subjectSchema`, and invokes the matching Definition's `inspect()`
5. Each ordinary `IRChild` returned by `inspect()` is passed to `compileFragment()` and compiled in isolation into an InspectionPlane; public identity, metadata, and animation semantics do not enter the auxiliary Scene
6. Render turns the InspectionPlane into non-hittable readonly layers; primary and auxiliary layers commit together only in the same revision

The InspectionPlane is `null` when no result matches or a callback returns no content. Extra cost comes only from observing selected owners, running Inspector callbacks, and compiling non-empty auxiliary fragments.

## Runtime selection

A request is runtime policy for which final occurrences reach an Inspector, not persisted diagram data. It may originate at a whole scene, an authored subtree, or the current occurrence:

| Structure                         | Meaning                                                                       |
| --------------------------------- | ----------------------------------------------------------------------------- |
| `InspectionSelectionRule` request | Selects an Inspector and scope with `inspector`, `target`, and `options`      |
| `InspectionSelectionRule` barrier | Prevents descendants from reopening Inspectors at a scene or authored subtree |
| scene target                      | Matches final occurrences with a given owner across the whole scene           |
| subtree target                    | Matches final occurrences below one authored Scope                            |
| self target                       | Matches the current object by source or occurrence index                      |

The playground places two curves in separate subtrees. Change target, control points, and labels, then enable the right barrier to see how local requests resolve against Core final occurrences:

One site may request several Inspectors. Sparse options for one Inspector merge from scene to subtree to current occurrence; ordinary `false` disables one Inspector only at the current site, while a barrier prevents descendants from reopening any Inspector.

Merging uses authored options, then the single `optionsSchema` applies defaults before `resolveOptions` expands shorthand. A parent with `labels: true` and a child with `{}` keeps labels enabled; an explicit child `labels: false` disables them. Every enabled rule is still validated at admission, even if it never matches or is later overridden.

Calling `StrokePathInspectOptionsSchema.parse({})` directly produces a defaulted snapshot containing `labels: false`. Passing that snapshot as child options makes `false` an explicit override. Persist authored configuration to retain omission intent; persisting parsed output stores materialized defaults instead.

## Results and errors

| Field                                 | Meaning                                                                |
| ------------------------------------- | ---------------------------------------------------------------------- |
| `InspectionCompileResult.primary`     | Ordinary Core compile output, unchanged by auxiliary content           |
| `InspectionCompileResult.inspection`  | Ordered auxiliary plane; `null` when every callback produces no output |
| `InspectionCompileResult.diagnostics` | Structured warnings from isolated fragments                            |

`RetikzInspectError.details.origin.stage` identifies a failure in selection, final-output validation, an `inspect` callback, output normalization, auxiliary-fragment compilation, or final assembly. Duplicate registry keys, unregistered requests, owner mismatch, and schema failures stop that inspection compile without delivering a partial auxiliary result.
