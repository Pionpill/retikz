`@retikz/vanilla` is the API foundation shared by all framework adapters. It organizes ordinary TypeScript data as an `InputScene`, normalizes that input into Core `IRScene`, and runs shared processing. React, Vue, and other framework packages only collect their framework input and host the result.

The package root works safely in SSR, build scripts, and other frameworks. Its default text measurer probes browser Canvas when measurement is requested. Browser SVG and Canvas mounting live at `@retikz/vanilla/dom`. IR, schemas, geometry, and compile rules belong to `@retikz/core`; backend output belongs to `@retikz/render`.

Applications use `createProcessingController`, `prepareStaticProcessing`, or `compileToScene` from the package root. Custom compile drivers implement `VanillaCompileDriver` with its input, session, and output contracts. Input preparation, runtime metadata snapshots, and driver execution/commit helpers remain internal.

## One-shot compilation

Pass Core IR or a Vanilla InputScene to `compileToScene` to obtain a Scene and artifacts without creating or disposing a session. Compile configuration stays under `options.compile`. Use `compileToSceneAsync` for asynchronous authoring preparation, with adapters that provide prepare.

```ts
import { compileToScene, compileToSceneAsync } from '@retikz/vanilla';

const result = compileToScene(ir);
const configured = compileToScene(ir, { compile: { padding: 10 } });
const prepared = await compileToSceneAsync(input, { adapters });

console.log(result.scene, result.artifacts);
```

A single graph returns a ProcessingResult at revision 0; explicit layers return an ordered list of named results. Use a controller for subsequent updates and subscriptions, or `normalizeXxx` when only assembling typed Input into Core IR.

## Default text measurement

An explicit `compile.measureText` takes precedence. Otherwise, Vanilla lazily uses Canvas 2D, falling back to the Core estimator when the environment or context is unavailable. Measurement failures and invalid metrics still fail. React's `Layout` uses the same default path.

`defaultFontFamily` supplies the measurement and display font when text has no explicit family; React forwards `Layout.style.fontFamily` to this option. If neither is set, browser measurement uses the computed font of the page `body`, then `sans-serif`. SVG export, SVG mounting, and Canvas mounting all accept this host default. Existing Scenes are not measured again, and font loading does not automatically trigger compilation. See [Text Metrics](/kernel/components/runtime-mechanics/text-metrics).

## Async authoring preparation

The internal `prepareProcessingInputAsync` traverses the complete author tree and calls adapter.prepare for non-computing preflight, then runs preparation.execute and normalizes the contributions. Nested inputs register through context.prepareChildren; children cannot execute during preparation. Synchronous adapters provide lower; asynchronous adapters must provide prepare, without probing support by invoking lower.

Use `compileToSceneAsync(input, options?)` for one-shot compilation, or `prepareStaticProcessingAsync` for explicit commit/discard. Interactive hosts use `createProcessingControllerAsync` and await committed/discarded update outcomes. Signals and newer requests invalidate stale results; failure preserves committed output. Core compilation and renderers remain synchronous; Promises live at the authoring preparation boundary.

Contributions bind prepared runtimeInputs to actual Source positions outside JSON IR. Composite children use opaque child transport rather than guessing instances from ids, dataset names or object references. Domain hosts already connect this boundary; applications normally use their async entry points.

## Install and use

```bash
pnpm add @retikz/vanilla
```

```ts
import { node, path, renderToSvgString, scene } from '@retikz/vanilla';
import { mount } from '@retikz/vanilla/dom';

const input = scene({
  id: 'flow',
  children: [
    node({ id: 'a', position: [0, 0], text: 'A' }),
    node({ id: 'b', position: [120, 0], text: 'B' }),
    path({ id: 'edge', way: ['a', 'b'], arrow: { end: {} } }),
  ],
});

const svg = renderToSvgString(input);
const view = mount(document.querySelector('#diagram')!, input);
```

`renderToSvgString` needs no DOM, so it suits SSR, build-time generation, and saving SVG. `mount` hosts a browser view, creating SVG by default or Canvas with `renderer: 'canvas'`. The returned `view` owns later `update`, interaction hydration, animation controls, and disposal.

`scene({ theme: { name, mode } })` writes a sparse Theme to the Input root, while `scope({ theme }, children)` uses the same local-inheritance form. Normalization copies Theme objects rather than mutating caller input; both routes finally use the same Core Theme and compile contract.

## Input normalization and processing

### Declare identity in the configuration

Node, Path, and Scope objects written directly in `children` must declare their `type`. The `node()`, `path()`, and `scope()` helpers and their JSX counterparts supply it for you.

Vanilla path configurations require exactly one of `way` and `children`. If both reach the runtime, explicit `children` take precedence, even when empty.

Vanilla constructors do not take a separate ID string argument. `node({ id, position })`, `path({ id, way })`, `coordinate({ id, position })`, and `layer({ name, children })` read identity from their configuration. Each input contract still determines whether `id` is required.

Domain builders also take their configuration directly, such as `shape.circle({ id, center, radius })` and `entity({ id, role, position })`. Inputs with a domain `id` reuse it as the embed identity; anonymous inputs do not gain a referenceable graphic ID. Layout inputs have no domain `id`, so use entries such as `flexLayout({ children })` directly.

Generic embedding uses an object with `kind`, `props`, and optional `id` and `authoring` fields: `embed({ kind, props })`. Plot and Table use `embedPlot(source, datasets, lowerOptions?)` and `embedTable(spec, options?)`, without an extra embed ID argument.

### Why InputScene exists

Directly building `@retikz/core` IR is valid, but applications often need authoring-friendly Path, Scope, Layer, Tier 2 embeds, and runtime metadata. `scene`, `layer`, `node`, `path`, `scope`, and `embed` construct those inputs as ordinary data, without JSX, a React runtime, or component lifecycles.

`InputScene` is not a second graphics semantic. `normalizeScene()` centrally handles input sugar, authoring provenance, and embed lowering, then produces the only Core `IRScene`. The resulting IR remains JSON-serializable; callers and their domain adapters decide whether `authoring` and `embed.props` are serializable.

## Execution and DOM boundary

| API                 | Purpose                             | Returns                      |
| ------------------- | ----------------------------------- | ---------------------------- |
| `renderToSvgString` | Produce an `<svg>` string for SSR   | `string`                     |
| `mount`             | Mount SVG or Canvas by `renderer`   | `VanillaView` / `CanvasView` |
| `mountSvg`          | Explicitly mount SVG DOM            | `VanillaView`                |
| `mountCanvas`       | Explicitly mount Canvas             | `CanvasView`                 |
| `hydrate`           | Bind handlers to SSR / existing SVG | `HydrationHandle`            |

The last four APIs are imported from `@retikz/vanilla/dom`. By default, `InputScene` and `IRScene` create a `VanillaViewMode.Retained` view. `update(next, options?)` atomically publishes the same processing transaction's Scene, artifacts, readonly layers, runtime metadata, events, and animation. A failed transaction publishes no new revision; if rollback itself fails, the view becomes broken and must be disposed and remounted.

With `runtime: { mode: 'static' }`, every `update()` of an `InputScene` or `IRScene` fully normalizes, compiles, and redraws without a Session, Snapshot, Patch, transaction, or rollback. A precompiled `Scene` is always static and accepts only another `Scene`.

`mode` and `updateStrategy` are fixed when mounting. `VanillaRetainedRuntimeOptions` permits `rendererFactory`; it is an optional DOM retained-backend extension point, and static mode rejects it. Dispose and remount to change the renderer, DPR, compile topology, or retained strategy.

## Layers and embeds

Direct children use an implicit main layer and return a single result. Explicit layers always return an ordered list of named results, even for zero or one layer. The default stacking values for background, main, and overlay are 0, 10, and 100; custom names default to 10. Ties keep declaration order. References and element stacking stay within a layer.

Layers inherit the common compile and reconciler options. The background preset selects full compilation; settings on the instance override that preset. Use `controller.replaceLayer` to update an overlay without resubmitting the background. Rendering still accepts one graph: pass an entry’s `result.scene` to render it individually. The renderer does not composite the list.

Tier 2 capabilities enter through `embed({ kind, id, props })`. Vanilla does not parse components or run hooks. It finds the caller-injected `InputEmbedAdapter` by `kind`, lowering typed props into a Core child and Composite dependency contribution.

```ts
import type { InputEmbedAdapter } from '@retikz/vanilla';
import { compileToScene, embed, layer, node, scene } from '@retikz/vanilla';

type BadgeProps = { label: string };

const BadgeInputEmbedAdapter: InputEmbedAdapter<BadgeProps> = {
  kind: 'badge',
  lower: (props, context) => ({
    node: node({ id: `${context.id}/label`, position: [0, 0], text: props.label }),
    providerDependencies: { roots: [], providers: [] },
  }),
};

const input = scene({
  layers: [layer({ name: 'content', children: [embed({ kind: 'badge', id: 'sales', props: { label: 'Sales' } })] })],
});

const [{ name, result }] = compileToScene(input, { adapters: [BadgeInputEmbedAdapter] });
console.log(name, result.scene);
```

`normalizeScene()` is exported from the package root. `adapters` is a top-level render, mount, and processing option—not a field inside `compile`. To inspect a normalized result, call `normalizeScene(input, { adapters })` and inspect the single result or each named entry’s result for `ir`, `contributions`, `runtimeMeta`, and `authoringSites`.

Adapters, Composite definitions, and compile topology are fixed for a retained mount's lifetime. A domain adapter can process new props at the same authored position; dispose and remount to change the adapter set, a Composite schema, definition count, or execution branch.

## Responsibility boundaries

| Capability              | What `@retikz/vanilla` owns                                 | Source of truth / boundary           |
| ----------------------- | ----------------------------------------------------------- | ------------------------------------ |
| Framework-neutral input | Builds InputScene, Layers, embeds, and Core primitive input | `@retikz/core` IR                    |
| Input normalization     | Lowers Input to IR and collects adapter contributions       | `@retikz/core` compile contract      |
| Shared processing       | Prepares input and manages the reconciler and results       | `@retikz/reconciler`                 |
| DOM host                | `/dom` SVG / Canvas output, updates, hydration, animation   | `@retikz/render` backend execution   |
| Tier 2 embeds           | Dispatches Input adapters and collects lowering results     | Domain packages own props / lowering |

React applications use [`@retikz/react`](/kernel/packages/react/overview) to collect JSX. Other frameworks should reuse this package's Input and processing in the same way. Use the relevant Vanilla entry directly for SSR strings or direct DOM / Canvas mounting.
