当内置控制点检查器不足以解释领域结果时，使用 `defineInspector()` 定义自己的 Inspector。内置与第三方定义共享同一注册表、选择、校验和辅助编译路径；不存在单独的内置白名单。

## 适用边界

Inspector 读取所属者发布的最终产物，并返回普通 `IRChild` 或其只读数组作为辅助内容。它不能写入主 Scene、修改主图，或绕开 Core 建立另一套渲染语义。

## 定义与注册

`InspectorKey.namespace` 使用拥有该能力的包稳定短名，而不是统一的 `retikz` 前缀：Core 使用 `core`，Layout 使用 `layout`，第三方使用所属包短名；`type` 在 namespace 内唯一。

## Definition 契约

| 字段                 | 职责                                            |
| -------------------- | ----------------------------------------------- |
| `namespace`、`type`  | 组成稳定复合键；namespace 使用能力所属包短名    |
| `owner`              | 指定要观察的 pathKind 或 composite owner        |
| `subjectSchema`      | 校验所属者发布的最终产物                        |
| `optionsInputSchema` | 校验每层稀疏选择选项                            |
| `optionsSchema`      | 把合并后的稀疏选项解析为规范选项                |
| `mergeOptionsInput`  | 可选的多层稀疏选项合并规则                      |
| `inspect`            | 将最终产物和上下文转换为普通 `IRChild` 辅助内容 |

## 执行机制

每次检查从显式 registry 开始。`createDefaultInspectorRegistry()` 先加入内置 Inspector，再把第三方 Definition 放入同一路径。选择解析后，只有可能匹配的所属者才请求 Core 发布观测结果；相同 `namespace + type` 会立即失败。

## 错误与限制

重复注册键或请求未注册 Inspector 时，registry 或选择会抛出 `RetikzInspectError`，不继续交付部分结果。最终产物、选项或输出未通过 schema 校验时，也会带对应阶段来源失败。

## API 参考

| API                                | 说明                                                    |
| ---------------------------------- | ------------------------------------------------------- |
| `defineInspector()`                | 校验并冻结一个 `InspectorDefinition`                    |
| `createInspectorRegistry()`        | 从显式 Definition 创建无全局状态的 registry；重复键失败 |
| `createDefaultInspectorRegistry()` | 创建内置 registry，并可追加第三方 Definition            |
| `STROKE_PATH_INSPECTOR_KEY`        | 内置 `stroke` Path Inspector 的复合键                   |
| `STROKE_PATH_INSPECTOR`            | 内置 `stroke` Path Inspector Definition                 |
