When a shape moves or rotates, the points that describe the shape can stay the same. A coordinate transform moves a point from the shape's own coordinate system into the coordinate system of the whole canvas, or converts it back again.

This page starts with the common case of local and world coordinates, then introduces two-dimensional affine matrices for composing translation, scaling, and rotation. On a first read, start with the first section and come back to affine matrices when you need them.

## Basic usage

Import from the root entry. Results are numbers or geometry, not rendered drawings.

```ts
import {
  localToWorld,
  worldToLocal,
  applyAffine,
  multiplyAffine,
  type CenteredShape,
  type AffineMatrix,
} from '@retikz/math';

const shape: CenteredShape = { x: 100, y: 60, rotate: 0 };
const world = localToWorld(shape, [20, 0]); // [120, 60]
const local = worldToLocal(shape, world); // [20, 0]
```

## Local and world coordinates

Imagine a shape with its own orientation inside a larger canvas. The canvas has a fixed coordinate system, while the shape has another one: its center is the local origin, and its local `x` and `y` axes rotate with the shape.

| Coordinate system | Origin and axes                                 | Common use                            |
| ----------------- | ----------------------------------------------- | ------------------------------------- |
| Local             | Origin at the shape center; axes rotate with it | Describe vertices, anchors, and edges |
| World             | Origin and axes fixed to the whole canvas       | Draw shapes and relate them to others |

In the diagram, the dashed lines are the fixed world axes, while the orange shape and orange axes belong to the same local coordinate system. Adjust the shape center, rotation, and local point in the control panel to see the same local point produce different world coordinates.

The demo control accepts degrees (°) and converts them with `degrees * Math.PI / 180` before calling the API. The API `rotate` value always uses radians.

`CenteredShape` describes this local coordinate system using a center and a rotation: `x` and `y` are the shape center in world coordinates, and `rotate` is the rotation in radians. `Math.PI / 4` is 45°; in screen coordinates, positive angles increase clockwise.

```ts
const shape: CenteredShape = { x: 100, y: 60, rotate: Math.PI / 4 };
const world = localToWorld(shape, [20, 0]); // approximately [114.1, 74.1]
const local = worldToLocal(shape, world); // approximately [20, 0]
```

`[20, 0]` is not a fixed canvas position. It means “20 units to the right of the shape center” in the shape's own coordinates. `localToWorld` rotates that point with the shape and then adds the shape center; `worldToLocal` performs the reverse operation.

Choose the function from the data you already have:

| Known data                          | Result you need               | Function       |
| ----------------------------------- | ----------------------------- | -------------- |
| A local vertex, anchor, or boundary | Its position on the canvas    | `localToWorld` |
| A canvas mouse or hit-test point    | Its position inside the shape | `worldToLocal` |

The two functions are inverses. Both return a new point and leave the input tuple unchanged.

### Algorithm notes

The upper lane maps a local point to a world point: `localToWorld` rotates around the local origin by `rotate`, then adds the shape center. The lower lane performs the reverse: `worldToLocal` first subtracts the shape center, then rotates by the negative angle. `CenteredShape` sits between the lanes and supplies the shared center and rotation; when `rotate` is `0` or omitted, rotation leaves the point unchanged. The two lanes use different colors to distinguish conversion directions.

## Two-dimensional affine matrices

The previous local-to-world conversion is itself an affine transform: rotate, then translate. `CenteredShape` reduces that common case to a center and an angle. When a transform also needs scaling, reflection, shear, or several composed steps, use a two-dimensional affine matrix. Think of it as a recipe for calculating a new point: give it `[x, y]`, and it produces `[x', y']`.

`AffineMatrix` follows SVG / Canvas notation: it is a six-number tuple in the fixed order `[a, b, c, d, e, f]`. The values have two parts:

| Part           | Intuitive role                                   |
| -------------- | ------------------------------------------------ |
| `[a, b, c, d]` | Combine rotation, scaling, reflection, and shear |
| `[e, f]`       | Move the result to a new position                |

The first four values form the linear part:

$$
\begin{bmatrix}
a & c \\
b & d
\end{bmatrix}
$$

By the input coordinate each value receives, they mean:

| Value | Contribution             |
| ----- | ------------------------ |
| `a`   | Input `x` to output `x'` |
| `b`   | Input `x` to output `y'` |
| `c`   | Input `y` to output `x'` |
| `d`   | Input `y` to output `y'` |

With that tuple order, the calculation for a point is:

$$
\begin{aligned}
x' &= ax + cy + e \\
y' &= bx + dy + f
\end{aligned}
$$

For example, these matrices first scale the horizontal coordinate by 2 and the vertical coordinate by 3, then move the result right by 10 and down by 20:

```ts
const translate: AffineMatrix = [1, 0, 0, 1, 10, 20];
const scale: AffineMatrix = [2, 0, 0, 3, 0, 0];
const matrix = multiplyAffine(translate, scale);

applyAffine(matrix, [4, 5]); // [18, 35]: scale first, then translate
```

The point therefore goes through `[4, 5] → [8, 15] → [18, 35]`; `[8, 15]` is the coordinate after scaling.

In `multiplyAffine(outer, inner)`, `inner` is the inner transform applied first, and `outer` is the outer transform applied afterward. The example therefore scales first and translates second; swapping the arguments changes the result.

### Algorithm notes

A two-dimensional affine calculation has two stages: compose the recipe, then apply it. The inner matrix, `inner`, transforms the original point first; the outer matrix, `outer`, then transforms that result. They do not act from left to right in their written order. The composed matrix, `combined`, therefore satisfies:

$$
\operatorname{apply}(OI,p)=\operatorname{apply}(O,\operatorname{apply}(I,p))
$$

For `outer = [A, B, C, D, E, F]` and `inner = [a, b, c, d, e, f]`, write the composed result as `combined = [a', b', c', d', e', f']`:

$$
\begin{aligned}
a' &= Aa + Cb & b' &= Ba + Db \\
c' &= Ac + Cd & d' &= Bc + Dd \\
e' &= Ae + Cf + E & f' &= Be + Df + F
\end{aligned}
$$

The first four values compose rotation, scale, reflection, or shear. The final two first transform the inner translation `[e, f]`, then add the outer translation `[E, F]`. `multiplyAffine` only composes the recipe; `applyAffine` then uses an input point's `x` and `y` in two linear combinations to produce the new point.

Choose between the two capabilities this way: use `localToWorld` / `worldToLocal` for local points around a shape center; use `AffineMatrix`, `multiplyAffine`, and `applyAffine` for arbitrary two-dimensional affine transforms or multi-step transform chains.

When a consumer needs to check a matrix before using it, `isFiniteNonSingularAffine` verifies that it contains finite values and is invertible. For cases such as stroke scaling that require one uniform scale, `getAffineSimilarityScale` returns the scale factor and returns `undefined` for other matrices.

| Category | API                         | Purpose                                                                   |
| -------- | --------------------------- | ------------------------------------------------------------------------- |
| Type     | `AffineMatrix`              | Represents a 2D affine matrix in `[a, b, c, d, e, f]` order               |
