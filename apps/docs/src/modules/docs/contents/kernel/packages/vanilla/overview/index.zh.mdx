`@retikz/vanilla` 是所有框架适配器共用的 API 基础包。它用普通 TypeScript 数据组织 `InputScene`，将其归一为 Core `IRScene`，再运行共享的 processing；React、Vue 等框架包只需要负责各自的输入收集和宿主接线。

包根可安全用于 SSR、构建脚本或其它框架。默认文字测量器在实际测量时探测浏览器 Canvas；浏览器 SVG / Canvas 挂载位于 `@retikz/vanilla/dom` 子入口。IR、schema、几何与编译规则属于 `@retikz/core`，后端输出属于 `@retikz/render`。

应用从包根调用 `SceneRuntime` 或 `compileToScene`。

持续会话的诊断通过 `runtime.diagnostics()` 读取。

单次编译和持续更新共用输入准备。单次编译直接返回 `CompileResult`；持续模式下，`runtime.read()` 和订阅回调拿到的是协调器已提交的同一个 `ReconcilerResult` 快照。用 `snapshot.compilation.result` 读取本帧编译产物，增量更新时把快照本身作为 `expected` 传回。订阅者可以读取新结果，不能在同一次同步通知中再次写入。预编译的 Scene 直接交给 Render，不创建编译会话。

已有编译好的 Scene 时，直接用 `renderToSvg(scene)` 导出 SVG。这个函数只读取场景，不会再次编译。

## 一次性编译

将 Core IR 或 Vanilla InputScene 交给 `compileToScene` 即可取得 Scene 和 artifacts，无需创建或释放会话。配置继续使用 `options.compile`。

```ts
import { compileToScene } from '@retikz/vanilla';

const result = compileToScene(ir);
const configured = compileToScene(ir, { compile: { padding: 10 } });

console.log(result.scene, result.artifacts);
```

单图编译直接返回 `CompileResult`，从中读取 Scene 和 artifacts；层栈由独立的 `compileLayers` 返回具名结果列表。需要后续更新与订阅时使用 `SceneRuntime`；只想将 typed Input 组装成 Core IR 时使用 `normalizeXxx`。

## 持续处理一张图

用 `SceneRuntime.fromInput(input, options)` 或 `SceneRuntime.fromIR(ir, options)` 建立会话。

```ts
import { SceneRuntime } from '@retikz/vanilla';

const runtime = SceneRuntime.fromInput(input);
try {
  runtime.replace(nextSource);
  const svg = runtime.renderToSvg();
} finally {
  runtime.dispose();
}
```

完整替换可以在作者输入与 IR 之间切换，不推导 diff。增量模式下，先用 `expected = runtime.read()` 取得当前版本，通过 `runtime.getScopeId(path, expected)` 寻址，再用 `runtime.update(batch, expected)` 提交。旧版本会被拒绝。导出只读取最后一次成功提交的帧。

## 默认文字测量

`compile.measureText` 显式提供时优先使用；否则由 Vanilla 按需使用 Canvas 2D，环境或上下文不可用时使用 Core 的估算器。实际测量异常和非法指标仍会报错。React 的 `Layout` 复用同一路径。

文字没有显式字体族时，默认浏览器测量器读取页面 `body` 的计算字体，取不到时使用 `sans-serif`。宿主 CSS 只影响显示，不会改变已有 Scene 的几何。详见[文字度量](/kernel/components/runtime-mechanics/text-metrics)。

## 输入就绪后再提交

应用先等待数据，再构造输入并调用 `compileToScene` 或 单图会话的 `replace`。提交顺序就是更新顺序；是否忽略较晚返回的旧请求由应用决定。嵌入 adapter 的 `lower` 同步返回节点、依赖及按实例绑定的运行时输入，后者不写入 JSON IR。

例如，外接执行器的 Plot 可以和普通节点在同一次更新中提交：

```ts
import { preparePlotData } from '@retikz/plot';
import { plotInputEmbedAdapter } from '@retikz/plot-vanilla';
import { embed, node, scene } from '@retikz/vanilla';

const task = await preparePlotData(spec, { dataBindings, dataTransformExecutor });
const preparedData = await task.execute();
runtime.replace(
  scene({
    children: [
      node({ id: 'origin', position: [0, 0] }),
      embed({ adapter: plotInputEmbedAdapter, props: { spec, preparedData } }),
    ],
  }),
);
```

## 安装与使用

```bash
pnpm add @retikz/vanilla
```

```ts
import { compileToScene, node, path, renderToSvg, scene } from '@retikz/vanilla';
import { mount } from '@retikz/vanilla/dom';

const input = scene({
  children: [
    node({ id: 'a', position: [0, 0], text: 'A' }),
    node({ id: 'b', position: [120, 0], text: 'B' }),
    path({ id: 'edge', way: ['a', 'b'], arrow: { end: {} } }),
  ],
});

const compileResult = compileToScene(input);
const svg = renderToSvg(compileResult.scene);
const view = mount(document.querySelector('#diagram')!, input);
```

`renderToSvg` 可安全用于 SSR、构建期生成或保存 SVG；`mount` 用于浏览器宿主，默认创建 SVG，也可以通过 `renderer: 'canvas'` 切换到 Canvas。返回的 `view` 负责后续 `update`、交互水合、动画控制与释放。

`scene({ theme: { name, mode } })` 会把稀疏 Theme 写入 Input 根，`scope({ theme }, children)` 复用同一局部继承写法。归一化沿用 Theme 引用，不修改调用方输入；最终两条路径都交给同一份 Core Theme 与 compile 契约。

## 输入归一与 processing

### 用配置对象声明身份

直接写入 children 的 Node、Path、Scope 对象必须声明 `type`。使用 `node()`、`path()`、`scope()` 或对应 JSX 组件时，入口会提供类别，不需要重复填写。

Vanilla 的路径配置必须在 `way` 与 `children` 中选择一项。`way` 检查算子和目标的顺序；显式 `children` 只展开简写，不按步数拒绝路径。短路径的几何诊断由 Core 编译器处理，与是否提供 `authoring` 无关。字符串相对偏移的两个分量都必须是有限数。三段折线（`-|-` 或 `|-|`）可用 `fraction` 指定中段位置。

Vanilla 构造函数不接收独立的 ID 字符串参数。`node({ id, position })`、`path({ id, way })`、`coordinate({ id, position })` 和 `layer({ name, scene })` 都从配置读取身份；是否必须提供 `id` 仍由对应输入契约决定。

领域 builder 同样直接接收配置，例如 `shape.circle({ id, center, radius })`、`entity({ id, role, position })`。已有领域 `id` 的输入会复用该值作为 embed 身份；匿名输入不因此获得可引用的图元 ID。Layout 输入没有领域 `id`，直接使用 `flexLayout({ children })` 等入口。

通用嵌入使用 `embed({ adapter, props })` 工厂绑定 adapter 与 props，还可传入 `id` 与 `authoring` 字段。Plot 与 Table 使用 `embedPlot(source, datasets, lowerOptions?)`、`embedTable(spec, options?)`，无需额外传入 embed ID。

### 为什么需要 InputScene

直接构造 `@retikz/core` IR 是可行的，但应用经常需要更便于书写的 Path、Scope、Layer、Tier 2 embed 与作者载荷。`scene`、`layer`、`node`、`path`、`scope` 与 `embed` 用普通数据构造这些作者输入，不要求 JSX、React runtime 或组件生命周期。

`InputScene` 不是第二套图形语义：`normalizeScene()` 只在 Vanilla 集中处理输入简写、作者来源与 embed 下沉，并产生唯一的 Core `IRScene`。最终 IR 保持 JSON 可序列化；`authoring` 与 `embed.props` 是否可序列化由调用方和对应的领域 adapter 决定。

## 执行与 DOM 边界

| API                 | 用途                                 | 返回                         |
| ------------------- | ------------------------------------ | ---------------------------- |
| `renderToSvg` | SSR / 构建期产出 `<svg>` 字符串      | `string`                     |
| `mount`             | 按 `renderer` 挂载 SVG 或 Canvas     | `VanillaView` / `CanvasView` |
| `mountSvg`          | 显式挂载 SVG DOM                     | `VanillaView`                |
| `mountCanvas`       | 显式挂载 Canvas                      | `CanvasView`                 |
| `hydrate`           | 对 SSR / 已有 SVG 根节点绑定 handler | `HydrationHandle`            |

后四项都从 `@retikz/vanilla/dom` 导入。默认情况下，`InputScene` 与 `IRScene` 创建 `VanillaViewMode.Retained` view：`update(next, options?)` 通过同一个 processing transaction 原子发布 Scene、artifacts、事件与动画。失败 transaction 不发布新 revision；若 rollback 自身失败，view 进入 broken 状态，必须 dispose 后 remount。

显式传 `runtime: { mode: 'static' }` 时，`InputScene` 或 `IRScene` 的每次 `update()` 都会完整归一、编译与重绘，不创建 Session、Snapshot、Patch、transaction 或 rollback。预编译 `Scene` 也总是 static，只接受下一份 `Scene`。

`mode` 与 `updateStrategy` 在 mount 时固定。`VanillaRetainedRuntimeOptions` 允许注入 `rendererFactory`；这是 DOM retained 后端的可选扩展点，static 模式不能传它。需要改变 renderer、DPR、compile topology 或 retained 策略时，先 dispose，再 remount。

## 分层与嵌入

直接传 children 只产生隐式 main，仍读取单图结果。使用 `compileLayers(layers)` 则始终得到具名结果列表，包括空列表或只有一层的情况。background、main、overlay 的默认层序分别为 0、10、100；自定义名称默认 10。相同层序保留声明顺序，元素不能跨层引用或越层绘制。

各层持有自己的完整场景，包括主题与视框。`createLayerController(layers, options)` 创建层栈；公共 compile 和 reconciler 配置由各层继承；背景预设使用全量模式，层实例可显式覆盖预设。更新浮层时调用 `controller.replaceLayer`，不必重新提交背景。渲染入口仍接收单图；可单独渲染持续层栈某项的 `result.compilation.result.scene`，不会自动合成整个列表。

Tier 2 能力通过 `embed({ adapter, id, props })` 接入。Vanilla 不解析组件，也不执行 hooks；它直接调用节点绑定的 `InputEmbedAdapter`，将已类型化 props 下沉为 Core child 与 Composite dependency contribution。

```ts
import type { InputEmbedAdapter } from '@retikz/vanilla';
import { compileLayers, embed, layer, node, scene } from '@retikz/vanilla';

type BadgeProps = { label: string };

const BadgeInputEmbedAdapter: InputEmbedAdapter<BadgeProps> = {
  kind: 'badge',
  lower: (props, context) => ({
    node: node({ id: `${context.id}/label`, position: [0, 0], text: props.label }),
    providerDependencies: { roots: [], providers: [] },
  }),
};

const layers = [
  layer({
    name: 'content',
    scene: scene([embed({ adapter: BadgeInputEmbedAdapter, id: 'sales', props: { label: 'Sales' } })]),
  }),
];

const [{ name, result }] = compileLayers(layers);
console.log(name, result.scene);
```

`normalizeScene()` 从包根导出；宿主不再需要注册 adapter。需要检查归一结果时，可从 `normalizeScene(input)` 返回的单图结果中读取 `ir`、`contributions`、`runtimeInputs` 与 `authoringSites`。 未提供 `authoring` 的节点不会生成来源记录；adapter 显式贡献的记录仍会保留。

调用方须在使用期间保持传入的编译与渲染配置、Composite 定义及已注册的事件表稳定；原地修改不受支持，Vanilla 不保证隔离其影响。领域 adapter 可以在同一输入位置处理新的 props；需要改变 Composite schema、definition 数量或执行分支时，dispose 后 remount。

## 职责边界

| 能力            | `@retikz/vanilla` 负责什么                               | 能力真源 / 边界                |
| --------------- | -------------------------------------------------------- | ------------------------------ |
| 无框架输入      | 构造 InputScene、Layer、embed 与 Core 图元输入           | `@retikz/core` IR              |
| 输入归一        | 将 Input 下沉为 IR，收集 adapter contribution 与作者来源 | `@retikz/core` compile 契约    |
| 共享 processing | 准备输入、管理协调器与处理结果                           | `@retikz/reconciler`           |
| DOM 宿主        | 在 `/dom` 输出 SVG / Canvas、更新、水合与动画生命周期    | `@retikz/render` 后端执行      |
| Tier 2 嵌入     | 调用节点绑定的 adapter 并聚合 lowering contribution      | 各领域包拥有 props 与 lowering |

React 应用使用 [`@retikz/react`](/kernel/packages/react/overview) 收集 JSX；其它框架同样应复用本包的 Input 与 processing。需要 SSR 字符串或直接 DOM / Canvas 挂载时，直接使用本包的对应入口。

## API 摘要

| API                                  | 类型          | 说明                                                     |
| ------------------------------------ | ------------- | -------------------------------------------------------- |
| `scene` / `layer`                    | Input helper  | 构造 Scene 与具名 Layer                                  |
| `node` / `coordinate` / `path`       | Input helper  | 构造 Core 图元或作者侧 Path 输入                         |
| `scope` / `embed`                    | Input helper  | 构造作用域与 Tier 2 embed 输入                           |
| `BuiltinLayerName`                   | const object  | 内置图层名称                                             |
| `InputScene` / `InputChild`          | type          | 框架无关的作者输入根与子项                               |
| `InputLayer` / `InputNode`           | type          | Layer 与 Node 输入                                       |
| `InputPath` / `InputScope`           | type          | 可带作者侧语法糖或载荷的路径和作用域输入                 |
| `InputEmbed`                         | type          | Tier 2 embed 输入                                        |
| `InputEmbedAdapter`                  | type          | 将 `InputEmbed` 下沉为 Core contribution                 |
| `isInputScene` / `normalizeScene`    | normalization | 区分已类型化的 InputScene / IRScene，并归一作者输入      |
| `SceneNormalizationResult`           | type          | IR、contributions、实例输入 与作者来源                   |
| `ProcessingOptions`                  | type          | compile 与 retained 更新策略                             |
| `SceneRuntime`                       | processing    | 无框架 retained processing controller                    |
| `compileToScene`                     | processing    | 一次性同步编译 InputScene 或 Core IR                     |
| `renderToSvg`                  | SSR           | 将已编译的 Scene 序列化为 SVG 字符串                     |
| `mount` / `mountSvg` / `mountCanvas` | DOM           | 从 `@retikz/vanilla/dom` 挂载浏览器 view                 |
| `VanillaRuntimeOptions`              | type          | InputScene / IRScene 的 retained 或 static runtime 配置  |
| `VanillaRetainedRuntimeOptions`      | type          | retained 模式、更新策略与可选 renderer factory           |
| `VanillaStaticRuntimeOptions`        | type          | 只允许 `mode: 'static'` 的封闭配置                       |
| `RetainedVanillaView`                | runtime       | IRScene / InputScene 的事务式 retained view              |
| `StaticVanillaView`                  | runtime       | Scene、IRScene 或 InputScene 的完整重绘 view             |
| `RetikzVanillaError`                 | error         | Vanilla 唯一错误类，通过 code、details 与 cause 区分失败 |
| `RetikzVanillaErrorCode`             | const object  | normalize、processing、runtime、与 DOM 稳定错误码        |
