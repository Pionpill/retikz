语义解析能够补全位置表达，却不一定知道某个名称现在指向哪份几何。Core 的 resolve 保留表达意图，compile/reference 再利用调度方提供的名称与变换上下文求点。名称生命周期和可见性由 Reconciler 维护。

## 整体流程

局部点属于当前 Scope，世界点包含当前及祖先 Scope 的变换。普通坐标先在局部计算再投影；命名目标先读取已发布的世界几何，再转换给局部消费者。没有变换时两个空间重合。

## 表达确定化与几何求值

`resolvePosition` 补全方向距离、极坐标原点及嵌套表达，不查询名称。例如 `{ of: 'A', direction: 'right' }` 可以确定有效 distance，却仍要等 A 的几何可查，才能知道放置位置。不能因为进入 Canonical 就提前丢弃引用。

| 表达                                                     | 求值规则                                                  |
| -------------------------------------------------------- | --------------------------------------------------------- |
| [20, 10]                                                 | 当前 Scope 的局部点                                       |
| `{ angle: 90, radius: 40 }`                              | 从局部原点计算；屏幕坐标中正角度朝下旋转                  |
| `{ of: 'A', direction: 'right', distance: 40 }`          | A 的世界中心转局部，再按局部方向移动；distance 是中心间距 |
| `{ of: 'A', offset: [40, 0] }`                           | 求局部基点后叠加局部偏移                                  |
| `{ between: [{ id: 'A' }, { id: 'B' }], fraction: 0.5 }` | 两个世界目标插值，再转回当前局部空间                      |

这些是共享机制的代表，各消费方的 Schema 决定允许哪些形式。Node 支持自身锚点对齐；Scope 的位置还涉及包络；路径相对游标不是这里的通用位置表达。

## 局部偏移与目标偏移

`{ of: 'A', offset: [40, 0] }` 的位移属于当前局部空间；节点目标 `{ id: 'A', offset: [40, 0] }` 的 offset 在世界空间叠加。缩放存在时，两者会产生不同结果。

<ComponentPreview files="coordinate-spaces" size="lg" hideCode type="illustration" />

图中基点为世界 [100, 50]，所属 Scope 缩放为 2。局部偏移 40 得到世界 [180, 50]；世界目标偏移 40 得到 [140, 50]。这不是默认值差异，而是两种契约选择了不同空间。

## 名称、目标与锚点

名称查找先取得 PositionReferenceView，包含 geometry、state 和来源；随后才求锚点。Node 和具名 Scope 提供边界几何，Coordinate 只提供位置，不绘制图元。

`evaluatePosition` 返回 localPoint / worldPoint。`evaluatePositionTargetWorld` 先返回 referencePoint，并在直接目标时保留 reference 与可选连接面绑定；`evaluatePositionTarget` 再补当前局部 point。插值结果不伪装成一个直接节点引用。

未指定 anchor 的位置目标通常读取中心，路径还可能继续执行自动边界裁剪。标准锚点与自定义形状锚点由能力契约解释，不能把字符串名称都当作通用坐标。未知锚点会失败；Coordinate 的零尺寸几何也不能支持有实际边长含义的比例点。

## 引用时机

Node 与 Coordinate 在访问时求值，引用对象需要可查。Node 自身锚点对齐必须先有临时自身布局，再计算目标与自身锚点的世界位移，反投影到局部空间；引用自身、未定义对象或仍在布局的 Scope 会失败。

Path 有独立的延迟机制：根路径等根子树完成，Scope 内路径等该 Scope 收尾。因此本层后续节点可以成为路径目标，但 Scope 内路径不能据此引用 Scope 之外更晚才声明的对象。

具名 Scope 在子项执行前可能只发布 position 占位。`scope-placeholder` 与 `resolved` 是不同状态；需要完整包络的读取不能把位置占位当成就绪边界。找不到引用时，底层求值返回 null 或空 referencePoint，由消费阶段决定失败或诊断，不补一个假原点。

## 完整实现流程

以下以 Coordinate 为主线：它经过语义解析和局部点求值，Reconciler 再投影世界点、发布名称并提供布局占位。它不会产生可见 ScenePrimitive。Node 与 Path 使用同一位置服务，但各自拥有最终定位或端点处理。

<ComponentPreview files="coordinate-implementation" size="lg" hideCode type="flow" />

Core 的 createPositionEvaluateContext 适配几何查询与坐标转换；Reconciler 的 createTreePositionContext 将名称栈、Scope 变换和共享边界状态投影为这个窄接口。把这些服务注入 Core，可以让原子计算不依赖某种树或增量引擎。
