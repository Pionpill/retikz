`@retikz/core` owns IR, Definitions, registries, compilation, and Scene semantics. `compileToScene()` remains the stateless full-compile entry; for state across revisions, `CoreSourceDefinition` and `createCoreComputation()` connect the same compile semantics to `@retikz/runtime`.

## Composable schema fragments

Custom inputs can import these closed fragments from `@retikz/core` and compose the fields they need. The fragments remain sparse and do not materialize defaults; the final entity still owns cross-field validation and its unknown-key policy.

| Fragment                      | Fields and purpose                                                               |
| ----------------------------- | -------------------------------------------------------------------------------- |
| `GraphicColorSchema`          | `color`: the graphic master color                                                |
| `GraphicElementOpacitySchema` | `opacity`: whole-element opacity                                                 |
| `GraphicFillSchema`           | `fill`, `fillOpacity`: fill paint and opacity                                    |
| `GraphicStrokeSchema`         | `stroke`, `strokeOpacity`: stroke paint and opacity                              |
| `StrokeStyleSchema`           | `strokeWidth`, `dashPattern`, `dashOffset`: width and dashes                     |
| `StrokeCapJoinSchema`         | `lineCap`, `lineJoin`: endpoint caps and corner joins                            |
| `TextVisualSchema`            | `textColor`, `font`: text color and font within an element                       |
| `TextLayoutSchema`            | `align`, `lineHeight`, `maxTextWidth`: text layout and wrapping                  |
| `PathTransformSchema`         | `roundedCorners`, `rotate`, `scale`: geometric corners and whole-path transforms |

Fill and stroke share `PaintValueSchema`, including gradient paints. Master color and whole-element opacity are selected independently; the text visual fragment does not include label-specific opacity or layout fields. Each fragment has a corresponding inferred `IRXxx` type. Existing complete Node, Path, and style aggregates remain available.

Composing `.shape` reuses fields only; it does not carry object-level refinements, transforms, or catchalls. Domain inputs should select only fragments they consume. For example, combining stroke, fill, and text for a Cell does not also admit `zIndex` or visual effects.

## Composite runtime inputs

`CompileOptions.compositeInputs` binds runtime input to exact Source positions for the current compilation. Composite callbacks consume it through context.runtimeInput; unbound positions yield undefined. Sources, functions and prepared results stay outside IR; Core does not interpret their domain meaning.

Composite context.sourceChild preserves authored child identity; context.bindChild explicitly binds generated children. Opaque children belong to one compile context and cannot be manually unpacked or serialized. Probes, replay and direct lowering consume the same bindings without reexecuting domain computation. Retained Computations publish runtime input and Source in one transaction.

## Theme environment

Core exports `ThemeMode`, `ThemeSchema`, `ResolvedTheme`, and `ResolvedThemeColors`. `IRScene.theme` and `IRScope.theme` persist only sparse, JSON-safe `style` / `mode` selectors. Compile starts from the default light baseline, inherits through Scene → Scope, and passes a complete frozen `ResolvedTheme` to `CompositeDefinition.expand`, layout-aware `compile`, and the observation context.

Published packages do not provide named styles. Define a custom style with `defineThemeStyle` and inject it through compile `themeStyles`. The resolver returns only sparse overrides relative to the current mode's default shared colors: `semantic` merges by role, while an explicit `categorical` palette replaces the default as a whole. Known fields that are omitted or explicitly returned as `undefined` retain their mode-aware defaults through the existing `??` fallback. Core parses the output once with its owner schema, so unknown fields, blank colors, empty palettes, and invalid values fail loudly without a generic JSON preflight or snapshot. Resolver functions and runtime results never enter IR, and an unregistered name also fails loudly.

```ts
import { defineThemeStyle, ThemeMode } from '@retikz/core';

const brand = defineThemeStyle({
  name: 'brand',
  resolve: ({ mode }) => ({
    semantic: { guide: mode === ThemeMode.Dark ? '#94a3b8' : '#64748b' },
  }),
});
```

Core only propagates selectors and creates a detached, frozen `colors` view; it does not interpret domain tokens. `ResolvedTheme.colors` exposes shared semantic colors (`error`, `success`, `warning`, and the lower-emphasis auxiliary `guide`) and the active categorical palette, whose values may repeat and are consumed with a stable modulo index. Core primitives, the final Scene, and renderers do not branch on Theme. See [Compile](/kernel/packages/core/overview) for behavior and failures and [Scene](/kernel/components/layout/schema-reference) for the schema.

Static CSS color parsing, opaque precomposition, and the generic `JsonValue` / `JsonObject` types and schemas are owned by [`@retikz/foundation`](/kernel/packages/foundation/schema-reference#jsonobjectschema). Core owns Theme mode, final master-color chains, and contextual-color materialization, and no longer re-exports those domain-free atoms from its root.

## Complete Snapshots And The Core Computation

Callers always submit a complete IR Snapshot. The Core owner copies, freezes, and compares the document. The Core Computation reads that typed Snapshot, produces a complete `CompileResult`, `SceneRuntimeSnapshot`, and optional `ScenePatch`, then lets the Runtime Runtime publish them atomically.

<ComponentPreview files="core-runtime-computation" size="xs" hideCode />

Runtime does not interpret Nodes, Paths, Scopes, Composites, or Scenes. Core decides domain identities, compile diagnostics, and full-fallback `replaceScene` Patches; Runtime only constrains dependency order, candidate isolation, revisions, and publication.

## Basic Wiring

`CoreSourceDefinition` and `createCoreComputation()` are ordinary Runtime Definitions, so they can share one Runtime with other domain Sources and Computations. The initial full run has no `patch`; a renderer mounts from the complete `snapshot`.

```ts
import { CORE_SOURCE_KEY, CORE_COMPUTATION_ID, CoreSourceDefinition, createCoreComputation } from '@retikz/core';
import {
  createRuntimeSourceInput,
  createRuntimeSourceRegistry,
  createRuntimeComputationRegistry,
  createRuntime,
} from '@retikz/runtime';

const ir = {
  version: 1,
  type: 'scene',
  children: [{ type: 'node', id: 'hello', position: [0, 0], text: 'Hello' }],
} as const;

const coreComputation = createCoreComputation({ padding: 16 });
const sources = createRuntimeSourceRegistry([CoreSourceDefinition]);
const computations = createRuntimeComputationRegistry({ sources, builtins: [coreComputation] });
const runtime = createRuntime({
  sources,
  computations,
  initialSnapshots: [createRuntimeSourceInput(CoreSourceDefinition, ir)],
});

const { output, snapshot, patch } = runtime.artifact(coreComputation).value;
// output.result: complete CompileResult
// snapshot.revision: 0
// patch: undefined
```

The fixed identities are `CORE_SOURCE_KEY = '@retikz/core/document'` and `CORE_COMPUTATION_ID = { owner: CORE_SOURCE_KEY, key: 'compile' }`. Do not copy the strings into a parallel owner.

## Artifact Contract

| Field                    | Role                                                                                            |
| ------------------------ | ----------------------------------------------------------------------------------------------- |
| `output.result`          | Scene and typed artifacts equivalent to fresh `compileToScene()` for the same IR/options        |
| `output.diagnostics`     | Core compile warnings in canonical order; dispatched to `onWarn` only after a successful commit |
| `output.observerOutputs` | Explicit observer outputs from the same candidate revision as the primary result                |
| `snapshot`               | Deeply immutable Scene, document root identity, and topology for the current Runtime revision   |
| `patch`                  | Atomic Scene Patch relative to the base revision; absent on the initial full run                |

Ordinary `compileToScene()` returns only the primary Scene and artifacts and creates no observation runtime. To read final occurrences, call `observeCompileToScene(ir, options, observers)`, or fix observer definitions in `createCoreComputation()` through `runtimeOptions.observers`. Every observer creates an exclusive session for one compile and runs `select`, `observe`, then `complete`.

Core provides only domain-neutral observation. A Composite publishes its final output through the existing `artifactSchema`. A Path kind may declare `ownerOutput.schema` and call `publish()` when `context.ownerOutput.requested` is true. Only final committed occurrences trigger `observe()`; failed or discarded probes remain invisible. Each event includes the final occurrence, probe/replay provenance, and the transform from owner-local coordinates to the primary Scene.

An observer can call `context.compileFragment()` to compile ordinary `IRChild` content in the current occurrence environment. The result contains an isolated static Scene, artifacts, and diagnostics; it never writes into the primary result and cannot reference public identities from the primary figure or another fragment. `complete()` chooses the observer's final output, which Core recursively freezes without prescribing a domain shape. Inspector registration, selection, colors, and readonly-layer assembly belong to the optional [`@retikz/inspect`](/kernel/packages/inspect) package.

`context.round(value)` reuses the current primary compile precision to compare recomputed geometry coordinates with the final output. Inspect callbacks expose the same method through their context.

The initial run performs a full compile. When an update cannot be proven locally safe, the Computation falls back to a full compile and publishes one `replaceScene` in `patch.operations`. Callers still consume the same Snapshot / Patch envelope instead of switching protocols.

Core cross-checks an optional ChangeSet against the complete previous and next Snapshots. One unique `update` hint must cover each changed value owned by the Scene root or a stable entity. Add/remove/move hints must completely explain the next identity set and order under their parent, with `parent` and `before` pointing to final positions in the next Snapshot.

The document root identity path is `['root']`. Each ordinary child with a unique non-empty `id` appends `[type, id]`. An identified Scope continues as a parent boundary and recursively indexes descendants, so a Node inside it can use `['root', 'scope', scopeId, 'node', nodeId]`. `localNamespace` only changes the reference frame, not this identity path. Moving an entity across Scopes changes its old and new paths, so the hint is remove + add rather than a move that retains the old identity. Scope add/remove hints do not cascade: every stable descendant must be covered by its own hint.

Structural hints are checked as a set; their array order is not Patch execution order, and each parent's move set must be a minimum reorder. Anonymous entities, same-parent duplicates, Composites, missing or redundant hints, invalid parents or `before` identities, and hints that cannot rebuild the next sibling order are mismatches.

The current local incremental path first covers one provably safe closed loop: the root contains only unique-id Nodes with absolute tuple positions, structure and order stay unchanged, exactly one Node changes only its solid-color `fill` string, and there are no custom shapes, resources, artifacts, or compile warnings. The Computation recompiles only that Node contribution, reuses the other committed root contributions, and publishes one emitted-subtree `update` operation; the output remains equivalent to a fresh `compileToScene()`. References, resources, custom shapes, Scopes, Composites, multi-owner changes, and every other case without a local proof continue to full fallback.

On a mismatch, `CORE_CHANGESET_MISMATCH` is published once as a Runtime diagnostic only after the fallback commits successfully. It never enters `output.diagnostics` or `onWarn`. A failed fallback compile publishes neither that diagnostic nor a new revision or artifact.

The private Core Computation read preserves the immutable source Snapshot and stable identity index for the next update; the committed full Scene Snapshot also serves as the contribution cache for the safe subset. Dependency Computations, participants, and `runtime.artifact()` only receive the public read above and cannot access the private source/index state.

## Immutable Computation Options

`createCoreComputation(options, runtimeOptions?)` copies the option record, registry arrays, and Definition records at factory time while fixing callback references. Later mutations to the original arrays or Definition fields do not alter an existing Computation.

Changing an ordinary measurer, lowerer, provider callback, or option still requires disposing the old Runtime and creating a Computation with new options. When a fixed Definition callback reads mutable external state, model that state as a Runtime Source and list it in `runtimeOptions.invalidationSources`; its source value invalidates the Core Computation without entering IR or Scene.

`invalidationSources` does not replace the fixed Definition topology or update callback references automatically. A new Computation always starts with a full run. Runtime injects tracing through the Computation context, so `trace` is not part of `CoreComputationOptions`.

The same invalidation source must appear in the source registry, Computation runtime options, initial Snapshots, and every update transaction that changes its state:

```ts
import { CoreSourceDefinition, createCoreComputation } from '@retikz/core';
import {
  createRuntimeSourceInput,
  createRuntimeSourceRegistry,
  createRuntimeSourceUpdate,
  createRuntimeComputationRegistry,
  createRuntime,
  defineRuntimeSource,
} from '@retikz/runtime';

const MeasureRevisionSource = defineRuntimeSource({
  key: 'app:measure-revision',
  value: {
    capture: value => value,
    read: value => value,
    equals: Object.is,
  },
});

const coreComputation = createCoreComputation({}, { invalidationSources: [MeasureRevisionSource] });
const sources = createRuntimeSourceRegistry([CoreSourceDefinition, MeasureRevisionSource]);
const computations = createRuntimeComputationRegistry({ sources, builtins: [coreComputation] });
const runtime = createRuntime({
  sources,
  computations,
  initialSnapshots: [
    createRuntimeSourceInput(CoreSourceDefinition, ir),
    createRuntimeSourceInput(MeasureRevisionSource, 0),
  ],
});

runtime.update({
  baseRevision: runtime.revision(),
  sources: [createRuntimeSourceUpdate(MeasureRevisionSource, 1)],
});
```

## Public API

| Export                                                                   | Role                                                                                        |
| ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------- |
| `CORE_SOURCE_KEY` / `CORE_COMPUTATION_ID`                                | Fixed identities for the Core document owner and compile Computation                        |
| `CoreSourceDefinition`                                                   | Capture/read/equality Definition for complete IR Snapshots                                  |
| `ThemeStyle` / `ThemeMode` / `ThemeSchema`                               | Built-in Theme vocabulary, strict IR schema, and Scene / Scope inheritance                  |
| `IRTheme` / `ResolvedTheme` / `ResolvedThemeColors`                      | Sparse persisted override, complete frozen environment, and shared color view               |
| `ThemeStyleDefinition` / `ThemeStyleColorOverrides` / `defineThemeStyle` | Define a sparse Core style resolver and inject it with `themeStyles`                        |
| `createCoreComputation(options, runtimeOptions?)`                        | Create a Runtime Computation Definition while preserving composite artifacts                |
| `CoreChange`                                                             | `add` / `update` / `remove` / `move` change-hint union                                      |
| `CoreComputationOptions<TComposites>`                                    | Computation-lifetime `CompileOptions` without `trace`                                       |
| `CoreComputationRuntimeOptions`                                          | Extra Runtime sources that invalidate Core without entering IR or Scene                     |
| `CoreComputationOutput<TComposites>`                                     | Complete compile result and warnings                                                        |
| `CoreComputationPublicRead<TComposites>`                                 | Public `output`, `snapshot`, and optional `patch`                                           |
| `CoreComputationDefinition<TComposites>`                                 | Artifact-input, owned-artifact, and private/public read generic relationship                |
| `RuntimeScene` / `SceneRuntimeSnapshot` / `ScenePatch`                   | Deeply readonly Scene and atomic Patch DTOs                                                 |
| `observeCompileToScene()`                                                | Run an explicit full compile with observer sessions                                         |
| `defineCompileObserver()` / `CompileObserverDefinition`                  | Define a compile observation session and its stable key                                     |
| `CompileObservation` / `CompileObservationContext`                       | Final owner output, occurrence, transform, occurrence Theme, and isolated fragment compiler |
| `CompileOwnerOutputDefinition` / `CompileOwnerOutputPublisher`           | Declare and publish optional final Path-kind output                                         |
| `ObservedCompileResult` / `CompileObserverOutput`                        | Primary compile result and domain-defined outputs in definition order                       |
| `RetikzCoreError` / `RetikzCoreErrorCode`                                | The single Core error class and stable parse, resolve, and compile codes                    |
