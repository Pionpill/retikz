Core defines how an object is resolved, laid out and emitted. Reconciler decides when it runs, which dependencies are ready, and how results are assembled. This page follows nodes A and B and their connecting path; later pages expand each entity's stages.

## Overall Flow

Reconciler accepts a contracted IRScene and compilation options, prepares the environment and visits children. It calls Core where the required context is available, then assembles Scene, resources, artifacts and diagnostics. There is no mandatory whole-tree Canonical Scene pass.

<ComponentPreview files="compilation-overview" size="lg" hideCode type="flow" />

External JSON is parsed at a Schema entry point. Typed IR is not reparsed at every package boundary. Constraints requiring a Definition, reference or layout result are checked where that information becomes available.

## Follow One Diagram Through the Stages

Both nodes below have a minimum 60 × 40 outer box, at centers [0, 0] and [180, 0], with zero padding and margin. The path is declared first. Its final segment still runs from A's right boundary [30, 0] to B's left boundary [150, 0].

```ts
import { SceneReconciler } from '@retikz/reconciler';
import type { IRScene } from '@retikz/core';

const ir: IRScene = {
  type: 'scene',
  version: 1,
  children: [
    {
      type: 'path',
      children: [
        { type: 'step', kind: 'move', to: { id: 'A' } },
        { type: 'step', kind: 'line', to: { id: 'B' } },
      ],
    },
    {
      type: 'node',
      id: 'A',
      position: [0, 0],
      text: 'A',
      layout: { minimumSize: { width: 60, height: 40 }, padding: 0, margin: 0 },
    },
    {
      type: 'node',
      id: 'B',
      position: [180, 0],
      text: 'B',
      layout: { minimumSize: { width: 60, height: 40 }, padding: 0, margin: 0 },
    },
  ],
};
const reconciler = new SceneReconciler({}, { incremental: false });
try {
  const result = reconciler.mount(ir).compilation.result;
  console.log(result.scene);
} finally {
  reconciler.dispose();
}
```

A node first becomes a CanonicalNode with effective style and capability bindings, then geometry and emitted output. The path retains named targets until node geometry is published; it can then select boundary intersections and produce commands. Neither author references nor declaration order need rewriting.

## Readiness by Entity

| Entity     | Required context                                           | Result returned to the scheduler                    |
| ---------- | ---------------------------------------------------------- | --------------------------------------------------- |
| Node       | Inheritance, definitions, measurement, position references | Layout, query geometry, primitives and bounds       |
| Coordinate | Position context and readable references                   | Published coordinate geometry, no visible primitive |
| Scope      | Inheritance first; envelope waits for child layouts        | Group attributes, envelope and projection data      |
| Path       | Readable named targets and owning space                    | Path output, bounds and shared resource references  |
| Composite  | Matched definition, proposal and child layout services     | Children or contribution, optional domain artifact  |

Scopes recursively contain these stages. Composite callbacks can request isolated child layout probes; Reconciler owns isolation and replay of selected results. These objects do not share one uniform IR-to-Primitive function.

## Declaration, Evaluation and Drawing Order

Children are dispatched in declaration order. A path reserves an output slot and is filled in after required geometry becomes available. Later evaluation therefore preserves its original drawing position. Final siblings are stably sorted by zIndex, retaining order for equal values.

This does not grant arbitrary forward references to every entity. Node placement and Coordinates evaluate during their visit and require readable targets. Paths have a dedicated deferral mechanism. Failed references and probes follow their own contracts; an unknown value must not be replaced with [0, 0].

## Environment and Reuse Ownership

Reconciler groups its stable environment into registries, host, layout and limits: definitions, measurement and TeX services, effective numerical options and execution limits. An execution also needs resource, naming, diagnostic and probe state. Core receives the narrow context required by a stage, rather than owning the session.

Core's prepared parameters consume stage products that the caller has established are valid and compute missing parts. They do not decide cache validity across executions. Full and incremental execution use these atomic stages; Reconciler owns dependency tracking, reuse decisions and output transactions.

## Complete Implementation Flow

Read from CompileManager through SubtreeCompiler into each visit or deferred handler to find actual Core calls. Once the root subtree finishes, CompileManager sends primitives, layout, resources and artifacts to snapshot assembly. Rendering consumes the resulting Scene afterward.
