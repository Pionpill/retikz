Primitives describe points, vectors, and basic geometric shapes. `@retikz/math` focuses only on mathematical and geometric relationships.

## Basic usage

Import from the root entry. Results are numbers or geometry, not rendered drawings.

```ts
import { point, vector2 } from '@retikz/math';

const end = vector2.add([20, 10], [40, -15]);
const distance = point.distance([20, 10], end); // 42.720018726587654
```

## Vector operations

2D geometric data can represent either a coordinate point or a vector: a point describes a position, while a vector describes direction and displacement. `Position` and `Vector2` both use the `[x, y]` form, but the method group should match the meaning of the data.

| Member     | Category     | Purpose                                                                                                                      |
| ---------- | ------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| `Position` | Type         | Represents a 2D coordinate point in `[x, y]` form                                                                            |
| `Vector2`  | Type         | Represents a 2D vector in `[x, y]` form                                                                                      |
| `point`    | Method group | Provides point distance, movement along a vector, movement toward a target, and equality                                     |
| `vector2`  | Method group | Provides vector addition, subtraction, scaling, dot and cross products, length, normalization, angle conversion, and normals |

Change the angle and length to see that the vector and its left-hand normal stay perpendicular.

### Algorithm notes

To move from one point toward another, first take their difference as a direction, normalize it, then scale it by the requested distance and add it back to the origin:

$$
\mathbf d = \mathbf b - \mathbf a,\qquad \hat{\mathbf d} = \frac{\mathbf d}{\lVert\mathbf d\rVert},\qquad \mathbf p' = \mathbf p + s\hat{\mathbf d}
$$

`point.shiftToward` follows this chain and leaves the source point unchanged when the two points coincide. `vector2.normalize` returns its fallback when the length is below the tolerance; use `vector2.normalizeOrNull` when zero-length or non-finite input must be handled explicitly. `point.along` and `point.against` do not normalize their direction, so `length` is a geometric distance only when that direction is a unit vector.

`vector2.normal` maps a 2D vector to a normal vector, preserving its length and making it perpendicular to the original:

$$
\operatorname{normal}(\mathbf v)=(-y,x),\qquad \mathbf v\cdot\operatorname{normal}(\mathbf v)=0,\qquad \lVert\operatorname{normal}(\mathbf v)\rVert=\lVert\mathbf v\rVert
$$

The page and renderer use SVG coordinates, where y grows downward, so this rotation appears clockwise on screen.

The dot product and 2D cross product reduce the relationship between two vectors to a scalar:

$$
\mathbf a\cdot\mathbf b=a_xb_x+a_yb_y,\qquad \mathbf a\times\mathbf b=a_xb_y-a_yb_x
$$

A zero dot product means perpendicular vectors; a zero cross product means collinear vectors, while its sign identifies the turn direction. These tests also underpin later algorithms such as convex hulls and segment intersections.

## Bounds calculations

Bounds calculations find the axis-aligned rectangle occupied by a set of geometry. Although the calculation directly consumes a set of `Position` points, general shapes such as ellipses and arcs can first derive boundary candidates and then join the same bounds calculation.

The demo adds the arc's boundary candidates to the point set, so the dashed rectangle covers the three points and the arc. Change a point coordinate or either arc angle to observe the bounds update in real time.

### Algorithm notes

When the input mixes points, curves, and basic shapes, the goal is one axis-aligned boundary—not a `boundsOf` that needs to understand every primitive. Each primitive helper first identifies the positions that can affect the outer box, then hands them to `boundsOf` for a uniform reduction.

Bounds calculation first generates candidate points from each geometry input type, then reduces those points only once; `boundsOf` does not identify geometry types itself.

<ComponentPreview files="bounds-candidate-flow" size="md" type="flow" hideCode />

#### Points

A point is already a coordinate, so it enters the candidate set directly. For an empty point set, `boundsOf` returns `undefined`; the caller chooses whether to ignore it, provide a fallback, or report an error.

#### Curves

In addition to their endpoints, circular arcs and axis-aligned elliptical arcs include any axis extrema that they sweep across. A circular candidate is computed as:

$$
p(\theta)=(c_x+r\cos\theta,c_y+r\sin\theta)
$$

An axial angle inside the angular span is:

$$
\theta\in\{0^\circ,90^\circ,180^\circ,270^\circ\}
$$

It can determine a bound even when neither endpoint does.

#### Basic shapes

Basic shapes such as circles and ellipses first derive their own boundary candidates, then join the point and curve candidates. Rotated ellipses are not handled directly by the elliptical-arc helper: compute them in local coordinates before mapping them to world coordinates.

#### Collect and reduce

`boundsOf` traverses every candidate point and takes the four coordinate extrema:

$$
\operatorname{AABB}(P)=(\min_{p\in P}p_x,\ \min_{p\in P}p_y,\ \max_{p\in P}p_x,\ \max_{p\in P}p_y)
$$

`mergeBounds` repeats the same min / max operation for two results, while `expandBounds` applies directional insets afterward.

## Ellipses and arcs

**Ellipse boundaries.** `ellipse` covers centers, inscribed and circumscribed ellipses, containment, and the boundary point toward a target.

**Circular and elliptical arcs.** Angles follow SVG coordinates: y points down, `0°` points along +x, `90°` along +y, and positive angles increase clockwise on screen.

### Algorithm notes

This section answers two curve-specific questions: where a ray from an ellipse center meets its boundary, and which extrema an arc or elliptical arc traverses that can affect its outer box. The first turns “toward a point” into a precise intersection; the second lets curves enter the same bounds calculation described above.

#### Ellipse boundary point

`ellipse.boundaryPoint` first converts the target direction to ellipse-local coordinates, producing $d=(d_x,d_y)$, then normalizes it by the semi-axes to reach the boundary:

$$
t=\frac{1}{\sqrt{(d_x/r_x)^2+(d_y/r_y)^2}},\qquad p_{\mathrm{local}}=t\,d
$$

Each quantity has a distinct role:

- $d$ is the local direction from the ellipse center to the target. Without rotation, it is simply the target's displacement from the center
- $t$ is the scale to travel along $d$. A shorter semi-axis allows less travel in that direction; the scale puts the result exactly on the ellipse boundary
- $p_{\mathrm{local}}$ is the final boundary point in local coordinates. Mapping it back to world coordinates restores the ellipse position and rotation

A zero semi-axis or a target at the center returns the ellipse center.

`pointAtArcAngle` / `pointAtEllipseArcAngle` select a curve point. An ellipse's `angleDeg` is a parameter angle and does not necessarily equal the polar angle observed from its center.

`collectArcBoundingCandidates` / `collectEllipseArcBoundingCandidates` derive endpoints and axis-extrema candidates for bounds. Elliptical-arc helpers only handle axis-aligned ellipses; compute a rotated ellipse in local space, then map it to world space with the [coordinate transforms](/kernel/packages/math/transforms).

## Errors and limitations

- `normalize` returns a fallback for near-zero length; `normalizeOrNull` returns `null` for zero or non-finite length.
- `point.along` / `against` do not normalize directions; length means distance only for unit vectors.
- `boundsOf([])` returns `undefined`; `boundaryPoint` returns the center for a zero ellipse axis or a centered target.
- Arc angles use degrees, clockwise on screen. An ellipse parameter angle is not its polar angle. Ellipse-arc bounds helpers accept axis-aligned input.
