Core 定义图元、资源与边界计算；Reconciler 收集子树贡献、完成延迟路径和排序，组装完整 Scene 及附属结果，再按会话提交协议发布。

## 整体流程

绘图数据进入 Scene，领域结果进入 artifacts，编译诊断位于快照 diagnostics，可选来源信息位于 provenance。它们服务不同消费者；renderer 不需要理解 Composite 的业务输入或布局算法。

## 调用者最终拿到什么

SceneReconciler 的结果带 revision 和 compilation。绘图结果路径是 `output.compilation.result.scene`，领域产物是同层 result.artifacts；诊断属于 compilation.diagnostics，不在 Scene 里。

```ts
import { SceneReconciler } from '@retikz/reconciler';

const reconciler = new SceneReconciler({}, { incremental: false });
try {
  const output = reconciler.mount({
    type: 'scene',
    version: 1,
    children: [{ type: 'node', text: 'A' }],
  });
  const { scene, artifacts } = output.compilation.result;
  const diagnostics = output.compilation.diagnostics;
  console.log(scene, artifacts, diagnostics);
} finally {
  reconciler.dispose();
}
```

这是 Reconciler 的公开结果。Vanilla 的便捷处理入口可以管理内部协调器生命周期；这里保留同一个底层结果模型，具体入口返回值应按所属包契约读取。

## Scene 是已布局的后端中立绘图

Scene.primitives 按绘制顺序排列，layout 保存 x / y / width / height；resources 和根动画在需要时出现。没有 Node、Scope 或领域 Composite 留给 renderer 再做语义编译。

| 图元             | 已经确定的内容                       |
| ---------------- | ------------------------------------ |
| RectPrimitive    | 矩形位置、尺寸与外观                 |
| EllipsePrimitive | 椭圆几何与外观                       |
| TextPrimitive    | 文字、行、基线和字体等排版结果       |
| PathPrimitive    | 结构化路径命令、描边、填充及装饰数据 |
| GroupPrimitive   | 子图元及共享变换、裁剪、身份与动画   |

这些契约描述可供不同后端解释的绘图语义，不存 DOM、Canvas context 或 SVG-only 回调。Path 的端点装饰仍可以通过结构化 marker 数据交付。

## 分组坐标与查询几何

Scene 不要求所有图元摊平成世界坐标。Scope 或 Node 可以保留 Group 变换，其 children 使用所属局部空间。renderer 组合这些变换完成绘制；编译期查询几何则按需要投影为世界记录，用于跨 Scope 引用。

因此，某个局部矩形 x 为 0、外组平移 20 时，其世界 x 为 20；不应把两者都写成 20 再叠加一次。Composite artifact 的坐标空间也由所属领域契约定义，不因 Scene 中存在分组就自动成为世界坐标。

## 绘制资源怎样共享

普通颜色可以直接出现在图元中。渐变、图案和图片保存在 `Scene.resources.paints`，由填充或描边的资源引用使用；裁剪路径保存在 `Scene.resources.clips`，由分组的 `clipRef` 引用。Core 的 paint / clip registry 物化后端中立资源并按内容身份复用；Reconciler 为每次工作区创建这些注册表，缓存、回放和最终 Scene 都保留相同分类。

`resources` 存在时，`paints` 和 `clips` 都是数组，没有对应资源的类别使用空数组。编译结果没有资源时可以省略整个字段；Render 运行时快照则始终补齐两个集合。资源更新与引用它的图元在同一 revision 生效。

Pattern Definition 可以生成 tile 的图元，但不能另带一份资源表。Path 等扩展回调的资源引用同样受宿主许可约束。隔离试算的资源只有选中 replay 才导入正式工作区，不能只复制图元而漏掉它引用的资源。

资源 id 是关联同一份 Scene 内引用与定义的身份，不是要求调用者解析含义的业务 key。SVG、Canvas 等后端各自物化资源；Core 不在此阶段输出具体 DOM defs。

## layout 与边界

Scope 几何包络供连接与放置，Composite allocationBounds 供父布局，visualBounds 是静态图元树的保守视觉包络。最终 Scene.layout 则是编译输出边界经视口策略处理的结果。

没有显式 viewBox 时，Reconciler 汇总的布局贡献经 Core 边界计算，再加 padding 并舍入。默认 padding 为 10；完全没有边界时返回 [0, 0, 100, 100] 所表示的默认画布，而不是从未知几何推导尺寸。显式 viewBox 直接决定 layout，仍需满足取整后的有限坐标和正宽高要求。

例如贯穿 A/B 示例的布局贡献范围为 x=-30 到 210、y=-20 到 20。默认留白后 layout 是 `{ x: -40, y: -30, width: 260, height: 60 }`。标签、阴影或装饰会改变相关输出贡献。

## artifacts、诊断与来源

Composite artifact 保存 namespace、type、结构化 occurrence 和 JSON value。occurrence 区分作者来源与展开位置，不能靠字符串路径猜某个生成节点的归属。产物按最终逻辑树顺序整理，与像素绘制分开交付。

diagnostics 保存本次成功编译可提交的警告，含 code、message 及来源信息；未选中试算的 warning 不应泄漏。按需捕获的 provenance 用于把图元关联回编译来源，不是 renderer 的必需输入。输出事务失败时如何回滚属于 Reconciler，不由 Core 在某个 emit 函数内处理。

快照、结果及 artifacts / diagnostics 数组的只读外壳不意味着整棵 Scene 在运行时递归冻结。消费者应遵守结果所有权，不能修改已发布快照来替代一次声明更新。
