`@retikz/react` 是 React 应用的首选入口。你用 `<Layout>`、`<Node>`、`<Path>`、`<Scope>`、`<Draw>` 等 JSX 组件声明图形；包内 adapter 把 props 与 children 转成 `@retikz/core` IR，再由 `<Layout>` 编译 Scene 并接入 SVG 或 Canvas 宿主。

它负责 React 写法和生命周期接线，不另造图形语义：IR、schema、几何与编译规则属于 `@retikz/core`，后端执行与跨后端 runtime 属于 `@retikz/render`。

## 安装与使用

`react` 与 `react-dom` 是 peer dependencies，版本不低于 18：

```bash
pnpm add @retikz/react react react-dom
```

```tsx
import { Draw, Layout, Node } from '@retikz/react';

export const Diagram = () => (
  <Layout>
    <Node id="source" position={[0, 0]}>
      Source
    </Node>
    <Node id="target" position={[160, 0]}>
      Target
    </Node>
    <Draw way={['source', 'target']} arrow="->" />
  </Layout>
);
```

`<Layout>` 默认输出 SVG；需要像素位图时传 `renderer="canvas"`。组件用法从[快速开始](/kernel/get-start)进入，完整宿主选项见 [Layout](/kernel/components/layout/overview)。

`<Layout theme>` 写入根 `IRScene.theme`，`<Scope theme>` 写入局部 `IRScope.theme`。Theme 是稀疏的 `style / mode / tokens` 覆盖；`tokens` 按 owner namespace 保存 JSON-safe token key，Core 内置 `core` namespace，领域 Composite 在 compile 中读取自己的 namespace。`themeTokenDefinitions` 是 Layout 的 compile 选项：React adapter 会把嵌入 Composite 的 Definition 与显式传入的 Definition 去重后交给 Core registry。`ir` 与显式 `theme` 同时使用时，prop 逐字段覆盖 `ir.theme`，不会修改输入对象。完整示例见 [Layout 的可继承 Theme](/kernel/components/layout/overview#可继承-theme)。

## 为什么需要 @retikz/react

### 用 JSX 降低描述成本

`@retikz/core` 的 IR 可以直接构造，但图形通常包含嵌套、复用和组合关系。JSX 用组件树自然表达这些结构，让 `<Layout>`、`<Scope>`、`<Node>`、`<Path>` 等声明贴近图形层级，减少手工拼装 Core IR 的样板代码。

retikz 把 React 作为官方支持的一等框架：`@retikz/react` 的组件 API、文档、示例和适配行为会随 Kernel 一起维护。React 在这里是 authoring layer；最终数据契约和编译语义仍由框架无关的 `@retikz/core` 拥有。

### 为什么不提供其他官方框架包

这不是 Core 只能接入 React。任何框架只要把自己的组件或模板结构转换成相同的 Core IR，并接入 `compileToScene` 与 renderer 生命周期，就能复用 retikz 的 Kernel 能力。

`@retikz/react` 同时是其他框架适配器的实现参考，展示组件树到 IR、宿主能力注入和渲染生命周期接线的完整边界。官方把维护资源集中在 React，不负责开发、发布或维护 Vue、Svelte 等其他框架包；这些适配器可由社区沿用同一边界独立实现。

## 组件不会直接渲染 DOM

### 为什么采用标记组件

选择标记组件不是因为 React 不能绘图，而是为了让图形语义只有一个真源。如果 `<Node>`、`<Path>` 各自实现 DOM、浏览器布局和几何计算，React DSL 就会逐渐形成一套与 Core IR 平行的规则；同一张图在 React、Vanilla 或其它适配器中也可能得到不同结果。

因此 JSX 只负责组织声明，builder 把它收敛为框架无关的 Core IR。中间过程不创建额外 DOM，也不把 CSS layout 变成图形编译的隐式输入；持久化、传输、SSR 和其它框架适配都可以继续复用同一份 IR → Scene 管线。

React 仍然在合适的边界发挥作用：它声明稳定的 `<svg>` / `<canvas>` host shell，并把 commit、ref 与卸载生命周期接到所选 Runtime host。默认 retained 路径由 `@retikz/render` participant 独占 SVG descendants 或 Canvas bitmap；static 路径则直接完整物化 Scene。两条路径都避免 React reconciliation 与 renderer 同时改写同一棵子树。薄的是图形语义，不是宿主接线。

`<Node>`、`<Path>`、`<Scope>` 等 Kernel 组件是 **IR 标记**，不是 DOM 组件。它们自身返回 `null`，只用稳定的 `displayName` 告诉 React builder“这是什么图元”；因此 `<Node>` 不会先生成一个 `<div>`，也不会拥有另一套浏览器布局语义。

```tsx
export const Node: FC<NodeProps> = () => null;
Node.displayName = TIKZ_NODE;
```

Sugar 组件也不新增 IR。例如 `<Draw>` 先用 Core 的 `parseWay` 解析 `way`，再返回标准 `<Path>` / `<Step>` Kernel JSX。下面只截取 line 分支；源码还覆盖 fold、curve、arc、cycle 等同一映射过程：

```tsx
const steps = parseWay(way);

return (
  <Path arrow={arrow}>
    {steps.map((step, index) => {
      if (step.kind === 'line') {
        return <Step key={index} kind="line" to={step.to} label={step.label} />;
      }
      return null;
    })}
  </Path>
);
```

`readSceneChildren` 同步遍历 children：识别 Kernel 标记、展开 Fragment，并直接调用函数式 Sugar 后继续递归。这个过程不经过 React DOM renderer，所以 Kernel / Sugar 必须是无 hook、无副作用的函数组件；最终由 `buildIRWithContributions` 组装出普通 JSON `IRScene`。

### Retained 更新边界

标记组件避免了中间 DOM 和重复图形语义，但 JSX → IR 仍会在 children 引用变化时重新执行。当前每次 `ir` 或 Core options 改变，React render 阶段还会调用一次 `compileToScene` 生成 SSR-safe seed；默认 retained 模式在客户端 commit 后还会由 Runtime Session 为 transaction 再编译同一输入。retained 更新降低的是后端提交成本，不会消除这次 render-time full compile。

频繁更新的大图可在组件外或 `useMemo` 中持有稳定 IR 与 Core options，再通过 `ir` prop 跳过 builder，并让 seed compile 的 memo 命中。

在 retained 模式下，客户端 commit 后 `Layout` 会创建 Runtime Session，把完整 IR Snapshot 与 renderer config 作为一次 transaction 更新。Core Program 能证明安全的变更会发布局部 Scene Patch；其它合法变更用 `replaceScene` fallback 保持 full oracle 等价。SVG / Canvas retained participant 在 prepare 阶段隔离候选状态，只有 transaction 成功后才把 DOM / bitmap、事件、动画句柄、artifacts 与 inspection plane 一起发布。

卸载时 Session 会反向 best-effort 清理，并在逻辑资源 retire 后同次重试失败的 renderer cleanup；已成功项不会重复执行。持续失败只进入 Runtime diagnostics，不会阻断 React 完成 unmount。

Definition 数组按有序元素 identity 规范化，因此 render 时重新创建 `[shape]` 这类等价容器不会重建 Session；Definition 本身、renderer backend、`idPrefix` 或 `runtime.rendererFactory` 改变时会重建。并发调度与 progressive materialization 仍不属于当前公开契约。

### 执行模式与更新策略

`<Layout>` 的 `runtime` 用两个正交参数选择宿主生命周期和 Program 更新方式。省略配置时是 `retained + auto`：

```tsx
<Layout /> {/* retained + auto */}
<Layout runtime={{ mode: 'retained', updateStrategy: 'full' }} />
<Layout runtime={{ mode: 'static' }} />
```

| 配置              | 更新行为                                         | Session、内存与失败语义                                                                 |
| ----------------- | ------------------------------------------------ | --------------------------------------------------------------------------------------- |
| `retained + auto` | 安全变化走局部 Patch，其余完整 fallback          | 保留 Snapshot、candidate、diagnostics、原子 commit 与 rollback；默认配置                |
| `retained + full` | 有实际依赖变化时跳过 Program `update()` 完整运行 | 与 auto 持有相同 Runtime 状态和事务能力；不是低内存模式                                 |
| `static`          | 每次完整 compile 并直接物化 SVG / Canvas         | 不创建 Session、Snapshot、diff、transaction 或 rollback；减少常驻状态，但每次工作量更大 |

`mode: 'static'` 不能同时传 `updateStrategy`、`rendererFactory` 或 `onDiagnostic`。TypeScript 的 `LayoutRuntimeOptions` 会拒绝组合，JavaScript 入口也会在创建宿主前抛错。static 的 compile 在宿主写入前失败时不会发布新画面；物化、动画或水合已开始后若失败则向外传播错误，但不承诺恢复旧宿主状态。

在同一个 retained host 上把 `updateStrategy` 从 `auto` 改为 `full`（或反向）会 dispose 旧 Session，并用当前完整输入创建新 Session；宿主元素 identity 保持稳定，revision 从 initial 重新开始。切换 `mode` 则会释放并替换整套宿主。若只想保留 transaction、diagnostics 和 rollback，同时排除增量路径，应选择 `retained + full`，不要选择 `static`。

## 从 JSX 到 Scene

`<Layout>` 先调用 React builder 把 JSX 适配为 Core IR；每次输入或 Core options 改变时，render 阶段用 `compileToScene` 生成 SSR-safe seed，客户端 commit 后由同一组 Core options 创建或更新 Core Program。下图蓝色节点属于 `@retikz/react` 的 authoring / adapter，橙色节点是 `@retikz/core` 拥有的数据契约与编译器。

<ComponentPreview files="react-to-scene" size="xs" hideCode />

| 阶段                       | 所有者          | 做什么                                                              |
| -------------------------- | --------------- | ------------------------------------------------------------------- |
| Kernel / Sugar JSX         | `@retikz/react` | 收集 props 与 children；Sugar 先展开为 Kernel                       |
| `buildIRWithContributions` | `@retikz/react` | 遍历组件树，生成 `IRScene`，同时收集可嵌入 Tier 2 的贡献            |
| `IRScene`                  | `@retikz/core`  | JSON 可序列化的绘图契约，不包含 React element、hook 或 DOM          |
| `compileToScene`           | `@retikz/core`  | 处理 composite，解析 registry、引用、几何、布局、资源与动画         |
| `CompileResult`            | `@retikz/core`  | 同次返回后端中立 `scene`、typed `artifacts` 与独立 inspection plane |

`Layout` 会把文本测量器、Definition registries、TeX lowerer 等宿主能力作为 compile options 注入，但这些选项不会把 React 写进 IR 或 Scene。直接传 `ir` prop 时会跳过 JSX builder。`artifacts` prop 请求 opt-in 产物，`onArtifacts` 在所选 host 发布后接收同次 compile 的 immutable artifacts；不会为通知再编译一次。

`<Layout inspect>` 提供整图布局策略，`<Scope inspect>` 提供 authored 子树策略；带 Inspector 的 Tier 2 组件和 `<Path inspect>` 可以只开启当前 occurrence。Builder 为每个目标生成带 `target: 'composite' | 'path'` 与 `policy.self` 的 authored sidecar，`inspect` 不进入 `IRScene`、`IRScope` 或 `IRPath`。`enabled: false` 对两类目标都是后代不可越过的硬屏障。

Static host 直接物化主图与辅助层；retained host 在同一 revision 原子提交两者。SVG SSR seed 也包含辅助层，首次 hydration 采用同一 frame，后续策略变化通过新 session 原子接管。Inspector 需要 authored occurrence、对应 Definition 与 settled subject；只剩预编译 Scene 的 Render 入口不能事后恢复这些信息。

## Scene 之后

Scene 已经没有 React 组件语义。在默认 retained 模式下，`@retikz/render` 负责把 Snapshot / Patch 执行到目标后端，`@retikz/react` 只补 React 宿主生命周期和 Session 接线：

| 目标   | `@retikz/render`                                                | `@retikz/react`                                      |
| ------ | --------------------------------------------------------------- | ---------------------------------------------------- |
| SVG    | retained renderer 独占 descendants，执行 Patch 或 full fallback | 声明稳定 `<svg>` shell，SSR seed 后以 `adopt` 接管   |
| Canvas | retained renderer 更新 dirty region 或 full fallback            | 声明稳定 `<canvas>` shell，并固定 mount 生命周期 DPR |

事件 handler 是函数，不能进入 JSON IR。children 模式下，React 侧会用另一条 `collectHydrationHandlers` 扫描按图元 id 收集函数；渲染完成后再绑定到 SVG 定位或 Canvas hit-test。直接传 `ir` prop 时，则通过 `handlers` prop 提供这条运行时旁路。

## 职责边界

| 能力       | `@retikz/react` 负责什么                          | 能力真源            |
| ---------- | ------------------------------------------------- | ------------------- |
| JSX DSL    | Kernel 组件一对一构造 IR；Sugar 同步展开为 Kernel | `@retikz/core` IR   |
| 编译宿主   | 收集 children / IR、注入选项并接入 React 生命周期 | `@retikz/core` 编译 |
| 渲染与交互 | 选择 SVG / Canvas、收集事件并连接宿主             | `@retikz/render`    |

`@retikz/react` 不包含无框架 plain spec；在非 React、SSR 字符串或直接 DOM 挂载场景使用 [`@retikz/vanilla`](/kernel/packages/vanilla)。
