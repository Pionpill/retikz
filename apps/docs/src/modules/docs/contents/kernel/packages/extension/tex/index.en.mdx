---
title: '@retikz/tex'
description: Lower LaTeX formulas in text into glyph paths that Core can compile and SVG or Canvas can render
---

Use `@retikz/tex` when Node text needs LaTeX and SVG and Canvas should share the same formula result. You still author formulas with `$...$`, `$$...$$`, or explicit math runs; this package converts them into glyph paths consumed by `@retikz/core`.

Core remains responsible for formula text and layout. This package owns MathJax integration, SVG parsing, lowering caches, and React initialization. Once a formula enters Scene, renderers no longer need to understand LaTeX or MathJax.

## Installation & integration

`mathjax-full` is an optional peer dependency. Applications using the built-in MathJax engine must install it alongside `@retikz/tex`:

<PackageManagerInstall packages="@retikz/tex mathjax-full" />

### React

React applications use `useLowerTex` from `@retikz/tex/react`. The hook prepares a shared MathJax engine asynchronously and returns an explicit `loading`, `ready`, or `error` state. Inject the synchronous lowerer into `<Layout>` only in the `ready` state:

```tsx
import { Layout, Node } from '@retikz/react';
import { useLowerTex } from '@retikz/tex/react';

const Diagram = () => {
  const lowerTexState = useLowerTex({ profile: 'math' });

  if (lowerTexState.status === 'loading') return <div>Loading MathJax…</div>;
  if (lowerTexState.status === 'error') return <div>{lowerTexState.diagnostic.message}</div>;

  return (
    <Layout lowerTex={lowerTexState.lowerTex}>
      <Node position={[0, 0]}>{'$\\frac{a}{b} = c$'}</Node>
    </Layout>
  );
};
```

Inject the lowerer once at the outer `<Layout lowerTex>` and its child text can reuse the same compile capability. `@retikz/tex/react` only handles the React lifecycle and shared engine; it does not change Core's text syntax.

### Vanilla

Vanilla applications create a MathJax engine, adapt it to Core `LowerTex` with `createLowerTex`, and pass it through `compile.lowerTex` to `renderToSvgString` or another Vanilla compile entry:

```ts
import { node, renderToSvgString, scene } from '@retikz/vanilla';
import { createLowerTex, createMathJaxEngine } from '@retikz/tex';

const lowerTex = createLowerTex(await createMathJaxEngine({ profile: 'math' }));
const input = scene({
  children: [node('formula', { position: [0, 0], text: '$\\frac{a}{b} = c$' })],
});

const svg = renderToSvgString(input, { compile: { lowerTex } });
```

When separating the engine and lowerer is unnecessary, await `createMathJaxLowerTex(options)` instead. Vanilla does not need React or `@retikz/tex/react`.

### Host injection

`@retikz/tex` does not find or mutate a host. It provides a function matching the Core contract, and the host injects that function at its compile entry:

| Host    | Injection point                | Effect                                                                     |
| ------- | ------------------------------ | -------------------------------------------------------------------------- |
| React   | `<Layout lowerTex={lowerTex}>` | Layout passes the lowerer into the Core compile context                    |
| Vanilla | `{ compile: { lowerTex } }`    | `renderToSvgString`, mount, or processing uses the same compile capability |

Formulas enter MathJax lowering only after injection. Without it, `$...$` in a string remains compatible ordinary text; an explicit math run is skipped and produces a Core warning.

## Contents

### Basic usage

Start with the three common forms: an inline formula in a string, a display formula in a string, and an explicit math run whose style can be controlled independently. The static demo below places all three forms in one Layout so you can first see their behavior in text:

<ComponentPreview
  files="tex-formula-basics.en"
  size="md"
  caption="One Layout shows an inline formula, an explicit math run, and a display formula together."
/>

Core first parses formula sugar in strings into text runs and math runs:

| Syntax                  | Meaning                                              |
| ----------------------- | ---------------------------------------------------- |
| `$...$`                 | Inline formula, measured on the text baseline        |
| `$$...$$`               | Display formula, with more generous vertical metrics |
| `\\$`                   | Literal dollar sign, not a formula delimiter         |
| `{ tex, displayMode? }` | Explicit math run for per-run styling                |

Explicit runs can be mixed with ordinary text runs:

```tsx
<Node
  text={[
    {
      runs: [{ tex: '\\sin\\alpha = \\frac{1}{2}', fill: 'red' }, { text: ' (red line length)' }],
    },
  ]}
/>
```

`displayMode` changes formula metrics; it does not split one Node into multiple Nodes. A multiline LaTeX environment remains one formula segment in the same line layout. Keep Chinese or other prose in a text run measured by the ordinary text measurer instead of relying on MathJax `\\text{}` font coverage.

### Extension usage

`MathJaxEngineOptions.profile` selects the base configuration, while `extensions` appends public extensions after it. With `base`, switching formula examples automatically enables the required extension; any other extensions you enabled manually remain active. `math` enables the built-in math extension set at once:

  size="md"
  caption="Switching a formula example automatically enables its required extension; combine other extensions manually to compare the resulting content."
/>

| Profile | Contents                    | Use it for                                          |
| ------- | --------------------------- | --------------------------------------------------- |
| `base`  | MathJax base TeX syntax     | Ordinary operators, fractions, roots, and scripts   |
| `math`  | Built-in math extension set | AMS, commands, brackets, cancellation, cases, color |

Profile values are listed by <ApiValues name="MathJaxProfile" />; public extensions are listed by <ApiValues name="MathJaxExtension" />. The internal `empheq` dependency required by `cases` is added automatically and is not part of the public extension set.

## Implementation principles

### Engine contract

Core does not depend on MathJax. It depends only on `LowerTex`:

```ts
type LowerTex = (
  content: { tex: string; displayMode?: boolean },
  style: { fontSize: number; color?: string },
) => LoweredTex | null;
```

`LoweredTex` contains paths in draw order and the formula's `width`, `height`, and `depth`. Each path carries independent fill / stroke, opacity, and path commands, so Core can continue laying it out and rendering it as ordinary Scene path primitives. The minimal engine consumed by Tex is the synchronous `MathJaxSvgEngine.convert(tex, { display }) => string` contract. Applications may use the built-in MathJax engine or inject a custom engine that returns the supported SVG subset.

This boundary keeps Core decoupled from MathJax: Core promises only the ability to lower a formula into glyph paths, so Tex can replace the engine without changing Core's text layout. `mathjax-full` can remain an optional dependency instead of forcing Core users who do not need formula support to download MathJax and carry its extra package size.

### Conversion pipeline

The figure expands one formula conversion as “Core entry → Tex lowering → Core output.” Pay attention to the Tex lane: it does not hand SVG to a renderer. It translates SVG geometry into Core's structured `PathCommand` values, then returns paths and formula metrics to Core.

<ComponentPreview files="tex-conversion-flow" size="md" hideCode />

Read the pipeline in this order:

1. **Core parses the input**: once the host injects `lowerTex`, `parseInlineRuns` recognizes `$...$` / `$$...$$` as math runs. Without the injection, strings remain compatible ordinary text, and escaped `\\$` remains a literal dollar sign.
2. **Core calls the layout capability**: `layoutInlineLine` walks text and math runs. For a formula it passes the TeX source, `displayMode`, font size, and color to `LowerTex`. It uses `height - depth` for the ascent above the baseline and `depth` for the descent below it, so formulas can share a line with ordinary text.
3. **MathJax produces SVG**: the built-in `MathJaxSvgEngine` creates the TeX input, SVG output, and DOM-free `liteAdaptor`. `convert` sends TeX to MathJax and returns an SVG string through `outerHTML`; `fontCache: 'none'` keeps glyph outlines inline so the next stage can parse them.
4. **Tex parses the SVG**: `lowerMathJaxSvg` first builds a restricted SVG node tree, then reads `path`, `use`, `rect`, `line`, and `polygon`. `path d` becomes absolute `move`, `line`, `quad`, `cubic`, and `close` `PathCommand` values. Node `translate`, `scale`, and `matrix` transforms are accumulated and applied together with the `viewBox` offset and `fontSize / 1000` scale. Fill, stroke, opacity, and `fillRule` travel with each path.
5. **Tex forms `LoweredTex`**: the SVG `viewBox` supplies `width`, `height`, and `depth`, while the path array keeps draw order. Unsupported `<text>`, `<foreignObject>`, nested `<svg>`, styles, or transforms reject the whole lowering with a diagnostic instead of returning partial paths.
6. **Core takes over again**: Core snapshots and validates the provider's `LoweredTex` as JSON with finite fields. Each path becomes a `PathPrim` with structured commands, fill / stroke, and opacity. The paths are wrapped in a baseline-translated `GroupPrim` and enter the renderer-agnostic Scene with ordinary text primitives. Only then does a renderer run, so it never needs to understand TeX, MathJax, or SVG.

The dashed dependency in the figure is the injected `LowerTex` capability; it does not mean that Core depends on MathJax.

### Cache and lifecycle

The figure combines the two related state machines: the upper lane shows a lowering cache hit or a miss that generates and writes glyphs, while the lower lane shows how React shares an engine, clears an old lowerer, discards stale results, and keeps initialization failures retryable.

<ComponentPreview files="tex-cache-lifecycle" size="xl" hideCode />

`createLowerTex` creates an in-memory cache per lowerer. Its key contains the TeX source, inline / display mode, font size, and host color. Successful results and deterministic MathJax / SVG failures are cached; engine exceptions are transient and are not cached, so the next call can retry. Every public lowering failure is sent to the latest `onDiagnostic` callback.

`useLowerTex` shares engines by the effective extension set, so equivalent shorthand such as `math` and `base + all extensions` reuses one engine. When that set changes, the hook immediately enters `loading` and clears the old lowerer; an async result for an unmounted or stale request is not written back. Initialization failure returns `error` and removes the shared failed entry so a later mount can retry. The cache covers only TeX-to-glyph conversion, not Core IR, Scene, Node layout, or renderer output.

## API reference

### `@retikz/tex`

| API                     | Description                                                                                                                                                              |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `createMathJaxLowerTex` | **Signature**<br />`(options?: MathJaxLowerTexOptions)`<br />`=> Promise<LowerTex>`<br />Creates the built-in MathJax engine and Core lowerer in one step                |
| `createMathJaxEngine`   | **Signature**<br />`(options?: MathJaxEngineOptions)`<br />`=> Promise<MathJaxSvgEngine>`<br />Dynamically loads `mathjax-full` and creates a synchronous SVG engine     |
| `createLowerTex`        | **Signature**<br />`(engine: MathJaxSvgEngine, options?: LowerTexOptions)`<br />`=> LowerTex`<br />Adapts a custom engine and owns SVG parsing, caching, and diagnostics |
| `MathJaxProfile`        | Built-in profile constants; values are listed by <ApiValues name="MathJaxProfile" />                                                                                     |
| `MathJaxExtension`      | Public extension constants; values are listed by <ApiValues name="MathJaxExtension" />                                                                                   |

**Configuration fields**

| Field                                      | Type, default, and behavior                                                                                                                  |
| ------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `MathJaxEngineOptions`<br />`.profile?`    | `MathJaxProfileValue`, default `'base'`. Selects a built-in syntax set                                                                       |
| `MathJaxEngineOptions`<br />`.extensions?` | `Array<MathJaxExtensionValue>`, default `[]`. Appends public extensions after the profile; normalization deduplicates and orders them stably |
| `LowerTexOptions`<br />`.onDiagnostic?`    | `(diagnostic: TexLoweringDiagnostic) => void`. Runs for every public lowering failure, including a deterministic cached failure              |
| `MathJaxLowerTexOptions`                   | `MathJaxEngineOptions & LowerTexOptions`. Used by `createMathJaxLowerTex` and `useLowerTex`                                                  |
| `MathJaxSvgEngine`<br />`.convert`         | `(tex: string, options: { display: boolean }) => string`. A custom engine synchronously returns the supported SVG subset                     |
| `TexLoweringDiagnostic`<br />`.kind`       | `'engine-error' \| 'mathjax-error' \| 'unsupported-svg' \| 'malformed-svg'`                                                                  |
| `TexLoweringDiagnostic`<br />`.source`     | `string`. The TeX source that failed; an initialization-stage `engine-error` uses an empty string                                            |
| `TexLoweringDiagnostic`<br />`.message`    | `string`. A diagnostic message from the engine, MathJax, or SVG parser                                                                       |

### `@retikz/tex/react`

| API           | Description                                                                                                                                |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `useLowerTex` | **Signature**<br />`(options?: MathJaxLowerTexOptions)`<br />`=> MathJaxLowerTexState`<br />Shares an async engine by effective extensions |

| `status`    | State shape and meaning                                                                                                                 |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `'loading'` | `{ status: 'loading' }`. Returned during initial startup or a profile / extensions change; it never carries the previous lowerer        |
| `'ready'`   | `{ status: 'ready', lowerTex: LowerTex }`. The engine is ready and `lowerTex` can be injected into Core synchronously                   |
| `'error'`   | `{ status: 'error', diagnostic: TexLoweringDiagnostic }`. Startup failed; the failed shared entry is removed so a later mount can retry |

### `@retikz/core`

| API                       | Description                                                                                                                                              |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `LowerTex`                | `(content: IRTexContent, style: { fontSize: number; color?: string }) => LoweredTex \| null`. Core's synchronous injection point; failures return `null` |
| `LoweredTex`              | `{ paths: Array<LoweredTexPath>, width: number, height: number, depth: number }`. Ordered paths, total height, and depth below the formula baseline      |
| `CompileOptions.lowerTex` | `LowerTex \| undefined`. Formula capability injection point in the Vanilla / Core compile context                                                        |

**Failures, caching, and retries**

| Scenario                                      | Observable result                                                                                                                                                       |
| --------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| String formula without an injected lowerer    | `$...$` / `$$...$$` remains ordinary text and does not enter formula parsing                                                                                            |
| Explicit math run without an injected lowerer | The formula segment is skipped and Core reports `TEX_LOWERER_MISSING`; text runs on the same line continue rendering                                                    |
| MathJax returns an error node                 | The lowerer returns `null`, reports `mathjax-error`, and Core reports `TEX_INVALID`; this deterministic failure is cached                                               |
| SVG is unsupported or malformed               | The whole formula is rejected without partial paths; `unsupported-svg` or `malformed-svg` and then Core `TEX_INVALID` are reported; the deterministic failure is cached |
| `engine.convert` throws                       | The lowerer returns `null`, reports `engine-error`, and Core reports `TEX_INVALID`; this transient failure is not cached and the next call can retry                    |
| `mathjax-full` is missing or startup fails    | The factory Promise rejects with installation or startup details; React returns `error`, removes the failed shared entry, and permits a later retry                     |
