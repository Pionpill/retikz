Built-in inspection gives a quick view of final output that Core already publishes. Complete React or Vanilla host setup in [Install and use](/kernel/packages/inspect#install-and-use), then request one of the Inspectors below; none changes the primary figure.

## Built-in Inspectors available now

The default registry currently contains one built-in Inspector. It belongs to Core's `stroke` Path owner rather than inspecting arbitrary Paths:

| Inspector               | Core owner           | Final output read                              | Auxiliary content                                   |
| ----------------------- | -------------------- | ---------------------------------------------- | --------------------------------------------------- |
| `STROKE_PATH_INSPECTOR` | `pathKind: 'stroke'` | Final adopted path commands and control points | Bézier handles, control points, and optional labels |

`createDefaultInspectorRegistry()` adds it automatically. No auxiliary fragment is produced when no `stroke` Path matches or the key is not requested.

## Path control points

The built-in `stroke` Path Inspector reads commands after Core has resolved them, rather than the authored `way`. Handles and control points therefore explain the final result after relative coordinates, node references, and similar input have been processed:

`controlPoints` defaults to enabled and `labels` defaults to disabled. Both affect auxiliary content only.

Control point labels have transparent backgrounds. Their text shares the current inspection request's palette color with the corresponding control points and guide lines.
