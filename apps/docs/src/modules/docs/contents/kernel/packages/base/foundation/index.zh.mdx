`@retikz/foundation` 是为所有包提供基础能力的纯工具模块，用于统一复用类型、标量校验、空白语义和错误骨架；Zod 是它唯一的 production dependency。

## 安装与使用

<PackageManagerInstall packages="@retikz/react react react-dom" />

```ts
import {
  assertNonEmptyString,
  NonBlankStringSchema,
  NormalizedFractionSchema,
  PositiveNumberSchema,
  RetikzError,
} from '@retikz/foundation';
import type { AssertEqual, OpenString, RetikzErrorOptions, ValueOf } from '@retikz/foundation';
```

开发者通常不需要直接使用 `@retikz/foundation`；它是一个为包之间复用基础能力而提供的纯内部工具包。

## 内容

### 类型工具

这三个工具只在编译期工作，不产生运行时代码，也不表达任何 IR 或领域模型。

| 导出                              | 语义                                     |
| --------------------------------- | ---------------------------------------- |
| `ValueOf<T>`                      | 取得对象所有 value 的联合类型            |
| `AssertEqual<TActual, TExpected>` | 只有双向可赋值时才得到 `true`            |
| `OpenString<T>`                   | 保留内置字面量提示，同时接受自定义字符串 |

### 通用契约

六个 schema 只校验标量，不 coercion、不 trim、不填默认值。完整对象、数组、领域区间和跨字段关系仍由消费包组合：

| 导出                       | 接受范围                                 |
| -------------------------- | ---------------------------------------- |
| `NonBlankStringSchema`     | 至少含一个非空白字符；成功时保留原字符串 |
| `PositiveNumberSchema`     | 大于 `0` 的有限数                        |
| `NonNegativeNumberSchema`  | 大于等于 `0` 的有限数                    |
| `PositiveIntegerSchema`    | 大于 `0` 的 safe integer                 |
| `NonNegativeIntegerSchema` | 大于等于 `0` 的 safe integer             |
| `NormalizedFractionSchema` | `0..1` 闭区间内的有限数，包含两个端点    |

```ts
NonBlankStringSchema.parse(' layer/main '); // 原样返回
PositiveNumberSchema.parse(1.5);
NormalizedFractionSchema.parse(0.5);
```

### 断言工具

`assertNonEmptyString(value, label)` 的参数已经由调用方约束为 `string`。它拒绝空串和运行时标准空白串，非空内容原样通过并返回 `void`。

```ts
assertNonEmptyString('layer/main', 'owner');
// ''、' '、'\t'、'\n' 和 Unicode 空白都会抛出：
// owner must be a non-empty string.
```

它不是 `unknown` 类型收窄器；需要 schema 结果时直接使用 `NonBlankStringSchema`。需要保留领域前缀、错误码或 class identity 的 owner 应捕获普通 `Error`，再在自己的边界构造领域错误。

### 错误处理

`RetikzErrorOptions`、`RetikzError` 与 `isRetikzError` 为领域 owner 提供统一的最小形态。owner 自己决定 code、details 字段和恢复语义：

```ts
type Details = Readonly<{ source: string }>;

class DomainError extends RetikzError<'DOMAIN_FAILED', Details> {
  constructor(details: Details, cause?: unknown) {
    super({ code: 'DOMAIN_FAILED', message: 'Domain failed', details, cause });
  }
}
```

| 成员              | 类型                                       | 语义                                                                                                                         |
| ----------------- | ------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| `code`            | `TCode`                                    | 结构化错误的分类代码，由 owner 定义                                                                                          |
| `message`         | `string`                                   | 面向调用方的错误消息                                                                                                         |
| `details`         | `TDetails`                                 | owner 提供的结构化错误详情；保留对象身份，不会自动深拷贝或冻结                                                               |
| `cause`           | `unknown`，可选                            | 导致当前错误的原始异常或值；省略时仍创建值为 `undefined` 的 own property                                                     |
| `isRetikzError()` | `(value: unknown) => value is RetikzError` | 判断值是否属于正常的 `RetikzError` class hierarchy，不作为 hostile object、跨 realm 或 Runtime/Core 私有 identity 的安全边界 |

## 何时抽象

<ComponentAlert
  type="tip"
  title="只有 retikz 开发者需要关注"
  description="普通开发者可以跳过本节；新增或调整 Foundation 基础能力时再回来阅读。"
/>

新增基础能力必须同时满足四项准入条件：

1. 不依赖 Retikz 领域、平台或状态；schema 只能复用 Foundation 已接受的 Zod 依赖
2. 有可独立命名的语义、不变量或失败边界
3. 已被至少两个独立包以同义方式消费，或属于 Foundation 最小错误、类型、断言协议
4. 不迫使上层包经由 Foundation 获得本应由 Core、Math、Runtime 或领域 owner 承担的能力

不满足条件的 helper、对象 / 数组 schema、几何算法、Diagnostic、错误目录和领域 resolver 应留在当前 owner。重复出现时先重新判断语义 owner，而不是把逻辑汇总进 Foundation。
