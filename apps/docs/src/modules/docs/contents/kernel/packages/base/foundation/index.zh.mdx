`@retikz/foundation` 是为所有包提供基础能力的纯工具模块，用于统一复用类型、JSON 与结构只读集合快照、标量校验、空白语义和错误骨架；Zod 是它唯一的 production dependency。

## 内容

### 类型工具

这五个工具只在编译期工作，不产生运行时代码，也不表达任何 IR 或领域模型。

| 导出                              | 语义                                             |
| --------------------------------- | ------------------------------------------------ |
| `ValueOf<T>`                      | 取得对象所有 value 的联合类型                    |
| `AssertEqual<TActual, TExpected>` | 只有双向可赋值时才得到 `true`                    |
| `OpenString<T>`                   | 保留内置字面量提示，同时接受自定义字符串         |
| `WithRequiredProperties<T, TKey>` | 只把指定 key 收窄为必填，保留其余属性及 readonly |
| `NonEmptyReadonlyArray<T>`        | 至少包含一个元素的只读数组                       |

例如，下面的 `name` 会变为必填，而 `note` 仍保持可选：

```ts
type Named = WithRequiredProperties<Readonly<{ name?: string; note?: string }>, 'name'>;
```

### 只读集合快照

`createReadonlyMap(entries)` 将输入条目复制为独立的浅快照。结果保持原生 Map 的查询、迭代和插入顺序，但不暴露 `set`、`delete` 或 `clear`；entry value 保持原对象身份，不会被深拷贝或冻结。

```ts
const definition = { kind: 'point' };
const source = new Map([['point', definition]]);
const definitions = createReadonlyMap(source);

source.clear();
definitions.has('point'); // true
```

### JSON 数据快照

`cloneAndFreezeJson(value, path)` 校验 JSON-safe plain data，并返回与原输入脱离的深冻结副本。循环引用、访问器、symbol key、稀疏数组、数组额外属性、非有限数和 class 实例都会抛出 `RetikzFoundationError`：

```ts
const snapshot = cloneAndFreezeJson({ filters: [{ field: 'age', value: 18 }] });

Object.isFrozen(snapshot); // true
Object.isFrozen(snapshot.filters); // true
```

`assertPlainDataContainers(value, path)` 只检查容器结构，不复制数据，也不读取访问器。它用于 owner 在 schema 之前拒绝 class 实例、Promise、异常属性描述符、symbol key、异常数组和循环引用；字符串、数字、`undefined` 等叶子值仍由 owner schema 校验：

```ts
assertPlainDataContainers({ tokens: { color: undefined } }, 'Theme provider output');
```

### 通用契约

六个固定 schema 只校验标量，不 coercion、不 trim、不填默认值。完整对象、数组、领域区间和跨字段关系仍由消费包组合：

| 导出                       | 接受范围                                 |
| -------------------------- | ---------------------------------------- |
| `NonBlankStringSchema`     | 至少含一个非空白字符；成功时保留原字符串 |
| `PositiveNumberSchema`     | 大于 `0` 的有限数                        |
| `NonNegativeNumberSchema`  | 大于等于 `0` 的有限数                    |
| `PositiveIntegerSchema`    | 大于 `0` 的 safe integer                 |
| `NonNegativeIntegerSchema` | 大于等于 `0` 的 safe integer             |
| `NormalizedFractionSchema` | `0..1` 闭区间内的有限数，包含两个端点    |

```ts
NonBlankStringSchema.parse(' layer/main '); // 原样返回
PositiveNumberSchema.parse(1.5);
NormalizedFractionSchema.parse(0.5);
```

`createOpenStringSchema(values)` 接受 const object enum，同时保留内置字面量提示与任意非空白自定义字符串。它不会查询 registry，也不会把扩展 key 收窄成白名单；生成的 JSON Schema 会同时包含已知 enum 分支与开放字符串分支：

```ts
const Role = { Participant: 'participant', Activity: 'activity' } as const;
const RoleSchema = createOpenStringSchema(Role);

RoleSchema.parse('participant');
RoleSchema.parse('custom.role');
```

### 断言工具

`assertNonEmptyString(value, label)` 和 `assertPositiveNumber(value, label)` 的参数分别已经由调用方约束为 `string` 和 `number`。前者拒绝空串和运行时标准空白串，后者拒绝 `0`、负数和非有限数；成功时都返回 `void`。

```ts
assertNonEmptyString('layer/main', 'owner');
// ''、' '、'\t'、'\n' 和 Unicode 空白都会抛出：
// owner must be a non-empty string.
assertPositiveNumber(1.5, 'SVG font size');
// 0、负数、Infinity、-Infinity 和 NaN 都会抛出：
// SVG font size must be a positive finite number.
```

失败时会直接抛出 `RetikzFoundationError`：字符串断言的 `code` 为 `FOUNDATION_NON_EMPTY_STRING_REQUIRED`，正数断言的 `code` 为 `FOUNDATION_POSITIVE_NUMBER_REQUIRED`；`details` 都保留 `label` 和原始 `value`，`cause` 同样指向被拒绝的值。它们都不是 `unknown` 类型收窄器；需要 schema 结果时直接使用对应 schema，调用方也不应捕获后把同一原子失败重复包装成领域错误。

### 错误处理

`RetikzErrorOptions`、`RetikzError` 与 `isRetikzError` 为领域 owner 提供统一的最小形态。`RetikzFoundationError` 统一承载 Foundation 自己拥有的原子错误，并通过参数区分具体失败；其它 owner 继续决定自己的 code、details 字段和恢复语义：

```ts
import { RetikzError, type ValueOf } from '@retikz/foundation';

type Details = Readonly<{ source: string }>;

const RetikzDomainErrorCode = {
  Failed: 'DOMAIN_FAILED',
} as const;

type RetikzDomainErrorCodeValue = ValueOf<typeof RetikzDomainErrorCode>;

class RetikzDomainError extends RetikzError<RetikzDomainErrorCodeValue, Details> {
  constructor(details: Details, cause?: unknown) {
    super({ code: RetikzDomainErrorCode.Failed, message: 'Domain failed', details, cause });
  }
}
```

| 成员              | 类型                                       | 语义                                                                                                                         |
| ----------------- | ------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| `code`            | `TCode`                                    | 结构化错误的分类代码，由 owner 定义                                                                                          |
| `message`         | `string`                                   | 面向调用方的错误消息                                                                                                         |
| `details`         | `TDetails`                                 | owner 提供的结构化错误详情；保留对象身份，不会自动深拷贝或冻结                                                               |
| `cause`           | `unknown`，可选                            | 导致当前错误的原始异常或值；省略时仍创建值为 `undefined` 的 own property                                                     |
| `isRetikzError()` | `(value: unknown) => value is RetikzError` | 判断值是否属于正常的 `RetikzError` class hierarchy，不作为 hostile object、跨 realm 或 Runtime/Core 私有 identity 的安全边界 |

## 何时抽象

<ComponentAlert
  type="tip"
  title="只有 retikz 开发者需要关注"
  description="普通开发者可以跳过本节；新增或调整 Foundation 基础能力时再回来阅读。"
/>

新增基础能力必须同时满足四项准入条件：

1. 不依赖 Retikz 领域、平台或状态；schema 只能复用 Foundation 已接受的 Zod 依赖
2. 有可独立命名的语义、不变量或失败边界
3. 已被至少两个独立包以同义方式消费，或属于 Foundation 最小错误、类型、断言协议
4. 不迫使上层包经由 Foundation 获得本应由 Core、Math、Runtime 或领域 owner 承担的能力

`createOpenStringSchema(values)` 是唯一允许的参数化 schema factory，只组合 const object enum 与 Foundation 已有的非空白字符串边界。其它 helper、对象 / 数组 schema、range factory、几何算法、Diagnostic、错误目录和领域 resolver 应留在当前 owner。重复出现时先重新判断语义 owner，而不是把逻辑汇总进 Foundation。
