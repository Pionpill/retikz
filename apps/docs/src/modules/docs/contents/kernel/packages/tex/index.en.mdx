`@retikz/tex` is the optional formula capability package. You still write `$...$`, `$$...$$`, or explicit math runs through text entry points such as `<Node>`; an injected `lowerTex` converts those formulas into glyph paths that `@retikz/core` can consume during compilation.

It does not introduce a formula component or own text IR and renderers. This package owns MathJax integration, SVG glyph parsing, lowering caches, and the React startup hook. Text layout and Scene contracts belong to `@retikz/core`, while final path execution belongs to `@retikz/render`.

## Installation & Usage

`mathjax-full` is an optional peer dependency installed and version-pinned by the application:

```bash
pnpm add @retikz/tex mathjax-full
```

React applications should normally use `useLowerTex`. The hook starts a shared MathJax engine asynchronously and returns the synchronous lowerer injected through `<Layout lowerTex>` once it is ready:

```tsx
import { Layout, Node } from '@retikz/react';
import { useLowerTex } from '@retikz/tex/react';

const Diagram = () => {
  const lowerTex = useLowerTex();

  return (
    <Layout lowerTex={lowerTex}>
      <Node position={[0, 0]}>{'$\\frac{a}{b} = c$'}</Node>
    </Layout>
  );
};
```

`useLowerTex` returns `undefined` until the engine is ready, then triggers recompilation. React injects through `<Layout lowerTex>`; Vanilla uses `compile.lowerTex`.

## Why @retikz/tex Exists

### Keeping Core Engine-Agnostic

Formula layout needs an engine such as MathJax, whose size and startup lifecycle differ from ordinary text measurement. If Core depended directly on MathJax, every user and renderer would inherit that dependency and lifecycle.

Core therefore defines only `LowerTex`: it receives TeX source, inline/display metrics, and font size, then returns plain glyph paths, dimensions, and baseline depth. `@retikz/tex` implements that injection point while depending only on the minimal `MathJaxSvgEngine.convert` abstraction. Applications can provide another engine that satisfies the same abstraction.

### No MathJax Dependency After Scene

| Stage               | Owner            | Output                                                  |
| ------------------- | ---------------- | ------------------------------------------------------- |
| Formula authoring   | Core text IR     | String sugar or a `{ tex, displayMode }` math run       |
| Formula lowering    | `@retikz/tex`    | Renderer-agnostic glyph commands and metrics            |
| Text layout / Scene | `@retikz/core`   | Baseline-aligned `PathPrim` / `GroupPrim`               |
| Backend output      | `@retikz/render` | SVG, Canvas, or another renderer sharing the same Scene |

Before entering Scene, formulas are already Core path primitives. SVG and Canvas do not need separate LaTeX implementations, and there is no parallel MathJax DOM versus Canvas formula model.

`$...$` uses inline metrics on the text baseline. `$$...$$` uses display metrics with more vertical room for fractions, sums, and integrals. A multiline LaTeX environment still belongs to one Node with one bbox and connection target. Enabling `shape` continues to use regular Node padding and boundary calculation.

## Mixed Text And Math

The most natural mathematical prose places formulas inside text. Mix them directly in a string and Core aligns formulas and ordinary text on the same baseline:

```tsx
<Node>{'when $v = d/t$, the displacement is $s = v t$'}</Node>
```

Use explicit `runs` when individual segments need their own color, opacity, or text font. Text runs accept `fill`, `opacity`, and `font`; math runs accept `fill`, `opacity`, and `displayMode`:

```tsx
<Node
  text={[
    {
      runs: [{ tex: '\\sin\\alpha = \\frac{1}{2}', fill: 'red' }, { text: ' (red segment length)' }],
    },
  ]}
/>
```

## Injection Paths

### React Hook

`useLowerTex` reuses one shared engine startup and avoids writing state after unmount. Most React applications only inject it into the outer `<Layout>`; descendant text then shares the same compile capability.

### Manual Construction

For non-React startup or custom MathJax packages, create the engine and lowerer from the main entry:

```ts
import { createLowerTex, createMathJaxEngine } from '@retikz/tex';

const engine = await createMathJaxEngine({ packages: ['base'] });
const lowerTex = createLowerTex(engine);
```

`options.packages` is passed to MathJax TeX input and defaults to `['base']`. You can also implement `MathJaxSvgEngine` directly, provided its synchronous `convert(tex, { display })` returns supported MathJax SVG.

### Vanilla

Vanilla places the same lowerer under `compile.lowerTex`; plain specs, Core IR, and Scene retain their existing entry behavior:

```ts
import { figure, node, renderToSvgString } from '@retikz/vanilla';
import { createLowerTex, createMathJaxEngine } from '@retikz/tex';

const lowerTex = createLowerTex(await createMathJaxEngine());
const spec = figure({
  children: [node('eq', { position: [0, 0], text: '$\\frac{a}{b} = c$' })],
});

const svg = renderToSvgString(spec, { compile: { lowerTex } });
```

## Failure And Performance Boundaries

| Condition                                 | Observable behavior                                                                                  |
| ----------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| String sugar without `lowerTex`           | Preserve `$...$` / `$$...$$` as ordinary text without parsing                                        |
| Explicit math run without `lowerTex`      | Skip the formula segment and emit `TEX_LOWERER_MISSING`; text runs on the same line still render     |
| Unclosed delimiter                        | Preserve content from the unclosed `$` literally and emit `TEXT_TEX_PARSE_ERROR`                     |
| Invalid engine output or conversion error | Return `null`; Core skips the formula and emits `TEX_INVALID`                                        |
| Failed `mathjax-full` startup             | Keep `useLowerTex` undefined and preserve the original error; clear the failed cache so mounts retry |

`createLowerTex` caches successful and failed lowering results by `fontSize | displayMode | tex source`, avoiding repeated MathJax conversion and SVG glyph parsing inside one lowerer. This cache covers only the pure TeX-to-glyph conversion. It does not cache Core IR, Scene, Node layout, or renderer output, and it does not provide incremental compilation or DOM / Canvas patching.

## Syntax

| Form              | Meaning                                                         |
| ----------------- | --------------------------------------------------------------- |
| `$...$`           | Inline formula using baseline-aligned inline metrics            |
| `$$...$$`         | Display metrics; alone in a Node, it behaves as a formula block |
| `\$`              | Literal dollar sign rather than a delimiter                     |
| `{ runs: [...] }` | Explicit sequence with independently styled text and math runs  |

## API Reference

| API                                 | Type                                      | Description                                                                                   |
| ----------------------------------- | ----------------------------------------- | --------------------------------------------------------------------------------------------- |
| `useLowerTex` (`@retikz/tex/react`) | `() => LowerTex \| undefined`             | Start and share the MathJax engine; return `undefined` while unavailable                      |
| `createMathJaxEngine`               | `(options?) => Promise<MathJaxSvgEngine>` | Create the MathJax SVG engine; `packages` defaults to `['base']`                              |
| `createLowerTex`                    | `(engine) => LowerTex`                    | Adapt an engine to Core and cache by font size, display mode, and TeX source                  |
| `MathJaxSvgEngine`                  | `{ convert(tex, { display }): string }`   | Minimal synchronous engine abstraction consumed by this package                               |
| `LowerTex` (`@retikz/core`)         | `(content, style) => LoweredTex \| null`  | Core injection point returning renderer-neutral glyph paths and metrics, or `null` on failure |
