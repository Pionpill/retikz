`@retikz/tex` lowers LaTeX into glyph `PathPrim`s that `@retikz/core` can render. A formula is not a separate content field — it is **part of the text**: `$...$` (inline) and `$$...$$` (display) inside any string are parsed at compile time, or you can write an explicit `{ runs: [...] }` sequence to mix text and math. The lowering is injected via `lowerTex`, so **core does not depend on MathJax**.

## Install & enable

`@retikz/tex` provides the TeX → glyph-path capability; MathJax is an optional peerDependency, installed and version-pinned by the app:

```bash
pnpm add @retikz/tex mathjax-full
```

In React, `useLowerTex` boots MathJax and injects the capability into `<Layout lowerTex>`; then write `$...$` in any `<Node>` text:

```tsx
import { Layout, Node } from '@retikz/react';
import { useLowerTex } from '@retikz/tex/react';

const Diagram = () => {
  const lowerTex = useLowerTex();

  return (
    <Layout lowerTex={lowerTex}>
      <Node position={[0, 0]}>{'$\\frac{a}{b} = c$'}</Node>
    </Layout>
  );
};
```

Without `lowerTex`, string sugar and explicit math runs behave differently:

- **String sugar:** `$...$` / `$$...$$` is not parsed; the dollar signs and enclosed content remain ordinary text.
- **Explicit math run:** the formula segment in `{ runs: [{ tex: '...' }] }` is skipped with a `TEX_LOWERER_MISSING` warning; other text still renders.

Inject it through `<Layout lowerTex>` in React or `compile.lowerTex` in Vanilla.

## Inline vs display

`$...$` uses inline metrics and sits on the text baseline; `$$...$$` uses display metrics (roomier fractions / sums / integrals). When a node's entire content is one `$$...$$`, it is equivalent to a standalone formula block, sized by the glyph bbox:

## Inline text + math

The most natural math reads as text with formulas mixed in. Just write them together in one string — outside `$...$` is text, inside is math, sharing one baseline:

```tsx
<Node>{'when $v = d/t$, the displacement is $s = v t$'}</Node>
```

For **per-segment color / style**, use explicit `runs`: each run is `{ text, fill?, font? }` or `{ tex, displayMode?, fill? }`:

```tsx
<Node text={[{ runs: [{ tex: '\\sin\\alpha = \\frac{1}{2}', fill: 'red' }, { text: ' (red segment length)' }] }]} />
```

## Vanilla

`createMathJaxEngine(options?)` (await) → `createLowerTex` → inject it as vanilla `compile.lowerTex`; node text uses `$...$` as usual. `options.packages` is passed to MathJax TeX input and defaults to `['base']`:

```ts
import { figure, node, renderToSvgString } from '@retikz/vanilla';
import { createMathJaxEngine, createLowerTex } from '@retikz/tex';

const lowerTex = createLowerTex(await createMathJaxEngine());
const spec = figure({
  children: [node('eq', { position: [0, 0], text: '$\\frac{a}{b} = c$' })],
});

const svg = renderToSvgString(spec, { compile: { lowerTex } });
```

## Syntax

| Form              | Meaning                                                                        |
| ----------------- | ------------------------------------------------------------------------------ |
| `$...$`           | Inline formula (inline metrics, on the text baseline)                          |
| `$$...$$`         | Display formula (block metrics; alone in a node = standalone / framed formula) |
| `\$`              | A literal dollar sign (not a delimiter)                                        |
| `{ runs: [...] }` | Explicit run sequence (canonical)                                              |

A text run can set its own `fill`, `opacity`, and `font`; a math run can set its own `fill` and `opacity`.

## API reference

| API                                 | Type                                      | Description                                                                                                  |
| ----------------------------------- | ----------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `useLowerTex` (`@retikz/tex/react`) | `() => LowerTex \| undefined`             | React hook: boots MathJax, returns the function to inject into `<Layout lowerTex>`; `undefined` until ready. |
| `createMathJaxEngine`               | `(options?) => Promise<MathJaxSvgEngine>` | Create a MathJax SVG engine; `packages` is passed to MathJax TeX input and defaults to `['base']`.           |
| `createLowerTex`                    | `(engine) => LowerTex`                    | Turn the engine into core's `lowerTex` injection function, cached by `fontSize\|display\|tex`.               |
| `LowerTex` (`@retikz/core`)         | `(content, style) => LoweredTex \| null`  | Core injection-point type; returns `null` on failure, compile emits `TEX_INVALID`.                           |
