A node declares content, shape, placement and appearance. `resolveNode` determines effective semantics; `compileNode` lays out and emits the node. Reconciler supplies measurement, references, resources and proposals, then integrates results with naming and subtree output.

## Overall Flow

CanonicalNode holds effective configuration and capability bindings. CompiledNodeLayout holds measured and positioned results. CompiledNode associates current Shape / Boundary bindings with layout and emit products. Query geometry is composed as needed; drawing consumes emit.overall.

## What Remains After Resolution

Resolution has handled inheritance, defaults, colors, shadows and capability parameters. Scale has already been applied to relevant dimensions, fonts and parameters. Compilation does not apply it again. References may still depend on geometry, and text dimensions depend on measurement, so Canonical is not final layout.

Node A from the running example fits its text inside a minimum 60 × 40 visual rectangle centered at [0, 0], without additional rotation:

```ts
const node = {
  type: 'node',
  id: 'A',
  position: [0, 0],
  text: 'A',
  layout: { minimumSize: { width: 60, height: 40 }, padding: 0, margin: 0 },
} satisfies import('@retikz/core').IRNode;
```

## Content Measurement and Shape Constraints

Core calls the injected measureText service rather than reading DOM. The host supplies width, height and optional ascent / descent; missing baseline metrics each use half the height. Reconciler supplies approximate measurement when no host service exists and owns reuse within an execution.

Plain text preserves explicit line breaks and wraps into physical lines under a width budget. Inline segments share a baseline; an indivisible formula can overflow. Padding is added to the content box before the Shape's computeCircumscribedGeometry runs. Minimum size and fixed visual width participate in the final size.

These nodes share the same content: a narrower text budget increases line count; an external label leaves the body dimensions unchanged.

<ComponentPreview files="layout-example" size="md" hideCode type="illustration" />

| Constraint            | Applies to                                                        |
| --------------------- | ----------------------------------------------------------------- |
| maxTextWidth          | Text wrapping budget, not an exact shape width                    |
| minimumSize           | Minimum visual box, without compressing content                   |
| width                 | Fixed visual width; compilation fails if content still cannot fit |
| Parent width proposal | Allocation budget accounting for margin and rotation              |

`measureNodeBody` uses bounded feedback between text width and custom shape dimensions. A parent proposal is not a guaranteed clipping constraint: the parent consumes the actual contribution returned. Fixed width and a parent proposal have different contracts.

## Content, Visual Shape and Allocation

In this figure, 40 × 24 content plus padding 8 becomes 56 × 40. Minimum size expands the visual box to 80 × 48; margin 6 produces a 92 × 60 allocation. Margin does not enlarge the visible rectangle, and labels do not enlarge the shape.

<ComponentPreview files="layout-boxes" size="lg" hideCode type="illustration" />

Asymmetric padding and shape offsets can separate content and visual centers, so layout stores them separately. Self-anchor placement needs a provisional layout before translating the node to its target.

## Baselines, Labels and Connection Geometry

A line slot must contain actual ascent + descent. With line height 24, ascent 14 and descent 4, each side gets 3 extra units, placing the baseline 17 units below the slot top. Emission reuses this baseline.

<ComponentPreview files="layout-baseline" size="lg" hideCode type="illustration" />

Labels are measured independently and placed using shape attachment points, direction and distance. Final bounds include labels, but paths do not automatically connect to label edges. Shape controls visible geometry; Boundary controls automatic connection geometry.

<ComponentPreview files="layout-boundaries" size="lg" hideCode type="illustration" />

Standard directional and numerical-angle anchors use the connection surface and margin. Shape-specific anchors and proportional edge points use the visual shape. Reconciler owns boundaryStore and associates query state with current bindings; a Core node stage does not create a multi-node store.

## Handing Off Output and Geometry

emitNode handles shape, content and label emission separately, then assembles local primitives and bounds. A text-bearing or rotated node uses GroupPrimitive for metadata and transforms. One Node does not necessarily equal one rectangle primitive.

Reconciler uses projectNodeGeometry to combine bindings and layout, projects it through Scope transforms and publishes it for references. Scene primitives remain in their owning space. Prepared inputs can supply complete or partial layout / emit products; Core computes missing parts, while Reconciler decides reuse validity.
