`@retikz/vanilla` 是无框架入口。你可以用 plain spec 描述图形，也可以直接传入 Core IR 或已编译的 `Scene`，再通过 SSR、SVG DOM 或 Canvas runtime 输出结果。

它负责普通数据写法、输入适配和宿主生命周期，不另造图形语义：IR、schema、几何与编译规则属于 `@retikz/core`，后端执行属于 `@retikz/render`。

## 安装与使用

```bash
pnpm add @retikz/vanilla
```

```ts
import { figure, layer, mount, node, path, renderToSvgString } from '@retikz/vanilla';

const spec = figure({
  id: 'flow',
  layers: [
    layer('main', [
      node('a', { position: [0, 0], text: 'A' }),
      node('b', { position: [120, 0], text: 'B' }),
      path('edge', {
        way: ['a', 'b'],
        marks: [{ pos: 1, mark: { kind: 'arrow' } }],
      }),
    ]),
  ],
});

const svg = renderToSvgString(spec);
const view = mount(document.querySelector('#diagram')!, spec);
```

`renderToSvgString` 不依赖 DOM，适合 SSR、构建期生成或保存 SVG；`mount` 用于浏览器宿主，默认创建 SVG，也可以通过 `renderer: 'canvas'` 切换到 Canvas。返回的 `view` 负责后续 `update`、交互水合、动画控制与释放。

`figure({ theme: { style, mode } })` 会把稀疏 Theme 写入根 `IRScene.theme`，`scope({ theme }, children)` 复用同一局部继承契约。helper 与 normalization 会复制 Theme 对象，不修改调用方输入；React 与 Vanilla 因而能把同一 Theme IR 交给同一条 Core compile 管线。

## 为什么需要 @retikz/vanilla

### 用普通数据组织图形

直接构造 `@retikz/core` IR 是可行的，但应用通常还需要图层、稳定 identity、Tier 2 嵌入和 runtime metadata。`figure`、`layer`、`node`、`path`、`scope` 与 `embed` 用普通对象和函数表达这些结构，不要求 JSX、React runtime 或组件生命周期，适合服务端、构建脚本、原生 DOM 应用和其它非 React 宿主。

这些 helper 只降低构造成本：`node`、`path` 等最终仍生成 Core 图元，plain spec 也必须先归一成同一份 Core IR。它不是与 Core 平行的第二套 IR。最终 Core IR 保持 JSON 可序列化；`embed.props` 是否可序列化则由调用方与对应 adapter 共同保证。

### 为什么分开 spec 与 runtime

spec 只描述“画什么”，不持有 DOM、Canvas、时钟或 `update` 方法；`mount` 再返回管理宿主状态的 view。同一份 spec 因而可以先用 `renderToSvgString` 做 SSR，也可以在浏览器挂载，或在渲染前单独调用 `normalizeFigureSpec` 检查产物。

这种分离让 authoring 数据保持可生成、可比较和可测试，也把副作用集中在 runtime 边界。Vanilla 薄的是图形语义，不是宿主接线：DOM 物化、Canvas 重绘、水合和动画生命周期仍由它负责。

## 从 spec 到 Scene

`@retikz/vanilla` 接受三个输入层级。下图蓝色节点属于 Vanilla 的 authoring / adapter，橙色节点是 Core 拥有的数据契约与编译器；`Scene` 之后才进入具体后端。

<ComponentPreview files="vanilla-pipeline" size="xs" hideCode />

| 输入           | 所有者            | Runtime 如何处理                                                   |
| -------------- | ----------------- | ------------------------------------------------------------------ |
| plain spec     | `@retikz/vanilla` | 归一图层、嵌入与 metadata；默认 retained，也可选择 raw static view |
| Core `IRScene` | `@retikz/core`    | 跳过 spec 归一；默认 retained，也可选择 raw static view            |
| `Scene`        | `@retikz/core`    | 跳过归一与编译，只创建完整重绘的 static view                       |

plain spec 路径会先由 `normalizeFigureSpec` 生成 Core IR，再由 Core Program 解析 composite、registry、引用、几何、布局、资源与动画。IR / plain spec 的 retained mount 通过 `createVanillaRetainedSession → prepareRetainedInput` 建立可连续更新的 Core + Render Session，raw static mount 则每次完整归一、编译并物化。`renderToSvgString` 和预编译 `Scene` 的 static mount 继续通过 `toSceneResult` 完成一次性编译 / 分流。所有入口最终都消费同一 Core Scene 与 Render 后端，不建立平行图形语义。

## Runtime 与性能边界

| API                 | 用途                                 | 返回                         |
| ------------------- | ------------------------------------ | ---------------------------- |
| `renderToSvgString` | SSR / 构建期产 `<svg>` 字符串        | `string`                     |
| `mount`             | 按 `renderer` 挂载 SVG 或 Canvas     | `VanillaView` / `CanvasView` |
| `mountSvg`          | 显式挂载 SVG DOM                     | `VanillaView`                |
| `mountCanvas`       | 显式挂载 Canvas                      | `CanvasView`                 |
| `hydrate`           | 对 SSR / 已有 SVG 根节点绑定 handler | `HydrationHandle`            |

`mountSvg` / `mountCanvas` 的返回值可用 `mode` 或 `VanillaViewMode` 判别。默认配置下，IR 与 plain spec 创建 `VanillaViewMode.Retained` view：`update(next, options?)` 把完整输入与可变 renderer config 放进同一次 transaction，Core 发布 Scene Patch 或 full fallback，Render participant 成功后才原子替换 DOM / bitmap、artifacts、inspection plane、runtime metadata、事件和动画句柄。失败 transaction 不发布新 revision；rollback 成功时旧 view 继续可用，rollback 自身失败时 Session 进入 broken，需要 dispose 后 remount。

retained `view.dispose()` 会移除宿主并完成一次反向 best-effort cleanup；失败项在逻辑资源 retire 后同次重试。若仍有 pending cleanup，重复调用 `view.dispose()` 只重试失败项；成功项与宿主移除保持幂等。

IR / plain spec 也可显式选择 static 完整重绘。三种合法组合为：

| 配置              | 更新行为                                         | Session、内存与失败语义                                                                 |
| ----------------- | ------------------------------------------------ | --------------------------------------------------------------------------------------- |
| `retained + auto` | 安全变化走局部 Patch，其余完整 fallback          | 保留 Snapshot、candidate、diagnostics、原子 commit 与 rollback；默认配置                |
| `retained + full` | 有实际依赖变化时跳过 Program `update()` 完整运行 | 与 auto 持有相同 Runtime 状态和事务能力；不是低内存模式                                 |
| `static`          | 每次完整 normalize、compile 并重绘               | 不创建 Session、Snapshot、diff、transaction 或 rollback；减少常驻状态，但每次工作量更大 |

raw static view 的 `update(next)` 接受 `IRScene | VanillaFigureSpec`，不锁死初始 input subtype，并在同一个 root 上更新 `runtimeMeta`、artifacts、水合与动画。compile / normalization 在宿主写入前失败时，旧画面与公开 getter 保持不变；物化、动画或水合切换已开始后若失败则同步抛错，但不承诺回滚，调用方应 dispose 后 remount。

预编译 `Scene` 仍天然创建 `VanillaViewMode.Static` view：`update(nextScene)` 保持 root identity，但完整重绘后端；它没有 Core Program、Patch、Runtime diagnostics、compile artifacts 或可运行的 inspector。这个入口拒绝整个 `runtime` 字段；传 `inspect` 也会 fail-loud，因为 adapter 不会从已编译 Scene 反推布局 artifact。需要产物或辅助层时，应传 IR / plain spec。

`mode` 与 `updateStrategy` 都在 mount 时固定。改变策略、DPR 或 compile topology 时必须 dispose 后 remount；不要尝试在 `update()` 中热切换。

retained view 的 `diagnostics()` 按队列顺序返回并清空 Runtime diagnostics。`runtimeMeta` 是 deeply immutable snapshot：layer、`childIds`、identity path 和只读索引都不与内部事务状态 alias；`hydrate()` 读取最新 committed Scene，无需在每次 update 后重新绑定。

SVG retained renderer 会保留未变 DOM identity；Canvas 对安全局部变更更新 dirty region，其余情况走 full fallback。并发调度与 progressive materialization 仍不属于当前公开契约。

## 选项结构

渲染入口的选项按消费阶段分组：

```ts
renderToSvgString(spec, {
  output: { width: 640, height: 360, idPrefix: 'flow' },
  compile: { composites, measureText },
  inspect: { layout: true },
  animation: { enabled: true },
});

mount(canvasRoot, spec, {
  renderer: 'canvas',
  output: { width: 640, height: 360 },
  canvas: { devicePixelRatio: 2 },
  runtime: { mode: 'retained', updateStrategy: 'auto', rendererFactory },
});

mount(svgRoot, spec, {
  runtime: { mode: 'static' },
});
```

`figure()` 只描述图；`output` 控制显示尺寸和资源 id，`compile` 注入 Core 编译能力，`inspect` 是整张图的 runtime-only 布局检查策略，`animation` 控制播放或截帧，`canvas` 只给 Canvas mount 使用。`compile` 的公开类型显式排除 `inspection`，避免与顶层 `inspect` 提交两份冲突策略。`runtime.mode` 默认是 `retained`，`runtime.updateStrategy` 默认是 `auto`；`rendererFactory` 只在 retained IR / plain spec mount 中替换内置 factory。static 与 `updateStrategy` / `rendererFactory` 互斥，非法 mode、primitive 或 accessor 都会在创建 DOM 前抛 `RETAINED_RUNTIME_INPUT_INVALID`。

Plain spec 还支持 `VanillaScopeSpec.inspect` 的 authored 子树策略，以及每个 `VanillaEmbedSpec.inspect` 的 occurrence-local 策略；Standard 的 `flexLayout()` / `gridLayout()` / `overlayLayout()` 第三个参数提供精确 family 类型。Normalization 只生成 Core authored sidecar，不把这些字段写入 `IRScope` 或 embed props。retained 更新改变 sidecar 时会完整创建候选 Session，成功后原子替换并释放旧 Session；失败时保留旧 frame。

`RenderToStringOptions`、`StaticMountOptions`、`StaticMountCanvasOptions` 与 `StaticMountUnifiedOptions` 是 SSR / 预编译 Scene 的既有 static 配置，继续拒绝整个 `runtime` 字段。raw-input static 则使用 `RawStaticMountOptions` / `RawStaticMountCanvasOptions`，必须显式传 `runtime: { mode: 'static' }`。

`animation.enabled` 省略时跟随系统的“减少动态效果”偏好；显式 `true` 强制开启，显式 `false` 强制关闭。`snapshotAt` 仍会覆盖播放开关并输出静态截帧。

retained `update()` 只接受与后端匹配的 closed plain-data options：SVG 的 `RetainedSvgUpdateOptions` 顶层只有 `animation`；Canvas 的 `RetainedCanvasUpdateOptions` 另有 `canvas.animationProperties`。`devicePixelRatio` 在 mount 时固定；SVG 传 Canvas-only 配置、热改 DPR、未知字段、symbol 或 accessor 都会抛稳定的 `RETAINED_RUNTIME_INPUT_INVALID`。需要改变 DPR 或 compile capability 时请 dispose 后 remount。

## 分层与嵌入

`figure({ children })` 会生成默认 layer。需要明确绘制顺序、稳定 layer id 或未来失效提示时，再用 `layers` 分层。`zIndex` 只决定 layer stack 排序，相同值保持声明顺序；`cache` 只进入 runtime metadata，不进入 Core IR。alpha.2 会把它折叠为 retained config hint，但 SVG / Canvas renderer 尚不消费该字段，也不会据此启用 auto / static / dynamic layer 复用。

Tier 2 能力通过 `embed(kind, id, props)` 接入。Vanilla 不解析组件，也不执行 hooks；它只按 `kind` 找到注入的 adapter，把 props 静态 lower 成 Core IR child、datasets 和 composite definitions。

```ts
import type { VanillaTier2Adapter } from '@retikz/vanilla';
import { embed, figure, layer, node, renderToSvgString } from '@retikz/vanilla';

type BadgeProps = { label: string };

const badgeAdapter: VanillaTier2Adapter<BadgeProps> = {
  kind: 'badge',
  namespace: 'badge',
  lower: (props, context) => ({
    node: node(`${context.id}/label`, { position: [0, 0], text: props.label }),
    datasets: {},
    makeComposites: () => [],
  }),
};

const spec = figure({
  layers: [layer('content', [embed('badge', 'sales', { label: 'Sales' })])],
});

const svg = renderToSvgString(spec, { adapters: [badgeAdapter] });
```

`normalizeFigureSpec` 从包根导出；`adapters` 是 render / mount 选项的顶层字段，不放在 `compile` 里。若需要在渲染前检查归一结果，可直接调用 `normalizeFigureSpec(spec, { adapters })`，读取返回的 `ir`、`composites` 与 `runtimeMeta`。

plain-spec retained update 可以替换同一 composite key/schema/执行分支的 callback，并与 Scene transaction 一起 commit 或 rollback；Definition 数量、顺序、key、schema、expand / compile 分支或 artifact schema 属于固定 topology，改变时必须 dispose 后 remount。

## 职责边界

| 能力               | `@retikz/vanilla` 负责什么                                      | 能力真源 / 边界                |
| ------------------ | --------------------------------------------------------------- | ------------------------------ |
| 普通数据 authoring | 提供 figure、layer、embed 与 Core 图元 helper，归一 plain spec  | `@retikz/core` IR              |
| 编译入口           | 接受 spec / IR / Scene，聚合 adapter 贡献并注入 compile options | `@retikz/core` 编译            |
| 宿主 runtime       | SSR 字符串、DOM / Canvas 挂载、update、水合与动画生命周期       | `@retikz/render` 后端执行      |
| Tier 2 嵌入        | 按 `kind` 调用 adapter 并聚合 lowering 贡献                     | 各领域包拥有 props 与 lowering |

在 React 应用中优先使用 [`@retikz/react`](/kernel/packages/react) 的 JSX 与宿主生命周期；需要无框架、SSR 字符串或直接 DOM / Canvas 挂载时使用本包。
