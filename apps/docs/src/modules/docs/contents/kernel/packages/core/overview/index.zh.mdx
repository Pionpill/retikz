`@retikz/core` 拥有 IR、Definition、registry、编译与 Scene 语义。`compileToScene()` 仍是无状态的完整编译入口；需要跨 revision 管理状态时，`CoreSourceDefinition` 与 `createCoreComputation()` 把同一编译语义接入 `@retikz/runtime`。

## 可组合的 Schema 片段

自定义组合输入可以从 `@retikz/core` 导入以下闭合片段，按需组合字段。它们保持稀疏，不主动物化默认；最终实体仍负责跨字段校验与未知字段策略。

| 片段                          | 字段与职责                                                  |
| ----------------------------- | ----------------------------------------------------------- |
| `GraphicColorSchema`          | `color`，图形主色                                           |
| `GraphicElementOpacitySchema` | `opacity`，整个图元的透明度                                 |
| `GraphicFillSchema`           | `fill`、`fillOpacity`，填充 paint 与透明度                  |
| `GraphicStrokeSchema`         | `stroke`、`strokeOpacity`，描边 paint 与透明度              |
| `StrokeStyleSchema`           | `strokeWidth`、`dashPattern`、`dashOffset`，线宽与虚线      |
| `StrokeCapJoinSchema`         | `lineCap`、`lineJoin`，端点与转角样式                       |
| `TextVisualSchema`            | `textColor`、`font`，图元内的文字颜色与字体                 |
| `TextLayoutSchema`            | `align`、`lineHeight`、`maxTextWidth`，文本排列与换行       |
| `PathTransformSchema`         | `roundedCorners`、`rotate`、`scale`，路径几何圆角与整体变换 |

填充和描边共同使用 `PaintValueSchema`，均可表达渐变。主色与整体透明度分别选择，文字片段不附带 label 专属透明度或布局字段。每个片段均提供对应的 `IRXxx` 推导类型；原有完整 Node、Path 与样式聚合仍可直接使用。

组合 `.shape` 只复用字段，不会继承对象级 refinement、transform 或 catchall。领域输入应仅选择实际消费的片段；例如 Cell 组合描边、填充和文字，仍不因此接受 `zIndex` 或视觉效果。

## 复合组件运行时输入

`CompileOptions.compositeInputs` 将 runtime input 精确绑定到本次 Source 节点位置，由 composite callback 通过 context.runtimeInput 消费；未绑定的位置为 undefined。数据源、函数和准备结果不进入 IR，Core 不解释其领域内容。

转交作者 child 时，composite context.sourceChild 保留其 Source 身份；生成 child 使用 context.bindChild 显式绑定输入。opaque child 必须由同一次编译上下文消费，不可自行展开或写入 JSON。probe、replay 和 direct lowering 使用同一绑定；布局测量不重新执行领域计算。retained Computation 的运行输入与 Source 在同一事务发布。

## Theme 环境

Core 公开 `ThemeMode`、`ThemeSchema`、`ResolvedTheme` 与 `ResolvedThemeColors`。`IRScene.theme` 和 `IRScope.theme` 仅保存稀疏、JSON-safe 的 `style` / `mode` selector；compile 从默认 light 基线开始按 Scene → Scope 继承，并把完整、冻结的 `ResolvedTheme` 传给 `CompositeDefinition.expand`、布局感知 `compile` 与 observation context。

发布包不提供命名 style；自定义 style 用 `defineThemeStyle` 定义并经 compile 的 `themeStyles` 注入。resolver 只需返回相对当前 `mode` 默认 shared colors 的稀疏覆盖：`semantic` 按角色合并，显式 `categorical` 整体替换默认 palette；省略或显式返回 `undefined` 的已知字段由现有 `??` fallback 继续使用该 mode 的默认值。输出只由 Core owner schema 解析一次，未知字段、空白颜色、空 palette 与非法值立即 fail-loud；不会再套通用 JSON preflight 或 snapshot。resolver 函数与运行时结果不进入 IR，未注册名称同样立即失败。

```ts
import { defineThemeStyle, ThemeMode } from '@retikz/core';

const brand = defineThemeStyle({
  name: 'brand',
  resolve: ({ mode }) => ({
    semantic: { guide: mode === ThemeMode.Dark ? '#94a3b8' : '#64748b' },
  }),
});
```

Core 只负责传播 selector 并生成 detached/frozen `colors` 视图，不解释领域 token。`ResolvedTheme.colors` 提供 shared semantic colors（包括 `error`、`success`、`warning` 与低强调辅助色 `guide`）以及当前 categorical palette；后者允许重复值，并由消费方按稳定 index 取余。Core primitive、最终 Scene 与 renderer 都不按 Theme 分支。契约和失败语义见[编译](/kernel/packages/core/overview)，schema 见[场景](/kernel/components/layout/schema-reference)。

静态 CSS 颜色解析、不透明预合成以及通用 `JsonValue` / `JsonObject` 类型与 schema 由 [`@retikz/foundation`](/kernel/packages/foundation/schema-reference#jsonobjectschema) 统一提供。Core 只拥有 Theme mode、最终主色链与派生颜色确定化，不再从根入口转发这些无领域原子。

## 完整 Snapshot 与 Core Computation

调用方始终提交完整 IR Snapshot。Core owner 负责复制、冻结和比较文档；Core Computation 读取 typed Snapshot，产生完整 `CompileResult`、`SceneRuntimeSnapshot` 与可选 `ScenePatch`，最后由 Runtime Runtime 原子发布。

Runtime 不解释 Node、Path、Scope、Composite 或 Scene。领域 identity、编译诊断和 full-fallback `replaceScene` Patch 都由 Core 决定；Runtime 只约束依赖顺序、candidate 隔离、revision 与发布。

## 基础接线

`CoreSourceDefinition` 和 `createCoreComputation()` 都是普通 Runtime Definition，可以与其它领域 Source / Computation 注册到同一个 Runtime。初始 full run 的 `patch` 为 `undefined`，renderer 从完整 `snapshot` mount。

```ts
import { CORE_SOURCE_KEY, CORE_COMPUTATION_ID, CoreSourceDefinition, createCoreComputation } from '@retikz/core';
import {
  createRuntimeSourceInput,
  createRuntimeSourceRegistry,
  createRuntimeComputationRegistry,
  createRuntime,
} from '@retikz/runtime';

const ir = {
  version: 1,
  type: 'scene',
  children: [{ type: 'node', id: 'hello', position: [0, 0], text: 'Hello' }],
} as const;

const coreComputation = createCoreComputation({ padding: 16 });
const sources = createRuntimeSourceRegistry([CoreSourceDefinition]);
const computations = createRuntimeComputationRegistry({ sources, builtins: [coreComputation] });
const runtime = createRuntime({
  sources,
  computations,
  initialSnapshots: [createRuntimeSourceInput(CoreSourceDefinition, ir)],
});

const { output, snapshot, patch } = runtime.artifact(coreComputation).value;
// output.result: 完整 CompileResult
// snapshot.revision: 0
// patch: undefined
```

固定 identity 为 `CORE_SOURCE_KEY = '@retikz/core/document'` 与 `CORE_COMPUTATION_ID = { owner: CORE_SOURCE_KEY, key: 'compile' }`。调用方不应复制字符串另建平行 owner。

## Artifact 契约

| 字段                     | 作用                                                                                |
| ------------------------ | ----------------------------------------------------------------------------------- |
| `output.result`          | 与同一 IR/options 下 fresh `compileToScene()` 等价的 Scene 与 typed artifacts       |
| `output.diagnostics`     | canonical 顺序的 Core compile warnings；只在成功 commit 后派发给 `onWarn`           |
| `output.observerOutputs` | 与主结果属于同一 candidate revision 的显式观测输出                                  |
| `snapshot`               | 当前 Runtime revision 的 deeply immutable Scene、document root identity 与 topology |
| `patch`                  | 相对 base revision 的原子 Scene Patch；initial full run 不提供                      |

普通 `compileToScene()` 只返回主 Scene 与 artifacts，不创建观测会话。需要读取最终 occurrence 时，调用 `observeCompileToScene(ir, options, observers)`，或在 `createCoreComputation()` 的 `runtimeOptions.observers` 中固定 observer definitions。每个 observer 都为一次 compile 创建独占 session，并依次执行 `select`、`observe` 与 `complete`。

Core 只提供领域中立的观测能力。Composite 通过现有 `artifactSchema` 发布最终产物；Path kind 可声明 `ownerOutput.schema`，并在 `context.ownerOutput.requested` 为真时调用 `publish()`。只有最终提交的 occurrence 会触发 `observe()`，失败或被丢弃的 probe 不可见；事件携带最终 occurrence、probe/replay 来源以及从所属者局部坐标到主 Scene 坐标的变换。

observer 可用 `context.compileFragment()` 在当前 occurrence 环境中编译普通 `IRChild`。返回的片段包含隔离的静态 Scene、artifacts 与 diagnostics，不写回主编译结果，也不能引用主图或其它片段的公共身份。observer 的最终输出由 `complete()` 决定并递归冻结，Core 不限定其领域结构。Inspector 的注册、选择、配色与只读图层组装位于可选的 [`@retikz/inspect`](/kernel/packages/inspect)。

`context.round(value)` 复用本次主图的编译精度，便于将重新计算的几何坐标与最终输出进行比较；Inspect 的回调上下文也提供同一个方法。

初始运行执行完整编译。update 无法安全局部证明时，Computation 会 full fallback，并在 `patch.operations` 中发布唯一的 `replaceScene`；调用方仍只消费同一个 Snapshot / Patch envelope，不需要切换协议。

Core 会把可选 ChangeSet 与 previous / next 完整 Snapshot 交叉校验。Scene 根和 stable entity 的每一项自身 value 变化都必须由唯一 `update` hint 恰好覆盖；add/remove/move 必须完整解释所属 parent 的 next identity 集合与顺序，`parent` / `before` 指向 next 的最终位置。

document root 的 identity path 是 `['root']`。每个拥有唯一非空 `id` 的普通 child 追加 `[type, id]`；有 `id` 的 Scope 继续作为 parent boundary 递归索引后代，因此 Scope 内 Node 可以形成 `['root', 'scope', scopeId, 'node', nodeId]`。`localNamespace` 只改变引用 frame，不改变这条 identity path；实体跨 Scope 移动时旧、新 path 不同，使用 remove + add，而不是保留旧 identity 的 move。Scope add/remove 不级联，每个 stable descendant 都必须由自己的 hint 单独覆盖。

结构 hint 按集合校验，ChangeSet 数组顺序不是 Patch 执行顺序，每个 parent 内的 move 集合必须构成最小重排。anonymous、同 parent duplicate、Composite、漏报、多余 hint、错误 parent / before 或无法重建 next sibling order 都会被判定为不匹配。

当前局部增量路径先覆盖一个可证明安全的闭环：root 只含 unique-id、绝对 tuple position 的 Node，结构与顺序不变，只有一个 Node 的纯色 `fill` string 变化，并且没有自定义 shape、资源、artifact 或 compile warning。Computation 只重编该 Node contribution，复用其它 committed root contribution，并以一个 emitted-subtree `update` operation 发布 Patch；输出仍与 fresh `compileToScene()` 等价。引用、资源、自定义 shape、Scope、Composite、多 owner 变化或其它无法局部证明的场景继续 full fallback。

不匹配时，`CORE_CHANGESET_MISMATCH` 只作为 Runtime diagnostic 在 fallback 成功 commit 后发布一次，不进入 `output.diagnostics` 或 `onWarn`。fallback compile 失败时不会发布该 diagnostic，也不会推进 revision 或替换 committed artifact。

Core Computation 的 private read 保存下一次 update 使用的 immutable source Snapshot 与 stable identity index；已提交的完整 Scene Snapshot 同时作为安全子集的 contribution cache。dependency Computation、participant 与 `runtime.artifact()` 只能看到上表中的 public read，不会取得 source/index 私有状态。

## 不可变 Computation options

`createCoreComputation(options, runtimeOptions?)` 在 factory 调用时复制 option record、registry array 与 Definition record，并固定 callback reference。之后修改原数组或 Definition 字段不会改变已创建 Computation。

普通 measurer、lowerer、provider callback 或 option 变化仍要求销毁旧 Runtime，再用新 options 创建 Computation。若固定 Definition 的 callback 会读取一份可变外部状态，可把该状态建模成 Runtime Source，并通过 `runtimeOptions.invalidationSources` 声明为额外失效依赖；source value 只触发 Core Computation 重算，不进入 IR 或 Scene。

`invalidationSources` 不会替换固定 Definition topology，也不会自动更新 callback reference。新 Computation 的第一轮总是 full run；`trace` 由 Runtime Computation context 统一注入，因此不属于 `CoreComputationOptions`。

同一个失效 owner 必须同时进入 source registry、Computation runtime options、初始 Snapshot，以及状态变化时的 update transaction：

```ts
import { CoreSourceDefinition, createCoreComputation } from '@retikz/core';
import {
  createRuntimeSourceInput,
  createRuntimeSourceRegistry,
  createRuntimeSourceUpdate,
  createRuntimeComputationRegistry,
  createRuntime,
  defineRuntimeSource,
} from '@retikz/runtime';

const MeasureRevisionSource = defineRuntimeSource({
  key: 'app:measure-revision',
  value: {
    capture: value => value,
    read: value => value,
    equals: Object.is,
  },
});

const coreComputation = createCoreComputation({}, { invalidationSources: [MeasureRevisionSource] });
const sources = createRuntimeSourceRegistry([CoreSourceDefinition, MeasureRevisionSource]);
const computations = createRuntimeComputationRegistry({ sources, builtins: [coreComputation] });
const runtime = createRuntime({
  sources,
  computations,
  initialSnapshots: [
    createRuntimeSourceInput(CoreSourceDefinition, ir),
    createRuntimeSourceInput(MeasureRevisionSource, 0),
  ],
});

runtime.update({
  baseRevision: runtime.revision(),
  sources: [createRuntimeSourceUpdate(MeasureRevisionSource, 1)],
});
```

## 公开 API

| 导出                                                                     | 作用                                                                  |
| ------------------------------------------------------------------------ | --------------------------------------------------------------------- |
| `CORE_SOURCE_KEY` / `CORE_COMPUTATION_ID`                                | Core document owner 与 compile Computation 的固定 identity            |
| `CoreSourceDefinition`                                                   | 完整 IR Snapshot 的 capture/read/equality Definition                  |
| `ThemeStyle` / `ThemeMode` / `ThemeSchema`                               | 内置 Theme 词汇、严格 IR schema 与 Scene / Scope 继承入口             |
| `IRTheme` / `ResolvedTheme` / `ResolvedThemeColors`                      | 稀疏持久化覆盖、完整冻结环境与 shared color view                      |
| `ThemeStyleDefinition` / `ThemeStyleColorOverrides` / `defineThemeStyle` | 定义稀疏 Core style resolver，并经 `themeStyles` 注入                 |
| `createCoreComputation(options, runtimeOptions?)`                        | 创建保留 composite artifact 泛型的 Runtime Computation Definition     |
| `CoreChange`                                                             | `add` / `update` / `remove` / `move` change hint union                |
| `CoreComputationOptions<TComposites>`                                    | `CompileOptions` 去掉 `trace` 后的 Computation 生命周期配置           |
| `CoreComputationRuntimeOptions`                                          | 声明只负责失效、不进入 IR / Scene 的额外 Runtime sources              |
| `CoreComputationOutput<TComposites>`                                     | 完整 compile result 与 warnings                                       |
| `CoreComputationPublicRead<TComposites>`                                 | public `output` / `snapshot` / optional `patch`                       |
| `CoreComputationDefinition<TComposites>`                                 | 保留 artifact input、owned artifact、private/public read 泛型         |
| `RuntimeScene` / `SceneRuntimeSnapshot` / `ScenePatch`                   | deeply readonly Scene 与原子 Patch DTO                                |
| `observeCompileToScene()`                                                | 显式执行带 observer sessions 的完整编译                               |
| `defineCompileObserver()` / `CompileObserverDefinition`                  | 定义一次编译期观测会话及其稳定 key                                    |
| `CompileObservation` / `CompileObservationContext`                       | 最终所属者产物、occurrence、变换、occurrence Theme 与隔离片段编译入口 |
| `CompileOwnerOutputDefinition` / `CompileOwnerOutputPublisher`           | Path kind 的按需最终产物声明与发布                                    |
| `ObservedCompileResult` / `CompileObserverOutput`                        | 主编译结果与按 definition 顺序返回的领域自定义输出                    |
| `RetikzCoreError` / `RetikzCoreErrorCode`                                | Core 唯一错误类与可判定的 parse、resolve、compile 等稳定错误码        |
