`@retikz/foundation` is a pure utility package that provides foundational capabilities for all packages, keeping shared types, JSON and structurally readonly collection snapshots, scalar validation, and blank-string semantics in one place. Zod is its only production dependency.

## Contents

### Type utilities

These utilities work only at compile time. They emit no runtime code and carry no IR or domain model.

| Export                            | Semantics                                                                  |
| --------------------------------- | -------------------------------------------------------------------------- |
| `ValueOf<T>`                      | Derive the union of an object's values                                     |
| `AssertEqual<TActual, TExpected>` | Return `true` only for bidirectionally assignable types                    |
| `OpenString<T>`                   | Keep built-in literal hints while accepting custom strings                 |
| `WithRequiredProperties<T, TKey>` | Make only selected keys required while preserving other and readonly props |
| `NonEmptyReadonlyArray<T>`        | Readonly array with at least one element                                   |
| `JsonValue`                       | Any recursive JSON value                                                   |
| `JsonObject`                      | String-keyed object of recursive JSON values                               |

For example, `name` becomes required while `note` remains optional:

```ts
type Named = WithRequiredProperties<Readonly<{ name?: string; note?: string }>, 'name'>;
```

### Readonly collection snapshots

`createReadonlyMap(entries)` copies input entries into an independent shallow snapshot. The result preserves native Map lookup, iteration, and insertion order without exposing `set`, `delete`, or `clear`; entry values retain their original identity and are not deep-copied or frozen.

```ts
const definition = { kind: 'point' };
const source = new Map([['point', definition]]);
const definitions = createReadonlyMap(source);

source.clear();
definitions.has('point'); // true
```

### Generic JSON schemas

`JsonObjectSchema` represents a string-keyed object of recursive JSON values. `JsonValueSchema` accepts strings, finite numbers, booleans, null, arrays, and objects. Foundation owns both contracts for reuse by metadata, custom-provider parameters, and open composite fields:

Both schemas use Zod's recursive JSON validation directly. The array branch of `JsonValue` is readonly so an `as const` Source can enter the unknown parse boundary directly. Validation adds no walker, `undefined` filter, structural optimization, clone, freeze, or second generic pass. Domain Source inputs still use their precise owner schema rather than replacing it with a generic JSON schema.

### JSON data snapshots

`cloneAndFreezeJson(value, path)` validates JSON-safe plain data and returns a detached deeply frozen copy. Cycles, accessors, symbol keys, sparse arrays, extra array properties, non-finite numbers, and class instances throw `RetikzFoundationError`:

```ts
const snapshot = cloneAndFreezeJson({ filters: [{ field: 'age', value: 18 }] });

Object.isFrozen(snapshot); // true
Object.isFrozen(snapshot.filters); // true
```

`assertPlainDataContainers(value, path)` checks container structure without copying data or reading accessors. It is reserved for runtime Definition boundaries that have no persisted schema but still need plain-container isolation. Source inputs with an owner schema consume the Zod `parse()` result directly instead of using this assertion as a generic preflight. Leaf values such as strings, numbers, and `undefined` are outside this assertion's responsibility:

```ts
assertPlainDataContainers({ supportsRouting: true }, 'Flow Layout Definition capabilities');
```

### General contracts

The six fixed scalar schemas validate without coercion, trimming, transforms, or defaults. Consumers still compose domain objects, domain ranges, and cross-field relations:

| Export                     | Accepted values                                                   |
| -------------------------- | ----------------------------------------------------------------- |
| `NonBlankStringSchema`     | At least one non-whitespace character; preserves successful input |
| `PositiveNumberSchema`     | Finite numbers greater than `0`                                   |
| `NonNegativeNumberSchema`  | Finite numbers greater than or equal to `0`                       |
| `PositiveIntegerSchema`    | Positive safe integers                                            |
| `NonNegativeIntegerSchema` | Non-negative safe integers                                        |
| `NormalizedFractionSchema` | Finite numbers in the inclusive `0..1` range                      |

```ts
NonBlankStringSchema.parse(' layer/main '); // returned unchanged
PositiveNumberSchema.parse(1.5);
NormalizedFractionSchema.parse(0.5);
```

`createOpenStringSchema(values)` accepts a const object enum while preserving both built-in literal suggestions and arbitrary non-blank custom strings. It does not query a registry or turn extension keys into a whitelist. Generated JSON Schema retains both the known enum branch and the open string branch:

```ts
const Role = { Participant: 'participant', Activity: 'activity' } as const;
const RoleSchema = createOpenStringSchema(Role);

RoleSchema.parse('participant');
RoleSchema.parse('custom.role');
```

### Static color atoms

`parseStaticCssColor(input)` parses a statically knowable CSS color into normalized sRGB channels `{ r, g, b, a }`; dynamic values such as `currentColor` and CSS variables return `null`. `compositeOpaqueColor(foreground, backdrop, weight)` precomposes a static foreground at a `0..1` weight over an opaque backdrop and returns lowercase `#rrggbb`:

```ts
parseStaticCssColor('darkorange');
compositeOpaqueColor('#336699', '#ffffff', 0.2); // '#d6e0eb'
```

Foundation owns only static parsing and pure color math; it knows nothing about Theme modes or drawing fields. Invalid colors, translucent backdrops, and out-of-range weights throw `RetikzFoundationError` with code `FOUNDATION_COLOR_ERROR`. Core decides when to call these atoms from the final style and Theme mode.

## When to abstract

<ComponentAlert
  type="tip"
  title="Only retikz contributors need this"
  description="Most developers can skip this section and return when adding or changing Foundation capabilities."
/>

Any new Foundation capability must satisfy all four conditions:

1. It has no dependency on a Retikz domain, platform, or state; schemas may only use Foundation's accepted Zod dependency
2. It has independently nameable semantics, an invariant, or a failure boundary
3. At least two independent packages consume it with the same meaning, or it is part of Foundation's minimal error, type, or assertion protocol
4. It does not make an upper package obtain a capability through Foundation that belongs to Core, Math, Runtime, or a domain owner

`createOpenStringSchema(values)` is the only permitted parameterized schema factory and only combines a const object enum with Foundation's existing non-blank string boundary. Except for the domain-free generic JSON value and object schemas, other object or array schemas, range factories, geometry algorithms, Diagnostics, error catalogs, and domain resolvers remain with their current owner. When repetition appears, reassess the semantic owner instead of collecting code in Foundation.
