> This is @retikz/render package documentation, not component docs; to draw, start from [Components](/kernel/components/layout).

The Canvas backend paints the figure as a raster bitmap rather than a DOM. It consumes the same Scene as SVG and aligns drawing semantics where the backend supports them; the whole figure is one canvas instead of an element tree. With no per-primitive DOM nodes, it usually stays steadier than SVG when you have hundreds of primitives or need frequent repaints / animation. The trade-off is losing per-element CSS selection and native accessibility semantics. Coordinate hit-testing restores interaction targeting, not DOM capabilities.

## How to use it

**React** — pass `renderer="canvas"` to `<Layout>` explicitly:

```tsx
import { Layout, Node } from '@retikz/react';

<Layout renderer="canvas">
  <Node id="a">hello</Node>
</Layout>;
```

**Vanilla (browser)** — `mountCanvas` mounts the figure as a `<canvas>`; its view adds canvas-side hydration and coordinate mapping on top of what `mountSvg` returns:

```ts
import { mountCanvas } from '@retikz/vanilla';

const view = mountCanvas(container, ir);
// view.root is the <canvas>; view.update(next) repaints; view.dispose() unmounts
```

The two entries have different input contracts:

| Entry                 | Accepted input                                  | Output     |
| --------------------- | ----------------------------------------------- | ---------- |
| React `<Layout>`      | JSX `children`<br />or `IRScene`                | `<canvas>` |
| Vanilla `mountCanvas` | `Scene` / `IRScene`<br />or `VanillaFigureSpec` | `<canvas>` |

`devicePixelRatio` defaults to `globalThis.devicePixelRatio` (falling back to 1), preserving enough bitmap resolution for high-DPI screens.

## Adding interaction to a Canvas figure

A canvas has no DOM primitives, so locating one relies on **coordinate hit-testing**: the pointer's client pixels are mapped back into Scene coordinates, then geometry hit-testing yields a primitive `id`. That locating is wrapped inside `view.hydrate`, while the handler registry has the same shape as SVG:

```ts
const view = mountCanvas(container, ir);
const handle = view.hydrate({
  handlers: { box: { click: event => toggle('box') } },
});
// handle.dispose() unbinds
```

The same `handlers` table works under SVG and Canvas; the locating implementation and host fields such as `context.element` still differ — see [Hydration](/kernel/packages/render/hydration).

## Known limits

Canvas support depends on the 2D APIs and resource loaders supplied by the host. Low-level `drawScene` accepts `warnUnsupported` for diagnostics; without it, diagnostics go to `console.warn`.

- If the host lacks `createConicGradient`, conic-gradient paint is skipped with a warning.
- Image paint needs `getImage` to return a decoded image. React `<Layout renderer="canvas">` supplies a loader and repaints after loading. In v0.4, Vanilla `mountCanvas` does not expose `getImage`, so image paint is skipped with a warning; custom hosts can call `renderToCanvas` / `drawScene` with a loader and repaint when it becomes ready.
- When calling `drawScene` directly, patterns and exact non-uniform gradient strokes depend on `createOffscreen`. Browser `renderToCanvas` supplies a default offscreen context; other hosts must inject one.
- A missing or currently unsupported paint / clip resource is skipped with a warning.

## Node image export

Use the dedicated `@retikz/render/canvas-node` entry when a server process or CLI needs to emit PNG / JPEG / WebP directly. It keeps the native canvas package out of browser bundles; install the optional peer in the consuming app before calling it:

```bash
pnpm add @napi-rs/canvas
```

```ts
import { compileToScene } from '@retikz/core';
import { renderSceneToImage } from '@retikz/render/canvas-node';

const scene = compileToScene(ir);
const png = await renderSceneToImage(scene, {
  width: 960,
  height: 540,
  devicePixelRatio: 2,
  format: 'png',
  background: '#fff',
});
```

`renderSceneToImage` consumes a compiled `Scene` and reuses `drawScene`. `width` / `height` are CSS-sized dimensions, and the encoded bitmap is multiplied by `devicePixelRatio`; exact effects still depend on the selected native canvas host.

## Canvas or SVG

|                 | Canvas                       | SVG                          |
| --------------- | ---------------------------- | ---------------------------- |
| Output          | Raster bitmap                | Vector DOM nodes             |
| Many primitives | Immediate mode stays steady  | Slows as nodes pile up       |
| Scaling         | Bound by resolution          | Crisp at any zoom            |
| CSS / selectors | One opaque canvas            | Every primitive hit-testable |
| Default         | Explicit `renderer="canvas"` | Yes                          |

Use Canvas for hundreds of primitives or frequent repaints / animation; use the default [SVG](/kernel/packages/render/svg) for a modest number of primitives, crisp vectors, per-element CSS, or native accessibility semantics. Both share Scene and handler-registry semantics, but check the Canvas capability limits above before switching.
