`@retikz/react` 是 React 应用的首选入口。你用 `<Layout>`、`<Node>`、`<Path>`、`<Scope>`、`<Draw>` 等 JSX 组件声明图形；包内 collector 把 props 与 children 收集为 `@retikz/vanilla` 的 `InputScene`，再由 `<Layout>` 宿主 processing 结果的 SVG 或 Canvas。

为组件封装 JSX 时，从 `@retikz/react` 导入对应的 Props。`CoordinateProps` 与 Vanilla 的 `CoordinateOptions` 相同；`NodeProps` 还接受水合事件和文字子节点。React 用 `<Path>` 组合 JSX 步骤，用 `<Draw way={…}>` 声明简写；两者都可搭配 `PathLabel`。自定义 Path 可由定义直接提供几何。Vanilla 的 `path` 仍接受 `way` 或步骤数组。

它负责 React 写法和结果宿主，不另造图形语义：IR、schema、几何与编译规则属于 `@retikz/core`；Input 归一、composite 依赖解析、Core Computation 与 session processing 状态属于 `@retikz/vanilla`。

包根提供组件、Props 和作者协议；组件名称读取与事件收集由 `Layout` 内部完成。`getDisplayName` 和 `collectHydrationHandlers` 是源码中的内部助手，不从包根导出。

## 安装与使用

`react` 与 `react-dom` 是 peer dependencies，版本不低于 18：

```bash
pnpm add @retikz/react react react-dom
```

```tsx
import { Draw, Layout, Node } from '@retikz/react';

export const Diagram = () => (
  <Layout>
    <Node id="source" position={[0, 0]}>
      Source
    </Node>
    <Node id="target" position={[160, 0]}>
      Target
    </Node>
    <Draw way={['source', 'target']} arrow="->" />
  </Layout>
);
```

`<Layout>` 默认输出 SVG；需要像素位图时传 `renderer="canvas"`。组件用法从[快速开始](/kernel/components/get-start)进入，完整宿主选项见 [Layout](/kernel/components/layout/usage)。

`<Layout theme>` 写入根 `IRScene.theme`，`<Scope theme>` 写入局部 `IRScope.theme`。Theme 是稀疏的 `name / mode` 覆盖；`themeDefinitions` 是 Layout 的 runtime-only compile 选项，用 `defineTheme` 注册自定义 Core theme。`ir` 与显式 `theme` 同时使用时，prop 逐字段覆盖 `ir.theme`，不会修改输入对象。完整示例见 [Layout 的可继承 Theme](/kernel/components/layout/extend#主题配置)。

## 为什么需要 @retikz/react

### 用 JSX 降低描述成本

`@retikz/core` 的 IR 可以直接构造，但图形通常包含嵌套、复用和组合关系。JSX 用组件树自然表达这些结构，让 `<Layout>`、`<Scope>`、`<Node>`、`<Path>` 等声明贴近图形层级，减少手工拼装作者输入的样板代码。

retikz 把 React 作为官方支持的一等框架：`@retikz/react` 的组件 API、文档、示例和适配行为会随 Kernel 一起维护。React 在这里是 authoring 与结果宿主层；最终数据契约和编译语义仍由框架无关的 `@retikz/core`，以及共享 processing 的 `@retikz/vanilla` 拥有。

### 为什么不提供其他官方框架包

这不是 Core 只能接入 React。任何框架只要把自己的组件或模板结构转换成相同的 `InputScene`，并把它交给 `@retikz/vanilla` processing，就能复用 retikz 的 Kernel 能力。

`@retikz/react` 同时是其他框架适配器的实现参考，展示组件树到 `InputScene`、宿主能力注入和 processing-result 接线的完整边界。官方把维护资源集中在 React，不负责开发、发布或维护 Vue、Svelte 等其他框架包；这些适配器可由社区沿用同一边界独立实现。

## 组件不会直接渲染 DOM

### 为什么采用标记组件

选择标记组件不是因为 React 不能绘图，而是为了让图形语义只有一个真源。如果 `<Node>`、`<Path>` 各自实现 DOM、浏览器布局和几何计算，React DSL 就会逐渐形成一套与 Core IR 平行的规则；同一张图在 React、Vanilla 或其它适配器中也可能得到不同结果。

因此 JSX 只负责组织声明，collector 把它收敛为框架无关的 `InputScene`。中间过程不创建额外 DOM，也不把 CSS layout 变成图形编译的隐式输入；共享 processing 再将 Input 归一为持久化、传输和其它框架适配可复用的 Core IR。

React 仍然在合适的边界发挥作用：它订阅 Vanilla processing 的只读结果，并把 commit、ref 与卸载生命周期接到稳定的 `<svg>` / `<canvas>` 宿主。场景会话归 Vanilla 管理；React 只把已完成的 Scene 映射为宿主。薄的是图形语义，不是宿主接线。

`<Node>`、`<Path>`、`<Scope>` 等 Kernel 组件是 **Input 标记**，不是 DOM 组件。它们自身返回 `null`，只用稳定的 `displayName` 告诉 React collector“这是什么图元”；因此 `<Node>` 不会先生成一个 `<div>`，也不会拥有另一套浏览器布局语义。

内置标记以及 Layout、Draw 的展示名称由包根导出的 `KernelDisplayName` 统一提供，取代原先的独立常量。例如，`KernelDisplayName.StepLabel` 的值为 `RetikzKernelStepLabel`。

```tsx
export const Node: FC<NodeProps> = () => null;
Node.displayName = KernelDisplayName.Node;
```

Draw 调用 Vanilla 的 `parseWay`，把解析好的步骤作为 Path 的子元素。下面两种写法等价：

```tsx
const shorthand = <Draw way={['A', 'B']} />;
const explicit = (
  <Path>
    <Step kind="move" to="A" />
    <Step kind="line" to="B" />
  </Path>
);
```

`readSceneChildren` 同步遍历 children：识别 Kernel 标记、展开 Fragment，并直接调用函数式 Sugar 后继续递归。这个过程不经过 React DOM renderer，所以 Kernel / Sugar 必须是无 hook、无副作用的函数组件；`convertReactToInputScene()` 产出唯一的 `InputScene`（嵌入项已绑定 adapter），再交给 Vanilla normalize。

检查一个 React 元素是否可嵌入时，把 `element.type` 传给 `isEmbeddableMarked`；需要适配器时使用 `resolveInputEmbedAdapter(element.type)`。元素可能不存在时，先判断元素是否存在。

### 更新边界

首次渲染通过 Vanilla 同步编译，服务端只输出带尺寸的宿主，不触发提交回调。客户端提交后，Layout 订阅一个 Vanilla 场景会话。新的 JSX 或 IR 交给同一会话完整替换；替换失败时继续显示最后一次成功结果。

等价的内联扩展数组（例如 `[shape]`）不会触发重新编译：Layout 比较定义的顺序和引用。更换编译参数会用新参数重新编译；更换协调器配置会建立新会话；卸载时释放会话。

### 执行模式与更新策略

`reconciler` 直接透传给 Vanilla。默认的 `full` 不保留增量缓存；`incremental` 保留缓存并支持协调器的批次更新策略。两种模式下，Layout 收到新的 JSX 或完整 IR 都调用 `replace` 完整编译，不会把 props 变化推断成增量批次。

```tsx
<Layout><Node /></Layout>
<Layout ir={sceneIR} reconciler={{ mode: 'incremental', updateStrategy: 'auto' }} />
<Layout ir={sceneIR} onDiagnostic={diagnostic => console.warn(diagnostic.message)} />
```

## 从 JSX 到 Scene

`<Layout>` 先调用 React collector 把 JSX 适配为 Vanilla Input；客户端提交后由 Vanilla 处理后续输入或编译选项变化。下图蓝色节点属于 `@retikz/react` 的 authoring / host，绿色节点是 `@retikz/vanilla` 的共享 processing，橙色节点是 `@retikz/core` 拥有的数据契约与编译器。

<ComponentPreview files="react-to-scene" size="xs" hideCode />

| 阶段                         | 所有者               | 做什么                                                             |
| ---------------------------- | -------------------- | ------------------------------------------------------------------ |
| Kernel / Sugar JSX           | `@retikz/react`      | 收集 props 与 children；Sugar 先展开为 Kernel                      |
| `convertReactToInputScene()` | `@retikz/react`      | 遍历组件树，生成 `InputScene`，嵌入项在构造时绑定 adapter          |
| `normalizeScene()`           | `@retikz/vanilla`    | 将 typed Input 归一为 `IRScene`，下沉 embeds 并汇总 composite 依赖 |
| `IRScene`                    | `@retikz/core`       | JSON 可序列化的绘图契约，不包含 React element、hook 或 DOM         |
| `SceneReconciler`            | `@retikz/core`       | 处理 composite，解析 registry、引用、几何、布局、资源与动画        |
| `CompileResult`              | `@retikz/reconciler` | 一次编译的 Scene 和 artifacts                                      |

`Layout` 会把文本测量器、Definition registries、TeX lowerer 等宿主能力作为 processing 的 compile options 注入，但这些选项不会把 React 写进 IR 或 Scene。直接传 `ir` prop 时会跳过 JSX collector。`artifacts` prop 请求 opt-in 产物，`onArtifacts` 在所选 host 发布后接收同次 compile 的 immutable artifacts；不会为通知再编译一次。

需要整帧结果时使用 `Layout.onCompileResult`；它在 React 提交后交付当前编译结果，不在服务端渲染期间调用。

## Scene 之后

Scene 已经没有 React 组件语义。Vanilla processing 负责发布当前 revision 的编译结果，`@retikz/react` 只订阅并把这个结果宿主到 React：

| 目标   | `@retikz/vanilla`                                          | `@retikz/react`                                                     |
| ------ | ---------------------------------------------------------- | ------------------------------------------------------------------- |
| SVG    | 原生 renderer 提交 SVG 子树、绑定事件与动画                | 持有根元素、设置显示尺寸并传入事件与动画配置                        |
| Canvas | 管理 processing controller、Core Computation 与 Scene 结果 | 提供 canvas 元素，由已有会话提交给与 Vanilla DOM 相同的 Render 后端 |

服务端渲染只输出带尺寸的空宿主；图形在客户端挂载后出现。需要静态 SVG 时，使用 Vanilla 的 `renderToSvg`。

事件函数不进入 IR。React 先收集 JSX 图元事件，再按图元 id 合并显式 `handlers`；同一事件依次调用两者。传入完整 IR 时只使用显式事件表。

## 职责边界

| 能力       | `@retikz/react` 负责什么                             | 能力真源                          |
| ---------- | ---------------------------------------------------- | --------------------------------- |
| JSX DSL    | Kernel 组件构造 Input；Sugar 同步展开为 Kernel       | `@retikz/vanilla` Input / Core IR |
| 编译宿主   | 收集 children / IR、注入选项并订阅 processing result | `@retikz/vanilla` processing      |
| 渲染与交互 | 选择 SVG / Canvas、收集事件并连接 React 宿主         | `@retikz/render` 输出能力         |

`@retikz/react` 不包含无框架 Input helper 或 DOM mount；在非 React、SSR 字符串或直接 DOM 挂载场景使用 [`@retikz/vanilla`](/kernel/packages/vanilla/overview)。
