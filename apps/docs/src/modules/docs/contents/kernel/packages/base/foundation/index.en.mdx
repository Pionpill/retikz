`@retikz/foundation` is a pure utility package that provides foundational capabilities for all packages, keeping shared types, scalar validation, blank-string semantics, and error shape in one place. Zod is its only production dependency.

## Install and use

<PackageManagerInstall packages="@retikz/react react react-dom" />

```ts
import {
  assertNonEmptyString,
  NonBlankStringSchema,
  NormalizedFractionSchema,
  PositiveNumberSchema,
  RetikzError,
} from '@retikz/foundation';
import type { AssertEqual, OpenString, RetikzErrorOptions, ValueOf } from '@retikz/foundation';
```

Developers usually do not need to use `@retikz/foundation` directly; it is a pure internal utility package created to share foundational capabilities across packages.

## Contents

### Type utilities

These utilities work only at compile time. They emit no runtime code and carry no IR or domain model.

| Export                            | Semantics                                                  |
| --------------------------------- | ---------------------------------------------------------- |
| `ValueOf<T>`                      | Derive the union of an object's values                     |
| `AssertEqual<TActual, TExpected>` | Return `true` only for bidirectionally assignable types    |
| `OpenString<T>`                   | Keep built-in literal hints while accepting custom strings |

### General contracts

The six schemas validate scalars without coercion, trimming, transforms, or defaults. Consumers still compose complete objects, arrays, domain ranges, and cross-field relations:

| Export                     | Accepted values                                                   |
| -------------------------- | ----------------------------------------------------------------- |
| `NonBlankStringSchema`     | At least one non-whitespace character; preserves successful input |
| `PositiveNumberSchema`     | Finite numbers greater than `0`                                   |
| `NonNegativeNumberSchema`  | Finite numbers greater than or equal to `0`                       |
| `PositiveIntegerSchema`    | Positive safe integers                                            |
| `NonNegativeIntegerSchema` | Non-negative safe integers                                        |
| `NormalizedFractionSchema` | Finite numbers in the inclusive `0..1` range                      |

```ts
NonBlankStringSchema.parse(' layer/main '); // returned unchanged
PositiveNumberSchema.parse(1.5);
NormalizedFractionSchema.parse(0.5);
```

### Assertion utilities

`assertNonEmptyString(value, label)` expects a value already narrowed to `string`. It rejects empty and runtime-standard whitespace-only strings, passes non-empty content unchanged, and returns `void`.

```ts
assertNonEmptyString('layer/main', 'owner');
// '', ' ', '\t', '\n', and Unicode whitespace throw:
// owner must be a non-empty string.
```

It is not an `unknown` type guard; use `NonBlankStringSchema` when a schema result is required. A consumer that needs a domain prefix, code, or class identity catches the ordinary `Error` and wraps it at its own boundary.

### Error handling

`RetikzErrorOptions`, `RetikzError`, and `isRetikzError` provide the smallest common shape for domain owners. Each owner still decides its code, details fields, and recovery semantics:

```ts
type Details = Readonly<{ source: string }>;

class DomainError extends RetikzError<'DOMAIN_FAILED', Details> {
  constructor(details: Details, cause?: unknown) {
    super({ code: 'DOMAIN_FAILED', message: 'Domain failed', details, cause });
  }
}
```

| Member            | Type                                       | Semantics                                                                                                                                                                |
| ----------------- | ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `code`            | `TCode`                                    | Structured-error classification code chosen by the owner                                                                                                                 |
| `message`         | `string`                                   | Error message presented to the caller                                                                                                                                    |
| `details`         | `TDetails`                                 | Structured details supplied by the owner; object identity is preserved and the value is not deep-copied or frozen automatically                                          |
| `cause`           | `unknown`, optional                        | Original exception or value that caused the error; omitting it still creates an own property whose value is `undefined`                                                  |
| `isRetikzError()` | `(value: unknown) => value is RetikzError` | Tests whether a value belongs to the ordinary `RetikzError` class hierarchy; it is not a hostile-object, cross-realm, or Core/Runtime private-identity security boundary |

## When to abstract

<ComponentAlert
  type="tip"
  title="Only retikz contributors need this"
  description="Most developers can skip this section and return when adding or changing Foundation capabilities."
/>

Any new Foundation capability must satisfy all four conditions:

1. It has no dependency on a Retikz domain, platform, or state; schemas may only use Foundation's accepted Zod dependency
2. It has independently nameable semantics, an invariant, or a failure boundary
3. At least two independent packages consume it with the same meaning, or it is part of Foundation's minimal error, type, or assertion protocol
4. It does not make an upper package obtain a capability through Foundation that belongs to Core, Math, Runtime, or a domain owner

Helpers, object or array schemas, geometry algorithms, Diagnostics, error catalogs, and domain resolvers that fail these conditions remain with their current owner. When repetition appears, reassess the semantic owner instead of collecting code in Foundation.

## API reference

| Category | Export                     | Type / use                                             |
| -------- | -------------------------- | ------------------------------------------------------ |
| type     | `ValueOf`                  | Object-value union                                     |
|          | `AssertEqual`              | Bidirectional equality                                 |
|          | `OpenString`               | Open string                                            |
| schema   | `NonBlankStringSchema`     | Non-blank string Zod schema that preserves input       |
|          | `PositiveNumberSchema`     | Positive finite-number Zod schema                      |
|          | `NonNegativeNumberSchema`  | Non-negative finite-number Zod schema                  |
|          | `PositiveIntegerSchema`    | Positive safe-integer Zod schema                       |
|          | `NonNegativeIntegerSchema` | Non-negative safe-integer Zod schema                   |
|          | `NormalizedFractionSchema` | Inclusive `0..1` Zod schema                            |
| assert   | `assertNonEmptyString`     | Typed string non-empty assertion                       |
| error    | `RetikzErrorOptions`       | Structured-error constructor options                   |
|          | `RetikzError`              | Extensible structured-error base class                 |
|          | `isRetikzError`            | Ordinary classifier for the Foundation class hierarchy |
