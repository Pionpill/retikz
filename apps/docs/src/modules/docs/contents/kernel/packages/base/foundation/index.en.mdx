`@retikz/foundation` is a pure utility package that provides foundational capabilities for all packages, keeping shared types, JSON and structurally readonly collection snapshots, scalar validation, blank-string semantics, and error shape in one place. Zod is its only production dependency.

## Contents

### Type utilities

These five utilities work only at compile time. They emit no runtime code and carry no IR or domain model.

| Export                            | Semantics                                                                  |
| --------------------------------- | -------------------------------------------------------------------------- |
| `ValueOf<T>`                      | Derive the union of an object's values                                     |
| `AssertEqual<TActual, TExpected>` | Return `true` only for bidirectionally assignable types                    |
| `OpenString<T>`                   | Keep built-in literal hints while accepting custom strings                 |
| `WithRequiredProperties<T, TKey>` | Make only selected keys required while preserving other and readonly props |
| `NonEmptyReadonlyArray<T>`        | Readonly array with at least one element                                   |

For example, `name` becomes required while `note` remains optional:

```ts
type Named = WithRequiredProperties<Readonly<{ name?: string; note?: string }>, 'name'>;
```

### Readonly collection snapshots

`createReadonlyMap(entries)` copies input entries into an independent shallow snapshot. The result preserves native Map lookup, iteration, and insertion order without exposing `set`, `delete`, or `clear`; entry values retain their original identity and are not deep-copied or frozen.

```ts
const definition = { kind: 'point' };
const source = new Map([['point', definition]]);
const definitions = createReadonlyMap(source);

source.clear();
definitions.has('point'); // true
```

### JSON data snapshots

`cloneAndFreezeJson(value, path)` validates JSON-safe plain data and returns a detached deeply frozen copy. Cycles, accessors, symbol keys, sparse arrays, extra array properties, non-finite numbers, and class instances throw `RetikzFoundationError`:

```ts
const snapshot = cloneAndFreezeJson({ filters: [{ field: 'age', value: 18 }] });

Object.isFrozen(snapshot); // true
Object.isFrozen(snapshot.filters); // true
```

`assertPlainDataContainers(value, path)` checks container structure without copying data or reading accessors. Owners use it before their schemas to reject class instances, promises, unsafe property descriptors, symbol keys, malformed arrays, and cycles; the owner schema still validates leaf values such as strings, numbers, and `undefined`:

```ts
assertPlainDataContainers({ tokens: { color: undefined } }, 'Theme provider output');
```

### General contracts

The six fixed schemas validate scalars without coercion, trimming, transforms, or defaults. Consumers still compose complete objects, arrays, domain ranges, and cross-field relations:

| Export                     | Accepted values                                                   |
| -------------------------- | ----------------------------------------------------------------- |
| `NonBlankStringSchema`     | At least one non-whitespace character; preserves successful input |
| `PositiveNumberSchema`     | Finite numbers greater than `0`                                   |
| `NonNegativeNumberSchema`  | Finite numbers greater than or equal to `0`                       |
| `PositiveIntegerSchema`    | Positive safe integers                                            |
| `NonNegativeIntegerSchema` | Non-negative safe integers                                        |
| `NormalizedFractionSchema` | Finite numbers in the inclusive `0..1` range                      |

```ts
NonBlankStringSchema.parse(' layer/main '); // returned unchanged
PositiveNumberSchema.parse(1.5);
NormalizedFractionSchema.parse(0.5);
```

`createOpenStringSchema(values)` accepts a const object enum while preserving both built-in literal suggestions and arbitrary non-blank custom strings. It does not query a registry or turn extension keys into a whitelist. Generated JSON Schema retains both the known enum branch and the open string branch:

```ts
const Role = { Participant: 'participant', Activity: 'activity' } as const;
const RoleSchema = createOpenStringSchema(Role);

RoleSchema.parse('participant');
RoleSchema.parse('custom.role');
```

### Static color atoms

`parseStaticCssColor(input)` parses a statically knowable CSS color into normalized sRGB channels `{ r, g, b, a }`; dynamic values such as `currentColor` and CSS variables return `null`. `compositeOpaqueColor(foreground, backdrop, weight)` precomposes a static foreground at a `0..1` weight over an opaque backdrop and returns lowercase `#rrggbb`:

```ts
parseStaticCssColor('darkorange');
compositeOpaqueColor('#336699', '#ffffff', 0.2); // '#d6e0eb'
```

Foundation owns only static parsing and pure color math; it knows nothing about Theme modes or drawing fields. Invalid colors, translucent backdrops, and out-of-range weights throw `RetikzFoundationError` with code `FOUNDATION_COLOR_ERROR`. Core decides when to call these atoms from the final style and Theme mode.

### Assertion utilities

`assertNonEmptyString(value, label)` and `assertPositiveNumber(value, label)` expect values already narrowed to `string` and `number`. The first rejects empty and runtime-standard whitespace-only strings; the second rejects `0`, negative, and non-finite numbers. Both return `void` on success.

```ts
assertNonEmptyString('layer/main', 'owner');
// '', ' ', '\t', '\n', and Unicode whitespace throw:
// owner must be a non-empty string.
assertPositiveNumber(1.5, 'SVG font size');
// 0, negative, Infinity, -Infinity, and NaN throw:
// SVG font size must be a positive finite number.
```

Failures directly throw `RetikzFoundationError`: the string assertion uses `FOUNDATION_NON_EMPTY_STRING_REQUIRED`, while the positive-number assertion uses `FOUNDATION_POSITIVE_NUMBER_REQUIRED`. Both retain the `label` and original `value` in `details`, and point `cause` to the rejected value. Neither assertion is an `unknown` type guard; use the corresponding schema when a schema result is required, and do not catch and redundantly wrap the same atomic failure as a domain error.

### Error handling

`RetikzErrorOptions`, `RetikzError`, and `isRetikzError` provide the smallest common shape for domain owners. `RetikzFoundationError` uniformly carries Foundation-owned atomic errors and distinguishes failures through constructor parameters; other owners still decide their codes, details fields, and recovery semantics:

```ts
import { RetikzError, type ValueOf } from '@retikz/foundation';

type Details = Readonly<{ source: string }>;

const RetikzDomainErrorCode = {
  Failed: 'DOMAIN_FAILED',
} as const;

type RetikzDomainErrorCodeValue = ValueOf<typeof RetikzDomainErrorCode>;

class RetikzDomainError extends RetikzError<RetikzDomainErrorCodeValue, Details> {
  constructor(details: Details, cause?: unknown) {
    super({ code: RetikzDomainErrorCode.Failed, message: 'Domain failed', details, cause });
  }
}
```

| Member            | Type                                       | Semantics                                                                                                                                                                |
| ----------------- | ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `code`            | `TCode`                                    | Structured-error classification code chosen by the owner                                                                                                                 |
| `message`         | `string`                                   | Error message presented to the caller                                                                                                                                    |
| `details`         | `TDetails`                                 | Structured details supplied by the owner; object identity is preserved and the value is not deep-copied or frozen automatically                                          |
| `cause`           | `unknown`, optional                        | Original exception or value that caused the error; omitting it still creates an own property whose value is `undefined`                                                  |
| `isRetikzError()` | `(value: unknown) => value is RetikzError` | Tests whether a value belongs to the ordinary `RetikzError` class hierarchy; it is not a hostile-object, cross-realm, or Core/Runtime private-identity security boundary |

## When to abstract

<ComponentAlert
  type="tip"
  title="Only retikz contributors need this"
  description="Most developers can skip this section and return when adding or changing Foundation capabilities."
/>

Any new Foundation capability must satisfy all four conditions:

1. It has no dependency on a Retikz domain, platform, or state; schemas may only use Foundation's accepted Zod dependency
2. It has independently nameable semantics, an invariant, or a failure boundary
3. At least two independent packages consume it with the same meaning, or it is part of Foundation's minimal error, type, or assertion protocol
4. It does not make an upper package obtain a capability through Foundation that belongs to Core, Math, Runtime, or a domain owner

`createOpenStringSchema(values)` is the only permitted parameterized schema factory and only combines a const object enum with Foundation's existing non-blank string boundary. Other helpers, object or array schemas, range factories, geometry algorithms, Diagnostics, error catalogs, and domain resolvers remain with their current owner. When repetition appears, reassess the semantic owner instead of collecting code in Foundation.
