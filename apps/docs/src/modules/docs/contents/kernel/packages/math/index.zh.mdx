`@retikz/math` 处理“怎么算”，不处理“怎么画”。当你需要移动一个点、求两条线的交点、计算凸包或把一组点转换成平滑曲线时，可以直接在普通 TypeScript 数据上完成计算，再把结果交给 `@retikz/core` 或上层组件。

> 如果目标是直接开始画图，请从 [组件](/kernel/components/layout) 开始；需要在绘制前组织几何数据时，再回到本节。

## 安装与使用

```bash
pnpm add @retikz/math
```

```ts
import { intersect, point, vector2 } from '@retikz/math';

const direction = vector2.fromAngleDegrees(-30);
const end = point.along([0, 0], direction, 120);
const hit = intersect.lineLine({
  a1: [0, 0],
  a2: end,
  b1: [20, -40],
  b2: [20, 40],
});
```

本包仅发布 ES modules，要求 Node.js 24 或更高版本。

## 为什么需要 @retikz/math

绘图中的很多步骤本质上只是确定性的数值计算。把它们从 IR、schema、React 和 renderer 中拆出来，可以让同一套几何语义被 core、领域包、服务端脚本和测试复用，也能在没有 DOM 或 Canvas 的环境中独立运行。

它有三个明确边界：

- 输入和输出是数字、tuple 与普通对象，不产生 IR 或 Scene
- API 以纯函数为主，不修改传入的点集，也不持有渲染状态
- 零运行时依赖，不负责组件组合、编译、测量或 SVG / Canvas 输出

## 与 @retikz/core 的关系

`@retikz/math` 与 `@retikz/core` 有两层关系。用户代码可以先用 math 把原始数值整理成普通几何结果，再交给 core；同时 core 编译器本身也直接调用 math 完成位置解析、路径端点与 bounds 等计算。math 不产生 IR 或 Scene，组件组合与 Scene 编译仍由 core 负责。

<ComponentPreview files="math-pipeline" size="xs" hideCode />

core 为绘图高频能力便捷转出 `DEFAULT_EPSILON`、`point`、`vector2`、`localToWorld` 和 `worldToLocal`，并把 math 的 `lerp` 以 `lerpPoint` 暴露。`Position` / `Vector2` 类型、外接范围、椭圆、圆弧与高阶算法仍应直接从 `@retikz/math` 导入。
