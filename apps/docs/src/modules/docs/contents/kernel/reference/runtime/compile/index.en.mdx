title: Compile
description: The IR-to-Scene compile entry point, layout options, text measuring, and warning contract

The `@retikz/core` compile layer turns JSON-serializable IR into a `Scene` and typed artifacts produced by the same canonical compile. React and Vanilla adapters, server-side export flows, and custom renderers share the same compile semantics at this boundary.

## Functions

| API                               | Signature                                                                                               | Purpose                                                                                      |
| --------------------------------- | ------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| `compileToScene`                  | `(ir: IRScene, options?: CompileOptions) => CompileResult`                                              | Main entry; returns `scene` and immutable `artifacts` together                               |
| `observeCompileToScene`           | `(ir, options, observers) => ObservedCompileResult`                                                     | Creates explicit observation sessions and returns primary plus definition-ordered outputs    |
| `lowerIRToKernel`                 | `(ir: IRScene, options?: LowerIRToKernelOptions) => LoweredIRScene`                                     | Recursively expands composites and returns Kernel IR with no Tier 2 nodes                    |
| `resolveCoreProviderDependencies` | `(options: ResolveCoreProviderDependenciesOptions) => CoreProviderDefinitions`                          | Resolves a rooted provider graph into Core-capability-grouped compile options                |
| `selectSpatialHandles`            | `(index: SpatialHandleIndex, selector: SpatialHandleSelector) => ReadonlyArray<QualifiedSpatialHandle>` | Precisely filters zero or more qualified spatial handles                                     |
| `resolveSpatialHandle`            | `(index: SpatialHandleIndex, selector: SpatialHandleSelector) => QualifiedSpatialHandle`                | Requires exactly one match and throws on a miss or ambiguity                                 |
| `computeLayout`                   | `(points, padding, round) => Layout`                                                                    | Computes the scene bounds from bbox candidate points; usually called inside `compileToScene` |
| `resolveBoxSpacing`               | `(value, fallback) => BoundsInsets`                                                                     | Normalizes a uniform or side-specific value into complete four-side spacing                  |
| `fallbackMeasurer`                | `(text, font) => TextMetrics`                                                                           | Default text measurer; approximate but runnable, useful as a no-DOM fallback                 |
| `formatCompileWarning`            | `(warning: CompileWarning) => string`                                                                   | Formats a structured warning into the standard readable message                              |
| `formatCompileOccurrence`         | `(locator: CompileOccurrenceLocator) => string`                                                         | Formats an artifact occurrence locator                                                       |
| `isNodeLayoutCompileArtifact`     | `(artifact: CompileArtifact) => artifact is NodeLayoutCompileArtifact`                                  | Narrows an opt-in Node-layout artifact                                                       |

`compileToScene` traverses and registers nodes and coordinates in the current scope before filling deferred path slots. A path can therefore reference a target declared later in that scope. Output is then stably sorted by ascending `zIndex`; only primitives with the same `zIndex` retain declaration order.

`lowerIRToKernel` performs no layout or Scene emission; it only consumes `composites` and `maxCompositeDepth`. An unregistered composite throws. A layout-aware composite with a `compile` branch also throws explicitly because standalone lowering has no text measurement, providers, reference environment, or parent constraint. A non-empty `spatialHandles` result also fails synchronously and directs the caller to `compileToScene()` for settled world geometry; absent or empty declarations remain valid. Full `compileToScene` emits `COMPOSITE_NOT_REGISTERED` and skips an unregistered node. Both paths throw on a nesting limit or cycle.

### Box Spacing Normalization

`resolveBoxSpacing(value, fallback)` accepts a non-negative number, an `IRBoxSpacing` object, or `undefined`, and returns `BoundsInsets` in `{ top, right, bottom, left }` form. A number applies to every side; each object side selects the first available value in `side > axis > default > fallback` order.

Callers validate `value` with their owning schema first. `fallback` must be finite and non-negative and is checked even when `value` already supplies every side; an invalid fallback throws. Every call returns a detached object.

## CompileOptions

`CompileOptions` stays a flat object at the call site; the tables below group fields by responsibility.

### Host Services

| Option        | Type                | Default                                     | Notes                                                    |
| ------------- | ------------------- | ------------------------------------------- | -------------------------------------------------------- |
| `measureText` | `TextMeasurer`      | `fallbackMeasurer`                          | Injects text measurement; React can use browser APIs     |
| `lowerTex`    | `LowerTex`          | `undefined`                                 | Injects TeX rendering; missing or failed rendering warns |
| `onWarn`      | `(warning) => void` | dev: `console.warn`<br />production: silent | Collects recoverable compile-time warnings               |

### Layout And Output

| Option          | Type                     | Default | Notes                                                                                                                                         |
| --------------- | ------------------------ | ------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `padding`       | `number`                 | `10`    | Extra layout padding in user units                                                                                                            |
| `precision`     | `number`                 | `2`     | Decimal precision for Scene coordinates, structured path commands, and layout values; internal geometry is double precision                   |
| `nodeDistance`  | `number`                 | `24`    | Default distance for `AtPosition` when `distance` is omitted                                                                                  |
| `labelDistance` | `number`                 | `12`    | Default net gap from the node boundary to the rotated label visual box when `Node.label.distance` is omitted; must be finite and non-negative |
| `fontSize`      | `number`                 | `16`    | Default font size; also the root size for presets and `rem`; explicit numeric font sizes are unchanged                                        |
| `artifacts`     | `CompileArtifactOptions` | `{}`    | Opt-in generic outputs; `{ nodeLayouts: true }` includes real Node `CompiledNodeLayout` snapshots                                             |

### Provider Registries

| Option           | Type                                     | Default        | Notes                                                                                                                                                                     |
| ---------------- | ---------------------------------------- | -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `shapes`         | `ReadonlyArray<ShapeDefinition>`         | Core basic set | Inject custom or optional Standard node shapes. See [Shape Extensions](/library/standard/extension/shape)                                                                 |
| `boundaries`     | `ReadonlyArray<BoundaryDefinition>`      | built-in set   | Append custom connection surfaces. See [Custom Boundaries](/kernel/components/node/custom-boundary)                                                                       |
| `clips`          | `ReadonlyArray<ClipDefinition>`          | Core basic set | Inject custom or Standard compound clips. See [Clip Extensions](/library/standard/extension/clip)                                                                         |
| `arrows`         | `ReadonlyArray<ArrowDefinition>`         | Core basic set | Inject custom or optional Standard arrows. See [Arrow Extensions](/library/standard/extension/arrow)                                                                      |
| `patterns`       | `ReadonlyArray<PatternDefinition>`       | built-in set   | Append custom fill pattern motifs. See [Custom Patterns](/kernel/components/effects/custom-pattern)                                                                       |
| `pathGenerators` | `ReadonlyArray<PathGeneratorDefinition>` | none           | Inject custom path generators; Core has no default entry. See [Path Generators](/kernel/components/draw/path-generator)                                                   |
| `pathKinds`      | `ReadonlyArray<PathKindDefinition>`      | built-in set   | Append custom or optional Standard path kind providers. See [Custom Paths](/kernel/components/draw/custom-path) and [Standard Ribbon](/library/standard/extension/ribbon) |

Definitions passed here merge with the matching Core basic collection. An empty key or a name that duplicates an item registered for the invocation throws immediately; providers are never overwritten. Optional Standard content follows this same merge and diagnostic path.

### Theme token owner registry

| Option        | Type                                  | Default         | Notes                                                                           |
| ------------- | ------------------------------------- | --------------- | ------------------------------------------------------------------------------- |
| `themeStyles` | `ReadonlyArray<ThemeStyleDefinition>` | built-in styles | Appends runtime Core style resolvers; conflicting style names throw immediately |

Each Definition binds a style name to a function that resolves `mode`. While resolving Scene / Scope Themes, Core inherits `style` / `mode` and generates shared colors with that resolver; an unregistered style or different Definition claiming the same name fails loudly. Functions exist only in runtime options and never enter IR.

### Composites

| Option              | Type                                    | Default | Notes                                                                                                      |
| ------------------- | --------------------------------------- | ------- | ---------------------------------------------------------------------------------------------------------- |
| `composites`        | `ReadonlyArray<AnyCompositeDefinition>` | `—`     | Inject Tier 2 `expand` or layout-aware `compile` definitions; unregistered composites warn and are skipped |
| `maxCompositeDepth` | `number`                                | `32`    | Maximum nested composite depth; exceeding it or a cycle throws                                             |

The two `CompositeDefinition` branches are mutually exclusive:

- `expand(node, context)` performs structural expansion in the current Theme context;
- `compile(node, context)` evaluates real child content through `context.proposal` and `layoutChild(child, proposal)` in the complete compile environment.

`expand` accepts only `{ children, spatialHandles? }`, not a bare child or child-array shorthand. A layout-aware `compile` result may provide the same `spatialHandles` declaration array; both branches share callback-bound validation.

Both branches read the complete, frozen `ResolvedTheme` at their position from `context.theme`. Resolution is fixed as the default light baseline → Scene → outer Scope → inner Scope, with each layer overriding only explicit `style`, `mode`, or namespace/token keys. `ResolvedTheme` also carries recursively frozen `tokens` and a detached/frozen shared `colors` view; `colors.semantic` always exposes error/success/warning, while `colors.categorical` is non-empty, may repeat values, and is consumed with a stable modulo index. `lowerIRToKernel()` uses the same resolver for `expand`, while a layout-aware definition still fails before its callback. Theme only lets a composite materialize domain-owned defaults; the final Scene and renderers neither carry nor interpret it.

A layout-aware definition with `artifactSchema` may return a JSON-safe `artifact` from the same `compile` call. The schema governs both public `CompileResult.artifacts` and final Composite owner outputs consumed by explicit observers; the Composite itself contains no Inspector definition.

### Provider graph assembly

The provider graph is a pure pre-compile assembly protocol, not a second registry. React, Vanilla, and reusable domain toolchains collect `CoreProviderContribution` values, call `resolveCoreProviderDependencies()` for capability-grouped `CoreProviderDefinitions`, then pass each collection to the matching `CompileOptions` field.

| Public contract                          | Key fields / result                                                         | Responsibility                                                     |
| ---------------------------------------- | --------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| `CoreProviderKey`                        | Regular: `capability`, `name`; composite: `capability`, `namespace`, `type` | Unambiguously identifies one Core provider                         |
| `CoreDependencyProvider`                 | `key`, `dependencies`, `datasets`, `makeDefinition`                         | Declares one Definition, direct dependencies, and runtime data     |
| `CoreProviderContribution`               | `roots`, `providers`                                                        | Declares roots required by an authored node and imported providers |
| `ResolveCoreProviderDependenciesOptions` | `contributions`, `definitions?`                                             | Merges provider results with final explicit Definitions            |

The resolver completes full preflight before running a maker. Repeated provider keys require the same maker reference and ordered dependencies. A repeated dataset reference under one provider key deduplicates only when its value is identical by `Object.is`. Missing providers and cycles report the complete chain. Output materializes in dependency-first, first-reachable order, then groups under matching compile options such as `shapes`, `arrows`, `clips`, `pathKinds`, `pathGenerators`, and `composites`; each maker runs once.

`options.composites` is the final explicit-Definition channel, not a private sidecar for nested adapters. Provider results come first; explicit Definitions append in authored order. The same object at the same key deduplicates, while a different object fails immediately. Authors calling `compileToScene()` with a complete Definition array may skip the provider graph and continue passing `CompileOptions.composites` directly.

`LayoutProposal` contains exactly `x` and `y`; each axis is a `LayoutAxisProposal`:

| `kind`      | Fields                         | Slot invariant                                                 |
| ----------- | ------------------------------ | -------------------------------------------------------------- |
| `intrinsic` | `mode: 'minimum' \| 'natural'` | The contribution resolved in the complete two-axis context     |
| `range`     | `min` / `max?`                 | In `[min, max]` when bounded, or at least `min` when unbounded |
| `exact`     | `value`                        | Exactly this finite non-negative value                         |

`NaturalLayoutProposal` is the deeply frozen natural / natural constant and the default proposal for root layout-aware composites. Proposals are strictly validated, detached, cloned, and frozen before child dispatch. Missing axes, extra fields, negatives, NaN, Infinity, and invalid ranges produce occurrence-aware contract errors. Explicit zero is valid and `-0` canonicalizes to `0`.

`layoutChild()` returns a `LayoutChildProbe`, narrowed by `LayoutChildProbeKind.Resolved` / `Failed`:

| Outcome    | Field     | Meaning                                                                                               |
| ---------- | --------- | ----------------------------------------------------------------------------------------------------- |
| `resolved` | `result`  | `LayoutChildResult`: resolved slot, real bounds, guides, and a replay transaction                     |
| `failed`   | `failure` | Callback-local, compile-local opaque `LayoutChildFailure`; discard it or pass it to `context.raise()` |

The fields of `LayoutChildResult` are independent:

| Field              | Meaning                                                                                      |
| ------------------ | -------------------------------------------------------------------------------------------- |
| `slotSize`         | Proposal-resolved `width` / `height`, with no origin or alignment semantics                  |
| `allocationBounds` | Real child-local layout occupancy, which may be larger or smaller than the slot              |
| `visualBounds`     | Conservative final static primitive-tree ink envelope; not used to resolve slots             |
| `alignmentGuides?` | One-dimensional child-local guides; `LayoutAlignmentGuideName` defines first / last baseline |
| `replay`           | One-use opaque token for the isolated transaction                                            |

Plain text computes contextual x minimum / natural contributions and reflows under finite x range / exact proposals. Mixed / TeX authored lines and fixed geometry remain atomic and keep real allocation unscaled. Y minimum / natural is the actual height after applying the complete x proposal. Built-ins reuse Core measurers, providers, and geometry without reading back from DOM or renderers.

A layout-aware `compile` result may declare container `allocationBounds` and `alignmentGuides` already expressed in composite-local allocation coordinates. Core unions final-child allocation when omitted, but does not choose or merge several child guides on behalf of the solver.

The parent solver selects a successful transaction with `context.replay(result, wrapper?)`. `wrapper.transforms` first places the child in parent allocation coordinates; `wrapper.clip` then clips in that parent coordinate system. It only tightens final Scene visual contribution without changing allocation or rewriting an existing `LayoutChildResult.visualBounds`. Final emission reuses the saved layout without expanding, measuring, or laying it out again.

`context.scope(props, children)` recursively wraps ordinary `IRChild` values, replay children, and other runtime Scope children. It exposes exactly the nine structural fields whose semantics remain deterministic after replay:

| Field            | Purpose                                                               |
| ---------------- | --------------------------------------------------------------------- |
| `theme`          | Establish a sparse Theme override for ordinary descendant IR children |
| `id`             | Register Scope identity in the parent namespace                       |
| `localNamespace` | Isolate names inside the Scope subtree                                |
| `transforms`     | Apply lowered numeric Scene transforms                                |
| `clip`           | Clip in the Scope's local coordinate system                           |
| `zIndex`         | Sort the Scope as one sibling unit                                    |
| `boundingShape`  | Describe the envelope of an identified Scope                          |
| `meta`           | Pass JSON metadata to the Scene group                                 |
| `animations`     | Pass Group animation tracks                                           |

`context.replay()` and `context.scope()` return runtime-only opaque handles that never enter IR, Scene, or renderer contracts. Failures, layout results, handles, and replays are checked by callback-local / compile-local identity. They cannot cross compiles or callbacks, be serialized, be forged through spreading, or be reused. The complete runtime output tree formed by replay and runtime Scope handles is preflighted before any sink write; ordinary `IRChild` values then continue through the existing compile dispatch. Wrappers and Scope props are detached, validated, and frozen when built.

Every probe keeps primitives, resources, warnings, artifacts, namespaces, identities, and observations in its isolated transaction. Discarded resolved / failed outcomes have zero observable effect on the final `CompileResult`. `context.raise(failure)` accepts only a failure created by the current callback and throws while preserving the original cause, provider, source path, and nested occurrence.

An occurrence's `probe[index]` segment records candidate `layoutChild()` dispatch. A successful selected transaction remaps that candidate origin to the existing `replay[index]` output commit, while `output` / `scopeChild` continue to describe the compile output tree. Resources, namespaces, warnings, bounds, and artifacts publish atomically only with the selected replay.

A layout-aware definition with `artifactSchema` may return a JSON-safe `artifact` from the same `compile` call. `compileToScene` wraps it as `{ kind:'composite', namespace, type, occurrence, value }`. The occurrence uses an original `sourcePath` plus a structured `expansionPath`; it does not depend on a global Map or captured callback. A precise definition tuple lets `CompileResult` infer the corresponding artifact union.

## Explicit Compile Observation

`observeCompileToScene()` reuses the same full compile pipeline but creates an exclusive session for every `CompileObserverDefinition`. Ordinary `compileToScene()` creates no session and captures no extra owner output.

| Phase    | Callback                        | Role                                                                                                        |
| -------- | ------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| Select   | `select(site)`                  | Decide before owner compilation whether to request output, using `owner` and authored `sourcePath`          |
| Observe  | `observe(observation, context)` | Consume a final occurrence, validated output, owner-local-to-primary transform, and probe/replay provenance |
| Complete | `complete()`                    | Return a domain-defined result after all events; Core recursively freezes it                                |

A Composite reuses its `artifactSchema` and `artifact` compile result. A Path kind explicitly declares `ownerOutput: { schema }` and calls `publish(value)` only when `context.ownerOutput.requested` is true. A selected owner that omits output, publishes twice, or fails schema validation throws. Failed and discarded probes never trigger `observe()`, and final events are stably ordered by occurrence and owner.

`context.compileFragment(children)` compiles ordinary Core children in the current occurrence's Theme, Scope style, and provider environment. The fragment returns an isolated `scene`, artifacts, and diagnostics without writing into the primary result. Public identity references into the primary figure or another fragment fail. Core does not prescribe the shape returned by `complete()`, so statistics, analysis, and [`@retikz/inspect`](/kernel/packages/extension/inspect) can all reuse this capability.

## Text Measuring

`TextMeasurer` is the only compile-layer hook that needs help from the host environment:

```ts
type TextMeasurer = (text: string, font: FontSpec) => TextMetrics;
```

| Type          | Fields                                      | Notes                                                 |
| ------------- | ------------------------------------------- | ----------------------------------------------------- |
| `FontSpec`    | `family?` / `size` / `weight?` / `style?`   | Font input passed to the measurer; `size` is required |
| `TextMetrics` | `width` / `height` / `ascent?` / `descent?` | Text box metrics; ascent / descent are optional       |

When `measureText` is omitted, `fallbackMeasurer` estimates width as `text.length * size * 0.55` and height as `size * 1.2`. It keeps compilation runnable, but it is not meant for precise typography.

Node labels normalize the `width` / `height` / `ascent` / `descent` produced during one measurement phase into one visual box. When both baseline metrics are absent, `height` is split evenly. When only one is present, `height` supplies the remainder. When both are present, spare leading is split evenly if their sum is smaller than `height`; otherwise the visual box expands to their sum. The same box drives the baseline, rotated spacing, pin endpoint, and automatic viewBox, with no remeasurement after the node rectangle is known. Any non-finite or negative Node-label metric throws directly; an invalid TeX box keeps the existing `TEX_INVALID` warning degradation.

## Warnings

`CompileWarning` is a synchronous, machine-readable warning:

| Field     | Type                   | Notes                                                   |
| --------- | ---------------------- | ------------------------------------------------------- |
| `code`    | string                 | Warning code                                            |
| `message` | string                 | Human-readable English message                          |
| `path`    | string                 | IR locator, such as `children[3].path.children[1].to`   |
| `origin`  | `CompileWarningOrigin` | Primary or owner / isolated-fragment observation origin |

Current built-in codes (the machine-readable `CompileWarningCode` constant is publicly exported, so you can reference these as enum members instead of hardcoding strings):

| Code                            | Meaning                                                                                                                             |
| ------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `UNRESOLVED_NODE_REFERENCE`     | A path or position references a missing node / coordinate                                                                           |
| `PATH_TOO_SHORT`                | A path has fewer than 2 steps / lacks a previous endpoint, so it cannot form a valid drawn segment; the whole path is skipped       |
| `OFFSET_BASE_UNRESOLVED`        | `OffsetPosition`'s base `of` cannot be resolved                                                                                     |
| `POLAR_ORIGIN_UNRESOLVED`       | `PolarPosition.origin` cannot be resolved                                                                                           |
| `AT_TARGET_UNRESOLVED`          | `AtPosition.of` cannot be resolved                                                                                                  |
| `DUPLICATE_NODE_ID`             | A duplicate id within the same namespace frame; the later definition overrides the earlier (last-wins)                              |
| `COMPOSITE_NOT_REGISTERED`      | A composite node's `namespace.type` is not registered; the node is skipped                                                          |
| `ANIMATION_INVALID_PROPERTY`    | An animation track has an invalid property (e.g. a non-viewBox property at scene root); the track is dropped                        |
| `ARC_MISSING_RADIUS`            | An arc step lacks `radius`; the whole path is skipped. `radius` may be a number for circular arcs or `{ x, y }` for elliptical arcs |
| `PARTIAL_ARC_NEEDS_BOTH_ANGLES` | `circlePath` / `ellipsePath` partial arcs need both `startAngle` and `endAngle`, otherwise treated as a full circle / ellipse       |
| `PARTIAL_ARC_CLOSED_INVALID`    | A partial circle / ellipse (with angles) cannot use `closed:'closed'`; falls back to `'chord'`                                      |
| `TEX_LOWERER_MISSING`           | An explicit math run has no injected `lowerTex`; that formula segment is skipped                                                    |
| `TEX_INVALID`                   | `lowerTex` cannot produce valid formula primitives; that formula segment is skipped                                                 |
| `TEX_TEXT_CONFLICT`             | Reserved diagnostic for a text / TeX payload conflict; the current compile path does not emit it                                    |
| `TEXT_TEX_PARSE_ERROR`          | With TeX enabled, a string has an unbalanced `$` / `$$`; the trailing fragment stays literal                                        |
| `BOUNDARY_TIGHT_FALLBACK`       | A shape lacks the requested tight / ink connection envelope; compile falls back to visual bounds                                    |
| `TEXT_AUTO_CONTRAST_UNRESOLVED` | A Node auto-contrast keyword has no static opaque fill; fixed `currentColor` is used and compilation continues                      |

Most warnings do not stop compilation. But when a coordinate's / node's own position cannot be resolved, compile **throws directly without emitting a warning** (deliberately: warning then throwing would leave the collector with a dead warning for a Scene that never gets produced), because it is a "position-defining" entity that breaks the contract for later references.

Every public warning has an `origin`. Ordinary compilation uses `{ kind: 'primary' }`. Warnings from an observed owner or isolated fragment use `{ kind: 'observation', owner, occurrence, stage }`. A fragment that reaches into the primary figure's or another fragment's public identity is promoted to a fatal error so a partially misleading result cannot publish.

For an auto-contrast warning, `path` is the current Node locator and `message` includes the unresolved fill, reason, and fixed fallback. A Node emits at most one warning even when many body runs, formulas, labels, or pins consume its color. No resolution or warning occurs when no consumer inherits the Node text color.

## Output

`compileToScene` returns a `CompileResult`:

| Field            | Type                             | Notes                                                                                           |
| ---------------- | -------------------------------- | ----------------------------------------------------------------------------------------------- |
| `scene`          | `Scene`                          | The laid-out scene consumed by renderers                                                        |
| `artifacts`      | `ReadonlyArray<CompileArtifact>` | Immutable typed artifacts from the same canonical compile as `scene`                            |
| `spatialHandles` | `SpatialHandleIndex`             | Same-revision qualified world-space index; frozen with empty `entries` when nothing is declared |

`observeCompileToScene()` returns `{ primary, observerOutputs }`. `primary` is equivalent to ordinary `compileToScene()` for the same IR and options. `observerOutputs` follows the input definition order, and each item carries the stable `key` plus that session's completed value.

Its `scene` contains:

| Field         | Type                      | Notes                                                                                                                                                   |
| ------------- | ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `primitives`  | `Array<ScenePrimitive>`   | Laid-out primitives, in render order                                                                                                                    |
| `layout`      | `Layout`                  | Scene bounds `{ x, y, width, height }`                                                                                                                  |
| `resources?`  | `Array<SceneResource>`    | Renderer-agnostic resource table (gradient / pattern / clip paint servers); the adapter materializes them (SVG → `<defs>`). Omitted when there are none |
| `animations?` | `Array<IRAnimationTrack>` | Scene-root (camera) timeline tracks (viewBox property), passed through from the IR root `animations`; omitted when there are none                       |

A custom renderer must consume `resources` and `animations`, otherwise gradients / clipping / camera animations are lost. If there are no bbox candidate points, `computeLayout` returns a `100×100` fallback layout.

### Spatial handle sidecar

Each `QualifiedSpatialHandle` contains the declaring owner's `key` / `role`, a world-space rectangular AABB, stable authored-order tags, optional JSON payload, `originOccurrence` / `finalOccurrence`, and an outer-to-inner `ownerPath`. An explicit composite `id` becomes `instanceId`; an anonymous owner is distinguished only by its current compile occurrence and receives no generated counter id.

Every selector field is exact. `owner` matches only the declaring owner. `within` matches an ordered continuous subpath of its ancestors. `tags` requires every requested tag. Because `key` is unique only within one owner occurrence, a cross-owner query should add `within`, `owner.instanceId`, or an occurrence.

The spatial index is a tooling sidecar, not part of Scene. SVG, Canvas, and SSR renderers receive only `scene`; they never read, copy, or transform `spatialHandles`. React `<Layout onCompileResult>` publishes the complete `CompileResult` after a successful static or retained commit. Vanilla exposes the current result through authored-input `SceneResult.compileResult` and live-view `compileResult`; passing a precompiled Scene produces `undefined`. A failed revision keeps the previous committed result, and a throwing user callback does not roll back a successful commit.
