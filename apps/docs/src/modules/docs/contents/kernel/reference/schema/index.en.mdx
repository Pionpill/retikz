This group is the data contract of the IR (intermediate representation): the JSON structure a retikz figure ultimately serializes to. AI generation, database storage, and custom converters all build on it. These pages cover independently useful public contracts; nested helper schemas stay with their owning topic instead of mirroring the source tree page by page.

> This is the reference layer, not component docs; to author figures, start from [Components](/kernel/components/layout).

## What each part covers

| Topic     | Responsibility                                        | Reach for it when                        |
| --------- | ----------------------------------------------------- | ---------------------------------------- |
| Scene     | IR root, view box, and top-level child union          | Generating or validating a whole drawing |
| Scope     | Subtree grouping, defaults, transforms, and clipping  | Building nested or local contexts        |
| Entity    | Node, Coordinate, text, shape, and boundary contracts | Generating nodes, coordinates, or text   |
| Path      | Path, steps, targets, ribbons, and arrows             | Generating paths and geometric relations |
| Placement | Position and target placement forms                   | Resolving or generating references       |
| Paint     | Shared visual fields, paints, patterns, and shadows   | Generating fill / stroke appearance      |
| Animation | JSON-safe keyframes, timing, triggers, and origins    | Generating declarative animation tracks  |
