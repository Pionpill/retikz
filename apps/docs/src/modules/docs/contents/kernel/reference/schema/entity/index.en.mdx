`entity` covers IR primitives that **have an id**, are **placed at a position**, and **don't draw paths themselves**. Both register into the same node index, so a Node id and a Coordinate id share the same namespace.

## Node

`NodeSchema` describes one positioned visual primitive. It's the heaviest IR entity — 30+ fields covering shape, fill / stroke style, padding, text content, font, scaling, and attached labels.

<Comparison target="tikz" title="Node field mapping">

`strokeOpacity` is stroke-only opacity; `dashed` / `dotted` map to TikZ's dashed / dotted presets; the `{ text, position }` form of `label` maps to `[label=top:foo]` / `[label=30:foo]`. `placement: 'inside'` is retikz's structured extension for labels placed inside a node.

## Node text color keyword

`NodeSchema.textColor` remains a regular string contract. `NodeTextColor.Contrast` is a reserved Node-host keyword that also works in the schema-derived `Scope.nodeDefault.textColor`; it selects pure black or white from the final static opaque fill.

Core parses only deterministic named, hex, `rgb()`, and `hsl()` colors; it never reads DOM or renderer state. Translucent / missing fills, gradients, patterns, images, and dynamic CSS colors use the fixed `currentColor` fallback and emit `TEXT_AUTO_CONTRAST_UNRESOLVED`.

## ShapeRef

`ShapeRefSchema` is the object form for parameterized shapes. Parameterless shapes can stay as strings; the object form sends a provider name and JSON parameters to the selected shape Definition.

## Boundary

`BoundarySchema` selects the connection surface used by path endpoints and directional anchors. The string `shape` uses the visual shape itself; another string or `ShapeRef` selects a built-in / registered boundary provider.

## Coordinate

`CoordinateSchema` requires an `id` (its whole purpose), never contributes to layout, and shares the node index with `Node`.

<Comparison target="tikz" title="Coordinate Mapping">

## NodeLabel

`NodeLabelSchema` describes extra text attached to a node. `Node.label` accepts either one object or an array.

<ZodSchema
  name="NodeLabelSchema"
  descriptions={{
    text: 'Label text content, rendered as one line',
    position:
      'Label position relative to the node border: 8-direction enum, center, numeric angle, or `{ boundary, fraction }` on a rectangle boundary; defaults to top; center draws at the node center',
    placement: 'Offset direction from the attachment point: outside (default) or inside; inside labels cannot use pin',
    distance:
      'Net gap from the node boundary to the rotated label visual box, in user units; defaults to 12; must be finite and non-negative; center ignores it',
    textColor: 'Label text color; defaults to currentColor',
    opacity: 'Label opacity 0..1; multiplied with the node opacity',
    font: 'Label font override; omitted fields inherit from the parent node font, then renderer defaults',
    rotate:
      "Rotates label text around its own center: none (default), radial along the position direction (the selected side's outward normal for a boundary fraction), tangent to it, or an explicit degree value; inside reverses only the label offset, not its orientation; rotation changes the visual-box projection, so the compiler adjusts the center to preserve the distance gap",
    keepUpright:
      'When true, flips rotated text by 180 degrees if it would otherwise read upside down; defaults to false',
    pin: 'Draws a leader from the node border to the rotated label visual box: true = default thin line; object = styled leader with stroke / strokeWidth / dashPattern / dashOffset; omitted / false = none. Only supported for outside labels',
  }}
/>

`position: { boundary, fraction }` currently targets box-like node boundaries: `boundary` is `'top'` / `'right'` / `'bottom'` / `'left'`, and `fraction` is the 0..1 proportional position on that side, defaulting to `0.5`. For non-`center` labels, the center offset is `distance + rotated visual-box projection radius` along the placement direction. A pin ends at the exact intersection of the same ray and rotated visual box.

## TextBlock

`TextBlockSchema` is the node text block shape: a single string for one line, or a non-empty array for multiple lines. Each `LineSpec` may be a plain string, a per-line style object, or a `{ runs }` mixed text / math line.

## Font

`FontSchema` is shared by node text, node labels, and per-line text overrides. All fields are optional, while family, size, weight, and style reuse Core's named value schemas. `size` accepts a positive number, a Web preset such as `sm` / `lg`, or an `em` / `rem` string; omitted sizes use `CompileOptions.fontSize`. TikZ-style sizes are handled by higher-level sugar, not core IR.
