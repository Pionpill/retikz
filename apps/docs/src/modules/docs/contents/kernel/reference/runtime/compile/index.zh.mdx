---
title: 编译
description: IR 到 Scene 的编译入口、布局选项、文字度量与 warning 合同
---

`@retikz/core` 的 compile 层把 JSON 化的 IR 转成同次产出的 `Scene` 与 typed artifacts。React / Vanilla adapter、服务端导出流程和自定义 renderer 都在这条边界上共享同一份编译语义。

## 函数

| API                               | Signature                                                                                               | 用途                                                                      |
| --------------------------------- | ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| `compileToScene`                  | `(ir: IRScene, options?: CompileOptions) => CompileResult`                                              | 主编译入口；同次返回 `scene` 与 immutable `artifacts`                     |
| `observeCompileToScene`           | `(ir, options, observers) => ObservedCompileResult`                                                     | 显式创建观测会话，返回主结果与按 definition 排序的 observer outputs       |
| `lowerIRToKernel`                 | `(ir: IRScene, options?: LowerIRToKernelOptions) => LoweredIRScene`                                     | 只递归展开 composite，返回不含 Tier 2 节点的 Kernel IR                    |
| `resolveCoreProviderDependencies` | `(options: ResolveCoreProviderDependenciesOptions) => CoreProviderDefinitions`                          | 解析 rooted provider graph，返回按 Core capability 分组的 compile options |
| `selectSpatialHandles`            | `(index: SpatialHandleIndex, selector: SpatialHandleSelector) => ReadonlyArray<QualifiedSpatialHandle>` | 精确筛选零到多个 qualified spatial handles                                |
| `resolveSpatialHandle`            | `(index: SpatialHandleIndex, selector: SpatialHandleSelector) => QualifiedSpatialHandle`                | 要求 selector 恰好命中一个 handle；miss / ambiguity 时抛错                |
| `computeLayout`                   | `(points, padding, round) => Layout`                                                                    | 从 bbox 候选点计算场景边界；通常由 `compileToScene` 内部调用              |
| `resolveBoxSpacing`               | `(value, fallback) => BoundsInsets`                                                                     | 把统一值或按边覆盖值归一化为完整四边间距                                  |
| `fallbackMeasurer`                | `(text, font) => TextMetrics`                                                                           | 默认文字度量；不准但可运行，适合无 DOM 环境的兜底                         |
| `formatCompileWarning`            | `(warning: CompileWarning) => string`                                                                   | 把结构化 warning 格式化为统一的可读消息                                   |
| `formatCompileOccurrence`         | `(locator: CompileOccurrenceLocator) => string`                                                         | 格式化 artifact 的 occurrence locator                                     |
| `isNodeLayoutCompileArtifact`     | `(artifact: CompileArtifact) => artifact is NodeLayoutCompileArtifact`                                  | 缩窄 opt-in Node layout artifact                                          |

`compileToScene` 先遍历并注册当前作用域内的 node / coordinate，再回填延迟发出的 path，因此路径可以引用同一作用域中写在它后面的目标。输出随后按 `zIndex` 升序稳定排序；只有 `zIndex` 相同的图元才保持声明顺序。

`lowerIRToKernel` 不做布局或 Scene 发出，只消费 `composites` 与 `maxCompositeDepth`。未注册 composite 会直接抛错；遇到带 `compile` 分支的 layout-aware composite 也会明确报错，因为独立 lowering 没有文字测量、provider、引用环境和父级约束。`expand` 返回非空 `spatialHandles` 时也会同步失败，并提示改用 `compileToScene()` 获取结算后的 world geometry；无声明或空声明不受影响。完整 `compileToScene` 对未注册 composite 发出 `COMPOSITE_NOT_REGISTERED` 并跳过；两条路径遇到嵌套超限或环都会抛错。

### 盒间距归一化

`resolveBoxSpacing(value, fallback)` 接受一个非负数、`IRBoxSpacing` 对象或 `undefined`，并返回 `{ top, right, bottom, left }` 形式的 `BoundsInsets`。统一数值会应用到四边；对象中的每一边按 `side > axis > default > fallback` 选择首个已提供的值。

调用方应先通过自身 schema 校验 `value`。`fallback` 必须是有限非负数，即使 `value` 已提供完整值也会检查；非法 fallback 会直接抛错。每次调用都返回独立的新对象。

## 编译选项

`CompileOptions` 调用时仍是扁平对象；下面按职责分组说明。

### 宿主能力

| Option        | Type                | Default                                     | 说明                                                  |
| ------------- | ------------------- | ------------------------------------------- | ----------------------------------------------------- |
| `measureText` | `TextMeasurer`      | `fallbackMeasurer`                          | 注入文字度量函数；React adapter 使用浏览器能力        |
| `lowerTex`    | `LowerTex`          | `undefined`                                 | 注入公式渲染能力；未注入或解析失败时会 warning 并降级 |
| `onWarn`      | `(warning) => void` | dev: `console.warn`<br />production: silent | 收集可恢复的编译期 warning                            |

### 布局与输出

| Option          | Type                     | Default | 说明                                                                                      |
| --------------- | ------------------------ | ------- | ----------------------------------------------------------------------------------------- |
| `padding`       | `number`                 | `10`    | layout 外围留白，单位为 user units                                                        |
| `precision`     | `number`                 | `2`     | 输出 Scene 图元坐标、结构化 path command 与 layout 数值的小数位；内部几何保持 double 精度 |
| `nodeDistance`  | `number`                 | `24`    | `AtPosition` 未写 `distance` 时使用的默认距离                                             |
| `labelDistance` | `number`                 | `12`    | `Node.label.distance` 未设置时，节点边界到旋转后标签视觉框的默认净距；必须为有限非负数    |
| `fontSize`      | `number`                 | `16`    | 默认字号；同时作为字号 preset 与 `rem` 的根字号，不改变显式数字字号                       |
| `artifacts`     | `CompileArtifactOptions` | `{}`    | opt-in 通用产物；`{ nodeLayouts: true }` 返回真实 Node 的 `CompiledNodeLayout` 布局快照   |

### 扩展注册表

| Option                | Type                                          | Default       | 说明                                                                                           |
| --------------------- | --------------------------------------------- | ------------- | ---------------------------------------------------------------------------------------------- |
| `shapes`              | `ReadonlyArray<ShapeDefinition>`              | Core 基础集合 | 注入自定义或 Standard 可选节点形状。见 [形状扩展](/library/standard/extension/shape)           |
| `boundaries`          | `ReadonlyArray<BoundaryDefinition>`           | 内置集合      | 追加自定义连接面。见 [自定义连接面](/kernel/components/node/custom-boundary)                   |
| `clips`               | `ReadonlyArray<ClipDefinition>`               | Core 基础集合 | 注入自定义或 Standard 组合裁剪。见 [裁剪扩展](/library/standard/extension/clip)                |
| `arrows`              | `ReadonlyArray<ArrowDefinition>`              | Core 基础集合 | 注入自定义或 Standard 可选箭头。见 [箭头扩展](/library/standard/extension/arrow)               |
| `patterns`            | `ReadonlyArray<PatternDefinition>`            | 内置集合      | 追加自定义填充图案。见 [自定义图案](/kernel/components/effects/custom-pattern)                 |
| `pathGenerators`      | `ReadonlyArray<PathGeneratorDefinition>`      | 无            | 注入自定义路径生成器；Core 没有默认项。见 [路径生成器](/kernel/components/draw/path-generator) |
| `pathKinds`           | `ReadonlyArray<PathKindDefinition>`           | 内置集合      | 追加自定义 path kind provider                                                                  |
| `ribbonWidthProfiles` | `ReadonlyArray<RibbonWidthProfileDefinition>` | 内置集合      | 追加 ribbon 宽度 profile；core 内置 `bulge`，profile 函数不进入 IR                             |

传入的 definitions 会与对应 Core 基础集合合并；空 key 或与同次已注册项重名都会立即抛错，不会覆盖已有 provider。Standard 可选内容也走同一条合并与诊断路径。

### Theme token owner registry

| Option        | Type                                  | Default     | 说明                                                    |
| ------------- | ------------------------------------- | ----------- | ------------------------------------------------------- |
| `themeStyles` | `ReadonlyArray<ThemeStyleDefinition>` | 内置 styles | 追加运行时 Core style resolver；同名 style 冲突立即抛错 |

每个 Definition 绑定一个 style name 与解析 `mode` 的函数。Core 在 Scene / Scope 解析时继承 `style` / `mode`，再由该 resolver 生成 shared colors；未注册 style 或同名不同 Definition 都 fail-loud。函数只存在于运行时 options，不会写入 IR。

### Composite

| Option              | Type                                    | Default | 说明                                                                                  |
| ------------------- | --------------------------------------- | ------- | ------------------------------------------------------------------------------------- |
| `composites`        | `ReadonlyArray<AnyCompositeDefinition>` | `—`     | 注入 Tier 2 的 `expand` 或 layout-aware `compile` definition；未注册时 warning 并跳过 |
| `maxCompositeDepth` | `number`                                | `32`    | composite 嵌套的最大深度；超限或成环会 throw                                          |

`CompositeDefinition` 的两个分支互斥：

- `expand(node, context)` 在当前 Theme 上下文中做结构展开；
- `compile(node, context)` 通过 `context.proposal` 与 `layoutChild(child, proposal)` 在完整 compile 环境中求值真实子内容。

`expand` 只接受 `{ children, spatialHandles? }`，不接受裸 child 或 child array shorthand。布局感知 `compile` 的结果也可提供同一 `spatialHandles` declaration 数组；两条路径共用相同的 callback-bound 校验。

两个分支都从 `context.theme` 读取当前位置完整、冻结的 `ResolvedTheme`。解析顺序固定为默认 light 基线 → Scene → 外层 Scope → 内层 Scope，每层只覆盖显式 `style`、`mode` 或 namespace/token key。`ResolvedTheme` 还提供递归冻结的 `tokens` 与 detached/frozen 的 `colors` shared view；`colors.semantic` 固定提供 error/success/warning，`colors.categorical` 始终非空，重复值按稳定 index 取余消费。`lowerIRToKernel()` 对 `expand` 使用同一解析器；layout-aware definition 仍在 callback 前 fail-loud。Theme 只供 Composite 物化自己的领域默认，最终 Scene 与 renderer 不携带或解释 Theme。

带 `artifactSchema` 的 layout-aware definition 可以在同一次 `compile` 返回 JSON-safe `artifact`。该 schema 既约束公开 `CompileResult.artifacts`，也是显式 observer 读取最终 Composite 所属者产物的契约；Composite 本身不包含 Inspector 定义。

### Provider graph 装配

Provider graph 是编译前的纯装配协议，不是第二套 registry。React、Vanilla 和可复用 domain 工具收集 `CoreProviderContribution`，调用 `resolveCoreProviderDependencies()` 得到按 capability 分组的 `CoreProviderDefinitions`，再把每组结果交给对应的 `CompileOptions` 字段。

| 公开契约                                 | 关键字段 / 结果                                                                 | 职责                                                      |
| ---------------------------------------- | ------------------------------------------------------------------------------- | --------------------------------------------------------- |
| `CoreProviderKey`                        | 普通能力用 `capability`、`name`；composite 用 `capability`、`namespace`、`type` | 无歧义标识一个 Core provider                              |
| `CoreDependencyProvider`                 | `key`、`dependencies`、`datasets`、`makeDefinition`                             | 声明一个 Definition、直接依赖与 runtime-only 数据         |
| `CoreProviderContribution`               | `roots`、`providers`                                                            | 声明当前 authored node 需要的根能力与已导入 provider 集合 |
| `ResolveCoreProviderDependenciesOptions` | `contributions`、`definitions?`                                                 | 把 provider 结果与最终显式 Definitions 合并               |

解析器先完成完整预检，再执行 maker：同 key 的 maker 引用与有序 dependencies 必须一致；同 provider key、同 dataset reference 只有 `Object.is` 同源才可去重；缺失 provider 和 cycle 会报告完整链。输出按 dependency-first、首次可达顺序物化，再按 `shapes`、`arrows`、`clips`、`pathGenerators`、`composites` 等匹配的 compile option 分组；每个 maker 只执行一次。

`options.composites` 是最终显式 Definition 通道，不是嵌套 adapter 的私有 sidecar。Provider 结果先加入，显式 Definition 保留 authored order 后追加；同 key 同对象去重，同 key 不同对象立即失败。直接调用 `compileToScene()` 的作者如果已经拥有完整 Definition 数组，可以跳过 provider graph，继续直接传 `CompileOptions.composites`。

`LayoutProposal` 必须恰好包含 `x` 与 `y`；每条轴使用 `LayoutAxisProposal`：

| `kind`      | 字段                           | slot 不变量                                       |
| ----------- | ------------------------------ | ------------------------------------------------- |
| `intrinsic` | `mode: 'minimum' \| 'natural'` | slot 是完整双轴上下文中解析出的 contribution      |
| `range`     | `min` / `max?`                 | `max` 存在时落在 `[min, max]`；省略时不小于 `min` |
| `exact`     | `value`                        | slot 严格等于该有限非负值                         |

`NaturalLayoutProposal` 是深冻结的 natural / natural 常量，也是根 layout-aware composite 的默认 proposal。Proposal 会在 child dispatch 前严格校验、detached clone 并冻结；缺轴、额外字段、负数、NaN、Infinity、非法 range 都直接报 occurrence-aware contract error，显式零合法，`-0` 规范为 `0`。

`layoutChild()` 返回 `LayoutChildProbe`，先按 `LayoutChildProbeKind.Resolved` / `Failed` 缩窄：

| Outcome    | 字段      | 语义                                                                                         |
| ---------- | --------- | -------------------------------------------------------------------------------------------- |
| `resolved` | `result`  | `LayoutChildResult`：resolved slot、真实 bounds、guides 与 replay transaction                |
| `failed`   | `failure` | callback-local、compile-local 的 opaque `LayoutChildFailure`；可丢弃或传给 `context.raise()` |

`LayoutChildResult` 的字段彼此独立：

| 字段               | 语义                                                                          |
| ------------------ | ----------------------------------------------------------------------------- |
| `slotSize`         | proposal 求值后的 `width` / `height`，没有 origin 或 alignment 语义           |
| `allocationBounds` | child 在自身局部坐标中的真实布局占用，可大于或小于 slot                       |
| `visualBounds`     | 最终静态 primitive tree 的保守墨迹包络，不参与 slot 求值                      |
| `alignmentGuides?` | child-local 一维 guide；`LayoutAlignmentGuideName` 内置 first / last baseline |
| `replay`           | 该隔离 transaction 的 one-use opaque token                                    |

Plain text 会在 x minimum / natural 下计算上下文化 contribution，并在有限 x range / exact 下重排；mixed / TeX authored line 与固定 geometry 保持原子，不缩放真实 allocation。Y minimum / natural 是应用完整 x proposal 后的真实排版高度。所有 built-in 都只复用 Core 的 measurer、provider 与几何，不回读 DOM 或 renderer。

layout-aware `compile` 可返回显式 `allocationBounds` 作为 composite 的 container allocation，以及已经位于 composite-local allocation coordinate 的 `alignmentGuides`。省略 allocation 时 Core 合并最终 children；Core 不自动替 solver 选择或合并多条 child guide。

父 solver 用 `context.replay(result, wrapper?)` 选择成功 transaction。`wrapper.transforms` 先把 child 放进 parent allocation coordinate，随后 `wrapper.clip` 在该父坐标系裁剪；它只收紧最终 Scene visual contribution，不改变 allocation，也不回写已有 `LayoutChildResult.visualBounds`。最终提交复用已布局结果，不再次展开、测量或布局。

`context.scope(props, children)` 可以递归包装普通 `IRChild`、replay child 与其它 runtime Scope child。它只开放 replay 后仍有确定语义的九个结构字段：

| 字段             | 作用                                    |
| ---------------- | --------------------------------------- |
| `theme`          | 为后代普通 IR child 建立稀疏 Theme 覆盖 |
| `id`             | 把 Scope identity 注册到父 namespace    |
| `localNamespace` | 隔离 Scope 子树命名                     |
| `transforms`     | 应用已 lowering 的数值 Scene transforms |
| `clip`           | 在 Scope 局部坐标裁剪                   |
| `zIndex`         | 让 Scope 作为同层单元排序               |
| `boundingShape`  | 声明带 id Scope 的包络形状              |
| `meta`           | 透传 JSON metadata                      |
| `animations`     | 透传 Group 动画轨道                     |

`context.replay()` / `context.scope()` 返回 runtime-only opaque handle，不进入 IR、Scene 或 renderer 合同。Failure、layout result、handle 与 replay 都由 callback-local / compile-local identity 校验，不能跨 compile、跨 callback、序列化、spread 后伪造或重复使用。由 replay / runtime Scope handle 形成的完整 runtime output tree 会在任何 sink 写入前预检；普通 `IRChild` 随后继续经过既有 compile dispatch。Replay wrapper 与 Scope props 在 builder 调用时 detached、校验并冻结。

每次 probe 的 primitive、resource、warning、artifact、namespace、identity 与 observation 都留在隔离 transaction。丢弃 resolved / failed outcome 对最终 `CompileResult` 零可观察；`context.raise(failure)` 只接受当前 callback 创建的 failure，并保留原始 cause、provider、source path 与 nested occurrence 后抛错。

Occurrence 的 `probe[index]` segment 表示候选 `layoutChild()` dispatch；最终成功 transaction 的 locator 把该候选来源重映射到既有 `replay[index]` output commit。`output` / `scopeChild` 继续描述 compile output tree。Resource、namespace、warning、bounds 与 artifact 只在选中 replay 的一次提交中原子发布。

带 `artifactSchema` 的 layout-aware definition 可在同一次 `compile` 返回 JSON-safe `artifact`。`compileToScene` 会把它封装为 `{ kind:'composite', namespace, type, occurrence, value }`；`occurrence` 由原始 `sourcePath` 和结构化 `expansionPath` 标识，不依赖全局 Map 或 callback capture。精确的 definition tuple 会让 `CompileResult` 推导对应 artifact union。

## 显式编译观测

`observeCompileToScene()` 复用同一条完整编译管线，但为每个 `CompileObserverDefinition` 创建独占 session。普通 `compileToScene()` 不创建 session，也不捕获额外所属者产物。

| 阶段 | 回调                            | 作用                                                                       |
| ---- | ------------------------------- | -------------------------------------------------------------------------- |
| 选择 | `select(site)`                  | 在所属者编译前按 `owner` 与 authored `sourcePath` 决定是否请求产物         |
| 观测 | `observe(observation, context)` | 消费最终 occurrence、已校验产物、局部到主 Scene 的变换及 probe/replay 来源 |
| 完成 | `complete()`                    | 在全部事件完成后返回领域自定义结果；Core 递归冻结输出                      |

Composite 复用 `artifactSchema` 与 `compile` 返回的 `artifact`。Path kind 则显式声明 `ownerOutput: { schema }`，并只在 `context.ownerOutput.requested` 为真时调用 `publish(value)`；被选择却没有发布、重复发布或 schema 校验失败都会直接报错。失败和被丢弃的 probe 不触发 `observe()`，最终事件按 occurrence 与 owner 稳定排序。

`context.compileFragment(children)` 可在当前 occurrence 的 Theme、Scope 样式与 provider 环境中编译普通 Core 子元素。片段返回独立 `scene`、artifacts 与 diagnostics，不写回主编译结果；跨片段或指向主图的公共身份引用会失败。Core 不约束 `complete()` 的结果结构，因此统计、分析和 [`@retikz/inspect`](/kernel/packages/extension/inspect) 都能复用这条能力。

## 文字度量

`TextMeasurer` 是 compile 层唯一需要外部环境帮助的地方：

```ts
type TextMeasurer = (text: string, font: FontSpec) => TextMetrics;
```

| Type          | 字段                                        | 说明                                  |
| ------------- | ------------------------------------------- | ------------------------------------- |
| `FontSpec`    | `family?` / `size` / `weight?` / `style?`   | 传给 measurer 的字体信息；`size` 必填 |
| `TextMetrics` | `width` / `height` / `ascent?` / `descent?` | 文本盒尺寸；ascent / descent 可选     |

如果不传 `measureText`，`fallbackMeasurer` 用 `text.length * size * 0.55` 估算宽度、`size * 1.2` 估算高度。它能保证编译可跑，但不适合做精确排版。

Node label 会把一次测量阶段得到的 `width` / `height` / `ascent` / `descent` 规范成唯一视觉框：两项基线指标都缺省时上下平分 `height`；只给一项时由 `height` 补齐另一项；两项都给时若二者之和小于 `height`，剩余 leading 上下平分，若大于 `height` 则视觉框扩到二者之和。该视觉框同时决定标签基线、旋转后间距、pin 终点与自动 viewBox，布局节点矩形后不会重新测量。Node label 的任何度量值若不是有限非负数会直接抛错；非法 TeX 盒仍按既有 `TEX_INVALID` warning 降级。

## 警告

`CompileWarning` 是机器可读的同步 warning：

| Field     | Type                   | 说明                                               |
| --------- | ---------------------- | -------------------------------------------------- |
| `code`    | string                 | warning 类型代码                                   |
| `message` | string                 | 英文人类可读消息                                   |
| `path`    | string                 | IR locator，例如 `children[3].path.children[1].to` |
| `origin`  | `CompileWarningOrigin` | 主编译或所属者 / 隔离片段观测来源                  |

当前内置 code（机器可读常量 `CompileWarningCode` 已公开导出，可按枚举引用而非硬编码字符串）：

| Code                            | 含义                                                                                        |
| ------------------------------- | ------------------------------------------------------------------------------------------- |
| `UNRESOLVED_NODE_REFERENCE`     | 路径或位置引用了不存在的节点 / coordinate                                                   |
| `PATH_TOO_SHORT`                | path 不足 2 步 / 缺前一终点，无法形成有效绘制段，整条 path 跳过                             |
| `OFFSET_BASE_UNRESOLVED`        | OffsetPosition 的基准 `of` 无法解析                                                         |
| `POLAR_ORIGIN_UNRESOLVED`       | PolarPosition 的 `origin` 无法解析                                                          |
| `AT_TARGET_UNRESOLVED`          | AtPosition 的 `of` 无法解析                                                                 |
| `DUPLICATE_NODE_ID`             | 同一命名空间帧内重复 id；后定义覆盖先定义（last-wins）                                      |
| `COMPOSITE_NOT_REGISTERED`      | composite 节点的 `namespace.type` 未注册，跳过该节点                                        |
| `ANIMATION_INVALID_PROPERTY`    | 动画 track 的 property 非法（如 scene-root 非 viewBox 属性），该 track 丢弃                 |
| `ARC_MISSING_RADIUS`            | arc step 缺 `radius`，整条 path 跳过；`radius` 可为数字圆弧或 `{ x, y }` 椭圆弧             |
| `PARTIAL_ARC_NEEDS_BOTH_ANGLES` | circlePath / ellipsePath 部分弧需同时给 `startAngle` 与 `endAngle`，否则按完整圆 / 椭圆处理 |
| `PARTIAL_ARC_CLOSED_INVALID`    | 带角度的部分圆 / 椭圆不能用 `closed:'closed'`，退回 `'chord'`                               |
| `TEX_LOWERER_MISSING`           | 显式 math run 没有注入 `lowerTex`；跳过该公式片段                                           |
| `TEX_INVALID`                   | `lowerTex` 无法生成有效公式图元；跳过该公式片段                                             |
| `TEX_TEXT_CONFLICT`             | 为 text / TeX 载荷冲突保留的诊断码；当前 compile 路径不发出                                 |
| `TEXT_TEX_PARSE_ERROR`          | 启用 TeX 时字符串含未闭合 `$` / `$$`；保留尾部字面文本                                      |
| `BOUNDARY_TIGHT_FALLBACK`       | shape 未提供请求的 tight / ink 连接包络；回退到 visual bounds                               |
| `TEXT_AUTO_CONTRAST_UNRESOLVED` | Node 自动对比色无法得到静态不透明 fill；使用固定 `currentColor`，Node 继续编译              |

大多数 warning 不会中断编译。但 coordinate / node 自身位置无法解析时**直接抛错、不发 warning**（源码刻意如此：warn 后立即 throw 会让收集器记录一条永不产出 Scene 的死告警），因为它属于「定义位置」的实体，会破坏后续引用合同。

公开 warning 的 `origin` 始终必填。普通编译使用 `{ kind: 'primary' }`；观测所属者或隔离片段产生的 warning 使用 `{ kind: 'observation', owner, occurrence, stage }`。隔离片段引用主 Scene 或其它片段的公共 identity 时会提升为致命错误，避免发布局部失真的结果。

自动对比色 warning 的 `path` 固定为当前 Node locator，`message` 会包含无法解析的 fill、原因与固定 fallback。同一 Node 即使有多段正文、公式、label 或 pin，也最多发一次；没有消费者继承 Node 文字颜色时不会解析关键字或发 warning。

## 输出

`compileToScene` 返回 `CompileResult`：

| Field            | Type                             | 说明                                                                     |
| ---------------- | -------------------------------- | ------------------------------------------------------------------------ |
| `scene`          | `Scene`                          | 已布局、可直接交给 renderer 的场景                                       |
| `artifacts`      | `ReadonlyArray<CompileArtifact>` | 与 `scene` 同一次 canonical compile 产生的 immutable typed artifacts     |
| `spatialHandles` | `SpatialHandleIndex`             | 同 revision 的 qualified world-space index；无声明时为冻结的空 `entries` |

`observeCompileToScene()` 返回 `{ primary, observerOutputs }`。`primary` 与同一 IR/options 下的普通 `compileToScene()` 等价；`observerOutputs` 按传入 definitions 的顺序排列，每项包含稳定 `key` 与该 session 的完成值。

其中 `scene` 包含：

| Field         | Type                      | 说明                                                                                                  |
| ------------- | ------------------------- | ----------------------------------------------------------------------------------------------------- |
| `primitives`  | `Array<ScenePrimitive>`   | 已布局图元，顺序就是渲染顺序                                                                          |
| `layout`      | `Layout`                  | 场景边界 `{ x, y, width, height }`                                                                    |
| `resources?`  | `Array<SceneResource>`    | 渲染无关资源表（渐变 / pattern / clip 等 paint server）；adapter 物化（SVG → `<defs>`）。无资源时省略 |
| `animations?` | `Array<IRAnimationTrack>` | scene 根（镜头）时间轴动画 tracks（viewBox property），从 IR 根 animations 透传；无则省略             |

自定义 renderer 必须消费 `resources` 与 `animations`，否则会丢渐变 / 裁剪 / 镜头动画。如果没有任何 bbox 候选点，`computeLayout` 返回 `100×100` 的兜底 layout。

### Spatial handle sidecar

每个 `QualifiedSpatialHandle` 都包含声明者的 `key` / `role`、world-space rect AABB、稳定 authored-order tags、可选 JSON payload、`originOccurrence` / `finalOccurrence`，以及从外到内的 `ownerPath`。显式 composite `id` 进入 owner 的 `instanceId`；匿名 owner 只由当前 compile occurrence 区分，不会获得自动计数 id。

selector 字段全部精确匹配。`owner` 只匹配声明者；`within` 按顺序匹配其祖先路径中的连续子路径；`tags` 要求结果包含给出的全部标签。`key` 只在一个 owner occurrence 内唯一，跨 owner 查询应补足 `within`、`owner.instanceId` 或 occurrence。

空间索引是工具链 sidecar，不属于 Scene。SVG / Canvas / SSR renderer 只接收 `scene`，不会读取、复制或变换 `spatialHandles`。React `<Layout onCompileResult>` 在 static / retained 成功 commit 后发布完整 `CompileResult`；Vanilla 的 authored-input `SceneResult.compileResult` 与 live view `compileResult` 暴露当前结果，直接传入预编译 Scene 时为 `undefined`。失败 revision 保留上一个已提交结果；用户 callback 抛错不会回滚成功 commit。
