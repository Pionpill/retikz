---
title: Path
description: A drawn path container, its step actions, and step targets
---

A `path` is the outer container for a drawn line. Its `children` field is an ordered array of `Step` actions. Compile lowers those steps into renderer-agnostic `PathPrim.commands`; SVG / Canvas adapters then materialize their platform commands. Each step's destination is a `Target`.

Core also exposes five reusable strict fragments for Path fields: stroke, fill, geometry, decoration, and structure. A fragment only owns local JSON fields and local invariants; it is not an independent compile / lowering entry point and does not add drawing capability. Standard, Plot, and other Tier 2 owners may compose the fragments with their own defaults and field restrictions.

## Path

<ZodSchema name="PathSchema" />

`PathSchema` is the open Core host schema for a Path. It combines the fragments above with `DrawableInstanceSchema` and `DrawableStyleSchema`, accepts an open `kind` name and JSON-safe `kindOptions`, and does not encode a closed list of Path kinds. During compile, Core resolves the selected `PathKindDefinition` and parses the complete subject with that definition's `schema`. Core's built-in `stroke` definition owns the complete `StrokePathSchema`, which requires `children` and rejects `kindOptions`; optional Standard Ribbon owns its own complete schema. The host schema remains reusable for custom definitions and Tier 2 owners.

`PathDefaultSchema` is an explicit Core Scope-owner composition of `GraphicStyleSchema`, `PathStrokeSchema`, `PathFillSchema`, and `PathGeometrySchema` without `children`. It excludes instance, structure, decoration, and `children` fields; it is not an accidental projection of complete Path and is not an independent compile entry. The default `stroke` path consumes every applicable field. Tier 2 owners may retain their own defaults and field restrictions when composing these fragments.

React `<Path thickness>` is component / builder sugar that becomes `strokeWidth` before IR is produced, so it is not part of `PathSchema`. See [Path styling](/kernel/components/draw/path#styling) for the preset values.

## DrawableStyle

`DrawableStyleSchema` is the shared geometry-style field set for Path kinds. The default `stroke` kind maps `color` to stroke; the optional Standard Ribbon definition maps its `color` to fill. `pathDefault` also uses this subset when it styles path-like drawables.

<ZodSchema name="DrawableStyleSchema" />

## DrawableInstance

`DrawableInstanceSchema` groups shared identity, provenance, animation, and stacking fields for Path. `id` / `meta` / `animations` are instance metadata and do not enter `pathDefault`; `zIndex` participates in sibling ordering but is not inherited as a default style.

## GeometryLabel

`GeometryLabelSchema` is the shared label contract for path-like hosts. `StepLabelSchema` is an alias of this schema; drawn steps and optional Standard Ribbon centerline labels reuse the same fields.
It describes label text, normalized position along the host segment or centerline, and tangent / normal-side placement.

## Target

`TargetSchema` is the union for path endpoints: Cartesian / polar / node target object `{ id, anchor?, offset?, boundary? }` / offset placement `{ of, offset }` / proportional placement `{ between, fraction }` / relative offsets (relative / relativeAccumulate). In the node target object, `boundary?` overrides the connection surface this single endpoint clips to (defaults to the node's own `boundary`, i.e. `shape`); `anchor?` auto-clips to the boundary when omitted.
