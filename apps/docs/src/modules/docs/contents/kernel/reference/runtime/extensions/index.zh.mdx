本页是扩展点词典：用于快速判断一个自定义能力属于哪种机制、从哪里注入、IR 保存什么。完整实现步骤放在对应能力分组末尾的扩展指南；能力归属和完备性判断见[架构](/kernel/concepts/design/principles)。

> 扩展函数和 registry 不写进 IR。IR 只保存可序列化的 key 与参数，宿主在编译或运行时注入实际行为。

## 扩展模型

| 模型                | 适用能力                                               | 生效阶段                       |
| ------------------- | ------------------------------------------------------ | ------------------------------ |
| Definition registry | shape、boundary、clip、arrow、pattern、path、composite | compile / layout-aware compile |
| Runtime registry    | easing、animation property                             | render / animation runtime     |
| Host lowerer        | TeX 等可选重型下沉                                     | compile 期文字布局             |

Definition 能力使用 `XxxDefinition` 与 `defineXxx` 描述扩展项，内置和自定义 definitions 合并成一次编译专用的 registry。Runtime registry 保存宿主函数，不进入 compile contract。Host lowerer 是可选宿主能力，不应为了单个集成扩张通用图元契约。

Layout proposal 不是新的 registry：它是每个 layout-aware `CompositeDefinition.compile` callback 内闭合的通用 child 求值合同。内置 child、第三方 provider 与 nested composite 都继续经过同一 composite / provider registry、同一 compile 环境和同一 replay transaction；Core 不按 child 类型维护测量白名单。

## 能力索引

| 能力               | IR 选择键          | 注入入口                                               |
| ------------------ | ------------------ | ------------------------------------------------------ |
| Shape              | `Node.shape`       | `CompileOptions.shapes`                                |
| Boundary           | `Node.boundary`    | `CompileOptions.boundaries`                            |
| Clip               | `Scope.clip.kind`  | `CompileOptions.clips`                                 |
| Arrow              | arrow shape name   | `CompileOptions.arrows`                                |
| Pattern            | pattern shape name | `CompileOptions.patterns`                              |
| Path generator     | generator name     | `CompileOptions.pathGenerators`                        |
| Path kind          | `Path.kind`        | `CompileOptions.pathKinds`                             |
| Ribbon profile     | profile name       | `CompileOptions.ribbonWidthProfiles`                   |
| Composite          | `namespace + type` | `CompileOptions.composites`                            |
| Easing             | easing name        | `<Layout easings>`                                     |
| Animation property | property name      | `<Layout animationProperties>`（仅 Canvas 自定义属性） |
| TeX lowerer        | math text payload  | `CompileOptions.lowerTex`                              |

## 诊断约定

- Compile Definition registry 在合并内置与自定义项时拒绝空 key 和重复 key，自定义项不能静默覆盖内置项。
- Easing / animation property 等 runtime registry 直接使用宿主传入的 `Record`，不经过上述 Definition 合并诊断；未知自定义动画属性由具体 renderer warning 并跳过。
- 普通 Definition 找不到 key 时 fail-loud，并列出已注册项。
- 未注册 composite 在完整 compile 中产生 warning 并跳过该节点；独立 lowering 会提升为错误。
- Composite registry 同时接受互斥的 `expand` 与 `compile` 分支；`lowerIRToKernel` 遇到依赖完整环境的 `compile` 分支会明确报错。
- layout-aware composite 的 `layoutChild(child, proposal)` 返回 resolved / failed outcome。未选中的失败保持隔离；选中失败必须通过当前 callback 的 `raise()` 提升，诊断保留原 provider、cause、source path 与 `probe[...]` occurrence。
- Proposal 是每次调用按值校验并冻结的输入；failure、result、replay 与 output child 才受 callback-local / compile-local ownership 约束，只能用 `replay()` / `raise()` / `scope()` 完成选择。对这些受 ownership 约束的对象重复使用、伪造、spread-copy、跨 compile 或跨 callback 传递，都会在任何提交前 fail-loud。
- Provider 主动抛出的普通错误可成为 recoverable failed probe；malformed provider output、非法 proposal、token misuse 与 Core invariant 属于 fatal contract / invariant error，不能被伪装成可丢弃失败。
- schema 或 payload 校验发生在 definition 消费前，错误应包含能力族与 lookup key。
