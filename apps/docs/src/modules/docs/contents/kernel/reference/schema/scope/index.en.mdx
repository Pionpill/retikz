`ScopeSchema` is the Tier 1 container node. It does not draw a new visual primitive; it establishes local transforms, style defaults, clipping, stacking, and reference boundaries for a child subtree. A Scope can still be referenced through its own `id`.

## Scope placement

`ScopePlacementSchema` is the closed self-anchor-to-target contract. `target` accepts only a Cartesian `[x, y]` in the parent frame or a previously completed `NodeTarget`; Polar, Offset, Between, and path-relative targets are excluded.

<ZodSchema name="ScopePlacementSchema" />

A NodeTarget offset is added once in world user units before projection into the parent frame. Forward, self, descendant, and unresolved Scope-placeholder references fail synchronously without topological sorting.

<span id="scopeselfpoint"></span>

### Scope self point

<ZodSchema name="ScopeSelfPointSchema" />

`origin` is always intrinsic local `[0, 0]`. Other anchors reuse standard names, numeric angles, and `{ side, fraction }`; an explicit local point is also accepted. For an empty Scope, origin, center, edges, corners, and numeric angles collapse to `[0, 0]`, while `{ side, fraction }` still fails on the zero-size envelope.

<span id="default-channels"></span>

### Four default channels

Scope separates defaults into four independent channels. Each fills only fields omitted by the matching host; `resetStyle` can block parent-Scope inheritance per channel.

| Field          | Reused contract                                                 | Does not own                             |
| -------------- | --------------------------------------------------------------- | ---------------------------------------- |
| `nodeDefault`  | Visual fields from [Node](/kernel/reference/schema/entity#node) | id, position, text, labels, or metadata  |
| `pathDefault`  | Visual fields from [Path](/kernel/reference/schema/path#path)   | kind, steps, marks, or instance metadata |
| `labelDefault` | Label color, textColor, opacity, and font                       | Text, position, or host relation         |
| `arrowDefault` | [ArrowDetail](/kernel/reference/schema/path#arrowdetail)        | Arrow existence or path placement        |

## Transform

`TransformSchema` is the union accepted by `Scope.transforms`. Index 0 is outermost and the last item acts first. Translation variants resolve to Cartesian translation; a rotate pivot lowers to Scene `cx/cy`, while a non-origin scale pivot lowers to `translate(p) → scale → translate(-p)`.

<ZodSchema name="TransformSchema" />

| `kind`              | Core fields                    | Effect                                 |
| ------------------- | ------------------------------ | -------------------------------------- |
| `translate`         | `x`, `y`                       | Cartesian translation                  |
| `polar-translate`   | `origin?`, `angle`, `radius`   | Translation derived from polar input   |
| `at-translate`      | `direction`, `of`, `distance?` | Translation relative to a named entity |
| `offset-translate`  | `of`, `offset?`                | Base point plus a 2D offset            |
| `between-translate` | `between`, `fraction`          | Proportional point between endpoints   |
| `rotate`            | `degrees`, `pivot?`            | Rotate around a Scope self point       |
| `scale`             | `x`, `y?`, `pivot?`            | Scale around a Scope self point        |

`pivot` defaults to `origin` and accepts a [Scope self point](#scope-self-point). v0.5 removes IR rotate `cx` / `cy`; migrate to `pivot: [cx, cy]`. Scene transform `cx` / `cy` remain lowering output.

## Clip

`ClipSpecSchema` is the union accepted by `Scope.clip`. Built-in geometry uses the JSON shapes below; a custom `kind` is registered through `CompileOptions.clips` and resolved during compile.

| Branch            | Discriminator            | Content                                        |
| ----------------- | ------------------------ | ---------------------------------------------- |
| Built-in geometry | `rect` / `circle`, etc.  | Uses one of the fixed schemas below            |
| `compound`        | `kind: 'compound'`       | Recursively combines multiple ClipSpec values  |
| Custom Definition | Any other non-empty kind | Fields are validated by `CompileOptions.clips` |
