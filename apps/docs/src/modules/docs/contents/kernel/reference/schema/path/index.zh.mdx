title: 路径
description: 笔画外壳、step 动作序列与 step 目标点
---

`path` 是一条笔画的外壳容器；它的 `children` 字段是一个 `Step` 动作有序数组。compile 按顺序把 step 降为渲染目标无关的 `PathPrim.commands`，SVG / Canvas adapter 再物化为各自的平台命令。

Core 另外公开五个可复用的严格 fragment，按描边、填充、几何、装饰和结构边界组织 Path 字段。fragment 只负责局部 JSON 字段与局部不变量，不是独立的 compile / lowering 入口，也不新增绘图能力；Standard、Plot 等 Tier 2 owner 可以按自己的默认值和字段限制组合它们。

`PathSchema` 是 Core 的开放 Path host schema。它把上述 fragment 与 `DrawableInstanceSchema`、`DrawableStyleSchema` 组合，接受开放的 `kind` 名和 JSON-safe `kindOptions`，不在 Core 中编码封闭的 Path kind 列表。编译时 Core 先解析选中的 `PathKindDefinition`，再用该 definition 的 `schema` 解析完整 subject。Core 内置 `stroke` definition 由完整的 `StrokePathSchema` 负责，要求 `children` 且拒绝 `kindOptions`；可选的 Standard Ribbon 则在 Standard 中拥有自己的完整 schema。这个 host schema 可继续被自定义 definition 与 Tier 2 owner 复用。

`PathDefaultSchema` 是 Core Scope owner 显式由 `GraphicStyleSchema`、`PathStrokeSchema`、`PathFillSchema` 和去掉 `children` 的 `PathGeometrySchema` 组合出的默认通道。它排除 instance、structure、decoration 字段和 `children`，不从完整 Path 偶然投影，也不是独立 compile 入口。默认 `stroke` path 消费其中全部适用字段。各 Tier 2 owner 仍可在此基础上保留自己的默认值和字段限制。

React `<Path thickness>` 是组件 / builder 语法糖，会在生成 IR 前换算成 `strokeWidth`，不属于 `PathSchema`；完整档位见 [Path 样式](/kernel/components/draw/path#样式)。

## 几何标签

`GeometryLabelSchema` 是 path-like 宿主共用的几何标签契约。`StepLabelSchema` 是这个 schema 的别名；除 move / cycle 之外的绘制 step 与可选 Standard Ribbon 的 `centerline` 标签都复用同一套字段。
它描述标签文字、沿宿主中心线或段的归一化位置，以及相对切线 / 法线的偏移方式。

`interrupt` 只在这里声明 JSON 形态，不是所有宿主都支持的绘图能力。Core resolve 在知道最终 Path kind 与有效 fill 后决定策略：无填充内置 `stroke` Path 的 canonical `center` 标签省略时自动断线，`sloped: true` 而未给 `side` 也属于该情况。`false` 保持连续，`true` 可强制非居中标签断线；有效 fill 上的 `true`，以及 Ribbon、custom 或其它非内置 Stroke Path 上的任意显式布尔值都会 fail-loud。

## 目标点

`TargetSchema` 是路径端点的 union：笛卡尔 / 极坐标 / 节点引用对象 `{ id, anchor?, offset?, boundary? }` / 偏移定位 `{ of, offset }` / 比例定位 `{ between, fraction }` / 相对偏移（relative / relativeAccumulate）。节点引用对象里 `boundary?` 单边覆盖本端点贴向的连接面（缺省取节点自身 `boundary`，默认 `shape`）；`anchor?` 缺省时自动贴边裁剪。字符串节点 id 是 React DSL 的便捷写法，会在进入 IR 前解析成对象：
