title: Scene Primitives
description: Look up the Scene, resources, structured primitives, and renderer boundary produced by compile
---

Scene primitives are the output contract of `compileToScene(...).scene`: after IR is laid out, the result no longer contains React, JSX, or Zod schemas. It is a structured drawing model that renderers can consume directly.

## Scene

| Type     | Fields             | Notes                                                                                                                                                                          |
| -------- | ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `Scene`  | `primitives`       | Laid-out primitive array, in render order                                                                                                                                      |
| `Scene`  | `layout`           | Scene bounds `{ x, y, width, height }`                                                                                                                                         |
| `Scene`  | `resources?`       | Renderer-agnostic resource table `Array<SceneResource>` (gradient / pattern / clip paint servers); the adapter materializes them (SVG → `<defs>`). Omitted when there are none |
| `Scene`  | `animations?`      | Scene-root (camera) timeline tracks `Array<IRAnimationTrack>` (viewBox property), passed through from the IR root `animations`. Omitted when there are none                    |
| `Layout` | `x` / `y`          | Top-left layout coordinate                                                                                                                                                     |
| `Layout` | `width` / `height` | Layout size                                                                                                                                                                    |

`ScenePrimitive` is a union of five primitives: `RectPrim | EllipsePrim | TextPrim | PathPrim | GroupPrim`. A custom renderer must consume `resources` and `animations`, otherwise gradients / clipping / camera animations are lost.

## Resources

`SceneResource = PaintResource | ClipResource`. A primitive's `PaintValue.resourceRef` and `GroupPrim.clipRef` store only an id; the renderer adapter materializes platform resources and resolves those references.

| Resource        | Fields                | Notes                                                                          |
| --------------- | --------------------- | ------------------------------------------------------------------------------ |
| `PaintResource` | `kind:'paint'` / `id` | `spec` stores `IRPaint`; a pattern may also carry the compile-resolved `tile?` |
| `ClipResource`  | `kind:'clip'` / `id`  | `path` stores a canonical `SceneClipPath` in user coordinates                  |

`ClipResource.path` has one renderer-neutral structure:

| Field      | Type                       | Notes                                                                |
| ---------- | -------------------------- | -------------------------------------------------------------------- |
| `commands` | `Array<PathCommand>`       | Validated commands canonicalized to stable field order and precision |
| `fillRule` | `'nonzero'` \| `'evenodd'` | Always explicit; an omitted provider value materializes as `nonzero` |

Complete Clip Definitions resolve authored specs and lower them into canonical paths during compile. Renderers neither consult IR schemas / provider registries nor interpret custom clip kinds; they consume only the resolved `spec`, `tile`, `path`, and primitive references here. The old `ClipResource.shape` contract is rejected.

## Shape Primitives

| Primitive     | Key fields                     | Notes                                                                                                                                                                 |
| ------------- | ------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `RectPrim`    | `x` / `y` / `width` / `height` | Top-left positioned rectangle; `cornerRadius` maps to both rx and ry                                                                                                  |
| `EllipsePrim` | `cx` / `cy` / `rx` / `ry`      | Center plus radii; circles use `rx === ry`; `rotate?` rotates degrees around the center                                                                               |
| `TextPrim`    | `x` / `y` / `lines`            | Text block; `align` / `baseline` define anchor semantics                                                                                                              |
| `PathPrim`    | `commands`                     | Structured path command array; also `fillRule` (`nonzero` / `evenodd`), `strokeLinecap` (`butt` / `round` / `square`), `strokeLinejoin` (`miter` / `round` / `bevel`) |
| `GroupPrim`   | `transforms` / `children`      | Child primitives wrapped in structured transforms; `clipRef?` points to a ClipResource in `Scene.resources`, clipping the whole group to that region when set         |

Every primitive carries the interaction-layer contract fields `id?` (stable anchor for `data-retikz-id` / hit-test), `meta?` (provenance metadata passed through from the IR element's `meta`; renderers ignore it, it never reaches the DOM), and `animations?` (timeline tracks; played when supported, otherwise the settled static state is rendered with a warning).

Shape primitives share common visual fields such as `fill`, `fillOpacity`, `stroke`, `strokeOpacity`, `strokeWidth`, `dashPattern`, `dashOffset`, and `opacity`. The `fill` and `stroke` of `RectPrim` / `EllipsePrim` / `PathPrim` are `PaintValue`s (CSS color string / a paint server referencing the resource table / `contextStroke`), not just strings. Not every primitive supports every field; for example, `TextPrim.fill` (string only) is text color.

Element-level visual effects only live on renderable main geometry primitives:

| Field        | Applies to                              | Notes                                                                        |
| ------------ | --------------------------------------- | ---------------------------------------------------------------------------- |
| `shadow?`    | `RectPrim` / `EllipsePrim` / `PathPrim` | Resolved `ResolvedDropShadow`; renderers materialize it as a platform shadow |
| `blendMode?` | `RectPrim` / `EllipsePrim` / `PathPrim` | `BlendModeValue`; renderers map it to the target platform's blend mode       |

`TextPrim` does not support element-level `shadow` / `blendMode`. `GroupPrim` currently only carries `transforms`, `clipRef`, `children`, and the common `id` / `meta` / `animations`; it has no group-level effect fields. Visual effects do not change a primitive's hit area; interaction should still use `id` / `meta` plus an external hit-test / hydration layer.

### Canonical visual bounds

A layout-aware composite's `layoutChild().visualBounds` is computed from the final static primitive tree; it is not an alias for `slotSize` or `allocationBounds`. A proposal describes parent availability, the slot is the origin-free result of evaluating that proposal, allocation is the child's real layout occupancy, and visual bounds describe only final ink. Renderers participate in none of these evaluations.

The visual envelope covers rectangles, rotated ellipses, text, complete path-command hulls, arrow markers, shadows, clips, and recursive group transforms. A paint contributes no geometry when its `fillOpacity` / `strokeOpacity` is explicitly `0`; CSS colors whose alpha cannot be resolved statically remain conservatively visible. Stroke joins use the canonical miter upper bound of `10`, which covers current renderer defaults and avoids backend- or composite-specific bounds guesses.

A layout-aware replay wrapper emits an equivalent `GroupPrim` around each replay root only when it has a non-empty `transforms` list or a `clip`; without an effective wrapper field, the original primitive is preserved. An inner transform group first places the child in parent allocation coordinates, then an outer `clipRef` clips in that parent coordinate system. Clipping tightens the final committed Scene's compile visual bounds, but it neither changes allocation bounds nor rewrites an earlier `LayoutChildResult.visualBounds`. Each root is wrapped independently, so roots with different zIndex values are not collapsed into one sorting unit.

Static / settled here means the static Scene state produced by compile. Animation does not expand this envelope; a capability that needs whole-animation bounds must solve that separately.

## Text

| Type       | Fields                                                                            | Notes                                                     |
| ---------- | --------------------------------------------------------------------------------- | --------------------------------------------------------- |
| `TextPrim` | `lines`                                                                           | At least one `TextLine`                                   |
| `TextPrim` | `fontSize` / `fontFamily?` / `fontWeight?` / `fontStyle?`                         | Block-level font defaults                                 |
| `TextPrim` | `lineHeight`                                                                      | Vertical distance between adjacent lines                  |
| `TextPrim` | `measuredWidth` / `measuredHeight`                                                | Text block metrics computed during compile                |
| `TextLine` | `text`                                                                            | Line content                                              |
| `TextLine` | `fontSize?` / `fontFamily?` / `fontWeight?` / `fontStyle?` / `fill?` / `opacity?` | Per-line override; missing fields inherit from `TextPrim` |

Renderers do not need to decide text layout again. They consume the anchor, line height, metrics, and line-level overrides in `TextPrim`.

## Path Commands

`PathPrim.commands` is structured path data, not an SVG `d` string. Adapters translate it to their target platform at render time.

| Command      | Fields                                                                                           | Notes                           |
| ------------ | ------------------------------------------------------------------------------------------------ | ------------------------------- |
| `move`       | `to`                                                                                             | Move cursor without drawing     |
| `line`       | `to`                                                                                             | Straight line                   |
| `quad`       | `control` / `to`                                                                                 | Quadratic Bezier                |
| `cubic`      | `control1` / `control2` / `to`                                                                   | Cubic Bezier                    |
| `arc`        | `center` / `radius` / `startAngle` / `endAngle` / `counterClockwise?`                            | Circular arc, angles in degrees |
| `ellipseArc` | `center` / `radiusX` / `radiusY` / `rotation?` / `startAngle` / `endAngle` / `counterClockwise?` | Elliptical arc                  |
| `close`      | —                                                                                                | Close back to the latest move   |

Coordinates use user units. Angles follow the screen-coordinate convention: `0 = +x`, `90 = +y`.

## Arrows

`PathPrim.arrowStart` / `arrowEnd` use `ResolvedArrowEnd`. Note: all visual inputs (`scale` / `length` / `width` / `color` / `fill` / `lineWidth`) are **consumed during the compile resolve phase** and do **not** appear in this structure. What gets attached is a "resolved marker description" — internal geometry plus wrapper params; the adapter only **materializes** it (embeds it in a `<marker>` or draws it on Canvas), with no switch, no `emit` call, and no arrows-registry lookup:

| Field          | Type                     | Notes                                                                                                                                |
| -------------- | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| `shape`        | `ArrowShapeValue`        | Shape name; rendering no longer depends on it after resolution — kept for identity / debugging                                       |
| `baseSize`     | `number`                 | Marker viewBox side length; the adapter derives viewBox `0 0 baseSize baseSize` and refY = baseSize/2                                |
| `refX`         | `number`                 | Line contact point (marker refX); hollow shapes already subtract lineWidth/2 during compile                                          |
| `markerWidth`  | `number`                 | Resolved tip length = (`length ?? def.defaultLength`) × scale                                                                        |
| `markerHeight` | `number`                 | Resolved tip width = (`width ?? def.defaultWidth`) × scale                                                                           |
| `opacity?`     | `number`                 | Marker element-level opacity 0..1; inherits the path opacity when omitted                                                            |
| `marker`       | `Array<MarkerPrimitive>` | `def.emit` output: internal geometry in the local baseSize coordinate space (`fill` limited to `string \| { kind:'contextStroke' }`) |

The compile layer has already resolved endpoint arrow entries from core IR `marks` into `ResolvedArrowEnd`: it looks up the effective arrow table, calls `def.emit` to produce geometry, and shrinks path endpoints. Renderers do not need to know the arrow registry or recompute visual sizes.

### Marker primitive subset

`ResolvedArrowEnd.marker` does not accept the full `ScenePrimitive` union. It uses a narrow subset in marker-local coordinates:

| Type                | Expresses                                 |
| ------------------- | ----------------------------------------- |
| `MarkerPathPrim`    | Structured path commands and basic paints |
| `MarkerEllipsePrim` | Circles and ellipses                      |
| `MarkerRectPrim`    | Rectangles and rounded rectangles         |
| `MarkerGroupPrim`   | Transforms and nested marker primitives   |

This subset excludes text, recursive arrows, external `resourceRef` values, and clips. `MarkerGroupPrim` can compose and transform child primitives but cannot bypass those restrictions.

## Transforms

`GroupPrim.transforms` is an ordered list of structured transforms:

| Transform   | Fields                    | Notes                                               |
| ----------- | ------------------------- | --------------------------------------------------- |
| `translate` | `x` / `y`                 | Translation                                         |
| `rotate`    | `degrees` / `cx?` / `cy?` | Rotation; defaults to origin when center is omitted |
| `scale`     | `x` / `y?`                | Scaling; `y` defaults to `x`                        |

This layer intentionally excludes SVG-only or Canvas-only features such as filters, markers, or image data. Adapters translate the common structure into whatever their platform supports.

For platform materialization behavior, continue to the [SVG renderer](/kernel/packages/render/render-svg) and [Canvas renderer](/kernel/packages/render/render-canvas).
