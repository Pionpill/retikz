For readers who want to understand how retikz works, contribute code, or write an adapter for a new framework.

The official repo currently maintains six kernel packages:

| Package                                                                                          | Role                                                                                                                                    | Status                |
| ------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------- | --------------------- |
| [`@retikz/math`](https://github.com/Pionpill/retikz/tree/next-kernel/packages/kernel/math)       | Zero-dependency pure computational geometry (vectors / affine / arc / intersections / circles / hull); the compute base core depends on | Officially maintained |
| [`@retikz/core`](https://github.com/Pionpill/retikz/tree/next-kernel/packages/kernel/core)       | IR schemas, geometry, parsers, and the Scene compiler; zero React, zero DOM                                                             | Officially maintained |
| [`@retikz/render`](https://github.com/Pionpill/retikz/tree/next-kernel/packages/kernel/render)   | Renderer-neutral Scene output adapters: SVG descriptors/strings, Canvas 2D, hydration helpers, and animation runtime utilities          | Officially maintained |
| [`@retikz/react`](https://github.com/Pionpill/retikz/tree/next-kernel/packages/kernel/react)     | React adapter: JSX components that compile to IR, then render through SVG or Canvas                                                     | Officially maintained |
| [`@retikz/vanilla`](https://github.com/Pionpill/retikz/tree/next-kernel/packages/kernel/vanilla) | Framework-neutral foundation: Input helpers, processing, SVG/Canvas mounting, hydration, animation controls, and SVG string output      | Officially maintained |
| [`@retikz/tex`](https://github.com/Pionpill/retikz/tree/next-kernel/packages/kernel/tex)         | Optional LaTeX integration: MathJax SVG glyph paths lowered into the renderer-agnostic Scene model                                      | Officially maintained |

Vue / Svelte / Solid / Native adapters are still future or community surfaces, but the IR remains universal: a new framework adapter can reuse `@retikz/core` and most renderer work from `@retikz/render`, then supply its own component bridge and text measurer where needed.

## @retikz/core

Zero-React, zero-DOM. `zod` is the only runtime dependency.

### Package Layout

| Module                                                                                                                                                                                                        | Responsibility                                                                                                                                                                                                                                                                                                   |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [`schemas/`](https://github.com/Pionpill/retikz/tree/next-kernel/packages/kernel/core/src/schemas)                                                                                                            | IR schema (zod) — position / node / coordinate / path / step / scope / paint / clip / scene, all defined with zod                                                                                                                                                                                                |
| [`shared/geometry/`](https://github.com/Pionpill/retikz/tree/next-kernel/packages/kernel/core/src/shared/geometry)                                                                                            | Reusable core geometry helpers — rect / circle / ellipse / diamond / polar / contour / bend / segment; pure compute primitives (vectors / affine / arc / intersections / circles / hull) live in [`@retikz/math`](https://github.com/Pionpill/retikz/tree/next-kernel/packages/kernel/math), re-exported by core |
| [`contract/scene/`](https://github.com/Pionpill/retikz/tree/next-kernel/packages/kernel/core/src/contract/scene)                                                                                              | Scene data model — render-target-agnostic primitives, resources, markers, and clipping; `primitive/` remains only as compatibility re-exports                                                                                                                                                                    |
| [`compile/`](https://github.com/Pionpill/retikz/tree/next-kernel/packages/kernel/core/src/compile)                                                                                                            | IR → Scene compiler — node layout, path resolution, style cascade, resource collection, layout                                                                                                                                                                                                                   |
| [`parse/`](https://github.com/Pionpill/retikz/tree/next-kernel/packages/kernel/core/src/parse)                                                                                                                | DSL → IR parsers — currently the Sugar `way` array and `target` strings                                                                                                                                                                                                                                          |
| [`contract/`](https://github.com/Pionpill/retikz/tree/next-kernel/packages/kernel/core/src/contract) / [`providers/`](https://github.com/Pionpill/retikz/tree/next-kernel/packages/kernel/core/src/providers) | v0.2 extension surfaces — custom shapes, arrows, pattern motifs, and path generators                                                                                                                                                                                                                             |
| [`index.ts`](https://github.com/Pionpill/retikz/blob/next-kernel/packages/kernel/core/src/index.ts)                                                                                                           | Public API surface — every adapter must import from this file only                                                                                                                                                                                                                                               |

### Recommended Reading Order

Walk inward from both ends: input contract (IR) first, then output contract (Scene), then the `compile` step that bridges them.

1. **[`src/index.ts`](https://github.com/Pionpill/retikz/blob/next-kernel/packages/kernel/core/src/index.ts) — Public API**<br />
   Skim the named re-exports. What `@retikz/core` exposes (and doesn't) lives here; every adapter must import from this single file.

2. **[`schemas/scene/schema.ts`](https://github.com/Pionpill/retikz/blob/next-kernel/packages/kernel/core/src/schemas/scene/schema.ts) — IR root**<br />
   `SceneSchema = { version, type: 'scene', children: ChildSchema[] }`; `ChildSchema` is a discriminated union of node / path / coordinate / scope.

3. **[`schemas/node/schema.ts`](https://github.com/Pionpill/retikz/blob/next-kernel/packages/kernel/core/src/schemas/node/schema.ts) + [`schemas/path/`](https://github.com/Pionpill/retikz/tree/next-kernel/packages/kernel/core/src/schemas/path) + [`schemas/position/`](https://github.com/Pionpill/retikz/tree/next-kernel/packages/kernel/core/src/schemas/position) — IR fields**<br />
   Read the zod schemas with their `.describe(...)` text. Each `.describe` is the LLM tool-use contract — schema and field semantics in one place.

4. **[`contract/scene/`](https://github.com/Pionpill/retikz/tree/next-kernel/packages/kernel/core/src/contract/scene) — Scene output**<br />
   `Scene = { primitives, layout, resources? }`. Primitives and resources are the render-target-agnostic common subset every adapter consumes; SVG-only / Canvas-only features are forbidden.

5. **Geometric foundation**<br />
   Pure functions + plain data, no classes. Pure compute primitives (vectors / affine / `arc` / intersections / circles / hull) live in the standalone [`@retikz/math`](https://github.com/Pionpill/retikz/tree/next-kernel/packages/kernel/math) package, re-exported by core; reusable shape / boundary / path geometry helpers live in [`shared/geometry/`](https://github.com/Pionpill/retikz/tree/next-kernel/packages/kernel/core/src/shared/geometry), and `geometry/` remains only as compatibility re-exports.

6. **[`compile/compile.ts`](https://github.com/Pionpill/retikz/blob/next-kernel/packages/kernel/core/src/compile/compile.ts) — Compiler entry**<br />
   `compileToScene(ir, options): CompileResult`. The main flow recursively processes children, lays out nodes and scopes, resolves paths, and collects Scene resources plus typed artifacts in the same compile. Reading it shows how IR becomes `result.scene` and `result.artifacts`.

7. **[`compile/node/`](https://github.com/Pionpill/retikz/tree/next-kernel/packages/kernel/core/src/compile/node) / [`path/`](https://github.com/Pionpill/retikz/tree/next-kernel/packages/kernel/core/src/compile/path) / [`position.ts`](https://github.com/Pionpill/retikz/blob/next-kernel/packages/kernel/core/src/compile/position.ts) — Sub-compilers**<br />
   Drill in as needed: node layout / path stepping / position resolution. [`text/metrics.ts`](https://github.com/Pionpill/retikz/blob/next-kernel/packages/kernel/core/src/compile/text/metrics.ts) ships a fallback measurer; adapters can inject a more accurate one.

8. **[`parse/`](https://github.com/Pionpill/retikz/tree/next-kernel/packages/kernel/core/src/parse) — Standalone grammar entry (optional)**<br />
   [`parseWay`](https://github.com/Pionpill/retikz/blob/next-kernel/packages/kernel/core/src/parse/way.ts) / [`parseTargetSugar`](https://github.com/Pionpill/retikz/blob/next-kernel/packages/kernel/core/src/parse/target-sugar.ts) handle standalone path and target string grammar. Vanilla `normalizePath` dispatches them to normalize typed InputPath into Core IR; React does not call them directly.

9. **Registry extension surfaces (optional)**<br />
   [`contract/`](https://github.com/Pionpill/retikz/tree/next-kernel/packages/kernel/core/src/contract) / [`providers/`](https://github.com/Pionpill/retikz/tree/next-kernel/packages/kernel/core/src/providers): third-party packages should start from `contract/`; built-in implementations and registry merging live under `providers/`.

### Constraints to Keep in Mind

Keep these constraints in mind when reading core; they explain why some implementation paths go through an extra layer instead of depending directly on the browser or React:

- **Zero React, zero DOM** — core must not `import 'react'` / `import 'react-dom'`; browser-specific capabilities (text measurement, events) are injected by the adapter.
- **IR data is 100% JSON-serializable** — no functions, class instances, refs, or Symbols in the IR schema.
- **Geometry uses pure functions + plain data only** — no classes; function bundles are exposed as `const ns = { method1, method2 }` namespaces.
- **`compileToScene` is a pure function** — same IR + same options ⇒ identical Scene and artifacts; no `Math.random()`, `Date.now()`, or module-level mutable state.
- **Runtime dependency allowlist** — `zod` only; new runtime deps must be justified in the PR description.

## @retikz/react

`peerDependencies: react / react-dom`. The package turns JSX into IR, calls `compileToScene` for Scene plus artifacts, and renders the Scene through SVG or Canvas.

### Package Layout

| Module                                                                                               | Responsibility                                                                                                                                                                                  |
| ---------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [`kernel/`](https://github.com/Pionpill/retikz/tree/next-kernel/packages/kernel/react/src/kernel)    | React DSL Kernel — `components` hold marker components, `protocol` holds shared recognition contracts, `adapter` bridges JSX → InputScene, and `runtime` hosts `<Layout>` plus hydration wiring |
| [`sugar/`](https://github.com/Pionpill/retikz/tree/next-kernel/packages/kernel/react/src/sugar)      | Sugar JSX components — `path` holds `<Draw>` / `<EdgeLabel>`, and `shapes` holds shape sugar; all expand into Kernel at compile time and introduce no new capabilities                          |
| [`render/`](https://github.com/Pionpill/retikz/tree/next-kernel/packages/kernel/react/src/render)    | React result-host wiring — `processing-result`, `svg`, `canvas`, and `text` handle processing results, SVG, CanvasHost, and the browser measurer                                                |
| [`index.ts`](https://github.com/Pionpill/retikz/blob/next-kernel/packages/kernel/react/src/index.ts) | Public API surface — Kernel + Sugar components, `createInputScene`, and `convertIRToReactNode`                                                                                                  |

### Recommended Reading Order

1. **[`src/index.ts`](https://github.com/Pionpill/retikz/blob/next-kernel/packages/kernel/react/src/index.ts) — Public API**<br />
   See the exported Kernel / Sugar components, prop types, and adapter bridges. Core grammar vocabulary remains exported by its Core owner; React exposes only its JSX entry points.

2. **[`kernel/Layout.tsx`](https://github.com/Pionpill/retikz/blob/next-kernel/packages/kernel/react/src/kernel/runtime/Layout.tsx) — Top-level orchestrator**<br />
   `<Layout>` is the entry point of the whole pipeline: children → `createInputScene` → Vanilla processing (normalization, Core Program, runtime) → `ProcessingResultHost`, with same-compile artifacts published after commit. One file gives you the adapter's overall shape.

3. **[`kernel/input-scene.ts`](https://github.com/Pionpill/retikz/blob/next-kernel/packages/kernel/react/src/kernel/adapter/input-scene.ts) — JSX → InputScene**<br />
   Dispatches by child `displayName` to construct authoring InputNode / InputPath / InputStep / InputScope values and collect Tier 2 `InputEmbedAdapter` values; it does not parse Core authoring grammar. The companion [`unbuilder.ts`](https://github.com/Pionpill/retikz/blob/next-kernel/packages/kernel/react/src/kernel/adapter/unbuilder.ts) goes the other way (IR → React element tree), useful for editor / AI workflows that "feed IR, render components".

4. **[`kernel/Node.tsx`](https://github.com/Pionpill/retikz/blob/next-kernel/packages/kernel/react/src/kernel/components/Node.tsx) / [`Path.tsx`](https://github.com/Pionpill/retikz/blob/next-kernel/packages/kernel/react/src/kernel/components/Path.tsx) / [`Step.tsx`](https://github.com/Pionpill/retikz/blob/next-kernel/packages/kernel/react/src/kernel/components/Step.tsx) etc. — Kernel components**<br />
   These components don't render anything themselves — they only declare a `displayName` and hand props to the Input collector. Read one and you've read them all.

5. **[`render/processing-result.tsx`](https://github.com/Pionpill/retikz/blob/next-kernel/packages/kernel/react/src/render/processing-result.tsx) — ProcessingResult → React host**<br />
   React only maps Vanilla's readonly processing result to SVG or Canvas, then binds hydration, animation, and artifact notifications. A different framework can reuse Vanilla processing and replace only this host layer.

6. **[`render/text/browser-measurer.ts`](https://github.com/Pionpill/retikz/blob/next-kernel/packages/kernel/react/src/render/text/browser-measurer.ts) — Text measurer injection**<br />
   A canvas-`measureText`-based `TextMeasurer`, injected into Core compilation through Vanilla processing's `CompileOptions.measureText`. When there's no document (SSR), it falls back to core's `fallbackMeasurer` automatically.

7. **[`sugar/Draw.tsx`](https://github.com/Pionpill/retikz/blob/next-kernel/packages/kernel/react/src/sugar/path/Draw.tsx) — Sugar forwarding**<br />
   `<Draw way={[...]}>` only forwards its props to Kernel `<Path>`. Vanilla `normalizePath` then parses `way` and emits Core Path steps; Sugar introduces no new drawing capability.

8. **Shape components in [`sugar/shapes/`](https://github.com/Pionpill/retikz/tree/next-kernel/packages/kernel/react/src/sugar/shapes) (optional)**<br />
   `<Circle>` / `<Ellipse>` / `<Arc>` / `<Sector>` / `<Rectangle>` / `<RegularPolygon>` / `<Star>` are Sugar too: they expand common geometry idioms into equivalent `<Path>` declarations. Standard `Grid` is instead a Tier 2 composite with its own persistent IR.

### Mapping when writing a new adapter

If you're building `@retikz/vue` / `@retikz/svelte` / etc., the React adapter maps over like this:

| In React                                          | Your new adapter needs                                                              |
| ------------------------------------------------- | ----------------------------------------------------------------------------------- |
| `kernel/*.tsx` components (declare `displayName`) | Equivalent component types in your framework (with a recognizable marker)           |
| `kernel/input-scene.ts` (JSX → InputScene)        | A children / vnode → InputScene bridge that reuses Vanilla normalization            |
| `render/processing-result.tsx`                    | Connecting a Vanilla processing result to your framework's native host              |
| `render/text/browser-measurer.ts`                 | A measurer for your environment (browser / SSR / Native) — implement `TextMeasurer` |

`@retikz/core`'s IR, `compileToScene`, `shared/geometry` helpers, and `contract/scene` types are reused unchanged — no need to rewrite them.
