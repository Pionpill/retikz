Most applications start from an adapter ending in `-react` or `-vanilla`; adapters connect domain capabilities to a React or plain JavaScript host. Domain packages without a suffix own IR, resolution, and compilation. Foundation packages are normally read directly only for extensions, diagnostics, or lower-level integration.

React and Vanilla share the same drawing semantics. React uses JSX in a component tree; Vanilla uses objects and functions in a non-React application, server-side rendering, or an application-managed host.

## Read the documentation

Sidebar entries and the icon beside a page title show its reading difficulty. The level describes the task you should complete after reading, not the page length or amount of code.

| Level     | Keyword    | Read it when                                                                                              |
| --------- | ---------- | --------------------------------------------------------------------------------------------------------- |
| Beginner  | Use        | You want to complete a figure or a focused feature with existing APIs                                     |
| Advanced  | Customize  | You need to combine capabilities, understand configuration constraints, or write code for a specific case |
| Internals | Principles | You need to extend Retikz, diagnose a complex issue, or debug performance and runtime behavior            |

Complete a beginner example first, then follow the problem into advanced pages. Read internals pages only when the problem needs a mechanism-level explanation. A beginner page may link to deeper material without making it required reading.
