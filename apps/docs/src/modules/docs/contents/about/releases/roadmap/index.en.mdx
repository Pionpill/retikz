Retikz's roadmap covers the whole drawing framework: strengthen shared foundations first, then advance higher-level expressions such as relationship diagrams, flowcharts, charts, and tables. Each group has its own responsibilities and version lines; Kernel's progress does not represent the entire project.

This roadmap describes current directions, not fixed release dates. Undecided plans remain blank. Consult each package family's release records for version-specific changes.

## Groups and dependency boundaries

| Group     | Responsibility                                                                                                | Dependencies and boundaries                                                         |
| --------- | ------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| Kernel    | Foundational contracts, geometry, incremental execution, drawing compilation, rendering, and host integration | Provides shared foundations without depending on Library, Schematic, or Viz         |
| Library   | Cross-domain graphics and container layout capabilities                                                       | Builds on Kernel; does not own flowchart or data-mapping semantics                  |
| Schematic | Entities, relationships, logical diagrams, and flowcharts                                                     | Reuses Kernel / Library as needed; owns its domain models and algorithms            |
| Viz       | Data processing, graphics grammar, common charts, and two-dimensional tables                                  | Drawing packages reuse Kernel / Library as needed; Data handles data, not rendering |

Dependencies within each group are also explicit. Depending on a lower layer means consuming its capabilities, not copying its implementation:

- **Library**: Layout provides domain-neutral container arrangement. Standard may consume Layout to provide general-purpose graphics; Layout does not depend on Standard.
- **Schematic**: Diagram depends on Graph. Graph provides entities, relationships, and composable diagram semantics; Diagram builds complete figures and automatic layout on top. Flow is a Diagram capability exposed through `@retikz/diagram/flow`, not a separate `@retikz/flow` package.
- **Viz**: Chart depends on Plot to translate common chart intentions into graphics grammar. Plot consumes Data's processing capabilities. Table also reuses Data but does not depend on Plot; graphical cell content enters through general drawing composition.

When higher layers encounter gaps, general drawing mechanisms belong in Kernel, cross-domain graphics and arrangement belong in Library, and flowchart- or visualization-specific semantics remain in their domains. React / Vanilla adapters follow their package families without creating parallel algorithms or drawing semantics.

## Development cadence

The overall cadence alternates between odd and even minor versions. The minor is the middle segment of `MAJOR.MINOR.PATCH`.

| Minor version                 | Focus                            | Approach                                                                                                      |
| ----------------------------- | -------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| Odd, such as `0.5` and `0.7`  | Add foundational capabilities    | Establish ownership, contracts, and a minimum usable implementation, then verify consumption by higher layers |
| Even, such as `0.6` and `0.8` | Refine foundational capabilities | Prioritize performance, correctness, edge cases, tests, documentation, and usability                          |

This expansion-then-refinement cadence does not replace the compatibility rules in [Versioning](/about/releases/versioning), or require every package to adopt the same version simultaneously. Kernel packages share a version; Standard, Layout, Graph, Diagram, Data, Plot, Chart, and Table evolve separately.

Foundational packages mature first, followed by their consumers. For example, improve Data processing before Plot adopts it; once Plot's graphics grammar is stable, Chart can complete common chart abstractions. Graph and Diagram follow the same order. Independent work can proceed separately.

## Short-term plans

Status follows the minor version: odd means Add, even means Refine. The table lists primary capability packages; React / Vanilla adapters follow.

Versions show only the major, minor, and patch segments of the current development version, omitting prerelease suffixes; they do not imply stable releases.

| Group     | Package              | Version | Status | Description                                            |
| --------- | -------------------- | ------- | ------ | ------------------------------------------------------ |
| Kernel    | `@retikz/core`, etc. | `0.5.0` | Add    | Performance optimization and foundational capabilities |
| Library   | `@retikz/standard`   | `0.1.0` | Add    | General drawing capabilities driven by other groups    |
|           | `@retikz/layout`     | `0.1.0` | Add    | Layout capabilities driven by other groups             |
| Schematic | `@retikz/graph`      | `0.1.0` | Add    | Refine basic logical diagrams                          |
|           | `@retikz/diagram`    | `0.1.0` | Add    | Add flowchart capabilities                             |
| Viz       | `@retikz/data`       | `0.2.0` | Refine | Refine data processing                                 |
|           | `@retikz/plot`       | `0.2.0` | Refine | Refine the grammar of graphics                         |
|           | `@retikz/chart`      | `0.1.0` | Add    | Complete basic chart abstractions                      |
|           | `@retikz/table`      | `0.1.0` | Add    | Build foundational table expression                    |

These foundations and their direct consumers take priority. Unspecified chart types, algorithms, or product capabilities do not yet receive target versions or deadlines.

## Long-term plans

The following long-term goals cover the current development version and its subsequent refinement version.

| Group     | Package              | Version       | Content                                                                                      |
| --------- | -------------------- | ------------- | -------------------------------------------------------------------------------------------- |
| Kernel    | `@retikz/core`, etc. | `0.5 - 0.6`   | Performance optimization: runtime development, diff algorithms, and incremental rendering    |
|           |                      | `0.7 - 0.8`   | Build interaction capabilities and refine animation                                          |
|           |                      | `0.9 - 0.10`  | Build cross-package composition capabilities                                                 |
|           |                      | `0.11 - 0.12` | LLM incremental rendering, LLM-friendly refinements, and API stabilization                   |
| Schematic | `@retikz/graph`      | `0.1 - 0.2`   | Refine basic logical diagrams and encapsulate common Blocks                                  |
|           | `@retikz/diagram`    | `0.1 - 0.2`   | Flowcharts                                                                                   |
| Viz       | `@retikz/data`       | `0.2`         | Optimize data processing and refine transforms                                               |
|           | `@retikz/plot`       | `0.2`         | Optimize the grammar of graphics, develop layout algorithms, and refactor coordinate systems |
|           |                      | `0.3 - 0.4`   | Performance optimization and interaction capabilities                                        |
|           |                      | `0.5 - 0.6`   | Multi-chart composition                                                                      |
|           | `@retikz/chart`      | `0.1 - 0.2`   | Common chart abstractions                                                                    |
|           | `@retikz/table`      | `0.1 - 0.2`   | Build foundational table capabilities                                                        |

Library generally responds to requirements from other packages and has no major standalone plans.
