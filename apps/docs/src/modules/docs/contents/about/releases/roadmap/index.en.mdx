The roadmap is a **goal list, not a promise** — it adjusts with community feedback and maintainer bandwidth. Concrete releases land by version in the [Changelog](/kernel/releases/changelog).

## Now

| Item                     | Status                                              |
| ------------------------ | --------------------------------------------------- |
| Six kernel packages      | ✅ `0.4.0-rc.1` lockstep                            |
| boundary fit / gap       | ✅ Shape-aware fitting and signed spacing converged |
| Canvas shadow opacity    | ✅ Named-color / HSL combinations fixed             |
| installation / packaging | 🧪 Release-candidate acceptance in progress         |

## Short Term: RC Acceptance

RC freezes v0.4's public surface: complete real installation and packaging acceptance first, then use compatibility bugs to decide whether another RC patch is needed before stable. New mechanisms stay in v0.5.

| Track       | Candidate                                | Content                                                                                                                 |
| ----------- | ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| v0.5 alpha  | headless interaction                     | Core provides target / intent / manifest contracts; tooltip / select UI and state machines stay in adapters or userland |
| v0.5 alpha  | Progressive / JSON Patch                 | Incremental rendering, AI step updates, local SVG / Canvas update strategies                                            |
| v0.4 RC     | compatible bugs / acceptance             | Add no capability; focus installation, artifact, documentation, and migration guidance acceptance                       |
| v0.4 stable | final-release preparation                | Publish when RC acceptance has no blockers; after stable, accept only SemVer patch fixes                                |
| Longer term | P3D / scope enrichment / blur-mask-layer | Pseudo-3D, `boundingShape` polygon / ellipse / padding, and visual-layer capabilities wait for stronger design pull     |

## Current v0.4 Shape

Kernel v0.4 has landed several base mechanisms that other layers can reuse.

| Goal               | Content                                                                                                     |
| ------------------ | ----------------------------------------------------------------------------------------------------------- |
| `@retikz/math`     | Zero-dependency geometry: vectors, affine transforms, arcs, intersections, hulls, minimal enclosing circles |
| `@retikz/tex`      | MathJax SVG lowering through `lowerTex`, with `$...$` / `{ runs }` inside text                              |
| Scene visuals      | `shadow` / `blendMode` plus existing `zIndex` as renderer-agnostic visual foundations                       |
| Path kind / ribbon | `Path.kind` provider and `kind="ribbon"` relation paths                                                     |
| Provider contract  | Unified registry model for shape / boundary / clip / path kind / composite extension surfaces               |

## Long term

| Topic            | Where                                                                       |
| ---------------- | --------------------------------------------------------------------------- |
| v0.4 RC / stable | API freeze, installation acceptance, docs and changelog audit               |
| v1+              | Domain packages such as `plot` / `viz` / `flow`, plus the broader ecosystem |

## Not on the roadmap

To keep scope honest, things we are **not** doing:

- Core directly depending on MathJax or putting a formula engine into IR
- Visual editor
- Full TikZ library-loading semantics
- Complete calc expression language
- Complex decorations such as `snake` / `coil`
- Canvas implemented by piping through SVG
