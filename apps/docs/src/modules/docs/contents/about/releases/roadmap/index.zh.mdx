Retikz 的路线图围绕整个绘图框架展开：先把共用底座做扎实，再让关系图、流程图、图表与表格等上层表达跟进。各组有自己的职责与版本线，不以 Kernel 的进度代表整个项目。

路线图描述当前方向，不承诺固定发布日期。尚未确定的规划留空，具体版本内容以对应包家族的发布记录为准。

## 分组与依赖边界

| 组        | 职责                                                       | 依赖与边界                                                 |
| --------- | ---------------------------------------------------------- | ---------------------------------------------------------- |
| Kernel    | 基础契约、几何计算、增量执行、绘图编译与渲染，以及宿主接入 | 提供共用底座，不反向依赖 Library、Schematic 或 Viz         |
| Library   | 跨领域复用的通用图形与容器排版能力                         | 基于 Kernel；不拥有流程图、数据映射等领域语义              |
| Schematic | 实体、关系、逻辑图式与流程图等结构表达                     | 按需复用 Kernel / Library；领域模型与算法留在本组          |
| Viz       | 数据处理、图形语法、常用图表与二维表格                     | 绘图包按需复用 Kernel / Library；Data 专注数据，不负责渲染 |

组内也有明确的依赖顺序。下面的“依赖”表示上层消费下层能力，而不是把下层实现复制一份：

- **Library**：Layout 提供领域无关的容器排版；Standard 可消费 Layout，补充通用图形。Layout 不反向依赖 Standard。
- **Schematic**：Diagram 依赖 Graph。Graph 提供实体、关系和可组合图式；Diagram 在其上组织完整图示与自动布局。Flow 是 Diagram 的具体能力，通过 `@retikz/diagram/flow` 提供，不是独立的 `@retikz/flow` 包。
- **Viz**：Chart 依赖 Plot，把常用图表意图展开为图形语法；Plot 消费 Data 的数据处理能力。Table 同样复用 Data，但不依赖 Plot，表格里的图形内容通过通用绘图组合机制接入。

上层遇到能力缺口时，通用绘图机制回到 Kernel，跨领域图形与排版能力回到 Library；只服务流程图或数据图表的语义留在对应领域。React / Vanilla 适配包跟随所属家族，不另建一套算法或绘图语义。

## 演进节奏

整体采用奇偶 minor 交替的推进节奏。minor 指版本号 `MAJOR.MINOR.PATCH` 的中间一段。

| minor                 | 重点         | 推进方式                                                   |
| --------------------- | ------------ | ---------------------------------------------------------- |
| 奇数，如 `0.5`、`0.7` | 新增底层能力 | 先明确能力归属，建立契约和最小可用实现，再验证上层能否使用 |
| 偶数，如 `0.6`、`0.8` | 完善底层能力 | 优先做性能优化、正确性与边界补齐，完善测试、文档和使用体验 |

这是一种“扩展后收敛”的研发节奏，不替代 [版本策略](/about/releases/versioning) 中的兼容性规则，也不要求所有包同时升到相同版本。Kernel 家族内部同步版本；Standard、Layout、Graph、Diagram、Data、Plot、Chart、Table 分别演进。

基础包先完善，上层包随后跟进。例如，先补齐 Data 的数据处理，再由 Plot 消费；Plot 的图形语法稳定后，Chart 再完成常用图表封装。Graph 与 Diagram 也遵循同样的先后关系。互不依赖的工作可以独立推进。

## 短期规划

状态按 minor 划分：奇数为新增，偶数为完善。表中列出主要能力包，React / Vanilla 适配包同步跟进。

版本列仅展示当前开发版本的主版本、次版本与修订号，省略预发布后缀，不代表已发布稳定版。

| 组名      | 包名               | 版本    | 状态 | 说明                         |
| --------- | ------------------ | ------- | ---- | ---------------------------- |
| Kernel    | `@retikz/core` 等  | `0.5.0` | 新增 | 性能优化与基础能力构建       |
| Library   | `@retikz/standard` | `0.1.0` | 新增 | 按其他组需求补充通用绘图能力 |
|           | `@retikz/layout`   | `0.1.0` | 新增 | 按其他组需求补充布局能力     |
| Schematic | `@retikz/graph`    | `0.1.0` | 新增 | 完善基础逻辑图式             |
|           | `@retikz/diagram`  | `0.1.0` | 新增 | 新增流程图能力               |
| Viz       | `@retikz/data`     | `0.2.0` | 完善 | 完善数据处理能力             |
|           | `@retikz/plot`     | `0.2.0` | 完善 | 完善图形语法内容             |
|           | `@retikz/chart`    | `0.1.0` | 新增 | 完成基础图表封装             |
|           | `@retikz/table`    | `0.1.0` | 新增 | 搭建表格基础表达能力         |

本轮先推进这些基础能力及其直接消费者，不为尚未明确的图型、算法或产品能力预设版本与截止时间。

以下为各包的长期目标，覆盖当前建设版本及后续完善版本。

|           |                   | `0.7 - 0.8`   | 交互能力构建、动画完善                      |
|           |                   | `0.9 - 0.10`  | 跨包组合能力构建                            |

| Schematic | `@retikz/graph`   | `0.1 - 0.2`   | 完善基础逻辑图示、常用 Block 封装           |
|           | `@retikz/diagram` | `0.1 - 0.2`   | Flow 流程图                                 |
| Viz       | `@retikz/data`    | `0.2`         | 数据处理优化、transform 完善                |

|           |                   | `0.3 - 0.4`   | 性能优化与交互能力构建                      |
