The Schematic group owns domain capabilities for graph semantics, relationship models, and algorithmic layout. The current Graph package family provides persistent, independently drawable relationship records. Future Diagram packages compute layout and routing above it without copying Graph schemas

## Start with Graph

Only `Graph` is a Tier 2 embed root. `Entity` and `Relation` are the two data-record and authoring-declaration families inside that root; ordinary Core content children are Graph-root decorations:

- Entity stores optional identity, node semantics, and direct Core Node fields
- Relation stores stable endpoints, direction, relationship semantics, and an optional route
- Graph-root decorations store ordinary Core content without Graph semantics

Entity and Relation each own independent `role → kind → predicate(params)`, Definition registry, and Theme selector contracts, then lower to ordinary Core/Layout output. Graph does not copy renderers, Scene, generic geometry, or layout algorithms

| Package                 | Responsibility                                                   | Use it when                              |
| ----------------------- | ---------------------------------------------------------------- | ---------------------------------------- |
| `@retikz/graph`         | Source schemas, factories, Definitions, resolve, and lowering    | Validating/persisting JSON or using Core |
| `@retikz/graph-react`   | Collects `<Graph>` JSX with standalone / embedded Layout hosting | React apps and Layout composition        |
| `@retikz/graph-vanilla` | `InputGraph` normalization and the root panel adapter            | Authoring in browsers, SSR, or scripts   |

All three packages produce the same `IRGraph`. React and Vanilla own authoring normalization only, not schemas, semantic defaults, or lowering

## Capability boundary

Graph owns reusable nodes, relations, identity, and directly authored drawing fields. It does not own:

- Automatic layout, routing, obstacle avoidance, or compound-edge computation; Diagram owns these capabilities
- Editor state such as selection, viewport, history, or transactions
- Domain execution models for UML, workflows, or state machines
- Renderer branches or parallel Scene / geometry systems
