Schematic 组承载图式语义、关系模型与算法布局等领域能力。当前 Graph package family 提供可持久化、可独立组合的 Graph、Group、Entity 与 Relation；未来 Diagram 在它之上计算布局与 routing，而不复制 Graph schema

## 从 Graph 开始

Graph 提供四类可以直接放进 Core 内容树的 Source composite：

- Graph 是可选的 Scope / `graphTheme` 上下文，children 可以是任意 Core / Tier 2 内容
- Group 是可嵌套的可见包含边界，复用 Surface、Layout caption 与 Core boundary labels
- Entity 保存可选 identity、实体语义与直接的 Core Node 字段
- Relation 保存 Core NodeTarget endpoints、direction、关系语义与可选 route

Entity 与 Relation 分别拥有 `role → kind → predicate(params)`、Definition registry 与 Theme selector，最终下沉为普通 Core Node / Path。Graph 与 Group 下沉为 Scope-based 内容；Graph 不复制 renderer、Scene、通用几何或布局算法

| 包                      | 负责什么                                                    | 什么时候使用                     |
| ----------------------- | ----------------------------------------------------------- | -------------------------------- |
| `@retikz/graph`         | Source schema、factory、Definition、resolve 与 lowering     | 校验/持久化 JSON 或直接接入 Core |
| `@retikz/graph-react`   | 四类 JSX authoring，并支持 standalone / embedded Graph 宿主 | React 应用与 Layout 组合         |
| `@retikz/graph-vanilla` | 四类 builder、normalization 与 InputEmbed adapters          | 无 React 的浏览器、SSR 或脚本    |

三个包共享同一 Graph / Group / Entity / Relation Source schema。React 与 Vanilla 只负责 authoring normalization，不拥有 schema、默认语义或 lowering

## 能力边界

Graph 拥有图式实体、关系、可见分组、局部 Theme context 与可复用绘制字段；它不拥有：

- 自动布局、routing、避障或 compound-edge 计算；这些由 Diagram 负责
- selection、viewport、history、transaction 等 Editor 状态
- UML、流程或状态机的领域执行模型
- renderer 分支或平行 Scene / 几何系统
