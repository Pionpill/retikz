Schematic 组承载图式语义、关系模型与算法布局等领域能力。当前 Graph package family 提供可持久化、可独立绘制的关系记录；未来 Diagram 在它之上计算布局与 routing，而不复制 Graph schema

## 从 Graph 开始

只有 `Graph` 是 Tier 2 embed root。`Entity` 与 `Relation` 是 root 内的两类 data records 和 authoring declarations；普通 Core content child 作为 Graph root decoration：

- Entity 保存可选 identity、节点语义与直接的 Core Node 字段
- Relation 保存稳定 endpoints、direction、关系语义与可选 route
- Graph root decoration 保存不带 Graph 语义的普通 Core 内容

Entity 与 Relation 分别拥有 `role → kind → predicate(params)`、Definition registry 与 Theme selector，最终下沉为普通 Core/Layout 输出。Graph 不复制 renderer、Scene、通用几何或布局算法

| 包                      | 负责什么                                                     | 什么时候使用                     |
| ----------------------- | ------------------------------------------------------------ | -------------------------------- |
| `@retikz/graph`         | Source schema、factory、Definition、resolve 与 lowering      | 校验/持久化 JSON 或直接接入 Core |
| `@retikz/graph-react`   | 收集 `<Graph>` JSX，并支持 standalone / embedded Layout 宿主 | React 应用与 Layout 组合         |
| `@retikz/graph-vanilla` | `InputGraph` normalization 与 root panel adapter             | 无 React 的浏览器、SSR 或脚本    |

三个包生成同一 `IRGraph`。React 与 Vanilla 只负责 authoring normalization，不拥有 schema、默认语义或 lowering

## 能力边界

Graph 拥有通用节点、关系、identity 与可复用绘制字段；它不拥有：

- 自动布局、routing、避障或 compound-edge 计算；这些由 Diagram 负责
- selection、viewport、history、transaction 等 Editor 状态
- UML、流程或状态机的领域执行模型
- renderer 分支或平行 Scene / 几何系统
