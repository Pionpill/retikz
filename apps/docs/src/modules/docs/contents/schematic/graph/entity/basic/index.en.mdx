`Entity` is a semantic node with an optional Core identity. Semantics, text, and Core Node-compatible placement live directly in one record, which independently lowers to one ordinary Core `Node`. Omitting `id` draws the node without registering a Core target that references can resolve

## Usage

```tsx
import { Entity } from '@retikz/graph-react';
import { Layout } from '@retikz/react';
```

```tsx
<Layout>
  <Entity id="task" role="activity" position={[180, 70]}>
    Process order
  </Entity>
</Layout>
```

`Entity` can appear directly in Layout, Scope, Graph, or any other Core-child position. Its children accept only strings, numbers, Fragments, or Core `<Text>` and write the direct `text` field. Keep drawing content as siblings rather than Entity children

## Examples

The seven built-in roles define only upper-level semantics and a base shape recipe. Graph **does not maintain a built-in catalog of Entity kinds or predicates**: a `kind` or `predicate.name` can be used only after it is registered in the current provider assembly. Docs logic figures register four kinds: `docs.logic.important`, `docs.logic.importantData`, `docs.logic.secondary`, and `docs.logic.algorithm`. The same kind can be registered independently for multiple roles. Every role demo starts without a kind, and its Kind control lists only the site kinds registered for that role

Theme owns the complete Entity visual language. Each demo below can precisely control instance color and text, while the page-level Theme selector switches the overall style among Academic, Vibrant, Clean, and other choices

Neutral uses a complete master-color outline with a light same-color `fill: 0.08`. Graph Clean explicitly removes the Entity fill while retaining that outline and uses black or white body text for the current mode; explicit instance `style.fill` and `style.textColor` values still take precedence

### participant: an active subject

`participant` represents a subject that actively participates, owns responsibility, or provides a capability. Typical objects include people, teams, organizations, external systems, and services. Use `activity` for work being performed and `resource` for an object that is merely consumed or stored

- **Built-in kinds / predicates:** none
- **Selectable site kinds:** `docs.logic.important`, for important logic content; `docs.logic.secondary`, for secondary or background content
- **Controllable predicate params example:** an extension could declare `{ capacity: number, region: string }` through `paramsSchema`, but built-in `participant` accepts no predefined params

### activity: work and action

`activity` represents work, an action, or a transformation that happens or must be performed. Typical objects include tasks, processing steps, subprocesses, and system operations. A persistent condition is a `state`; an instantaneous occurrence is an `event`

- **Built-in kinds / predicates:** none
- **Selectable site kinds:** `docs.logic.important` for important logic content, `docs.logic.secondary` for secondary or background content, and `docs.logic.algorithm` for algorithmic, high-complexity, or performance-sensitive logic
- **Controllable predicate params example:** an extension could declare `{ retryable: boolean, slaMinutes: number }`; its `paramsSchema` owns the exact fields, defaults, and ranges

### event: a point in time

`event` represents an occurrence, boundary, or lifecycle point in time. Typical objects include start, end, timeout, message arrival, and failure events. It does not represent ongoing work or a condition that persists

- **Controllable predicate params example:** an extension could declare `{ interrupting: boolean, channel: string }`; Graph stores only JSON-safe params accepted by that schema

### state: a persistent condition

`state` represents a condition that persists for an object or system. Typical objects include pending, active, suspended, and failed states. The action that changes a state is an `activity`; the instant of transition may be modeled as an `event`

- **Controllable predicate params example:** an extension could declare `{ severity: 'low' | 'high', terminal: boolean }`, with the enum and value domain validated by `paramsSchema`

### gateway: a semantic control point

`gateway` represents a split, merge, or synchronization point with explicit control semantics. Typical objects include exclusive choices, parallel splits, parallel joins, and multi-way synchronization. Do not use it merely to obtain a diamond shape or in place of a participant or business resource

- **Built-in kinds / predicates:** none

### resource: an object that is used or stored

`resource` represents an object that is used, produced, transferred, or stored. Typical objects include documents, databases, queues, datasets, and artifacts. A system that actively participates and provides a capability is usually a `participant`. Its default contour closes two half-elliptic caps with straight sides, so the top does not form a complete ellipse; symmetric vertical padding keeps the text vertically centered

- **Built-in kinds / predicates:** none
- **Selectable site kinds:** `docs.logic.importantData`, for important data, data structures, types, or schemas; `docs.logic.secondary`, for secondary or background content
- **Controllable predicate params example:** an extension could declare `{ mutable: boolean, replicas: number }` and map validated params to sparse appearance rules after predicate resolution

### concept: an abstract knowledge object

`concept` represents an abstract knowledge object rather than a concrete runtime instance. Typical objects include classes, claims, topics, domain concepts, and rules. Use `activity` for executable work and `participant` for an active connectable subject

### Semantic status

`status` preserves a directly readable Graph state on an Entity. `error`, `success`, `warning`, and `disabled` use the current Core Theme's `semantic.error`, `semantic.success`, `semantic.warning`, and `semantic.guide` respectively. `disabled` also uses a `[6, 4]` dashed stroke, distinguishing it from the gray `docs.logic.secondary` kind. Omitting the field means no special marker; Graph does not write a `normal` value. This is distinct from the `state` role: status describes the current diagram semantics, while that role represents a persistent condition

Every role demo and the combined style playground can switch between no status and the four status values. With no status, demos with a site kind show the kind semantic color; once a status is selected, the current Theme status color takes precedence. You can also write `status` directly in any Entity Source. Explicit Core Node-compatible appearance such as `style.color`, `style.fill`, and `style.stroke` still overrides the status default without removing `status` from Source. A predicate's `params.status` remains domain data interpreted by that predicate and is never mapped to Graph status

### Style adjustments

The combined playground uses the `activity` role to switch among its three registered site kinds: `docs.logic.important` is blue, `docs.logic.secondary` is gray, and `docs.logic.algorithm` is violet. Event, state, gateway, and resource also support the orange `docs.logic.importantData`. Fill and stroke defer to the kind rule by default; choosing a concrete color overrides that semantic color

## How it works

<ComponentAlert
  type="tip"
  title="Optional for everyday use"
  description="Revisit when persisting Graph data, integrating Diagram, or diagnosing compile input."
/>

An Entity Source record stores authored fields only. `id`, `text`, and `position` may all be omitted without materializing empty wrappers, generated ids, or defaults. An Entity without `id` is still drawn from its role but registers no target in the Core namespace. At compile time, the role supplies shape, boundary, padding, corner radius, and base minimum size. Theme supplies appearance defaults, while explicit non-structural Node fields such as `style.color`, `style.fill`, `style.dashed`, `style.dashPattern`, and `style.textColor` take final precedence

An explicit static `style.color` drives both numeric default stroke and fill channels. Compilation fails loudly when a non-static master such as `currentColor` must still resolve either numeric color channel. Use a static `style.color`, or provide both a string stroke and an opaque static fill, so Graph never guesses the host CSS color or backdrop

Entity performs its own registry lookup and lowers to an ordinary Core `Node`. Graph only provides built-in roles; every kind must be registered by an upper layer in the provider assembly, and an unregistered key fails loudly. Core, Scene, and renderers do not interpret Entity roles or kinds. Graph only adds local Theme context when present; it is not a compile prerequisite

Within one Graph root's publicly visible content tree, Entities and Relations may use the same `group` to express one visual chain. Graph assigns colors from the current categorical palette in first-appearance order; elements without a group keep their existing appearance. `group` does not participate in kinds, selectors, or status; Graph rules and explicit colors such as instance `style.color` still win

## API Reference

Entity visual fields belong to `style`; text layout, size and spacing belong to `layout`. The role still owns padding, so instances cannot set `layout.padding`.

| Prop         | Type                                    | Default | Description                                                                                                                        |
| ------------ | --------------------------------------- | ------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `id?`        | `string`                                | —       | Optional Core target id; omission registers no reference target                                                                    |
| `role`       | `string`                                | —       | Registered open semantic role key                                                                                                  |
| `kind?`      | `string`                                | —       | Stable subtype registered by an upper layer. Its identity is `(role, kind)`, so the same kind may be registered for multiple roles |
| `group?`     | `string`                                | —       | Visual color-group identifier within one Graph root; the same value as a Relation reuses its automatic categorical color           |
| `predicate?` | `{ name: string; params?: JsonObject }` | —       | Registered predicate and its JSON-safe parameters                                                                                  |
| `status?`    | `GraphStatusValue`                      | —       | Optional closed Graph state: `error`, `success`, `warning`, or `disabled`                                                          |
| `position?`  | `IRPosition`                            | —       | Directly reuses the Core Node position language                                                                                    |
| `text?`      | `IRNode['text']`                        | —       | Node-compatible text                                                                                                               |
| `children?`  | Node-compatible text                    | —       | React text entry; it cannot host arbitrary drawing children                                                                        |
| `meta?`      | `JsonObject`                            | —       | Metadata ignored by Graph semantics                                                                                                |
