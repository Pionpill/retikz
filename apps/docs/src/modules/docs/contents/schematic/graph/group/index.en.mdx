Group expresses containment with a visible boundary while preserving the relative layout of children. Use [Block](/schematic/graph/block) to arrange content vertically. This single page includes usage, implementation, API, and Schema. See [Getting started](/schematic/graph/get-start) for installation and host setup.

## Basic usage

### caption

`caption` is the title and description region inside the shell. It can sit above or below the body and arrange its items horizontally or vertically. Use the controls below to adjust its position, direction, and spacing. The title defaults to `sm` without bold weight; the description defaults to `xs` with reduced opacity

### label

`labels` are Core Node labels attached around the Group shell. Use the controls to adjust three labels independently. They accept directional positions, boundary fractions, or an omitted position; omission places the label at the lower-left outside the shell without changing the body's layout

## Extended usage

Nested Groups express subsystem boundaries. Give outer and inner groups distinct ids to let Relations target either shell. Internal Entity ids receive no group prefix. For repeated instances, enable localNamespace on each instance and author internal connections within it.

<ComponentPreview files="group-nested" size="sm" />

Place FlexLayout / GridLayout inside Group when objects need arrangement. The layout container determines relative positions and Group encloses the result. Use [Flow](/schematic/diagram/flow/basic) for whole-graph arrangement. The `Entity.group` categorical color key has no automatic association with a Group container.

## Errors and limits

- caption requires title or description, using `{ text: ... }` objects. A provided labels array must be nonempty.
- Group does not avoid obstacles or label collisions and does not connect children automatically. Ids must be unique within their namespace.
- graphDefaults / graphRules affect visible descendants, not the current shell, caption, or boundary labels. Set background / border on the current shell.
- overflow constrains Surface content. Outside labels still contribute to visual bounds; do not assume they are clipped.

### Arbitrary children and Graph Theme

- `children` directly uses Core `IRChild`: Entity, Relation, Group, Node, Path, Scope, Layout, Plot, or any registered composite
- `defaults.node`, `defaults.path`, `defaults.label`, Core `theme`, transforms, placement, clipping, and namespaces retain Scope semantics
- A named Graph Theme supplies the Group root shell `background`, `border`, and `cornerRadius` baseline. Explicit Source fields win and use complete top-level field replacement instead of deep-merging inside `border` or `background`
- `graphDefaults` affects visible Entity / Relation descendants and descendant Group / Block shells; `graphRules` matches only descendant Entities and Relations. Neither affects this Group’s own shell, caption, boundary labels, or ordinary Core children
- Changing the content `theme` or setting Core `defaults.reset` preserves author defaults and rules. This shell uses the incoming theme and ancestor defaults
- Group does not stack children automatically and owns no routing, obstacle avoidance, or label collision. Put FlexLayout, GridLayout, or OverlayLayout inside when ordinary arrangement is required
- An explicit Group `id` names the shell envelope and remains targetable through Core `IRNodeTarget`

### Surface, caption, and boundary-label lowering

Group lowering combines the caption and authored children into the single Surface content, lowers the shell to Standard Surface, and uses a transparent Core Node to carry boundary labels. The caption participates in the shell's inner allocation; labels expand only the final visual bounds and do not change the shell boundary used when a Relation targets the Group. Neither Graph nor Group stores automatic layout results or defines a second position or boundary model for labels
