## Extension boundary

Register a Definition when several Relations share stable meaning, direction constraints, or a marker / dash recipe. Write one-off routes and labels directly on the Relation record. Automatic routing and compound-edge algorithms belong to Diagram, not Relation Definitions

## Define the capability

| Definition                | Responsibility                                                                               |
| ------------------------- | -------------------------------------------------------------------------------------------- |
| `defineRelationRole`      | Defines primary semantics, default / allowed directions, and a complete recipe per direction |
| `defineRelationKind`      | Narrows directions within one role and contributes sparse structure deltas                   |
| `defineRelationPredicate` | Validates JSON params and may resolve sparse structure deltas from Canonical params          |

A role must cover every allowed direction, while a kind may only narrow that set. A custom marker shape is a Core Arrow provider key; Graph does not own a parallel marker registry

## Inject into a host

React can pass `relationRoles`, `relationKinds`, and `relationPredicates` directly to the `<Relation>` that consumes them. Use `<Graph>` when several descendants share definitions and local `graphTheme`. Vanilla can pass the same arrays to `relation(id, input)` or `graph(id, input)`, while direct IR compilation uses `createGraphDefinitions(options)` or `createGraphProviders(options)`

```tsx
<Graph relationKinds={[feedbackKind]} relationPredicates={[priorityPredicate]}>
  <Relation
    id="feedback"
    role="flow"
    kind="workflow.feedback"
    predicate={{ name: 'workflow.priority', params: { urgent: true } }}
    source={{ id: 'review' }}
    target={{ id: 'revise' }}
    way={['review', 'revise']}
  />
</Graph>
```

## Execution model

Relation validates the effective direction, resolves complete marker / dash structure from role, kind, and predicate, then applies Theme appearance rules. Core namespace resolves endpoint identities while compiling the Path. The authored route enters Core `Path` unchanged; marker shortening, provider lookup, and renderer output remain Core/Render responsibilities

## Errors and limits

- Duplicate keys, built-in key replacement, unregistered role / kind / predicate, or role ownership mismatch fail loudly
- Definition creation fails when a role default is outside its allowed set, a complete recipe is missing, or a kind expands the allowed set
- A predicate resolver never runs when its params fail the predicate's Zod schema
- Relation neither computes an authored route from endpoint coordinates nor compares route endpoints; omission emits a direct source-to-target connection
- A missing custom Arrow provider is reported through the Core registry and never falls back to a built-in marker

## API Reference

| Public export                                                  | Purpose                                                              |
| -------------------------------------------------------------- | -------------------------------------------------------------------- |
| `defineRelationRole` / `RelationRoleDefinition`                | Defines direction constraints and a complete role recipe             |
| `defineRelationKind` / `RelationKindDefinition`                | Defines a stable subtype and narrows directions                      |
| `defineRelationPredicate` / `RelationPredicateDefinitionInput` | Defines a predicate with type-safe JSON params                       |
| `RelationRole` / `RelationKind` / `RelationDirection`          | Lists built-in semantics and direction vocabulary                    |
| `GraphDefinitionOptions`                                       | Assembles Relation Definitions in the Graph-family provider assembly |
