Graph uses composable components to describe domain objects, boundaries, and relationships. `Entity` describes an object, `Relation` connects referenceable targets, `Group` draws a visible boundary around arbitrary content, and `Block` organizes code and engineering objects. An optional `Graph` root gives them one local semantic and styling context.

Graph does not arrange members or plan connections automatically. After giving objects positions, add a focused layout or routing capability when needed.

## Responsibilities

| Member   | Responsibility                                       | When to read                                       |
| -------- | ---------------------------------------------------- | -------------------------------------------------- |
| Graph    | Defaults, conditional style rules, and Theme context | Several Graph components share rules               |
| Entity   | A domain object with role, text, and position        | Describing an object in the diagram                |
| Relation | A relationship that targets named objects            | Connecting two objects or visible boundaries       |
| Group    | A visible boundary, caption, and labels              | Showing a scope, phase, or responsibility boundary |
| Block    | Structured vertical content for engineering objects  | You need Header, Section, and Row                  |

## The whole picture

This minimal diagram first declares two referenceable Entities, then connects them with a Relation. It shows Graph's basic collaboration: objects retain their own semantics and positions while a relationship only refers to their ids. A Group can later establish a boundary, or a Block can replace an object that needs structured content.

## Where to start

- Build your first object-relationship diagram in the [Quick start](/schematic/graph/get-start)
- Read the [Introduction](/schematic/graph/introduction) to decide whether Graph fits the problem
- When you know what needs describing, enter Entity, Relation, Group, or Block directly
- For automatic layout, obstacle avoidance, or routing, choose the focused capability for that job
