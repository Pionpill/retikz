## 适用边界

当多个 Entity 需要复用稳定语义或结构时注册 Definition。一次性文本直接写 `text`，一次性非规范业务信息放 `meta`；任意其它 Core content child 不是 Entity 扩展面，应作为同一 Layout、Scope 或 Graph 下的 sibling

## 定义能力

Entity 拥有三套独立 Definition：

| Definition              | 职责                                                 |
| ----------------------- | ---------------------------------------------------- |
| `defineEntityRole`      | 定义主要语义与完整 shape、padding、minimum size 结构 |
| `defineEntityKind`      | 在一个 role 内定义稳定语义子类型                     |
| `defineEntityPredicate` | 用 Zod 校验 JSON params                              |

每个 role 持有自己的 shape 与基础结构。kind 和 predicate 都不复制 role shape；Graph Theme rules 根据 Canonical semantics 提供 appearance 默认，Entity Source 上显式编写的非结构 Node 外观字段最终覆盖这些默认

## Predicate params 闭环

上方 demo 注册了 `service.availability` predicate。它的 `paramsSchema` 明确声明 `status` 只能是 `available`、`degraded` 或 `offline`，`critical` 必须是 boolean；controls 的两个参数直接写入 Entity Source：

```tsx
<Entity
  role="service"
  kind="service.gateway"
  predicate={{
    name: 'service.availability',
    params: { status, critical },
  }}
/>
```

Graph 先用该 Definition 的 Zod schema 解析 params，再让 Theme selector 匹配 Canonical predicate。demo 中 Theme rules 根据 `status` 和 `critical` 选择主色与描边宽度。没有注册 predicate 时，Entity 没有任何预设参数名、默认值或范围

## 注入宿主

React 可以把 definitions 直接传给使用它们的 `<Entity>`。多个后代共享同一组 definitions 和局部 `graphTheme` 时，再由 `<Graph>` 统一提供：

```tsx
<Graph entityRoles={[serviceRole]} entityKinds={[gatewayKind]} entityPredicates={[availabilityPredicate]}>
  <Entity
    id="api"
    role="service"
    kind="service.gateway"
    predicate={{ name: 'service.availability', params: { status: 'available', critical: false } }}
    position={[180, 80]}
  >
    API gateway
  </Entity>
</Graph>
```

Vanilla 可把相同 options 传给 `entity(id, input)` 或 `graph(id, input)`；`EntityInputEmbedAdapter` 与 `GraphInputEmbedAdapter` 都会贡献匹配的 provider closure。直接编译持久化 IR 时，用 `createGraphDefinitions(options)` 或 `createGraphProviders(options)` 装配相同 definitions

## 执行机制

当前 provider assembly 先将内置与自定义 definitions 合并到局部 registries，校验 `role → kind → predicate`，再按顺序应用匹配的 Graph Theme appearance rules。lowering 随后叠加 Entity 显式非结构 Node 字段，再写入 role structure，并按轴合并 `minimumSize`；最终 Entity 仍是一个普通 Core `Node`

## 错误与限制

- 空 key、重复 key、覆盖内置 key，或同一 assembly 中不同对象争用同一 key 时 fail-loud
- 未注册 role / kind / predicate、kind 与 role 不匹配、predicate params 校验失败时 fail-loud
- 自定义 shape 继续由 Core Shape registry 解析；缺少 provider 时不回退到 rectangle
- Entity data、predicate params 与 `meta` 必须 JSON-safe；函数、ReactNode 和 renderer resource 不能进入 Source IR
- `<Entity>` 可以独立 embed，但 children 仍只接受 Node-compatible 文本；任意绘图内容必须作为 sibling

## API 参考

| 公开导出                                                   | 用途                                            |
| ---------------------------------------------------------- | ----------------------------------------------- |
| `defineEntityRole` / `EntityRoleDefinition`                | 定义完整 role 结构与 shape                      |
| `defineEntityKind` / `EntityKindDefinition`                | 定义 role 内稳定子类型                          |
| `defineEntityPredicate` / `EntityPredicateDefinitionInput` | 定义带类型安全 JSON params 的 predicate         |
| `EntityRole`                                               | 查询内置开放 role key                           |
| `GraphThemeLayerSchema` / `IRGraphThemeLayer`              | 编写非空 ordered appearance rules               |
| `GraphDefinitionOptions`                                   | 在 Graph assembly 中装配三类 Entity definitions |
