## Extension boundary

Register a Definition when several Entities share stable semantics or structure. Write one-off text directly as `text`, keep non-normative business data in `meta`, and keep other Core content as siblings in the same Layout, Scope, or Graph

## Define the capability

Entity owns three independent Definition families:

| Definition              | Responsibility                                                                    |
| ----------------------- | --------------------------------------------------------------------------------- |
| `defineEntityRole`      | Defines primary semantics and complete shape, padding, and minimum-size structure |
| `defineEntityKind`      | Defines a stable semantic subtype within one role                                 |
| `defineEntityPredicate` | Validates JSON params with Zod                                                    |

Each role owns its shape and base structure. Kinds and predicates do not duplicate that shape. Graph Theme rules match Canonical semantics to supply appearance defaults, and explicit non-structural Node appearance fields on Entity Source take final precedence

## Predicate params loop

The demo above registers a `service.availability` predicate. Its `paramsSchema` requires `status` to be `available`, `degraded`, or `offline` and `critical` to be a boolean. The two controls write those params directly into Entity Source:

```tsx
<Entity
  role="service"
  kind="service.gateway"
  predicate={{
    name: 'service.availability',
    params: { status, critical },
  }}
/>
```

Graph parses params with the Definition's Zod schema before Theme selectors match the Canonical predicate. In the demo, Theme rules use `status` and `critical` to select color and stroke width. Without a registered predicate, an Entity has no predefined param names, defaults, or ranges

## Inject into a host

React can pass definitions directly to the `<Entity>` that consumes them. Use `<Graph>` when several descendants share the same definitions and local `graphTheme`:

```tsx
<Graph entityRoles={[serviceRole]} entityKinds={[gatewayKind]} entityPredicates={[availabilityPredicate]}>
  <Entity
    id="api"
    role="service"
    kind="service.gateway"
    predicate={{ name: 'service.availability', params: { status: 'available', critical: false } }}
    position={[180, 80]}
  >
    API gateway
  </Entity>
</Graph>
```

Vanilla can pass the same options to `entity(id, input)` or `graph(id, input)`. Both `EntityInputEmbedAdapter` and `GraphInputEmbedAdapter` contribute the matching provider closure. When compiling persisted IR directly, assemble the same definitions through `createGraphDefinitions(options)` or `createGraphProviders(options)`

## Execution model

The current provider assembly merges built-in and custom definitions into local registries, validates `role → kind → predicate`, then applies matching Graph Theme appearance rules in order. Lowering overlays explicit non-structural Entity Node fields, writes role structure, and merges `minimumSize` per axis. The final Entity is still one ordinary Core `Node`

## Errors and limits

- Blank keys, duplicate keys, built-in key replacement, or different Definition objects competing for one key in an assembly fail loudly
- An unregistered role / kind / predicate, role mismatch, or invalid predicate params fail loudly
- Custom shapes remain Core Shape registry entries; a missing provider never falls back to a rectangle
- Entity data, predicate params, and `meta` must be JSON-safe; functions, ReactNode values, and renderer resources cannot enter Source IR
- `<Entity>` can be embedded independently, but its children remain Node-compatible text; other drawing content must be a sibling

## API Reference

| Public export                                              | Purpose                                        |
| ---------------------------------------------------------- | ---------------------------------------------- |
| `defineEntityRole` / `EntityRoleDefinition`                | Defines complete role structure and shape      |
| `defineEntityKind` / `EntityKindDefinition`                | Defines a stable subtype within a role         |
| `defineEntityPredicate` / `EntityPredicateDefinitionInput` | Defines a predicate with type-safe JSON params |
| `EntityRole`                                               | Lists built-in open role keys                  |
| `GraphThemeLayerSchema` / `IRGraphThemeLayer`              | Authors non-empty ordered appearance rules     |
| `GraphDefinitionOptions`                                   | Assembles the three Entity Definition families |
