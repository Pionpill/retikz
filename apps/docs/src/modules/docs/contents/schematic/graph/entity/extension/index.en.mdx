title: Entity Extensions

Entity extensions are useful for three needs: adding new semantic roles and geometry defaults, reusing an appearance recipe, or applying Entity styles by Theme, role, or variant. A Definition is active only in the assembly used by one compile or render operation, while persisted IR stores only `role`, `variant`, and JSON-safe parameters; reloading IR with custom keys requires the matching Definitions again

## Custom extensions

If only one Entity needs a change, use its Node props directly. Register a Definition when several Entities should share semantics, geometry defaults, or Theme rules. Graph extension points are split by responsibility: roles own geometry defaults, variants own Entity appearance, and Theme styles own token baselines and selector rules

| API                       | Responsibility                                                                                                                     |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `defineEntityRole()`      | Registers a role key and geometry defaults such as `shape`, `padding`, and `minimumSize`; explicit Entity fields win independently |
| `defineEntityVariant()`   | Registers a variant key and returns sparse `GraphThemeToken` values from `theme` and the materialized `color`; appearance only     |
| `defineGraphThemeStyle()` | Registers a Graph Theme token baseline and selector rules paired with a same-name Core Theme style                                 |

```ts
import { defineThemeStyle, ThemeMode } from '@retikz/core';
import {
  defineEntityRole,
  defineEntityVariant,
  defineGraphThemeStyle,
  getDefaultGraphThemePreset,
  GraphThemeToken,
} from '@retikz/graph';

const brandCoreTheme = defineThemeStyle({
  name: 'brand',
  resolve: ({ mode }) => ({
    semantic: {
      error: mode === ThemeMode.Light ? '#dc2626' : '#fca5a5',
      success: mode === ThemeMode.Light ? '#16a34a' : '#86efac',
      warning: mode === ThemeMode.Light ? '#ca8a04' : '#fde047',
      guide: mode === ThemeMode.Light ? '#6b7280' : '#9ca3af',
    },
    categorical: ['#2563eb'],
  }),
});

const serviceRole = defineEntityRole({
  role: 'service',
  shape: { type: 'rectangle', params: { cornerRadius: 10 } },
  padding: { x: 14, y: 8 },
});

const mutedVariant = defineEntityVariant({
  variant: 'muted',
  resolve: ({ color }) => ({
    [GraphThemeToken.EntityTextForeground]: color,
    [GraphThemeToken.EntityStroke]: 'none',
    [GraphThemeToken.EntityFill]: color,
    [GraphThemeToken.EntityFillOpacity]: 0.12,
  }),
});

const brandGraphTheme = defineGraphThemeStyle({
  name: 'brand',
  resolve: theme => ({
    tokens: {
      ...getDefaultGraphThemePreset(theme),
      [GraphThemeToken.EntityStrokeOpacity]: theme.mode === ThemeMode.Light ? 0.7 : 0.9,
    },
    tokenRules: [
      {
        select: { variant: 'muted' },
        tokens: {
          [GraphThemeToken.EntityFillOpacity]: theme.mode === ThemeMode.Light ? 0.2 : 0.3,
        },
      },
    ],
  }),
});

const options = {
  entityRoles: [serviceRole],
  entityVariants: [mutedVariant],
  graphThemeStyles: [brandGraphTheme],
};
```

A variant owns appearance only; it cannot change role, shape, or other geometry fields

### Vanilla usage

Vanilla authoring declares the Definitions for a Graph subtree directly on the `graph()` input. The Core Theme style is injected through Vanilla's `compile.themeStyles`; `createGraphVanillaAdapters()` only installs the Graph embed adapters:

```ts
import { renderToSvgString } from '@retikz/vanilla';
import { createGraphVanillaAdapters, entity, graph } from '@retikz/graph-vanilla';

const svg = renderToSvgString(
  {
    theme: { style: 'brand' },
    children: [
      graph('service-map', {
        entityRoles: [serviceRole],
        entityVariants: [mutedVariant],
        graphThemeStyles: [brandGraphTheme],
        children: [
          entity('service', {
            role: 'service',
            variant: 'muted',
            position: [0, 0],
            text: 'Service',
          }),
        ],
      }),
    ],
  },
  {
    adapters: createGraphVanillaAdapters(),
    compile: { themeStyles: [brandCoreTheme] },
  },
);
```

### React usage

React authoring follows the Core / Standard style: declare Definitions directly on `<Graph>` and provide the Core Theme style on the root `<Layout>`. The extension content is scoped to that Graph subtree and is not written to persisted IR:

```tsx
import { Layout } from '@retikz/react';
import { Entity, Graph } from '@retikz/graph-react';

const view = (
  <Layout theme={{ style: 'brand' }} themeStyles={[brandCoreTheme]}>
    <Graph
      id="service-map"
      entityRoles={[serviceRole]}
      entityVariants={[mutedVariant]}
      graphThemeStyles={[brandGraphTheme]}
    >
      <Entity id="service" role="service" variant="muted" position={[0, 0]}>
        Service
      </Entity>
    </Graph>
  </Layout>
);
```

If you already have persisted IR, continue using `createGraphDefinitions(options)` and provide the matching Core `themeStyles`: `<Layout ir={scene} composites={createGraphDefinitions(options)} themeStyles={[brandCoreTheme]}>`. Definition functions belong to runtime assembly and never enter Graph IR; without the custom Definitions, the corresponding IR keys fail explicitly during lookup

## Graph Theme selectors

`defineGraphThemeStyle()` pairs with a Core Theme style of the same name. It returns a complete Graph token baseline followed by ordered `tokenRules`; an array within `role` or `variant` is OR, both selector fields together are AND, and a later matching rule replaces an earlier value for the same token

Execution fails loudly for invalid extension input:

- A blank custom key, a built-in collision, or different Definition objects sharing a key in one assembly fails immediately instead of using last-wins
- An unregistered Entity role or variant, an unknown selector key, or a Core Theme style without a same-name Graph Theme style fails immediately
- A custom role's `shape` is still resolved by the Core shape registry; Graph never substitutes rectangle for an unknown shape
- `currentColor` materializes to `#000000` in Light mode or `#ffffff` in Dark mode before entering a variant recipe
- Graph Theme selectors target Entity only; Relation, the Container shell, and third-party composites do not consume these tokens

## API reference

### Public exports

| Export                                                | Package                 | Purpose                                                            |
| ----------------------------------------------------- | ----------------------- | ------------------------------------------------------------------ |
| `defineEntityRole` / `EntityRoleDefinition`           | `@retikz/graph`         | Defines role geometry defaults                                     |
| `defineEntityVariant` / `EntityVariantDefinition`     | `@retikz/graph`         | Defines a Theme-aware appearance recipe                            |
| `defineGraphThemeStyle` / `GraphThemeStyleDefinition` | `@retikz/graph`         | Defines a Graph token baseline and selector rules                  |
| `GraphThemeToken`                                     | `@retikz/graph`         | Names the eight Entity presentation tokens                         |
| `createGraphDefinitions` / `createGraphProviders`     | `@retikz/graph`         | Assembles Definitions for direct compile or providers              |
| `GraphProps`                                          | `@retikz/graph-react`   | Declares Definition options directly on `<Graph>`                  |
| `InputGraph`                                          | `@retikz/graph-vanilla` | Declares Definition options directly on `graph()`                  |
| `createGraphVanillaAdapters`                          | `@retikz/graph-vanilla` | Installs the Graph, Container, Entity, and Relation embed adapters |

### Definitions and configuration

| Contract                    | Fields                                                         | Semantics                                                                                             |
| --------------------------- | -------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `EntityRoleDefinition`      | `role`<br />`shape`<br />`padding`<br />`minimumSize?`         | Role key and overridable geometry defaults                                                            |
| `EntityVariantDefinition`   | `variant`<br />`resolve(context)`                              | Variant key and sparse appearance-token recipe; context provides `theme` and the materialized `color` |
| `GraphThemeStyleDefinition` | `name`<br />`resolve(theme)`                                   | Graph Theme resolver paired with a Core style; returns complete `tokens` and ordered `tokenRules`     |
| `GraphDefinitionOptions`    | `entityRoles?`<br />`entityVariants?`<br />`graphThemeStyles?` | User Definitions shared by one assembly                                                               |

`GraphThemeToken` covers primary color, text foreground, fill, stroke, stroke width, fill opacity, stroke opacity, and overall opacity. Common identifiers include `GraphThemeToken.EntityColor`, `GraphThemeToken.EntityTextForeground`, `GraphThemeToken.EntityFill`, `GraphThemeToken.EntityStroke`, and `GraphThemeToken.EntityOpacity`. Selector data stays in Graph IR; Definition functions exist only in runtime options
