Read [Basic usage](/schematic/graph/block/usage) first. This page explains how Block arranges arbitrary content while remaining a single connection target, and how Header, Section, and Row arrange their own content.

## A shell surrounds the column layout

Block does not require a fixed set of child components. It wraps each child in a Flex item and passes the items to a column FlexLayout. Standard Surface adds padding, background, and border around the result. Surface retains the Block Scope fields, so the visible shell and published id use the same container boundary.

- Flex item: a layout item for one child occurrence, preserving authored order and using content size by default.
- Surface: a visible shell measured from its content, carrying transforms, local namespace, and reference identity.

`gap` separates direct children; `padding` separates content from the shell. `width` / `minWidth` include horizontal padding. Resolve uses 240 when minWidth is absent; lowering supplies gap 8 and padding 8. These effective values do not mutate sparse Source.

## Header direction affects only its text region

The outer Header always arranges icon, text region, and trail horizontally. `direction` changes the arrangement of title and description inside the text region; it never moves the icon above the title. The text region can grow into remaining width while slots keep their content sizes.

The title defaults to bold base text; description uses xs with opacity 0.7. Explicit text fields in an `IRBlockText` object override these defaults. Generated text is wrapped in a Scope that resets Node defaults, preventing inherited Node shell styles from entering Header text.

## Row divides space between direct items

Section places its optional title before children in a column Flex. Row converts `content` into ordinary text Nodes, or takes `children` directly, then creates horizontal Flex items for either form.

Every Row item uses `basis: 0`, `grow: 1`, `shrink: 1`, and `min: 0`. Items share the available width after gaps equally; text length does not determine the ratio. Longer text does not automatically receive a wider column. Supply text constraints when wrapping is needed. Section and Row each create their own Surface, allowing an explicit id to become an independent connection target.

Header, Section, and Row have independent composite definitions. Compilation measures their lowered layout and replays the result; none requires an enclosing Block.

## The current shell and descendant rules resolve separately

The current Block shell starts from the effective Graph Theme baseline. Explicit background, border, and cornerRadius replace their corresponding top-level fields. An explicit border replaces the complete theme border; it does not inherit individual dash or opacity fields.

Block graphDefaults / graphRules establish descendant context: defaults can affect Entity, Relation, Group, and Block; rules match Entity / Relation. They pass through known content boundaries without changing the current Block shell, ordinary Core children, or unknown composites. A local theme does not erase these author rules.

The id enters Scope unchanged; Block adds no parent prefix. Enable localNamespace for isolated naming. Target resolution and boundary diagnostics use the same Core rules.

## CodeBlock establishes its theme before composing content

A custom code entity compose callback must read the local theme. Composing content before applying theme would give the callback its parent's theme. The extension first establishes a theme Scope, resolves codeBlockTokens inside it, invokes compose, and places the returned content in one Block root.
