`@retikz/graph` 拥有 JSON-safe Source IR、Definition registry、resolve 与 lowering。Graph、Entity、Relation 都是可独立编译的 Tier 2 composite；Graph 额外复用完整 Core Scope contract，作为顶层 React 宿主时建立 Scene，嵌入时只贡献一个局部 Scope

## 公开导出

| 能力       | `@retikz/graph`                                                                                    | React                               | Vanilla                                                            |
| ---------- | -------------------------------------------------------------------------------------------------- | ----------------------------------- | ------------------------------------------------------------------ |
| Graph      | `GraphSchema`、`IRGraph`、`createGraph`、`GraphDefinition`、`GraphProviderKey`                     | `Graph`、`GraphProps`               | `graph`、`GraphInputEmbedAdapter`、`GraphInputEmbedProps`          |
| Entity     | `EntitySchema`、`IRGraphEntity`、`createEntity`、`EntityDefinition`、`EntityProviderKey`           | `Entity`、`EntityProps`             | `entity`、`EntityInputEmbedAdapter`、`EntityInputEmbedProps`       |
| Relation   | `RelationSchema`、`IRGraphRelation`、`createRelation`、`RelationDefinition`、`RelationProviderKey` | `Relation`、`RelationProps`         | `relation`、`RelationInputEmbedAdapter`、`RelationInputEmbedProps` |
| 开放词汇   | `EntityRole`、`RelationRole`、`RelationKind` 及对应 schema                                         | —                                   | —                                                                  |
| Theme 扩展 | `GraphThemeStyleDefinition`、`GraphThemeStyleOverrides`、`defineGraphThemeStyle`                   | `graphThemeStyles` 可声明在三个组件 | `graphThemeStyles` 可传给三个 adapter                              |
| 装配       | `GraphDefinitionOptions`、`createGraphDefinitions`、`createGraphProviders`                         | options 可声明在三个组件            | `createGraphVanillaAdapters`                                       |

## Graph Source composite

Source IR 只保存作者提供的事实。省略可选 `children`、位置、route、文本、Theme 与样式时，schema 不会填入空对象、默认值或自动 id。Graph 不建立成员集合；它只把局部 Graph context 投影给语义后代，再保留完整有序 child tree

Graph `children` 直接使用 Core `ChildSchema`，可以混合 Entity、Relation、Node、Coordinate、Path、Scope 及其它 composite。`theme`、样式默认、transform、placement、clip、bounding shape、animation 与 `meta` 都保留 Core Scope 语义；Graph-only 字段只有 `graphTheme`

Entity role、Relation role / kind 都是开放 key。schema 会把内置 const object 词汇作为 TypeScript 和 JSON Schema 提示，但仍接受任意非空白自定义字符串；是否已注册只在 resolve 阶段校验。Entity kind 与 predicate name 当前没有内置词汇，因此继续显示为普通非空白字符串

```json
  "type": "graph",
  "nodeDefault": { "strokeWidth": 1.5 },

      "namespace": "graph",
      "type": "entity",

```

完整 Scope 字段的嵌套结构与继承规则见 [Scope schema](/kernel/reference/schema/scope)。

## Entity schema

Entity 把语义与 Core Node 实例字段放在同一个 Source record。除了由 role 决定的 `type`、`shape`、`boundary`、`padding`、`cornerRadius`，其余 Node 字段都可直接使用；`id`、`position` 和 `text` 可省略。当前位置的 Core Theme 与可选 Graph Theme 提供外观默认，Entity 上显式编写的 `fill`、`dashed`、`textColor` 等字段最终覆盖 Theme

## Relation schema

Relation 同时保存 Core `IRNodeTarget` endpoint、语义、完整 Core Geometry Labels 与可选 Core route。`RelationSchema` 从 `PathBaseSchema` 只排除 discriminator / kind、`children` / `label`、任意 `marks` 与 fill family，其余 Core Path 字段直接复用。Relation resolve 不校验 Graph 成员身份；Core Path 统一解析 Node、Coordinate、resolved Scope 或上层 composite 发布的 target，并拥有 unresolved / duplicate-id 诊断

Theme 是 Relation 的默认来源，不是可用字段白名单。Relation 显式 Path paint、stroke、effect、dash 与 transform 字段最终覆盖适用默认；`labels` 的公开类型是 `Array<IRGeometryLabel>`，每个 label 的 `textColor`、`opacity` 和字体子字段再覆盖 Relation label 默认

`source` 与 `target` 的完整公开类型是 `IRNodeTarget`：

| 字段        | 类型               | 默认值           | 描述                                                    |
| ----------- | ------------------ | ---------------- | ------------------------------------------------------- |
| `id`        | `string`           | —                | Node、Coordinate、resolved Scope 或 composite target id |
| `anchor?`   | `IRAnchorRef`      | 由消费上下文决定 | 命名、角度或 boundary-fraction anchor                   |
| `offset?`   | `[number, number]` | —                | anchor 解析后的 world-space 偏移                        |
| `boundary?` | `IRBoundary`       | target 默认边界  | 当前 endpoint 的连接表面覆盖                            |

省略 `route` 时 lowering 生成 `move(source) → line(target)`；显式 route 使用 `Array<IRGraphRelationRouteStep>`，保持完整 Core Position language，且 route step 不承载 label

Core `theme` 选择或覆盖通用 Theme；`graphTheme` 只保存 Graph-local ordered appearance rules。Entity rule 可按 role / kind / predicate 匹配，Relation rule 可按 role / kind / predicate / direction 匹配；role 持有完整结构，kind / predicate 只能提供允许的结构 delta

`defineGraphThemeStyle()` 的 `resolve(theme)` 返回 `GraphThemeStyleOverrides`，只写相对当前明暗模式默认 preset 需要改变的字段。`entity`、`relation` 及各自的 `tokens`、`rules` 都可以省略；显式 `tokens: {}` 无效，因为 token override 必须至少包含一个字段

```ts
const compact = defineGraphThemeStyle({
  name: 'compact',
  resolve: () => ({
    entity: { tokens: { strokeWidth: 1.5 } },
  }),
});

const composites = createGraphDefinitions({ graphThemeStyles: [compact] });
```

Graph resolver 按以下顺序形成完整外观，后面的来源只覆盖自己声明的字段：

1. 当前 Core Theme mode 对应的 Graph 默认 preset tokens
2. 自定义 style 的稀疏 tokens
3. Graph 默认 rules
4. 自定义 style rules
5. 从外到内的 Graph-local `graphTheme` rules
6. Entity / Relation 显式 appearance 字段

自定义 style rules 追加在默认 rules 后；省略 `rules` 或提供 `rules: []` 都不会清空内置规则。未知 Core Theme style 仍要求注册同名 Graph Theme style Definition，否则 resolve 会 fail-loud

## React 与 Vanilla authoring

React `<Graph>` 按作者顺序收集任意 Core/Tier 2 children。Entity children 写入直接 `text`；Relation `<Step>` children 写入直接 `route`。`<Entity>` 与 `<Relation>` 也可直接放在 Layout、Scope 或其它接受 Core child 的位置

Graph standalone 与嵌入模式共享同一个 Source contract：

```tsx
<Graph width={420} height={160}>...</Graph>

<Layout width={800} height={220}>
  <Graph transforms={[{ kind: 'translate', x: 80, y: 40 }]}>...</Graph>
</Layout>
```

standalone 的 `width`、`height`、`viewBox`、renderer、runtime 与 DOM props 属于 Layout Scene 宿主；嵌入时把它们移到外层 Layout。`transforms`、`placement`、`zIndex` 与 `clip` 等直接属于 `IRGraph`，没有额外 panel envelope

Vanilla `normalizeGraph()`、`normalizeEntity()` 与 `normalizeRelation()` 只做工厂校验、child 归一化和可选 `way → route` sugar，不拆 envelope、不填默认值。`createGraphVanillaAdapters()` 一次安装三个 adapter

`graph(traversalId, input)`、`entity(traversalId, input)` 与 `relation(traversalId, input)` 的第一个参数只供 Vanilla authoring traversal 定位，不是 Source `id`，也不会自动写入或生成 Graph/Entity/Relation identity

Definition options 可以直接传给三个 React 组件或三个 Vanilla adapter。持久化 IR 通过下面任一装配入口使用相同 definitions：

```ts
const scene = compileToScene(sourceIR, {
  composites: createGraphDefinitions(options),
});
```

registries 是 assembly-local；同 key 的不同 Definition objects fail-loud，不使用 last-wins、module-global registration 或内置白名单
