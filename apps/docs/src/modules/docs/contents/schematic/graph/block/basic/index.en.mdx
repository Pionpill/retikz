`Block` is an open content container that Relations can target. It arranges arbitrary Core or Tier 2 children vertically in authored order, making it useful for code structures, engineering objects, and custom graph nodes. Header, Section, and Row are optional common compositions

## Usage

```tsx
import { Block, BlockHeader, BlockRow, BlockSection } from '@retikz/graph-react';
```

```tsx
<Block id="user">
  <BlockHeader title="User" description="Domain entity" />
  <BlockSection title="Fields">
    <BlockRow content={['name', 'string']} />
  </BlockSection>
</Block>
```

`Block` provides built-in components such as `BlockHeader`, `BlockSection`, and `BlockRow`, while also accepting any retikz component

## Examples

### Built-in components

The Block family provides four common built-in components:

| Element        | Responsibility                                                            |
| -------------- | ------------------------------------------------------------------------- |
| `Block`        | Provides the targetable outer column layout and visible boundary          |
| `BlockHeader`  | Shows a required title, optional description, and open icon / trail slots |
| `BlockSection` | Gives ordered content an optional title and independent boundary          |
| `BlockRow`     | Arranges one or more text items horizontally through `content`            |

The playground builds a minimal data structure using only built-in components. The first Section is always present. Its controls can add an extra Row to that Section or add a second Section, then independently adjust spacing between the Block's direct children, items inside each Section, and content items inside each Row. Row uses a horizontal Flex layout: one item fills the available width, two split it 1:1, and three split it 1:1:1. Every item can be a string or an `IRBlockText` object with local text styles. Row content defaults to the `sm` font size. The equal-sharing defaults—`basis: 0`, `grow: 1`, `shrink: 1`, and `min: 0`—apply during lowering and are not written back to Source IR

## How it works

  type="tip"

### Layout composition

Block passes authored children to a column FlexLayout, then uses Standard Surface for the shell. The Header shell always arranges icon → text region → trail horizontally; title and description default to a vertical text region and can switch to horizontal. Section uses a column layout. Row reuses the Header / Section `IRBlockText` contract and lowers `content` to borderless ordinary Core Nodes while preserving explicit text styles; `children` map arbitrary direct children to equal-share row Flex items. Each is backed by its own Definition and provider, so Header, Section, and Row also compile outside Block

Block has an effective default `minWidth` of `240`; gap, padding, appearance, and sizing defaults apply during resolve / lowering without being written into sparse Source IR. Explicit `width` or `minWidth` wins, and empty children keep the same stable Scope → Surface → Flex root shape

### Identity and theme

Block supports the complete Core Scope, including `localNamespace`; Section and Row reuse the same contract. Explicit ids are published in the actual Core namespace and do not automatically receive a Block prefix. Duplicate ids, invisible targets, anchors, and boundary failures continue to use Core diagnostics

A named Graph Theme supplies the Block root shell `background`, `border`, and `cornerRadius` baseline. Explicit Source fields on Block win through complete top-level field replacement, so an authored `border` does not deep-merge Theme dash, opacity, or width fields

`graphTheme` crosses only known Graph, Group, Block, Header, Section, Row, and Core Scope content boundaries before projecting into visible Entities and Relations. It does not directly style structure shells, ordinary Core children, or unknown Tier 2 composites

## API Reference

Direct IR, React, and Vanilla entries produce the same JSON-safe Source. Block, Section, and Row reuse the complete Core Scope and Standard Surface fields. `IRBlockText` accepts a plain string or a text object with style overrides; the tables expand only fields introduced or constrained by these components

The shell appearance defaults in the Block table come from the Neutral Graph Theme. A same-name Graph Theme Definition may replace the baseline for omitted fields without writing values back into Source

### IRBlockText

| Prop            | Type                | Default  | Description                                       |
| --------------- | ------------------- | -------- | ------------------------------------------------- |
| `text`          | `IRTextBlock`       | required | Single-line string or multiline text content      |
| `align?`        | Core text alignment | —        | Alignment within a multiline text block           |
| `lineHeight?`   | `number`            | —        | Text line height                                  |
| `maxTextWidth?` | `number`            | —        | Maximum text width before wrapping                |
| `textColor?`    | Core text color     | —        | Text color override                               |
| `font?`         | `IRFont`            | —        | Local font family, size, weight, and style values |
| `opacity?`      | `number`            | —        | Text opacity                                      |

A direct string is equivalent to setting only `text`. The object exposes text content and text styles, not Node identity, position, padding, fill, or stroke

### Block

| Prop            | Type                         | Default                      | Description                                                           |
| --------------- | ---------------------------- | ---------------------------- | --------------------------------------------------------------------- |
| `children?`     | `ReadonlyArray<IRChild>`     | —                            | Arbitrary ordered children; `ReactNode` in React authoring            |
| `graphTheme?`   | `IRGraphThemeLayer`          | —                            | Local Graph Theme layer                                               |
| `width?`        | `number`                     | —                            | Fixed outer width including horizontal padding                        |
| `minWidth?`     | `number`                     | `240`                        | Minimum outer width including horizontal padding; omitted from Source |
| `gap?`          | `number`                     | `8`                          | Vertical space between children                                       |
| `padding?`      | `SurfaceInput['padding']`    | `8`                          | Outer shell padding                                                   |
| `background?`   | `SurfaceInput['background']` | transparent                  | Outer shell background                                                |
| `border?`       | `SurfaceInput['border']`     | `currentColor` / `0.2` / `1` | Outer shell border                                                    |
| `cornerRadius?` | `number`                     | `8`                          | Outer shell corner radius                                             |
| `overflow?`     | `'visible' \| 'clip'`        | `'visible'`                  | Surface overflow semantics                                            |

### BlockHeader

| Prop              | Type                         | Default      | Description                                                                                     |
| ----------------- | ---------------------------- | ------------ | ----------------------------------------------------------------------------------------------- |
| `icon?`           | `IRChild`                    | —            | At most one arbitrary child before the text region                                              |
| `title`           | `IRBlockText`                | required     | String or text object; primary title defaults to `base` and bold with opacity `1`               |
| `description?`    | `IRBlockText`                | —            | String or text object; secondary text defaults to `xs` and opacity `0.7`                        |
| `direction?`      | `'horizontal' \| 'vertical'` | `'vertical'` | Layout direction of the title and description text region; does not change the outer slot order |
| `itemGap?`        | `number`                     | `4`          | Minimum physical gap between title and description                                              |
| `justifyContent?` | Flex main distribution       | `'start'`    | Main-axis free-space distribution in the text region; reuses FlexLayout semantics               |
| `trail?`          | `IRChild`                    | —            | At most one arbitrary child after the text region                                               |

### BlockSection

| Prop        | Type                     | Default | Description                                                     |
| ----------- | ------------------------ | ------- | --------------------------------------------------------------- |
| `title?`    | `IRBlockText`            | —       | Optional string or text-object title placed before the children |
| `children?` | `ReadonlyArray<IRChild>` | —       | Arbitrary ordered children                                      |
| `gap?`      | `number`                 | `4`     | Vertical space between Section items                            |

Section defaults to `8` padding, a `currentColor / 0.037` background, no border, and an `8` corner radius while reusing the complete Scope and Surface fields. The background follows the current foreground color across light and dark themes, and an explicit `background` / `border` wins

### BlockRow

| Prop            | Type                           | Default | Description                                                                                 |
| --------------- | ------------------------------ | ------- | ------------------------------------------------------------------------------------------- |
| `row.content?`  | `IRBlockText \| IRBlockText[]` | —       | String or text object; one fills the Row, many share it; mutually exclusive with `children` |
| `row.children?` | `ReadonlyArray<IRChild>`       | —       | Arbitrary direct children; one fills the Row and many share it with the same defaults       |
| `row.gap?`      | `number`                       | `8`     | Horizontal space between Row items                                                          |

Row defaults to no padding (`0`), a horizontal gap of `8`, and an `sm` content font size, with a transparent background, no border, and no corner radius while reusing the complete Scope and Surface fields. Explicit `content.font.size` wins. Prefer `content` for ordinary text and local text styles; use `children` directly for a complete Node shell, other composites, or arbitrary custom content. Every direct child lowers with `basis: 0`, `grow: 1`, `shrink: 1`, and an effective `min: 0`; these values are not written back to Source
