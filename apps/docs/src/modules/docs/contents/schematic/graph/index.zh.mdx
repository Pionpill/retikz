title: Graph
description: 用可选 Graph Scope、Block、Group、Entity、Relation 与任意 Core 内容建立可组合图式。
---

Graph 是一个可选的上下文薄壳。它复用 Core `Scope` 的完整能力，并额外向可见的 Entity 与 Relation 后代提供局部 `graphTheme`；自动布局、routing 算法和 renderer 不属于 Graph。

Block、Group、Entity 与 Relation 也是独立的 Tier 2 composite，可以直接放在 Layout、Scope 或其它接受 Core child 的位置。Block 用固定 Header、Section、Row 与 Cell 表达代码和工程对象；Graph 不维护成员列表或 identity index，Relation 的引用与重复 id 诊断统一交给 Core namespace。

## 两种宿主模式

Graph 作为顶层 React 组件时，和 Layout、Plot、Table 一样建立一个 Scene 宿主，不需要再包一层 Layout：

```tsx
<Graph width={420} height={160}>
  <Entity id="service" role="activity" position={[120, 80]}>
    服务
  </Entity>
</Graph>
```

如果外层已经有 Layout，Graph 只下沉为影响局部内容的一个 Scope，不创建第二个 SVG 或 Canvas：

```tsx
<Layout width={800} height={220}>
  <Graph transforms={[{ kind: 'translate', x: 80, y: 40 }]}>
    <Entity role="activity" position={[120, 80]}>
      局部内容
    </Entity>
  </Graph>
</Layout>
```

`theme`、`nodeDefault`、`pathDefault`、`labelDefault`、`arrowDefault`、`resetStyle`、`transforms`、`placement`、`zIndex`、`clip` 等字段直接属于 `IRGraph`，并沿用 Core Scope 语义。`width`、`height`、renderer、runtime 与 DOM 属性只属于 standalone Scene 宿主；嵌入 Graph 时应把这些属性放到外层 Layout。

## 职责一览

| 成员       | 职责                                                       | 不负责                        |
| ---------- | ---------------------------------------------------------- | ----------------------------- |
| Graph      | Core Scope 公共面与局部 Graph Theme                        | 成员索引、排布、routing       |
| Block      | 结构化对象、局部 Flex 排版与可寻址 Section / Row           | Port 模型、执行、自动 routing |
| Group      | 任意内容的可见边界、caption 与 boundary labels             | 自动排布、routing、避障       |
| Entity     | 节点语义，并独立下沉为普通 Core Node                       | 生成 id、承载任意绘图 child   |
| Relation   | Core NodeTarget endpoint、关系语义，并独立下沉为 Core Path | Graph 成员校验、自动 routing  |
| Core child | 与 Entity、Relation 按作者顺序自由组合                     | 消费 Graph-local 语义规则     |
