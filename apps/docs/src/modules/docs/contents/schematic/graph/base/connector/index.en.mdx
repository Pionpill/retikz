title: Relation

`Relation` is a lightweight relationship IR that retains the `graph` namespace. It directly reuses Core stroke Path steps, targets, labels, marks, strokes, and transforms, then lowers one-to-one through `RelationDefinition` into a same-id Core Path. It does not maintain a parallel route model, compute automatic routes, or avoid obstacles

## Usage

```tsx
import { FoldStepVia } from '@retikz/core';
import { Layout, Scope, Step } from '@retikz/react';
import { Relation, Entity } from '@retikz/graph-react';
```

```tsx
<Layout width={420} height={160}>
  <Scope transforms={[{ kind: 'translate', x: 24, y: 56 }]}>
    <Entity id="start" role="terminal" position={[0, 0]}>
      Start
    </Entity>
  </Scope>
  <Scope transforms={[{ kind: 'translate', x: 220, y: 56 }]}>
    <Entity id="step" role="stage" position={[0, 0]}>
      Step
    </Entity>
  </Scope>
  <Relation id="start-to-step" role="flow">
    <Step kind="move" to="start" />
    <Step kind="fold" via={FoldStepVia.HorizontalThenVertical} to="step" label={{ text: 'next' }} />
  </Relation>
</Layout>
```

React `<Step>` children are the Path authoring form and preserve the complete Core Step contract. Put a label on the exact step that should carry it instead of routing it through a Relation-specific projection

## Two authoring forms

Relation offers two mutually exclusive inputs but persists only one canonical IR:

```ts
import { DrawWay } from '@retikz/core';
import { createRelation } from '@retikz/graph';

const bySteps = createRelation({
  id: 'edge-a',
  role: 'flow',
  children: [
    { kind: 'move', to: 'start' },
    { kind: 'line', to: 'step' },
  ],
});

const byWay = createRelation({
  id: 'edge-b',
  role: 'flow',
  way: ['start', DrawWay.Hv, 'step'],
});
```

- The Path form supplies `children: Array<IRStep>` and is the only persisted JSON form
- The Draw form supplies `way: WayDSL`; the factory, React, or Vanilla authoring entry immediately reuses Core `parseWay()` to produce `children`
- Exactly one of `children` or `way` is required; supplying both or neither fails loudly
- `way` is not part of `RelationSchema` and never enters JSON, a Definition, or the Scene

<ComponentPreview files="connector-routing" size="lg" />

Direct JSON must contain canonical `children` and explicitly inject `RelationDefinition`. Vanilla `relation()` returns an embed; `RelationInputEmbedAdapter` creates a same-id `IRRelation` from the embed id

When `marks` is omitted, Relation adds one terminal arrow. An explicit `marks` array completely replaces that default, so `marks: []` explicitly disables arrows

## How it works

<ComponentAlert
  type="tip"
  title="Optional for everyday use"
  description="Read this section only when diagnosing canonicalization, Definitions, or Core Path behavior."
/>

`RelationDefinition` removes only `namespace`, semantic `type`, and the authored-only `role`, then passes every other field to a Core stroke Path while preserving the authored `id`. Relation creates no typed artifact, wrapper, private geometry, or renderer branch. New applicable public Core Path fields can flow through the reused schema surface

`role` expresses authored semantics only; it is not copied implicitly into Path `meta` or a Scene primitive. Targets follow Core Step behavior and diagnostics exactly. The former Container section target, `from/to/routing/appearance` surface, and Relation-specific route constants have been removed

## API Reference

| Field                  | Type                               | Default               | Description                                                                |
| ---------------------- | ---------------------------------- | --------------------- | -------------------------------------------------------------------------- |
| `id`                   | `string`                           | —                     | Stable authored Relation identity and lowered Core Path id                 |
| `role`                 | `RelationRoleValue`                | —                     | Relation semantic retained only in Graph IR                                |
| `children`             | `Array<IRStep>`                    | —                     | Canonical Core Path Step sequence and the only JSON geometry form          |
| `way` (authoring only) | `WayDSL`                           | —                     | Mutually exclusive with `children` and normalized through `parseWay()`     |
| `marks?`               | Core Path mark placements          | terminal arrow at `1` | An explicit array fully replaces the default; `[]` disables arrows         |
| Other Path fields      | Applicable Core stroke Path fields | Core defaults         | Labels, stroke, fill, dash, caps/joins, corners, transforms, metadata, etc |
