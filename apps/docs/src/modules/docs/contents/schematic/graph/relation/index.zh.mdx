Relation 表达两个对象之间的关系。用 `source` 和 `target` 引用端点，选择 `role` 决定关系语义与默认箭头，再按需要添加标签、方向和路径。端点可以是 Entity，也可以是 Core Node、Coordinate 或其它组件发布的命名目标。

## 职责一览

| 能力       | 负责什么                                                   | 何时使用                   |
| ---------- | ---------------------------------------------------------- | -------------------------- |
| 端点引用   | 保存 source 与 target，不因箭头反向而交换                  | 连接已有命名对象           |
| 关系语义   | role、kind 与 predicate 描述关系，direction 选择允许的方向 | 表达依赖、继承或领域关系   |
| 路径与标签 | 默认直连，接受显式 route 和沿线 labels                     | 调整走线或补充关系说明     |
| 外观       | 继承主题、状态和 Graph 规则，允许实例覆盖                  | 统一图表风格或强调一条关系 |

图中的两个 Entity 提供命名端点；Relation 用 `flow` 表达从发送到接收的流动。端点的位置由对象决定，关系负责连接它们。

## 职责与边界

Relation 不创建端点，也不自动布局或避障。只需要自由绘制路径时使用 Core Path；需要自动安排流程节点时使用 [FlowDiagram](/schematic/diagram/flow)。Graph 可以提供共享定义与外观上下文。

`source` / `target`、`direction` 与 `route` 分别描述端点、语义方向和几何路径。自定义路径不会反过来改写端点；改变箭头方向也不会交换对象的身份。
