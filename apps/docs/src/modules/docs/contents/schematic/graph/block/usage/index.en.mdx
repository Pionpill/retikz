## Organize content

### Built-in components

The Block family provides four common built-in components:

| Element        | Responsibility                                                            |
| -------------- | ------------------------------------------------------------------------- |
| `Block`        | Provides the targetable outer column layout and visible boundary          |
| `BlockHeader`  | Shows a required title, optional description, and open icon / trail slots |
| `BlockSection` | Gives ordered content an optional title and independent boundary          |
| `BlockRow`     | Arranges one or more text items horizontally through `content`            |

The playground builds a minimal data structure using only built-in components. The first Section is always present. Its controls can add an extra Row to that Section or add a second Section, then independently adjust spacing between the Block's direct children, items inside each Section, and content items inside each Row. Row uses a horizontal Flex layout: one item fills the available width, two split it 1:1, and three split it 1:1:1. Every item can be a string or an `IRBlockText` object with local text styles. Row content defaults to the `sm` font size. The equal-sharing defaults—`basis: 0`, `grow: 1`, `shrink: 1`, and `min: 0`—apply during lowering and are not written back to Source IR

### Custom elements

Both `BlockHeader.icon` and `BlockHeader.trail` accept an arbitrary child, and a Block body is not limited to Section or Row. ### Independent regions and connections

Section and Row support the complete Core Scope and can participate in Core addressing through explicit ids. Relation keeps using `NodeTarget + anchor / boundary`; Block does not create a second Port IR

### Encapsulating code entities

To store names, properties, or logic as an independent entity, see [Block extension usage](/schematic/graph/block/custom). A strict Source and Definition generate Block content while reusing its layout, theme, and connection capabilities.

## Errors and limits

- `BlockRow.content` and `children` are mutually exclusive. Use content for text and children for full nodes or other components.
- Header requires title and accepts at most one child in each icon / trail slot. Header has no independent Scope id.
- Block / Section / Row ids receive no parent prefix. Use localNamespace when names need isolation.
- width and minWidth include horizontal padding; omitted Block minWidth resolves to 240. Compile defaults do not mutate Source.
- graphDefaults / graphRules affect visible descendants. Style the current shell with background / border / cornerRadius. An explicit border replaces the entire theme border field.
