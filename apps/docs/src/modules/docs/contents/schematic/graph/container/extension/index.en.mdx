The basic shell covers one local structure. When Container carries Entity values, nests another Container, or is generated outside JSX, it still reuses the same canonical header and sections child contract

## Extension boundary

Extended Container usage covers region composition, Entity variant inheritance, nested containers, and non-React input. It does not own automatic layout strategy, graph topology, automatic routing, or a separate geometry engine

## Entity variant inheritance

`entityVariant` provides a default only for descendant Entity values; it does not change the Container shell or divider. A nested Container shadows the outer scope, explicit Entity `variant` wins, and `variant="default"` resets the inherited value

```tsx
import { Container, ContainerSection, Entity } from '@retikz/graph-react';

<Container id="order" entityVariant="secondary">
  <ContainerSection sectionKey="input">
    <Entity id="load" role="stage" position={[0, 0]} />
  </ContainerSection>
  <ContainerSection sectionKey="important">
    <Entity id="validate" role="stage" position={[0, 0]} variant="primary" />
  </ContainerSection>
</Container>;
```

## Direct IR and Definition injection

Direct IR uses the same JSON-safe child contract as JSX and explicitly injects `ContainerDefinition`. A region child can be a Node, Path, Entity, another composite, or a nested Container

```ts
import { createContainer, ContainerDefinition } from '@retikz/graph';

const block = createContainer({
  id: 'order',
  header: { child: { type: 'node', position: [0, 0], text: 'Order' } },
  sections: [{ key: 'body', child: { type: 'node', position: [0, 0], text: 'Body' } }],
});

const compile = { composites: [ContainerDefinition] };
```

If children contain Entity or Relation values, inject their Definitions too; use `createGraphDefinitions()` to provide the complete Graph set

## Vanilla adapter

Vanilla uses an embed id for Container. The adapter derives the canonical `id` internally and sends the elements actually used through the same Definition path

```ts
import { ContainerInputEmbedAdapter, container } from '@retikz/graph-vanilla';

const embed = container('order', {
  sections: [{ key: 'body', child: { type: 'node', position: [0, 0], text: 'Body' } }],
});
const adapters = [ContainerInputEmbedAdapter];
```

## How it works

  type="tip"

The compiler creates a synthetic column FlexLayout region for the header and sections, then projects the Flex artifact into the Container artifact. Region children enter the same Core compilation path; the shell and divider are visual projections rather than a second authored graph

## API Reference

| Prop                  | Type                       | Default                               | Description                                            |
| --------------------- | -------------------------- | ------------------------------------- | ------------------------------------------------------ |
| `entityVariant?`      | `EntityVariantValue`       | omitted                               | Default variant for descendant Entity values           |
| `size?`               | `LayoutSizeInput`          | content allocation                    | Outer allocation policy                                |
| `appearance?`         | `ContainerAppearanceInput` | neutral shell, radius `8`, divider on | Shell, divider, corner radius, and stacking appearance |
| `createContainer()`   | `@retikz/graph`            | —                                     | Creates canonical Container IR                         |
| `ContainerDefinition` | `@retikz/graph`            | —                                     | Connects Container IR to compilation                   |
