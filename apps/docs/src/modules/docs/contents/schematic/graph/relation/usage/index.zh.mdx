### 连接端点

React / Vanilla 支持 `source="sender"`，入口会归一为 `{ id: 'sender' }`。IR 和 `createRelation()` 只接受完整对象；需要指定锚点时使用 `source={{ id: 'sender', anchor: 'right' }}`。可引用 Core Node、Coordinate、已解析 Scope 或上层组件发布的 target；重复 id 或找不到目标由 Core 报错。

端点和方向分别保存。`reverse` 把箭头放到 source 一端，不会交换 source / target 的语义身份。方向必须属于当前 role / kind 允许的集合。

## 选择关系语义

五个内置 role 定义关系的上位语义、source / target 基础解释、允许 direction 与 marker family。Relation **没有内置 kind 或 predicate**；`kind` 必须由用户注册，`predicate.name` 和 params 也需要对应 definition

Relation 的示例统一使用默认风格，并支持明暗模式。下面的 controls 只开放当前 role 支持的 direction、状态和精确 Relation 颜色；需要统一定制外观时，可使用 Graph 默认值与条件规则

`kind` 用于用户定义的领域分类。未指定时使用 role 默认结构；指定后必须在当前 provider assembly 中注册，未注册会报错。定义和注册方式见[自定义](/schematic/graph/relation/custom)

| role             | 默认方向  | 默认路径与端点                     |
| ---------------- | --------- | ---------------------------------- |
| `association`    | `forward` | 实线；target 端实心 `diamond`      |
| `dependency`     | `forward` | 实线；target 端开放 `straightBarb` |
| `generalization` | `forward` | 实线；target 端实心 `normal`       |
| `flow`           | `forward` | 实线；target 端 `stealth`          |
| `influence`      | `forward` | 实线；target 端 `circle`           |

### association：关联关系

`association` 表示两个对象之间的一般关联。默认使用 `forward`，在 target 端使用实心 `diamond`；也可以显式选择 `none`、`reverse` 或 `both`

- **默认 / 允许 direction：** `forward` / `none`、`forward`、`reverse`、`both`
- **内置 predicate：** 无；领域扩展可以注册 cardinality predicate，并用 params schema 校验 source / target 基数

### dependency：依赖关系

`dependency` 表示 source 依赖 target：source 是依赖方，target 是被依赖方。它固定为 `forward`，默认以实线路径和 target 端开放、无填充的 `straightBarb` 表达

- **默认 / 允许 direction：** `forward` / 仅 `forward`
- **内置 predicate：** 无；扩展可以声明 `{ optional: boolean, reason: string }` 等 params，具体字段和值域由 predicate definition 决定

### generalization：泛化关系

`generalization` 表示 source 是 target 的更具体类型：source 是 subtype，target 是 supertype。它固定为 `forward`，默认以实线路径和 target 端实心 `normal` 箭头表达

- **默认 / 允许 direction：** `forward` / 仅 `forward`
- **内置 predicate：** 无；类型系统扩展可以用 params 表达 discriminator 或约束，但 Graph 不执行类型检查

### flow：对象之间的流动

`flow` 表示对象、活动或状态之间发生传递、推进或状态流转。source 与 target 是稳定 route endpoints，有效 direction 决定 stealth marker 位于哪一端

- **默认 / 允许 direction：** `forward` / `forward`、`reverse`、`both`
- **内置 predicate：** 无；工作流扩展可以声明 `{ expression: string, priority: number }` 等条件 params，Graph 只校验和保存，不执行条件

### influence：影响关系

`influence` 表示一个对象对另一个对象产生作用，不要求它们之间存在数据传递或执行依赖。有效 direction 决定实心圆形 `circle` marker 位于 source、target 或两端

- **默认 / 允许 direction：** `forward` / `forward`、`reverse`、`both`
- **内置 predicate：** 无；分析模型可以声明 `{ weight: number, confidence: number }` 等 params，并通过 Theme selector 选择 appearance

### 语义状态

`status` 为 Relation 保存可直接读取的图式状态：`error`、`success`、`warning` 与 `disabled` 分别使用当前 Core Theme 的 `semantic.error`、`semantic.success`、`semantic.warning` 与 `semantic.guide`。`disabled` 还会以 `[6, 4]` 虚线绘制箭身，箭头 marker 保持灰色与原有 shape。省略 status 表示没有特别标记，不写入 `normal`。状态只提供 appearance 默认，不改变 role、kind、direction、route 或 marker shape

每个 Relation role demo 的 controls 都可在“无状态”和这四种状态之间切换。Relation 的 path 与实际存在的 source / target marker 会继承同一 status 颜色。显式 path、marker 或 label appearance 最终优先，但保留 Source status；领域 predicate 的 `params.status` 也不会自动映射到这里

## 标签与路径

`labels` 接受 Core GeometryLabel。`text` 支持换行字符串和文字行数组；默认位于路径中心线上，默认字体为 `sm`，文字颜色跟随 Relation 主色。单个 label 的 `textColor`、`font` 与 `opacity` 覆盖关系级默认。

省略 `route` 时从 source 直连 target。显式 `route` 是至少两个 Core Step 的完整序列，使用根坐标空间；React / Vanilla 的 `way` 会归一为 route，React 也支持 Step children。三种编写形式互斥。关系标签放在 `labels`，不能放到 route step 的 `label` 上。

```tsx
<Relation
  role="flow"
  source="sender"
  target="receiver"
  way={['sender', [200, 140], 'receiver']}
  labels={[{ text: '传输', position: 0.5 }]}
/>
```

这条折线路径必须自己包含需要经过的端点和拐点；Relation 不补接首尾，也不自动避开障碍物。

## 错误与限制

- 未注册 role / kind / predicate、kind 与 role 不匹配、非法 direction 或 predicate 参数都会报错。内置关系不包含 predicate。
- `style` 不提供 fill、fillOpacity、fillRule；Relation 不开放任意 Path marks。需要这些能力时直接使用 Core Path。
- Graph 内相同 `group` 的 Entity / Relation 共享分类色；它不是 Group 容器。独立 Relation 不分配组色。状态和组色提供默认，显式外观与匹配的作者规则优先。
