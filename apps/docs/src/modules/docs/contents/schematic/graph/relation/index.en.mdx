---
title: Relation
description: Connect named objects to express association, dependency, flow, generalization, or influence.
---

Relation describes a relationship between two objects. Reference endpoints with `source` and `target`, choose a `role` for its semantics and default markers, then add labels, direction, or a route as needed. Endpoints may be Entities, Core Nodes, Coordinates, or named targets published by other components.

## Responsibilities

| Capability             | Responsibility                                                                            | When to use it                                           |
| ---------------------- | ----------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| Endpoint references    | Preserve source and target even when markers reverse                                      | Connect existing named objects                           |
| Relationship semantics | role, kind, and predicate describe the relation; direction selects an allowed orientation | Express dependency, inheritance, or domain relationships |
| Paths and labels       | Connect directly by default; accept explicit routes and labels                            | Adjust geometry or explain a relationship                |
| Appearance             | Inherit theme, status, and Graph rules with instance overrides                            | Coordinate a diagram's style or emphasize one relation   |

The two Entities provide named endpoints. The Relation uses `flow` to express transmission from sender to receiver. Objects determine their positions; the relation connects them.

## Boundaries

Relation does not create endpoints, lay out objects, or route around obstacles. Use Core Path for free-form geometry, or [FlowDiagram](/schematic/diagram/flow) for automatic flow-node placement. Graph supplies optional shared definitions and appearance context.

`source` / `target`, `direction`, and `route` describe endpoint identity, semantic direction, and geometry respectively. A custom route does not rewrite endpoints, and reversing markers does not exchange object identities.
