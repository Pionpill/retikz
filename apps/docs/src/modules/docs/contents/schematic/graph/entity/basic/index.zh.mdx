title: Entity 基础用法
description: 用一个精简 record 编写节点语义、文本与位置，并在任意 Core child 位置独立使用。
---

`Entity` 是带可选 Core identity 的语义节点。语义、文本与 Core Node-compatible 位置都直接写在同一个 record 中，最终独立 lower 为一个普通 Core `Node`。省略 `id` 时只绘制节点，不注册可被引用的 Core target

## 用法

```tsx
import { Entity } from '@retikz/graph-react';
import { Layout } from '@retikz/react';
```

```tsx
<Layout width={360} height={140}>
  <Entity id="task" role="activity" position={[180, 70]}>
    处理订单
  </Entity>
</Layout>
```

`Entity` 可以直接放在 Layout、Scope、Graph 或其它接受 Core child 的位置。children 只接受字符串、数字、Fragment 或 Core `<Text>`，并写入直接 `text` 字段；任意绘图内容应作为它的 sibling，而不是 Entity child

## 例子

七个内置 role 只定义上位语义和基础 shape recipe。Graph **没有内置 Entity kind 或 predicate**；`kind` 与 `predicate.name` 只有先在当前 provider assembly 注册后才能使用。下文列出的 kind 和 params 都是领域扩展示例，不是可直接使用的内置值

Entity 的整体外观统一由 Theme 管理。下面每个 demo 都允许精确调整实例颜色和文本；页面顶部的 Theme selector 统一切换 Academic、Vibrant、Clean 等整体视觉风格

Neutral 默认也是 Graph Clean 完整继承的简洁样式：`stroke: 1` 使用最终静态主色绘制完整描边，`fill: 0.08` 将同一主色按 8% 权重在当前 mode backdrop 上预合成为不透明填充，`textColor: 'contrast'` 再根据最终填充解析为黑色或白色正文。这里的 `0.08` 是 contextual color 权重，不是 `fillOpacity`

### participant：参与主体

`participant` 表示主动参与、负责或提供能力的主体。典型对象包括人员、团队、组织、外部系统和服务；如果对象描述的是被执行的工作，应使用 `activity`，如果只是被消费或保存的对象，应使用 `resource`

- **内置 kind / predicate：** 无
- **可注册 kind 示例：** `participant.person`、`participant.team`、`participant.system`；这些只是全局唯一 key 的示例
- **可控制 predicate params 示例：** 扩展可以用 `paramsSchema` 声明 `{ capacity: number, region: string }`，但内置 `participant` 不接受任何预设 params

### activity：工作与动作

`activity` 表示正在发生或需要执行的工作、动作和转换过程。典型对象包括任务、处理步骤、子流程和系统操作；持续存在的条件属于 `state`，瞬时发生点属于 `event`

- **内置 kind / predicate：** 无
- **可注册 kind 示例：** `activity.task`、`activity.subprocess`、`activity.operation`
- **可控制 predicate params 示例：** 扩展可以声明 `{ retryable: boolean, slaMinutes: number }`，具体字段、默认值和范围完全由该 predicate 的 `paramsSchema` 决定

### event：发生点

`event` 表示时间上的发生点、边界或生命周期事件。典型对象包括开始、结束、超时、消息到达和异常发生；它不表示持续执行的任务，也不表示持续成立的条件

- **内置 kind / predicate：** 无
- **可注册 kind 示例：** `event.start`、`event.end`、`event.timer`、`event.message`
- **可控制 predicate params 示例：** 扩展可以声明 `{ interrupting: boolean, channel: string }`；Graph 只保存通过该 schema 的 JSON-safe params

<ComponentPreview files="entity-event" size="sm" caption="调整 event 的默认描边、Graph Theme 主色和文本。" />

### state：持续条件

`state` 表示对象或系统在一段时间内持续存在的条件。典型对象包括等待中、已激活、已暂停和失败；触发状态变化的动作属于 `activity`，状态切换发生的时刻可以建模为 `event`

- **内置 kind / predicate：** 无
- **可注册 kind 示例：** `state.pending`、`state.active`、`state.failed`
- **可控制 predicate params 示例：** 扩展可以声明 `{ severity: 'low' | 'high', terminal: boolean }`，枚举和值域由 `paramsSchema` 校验

<ComponentPreview files="entity-state" size="sm" caption="调整 state 的默认描边、Graph Theme 主色和文本。" />

### gateway：语义控制点

`gateway` 表示有明确语义的分叉、汇合或同步控制点。典型对象包括互斥选择、并行拆分、并行汇合和多路同步；不要仅因为想要菱形外观就使用它，也不要用它代替参与者或业务资源

- **内置 kind / predicate：** 无
- **可注册 kind 示例：** `gateway.exclusive`、`gateway.parallel`、`gateway.inclusive`
- **可控制 predicate params 示例：** 扩展可以声明 `{ mode: 'split' | 'merge', branches: number }`，例如用 params 驱动强调程度而不改变 gateway 的结构 recipe

<ComponentPreview files="entity-gateway" size="sm" caption="调整 gateway 的默认描边、Graph Theme 主色和文本。" />

### resource：被使用或保存的对象

`resource` 表示被使用、产生、传递或存储的对象。典型对象包括文档、数据库、消息队列、数据集和制品；能够主动参与并提供能力的系统通常应建模为 `participant`。默认轮廓由上下两个半椭圆端和两侧直线闭合，顶部不会形成完整椭圆；对称的纵向 padding 让文本保持垂直居中

- **内置 kind / predicate：** 无
- **可注册 kind 示例：** `resource.document`、`resource.database`、`resource.queue`
- **可控制 predicate params 示例：** 扩展可以声明 `{ mutable: boolean, replicas: number }`，并由 predicate resolver 把已校验参数映射为稀疏外观 token

### concept：抽象知识对象

`concept` 表示不直接对应运行时实例的抽象知识对象。典型对象包括 class、claim、topic、domain concept 和规则；具体执行步骤使用 `activity`，可连接的运行主体使用 `participant`

- **内置 kind / predicate：** 无
- **可注册 kind 示例：** `concept.class`、`concept.claim`、`concept.topic`
- **可控制 predicate params 示例：** 扩展可以声明 `{ confidence: number, source: string }`，但 params 仍只是该 predicate 的领域契约，不是 `concept` role 的固定字段

## 技术原理

  type="tip"
  title="上手阶段可跳过本节"
  description="需要持久化 Graph data、接入 Diagram 或排查 compile 输入时再回来阅读。"
/>

Entity Source record 只保存作者提供的字段。`id`、`text` 与 `position` 都可省略，不会产生空 wrapper、自动 id 或默认属性；省略 `id` 的 Entity 仍会按 role 绘制，但不会向 Core namespace 注册 target。role 在编译时提供 shape、boundary、padding、cornerRadius 与基础 minimum size；Theme 提供外观默认，Entity 显式 `color`、`fill`、`dashed`、`dashPattern`、`textColor` 等非结构 Node 字段最终覆盖 Theme

显式静态 `color` 会同时驱动默认的数值 stroke 与 fill。`currentColor` 等非静态主色如果仍需解析任一数值颜色通道，编译会明确失败；调用方应改用静态 `color`，或同时提供字符串 stroke 与不透明静态 fill，避免猜测宿主 CSS 颜色或背景

Entity 自己完成 registry lookup 并 lower 为普通 Core `Node`。Core、Scene 和 renderer 不解释 Entity role；Graph 只在存在时额外提供局部 Theme context，不是 Entity 的编译前提

## API 参考

| 属性         | 类型                                      | 默认值 | 描述                                               |
| ------------ | ----------------------------------------- | ------ | -------------------------------------------------- |
| `id?`        | `string`                                  | —      | 可选 Core target id；省略时不注册引用目标          |
| `role`       | `string`                                  | —      | 已注册的开放语义角色 key                           |
| `kind?`      | `string`                                  | —      | role 内已注册的稳定子类型                          |
| `predicate?` | `{ name: string; params?: IRJsonObject }` | —      | 已注册 predicate 及其 JSON-safe 参数               |
| `position?`  | `IRPosition`                              | —      | 直接复用 Core Node position language               |
| `text?`      | `IRNode['text']`                          | —      | Node-compatible text                               |
| `children?`  | Node-compatible text                      | —      | React authoring 的文本入口；不能承载任意绘图 child |
| `meta?`      | `IRJsonObject`                            | —      | Graph 不解释的元信息                               |
