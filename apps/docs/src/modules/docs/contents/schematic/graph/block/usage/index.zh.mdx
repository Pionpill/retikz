用 Block 将标题、分区和文本行组合为可以被关系连接的对象。先完成[快速开始](/schematic/graph/get-start)，再选择下方任一接入方式。

## 接入方式

          title: '字段',
          children: [
            {
              namespace: 'graph',
              type: 'blockRow',
              content: ['name', 'string'],
            },
          ],
        },
      ],
    },
  ],
};
const Example: FC = () => <Layout ir={ir} extensions={{ composites: createGraphDefinitions() }} />;

<DocTab value="vanilla-api" label="Vanilla API">

```tsx
import { block, blockHeader, blockSection, blockRow, createGraphVanillaAdapters } from '@retikz/graph-vanilla';
import { scene } from '@retikz/vanilla';
import { mount } from '@retikz/vanilla/dom';
const input = scene({
  children: [
    block({
      id: 'user',
      children: [
        blockHeader({ title: 'User', description: '领域实体' }),
        blockSection({ title: '字段', children: [blockRow({ content: ['name', 'string'] })] }),
      ],
    }),
  ],
});
const view = mount(document.getElementById('diagram')!, input, { adapters: createGraphVanillaAdapters() });
```

## 组织内容

### 内置组件

Block family 提供四个常用的内置组件：

| 元素           | 职责                                                        |
| -------------- | ----------------------------------------------------------- |
| `Block`        | 提供可被关系引用的外层纵向布局与可见边界                    |
| `BlockHeader`  | 展示必填 title 与可选 description，并提供 icon / trail slot |
| `BlockSection` | 为一组有序内容提供可选标题与独立边界                        |
| `BlockRow`     | 用 `content` 横向排列一个或多个文本项                       |

下面的 playground 只使用内置组件组合最小数据结构。第一个 Section 始终存在；controls 可以为它添加额外 Row，或添加第二个 Section，并分别调整 Block 直接 children、Section 内部 items 与 Row 内容项之间的间距。Row 使用横向 Flex 布局：一个内容项占满可用宽度，两个内容项按 1:1 均分，三个内容项按 1:1:1 均分；每项既可以是字符串，也可以是带局部文字样式的 `IRBlockText` 对象。Row content 默认使用 `sm` 字号；等分所需的 `basis: 0`、`grow: 1`、`shrink: 1` 与 `min: 0` 是 lowering 默认值，不会写回输入 Source IR

### 自定义元素

`BlockHeader` 的 `icon` 与 `trail` 都接受任意 child，`Block` body 也不限于 Section 或 Row。下面的例子在 Header 两侧放入自定义 Core Node，并在 body 中直接加入一个普通 Node；controls 可以修改这个 Node 的内容、shape、尺寸、变换与外观，所有状态都与内置结构共用同一条编译链路

### 独立区域与连接

Section 与 Row 支持完整的 Core Scope，并可通过显式 `id` 参与 Core 的寻址。Relation 继续复用 `NodeTarget + anchor / boundary`；Block 不建立第二套 Port IR

本例固定 Block 宽度与内容高度；右侧 way 的终点使用已编写的坐标。修改内容或字体后需要重新调整路径，它不是自动寻路示例。

### 样式调整

Block 外框复用 Standard Surface。这个 playground 通过 controls 改变 shell 的内边距、背景、边框与圆角，并分别调整 `BlockHeader` title、description 与 `BlockRow.content` 的颜色、字号、字重、字形和透明度

### 封装代码实体

需要把名称、属性或逻辑保存为独立实体时，参阅 [Block 扩展用法](/schematic/graph/block/extension)。它使用严格 Source 与 Definition 生成 Block 内容，并复用现有布局、主题和连接能力。

## 错误与限制

- `BlockRow.content` 与 `children` 互斥；文字用 content，需要完整节点外壳或其他组件时使用 children。
- Header 的 title 必填，icon / trail 各接受至多一个 child。Header 不提供独立 Scope id。
- Block / Section / Row 的 id 不自动加父级前缀；需要隔离名称时使用 localNamespace。
- width 与 minWidth 包含水平 padding；省略时 Block 的有效 minWidth 为 240。默认值在编译时生效，不写回 Source。
- graphDefaults / graphRules 作用于可见后代，当前 Block 外框直接用 background / border / cornerRadius 设置。显式 border 替换主题的整个 border 字段。
