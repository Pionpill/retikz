`@retikz/graph` owns JSON-safe Source IR, Definition registries, resolve, and lowering. Graph, Entity, and Relation are independently compilable Tier 2 composites. Graph additionally reuses the complete Core Scope contract: it creates a Scene as a top-level React host and contributes only one local Scope when embedded

## Graph Source composite

Source IR stores authored facts only. Omitted `children`, positions, routes, text, Theme, and styles do not materialize empty objects, defaults, or generated ids. Graph owns no member collection; it only projects local Graph context to semantic descendants and preserves the complete ordered child tree

<ZodSchema name="GraphSchema" />

Graph `children` directly uses Core `ChildSchema` and may mix Entity, Relation, Node, Coordinate, Path, Scope, and other composites in author order. Core Scope semantics remain intact for `theme`, style defaults, transforms, placement, clipping, bounding shape, animations, and `meta`. Only `graphTheme` is Graph-specific

Entity role and Relation role / kind are open keys. Their schemas expose built-in const-object vocabularies as TypeScript and JSON Schema suggestions while still accepting arbitrary non-blank custom strings; registration is checked only during resolve. Entity kind and predicate name currently have no built-in vocabulary, so they remain ordinary non-blank strings

```json
{
  "namespace": "graph",
  "type": "graph",
  "nodeDefault": { "strokeWidth": 1.5 },
  "children": [
    {
      "namespace": "graph",
      "type": "entity",
      "id": "start",
      "role": "event",
      "position": [80, 80]
    },
    {
      "namespace": "graph",
      "type": "relation",
      "role": "flow",
      "source": { "id": "start" },
      "target": { "id": "task" }
    },
    { "type": "node", "id": "task", "position": [320, 80], "text": "Process" }
  ]
}
```

See the [Scope schema](/kernel/reference/schema/scope) for nested field shapes and inheritance rules.

## Entity schema

Entity keeps semantics and Core Node instance fields in one Source record. Every Node field is available except role-owned `type`, `shape`, `boundary`, `padding`, and `cornerRadius`. `id`, `position`, and `text` are optional. The current Core Theme and optional Graph Theme supply appearance defaults, while explicit Entity fields such as `fill`, `dashed`, and `textColor` take final precedence

<ZodSchema name="EntitySchema" />

Omitting `id` generates no internal id and registers no target in the Core namespace. The Entity is still drawable; provide an id only when references need one

## Relation schema

Relation keeps Core `IRNodeTarget` endpoints, semantics, complete Core Geometry Labels, and an optional Core route together. `RelationSchema` excludes only the discriminator and kind, `children` / `label`, arbitrary `marks`, and the fill family from `PathBaseSchema`; every other Core Path field is reused directly. Relation resolve performs no Graph membership validation. Core Path resolves Nodes, Coordinates, resolved Scopes, or targets published by upper composites and owns unresolved / duplicate-id diagnostics

<ZodSchema name="RelationSchema" />

Theme is a source of Relation defaults, not a field whitelist. Explicit Relation Path paint, stroke, effect, dash, and transform fields take final precedence. The public `labels` type is `Array<IRGeometryLabel>`; each label's `textColor`, `opacity`, and individual font fields then override Relation label defaults

The complete public type of `source` and `target` is `IRNodeTarget`:

| Field       | Type               | Default                 | Description                                              |
| ----------- | ------------------ | ----------------------- | -------------------------------------------------------- |
| `id`        | `string`           | —                       | Node, Coordinate, resolved Scope, or composite target id |
| `anchor?`   | `IRAnchorRef`      | consuming context       | Named, angle, or boundary-fraction anchor                |
| `offset?`   | `[number, number]` | —                       | World-space offset applied after anchor resolution       |
| `boundary?` | `IRBoundary`       | target default boundary | Per-endpoint connection-surface override                 |

When `route` is omitted, lowering emits `move(source) → line(target)`. An explicit route uses `Array<IRGraphRelationRouteStep>`, retains the complete Core Position language, and cannot carry labels on route steps

## Master and derived colors

Entity and Relation `color` values are string masters. Applicable `fill`, `stroke`, text foreground, and marker colors may also use a `0..1` number, which Core resolves only after Graph Theme, Graph-local rules, and instance fields have fully cascaded. Entity follows its final Entity master. Relation stroke, labels, and marker color follow the Relation master, while marker fill follows the resolved marker color. A number is not opacity, and palettes, gradient stops, patterns, and shadow colors remain string-only.

<ZodSchema name="GraphThemeLayerSchema" />

Core `theme` selects or overrides the general Theme. `graphTheme` stores only Graph-local ordered appearance rules. Entity rules may select by role, kind, or predicate, while Relation rules may additionally select by direction. A role owns complete structure, and a kind or predicate may contribute an allowed structural delta

The `resolve(theme)` callback passed to `defineGraphThemeStyle()` returns `GraphThemeStyleOverrides` and only declares fields that differ from the mode-aware default preset. `entity`, `relation`, and their `tokens` and `rules` are all optional; an explicitly `undefined` known token in the runtime callback is treated as omitted. An explicit `tokens: {}` remains invalid because a token override must contain at least one field, and the returned value may contain only plain-data containers

```ts
const compact = defineGraphThemeStyle({
  name: 'compact',
  resolve: () => ({
    entity: { tokens: { strokeWidth: 1.5 } },
  }),
});

const composites = createGraphDefinitions({ graphThemeStyles: [compact] });
```

Graph resolve materializes complete appearance in the following order, with each later source overriding only the fields it declares:

1. Graph default preset tokens for the current Core Theme mode
2. Sparse custom style tokens
3. Default Graph rules
4. Custom style rules
5. Outer-to-inner Graph-local `graphTheme` rules
6. Explicit Entity / Relation appearance fields

Custom style rules append after the defaults. Omitting `rules` or returning `rules: []` never clears built-in rules. An unknown Core Theme style still requires a Graph Theme style Definition with the same name and fails loudly during resolve otherwise

## React and Vanilla authoring

React `<Graph>` collects arbitrary Core and Tier 2 children in author order. Entity children write direct `text`; Relation `<Step>` children write direct `route`. `<Entity>` and `<Relation>` may also appear directly in Layout, Scope, or any other Core-child position

Standalone and embedded Graph share the same Source contract:

```tsx
<Graph width={420} height={160}>...</Graph>

<Layout width={800} height={220}>
  <Graph transforms={[{ kind: 'translate', x: 80, y: 40 }]}>...</Graph>
</Layout>
```

Standalone `width`, `height`, `viewBox`, renderer, runtime, and DOM props belong to the Layout Scene host; move them to the outer Layout when Graph is embedded. `transforms`, `placement`, `zIndex`, and `clip` belong directly to `IRGraph`; there is no extra panel envelope

Vanilla `normalizeGraph()`, `normalizeEntity()`, and `normalizeRelation()` perform factory validation, child normalization, and optional `way → route` sugar only. They neither split envelopes nor materialize defaults. `createGraphVanillaAdapters()` installs all three adapters

The first argument of `graph(traversalId, input)`, `entity(traversalId, input)`, and `relation(traversalId, input)` is only a Vanilla authoring traversal id. It is not Source `id` and never writes or generates Graph, Entity, or Relation identity

Definition options can be passed directly to all three React components or Vanilla adapters. Persisted IR uses the same definitions through either assembly entry:

```ts
const scene = compileToScene(sourceIR, {
  composites: createGraphDefinitions(options),
});
```

Registries are assembly-local. Different Definition objects competing for one key fail loudly; there is no last-wins behavior, module-global registration, or built-in whitelist dispatch
