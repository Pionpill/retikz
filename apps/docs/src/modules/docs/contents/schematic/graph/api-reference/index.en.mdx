`@retikz/graph` owns persisted Graph IR, Definitions, registries, resolve, and lowering. The React and Vanilla packages only normalize their authoring input into that same IR. Graph ultimately lowers to Core `Scope`, `Node`, and `Path` values

## Public exports

| Capability | Graph                                                                                 | React                        | Vanilla                                                                      |
| ---------- | ------------------------------------------------------------------------------------- | ---------------------------- | ---------------------------------------------------------------------------- |
| Graph      | `GraphSchema`, `IRGraph`, `createGraph`, `GraphDefinition`, `GraphProviderKey`        | `Graph`                      | `graph`, `GraphInputEmbedAdapter`                                            |
| Entity     | `EntitySchema`, `IREntity`, `createEntity`, `EntityDefinition`                        | `Entity`                     | `entity`, `EntityInputEmbedAdapter`                                          |
| Relation   | `RelationSchema`, `IRRelation`, `createRelation`, `RelationDefinition`                | `Relation`                   | `relation`, `RelationInputEmbedAdapter`                                      |
| Container  | `ContainerSchema`, `IRContainer`, `createContainer`, `ContainerDefinition`            | `Container`, markers         | `container`, `ContainerInputEmbedAdapter`                                    |
| Extensions | Three `defineXxx` helpers, `GraphDefinitionOptions`, `GraphThemeToken`, registry APIs | —                            | —                                                                            |
| Assembly   | `createGraphDefinitions`, `createGraphProviders`                                      | Declare options on `<Graph>` | Declare options on `graph()`; `createGraphVanillaAdapters` installs adapters |

`GraphType` exposes the four public discriminators `graph`, `container`, `entity`, and `relation`. Roles and variants are open non-blank strings; `EntityRole`, `EntityVariant`, and `RelationRole` still provide the built-in vocabularies

## Graph presentation root

`IRGraph` is an optional global presentation root. It creates a same-id Core Scope and supplies descendant Entities with a default variant, local tokens, and selector rules:

| Field                   | Type                           | Semantics                                 |
| ----------------------- | ------------------------------ | ----------------------------------------- |
| `namespace`             | `'graph'`                      | Graph owner                               |
| `type`                  | `'graph'`                      | Presentation-root discriminator           |
| `id?`                   | `string`                       | Core Scope id after lowering              |
| `entityVariant?`        | `string`                       | Default variant for descendant Entities   |
| `graphThemeTokens?`     | `IRGraphThemeTokenOverrides`   | Local tokens for this Graph scope         |
| `graphThemeTokenRules?` | `IRGraphEntityThemeTokenRules` | Ordered rules by effective role / variant |
| `children`              | `Array<IRChild>`               | Graph-owned or ordinary Core children     |

An explicit Entity `variant` wins over the nearest Graph or Container default, while explicit `default` resets an outer default. Nested Graph tokens merge field by field from outer to inner without leaking into siblings

## Entity input and Theme

Entity reuses the applicable Core Node authoring surface. `id`, `role`, and `position` are required, while string children or `<Text>` become Node text. A role Definition supplies shape, padding, and optional minimum size; explicit Entity fields win independently

Final primary color comes from the Graph Theme baseline, rules, layers, and Entity `color`. An omitted value or `currentColor` becomes black in Light mode or white in Dark mode before entering a variant Definition. Explicit Entity fields always have final priority for other appearance values

`GraphThemeToken` contains:

- `graph.entity.color`
- `graph.entity.text.foreground`
- `graph.entity.fill` / `graph.entity.stroke` / `graph.entity.strokeWidth`
- `graph.entity.fillOpacity` / `graph.entity.strokeOpacity` / `graph.entity.opacity`

## Relation and Container

Canonical `IRRelation` JSON uses Core Step `children`. `createRelation`, React, and Vanilla also accept an authoring-only Core `WayDSL`, which normalizes to `children` at the boundary. Omitting `marks` adds a terminal arrow; an explicit `marks` value, including `[]`, completely replaces that default

Container retains headers, sections, layout artifacts, and its `entityVariant` scope. The Container shell, dividers, and Relation do not consume Entity Theme tokens

## Definition and provider assembly

Direct IR gets five composite Definitions from `createGraphDefinitions(options)`. A provider graph uses `GraphProviderKey` as its root and receives the complete dependency closure from `createGraphProviders(options)`:

```ts
const options = {
  entityRoles: [serviceRole],
  entityVariants: [mutedVariant],
  graphThemeStyles: [brandGraphTheme],
};

const scene = compileToScene(ir, {
  composites: createGraphDefinitions(options),
});
```

Repeated contributions with the same key and same Definition object are deduplicated; different objects sharing a key fail. Every registry is assembly-local and does not mutate module-global state

## React and Vanilla

`<Graph>` and `graph(id, input)` both accept multiple children and produce a same-id `IRGraph`. `entityRoles`, `entityVariants`, and `graphThemeStyles` are declared directly on the Graph authoring input: React carries them on `<Graph>`, while Vanilla carries them on `graph()`. `createGraphVanillaAdapters()` only installs the four Graph, Container, Entity, and Relation embed adapters

The default `<Layout>` JSX path uses built-in definitions. For a custom role, variant, or Graph Theme style, declare the options directly on `<Graph>`; when you already have persisted IR, render it through `<Layout ir composites={createGraphDefinitions(options)}>`
