`@retikz/graph` owns JSON-safe Source IR, Definition registries, resolve, and lowering. Graph, Group, Block, BlockHeader, BlockSection, BlockRow, Entity, and Relation compile independently. Graph additionally hosts a Scene at the top React level, Group composes general visible boundaries, and Block vertically arranges open content

## Graph Source composite

Source IR stores authored facts only. Omitted `children`, positions, routes, text, Theme, and styles do not materialize empty objects, defaults, or generated ids. Graph owns no member collection; it only projects local Graph context to semantic descendants and preserves the complete ordered child tree

<ZodSchema name="GraphSchema" />

Graph `children` directly uses Core `ChildSchema` and may mix Entity, Relation, Node, Coordinate, Path, Scope, and other composites in author order. Core Scope semantics remain intact for `theme`, style defaults, transforms, placement, clipping, bounding shape, animations, and `meta`. `graphDefaults` and `graphRules` are the Graph-specific defaults and rule inputs

Entity role and Relation role / kind are open keys. Their schemas expose built-in const-object vocabularies as TypeScript and JSON Schema suggestions while still accepting arbitrary non-blank custom strings; registration is checked only during resolve. Entity kind and predicate name currently have no built-in vocabulary, so they remain ordinary non-blank strings

```json
{
  "namespace": "graph",
  "type": "graph",
  "defaults": { "node": { "style": { "strokeWidth": 1.5 } } },
  "children": [
    {
      "namespace": "graph",
      "type": "entity",
      "id": "start",
      "role": "event",
      "position": [80, 80]
    },
    {
      "namespace": "graph",
      "type": "relation",
      "role": "flow",
      "source": { "id": "start" },
      "target": { "id": "task" }
    },
    { "type": "node", "id": "task", "position": [320, 80], "text": "Process" }
  ]
}
```

See the [Scope schema](/kernel/reference/schema/scope) for nested field shapes and inheritance rules.

## Group schema

Group stores a nested arbitrary-`IRChild` containment relation and composes the complete Core Scope surface, Standard Surface presentation, a structured caption, and Core `IRNodeLabel` values. Caption and Surface participate in allocation, while outside labels expand visual bounds only. Group performs no authored-child layout, routing, obstacle avoidance, or collision handling

<ZodSchema name="GroupSchema" />

The Neutral Graph Theme supplies the Group root shell baseline: background `lightgray` / `0.04`, border `lightgray` / `1` with `dashPattern` `[4, 3]`, and corner radius `4`. A same-name Graph Theme Definition can replace those three omitted fields, and explicit Source fields win. Other defaults are consumed only during lowering: padding `10` and overflow `visible`. Caption defaults to top and horizontal arrangement with `itemGap` / `bodyGap` of `4`; the title defaults to `sm` without a bold weight, and the description defaults to `xs` with 0.7 opacity. Group boundary labels default to the description's `xs` font size and gray (`gray`), while explicit font and color fields remain authoritative. They default to Core attachment-tangent `start` when `align` is omitted, and to `{ boundary: 'bottom', fraction: 0 }` when `position` is omitted; they attach to the left end of the bottom boundary and offset downward outside the shell, aligning the text's left edge with the shell's left edge. All other position, boundary, placement, rotation, keep-upright, and pin contracts remain direct Core `NodeLabelSchema` contracts, with `placement` still defaulting to `outside`

## Block schema

Block stores arbitrary ordered `IRChild` values and combines a column FlexLayout with Standard Surface into an addressable open-content container. Block, Section, and Row reuse the complete Core Scope, including `localNamespace`. Their explicit ids are published in the actual Core namespace without an automatic Block prefix

The Neutral Graph Theme supplies the Block root shell baseline: a transparent background, a `currentColor / 0.2 / 1` border, and corner radius `8`. A same-name Graph Theme Definition can replace those three omitted fields, and explicit Source fields win. Other Block lowering defaults are gap `8`, padding `8`, and overflow `visible`; Section defaults to padding `8`, a `currentColor / 0.037` background, and a `currentColor / 0.1 / 1` border, while Row defaults to padding `0` and a horizontal gap of `8`. `width` and `minWidth` constrain the outer width including horizontal padding; when both are omitted, the effective `minWidth` is `240` without being written into Source. Header, Section, and Row are independent composites; Section accepts arbitrary children. Row `content: IRBlockText | IRBlockText[]` reuses the Header / Section text structure, defaults to the `sm` font size, and preserves an explicit `font.size`; one item fills the Row and many items share it equally, and `content` is mutually exclusive with `children`. Complete Node shells and custom content go directly into `children: IRChild[]` and share the Row with the same defaults. Relations connect to actual lower targets through the existing `IRNodeTarget + anchor / boundary` rather than a Port IR

## Entity schema

Entity instance appearance and layout use `style` / `layout`; Relation path appearance uses `style`. Graph / Group / Block Scope cascading values use `style`, and descendant defaults use `defaults`. Graph Theme output and `graphDefaults` follow the corresponding Source paths; `graphRules` uses the same restricted appearance fields.

Entity keeps semantics and Core Node instance fields in one Source record. Every Node field is available except role-owned `type`, `shape`, `boundary`, `layout.padding`, and `cornerRadius`. `id`, `position`, `text`, and closed `status` are optional. The current Core Theme and optional Graph Theme supply appearance defaults, while explicit Entity fields such as `style.fill`, `style.dashed`, and `style.textColor` take final precedence

<ZodSchema name="EntitySchema" />

Omitting `id` generates no internal id and registers no target in the Core namespace. The Entity is still drawable; provide an id only when references need one

## Relation schema

Relation keeps Core `IRNodeTarget` endpoints, semantics, optional closed `status`, complete Core Geometry Labels, and an optional Core route together. `RelationSchema` excludes only the discriminator and kind, `children` / `label`, arbitrary `marks`, and the fill family from `PathBaseSchema`; every other Core Path field is reused directly. Relation resolve performs no Graph membership validation. Core Path resolves Nodes, Coordinates, resolved Scopes, or targets published by upper composites and owns unresolved / duplicate-id diagnostics

<ZodSchema name="RelationSchema" />

Theme is a source of Relation defaults, not a field whitelist. Explicit Relation Path paint, stroke, effect, dash, and transform fields take final precedence. The public `labels` type is `Array<IRGeometryLabel>`; each label's `textColor`, `opacity`, and individual font fields then override Relation label defaults

The complete public type of `source` and `target` is `IRNodeTarget`:

| Field       | Type               | Default                 | Description                                              |
| ----------- | ------------------ | ----------------------- | -------------------------------------------------------- |
| `id`        | `string`           | —                       | Node, Coordinate, resolved Scope, or composite target id |
| `anchor?`   | `IRAnchorRef`      | consuming context       | Named, angle, or boundary-fraction anchor                |
| `offset?`   | `[number, number]` | —                       | World-space offset applied after anchor resolution       |
| `boundary?` | `IRBoundary`       | target default boundary | Per-endpoint connection-surface override                 |

When `route` is omitted, lowering emits `move(source) → line(target)`. An explicit route uses `Array<IRGraphRelationRouteStep>`, retains the complete Core Position language, and cannot carry labels on route steps

## Master and derived colors

Entity and Relation `style.color` values are string masters. Applicable `fill`, `stroke`, text foreground, and marker colors may also use a `0..1` number, which Core resolves only after Graph Theme, Graph-local rules, and instance fields have fully cascaded. Entity follows its final Entity master. Relation stroke, labels, and marker color follow the Relation master, while marker fill follows the resolved marker color. A number is not opacity, and palettes, gradient stops, patterns, and shadow colors remain string-only.

## Shared references and Graph Theme

<ZodSchema name="GraphPredicateRefSchema" />

<ZodSchema name="GraphDefaultsSchema" />

Core `theme` selects the theme environment. `graphDefaults` supplies explicit descendant defaults, while `graphRules` independently stores ordered rules; either can be used alone. Defaults retain Source paths: Entity uses `style` / `layout`, Relation keeps marker and label formatting at the root, and Group / Block use root Surface fields. Defaults exclude content, identity, roles, routing, and algorithm policy.

| Rule contract                                        | Assignments                                           | Selectors                                      |
| ---------------------------------------------------- | ----------------------------------------------------- | ---------------------------------------------- |
| Entity branch of `GraphRuleSchema` / `IRGraphRule`   | `style` without `font`; no `layout`                   | `role`, `kind`, `predicate`, `status`          |
| Relation branch of `GraphRuleSchema` / `IRGraphRule` | Restricted `style` and root marker / label formatting | The same conditions plus effective `direction` |

Relation defaults and rules exclude fill and structural dashPattern. Marker appearance cannot create a marker or change its shape / size. Group and Block have no selector rules.

The `resolve(theme)` callback of `defineGraphThemeStyle()` returns `GraphThemeStyleSource`: `{ defaults?, rules? }`. Its defaults share the graphDefaults fragment, and its rules share the graphRules contract. There is no tokens wrapper. Empty fragments, empty groups, and optional `undefined` known fields supply no override; valid `0`, `false`, and field-permitted `null` values remain meaningful.

```ts
const compact = defineGraphThemeStyle({
  name: 'compact',
  resolve: () => ({
    defaults: {
      entity: { style: { strokeWidth: 1.5 }, layout: { maxTextWidth: 180 } },
      group: { cornerRadius: 2 },
      block: { border: { stroke: 'currentColor', strokeWidth: 1.5 } },
    },
    rules: [{ type: 'entity', selector: { status: 'error' }, style: { strokeWidth: 3 } }],
  }),
});

const composites = createGraphDefinitions({ graphThemeStyles: [compact] });
```

Local precedence, from lowest to highest:

1. Neutral defaults for the current Core Theme mode
2. Defaults from the matching Graph Definition
3. Matching Neutral and named Definition rules, in declaration order
4. Author scopes from outer to inner, applying each layer’s graphDefaults before its matching graphRules
5. Entity / Relation instance fields

Inner defaults can therefore override outer rules, and instance fields always win. Empty rule arrays do not clear upstream rules. Changing `theme` or setting Core `defaults.reset` preserves author defaults and rules. Optional font/layout fields that remain absent continue using the existing Core defaults channels.

`style` / `layout` merge by field. A nonempty Node font replaces the whole font; Relation labelFont completes individual fields before each label.font is applied. Compound leaves such as background, border, paint, shadow, and margin replace whole values without recursive merging.

A Group / Block shell uses the incoming Core Theme, ancestor author defaults, and its own explicit Surface fields. Its own graphDefaults / graphRules apply only to descendants. Projection follows existing Graph/Core content boundaries and does not enter Flow or unknown composite internals.

An unregistered matching Graph Theme style reports `DefinitionNotRegistered`. Invalid callback output and callback exceptions are wrapped by the Graph owner with their cause preserved.

## React and Vanilla authoring

React `<Graph>` and `<Block>` collect arbitrary Core and Tier 2 children in author order. `<BlockHeader>`, `<BlockSection>`, and `<BlockRow>` are independent embeds. Header exposes the `icon` and `trail` slots. Pass ordinary Row text through `content` and use children directly for custom content. Entity children write direct `text`, and Relation `<Step>` children write direct `route`

Standalone and embedded Graph share the same Source contract:

```tsx
<Graph>...</Graph>

<Layout>
  <Graph transforms={[{ kind: 'translate', x: 80, y: 40 }]}>...</Graph>
</Layout>
```

Standalone `width`, `height`, `viewBox`, renderer, runtime, and DOM props belong to the Layout Scene host; move them to the outer Layout when Graph is embedded. `transforms`, `placement`, `zIndex`, and `clip` belong directly to `IRGraph`; there is no extra panel envelope

Vanilla `normalizeBlockHeader()`, `normalizeBlockSection()`, and `normalizeBlockRow()` behave like the other Graph-family normalizers and only assemble Source. Header uses `trail` for its right-side child. Row `content` remains unchanged, and children directly accept arbitrary `InputGraphChild` values. `createGraphVanillaAdapters()` installs every independent adapter

The first `traversalId` argument of every Graph-family builder only locates Vanilla authoring. It is not Source `id` and never writes or generates semantic identity

Definition options can be passed directly to each React composite or Vanilla adapter. Persisted IR uses the same definitions through either assembly entry:

```ts
const scene = compileToScene(sourceIR, {
  composites: createGraphDefinitions(options),
});
```

Registries are assembly-local. Different Definition objects competing for one key fail loudly; there is no last-wins behavior, module-global registration, or built-in whitelist dispatch
