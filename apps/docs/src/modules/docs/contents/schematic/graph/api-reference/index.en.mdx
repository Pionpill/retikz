Graph is split by responsibility: `@retikz/graph` provides canonical JSON, schemas, factories, and Definitions; `@retikz/graph-react` provides React authoring; `@retikz/graph-vanilla` provides embed-returning builders and explicit adapters. All three entries normalize to the same Graph IR and lower through the same Definitions

## Public exports

| Capability | Graph                                                                      | React                | Vanilla                                   |
| ---------- | -------------------------------------------------------------------------- | -------------------- | ----------------------------------------- |
| Entity     | `EntitySchema`, `IREntity`, `createEntity`, `EntityDefinition`             | `Entity`             | `entity`, `EntityInputEmbedAdapter`       |
| Relation   | `RelationSchema`, `IRRelation`, `createRelation`, `RelationDefinition`     | `Relation`           | `relation`, `RelationInputEmbedAdapter`   |
| Container  | `ContainerSchema`, `IRContainer`, `createContainer`, `ContainerDefinition` | `Container`, markers | `container`, `ContainerInputEmbedAdapter` |

All three public elements retain `namespace: 'graph'` and their semantic `type`. Entity uses `role` for the four base semantics. Definitions are explicit lowering contracts from Graph IR to Core IR and never enter persisted JSON

## Entity inputs

`Entity` reuses the applicable Core Node authoring surface. `id`, `role`, and `position` are required, string children or `<Text>` become Node text, `role` supplies a default shape, and explicit `shape` can replace it

```tsx
<Entity id="step" role="stage" position={[0, 0]}>Process</Entity>
<Entity id="check" role="decision" position={[80, 0]}><Text>Ready?</Text></Entity>
```

The matching factory returns canonical Graph IR rather than a Core `IRNode`. Its Definition then lowers it one-to-one into a same-id Node:

```ts
const step = createEntity({ id: 'step', role: 'stage', position: [0, 0], text: 'Process' });
// { namespace: 'graph', type: 'entity', role: 'stage', id: 'step', ... }
```

## Relation inputs

Canonical `IRRelation` JSON uses Core Step `children`. `createRelation`, React, and Vanilla also accept a Core `WayDSL` `way` authoring shorthand. The two forms are mutually exclusive, and `way` is normalized through `parseWay()` at the authoring boundary, so it is never persisted. `role` uses the closed Relation relation vocabulary and is discarded during lowering

Omitting `marks` adds a terminal arrow; an explicit `marks` value, including `[]`, completely replaces that default

## Definition loading

Direct IR must explicitly inject the Definition for every Graph element used by the figure. When one is missing, Core fails loudly with its unregistered-composite diagnostic:

```ts
import { compileToScene } from '@retikz/core';
import { RelationDefinition, EntityDefinition } from '@retikz/graph';

compileToScene(scene, {
  composites: [EntityDefinition, RelationDefinition],
});
```

React components and Vanilla adapters contribute only the Definitions required by the authored elements and do not register global state

## Vanilla identity

`entity` and `relation` return embeds and use their embed ids to create the corresponding Graph IR. Entity and Relation lower to same-id Core Node / Path values; Container retains its derived ids under its multi-element composite contract
