Every concrete Diagram needs to assemble its title, description, legend, and drawing core into one result. Diagram Framework concentrates these domain-independent responsibilities in a shared Foundation so that concrete types own only their drawing semantics.

The figure shows the complete assembly: the outer boundary carries Frame / Appearance, the title, description, and legend belong to Presentation, and a concrete Diagram type provides the gray dashed region.

## Three layers

| Layer              | Current abstraction                                                                                  | Owner                 |
| ------------------ | ---------------------------------------------------------------------------------------------------- | --------------------- |
| Presentation       | Title, description, and explicit Standard Legend outside the drawing core                            | Diagram Framework     |
| Frame / Appearance | Spacing, region arrangement, legend docking, background, border, radius, overflow, and Diagram Theme | Diagram Framework     |
| Drawing Core       | Measurement, layout, routing, and domain semantics for the drawn objects                             | Concrete Diagram type |

The layers remain orthogonal: Frame spacing does not become node spacing inside the drawing core, and Presentation does not inspect drawing-domain data. A concrete Diagram only passes its completed drawing child into the Framework assembly.

## Presentation

Titles and descriptions reuse Core `TextBlock`, including multiple lines, line-level and run-level styling, and mixed text / TeX runs. Legends reuse an explicit Standard Legend instead of introducing a Diagram-specific legend model.

Titles, descriptions, and legends are all optional regions. When a region is absent, its container and spacing collapse completely and leave no empty allocation in the final layout.

## Frame and Appearance

Frame controls separate gaps from title to description, heading to main, and drawing to legend. The Legend can dock to the top, right, bottom, or left and align along the tangent axis of its docking side.

The complete figure reuses Standard Surface padding, background, border, corner radius, and overflow. Diagram Theme adds a Neutral baseline, same-name style Definitions coordinated with Core Theme, and sparse instance overrides.

## Unified assembly

Framework combines present regions into a fixed heading / main structure and treats the concrete drawing child as opaque input. Every region passes through Layout Flex, Standard Surface, and Core Scope into the same Scene, bounds, clipping, and export result.

Framework retains only independent facts and neither reads, changes, nor persists the drawing child's domain semantics. It also publishes no Diagram-specific identity, metadata, or artifact; Layout and Legend results remain owned by their existing dependencies.

## Boundary with concrete Flow

- Framework still exposes no abstract `IRDiagram` or instantiable generic Diagram root
- `FlowDiagram` exposes Source, React, and Vanilla authoring through symmetric `./flow` package entries
- The drawing child remains internal assembly input instead of becoming a public Flow Source `body`
- Flow owns Graph measurement, automatic layout, routing, orchestration, and `FlowDiagramArtifact`

These boundaries keep Framework as the shared foundation for concrete Diagrams, while [Flow Diagram](/schematic/diagram/flow) exposes only the domain contracts required for its complete loop.
