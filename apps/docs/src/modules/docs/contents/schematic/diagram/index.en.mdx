title: Diagram
description: Combine a shared Diagram Framework with a concrete drawing core to produce complete figures that are laid out, rendered, and exported as one unit.
---

Diagram serves figures that need to be delivered as a complete unit. It does not redefine nodes, relations, or drawing primitives. Instead, it provides shared supporting regions, framing, and an output boundary outside a concrete drawing core.

Graph describes the objects and relations inside a graph. A concrete Diagram type decides how to measure, arrange, and connect them, while Diagram Framework owns the shared assembly between those layers.

## Responsibilities

| Layer             | Owns                                                                | Does not own                                     |
| ----------------- | ------------------------------------------------------------------- | ------------------------------------------------ |
| Graph             | Block, Group, Entity, Relation, and relation semantics              | Complete assembly, automatic layout, or routing  |
| Diagram Framework | Presentation, Frame, Appearance, and output boundary                | Interpretation or rewriting of a drawing core    |
| Concrete Diagram  | Domain drawing core, measurement, layout, routing, and result model | Copies of Core, Layout, or Standard capabilities |

The first concrete type is `FlowDiagram`. It closes the loop from an LLM-friendly relation Source through an automatic layout Definition and Graph materialization to a renderer-neutral artifact.
