Flow represents steps as entities and their connections as relations. Runtime layout computes positions. Start with the minimal result, then add groups, routing, or shared styles as needed.

## Using this topic

In React, declare a Flow with `FlowDiagram` and its children. In Vanilla, construct the Source with `flowDiagram()`. Existing JSON IR requires the Flow provider in its host. See [Diagram quick start](/schematic/diagram/get-start) for basic host setup.

## Basic layout

A Flow Source contains the members below. React components declare them; the runtime computes positions and connection paths from entities, containers, and relations.

| Element          | React member                    | Source member      | Purpose                                                                               |
| ---------------- | ------------------------------- | ------------------ | ------------------------------------------------------------------------------------- |
| Flow diagram     | `FlowDiagram`                   | Entire Flow Source | Collects diagram elements and triggers automatic layout and connections               |
| Entity           | `FlowEntity`, `FlowEntities`    | `entities`         | Represents a step or node, with optional text, role, and status                       |
| Relation         | `FlowRelation`, `FlowRelations` | `relations`        | Declared at the Flow root; connects entity or group ids through `source` and `target` |
| Semantic group   | `FlowGroup`                     | `groups`           | Draws a visible boundary around members and sets local layout and routing             |
| Layout container | `FlowLayout`                    | `layouts`          | Fixes members in a linear or grid arrangement without drawing a frame                 |

The form submission flow starts with user input, passes through a frontend form and backend service, then writes to the database. The frontend form `text` is a Core `TextBlock`: its main text accepts line breaks, while its subtitle is a separately styled text line. The panel also changes alignment, line height, and maximum width for the whole text block; these Entity-level `layout` fields neither apply to individual lines nor change the Flow layout. Optional Entity and Relation `status` values project directly to Graph: Graph Theme owns their appearance, while status does not change layout or routing.

## Connections and routing

A Relation routing setting changes its path without defining a new layout.

| `routing.kind` | Behavior                                       | Notes                                                                                                                                               |
| -------------- | ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `straight`     | Connects the endpoints directly                | Built-in default; a simple path without automatic obstacle avoidance                                                                                |
| `orthogonal`   | Orthogonal polyline following layout direction | Midpoint-first avoidance with three turn positions; optional locked fraction and rounded corners. Aligned endpoints stay straight without avoidance |
| `-\|`          | Horizontal then vertical from source           | Fixed single elbow, independent of layout direction; optional rounded corner, no automatic avoidance                                                |
| `\|-`          | Vertical then horizontal from source           | Fixed single elbow, independent of layout direction; optional rounded corner, no automatic avoidance                                                |
| `bend`         | Bends by angle or endpoint tangents            | First choice for ordinary curves; automatic mode searches finite avoidance candidates, or specify a side, angle or tangents                         |
| `curve`        | Quadratic Bezier with one control point        | Use when bend candidates are insufficient; omit the control for automatic generation. An explicit control usually lies off the curve                |
| `cubic`        | Cubic Bezier with two control points           | Controls the endpoint tangents separately for more complex curves; omit both controls for automatic generation or supply both explicitly            |
| `smooth`       | Interpolates ordered intermediate waypoints    | Use for known passage positions, typically 2–3 points; checks collisions without adjusting the route automatically                                  |

Switch between eight `routing.kind` values for fixed endpoints A and B to compare straight, polyline, bend, Bezier and through-point routes. `-|` goes horizontally then vertically; `|-` goes vertically then horizontally. Neither the primary layout direction nor arrow direction changes this order, and neither mode routes around other nodes. The preview's React and Vanilla source use the same `routing` configuration.

- **straight**: The simplest direct connection, without automatic avoidance.
- **orthogonal**: Use for axis-aligned flowcharts. It compares three turn positions for avoidance by default, or locks an explicit fraction. Horizontally or vertically aligned endpoints connect directly.
- **`-|` / `|-`**: Use when the route must go horizontally then vertically, or vice versa. These single-elbow routes support rounded corners but do not avoid obstacles automatically.
- **bend**: The first choice for ordinary curves. Adjust the side, angle or tangents; automatic mode searches a finite set of avoidance candidates.
- **curve / cubic**: Use when bend is not flexible enough. They support one or two control points respectively; omitting the controls generates avoidance candidates automatically.
- **smooth**: Use when the route must pass through specified positions, typically 2–3 intermediate points. It checks for collisions without adjusting the route.

Automatic avoidance does not guarantee a collision-free route. If every candidate conflicts, it keeps the best route and warns; it does not switch routing kinds automatically.

See [Extended usage](/schematic/diagram/flow/extended) for parameters and [Implementation](/schematic/diagram/flow/mechanism) for candidate generation and collision detection.
