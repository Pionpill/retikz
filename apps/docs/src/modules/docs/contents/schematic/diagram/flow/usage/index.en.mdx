Flow represents steps as entities and their connections as relations. Runtime layout computes positions. Start with the minimal result, then add groups, routing, or shared styles as needed.

## Using this topic

In React, declare a Flow with `FlowDiagram` and its children. In Vanilla, construct the Source with `flowDiagram()`. Existing JSON IR requires the Flow provider in its host. See [Diagram quick start](/schematic/diagram/get-start) for basic host setup.

## Basic layout

A Flow Source contains the members below. React components declare them; the runtime computes positions and connection paths from entities, containers, and relations.

| Element          | React member                    | Source member      | Purpose                                                                               |
| ---------------- | ------------------------------- | ------------------ | ------------------------------------------------------------------------------------- |
| Flow diagram     | `FlowDiagram`                   | Entire Flow Source | Collects diagram elements and triggers automatic layout and connections               |
| Entity           | `FlowEntity`, `FlowEntities`    | `entities`         | Represents a step or node, with optional text, role, and status                       |
| Relation         | `FlowRelation`, `FlowRelations` | `relations`        | Declared at the Flow root; connects entity or group ids through `source` and `target` |
| Semantic group   | `FlowGroup`                     | `groups`           | Draws a visible boundary around members and sets local layout and routing             |
| Layout container | `FlowLayout`                    | `layouts`          | Fixes members in a linear or grid arrangement without drawing a frame                 |

The form submission flow starts with user input, passes through a frontend form and backend service, then writes to the database. The frontend form `text` is a Core `TextBlock`: its main text accepts line breaks, while its subtitle is a separately styled text line. The panel also changes alignment, line height, and maximum width for the whole text block; these Entity-level `layout` fields neither apply to individual lines nor change the Flow layout. Optional Entity and Relation `status` values project directly to Graph: Graph Theme owns their appearance, while status does not change layout or routing.

## Connections and routing

A Relation routing setting changes its path without defining a new layout.

| `routing.kind` | Behavior                                                         | Rounding                |
| -------------- | ---------------------------------------------------------------- | ----------------------- |
| `bend`         | Regular curve; omitted side and angle are selected automatically | No `cornerRadius`       |
| `straight`     | Straight line; built-in default                                  | No `cornerRadius`       |
| `orthogonal`   | Orthogonal polyline based on layout direction                    | Optional `cornerRadius` |
| `-\|`          | Horizontal then vertical from source                             | Optional `cornerRadius` |
| `\|-`          | Vertical then horizontal from source                             | Optional `cornerRadius` |

Switch between five `routing.kind` values for fixed endpoints A and B to compare a straight line, an orthogonal path, and two single-elbow paths. `-|` goes horizontally then vertically; `|-` goes vertically then horizontally. Neither the primary layout direction nor arrow direction changes this order, and neither mode routes around other nodes. The preview's React and Vanilla source use the same `routing` configuration.

Single-elbow routes become straight for aligned endpoints; coincident centers report a routing error. Set `cornerRadius: 0` for a sharp corner or a positive value for rounding. Parallel edges can overlap; adjust the layout when needed, rather than treating single-elbow routing as an obstacle-avoidance algorithm.

Root and Group `routing` declare routing separately from layout; Relation `routing` takes precedence. Otherwise, routing follows the nearest common Group of the endpoints, then the root and layout Definition defaults. FlowLayout does not establish a routing layer: orthogonal routing on a Group remains effective inside its nested Layout even when the root uses straight routing.

All three axis-aligned modes share radius inheritance: instance `cornerRadius`, then the ancestor's effective routing radius, then the Definition's `orthogonalCornerRadius`, which is `8` for the built-in layout. Changing `kind` preserves an inherited radius; explicit `0` disables rounding.

Writing only `routing: { kind: 'bend' }` compares left/right candidates at `30° / 45° / 60°` when no angle is authored or inherited. Set `bendDirection: 'left' | 'right'` to constrain the side, or `bendAngle` to fix the angle. Side is relative to authored source → target, independent of reverse arrows. Negative angles flip the curve; zero remains a bend route with straight geometry. The angle range is `(-180, 180)`.

Either `outAngle` or `inAngle` selects the tangent family and takes precedence over symmetric fields. The missing angle inherits from an active tangent ancestor, otherwise defaults to `0` or `180`; `looseness` defaults to `1` and only affects tangent mode. Angles are absolute screen angles: 0 points right and 90 points down. Automatic side and angle controls omit their respective fields rather than adding Source enum values.

Automatic selection prioritizes node conflicts, using labels only to break node-score ties. Edge overlaps and crossings are not compared. Ties prefer the smaller angle, then left. Explicit or inherited angles and sides are preserved; nodes and route kinds do not change. If all candidates cross nodes, it draws the chosen curve and reports `FlowBendObstacleConflict` at the original relation. Explicit sides and tangent routes are checked too. Parallel relations may overlap; the built-in layout still rejects self-loops. Only the active parameter family inherits: a local side or angle without local tangent angles exits an inherited tangent family; ignored ancestor fields never return.
