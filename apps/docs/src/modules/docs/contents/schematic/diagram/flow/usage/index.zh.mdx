Flow 用实体表示步骤，用关系表示步骤间的连接，运行时自动计算位置。先看最小结果，再决定是否需要分组、路由或共享样式。

## 接入方式

React 可用 `FlowDiagram` 及其子元素声明 Flow；Vanilla 可用 `flowDiagram()` 构造 Source。已有 JSON IR 时，需为宿主装配 Flow provider。宿主的基本接入见 [Diagram 快速开始](/schematic/diagram/get-start)。

## 基础排布

Flow Source 由下列成员组成。React 组件负责声明这些成员，运行时根据实体、容器与关系计算位置和连线路径。

| 元素     | React 成员                      | Source 成员      | 职能                                                           |
| -------- | ------------------------------- | ---------------- | -------------------------------------------------------------- |
| Flow 图  | `FlowDiagram`                   | 整个 Flow Source | 汇总图内元素，并触发自动排布与连接                             |
| 实体     | `FlowEntity`、`FlowEntities`    | `entities`       | 表示步骤或节点；可设置文字、角色与状态                         |
| 关系     | `FlowRelation`、`FlowRelations` | `relations`      | 在 Flow 根声明，按 `source` 和 `target` 的 id 连接实体或语义组 |
| 语义组   | `FlowGroup`                     | `groups`         | 为一组元素建立可见边界，并设置局部排布与路由                   |
| 排布容器 | `FlowLayout`                    | `layouts`        | 将成员按线性或网格方式固定排列，不绘制外框                     |

表单填写流程从用户输入开始，经过前端表单和后端服务，最终写入数据库。前端表单的 `text` 是 Core `TextBlock`：主文本支持换行，副标题是一条带独立颜色和字号的文本行。面板还可调整整个文本块的对齐、行距与最大宽度；这些是 Entity 级 `layout`，不会分别作用于某一行，也不会改变 Flow 的节点排布。实体和关系可选的 `status` 直接投影给 Graph；Graph Theme 负责状态外观，状态本身不改变排布或 routing。

## 连线与路由

关系的 routing 配置改变路径形状，不需要定义新布局。

| `routing.kind` | 行为                   | 备注                                                                           |
| -------------- | ---------------------- | ------------------------------------------------------------------------------ |
| `straight`     | 直接连接两端           | 内置默认；路径简洁，不自动绕开节点                                             |
| `orthogonal`   | 按布局方向生成正交折线 | 中点优先比较三个折点避让，可锁定比例和设置圆角；两端对齐时直连、不避让         |
| `-\|`          | 从 source 先水平后垂直 | 固定单折角；不随布局方向变化，可设置圆角，不自动避让                           |
| `\|-`          | 从 source 先垂直后水平 | 固定单折角；不随布局方向变化，可设置圆角，不自动避让                           |
| `bend`         | 按角度或端点切线弯曲   | 常规曲线优先选用；自动模式在有限候选中避让，也可指定方向、角度或切线           |
| `curve`        | 一个控制点的二次贝塞尔 | 适合 bend 候选不足时的绕行；省略控制点自动生成，显式控制点通常不在曲线上       |
| `cubic`        | 两个控制点的三次贝塞尔 | 可分别控制两端切线，适合更复杂的弯曲；省略全部控制点自动生成，显式时须成对提供 |
| `smooth`       | 平滑经过有序中间点     | 已知必经位置时使用，通常设置 2～3 个点；只检查碰撞，不自动调整路线             |

在固定的 A、B 之间切换八种 `routing.kind`，比较直线、折线、bend、贝塞尔与过点曲线。`-|` 先水平再垂直，`|-` 先垂直再水平；它们不受主布局方向或箭头方向影响，也不会为其它节点自动绕行。预览的 React 与 Vanilla 源码使用相同的 `routing` 配置。

- **straight**：最简单的直接连接，不自动避让。
- **orthogonal**：适合横平竖直的流程图；默认比较三个折点位置避让，也可锁定比例。端点水平或垂直对齐时直连。
- **`-|` / `|-`**：明确需要先横后竖或先竖后横时使用；单折角，可设圆角，不自动避让。
- **bend**：常规曲线首选；按方向、角度或切线调整形状，默认用有限候选避让。
- **curve / cubic**：bend 不够灵活时使用；分别支持一个、两个控制点，省略控制点时自动生成避让候选。
- **smooth**：路线必须经过指定位置时使用；通常设置 2～3 个中间点，只检查碰撞，不自动调整路线。

自动避让不保证完全无碰撞；候选均有冲突时保留最佳路线并发出警告，也不会自动切换路由类型。

参数配置见[扩展用法](/schematic/diagram/flow/extended)，候选生成与碰撞检测见[实现原理](/schematic/diagram/flow/mechanism)。
