Flow 用实体表示步骤，用关系表示步骤间的连接，运行时自动计算位置。先看最小结果，再决定是否需要分组、路由或共享样式。

## 接入方式

React 可用 `FlowDiagram` 及其子元素声明 Flow；Vanilla 可用 `flowDiagram()` 构造 Source。已有 JSON IR 时，需为宿主装配 Flow provider。宿主的基本接入见 [Diagram 快速开始](/schematic/diagram/get-start)。

## 基础排布

Flow Source 由下列成员组成。React 组件负责声明这些成员，运行时根据实体、容器与关系计算位置和连线路径。

| 元素     | React 成员                      | Source 成员      | 职能                                                           |
| -------- | ------------------------------- | ---------------- | -------------------------------------------------------------- |
| Flow 图  | `FlowDiagram`                   | 整个 Flow Source | 汇总图内元素，并触发自动排布与连接                             |
| 实体     | `FlowEntity`、`FlowEntities`    | `entities`       | 表示步骤或节点；可设置文字、角色与状态                         |
| 关系     | `FlowRelation`、`FlowRelations` | `relations`      | 在 Flow 根声明，按 `source` 和 `target` 的 id 连接实体或语义组 |
| 语义组   | `FlowGroup`                     | `groups`         | 为一组元素建立可见边界，并设置局部排布与路由                   |
| 排布容器 | `FlowLayout`                    | `layouts`        | 将成员按线性或网格方式固定排列，不绘制外框                     |

表单填写流程从用户输入开始，经过前端表单和后端服务，最终写入数据库。前端表单的 `text` 是 Core `TextBlock`：主文本支持换行，副标题是一条带独立颜色和字号的文本行。面板还可调整整个文本块的对齐、行距与最大宽度；这些是 Entity 级 `layout`，不会分别作用于某一行，也不会改变 Flow 的节点排布。实体和关系可选的 `status` 直接投影给 Graph；Graph Theme 负责状态外观，状态本身不改变排布或 routing。

## 连线与路由

关系的 routing 配置改变路径形状，不需要定义新布局。

| `routing.kind` | 行为                               | 圆角                  |
| -------------- | ---------------------------------- | --------------------- |
| `bend`         | 常规曲线；省略方向和角度时自动选择 | 不接受 `cornerRadius` |
| `straight`     | 直线；内置默认                     | 不接受 `cornerRadius` |
| `orthogonal`   | 按布局方向生成正交折线             | 可选 `cornerRadius`   |
| `-\|`          | 从 source 先水平后垂直             | 可选 `cornerRadius`   |
| `\|-`          | 从 source 先垂直后水平             | 可选 `cornerRadius`   |

在固定的 A、B 之间切换五种 `routing.kind`，比较直线、正交折线与两种单折角路径。`-|` 先水平再垂直，`|-` 先垂直再水平；它们不受主布局方向或箭头方向影响，也不会为其它节点自动绕行。预览的 React 与 Vanilla 源码使用相同的 `routing` 配置。

单折角路由两端对齐时退化为直线；中心完全重合时会报路由错误。`cornerRadius: 0` 保留直角，正数使用圆角。平行边可能重叠；需要避开节点时应调整布局，而不是把单折角路由当作避障算法。

仅写 `routing: { kind: 'bend' }` 即可得到曲线。未指定且未继承角度时，布局比较左右各 `30° / 45° / 60°`，最多六条候选；也可以用 `bendDirection: 'left' | 'right'` 限定搜索方向，用 `bendAngle` 锁定角度。侧向始终相对 authored source → target，反向箭头不改变它。负角度翻侧，`0` 画成直线但仍是 bend；角度范围为开区间 `(-180, 180)`。

任一 `outAngle` 或 `inAngle` 出现即进入切线模式，优先于对称角度和方向；另一角度先继承有效的切线祖先，否则分别补 `0` 或 `180`，`looseness` 默认 `1` 且只在切线模式生效。角度是屏幕绝对角度，`0` 向右、`90` 向下。面板的自动方向和自动角度分别代表省略对应字段，不是 Source 中的新枚举值。

bend 与直线、折线并列，用于常规连接。自动选择优先减少节点穿越，标签只在节点评分相同时决胜，不比较路径重叠或交叉；同分优先小角度，再选左侧。显式或继承的角度与方向保持不变，也不移动节点。所有候选都穿越节点时仍绘图，并在对应关系上报告 `FlowBendObstacleConflict`。显式方向和切线也会检测冲突；平行边可能重叠，内置布局仍不支持自环。

根和 Group 用独立 `routing` 设置路由意图，Relation 的 `routing` 优先。未指定时取两个 endpoint 最近公共 Group 的有效路由，再取根和布局 Definition 的默认路由；中间的 FlowLayout 不建立路由层。例如根为 straight、Group 为 orthogonal 时，嵌套 Layout 内的关系仍使用 orthogonal。

三种轴对齐模式共享圆角继承：实例 `cornerRadius` 优先，其次祖先有效 routing 的半径，再取 Definition 的 `orthogonalCornerRadius`，内置值为 `8`。切换 `kind` 不丢失继承半径，显式 `0` 禁用圆角。

bend 只继承同种路由的有效参数族。局部提供方向或角度而不提供切线角时，会退出祖先切线模式；祖先未生效的对称字段不会回流。
