## 用法

```tsx
import { FlowDiagram, FlowEntities, FlowRelations } from '@retikz/diagram-react/flow';
```

```tsx
<FlowDiagram>
  <FlowEntities items={['Source', 'Validate']} />
  <FlowEntities items={['Store']} />
  <FlowRelations
    items={[
      ['Source', 'Validate'],
      ['Validate', 'Store'],
    ]}
  />
</FlowDiagram>
```

`FlowEntities` 的字符串条目同时作为 `id` 和 `text`；`FlowRelations` 的 tuple 只写 `source` 与 `target`。需要稳定 id、国际化文本或其它字段时改用对象条目。两种批量 marker 默认都是追加收集器，可以写多个，也能和单项 `FlowEntity` / `FlowRelation` 混用；重复 Entity id 仍由 Flow Source 报错。

需要明确一个批量 marker 已列出当前 owner 的全部同类声明时，设置 `complete`。`complete` 默认为 `false`；设为 `true` 后，该 marker 不能和当前 owner 的其它同类单项或批量 marker 共存。`FlowEntities` 的 owner 可以是 Flow 根、Group 或 Layout，不同 owner 互不冲突；`FlowRelations` 只能位于 Flow 根。

`FlowDiagram` 既可直接复用 `Layout` 作为 standalone 宿主，也可作为外层 `Layout` 的 embed。Source 中不写 `position` 或 route；省略运行时配置时使用内置 `layered`，relation 默认采用直线 routing。需要折线时可显式选择 `orthogonal`。

## 例子

### 基础排布

表单填写流程从用户输入开始，经过前端表单和后端服务，最终写入数据库。前端表单的 `text` 是 Core `TextBlock`：主文本支持换行，副标题是一条带独立颜色和字号的文本行。面板还可调整整个文本块的对齐、行距与最大宽度；这些是 Entity 级 `layout`，不会分别作用于某一行，也不会改变 Flow 的节点排布。实体和关系可选的 `status` 直接投影给 Graph；Graph Theme 负责状态外观，状态本身不改变排布或 routing。

### 分组排布

Flow 有两种分组形式：`FlowGroup` 表达有业务含义的可见边界，`FlowLayout` 只把若干元素组织成一个布局单元。两者都通过 `children` 建立包含关系，也可以相互嵌套。

| 差别           | `FlowGroup`                                      | `FlowLayout`                                      |
| -------------- | ------------------------------------------------ | ------------------------------------------------- |
| 主要职责       | 表达一个可命名、可设置样式的语义分组             | 固定排列 direct children                          |
| 可见结果       | 物化为带边框、背景和可选标题的 Graph Group       | 不生成边框、背景或标题                            |
| 内部排布       | `layout` 提供自动布局方向、同层间距与层级间距    | `kind="linear"` 一维排列或 `kind="grid"` 行列对齐 |
| Relation 端点  | 可以作为端点                                     | 不能作为端点，只能连接其中的 Entity/Group         |
| Source catalog | 存入 `groups`，`children` 保留直接成员与同级顺序 | 存入 `layouts`，`children` 保留固定顺序           |

React 中的嵌套只是编写便利；adapter 会将 Group、Layout 和 Entity 归一到平级 catalog，并以各 owner 的 `children` 作为唯一包含事实。示例上半部分是可见 Group，下半部分是无外壳 Layout；从 Group 外壳到队列的关系同时展示了 Group endpoint。

### 行列对齐

不同排的节点需要两两对齐时，使用 `FlowLayout kind="grid"`。推荐将 `placements` 写成二维数组：外层下标为从 0 开始的行，内层下标为列，单元格填直接子元素 id，`null` 表示空单元格；也可使用以 child id 为键、值为 `{ row, column }` 的对象映射。两种结构得到相同的行列位置；同列共享中心 x，同排共享中心 y，节点保持真实尺寸。Group 仍自动布局；需要时可在 Group 内嵌套 Grid。

```tsx
import { FlowDiagram, FlowEntities, FlowLayout } from '@retikz/diagram-react/flow';

<FlowDiagram>
  <FlowLayout
    kind="grid"
    id="stages"
    placements={[
      ['request', 'cache'],
      ['parse', 'result'],
    ]}
  >
    <FlowEntities items={['request', 'cache', 'parse', 'result']} />
  </FlowLayout>
</FlowDiagram>;
```

Vanilla 用同样的 `placements`，显式 `children` 只负责包含与绘制顺序，得到同一 Flow Source：

```ts
import { normalizeFlowDiagram } from '@retikz/diagram-vanilla/flow';

const source = normalizeFlowDiagram({
  entities: ['request', 'cache', 'parse', 'result'].map(id => ({ id, text: id })),
  groups: [],
  layouts: [
    {
      kind: 'grid',
      id: 'stages',
      children: ['request', 'cache', 'parse', 'result'],
      placements: [
        ['request', 'cache'],
        ['parse', 'result'],
      ],
    },
  ],
  children: ['stages'],
});
```

每个直接子项都必须指定单元格，不能重叠、跨格或引用其它容器的后代。空行列保留，但不生成占位元素。`rowGap`、`columnGap` 分别默认继承 `nodeGap`，接受显式 `0`；非对称 margin 会对称预留足够空间，不推偏节点中心。Grid 不随流程方向旋转。

`reserveLabelSpace` 默认开启。带标签的横向 Relation 会把其测量宽度加到 `columnGap`，纵向 Relation 会把测量高度加到 `rowGap`；同轴多个标签取最大尺寸，因此其它行列也会使用同一扩张后的间距。例如 `columnGap={32}` 且标签宽度为 `12` 时，实际列间距为 `44`。设为 `false` 后，Grid 严格使用 `rowGap` / `columnGap` 配置值，不为标签预留空间。此行为不保证斜线、折线或跨越中间节点的全局避碰。[TeX 缓存图](/kernel/packages/tex/principles#缓存失败与重试) 展示了实际用法。

### 全局配置

`flowDefaults` 让 Flow 根为全部同类对象提供统一默认样式。`entity.style` 会作用于每个 Entity，`relation.style` 会作用于每条 Relation；这里的设置不改变 Source 的 id、包含关系、节点布局或连线路径。局部 `style` 仍可在需要时覆盖全局值，但本例只展示全局配置。

## 技术原理

<ComponentAlert
  type="tip"
  title="上手阶段可跳过本节"

/>

| 阶段 | 输入                               | 用户可见结果                                                              |
| ---- | ---------------------------------- | ------------------------------------------------------------------------- |
| 测量 | 最终 Graph Definition 与 Theme     | 固定 leaf 尺寸、Group shell、Layout children 与 relation label 尺寸       |
| 布局 | `FlowLayoutInput` + Layout context | Flex/Grid 固定 placement、自动 element bounds、route 与 label reservation |
| 物化 | 同一份已验证几何                   | Graph Scene、`FlowDiagramArtifact` 与 world-space handles                 |

Layout callback 必须同步返回 JSON-safe plain data，并为每个 authored Layout 恰好调用一次 `placeLayout`。Flow 以 `@retikz/layout` 的 Flex/Grid compiler 产生固定 placement，再校验 provider 没有改写 Layout 的相对 bounds；其余 id、尺寸、containment、碰撞、route 与 label coverage 也会在 Graph/Core 渲染前验证。Definition 的 `placementKinds` 必须声明支持的种类；不支持的请求在 callback 前报错。

## 默认值与路由

`theme: { style, mode }` 选择主题环境；`flowThemeStyles` / `diagramThemeStyles` 注入对应 Definition。`graphRules` 是 Flow 根级的 Graph 条件外观规则，只投影到 Flow 下沉的 Entity 与 Relation，不改变布局、routing 或包含关系。`flowDefaults` 与 `diagramDefaults` 是显式默认值，使用正式 Source 的相同路径。Entity 与 Relation 的 `group` 直接复用 Graph：同一 Flow 根中相同 group 共享从分类色板正序自动取得的颜色，未分组元素保持原有外观。Entity / Relation 外观的覆盖顺序为 Graph Theme、根 `graphRules`、`flowDefaults`、实例字段。

Flow defaults 只包含 `layout.nodeGap/rankGap`、`entity.style/layout`、Group 的 Surface 外观与 `caption.title` 格式，以及 Relation 的路径、marker 和标签格式。它不包含内容、identity、children、direction、routing 或 overflow，也不会创建标题、Group 或 marker。空对象与 undefined 不覆盖已有值，0 和 false 保留；Node 字体整体替换，Relation 的 `labelFont` 按字段合并。

根和 Group 用独立 `routing` 设置路由意图，Relation 的 `routing` 优先。未指定时取两个 endpoint 最近公共 Group 的有效路由，再取根和布局 Definition 的默认路由；中间的 FlowLayout 不建立路由层。例如根为 straight、Group 为 orthogonal 时，嵌套 Layout 内的关系仍使用 orthogonal。
