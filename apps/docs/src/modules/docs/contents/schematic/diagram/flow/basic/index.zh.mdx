## 用法

```tsx
import { FlowDiagram, FlowEntities, FlowRelations } from '@retikz/diagram-react/flow';
```

```tsx
<FlowDiagram width={640} height="auto">
  <FlowEntities items={['Source', 'Validate']} />
  <FlowEntities items={['Store']} />
  <FlowRelations
    items={[
      ['Source', 'Validate'],
      ['Validate', 'Store'],
    ]}
  />
</FlowDiagram>
```

`FlowEntities` 的字符串条目同时作为 `id` 和 `text`；`FlowRelations` 的 tuple 只写 `source` 与 `target`。需要稳定 id、国际化文本或其它字段时改用对象条目。两种批量 marker 默认都是追加收集器，可以写多个，也能和单项 `FlowEntity` / `FlowRelation` 混用；重复 Entity id 仍由 Flow Source 报错。

需要明确一个批量 marker 已列出当前 owner 的全部同类声明时，设置 `complete`。`complete` 默认为 `false`；设为 `true` 后，该 marker 不能和当前 owner 的其它同类单项或批量 marker 共存。`FlowEntities` 的 owner 可以是 Flow 根、Group 或 Layout，不同 owner 互不冲突；`FlowRelations` 只能位于 Flow 根。

`FlowDiagram` 既可直接复用 `Layout` 作为 standalone 宿主，也可作为外层 `Layout` 的 embed。Source 中不写 `position` 或 route；省略运行时配置时使用内置 `layered`，relation 默认采用直线 routing。需要折线时可显式选择 `orthogonal`。

## 例子

### 基础排布

表单填写流程从用户输入开始，经过前端表单和后端服务，最终写入数据库。前端表单的 `text` 是 Core `TextBlock`：主文本支持换行，副标题是一条带独立颜色和字号的文本行。面板还可调整整个文本块的对齐、行距与最大宽度；这些是 Entity 级 `style`，不会分别作用于某一行，也不会改变 Flow 的节点排布。实体和关系可选的 `status` 直接投影给 Graph；Graph Theme 负责状态外观，状态本身不改变排布或 routing。

### 分组排布

Flow 有两种分组形式：`FlowGroup` 表达有业务含义的可见边界，`FlowLayout` 只把若干元素组织成一个布局单元。两者都通过 `children` 建立包含关系，也可以相互嵌套。

| 差别           | `FlowGroup`                                      | `FlowLayout`                              |
| -------------- | ------------------------------------------------ | ----------------------------------------- |
| 主要职责       | 表达一个可命名、可设置样式的语义分组             | 固定排列 direct children                  |
| 可见结果       | 物化为带边框、背景和可选标题的 Graph Group       | 不生成边框、背景或标题                    |
| 内部排布       | `layout` 提供自动布局方向、同层间距与层级间距    | `direction`、`gap`、`align` 直接控制排列  |
| Relation 端点  | 可以作为端点                                     | 不能作为端点，只能连接其中的 Entity/Group |
| Source catalog | 存入 `groups`，`children` 保留直接成员与同级顺序 | 存入 `layouts`，`children` 保留固定顺序   |

React 中的嵌套只是编写便利；adapter 会将 Group、Layout 和 Entity 归一到平级 catalog，并以各 owner 的 `children` 作为唯一包含事实。示例上半部分是可见 Group，下半部分是无外壳 Layout；从 Group 外壳到队列的关系同时展示了 Group endpoint。

### 全局配置

`flowTheme` 让 Flow 根为全部同类对象提供统一默认样式。`entity.style` 会作用于每个 Entity，`relation.style` 会作用于每条 Relation；这里的设置不改变 Source 的 id、包含关系、节点布局或连线路径。局部 `style` 仍可在需要时覆盖全局值，但本例只展示全局配置。

## 技术原理

<ComponentAlert
  type="tip"
  title="上手阶段可跳过本节"
  description="需要读取布局结果、排查 Definition 或生成 LLM 工具契约时再回来读。"
/>

| 阶段 | 输入                               | 用户可见结果                                                         |
| ---- | ---------------------------------- | -------------------------------------------------------------------- |
| 测量 | 最终 Graph Definition 与 Theme     | 固定 leaf 尺寸、Group shell、Layout children 与 relation label 尺寸  |
| 布局 | `FlowLayoutInput` + Layout context | Flex 固定 placement、自动 element bounds、route 与 label reservation |
| 物化 | 同一份已验证几何                   | Graph Scene、`FlowDiagramArtifact` 与 world-space handles            |

Layout callback 必须同步返回 JSON-safe plain data，并为每个 authored Layout 恰好调用一次 `placeLayout`。Flow 以 `@retikz/layout` 的 Flex compiler 产生固定 placement，再校验 provider 没有改写 Layout 的相对 bounds；其余 id、尺寸、containment、碰撞、route 与 label coverage 也会在 Graph/Core 渲染前验证。

## API 参考

### React authoring

| 组件            | 核心属性                                                                                                                                          | 默认值                   | 描述                                                                                                                                                                                                                                                                                                     |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `FlowDiagram`   | `entities` / `groups` / `layouts` / 根 `children` / `relations` 由 JSX children 收集；`presentation?`、`frame?`、`flowThemeTokens?`、`flowTheme?` | `layered` + 直线 routing | Source 根、Definition 注入和 standalone `Layout` 宿主                                                                                                                                                                                                                                                    |
| `FlowEntity`    | `id`、`text`、`role?`、`kind?`、`status?`、`rank?`、`style?`、`layout?`                                                                           | role=`concept`           | 单一 Graph Entity。`text` 可为字符串或 TextBlock 行数组；每行可覆盖 `fill` 与 `font`，但 Flow 中至少须有一条非空文本或 TeX run。`status` 复用 Graph 的 `error`、`success`、`warning`、`disabled`，省略时不标记状态。`style.align`、`lineHeight`、`maxTextWidth` 分别控制整个文本块的对齐、行距与换行宽度 |
| `FlowEntities`  | `items: ReadonlyArray<string \| InputFlowEntity>`<br />`complete?: boolean`                                                                       | complete=`false`         | 在当前位置按数组顺序声明 Entity。默认可与同 owner 的其它 Entity marker 追加混用；`complete` 表示当前 owner 的唯一完整 Entity 清单                                                                                                                                                                        |
| `FlowGroup`     | `id`、`label?`、`rank?`、`layout?`、`style?`、`children`                                                                                          | Graph Group              | 可见语义边界；`layout` 自动排列自身 children，Relation 不放在 Group children 中                                                                                                                                                                                                                          |
| `FlowLayout`    | `id`、`direction`、`gap?`、`align?`、`rank?`、`children`                                                                                          | align=`center`           | 无外壳固定排列；`gap` 省略时继承有效 `nodeGap`，不能作为 Relation endpoint                                                                                                                                                                                                                               |
| `FlowRelation`  | `source`、`target`、`label?`、`role?`、`kind?`、`status?`、`direction?`、`style?`、`layout?`                                                      | role=`flow`              | 无独立 id 的根级有序关系与可选局部 routing。endpoint 可为 Entity 或 Group，不能为 Layout；Graph Theme 提供默认外观，显式 `style` 仍可覆盖外观                                                                                                                                                            |
| `FlowRelations` | `items: ReadonlyArray<readonly [string, string] \| InputFlowRelation>`<br />`complete?: boolean`                                                  | complete=`false`         | 在 Flow 根按数组顺序声明 Relation。默认可与其它 Relation marker 追加混用；`complete` 表示根级唯一完整 Relation 清单                                                                                                                                                                                      |
