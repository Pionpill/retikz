Plot 从当前位置的 Core effective Theme 读取 `style` 与 `mode`。Plot 始终先建立随 `mode` 与 Core shared categorical 变化的默认 baseline；显式 `style` 再选择同名领域 definition，并只覆盖它明确返回的 token 与 Axis rules。发布包不内置命名 style；本站通过公开 Core / Plot definitions 注入 Academic、Vibrant、Clean 三个参考 preset。`IRPlot` 不重复声明 Core 的 `style` / `mode`；主题只控制视觉默认，不改变数据、坐标、Axis 是否存在、minor tick source 或 mark 结构。

<ComponentPreview files="theme-tokens" size="lg" />

示例把 `plot.typography.foreground` 设为字符串主色 `#2563EB`，再用 `0.08` 派生绘图区背景、用 `0.25` 派生 grid 描边；categorical palette 仍由字符串颜色组成。数值是主色权重，不是不透明度：Core 会按 Light 白底或 Dark 黑底预合成为不透明颜色，`axis.grid.drawOpacity` 等 opacity token 继续独立生效。

结构化 theme 中对应的绘图区字段是 `plotArea.fill`；它只填充二维坐标中扣除 axis、legend 与布局预留后的 Plot area，坐标轴标签区、facet 间隙和外围 Chart canvas 保持透明。一维直线与一维圆周只有投影路径，不生成可填充的 Plot area，也不输出跨绘图区的 grid layer。React、Vanilla 和 plain JSON 都把同一 token 与 rule 原样交给 Plot resolver，adapter 不补自己的 preset；Core Theme 提供 effective `style` / `mode` 与 shared colors。

本站参考 Vibrant preset 在 Light 下使用浅蓝灰绘图区，在 Dark 下使用深色绘图区；默认 baseline、Academic 与 Clean 保持透明。显式 `plot.area.fill` 或 `plotTheme.plotArea.fill` 仍按正常级联覆盖 preset。

## 可扩展 style

用 `definePlotThemeStyle({ name: 'brand', resolve: theme => ({ tokens, tokenRules }) })` 定义 Plot 的运行时 preset，并通过 `plotThemeStyles` 注入 `lowerPlots`、`<Plot>` 或 `renderPlot()`；React 子树也可通过 `PlotThemeProvider` ambient 注入。`tokens` 可省略，并与 `plotThemeTokens` 复用同一严格稀疏 schema；`tokenRules` 也可省略，提供时追加在默认 Axis rules 后。未返回或在 runtime definition 中显式返回 `undefined` 的 token 继续使用当前 mode 的默认值；持久化 `plotThemeTokens` / `plotThemeTokenRules` 仍拒绝显式 `undefined`。resolver 函数与解析结果不进入 `IRPlot`。在同一图中还要把同名 Core definition 传给 `themeStyles` 或 Core `ThemeProvider`，否则 Core 或 Plot 任一层都会 fail-loud。Chart typed authoring 还要通过 `<ChartThemeProvider themeDefinitions={...}>` 或 Vanilla factory 的 `themeDefinitions` 注入 Chart definitions；`lowerOptions.plotThemeStyles` 仍只负责 Plot definitions。

## 级联与原子替换

```text
Core effective Theme
  → mode / shared categorical 建立默认 Plot tokens 与 Axis rules
  → Plot style 稀疏 tokens
  → 追加 Plot style 中匹配 Axis dimension 的 tokenRules
  → local IRPlot.plotThemeTokens
  → local IRPlot.plotThemeTokenRules
  → local IRPlot.plotTheme
  → explicit guide / mark / scale config
```

- `plotThemeTokens` 是严格、稀疏的 canonical token map；未知 key、显式 `undefined` 和非法值会失败
- 原生 `plotTheme` 更接近 Plot 正式结构，可以设置 token 没有表达的合法字段
- `plotThemeTokenRules` 只接受 Axis token，并按 `select.dimension` 匹配已有 Axis；同层后声明 rule 覆盖先声明 rule
- 数组、scalar、`false` 与 discriminator 改变的对象整体替换；同一结构的闭合对象才按合法字段合并
- 显式 scale `range` / `scheme` 与局部 axis、legend、mark 配置始终优先

## Canonical token

`PlotThemeToken` 公开 42 个稳定 key。key 的 owner 是 Plot；值约束复用 Core paint / font / opacity 原子、Plot guide / scale schema 与 Standard Legend gap 原子。

`plot.typography.foreground` 是所有 Plot-owned guide 的字符串主色。Plot area fill、Axis line/grid stroke、tick label、Axis title、Legend title/label 等派生颜色槽接受精确 CSS 字符串，也接受 `[0, 1]` 数值权重；数值直到 lowering 到 Core 后才按最终主色与 Theme mode 确定化。数据 mark 不继承 typography 主色，palette、scheme、scale range、gradient、pattern 与 shadow 内部颜色也保持 string-only。

| 分组            | Canonical keys                                                                                                                                                                                                                                                                                                                           |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Plot area       | `plot.area.fill`                                                                                                                                                                                                                                                                                                                         |
| Typography      | `plot.typography.foreground`、`plot.typography.font.family`、`plot.typography.font.size`                                                                                                                                                                                                                                                 |
| Axis line       | `axis.line.enabled`、`axis.line.stroke`、`axis.line.strokeWidth`、`axis.line.drawOpacity`                                                                                                                                                                                                                                                |
| Axis tick       | `axis.tick.mark`                                                                                                                                                                                                                                                                                                                         |
| Axis tick label | `axis.tickLabel.enabled`、`axis.tickLabel.foreground`、`axis.tickLabel.font.size`、`axis.tickLabel.gap`                                                                                                                                                                                                                                  |
| Axis title      | `axis.title.enabled`、`axis.title.foreground`、`axis.title.font.size`、`axis.title.font.weight`、`axis.title.padding`                                                                                                                                                                                                                    |
| Axis grid       | `axis.grid.enabled`、`axis.grid.stroke`、`axis.grid.strokeWidth`、`axis.grid.drawOpacity`、`axis.grid.includeDomain`                                                                                                                                                                                                                     |
| Legend          | `legend.title.foreground`、`legend.title.font.size`、`legend.title.font.weight`、`legend.label.foreground`、`legend.label.font.size`、`legend.swatch.size`、`legend.swatch.gap`、`legend.entry.gap`、`legend.title.gap`、`legend.ramp.length`、`legend.ramp.thickness`、`legend.symbol.size`、`legend.symbol.scale`、`legend.symbol.fit` |
| Palette         | `plot.palette.categorical`、`plot.palette.series`、`plot.palette.sector`、`plot.palette.sequential`、`plot.palette.diverging`、`plot.palette.shape`                                                                                                                                                                                      |

`axis.line.enabled` 与 `axis.grid.enabled` 只决定已有 Axis 的视觉默认；三个 grid paint token 设置启用后的 major grid 线条，`axis.grid.includeDomain` 决定它是否补齐 effective domain 首尾位置。端点 token 不会单独创建或启用 grid。默认 baseline 让已有 x / y major grid 包含端点，本站三个参考风格保持关闭；Axis guide 的显式 boolean 最终优先。Theme 不创建 Axis、tick 或 minor grid，major/minor tick source 与独立样式仍由 Axis guide 局部配置负责。

`axis.title.enabled` 控制已有 Axis guide 提供的 title 是否渲染。默认 baseline、Academic 与 Vibrant 默认开启，Clean 默认关闭；全局 token、dimension rule 或结构化 `plotTheme.axis.title` 样式对象可以重新开启。Axis guide 的 `title` 仍提供内容和局部样式，但不会自动越过关闭状态。

`axis.title.padding` 控制 tick label 带到轴标题中心的默认距离，默认 baseline 与本站三个参考风格均为 `12`。它可以通过 dimension rule 精确覆盖；结构化 `plotTheme.axis.title.padding` 和单个 Axis 的 `title.padding` 依次拥有更高优先级。

`plotThemeTokenRules` 使用 `{ select: { dimension }, tokens }`。`dimension` 接受一个非空开放字符串，或一个非空、无重复项的数组，因此同一契约可匹配 `x`、`y`、`radius`、`angle` 与自定义 Coordinate role。rule 只允许 `axis.line.*`、`axis.tick.*`、`axis.tickLabel.*`、`axis.title.*` 和 `axis.grid.*`；Axis guide 自身的显式视觉配置最终优先，但 title 内容不会自动覆盖 `axis.title.enabled: false`。

## PlotThemeTokenResolutionSchema

`PlotThemeTokenResolutionSchema` 使用完全相同的 42 个字段契约，但每个字段都必需。默认 Light / Dark preset 与最终级联结果通过它；注入 definition 的 `tokens` 则通过上面的 sparse overrides schema，因此自定义 style 不需要复制默认 token。

## Inspection

`resolvePlotTheme(effectiveTheme, input)` 是公开纯 resolver，返回 `IRPlotThemeResolution`，其 schema 是 `PlotThemeResolutionSchema`：

| 字段                | 含义                                                     |
| ------------------- | -------------------------------------------------------- |
| `style` / `mode`    | 选择 preset 的 effective Core Theme 环境                 |
| `tokens`            | 级联后的完整 token map                                   |
| `tokenSources`      | 每个 canonical token 的唯一胜出来源与稳定 path           |
| `tokenRules`        | 按实际级联顺序保留的 default、style 与 IRPlot Axis rules |
| `authoredOverrides` | 记录原生 `plotTheme` 入口                                |
| `plotTheme`         | 已映射并校验的完整原生 Plot theme                        |
| `palette`           | scale、mark 与 legend 共享的最终 palette / scheme        |

`tokenSources[].kind` 只回答 token 是从上层 effective Theme 直接投影（`inherit`），还是由 Plot 默认值、style definition 或当前 Plot 输入构建（`local`），不表示级联优先级。具体胜出入口由 `path` 区分：未被 style 覆盖的 token 保留 `$default/...`，显式 style token 使用 `$style/...`，Plot-local 输入使用 `$spec/plotThemeTokens/...` 或 `$spec/plotTheme/...`。`tokenRules[].path` 按实际顺序使用 `$default/.../tokenRules/<index>`、`$style/.../tokenRules/<index>` 或 `$spec/plotThemeTokenRules/<index>`；`authoredOverrides` 中的 `plotTheme` 也记录为 `local`。

Chart 可以调用这个 resolver 读取 recipe 需要的瞬时 series palette，但不会把完整 resolved theme 写回 `IRPlot`，也不会把 Plot token 标记为 Chart-owned。

`PlotThemeSchema` 是级联后进入 guide、scale 与 lowering 的正式原生结构。它可以表达 tick label rotate / layout、axis title rotate 等 canonical token 之外的合法字段；这些字段保留在最终 `plotTheme` 中，不会伪造不存在的 token source。`axis.title.enabled` / `axis.title.padding` 分别与结构化 `axis.title` 的 `false | style` 和 `axis.title.padding` 双向映射；`axis.grid.includeDomain` 也与同名 canonical token 双向映射，三者都保留正式 token source。
