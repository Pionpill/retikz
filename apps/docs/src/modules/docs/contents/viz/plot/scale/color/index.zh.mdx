---
title: 颜色比例尺
description: 颜色比例尺把分类、连续和带中点的数据映射成离散颜色、连续色带或分档颜色。
---

颜色比例尺回答「这个数据值应该用什么颜色」。scale 负责建立数据到颜色的映射，`Legend` 再把这套映射解释给读者；添加图例不会改变 scale 类型或配色。

| 数据与任务           | 推荐 scale                            | 图例形态 |
| -------------------- | ------------------------------------- | -------- |
| 分类字段             | `ordinal`                             | 色块     |
| 连续 / 时间字段      | `sequential`                          | 渐变色带 |
| 有意义中点的连续数值 | `diverging`                           | 渐变色带 |
| 连续量需要切档       | `quantize` / `threshold` / `quantile` | 分档色块 |

## 分类颜色：ordinal

把 `color` 绑定到分类字段，`<Plot>` 会自动派生 `ordinal`，每个类别取一个离散颜色。分类 color 也会在没有显式 series 时把 path 数据拆成多个系列。

  files={['scale-ordinal', 'scale-ordinal.data.ts']}

`ordinal` 不在类别之间插值。需要稳定的业务颜色时，可在 full spec 中提供显式 `domain` 与同顺序的 `range`；只依赖自动 domain 时，类别顺序来自数据。

## 连续颜色：sequential 与 diverging

`sequential` 用一条由低到高的色带表达连续量；`diverging` 用三段 domain 表达低端、中点和高端，适合盈亏、偏差、温差等围绕基准值展开的数据。

<ComponentPreview
  size="lg"
  files={['scale-continuous', 'scale-continuous.data.ts']}
  caption="切换 sequential 与 diverging、选择配色并移动中点；同一份 -50 到 50 数据会立即显示映射差异。"
/>

两类 scale 都可以使用可序列化的命名 `scheme`。常用 sequential scheme 有 `viridis`、`blues`、`greens`、`magma`；常用 diverging scheme 有 `rdbu`、`brbg`、`spectral`。需要自定义颜色时可用 `range` 覆盖 scheme。

连续颜色只适用于按 datum 独立着色的 point、interval、rect、sector 等图元。path 与 area 是整条图元统一着色，不能沿路径绑定变化的连续 color 字段。

## 离散化：quantize / threshold / quantile

离散化 scale 仍接收连续数据，但只输出有限档颜色。三者的差别在于如何确定分界：

| 类型        | 分界依据                             | 适合任务                 |
| ----------- | ------------------------------------ | ------------------------ |
| `quantize`  | 把显式 domain 等宽切成 `count` 档    | 等距数值区间、分级统计图 |
| `threshold` | 使用业务给定的 `breakpoints`         | 告警线、政策线、等级标准 |
| `quantile`  | 根据数据分位切档，每档样本数近似相等 | 偏斜分布、减弱离群值影响 |

<ComponentPreview
  size="lg"
  files={['scale-discretization', 'scale-discretization.data.ts']}
  caption="切换 quantize、threshold 与 quantile；调整档数、业务阈值和配色，比较同一份偏斜数据如何落入不同色档。"
/>

配置时注意：

- `threshold.breakpoints` 必须严格升序，档数等于断点数加一；显式 `range` 的长度也必须匹配
- `quantize` / `quantile` 的 `count` 默认是 `5`；只给 `range` 时，以 `range` 长度作为档数
- 同时提供 `count` 与 `range` 时，两者必须一致
- `quantile` 的边界由实际数据计算，不使用显式数值 domain

## 技术原理

React 的自动入口覆盖两条常用路径：

- 分类 color 字段自动派生 `ordinal`
- 声明为 `continuous` 或 `temporal` 的 color 字段自动派生 `sequential`

`diverging`、三种离散化 scale、显式 scheme / range / domain 等高级配置写入 `IRPlotSpec.scales`，再让 mark 的 color field binding 通过 `scale` 名称引用。`<Legend channel="color" />` 或 full spec 中的 legend guide 只负责展示已解析的映射。

自动派生和显式配置只是两个入口：它们最终都由同一套 scale definition 与 resolver 解析，不会形成两套颜色语义。

<ComponentPreview files="scale-color-flow" size="xs" hideCode />

resolver 按 scale 类型解析 domain、分档边界与 scheme / range，得到包含颜色映射和必要边界信息的 resolved scale。mark 用它给 datum 着色，Legend 读取同一个结果生成色带或分档色块，因此添加图例不会改变映射本身。

## API 参考

颜色 scale 在 full spec 中都需要 `name`，mark 的 color field binding 再通过 `scale` 引用它。自动派生只覆盖 `ordinal` 与 `sequential`；其余类型和显式 domain / scheme / range 写入 `IRPlotSpec.scales`。

| `type`       | 输入与分界                       | 配色与默认值                                 |
| ------------ | -------------------------------- | -------------------------------------------- |
| `ordinal`    | 分类 `domain`，省略时按数据顺序  | 离散 `range`；省略时使用 Plot 分类色         |
| `sequential` | 两段 `domain`，省略时取数据范围  | `scheme` 默认 `viridis`；两色 `range` 可覆盖 |
| `diverging`  | 三段 `domain`：低 / 中 / 高      | `scheme` 默认 `rdbu`；三色 `range` 可覆盖    |
| `quantize`   | 两段 `domain`；`count` 默认 `5`  | scheme 采样或显式离散 `range`                |
| `threshold`  | 必填升序 `breakpoints`           | 色档数为断点数加一，`range` 长度必须匹配     |
| `quantile`   | 按数据分位切分；`count` 默认 `5` | scheme 采样或显式离散 `range`                |

`range` 同时出现时会覆盖 `scheme`；`quantize` / `quantile` 同时提供 `count` 与 `range` 时长度必须一致。自定义 scale operation 也遵循同一套公开 IR 契约。
