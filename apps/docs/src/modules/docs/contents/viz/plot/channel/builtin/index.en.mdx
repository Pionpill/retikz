After learning [channel binding](/viz/plot/channel/binding), use this page to choose built-in channels: compare values by position, distinguish categories by color and shape, express quantities through size, and add text and path styling.

The property tables describe the example marks; they do not imply that every mark supports every property. Label layout, path ordering, and series grouping also affect the result and are explained separately from visual channels.

## Position

Position channels select fields for coordinate calculation. In this 2D Cartesian example, x sets horizontal position and y sets vertical position. Switch fields to compare a different pair of quantities.

| Property | Values     | Effect and constraints                                                                  |
| -------- | ---------- | --------------------------------------------------------------------------------------- |
| `x`      | Field name | First position role; horizontal in this example.                                        |
| `y`      | Field name | Second position role; vertical in this example.                                         |
| `z`      | Field name | Third position role for custom coordinates; unused by the built-in 2D coordinates here. |

## Visual encoding

Color distinguishes categories, size compares quantities, and shape provides another way to identify categories. Constants give marks a uniform appearance; field bindings let styles vary by record.

| Property         | Values                                       | Effect and constraints                                                                       |
| ---------------- | -------------------------------------------- | -------------------------------------------------------------------------------------------- |
| `color`          | Field or explicit color constant             | Main color; the mark determines which visual properties it affects.                          |
| `fill`           | Field, color, or paint object                | Controls the interior fill.                                                                  |
| `stroke`         | Field, color, or paint object                | Controls the outline paint.                                                                  |
| `opacity`        | Field, 0–1, or grouped object                | Shorthand sets overall opacity; an object adjusts individual factors.                        |
| `opacity.fill`   | Field or 0–1                                 | Changes fill opacity only.                                                                   |
| `opacity.stroke` | Field or 0–1                                 | Changes stroke opacity only.                                                                 |
| `size`           | Numeric field or nonnegative radius          | Fields use a square-root radius mapping by default; numeric constants are final point radii. |
| `shape`          | Categorical field or explicit shape constant | Fields assign shapes by category; example constants are circle, rectangle, and diamond.      |
| `strokeWidth`    | Numeric field or nonnegative number          | Controls stroke width independently of stroke color.                                         |

<ComponentAlert
  type="tip"
  title="Opacity values multiply"
  description="opacity.overall, opacity.fill, and opacity.stroke specify opacity: 0 is fully transparent and 1 is fully opaque. Overall opacity multiplies fill or stroke opacity. For example, opacity: { overall: 0.5, fill: 0.5 } produces an effective fill opacity of 0.5 × 0.5 = 0.25: 25% opaque and 75% transparent. Stroke opacity follows the same rule: overall × stroke. This assumes a fully opaque color and no additional ancestor opacity."
/>

Use `opacity: 0.5` for overall opacity. For separate control, use `opacity: { overall: 0.5, fill: 0.5, stroke: 1 }`. Each member supports a field binding or a constant. Omitted members inherit independently and otherwise resolve to 1; a numeric shorthand sets only overall.

Switch the paint channel, then adjust opacity, radius, and shape to compare the same points. This playground uses constants; compare field-driven color and size on the channel binding page.

### Nodes

Node styles control shape size, corner radius, rotation, scale, and shadow. This example omits text so you can focus on the node bodies.

| Property       | Values                                  | Effect and constraints                                                                      |
| -------------- | --------------------------------------- | ------------------------------------------------------------------------------------------- |
| `minimumSize`  | Nonnegative number or size object       | Minimum node size; a datum’s size binding takes precedence when present.                    |
| `padding`      | Number or spacing object                | Internal node spacing.                                                                      |
| `cornerRadius` | Nonnegative number                      | Rectangle corner radius.                                                                    |
| `rotate`       | Number                                  | Node rotation angle.                                                                        |
| `scale`        | Number or axis-scale object             | Scales node appearance without changing positional field bindings.                          |
| `shadow`       | Here: none, sm, md, lg, xl              | Shadow preset; none disables shadows, while the other presets change the shadow appearance. |
| `blendMode`    | Here: normal, multiply, screen, overlay | Color compositing in overlapping regions; the result depends on the background and overlap. |

Adjust minimum size and corner radius, then try rotation, scale, and shadow on the three rectangles.

### Text

With text set, PointMark displays each data point as field text. This example covers text color, font, alignment, and wrapping. These text marks are separate from external label annotations.

| Property       | Values                           | Effect and constraints                       |
| -------------- | -------------------------------- | -------------------------------------------- |
| `text`         | Field name                       | Uses field text as the point mark’s content. |
| `textColor`    | Field or explicit color constant | Color of text inside the node.               |
| `align`        | start, middle, end               | Horizontal alignment of node text.           |
| `font`         | Font object, e.g. `{ size: 14 }` | Font size, weight, and related settings.     |
| `lineHeight`   | Positive number                  | Text line height.                            |
| `maxTextWidth` | Positive number                  | Maximum text width, affecting wrapping.      |

Reduce the maximum text width to observe wrapping, then adjust font size, line height, and alignment.

### Labels

label adds an annotation beside a mark while keeping the node body visible. Use it to identify a data point by name or value. Text inside the node is still set through text.

| Property          | Values                           | Effect and constraints                        |
| ----------------- | -------------------------------- | --------------------------------------------- |
| `label`           | Field, detailed object, or array | Adds external labels; omitted means no label. |
| `label.position`  | Here: top, right, bottom, left   | Label placement relative to the node.         |
| `label.distance`  | Number                           | Distance between label and node.              |
| `label.pin`       | Boolean                          | Whether to show a label pin.                  |
| `label.textColor` | Color                            | Label text color.                             |

Use `encodings.label: { content: 'name' }` for field content and `properties.label: { position: 'top', distance: 12, pin: true }` for layout. Fixed text belongs to `properties.label.content`. Multiple labels match encodings and properties by array index.

The example labels three nodes with the tag field. Change the label position, distance, or pin while the node bodies and data positions stay fixed.

### Paths

Path styles control line paint, width, dashes, endpoints, and joins. Choose the feature you want to change, then adjust its property.

| Property         | Values                              | Effect and constraints                                                 |
| ---------------- | ----------------------------------- | ---------------------------------------------------------------------- |
| `stroke`         | Field or explicit color constant    | Line paint.                                                            |
| `strokeWidth`    | Numeric field or nonnegative number | Line width.                                                            |
| `opacity`        | Field or 0–1                        | Opacity of the path.                                                   |
| `dashPattern`    | Numeric array                       | Alternating dash and gap lengths; this example uses [7, 4] and [1, 4]. |
| `lineCap`        | butt, round, square                 | Flat, rounded, or projecting square endpoints.                         |
| `lineJoin`       | miter, round, bevel                 | Mitered, rounded, or beveled joins.                                    |
| `roundedCorners` | Nonnegative number                  | Rounds the path geometry at corners.                                   |

Set corner rounding to 0 and compare the three join styles, then increase the radius. Switch between dashed and dotted lines to observe how endpoint style affects them.

## Ordering and grouping

Drawing order, connection order, and series grouping serve different purposes. zIndex controls overlap order, order sorts rows along a path, and series splits rows into separate series.

| Property | Values          | Effect and constraints                                                      |
| -------- | --------------- | --------------------------------------------------------------------------- |
| `zIndex` | Field or number | Controls point overlap within a drawing layer; larger values appear on top. |
| `order`  | Field name      | Sorts rows by this field before connecting; omission uses input order.      |
| `series` | Field name      | Splits rows by field value, generating a separate path per series.          |

Rows are deliberately shuffled. Toggle sorting to compare input order with step order, and grouping to compare one path with two series paths. A and B overlap at step=2; adjust B’s drawing order to change which point covers the other.

<ComponentAlert
  type="tip"
  title="How this differs from data transforms"
  description="Data transforms run first: sort changes output row order, while groupBy defines groups for the current operation, such as sorting within groups, summarizing, selecting rows, or annotating rows with computed results. A mark’s order and series then determine how points connect and split into paths, without aggregation or changes to upstream data. Transform grouping does not automatically create separate paths; use series to specify them. You can omit order for already sorted data; setting it sorts the rows again when constructing paths."
/>

## Errors and limitations

- **Check mark support first.** Point, path, and interval mark properties do not all have the same shape. Do not copy configurations between mark types without checking.
- **Group by source.** `encodings` reads fields and `properties` supplies fixed values. An encoding wins at the same target; invalid bindings do not fall back.
- **Distinguish mappings from direct values.** A point size field uses a square-root scale by default; a constant size is a radius. Shape fields must be categorical. Opacity ranges from 0 to 1; radii and stroke widths cannot be negative.
- **Target the intended paint.** Use fill and stroke to control them independently. textColor affects node text; label.textColor affects external labels.
- **Leave space for large marks and labels.** domainPadding expands position-scale domains. Large radii, rotation, or labels may need more room; check dimensions and domains if marks extend outside the drawing.
