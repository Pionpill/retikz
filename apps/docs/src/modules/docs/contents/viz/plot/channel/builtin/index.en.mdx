title: Built-In Channels
description: Look up plot built-in channels by visual goal, including their field, fixed-value, and legend support.
---

Built-in channels map data to visual results such as position, style, text, and paths. In React DSL, declare channels directly as mark props, such as `<PointMark x="gdp" color="region" />`. Start with a visual goal in the overview below, then use the corresponding section to check value forms, visual results, and legend support.

Each table gives the form and visible meaning first, then the internal property destination in its last column. You can skip destinations on a first read.

| Type          | Channels                                                                                                | Meaning                                        |
| ------------- | ------------------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| Position      | `x` / `y` / `z`                                                                                         | Fields determine coordinate roles              |
| Style         | `color` / `fill` / `stroke` / `textColor`<br />`opacity` / `size` / `shape`                             | Color, opacity, size, and shape                |
| Node geometry | `padding` / `cornerRadius`<br />`rotate` / `minimumSize`                                                | Node size, spacing, and transforms             |
| Text          | `text` / `label`                                                                                        | Text inside nodes and labels attached to nodes |
| Paths         | `strokeWidth` / `thickness` / `lineCap` / `lineJoin`<br />`roundedCorners` / `fillRule` / `dashPattern` | Path stroke, caps, joins, fill, and dashes     |
| Effects       | `shadow` / `blendMode`                                                                                  | Shadows and compositing                        |
| Other         | `zIndex` / `order` / `series`                                                                           | Drawing order, ordering, and series splitting  |

## Position

Position channels say which row fields participate in coordinate projection. `x` / `y` / `z` are not fixed screen directions; the coordinate system reinterprets them. `cartesian2D` treats `x` / `y` as horizontal / vertical, while `polar2D` treats them as angle / radius.

| Channel | Channel Value        | Meaning                | Delivery                        |
| ------- | -------------------- | ---------------------- | ------------------------------- |
| `x`     | Field: `x = "field"` | First positional role  | first coordinate position role  |
| `y`     | Field: `y = "field"` | Second positional role | second coordinate position role |
| `z`     | Field: `z = "field"` | Third positional role  | third coordinate position role  |

## Style

Style channels control the visible appearance of a mark. Color, opacity, size, and shape are style channels. Use the panel to change the target channel and values while the same points and data remain fixed.

### Color

| Channel     | Channel Value                                                   | Meaning             | Delivery / guide                                                            |
| ----------- | --------------------------------------------------------------- | ------------------- | --------------------------------------------------------------------------- |
| `color`     | Field: `color = "field"`<br />Constant: `color = "red"`         | Main semantic color | mark-selected fill / stroke / text color; field values support color legend |
| `fill`      | Field: `fill = "field"`<br />Constant: `fill = "red"`           | Fill paint          | mark fill; node-backed marks can write node `fill`                          |
| `stroke`    | Field: `stroke = "field"`<br />Constant: `stroke = "red"`       | Stroke paint        | mark stroke; path-backed marks can write path stroke                        |
| `textColor` | Field: `textColor = "field"`<br />Constant: `textColor = "red"` | Text paint          | core node `textColor`                                                       |

### Opacity

Overall opacity affects both fill and stroke, fill opacity only fades the interior, and stroke opacity only fades the outline.

| Channel         | Channel Value                                                           | Meaning         | Delivery / guide                                                                           |
| --------------- | ----------------------------------------------------------------------- | --------------- | ------------------------------------------------------------------------------------------ |
| `opacity`       | Field: `opacity = "field"`<br />Constant: `opacity = {0.45}`            | Overall opacity | `IRScope.opacity`, `IRNode.opacity`, or `IRPath.opacity`; field values support ramp legend |
| `fillOpacity`   | Field: `fillOpacity = "field"`<br />Constant: `fillOpacity = {0.7}`     | Fill opacity    | scope / node / path fill opacity                                                           |
| `strokeOpacity` | Field: `strokeOpacity = "field"`<br />Constant: `strokeOpacity = {0.7}` | Stroke opacity  | scope / node / path stroke opacity                                                         |

### Size

The `size` channel is for quantitative magnitude. Field values default to a sqrt scale so perceived area is closer to the data difference.

| Channel | Channel Value                                       | Meaning    | Delivery / guide                                                                 |
| ------- | --------------------------------------------------- | ---------- | -------------------------------------------------------------------------------- |
| `size`  | Field: `size = "field"`<br />Constant: `size = {8}` | Glyph size | node `minimumSize`; field values default to a sqrt scale and support size legend |

### Shape

The `shape` channel is for categories. Categorical values map to built-in glyph shapes and can produce a symbol legend.

| Channel | Channel Value                                              | Meaning     | Delivery / guide                                 |
| ------- | ---------------------------------------------------------- | ----------- | ------------------------------------------------ |
| `shape` | Field: `shape = "field"`<br />Constant: `shape = "circle"` | Glyph shape | node `shape`; field values support symbol legend |

## Nodes, Text, And Effects

These channels all act on nodes produced by a mark. The panel keeps the same text nodes in place so size, typography, outside labels, and effects can be adjusted continuously instead of split across four static figures.

### Node Geometry

Node geometry channels directly control a node's size constraints, spacing, corner radius, and rotation. They do not map data to color or visual size.

| Channel              | Channel Value                                                                            | Meaning                 | Delivery                   |
| -------------------- | ---------------------------------------------------------------------------------------- | ----------------------- | -------------------------- |
| `minimumSize`        | Field: `minimumSize = "field"`<br />Constant: `minimumSize = {54}`                       | Node size constraints   | core node size fields      |
| `padding` / `margin` | Field: `padding = "field"`<br />Constant: `padding = {8}` / `padding = {{ x: 8, y: 4 }}` | Node spacing            | core node spacing fields   |
| `cornerRadius`       | Field: `cornerRadius = "field"`<br />Constant: `cornerRadius = {8}`                      | Rectangle corner radius | core node `cornerRadius`   |
| `rotate` / `scale`   | Field: `rotate = "field"`<br />Constant: `rotate = {18}`                                 | Node transform hints    | core node transform fields |

### Text inside nodes

`text` makes a point mark display text from a field. `textColor`, `align`, `lineHeight`, `maxTextWidth`, and `font` control its layout and color.

| Channel                                             | Channel Value                                                                                               | Meaning                                | Delivery                           |
| --------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- | -------------------------------------- | ---------------------------------- |
| `text`                                              | Field: `text = "field"`                                                                                     | Visible text for text-like point marks | mark assembly, then core node text |
| `align` / `lineHeight`<br />`maxTextWidth` / `font` | Field: `maxTextWidth = "field"`<br />Constant: `maxTextWidth = {54}`<br />Constant: `font = {{ size: 13 }}` | Text layout                            | core node text layout fields       |

### Node labels

`label` does not replace node content. It adds an outside label to the node for each data point. `labelPosition`, `labelDistance`, and `labelPin` control placement and the leader line.

| Channel                                           | Channel Value                                                           | Meaning          | Delivery               |
| ------------------------------------------------- | ----------------------------------------------------------------------- | ---------------- | ---------------------- |
| `label`                                           | Field: `label = "field"`                                                | Datum host label | core node `label`      |
| `labelPosition` / `labelDistance`<br />`labelPin` | Constant: `labelPosition = "top"`<br />Constant: `labelDistance = {16}` | Label layout     | core node label fields |

### Effects

Effect channels are shared visual hints. `shadow` changes the node projection, while `blendMode` changes color compositing where shapes overlap. `boundary` remains in the table as the advanced boundary override.

| Channel     | Channel Value                                                                 | Meaning                 | Delivery                   |
| ----------- | ----------------------------------------------------------------------------- | ----------------------- | -------------------------- |
| `shadow`    | Field: `shadow = "field"`<br />Constant: `shadow = "xl"`                      | Shadow preset or object | core node/path `shadow`    |
| `blendMode` | Field: `blendMode = "field"`<br />Constant: `blendMode = "multiply"`          | Compositing mode        | core node/path `blendMode` |
| `boundary`  | Field: `boundary = "field"`<br />Constant: `boundary = {{ shape: "circle" }}` | Node boundary override  | core node `boundary`       |

## Paths

Path channels apply to marks that produce paths, such as line marks, relation lines, region boundaries, and reference lines. Endpoint arrows are not channels; configure them with `marks` on the relevant path.

### Path styling

| Channel                                | Channel Value                                                           | Meaning               | Delivery / guide                                                            |
| -------------------------------------- | ----------------------------------------------------------------------- | --------------------- | --------------------------------------------------------------------------- |
| `strokeWidth`                          | Field: `strokeWidth = "field"`<br />Constant: `strokeWidth = {4}`       | Stroke width          | scope / node / path `strokeWidth`; field values default to range `[0.5, 4]` |
| `thickness`                            | Field: `thickness = "field"`<br />Constant: `thickness = "thick"`       | Semantic width preset | converted to core path `strokeWidth`                                        |
| `roundedCorners`                       | Field: `roundedCorners = "field"`<br />Constant: `roundedCorners = {8}` | Path corner hint      | core path `roundedCorners`                                                  |
| `fillRule`                             | Field: `fillRule = "field"`<br />Constant: `fillRule = "evenodd"`       | Closed-path fill rule | core path `fillRule`                                                        |
| `lineCap`<br />`lineJoin`              | Field: `lineCap = "field"`<br />Constant: `lineCap = "round"`           | Stroke cap and join   | core path line fields                                                       |
| `dashPattern` / `dashed`<br />`dotted` | Field: `dashPattern = "field"`<br />Constant: `dashPattern = {[7, 4]}`  | Stroke pattern        | core node/path dash fields                                                  |

## Other

Other channels do not directly describe color, position, or path shape. They control drawing order, row ordering, and series splitting.

<ComponentPreview
  files={['builtin-other', 'builtin-other.data.ts']}
  size="md"
  caption="The input rows are intentionally shuffled: series splits two lines, order restores their step sequence, and points use a higher zIndex to stay above the lines."
/>

| Channel  | Channel Value                                           | Meaning                            | Delivery                                 |
| -------- | ------------------------------------------------------- | ---------------------------------- | ---------------------------------------- |
| `zIndex` | Field: `zIndex = "field"`<br />Constant: `zIndex = {1}` | Drawing-order hint                 | scope / node / path `zIndex`             |
| `order`  | Field: `order = "field"`                                | Connection order for path marks    | mark reads the field and sorts datums    |
| `series` | Field: `series = "field"`                               | Multi-series splitting or grouping | mark reads the field and splits elements |

`order` and `series` are not part of the `encoding` object, but they are still field-driven channel entries. In React DSL, users write them as mark props too.
