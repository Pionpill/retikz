Use `relate` to select two representative rows from every group and derive a relation. It runs separate selectors for source and target, projects endpoint fields, and computes optional measures. Each group emits zero or one row.

`relate` commonly lives in `RelationMark.transform`, but it is not private to RelationMark. Its output fields are ordinary derived data that other marks can consume.

## Row Pairing

`relate` separates “which two rows to select” from “which endpoint fields to emit.” Source and target may use different selectors, but both run inside the same `groupBy` group.

### Dynamic Demo

Switch between global and per-series pairing, then choose first, last, lowest, or highest rows independently for source and target. The data table stays expanded so arrow endpoints, direction, and difference labels remain easy to inspect.

<ComponentPreview files={['transform-relate', 'transform-relate.data.ts']} size="md" />

Per-series pairing emits one relation for each series; all-rows pairing emits one global relation. The demo projects `sourceId` / `targetId`, then calculates `target.value - source.value`. `PathMark` and `PointMark` continue reading source data; only the mark-local `RelationMark` transform reads the paired result.

### API Reference

`IRPlotRelateTransform` fixes `kind` to `'relate'`.

| prop        | type                                | default          | description                                    |
| ----------- | ----------------------------------- | ---------------- | ---------------------------------------------- |
| `groupBy?`  | `Array<string>`                     | one global group | Generate zero or one relation row per group    |
| `source`    | `IRPlotEndpointProjection`          | —                | Source selector and non-empty field projection |
| `target`    | `IRPlotEndpointProjection`          | —                | Target selector and non-empty field projection |
| `measures?` | `Array<IRPlotPairMeasureOperation>` | —                | Derived measures between source and target     |

`IRPlotEndpointProjection` contains:

| prop       | type                      | description                                     |
| ---------- | ------------------------- | ----------------------------------------------- |
| `selector` | `IRDataSelectorOperation` | Select endpoint candidates inside the group     |
| `fields`   | `Record<string, string>`  | Non-empty “output suffix -> endpoint field” map |

For example, `source.fields: { id: 'id', x: 'month' }` emits `sourceId` and `sourceX`. `measures` currently includes <ApiValues name="PairMeasureOperationKind" />. `difference` calculates `target[field] - source[field]` and may emit both numeric and label fields.

### How It Works

The source and target branches in the figure are parallel selections, not sequential filters. They only join for field projection and measure calculation after both endpoints exist, so each group emits at most one relation row.

<ComponentPreview files="transform-relate-logic" hideCode size="xl" />

Execution has four steps:

1. `groupBy` creates independent groups; when omitted, all input rows share one group.
2. Source and target each call a shared data selector and take the first selected row.
3. `fields` writes endpoint values as `sourceXxx` / `targetXxx`; `measures` reads the original endpoint rows to derive values.
4. When both endpoints exist, one row is emitted with provenance from both. If either selector returns no row, the group is skipped without empty placeholders.

Each endpoint `fields` map must be non-empty. `labelPrefix` is only added to non-negative label text and does not change the numeric measure.
