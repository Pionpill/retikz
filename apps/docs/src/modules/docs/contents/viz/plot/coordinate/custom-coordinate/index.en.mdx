title: Custom Coordinates

A coordinate maps position values into screen geometry. When built-in coordinates cannot express the target space, use `defineCoordinate` to declare a runtime projection; Plot IR still stores only the custom `type` and JSON config.

## Applicability

- Define a custom coordinate for new position roles, projection functions, curved axes, or a special space.
- React `<PointMark>` currently exposes `x` / `y` / `z` directly. Express arbitrary `u` / `v` roles through full-spec or Vanilla `encoding`.
- Use a [Custom Scale](/viz/plot/scale/custom-scale) when only domain mapping changes, or a [Custom Mark](/viz/plot/mark/custom-mark) when only mark geometry changes.
- A coordinate definition owns the frame and guides; it should not generate business marks or renderer-specific objects.

## Define the capability

`defineCoordinate<TCoordinateOperation>` receives this contract:

| Field     | Purpose                                                                                 |
| --------- | --------------------------------------------------------------------------------------- |
| `schema`  | Validates the custom coordinate operation; a non-built-in literal `type` is its key     |
| `roles`   | Declares the required position channels and their order                                 |
| `resolve` | Builds a `CoordinateResolution` from the operation, domains, scales, canvas, and guides |

The returned `frame` projects points and optional Cells; `plotArea` describes the drawing region; `axisLayers` and `gridLayers` deliver guide output.

The bridge coordinate below arches the x-axis into a parabola while y stays vertical. Drag the arch-height control to see how an operation parameter changes projection; its definition uses a closed schema, and the source switcher exposes the data and host injection:

## Inject into the host

Inject the definition with `<Plot coordinates={[bridgeCoordinate]}>` and reference it from the coordinate operation:

```tsx
<Plot coordinate={{ type: 'bridge', archHeight: 60 }} coordinates={[bridgeCoordinate]}>
  <PointMark x="x" y="y" />
</Plot>
```

Arbitrary position roles are not limited by the React mark-prop name set, but they require a full spec:

```ts
const spec = {
  // ...
  coordinate: { type: 'uv' },
  marks: [{ type: 'point', encoding: { u: { field: 'u' }, v: { field: 'v' } } }],
};
```

The definition with `roles: ['u', 'v']` must still be injected through `<Plot coordinates>` or `renderPlot` options. Projection functions stay in the host; IR stores only the type, config, and bindings.

## Execution

1. The host merges built-in and custom coordinate definitions into one registry and validates role names and duplicate types.
2. Lowering looks up `coordinate.type`; a miss fails immediately, while a hit validates the JSON operation with the definition schema.
3. `CoordinateDefinitionResolveContext` collects each role's domain, resolves position scales, and exposes canvas and guide information.
4. `resolve` builds a frame with `createCoordinateFrame`, then returns the `plotArea`, axis layers, and grid layers.
5. Marks project through `frame.projectRoles` or optional `frame.projectCell` without depending on the concrete coordinate implementation.

`createCoordinateFrame` can receive `roleScales`, `frameAlong`, and `projectCell`. The first supports custom axes and interval role scales; the last projects a logical Cell into rect, sector, contour, or related geometry.

## Errors and limits

- A custom `type` cannot override a built-in coordinate or be registered twice. Referencing an unregistered type asks the current host options to inject its definition.
- Missing required roles, encoding keys unsupported by the coordinate, or schema validation failures all fail immediately.
- The example uses `z.strictObject`; an unknown key such as `archHeigth` is not silently stripped or replaced by a default.
- Point-like marks only require `projectRoles`; interval-like marks also require matching `roleScales` and `projectCell`.
- A custom coordinate uses the `plotArea` returned by its definition and does not automatically inherit cartesian margin and legend reservation.
- Curved axes can be generated through `lowerCustomAxis`; grids, 3D spaces, and multi-plot composition require explicit definition capabilities.

This operation fails because its config key is misspelled:

```ts
coordinate: { type: 'bridge', archHeigth: 60 }
```

## API reference

Public exports:

| Import from `@retikz/plot`           | Use                                                        |
| ------------------------------------ | ---------------------------------------------------------- |
| `defineCoordinate`                   | Builds a coordinate definition from schema, roles, resolve |
| `CoordinateDefinition`               | Full role and resolve runtime contract                     |
| `CoordinateDefinitionResolveContext` | Domain, scale, canvas, and guide resolution entry points   |
| `createCoordinateFrame`              | Builds point, tangent, and optional Cell projection frame  |

Host injection:

| Host                                     | Public contract     | Injection field                           |
| ---------------------------------------- | ------------------- | ----------------------------------------- |
| `<Plot>` from `@retikz/plot-react`       | `PlotProps`         | `coordinates`                             |
| `renderPlot` from `@retikz/plot-vanilla` | `RenderPlotOptions` | Inherited `LowerPlotsOptions.coordinates` |
