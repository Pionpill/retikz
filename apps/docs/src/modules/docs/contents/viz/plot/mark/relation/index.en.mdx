title: RelationMark
description: RelationMark lowers source / target relationships from data rows into core Paths, using kind to distinguish stroked paths from ribbon bands.
---

`<RelationMark>` represents a drawable source-target relationship between two targets. Each relation row lowers to one core `Path`; the default is a stroked path, while `kind="ribbon"` emits a ribbon Path.

A target can be an existing core id, a stable id generated by `PointMark` / `IntervalMark` / `PathMark` through `anchorId`, or a coordinate projected from the current relation row. Data composition and layout remain the responsibility of transforms and arrangements.

## Usage

```tsx
import { Plot, PointMark, RelationMark } from '@retikz/plot-react';
```

```tsx
<Plot data={edges}>
  <PointMark x="sourceX" y="sourceY" anchorId={{ prefix: 'node', field: 'sourceId' }} />
  <PointMark x="targetX" y="targetY" anchorId={{ prefix: 'node', field: 'targetId' }} />
  <RelationMark
    source={{ anchorId: { prefix: 'node', field: 'sourceId' } }}
    target={{ anchorId: { prefix: 'node', field: 'targetId' } }}
    path={{ options: { marks: [{ pos: 1, mark: { kind: 'arrow' } }] } }}
  />
</Plot>
```

`RelationMark` is usually paired with positional marks that define `anchorId`. The positional mark projects rows into core `Node` / `Coordinate` elements and gives them stable ids. The relation mark uses the same rule shape on its own rows to compute source / target ids, then lowers to a core `Path`. When the edge rows do not already exist, `transform` can derive relation rows locally for this mark.

Under polar2D, RelationMark inherits coordinate interpolation only for a default path whose source, target, and every `path.via` use `{ project }`. `path.interpolation` may override that default locally. ID / anchor targets, explicit `route`, `routing`, and ribbon geometry remain owned by Relation routing. Setting interpolation explicitly on those excluded forms fails loudly; omitting it preserves their existing behavior.

### When to Use

RelationMark is the low-level relationship path mark. It does not reinvent arrows, labels, or routed lines; it turns relationship data into a core `Path.children` step sequence. Dependency lines, flow lines, reference lines, and labeled graphConnectors are all different configurations of the same source-target path.

| Presentation            | Key props                           | Notes                                                                                                       |
| ----------------------- | ----------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| Point-to-point relation | `source` / `target`                 | Reference existing nodes by id or generated anchor rules, then connect with the default `move -> line` path |
| Waypoint path           | `path.via` / `path.route[].to`      | Projected waypoints generate core `Coordinate` elements, so later ids can reference them                    |
| Geometry label          | `label`                             | Lowers to core `Path.label`; path and ribbon relations share the same host label                            |
| Step label              | `path.label` / `path.route[].label` | Lowers to core step label; explicit step labels win over shorthand                                          |
| Core Path capabilities  | `path.options`                      | Passes through path-only options such as marks, rounded corners, and dash patterns                          |
| Path ribbon kind        | `kind="ribbon"` / `ribbon`          | Lowers source-target rows into core `Path` objects with `kind: 'ribbon'` for Sankey-style bands             |
| Shared style            | `style`                             | Shared paint and opacity fields used by both path and ribbon relations                                      |

#### Bubble Relation

## How it works

<ComponentAlert
  type="tip"
  title="You can skip this section at first"
  description="Return when debugging target resolution, automatic routing, ribbon lowering, or generated anchorId errors."
/>

`<RelationMark>` reads one `source` / `target` pair per row, resolves both into locatable core targets, and creates an ordinary path or ribbon. Its local `transform` runs after plot-level transforms, so it can derive relation rows before targets, labels, styles, and widths read those derived fields.

The following flow stops at the RelationMark boundary: path and ribbon relations share target resolution, branch only while building geometry, and both produce a core `Path`.

<ComponentPreview files="relation-lowering-flow" hideCode size="xs" />

| Stage                 | Observable behavior                                                                                                                                             |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Resolve targets       | `{ id }` references an existing target, `{ anchorId }` generates a target id from the current row, and `{ project }` projects role fields into a new coordinate |
| Build route           | An all-projected polar2D default path may sample by coordinate interpolation; route, routing, ID / anchor targets, and ribbon do not inherit it                 |
| Generate geometry     | The default creates a core `Path`; `kind="ribbon"` uses `ribbon.width` / `endWidth` to create a ribbon Path and ignores path routing                            |
| Decorate and diagnose | Top-level `label` attaches to the final Path and step labels attach to segments; missing targets and duplicate generated anchor ids report mark and row context |

`path.route` and `path.routing` are mutually exclusive. Default, line, and bend routing place `path.label` on the last drawable step. Orthogonal routing defaults to `labelStep="main"` and places the label on the longest main segment; only `labelStep="last"` selects the final segment. An explicit `path.route[].label` takes precedence.

## API Reference

This table keeps only RelationMark-specific props and props whose meaning is redefined here. React users can import `RelationMarkProps` from `@retikz/plot-react`; the `IRPlot*` types in the table come from `@retikz/plot`, while Vanilla authoring uses `InputPlotRelationPathGeometry` from `@retikz/plot-vanilla`. See [transforms](/viz/plot/transform) for local `transform` and `relate`, [channel bindings](/viz/plot/channel/binding) for extension channels, and [coordinates](/viz/plot/coordinate) for projected targets. Put color, stroke, opacity, shadow, and other shared path / ribbon styles in `style`; put ordinary-path-only marks, dashes, and corners in `path.options`.

| Prop                  | Type                                                | Default             | Description                                                                                                         |
| --------------------- | --------------------------------------------------- | ------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `source` / `target`   | `RelationMarkProps['source']`                       | Required            | Start and end targets: direct id, row-generated anchor id, or projected coordinate                                  |
| `kind?`               | <ApiValues name="RelationGeometryKind" />           | `path`              | Create an ordinary Path or ribbon Path for each row                                                                 |
| `label?`              | `RelationMarkProps['label']`                        | —                   | Geometry label for the whole relation                                                                               |
| `path.via?`           | `NonNullable<RelationMarkProps['path']>['via']`     | —                   | Intermediate targets for default or algorithmic routing; Vanilla input is `InputPlotRelationPathGeometry['via']`    |
| `path.interpolation?` | <ApiValues name="PolarInterpolation" />             | Coordinate default  | Connection-space override only for all-projected polar2D default paths; incompatible with route, routing, or ribbon |
| `path.routing?`       | `NonNullable<RelationMarkProps['path']>['routing']` | `line`              | `line`, `bend`, or `orthogonal`; mutually exclusive with `path.route`                                               |
| `path.route?`         | `NonNullable<RelationMarkProps['path']>['route']`   | —                   | Explicit core-like steps; a final step without `to` points at target                                                |
| `path.label?`         | `NonNullable<RelationMarkProps['path']>['label']`   | —                   | Step-label shorthand for default or algorithmic paths                                                               |
| `path.options?`       | `NonNullable<RelationMarkProps['path']>['options']` | —                   | Path-only marks, dashes, rounded corners, line caps, and joins                                                      |
| `ribbon.width`        | `IRPlotRelationRibbonOptions['width']`              | Required for ribbon | Source width; also the full width when `endWidth` is absent                                                         |
| `ribbon.endWidth?`    | `IRPlotRelationRibbonOptions['endWidth']`           | —                   | Target width                                                                                                        |
| `ribbon.options?`     | `IRPlotRelationRibbonOptions['options']`            | —                   | Alignment, sampling, and width interpolation                                                                        |
| `style?`              | `RelationMarkProps['style']`                        | —                   | Visual styles shared by path and ribbon                                                                             |
| `color?`              | `RelationMarkProps['color']`                        | —                   | Field-driven relation color channel                                                                                 |
