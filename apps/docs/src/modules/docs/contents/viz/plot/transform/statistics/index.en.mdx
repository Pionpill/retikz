title: Density & Trend
description: Use density and smooth to turn raw samples into density or trend rows that PathMark can draw.
---

Use `density` to estimate a distribution curve from one-dimensional samples. Use `smooth` to fit a linear trend from `(x, y)` samples. Both emit a batch of new rows per group rather than one statistic.

General reducers, selectors, and grouped summaries belong to [Data Transforms](/viz/data/transform).

## Density

`density` runs Gaussian kernel density estimation on each group's finite one-dimensional samples, emitting evenly spaced positions and density values. `PathMark` then connects those rows as a curve or area.

### Dynamic Demo

Switch between automatic Silverman bandwidth and an explicit value, then adjust `sampleCount`. Fixed coordinate domains make bandwidth and sampling density directly comparable.

<ComponentPreview files={['transform-density', 'transform-density.data.ts']} size="md" />

Bandwidth controls how far each observation spreads along the x-axis. A smaller bandwidth preserves more local peaks and valleys; a larger one blends a wider neighborhood into a smoother curve. `sampleCount` only changes output sampling density, not smoothing strength.

### API Reference

`IRPlotDensityTransform` fixes `kind` to `'density'`.

| prop           | type                         | default                 | description                               |
| -------------- | ---------------------------- | ----------------------- | ----------------------------------------- |
| `field`        | `string`                     | —                       | One-dimensional continuous input field    |
| `groupBy?`     | `Array<string>`              | one global group        | Estimate density independently per group  |
| `bandwidth?`   | `IRPlotDensityBandwidthSpec` | `silverman`             | KDE bandwidth strategy                    |
| `sampleCount?` | `number`                     | `64`                    | Sampled output rows per group; at least 2 |
| `extent?`      | `[number, number]`           | expanded observed range | Sampling interval                         |
| `xAs`          | `string`                     | —                       | Output field for density sample positions |
| `densityAs`    | `string`                     | —                       | Output field for density values           |

`bandwidth.kind` uses <ApiValues name="DensityBandwidthKind" />. The `value` branch also requires a positive `value`.

### How It Works

The `density` main chain is “group finite samples → resolve bandwidth → average kernels at each position → emit sampled rows.” Bandwidth strategy and sampling configuration are auxiliary inputs, not extra data-processing stages.

<ComponentPreview files="transform-density-logic" hideCode size="xl" />

Each group first drops non-finite `field` values and sorts the rest. The Silverman strategy combines standard deviation and interquartile range to estimate a positive bandwidth. The explicit strategy uses `bandwidth.value` directly.

When `extent` is omitted, the sampling domain expands three bandwidths beyond each observed endpoint. `linearSamplesOf` generates `sampleCount` evenly spaced positions, where density is the mean of all Gaussian sample kernels:

`f(x) = (1 / n h) × Σ K((x - xᵢ) / h)`

A group with no finite samples throws. Silverman also requires at least two finite values and a positive derived bandwidth; use an explicit positive bandwidth for single-value or constant groups. Every group emits `sampleCount` rows with group fields and provenance.

## Trend

`smooth` currently fits each group's `(x, y)` values with ordinary least squares and emits predicted samples. Keep source points and trend output in separate marks: solid points read source data; the path and hollow points reuse one transform configuration, but each mark runs its own local transform and builds its own data view.

### Dynamic Demo

Adjust the number of predictions and switch between the observed range and explicit extrapolation. Hollow points show the predicted rows directly while the coordinate domain stays fixed: `sampleCount` changes their spacing, and `extent` only changes the sampled trend interval.

<ComponentPreview files={['transform-smooth', 'transform-smooth.data.ts']} size="md" />

### API Reference

`IRPlotSmoothTransform` fixes `kind` to `'smooth'`.

| prop           | type                     | default                 | description                                    |
| -------------- | ------------------------ | ----------------------- | ---------------------------------------------- |
| `x`            | `string`                 | —                       | Independent regression field                   |
| `y`            | `string`                 | —                       | Dependent regression field                     |
| `groupBy?`     | `Array<string>`          | one global group        | Fit trends independently per group             |
| `method?`      | `IRPlotSmoothMethodSpec` | `linear`                | Smoothing method                               |
| `sampleCount?` | `number`                 | `64`                    | Predicted output rows per group; at least 2    |
| `extent?`      | `[number, number]`       | finite observed x range | Sampling interval; explicit values extrapolate |
| `xAs`          | `string`                 | —                       | Output field for predicted positions           |
| `yAs`          | `string`                 | —                       | Output field for predicted values              |

`method.kind` uses <ApiValues name="SmoothMethodKind" />. The only current branch is `linear`, with no extra fields.

### How It Works

`smooth` first filters finite `(x, y)` pairs, then fits one linear model per group. `extent` and `sampleCount` only control prediction sampling after the model is fitted.

<ComponentPreview files="transform-smooth-logic" hideCode size="xl" />

Ordinary least squares computes `meanX`, `meanY`, x variance, and xy covariance before deriving:

`slope = covarianceXY / varianceX`

`intercept = meanY - slope × meanX`

Without `extent`, sampling uses the finite observed x minimum and maximum. An explicit range can extrapolate beyond the observations. Each evenly spaced x writes `intercept + slope × x`, so every group emits `sampleCount` rows.

Each group needs at least two finite pairs and positive x variance; a vertical line cannot be represented as `y = a + bx`. The `extent` lower bound must be smaller than its upper bound, output fields must differ, and neither may overwrite a `groupBy` field.
