---
title: 1D Coordinates
description: '1D coordinates place one positional field on a line or circle for axis events, timelines, and cyclic events.'
---

When data only needs positioning along one path, you do not need to invent a second positional field. “1D” describes how many dimensions participate in positioning, not whether an axis is visible: `cartesian1D` reads `x` and places values on a line, while `polar1D` wraps them around a circle.

## Try It

Switch between the line and circle in the control panel. In the circular form, you can also adjust the outer radius and angular range.

## Compose After Mapping

A 1D coordinate does not have to be the final graphic. It can first arrange objects along a line and let the mapped results participate in links. The figure places 12 objects on the upper line; every four connect to one shared summary point below, producing three groups.

Within the same Plot, `PointMark` first uses `thingX` to map the single positional field into core Nodes, then a mark-local `summarize` collapses repeated target fields into three lower Nodes. `anchorId` gives these results stable ids, so `RelationMark` can make every four source Nodes reference the same target Node. Mapped results can therefore continue into converging links, annotations, and other follow-up operations.

## Choose and Configure

| Goal            | Coordinate configuration                              | Key configuration                     |
| --------------- | ----------------------------------------------------- | ------------------------------------- |
| Horizontal line | `coordinate="cartesian1D"`                            | `orientation: 'horizontal'`           |
| Vertical line   | `{ type: 'cartesian1D', orientation: 'vertical' }`    | `orientation: 'vertical'`             |
| Full circle     | `coordinate="polar1D"`                                | `radius: 1`, angles from `0` to `360` |
| Partial circle  | `{ type: 'polar1D', startAngle: 180, endAngle: 360 }` | Set `startAngle` and `endAngle`       |

Both object forms belong to `CoordinateInput`, exported by `@retikz/plot-react`. `cartesian1D` is horizontal by default. For `polar1D`, `radius` defaults to `1`, meaning the full available outer radius; its range is `0 < radius <= 1`, not a pixel value. Angles use degrees and default to `0` through `360`.

The playground's “Sweep angle” is a teaching control, not a `CoordinateInput` field. Internally it becomes `endAngle = startAngle + sweepAngle`.

The number of coordinate dimensions does not restrict the scale type. The position field can still use linear, log, time, and other scales. This example explicitly fixes the hour domain to `[0, 24]`, so hour `22` lands at `330°` on a full circle.

`<PointMark>` is currently the only mark whose position can be projected directly by a 1D coordinate, covering axis events, timeline nodes, and circular event points. `RelationMark` can still reference already positioned targets, as in the figure above. Bars, sectors, and areas require a 2D region and report an error in a 1D coordinate.
