Marks are the geometry layer of the graphic grammar. They answer “what geometry should each row or group of rows produce?”—a point, path, interval, or relation path between two targets.

Choose a mark from the geometric relationship in the data, not from the final chart name. The same `IntervalMark` can form bars, heatmaps, or pies, while the same `PointMark` can appear as scatter points, bubbles, or text.

For a mark without an authored color, `defaultColorIndex` selects a zero-based, cycling index in `defaultPlot.palette.series`. It takes precedence over `defaultColorGroup`, does not consume an automatic group slot, and never overrides explicit paints or field mappings.

## Responsibilities

| Category | Mark           | What it expresses                         | Common uses                              |
| -------- | -------------- | ----------------------------------------- | ---------------------------------------- |
| Primary  | `PointMark`    | One position or node per row              | Scatter, bubbles, shape marks, text      |
|          | `PathMark`     | A one-dimensional trajectory from a group | Lines, area boundaries, radar outlines   |
|          | `IntervalMark` | Products of intervals on position roles   | Bars, histograms, heatmaps, radial forms |

A mark owns only the contract that turns data into geometry:

- [Scales](/viz/plot/scale) map field values to positions, colors, sizes, and other visual values
- [Coordinates](/viz/plot/coordinate) interpret position roles and project them onto the canvas
- [Guides](/viz/plot/guide) provide axes, legends, and other reading aids
- Renderers output the lowered core geometry as SVG, Canvas, or another target

Built-in marks eventually lower into [@retikz/core](/kernel/components/introduction) Node, Path, and other Kernel IR, but using them does not require handling those objects directly.

## Position inputs and reference marks

Point, Path, and Interval marks share these position inputs:

| Input    | Syntax                                  | Meaning                                                        |
| -------- | --------------------------------------- | -------------------------------------------------------------- |
| Field    | `{ field: 'x' }`                        | Read a final result row                                        |
| Constant | `{ value: 50 }`                         | Data-space number or category string                           |
| Edge     | `{ edge: 'start' }` / `{ edge: 'end' }` | Endpoints of the final mapped range, including reversed ranges |

Positions belong in `encodings`; geometry styles belong in `properties`. Effective field dependencies generate marks from final result rows; constants and edges alone generate one instance per actual view. Empty result tables generate no data instances. `transforms: []` is equivalent to omission; nonempty transforms require field dependencies.
