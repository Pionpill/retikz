title: Dimensional coordinates
description: Choose Cartesian or polar projections for one or two positional fields to place marks on a plane, line, or circle.
---

Coordinates determine where positional fields land on the canvas. Fields bind to position channels and pass through scales before projection. Two positional fields can describe horizontal and vertical positions, or angle and radius. With one positional field, place objects along a line or circle without inventing a second field.

Choose the projection through Plot's `coordinate` prop. One and two dimensions refer to the number of positional dimensions, regardless of whether axes are visible.

| Positioning goal                             | `coordinate`  | Position channels                  |
| -------------------------------------------- | ------------- | ---------------------------------- |
| Compare position and height on a plane       | `cartesian2D` | `x` is horizontal, `y` is vertical |
| Compare angles and distances around a center | `polar2D`     | `x` is angle, `y` is radius        |
| Arrange events or nodes along a line         | `cartesian1D` | `x` is position along the line     |
| Arrange cyclic events around a circle        | `polar1D`     | `x` is angle                       |

These forms reuse field bindings and scales. Read [Channels](/viz/plot/channel) for field binding, or [Coordinate composition](/viz/plot/coordinate/composition) for dual axes, facets, and shared tracks.

## 2D coordinates

A 2D coordinate uses two positional dimensions to control horizontal and vertical positions, or angle and radius.

### Cartesian coordinates

Cartesian coordinates map `x` horizontally and `y` vertically, making them suitable for comparing categories and values along shared straight axes. The playground fixes the coordinate and six data rows while letting you switch marks, adjust plot-area margins, and toggle the y grid:

- Points use `<PointMark>` to show the position of each row.
- Lines use an open `<PathMark>` to connect those positions by `order`.
- Areas use `<IntervalMark>` to occupy each category band and extend upward from the `y = 0` x-axis baseline.

### Polar coordinates

Polar coordinates map `x` to angular positions around the center and `y` to radial distance. They reuse the same data and marks, but their projected relationships change:

- Points spread around the angle, with values determining their radii.
- Lines use a closed `<PathMark>` that connects the final point back to the first.
- Areas still use `<IntervalMark>`, producing radial intervals separated by category.

`interpolation` chooses the connection space between neighboring polar positions. When omitted, a continuous angular scale uses `polar`, interpolating in angular / radial output space before projection; a discrete angular scale uses `chord`, connecting projected vertices directly. An explicit coordinate value affects both the grid and inheriting marks. PathMark and IntervalMark may override it locally, while PointMark exposes no such setting because points have no adjacent boundary.

The playground controls coordinate and mark interpolation separately, along with `innerRadius`, the start angle, and the sweep angle. Sweep angle is a teaching parameter in the panel; the coordinate receives `endAngle = startAngle + sweepAngle`.

## 1D coordinates

A 1D coordinate uses one positional dimension to place events or nodes along a line or a circle with a fixed radius.

### Position along a line or circle

| Goal            | Coordinate configuration                              | Key configuration                     |
| --------------- | ----------------------------------------------------- | ------------------------------------- |
| Horizontal line | `coordinate="cartesian1D"`                            | `orientation: 'horizontal'`           |
| Vertical line   | `{ type: 'cartesian1D', orientation: 'vertical' }`    | `orientation: 'vertical'`             |
| Full circle     | `coordinate="polar1D"`                                | `radius: 1`, angles from `0` to `360` |
| Partial circle  | `{ type: 'polar1D', startAngle: 180, endAngle: 360 }` | Set `startAngle` and `endAngle`       |

Both object forms are values of `<Plot>`'s `PlotDslProps['coordinate']` prop. `cartesian1D` is horizontal by default. For `polar1D`, `radius` defaults to `1`, meaning the full available outer radius; its range is `0 < radius <= 1`, not a pixel value. Angles use degrees and default to `0` through `360`.

The playground's “Sweep angle” is a teaching control, not a `PlotDslProps['coordinate']` field. Internally it becomes `endAngle = startAngle + sweepAngle`.

The number of coordinate dimensions does not restrict the scale type. The position field can still use linear, log, time, and other scales. This example explicitly fixes the hour domain to `[0, 24]`, so hour `22` lands at `330°` on a full circle.

`<PointMark>` is currently the only mark whose position can be projected directly by a 1D coordinate, covering axis events, timeline nodes, and circular event points. `PathMark` can still reference already positioned targets, as in the following example. Bars, sectors, and areas require a 2D region and report an error in a 1D coordinate.

Switch between the line and circle in the control panel. In the circular form, you can also adjust the outer radius and angular range.

### Connect positioned objects

A 1D coordinate does not have to be the final graphic. It can first arrange objects along a line and let the mapped results participate in links. The figure places 12 objects on the upper line; every four connect to one shared summary point below, producing three groups.

Within the same Plot, `PointMark` first uses `thingX` to map the single positional field into nodes, then a mark-local `summarize` collapses repeated target fields into three lower Nodes. `anchorId` gives these results stable ids, so `PathMark` can make every four source Nodes reference the same target Node. Mapped results can therefore continue into converging links, annotations, and other follow-up operations.

## Custom coordinates

When built-in projections cannot express the target space, define new positional roles and a projection, then register the coordinate with Plot. Custom coordinates use the same position-channel and scale bindings; their declared roles determine the dimensions.

See [Custom coordinates](/viz/plot/coordinate/custom-coordinate) for a complete definition, registration, and usage example. To change only the mapping from data values to positional values, use [scales](/viz/plot/scale).
