数据模型说明字段是什么、真实数据怎么接进来；通道绑定说明字段**用在哪里**。在 React 写法里没有单独的 `<Encoding>` 组件，通道通常直接写在 mark props 上。

```tsx
<PointMark x="gdp" y="life" color="region" size="population" />
<PointMark x="gdp" y="life" text="abbr" />
```

这些 props 就是通道的使用入口：`x` 是位置通道，`color` 是颜色通道，`size` 是样式通道。一个图元可以同时使用多个通道，把同一行数据转成位置、外观和文字。

## 字段与常量

React DSL 里字符串通常表示字段名：

```tsx
<PointMark x="gdp" y="life" color="region" />
```

少数通道也接受常量。最典型的是 `ReferenceMark`：

```tsx
<ReferenceMark y={80} color="crimson" />
```

对于既能接收字段名、又能接收字符串常量的**内置扁平样式 prop**，React DSL 按下面的优先级消除歧义：

1. 先在当前数据集与数据模型中匹配同名字段；命中后生成字段绑定。
2. 只有字段未命中时，才检查这个字符串是不是该 prop 接受的合法常量，例如 CSS 颜色或内置形状名。
3. 两种规则都不接受时，构建器会给出警告并跳过这个 prop。

因此，如果数据中存在名为 `crimson` 的字段，`color="crimson"` 会优先读取该字段，而不是使用深红色常量。需要避开同名歧义时，可以显式声明常量：

```tsx
<PointMark color={{ kind: 'constant', value: 'crimson' }} />
```

这套判定只发生在 React DSL 构建 `IRPlot` 时，不表示某一行缺少字段值后会回退到常量。进入 Plot IR 后，一个通道仍然只能二选一：要么读取每行数据中的字段，要么始终使用同一个固定值。

位置通道的字符串仍直接表示字段；自定义 `channels` 中的字符串也直接表示字段，常量需要显式写成 `{ kind: 'constant', value }`。完整的构建期判定与运行期取值链路见后文“技术原理”。

## 绑定试验场

在面板中切换 `x` / `y` 字段，并把颜色、大小或形状从字段驱动改成固定值。图形结构保持不变，因此每次操作只展示当前通道绑定带来的差异。

同一行数据可以同时绑定到多个通道：`gdp` 与 `life` 决定位置，`region` 决定颜色和形状，`population` 决定点半径，`abbr` 决定文字标注。切成固定值后，数据行不再参与对应样式的计算。

`Axis` 根据位置通道显示坐标刻度。本试验场只挂载了颜色和大小图例，因此相应通道改成固定值后，对应 `Legend` 会消失；完整能力还支持为字段驱动的透明度和形状通道添加图例。

## 比例尺与坐标系

通道只负责“取哪个值”。比例尺负责把值映射到绘图空间或视觉属性；坐标系负责解释位置通道的角色。例如同样的 `x="quarter"`、`y="value"`，在 `cartesian2D` 下是横向分类 + 纵向数值，在 `polar2D` 下会变成角向分类 + 径向数值。

继续阅读[内置通道](/viz/plot/channel/builtin)可以看到样式通道如何落到 core 元素属性；阅读[比例尺](/viz/plot/scale)可以看到字段类型如何派生 scale；阅读[坐标系](/viz/plot/coordinate)可以看到位置通道如何被不同坐标系重解释。

## 技术原理

React 图元属性会在构建 `IRPlot` 时转成可序列化的通道配置。字段在内部表示为 `{ field: 'gdp' }`，常量表示为 `{ value: 80 }`。

下图把内置扁平样式 prop 的**构建期判定**和通道的**运行期取值**串在一起。编号表示候选优先级：字符串先匹配字段名，只有未命中时才检查合法常量；两者都不接受时警告并跳过，而不是继续处理数据行。

绑定类型一旦写入 Plot IR 就不再回退：字段绑定从 canonical row 解析逐行值，常量绑定直接读取自身的 `value`。两条路径最终都把已解析值交给支持该通道的图元。

字段名解析遵循和数据模型相同的规则：先检查整段字段名是不是数据行上的直接属性，再按 `.` 逐层查找。数据准备阶段会先应用 `fieldMap`、`format` 和 `resolveField`，再把规范化结果写回逻辑字段名；这些准备完成的数据行称为 canonical row。

不同图元只读取自己支持的通道。`PathMark` 可以使用 `x` / `y` / `order` / `series` / `color` / `strokeWidth` 生成折线；`PointMark` 则读取位置与节点样式。通道只描述“读哪个值”和“它控制什么视觉结果”，不会直接保存渲染结果。

| 写法                           | 内部含义                                                       |
| ------------------------------ | -------------------------------------------------------------- |
| `<PointMark x="gdp" />`        | `x` 是字段通道，读取 canonical 行里的 `gdp`                    |
| `<PointMark color="region" />` | `color` 是字段通道，会按字段类型派生颜色比例尺                 |
| `<ReferenceMark y={80} />`     | `y` 是常量通道，不读取数据行                                   |
| `<PathMark order="month" />`   | `order` 不在 `encoding` 对象里，但仍按字段读取，用于数据行排序 |

通道只回答“读哪个值”；至于值怎么映射成绘图空间、位置通道怎么被坐标系解释，交给比例尺和坐标系。
