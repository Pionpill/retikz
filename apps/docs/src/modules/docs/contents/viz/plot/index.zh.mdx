`@retikz/plot` 是 Viz 组的绘图语义层。它用可序列化的 Plot IR 描述字段绑定、比例尺、坐标系、图元、辅助元素与组合关系，再把这些高层语义下沉为 Kernel 能编译的 Core IR。

Plot 不拥有数据底座或渲染器：[Data](/viz/data)负责字段模型与通用数据处理，Kernel 负责编译、布局和 Scene，SVG / Canvas renderer 只消费 Scene。这样，React、Vanilla、手写 spec 或 AI 生成的配置都能复用同一份语义契约和 lowering 路径。

## 从声明到 Scene

1. **形成 Plot IR**：`<Plot>` 子组件、Vanilla `plot()` 与完整 `InputPlot` 最终都形成同一份 JSON-safe `IRPlot`。`InputPlot` 是 `@retikz/plot-vanilla` 的 TypeScript authoring 输入；React DSL 只是桥接入口，不拥有另一套图表语义。
2. **接入外部数据**：IR 通过 `data.reference` 指向运行时数据集。字段解析、通用变换与来源追溯由 Data 提供，数据行本身不进入 IR。
3. **解析绘图语义**：lowering 依次处理数据变换、通道绑定、比例尺和坐标投影，再由 mark 与 guide definition 生成可下沉结果。内置与自定义能力走同一套 registry、resolver 与 consumer 路径。
4. **下沉到 Core IR**：`lowerPlots` 作为 Tier 2 composite definition，把 Plot 节点展开为 `Scope`、`Node`、`Path` 等 Core IR；lineage、locator 和 diagnostics 作为运行时结果单独返回。
5. **编译与渲染**：Kernel 将 Core IR 编译为 renderer-agnostic Scene，随后由 SVG 或 Canvas renderer 输出。Plot 不绕开 Scene，也不实现平行渲染器。

## 三个包怎样分工

| 包                     | 拥有的职责                                                       | 典型入口                                                   |
| ---------------------- | ---------------------------------------------------------------- | ---------------------------------------------------------- |
| `@retikz/plot`         | `IRPlot*` schema、Definition / registry、领域解析与 lowering     | `PlotSchema`、`lowerPlots`                             |
| `@retikz/plot-react`   | React `XxxProps` / children 收集与 React 宿主接线                | `<Plot>`                                                   |
| `@retikz/plot-vanilla` | `InputPlot*` 类型、normalize、InputEmbed 接线、SSR 与无 DOM 渲染 | `plot()`、`normalizePlot()`、`embedPlot()`、`renderPlot()` |

三包共享 `@retikz/plot` 的 IR 与 lowering 真源。`@retikz/plot-vanilla` 是 framework-neutral 的 authoring owner：它拥有 TypeScript-only `InputPlot*`、`PlotSource` 与 `InputPlotEmbed`，把 `InputPlot` 的 `facets`、`scaffolds` 与 axis / topology binding 展开为 `IRPlot`，但不会对已类型化输入重复 schema 校验。只有 `IRPlot*` 是持久化 schema 类型；未知外部数据仍应通过 Plot schema 或 parser 进入 IR。

React 只负责收集 JSX / props 并调度 Plot Vanilla；它不维护平行的 Plot IR builder、schema parse 或 lowering。已经持有完整 `IRPlot` 时，可以直接交给运行时，无需再次套 authoring helper。

## Plot 负责与不负责什么

| Plot 负责                               | 交给其它模块                                                            |
| --------------------------------------- | ----------------------------------------------------------------------- |
| Plot IR、领域主题 token 与图形语法契约  | 字段模型、解析、通用变换与来源追溯交给 [Data](/viz/data)                |
| channel、scale、coordinate、mark、guide | Core IR、布局、引用解析与 Scene 编译交给 [Kernel](/kernel/introduction) |
| composition 与 Plot → Core lowering     | SVG / Canvas 输出交给 renderer                                          |
| Definition、registry、resolver 与诊断   | React / Vanilla 生命周期与宿主接线交给 adapter                          |
| 面向图表的语义映射与主题 lowering       | 行列结构、Cell 语义与表格布局交给独立的 [Table](/viz/table)             |

如果一种能力不依赖图表字段映射，例如通用数据变换、底层几何或表格 Cell，它就不应进入 Plot。反过来，新的 scale、coordinate、mark 或 guide 应先成为可注册的 Definition，再以内置能力使用同一条路径。

Plot 还拥有绘图区、guide 与 palette 的 canonical theme token。它消费 Core effective Theme 选择同名领域 preset，再把局部 `plotThemeTokens`、Axis `plotThemeTokenRules` 与原生 `plotTheme` 映射到同一 lowering 主链；完整 key 与优先级见[主题契约](/viz/plot/reference/theme)。内置与自定义 preset 都通过 `definePlotThemeStyle` / `plotThemeStyles` 走同一 resolver。
