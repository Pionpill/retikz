Visual channels in `encodings` bind fields; fixed visual values belong to `properties`. Positions use `{ field }`, `{ value }`, or `{ edge }`, with scales selected by coordinate roles. Supply consecutive roles: `x`, `x/y`, or `x/y/z`; z cannot appear without y.

Shared encodings describe positions, visual channels and host properties. Complete mark encodings combine them with mark-specific position and construction rules.

## LabelEncodingSchema

<ZodSchema name="LabelEncodingSchema" />

`encodings.label: 'name'` is shorthand for `{ text: 'name' }`, a field binding; `properties.label: 'Highlight'` is fixed text. Use an object for additional settings. Non-empty arrays can mix strings and objects, with one label per entry.

| Target                      | Encoding                                                     |
| --------------------------- | ------------------------------------------------------------ |
| `text`                      | Field name; fixed `displayFormat` controls formatting        |
| `font.size`, `font.weight`  | Field name or numeric `{ field, scale }` mapping             |
| `font.family`, `font.style` | Field name; reads the font family or style directly          |
| `textColor`, `opacity`      | Field name or explicit scale; opacity is a label-only scalar |
| Host attachment properties  | Field names with separate Node and Geometry constraints      |

Unencoded font leaves retain fixed settings and inheritance. Failed bindings do not fall back to fixed values. A style-only binding still creates data-driven Mark instances. Path labels use the first row of each actual segment, not one label per vertex.
