---
title: PathMark
description: 'PathMark is a one-dimensional trajectory made from ordered points; lines, closed paths, multi-series lines, and radar outlines are presentation forms of the same mark.'
---

`<PathMark>` produces one 1D trajectory from a set of data rows. It projects each row into a point, sorts the points by `order`, and lowers the result into a core `Path`. Under cartesian2D it is usually a line; under polar2D it can become a polar path or a radar outline.

`x` / `y` bind position channels, `order` decides connection order, `series` decides whether to split into multiple paths, `curve` decides how adjacent points connect, and `closure` decides whether the path closes by baseline or by cycle. PathMark currently supports cartesian2D and polar2D.

## Usage

```tsx
import { PathMark, Plot } from '@retikz/plot-react';
```

```tsx
<Plot data={revenue}>
  <PathMark x="month" y="revenue" order="month" />
</Plot>
```

Set `order` explicitly. Otherwise PathMark follows data array order, so a different row order changes the path shape.

### When to Use

PathMark is a low-level line mark: it only connects a set of ordered anchors into one 1D trajectory. It does not care whether the presentation layer calls that trajectory a line chart, trend line, outline, or radar outline; those are interpretations of the same PathMark.

The presentation form mainly changes through three groups of props: position channels decide where points come from, series channels decide how many paths are produced, and geometry props decide whether the path closes as a line or as a fillable area.

| Presentation form | Key props           | Behavior                                                                                                          |
| ----------------- | ------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Line              | `x` / `y` / `order` | Project each row into a point, then connect the points in order                                                   |
| Multi-series line | `series` / `color`  | Split rows by series first, then produce one path per group                                                       |
| Radar outline     | `polar2D`           | Polar paths close by default; set `closed={false}` for an open path                                               |
| Path area         | `closure` / `fill`  | Close the path by cycle, constant baseline, or per-row stacked baseline; set `fill` explicitly to fill the result |

When `transform` is placed on PathMark, only that path layer sees the changed rows. The point layer always keeps the original channel values; the path layer can fit one overall trend or use `groupBy` to fit one trend per channel. Switching the fit mode leaves the point layer unchanged.

### Close a Polar Path

`closed` connects the last point back to the first. Under `polar2D`, PathMark also closes by default when `closed` is omitted. The example keeps the left path closed and starts the right path open; toggle “Close right path” to compare the two connection results directly.

### Change Adjacent-Point Connections

`curve` controls how adjacent points connect. The left side uses cartesian2D and the right side uses polar2D; when you switch the connection type, both sides update together. Gray data points are shown by default so you can judge whether each curve passes through the original positions; turn off “Show data points” to inspect only the path outline. The polar plot does not set an inner radius, so PathMark projects angular and radial positions directly. Because `monotoneX` / `monotoneY` rely on monotonic projected screen x / y values, they fall back to `linear` under polar2D to avoid long control handles in closed areas.

<ComponentPreview files={['line-curve', 'line-curve.data.ts']} size="md" />

| Value        | Meaning                    | Behavior                                                                                                                   |
| ------------ | -------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `linear`     | Straight line              | Preserves the segment-by-segment relationship between neighboring points; useful when local changes should stay explicit   |
| `step`       | Midpoint step              | Switches the y value midway between two x positions; useful for state or inventory-like data                               |
| `stepBefore` | Before step                | Switches to the new value first, then moves along x; useful when a new value takes effect immediately                      |
| `stepAfter`  | After step                 | Keeps the old value until the next x position, then switches; useful when an old value remains valid until the next moment |
| `basis`      | Smooth spline              | Produces the softest curve, but does not guarantee passing through every middle point; useful for an overall trend         |
| `cardinal`   | Cardinal spline            | Passes through data points with a softer curve than straight lines, but local extrema may overshoot slightly               |
| `catmullRom` | Point-passing smooth curve | Passes through data points while preserving more local shape; useful as a general smooth line                              |
| `monotoneX`  | Monotone x                 | When x is monotonic, reduces y overshoot beyond neighboring extrema; prefer this for BI trend lines                        |
| `monotoneY`  | Monotone y                 | When y is monotonic, reduces x overshoot beyond neighboring extrema; useful for vertical trajectories                      |
| `natural`    | Natural spline             | Keeps the whole curve continuous with relaxed endpoints; useful when continuous curvature matters                          |

### Build Fillable Areas

`closure` only closes PathMark into a fillable path; it does not enable filling by itself. `stroke` is on by default, and `stroke="none"` removes the border line; `fill` is off by default, and a concrete color or paint enables filling. The left area effect is composed from two PathMark layers: one `baseline + fill + stroke="none"` layer for the area, and one normal path layer for the upper outline. The right side uses `cycle + fill` to fill a radar polygon. Use “Baseline value” to move the return edge of the left area; the cycle closure on the right is unaffected. “Horizontal padding” controls the distance between the first and last categories and the y axis, while “Vertical padding” controls extra space at both ends of the inferred value domain. Set both to `0` to make the area meet the y and x axes.

<ComponentPreview files={['line-closure', 'line-closure.data.ts']} size="md" />

When `baseline` is omitted, it follows the value axis: use 0 when 0 is inside the value-axis domain; if an explicit domain excludes 0, such as `[30, 80]`, use the nearest domain edge, 30. Pass `closure={{ kind: 'baseline', baseline: ... }}` when the lower edge should be pinned to another value.

For stacked areas, bind the upper boundary to `y` and pass the lower boundary field as `closure.baselineField`. The data can come from a stack transform or from precomputed `y0` / `y1` fields. The example uses the same fill-layer plus outline-layer composition for the area-chart effect. When `curve` is set, both boundaries use the same connection mode.

<ComponentPreview files={['line-stack-area', 'line-stack-area.data.ts']} size="md" />

### Preserve Data Gaps

When a row cannot project into a valid point, PathMark breaks there by default and lowers the surrounding runs into separate core `Path` elements. If the path also has `closure` and `fill`, the fill follows the same segments instead of spanning across the missing gap.

In this example, `Yasin` has no 2019 value, so both the outline and the filled area stop between 2018 and 2020. Set `connectNulls` explicitly when a chart should connect across gaps.

## How it works

<ComponentAlert
  type="tip"
  title="You can skip this section at first"
  description="Return when debugging series splitting, missing-value breaks, polar closure defaults, or anchorId output."
/>

`<PathMark>` is dispatched from `PlotSpec` through the mark registry to path lowering. It accepts cartesian2D and polar2D only because those frames provide an ordered trajectory for the required position roles; unsupported frames fail loudly.

| Stage               | Observable behavior                                                                                                                                    |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Order and group     | Rows split by `series` and then sort by `order`; without `series`, a categorical `color` field can split implicit series                               |
| Project and segment | Each row projects to a point; invalid points break the trajectory unless `connectNulls` is enabled                                                     |
| Connect and close   | `curve` controls adjacent segments; `closed` joins last to first, while `closure` creates cycle, baseline, or stack boundaries                         |
| Lower               | Every continuous segment becomes a core `Path`; series form child layers, and `anchorId` additionally creates referenceable core `Coordinate` vertices |

Series child layers preserve the same semantic grouping across renderers; missing values can further split each series into one or more continuous Path segments.

`fill` only paints an existing closed boundary; it does not close an open path. When missing values create multiple continuous segments, each segment closes and fills independently instead of spanning the gap.
