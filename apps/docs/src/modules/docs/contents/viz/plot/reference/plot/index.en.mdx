`PlotSchema` is the root contract for the Plot Tier 2 composite. It references an external dataset and declares transforms, scales, coordinates, marks, and guides; lowering expands the result into Kernel IR.

## PlotSchema

<ZodSchema name="PlotSchema" />

Plot describes the drawing body and its Axis, Legend, Facet, mark, reference, and annotation text. Complete-chart titles, notes, and sources belong to Chart presentation, which composes them with the Plot body through Standard. The removed top-level `layout` and `labels` fields are rejected strictly.

Exactly one of `coordinate` and `composition` must be present. Scale names, view ids, and arrangement ids must be unique within one Plot; every `coordinateView` referenced by a mark or axis must already be registered.

Theme inputs resolve in this order: the Plot preset and Axis rules selected by the Core effective Theme → Chart-forwarded defaults → local `defaultPlot` and `plotRules` → local guide / mark / scale configuration. See the [theme contract](/viz/plot/reference/theme) for the Source-shaped defaults and cascade.

## PlotDataExecutionSchema

<ZodSchema name="PlotDataExecutionSchema" />

`dataExecution` accepts one shared policy or a `{ root, marks }` object. `root` applies to the root transform pipeline; `marks` applies to every mark-local pipeline, including marks in facets. Both groups are required and may be empty objects. Top-level `mode` / `external` cannot be mixed with the groups.

```json
{
  "dataExecution": {
    "root": { "mode": "hybrid", "external": "sql" },
    "marks": { "mode": "builtin" }
  }
}
```

Neither group inherits from the other. Each declaration overrides its selected group; omitted fields inherit executor defaults, with builtin as the final mode default. The shared form `{ mode: 'hybrid', external: 'sql' }` applies to both groups. React root props, Vanilla inputs and IR use the same structure. See the [runtime contract](/viz/plot/reference/runtime) for entry-point restrictions.
