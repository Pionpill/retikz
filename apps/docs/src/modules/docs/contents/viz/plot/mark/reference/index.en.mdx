---
title: ReferenceMark
description: 'ReferenceMark expresses reference constraints: constant or field values expanded into lines, one-axis bands, or coordinate regions.'
---

`<ReferenceMark>` declares a reference constraint in data space. By default, bind `y` for a horizontal reference and bind `x` for a vertical reference; a lower bound alone becomes a line, while `xTo` / `yTo` turns it into a one-axis band. Set `kind="region"` and ReferenceMark uses `x` / `xTo` plus `y` / `yTo` to build a bounded 2D region. A number is a constant; a field value in `ReferenceMarkProps` is read per row and produces one reference per row. The corresponding Vanilla field-name TypeScript type is `InputPlotFieldName`.

It joins the same draw order as `<PointMark>` / `<IntervalMark>`, but it does not start from point, line, or interval dimensions. It first fixes one axis value, then expands along the opposite axis domain.

## Usage

```tsx
import { Plot, ReferenceMark } from '@retikz/plot-react';
```

```tsx
<Plot data={scores}>
  <ReferenceMark y={60} color="crimson" />
  <ReferenceMark y={60} yTo={80} color="#fde68a" />
</Plot>
```

For the default line / band form, exactly one of `x` / `y` is required. `xTo` only pairs with `x`, and `yTo` only pairs with `y`; partial spans along the opposite axis use `extentField` / `extentToField` together. The region form must explicitly set `kind="region"` and provide both `x` / `xTo` and `y` / `yTo`.

### When to Use

ReferenceMark is a low-level reference mark: it turns one fixed axis value into a line, a one-axis interval into a band, or two axis intervals into a region. What the presentation layer calls a threshold line, tolerance band, reference ring, sector wedge, or highlighted range is not a different mark; it is the same ReferenceMark under different coordinate and bound settings.

The bound axis decides orientation, and the optional upper bound decides the form:

| Presentation form         | Key props                                   | Description                                         |
| ------------------------- | ------------------------------------------- | --------------------------------------------------- |
| Horizontal reference line | `y`                                         | Fixed y value, spanning the x domain                |
| Vertical reference line   | `x`                                         | Fixed x value, spanning the y domain                |
| Horizontal reference band | `y` / `yTo`                                 | Fixed y interval, filling `y∈[y,yTo]`               |
| Vertical reference band   | `x` / `xTo`                                 | Fixed x interval, filling `x∈[x,xTo]`               |
| Bounded 2D region         | `kind="region"` + `x` / `xTo` / `y` / `yTo` | Fixed x and y intervals, filling their intersection |

Under `polar2D`, the coordinate system reinterprets the same props: `y` is a constant-radius reference ring, `y` / `yTo` is an annular band, `x` is a radial reference line, `x` / `xTo` is a sector wedge, and `kind="region"` constrains both angle and radius to form an annular sector.

## Examples

All five examples can switch between Cartesian and polar coordinates from the Coordinate System section. The ReferenceMark bounds stay unchanged; the coordinate system reprojects the same axis value or interval into a line, ring, band, or sector.

### Basic Reference Line

A single constant `x` or `y` produces one reference line across the opposite axis domain. Switch the Reference Axis to compare horizontal and vertical lines, then switch to polar coordinates to see the same configurations become a ring or radial line.

### Reference Band

Add an upper bound on the same axis and ReferenceMark turns from a line into a filled band. Under polar coordinates, `y` / `yTo` becomes an annular band while `x` / `xTo` becomes a sector wedge. Bands are usually declared before data marks.

<ComponentPreview files={['rule-band', 'rule-threshold.data.ts']} size="lg" />

`xTo` mirrors `yTo`: with `x` bound, use `xTo` for a vertical band. The upper bound must match the bound axis, otherwise construction or lowering throws.

### Two-Dimensional Reference Region

`kind="region"` turns ReferenceMark from a one-axis constraint into a coordinate cell region. In cartesian coordinates it draws a rectangle; under polar coordinates the same `x` / `xTo` / `y` / `yTo` pair becomes an angle interval plus a radius interval, producing an annular sector.

<ComponentPreview files={['rule-region', 'rule-region.data.ts']} size="lg" />

### Per-Row References

`y="threshold"` is a field axis value, so each data row produces one reference line. In that form, `color="tier"` is interpreted as a color field and grouped by category.

<ComponentPreview files={['rule-per-datum', 'rule-per-datum.data.ts']} size="lg" />

In React authoring, the lower `x` / `y` binding decides how a color string is interpreted: a numeric lower bound makes it a constant color, while a field lower bound makes it a color field. Even when a field upper bound or extent makes the reference run per row, `color` remains constant if the lower bound is numeric.

### Partial References

Lines and bands span the full opposite-axis domain by default. Add `extentField` / `extentToField` and each row can read the start and end of that opposite role from two fields, shortening the constraint into a partial line or band. The two props must be set together.

<ComponentPreview files={['rule-extent', 'rule-extent.data.ts']} size="lg" />

An extent changes only the coverage along the opposite axis; it does not change the reference-axis value bound by `x` / `y`. Under `polar2D`, that opposite role becomes the corresponding angular or radial span.

## How it works

<ComponentAlert
  type="tip"
  title="You can skip this section at first"
  description="Return when debugging line, band, or region inference, constant versus per-row output, or coordinate support."
/>

`<ReferenceMark>` validates bound combinations before entering `IRPlotSpec`; invalid configurations are not guessed silently. Lowering then distinguishes line, band, and region geometry from the lower bounds, upper bounds, and `kind`.

The figure keeps to the ReferenceMark responsibility boundary and shows its two lowering paths: a line produces path steps directly, while a band or region first forms a logical Cell and asks the coordinate frame to project it.

<ComponentPreview files="reference-lowering-flow" hideCode size="sm" />

Classification also decides iteration: all-constant bounds without an extent produce one primitive; a field position, upper bound, or extent runs per row. Both paths stop at the generated core primitive rather than repeating the full Scene compilation pipeline.

| Stage       | Observable behavior                                                                                                                           |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| Validate    | The default form binds exactly one of `x` / `y`; upper bounds pair with the same role; region supplies every bound required by the coordinate |
| Choose rows | A fully constant reference creates one geometry; field-driven positions, upper bounds, or extents produce geometry for each valid row         |
| Project     | Lines become core `Path` objects under cartesian2D / polar2D; bands and regions use `projectCell` to create fillable core `Node` objects      |
| Decorate    | Lines use Path styling and geometry labels; bands / regions use Node styling and node labels; field colors group per datum                    |

A completely constant reference cannot bind color to a field because there is no datum to read. Use a constant color, or bind the reference position to a field.

## API Reference

This table keeps only ReferenceMark-specific props and props whose meaning is redefined here. See [channel bindings](/viz/plot/channel/binding) for field and constant inputs, [transforms](/viz/plot/transform) for local `transform` and layer props, and [coordinates](/viz/plot/coordinate) for coordinate-view props. Lines follow shared [Path styling](/kernel/components/draw/path#styling), while bands and regions follow shared [Node styling](/kernel/components/node/overview#visual-style-api).

| Prop                              | Type                                   | Default              | Description                                                                                                                   |
| --------------------------------- | -------------------------------------- | -------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `x?` / `y?`                       | `ReferenceMarkProps['x']`              | —                    | Reference-axis value for the default form; set exactly one. Numbers are constant, fields produce one reference per row        |
| `xTo?` / `yTo?`                   | `ReferenceMarkProps['xTo']`            | —                    | Upper bound paired with the same lower-bound role; turns a line into a band                                                   |
| `kind?`                           | <ApiValues name="ReferenceMarkKind" /> | —                    | Set `region` to build an area from bounds on multiple roles                                                                   |
| `extentField?` / `extentToField?` | `ReferenceMarkProps['extentField']`    | Full opposite domain | Per-row start and end that shorten a line / band along the opposite role; set them together                                   |
| `color?`                          | `string`                               | Default layer color  | A numeric lower `x` / `y` sets color directly; a field lower bound interprets the string as a per-row color field             |
| `label?`                          | `ReferenceMarkProps['label']`          | —                    | Lowers to a geometry label for lines and a node label for bands / regions; content lives in `content.field` / `content.value` |
