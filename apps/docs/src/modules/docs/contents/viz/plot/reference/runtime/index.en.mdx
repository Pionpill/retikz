title: Runtime Overview
description: Query how React, Vanilla, and direct Plot IR converge on one lowering path that produces Scene, rendered output, and separate runtime artifacts through Core.
---

The Plot runtime separates how a chart is authored from how it executes. React, Vanilla, or generated tools first produce the same `IRPlot`; datasets and function-bearing Definitions are injected at execution time; then `@retikz/plot` lowers high-level chart semantics to Core IR. Core compiles the Scene, and renderers consume only the Scene.

> This page explains the overall runtime contract rather than repeating schema fields. Use the contract pages in this group for JSON shapes, and see [Design Principles](/kernel/concepts/design/principles) for the complete Kernel compilation boundary.

## Hosts and Package Boundaries

<ComponentPreview files="plot-runtime-architecture" size="xs" hideCode />

React and Vanilla provide different authoring and host wiring without duplicating Plot algorithms. Standalone `<Plot>` bridges its `XxxProps` / children to a Plot Vanilla `InputPlotEmbed` and hands it to the same `PlotInputEmbedAdapter`; `embedPlot()` creates an `InputEmbed` for Vanilla `scene()`, and `PlotInputEmbedAdapter` performs the `InputPlot -> IRPlot` normalization and lowering. `renderPlot()` remains the independent DOM-free SSR and lineage entry.

`<Plot theme>` is the local Core Scope Theme around the Plot panel: standalone and embedded paths both wrap the Plot node in that Scope, so it only overrides that Plot's `style`, `mode`, and namespaced `tokens`. It is distinct from the Plot-spec fields `plotThemeTokens` and `plotTheme`, which are Plot-owned visual inputs. Vanilla `renderPlot(spec, data, { theme })` instead writes `theme` to the root `IRScene.theme`, making it the Core Theme for the entire compiled Scene; it does not rewrite `spec.plotThemeTokens` or `spec.plotTheme`.

All three entries delegate data, scale, coordinate, mark, and guide semantics to `@retikz/plot`, then return Core IR to the shared compilation path. SVG, Canvas, and SVG strings are output forms; SSR is a host scenario supported by Vanilla, not a separate Plot semantics path.

## Authoring and Runtime Boundary

<ComponentPreview files="plot-authoring-convergence" size="md" hideCode />

The React DSL only collects JSX / props and dispatches Plot Vanilla, while Vanilla's `plot()` accepts an `InputPlot` plain object. Both use `@retikz/plot-vanilla` to expand axis, facet, and scaffold bindings into the same `IRPlot`. Typed authoring input is not schema-parsed again; only `IRPlot*` values use Plot schemas, while configuration from JSON, files, or another unknown boundary must enter IR through `PlotSchema` or a parser.

For a Vanilla runtime source, `{ input }` runs `normalizePlot` exactly once. `{ spec }` is already an `IRPlot`: the runtime preserves its object identity and bypasses normalization. Unknown JSON must be parsed with the Plot schema or another parser before it is supplied as `spec`; runtime entry points do not treat untyped JSON as IR.

`IRPlot` stores only JSON-safe grammar and `data.reference`. Actual rows, field resolvers, label functions, and custom transform, scale, channel, coordinate, or mark Definitions are runtime inputs. They meet the IR at execution, but are never written back into it.

| Input layer          | Typical entry                                                        | Enters `IRPlot`                                                                                    |
| -------------------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| React DSL            | `<Plot>` plus mark, guide, and scale children                        | After shared normalization                                                                             |
| React spec           | `<Plot spec={...} data={...}>`                                       | The `spec` does                                                                                        |
| Vanilla              | `plot(InputPlot)`, `{ input: InputPlot }`, or `{ spec: IRPlot }` | InputPlot forms normalize once; `spec` enters directly; unknown JSON requires Plot schema/parser first |
| Runtime dependencies | datasets, field maps, resolvers, and Definitions                     | No                                                                                                     |

## Lowering and Outputs

<ComponentPreview files="plot-lowering-flow" size="sm" hideCode />

The main lowering path resolves transform, statistics, row-selector, scale, mark, and format registries inside `prepareRows()`, then normalizes data from the data model, field maps, and resolver. It next applies transforms, resolves the frame, and builds the channel registry. Channel and mark Definitions produce primitives; guides, themes, composition, and layout add explanatory and spatial structure. The result expands into Core `Scope`, `Node`, and `Path` IR.

`lowerPlots()` returns the Definition consumed by Core composite compilation. It does not create DOM and does not select a renderer. `compileToScene()` consumes the lowered Core IR and produces a Scene; React `<Layout>` or a Vanilla renderer then chooses SVG, Canvas, or string output.

Lineage and location are independent recomputation paths over shared inputs, not sidecars emitted directly by the main lowering path. `lowerPlotWithLineage()` returns Core IR children with a `PlotLineageRun`, while `createPlotLocator()` reuses data preparation and frame resolution to calculate datum and series anchors. Both accept the same spec, datasets, and lowering configuration without writing a complete runtime record into `IRPlot` or Scene metadata. See [Plot Lineage](/viz/data/provenance/plot) for its options and data boundary.

## Entries and Results

| Scenario            | Entry                                               | Primary result                                        |
| ------------------- | --------------------------------------------------- | ----------------------------------------------------- |
| React standalone    | `<Plot>`                                            | SVG / Canvas managed by `<Layout>`                    |
| React embedded      | `<Layout><Plot /></Layout>`                         | Scene compiled with other Tier 2 IR                   |
| Vanilla embedded    | `embedPlot()` plus `PlotInputEmbedAdapter`          | Scene inside a Kernel Input Scene / layer             |
| Vanilla / SSR       | `renderPlot(spec, datasets, { theme, ...options })` | SVG string or `{ svg, lineage }` under the root Theme |
| Custom host         | `lowerPlots(datasets, options)` plus Core compile   | Core IR → Scene                                       |
| Audit / interaction | `lowerPlotWithLineage()` and `createPlotLocator()`  | Runtime-only lineage / anchor                         |
