---
title: PlotAxis
description: Use <PlotAxis> to explain positional scales with lines, ticks, labels, and grids under Cartesian or polar coordinates.
---

`<PlotAxis>` is the visual counterpart of a positional scale. `dimension` selects the coordinate dimension to explain: Cartesian uses `x` / `y`, while polar uses `x` (angular) / `y` (radial). A dimension that does not belong to the current coordinate system fails loudly.

`<Plot>` does not add axes automatically. Declare one `<PlotAxis>` for every axis you need. The line, ticks, tick labels, title, and grid are configuration slots on that same PlotAxis guide.

Import the components from `@retikz/plot-react` and declare guides alongside the mark.

```tsx
import { Plot, PlotAxis, PlotScale, PointMark } from '@retikz/plot-react';
import { createRoot } from 'react-dom/client';

const rows = [
  { gdp: 400, life: 76, region: 'A' },
  { gdp: 900, life: 81, region: 'B' },
  { gdp: 1600, life: 84, region: 'A' },
];

createRoot(document.getElementById('plot')!).render(
  <Plot data={rows} width={360} height={220}>
    <PlotScale dimension="x" type="linear" domainPadding={{ kind: 'ratio', lower: 0.15, upper: 0.15 }} />
    <PlotScale dimension="y" type="linear" domainPadding={{ kind: 'ratio', lower: 0.15, upper: 0.15 }} />
    <PointMark encodings={{ position: { x: { field: 'gdp' }, y: { field: 'life' } } }} properties={{ size: 6 }} />
    <PlotAxis dimension="x" />
    <PlotAxis dimension="y" grid />
  </Plot>,
);
```

Import the configuration type from `@retikz/plot` and pass the IR to the React `Plot` through `spec`.

```tsx
import { Plot } from '@retikz/plot-react';
import type { IRPlot } from '@retikz/plot';
import { createRoot } from 'react-dom/client';

const rows = [
  { gdp: 400, life: 76, region: 'A' },
  { gdp: 900, life: 81, region: 'B' },
  { gdp: 1600, life: 84, region: 'A' },
];

const spec: IRPlot = {
  namespace: 'plot',
  type: 'plot',
  data: { reference: 'rows' },
  scales: [
    { type: 'linear', name: 'x', domainPadding: { kind: 'ratio', lower: 0.15, upper: 0.15 } },
    { type: 'linear', name: 'y', domainPadding: { kind: 'ratio', lower: 0.15, upper: 0.15 } },
  ],
  coordinate: { type: 'cartesian2D', x: 'x', y: 'y' },
  marks: [
    { type: 'point', encodings: { position: { x: { field: 'gdp' }, y: { field: 'life' } } }, properties: { size: 6 } },
  ],
  guides: [
    { type: 'axis', dimension: 'x' },
    { type: 'axis', dimension: 'y', grid: true },
  ],
};

createRoot(document.getElementById('plot')!).render(<Plot spec={spec} data={{ rows }} width={360} height={220} />);
```

## Basic usage

### Coordinate system and axis roles

Start with the same data and the same `<PathMark>`. When switching between `cartesian2D` and `polar2D`, `dimension="x"` explains horizontal or angular position, while `dimension="y"` explains vertical or radial position. A `grid` still belongs to the PlotAxis that creates it.

With discrete angular categories, polar coordinates use chord connections by default, producing polygonal equal-value grids. The radial axis, ticks and labels use the same projection, so ticks align with the polygon edges rather than extending to a circumscribed circle. Explicit `interpolation: 'polar'` keeps circular projection.

## Extended usage

### Ticks, labels and origin axes

After the basic roles are clear, tune the complete configuration in a Cartesian coordinate system. The continuous scenes cover `ticks.interval`, `ticks.density`, and independent major / minor grid sources. The categorical scene isolates rotation, hiding, and boundary handling under `tickLabels.layout`.

Label margins and collision handling use Core text layout, including font family, weight, wrapping, and line height. A host measurer supplied through `CompileOptions.measureText` serves both Plot layout and final text rendering; without one, Core's default measurement applies. Polar angular-label radius reserves and legend text spacing use the same measurement path.

Explicit `em` sizes on axis and legend labels inherit the enclosing font size. For example, with an enclosing size of `16`, `1.5em` is measured and rendered at `24`; Plot does not introduce a separate relative-size baseline.

In the origin scene, both axes use `placement.kind="origin"` to cross the other dimension at 0. Placement does not expand the domain; `crossing` controls the intersection label, while `line.arrow` and `ticks.endpoint` control endpoint arrows and nearby tick avoidance.

## Errors and limitations

The dimension must belong to the current coordinate system. Cartesian origin placement and endpoint arrows should not be applied to polar axes. Origin placement does not expand the scale domain; the crossing value must lie in the visible range.

### Tick and grid sources

PlotAxis creates candidate ticks with the priority `ticks.values > ticks.interval > ticks.count`, then applies `density` to obtain visible ticks. The grid reuses those results unless `grid.ticks` requests a separate candidate source, so its density can remain independent from axis labels. `grid.includeDomain` appends missing effective scale-domain endpoints after that resolution and deduplicates them by final projected coordinate; it does not change axis ticks or automatically add endpoints to the minor grid. Its guide-local default is `false`, while Theme may provide a default for an enabled major grid: the unstyled default baseline uses `true` for x/y axes and the site's three injected reference styles use `false`. The Theme endpoint token does not enable a grid by itself, and an explicit guide boolean wins last. Minor-grid positions still come from `grid.minor.ticks`, then drop positions that overlap the major grid.

### Semantic layers

Axes sit above marks by default, while grids stay below them. `layer={{ zIndex }}` overrides only the axis scope; grid always uses its separate background layer so lines do not cover the data. The default order is grid `-300`, marks `0`, axis `200`, facet labels `300`, and legend `500`.
