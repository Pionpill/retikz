---
title: Axis
description: Use <Axis> to explain positional scales with lines, ticks, labels, and grids under Cartesian or polar coordinates.
---

`<Axis>` is the visual counterpart of a positional scale. `dimension` selects the coordinate dimension to explain: Cartesian uses `x` / `y`, while polar uses `x` (angular) / `y` (radial). A dimension that does not belong to the current coordinate system fails loudly.

`<Plot>` does not add axes automatically. Declare one `<Axis>` for every axis you need. The line, ticks, tick labels, title, and grid are configuration slots on that same Axis guide.

## Usage

```tsx
import { Axis, PathMark, Plot } from '@retikz/plot-react';
```

```tsx
<Plot data={rows}>
  <PathMark x="month" y="revenue" order="month" />
  <Axis dimension="x" />
  <Axis dimension="y" grid />
</Plot>
```

## Examples

### Coordinate system and axis roles

Start with the same data and the same `<PathMark>`. When switching between `cartesian2D` and `polar2D`, `dimension="x"` explains horizontal or angular position, while `dimension="y"` explains vertical or radial position. A `grid` still belongs to the Axis that creates it.

### Cartesian Axis playground

After the basic roles are clear, tune the complete configuration in a Cartesian coordinate system. The continuous scenes cover `ticks.interval`, `ticks.density`, `ticks.mark`, and independent major / minor grid sources. The categorical scene isolates rotation, hiding, and boundary handling under `tickLabels.layout`.

In the origin scene, both axes use `placement.kind="origin"` to cross the other dimension at 0. Placement does not expand the domain; `crossing` controls the intersection label, while `line.arrow` and `ticks.endpoint` control endpoint arrows and nearby tick avoidance.

## How it works

<ComponentAlert
  type="tip"
  title="Learn the API before the generation order"
  description="For everyday configuration, the examples and API table above are enough. This section explains why tick, grid, and semantic layer controls remain independent."
/>

### Tick and grid sources

Axis creates candidate ticks with the priority `ticks.values > ticks.interval > ticks.count`, then applies `density` to obtain visible ticks. The grid reuses those results unless `grid.ticks` requests a separate candidate source, so its density can remain independent from axis labels. `grid.includeDomain` appends missing effective scale-domain endpoints after that resolution and deduplicates them by final projected coordinate; it does not change axis ticks or automatically add endpoints to the minor grid. Its guide-local default is `false`, while Theme may provide a default for an enabled major grid: the unstyled default baseline uses `true` for x/y axes and the site's three injected reference styles use `false`. The Theme endpoint token does not enable a grid by itself, and an explicit guide boolean wins last. Minor-grid positions still come from `grid.minor.ticks`, then drop positions that overlap the major grid.

### Semantic layers

Axes sit above marks by default, while grids stay below them. `layer={{ zIndex }}` overrides only the axis scope; grid always uses its separate background layer so lines do not cover the data. The default order is grid `-300`, marks `0`, axis `200`, facet labels `300`, and legend `500`.

## API Reference

| Prop          | Type                      | Default       | Description                                                                                                                                    |
| ------------- | ------------------------- | ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `dimension`   | `AxisProps['dimension']`  | —             | Dimension to explain: Cartesian / polar use x / y; it must belong to the current coordinate system                                             |
| `scale?`      | `PositionScaleType`       | auto-derived  | Positional scale shortcut; equivalent to `<Scale dimension="..." type="..." />` for the same dimension                                         |
| `placement?`  | `AxisProps['placement']`  | inferred      | Baseline placement; branch `kind` values are listed by <ApiValues name="AxisPlacementKind" />; `origin` only applies to Cartesian axes         |
| `line?`       | `AxisProps['line']`       | default line  | Axis-line style and endpoint geometry; `extent` and `arrow` currently apply only to Cartesian axes                                             |
| `crossing?`   | `AxisProps['crossing']`   | normal ticks  | Tick / label policy at a crossing value; `label:'corner'` can move a shared origin label to a corner                                           |
| `ticks?`      | `AxisProps['ticks']`      | default ticks | Candidate source, visible density, endpoint avoidance, and tick-marker appearance                                                              |
| `tickLabels?` | `AxisProps['tickLabels']` | `true`        | Tick-label visibility, format, and style; explicit `rotate` wins over `layout.rotate`, and `layout:false` disables adaptive collision handling |
| `title?`      | `AxisProps['title']`      | —             | Axis-title content, spacing, placement along the axis, orientation, and local offset                                                           |
| `grid?`       | `AxisProps['grid']`       | `false`       | Grid visibility, style, and independent tick source; `minor` adds minor lines, while `applyTo/select` targets composition or facet views       |
| `layer?`      | `AxisProps['layer']`      | axis layer    | Override the semantic layer of the axis scope without changing the grid's background layer                                                     |
| `id?`         | `AxisProps['id']`         | —             | Optional guide handle used to identify the axis and its derived grid consistently                                                              |

### Key object fields

| Object field         | Type                                                | Default                     | Purpose                                                                                                                |
| -------------------- | --------------------------------------------------- | --------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `placement.kind`     | <ApiValues name="AxisPlacementKind" />              | inferred                    | Select automatic, cardinal-side, coordinate-native-edge, or Cartesian-origin placement                                 |
| `placement.side`     | `'top' \| 'right' \| 'bottom' \| 'left'`            | —                           | Required cardinal side for `kind:'side'`                                                                               |
| `placement.edge`     | `string`                                            | —                           | Required coordinate-native edge id for `kind:'edge'`                                                                   |
| `placement.origin`   | `string \| number`                                  | `0`                         | Cross-dimension data value for `kind:'origin'`                                                                         |
| `ticks.values`       | `Array<string \| number>`                           | —                           | Explicit candidates; higher priority than `interval` and `count`                                                       |
| `ticks.interval`     | `{ kind:'number' \| 'time' \| 'category'; ... }`    | —                           | Fixed numeric step, UTC time unit, or category-index stride                                                            |
| `ticks.count`        | `number`                                            | scale default               | Target candidate count when `values` and `interval` are absent                                                         |
| `ticks.density`      | `{ kind:'all' \| 'sample'; ... }`                   | all candidates              | The sample branch thins visible ticks by `maxCount` or `minGap`                                                        |
| `ticks.mark`         | `false \| { kind; ... }`                            | line mark                   | Select a line, built-in shape, or custom mark; do not combine it with `ticks.length` / `ticks.line`                    |
| `ticks.endpoint`     | `false \| { hideWhenArrow?; distance?; affect? }`   | avoid arrow endpoints       | Hide tick marks near endpoint arrows; `affect` can hide labels too                                                     |
| `tickLabels.format`  | `string`                                            | automatic format            | d3-format for numbers or UTC d3-time-format for temporal ticks                                                         |
| `tickLabels.rotate`  | `number`                                            | adaptive                    | Fixed rotation angle; an explicit value wins over `layout.rotate`                                                      |
| `tickLabels.layout`  | `false \| { rotate?; hide?; bounds?; sampleSize? }` | adaptive layout             | Control auto rotation, overlap hiding, and axis-span boundary handling                                                 |
| `grid.ticks`         | `{ values?; interval?; count? }`                    | visible axis ticks          | Give the major grid an independent candidate source                                                                    |
| `grid.density`       | `{ kind:'all' \| 'sample'; ... }`                   | all grid candidates         | Thin grid positions without changing axis ticks                                                                        |
| `grid.includeDomain` | `boolean`                                           | `false`; Theme may override | Append missing effective-domain endpoints after major-grid source and density resolution; an explicit local value wins |
| `grid.minor`         | `false \| { ticks; density?; bandPosition?; ... }`  | `false`                     | Generate minor lines from a separate source and remove positions overlapping the major grid                            |
| `grid.applyTo`       | `'local' \| 'all' \| 'none' \| 'selected'`          | composition policy          | Project the grid to the current, shared, or explicitly selected targets                                                |
| `grid.select`        | `{ view?; facet?; track? }`                         | —                           | Required with `applyTo:'selected'`; matches view, facet, or track targets                                              |

`coordinateView`, `facetId`, `scaffoldId`, and `trackId` are advanced fields used by composition and facet flows to locate axis ownership. Ordinary single plots do not need them; see [coordinate composition](/viz/plot/coordinate/composition) when building composed axes.

Visual styling belongs to `line`, `ticks`, `tickLabels`, `title`, and `grid`. For example, `dashPattern` / `dashOffset` configure dashed lines, while text styles stay on their respective text slots; no separate styling component is needed.
