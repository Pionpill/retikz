Plot 运行时把“怎样声明图”和“怎样执行图”分开：React、Vanilla 或生成式工具先形成同一份 `IRPlotSpec`，datasets 与带函数的 Definition 在执行时注入，`@retikz/plot` 再把高层图表语义下沉为 Core IR。Core 负责编译 Scene，renderer 只消费 Scene。

> 这里解释整体运行契约，不重复 schema 字段。JSON 形状请查本组的契约页；完整 Kernel 编译边界见[设计原则](/kernel/concepts/design/principles)。

## 宿主与包边界

<ComponentPreview files="plot-runtime-architecture" size="xs" hideCode />

React 与 Vanilla 提供不同的 authoring 和宿主接线，但不复制 Plot 算法。Standalone `<Plot>` 把规格收集为 React Input Scene，并交给同一份 `PlotInputEmbedAdapter`；`embedPlot()` 创建可放入 Vanilla `scene()` 的 InputEmbed，配合 `PlotInputEmbedAdapter` 完成归一与下沉。`renderPlot()` 则保留为独立的无 DOM SSR 与 lineage 入口。

`<Plot theme>` 是 Plot 面板所在 Core Scope 的局部 Theme：standalone 与 embedded 都把它包在 Plot node 外层，因此只覆盖该 Plot 的 `style`、`mode` 与 namespaced `tokens`。它不同于 Plot spec 内的 `plotThemeTokens` / `plotTheme`，后两者是 Plot owner 的视觉字段。Vanilla `renderPlot(spec, data, { theme })` 则把 `theme` 写入根 `IRScene.theme`，作为整个编译 Scene 的 Core Theme；它不会改写 `spec.plotThemeTokens` 或 `spec.plotTheme`。

三条入口最终都委托 `@retikz/plot` 解析数据、比例尺、坐标系、图元与辅助，再把 Core IR 交还统一编译链。SVG、Canvas 与 SVG 字符串是输出形态；SSR 是 Vanilla 可运行的宿主场景，不是另一套 Plot 语义。

## 声明与运行时边界

<ComponentPreview files="plot-authoring-convergence" size="md" hideCode />

React DSL 只收集 JSX / props 并调度 Plot Vanilla；Vanilla 的 `plot()` 接收 plain object。两者都由 `@retikz/plot-vanilla` 展开 axis、facet 与 scaffold binding，形成同一份 `IRPlotSpec`。已类型化的 authoring 输入不会重复 schema 校验；来自 JSON、文件或其它未知边界的配置应先通过 `PlotSpecSchema` 或 parser 进入 IR。

`IRPlotSpec` 只保存 JSON-safe 语法与 `data.reference`。真实数据行、字段 resolver、label 函数以及自定义 transform、scale、channel、coordinate、mark 等 Definition 属于运行时输入；它们与 IR 在执行节点汇合，但不会被写回 IR。

| 输入层     | 典型入口                                         | 进入 `IRPlotSpec`      |
| ---------- | ------------------------------------------------ | ---------------------- |
| React DSL  | `<Plot>`、mark / guide / scale 子组件            | 共享规范化后进入       |
| React spec | `<Plot spec={...} data={...}>`                   | `spec` 进入            |
| Vanilla    | `plot({...})`、完整 `InputPlot`                  | 共享规范化或校验后进入 |
| 运行时依赖 | datasets、field maps、resolver、各类 Definitions | 不进入                 |

## Lowering 与产物

<ComponentPreview files="plot-lowering-flow" size="sm" hideCode />

主 lowering 在 `prepareRows()` 内解析 transform、statistics、row selector、scale、mark 与 format registry，并按 data model、field map 和 resolver 归一化数据。随后执行 transform、解析 frame 并建立 channel registry；channel 与 mark Definition 生成图元，guide、theme、composition 与 layout 补齐辅助和空间关系，最终展开为 `Scope`、`Node`、`Path` 等 Core IR。

`lowerPlots()` 返回供 Core composite 编译使用的 Definition；它不直接创建 DOM，也不直接选择 renderer。`compileToScene()` 消费下沉后的 Core IR 并产生 Scene，React `<Layout>` 或 Vanilla renderer 再决定 SVG、Canvas 或字符串输出。

溯源与定位是基于共享输入的独立重算路径，而不是主 lowering 直接吐出的旁路产物：`lowerPlotWithLineage()` 返回 Core IR children 与 `PlotLineageRun`，`createPlotLocator()` 复用数据准备与 frame 解析来计算 datum / series anchor。它们接收同一份 spec、datasets 与 lowering 配置，但不会把整份运行记录写进 `IRPlotSpec` 或 Scene meta。完整开关与数据边界见[Plot 溯源](/viz/data/provenance/plot)。

## 入口与输出

| 场景             | 入口                                                | 主要输出                                      |
| ---------------- | --------------------------------------------------- | --------------------------------------------- |
| React standalone | `<Plot>`                                            | `<Layout>` 管理的 SVG / Canvas                |
| React embedded   | `<Layout><Plot /></Layout>`                         | 与其它 Tier 2 内容合编的 Scene                |
| Vanilla embedded | `embedPlot()` + `PlotInputEmbedAdapter`             | Kernel Input Scene / layer 中的 Scene         |
| Vanilla / SSR    | `renderPlot(spec, datasets, { theme, ...options })` | 根 Theme 下的 SVG 字符串或 `{ svg, lineage }` |
| 自定义宿主       | `lowerPlots(datasets, options)` + Core compile      | Core IR → Scene                               |
| 审计与交互       | `lowerPlotWithLineage()`、`createPlotLocator()`     | runtime-only lineage / anchor                 |
