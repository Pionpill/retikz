`<PointMark>` is the simplest mark: it first positions each data row in the active coordinate system, then draws one core `Node` at that position. That Node can be a default dot, shape marker, bubble, text, or a dot with a label; scatter plots, bubble plots, and text points are presentation-level wrappers around the same base mark.

Which position channels you bind depends on the [coordinate system](/viz/plot/coordinate): built-in 1D coordinates use `x`, built-in 2D coordinates use `x` / `y`, and custom coordinates may declare additional roles. The props are optional at the component level; the active coordinate validates the required dimensions at compile time.

## Usage

```tsx
import { Plot, PointMark } from '@retikz/plot-react';
```

```tsx
<Plot data={cities}>
  <PointMark x="lng" y="lat" />
</Plot>
```

PointMark often overlays PathMark — draw `<PathMark>` first, then layer `<PointMark>` on the same data to mark each observation.

### When to Use

PointMark is a low-level point mark: it only projects each data row into one coordinate position, then writes style and text channels onto the Node for that position. What the presentation layer calls a scatter plot, bubble plot, or text point is not a different low-level mark; it is the same PointMark with different channels configured.

This is why PointMark usually does not need coordinate-specific adapters. The coordinate system projects position roles into a screen point, and the presentation layer decides how that point is drawn.

| Presentation form | Key props            | Behavior                                                                                       |
| ----------------- | -------------------- | ---------------------------------------------------------------------------------------------- |
| Scatter point     | `x` / `y`            | The default form: one point per data row; `color` / `shape` continue to decorate the point set |
| Bubble plot       | `size`               | A numeric field drives point radius without changing position                                  |
| Text point        | `text` / `dx` / `dy` | With `text` alone, draws a text Node; conceptually a presentation-level TextMark               |

### Adjust Point Appearance

`color` / `size` / `opacity` / `shape` / `stroke` / `strokeWidth` change a point's visible form without changing its projected position. Field bindings encode appearance from data, while constant colors and `IRPaintSpec` apply one solid or gradient paint to the layer.

Node style props such as `stroke`, `strokeWidth`, `opacity`, `fillOpacity`, and `rotate` can all bind to data fields. At the component layer, strings and numbers are syntax sugar: a string becomes `{ kind: 'field', value: FieldName }` when it matches a data field; if it does not match a field but is a valid constant, it becomes `{ kind: 'constant', value }`; otherwise it is skipped with a warning. Use the explicit form when you need to remove ambiguity.

<ComponentPreview files={['point-style', 'point-api.data.ts']} size="md" />

### Show Labels or Text Points

For text attached to dots, prefer `label`: it writes to the core `Node.label` on each point, so a single `PointMark` can draw the dot and its label. The playground covers center, four sides, and four corners; `labelPosition` also accepts an angle or `{ boundary, fraction }` for precise placement along the real boundary. Use `labelTextColor`, `labelOpacity`, `labelFont`, `labelRotate`, and `labelKeepUpright` for label appearance and orientation. `text` is a different mode: it replaces the point itself with a borderless text Node. `dx` / `dy` apply a small screen-space offset.

## How it works

<ComponentAlert
  type="tip"
  title="You can skip this section at first"
  description="Return when debugging skipped invalid rows, text points replacing glyphs, or how color groups lower into core IR."
/>

`<PointMark>` declares a data-to-point mapping; it does not render DOM. Once collected into `PlotSpec`, the mark registry dispatches it to point lowering, which reuses the active coordinate frame and core `Node`.

| Stage    | Observable behavior                                                                                                                 |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| Project  | Each row is projected through the `x` / `y` / `z` roles required by the coordinate frame; rows without a valid position are skipped |
| Generate | Ordinary mode creates one core `Node` per row; setting `text` creates a text Node instead and applies `dx` / `dy`                   |
| Decorate | `size`, `shape`, color, and Node styles decorate the datum Node; `label` preserves the point and attaches `Node.label`              |
| Layer    | Rows share `nodeDefault` without a color channel; field-driven colors form color groups before mark layer metadata is attached      |

The coordinate frame decides where the point is, PointMark decides which Node is generated per row, and shape, text, and visual styling reuse [Node](/kernel/components/node/overview). Each mark lowers into its own layer. Use `layer={{ zIndex }}` to move the whole mark relative to axes and legends; the `zIndex` prop orders datum Nodes only inside this mark.

## API Reference

This table keeps only PointMark-specific props and props whose meaning is redefined here. See [channel bindings](/viz/plot/channel/binding) for field and explicit field / constant inputs, [transforms](/viz/plot/transform) for `transform` and `layer`, and [coordinates](/viz/plot/coordinate) for coordinate-view props. Shared `fill`, `stroke`, opacity, corner, font, shadow, and related visual props follow [Node styling](/kernel/components/node/overview#visual-style-api) and are not duplicated here.

| Prop                                 | Type                                                                                                                                                                            | Default                                                     | Description                                                                 |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- | --------------------------------------------------------------------------- |
| `id?`                                | `string`                                                                                                                                                                        | —                                                           | Mark handle; required with `resolveLabel`                                   |
| `x?` / `y?` / `z?`                   | `FieldName`                                                                                                                                                                     | —                                                           | Position-role fields; the coordinate frame decides which roles are required |
