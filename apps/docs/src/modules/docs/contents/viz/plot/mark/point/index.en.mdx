title: PointMark
description: Draw one node per data row, encode position, size and shape, add text, and spread overlapping observations.
---

`PointMark` draws a [node (Node)](/kernel/components/node) at the position of each data row. Two numeric fields (corresponding to `x` and `y`) determine the position, while other visual channels of the node convey additional information.

A node here is not limited to a conventional scatter point: it corresponds to the underlying Kernel Node component and can appear as a scatter point, text, a shape, or other forms. This page starts with three points, then covers appearance, labels and spreading overlapping observations. See [channel binding](/viz/plot/channel/binding) for fields and constants, and [Quick start](/viz/plot/get-start) for installation.

## Using this topic

The example binds GDP to the horizontal axis and life expectancy to the vertical axis. Each record becomes a circle with radius 6. Both scales add 15% domain padding so the edge points remain visible. These are example settings, not PointMark defaults.

```tsx
import { Plot, PlotAxis, PlotScale, PointMark } from '@retikz/plot-react';
import { createRoot } from 'react-dom/client';

const rows = [
  { gdp: 400, life: 76, region: 'A', population: 8 },
  { gdp: 900, life: 81, region: 'B', population: 16 },
  { gdp: 1600, life: 84, region: 'A', population: 28 },
];

createRoot(document.getElementById('plot')!).render(
  <Plot data={rows} width={360} height={220}>
    <PlotScale dimension="x" type="linear" domainPadding={{ kind: 'ratio', lower: 0.15, upper: 0.15 }} />
    <PlotScale dimension="y" type="linear" domainPadding={{ kind: 'ratio', lower: 0.15, upper: 0.15 }} />
    <PointMark x="gdp" y="life" size={6} />
    <PlotAxis dimension="x" />
    <PlotAxis dimension="y" />
  </Plot>,
);
```

  namespace: 'plot',
  type: 'plot',

      type: 'point',

    { type: 'axis', dimension: 'x' },

## Basic usage

Unless noted otherwise, the visual properties below support constant and field channels. Numbers, booleans, and objects can use constant shorthand; use explicit constant bindings for ambiguous strings such as colors. See [channel binding](/viz/plot/channel/binding) for field rules. Tables group properties by responsibility, and each demo combines properties from that group.

### Position and size

`x` and `y` select the fields to read. Cartesian coordinates interpret them as horizontal and vertical positions; polar coordinates interpret `x` as angle and `y` as radius. Each row still produces one point.

| Property      | Meaning              | Description                                                                                                                                                                    |
| ------------- | -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `x`, `y`      | Position fields      | Component props accept field names or paths only: horizontal/vertical in Cartesian coordinates and angle/radius in polar coordinates. One-dimensional coordinates use only `x` |
| `z`           | Third position field | For custom coordinates consuming a third position role; unused by built-in coordinates                                                                                         |
| `size`        | Node radius          | Constants specify the radius directly; numeric fields use a square-root scale by default for area comparison. Negative values raise an error                                   |
| `minimumSize` | Minimum visual size  | A number or an object with `width`, `height`, and `default`; `size` takes precedence for ordinary points. The Minimum size mode omits `size`                                   |
| `color`       | Overall color        | This example colors regions categorically; see Appearance for the full set of paint properties                                                                                 |

Keep the position fields fixed while comparing constant points with population bubbles, then change the fields to observe the positions.

### Edge padding

A node's position is its center. At the edge of the plotting area, its radius can extend beyond the boundary. `PointMark` therefore defaults to `max-radius`, reserving the largest node radius on continuous position scales. Data and node sizes stay unchanged; the scale mapping changes.

| Property                  | Meaning                  | Description                                                                                                                                                                                       |
| ------------------------- | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `autoPadding`             | Automatic padding policy | Defaults to `max-radius`; `point-aware` uses actual positions and radii; `false` disables this mark's automatic contribution. Accepts a policy directly, without field-channel binding            |
| `autoPadding.clearance`   | Edge clearance           | Nonnegative drawing units in `{ kind, clearance }`, default 0. Accepts a number or box-spacing object; explicit sides require Cartesian coordinates                                               |
| `PlotScale.domainPadding` | Scale override           | A number, including 0, fixes both ends. `range` fixes specified ends and fills omitted ends automatically; omitted `ratio` ends are 0. Explicit `mark` padding selects participants independently |

The example keeps a large central point and two small edge points unchanged. Switch policies to see whether the central point needs extra space, then increase clearance or set the x scale's start padding to zero to compare precedence.

Maximum-radius padding does not scan data rows: constant sizes use `size`, while field sizes use the maximum output of the size scale. Categorical position scales retain their own padding. Point-aware padding uses valid data and positions after placement adjustments, allowing a central point's existing edge distance to satisfy its constraint. It supports continuous, categorical, and polar mappings with the required capabilities.

Both policies protect the radius expressed by `size`, without measuring text, strokes, shadows, shape scaling, or `minimumSize` bounds. Shared scales take the maximum demand at each end; mixed policies and shared facets satisfy their constraints in one final mapping. Unknown size bounds, missing capabilities, or an infeasible plotting area produce errors.

### Appearance

Fill, stroke and opacity change how points look. This example offers three color sources and shows only the controls relevant to the selected mode.

| Property      | Meaning             | Description                                                                                                                                                                                |
| ------------- | ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `color`       | Overall color       | Categorical fields map through a color scale; use an explicit constant binding for a fixed color. Explicit `fill` can override the node fill                                               |
| `fill`        | Fill                | Supports fields, constant colors, and Paint kinds `linearGradient`, `radialGradient`, `conicGradient`, `pattern`, and `image`; strings are interpreted as field names                      |
| `stroke`      | Stroke color        | Supports fields, constant colors, and Paint objects like `fill`; use an explicit constant binding for a solid color                                                                        |
| `strokeWidth` | Stroke width        | A nonnegative value in output units; 0 hides the stroke                                                                                                                                    |
| `opacity`     | Opacity             | A single value sets overall opacity; an object sets `overall`, `fill`, and `stroke` independently. Each accepts constant or field bindings; overall multiplies the fill and stroke factors |
| `dashed`      | Dashed stroke       | A boolean channel enabling the dashed preset                                                                                                                                               |
| `dotted`      | Dotted stroke       | A boolean channel enabling the dotted preset; `dashed` takes precedence when both are enabled                                                                                              |
| `dashPattern` | Custom dash pattern | An array alternating dash and gap lengths; overrides `dashed` and `dotted`                                                                                                                 |
| `shadow`      | Shadow              | A shadow preset or custom shadow object, optionally mapped per node through a field                                                                                                        |
| `blendMode`   | Blend mode          | Controls color compositing with graphics below, including `normal`, `multiply`, and `screen`                                                                                               |
| `zIndex`      | Node drawing order  | Controls the drawing order of generated nodes, distinct from the mark-level semantic `layer`                                                                                               |

The example overlaps nodes in pairs to expose blending and drawing order. Disable custom dashes and dashed strokes before comparing dotted strokes. Switch between forward and reverse order to inspect overlapping edges.

### Shape

`shape` can select a constant shape or map a categorical field to shapes. This example compares constant shapes: choose a circle, rectangle or diamond, or use a parameterized reference to set the number of star points or polygon sides. Rotation and size apply to the selected shape.

| Property       | Meaning             | Description                                                                                                                 |
| -------------- | ------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `shape`        | Node shape          | A registered name or `{ type, params }` reference; field bindings require categorical data, not continuous or temporal data |
| `rotate`       | Rotation angle      | Rotates around the node position in degrees; rotating a circle has no visible effect                                        |
| `scale`        | Node scale          | A uniform factor or `{ x, y, default }` axis configuration; does not change the data position                               |
| `cornerRadius` | Corner radius       | A nonnegative value; the effect depends on shape support. Select a rectangle to observe it                                  |
| `padding`      | Inner spacing       | Spacing from content to border; a number or a directional spacing object                                                    |
| `margin`       | Connection margin   | An offset outside the connection boundary; affects connections without changing the visible fill shape                      |
| `boundary`     | Connection boundary | The connection contour: `shape`, `circle`, or a shape reference; independent of the visible `shape`                         |

The star shape is provided by `StarShapeDefinition` from `@retikz/extension`; this example registers it explicitly through Layout’s `extensions.shapes`.

### Text and labels

Choose whether text should accompany the point or replace it.

| Property        | Meaning                | Description                                                                                                                                                                              |
| --------------- | ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `text`          | Text node content      | The component prop binds a field only; renders borderless text instead of an ordinary shape                                                                                              |
| `displayFormat` | Text format            | A numeric or time format string used with `text`; a direct setting, not a channel binding                                                                                                |
| `textColor`     | Text color             | A constant or field channel for text nodes; attached labels use their own color in `label`                                                                                               |
| `font`          | Font                   | A font configuration or field channel, including size, weight, and family; attached labels use `label.font`                                                                              |
| `align`         | Multiline alignment    | `start`, `middle`, or `end` within the multiline text block                                                                                                                              |
| `lineHeight`    | Line height            | A positive value in output units for multiline text nodes                                                                                                                                |
| `maxTextWidth`  | Maximum text width     | A positive width limit that wraps text; combine with line height and alignment                                                                                                           |
| `dx`, `dy`      | Text offsets           | Direct numeric values, not field channels; positive values move right and down. Applies only to text nodes                                                                               |
| `label`         | Attached labels        | A field name, label object, or ordered array of labels. Objects configure content, position, distance, pins, and style; use `value` for fixed content and `displayFormat` for formatting |
| `resolveLabel`  | Runtime label callback | Receives a row and returns text, taking precedence over label content. Requires a mark `id`; callbacks are not serialized into IR                                                        |

Label position, distance, pins and font belong in the `label` object. Source IR stores the text binding in `label.content`. Text points use `textColor` and `font` for appearance. Their `dx` and `dy` offsets move right and down for positive values; these offsets do not move ordinary point shapes.

## Extended usage

Use `placement.adjustments` to spread observations that overlap at the same position. The following demo uses built-in `jitter`, which adjusts positions after scale mapping without changing data rows or field values. The Data transform named `jitter` instead derives a field before scale mapping.

### Jitter

Switch between Cartesian and polar coordinates using the coordinate selector. In Cartesian coordinates, a step ratio spreads nodes within category intervals; output units specify the total post-scale width. Plot reserves the jitter half-span and node extent at both ends. Axis lines stay at the plot boundaries while category ticks follow the mapped node positions. In polar coordinates, step ratio uses discrete category angles, while output units use continuous numeric angles.

`distribution` defaults to `{ kind: 'uniform' }`, spreading offsets across the full range. `{ kind: 'normal', sigma }` uses a zero-mean normal distribution truncated to normalized `[-1, 1]`, so points concentrate near the category center while staying inside the `span` envelope. `sigma` is relative to the jitter half-span: it defaults to `0.5`; smaller values concentrate more points, while larger values approach the full allowed range.

The x role is an angle in polar coordinates. Discrete angles use a tick-step ratio: the default `chord` mode moves jittered points along the straight edge between adjacent polygon vertices. Continuous angles use numeric output units and move along circular arcs. Both modes compose the angle before projecting with each row's y radius, so outer points travel farther on screen instead of receiving a uniform `dx` / `dy`. The demo uses radial `domainPadding` to reserve the spread space and Point radius at the outer edge.

## Errors and limitations

- Position bindings must satisfy the coordinate system: built-in one-dimensional coordinates use `x`, and two-dimensional coordinates use `x` and `y`. Optional component properties do not remove these requirements.
- Ordinary points skip rows whose size field is missing, `null` or non-finite. Negative sizes raise an error. Text points use the text path and do not apply this size filter.
- Field-based `shape` mappings require categorical data. Continuous and temporal fields are rejected. Constant shapes use registered names or parameterized references.
- `resolveLabel` is a runtime callback and requires a mark `id`. The callback is not stored in serializable IR.
- Adjustments preserve declaration order within each stage. All role adjustments precede coordinate projection; screen adjustments follow it. Built-in jitter reproduces positions only when seed, effective row order, role, span and discrete scale step are unchanged.

  type="tip"

The component normalizes shorthand properties into a Plot configuration with `type: 'point'`. Position scales convert field values into values understood by the coordinate system, and placement applies position adjustments. The mark uses the resulting positions to create Node objects for rendering.

Geometry generation branches between ordinary points and text points. Ordinary points consume size and shape, then attach labels. A text channel instead produces borderless text and applies `dx` and `dy`. Invalid positions or missing text skip the corresponding rows. Finally, points are organized by color and receive the mark layer configuration.

### Padding calculation

The figure compares explicit zero padding with automatic padding using the same data, radii, and plotting area. Automatic padding moves extreme point centers inward without changing the canvas or node sizes.

<ComponentPreview files="point-padding-figure" hideCode type="illustration" size="lg" />

The following four panels use the same data, size mapping, and plotting area. They compare both policies with zero clearance and directional clearance (default 8, top 20, left 0).

<ComponentPreview files="point-padding-strategies-figure" hideCode type="illustration" size="lg" />

Maximum-radius padding reserves the largest node radius plus the clearance for each side. Point-aware padding uses the central point's existing distance from the edges and adds only the space each point needs. Node sizes stay the same across all four panels; the position-scale mapping changes.

Plot collects demands by each mark's actual position-scale binding. Maximum radius plus clearance sets a minimum at each end; point-aware padding adds constraints from positions and radii in the same mapping. Shared facets solve one domain, which is then used by axes, grids, and marks. This happens before rendering, without measuring SVG or Canvas output.
