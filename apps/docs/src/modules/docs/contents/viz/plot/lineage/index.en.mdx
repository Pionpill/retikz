title: Plot Lineage
description: Plot lineage enriches Data provenance and transform records with mark, encoding, scale, and layout semantics for host-side runtime audits.
---

Data explains where a row came from and which transforms it passed through. Plot must additionally explain how that row became a mark, which channels and scales it used, and which layout contained it. Plot lineage combines both layers into a `PlotLineageRun` for inspectors, audit panels, and interaction trace-back.

## From Data to Marks

<ComponentPreview files="plot-lineage-flow" size="sm" hideCode />

Plot lineage reuses [Data Provenance](/viz/data/provenance), then adds Plot-owned semantics: root versus mark-local transform scopes, mark identity and encoding, declared scales, coordinate layout, and host-approved query or AI metadata.

`PlotLineageRun` is a runtime artifact. It does not enter `IRPlotSpec` and is not written into Scene metadata, so rendered output and lineage can follow different storage, permission, and retention policies.

## Two Separate Paths

<ComponentPreview files="plot-lineage-paths" size="sm" hideCode />

Plot has two similarly named source capabilities with different jobs:

| Path                        | Entry options                                   | Output location                           | Typical use                          |
| --------------------------- | ----------------------------------------------- | ----------------------------------------- | ------------------------------------ |
| Lowered provenance metadata | `provenance`, `datumProvenance`, `datumIdField` | Core primitive ids / meta in the Scene    | Locators, stable anchors, inspection |
| Runtime Plot lineage        | `lineage`, `hostLineageMetadata`                | `PlotLineageRun` return value or callback | Audit, explanation, host inspectors  |

Lowered provenance can change the ids and metadata carried by generated primitives. Plot lineage only records one run on a side channel. Enabling `lineage` does not copy the artifact into the Scene, and enabling `datumProvenance` does not create a `PlotLineageRun`.

## React Integration

Author the chart with the normal `<Plot>` entry. Pass `lineage` when the host needs the artifact and receive it through `onLineage`:

```tsx
import { useCallback, useMemo, useState } from 'react';
import { Axis, IntervalMark, Plot } from '@retikz/plot-react';
import type { PlotLineageOptions, PlotLineageRun } from '@retikz/plot';

export function SalesPlot({ sales, queryId }: { sales: Array<Record<string, unknown>>; queryId: string }) {
  const [, setAuditLineage] = useState<PlotLineageRun | null>(null);
  const lineage = useMemo<PlotLineageOptions>(
    () => ({
      scaleMappings: true,
      layoutContext: true,
      rowValues: { maxRows: 3, fields: ['region', 'revenue'] },
      hostMetadata: { query: true },
    }),
    [],
  );
  const handleLineage = useCallback((run: PlotLineageRun) => {
    setAuditLineage(run);
  }, []);

  return (
    <Plot
      id="salesPlot"
      data={sales}
      width={420}
      height={260}
      lineage={lineage}
      hostLineageMetadata={{ queryId, datasetVersion: 'sales-v3' }}
      onLineage={handleLineage}
    >
      <IntervalMark id="revenueBars" x="region" y="revenue" color="month" />
      <Axis dimension="x" />
      <Axis dimension="y" grid />
    </Plot>
  );
}
```

The presence of `onLineage` enables the minimal default configuration even when `lineage` is omitted. Pass `lineage={false}` to disable it explicitly. Use the React adapter's `resolvePlotLineage` when lineage is needed outside rendering.

## Vanilla and SSR

Vanilla and SSR pass the same options to `renderPlot`. Without lineage options it returns an SVG string; with a `lineage` object it returns `{ svg, lineage }`.

```ts
import { plotBuilder, renderPlot } from '@retikz/plot-vanilla';

const spec = plotBuilder({
  data: { reference: 'sales' },
  scales: [
    { type: 'band', name: 'x' },
    { type: 'linear', name: 'y' },
  ],
  coordinate: { type: 'cartesian2D', x: 'x', y: 'y' },
})
  .interval({ type: 'interval', encoding: { x: { field: 'region' }, y: { field: 'revenue' } } })
  .build();

const { svg, lineage } = renderPlot(
  spec,
  { sales },
  {
    width: 420,
    height: 260,
    lineage: {
      scaleMappings: true,
      rowValues: { maxRows: 3, fields: ['region', 'revenue'] },
      hostMetadata: { query: true },
    },
    hostLineageMetadata: { queryId: 'q-sales', datasetVersion: 'sales-v3' },
  },
);
```

## Recording Scope

`lineage: {}` keeps a lightweight summary sufficient to identify marks and transform scopes. Higher-cost or sensitive details are independent opt-ins:

| Option            | Default | Records                                                   |
| ----------------- | ------- | --------------------------------------------------------- |
| `data`            | `{}`    | Data source summaries and transform steps                 |
| `markIdentity`    | `true`  | Plot id, data reference, and mark id / type / index       |
| `markEncoding`    | `true`  | Fields consumed by mark channels and their scale bindings |
| `transformScopes` | `true`  | Root and mark-local transform segmentation                |
| `scaleMappings`   | `false` | Declared `spec.scales` and their channel bindings         |
| `layoutContext`   | `false` | Coordinate, view, facet, and track summaries              |
| `locatorAnchors`  | `false` | Locator addresses and resolved anchors                    |
| `rowValues`       | `false` | Final row samples with required row and field limits      |
| `hostMetadata`    | `false` | Selected host query, AI, permission, and extra metadata   |

`scaleMappings` records only scales declared in `spec.scales` and their mark-channel bindings. Temporary scales derived inside lowering are not a stable contract. `rowValues` is off by default so an audit artifact never copies complete business rows accidentally.

## Interaction Trace-Back

Use `createPlotLineageLocator` to trace a hit datum or series back to its source. It returns `markIndex`, `transformedIndex`, a source summary, and optional mark lineage beside the ordinary locator anchor:

```ts
import { createPlotLineageLocator } from '@retikz/plot';

const locator = createPlotLineageLocator(spec, datasets, {
  lineage: { locatorAnchors: true },
});

const result = locator.datum(4);
```

This entry is suitable for tooltips, AI explanation panels, or audit navigation. The host still decides what is displayed.
