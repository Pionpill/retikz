title: Custom Channels
description: Use a ChannelDefinition to resolve fields or constants into existing Core properties, then inject it into Plot's shared channel registry through channelDefinitions.

After learning [field and constant bindings](/viz/plot/channel/binding), you can define your own channel names and value mappings. This page maps `score` to point opacity through `intensity`: higher scores produce more opaque points, while a constant gives every point the same opacity.

## Applicability

- Define a custom channel when you need a new `encoding.channels.<name>` that participates in field / constant binding, per-row evaluation, and legend descriptors.
- Use a [Custom Scale](/viz/plot/scale/custom-scale) only when changing value-to-coordinate or value-to-color mapping. Other visual properties such as size and opacity are still evaluated and delivered by their channels.
- Field preparation, aggregation, and filtering belong to [Data Extensions](/viz/data/model/extensions), not a channel resolver.

## Define the capability

Use `defineScopeChannel`, `defineNodeChannel`, `definePathChannel`, or the generic `defineChannel`:

| Field     | Purpose                                                                                                    |
| --------- | ---------------------------------------------------------------------------------------------------------- |
| `channel` | Unique registry name used by `encoding.channels.<name>`                                                    |
| `output`  | Declares output type and optional range / palette / clamp metadata; it does not map or clamp values itself |
| `legend?` | Declares the legend form                                                                                   |
| `resolve` | Reads a field or constant binding, performs mapping and clamp, and returns a resolver plus descriptor      |
| `deliver` | Writes each resolved value to an existing Core property                                                    |

This example uses `defineNodeChannel` because opacity is delivered to each point. The complete definition below is shared by the React and Vanilla hosts:

```ts
import { defineNodeChannel } from '@retikz/plot';

type ExtensionChannelBinding = { field?: string; value?: unknown };

const extensionChannelsOf = (mark: {
  encoding?: { channels?: Partial<Record<string, ExtensionChannelBinding>> };
}): Partial<Record<string, ExtensionChannelBinding>> => mark.encoding?.channels ?? {};

const clampIntensity = (value: number): number => Math.min(1, Math.max(0.3, value));

/** Custom intensity channel: map field values to opacity and clamp constants before delivery */
export const intensityChannel = defineNodeChannel<number>({
  channel: 'intensity',
  output: { outputKind: 'number', range: [0.3, 1], clamp: true },
  legend: 'ramp',
  resolve: (ctx, mark) => {
    const binding = extensionChannelsOf(mark).intensity;
    if (binding === undefined) return undefined;
    if (binding.value !== undefined) {
      if (typeof binding.value !== 'number' || !Number.isFinite(binding.value)) {
        throw new Error('lowerPlots: intensity constant must be a finite number');
      }

      const value = clampIntensity(binding.value);

      return { resolver: () => value };
    }

    if (binding.field === undefined) return undefined;

    const field = binding.field;
    const values = ctx.rows.map(row => Number(row[field])).filter(Number.isFinite);
    if (values.length === 0) return undefined;

    const lo = Math.min(...values);
    const hi = Math.max(...values);
    const map = (value: number): number => clampIntensity(0.3 + (hi === lo ? 0.5 : (value - lo) / (hi - lo)) * 0.7);

    return {
      resolver: row => {
        const value = Number(row[field]);
        return Number.isFinite(value) ? map(value) : undefined;
      },
      descriptor: {
        channel: 'intensity',
        scaleType: 'linear',
        domain: [lo, hi],
        range: [0.3, 1],
        field,
        fieldType: ctx.model.find(definition => definition.name === field)?.type,
      },
    };
  },
  deliver: (node, value) => {
    node.style = { ...node.style, opacity: value };
  },
});
```

`resolve` reads the current mark’s `intensity` binding. In field mode, it maps the data minimum and maximum to `[0.3, 1]`; in constant mode, it clamps the number to that range. The returned `resolver` supplies opacity for each row. Field mode also returns a `descriptor` that tells the legend the data and visual ranges. `output.range` and `output.clamp` declare metadata only; this definition performs the mapping and clamping.

Finally, `deliver` writes the resolved opacity to the node style.

## Inject and use

React and Vanilla share the definition above; choose the host used by your project. The preview’s React and Vanilla source views contain complete examples. The excerpts below show only where injection differs.

<DocTabs defaultValue="react">
<DocTab value="react" label="React">

Inject the definition on `Plot`, then reference its registered name in the child mark’s `channels`:

```tsx
<Plot data={customChannelPoints} channelDefinitions={[intensityChannel]}>
  <PointMark x="x" y="y" channels={{ intensity: 'score' }} />
</Plot>
```

A string in the React DSL means a field name; use `{ kind: 'constant', value }` for a constant:

```tsx
<PointMark channels={{ intensity: 'score' }} />
<PointMark channels={{ intensity: { kind: 'constant', value: 0.65 } }} />
```

</DocTab>
<DocTab value="vanilla" label="Vanilla">

Inject through the third argument of `renderPlot`. Here, `spec` is the Plot configuration in the preview’s Vanilla source, where `encoding.channels.intensity` already binds score:

```ts
const svg = renderPlot(
  spec,
  { points: customChannelPoints },
  {
    channelDefinitions: [intensityChannel],
  },
);
```

The Vanilla example uses Plot IR directly: bind a field with `{ field }` or a constant with `{ value }`:

```ts
import type { IRPlotChannel } from '@retikz/plot';

const fieldBinding: IRPlotChannel = { field: 'score' };
const constantBinding: IRPlotChannel = { value: 0.65 };
```

</DocTab>
</DocTabs>

The definition always stays in the runtime and never enters Plot IR.

## Errors and limits

- A custom `channel` cannot override a built-in name or be registered twice; binding an unregistered channel fails during lowering.
- Each binding must select exactly one of `field` and `value`, and constants must be JSON values.
- The definition decides which value types it accepts. The example `intensity` constant accepts only finite numbers and performs its own clamp in `resolve`.
- `resolve` should not mutate data or generate geometry; `deliver` may only write properties supported by the corresponding Core primitive.
- IR stores only field or JSON-constant bindings, never functions or definitions.

This binding fails schema validation because it sets both a field and a constant:

```ts
encoding: {
  channels: { intensity: { field: 'score', value: 0.65 } },
}
```
