---
title: 派生与抖动
description: 派生与抖动保持输入行数不变，只按单行字段补出区间或在数据空间生成确定性偏移。
---

需要为每个输入行补出区间时用 `derive-interval`；需要在连续数值空间抖开重叠点时用 `jitter`。两者都保留行数，不做分组统计或代表行选择。

| kind              | 行数  | 常见用途                            |
| ----------------- | ----- | ----------------------------------- |
| `derive-interval` | N → N | 把单行数值整理成 `[start,end]` 区间 |
| `jitter`          | N → N | 在数据空间抖开重叠散点              |

## 派生区间

`derive-interval` 给每一行独立算出一个区间。它不看其它行，适合甘特条、显式区间、非零基线柱。

### API 参考

`IRPlotDeriveIntervalTransform` 的 `kind` 固定为 `'derive-interval'`。两种输入模式共享输出字段配置。

| prop          | 类型     | 默认值 | 说明                                          |
| ------------- | -------- | ------ | --------------------------------------------- |
| `from?`       | `string` | —      | baseline 到 value 模式的值字段                |
| `baseline?`   | `number` | `0`    | `from` 模式的起点                             |
| `startFrom?`  | `string` | —      | 两字段模式的区间起点；与 `endFrom` 成对出现   |
| `endFrom?`    | `string` | —      | 两字段模式的区间终点；与 `startFrom` 成对出现 |
| `startField?` | `string` | `y0`   | 输出起点字段名                                |
| `endField?`   | `string` | `y1`   | 输出终点字段名                                |

### 技术原理

`derive-interval` 先确定全局配置使用哪一种模式，再用同一规则逐行派生。图中的橙色节点是行数据，蓝色节点是逐行处理；只有红色支路会终止 lowering。

<ComponentPreview files="transform-derive-interval-logic" hideCode size="sm" />

模式选择和字段写入分为四步：

1. `startFrom` 与 `endFrom` 同时存在时，双字段模式优先，即使还设置了 `from` 也不会读取它。
2. 双字段不完整时改用 `from` 模式；如果 `from` 也不存在，lowering 会在遍历数据前抛错。
3. 每一行都通过 `resolveFieldPath` 取值。源值不是有限数时，`finiteOr` 用 `baseline` 兜底。
4. 返回值展开原始行，再写入 `startField` / `endField`，所以字段会增加或覆盖，但行数始终保持 N → N。

它和 `stack` 都默认产出 `y0` / `y1`，但语义不同：`derive-interval` 是单行派生，`stack` 是跨行累积。

## 抖动

`jitter` 给连续数值位置字段加一个伪随机偏移，把重叠散点抖开。适合连续数值轴上的同位置观测点；分类刻度间距或极坐标 angle 相关的散布改用 Point 的 [placement jitter](/viz/plot/mark/point#位置散布)。

### API 参考

`IRPlotJitterTransform` 的 `kind` 固定为 `'jitter'`。

| prop      | 类型                            | 默认值 | 说明                         |
| --------- | ------------------------------- | ------ | ---------------------------- |
| `axis?`   | <ApiValues name="JitterAxis" /> | `'x'`  | 抖动作用轴                   |
| `xField?` | `string`                        | `x`    | x 方向被抖动的连续数值字段   |
| `yField?` | `string`                        | `y`    | y 方向被抖动的连续数值字段   |
| `amount?` | `number`                        | `1`    | 最大绝对偏移，单位是数据单位 |
| `seed?`   | `number`                        | `0`    | 确定性 PRNG 种子             |

### 技术原理

`jitter` 的主链是“选字段 → 生成偏移 → 写回行 → 进入比例尺”。图上方的 `mulberry32(seed)` 是辅助输入，它不改变行数，只为每次字段扰动提供一个确定的 `u`。

<ComponentPreview files="transform-jitter-logic" hideCode size="sm" />

`axis` 决定处理 x、y 还是两者，`xField` / `yField` 再确定实际字段。每处理一个目标字段，PRNG 都先前进一步得到 `u ∈ [0,1)`，然后计算：

`δ = (2u - 1) × amount`

有限数值写回 `value + δ`；非有限值保持原值，但仍消耗这一次随机数，避免后续行的序列错位。因此，相同 `seed`、相同字段选择和相同行顺序会得到同一组偏移，SSR 与浏览器 hydration 可以复现一致结果。

偏移发生在 Scale 之前，所以 `amount` 的单位是数据单位，不是像素。变换只复制并更新行字段，输入与输出仍是 N → N。
