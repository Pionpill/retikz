`<PointMark>` 是最简单的图元：它先让每行数据在当前坐标系里得到一个位置，再在这个位置绘制一个 core `Node`。这个 Node 可以是默认圆点、形状标记、气泡、文本，或带标签的组合形态；散点图、气泡图和文本点都可以看作它的上层封装。

绑哪些位置通道由[坐标系](/viz/plot/coordinate)决定：内置一维坐标使用 `x`，内置二维坐标使用 `x` / `y`；自定义坐标可以声明额外 role。这些属性在组件层都是可选的；当前坐标系会在编译期校验需要哪些维度。

## 用法

```tsx
import { Plot, PointMark } from '@retikz/plot-react';
```

```tsx
<Plot data={cities}>
  <PointMark x="lng" y="lat" />
</Plot>
```

PointMark 常和 PathMark 叠加——同一份数据先画 `<PathMark>` 再叠 `<PointMark>` 标出每个观测点。

### 何时使用

PointMark 是底层点 mark：它只负责把每行数据投影成一个坐标位置，并把样式、文本等通道写到这个位置对应的 Node 上。表现层看到的“散点图”“气泡图”“文本点”不是不同的底层 mark，而是同一个 PointMark 在不同通道配置下的显示形态。

这也是 PointMark 通常不需要按坐标系单独适配的原因：坐标系只负责把位置角色投影成屏幕点，表现层再决定这个点画成什么。

| 表现形态 | 关键属性             | 说明                                                           |
| -------- | -------------------- | -------------------------------------------------------------- |
| 散点     | `x` / `y`            | 默认形态，每行数据绘制一个点；`color` / `shape` 继续装饰这组点 |
| 气泡图   | `size`               | 点半径由数值字段驱动，位置投影不变                             |
| 文本点   | `text` / `dx` / `dy` | 单独使用 `text` 时绘制文本 Node，可理解为表现层的 TextMark     |

PointMark 在每个位置生成的是 core Node，而不是固定的圆。`shape` 既可以是圆、矩形、菱形等简单形状名，也可以是带 `params` 的星形、多边形或已注册的自定义形状引用；参数化形状还能继续调整角数或边数。

## 技术原理

<ComponentAlert
  type="tip"
  title="上手阶段可跳过本节"

/>

`<PointMark>` 只声明数据到点几何的映射，不直接渲染 DOM。它进入 `PlotSpec` 后由 mark registry 分派给 point lowering，并复用当前坐标系与 core `Node`。

| 阶段 | 可观察行为                                                                               |
| ---- | ---------------------------------------------------------------------------------------- |
| 投影 | 每行数据按当前坐标系需要的 `x` / `y` / `z` 角色投影；无法得到有效位置的行被跳过          |
| 生成 | 普通模式每行生成一个 core `Node`；设置 `text` 后改为文本 Node，并用 `dx` / `dy` 微调位置 |
| 装饰 | `size`、`shape`、颜色与 Node 样式写入 datum Node；`label` 保留点本身并挂到 `Node.label`  |
| 分层 | 没有颜色通道时共享 `nodeDefault`；按字段着色时按颜色组织子层，最后附加 mark 图层信息     |

普通 glyph 模式下，字段尺寸为缺失值、`null`、`NaN` 或无穷值时，该行不会生成 Point glyph；尺寸字段 descriptor、scale identity 与可选 legend 是数据集级信息，仍会保留。负数尺寸会直接报错，不会被跳过或截断。设置 `text` 后使用既有文本 Node 路径，不受这条仅针对 glyph 的尺寸守门影响。

因此坐标系只决定“点在哪里”，PointMark 决定“每行生成什么 Node”，而具体形状、文字与视觉样式仍复用 [Node](/kernel/components/node/overview) 的能力。每个 mark 默认处于独立图层；调整整个 mark 与轴、图例的前后关系时使用 `layer={{ zIndex }}`，`zIndex` prop 只控制当前 mark 内 datum Node 的顺序。
