title: PointMark · 点图元
description: 用 PointMark 将每行数据画成一个节点，按字段控制位置、大小与形状，并添加文字或散布重叠的观测。
---

一行数据对应一个位置，`PointMark` 在这个位置画一个[节点（Node）](/kernel/components/node)。通过两个数值字段（对应 `x`、`y`）确定位置，再通过节点的其他视觉通道展示相应的信息。

这里的节点并不局限于传统意义上的散点，而是对应底层 Kernel 的 Node 组件，因此可以展现为散点、文本、图形等多种形式。本页先用三个点完成接入，再介绍外观、标签和重叠点的散布。字段与常量的区别见[通道绑定](/viz/plot/channel/binding)，安装和宿主接入见[快速开始](/viz/plot/get-start)。

## 基础用法

以下视觉属性除特别注明外，均支持常量通道和字段通道。数字、布尔或对象可作为常量简写；颜色等有歧义的字符串使用显式常量绑定，字段绑定规则见[通道绑定](/viz/plot/channel/binding)。表格按属性职责分组，demo 展示同组属性的组合效果。

### 位置

`encodings.position` 按坐标角色指定位置来源。直角坐标中 x、y 表示水平与垂直位置；极坐标中 x 表示角度，y 表示半径。一维提供 x，二维提供 x、y，三维依次提供 x、y、z。

| 输入     | 写法                                    | 含义                                                   |
| -------- | --------------------------------------- | ------------------------------------------------------ |
| 字段     | `{ field: 'x' }`                        | 读取当前数据行的字段，再经过比例尺映射                 |
| 常量     | `{ value: 50 }`                         | 固定的数据空间值，也可以是分类字符串；仍经过比例尺映射 |
| 范围边界 | `{ edge: 'start' }` / `{ edge: 'end' }` | 最终坐标角色范围的起点或终点，跟随范围反转             |

### 外观

填充、描边和透明度改变点的外观。示例把颜色来源分为三种，切换来源后只显示当前模式可操作的字段。

| 属性                  | 含义             | 说明                                                                                                                               |
| --------------------- | ---------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `size`                | 节点半径         | 常量直接指定半径；数值字段默认通过平方根比例尺映射，便于比较面积。负值报错                                                         |
| `minimumSize`         | 最小视觉尺寸     | 支持数字或包含 `width`、`height`、`default` 的对象；普通点的 `size` 优先。示例切换到“最小尺寸”后省略 `size`                        |
| `color`               | 整体颜色         | 分类字段通过颜色比例尺映射；常量颜色使用显式常量绑定。显式 `fill` 可覆盖节点填充                                                   |
| `fill`                | 填充             | 支持字段、常量色，以及 `linearGradient`、`radialGradient`、`conicGradient`、`pattern`、`image` 等 Paint `kind`；字符串按字段名解析 |
| `dashOffset`          | 虚线偏移         | 有限正负数；与 `dashPattern` 配合，支持固定属性和字段编码                                                                          |
| `lineCap`、`lineJoin` | 描边端点与连接角 | 线帽为 butt / round / square，连接角为 miter / round / bevel；支持固定属性和字段编码                                               |
| `stroke`              | 描边颜色         | 与 `fill` 一样支持字段、常量色和 Paint 对象；需要纯色时使用显式常量绑定                                                            |
| `strokeWidth`         | 描边宽度         | 非负数，输出单位；设为 0 可隐藏描边                                                                                                |
| `opacity`             | 透明度           | 单值设置整体不透明度，也可分别设置 `overall`、`fill`、`stroke`；各分量支持常量与字段绑定，整体因子与填充、描边因子相乘             |
| `dashed`              | 虚线描边         | 布尔通道，启用预设虚线                                                                                                             |
| `dotted`              | 点线描边         | 布尔通道，启用预设点线；同时启用 `dashed` 时后者优先                                                                               |
| `dashPattern`         | 自定义虚线       | 数值数组，交替指定实线段与间隔长度；优先于 `dashed` 和 `dotted`                                                                    |
| `shadow`              | 阴影             | 支持阴影预设或自定义阴影对象，可通过字段逐节点设置                                                                                 |
| `blendMode`           | 混合模式         | 控制与下方图形的颜色合成，例如 `normal`、`multiply`、`screen`                                                                      |
| `zIndex`              | 节点绘制顺序     | 控制生成节点的绘制顺序；不等同于整个图元的语义 `layer`                                                                             |

固定 `fill`、`stroke` 可使用 CSS 颜色、结构化 Paint 或 0–1 的主色权重（`0` 也是有效值）。固定 `opacity: 0.6` 等价于 `{ overall: 0.6 }`；`encodings.opacity` 仍按 `overall`、`fill`、`stroke` 分量绑定，只覆盖对应的固定分量。 `textColor` 支持 CSS 颜色或 0 到 1 的主色权重。

尺寸可使用固定半径、按人口字段映射或最小尺寸三种模式。最小尺寸模式不设置 `size`，由 `minimumSize` 决定节点大小。

### 形状

节点默认保持屏幕方向。`orientation={{ kind: 'coordinate', role: 'x', align: 'tangent' }}` 让节点沿当前位置的 x 坐标曲线定向；`normal` 改为其正法向。`role` 是坐标角色，不是可见坐标轴的 ID。极坐标中 x 表示角向、y 表示径向，自定义曲线坐标沿用同一规则。

在下方示例中选择极坐标和矩形，再切换“方向对齐”。`rotate` 是在对齐角度上追加的旋转偏移；圆形自身旋转没有可见差异。方向跟随角色空间的位置调整，屏幕偏移只移动节点，不重新计算方向。

`shape` 可以指定固定形状，也可以按分类字段选择形状。此处比较固定形状：选择圆、矩形或菱形，或者用带参数的形状引用设置星形角数和多边形边数。旋转与尺寸都作用于当前形状。

| 属性           | 含义       | 说明                                                                                                              |
| -------------- | ---------- | ----------------------------------------------------------------------------------------------------------------- |
| `shape`        | 节点形状   | 支持已注册的形状名或 `{ type, params }` 引用；字段绑定要求分类字段，连续和时间字段不支持                          |
| `orientation`  | 方向参考   | 图元级配置；默认 `{ kind: 'screen' }`，或 `{ kind: 'coordinate', role, align: 'tangent' / 'normal' }`；不绑定字段 |
| `rotate`       | 旋转角度   | 以度为单位叠加到方向对齐角；支持常量与字段通道，圆形旋转没有可见差异                                              |
| `scale`        | 节点缩放   | 支持统一倍数或 `{ x, y, default }` 轴向配置，不改变数据位置                                                       |
| `cornerRadius` | 圆角半径   | 非负数；效果取决于所选形状是否支持圆角，本例切换到矩形观察                                                        |
| `padding`      | 内边距     | 从内容到边框的间距；支持数字或按方向设置的间距对象                                                                |
| `margin`       | 连接外边距 | 连接边界外的偏移，影响连接位置，不改变可见填充形状                                                                |
| `boundary`     | 连接边界   | 指定连接使用的轮廓，支持 `shape`、`circle` 或形状引用；与可见 `shape` 分开设置                                    |

星形由 `@retikz/extension` 的 `StarShapeDefinition` 提供；本例通过 Layout 的 `extensions.shapes` 显式注册。

示例的起始尺寸为 18，灰色辅助连线由 RelationMark 绘制，用于观察节点外边距（`margin`）对连线接入位置的影响，可通过“显示连线”开关关闭。切换到矩形后比较圆角、内边距与连接外边距；“圆形包络”使用 `fit: 'bounds'`，改变连线接入的位置，不改变可见形状。

### 文字与标签

文字有两种用途，先选择需要的结果，再设置样式。

| 属性            | 含义           | 说明                                                                                                                                                  |
| --------------- | -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `text`          | 文本节点内容   | 组件属性只绑定字段；设置后以无边框文字代替普通形状                                                                                                    |
| `displayFormat` | 文本格式       | 仅与 `text` 字段同用，直接指定数值或时间格式串，不是通道绑定                                                                                          |
| `textColor`     | 文字颜色       | 支持常量或字段通道，作用于文本节点；附属标签的颜色在 `label` 中设置                                                                                   |
| `font`          | 字体           | 支持字体配置对象或字段通道，可设置字号、字重、字体族等；附属标签使用 `label.font`                                                                     |
| `align`         | 多行文字对齐   | 支持 `start`、`middle`、`end`，作用于多行文本块内部                                                                                                   |
| `lineHeight`    | 文字行高       | 正数，输出单位；作用于多行文本节点                                                                                                                    |
| `maxTextWidth`  | 文字宽度上限   | 正数，超过宽度时换行；与行高、对齐结合使用                                                                                                            |
| `dx`、`dy`      | 文本位置偏移   | 直接指定数值，不支持字段通道；正值分别向右和屏幕下方移动，仅作用于文本节点                                                                            |
| `label`         | 附属标签       | 支持字段名、标签对象或有序标签数组；对象指定内容、位置、距离、引线与样式。固定内容使用 `properties.label` 的字符串或 `text`，格式使用 `displayFormat` |
| `resolveLabel`  | 运行时标签回调 | 接收数据行并返回文字，优先于标签内容；必须设置图元 `id`，回调不进入可序列化 IR                                                                        |

标签的位置、距离、引线与字体写在 `label` 对象中；Source IR 的文字绑定写在 `label.text`。文本点通过 `textColor`、`font` 设置文字外观，`dx`、`dy` 调整相对位置，正值分别向右、向屏幕下方移动。它们不会平移普通散点。

切换“文本点”与“多行文字”后比较对齐、行高和宽度；选择人口字段后比较数值格式。“回调标签”展示由同一行的字母和人口数值组合生成的内容。

标签内容可简写为 `encodings.label: 'name'`，固定文字写 `properties.label: '重点'`。对象形式支持 `font.size`、`font.weight`、`textColor` 等字段编码，多标签数组按索引配对；未编码的字体叶子继续继承。详见[标签编码](/viz/plot/reference/encoding#labelencodingschema)。

标签模式中，字号与字重控件改变数据中的 `labelSize`、`labelWeight` 字段；各行字号不同，固定字体的其它属性仍保留。

## 扩展用法

### 边缘留白

节点的位置表示中心。极值点落在绘图区边缘时，半径会伸出边界，因此 `PointMark` 默认采用 `max-radius`，为连续位置尺度预留最大节点半径。位置、数据和节点尺寸保持不变，变化的是尺度映射。

| 属性                      | 含义         | 说明                                                                                                                      |
| ------------------------- | ------------ | ------------------------------------------------------------------------------------------------------------------------- |
| `autoPadding`             | 自动留白策略 | `max-radius` 为默认值；`point-aware` 按实际位置与半径求解；`false` 关闭当前图元的自动贡献。直接传策略，不通过字段通道绑定 |
| `autoPadding.clearance`   | 外缘净空     | 对象形式 `{ kind, clearance }` 中的非负绘图单位，默认 0；支持数字或四边间距对象，明确四边仅适用于笛卡尔坐标               |
| `PlotScale.domainPadding` | 尺度覆盖     | 数字（包括 0）固定两端；`range` 只固定已写的端，省略端自动补齐；`ratio` 省略端为 0；显式 `mark` 分支独立指定参与图元      |

示例保持中央大点与边缘小点的大小不变。切换策略，观察中央大点是否需要额外边缘空间；再增加净空，或将 x 尺度起点设为零，比较显式配置的优先级。

最大半径策略不扫描数据行：固定尺寸使用 `size`，字段尺寸使用尺寸尺度输出范围的最大值；分类位置尺度保留自身 padding。逐点策略使用有效数据及位置调整后的实际位置，利用中央大点已有的边缘空间，并支持具有对应能力的连续、分类和极坐标尺度。

两种策略只保护 `size` 表达的半径，不测量文字、描边、阴影、形状缩放或 `minimumSize` 的包围盒。多个图元共享尺度时，各端取最大需求；混合策略和共享分面在同一最终映射上满足约束。未知尺寸上界、缺少所需能力或无可行绘图区时会报错。

### 抖动

当同类观测挤在同一位置时，可以用 `placement.adjustments` 将点略微散开。下面的示例使用内置 `jitter`：它调整已经过比例尺映射的位置，原始数据和字段值保持不变。Data transform 中的 `jitter` 则派生数据字段，再由比例尺映射。

通过坐标系下拉框切换直角坐标与极坐标。直角坐标下，刻度间距比例将同组节点散布在分类间距内；输出单位直接指定比例尺映射后的总宽度。Plot 会为两端预留抖动半宽与节点外延，轴线保持绘图区边界，分类刻度随节点映射位置调整。极坐标下，刻度间距比例使用离散分类角度，输出单位使用连续数值角度。

`distribution` 默认为 `{ kind: 'uniform' }`，让偏移在整个范围内均匀散布。`{ kind: 'normal', sigma }` 使用零均值、截断在归一化 `[-1, 1]` 内的正态分布，因此点主要靠近类别中心，仍不会超出 `span` 的边界。`sigma` 相对于散布半宽表达：默认 `0.5`，值越小越集中，值越大越接近整个允许范围。

极坐标中的 x role 是角度。离散角度使用刻度间距比例：默认 `chord` 模式让抖动点沿相邻多边形顶点之间的直线边移动；连续角度使用数值输出单位并沿圆弧移动。两种模式都先合成角度，再按每条数据的 y 半径投影，所以外圈的屏幕位移更长，而不是统一的 `dx` / `dy`。示例通过径向 `domainPadding` 为散布空间和 Point 半径预留外侧距离。

## 错误与限制

- 位置通道须满足当前坐标系：内置一维坐标使用 `x`，二维使用 `x` 和 `y`。不能因为组件类型中属性可选，就省略坐标系需要的字段。
- 普通点的尺寸字段缺失、为 `null` 或不是有限数值时，该行不绘制点；负尺寸会报错。文本点走文字路径，不使用这条尺寸过滤规则。
- `shape` 的字段映射要求分类字段，连续或时间字段会报错。固定形状使用已注册的名称或参数化引用。
- `resolveLabel` 是运行时回调，使用时必须指定图元 `id`；回调不进入可序列化 IR。
- 同阶段的位置调整保持声明顺序；所有 role 阶段调整都在坐标投影前，screen 阶段都在投影后。内置 jitter 在 seed、有效行顺序、角色、宽度和离散刻度间距相同时才重现相同位置。

### 点的解析

点图元对应坐标系中的一个点，默认只依赖坐标系定位：坐标系将数据位置映射为绘图位置，点图元再在该位置生成一个 Node 节点。节点可以呈现为圆、星形或文字，其形状和外观由 Node 自身的属性决定，不随坐标空间的几何形式发生变形；显式方向对齐只额外改变节点的旋转角。

与需要连接多个顶点的 [PathMark](/viz/plot/mark/path) 不同，点图元不建立数据行之间的连接或顺序关系；与需要解释起止范围的 [IntervalMark](/viz/plot/mark/interval) 不同，它也不把坐标空间中的一段范围展开成几何区域。每条有效数据独立产生一个节点。数据变换、共享比例尺、留白求解或位置调整仍可以综合多行数据，但这些处理不改变点图元逐行生成节点的方式。

坐标系负责确定节点中心的位置，节点自身的形状随后在绘图空间中解析。例如，相同大小的圆点从直角坐标切换到极坐标后，中心按角度和半径重新定位，圆形不会随坐标网格弯曲成扇形。这里的独立性指投影完成后的节点形状；切换坐标系仍会影响位置、留白和投影前的位置调整。

点图元最终 lower（下沉转换）为 [Node](/kernel/components/node)。下面用同一个点展示定位、绘制和细节处理：上排为直角坐标，下排为极坐标；橙色点始终标记投影后的中心，灰色点线是定位辅助线。

<ComponentPreview files="point-projection" hideCode type="illustration" size="xxl" />

1. **定位**：输入归一化后，Plot 取得数据视图、执行变换并解析通道。位置字段先经过比例尺，再由坐标系投影到屏幕：直角坐标中由两个坐标分量确定位置，极坐标中由角度和半径确定位置。配置 placement 时，role 阶段在投影前调整，screen 阶段在投影后调整；留白与布局求解提供最终尺度和坐标帧。
2. **绘制**：每条有效数据在最终位置生成一个 Node，将尺寸、形状和颜色等通道结果交给节点。图中的矩形在两种坐标系下都保持 48 × 28 的屏幕尺寸，不会变成扇区。文字通道则生成文字节点，并应用 `dx`、`dy` 偏移。
3. **细节处理**：节点处理描边、文字、标签和锚点，最后编译为 Scene，由 SVG 或 Canvas 绘制。图中加粗描边并添加标签，中心不变；显式配置方向对齐时还会旋转节点，具体见下一节。无效位置或缺失文字会跳过相应行；普通点的尺寸字段缺失或非有限时跳过，负尺寸则报错。

### 方向对齐

坐标系除了能回答“这个点画在哪里”，还可以回答“从这里沿某个坐标方向走，应该朝哪边”。方向对齐就是利用这个信息，让节点跟着坐标方向旋转。

下面是启用坐标方向对齐后的整体流程：坐标系提供查询能力，PointMark 取得方向并合成角度，最后交给 Node 应用。

<ComponentPreview files="point-orientation-flow" hideCode type="flow" size="md" />

**1. 坐标系给出当前位置的方向**

以极坐标为例：保持半径不变、增加角度，点会沿着圆周移动。它在当前位置沿圆周前进的方向，就是角向的**切向**；与切向垂直的方向，就是**法向**。如果保持角度不变、增加半径，点则沿着从圆心向外的方向移动，这就是径向的切向。

因此，同一个位置可以查询不同坐标方向：内置极坐标用 `x` 表示角向、`y` 表示径向。坐标系通过 `tangentAt(role, mappedRoles)` 提供查询：传入要沿着哪个坐标方向，以及点当前的坐标参数，返回屏幕上的切向。法向由这个切向顺时针旋转 90° 得到，无需坐标系再提供一份。直角坐标的方向固定；极坐标和其他曲线坐标的方向可以随位置变化。

**2. 点图元查询自己所在位置的方向**

点图元先确定每条数据在坐标系中的位置，再根据 `orientation` 查询方向。例如 `role: 'x'`、`align: 'tangent'` 表示“取我当前位置的 x 切向”；改成 `align: 'normal'`，就使用对应的法向。

如果角向抖动改变了节点的角度，查询时会使用抖动后的角度，所以节点会跟着新位置转向。屏幕偏移只是在绘图结果上挪动节点，不改变它在坐标系中的方向参考。

**3. 把方向应用到 Node**

点图元将查询到的方向换算成旋转角，让节点原本朝右的方向与它对齐，然后加上用户设置的 `rotate`。最终位置和角度一起交给 Node；Node 负责旋转形状、文字及其连接边界。

可以在[形状示例](#形状)中选择“方向对齐”预设观察：长方形沿圆周切向摆放，改为 x 法向后，中心位置不变，长边转过 90°。再调整 `rotate`，就是在这个朝向上继续旋转。

默认的屏幕方向跳过上述查询，只使用 `rotate`。如果坐标系不支持方向查询，或当前位置没有唯一方向（例如圆心的角向、折线的尖点），显式请求方向对齐会报错。文字与形状使用同一规则，不会自动把倒置文字翻正。

## 图元引用

设置 Mark 的 `id` 和 `encodings.anchorId` 身份字段后，后面声明的 Path 可以通过 `mark + key` 连接其中一个节点。`key` 匹配最终数据行的身份值，不是拼接后的 Core id；固定模板或生成器则以其输出作为身份。数值 `1` 与字符串 `'1'` 视为同一身份，同一 Mark 内不得重复。用法见 [Path 图元目标](/viz/plot/mark/path#图元目标)。
