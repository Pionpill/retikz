title: IntervalMark
description: Define data intervals with IntervalMark and project them into bars, histograms, heatmaps, pie charts, and donut charts.
---

`IntervalMark` turns each row into a region. It determines the start and end of each dimension, then lets the coordinate system project that region. A category interval and a value interval form a bar; two category intervals form a heatmap cell; angular and radial intervals form a sector.

This page starts with bars, then covers series arrangements, continuous intervals, and polar sectors. See [channel binding](/viz/plot/channel/binding) for field syntax and [getting started](/viz/plot/get-start) for installation and host setup.

For a constant reference point, line, or region drawn once per view, use [independent annotations](/viz/plot/mark/annotation).

## Integration

The example plots revenue for three quarters. `x` binds the quarter and `y` binds revenue; each bar extends from a baseline of 0 to its value.

## Basic usage

### Position and direction

By default, `x` supplies a category band and `y` supplies an interval from 0 to the value. The band scale determines bar width; its `paddingInner` controls the gap between bars.

For horizontal bars, set `direction="horizontal"`, bind the numeric field to `x`, and bind the category field to `y`. In polar mode, the example uses angular categories and radial values, so the horizontal option is unavailable. Adjust corners, stroke, opacity, and labels to inspect the resulting appearance.

| Property                           | Meaning            | Details                                                             |
| ---------------------------------- | ------------------ | ------------------------------------------------------------------- |
| `x`, `y`                           | Position fields    | Field names or paths; angle and radius in polar coordinates         |
| `direction`                        | Bar direction      | Defaults to `vertical`; `horizontal` swaps category and value roles |
| `color`, `fill`                    | Region color       | `color` binds a field; `fill` accepts a field or constant           |
| `cornerRadius`                     | Rounded corners    | Decorates the projected region without changing the data interval   |
| `stroke`, `strokeWidth`, `opacity` | Stroke and opacity | Style the resulting region                                          |
| `label`                            | Data labels        | A field name, node label configuration, or ordered array            |

### Series arrangement

When a category contains multiple series, `group` identifies the arrangement groups and `color` controls coloring. `series` can also supply the groups and is used for color when `color` is omitted.

`dodge` divides the category band into adjacent sub-bands; `stack` accumulates values into adjoining intervals; `normalize-stack` converts each category to percentages before stacking. Changing coordinates changes the geometry while preserving these grouping and accumulation relationships.

| Property           | Meaning              | Details                                                                                   |
| ------------------ | -------------------- | ----------------------------------------------------------------------------------------- |
| `group`, `series`  | Series fields        | Identify series within each category; `group` takes precedence for arrangement            |
| `arrangement`      | Arrangement strategy | `dodge`, `stack`, or `normalize-stack`                                                    |
| `stackOffset`      | Stack baseline       | Ordinary stacks support `zero`, `normalize`, `diverging`, `center`, and `overlap`         |
| `stack`, `percent` | Shorthand            | Select stacking or percentage stacking; prefer `arrangement` to state the intent directly |

## Extended usage

### Continuous intervals

A histogram first uses a bin transform to produce bin starts, ends, and counts, then binds them with `x0`, `x1`, and `y`. IntervalMark draws the resulting intervals; the transform performs the binning.

When width represents data, `width` accumulates nonnegative weights in row order. For example, width can represent GDP while height represents cost, assigning adjacent continuous intervals to the rows. Switch the interval source to compare explicit endpoints with proportional widths. Both become angular intervals in polar coordinates.

| Property    | Meaning            | Details                                                                                     |
| ----------- | ------------------ | ------------------------------------------------------------------------------------------- |
| `x0`, `x1`  | Interval endpoints | Must be supplied together; expand to an `extent` in `bounds.x`                              |
| `y`         | Interval height    | Usually a count or aggregate value in a histogram                                           |
| `width`     | Proportional width | Accumulates in row order; negative values are rejected; cannot be combined with `x0` / `x1` |
| `transform` | Data preparation   | Applies transforms locally to the mark; this example uses PlotTransform before the layer    |

### Two-dimensional intervals

`bounds` specifies how each position dimension produces its interval. Five forms describe the boundary source:

| `kind`         | Meaning             | Details                                                                |
| -------------- | ------------------- | ---------------------------------------------------------------------- |
| `band`         | Category band       | Uses the full category bandwidth; `group` can divide it into sub-bands |
| `span`         | Baseline to value   | Extends from `baseline` (default 0) to the position field value        |
| `extent`       | Explicit endpoints  | Uses `from` / `to` fields for the two endpoints                        |
| `proportional` | Accumulated weights | Uses the nonnegative width `field` and accumulates in row order        |
| `full`         | Full range          | Covers the mapped range of the dimension                               |

A heatmap uses `bounds={{ x: { kind: 'band' }, y: { kind: 'band' } }}` to form a category grid. Changing the second dimension to `full` makes each region fill that dimension; rows sharing the first dimension then overlap. Switch to polar coordinates to turn the rectangular grid into a ring grid.

| Property | Meaning                        | Details                                                           |
| -------- | ------------------------------ | ----------------------------------------------------------------- |
| `bounds` | Per-dimension interval sources | Overrides the default x band / y span inference                   |
| `x`, `y` | Position fields                | Both bind category fields for a heatmap                           |
| `color`  | Value coloring                 | Maps each cell value to a color; disabling it uses a uniform fill |

### Pie and donut charts

`angle` binds a share field and accumulates angular intervals in row order, using the full radial range. Set `innerRadius` on the polar coordinate system to create a donut; it is a coordinate option, not an IntervalMark property.

`padAngle` leaves an angular gap between sectors, and `pull` moves a sector outward along its middle angle. The example includes pie, donut, and highlighted-sector presets, with controls for individual parameters.

| Property   | Meaning        | Details                                                    |
| ---------- | -------------- | ---------------------------------------------------------- |
| `angle`    | Share field    | Pie / donut shorthand for polar coordinates                |
| `padAngle` | Angular gap    | In degrees; shrinks the angular interval before projection |
| `pull`     | Outward offset | Nonnegative drawing units; accepts a field or constant     |
| `label`    | Sector labels  | Node label configuration with a field or explicit content  |

## Errors and limitations

- `x0` / `x1` must be paired and cannot be combined with horizontal direction or series arrangements.
- `width` cannot be combined with explicit `bounds`, `x0` / `x1`, or series arrangement settings. For custom layouts, precompute endpoints and use `extent`.
- `angle` cannot be combined with `x` / `y`, `x0` / `x1`, `width`, `direction`, stacking, or `bounds`.
- Explicit `bounds` cannot be combined with `direction`; express orientation through the bounds. Stacking requires `group` or `series` to identify segments, and `normalize-stack` rejects an additional `stackOffset`.
- Explicit `interpolation` and `pull` are only supported in polar2D. A custom coordinate system must implement `projectCell` to draw intervals.
- Invalid mapped positions and unrenderable projected geometry are skipped. The endpoint fields of an `extent` must be finite numbers or an error is raised. Negative proportional widths, accumulation overflow, and negative or non-finite outward offsets are also errors.
- `resolveLabel` is a runtime callback requiring a mark `id`; it is not serialized into IR. Projection generates the region shape, so Node geometry capabilities are not all exposed as IntervalMark properties.

## Implementation

### Interval resolution

The three marks use coordinates at different levels. PointMark primarily projects position while expressing shape and size in drawing space; orientation can be aligned separately. PathMark projects a connecting route, which can curve along continuous polar angles. IntervalMark projects the whole region, including its boundary and interior: a rectangular interval can become a sector. PathMark describes connecting lines and IntervalMark describes interval regions. A closed path can also be filled, but its region still follows its closure rule.

<ComponentPreview files="interval-resolution-flow" hideCode type="flow" size="md" />

Shorthand inputs are normalized first. Ordinary bars produce a category `band` and a value `span`; `x0` / `x1` become an `extent`; `angle` produces cumulative angular endpoints and a `full` radial interval. Series arrangements prepare grouped sub-bands or stack transforms. Scales then map each row's boundaries into a Cell: a logical region with a start and end for each position role.

The coordinate frame's `projectCell` takes that Cell and returns rectangle, sector, or contour geometry. IntervalMark builds a Node from it, attaches styles, data labels, and addressable anchors, then passes it to compilation and rendering.

The following snapshots follow the same interval through three geometric stages. The top row uses Cartesian coordinates and the bottom row uses polar coordinates. All columns retain the same interval endpoints.

<ComponentPreview files="interval-projection" hideCode type="illustration" size="xxl" />

1. **Find the axis normals**: at each interval endpoint, find the local direction perpendicular to the axis tangent. Orange arrows show normals to the x / angular axis; blue arrows show normals to the y / radial axis.
2. **Bound the projected region**: Cartesian construction lines are horizontal and vertical, enclosing a rectangle. In polar coordinates, angular endpoints define radial rays and radial endpoints define concentric arcs, enclosing an annular sector. The normal to the radial axis gives only the local tangent of that arc; extending it as a straight line would produce the wrong boundary.
3. **Paint the region**: apply fill, stroke, and rounded corners to the projected region. The original construction lines remain visible to show how rounding changes corners without changing the interval endpoints. Stroke is centered on the boundary, so a thick stroke can extend outside the region.

These construction lines explain the geometry. The implementation calculates rectangles or sectors directly from Cell interval endpoints; it does not construct normals or intersect helper lines. The generated shape handles rounded corners after projection. The bottom row uses curved `polar` boundaries.
