`<IntervalMark>` is not a "bar mark"; it is the interval mark. It builds intervals across one or more position roles for each datum, then lets the coordinate system project them: rectangles under cartesian coordinates, radial bars or sectors under polar coordinates.

With plain `x` / `y`, `x` is a band interval and `y` spans from baseline `0` to the value. With explicit `bounds`, each role can be declared as `band` / `span` / `extent` / `proportional` / `full`. In the tables below, `FieldName` means a data field name or field path, such as `quarter` / `sales.revenue`.

## Usage

```tsx
import { IntervalMark, Plot } from '@retikz/plot-react';
```

```tsx
<Plot data={revenue}>
  <IntervalMark x="quarter" y="value" />
</Plot>
```

A basic bar only needs `x` / `y`. Variable-width bars use `width` for proportional intervals; histograms use `x0` / `x1` for continuous intervals; heatmaps use `bounds` for double-band cells; pies and donuts use `angle` so the React DSL can accumulate angular extents.

### When to Use

IntervalMark is the low-level cell mark: it turns each data row into an orthogonal interval cell, then the coordinate system projects that cell into a rectangle, sector, or contour. Bars, histograms, heatmaps, radial bars, pies, and donuts are not separate low-level marks; they are presentation forms of the same IntervalMark under different `bounds`, `series`, `stack`, and `coordinate` settings.

| Form                   | Key props                                 | Meaning                                                                         |
| ---------------------- | ----------------------------------------- | ------------------------------------------------------------------------------- |
| Bar                    | `x` / `y`                                 | `x` provides the category slot; `y` spans from `0` to the value                 |
| Horizontal bar         | `direction="horizontal"`                  | `x` becomes the numeric length; `y` becomes the categorical band                |
| Variable-width bar     | `x` / `width`                             | `width` accumulates contiguous proportional intervals; `x` supplies axis labels |
| Grouped bar            | `arrangement="dodge"` / `group`           | Split one category slot into sub-bands by group                                 |
| Stacked bar            | `arrangement="stack"` / `group`           | A stack transform produces `y0` / `y1`; the value role becomes an extent        |
| Normalized stacked bar | `arrangement="normalize-stack"` / `group` | Normalize each category to percentages, then stack                              |
| Histogram              | `x0` / `x1` / `y`                         | `x0` / `x1` provide a continuous x interval; `y` provides the height            |
| Heatmap / grid         | `bounds`                                  | Both `bounds.x` and `bounds.y` are declared as `band`                           |
| Pie / donut            | `angle` / `coordinate`                    | `angle` accumulates into angular extents; the radial role uses full             |

## Examples

The first four examples can all switch between Cartesian and polar coordinates. The IntervalMark configuration stays the same: Cartesian coordinates usually project a cell as a rectangle, while polar coordinates project the same cell as a sector or annular grid.

### Basic Usage

`x` / `y` are the smallest bar form: `x` binds a categorical field, and `y` binds a numeric field. The coordinate system interprets the categorical field as a band and the numeric field as a span from `0` to the value.

Under Cartesian coordinates, `direction="horizontal"` swaps the category and value roles. Polar coordinates have no horizontal-bar semantics, so the polar branch keeps `x` as the angular band and `y` as the radial span.

The same playground also exposes gap, corner radius, opacity, stroke, labels, and shadow. These controls decorate the resulting core `Node` without changing the interval source.

### Series Arrangement

`arrangement` controls how multiple series share a categorical band: `dodge` creates adjacent sub-bands, `stack` accumulates continuous extents, and `normalize-stack` normalizes each category before stacking. `group` selects the arrangement groups, while `color` controls visual encoding.

Switching coordinates changes only the projection direction; dodge, stack, and normalized-stack relationships stay intact. `stackOffset` appears only for a regular stack and offers zero, normalized, diverging, centered, and overlapping baselines.

### Continuous Intervals

`x0` / `x1` define a continuous extent. Histogram mode first produces `binStart` / `binEnd` through a bin transform, then IntervalMark uses them as x intervals. Proportional mode uses `width` to allocate contiguous interval widths by GDP.

Under polar coordinates, the continuous x interval becomes a continuous angular interval while y remains the radial length. Switch the interval source in the controls; bin count appears only for the histogram branch, and horizontal / vertical padding still applies to the corresponding continuous scales.

### 2D Cells

`bounds` overrides the default inference. A heatmap needs both directions to be bands, so it writes `bounds={{ x: { kind: 'band' }, y: { kind: 'band' } }}` explicitly. Changing y to `full` makes every x band occupy the complete other dimension.

The same two-dimensional intervals form a rectangular grid under Cartesian coordinates and annular cells under polar coordinates. Disabling color mapping changes only the fill, not the cell boundaries.

### Pie and Donut

`angle` is the shortcut for pies and donuts: it accumulates a share field into angular extents, and the radial role uses full. A donut is not a new mark; it is a polar coordinate with `innerRadius`.

This shortcut is valid only in polar coordinates, so it does not expose an invalid coordinate switch. `padAngle` creates a real angular gap, while `pull` offsets a sector along its midline. The Pie, Donut, and Exploded presets below share one scene.

## How it works

<ComponentAlert
  type="tip"
  title="You can skip this section at first"
  description="Return when debugging how convenience props become bounds, group and stack ordering, or how coordinate frames create cell geometry."
/>

`<IntervalMark>` is not a bar-chart-only component. It describes intervals on each position role, then asks the active coordinate frame to project those intervals through `projectCell` into a rectangle, sector, or contour. Frames without cell projection support fail loudly.

The main path below stops at the IntervalMark boundary: convenience props or explicit `bounds` first normalize into intervals for each role, then position-scale outputs build a logical Cell. The active coordinate frame owns the resulting geometry.

<ComponentPreview files="interval-cell-flow" hideCode size="sm" />

`series` / `group` and `arrangement` prepare the fields and bounds needed for dodge, stack, or normalized stack before this path begins. After `projectCell`, cartesian coordinates commonly produce rects, polar coordinates produce sectors, and custom frames reuse the same Cell projection contract; only then does the geometry become a core `Node` layer.

`padAngle` shrinks a sector's angular bounds, while `pull` moves its center along the final bisector. Both affect projected visual geometry without rewriting source data.
