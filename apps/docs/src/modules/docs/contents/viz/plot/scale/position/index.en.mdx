---
title: Positional scales
description: Positional scales map a data value to a coordinate / length / radius — numeric axes (linear / log / sqrt / pow / symlog / radial), the time axis, and categorical axes (band / point).
---

Positional scales map a data value to a **coordinate / length / radius** on the canvas: the `x` / `y` position (`angle` / `radius` under polar) and the `size` channel's radius. By input field they fall into three kinds — continuous numbers, time, and categories. `<Plot>` auto-picks one from the field's measurement type, so common charts need none by hand.

## Positional scale types

| Type     | For                                      | Notes                                                                                           |
| -------- | ---------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `linear` | Continuous numbers                       | Evenly-spaced linear mapping (default)                                                          |
| `log`    | Positive values across magnitudes        | Logarithmic; `base` defaults to 10; point / line only                                           |
| `sqrt`   | Area-perceptual                          | Square-root; point / line only (the `size` channel's default)                                   |
| `pow`    | Custom power                             | Power mapping (needs `exponent`; via a full spec)                                               |
| `symlog` | Wide-range data crossing zero / negative | Symmetric log; `constant` defaults to 1; point / line only                                      |
| `radial` | Polar / rose chart radius                | Radial: output radius makes area proportional to value; usable as an interval / area value axis |
| `time`   | Temporal field                           | Continuous time mapping; ticks land on human-readable time boundaries                           |
| `band`   | Categorical (bars)                       | Each category gets an equal-width slot; marks sit in the center and can fill it                 |
| `point`  | Categorical (lines / scatter)            | Each category lands on an evenly-spaced point, no slot width                                    |

## Domain Padding

When a continuous positional scale (`linear` / `time` / `log` / `pow` / `sqrt` / `symlog` / `radial`) has no explicit `domain`, Plot infers the data min / max and pads both ends by 5% by default. That keeps single-point charts, all-positive scatter, and corner extrema from sitting directly on the coordinate frame.

Use `domainPadding={0}` to restore edge-to-edge behavior, or `domainPadding={{ lower: 0, upper: 0.1 }}` when only the upper side needs room. `singleValueSpan` controls the minimum span when all values are equal.

## Linear vs log

When data spans several orders of magnitude, a linear axis crushes the small values against the bottom. A log axis (`<Scale dimension="y" type="log" />`) gives every magnitude equal height, so small values stay legible. The default base is 10; set `base={Math.E}` for the natural logarithm. `base` must be greater than 1. Both charts use the same yearly user counts.

## Square root

`<Scale dimension="y" type="sqrt" />` maps by square root, taming the visual exaggeration of large values; it is also the default scale for the `size` channel (point radius), so a dot's **area** stays proportional to the data.

## Point / line only

`log` / `pow` / `sqrt` apply only to points and lines. Bars and areas start from a 0 baseline, and 0 is undefined on a log / power axis — pairing a non-linear scale with a bar / area errors out and tells you to use point / line instead.

## Symlog

`log` cannot handle zero or negatives, yet profit/loss, temperature deltas, and growth rates often cross zero _and_ span magnitudes. `<Scale dimension="y" type="symlog" />` uses a **symmetric log** — a linear region near zero with logarithmic tails on either side — so zero and negative values are defined. The width of the linear region is set by `constant` (default `1`; raise it to keep more of the center linear). On the positive side, `constant={50}` is equivalent to `ln(1 + x / 50)`. Like `log` / `sqrt` / `pow`, `symlog` is a non-linear scale and applies to point / line only.

## Radial

`radial` maps a value to a radius such that the **area** of a sector / ring (not the radius length) stays proportional to the value — exactly how a polar rose chart (Nightingale chart) encodes magnitude. It is a square-root-style mapping, but unlike `sqrt` it starts from a 0 baseline and is meant for the radius value axis, so it **is** allowed with interval / path-closure marks (rose-chart sectors or closed areas), whereas `sqrt` is not.

## Time axis

A temporal field (`temporal`) defaults to `time` on positional channels. It is a continuous mapping at heart, but ticks land on **human-readable time boundaries** (month starts, quarters, whole hours…) rather than evenly-spaced numbers, and labels are formatted as time instead of treating dates as raw numbers. Declare the field as `temporal` in the model and x goes through the time scale automatically — no `<Scale>` by hand.

Date values can be ISO strings (e.g. `'2024-01-01'`) or timestamps; the time scale parses them into positions on the axis. See [Data processing](/viz/data/model) for date field parsing details. Time is continuous too, so binding `color` to a temporal field derives the continuous band `sequential` — see [Color scales](/viz/plot/scale/color).

## Categorical axes: band and point

A categorical field (`categorical`) has no continuous numeric order; the positional scale's job is to spread a finite set of categories **evenly across position**. Position defaults to `band` (bars); lines and scatter use `point`.

| Type    | Placement                                                                                   | For                                    |
| ------- | ------------------------------------------------------------------------------------------- | -------------------------------------- |
| `band`  | Each category gets an equal-width slot; marks sit in the center and can fill the slot width | Bar charts (default)                   |
| `point` | Each category lands on an evenly-spaced point, no slot width                                | Categorical lines, categorical scatter |

Declare the field as `categorical` and the positional channel defaults to `band`: each category gets an equal slot, with the bar centered in it.

<ComponentPreview files={['scale-band', 'scale-band.data.ts']} />

<p className="text-sm text-muted-foreground">
  segment declared as categorical → x goes through band; five plan tiers split into equal slots.

Lines and scatter want points, not slots — there is no "width" between categories, so switch to `point` explicitly to land each category on an evenly-spaced point:

```tsx
<Plot data={rows} model={[{ name: 'segment', type: 'categorical' }]}>
  <PathMark x="segment" y="revenue" order="segment" />
  <Scale dimension="x" type="point" />
  <Axis dimension="x" />
</Plot>
```

Binding a categorical field to `color` goes through `ordinal` discrete coloring — see [Color scales](/viz/plot/scale/color).
