---
title: Positional Scales
description: Positional scales map numeric, temporal, and categorical fields to coordinates, lengths, or radii, with logarithmic, symmetric-log, area-aware, and categorical choices when the default linear mapping is not enough.
---

A positional scale answers where a field lands on the canvas, how long it is, or what radius it takes. `<Plot>` derives `linear`, `time`, or `band` defaults from the field type; switch scales explicitly when data spans magnitudes, crosses zero, encodes area, or needs categorical points instead of slots.

## Choosing a scale

| Data and task                                   | Recommended scale | Key distinction                               |
| ----------------------------------------------- | ----------------- | --------------------------------------------- |
| Ordinary continuous numbers                     | `linear`          | Evenly spaced and the default                 |
| All-positive values spanning magnitudes         | `log`             | Equal distance per order of magnitude         |
| Non-negative values where large values dominate | `sqrt`            | Compress large differences with a square root |
| Wide-range values crossing zero                 | `symlog`          | Linear near zero, logarithmic in the tails    |
| Polar radius whose area represents value        | `radial`          | Allows interval / closed-area baselines       |
| Temporal field                                  | `time`            | Ticks land on human-readable boundaries       |
| Categorical bars / categorical lines            | `band` / `point`  | A slot with width / a single point            |

`pow` supplies a custom exponent, but the current React `<PlotScale>` does not expose that type; configure it through the full `IRPlot.scales` surface.

## Continuous numbers

`linear`, `log`, `sqrt`, and `symlog` share one interactive chart. Choose a dataset in the controls, then switch the scale and tune its parameters to inspect the mapping directly.

| Type                | Suited data                                | Key behavior and options                                                                                |
| ------------------- | ------------------------------------------ | ------------------------------------------------------------------------------------------------------- |
| `linear`<br />`log` | ordinary values; positive values by orders | `log` spaces each order evenly; `base` defaults to `10`, must be greater than `1`, and accepts `Math.E` |
| `sqrt`<br />`pow`   | reduce large values; custom exponent       | `sqrt` uses a fixed square root; configure `pow.exponent` in the full spec                              |
| `symlog`            | wide-range values that cross zero          | stays linear near zero; `constant` defaults to `1`, and larger values widen the linear region           |

The `size` channel also uses `sqrt` so point area tracks magnitude, but that mapping belongs to [Built-in Channels](/viz/plot/channel/builtin) and is not configured by the positional `<PlotScale dimension>` API.

### Radial

`radial` maps values to radii so the **area** of a sector or ring stays proportional to the value. It starts from a zero baseline and is designed for the polar radial value axis, so it can be used with intervals and path closures; the square-root-style `sqrt` scale cannot.

### Non-linear scales and baselines

`log`, `pow`, `sqrt`, and `symlog` cannot be the value axis for bars, areas, or path closures because those marks also map a baseline. Use an open point / line mark or retain a linear value axis. `radial` is the explicit exception because it owns an area-aware zero baseline.

## Time

A `temporal` field defaults to `time` on positional channels. It remains continuous, but ticks land on month starts, quarters, whole hours, and other readable boundaries, while labels are formatted as time. Declare the field as `temporal` in the model and no `<PlotScale>` is needed.

<ComponentPreview
  size="lg"
  files={['scale-time', 'scale-time.data.ts']}
  caption="The x channel does not declare PlotScale explicitly; the temporal model field derives a time scale and formats quarterly dates at readable time boundaries."
/>

Dates can be ISO strings or timestamps. See [Data Intake](/viz/data/model/intake) for parsing rules. Binding a temporal field to `color` derives a continuous `sequential` band; see [Color Scales](/viz/plot/scale/color).

## Categories: band and point

Categorical fields have no continuous numeric order. The default `band` scale gives each category a slot with width, which suits bars. Categorical lines and scatter need positions rather than slots, so switch explicitly to `point`.

| Type    | Placement                                   | Suited marks                  |
| ------- | ------------------------------------------- | ----------------------------- |
| `band`  | One slot per category, with available width | bars and heatmap cells        |
| `point` | One evenly spaced point, with no slot width | categorical lines and scatter |

<ComponentPreview
  size="lg"
  files={['scale-band', 'scale-band.data.ts']}
  caption="Switch scales: band supplies bandwidth to intervals, while point provides evenly spaced positions for lines and points; the panel only shows padding for the current type."
/>

A categorical line can opt into point positions:

```tsx
<Plot data={rows} model={[{ name: 'segment', type: 'categorical' }]}>
  <PathMark x="segment" y="revenue" order="segment" />
  <PlotScale dimension="x" type="point" />
  <PlotAxis dimension="x" />
</Plot>
```

## How it works

A positional scale gains its full context during lowering. In the figure, `derive` combines the field type, mark structure, and an explicit `<PlotScale>` to select a type. `validate` then checks field compatibility, valid domains, and baseline constraints. The resolver takes a domain from bound data or explicit configuration and a range from the available coordinate extent.

<ComponentPreview files="scale-position-flow" size="xs" hideCode />

The resolved scale serves both marks and guides: continuous scales output numeric coordinates, `band` also supplies bandwidth, and `point` supplies discrete positions only. Axis ticks come from that same resolved scale, so mark positions, bandwidth, and axes do not maintain separate mappings.

## API Reference

React `<PlotScale>` is the declaration surface for common positional types. A `band` scale can be derived from interval structure or configured explicitly for bar gaps and outer padding. `pow` and complete IR fields belong in `IRPlot.scales`. `PlotAxis.scale` is a shortcut for common types on the same dimension.

| Prop               | Type                                | Default        | Description                                                                    |
| ------------------ | ----------------------------------- | -------------- | ------------------------------------------------------------------------------ |
| `dimension`        | `'x' \| 'y'`                        | —              | Coordinate dimension; polar uses `x` / `y` for angular / radial roles          |
| `type`             | `PlotScaleProps['type']`            | —              | `linear`, `time`, `band`, `point`, `log`, `sqrt`, `symlog`, or `radial`        |
| `domain?`          | `PlotScaleProps['domain']`          | inferred       | Continuous input extent, or an ordered category list for `band` / `point`      |
| `domainPadding?`   | `PlotScaleProps['domainPadding']`   | `5%` inferred  | Fractional padding around continuous domains; explicit domains default to 0    |
| `singleValueSpan?` | `PlotScaleProps['singleValueSpan']` | type-derived   | Minimum span used to expand a single-value domain                              |
| `base?`            | `PlotScaleProps['base']`            | `10`           | `log` only; must be greater than `1`                                           |
| `constant?`        | `PlotScaleProps['constant']`        | `1`            | `symlog` only; controls the width of the linear region around zero             |
| `paddingInner?`    | `number`                            | `0.1`          | `band` only; gap between adjacent bands as a fraction of step, from `0` to `1` |
| `paddingOuter?`    | `number`                            | `paddingInner` | `band` only; outer padding as a fraction of step, from `0` to `1`              |
| `padding?`         | `number`                            | `0.5`          | `point` only; outer padding as a fraction of step, from `0` to `1`             |
| `align?`           | `number`                            | `0.5`          | `band` / `point`; distributes outer padding across both ends, from `0` to `1`  |

The complete `IRPlotScale` surface can also name a scale, set an output `range`, and configure fields that the React DSL does not expose, including `pow.exponent`, `nice`, and `clamp`. These `IRPlot*` types and schemas come from `@retikz/plot`; every variant and custom scale operation follows this public IR contract.
