Annotations use geometric elements to mark information in the plotting area, such as target points, reference lines, and background regions. They share the geometric drawing capabilities of marks and come in the same three types: point, path, and interval.

Annotation positions pass through Plot scales and [coordinates](/viz/plot/coordinate). Constants without `transforms` produce one instance in the current view. A field binding or explicit `transforms` produces one complete geometry per result row. The three entry points are:

| Geometry               | React                | Vanilla              | Source IR                              |
| ---------------------- | -------------------- | -------------------- | -------------------------------------- |
| Point or text          | `PointAnnotation`    | `pointAnnotation`    | `type: 'point', kind: 'annotation'`    |
| Explicit endpoint path | `PathAnnotation`     | `pathAnnotation`     | `type: 'path', kind: 'annotation'`     |
| Bounded region         | `IntervalAnnotation` | `intervalAnnotation` | `type: 'interval', kind: 'annotation'` |

## Using annotations

All three Annotation types support the following position inputs, which can be mixed within one geometry:

| Input      | Syntax                                 | Meaning                                                                                                          |
| ---------- | -------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| Constant   | `properties.position.x: 50` or `'A'`        | A fixed data-space position; strings are always literal values                                                   |
| Data field | `{ field: 'name' }`                    | Reads a field from the current result row                                                                        |
| View edge  | `{ edge: 'start' }`, `{ edge: 'end' }` | The endpoints of the coordinate role's final mapped range; they follow range reversal, not data minima or maxima |

Local `transforms` uses the same declarations as Mark. It consumes root-transformed data, or the current partition inside a facet. Use an [aggregation transform](/viz/data/transforms/aggregation-annotation) to calculate statistics, then bind the output fields to positions. The local chain does not change sibling data views.

| Declaration                                  | Instance count                                   |
| -------------------------------------------- | ------------------------------------------------ |
| Constants or edges, with `transforms` omitted | One per current view                             |
| Any field encoding is present            | One per result row                               |
| Explicit `transforms`, including `[]`         | One per result row, even with constant positions |

An empty result produces no data-bound annotations. Styles, text, and labels remain constant; fields bind positions.

This example binds an empty array and specifies both scale domains. It still draws one reference line, one background region, and one text point: row count does not determine annotation count.

## Point annotations

A point annotation draws a shape or text at a specified position. It uses the shape, appearance, and label capabilities of point marks, with data-bindable positions and constant text content. With `text`, the text itself is the point annotation. With `label`, text attaches to the shape with a configurable direction and gap.

Annotation-specific properties include:

| Property   | Purpose                                                                                        |
| ---------- | ---------------------------------------------------------------------------------------------- |
| `x`        | Position binding for the first coordinate role                                                 |
| `y`        | Position binding for the second coordinate role                                                |
| `position` | Complete role mapping, mutually exclusive with the `x` and `y` shorthand; use for custom roles |

Use the preset selector to switch between geometry and text only. Geometry supports size and attached labels; text supports font size. All demos start in Cartesian coordinates and also offer polar coordinates with continuous or discrete angles. Continuous mode maps the horizontal position from 0–100 to 0–360°; discrete mode uses categories A–F.

## Path annotations

A path annotation specifies two complete positions with `from` and `to`, for reference lines and connections between points. Both endpoints pass through scales and coordinate projection. Strokes and labels use the existing path drawing capabilities.

Annotation-specific properties include:

| Property     | Purpose                                                                                                   |
| ------------ | --------------------------------------------------------------------------------------------------------- |
| `from`       | Complete role mapping for the start                                                                       |
| `to`         | Complete role mapping for the end                                                                         |
| `connection` | Defaults to `coordinate`, following coordinate geometry; `straight` connects projected endpoints directly |

The default view shows a horizontal connection in Cartesian coordinates. Switch to continuous-angle polar coordinates, then change the connection mode to turn the blue arc into a chord while the orange endpoints stay in place. With discrete angles, coordinate connections pass through intermediate categories: A→C passes through B. Straight connections join only the endpoints. Move the label to see it follow the current path.

`connection` also applies to custom coordinates, which provide the coordinate-following geometry. This entry describes a path between two endpoints and has no data-series, ordering, or missing-value connection settings. See [path marks](/viz/plot/mark/path) for path labels.

To span the plotting area, use `{ edge: 'start' }` and `{ edge: 'end' }` for the corresponding endpoint role, as in the horizontal reference line in the entry example. These follow the endpoints of the role's final mapped range, including reversal; they do not mean the data minimum and maximum.

`PathAnnotation` binds both endpoints to the same result row. The example uses `summarize` to calculate a y statistic and the minimum and maximum x values. Grouping produces two rows and two independent reference lines; endpoints from separate groups are never joined. Blue and orange distinguish the groups, with each reference line matching its observations. In polar coordinates, each reference line follows an arc at a fixed radius.

Enable “Span the full horizontal view” to replace the x fields with edges while keeping y bound to the statistic. Data extents and full-view spans are expressed explicitly by different position inputs.

## Interval annotations

An interval annotation specifies a start and end for each coordinate role and projects that region into the plotting area. It forms a rectangle in Cartesian coordinates and can form a sector or annular sector in polar coordinates. Fill, stroke, and labels use the interval mark drawing capabilities.

Annotation-specific properties include:

| Property     | Purpose                                                                                       |
| ------------ | --------------------------------------------------------------------------------------------- |
| `x`          | First role's `{ from, to }` range                                                             |
| `y`          | Second role's `{ from, to }` range                                                            |
| `bounds`     | Complete role bounds, mutually exclusive with the `x` and `y` shorthand                       |
| `connection` | Defaults to `coordinate`, following coordinate boundaries; `straight` joins projected corners |

Adjust the horizontal endpoints to change the region's width. Enable “Full vertical range” to use `edge` for the vertical bounds. Place the label above, at the center, or below the region.

Every role needs a range; omitting a role does not span it automatically. See [interval marks](/viz/plot/mark/interval) for region shapes and boundaries.

With discrete angles, the default B–E interval follows C and D along both boundaries, forming a polygon. In `straight` mode, only the four projected corners are connected; opposite angles can make them collinear and collapse the region. Paths and intervals follow mapped endpoint order without selecting a shortest route across the seam.

Each `IntervalAnnotation` boundary can bind a field. The example computes minimum and maximum values for x and y to draw the observed extent. Grouping creates one region per group, using blue and orange to match the observations, with a fill opacity of 0.2. Switching x to edges spans the full view width while preserving each region’s data-driven y extent. In polar coordinates, regions follow their angular and radial extents.

## Additional notes

- Root Plot `data` and its actual binding are required, even with only annotations. An explicit empty array is valid, but scales still need usable domains.
- Data-bound annotations use the Mark `dataExecution.marks` policy. Transforms requiring an external executor use asynchronous preparation. Independent annotations execute no local data chain and produce no datum lineage; data-bound annotations support result-row and aggregate-source queries.
- `contributeToDomain` defaults to `false`. When enabled, constants and final result-row positions contribute to scale domains; `edge` values never do.
- Missing or unknown roles, unmappable positions, and unsupported coordinate projections produce errors. Demo colors, opacity, and explicit domains are presentation settings.
