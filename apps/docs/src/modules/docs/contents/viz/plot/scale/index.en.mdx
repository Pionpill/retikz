title: Scales
description: 'Scales connect field semantics to visual output: position and color are the main choice points; size and opacity can synthesize or reference scales, while shape currently synthesizes an ordinal glyph mapping only.'
---

A scale decides what a data value becomes on the canvas. Position channels turn fields into coordinates, lengths, or radii, while color and other visual channels turn fields into color, size, opacity, or shape. `<Plot>` first picks common defaults from the field type and mark structure; specialized semantics remain explicit.

A scale maps values but does not explain the mapping to the reader. [Axes](/viz/plot/guide/axis) display positional ticks, while [legends](/viz/plot/guide/legend) can explain color, size, opacity, and shape. Brand palettes and domain-specific mappings beyond the built-ins go through [custom scales](/viz/plot/extend/scale).

## Responsibilities

| Family                | Mapping it owns                                               | Configuration entry                               |
| --------------------- | ------------------------------------------------------------- | ------------------------------------------------- |
| Positional            | numeric / temporal / categorical → coordinate, length, radius | this section's position page; `<Scale dimension>` |
| Color                 | categorical / continuous / temporal → discrete color or band  | this section's color page; color field binding    |
| Other visual channels | numeric / categorical → size, opacity, shape                  | [Built-in Channels](/viz/plot/channel/builtin)    |

All three entry points follow the same path: establish the field's measurement type, decide whether the default mapping is enough, then hand the scale output to coordinate projection, mark channels, and guides. React's `<Scale dimension>` configures positional dimensions only. `size` can reference `sqrt` and `opacity` can reference `linear`; mark channels can also synthesize both. `shape` currently uses only the channel-generated `ordinal` glyph mapping and does not accept an explicit scale reference.

Common automatic defaults are:

| Field type    | Positional default | Color default (per-datum marks) |
| ------------- | ------------------ | ------------------------------- |
| `continuous`  | `linear`           | `sequential`                    |
| `temporal`    | `time`             | `sequential`                    |
| `categorical` | `band`             | `ordinal`                       |

Automatic defaults cover the common path only. Categorical lines and scatter switch position to `point`; position data spanning magnitudes, crossing zero, or encoding area calls for `log`, `symlog`, `sqrt`, or `radial`. Color with a meaningful midpoint uses `diverging`, while business thresholds and data quantiles use explicit scales such as `threshold` and `quantile`.

For other visual channels, continuous `size` defaults to the area-aware `sqrt`, continuous `opacity` uses `linear`, and categorical `shape` uses `ordinal`. These mappings belong to channel resolution; they do not make size, opacity, or shape valid targets for `<Scale dimension>`.

The React DSL still writes polar dimensions as `x` / `y`: `x` means angular and `y` means radial under a polar coordinate. The two pages below cover the full choice set, valid inputs, and the React / full-spec boundary. See the [Field Contract](/viz/data/model/contract) for declaring measurement types.
