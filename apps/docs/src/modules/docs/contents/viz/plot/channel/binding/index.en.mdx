---
title: Channel Binding
description: Channel binding explains how fields or fixed values control visual results such as position, color, size, shape, and text.
---

A dataset can produce many different graphics because the data itself does not specify how each field should appear. Channels connect **data to visual properties** in the grammar of graphics. Position, color, size, shape, and text are ways a graphic can carry information; a channel binding assigns a field or fixed value to one of those properties.

For example, a row might describe a region's GDP, life expectancy, and population. After choosing a point to represent the row, you can bind GDP to `x`, life expectancy to `y`, and population to `size`. Readers can then compare the data through point positions and sizes instead of reading every number. One field can also drive several channels, such as using both color and shape to distinguish regions.

Channels work alongside the other parts of the grammar:

| Part                                | Responsibility                                                      | In this example                                                                     |
| ----------------------------------- | ------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| Data                                | Supplies records and field values                                   | Each row contains GDP, life expectancy, population, and region                      |
| [Marks](/viz/plot/mark)             | Choose the drawing form used to represent records                   | Represent each record with a point                                                  |
| [Scales](/viz/plot/scale)           | Convert data values into drawable position values, colors, or sizes | Convert population counts into suitable point radii                                 |
| [Coordinates](/viz/plot/coordinate) | Interpret position channels and project them onto the drawing       | Interpret `x` and `y` as horizontal and vertical positions in Cartesian coordinates |

Thus, binding `population` to `size` declares that population controls size. The scale determines the actual size, and the mark determines the drawing form. Changing bindings lets the same data and marks express different comparisons.

Import components from `@retikz/plot-react` and declare field bindings on `PointMark`.

```tsx
import { Plot, PlotAxis, PlotScale, PointMark } from '@retikz/plot-react';
import { createRoot } from 'react-dom/client';

const rows = [
  { gdp: 400, life: 76, region: 'A', population: 8 },
  { gdp: 900, life: 81, region: 'B', population: 16 },
  { gdp: 1600, life: 84, region: 'A', population: 28 },
];

createRoot(document.getElementById('plot')!).render(
  <Plot data={rows} width={360} height={220}>
    <PlotScale dimension="x" type="linear" domainPadding={{ kind: 'ratio', lower: 0.15, upper: 0.15 }} />
    <PlotScale dimension="y" type="linear" domainPadding={{ kind: 'ratio', lower: 0.15, upper: 0.15 }} />
    <PointMark x="gdp" y="life" color="region" size="population" />
    <PlotAxis dimension="x" />
    <PlotAxis dimension="y" />
  </Plot>,
);
```

Import the configuration type from `@retikz/plot` and pass the IR to the React `Plot` through `spec`.

```tsx
import { Plot } from '@retikz/plot-react';
import type { IRPlot } from '@retikz/plot';
import { createRoot } from 'react-dom/client';

const rows = [
  { gdp: 400, life: 76, region: 'A', population: 8 },
  { gdp: 900, life: 81, region: 'B', population: 16 },
  { gdp: 1600, life: 84, region: 'A', population: 28 },
];

const spec: IRPlot = {
  namespace: 'plot',
  type: 'plot',
  data: { reference: 'rows' },
  scales: [
    { type: 'linear', name: 'x', domainPadding: { kind: 'ratio', lower: 0.15, upper: 0.15 } },
    { type: 'linear', name: 'y', domainPadding: { kind: 'ratio', lower: 0.15, upper: 0.15 } },
  ],
  coordinate: { type: 'cartesian2D', x: 'x', y: 'y' },
  marks: [
    {
      type: 'point',
      encoding: { x: { field: 'gdp' }, y: { field: 'life' } },
      color: { kind: 'field', value: 'region' },
      size: { kind: 'field', value: 'population' },
    },
  ],
  guides: [
    { type: 'axis', dimension: 'x' },
    { type: 'axis', dimension: 'y' },
  ],
};

createRoot(document.getElementById('plot')!).render(<Plot spec={spec} data={{ rows }} width={360} height={220} />);
```

## Fields and constants

Channels have two binding forms: a **field channel** reads a named field from each data row, while a **constant channel** uses a fixed value from the configuration. Choose between them based on whether the visual property should vary with the data.

| Form             | Value source and effect                                                                                                   | When to use it                                                                                  | Binding syntax                                                                   |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| Field channel    | Reads a field from each row, then applies the channel and scale rules; records can have different positions or styles     | Compare values by position, distinguish categories by color, or express quantities through size | Position: `{ field: 'gdp' }`; point color: `{ kind: 'field', value: 'region' }`  |
| Constant channel | Always reads the same configured value without reading a data field; the corresponding position or style stays consistent | Draw a fixed threshold line or give every point the same color                                  | Position: `{ value: 80 }`; point color: `{ kind: 'constant', value: 'crimson' }` |

The table shows explicit Vanilla / IR bindings. The entry tabs above provide complete mark configurations and React shorthand. Constant positions still pass through scales and coordinates: binding a reference line’s `y` to `80` means the data value 80, not 80 pixels from the top of the canvas. Each mark accepts only the channels and binding forms it supports.

| Property | Example                                   | Effect and constraint                                                           |
| -------- | ----------------------------------------- | ------------------------------------------------------------------------------- |
| `x`      | `"gdp"`                                   | Field for horizontal point position                                             |
| `y`      | `"life"`                                  | Field for vertical point position                                               |
| `color`  | `"region"` or an explicit constant        | Color by category or use one color                                              |
| `size`   | `"population"` or `12`                    | Map numeric values to radii or use a fixed radius; negative values are rejected |
| `shape`  | `"region"` or an explicit circle constant | Assign shapes by category; the field must be categorical                        |
| `label`  | `"abbr"`                                  | Add field-based labels to points                                                |

Use the panel to switch the `x` / `y` fields and change color, size, or shape from field-driven values to constants. The chart structure stays fixed, so each action isolates the effect of the selected binding.

One row can bind to several channels at once: `gdp` and `life` determine position, `region` determines color and shape, `population` determines point radius, and `abbr` supplies labels. When a style switches to a constant, that data field no longer participates in the corresponding visual calculation.

`PlotAxis` uses position channels to display coordinate ticks. This playground only mounts color and size legends, so switching either channel to a constant removes its `PlotLegend`. The full API can also add legends for field-driven opacity and shape channels.

## Errors and limitations

- **Strings match fields first.** React built-in flat style props such as `color` first match a field in the current dataset or model, then try a valid constant. If neither accepts the string, the prop is skipped with a warning. This is not a fallback for missing values in individual rows.
- **Make fixed styles unambiguous.** If a `crimson` field exists, `color="crimson"` reads it. Use `color={{ kind: 'constant', value: 'crimson' }}` for one fixed color. Explicit IR uses `color: { kind: 'constant', value: 'crimson' }`.
- **Position and style objects differ.** IR position bindings live in `encoding` and use `{ field }` or `{ value }`. Point color and size live on the mark and use `{ kind, value }`.
- **Exact field keys take precedence.** If both a direct `"metrics.gdp"` property and nested `metrics.gdp` exist, the direct property wins. Dotted traversal only applies when the complete key is absent. Ensure bound fields contain valid values.
- **Each mark defines supported channels.** `PointMark` `x` / `y` props require field names. Strings in custom `channels` also mean fields; constants use explicit `{ kind: 'constant', value }`.
- **Scales provide padding.** `domainPadding` expands the data domain. Larger points or labels may require more padding; channel binding does not automatically prevent overflow.
