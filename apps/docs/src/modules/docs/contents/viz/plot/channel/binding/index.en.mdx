title: Channel Binding
description: Bind data fields with encodings and set fixed positions and appearance with properties.
---

A dataset can produce many different graphics because the data itself does not specify how each field should appear. Channels connect **data to visual properties** in the grammar of graphics. Position, color, size, shape, and text are ways a graphic can carry information; a channel binding assigns a data field to one of those properties. Fixed appearance is configured separately.

For example, a row might describe a region's GDP, life expectancy, and population. After choosing a point to represent the row, you can bind GDP to `x`, life expectancy to `y`, and population to `size`. Readers can then compare the data through point positions and sizes instead of reading every number. One field can also drive several channels, such as using both color and shape to distinguish regions.

Channels work alongside the other parts of the grammar:

| Part                                | Responsibility                                                      | In this example                                                                     |
| ----------------------------------- | ------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| Data                                | Supplies records and field values                                   | Each row contains GDP, life expectancy, population, and region                      |
| [Marks](/viz/plot/mark)             | Choose the drawing form used to represent records                   | Represent each record with a point                                                  |
| [Scales](/viz/plot/scale)           | Convert data values into drawable position values, colors, or sizes | Convert population counts into suitable point radii                                 |
| [Coordinates](/viz/plot/coordinate) | Interpret position channels and project them onto the drawing       | Interpret `x` and `y` as horizontal and vertical positions in Cartesian coordinates |

Thus, binding `population` to `size` declares that population controls size. The scale determines the actual size, and the mark determines the drawing form. Changing bindings lets the same data and marks express different comparisons.

## Using this topic

Complete installation in [Quick start](/viz/plot/get-start). This example binds position, color, and size using three illustrative rows. The result is three points with different positions, colors, or sizes. Both position scales use `domainPadding` to leave room around boundary points.

<DocTab value="react-jsx" label="React + JSX">

Import components from `@retikz/plot-react` and declare field bindings on `PointMark`.

```tsx
import { Plot, PlotAxis, PlotScale, PointMark } from '@retikz/plot-react';
import { createRoot } from 'react-dom/client';

const rows = [
  { gdp: 400, life: 76, region: 'A', population: 8 },
  { gdp: 900, life: 81, region: 'B', population: 16 },
  { gdp: 1600, life: 84, region: 'A', population: 28 },
];

createRoot(document.getElementById('plot')!).render(
  <Plot data={rows} width={360} height={220}>
    <PlotScale dimension="x" type="linear" domainPadding={{ kind: 'ratio', lower: 0.15, upper: 0.15 }} />
    <PlotScale dimension="y" type="linear" domainPadding={{ kind: 'ratio', lower: 0.15, upper: 0.15 }} />
    <PointMark
      encodings={{ position: { x: { field: 'gdp' }, y: { field: 'life' } }, color: 'region', size: 'population' }}
    />
    <PlotAxis dimension="x" />
    <PlotAxis dimension="y" />
  </Plot>,
);
```

Import the configuration type from `@retikz/plot` and pass the IR to the React `Plot` through `spec`.

```tsx
import { Plot } from '@retikz/plot-react';
import type { IRPlot } from '@retikz/plot';
import { createRoot } from 'react-dom/client';

const rows = [
  { gdp: 400, life: 76, region: 'A', population: 8 },
  { gdp: 900, life: 81, region: 'B', population: 16 },
  { gdp: 1600, life: 84, region: 'A', population: 28 },
];

const spec: IRPlot = {
  namespace: 'plot',
  type: 'plot',
  data: { reference: 'rows' },
  scales: [
    { type: 'linear', name: 'x', domainPadding: { kind: 'ratio', lower: 0.15, upper: 0.15 } },
    { type: 'linear', name: 'y', domainPadding: { kind: 'ratio', lower: 0.15, upper: 0.15 } },
  ],
  coordinate: { type: 'cartesian2D', x: 'x', y: 'y' },
  marks: [
    {
      type: 'point',

      encodings: { position: { x: { field: 'gdp' }, y: { field: 'life' } }, color: 'region', size: 'population' },
    },
  ],
  guides: [
    { type: 'axis', dimension: 'x' },
    { type: 'axis', dimension: 'y' },
  ],
};

createRoot(document.getElementById('plot')!).render(<Plot spec={spec} data={{ rows }} width={360} height={220} />);
```

The explicit `data.reference` must match the dataset name `rows`. All four entries express the same bindings. React dimensions specify the drawing area; Vanilla render options also specify SVG output dimensions, so outer bounds may differ.

## Encodings and fixed properties

`encodings` selects fields to read; `properties` supplies fixed values. React, Vanilla, and JSON use the same groups. Named components and factories supply `type` and `kind`; JSON marks declare both explicitly.

| Target              | Field encoding                           | Fixed property                                        |
| ------------------- | ---------------------------------------- | ----------------------------------------------------- |
| Horizontal position | `encodings.position.x: { field: 'gdp' }` | `encodings.position.x: { value: 400 }`                |
| Color               | `encodings.color: 'region'`              | `properties.color: 'crimson'`                         |
| Size                | `encodings.size: 'population'`           | `properties.size: 12`                                 |
| Shape               | `encodings.shape: 'region'`              | `properties.shape: 'circle'`                          |
| Label content       | `encodings.label: { content: 'abbr' }`   | `properties.label: { content: 'A', position: 'top' }` |

Write a field name for an ordinary binding. To select a declared scale, use `{ field: 'population', scale: 'populationSize' }`. Coordinates own position scales. Use `{ field: 'gdp' }` to bind a position field, `{ value: 80 }` for a constant, or an edge for a view boundary.

Fixed positions remain in data space: `encodings.position.y: { value: 80 }` means the data value 80, which passes through scale and coordinate projection. `{ edge: 'start' }` and `{ edge: 'end' }` refer to the final view range edges; see [annotations](/viz/plot/mark).

An encoding wins over a fixed property at the same target. Missing fields or failed scale mappings raise errors instead of falling back to the fixed property. Other targets remain independent: encoding `opacity.overall` preserves fixed `opacity.fill` and `opacity.stroke` factors.

One row can bind to several channels at once: `gdp` and `life` determine position, `region` determines color and shape, `population` determines point radius, and `abbr` supplies labels. When a style switches to a constant, that data field no longer participates in the corresponding visual calculation.

`PlotAxis` uses position channels to display coordinate ticks. This playground only mounts color and size legends, so switching either channel to a constant removes its `PlotLegend`. The full API can also add legends for field-driven opacity and shape channels.

## Errors and limitations

- Strings in `encodings` always name fields; strings in `properties` always supply fixed values. Their meaning does not depend on the dataset.
- Exact field keys take precedence: a direct `"metrics.gdp"` property wins over a nested object. Dotted traversal applies only when the complete key is absent.
- Each mark accepts its declared encoding targets. Custom channels also register under `encodings`, without a separate `channels` dictionary.
- `transforms` runs local data operations for this mark. Plot root operations still use `transform`. Bound fields must exist in the local result.
