基础表格契约定义所有表型共享的顶层身份与 Cell 内容，并提供 manual / custom 精确根变体。detail 专有的数据引用与列结构见[明细表契约](/viz/table/reference/contract-detail)；Cell box、轨道和 border 配置见[布局契约](/viz/table/reference/contract-layout)。

## IRTable 根

`IRTable` 是 `IRDetailTable | IRManualTable | IRCustomTable` 的聚合类型。三个变体共享 `namespace + type`，再分别约束 `data` 与 `structure`。

| 字段                  | 类型                                | 默认值     | 描述                                             |
| --------------------- | ----------------------------------- | ---------- | ------------------------------------------------ |
| `namespace`           | `'table'`                           | —          | Tier 2 composite 命名空间                        |
| `type`                | <ApiValues name="TableComposite" /> | —          | 顶层 Table node type                             |
| `id?`                 | `string`                            | —          | 可选稳定 id                                      |
| `appearanceDefaults?` | `IRTableAppearanceDefaults`         | `{}`       | 已存在 body / columnHeader Cell 的稀疏外观默认值 |
| `layout?`             | `IRTableLayout`                     | 轨道默认值 | 轨道、稀疏覆盖、gap 与 border                    |
| `meta?`               | `JsonObject`                        | —          | lowering 原样保留的 JSON-safe 元数据             |
| `rules?`              | `Array<IRTableCellRule>`            | `[]`       | 按声明顺序应用的 Cell 覆盖                       |
| `encodings?`          | `Array<IRTableCellVisualEncoding>`  | `[]`       | 按顺序把原始值映射到颜色通道                     |
| `visualDefaults?`     | `IRTableVisualDefaults`             | `{}`       | 已存在 visual encoding 的颜色范围默认值          |
| `tableDefaults?`      | `IRTableDefaults`                   | `{}`       | 稀疏默认片段，优先级低于同级显式 Source 字段     |
| `data?`               | `IRDataReference`                   | —          | detail 必需、manual 禁止、custom 可选            |
| `structure`           | `IRTableStructureOperation`         | —          | detail、manual 或 custom Structure               |

## Cell 内容

`IRManualTableCell` 是 manual `rows` 中可直接持久化的非空 entry。`string | number | boolean` 是 value 简写；rich object 可保存 value/content、span 与 layout。`null` 属于 rows 的空槽哨兵，不是这个 Cell union；真正的 null scalar 写成 `{ value: null }`。

## Table Source defaults

Core Theme 的 `style` / `mode` 由宿主 `Layout` 或 `renderTable(..., { theme })` 提供。Table 按 mode 建立 owner-local 默认 baseline，再合并同名 `TableThemeStyleDefinition` 返回的 `{ defaults?: IRTableDefaults }`。Source 的 `tableDefaults`、`appearanceDefaults`、`visualDefaults` 与显式 `layout.borders` 按顺序覆盖前面的 defaults；Cell 的局部配置、visual encoding 与有序 rules 再完成最终计划。

`appearanceDefaults`、`visualDefaults` 与 `tableDefaults` 都是稀疏对象，只能为已经存在的 Cell、border 或 visual encoding 提供默认值，不会创建 Cell、rule、border、encoding 或 Legend。`layout.borders.outer` 是按物理方向组织的稀疏对象，可分别设置 `top`、`right`、`bottom`、`left`。

发布包不预注册命名的 Core 或 Table definitions。本站的 `academic`、`vibrant`、`clean` 与应用自定义 style 一样，必须在实际消费它的两个 owner 中注入同名 definition：standalone `compileTable` 通过 `compile.themeStyles` 注入 Core definition，并通过 `lower.tableThemeStyles` 注入 Table definition；缺少 Table 同名 definition 会在 Table resolver fail-loud。
