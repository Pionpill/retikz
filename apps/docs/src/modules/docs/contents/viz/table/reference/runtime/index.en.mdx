TableSpec stores only JSON-safe structure. Datasets, Definitions, Core compile options, and host capabilities arrive at runtime. Table runtime has two jobs to explain: how different entries converge on one execution path, and how one layout-aware transaction produces both Scene and manifest.

> This page explains runtime wiring and execution without repeating schema fields. See [Table contracts](/viz/table/reference/contract-table) for TableSpec and Cell content, [Layout contracts](/viz/table/reference/contract-layout) for track and border inputs, and [Artifact contracts](/viz/table/reference/manifest) for compile outputs.

## How entries converge

React standalone, Vanilla SSR, direct `compileTable()`, and embedded Tables use different authoring and host surfaces, but they do not duplicate Table normalization, presentation, or layout algorithms.

Standalone entries build a canonical `children[0]` root Scene and pass Table definitions plus extra composites into Core compile. React delegates rendering to `<Layout>`; Vanilla `renderTable()` renders the same Scene to an SVG string.

An embedded Table does not start a local compile. It contributes its spec, datasets, Structure / Presentation definitions, and extra composites to the outer `<Layout>` or Vanilla adapter. The host performs the shared compile and exposes results through host artifacts.

## One Table transaction

`table.table` is a layout-aware composite: it must measure arbitrary Core or Tier 2 Cell content, then commit only the selected replay after track sizes are known. The complete process stays inside one Core compile transaction.

1. **Canonical model**: Table schema validation runs first. A Structure definition normalizes manual, detail, or custom input into one semantic model; Presentation definitions turn Cell payloads into layoutable content.
2. **Natural proposal probes**: every Cell calls `layoutChild` with `NaturalLayoutProposal` to obtain allocation and visual bounds. These probes measure content but do not commit output.
3. **Columns and wrap**: natural width, spans, gaps, track configuration, and the parent x-axis `exact.value` or finite `range.max` feed the column solver. Only wrapping Cells issue another `x: range(0, contentWidth)` probe.
4. **Rows and placement**: final probe heights feed the row solver. The transaction then computes Cell boxes, padding-reduced content boxes, fit / align / overflow placement, and the border conflict graph.
5. **Replay and publish**: the runtime replays only each Cell's final probe and the final border Scope to build Scene children. The same composite occurrence publishes a detached, recursively frozen `TableLayoutManifest`.

### Three runtime invariants

- **One Core compile only**: the manifest is a typed artifact from that compile; observing it never starts a second lowering pass.
- **A probe is not output**: natural and range proposals may create multiple candidates. Candidates that are not replayed never enter the final Scene or artifacts; `context.raise()` preserves the selected failed probe's original identity.
- **The root artifact uses occurrence identity**: standalone root selection uses `sourcePath: 'children[0]'` plus an empty `expansionPath`; public `tableId` is not an instance selector.

## React

`@retikz/table-react` exposes three roots: `Table` accepts a complete `IRTableSpec`, `DetailTable` creates record-per-row specs, and `ManualTable` creates explicit-grid specs. All three share `TableCommonProps` and one runtime.

| Entry         | Core input                              | Structure authoring                      |
| ------------- | --------------------------------------- | ---------------------------------------- |
| `Table`       | `spec`, optional `data`                 | An already constructed precise TableSpec |
| `DetailTable` | `dataRef`, `data`, and `columns`        | `columns` or `DetailColumn` children     |
| `ManualTable` | Rectangular `rows`, optional `rowKinds` | `rows` props or `Row` / `Cell` children  |

The two `ManualTable` authoring modes are mutually exclusive. Props mode forwards the persisted row-major structure. Marker mode derives width from the maximum occupied position, pads with `null`, and then uses the same `createManualTableSpec()` and Table schema.

`TableLayoutHostProps` precisely reuses the host fields currently supported by Kernel `<Layout ir>`: handlers, output size/viewBox, renderer, animation, resource ids, Core provider definitions, and the TeX lowerer. See the authoritative [Layout API](/kernel/components/layout/overview) for the complete field semantics. Scope styles, full `compile`, `artifacts/onArtifacts`, and `embeddables` are not part of the Table-root public surface.

| Shared prop                | Type                                            | Default | Description                                           |
| -------------------------- | ----------------------------------------------- | ------- | ----------------------------------------------------- |
| `structureDefinitions?`    | `LowerTablesOptions['structureDefinitions']`    | `[]`    | Custom Structure definitions                          |
| `presentationDefinitions?` | `LowerTablesOptions['presentationDefinitions']` | `[]`    | Custom Cell presentation definitions                  |
| `composites?`              | `ReadonlyArray<AnyCompositeDefinition>`         | `[]`    | Extra definitions required by Tier 2 Cell content     |
| `onManifest?`              | `(manifest: TableLayoutManifest) => void`       | —       | Reports the same compile's root manifest after commit |

The standalone runtime builds a canonical `children[0]` Scene. From `Layout.onArtifacts` it selects exactly one artifact with definition key `table.table`, `sourcePath: 'children[0]'`, and `expansionPath: []`. Notifications are deduplicated by serialized manifest content, and SSR render causes no callback side effect.

### Embedded

A Table used as a parent `<Layout>` child requires a non-empty stable id. Datasets, Table definitions, and `composites` contribute to the outer host. Local `onManifest` and every standalone host prop fail loudly in one diagnostic that asks callers to move them to the outer `<Layout>`. Use the host's `onArtifacts` when embedded artifacts are needed.

## Vanilla

`detailTable()` / `manualTable()` construct plain specs; `embedTable()` with `createTableAdapter()` enters figure/mount composition; `renderTable()` is the one-shot SSR entry.

```ts
const result = renderTable(spec, {
  data: { scores: rows },
  lowerOptions: { presentationDefinitions },
  compile: {
    composites: [customCellComposite],
    shapes: [customShape],
  },
  animation: { enabled: false },
  output: { width: 640, height: 360 },
  artifacts: true,
});

result.svg;
result.manifest;
```

| `renderTable` option | Type                                 | Default | Description                                      |
| -------------------- | ------------------------------------ | ------- | ------------------------------------------------ |
| `data?`              | `ExternalDatasets`                   | `{}`    | Table datasets                                   |
| `lowerOptions?`      | `LowerTablesOptions`                 | `{}`    | Structure / Presentation definitions             |
| `compile?`           | `RenderToStringOptions['compile']`   | `{}`    | Core compile options; extra composites live here |
| `animation?`         | `RenderToStringOptions['animation']` | `{}`    | SSR animation, snapshot, and easing options      |
| `output?`            | `RenderToStringOptions['output']`    | `{}`    | SVG id prefix and display dimensions             |
| `artifacts?`         | `boolean`                            | `false` | Return `{ svg, manifest }` when true             |

Top-level `composites` has been removed; use `compile.composites`. `renderTable()` calls `compileTable()` exactly once whether `artifacts` is true or false. False only ignores the sidecar and does not change the Scene or transaction.

## Table compile API

| Export                 | Purpose                                                                   |
| ---------------------- | ------------------------------------------------------------------------- |
| `lowerTables()`        | Creates the layout-aware `table.table` definition for a host compile      |
| `compileTable()`       | Compiles one canonical root Table into Scene, all artifacts, and manifest |
| `CompileTableOptions`  | Separates `lower` options from Core `compile` options                     |
| `CompileTableResult`   | `CompileResult` plus the exact-root `manifest`                            |
| `TableCompileArtifact` | `CompositeCompileArtifact<'table', 'table', TableLayoutManifest>`         |

`compileTable(spec, datasets, options?)` merges `lowerTables()` with `compile.composites`, then calls `compileToScene()` once. Its `manifest` is the same immutable reference as the exact root artifact's `value`; nested Tables, repeated table ids, and unrelated composite artifacts cannot be mistaken for the root.

A layout-aware Table cannot persist its compile-local replay tree through pure Tier 1 `lowerIRToKernel()`. Use `compileTable()` for a standalone result. For an embedded Scene, pass `lowerTables()` definitions to host `compileToScene()`, React `<Layout>`, or the Vanilla adapter.

The manifest is a JSON-safe, detached, recursively frozen typed-artifact payload. See [Artifact contracts](/viz/table/reference/manifest) for its fields and nested DTOs. Core compile traversal creates the root artifact occurrence; it never enters TableSpec or the manifest. `tableId` is not an instance selector; exact occurrences distinguish anonymous roots, nested Tables, and repeated ids.

## Runtime migration

| Previous form                      | Current form                                    |
| ---------------------------------- | ----------------------------------------------- |
| `lowerTableWithArtifacts()`        | `compileTable()`                                |
| `renderTable(..., { composites })` | `renderTable(..., { compile: { composites } })` |
| Embedded Table `onManifest`        | Outer `<Layout onArtifacts>`                    |
