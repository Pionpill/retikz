Table's three host entries share one runtime. React components and Vanilla helpers first produce the same JSON TableSpec variants. External datasets, function-bearing Definitions, and extra composites arrive as runtime inputs. The Table pipeline resolves Structure, presents Cells, computes layout, lowers Core IR, and produces a matching layout manifest.

## Responsibilities

| Topic          | Responsibility                                             | Reach for it when                           |
| -------------- | ---------------------------------------------------------- | ------------------------------------------- |
| Spec authoring | Produce precise TableSpec from detail/manual author inputs | Avoiding hand-written complete IR           |
| React          | Render standalone or inside a parent `Layout`              | React pages and component composition       |
| Vanilla / SSR  | Embed into a figure/layer or emit one-shot SVG             | Non-React hosts and server export           |
| Lowering       | Merge Definition registries and emit Core IR               | Integrating Core compile or a custom host   |
| Manifest       | Expose semantic geometry for tables, tracks, and Cells     | Hit testing, debugging, export, interaction |

## Spec authoring

Authoring helpers only produce and validate JSON-safe specs. They do not bind a renderer or write datasets and Definitions into IR.

| API                            | Type                                          | Description                                         |
| ------------------------------ | --------------------------------------------- | --------------------------------------------------- |
| `createDetailTableSpec(input)` | `(DetailTableSpecInput) => IRDetailTableSpec` | Builds a detail spec and normalizes string headers  |
| `createManualTableSpec(input)` | `(ManualTableSpecInput) => IRManualTableSpec` | Builds a manual spec from explicit dimensions/Cells |
| `detailTable(input)`           | `(DetailTableSpecInput) => IRDetailTableSpec` | Vanilla's direct delegation to the detail helper    |
| `manualTable(input)`           | `(ManualTableSpecInput) => IRManualTableSpec` | Vanilla's direct delegation to the manual helper    |

## React runtime

### Entries

| Component     | Spec source                                              | Runtime data               |
| ------------- | -------------------------------------------------------- | -------------------------- |
| `Table`       | Caller-provided complete `IRTableSpec`                   | `data?: ExternalDatasets`  |
| `DetailTable` | Builds a precise detail spec from `DetailTableSpecInput` | `data: Array<ExternalRow>` |
| `ManualTable` | Builds a precise manual spec from `ManualTableSpecInput` | No external dataset        |

`Table` always receives a complete `spec`. `DetailTable` chooses between the complete `columns` prop and `DetailColumn` children; `ManualTable` chooses between complete `cells` / `rowKinds` props and nested `Row` / `Cell` markers. The three markers only collect React authoring input and still produce the same detail or manual TableSpec.

Nested manual authoring still requires explicit root `rows` / `columns`; Row count must equal `rows`, and each row may omit trailing Cells. Use the `cells` prop for arbitrary sparse addresses. A `Cell` accepts mutually exclusive scalar children, `value`, or JSON-safe `content` payload sources.

All three components share these runtime props:

| Prop                      | Type                                           | Default | Description                                             |
| ------------------------- | ---------------------------------------------- | ------- | ------------------------------------------------------- |
| `structureDefinitions`    | `ReadonlyArray<AnyTableStructureDefinition>`   | `[]`    | Custom Structure definitions                            |
| `presentationDefinitions` | `ReadonlyArray<AnyCellPresentationDefinition>` | `[]`    | Custom Cell presentation definitions                    |
| `composites`              | `ReadonlyArray<CompositeDefinition>`           | `[]`    | Definitions required by Tier 2 Cell content             |
| `onManifest`              | `(manifest: TableLayoutManifest) => void`      | —       | Standalone layout callback; unsupported when embedded   |
| `renderer`                | `'svg' \| 'canvas'`                            | `'svg'` | Renderer backend                                        |
| `width` / `height`        | `number \| string`                             | —       | Host display size; does not change Table's fixed tracks |
| `className` / `style`     | `string`<br />`CSSProperties`                  | —       | Passed to the rendering host                            |

Standalone components may omit their TableSpec `id`; embedding in a parent `Layout` requires a stable id. Embedded mode cannot use `onManifest`, so consume the sidecar through `lowerTableWithArtifacts()` explicitly.

## Vanilla runtime

Vanilla does not use a fluent builder. `embedTable()` produces an embed spec for browser composition, `createTableAdapter()` creates a reusable stateless adapter, and `renderTable()` handles one-shot SSR.

| API                              | Type                                         | Description                                        |
| -------------------------------- | -------------------------------------------- | -------------------------------------------------- |
| `embedTable(id, spec, options?)` | `(...) => VanillaEmbedSpec<TableEmbedProps>` | Embeds Table into a Kernel figure / layer          |
| `createTableAdapter()`           | `() => VanillaTier2Adapter<TableEmbedProps>` | Creates a stateless Table adapter                  |
| `renderTable`                    | `RenderTable`                                | Emits SVG; artifact mode also returns the manifest |

The `embedTable()` embed id must be non-empty. TableSpec itself may stay anonymous, in which case the lowered root id is `${embedId}/table`.

### Runtime options

| Prop           | Type                                 | Default | Description                                               |
| -------------- | ------------------------------------ | ------- | --------------------------------------------------------- |
| `data`         | `ExternalDatasets`                   | `{}`    | External datasets indexed by spec reference               |
| `lowerOptions` | `LowerTablesOptions`                 | `{}`    | Structure and Presentation definitions                    |
| `composites`   | `ReadonlyArray<CompositeDefinition>` | `[]`    | Definitions required by Tier 2 Cell content               |
| `output`       | `RenderToStringOptions['output']`    | —       | `renderTable` only: SVG host dimensions and id prefix     |
| `artifacts`    | `true \| false`                      | `false` | `renderTable` only: whether to return `{ svg, manifest }` |

## Lowering and extensions

| API                                                 | Description                                                 |
| --------------------------------------------------- | ----------------------------------------------------------- |
| `defineTableStructure(definition)`                  | Defines a Structure provider selected by `structure.kind`   |
| `defineCellPresentation(definition)`                | Defines value-payload presentation into a Core child        |
| `lowerTables(datasets, options?)`                   | Produces Table composite definitions for Core compile       |
| `lowerTableWithArtifacts(spec, datasets, options?)` | Returns a Core child and its matching `TableLayoutManifest` |

`LowerTablesOptions` contains `structureDefinitions` and `presentationDefinitions`. Built-in and custom Definitions enter the same registry; duplicate kinds or names fail. Definitions contain functions, so they are runtime dependencies rather than persistable TableSpec fields.

## Manifest

`TableLayoutManifest` comes from the same resolution as Core IR and contains:

- optional `tableId` and table `bounds`
- semantic-order `rows` / `columns`, each with `id`, `index`, `offset`, and `size`
- semantic-order `cells`, each with `cellId`, `box`, `location`, `roles`, and optional `source`

Standalone React receives layout updates through `onManifest`. Embedded callers use `lowerTableWithArtifacts()` explicitly, while SSR uses `renderTable(spec, { artifacts: true })`.
