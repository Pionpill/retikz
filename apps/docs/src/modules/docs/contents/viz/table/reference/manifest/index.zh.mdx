`TableLayoutManifest` 是同次 Table compile 产出的 JSON-safe、detached、递归冻结 typed artifact payload。运行时如何取得 exact root manifest 见[运行时](/viz/table/reference/runtime#table-compile-api)；本页只列输出形状与嵌套 DTO。

Manifest 的 `style` 区域还保存 effective Core `style`、`themeMode`、完整 resolved Table `tokens` 与逐 key `sources`。这里的 `themeMode` 是同次 compile 的输出元数据，用于说明选择了哪一份 preset；TableSpec 的输入字段仍是 host `theme` 与 `tableThemeTokens`，二者不是同一个层级。

## Border provenance

border manifest 把最终可见 edge 与原子边冲突来源一起保存。以下 schema 从 resolved line 和候选 contribution 逐层组成 atom，再组成 merged edge。

<ZodSchema
  name="ResolvedTableBorderLineSchema"
  description="完成默认值解析、可直接 lowering 为 Core Path 的 border line style。"
  descriptions={{
    stroke: '非 none 的 resolved Core paint。',
    width: 'resolved 非负 border 宽度。',
    strokeOpacity: '解析后的 border 线条不透明度。',
    dashPattern: '可选非空正数 dash pattern；省略表示实线。',
    dashOffset: 'resolved 有限 dash offset。',
    lineCap: 'canonical border 端点样式。',
    lineJoin: 'canonical border 转角样式。',
  }}
/>

### TableBorderSourceSchema

<ZodSchema
  name="TableBorderSourceSchema"
  description="border 候选的 canonical 来源：Cell side、Table outer 默认边或内部 grid 默认边。"
  descriptions={{
    kind: 'Cell side 或 Table 默认边来源的判别值。',
    cellId: '保留用于 provenance 的语义 Cell id。',
    row: 'Cell 起点的 canonical 零基行索引。',
    column: 'Cell 起点的 canonical 零基列索引。',
    side: '提供候选的物理 Cell side 或 Table 外边。',
    scope: 'Table outer、horizontal 或 vertical 默认边作用域。',
    boundaryIndex: '内部 grid 边界的 canonical 零基索引。',
  }}
/>

Cell 来源保留 `cellId + row + column + side`；Table 默认来源使用 `scope + side` 或 `scope + boundaryIndex`，不依赖对象遍历顺序决定冲突结果。
