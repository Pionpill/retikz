TableSpec 只保存 JSON-safe 结构；datasets、Definitions、Core compile options 与宿主能力在运行时注入。Table runtime 需要回答两个问题：不同入口如何汇入同一执行链，以及一次 layout-aware transaction 如何同时产出 Scene 与 manifest。

> 这里解释运行时接线与执行逻辑，不重复 schema 字段。TableSpec 与 Cell 内容见[表格契约](/viz/table/reference/contract-table)，轨道与 border 输入见[布局契约](/viz/table/reference/contract-layout)，compile 输出见[产物契约](/viz/table/reference/manifest)。

## 入口如何汇合

React standalone、Vanilla SSR、直接 `compileTable()` 与 embedded Table 的 authoring 和宿主方式不同，但它们不会复制 Table 的 normalize、Theme token cascade、presentation 或 layout 算法。

Standalone 入口构造 canonical `children[0]` 根 Scene，把 Table definitions 与额外 composites 一起交给 Core compile；React 由 `<Layout>` 管理渲染，Vanilla 的 `renderTable()` 再把同一 Scene 输出为 SVG 字符串。

Standalone 的 `theme` 写入根 Core Scene；embedded Table 不启动局部 compile，也不创建自己的根 Theme，而是把 spec、datasets、Formatter / Structure / Presentation / Visual Scale definitions 与额外 composites 贡献给外层 `<Layout>` 或 Vanilla adapter，由宿主统一编译并通过宿主 artifacts 观察结果。

## 一次 Table transaction

`table.table` 是 layout-aware composite：它既要测量 Cell 内任意 Core / Tier 2 内容，也要在最终轨道尺寸确定后只提交被选中的 replay。整个过程发生在一次 Core compile transaction 内。

1. **Canonical model**：先通过 Table schema，再由 Structure definition 规范化语义模型。每个 Cell 先按 Core Theme `style` / `mode` 选择的 preset、shared categorical、inherited `theme.tokens.table`、local `tableThemeTokens`、Cell 配置、encoding 与有序 rules 解析最终计划；value Cell 再执行胜出的 formatter/Presentation，content Cell 则绕过两者并应用解析后的 content style。
2. **Natural proposal probes**：每个 Cell 先用 `NaturalLayoutProposal` 执行 `layoutChild`，得到内容的 allocation bounds 与 visual bounds；这些 probe 只用于测量。
3. **列求解与 wrap**：natural 宽度、span、gap、track 配置，以及父级 x 轴 `exact.value` 或有限 `range.max` 一起进入列求解。只有开启 wrap 的 Cell 才按最终内容宽度再发起 `x: range(0, contentWidth)` probe。
4. **行求解与放置**：最终 probe 的高度进入行求解，随后计算 Cell box、padding 后的 content box、fit / align / overflow placement，并建立 border conflict graph。
5. **Replay 与发布**：runtime 只 replay 每个 Cell 的最终 probe 与最终 border Scope，构造 Scene children；同一 composite occurrence 同时发布 detached、递归冻结的 `TableLayoutManifest`。

### 三个运行时不变量

- **只有一次 Core compile**：manifest 是同次 compile 的 typed artifact，不会触发第二次 lowering。
- **probe 不等于输出**：natural / range proposal 可以产生多个候选，未被 replay 的候选不会进入最终 Scene 或 artifacts；选中的 failed probe 由 `context.raise()` 保留原始失败身份。
- **根产物按 occurrence 定位**：standalone 根使用 `sourcePath: 'children[0]'` 与空 `expansionPath`；公开 `tableId` 不是实例 selector。

## React

`@retikz/table-react` 提供三个根入口：`Table` 接受完整 `IRTableSpec`，`DetailTable` 生成 record-per-row spec，`ManualTable` 生成显式网格 spec。三者共享 `TableCommonProps` 与同一 runtime。

| 入口          | 核心输入                     | 结构 authoring                          |
| ------------- | ---------------------------- | --------------------------------------- |
| `Table`       | `spec`、可选 `data`          | 已构造的精确 TableSpec                  |
| `DetailTable` | `dataRef`、`data`、`columns` | `columns` 或 `DetailColumn` children    |
| `ManualTable` | 矩形 `rows`、可选 `rowKinds` | `rows` props 或 `Row` / `Cell` children |

`ManualTable` 的两种 authoring 模式互斥。props 模式直接转发行优先持久化结构；marker 模式根据最大占用位置推导列数并补 `null`，然后交给同一个 `createManualTableSpec()` 与 Table schema。

`TableLayoutHostProps` 精确复用 Kernel `<Layout ir>` 当前支持的宿主字段：handlers、输出尺寸/viewBox、renderer、动画、资源 id、Core provider definitions 与 TeX lowerer。standalone 宿主 CSS 使用 `containerStyle`，它只在进入内部 Layout 时改名为 `style`，绝不进入 TableSpec。完整字段与语义见 [Layout API](/kernel/components/layout/overview)；Scope style、完整 `compile`、`artifacts/onArtifacts` 与 `embeddables` 不属于 Table 根组件公共面。

| 共享属性                   | 类型                                            | 默认值 | 描述                                               |
| -------------------------- | ----------------------------------------------- | ------ | -------------------------------------------------- |
| `containerStyle?`          | `LayoutProps['style']`                          | —      | standalone 宿主 CSS；embedded 不支持               |
| `formatterDefinitions?`    | `LowerTablesOptions['formatterDefinitions']`    | `[]`   | 自定义 Cell formatter definitions                  |
| `structureDefinitions?`    | `LowerTablesOptions['structureDefinitions']`    | `[]`   | 自定义 Structure definitions                       |
| `presentationDefinitions?` | `LowerTablesOptions['presentationDefinitions']` | `[]`   | 自定义 Cell presentation definitions               |
| `visualScaleDefinitions?`  | `LowerTablesOptions['visualScaleDefinitions']`  | `[]`   | 自定义 Cell visual scale definitions               |
| `composites?`              | `ReadonlyArray<AnyCompositeDefinition>`         | `[]`   | Cell 内嵌 Tier 2 内容使用的额外 definitions        |
| `onManifest?`              | `(manifest: TableLayoutManifest) => void`       | —      | standalone commit 后接收同次 compile 的根 manifest |

standalone runtime 构造 canonical `children[0]` 根 Scene，并从 `Layout.onArtifacts` 只选择 definition key 为 `table.table`、`sourcePath: 'children[0]'`、`expansionPath: []` 的 artifact。回调按 manifest 的序列化内容去重；SSR render 不触发副作用。

四类 definitions 与 composites 进入 runtime contribution 时按稳定 key 和对象 identity 合并。runtime 保存复制后冻结的 arrays、`lowerOptions` 与 envelope，调用方后续 `push` 不会改变已创建 contribution；definition/composite 对象本身仍由调用方拥有，不会被 clone 或 freeze。

### Theme 输入

| 输入                | 类型                              | 默认值 | 作用                                                                     |
| ------------------- | --------------------------------- | ------ | ------------------------------------------------------------------------ |
| `theme?`            | `IRScene['theme']`                | —      | standalone 根 Core Theme；embedded 时由外层 `<Layout theme>` 提供        |
| `tableThemeTokens?` | `IRTableSpec['tableThemeTokens']` | `{}`   | TableSpec 局部 sparse token overlay，高于 inherited `theme.tokens.table` |

`theme.style` / `theme.mode` 只决定当前 Core 环境与 Table preset；`theme.tokens.table` 经过 `TableThemeTokenDefinition` 校验后按 namespace 继承。Core 的 `colors.categorical` 投影为 Table 的 `data.categorical`，再由 `tableThemeTokens` 覆盖同名叶；host `containerStyle` 仍只是 CSS，不进入这一 cascade。

### Embedded

Table 作为父级 `<Layout>` child 时必须有非空稳定 id。datasets、Table definitions 与 `composites` 会贡献给外层宿主；局部 `onManifest` 和任一 standalone host prop 都会 fail-loud，并在同一错误中提示把字段移动到外层 `<Layout>`。宿主需要 artifact 时使用外层 `onArtifacts`。

## 自定义视觉比例尺

视觉比例尺 Definition 的 `resolve()` 接收 JSON-safe options、按 canonical Cell 顺序排列的 non-null 原始值，以及同次 Table style palette。每条 encoding 只解析一次，并返回一个 runtime-only resolution：

```ts
import { defineCellVisualScale } from '@retikz/table';
import { z } from 'zod';

const riskScale = defineCellVisualScale({
  name: 'risk-color',
  optionsSchema: z.strictObject({
    edge: z.number(),
    low: z.string(),
    high: z.string(),
  }),
  resolve: options => ({
    of: value => {
      if (typeof value !== 'number') throw new Error('risk-color values must be numbers');
      return value < options.edge ? options.low : options.high;
    },
    legendForm: 'swatch',
    domain: [options.edge],
    range: [options.low, options.high],
    edges: [options.edge],
  }),
});
```

| Resolution 字段    | 作用                                                                       |
| ------------------ | -------------------------------------------------------------------------- |
| `of(value)`        | 把 canonical 原始 scalar 映射为颜色；返回 `undefined` 表示该 Cell 不写颜色 |
| `legendForm`       | `ramp` 或 `swatch` descriptor 形态                                         |
| `domain` / `range` | 与 evaluator 同次解析得到的 JSON-safe domain 与颜色序列                    |
| `edges?`           | `swatch` 阈值分档的严格递增边界                                            |

Table 会检查 options / domain 的 JSON 形状、range / evaluator 的 Core CSS color、form 数组关系，以及同一 scalar 重复求值的确定性，并复制、冻结 descriptor 数据。任意 evaluator 与 descriptor 的完整语义无法由有限运行时检查证明，因此 custom Definition 作者必须保证 `of()` 与 `legendForm` / `domain` / `range` / `edges` 表达同一映射。

内置 Definition 为 `ordinal-color`、`sequential-color` 与 `threshold-color`。encoding 只有显式写 `legend: { ... }` 且 resolution 非空时才产生 descriptor seed。alpha.3 在这里闭环；自动绘制 Standard Legend、`legendLayout` 与最终 Legend artifact join 计划在 Table alpha.6 接入。

## Vanilla

`detailTable()` / `manualTable()` 构造 plain spec；`embedTable()` 与 `createTableAdapter()` 接入 figure/mount；`renderTable()` 是一次性 SSR 入口。

```ts
const result = renderTable(spec, {
  theme: { style: 'academic', mode: 'light' },
  data: { scores: rows },
  lowerOptions: { formatterDefinitions, presentationDefinitions, visualScaleDefinitions },
  compile: {
    composites: [customCellComposite],
    shapes: [customShape],
  },
  animation: { enabled: false },
  output: { width: 640, height: 360 },
  artifacts: true,
});

result.svg;
result.manifest;
```

| `renderTable` 选项 | 类型                                 | 默认值  | 描述                                                            |
| ------------------ | ------------------------------------ | ------- | --------------------------------------------------------------- |
| `theme?`           | `IRScene['theme']`                   | —       | 写入 standalone 根 Scene 的 Core Theme                          |
| `data?`            | `ExternalDatasets`                   | `{}`    | Table 数据集                                                    |
| `lowerOptions?`    | `LowerTablesOptions`                 | `{}`    | Formatter / Structure / Presentation / Visual Scale definitions |
| `compile?`         | `RenderToStringOptions['compile']`   | `{}`    | Core compile options；额外 composites 写在这里                  |
| `animation?`       | `RenderToStringOptions['animation']` | `{}`    | SSR 动画/截帧/easing 选项                                       |
| `output?`          | `RenderToStringOptions['output']`    | `{}`    | SVG id 前缀与显示尺寸                                           |
| `artifacts?`       | `boolean`                            | `false` | `true` 返回 `{ svg, manifest }`                                 |

顶层 `composites` 已删除；使用 `compile.composites`。无论 `artifacts` 是否为 true，`renderTable()` 都只调用一次 `compileTable()`；false 只忽略 sidecar，不改变 Scene 或 transaction。

## Table compile API

| 导出                   | 作用                                                                 |
| ---------------------- | -------------------------------------------------------------------- |
| `lowerTables()`        | 创建 layout-aware `table.table` composite definition，供宿主 compile |
| `compileTable()`       | 编译 canonical 单根 Table，返回 Scene、完整 artifacts 与根 manifest  |
| `CompileTableOptions`  | 分开承载 `lower` 与 `compile` 选项                                   |
| `CompileTableResult`   | `CompileResult` 加 exact root `manifest`                             |
| `TableCompileArtifact` | `CompositeCompileArtifact<'table', 'table', TableLayoutManifest>`    |

`compileTable(spec, datasets, options?)` 合并 `lowerTables()` 与 `compile.composites` 后只调用一次 `compileToScene()`。返回的 `manifest` 与 exact root artifact 的 `value` 是同一 immutable 引用；nested Table、重复 table id 或其它 composite artifacts 不会误选。

layout-aware Table 不能通过纯 Tier 1 `lowerIRToKernel()` 保存 compile-local replay tree。需要 standalone 结果时使用 `compileTable()`；嵌入其它 Scene 时把 `lowerTables()` definitions 交给宿主 `compileToScene()`、React `<Layout>` 或 Vanilla adapter。

manifest 是 JSON-safe、detached、递归冻结的 typed artifact payload；字段与嵌套 DTO 见[产物契约](/viz/table/reference/manifest)。根 artifact occurrence 由 Core compile traversal 生成，不进入 TableSpec 或 manifest；`tableId` 不是实例 selector，匿名根、nested Table 与重复 id 都由 exact occurrence 区分。

## 运行时入口边界

| 旧写法                             | 当前写法                                        |
| ---------------------------------- | ----------------------------------------------- |
| `lowerTableWithArtifacts()`        | `compileTable()`                                |
| `renderTable(..., { composites })` | `renderTable(..., { compile: { composites } })` |
| embedded Table 的 `onManifest`     | 外层 `<Layout onArtifacts>`                     |

Table 的 Core preset 来自 host `theme.style` / `theme.mode`；inherited `theme.tokens.table` 与 local `tableThemeTokens` 按 namespace 和 spec 层级解析。宿主 CSS 继续使用 `containerStyle`，不进入 TableSpec。省略 Theme 时从 `neutral + light` 基线开始；resolved manifest 另行记录 effective `style`、`themeMode`、完整 token map 与来源。
