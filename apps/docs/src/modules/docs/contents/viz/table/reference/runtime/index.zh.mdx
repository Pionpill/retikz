TableSpec 只保存 JSON-safe 结构；datasets、Definitions、Core compile options 与宿主能力在运行时注入。所有 standalone 入口都让 Table 在同一次 Core compile 中完成内容测量、轨道求解、replay、Scene 与 manifest，不再为了 sidecar 执行第二次 lowering。

> 这里解释运行时接线与执行逻辑，不重复 schema 字段。TableSpec、Cell、轨道、border 与 manifest 的 JSON 形状请查[表格契约](/viz/table/reference/contract-table)。

## React

`@retikz/table-react` 提供三个根入口：`Table` 接受完整 `IRTableSpec`，`DetailTable` 生成 record-per-row spec，`ManualTable` 生成显式网格 spec。三者共享 `TableCommonProps` 与同一 runtime。

| 入口          | 核心输入                     | 结构 authoring                       |
| ------------- | ---------------------------- | ------------------------------------ |
| `Table`       | `spec`、可选 `data`          | 已构造的精确 TableSpec               |
| `DetailTable` | `dataRef`、`data`、`columns` | `columns` 或 `DetailColumn` children |
| `ManualTable` | `rows`、`columns`、`cells`   | `cells` 或 `Row` / `Cell` children   |

`TableLayoutHostProps` 精确复用 Kernel `<Layout ir>` 当前支持的宿主字段：handlers、输出尺寸/viewBox、renderer、动画、资源 id、Core provider definitions 与 TeX lowerer。完整字段与语义见 [Layout API](/kernel/components/layout/overview)；Scope style、完整 `compile`、`artifacts/onArtifacts` 与 `embeddables` 不属于 Table 根组件公共面。

| 共享属性                   | 类型                                            | 默认值 | 描述                                               |
| -------------------------- | ----------------------------------------------- | ------ | -------------------------------------------------- |
| `structureDefinitions?`    | `LowerTablesOptions['structureDefinitions']`    | `[]`   | 自定义 Structure definitions                       |
| `presentationDefinitions?` | `LowerTablesOptions['presentationDefinitions']` | `[]`   | 自定义 Cell presentation definitions               |
| `composites?`              | `ReadonlyArray<AnyCompositeDefinition>`         | `[]`   | Cell 内嵌 Tier 2 内容使用的额外 definitions        |
| `onManifest?`              | `(manifest: TableLayoutManifest) => void`       | —      | standalone commit 后接收同次 compile 的根 manifest |

standalone runtime 构造 canonical `children[0]` 根 Scene，并从 `Layout.onArtifacts` 只选择 definition key 为 `table.table`、`sourcePath: 'children[0]'`、`expansionPath: []` 的 artifact。回调按 manifest 的序列化内容去重；SSR render 不触发副作用。

### Embedded

Table 作为父级 `<Layout>` child 时必须有非空稳定 id。datasets、Table definitions 与 `composites` 会贡献给外层宿主；局部 `onManifest` 和任一 standalone host prop 都会 fail-loud，并在同一错误中提示把字段移动到外层 `<Layout>`。宿主需要 artifact 时使用外层 `onArtifacts`。

## Vanilla

`detailTable()` / `manualTable()` 构造 plain spec；`embedTable()` 与 `createTableAdapter()` 接入 figure/mount；`renderTable()` 是一次性 SSR 入口。

```ts
const result = renderTable(spec, {
  data: { scores: rows },
  lowerOptions: { presentationDefinitions },
  compile: {
    composites: [customCellComposite],
    shapes: [customShape],
  },
  animation: { enabled: false },
  output: { width: 640, height: 360 },
  artifacts: true,
});

result.svg;
result.manifest;
```

| `renderTable` 选项 | 类型                                 | 默认值  | 描述                                           |
| ------------------ | ------------------------------------ | ------- | ---------------------------------------------- |
| `data?`            | `ExternalDatasets`                   | `{}`    | Table 数据集                                   |
| `lowerOptions?`    | `LowerTablesOptions`                 | `{}`    | Structure / Presentation 扩展定义              |
| `compile?`         | `RenderToStringOptions['compile']`   | `{}`    | Core compile options；额外 composites 写在这里 |
| `animation?`       | `RenderToStringOptions['animation']` | `{}`    | SSR 动画/截帧/easing 选项                      |
| `output?`          | `RenderToStringOptions['output']`    | `{}`    | SVG id 前缀与显示尺寸                          |
| `artifacts?`       | `boolean`                            | `false` | `true` 返回 `{ svg, manifest }`                |

顶层 `composites` 已删除；使用 `compile.composites`。无论 `artifacts` 是否为 true，`renderTable()` 都只调用一次 `compileTable()`；false 只忽略 sidecar，不改变 Scene 或 transaction。

## Table compile API

| 导出                   | 作用                                                                 |
| ---------------------- | -------------------------------------------------------------------- |
| `lowerTables()`        | 创建 layout-aware `table.table` composite definition，供宿主 compile |
| `compileTable()`       | 编译 canonical 单根 Table，返回 Scene、完整 artifacts 与根 manifest  |
| `CompileTableOptions`  | 分开承载 `lower` 与 `compile` 选项                                   |
| `CompileTableResult`   | `CompileResult` 加 exact root `manifest`                             |
| `TableCompileArtifact` | `CompositeCompileArtifact<'table', 'table', TableLayoutManifest>`    |

`compileTable(spec, datasets, options?)` 合并 `lowerTables()` 与 `compile.composites` 后只调用一次 `compileToScene()`。返回的 `manifest` 与 exact root artifact 的 `value` 是同一 immutable 引用；nested Table、重复 table id 或其它 composite artifacts 不会误选。

layout-aware Table 不能通过纯 Tier 1 `lowerIRToKernel()` 保存 compile-local replay tree。需要 standalone 结果时使用 `compileTable()`；嵌入其它 Scene 时把 `lowerTables()` definitions 交给宿主 `compileToScene()`、React `<Layout>` 或 Vanilla adapter。

manifest 是 JSON-safe、detached、递归冻结的 typed artifact payload；字段与嵌套 DTO 见[表格契约的布局 manifest](/viz/table/reference/contract-table#布局-manifest)。根 artifact occurrence 由 Core compile traversal 生成，不进入 TableSpec 或 manifest；`tableId` 不是实例 selector，匿名根、nested Table 与重复 id 都由 exact occurrence 区分。

## 运行时迁移

| 旧写法                             | 当前写法                                        |
| ---------------------------------- | ----------------------------------------------- |
| `lowerTableWithArtifacts()`        | `compileTable()`                                |
| `renderTable(..., { composites })` | `renderTable(..., { compile: { composites } })` |
| embedded Table 的 `onManifest`     | 外层 `<Layout onArtifacts>`                     |
