Detail tables, explicit grids, and custom structures use different inputs, but all enter the same Table model. This group explains how those stable concepts work together for readers who need layout control, artifact consumption, or extensions.

The main path first answers “which Cells exist,” then “what each Cell draws” and “where it is placed.” `Scene` and `Manifest` come from the same compile and serve rendering versus geometry and semantic consumers.

## Responsibilities

| Topic                  | Responsibility                                             | Reach for it when                                |
| ---------------------- | ---------------------------------------------------------- | ------------------------------------------------ |
| Structure & Cells      | Unify row, column, Cell identity, semantics, and source    | Creating a table shape or tracing a Cell         |
| Content Presentation   | Turn scalar values into layout-ready Core content          | Custom formatting, graphics, or providers        |
| Layout & Borders       | Measure, solve tracks, place content, resolve shared edges | Controlling size, wrapping, spans, borders       |
| Artifacts & Provenance | Expose track, Cell, border geometry and source             | Hit testing, debugging, export, host integration |

All four layers share one canonical model. Structure does not draw, Presentation does not size tracks, Layout does not reinterpret business data, and Manifest only observes the deterministic result of the same compile.
