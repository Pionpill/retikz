title: Detail Table
description: Use DetailTable to map each external record into one Cell row and render it through React, Vanilla, or SSR.
---

Detail tables fit two-dimensional data with one record per row, such as lists, ledgers, and record sets. Declare a data reference and columns; `DetailTable` reads every record in column order and generates header and body Cells.

## Usage

```tsx
import { DetailColumn, DetailTable } from '@retikz/table-react';
```

For programmatic column construction, pass the complete `columns` prop:

```tsx
<DetailTable
  dataRef="scores"
  data={rows}
  columns={[
    { id: 'name', field: 'name', header: 'Name' },
    { id: 'score', field: 'score', header: 'Score' },
  ]}
/>
```

`dataRef` is the stable reference stored in IRTable. `data` contains current runtime records and never enters the persistable spec. `columns` controls field access, display order, headers, and optional Cell presentations.

For JSX-local column declarations, use `DetailColumn` children:

```tsx
<DetailTable id="scores" dataRef="scores" data={rows}>
  <DetailColumn id="name" field="name" header="Name" />
  <DetailColumn id="score" field="score" header="Score" />
</DetailTable>
```

Choose either `columns` or `DetailColumn` children. Both forms produce the same detail-table spec, and every `DetailTable` root prop other than `columns` is available in both forms.

Table first resolves the final plan for each Cell. The host `theme.mode` establishes the Table owner-local default preset; an explicit `theme.style` then applies the injected sparse Table definition with the same name. Shared `colors.categorical` supplies the common categorical palette, and spec-local `tableThemeTokens` override Table tokens. Column configuration supplies formatter/presentation references and local appearance; `encodings` map raw data to color; and declaration-ordered `rules` apply the final matching overrides, including formatter or presentation winners. Only then does the winning formatter turn a raw field value into its display value. Only `tableThemeTokens` enters the JSON-safe IRTable; the host `theme` propagates through the Core Scene / Scope.

### Layout playground

With data and column order held constant, tracks determine each Cell box and Cell policy determines how content enters that box. Use the Tracks, Note Cells, and Border Graph sections to observe note-column width, text placement, clipping, and the blue shared edge.

`auto` reads intrinsic size, `fixed` uses an explicit size, and `minmax` absorbs content contributions between bounds. `fraction` distributes remaining width only when the parent compile provides an x-axis `exact` proposal or a `range` proposal with a finite `max`. Standalone `DetailTable` `width` / `height` controls output size, not layout proposals.

`DetailColumn.headerLayout` / `bodyLayout` configure header and body Cells independently. Padding first establishes the content box; wrapping reruns content layout with the solved column width; fit and alignment place the selected replay; overflow finally decides whether content outside the box remains visible.

### Vanilla and SSR

The Vanilla API uses a plain helper to construct the same detail-table spec. Use `embedTable()` with `TableInputEmbedAdapter` for browser composition, or `renderTable()` for one-shot server rendering.

```ts
import { detailTable, renderTable } from '@retikz/table-vanilla';

const spec = detailTable({
  id: 'scores',
  dataRef: 'scores',
  columns: [
    { id: 'name', field: 'name', header: 'Name' },
    { id: 'score', field: 'score', header: 'Score' },
  ],
});

const svg = renderTable(spec, { data: { scores: rows } });
```

### One layout transaction

A Table compile performs these stages in a fixed order. They share one canonical model, so observing a manifest never triggers a second lowering pass.

| Stage          | Input and processing                                    | Observable result                                               |
| -------------- | ------------------------------------------------------- | --------------------------------------------------------------- |
| Structure      | records + columns produce value Cells                   | Stable column order, headers, and body semantics                |
| Measure/solve  | intrinsic layout, track contributions, wrap reflow      | Resolved tracks and Cell boxes                                  |
| Place content  | padding, fit, alignment, overflow                       | Allocation and visual-overflow bounds                           |
| Border Graph   | Table defaults and Cell sides resolve by conflict order | Deterministic shared edges, winners, and contributor provenance |
| Compile commit | replay Cells and borders, commit Scene + typed artifact | Scene and exact-root manifest from the same compile             |

### Read the same-compile manifest

The standalone React entry selects the exact root Table artifact from `<Layout onArtifacts>` and deduplicates `onManifest` notifications by manifest content. When embedded in an outer `<Layout>`, local `onManifest` is unsupported; read the host's `onArtifacts` instead.

```tsx
<DetailTable
  dataRef="scores"
  data={rows}
  columns={columns}
  onManifest={manifest => console.log(manifest.allocationBounds)}
/>
```

For Vanilla SSR, `artifacts: true` only requests the sidecar. SVG and manifest still come from one `compileTable()` call:

```ts
const result = renderTable(spec, {
  data: { scores: rows },
  artifacts: true,
});

result.svg;
result.manifest;
```

## API Reference

### DetailTable

| Prop                             | Type                                                                      | Default        | Description                                                                       |
| -------------------------------- | ------------------------------------------------------------------------- | -------------- | --------------------------------------------------------------------------------- |
| `dataRef`                        | `DetailTableProps['dataRef']`                                             | —              | External dataset reference stored in the spec                                     |
| `data`                           | `DetailTableProps['data']`                                                | —              | Current detail records; excluded from the spec                                    |
| `columns?`                       | `DetailTableProps['columns']`                                             | —              | Programmatic fields, headers, and presentations; exclusive with children          |
| `children?`                      | `DetailTableProps['children']`                                            | —              | `DetailColumn` declarations in order; exclusive with `columns`                    |
| `model?`                         | `DetailTableProps['model']`                                               | —              | Optional field model                                                              |
| `header?`                        | `DetailTableProps['header']`                                              | `true`         | Whether to generate a column-header row                                           |
| `id?`                            | `DetailTableProps['id']`                                                  | —              | Optional stable Table id; omission stays anonymous in standalone and embedded use |
| `layout?`                        | `DetailTableProps['layout']`                                              | track defaults | Default/indexed track sizes, gaps, and Table borders                              |
| `rules?`                         | `DetailTableProps['rules']`                                               | `[]`           | Declaration-ordered formatter, presentation, or appearance overrides              |
| `encodings?`                     | `DetailTableProps['encodings']`                                           | `[]`           | Maps selected value-Cell raw values to background or content colors               |
| `theme?`                         | `DetailTableProps['theme']`                                               | —              | Standalone root Core Theme; embedded mode uses the outer `<Layout>`               |
| `tableThemeTokens?`              | `DetailTableProps['tableThemeTokens']`                                    | `{}`           | Sparse IRTable token overlay above the Table style baseline                       |
| `meta?`                          | `DetailTableProps['meta']`                                                | —              | JSON metadata stored in IRTable                                                   |
| `formatterDefinitions?`          | `DetailTableProps['formatterDefinitions']`                                | `[]`           | Custom Cell formatter definitions                                                 |
| `structureDefinitions?`          | `DetailTableProps['structureDefinitions']`                                | `[]`           | Custom structure definitions                                                      |
| `presentationDefinitions?`       | `DetailTableProps['presentationDefinitions']`                             | `[]`           | Custom Cell presentation definitions                                              |
| `visualScaleDefinitions?`        | `DetailTableProps['visualScaleDefinitions']`                              | `[]`           | Custom Cell visual-scale definitions                                              |
| `themeStyles?`                   | `DetailTableProps['themeStyles']`                                         | `[]`           | Standalone Core Theme style definitions; supplied by the outer host when embedded |
| `tableThemeStyles?`              | `DetailTableProps['tableThemeStyles']`                                    | `[]`           | Table baseline definitions sharing the Core style name                            |
| `composites?`                    | `DetailTableProps['composites']`                                          | `[]`           | Definitions required by Tier 2 Cell content                                       |
| `onManifest?`                    | `DetailTableProps['onManifest']`                                          | —              | Standalone layout artifact callback; unsupported when embedded                    |
| `width?` / `height?`             | `DetailTableProps['width']`                                               | —              | Host size; does not change Table layout proposals                                 |
| `viewBox?`                       | `DetailTableProps['viewBox']`                                             | —              | Scene camera; does not affect track solving                                       |
| `animate?` / `snapshotAt?`       | `DetailTableProps['animate']`                                             | —              | Reuses the Kernel Layout animation host contract                                  |
| `renderer?`                      | `DetailTableProps['renderer']`                                            | `'svg'`        | Rendering backend                                                                 |
| `className?` / `containerStyle?` | `DetailTableProps['className']`<br />`DetailTableProps['containerStyle']` | —              | Passed to the standalone rendering host; rejected when embedded                   |

### DetailColumn

| Prop            | Type                                | Default | Description                                          |
| --------------- | ----------------------------------- | ------- | ---------------------------------------------------- |
| `id`            | `DetailColumnProps['id']`           | —       | Stable column identifier                             |
| `field`         | `DetailColumnProps['field']`        | —       | Field read from each record                          |
| `header?`       | `DetailColumnProps['header']`       | —       | Header payload; strings normalize to value Cells     |
| `formatter?`    | `DetailColumnProps['formatter']`    | —       | Formatter reference for body raw values              |
| `presentation?` | `DetailColumnProps['presentation']` | —       | Optional presentation reference for body value Cells |
| `headerLayout?` | `DetailColumnProps['headerLayout']` | —       | Header Cell layout and four-sided border policy      |
| `bodyLayout?`   | `DetailColumnProps['bodyLayout']`   | —       | Body Cell layout and four-sided border policy        |

`detailTable(input)` accepts the same spec inputs and returns `IRDetailTable`. See [API Reference](/viz/table/reference) for complete `Table`, `ManualTable`, schema, adapter, and lowering contracts.

Formatters and presentations only process value Cells. A Cell with direct `content` already owns a renderable child and bypasses both; pairing `content` with a formatter or presentation fails loudly.
