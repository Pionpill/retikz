---
title: Detail Table
description: Use DetailTable to map each external record into one Cell row and render it through React, Vanilla, or SSR.
---

Detail tables fit two-dimensional data with one record per row, such as lists, ledgers, and record sets. Declare a data reference and columns; `DetailTable` reads every record in column order and generates header and body Cells.

## Usage

```tsx
import { DetailColumn, DetailTable } from '@retikz/table-react';
```

For programmatic column construction, pass the complete `columns` prop:

```tsx
<DetailTable
  dataRef="scores"
  data={rows}
  columns={[
    { id: 'name', field: 'name', header: 'Name' },
    { id: 'score', field: 'score', header: 'Score' },
  ]}
/>
```

`dataRef` is the stable reference stored in TableSpec. `data` contains current runtime records and never enters the persistable spec. `columns` controls field access, display order, headers, and optional Cell presentations.

For JSX-local column declarations, use `DetailColumn` children:

```tsx
<DetailTable id="scores" dataRef="scores" data={rows}>
  <DetailColumn id="name" field="name" header="Name" />
  <DetailColumn id="score" field="score" header="Score" />
</DetailTable>
```

Choose either `columns` or `DetailColumn` children. Both forms produce the same detail-table spec, and every `DetailTable` root prop other than `columns` is available in both forms.

### Adjust fixed tracks

The current release uses uniform `columnWidth`, `rowHeight`, and optional `headerHeight`. Cell content does not resize columns or rows. Defaults are `120` for column width, `32` for body row height, and `0` for row and column gaps.

```tsx
<DetailTable
  dataRef="scores"
  data={rows}
  columns={columns}
  layout={{
    columnWidth: 144,
    rowHeight: 36,
    headerHeight: 40,
    columnGap: 8,
    rowGap: 4,
  }}
/>
```

Content measurement, intrinsic row height, spans, and complete border rules are outside v0.1. Host `width` / `height` only changes the displayed SVG or Canvas size; it does not rewrite track sizes.

### Vanilla and SSR

The Vanilla API uses a plain helper to construct the same detail-table spec. Use `embedTable()` with `createTableAdapter()` for browser composition, or `renderTable()` for one-shot server rendering.

```ts
import { detailTable, renderTable } from '@retikz/table-vanilla';

const spec = detailTable({
  id: 'scores',
  dataRef: 'scores',
  columns: [
    { id: 'name', field: 'name', header: 'Name' },
    { id: 'score', field: 'score', header: 'Score' },
  ],
});

const svg = renderTable(spec, { data: { scores: rows } });
```

## API Reference

### DetailTable

| Prop                       | Type                                                             | Default              | Description                                                              |
| -------------------------- | ---------------------------------------------------------------- | -------------------- | ------------------------------------------------------------------------ |
| `dataRef`                  | `DetailTableProps['dataRef']`                                    | —                    | External dataset reference stored in the spec                            |
| `data`                     | `DetailTableProps['data']`                                       | —                    | Current detail records; excluded from the spec                           |
| `columns?`                 | `DetailTableProps['columns']`                                    | —                    | Programmatic fields, headers, and presentations; exclusive with children |
| `children?`                | `DetailTableProps['children']`                                   | —                    | `DetailColumn` declarations in order; exclusive with `columns`           |
| `model?`                   | `DetailTableProps['model']`                                      | —                    | Optional field model                                                     |
| `header?`                  | `DetailTableProps['header']`                                     | `true`               | Whether to generate a column-header row                                  |
| `id?`                      | `DetailTableProps['id']`                                         | —                    | Stable Table id; required inside a parent `Layout`                       |
| `layout?`                  | `DetailTableProps['layout']`                                     | fixed-track defaults | Column width, body/header heights, and row/column gaps                   |
| `structureDefinitions?`    | `DetailTableProps['structureDefinitions']`                       | `[]`                 | Custom structure definitions                                             |
| `presentationDefinitions?` | `DetailTableProps['presentationDefinitions']`                    | `[]`                 | Custom Cell presentation definitions                                     |
| `composites?`              | `DetailTableProps['composites']`                                 | `[]`                 | Definitions required by Tier 2 Cell content                              |
| `onManifest?`              | `DetailTableProps['onManifest']`                                 | —                    | Standalone layout artifact callback; unsupported when embedded           |
| `width?` / `height?`       | `DetailTableProps['width']`                                      | —                    | Host size; does not change fixed tracks                                  |
| `renderer?`                | `DetailTableProps['renderer']`                                   | `'svg'`              | Rendering backend                                                        |
| `className?` / `style?`    | `DetailTableProps['className']`<br />`DetailTableProps['style']` | —                    | Passed to the rendering host                                             |

### DetailColumn

| Prop            | Type                                | Default | Description                                          |
| --------------- | ----------------------------------- | ------- | ---------------------------------------------------- |
| `id`            | `DetailColumnProps['id']`           | —       | Stable column identifier                             |
| `field`         | `DetailColumnProps['field']`        | —       | Field read from each record                          |
| `header?`       | `DetailColumnProps['header']`       | —       | Header payload; strings normalize to value Cells     |
| `presentation?` | `DetailColumnProps['presentation']` | —       | Optional presentation reference for body value Cells |

`detailTable(input)` accepts the same spec inputs and returns `IRDetailTableSpec`. See [API Reference](/viz/table/reference) for complete `Table`, `ManualTable`, schema, adapter, and lowering contracts.
