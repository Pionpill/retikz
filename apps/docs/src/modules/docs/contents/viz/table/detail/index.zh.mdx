---
title: 明细表
description: 用 DetailTable 将每条外部记录映射为一行 Cell，并在 React、Vanilla 或 SSR 中渲染。
---

明细表适合一条记录对应一行的二维数据，例如名单、流水和记录清单。你只需声明数据引用和列，`DetailTable` 会按列顺序读取每条记录，并生成列头与正文 Cell。

## 用法

```tsx
import { DetailColumn, DetailTable } from '@retikz/table-react';
```

程序化构造列时，传入完整的 `columns`：

```tsx
<DetailTable
  dataRef="scores"
  data={rows}
  columns={[
    { id: 'name', field: 'name', header: '姓名' },
    { id: 'score', field: 'score', header: '分数' },
  ]}
/>
```

`dataRef` 是写入 TableSpec 的稳定引用；`data` 是当前运行时记录，不会进入可持久化 spec。`columns` 同时决定读取字段、显示顺序、列头和可选的 Cell presentation。

在 JSX 中就近声明列时，推荐使用 `DetailColumn` children：

```tsx
<DetailTable id="scores" dataRef="scores" data={rows}>
  <DetailColumn id="name" field="name" header="姓名" />
  <DetailColumn id="score" field="score" header="分数" />
</DetailTable>
```

`columns` 与 `DetailColumn` children 只能二选一；两种写法会得到相同的明细表 spec。除 `columns` 外，`DetailTable` 的根属性在两种写法中完全一致。

Table 会先解析每个 Cell 的最终计划：Core Theme 的 `style` / `mode` 选择 Table preset，shared `colors.categorical` 提供视觉编码的公共分类色，spec-local `tableThemeTokens` 覆盖 Table token。列级配置提供 formatter/presentation 与局部外观，`encodings` 映射原始数据颜色，声明顺序中的 `rules` 最后覆盖匹配 Cell，也可以改写 formatter/presentation 胜者。随后才由胜出的 formatter 把原始字段值转成显示值；只有 `tableThemeTokens` 会写入 JSON-safe TableSpec，宿主 `theme` 由 Core Scene / Scope 传播。

`auto` 读取内容自然尺寸，`fixed` 使用明确尺寸，`minmax` 在上下界之间吸收内容贡献。`fraction` 只有在父级 compile 给出 x 轴 `exact` proposal 或带有限 `max` 的 `range` proposal 时才分配剩余宽度；standalone `DetailTable` 的 `width` / `height` 只控制输出尺寸，不是布局 proposal。

`DetailColumn.headerLayout` / `bodyLayout` 分别控制列头与正文 Cell。padding 先缩出 content box；wrap 使用已求解列宽重新布局内容；fit 与对齐放置选中的 replay；overflow 最后决定内容框外的部分是否可见。

### Vanilla 与 SSR

Vanilla API 使用 plain helper 构造同一份明细表 spec。浏览器组合时使用 `embedTable()` 与 `createTableAdapter()`；一次性服务端渲染使用 `renderTable()`。

```ts
import { detailTable, renderTable } from '@retikz/table-vanilla';

const spec = detailTable({
  id: 'scores',
  dataRef: 'scores',
  columns: [
    { id: 'name', field: 'name', header: '姓名' },
    { id: 'score', field: 'score', header: '分数' },
  ],
});

const svg = renderTable(spec, { data: { scores: rows } });
```

### 一次布局事务

一次 Table compile 会按固定顺序完成下面的工作；所有步骤共享同一份规范化表格输入。读取 manifest 只观察这次编译的结果，不会另跑一次 lowering。

| 阶段         | 输入与处理                                       | 用户可见结果                           |
| ------------ | ------------------------------------------------ | -------------------------------------- |
| 结构与呈现   | records + columns 生成 value Cell                | 列顺序、列头与正文语义稳定             |
| 测量与轨道   | 先测内容，再汇总轨道贡献并按已解列宽换行         | 最终行列尺寸和每个 Cell 的占位框       |
| 内容放置     | 应用 padding、fit、alignment 与 overflow         | 内容占位范围与实际可见范围             |
| Border Graph | Table 默认边与 Cell 边按优先级解决冲突           | 每条共享边只留下确定结果及来源         |
| 编译输出     | replay Cell 与边框，产出 Scene 和已校验 artifact | 同次编译返回 Scene 与根 Table manifest |

### 从同次 compile 读取 manifest

React standalone 入口从 `<Layout onArtifacts>` 选择 exact root Table artifact，并按 manifest 内容去重后调用 `onManifest`。嵌入外层 `<Layout>` 时，本地 `onManifest` 不受支持，应由宿主读取 `onArtifacts`。

```tsx
<DetailTable
  dataRef="scores"
  data={rows}
  columns={columns}
  onManifest={manifest => console.log(manifest.allocationBounds)}
/>
```

Vanilla SSR 的 `artifacts: true` 只决定是否返回 sidecar；SVG 与 manifest 仍来自一次 `compileTable()`：

```ts
const result = renderTable(spec, {
  data: { scores: rows },
  artifacts: true,
});

result.svg;
result.manifest;
```

## API 参考

### DetailTable

| 属性                             | 类型                                                                      | 默认值     | 描述                                                               |
| -------------------------------- | ------------------------------------------------------------------------- | ---------- | ------------------------------------------------------------------ |
| `dataRef`                        | `DetailTableProps['dataRef']`                                             | —          | spec 中的外部数据引用名                                            |
| `data`                           | `DetailTableProps['data']`                                                | —          | 当前明细记录；不写入 spec                                          |
| `columns?`                       | `DetailTableProps['columns']`                                             | —          | 程序化地按展示顺序声明字段、列头与 presentation；与 children 互斥  |
| `children?`                      | `DetailTableProps['children']`                                            | —          | `DetailColumn` 声明顺序；与 `columns` 互斥                         |
| `model?`                         | `DetailTableProps['model']`                                               | —          | 可选字段模型                                                       |
| `header?`                        | `DetailTableProps['header']`                                              | `true`     | 是否生成列头行                                                     |
| `id?`                            | `DetailTableProps['id']`                                                  | —          | 稳定 Table id；嵌入父级 `Layout` 时必填                            |
| `layout?`                        | `DetailTableProps['layout']`                                              | 轨道默认值 | 默认/索引轨道尺寸、间距与 Table border                             |
| `rules?`                         | `DetailTableProps['rules']`                                               | `[]`       | 按声明顺序匹配并覆盖 formatter、presentation 或外观                |
| `encodings?`                     | `DetailTableProps['encodings']`                                           | `[]`       | 把选中 value Cell 的原始值映射到背景或内容颜色                     |
| `theme?`                         | `DetailTableProps['theme']`                                               | —          | standalone 根 Core Theme；embedded 时由外层 `<Layout>` 提供        |
| `tableThemeTokens?`              | `DetailTableProps['tableThemeTokens']`                                    | `{}`       | 当前 TableSpec 的稀疏 Table token 覆盖，优先于 inherited namespace |
| `meta?`                          | `DetailTableProps['meta']`                                                | —          | 写入 TableSpec 的 JSON 元数据                                      |
| `formatterDefinitions?`          | `DetailTableProps['formatterDefinitions']`                                | `[]`       | 自定义 Cell formatter definitions                                  |
| `structureDefinitions?`          | `DetailTableProps['structureDefinitions']`                                | `[]`       | 自定义结构 definitions                                             |
| `presentationDefinitions?`       | `DetailTableProps['presentationDefinitions']`                             | `[]`       | 自定义 Cell presentation definitions                               |
| `visualScaleDefinitions?`        | `DetailTableProps['visualScaleDefinitions']`                              | `[]`       | 自定义 Cell visual scale definitions                               |
| `composites?`                    | `DetailTableProps['composites']`                                          | `[]`       | Cell 内嵌 Tier 2 内容所需 definitions                              |
| `onManifest?`                    | `DetailTableProps['onManifest']`                                          | —          | standalone 布局产物通知；嵌入时不支持                              |
| `width?` / `height?`             | `DetailTableProps['width']`                                               | —          | 宿主显示尺寸；不改变 Table layout proposal                         |
| `viewBox?`                       | `DetailTableProps['viewBox']`                                             | —          | Scene 相机；不改变轨道求解                                         |
| `animate?` / `snapshotAt?`       | `DetailTableProps['animate']`                                             | —          | 复用 Kernel Layout 的动画宿主合同                                  |
| `renderer?`                      | `DetailTableProps['renderer']`                                            | `'svg'`    | 渲染后端                                                           |
| `className?` / `containerStyle?` | `DetailTableProps['className']`<br />`DetailTableProps['containerStyle']` | —          | 仅 standalone 透传给渲染宿主；嵌入时拒绝                           |

### DetailColumn

| 属性            | 类型                                | 默认值 | 描述                                  |
| --------------- | ----------------------------------- | ------ | ------------------------------------- |
| `id`            | `DetailColumnProps['id']`           | —      | 列的稳定标识                          |
| `field`         | `DetailColumnProps['field']`        | —      | 从每条记录读取的字段                  |
| `header?`       | `DetailColumnProps['header']`       | —      | 列头 payload；字符串会转为 value Cell |
| `formatter?`    | `DetailColumnProps['formatter']`    | —      | 正文原始 value 的 formatter 引用      |
| `presentation?` | `DetailColumnProps['presentation']` | —      | 正文 value Cell 的可选呈现引用        |
| `headerLayout?` | `DetailColumnProps['headerLayout']` | —      | 列头 Cell 的布局与四边 border 策略    |
| `bodyLayout?`   | `DetailColumnProps['bodyLayout']`   | —      | 正文 Cell 的布局与四边 border 策略    |

`detailTable(input)` 接收同一组 spec 输入并返回 `IRDetailTableSpec`。完整的 `Table`、`ManualTable`、schema、adapter 和 lowering 契约见 [API 参考](/viz/table/reference)。

Formatter 与 presentation 只处理 value Cell。直接提供 `content` 的 Cell 已经持有可渲染 child，会绕过两者；同时声明 `content` 与 formatter/presentation 会 fail-loud。
