明细表、显式网格和自定义结构的输入方式不同，但都会进入同一套 Table 模型。这个分组解释这些稳定概念如何协作，适合需要控制布局、读取产物或编写扩展的读者。

图中的主链先回答“有哪些 Cell”，再回答“Cell 里画什么”和“Cell 放在哪里”。`Scene` 与 `Manifest` 来自同一次编译，分别服务渲染和几何、语义消费。

## 职责一览

| 主题         | 负责什么                             | 何时查阅                         |
| ------------ | ------------------------------------ | -------------------------------- |
| 结构与单元格 | 统一行、列、Cell 身份、语义与来源    | 自定义表型或追踪 Cell 从哪里产生 |
| 内容呈现     | 把标量值解析为可布局的 Core 内容     | 自定义格式、图形内容或呈现扩展   |
| 布局与边框   | 测量内容、求解轨道、放置与解析共享边 | 控制尺寸、换行、跨度和边框冲突   |
| 产物与追溯   | 暴露轨道、Cell、边框几何与来源       | 命中、调试、导出或宿主集成       |

这四层共享同一份 canonical model。Structure 不负责绘制，Presentation 不负责轨道，Layout 不重新解释业务数据，Manifest 只观察同次编译的确定结果。
