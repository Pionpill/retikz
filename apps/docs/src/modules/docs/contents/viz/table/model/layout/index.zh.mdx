Table 布局同时处理内容的自然尺寸、父级约束、跨轨 Cell 和可见溢出。它不是把固定矩形简单排成网格，而是在一次事务中让轨道尺寸与 Cell 内容相互约束。

## 从测量到最终 replay

<ComponentPreview files="table-layout-stages" hideCode size="xs" />

图中的顺序是稳定的：先取得自然内容贡献，列宽确定后才为 `wrap` Cell 提供宽度约束；最终高度再参与行轨道求解。Cell box、内容放置和边框都基于这组已解轨道。

| 阶段         | 解决的问题                   | 产生的稳定信息                   |
| ------------ | ---------------------------- | -------------------------------- |
| 自然测量     | 内容不受表格约束时多大       | 行列 contribution                |
| 轨道求解     | 约束和内容如何分配给每条轨道 | row/column offset 与 size        |
| 内容放置     | child 如何进入 content box   | 变换后 allocation/visual bounds  |
| Border Graph | 共享边保留哪条候选           | winner、contributors 与可见 edge |
| 最终 replay  | 只提交选中的最终内容         | Scene children 与 manifest       |

probe 只参与求解，不会作为重复图元进入 Scene。最终输出 replay 的是经过 wrap、fit、alignment 和 overflow 决策后选中的 child 结果。

## 轨道如何获得尺寸

| 轨道类型   | 自然状态                     | 有限父级宽度下               |
| ---------- | ---------------------------- | ---------------------------- |
| `fixed`    | 使用明确尺寸                 | 不吸收额外空间               |
| `auto`     | 使用最大内容贡献             | 保持该贡献                   |
| `fraction` | 无有限宽度时退回内容贡献     | 按权重吸收剩余空间           |
| `minmax`   | 在下界、内容贡献和上界间求值 | 上界可继续参与有限或弹性增长 |

非 spanning Cell 直接向所在轨道贡献外部尺寸。跨轨 Cell 先计算已覆盖轨道和内部 gap；仍有 deficit 时，按确定顺序把需求传播给可增长轨道。全部 fixed 且不足时不会偷偷扩大固定轨道，内容是否超出 Cell 由后续 overflow 策略决定。

`fraction` 需要父级在该轴给出 exact 或有限 range proposal 才有“剩余空间”可分配；宿主 SVG 的显示宽度本身不是 Table layout proposal。

## 单元格与可见内容

井字中央的单元格就是 `box`：它由覆盖的轨道、内部 gap 和 span 共同确定；减去 padding 后得到 `contentBox`。随后 child 的占位和肉眼可见范围还可能继续分离。

<ComponentPreview files="table-cell-box" hideCode size="sm" />

从外到内可按下面四层理解。前两层逐层内缩；后两层是内容结果，可见范围不一定留在内容区内。

| 层级         | 形成方式                                                 | 外部间距                               | 负责什么                        |
| ------------ | -------------------------------------------------------- | -------------------------------------- | ------------------------------- |
| `box`        | 已解轨道 + `span`                                        | `columnGap` / `rowGap`，默认 `0`       | Cell 网格占位与边框位置         |
| `contentBox` | `box - padding`                                          | `padding`，默认 `0`                    | wrap、fit、对齐区域与 clip 边界 |
| 内容占位     | child 测量（`wrap: false`）→ `fit: none` → 两轴 `center` | 无独立属性；由内容尺寸与对齐产生       | replay 的逻辑位置与尺寸         |
| 可见范围     | child visual bounds → `overflow: visible`                | 无独立属性；`visible` 时可以越出内容区 | 最终肉眼可见的范围              |

蓝色内容占位对应 `contentAllocationBounds`，橙色可见范围对应 `visualOverflowBounds`。manifest 分别保留它们，因为逻辑占位与肉眼可见范围不一定相同。

图中两者高度不同也不是 Table 的间距属性造成的：蓝框来自 child 的 `allocationBounds`，橙框来自 child 的 `visualBounds`，描边等可见几何可能让后者更高。Table 对两者使用相同的 fit 和 alignment；`overflow` 只决定保留这段可见溢出，还是把它裁回 `contentBox`。如果 child 的两套原始 bounds 相同，默认 `visible` 下两框也会同高。

## Border Graph

边框不是每个 Cell 各画四条线。`collapse` 模式会把 Table 默认边和相邻 Cell side 放到相同原子边上，以 priority、Cell specificity、显式隐藏、线宽、owner side 与稳定来源顺序确定 winner；`separate` 模式则保留每个真实 Cell side。

只有可见 winner 会进入最终 edge。相邻、同样式且不会穿过垂直交点的实线原子可以确定性合并，同时在 manifest 中保留每个 atom 的 winner 与 contributors。
