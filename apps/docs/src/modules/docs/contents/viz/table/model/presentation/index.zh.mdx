Structure 已经决定 Cell 是谁、位于哪里，但标量值还不是可测量、可渲染的图形内容。Presentation 层把 value Cell 转成 Core child，同时允许已经持有图形内容的 Cell 直接进入下一阶段。

## 两种内容路径

<ComponentPreview files="table-presentation-flow" hideCode size="xs" />

图中的两条路径最终都得到一个与原 Cell 同 identity、同顺序的 Core child。差别在于谁负责构造它：

| payload   | 保存什么                                   | 如何得到 Core child                 |
| --------- | ------------------------------------------ | ----------------------------------- |
| `value`   | `string`、`number`、`boolean` 等常规值     | registry 解析 Definition 后调用     |
| `content` | 文本、图标、Node、组合图形等任意可渲染内容 | 校验后直接使用，不调用 presentation |

`value` 保存普通单元格值，例如姓名字符串、金额数字或布尔状态；Presentation 决定这些值最终如何显示。

`content` 直接保存任意可渲染内容，例如带样式文本、图标、Node 或组合图形。它不再调用 Presentation，因此 presentation options 只属于 value 路径。

## 内置与自定义走同一入口

未指定 presentation 时，value Cell 使用内置 `text`。它把 scalar 转成无描边、无填充、零 padding 的 Core Node；`null` 呈现为空字符串。

自定义 Presentation Definition 由稳定名称、精确 options schema 与 `present()` 组成。运行时把内置和自定义 Definition 合并进同一个 registry，再按 `presentation.name` 解析；重复名称、未注册名称、非法 options 或非 JSON-safe 输出都会 fail-loud。

Presentation 的输出仍需通过 Core child schema。这样内置文本与自定义图形共用后续测量、布局、replay 和 renderer，而不是为表格建立第二套渲染语义。

## Presentation 不负责什么

| 相邻职责  | Presentation 会读取 | Presentation 不决定              |
| --------- | ------------------- | -------------------------------- |
| Structure | Cell id、payload    | 行列地址、角色、来源与 span      |
| Layout    | 产出的 Core child   | 轨道尺寸、padding、fit、overflow |
| Renderer  | 不直接接触 renderer | SVG、Canvas 或 SSR 的输出实现    |

因此，同一个 Presentation Definition 可以被不同表型复用；同一个 Cell 的布局策略也可以独立于值的呈现方式调整。
