明细表契约把“每条外部记录生成一行”保存为可序列化规则，而不把记录本身写进 IR。`data.reference` 指向运行时 dataset，`structure.columns` 决定字段读取、列顺序、列头与正文 formatter/presentation；共享根字段再承载 rules、encodings 与 `tableThemeTokens`。Core Theme 的 `style` / `mode` 由宿主 Scene / Scope 提供，不写入 IRDetailTable。

## IRDetailTable

`IRDetailTable` 是明细表的精确根类型。与聚合 `IRTable` 相比，它明确要求 `data`，并把 `structure` 收窄为 `detail`。

| 字段        | 类型                                                                                                                                                   | 默认值                                     | 描述                                                                                                |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------ | --------------------------------------------------------------------------------------------------- |
| `data`      | `IRDetailTable['data']`<br />- `reference: string`<br />- `model?: IRDataModel`                                                                        | —<br />- —<br />- —                        | 必需的外部 dataset reference<br />- 运行时 dataset 名称<br />- 可选数据模型                         |
| `structure` | `IRDetailTableStructure`<br />- `kind:` <ApiValues name="TableStructureKind" /><br />- `columns: Array<IRTableDetailColumn>`<br />- `header?: boolean` | —<br />- `'detail'`<br />- —<br />- `true` | record-per-row Structure<br />- Structure 判别值<br />- 至少一列，id 必须唯一<br />- 是否生成列头行 |

## Column

### TableDetailColumnSchema

<ZodSchema
  name="TableDetailColumnSchema"
  description="明细列：稳定 id、字段路径、列头、正文 formatter/presentation 与列头/正文 Cell 布局。"

    bodyLayout: '应用于该列所有正文 Cell 的可选布局与四边 border 策略。',
  }}
/>

作者侧 `TableDetailColumnInput` 额外允许把 `header` 写成字符串；`createDetailTableIR()`、`DetailTable` 和 `detailTable()` 会把它规范化为 `{ kind: 'value', value: header }`。
`headerLayout` / `bodyLayout` 共用 [TableCellLayoutSchema](/viz/table/reference/contract-layout#tablecelllayoutschema)，可分别设置 padding、对齐、wrap、fit、overflow 与 border。

列 `formatter` 是 body value Cell 的默认引用；根 `rules` 可以按 Cell selector 有序覆盖它。formatter 只改变显示 scalar，字段选择、visual encoding 和 value predicate 始终读取 formatter 前的原始值。

## 精确 schema 的使用边界

只生成明细表的 LLM、表单或持久化接口应使用 `DetailTableSchema`，这样不会暴露 manual/custom 无关字段。只有在同一协议需要接收多种 Table 根变体时，才切换到聚合 `TableSchema`。
