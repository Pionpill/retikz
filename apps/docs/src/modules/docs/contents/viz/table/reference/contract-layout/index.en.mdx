Layout contracts describe how Cells occupy tracks, how content fits a Cell box, and how a Table configures tracks and borders. This page lists inputs; see [Artifact contracts](/viz/table/reference/manifest) for resolved geometry and provenance after compile.

## Cell layout

### TableCellSpanSchema

<ZodSchema name="TableCellSpanSchema" />

A span cannot leave the row/column range, overlap another Cell, or cross row kinds.

## Table layout

### TableLayoutSchema

<ZodSchema name="TableLayoutSchema" />

Omitted fields resolve to fixed `120` columns, fixed `32` body rows, header rows that follow the body default, and zero gaps. `auto` and `minmax` consume content contributions; fractions expand columns only under a finite parent-width constraint, while rows currently use natural contributions.

## Track size primitives

The following primitives are used directly by `TableLayoutSchema.columnSize` / `rowSize` / `headerRowSize` and sparse overrides. They express fixed sizes, intrinsic content sizes, remaining-space fractions, and bounded tracks.

Track size discriminators are <ApiValues name="TableTrackSizeKind" />.

### TableFixedTrackSizeSchema

<ZodSchema name="TableFixedTrackSizeSchema" />

A fixed value may be `0` to represent an explicitly collapsed track.

### TableAutoTrackSizeSchema

<ZodSchema name="TableAutoTrackSizeSchema" />

### TableFractionTrackSizeSchema

<ZodSchema name="TableFractionTrackSizeSchema" />

The runtime materializes an omitted `weight` as `1`.

### TableMinmaxTrackSizeSchema

<ZodSchema name="TableMinmaxTrackSizeSchema" />

When both bounds are fixed, `min.value` cannot exceed `max.value`. The minimum accepts fixed or auto sizing; the maximum accepts fixed, auto, or fraction sizing.
