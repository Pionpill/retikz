Base Table contracts define the top-level identity, Cell content, and layout fields shared by every table type, plus precise manual and custom root variants. See [Detail Table contracts](/viz/table/reference/contract-detail) for the detail-only data reference and column structure.

## TableSpec root

`IRTableSpec` aggregates `IRDetailTableSpec | IRManualTableSpec | IRCustomTableSpec`. The three variants share `namespace + type` fields and constrain `data` and `structure` independently.

| Field       | Type                                | Default        | Description                                              |
| ----------- | ----------------------------------- | -------------- | -------------------------------------------------------- |
| `namespace` | `'table'`                           | —              | Tier 2 composite namespace                               |
| `type`      | <ApiValues name="TableComposite" /> | —              | Top-level Table node type                                |
| `id?`       | `string`                            | —              | Optional stable id                                       |
| `layout?`   | `IRTableLayout`                     | track defaults | Tracks, sparse overrides, gaps, and borders              |
| `meta?`     | `IRJsonObject`                      | —              | JSON-safe metadata preserved by lowering                 |
| `data?`     | `IRDataReference`                   | —              | Required by detail, forbidden by manual, optional custom |
| `structure` | `IRTableStructureOperation`         | —              | Detail, manual, or custom Structure                      |

## Cells

`IRManualTableCell` is the directly persistable non-null entry used inside manual `rows`. `string | number | boolean` are value shorthands; rich objects carry value/content, spans, layout, and semantic fields. `null` is the row-matrix empty-slot sentinel, not a Cell union member; use `{ value: null }` for a real null scalar.

## Layout

### TableLayoutSchema

<ZodSchema name="TableLayoutSchema" />

Omitted fields resolve to fixed `120` columns, fixed `32` body rows, header rows that follow the body default, and zero gaps. `auto` and `minmax` consume content contributions; fractions expand columns only under a finite parent-width constraint, while rows currently use natural contributions.

## Track size primitives

The following primitives are used directly by `TableLayoutSchema.columnSize` / `rowSize` / `headerRowSize` and sparse overrides. They express fixed sizes, intrinsic content sizes, remaining-space fractions, and bounded tracks.

Track size discriminators are <ApiValues name="TableTrackSizeKind" />.
