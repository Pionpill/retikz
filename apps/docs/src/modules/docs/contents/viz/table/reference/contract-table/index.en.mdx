Base Table contracts define the top-level identity and Cell content shared by every table type, plus precise manual and custom root variants. See [Detail Table contracts](/viz/table/reference/contract-detail) for detail-only data references and columns, or [Layout contracts](/viz/table/reference/contract-layout) for Cell boxes, tracks, and borders.

## IRTable root

`IRTable` aggregates `IRDetailTable | IRManualTable | IRCustomTable`. The three variants share `namespace + type` fields and constrain `data` and `structure` independently.

| Field                 | Type                                | Default        | Description                                              |
| --------------------- | ----------------------------------- | -------------- | -------------------------------------------------------- |
| `namespace`           | `'table'`                           | —              | Tier 2 composite namespace                               |
| `type`                | <ApiValues name="TableComposite" /> | —              | Top-level Table node type                                |
| `id?`                 | `string`                            | —              | Optional stable id                                       |
| `appearanceDefaults?` | `IRTableAppearanceDefaults`         | `{}`           | Sparse appearance defaults for existing Cells            |
| `layout?`             | `IRTableLayout`                     | track defaults | Tracks, sparse overrides, gaps, and borders              |
| `meta?`               | `JsonObject`                        | —              | JSON-safe metadata preserved by lowering                 |
| `rules?`              | `Array<IRTableCellRule>`            | `[]`           | Declaration-ordered Cell overrides                       |
| `encodings?`          | `Array<IRTableCellVisualEncoding>`  | `[]`           | Ordered raw-value mappings to color channels             |
| `visualDefaults?`     | `IRTableVisualDefaults`             | `{}`           | Default color ranges for existing visual encodings       |
| `tableDefaults?`      | `IRTableDefaults`                   | `{}`           | Sparse defaults below explicit Source fields             |
| `data?`               | `IRDataReference`                   | —              | Required by detail, forbidden by manual, optional custom |
| `structure`           | `IRTableStructureOperation`         | —              | Detail, manual, or custom Structure                      |

## Cell content

`IRManualTableCell` is the directly persistable non-null entry used inside manual `rows`. `string | number | boolean` are value shorthands; rich objects carry value/content, spans, layout, and semantic fields. `null` is the row-matrix empty-slot sentinel, not a Cell union member; use `{ value: null }` for a real null scalar.

Rich entries may provide a stable `id`. When omitted, the Cell remains anonymous and later stages correlate it through canonical address and array order rather than materializing an address-derived id.

## Table Source defaults

Core Theme `style` / `mode` comes from the host `Layout` or `renderTable(..., { theme })`. Table builds an owner-local baseline for the mode, then merges the same-named `TableThemeStyleDefinition` result shaped as `{ defaults?: IRTableDefaults }`. Source `tableDefaults`, `appearanceDefaults`, `visualDefaults`, and explicit `layout.borders` override earlier defaults in order; Cell-local configuration, visual encodings, and ordered rules then complete the final plan.

`appearanceDefaults`, `visualDefaults`, and `tableDefaults` are sparse objects. They provide defaults only for existing Cells, borders, or visual encodings and never create Cells, rules, borders, encodings, or Legends. `layout.borders.outer` is a sparse physical-side object with independent `top`, `right`, `bottom`, and `left` candidates.

Published packages do not pre-register named Core or Table definitions. This site's `academic`, `vibrant`, and `clean` reference styles follow the same rule as application-defined styles: inject the same name into both consuming owners. Standalone `compileTable` receives the Core definition through `compile.themeStyles` and the Table definition through `lower.tableThemeStyles`. Missing the matching Table definition fails loudly in the Table resolver.

### TableDefaultsSchema

<ZodSchema name="TableDefaultsSchema" />

Omitting `style` selects the Table owner-local baseline for the host mode. This site's `academic` reference follows a publication / booktabs direction, `vibrant` uses strong colors with a light surface, and `clean` removes as much nonessential decoration as possible. An injected definition returns only sparse defaults for the current mode; the baseline fills the rest, and Source defaults can target only defaultable visual fields of existing structure and encodings. The resolved manifest records complete defaults and the actual cascade layers; `themeMode` is output metadata, not an IRTable input field.
