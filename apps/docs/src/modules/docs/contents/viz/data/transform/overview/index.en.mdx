`<PlotTransform>` is a declarative component from `@retikz/plot-react`. It places one JSON-serializable transform operation into the current `<Plot>` data pipeline and renders no graphics of its own.

The Data transform contract does not depend on Plot; this component is only a Plot React authoring entry point for that contract. Other consumers can call `@retikz/data` operations and runtime functions directly without going through `<PlotTransform>`.

## Usage

```tsx
import { Plot, PlotTransform } from '@retikz/plot-react';
```

```tsx
<Plot data={rows}>
  <PlotTransform operation={{ kind: 'sort', field: 'date', order: 'ascending' }} />
  {/* marks */}
</Plot>
```

One `<PlotTransform>` represents one operation. For a multi-step pipeline, declare components in dependency order: the output rows of one step become the input rows of the next.

### Choose an entry point

All three forms belong to the Plot application layer, but their scope differs.

| Entry                    | Best for                                    | Scope                                            |
| ------------------------ | ------------------------------------------- | ------------------------------------------------ |
| `<PlotTransform ... />`  | Reading and composing operations in JSX     | Shared pipeline of the current Plot              |
| `dataTransforms={[...]}` | Programmatically generated operation arrays | Shared pipeline, before component declarations   |
| mark-local `transform`   | A local data view for one mark              | That mark only; other mark inputs stay unchanged |

Data defines and executes all twelve built-in kinds through the same component. See [Data Contract](/viz/data/reference/contract#datatransformschema) for complete contracts and [Plot transforms](/viz/plot/transform) for composition examples.

## How it works

<ComponentAlert
  type="tip"
  title="Optional for everyday use"
  description="Revisit this section when debugging why the component renders nothing, how multiple entry points are ordered, or how automatic transforms are deduplicated."
/>

The `PlotTransform` function returns `null`. While building the plot spec, `Plot` synchronously walks its children, recognizes `PlotTransform` elements, and collects their props as `IRDataTransformDeclaration` values. It is therefore a configuration carrier rather than a visible layer, and it accepts no children.

The shared pipeline is assembled in this order:

1. the `dataTransforms` array
2. `<PlotTransform>` elements in JSX declaration order
3. operations generated by mark shortcuts

When an explicit `stack` has the same signature as an automatic `stack`, the automatic operation is suppressed to avoid double stacking. Other operations keep their assembled order.

## API Reference

#### PlotTransform / PlotTransformProps

`PlotTransformProps` uses `IRDataTransformDeclaration`. Required `operation` is discriminated by `kind`; optional `dataExecution` chooses computation for this stage.

| Prop            | Type              | Meaning                                                                                     |
| --------------- | ----------------- | ------------------------------------------------------------------------------------------- |
| `operation`     | `IRDataTransform` | Operation parameters; see [Data Contract](/viz/data/reference/contract#datatransformschema) |
| `dataExecution` | `IRDataExecution` | Sparse `mode` and `external` name, inherited independently                                  |

The component, `dataTransforms`, and mark-local `transform` all use `{ operation, dataExecution? }` rather than bare operations. Built-in and custom operations share this declaration.

Executor defaults < Plot root `dataExecution` < declaration `dataExecution`, with priority increasing to the right. The final default is `builtin`; `external` requires support for every stage; `hybrid` selects local computation only when external preflight explicitly reports unsupported. See [Extension Mechanisms](/viz/data/transform/extensions) for provider registration and Promise host integration.
