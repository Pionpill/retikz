title: Data provenance
description: Trace transform outputs to input records, record transform, field-flow and operator events, and limit samples or consume events through a callback.
---

A summary row can represent several detail records, and sorting changes output positions. Data preserves source indices so an application can look up contributing records or inspect a computation. See [Data transforms](/viz/data/transform) for operation declarations.

| Provenance type | Records and purpose                                                                                  | How to read it                                                                  |
| --------------- | ---------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| Row provenance  | Input indices behind an output row, for looking up one or more original records                      | Call `readSourceIndex` or `readSourceIndices` on the output row                 |
| Lineage events  | Transform stages, field flow and operator records from one execution, for inspecting the computation | Read the returned `lineage.events`, or receive events through a `sink` callback |

Both forms remain separate from business fields.

## Using provenance

Use `applyTransforms` to execute operations. `provenance: true` assigns sources to unmarked inputs, and `lineage: true` records events with the default configuration. The example enables both, sorts four sales records and sums revenue by region, producing West with a total of 6 and East with a total of 8.

```ts
import { applyTransforms, readSourceIndices } from '@retikz/data';

const sourceRows = [
  { region: 'East', period: 1, revenue: 3 },
  { region: 'East', period: 2, revenue: 5 },
  { region: 'West', period: 1, revenue: 2 },
  { region: 'West', period: 2, revenue: 4 },
];
const operations = [
  { kind: 'sort', params: { field: 'revenue', order: 'ascending' } },
  {
    kind: 'summarize',
    params: {
      groupBy: ['region'],
      metrics: [{ kind: 'sum', field: 'revenue', as: 'total' }],
    },
  },
] satisfies Array<import('@retikz/data').IRDataTransform>;
const { rows, lineage } = applyTransforms(sourceRows, operations, { provenance: true, lineage: true });
const indices = readSourceIndices(rows[0]); // [2, 3], the two West records
const details = indices?.map(index => sourceRows[index]);
console.log(details, lineage?.events);
```

| Property     | Default | Description                                                                                                                                                                                                                                |
| ------------ | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `provenance` | `false` | Set it to `true` to assign source indices to unmarked inputs. Existing sources are always retained.                                                                                                                                        |
| `lineage`    | `false` | Omit it or pass `false` to disable event recording, `true` to use the default configuration, or an object to customize event content, samples and a callback. Source summaries read existing markers without assigning new source indices. |

To customize recording scope, use a `lineage` object with these properties. Omitted properties use their defaults:

| Property                    | Default                                          | Description                                                                                                                                     |
| --------------------------- | ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `sourceIdentity`            | `{ mode: 'summary', maxIndices: 20 }`            | Records source count, an index prefix and truncation. `false` disables source summaries; `true` or `{}` uses the default summary configuration. |
| `sourceIdentity.mode`       | `'summary'`                                      | `'summary'` retains an index prefix; `'full'` retains all indices.                                                                              |
| `sourceIdentity.maxIndices` | `20`                                             | A positive integer limiting the number of indices retained in summary mode.                                                                     |
| `transformSteps`            | `true`                                           | Records transform order, names, input/output row counts and fields.                                                                             |
| `fieldFlow`                 | `false`                                          | Set it to `true` to record field reads and outputs declared by the Definition.                                                                  |
| `reducerOperations`         | `false`                                          | Set it to `true` to record reducer configuration, fields, row counts and sources.                                                               |
| `selectorOperations`        | `false`                                          | Set it to `true` to record selector configuration, input sources and selected sources.                                                          |
| `rowSamples`                | `false`                                          | Pass `{ maxRows, fields }` to record field-value samples before and after transforms.                                                           |
| `calculationDetails`        | `false`                                          | Pass `{ maxRows, fields }` to sample reducer inputs or selector candidates. The corresponding operator recording must also be enabled.          |
| `sink`                      | Not set                                          | Pass `event => ...` to receive events individually during execution.                                                                            |
| `retainEvents`              | With `sink`: `false`<br />Without `sink`: `true` | Set it to `true` to also retain the returned event array. Without a `sink`, events are always retained.                                         |

For an existing `DataView`, use `applyTransformsToDataView` with the same provenance options. For external execution, see [External computation](/viz/data/transform/computation).

## How sources propagate

Switch operations to compare output fields and sources for the same inputs. Every option first sorts by `revenue` ascending. See [Transform operations](/viz/data/transforms) for details on each operation.

`readSourceIndex(row)` reads a single-row source; `readSourceIndices(row)` reads group sources. The markers use `SOURCE_INDEX` and `SOURCE_INDICES` Symbol keys. Field paths and `JSON.stringify` ignore them, while object spread preserves these enumerable Symbols. A JSON round trip loses provenance.

`provenance` is off by default. For row sources without events, pass `{ provenance: true }`, or tag rows separately with `tagSourceIndex`. Existing single-row or group sources survive subsequent calls without renumbering; look them up in the dataset where their indices were first assigned.

## Recording scope

With `lineage: true`, the entry records a `source` event and `transformStep` summaries, with row counts, declared input/output fields and source summaries. Source summaries retain at most 20 indices by default; enable other records individually.

The next example always runs sort, select each group's maximum row, then sum each group. Its summary limit is 2 to expose `count`, `indices` and `truncated`; the API default remains 20.

`sourceIdentity: false` omits event source summaries without removing row markers. `{ mode: 'full' }` records all indices. `maxIndices` limits summaries only, not a row's group provenance.

Both `rowSamples` and `calculationDetails` require a positive integer `maxRows` and a nonempty `fields` whitelist. The limit applies to each sample, not the whole run. `calculationDetails` also needs `selectorOperations` or `reducerOperations`; it does not generate operator events by itself. There is currently no separate regression event. Transform steps and row samples still describe fitting inputs and outputs.

Field flow uses declarations, without tracing individual cells or every step in a callback. Event source collections concatenate row sources and can repeat indices. Multiple predictions referencing one group, for example, make `count` differ from the number of distinct original records.

## Consuming events

Read the returned `lineage.events` by default. Supply `sink` to receive events individually during execution; the returned array is then empty by default. Set `retainEvents: true` when both forms are needed.

```ts
const result = applyTransforms(sourceRows, operations, {
  provenance: true,
  lineage: {
    sink: event => console.log(event),
    retainEvents: true,
  },
});
```

Without `sink`, events always remain in the returned array, even with `retainEvents: false`. A failed computation throws instead of returning a complete result; events already delivered describe only a partial execution. The application chooses storage and display behavior. Events are not written into data IR.

## Custom transforms

A row-preserving implementation can use `{ ...row, derived: value }` to carry sources. When constructing an output representing multiple inputs, call `context.groupProvenance(output, members)` with the actual contributing rows:

```ts
apply: (rows, operation, context) => [
  context.groupProvenance(
    { total: rows.reduce((sum, row) => sum + Number(row.revenue), 0) },
    rows,
  ),
],
```

This is the computation callback of a transform Implementation; see [Extension mechanisms](/viz/data/transform/extensions) for definition and registration. Stage records read field declarations from the Definition, so custom computations must declare fields accurately and preserve sources. An output position is not an original index. A result without a unique source must not claim single-row provenance.
