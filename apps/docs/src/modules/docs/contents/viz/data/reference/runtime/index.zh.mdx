title: 运行时
description: 查询 @retikz/data 如何注入外部 rows 与 Definition、解析 registry、规范化字段、执行 transform 并返回 lineage。

Data schema 只保存配置；外部 rows、字段 parser、Definition、registry 与事件 sink 都是运行时对象。`@retikz/data` 保持纯计算和宿主无关，输出 canonical rows、字段信息、provenance 标记或 lineage 事件，不生成 Scene 或视觉图元。

沿实线看 rows 的主处理路径：宿主数据先完成字段解析与规范化，再依次执行 transform。虚线表示 Definition、registry 与 JSON 契约提供的运行时依赖，以及可选的诊断输出。

因此，JSON-safe 契约决定允许保存什么配置，Definition 声明这些配置的语义，Implementation 与执行器决定如何计算。处理后的 rows 可按需携带 Symbol provenance；lineage 则作为独立运行记录返回或发送给事件 sink。

## 语义与计算分离

| 契约       | 语义 Definition                             | 计算 Implementation |
| ---------- | ------------------------------------------- | ------------------- |
| transform  | schema、输入字段、outputModel、dependencies | apply               |
| reducer    | schema、输入字段、outputs                   | reduce              |
| selector   | schema、输入字段                            | select              |
| regression | schema                                      | fit                 |

`defineTransform` 等语义工厂与对应 `define*Implementation` 分别注册。实现必须引用注册表中的同一个 Definition，不能用相同 kind 替代身份。内置语义与实现也遵守此契约。FieldFormatDefinition 继续拥有源值 parser，不参与此次计算分离。

语义 registry 合并内置与自定义 Definition；重复键或覆盖内置键失败。开放 operation 的 JSON schema 保存参数，dispatch 后由精确 Definition schema 一次解析。`resolveDataTransforms(declarations, inputModel, options?)` 按顺序解析字段与完整输出模型，不读取行或执行计算。

## 异步执行

`createDataTransformExecutor(options?)` 保存本地实现、具名 externalProviders、默认 dataExecution 和可选 materializeSource。执行配置优先级为执行器 < 宿主根 < 单条 declaration，mode 与 external 名称分别继承。

1. `executor.prepare(descriptor, resolution, options?)` 预检整个计划；descriptor 只提供模型与必要源句柄，不伪造 rows
2. 返回 ready 后，用 `bind(actualInput)` 绑定真实 source 或 result
3. 调用一次 `execute()`，取得 `DataTransformResult` 或 Promise；任何成功、失败或取消后均不能重试该实例
4. `ingestDataTransformResult` 核对 rows、完整 model 与语义计划；空行仍保留字段和分类顺序，额外 payload 字段不会自动进入模型

`executeDataTransforms` 是上述过程的单次调用入口。provider 的 resolve 与阶段 execute 都允许 Promise。hybrid 仅对预检明确 unsupported 的阶段选择本地；查询异常、执行失败、非法输出或取消均不补算。完整模式和可运行例子见[扩展机制](/viz/data/transform/extensions)。

## 字段准备

| 入口                     | 职责                                                             |
| ------------------------ | ---------------------------------------------------------------- |
| `resolveFieldTypes()`    | 合并 `model` 声明与样本推断，并校验严格字段集合                  |
| `applyFieldResolver()`   | 应用宿主提供的逐字段类型/parse 覆盖                              |
| `collectFormatFields()`  | 从具名 format Definition 补出蕴含类型与 parser                   |
| `normalizeRows()`        | 按 field map、最终类型与 parser 写回逻辑字段名，保留其它原始字段 |
| `validateBoundData()`    | 抽样解释某字段为何没有有效值                                     |
| `assertAllValuesValid()` | 对 canonical rows 执行全量严格校验                               |

`normalizeRows()` 不执行 transform。消费方先完成字段收集、类型解析与规范化，再把 canonical rows 交给 transform pipeline；这种边界让 Plot、Table 与其它宿主复用同一套 Data 处理语义。

## 分类域

`defineFieldOrder` 定义具名比较器；`resolveFieldOrderRegistry(definitions?)` 合并内置与请求内定义，禁止重复名称。`assertFieldOrders(model, registry?)` 在模型接入时验证所有具名顺序，即使没有有效类别也执行。

`resolveCategoryDomain(values, order, registry?)` 返回新的类别排列，跳过非字符串或非有限数字，按值身份去重。省略 registry 时使用内置定义。显式数组保留声明类别并追加未列出的观测值；排序不会修改行、类型或 lineage。契约与示例见[扩展机制](/viz/data/model/extensions#定义分类顺序)。

## Transform 与 lineage

`applyTransforms(rows, operations?, options?)` 按声明顺序执行 operation，只返回 rows；options 提供 registry、独立同步实现与 context。Promise 或外接模式使用执行器。`applyTransformsWithLineage(rows, operations?, options?)` 会先给输入行添加不可序列化到 JSON 的 Symbol 来源标记，再返回：

| 字段      | 类型                 | 说明                                                       |
| --------- | -------------------- | ---------------------------------------------------------- |
| `rows`    | `Array<ExternalRow>` | 变换后的调用方输入 rows；上游已规范化时保持 canonical 语义 |
| `lineage` | `DataLineageRun`     | 本次运行保留的结构化事件；使用 sink 时默认不重复留存事件   |

`DataLineageOptions` 默认只记录轻量 source 与 transform-step 摘要。`rowSamples` 和 `calculationDetails` 必须显式给出 `maxRows` 与字段白名单；完整来源索引也必须通过 `sourceIdentity: { mode: 'full' }` 显式开启。它们是诊断能力，不会回写 Data IR。
