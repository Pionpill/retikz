字段模型为数据约定稳定的名字与含义。先确定字段表示类别、数值还是时间，再通过 `model` 声明解析规则和必要的分类顺序，数据变换与消费方就能使用同一份约定。

## 字段模型

销售接口可能返回 `{ region: 'north', revenue: 12 }`，预测接口则返回 `{ area: 'north', pricing: { amount: '12' } }`。两者都表示地区和收入，但字段路径与值的存储形式不同。

模型约定后续始终使用 `region` 和 `revenue`，这些名字叫**逻辑字段**；原始记录中的 `area`、`pricing.amount` 叫**物理路径**。接入时通过字段映射对齐名字，再把数字串解析为数值。下面两份记录是可替换的数据来源，最终提供相同的逻辑字段：

<ComponentPreview files="source-to-logical-fields" size="md" hideCode type="illustration" />

物理路径与逻辑字段同名时无需映射；具体配置见[数据接入](/viz/data/model/intake)。字段模型（`IRDataModel`）只保存字段约定，真实数据行在运行时另行传入。

## 测量类型

同样是数字 `10`，它可能表示可以计算差值的收入，也可能只是一个阶段编号。`@retikz/data` 的字段类型描述的是**怎样理解和使用字段**，不是原始数据采用了 `number`、`string` 还是 `Date` 存储。

`@retikz/data` 提供三种内置测量类型：

| 测量类型      | 类型名 | 字段含义                         | 例子                         |
| ------------- | ------ | -------------------------------- | ---------------------------- |
| `continuous`  | 连续型 | 数值大小和差值有意义             | 收入 `12`、温度 `20`         |
| `categorical` | 离散型 | 值用于区分类别，编码间距没有意义 | 地区 `north`、阶段编号 `10`  |
| `temporal`    | 时间戳 | 值表示日期或时间点               | `2026-09-23`、带时区的时间戳 |

这三类是当前数据处理与可视化共同需要的基本区分：数值距离、类别身份和时间顺序。`@retikz/data` 据此整理参与字段的有效值：连续字段成为有限数值，时间字段成为毫秒时间戳，分类字段保留字符串或有限数字类别。下游消费模块可按相同的字段语义做变换或映射，而无需重新猜测原始值。字段类型只约定数据语义，不规定消费方如何呈现。

<Comparison target="vega" title="Vega-Lite 的字段语义类型">
这里对照的是 Vega 生态中 Vega-Lite 编码字段的 `type`：它描述字段的测量含义或地理形状角色，而不是数据加载时的输入解析类型。

| Vega-Lite 类型 | 字段含义                 | 与 `@retikz/data` 的关系                        |
| -------------- | ------------------------ | ----------------------------------------------- |
| `quantitative` | 可比较大小与差值的量     | 对应 `continuous`                               |
| `nominal`      | 无序的离散类别           | 对应 `categorical`                              |
| `ordinal`      | 有顺序的离散类别         | 归入 `categorical`，可通过 `order` 指定类别顺序 |
| `temporal`     | 日期或时间               | 对应 `temporal`                                 |
| `geojson`      | 用于 geoshape 的地理形状 | `@retikz/data` 没有对应的字段测量类型           |

`@retikz/data` 将有序与无序类别合并为 `categorical`，没有单独的 `ordinal` 类型。Vega-Lite 的 `geojson` 专用于地理形状；经纬度通道中的数值仍属于 `quantitative`，不能把所有地理字段都归为 `geojson`。当前没有对应 `geojson` 的字段类型。

</Comparison>

选择测量类型时，应根据字段含义，而不是原始值的存储形式。考虑下面两列：

```json
{ "stage": 10, "revenue": "12" }
```

`stage` 应声明为 `categorical`：`10` 与 `20` 是不同阶段，不意味着阶段之间有十个单位的距离。`revenue` 应声明为 `continuous`：虽然原始值是字符串，归一化后它可以成为数值 `12`，供求和等操作使用。数字也能表示类别，字符串也能表示数值；选择类型要看字段含义。

`temporal` 与连续数值同样可以比较先后和间隔，但它保留时间语义，让消费模块选择时间刻度和日期格式。普通数字不会仅因看起来像时间戳就自动推断成时间；非默认日期格式也需要明确解析。

## 字段声明

`model` 是字段声明的数组。例如，下面约定地区是类别、收入是连续数值：

```ts
import type { IRDataModel } from '@retikz/data';

const model: IRDataModel = [
  { name: 'region', type: 'categorical' },
  { name: 'revenue', type: 'continuous' },
];
```

把它传给消费方的 `model` 属性后，`revenue: '12'` 可以被解析为 `revenue: 12`。简单、无歧义的数据可以省略模型并使用自动推断；字段含义不能随样本变化时，应显式声明。

每项字段声明都是可从 `@retikz/data` 导入的 `IRDataFieldDefinition`。它是按 `type` 区分的联合类型，各分支共享以下字段：

| 公共字段  | 类型                                                    | 作用                                                                   |
| --------- | ------------------------------------------------------- | ---------------------------------------------------------------------- |
| `name`    | `string`                                                | 必填的非空白逻辑字段名，供数据变换与消费方引用                         |
| `format?` | <ApiValues name="BuiltinDataFieldFormat" /> \| `string` | 可选的内置或自定义解析格式；省略时使用默认转换，具名格式也可以蕴含类型 |

除了公共字段，字段声明还涉及两个字段：`type` 指定测量类型，省略时从格式或数据推断；`order` 指定分类域顺序，是否允许声明取决于 `type`。两者的组合约束如下：

| `type`                        | 字段含义             | `order` 约束                                                                                                                        |
| ----------------------------- | -------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `'categorical'`               | 离散类别             | 可省略；接受 <ApiValues name="BuiltinFieldOrderMode" />、自定义名称或非空 `Array<string \| number>`                                 |
| `'continuous'` / `'temporal'` | 连续数值 / 日期时间  | 不允许声明，包括 `'appearance'`                                                                                                     |
| 省略                          | 从格式或数据推断类型 | 可省略；接受 <ApiValues name="BuiltinFieldOrderMode" />、自定义名称或非空 `Array<string \| number>`；声明后若解析为非分类类型则报错 |

**省略字段类型与漏掉字段声明是两回事。** 可以只写 `{ name: 'region' }`，保留类型推断；但一旦声明 `model`，当前数据管线引用的每个源字段都必须列在其中，字段名也不能重复。例如，配置引用了 `revenue`，模型却只有 `size`，就会报错；原始数据里未被引用的额外列无需全部列出。

## 字段解析

`name` 确定要读取的逻辑字段；`type` 和 `format` 决定字段类型及解析规则。下图按是否声明 `format`、是否声明 `type` 区分三种情况，三条分支任选其一，再汇合到值解析与顺序处理：

<ComponentPreview files="field-resolution" hideCode type="flow" size="xl" />

- **有 `format`**：使用已注册格式的类型和解析器。若同时声明 `type`，两者必须一致；未知格式或类型冲突会报错。例如 `percent` 对应 `continuous`，将 `'50%'` 解析为 `0.5`。
- **无 `format`，有 `type`**：使用声明类型的默认转换。例如 `continuous` 可以将严格数字串 `'12'` 转为数值 `12`。
- **两者都省略**：从样本推断类型，再使用默认转换。数字编码的类别应显式声明为 `categorical`，数字串也不会仅凭内容被推断为连续量。

`order` 不参与类型推断。显式非分类类型搭配 `order` 会在声明校验时被拒绝；省略 `type` 时，若最终解析为非分类类型也会报错。分类字段如何排列见[数据接入的分类顺序](/viz/data/model/intake#分类顺序)。

图中按逻辑字段取值；物理路径不同或需要了解内置格式时，见[数据接入](/viz/data/model/intake)。需要在值解析前通过程序化解析器覆盖类型或解析规则时，见[扩展机制](/viz/data/model/extensions)。

### 自动推断

未声明 `type`、也没有 `format` 蕴含类型时，`@retikz/data` 按下面的规则识别原始样本：

| JavaScript 值      | 示例或条件                                                             | 样本测量类型         |
| ------------------ | ---------------------------------------------------------------------- | -------------------- |
| `number`           | 有限数值，如 `12`；数值时间戳也属于此类                                | `continuous`         |
| `bigint`           | 如 `12n`                                                               | `continuous`         |
| `Date`             | `Date` 实例                                                            | `temporal`           |
| `string`：日期形式 | `2026-09-23`，或带 `Z` / 时区偏移的日期时间，如 `2026-09-23T08:00:00Z` | `temporal`           |
| `string`：其它形式 | `'north'`、`'12'`、`'2026/09/23'`、不带时区的日期时间                  | `categorical`        |
| `boolean`          | `true`、`false`                                                        | `categorical`        |
| 其它值             | `null`、`undefined`、`NaN`、无穷数、普通对象、数组、函数、`symbol`     | 跳过，不计入有效样本 |

推断针对整列：最多扫描前 1000 行，收集前 100 个有效样本；样本全部属于同一种测量类型时采用该类型，出现多种测量类型或没有有效样本时回退到 `categorical`。例如，`12` 与 `12n` 同属连续量，得到 `continuous`；`12` 与 `'12'` 混合则得到 `categorical`。日期形式识别不等于日期有效性校验，实际值仍需经过后续解析。

规范化后的行使用逻辑字段名，行数保持不变；它不会为缺失值补造数据。缺失值、解析失败及处理策略见[数据接入的校验策略](/viz/data/model/intake#校验策略)。
