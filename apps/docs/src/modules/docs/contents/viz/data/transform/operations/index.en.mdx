`@retikz/data` provides twelve built-in row-data operations. They process canonical rows without knowing whether the result will feed a chart, table, or another consumer; this page uses Plot only as the default example host.

## All built-in operations

All twelve operations obtain their schemas, definitions, registry, and computation from the `@retikz/data` package root. Operations execute in declaration order. Operations that replace row shape also replace the result model; subsequent consumers can only read retained fields.

| Operations                           | Input → output                                                  | Examples/reference                                     |
| ------------------------------------ | --------------------------------------------------------------- | ------------------------------------------------------ |
| sort / summarize / select / annotate | Records → reordered, aggregated, selected, or annotated records | Examples below                                         |
| stack / normalize                    | Numeric records → cumulative intervals or group shares          | [Drawing compositions](/viz/plot/transform/annotation) |
| derive-interval / jitter             | Numeric fields → interval fields or deterministic offsets       | [Field derivation](/viz/plot/transform/row)            |
| bin                                  | Continuous observations → bin edges and metric records          | [Binning example](/viz/plot/transform/bin)             |
| relate                               | Groups and endpoint selectors → paired records                  | [Relation example](/viz/plot/transform/relate)         |
| density / smooth                     | Numeric samples → density or fitted prediction records          | [Statistical sampling](/viz/plot/transform/statistics) |

See [Data Contract](/viz/data/reference/contract#datatransformschema) for complete configuration. `applyTransforms(rows, operations)` executes independently; Plot and Chart consume the same data contracts.

## Capabilities

| kind        | Row count | Data meaning                             | Common use                                 |
| ----------- | --------- | ---------------------------------------- | ------------------------------------------ |
| `sort`      | N → N     | Stably reorder rows by a field           | Fix temporal order or prepare later input  |
| `summarize` | N → G     | Generate one statistical row per group   | Group summaries and statistical abstracts  |
| `select`    | N → K     | Select representative original rows      | Extremes, top-N, and outlier samples       |
| `annotate`  | N → N     | Broadcast group stats or representatives | Mean lines, thresholds, and context layers |

## sort

`sort` stably reorders rows by one field. Equal values keep their original relative order, which is useful before line connection, time-series display, or later grouped processing.

`null`, `undefined`, `NaN`, and infinities are treated as missing and remain after valid values in both ascending and descending order.

Keep it separate from [`order`](/viz/data/model/fields-and-types#category-order) in the field contract: `sort` reorders rows, while `order` reorders a categorical domain.

| prop     | type                               | default       | description |
| -------- | ---------------------------------- | ------------- | ----------- |
| `field`  | `string`                           | —             | Sort field  |
| `order?` | <ApiValues name="DataSortOrder" /> | `'ascending'` | Direction   |

## summarize

`summarize` groups by `groupBy`, then reduces each group into one output row through `metrics`. The output row keeps the group keys, and every reducer must declare an `as` field name.

Output names must be unique within one operation: reducer outputs cannot collide with `groupBy` or with each other. The schema rejects static field conflicts from built-in reducers; custom reducer fields declared by the Definition's `outputs` fail before reducer execution.

  defaultSourceFile="transform-summarize-preview.tsx"
  size="lg"
  caption="The table contains detail orders; each bar is one region reduced into the shared metric field."

`IRDataSummarizeTransform` fixes `kind` to `'summarize'`.

| prop       | type                   | default          | description                                            |
| ---------- | ---------------------- | ---------------- | ------------------------------------------------------ |
| `groupBy?` | `Array<string>`        | one global group | Group key fields; supports composite keys              |
| `metrics`  | `IRDataReducerMetrics` | —                | Group statistics; every reducer declares output fields |

```tsx
<PlotTransform
  operation={{
    kind: 'summarize',
    groupBy: ['region'],
    metrics: [
      { kind: 'sum', field: 'revenue', as: 'total' },
      { kind: 'median', field: 'revenue', as: 'median' },
      { kind: 'count', as: 'orders' },
    ],
  }}
/>
```

## select

`select` runs a selector per group and outputs the selected original rows. It does not reduce values into new statistical objects, so it preserves city names, ids, anchors, and other original fields while keeping only extremes, top-N rows, or outliers.

  defaultSourceFile="transform-select-preview.tsx"
  size="lg"
  caption="Every point still represents an original city row; tied values make first, last, and all visibly distinct."
/>

`IRDataSelectTransform` fixes `kind` to `'select'`.

| prop       | type                      | default          | description                         |
| ---------- | ------------------------- | ---------------- | ----------------------------------- |
| `groupBy?` | `Array<string>`           | one global group | Group key fields                    |
| `selector` | `IRDataSelectorOperation` | —                | Representative-row rule             |
| `rankAs?`  | `string`                  | —                | One-based rank field on output rows |

```tsx
<PlotTransform
  operation={{ kind: 'select', groupBy: ['region'], selector: { kind: 'top', by: 'revenue', n: 3 }, rankAs: 'rank' }}
/>
```

## annotate

`annotate` groups rows first, then broadcasts reducer results or selected representative values back to every row in the group. It is useful for group mean lines, median bands, or thresholds around detail rows.

Selector annotations accept only built-in rules that select at most one row: `min` / `max`, `first` / `last` / `nth`, and `top` / `bottom` with `n: 1`. Tie handling may use the default `first` or `last`, but not `all`. Use `select` for multi-row selection and `outside-quantile-band`; express other scalar annotations as reducers.

  defaultSourceFile="transform-annotate-preview.tsx"
  size="lg"
  caption="Detail points remain unchanged while reference lines read the current benchmark statistic broadcast to every row."

`IRDataAnnotateTransform` fixes `kind` to `'annotate'` and requires at least `metrics` or `selectors`.

| prop         | type                            | default          | description                                   |
| ------------ | ------------------------------- | ---------------- | --------------------------------------------- |
| `groupBy?`   | `Array<string>`                 | one global group | Group key fields; supports composite keys     |
| `metrics?`   | `IRDataReducerMetrics`          | —                | Statistical metrics to broadcast to every row |
| `selectors?` | `Array<IRDataAnnotateSelector>` | —                | Broadcast one representative                  |

```tsx
<PlotTransform
  operation={{
    kind: 'annotate',
    groupBy: ['store'],
    metrics: [{ kind: 'mean', field: 'revenue', as: 'storeMean' }],
    selectors: [{ selector: { kind: 'max', by: 'revenue' }, as: 'storeMax' }],
  }}
/>
```

Metric outputs and selector `as` fields must also be unique within an `annotate` operation. See [Statistical Sub-operators](/viz/data/transform/statistics) for the full reducer and selector sets.

## Public types

Types inferred from transform schemas use the `IRDataXxx` convention.

| Scope         | Types                                                                                                 |
| ------------- | ----------------------------------------------------------------------------------------------------- |
| Overall union | `IRDataTransform`, `IRDataBuiltinTransform`                                                           |
| Built-ins     | `IRDataSortTransform`, `IRDataSummarizeTransform`, `IRDataSelectTransform`, `IRDataAnnotateTransform` |
| Nested config | `IRDataOrderBy`, `IRDataAnnotateSelector`                                                             |

See [`Transform`](/viz/data/transform/overview) to declare these operations in Plot React, or [Extension Mechanisms](/viz/data/transform/extensions) to register a custom kind.
