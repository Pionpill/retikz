title: Data Transforms
description: Data transforms rewrite canonical rows in order and make sorting, summarization, representative-row selection, and statistical annotation reusable across consumers.

Data transforms belong to `@retikz/data`. They read canonical rows produced by the data model, process them in order, and return new canonical rows for charts, tables, and other consumers.

## Overall flow

The following `summarize` example starts with canonical product-level detail. Grouping by `region` returns region-level summary rows, replacing `product` and `revenue` with the derived `total` and `orders` fields.

<ComponentPreview files="data-transform-shape" size="md" previewClassName="!p-3" hideCode />

This example changes both row grain and the field set, but not every transform changes the column shape: `sort` only reorders rows, `select` primarily changes row count, and `annotate` preserves detail rows while adding statistical fields.

| Stage              | Input                        | Output                     | Responsibility                                  |
| ------------------ | ---------------------------- | -------------------------- | ----------------------------------------------- |
| Data model         | External rows + field model  | Canonical rows             | Align fields, parse values, and validate intake |
| Transform pipeline | Canonical rows + operation[] | New canonical rows         | Sort, summarize, select, or annotate in order   |
| Consumer           | Transformed rows             | Chart, table, or domain UI | Interpret fields and produce a concrete view    |

Every operation is JSON-serializable configuration backed by a Definition that supplies runtime behavior. Fields read by transforms participate in model validation; fields produced by transforms do not need to be declared in the model ahead of time.

## Responsibilities

| Topic                 | Responsibility                                        | Read it when                                             |
| --------------------- | ----------------------------------------------------- | -------------------------------------------------------- |
| Transform Operations  | Declaration parsing, model propagation, and execution | You want to understand pipeline validation and execution |
| Computation Operators | Reducer / selector cooperation with their host        | You want to trace local computation into output rows     |
| Computation Contracts | Local and external support, binding and execution     | You need another execution engine or asynchronous input  |
| Extension Mechanisms  | Custom transform, reducer, and selector Definitions   | Built-ins cannot express new processing semantics        |

Data owns all twelve built-ins. Their drawing compositions are shown under [Plot transforms](/viz/plot/transform), and complete contracts live in [Data Contract](/viz/data/reference/contract#datatransformschema). Registration of custom transforms, reducers, and selectors is centralized under [Extension Mechanisms](/viz/data/transform/extensions), while runtime lineage events live under [Data Provenance](/viz/data/provenance/data).
