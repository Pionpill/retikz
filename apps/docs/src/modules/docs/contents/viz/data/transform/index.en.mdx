---
title: Data Transforms
description: Data transforms rewrite canonical rows in order and make sorting, summarization, representative-row selection, and statistical annotation reusable across consumers.
---

Data transforms belong to `@retikz/data`. They read canonical rows produced by the data model, process them in order, and return new canonical rows for charts, tables, and other consumers.

This site uses Plot as the default example host only because a chart makes changes in row count, order, and statistical fields easy to see. Plot's React API can apply these capabilities through `<Transform>`, `dataTransforms`, or mark-local `transform`; those entry points are not part of Data itself.

## Overall flow

| Stage              | Input                        | Output                     | Responsibility                                  |
| ------------------ | ---------------------------- | -------------------------- | ----------------------------------------------- |
| Data model         | External rows + field model  | Canonical rows             | Align fields, parse values, and validate intake |
| Transform pipeline | Canonical rows + operation[] | New canonical rows         | Sort, summarize, select, or annotate in order   |
| Consumer           | Transformed rows             | Chart, table, or domain UI | Interpret fields and produce a concrete view    |

Every operation is JSON-serializable configuration backed by a Definition that supplies runtime behavior. Fields read by transforms participate in model validation; fields produced by transforms do not need to be declared in the model ahead of time.

## Responsibilities

| Topic                     | Responsibility                                                    | Read it when                                      |
| ------------------------- | ----------------------------------------------------------------- | ------------------------------------------------- |
| Transform                 | Declare Plot React operations and understand multi-entry ordering | You compose a pipeline in JSX or debug its order  |
| Transform Operations      | `sort`, `summarize`, `select`, and `annotate`                     | You reorder, aggregate, or retain original rows   |
| Statistical Sub-operators | Reducers, selectors, and quantile-band composition                | You compute metrics, choose extremes, or boxplots |
| Extension Mechanisms      | Custom transform, reducer, and selector Definitions               | Built-ins cannot express new processing semantics |

Plot-registered `stack`, `bin`, `normalize`, `derive-interval`, `relate`, `jitter`, `density`, and `smooth` remain under [Drawing Grammar transforms](/viz/plot/transform). Registration of custom transforms, reducers, and selectors is centralized under [Extension Mechanisms](/viz/data/transform/extensions), while runtime lineage events live under [Provenance](/viz/data/provenance).
