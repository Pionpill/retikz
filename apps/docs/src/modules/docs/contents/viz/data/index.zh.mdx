`@retikz/data` 是宿主无关的纯数据处理层：声明字段模型、把外部数据整理成 canonical 行、运行数据变换，并保留可追踪的来源信息。它不依赖 Plot，也不决定数据最终怎样展示；Plot、Table 或其它消费模块都可以读取同一份处理结果。

真实数据本身**不进入可序列化契约**。配置只描述“读哪些字段、字段是什么类型、怎么解析和变换”；数据行由消费方在运行数据管线时传入，只有 `model`、`format`、transform operation 这类契约会持久化。于是同一份配置能复用到不同数据源，也便于序列化与 AI 生成。

## 处理链路

数据管线会先收集消费方真正用到的字段，再把外部行整理成 canonical 行（规范化行：字段对齐、解析、类型归一后写回逻辑字段名的标准行）。后续数据变换与各类消费模块都读取这份规范化结果，而不是反复直接读原始数据。

| 步骤         | 做什么                                                         | 主要配置                          |
| ------------ | -------------------------------------------------------------- | --------------------------------- |
| 数据引用     | 选择当前视图使用哪份外部数据，数据本身不进入 IR                | `data` / `data.reference`         |
| 字段契约     | 确定逻辑字段名、类型、分类顺序与声明式格式；未声明时按样本推断 | `model`                           |
| 源字段对齐   | 把逻辑字段映射到真实数据路径，支持字段改名与嵌套路径           | `fieldMap` / `fieldMaps`          |
| 解析与归一化 | 按字段契约与格式解析值，并写回逻辑字段名                       | `model` / `format` / 字段类型     |
| 数据校验     | 对参与字段做抽样或全量校验，决定非法值跳过还是报错             | `validateData` / `invalid`        |
| 变换与交付   | 数据变换改写 canonical 行，再把结果交给具体消费模块            | `sort` / `summarize` / 消费方配置 |

`model`、`format` 和数据变换 operation 是可序列化契约，函数只在运行时参与处理，不进入 IR。内置能力之外的运行时注册统一见[扩展机制](/viz/data/model/extensions)。

## 消费边界

数据层只负责把外部行整理成 canonical 行，不规定结果必须进入哪一种视图，也不拥有通道、图元或布局语义。

在 Plot 应用中，mark、transform 与 scale 可以按逻辑字段名读取这些结果，字段或常量如何进入 `x` / `y` / `color` / `size` / `text` 由[绘图语法的通道](/viz/plot/channel)说明。其它消费模块可以用自己的契约读取同一份规范化行。
