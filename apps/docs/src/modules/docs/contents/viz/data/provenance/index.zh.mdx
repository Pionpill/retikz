---
title: 来源追踪
description: 来源追踪记录 canonical 行和 transform 输出行来自哪些原始行，让下游模块可以解释统计结果、定位异常和构造交互元信息。
---

数据一旦经过字段映射、解析和 transform，输出行就不一定还能直接等同于原始数据集里的某一行。`@retikz/data` 的 provenance 用来记录这条输出行从哪里来：是原始行、重排行、分组统计行、代表行，还是多个来源合成出的派生行。

provenance 是数据层能力，不负责创建 plot 节点 id，也不决定交互命中策略。plot 可以把这些来源信息继续写入 mark meta，table 可以用它解释汇总行，geo 可以用它回溯空间聚合来源。

## 记录什么

| 字段             | 含义                                           | 典型来源                         |
| ---------------- | ---------------------------------------------- | -------------------------------- |
| `sourceIndex`    | 原始数据集里的行号；仅能唯一回指原行时存在     | 字段解析、`sort`、`select`       |
| `sourceIndexes`  | 多个原始行号；适合分组统计或聚合结果           | `summarize`、`annotate`          |
| `transformedIndex` | 当前阶段输出行序号                           | 每个 transform 阶段              |
| `derived`        | 该行是否由统计、采样或投影生成                 | `summarize`、plot 注册的 `bin`   |
| `operation`      | 产生该行的 transform kind 或处理阶段           | `sort` / `summarize` / custom    |
| `lineage`        | 需要跨多个阶段保留来源时追加的轻量链路信息     | 多段 transform 管线              |

这些字段是调试和消费层元信息，不会改变字段值、scale 推断或 mark 几何。数据层只保证“可追踪时就保留，不可唯一追踪时不伪造单一来源”。

## transform 后的语义

不同 transform 对来源的保留方式不同：

| transform 类型             | 来源语义                                      |
| -------------------------- | --------------------------------------------- |
| 保行重写，如 `sort`        | 行仍来自同一原始行，保留 `sourceIndex`        |
| 代表行选择，如 `select`    | 输出行就是被选中的原始行，保留 `sourceIndex`  |
| 统计汇总，如 `summarize`   | 输出行来自一组原始行，记录 `sourceIndexes`    |
| 统计标注，如 `annotate`    | 明细行保留自身 `sourceIndex`，附加组统计来源  |
| 自定义 transform           | definition 负责声明是否能保留或合成 provenance |

这个规则避免把统计行伪装成某一条原始数据。比如分组求和后的 `total` 不是任何一个订单，而是一组订单的派生结果；它应该携带来源集合，而不是随便挑一个 `sourceIndex`。

## 下游消费

provenance 常见有三类消费者：

| 消费方 | 使用方式 |
| ------ | -------- |
| plot   | 把来源信息写入 mark meta，供 tooltip、locator 或调试工具读取；plot 自己注册的 datum id / anchor 仍在[绘图语法](/viz/grammar)下说明 |
| table  | 在汇总行、筛选行或异常行旁展示来源数量与回溯入口 |
| geo    | 对聚合后的区域、网格或采样点解释来自哪些原始空间记录 |

如果只需要在 plot 里绑定 `x` / `y` / `color`，不需要手动处理 provenance；它是给调试、交互和跨模块解释用的附加数据。

## 自定义定义

自定义 transform 应尽量显式声明 provenance 行为：

| 情况 | 建议 |
| ---- | ---- |
| 一行输入对应一行输出 | 复制输入行 provenance，并更新 `transformedIndex` |
| 多行规约成一行 | 写入来源集合，不写单一 `sourceIndex` |
| 生成采样 / 模拟行 | 标记 `derived`，并写明 `operation` |
| 来源无法可靠追踪 | 省略来源字段，不伪造可追踪性 |

这样下游模块可以在不理解自定义算法细节的情况下，仍然知道一行数据是否可回溯、能回溯到多少原始行，以及这条来源链是否经过派生。
