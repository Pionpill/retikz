---
title: Data 来源追溯
description: 来源追溯让变换后的数据行仍能回指原始输入，并用可选的运行时事件解释数据怎样被处理。
---

数据经过解析、排序或汇总后，输出行可能已经不再等同于原始数据集中的某一行。`@retikz/data` 用来源追溯回答两个不同的问题：**这行来自哪里**，以及**这次计算经历了什么**。

来源追溯是宿主无关的数据层能力，不创建 Plot 图元 id，也不决定 tooltip 或命中策略。本文用 Plot、Table 等作为消费示例；这些宿主不属于 Data 契约。

## 整体流程

<ComponentPreview files="provenance-flow" size="xs" hideCode />

来源身份在数据进入变换管线时建立。保行变换继续携带单行来源，聚合类变换把多个来源合并成集合，最终与 canonical 行一起交给消费模块。下游不需要根据字段值或输出位置重新猜测来源。

## 两种来源产物

<ComponentPreview files="provenance-artifacts" size="sm" hideCode />

Data 将“随行传播的来源”与“解释一次运行的事件”分成两套产物，避免把审计信息塞进业务数据行。

| 产物           | 载体                                     | 回答的问题                 | 生命周期                      |
| -------------- | ---------------------------------------- | -------------------------- | ----------------------------- |
| 行级来源元数据 | `SOURCE_INDEX` / `SOURCE_INDICES` Symbol | 当前行来自哪些输入行       | 随数据行传播                  |
| 运行时链路事件 | `DataLineageRun.events`                  | 运行了哪些阶段、字段和算子 | 由本次调用返回或发送给 `sink` |

### 行级来源元数据

`SOURCE_INDEX` 和 `SOURCE_INDICES` 是 Symbol 键，不是字符串字段名：

| Symbol           | 何时存在                               | 读取方式                 |
| ---------------- | -------------------------------------- | ------------------------ |
| `SOURCE_INDEX`   | 当前行仍能唯一回指一条原始输入行       | `readSourceIndex(row)`   |
| `SOURCE_INDICES` | 当前行由多条输入行汇总、分组或聚合而成 | `readSourceIndices(row)` |

对象展开会保留这些可枚举 Symbol，因此常规保行变换可以自然传播来源；字段路径解析和 `JSON.stringify` 会忽略它们，不会污染数据字段或可序列化配置。自己组装 Data 管线时可用 `tagSourceIndex` 给输入行打标；`applyTransformsWithLineage` 已自动完成这一步。

### 运行时链路事件

链路事件按开关记录 source、transform 阶段、字段流、reducer、selector 或受限的行样本。它们不会写回数据行，也不会进入 JSON IR。`transformedIndex`、transform kind 和字段流等运行信息属于事件或具体宿主的产物，不是 Data 行上的通用字段。

## 来源怎样传播

<ComponentPreview files="provenance-transform" size="sm" hideCode />

| 变换形态                 | 来源语义                                                        |
| ------------------------ | --------------------------------------------------------------- |
| 稳定重排，如 `sort`      | 行仍来自同一输入行，保留 `SOURCE_INDEX`                         |
| 代表行选择，如 `select`  | 输出就是被选中的原始行，保留该行来源                            |
| 明细标注，如 `annotate`  | 每条明细行保留自身来源；新增统计字段不改变行身份                |
| 分组汇总，如 `summarize` | 输出行代表整组输入，写入 `SOURCE_INDICES`                       |
| 自定义改行数变换         | 若输出代表一组输入，必须通过 `context.groupProvenance` 合并来源 |

关键约束是：**不可唯一追溯时，不伪造单一来源**。例如分组求和后的 `total` 不是某一笔订单，而是一组订单的派生结果；它应该携带来源集合。

## 记录计算链路

需要解释 transform 顺序、字段输入输出或统计子算子时，用 `applyTransformsWithLineage` 代替 `applyTransforms`。两者执行相同的 transform Definition；前者额外返回运行时事件。

```ts
import { applyTransformsWithLineage } from '@retikz/data';

const { rows, lineage } = applyTransformsWithLineage(sourceRows, operations, {
  lineage: {
    sourceIdentity: { mode: 'summary', maxIndices: 10 },
    fieldFlow: true,
    reducerOperations: true,
    rowSamples: { maxRows: 5, fields: ['region', 'revenue', 'total'] },
  },
});
```

`lineage: {}` 默认只记录来源索引摘要和 transform 阶段摘要，包括顺序、kind、输入 / 输出行数与字段集合。其它信息必须显式开启：

| 开关                 | 默认值                    | 记录内容                                                   |
| -------------------- | ------------------------- | ---------------------------------------------------------- |
| `sourceIdentity`     | `summary`，最多 20 个索引 | 来源数量、受上限约束的索引前缀和截断状态                   |
| `transformSteps`     | `true`                    | transform 顺序、kind、行数和字段集合                       |
| `fieldFlow`          | `false`                   | 每个阶段读取与产出的字段                                   |
| `reducerOperations`  | `false`                   | reducer 配置、字段、行数与来源摘要                         |
| `selectorOperations` | `false`                   | selector 配置、输入来源与选中来源摘要                      |
| `rowSamples`         | `false`                   | transform 前后受行数和字段白名单约束的样本                 |
| `calculationDetails` | `false`                   | reducer 输入或 selector 候选详情，同样要求行数与字段白名单 |

`sourceIdentity: { mode: 'full' }` 会记录完整来源索引，必须由宿主明确开启。`rowSamples` 与 `calculationDetails` 都要求正整数 `maxRows` 和非空 `fields`，避免默认复制整行数据。

如果提供 `lineage.sink`，事件会逐条发送给回调，默认不再保留到返回的 `lineage.events`。宿主同时需要流式消费和完整数组时，再设置 `retainEvents: true`。

## 消费边界

<ComponentPreview files="provenance-consumers" size="md" hideCode />

Data 只交付数据行、行级来源和可选链路事件；怎样把它们变成视图、交互或审计面板，由具体宿主决定。

| 消费方   | 典型用途                                                 |
| -------- | -------------------------------------------------------- |
| Plot     | 把 Data 链路补充为图元、比例尺和布局语义，支持定位与审计 |
| Table    | 解释汇总行、筛选行或异常行来自哪些明细                   |
| 其它宿主 | 按自身契约追溯聚合、采样或派生结果                       |

只做字段绑定、排序或汇总时通常不需要直接读取来源元数据；它主要服务回查、诊断和审计。Plot 如何生成宿主专属链路，见[Plot 溯源](/viz/data/provenance/plot)。
