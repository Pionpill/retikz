---
title: 扩展机制
description: 定义字段格式、分类顺序与运行时解析器，同时保持数据模型配置可序列化。
---

数据模型支持扩展字段解析与分类顺序。可复用的解析规则注册为具名格式，一次性或数据源专用规则通过运行时字段解析器（resolver）提供；两者都不会把函数写进可序列化配置。

## 适用边界

先阅读[字段类型](/viz/data/model/field-types)与[数据接入](/viz/data/model/intake)，优先使用内置格式和排序规则。只有新的存储格式会跨数据源复用时才注册 `FieldFormatDefinition`；只服务当前数据源的解析分支使用 `resolveField`。

| 扩展入口            | 解决什么                 | 配置保存什么  |
| ------------------- | ------------------------ | ------------- |
| `defineFieldOrder`  | 自定义类别比较规则       | `order` 名称  |
| `defineFieldFormat` | 可复用字段存储格式       | `format` 名称 |
| `resolveField`      | 临时类型覆盖与字段解析器 | 不进入配置    |

`fieldMap` 只负责把逻辑字段映射到真实路径，不执行解析，也不是扩展注册机制。字段测量类型仍是封闭的 `continuous`、`temporal` 与 `categorical`；自定义解析最终必须落到这三种规范值域。

## 定义字段格式

需要通过名称引用、可跨数据源复用的格式使用 `defineFieldFormat`。`name` 是 model 中的引用键，`impliedType` 声明规范值类型，`parse` 把原始值转换为字符串、有限数值或 `undefined`。

报表中的收入可能写成 `'1.2K'`，但计算和绘图需要数值 `1200`。下面自定义一个名为 `thousands` 的解析格式：`K` 表示千，去掉 `K` 后缀，将前面的数字乘以 `1000`，并把字段类型确定为 `continuous`。例如，`'1.2K' → 1200`、`'2.4K' → 2400`；普通数值和不带后缀的数字串按原数值处理。

`thousands` 是本示例注册的名称，不是内置格式。将定义加入本次数据处理使用的格式注册表后，收入字段用 `format: 'thousands'` 引用它；`model` 只保存格式名，解析函数留在运行时。

关键是定义解析规则、注册名称，再由字段声明引用；下面直接展示 Data API：

```ts
import type { IRDataModel } from '@retikz/data';
import { defineFieldFormat, resolveFormatRegistry } from '@retikz/data';

const thousands = defineFieldFormat({
  name: 'thousands',
  impliedType: 'continuous',
  parse: raw => {
    if (typeof raw === 'number') return raw;
    if (typeof raw !== 'string') return undefined;
    const text = raw.trim();
    const value = text.endsWith('K') ? Number(text.slice(0, -1)) * 1000 : Number(text);
    return Number.isFinite(value) ? value : undefined;
  },
});
const model: IRDataModel = [{ name: 'revenue', format: 'thousands' }];
const registry = resolveFormatRegistry([thousands]);
registry.get('thousands')?.parse('1.2K'); // 1200
```

## 定义分类顺序

内置自然排序适合版本标签与编号；语言排序或其它业务规则可通过 `defineFieldOrder` 定义。下面注册 `labelLength`，默认按标签长度比较，等长标签保持出现顺序。切换内置规则可以比较结果；长度排序只是演示自定义比较器，并不等价于版本号排序。

定义比较器并注册后，可以直接用 Data API 生成分类域：

```ts
import { defineFieldOrder, resolveCategoryDomain, resolveFieldOrderRegistry } from '@retikz/data';

const labelLength = defineFieldOrder({
  name: 'labelLength',
  compare: (a, b) => String(a).length - String(b).length,
});
const registry = resolveFieldOrderRegistry([labelLength]);
const domain = resolveCategoryDomain(['10.18', '2.0', '10.2', '10.2.0'], 'labelLength', registry);
// ['2.0', '10.2', '10.18', '10.2.0']
```

定义包含 `name` 与 `compare(a, b, context)`。比较器返回有限数值：负数表示 a 在前，零表示同序，正数表示 a 在后；`context.values` 是当前作用域去重后的有效类别，按出现序排列。比较器应为纯函数，满足反对称性与传递性，不修改值或上下文。

分类顺序只决定类别域，不改变原始数据行的顺序。字段模型用 `order: 'labelLength'` 保存名称，比较器由运行时注册表提供。

## 运行时字段解析

一次性逻辑或数据源专用分支使用 `resolveField`。它按逻辑字段返回可选的 `type` 与 `parse`，覆盖已确定的类型或解析器；返回 `undefined` 时保留原有结果。格式注册和类型兼容检查先于 resolver，因此它不能绕过未知格式或格式与显式类型冲突。

下面把 `2026Q1` 这样的季度标签转成季度起始时刻。模型已经声明 `quarter` 为时间类型，因此 resolver 只需返回 `parse`。如果模型未显式声明类型，返回解析函数时必须同时返回 `type`，即使格式或样本已能确定类型也一样。

运行时解析器只关心字段与原始值。下面显式返回时间类型，将季度标签转换为该季度起始时刻：

```ts
import type { ResolveField } from '@retikz/data';

const resolveField: ResolveField = field =>
  field === 'quarter'
    ? {
        type: 'temporal',
        parse: raw => {
          const match = /^(\d{4})Q([1-4])$/.exec(String(raw));
          return match ? Date.UTC(Number(match[1]), (Number(match[2]) - 1) * 3, 1) : undefined;
        },
      }
    : undefined;
```

`resolveField` 是运行时逃生舱，不经过注册表（registry）。它及其返回的解析函数不能序列化，也不会进入 IR，只保留在消费侧的运行时代码中。需要稳定名称、跨宿主复用或持久化配置时，应改为 `FieldFormatDefinition`：IR 只保存格式名称，定义及其解析函数仍由消费侧在运行时提供。

## 错误与限制

| 情况                                                  | 结果                                                                          |
| ----------------------------------------------------- | ----------------------------------------------------------------------------- |
| 格式名为空、排序名为空白，或名称重复、覆盖内置名      | 注册表构建报错                                                                |
| 模型引用未注册格式或排序名                            | 接入失败；接收模型的进程也必须注入同名定义                                    |
| 格式类型与显式 `type` 冲突                            | 在 resolver 执行前报错                                                        |
| resolver 返回 `parse`，但模型和返回值都未显式给出类型 | 接入失败；推断类型或格式蕴含类型不能代替这项声明                              |
| 解析器返回与类型不符的值、`undefined` 或非有限数值    | 形成不可用值，交给[校验策略](/viz/data/model/intake#校验策略)，不重试默认转换 |
| 排序比较器抛错或返回非有限数值                        | 抛出 `RetikzDataError`；回调异常保留为 `cause`                                |

字段解析只负责单值规范化，不重排行、不改变行数，也不生成统计字段；这些能力属于[数据变换扩展](/viz/data/transform/extensions)。
