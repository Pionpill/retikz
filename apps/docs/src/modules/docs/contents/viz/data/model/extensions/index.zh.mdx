Data 的自定义能力遵循同一条边界：配置只保存格式名或 `{ kind, ...config }`，函数留在运行时 Definition 中，并由消费宿主注入。下面用 React `<Plot>` 展示结果，但这些扩展契约属于 Data，不依赖 Plot。

## 适用边界

优先组合内置格式、transform、reducer 与 selector；只有现有操作不能表达稳定、可复用的数据语义时才注册 Definition。一次性或数据源专用的字段解析使用 `resolveField`，不为它创建全局注册键。

| 扩展入口                  | 解决什么                  | IR 保存什么              |
| ------------------------- | ------------------------- | ------------------------ |
| `defineFieldFormat`       | 可复用字段存储格式        | `format` 名称            |
| `resolveField`            | 临时类型覆盖与字段 parser | 不进入 IR                |
| `defineTransform`         | 新的行处理操作            | `{ kind, ...config }`    |
| `defineStatisticsReducer` | 分组行归约为字段片段      | reducer `{ kind, ... }`  |
| `defineRowSelector`       | 从分组中选择原始行        | selector `{ kind, ... }` |

`fieldMap` 只是逻辑字段到真实路径的映射，不执行计算，也不是扩展注册机制。字段测量类型仍是封闭的 `continuous`、`temporal` 与 `categorical`；自定义格式或 resolver 只能落到这三种规范值域。

## 扩展字段解析

可持久化、可跨数据源复用的格式使用 `defineFieldFormat`。`name` 是 model 中的引用键，`impliedType` 声明规范值类型，`parse` 把原始值转换为字符串、有限数值或 `undefined`。

### 运行时字段解析

一次性逻辑或数据源专用分支使用 `resolveField`。它按逻辑字段返回可选的 `type` 与 `parse`，优先级高于 model、声明式格式和默认转换；返回 `undefined` 时回到标准接入路径。

<ComponentPreview files={['extension-resolver', 'extension-resolver.data.ts']} />

`resolveField` 是运行时逃生舱，不经过 registry，也不能序列化。需要稳定名称、跨宿主复用或持久化配置时，应改为 `FieldFormatDefinition`。

## 扩展数据操作

新的行处理语义使用 `defineTransform`。Definition 的 `schema` 校验 JSON 配置并从 `kind` 提取注册键；`inputFields` 与 `outputFields` 让严格 model 校验区分源字段和派生字段；`apply` 执行纯数据变换。

<ComponentPreview files={['extension-transform', 'extension-transform.data.ts']} />

宿主通过 `transformDefinitions` 注入 Definition。内置与自定义 transform 合并进同一 registry，随后按操作 `kind` 查找、校验并执行。

### 来源追踪

自定义 transform 必须保持纯且确定。保留原行对象时会自然保留单行来源；改变行数且输出行代表一组源行时，用 `TransformContext.groupProvenance` 给结果挂组级来源：

| 输出关系             | 来源处理                                          |
| -------------------- | ------------------------------------------------- |
| 一行输入对应一行输出 | 保留原行的 provenance                             |
| 多行规约成一行       | 调用 `groupProvenance(out, members)` 记录来源集合 |
| 生成行没有明确来源   | 允许不携带来源，不伪造单一 `sourceIndex`          |

启用 lineage 时，同一 Definition 可能在普通下沉与记录链路时分别执行。因此随机或有状态逻辑应由宿主先固化输入，或在 Definition 外完成不确定计算。

## 扩展统计子算子

已有 transform 结构足够、只缺新的统计计算时，不必创建完整 transform：

| 子算子                    | 返回值       | 注入入口                       |
| ------------------------- | ------------ | ------------------------------ |
| `defineStatisticsReducer` | 一个字段片段 | `statisticsReducerDefinitions` |
| `defineRowSelector`       | 原始行及排名 | `rowSelectorDefinitions`       |

下面左图用自定义 reducer 计算每组极值中点，右图用自定义 selector 选择每组最接近均值的原始行。两者分别被内置 `summarize` 与 `select` 消费。

<ComponentPreview files={['extension-statistics', 'extension-statistics.data.ts']} />

reducer 用 `inputFields` 和 `outputFields` 声明字段流；selector 只声明读取字段，并返回原始行以保留来源与其它列。需要改变整行结构或执行多步处理时，再升级为自定义 transform。

## 执行机制

所有 Definition 扩展都经过同一条运行时路径：

```text
注入 Definition → 合并内置与自定义 registry → 按名称或 kind 查找 → operation schema 校验 → 执行
```

消费宿主负责把 Definition 集合交给 Data pipeline。以 Plot 为例，`formatDefinitions`、`transformDefinitions`、`statisticsReducerDefinitions` 与 `rowSelectorDefinitions` 都是运行时选项；Table 或其它模块可以用自己的 adapter 注入同一批 Data Definition。

## 错误与限制

| 情况                  | 结果                                                     |
| --------------------- | -------------------------------------------------------- |
| 与内置或自定义键重复  | registry 构建立即报错                                    |
| 配置引用未注册键      | 执行前报未注册错误                                       |
| operation 不符 schema | 在调用扩展实现前报错                                     |
| 配置含函数或非法数值  | 拒绝非 JSON-safe payload                                 |
| parser 返回错误类型   | 形成非法值，交给[校验与诊断](/viz/data/model/validation) |

Definition 不应依赖 Plot 的 mark、scale、coordinate 或 renderer。需要视觉语义的扩展属于 Plot；需要连接数据库、处理权限或缓存的扩展属于应用或 source adapter。
