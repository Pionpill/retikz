同样是数字 `10`，它可能表示可以计算差值的收入，也可能只是一个阶段编号。`@retikz/data` 的字段类型描述的是**怎样理解和使用字段**，不是原始数据采用了 `number`、`string` 还是 `Date` 存储。如果还不清楚字段如何从外部数据进入结果行，先读[数据行与字段](/viz/data/basic/rows-and-fields)。

## 为什么需要测量类型

数据源会切换，字段里的值也会变化。如果数据变换和可视化各自根据当前值猜测字段含义，同一个逻辑字段可能一会儿被当作可计算的数值，一会儿被当作类别；原始值从 `12` 变成 `'12'` 也可能改变处理结果。

测量类型让数据模型先约定字段的含义。`@retikz/data` 在接入时据此解析并归一化字段值，后续处理依赖同一份字段语义，不必重新猜测原始数据。这样数据源或样本发生变化时，字段的计算、分组与映射规则仍有稳定的依据。

## 三种内置类型

| 测量类型      | 字段含义                         | 例子                         |
| ------------- | -------------------------------- | ---------------------------- |
| `continuous`  | 数值大小和差值有意义             | 收入 `12`、温度 `20`         |
| `categorical` | 值用于区分类别，编码间距没有意义 | 地区 `north`、阶段编号 `10`  |
| `temporal`    | 值表示日期或时间点               | `2026-09-23`、带时区的时间戳 |

这三类是当前数据处理与可视化共同需要的基本区分：数值距离、类别身份和时间顺序。`@retikz/data` 据此整理参与字段的有效值：连续字段成为有限数值，时间字段成为毫秒时间戳，分类字段保留字符串或有限数字类别。下游消费模块可按相同的字段语义做变换或映射，而无需重新猜测原始值。[Plot 的比例尺](/viz/plot/scale)是一个消费例子；类型本身不规定图形怎样呈现。

## 原始值不决定字段语义

考虑下面两列：

```json
{ "stage": 10, "revenue": "12" }
```

`stage` 应声明为 `categorical`：`10` 与 `20` 是不同阶段，不意味着阶段之间有十个单位的距离。`revenue` 应声明为 `continuous`：虽然原始值是字符串，归一化后它可以成为数值 `12`，供求和等操作使用。数字也能表示类别，字符串也能表示数值；选择类型要看字段含义。

`temporal` 与连续数值同样可以比较先后和间隔，但它保留时间语义，让消费模块选择时间刻度和日期格式。普通数字不会仅因看起来像时间戳就自动推断成时间；非默认日期格式也需要明确解析。

## 类型与解析格式

`type` 回答“这个字段表示什么”；`format` 回答“原始值按什么规则解析”。例如，`'50%'` 表示连续量，但需要 `percent` 格式才会解析成 `0.5`。类型与格式可以一起声明；具名格式也可以蕴含类型。完整字段写法与优先级见[字段契约](/viz/data/model/contract)，内置格式及字段映射见[数据接入](/viz/data/model/intake)。

未声明时，`@retikz/data` 会从有效样本推断类型。数字编码的类别可能被推断为连续，数字字符串则不会仅凭内容被推断为连续。因此，当类型会影响结果，或输入格式不够明确时，应在 `model` 中显式声明；简单、无歧义的数据可以先使用推断。
