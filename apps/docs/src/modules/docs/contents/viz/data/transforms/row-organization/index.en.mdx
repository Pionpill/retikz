---
title: Row organization
description: Reorder rows with sort, or retain original records per group with select and optionally include ranks.
---

Row organization transforms change row order or which records are retained. `sort` keeps every row and changes their order. `select` outputs the original records chosen by a selector. Both retain existing fields; `select` can also add a rank field.

## sort

`sort` orders records by one field, preserving every row and field. With `groupBy`, sorting runs independently within each group, and groups are expanded in field-list order, retaining first-seen keys within each parent group. Omitted or empty grouping means global sorting. For example, `groupBy: ['team', 'item']` groups by team, then by item within each team. This example outputs A phone, A book, B phone, then B book. Group keys are not implicitly sorted alphabetically or numerically. Equal sort keys retain their relative order within a group. The sort schema is `SortTransformSchema`, with these parameters:

| Property         | Type                          | Description                                                         |
| ---------------- | ----------------------------- | ------------------------------------------------------------------- |
| `kind`           | `'sort'`                      | Transform kind                                                      |
| `params.groupBy` | `Array<string>`               | Optional calculation group fields; omitted or empty means one group |
| `params.field`   | `string`                      | Required, nonblank sort field name                                  |
| `params.order`   | `'ascending' \| 'descending'` | Optional sort direction; defaults to `'ascending'`                  |

## select

`select` groups records by `groupBy`, runs `selector` within each group, and outputs the selected records with their existing fields. Omitting `groupBy` or supplying an empty array treats all records as one group. Multiple fields form a composite key: records belong to the same group only when all group values match. Groups follow the same order as sort: field hierarchy with first-seen keys at each level. A group with no selection produces no output rows.

When `rankAs` is provided, the selector's one-based rank is written to that field. Omitting it leaves out the rank column. Each selector defines its ranking semantics; see [selector](/viz/data/operators/selector) for selection and tie policies. The row selection schema is `SelectTransformSchema`, with these parameters:

| Property          | Type                      | Description                                                                    |
| ----------------- | ------------------------- | ------------------------------------------------------------------------------ |
| `kind`            | `'select'`                | Transform kind                                                                 |
| `params.groupBy`  | `Array<string>`           | Optional group fields; omitted or empty means one group containing all records |
| `params.selector` | `IRDataSelectorOperation` | Required selector declaration to run within each group                         |
| `params.rankAs`   | `string`                  | Optional, nonblank output field name for one-based ranks                       |
