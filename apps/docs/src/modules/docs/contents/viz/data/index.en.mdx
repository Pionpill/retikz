`@retikz/data` is the host-independent data-processing layer: declare field models, normalize external rows into canonical rows, run data transforms, and preserve provenance. It does not depend on Plot or decide how data is ultimately presented; Plot, Table, and other consumers can read the same prepared result.

  title="Example host"
  description="This section uses Plot by default to visualize data before and after processing, so examples contain Plot components, marks, scales, and channels. Those are consumption patterns in a Plot application, not Data contracts, and they do not make @retikz/data depend on @retikz/plot."

Real data **does not enter the serializable contract**. Config records which fields to read, their types, and which serializable processing / transform operations to run. A consumer supplies rows when it runs the data pipeline; contracts such as `model`, `format`, and transform operations can be persisted. That keeps one config reusable across sources, serializable, and AI-friendly.

## Pipeline

The data pipeline first collects fields actually used by a consumer, then turns external rows into canonical rows (normalized rows where fields are mapped, parsed, type-normalized, and written back under logical names). Data transforms and consumer modules read that result instead of repeatedly reading raw data.

| Step                | What it does                                                                                                | Main config                            |
| ------------------- | ----------------------------------------------------------------------------------------------------------- | -------------------------------------- |
| Data reference      | Select the external dataset for this view; rows themselves stay out of IR                                   | `data` / `data.reference`              |
| Field contract      | Define logical field names, types, category order, and declarative formats; infer from samples when omitted | `model`                                |
| Source mapping      | Map logical fields to real data paths, including renamed fields and nested paths                            | `fieldMap` / `fieldMaps`               |
| Parse / normalize   | Parse values from field contracts and formats, then write results under logical field names                 | `model` / `format` / field type        |
| Validation          | Sample-check or fully check participating fields, and decide whether invalid values skip or throw           | `validateData` / `invalid`             |
| Transform / handoff | Data transforms rewrite canonical rows, then hand the result to a consumer module                           | `sort` / `summarize` / consumer config |

`model`, `format`, and data transform operations are serializable contracts. Functions participate only at runtime and do not enter IR. See [Data Model Extensions](/viz/data/model/extensions) for custom field formats and parsing, and [Data Transform Extensions](/viz/data/transform/extensions) for custom transforms, reducers, and selectors.

## Consumption boundary

The data layer stops after producing canonical rows. It does not require a particular view and does not own channels, marks, or layout semantics.

In a Plot application, marks, transforms, and scales can read those rows by logical field name. [Plot Grammar channels](/viz/plot/channel) explain how fields or constants enter Plot `x` / `y` / `color` / `size` / `text`; other consumers can apply their own contracts to the same canonical rows.
