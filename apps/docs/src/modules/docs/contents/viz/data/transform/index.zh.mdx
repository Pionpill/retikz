title: 数据变换
description: 数据变换按顺序改写规范化行，并把排序、汇总、代表行选择与统计标注交给不同消费模块复用。
---

数据变换属于 `@retikz/data`。它们读取数据模型产出的规范化行，按顺序处理后输出新的规范化行，可供图形、表格或其它消费模块使用。

## 整体流程

下面以 `summarize` 为例：输入是商品粒度的规范化明细，变换按 `region` 分组后，输出改成地区粒度的汇总行。`product`、`revenue` 被汇总结果字段 `total`、`orders` 取代。

<ComponentPreview files="data-transform-shape" size="md" previewClassName="!p-3" hideCode />

这个例子同时改变了行粒度和字段集合，但并非所有变换都会改列结构：`sort` 只重排行，`select` 主要改变行数，`annotate` 则保留明细行并增加统计字段。

| 阶段         | 输入                  | 输出                     | 负责什么                         |
| ------------ | --------------------- | ------------------------ | -------------------------------- |
| 数据模型     | 外部数据行 + 字段契约 | 规范化行                 | 对齐字段、解析值并执行接入校验   |
| 数据变换管线 | 规范化行 + 操作数组   | 新的规范化行             | 按声明顺序排序、汇总、选择或标注 |
| 消费模块     | 变换后的行            | 图形、表格或其它领域输出 | 解释字段并形成具体视图           |

每个变换操作（operation）都是 JSON 可序列化配置，由 Definition 声明字段语义，再由独立 Implementation 或外接 provider 提供计算。变换读取的字段会参与 `model` 校验；变换新产出的字段不需要提前声明进 `model`。

## 职责一览

| 主题     | 负责什么                         | 何时阅读                           |
| -------- | -------------------------------- | ---------------------------------- |
| 变换操作 | 声明解析、模型推进与计算执行     | 要理解变换链如何校验与执行时       |
| 计算算子 | reducer / selector 与宿主的协作  | 要理解局部统计如何组织为输出行时   |
| 计算契约 | 本地与外接计算的匹配、绑定和执行 | 要切换计算方式或接入异步数据源时   |
| 扩展机制 | 自定义变换、规约器与行选择器定义 | 内置操作无法表达新的数据处理语义时 |

Data 统一提供十二种内置变换；堆叠、分桶、区间、关联、扰动与统计采样的绘图组合示例见[绘图语法的变换](/viz/plot/transform)，完整字段契约见 [Schema 参考](/viz/data/transform/schema-reference)。自定义变换、规约器或行选择器的注册方式集中放在[扩展机制](/viz/data/transform/extensions)，运行链路事件则见[Data 来源追溯](/viz/data/provenance/data)。
