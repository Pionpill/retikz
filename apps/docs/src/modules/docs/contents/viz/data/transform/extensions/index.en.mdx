title: Extension mechanisms
description: Define transform semantics separately from computation, then choose local, external or hybrid execution with one executor.
---

Data uses a Definition to describe an operation and an Implementation to compute it. Operations `{ kind, ...config }` and execution settings are JSON-safe; schemas, functions, executors and source handles remain runtime objects.

## When to extend

Define a transform for new row semantics, a reducer when `summarize` or `annotate` needs a statistic, or a selector when `select` needs a selection rule. To replace the computation engine, reuse the existing Definition instead of assigning different semantics to the same name.

`kind` is open, but custom names cannot replace built-ins. All entries are exported from the `@retikz/data` root.

## Define the capability

`defineTransform` accepts an exact `schema`, optional `inputFields` and required `outputModel`. Semantic callbacks read parameters and field models, never rows or computation. Declare every statistical dependency with `dependencies`; use `validate` for model invariants.

Use `preserve.outputs` to extend a model or `replace.fields` to replace it. An output may omit its type when no evidence exists. `{ from: field }` preserves the source type and applicable categorical order. Derived field names are projected from this model.

External results may supply field types that were unknown during preflight. Subsequent local stages that preserve a field or inherit it through `{ from: field }` retain the type evidence from the actual input model, even when the result is empty. This does not change the execution routes fixed during preflight.

`defineTransformImplementation({ definition, apply })` references that same Definition. This `scale-field` example reads `x` and creates `scaledX` using `factor`:

Implementations must honor the Definition and leave input arrays and rows unchanged. Spreading an original row preserves its provenance Symbols; use the computation context's `groupProvenance(out, members)` for grouped output. Semantic Definitions do not hold these helpers.

### Statistical operations

`defineStatisticsReducer` describes its schema, inputs and every output through required `outputs`. Non-scalar or unknown outputs declare only their names. `defineStatisticsReducerImplementation({ definition, reduce })` supplies computation.

`defineRowSelector` declares a schema and inputs; `defineRowSelectorImplementation({ definition, select })` returns original rows and optional one-based ranks. `defineRegression` and `defineRegressionImplementation({ definition, fit })` follow the same split.

## Inject and use

Register semantic definitions and local implementations separately. Plot exposes these props; Chart accepts the same names in `lowerOptions`, while Table uses its lowering options.

| Capability | Semantic definitions           | Synchronous local implementations  |
| ---------- | ------------------------------ | ---------------------------------- |
| transform  | `transformDefinitions`         | `transformImplementations`         |
| reducer    | `statisticsReducerDefinitions` | `statisticsReducerImplementations` |
| selector   | `rowSelectorDefinitions`       | `rowSelectorImplementations`       |
| regression | `regressionDefinitions`        | `regressionImplementations`        |

Hosts use `{ operation, dataExecution? }` declarations. `operation` holds computation parameters; `dataExecution` selects execution:

```tsx
<Plot data={rows} transformDefinitions={[scaleField]} transformImplementations={[scaleFieldImplementation]}>
  <PlotTransform operation={{ kind: 'scale-field', field: 'x', as: 'scaledX', factor: 2 }} />
  <PointMark x="scaledX" y="y" />
</Plot>
```

Data's synchronous `applyTransforms` still takes operation arrays. For asynchronous execution, first resolve declarations and an input model with `resolveDataTransforms`, then call `executeDataTransforms`.

## External computation and Promises

`DataTransformImplementationProvider.resolve(stage, context)` reports support before computation. A supported entry references `stage.definition` and supplies `execute(input)`, returning `{ rows, model }` or a Promise. Recognize an adapted Definition's identity and check parameters, statistical dependencies, input types and provenance requirements; a matching `kind` alone does not establish support.

This example provider supports the `scale-field` Definition above on canonical rows and returns a Promise. Changing modes preserves semantics; the counter records actual completed external computations:

Register the external entry and reference its name:

```ts
import { createDataTransformExecutor } from '@retikz/data';

const executor = createDataTransformExecutor({
  dataExecution: { mode: 'hybrid', external: 'engine' },
  externalProviders: [{ name: 'engine', provider }],
  transformImplementations: [scaleFieldImplementation],
});
```

| mode       | Stage selection                                                                            |
| ---------- | ------------------------------------------------------------------------------------------ |
| `builtin`  | Local implementations only; the final default                                              |
| `external` | Every stage must be supported externally, otherwise the request fails                      |
| `hybrid`   | Prefer external support; choose local only when preflight explicitly reports `unsupported` |

Priority increases from executor defaults to Plot / Chart / Table root settings to individual declarations. `mode` and `external` inherit independently. Registering a provider does not change the mode. Exceptions, rejections, cancellation and invalid results never trigger hybrid recomputation.

### Hosts and bindings

Standalone React Plot, Chart and Table clients automatically use shared asynchronous preparation. In an outer Layout, set `runtime={{ preparation: 'async' }}`. The whole author tree preflights before computation and publishes atomically; a current failure preserves the committed frame, while stale and post-unmount results are ignored.

Use Vanilla `renderPlotAsync`, `renderChartAsync`, `renderTableAsync`, or `processToStaticInputResultAsync` with the corresponding adapters. Synchronous entries and synchronous React SSR accept local synchronous computation only; use asynchronous Vanilla entries for external or Promise SSR.

```tsx
<Layout runtime={{ preparation: 'async' }}>
  <Plot data={rows} dataTransformExecutor={executor} transformDefinitions={[scaleField]}>
    <PlotTransform operation={{ kind: 'scale-field', field: 'x', as: 'scaledX', factor: 2 }} />
    <PointMark x="scaledX" y="y" />
  </Plot>
</Layout>
```

`dataBindings` maps reference names to `rows`, `result` or `source` and is mutually exclusive with raw data props. `rows` uses source parsing. `result` supplies a complete logical model and is not reparsed. Native `source` requires an explicit complete `data.model`; an adapter or `materializeSource` must produce canonical results. Results and native sources reject source formats, parsers and field maps.

Table consumes transformed data before structure resolution. Detail and data-bound Custom Tables accept declarations; Manual and unbound Custom Tables reject them. Table `sourceIndex` addresses rows in this bound result, not database keys or pre-aggregation source row numbers.

## Errors and limitations

- Duplicate semantic keys, duplicate implementations and mismatched Definition references fail immediately.
- Definition-only extensions can execute externally; local execution requires an Implementation.
- Preflight performs no computation. After every stage is supported, `bind(actualInput)` fixes the actual input; each execution instance can execute once.
- Empty outputs retain unknown fields and categorical order; extra payload fields do not become model fields.
- `signal` cancels the request without recomputation. Applications still own connections, credentials and network resources.
