title: Extension Mechanisms
description: Extend data transforms and statistical sub-operators with runtime Definitions while keeping operation configuration serializable.
---

Data-transform extension points add row-processing operations or statistical reducers and selectors used by existing transforms. An operation stores only `{ kind, ...config }`; schemas and execution functions remain in runtime Definitions and never enter serializable configuration.

## Applicability

Prefer built-in operations. Register a Definition only when new row-processing semantics need a stable name, configuration validation, and reuse across hosts. Transform, reducer, and selector `kind` values are open strings: built-in constants provide common suggestions, not a whitelist for custom keys.

| Extension entry point     | Responsibility                                  | Stored configuration |
| ------------------------- | ----------------------------------------------- | -------------------- |
| `defineTransform`         | Reorder, filter, add, or remove rows and fields | `{ kind, ... }`      |
| `defineStatisticsReducer` | Reduce a group of rows into a field fragment    | Reducer operation    |
| `defineRowSelector`       | Select original rows from a group               | Selector operation   |

Extend a reducer when `summarize` or `annotate` only lacks a statistical calculation. Extend a selector when `select`, or a host transform that explicitly supports selectors, only lacks a row-selection rule. Data's `annotate` selector entry accepts only the built-in single-row subset, not custom selectors. Define a complete transform when the feature needs a new grouping strategy, multiple processing stages, or a different row structure.

## Defining Data Operations

`defineTransform` extracts a unique `kind` from `schema`, declares read fields through `inputFields`, lists generated field names through `outputFields`, and can describe the complete resulting field-type graph through `outputModel`. `apply` must be pure and deterministic and must not mutate the input array or rows.

### Provenance

A row-preserving transform usually retains provenance by spreading the original row. When a transform changes the row count and an output represents a group of source rows, use `TransformContext.groupProvenance` to associate those members. A newly generated row with no source counterpart may omit provenance.

| Scenario                        | Recommended handling                                      |
| ------------------------------- | --------------------------------------------------------- |
| Reorder or retain original rows | Return the original row or spread it before adding fields |
| Aggregate multiple rows         | Wrap output with `groupProvenance(out, members)`          |
| Generate source-free data       | Return a new row and allow provenance to be empty         |

Each lowering, locator, or lineage call is an independent runtime request, so Definitions must remain pure and deterministic; separate requests do not share an execution cache. Within one lineage-enabled data path, every operation executes once and its row result, field-type evidence, and lineage share that output.

## Defining Statistical Sub-operators

Reducers and selectors are not independent pipeline steps. `summarize` and `annotate` can invoke built-in or custom reducers. `select` and host transforms that explicitly support selectors can invoke built-in or custom selectors. Data's `annotate` selector entry accepts only the built-in single-row subset.

| Sub-operator | Core function | Result                                    | Typical use                      |
| ------------ | ------------- | ----------------------------------------- | -------------------------------- |
| Reducer      | `reduce`      | Field fragment written to output          | Custom statistics and aggregates |
| Selector     | `select`      | Original row plus optional one-based rank | Representative or ranked rows    |

A reducer should declare read and written fields through `inputFields` and `outputFields`, then use `outputs` to provide field-type evidence for statically describable scalar outputs. A selector declares its read fields through `inputFields` and returns selected original rows. Promote the logic to a complete transform when it must change several fields or combine multiple stages.

## Injecting A Host

The consuming host passes custom Definitions into the data-transform pipeline. In Plot:

| Capability       | Injection entry point          | Operation reference       |
| ---------------- | ------------------------------ | ------------------------- |
| Custom transform | `transformDefinitions`         | `kind`                    |
| Custom reducer   | `statisticsReducerDefinitions` | `reducer operation.kind`  |
| Custom selector  | `rowSelectorDefinitions`       | `selector operation.kind` |

Other consumers can expose equivalent adapter entry points. The Definition and operation contracts themselves belong to Data.

## Execution

```text
inject Definitions → merge built-in and custom registries → look up kind → validate schema → execute
```

Field collection and actual execution use the same registry. Each step parses the operation with its Definition schema, resolves `outputModel`, executes `apply`, and advances `{ rows, fieldTypes, fieldTypeEvidence }` together. `inputFields` includes source fields read by an extension in strict model validation, while `outputFields` marks derived fields so they do not have to appear in the source data model.

### Compact Field-Mapping Gate

An open `kind` only means Source can store a custom operation; it does not automatically make that operation suitable for compact field mapping. A host such as Chart requires a complete capability declaration before using a Definition inside an encoding:

| Definition | Required declarations                                                        | If incomplete                                                             |
| ---------- | ---------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| Transform  | `compact` phase / binding class / field effect plus a complete `outputModel` | It remains a full transform, not a compact mapping                        |
| Reducer    | `outputs()` returns exactly one typed scalar descriptor                      | It remains available to full statistics transforms, not compact aggregate |

The host also checks the Definition phase, field effect, output field, and target consumer for compatibility. Custom and built-in keys share one registry, schema, and capability path; the host does not copy a built-in enum.

## Errors And Limits

| Condition                                                                                   | Result                                  |
| ------------------------------------------------------------------------------------------- | --------------------------------------- |
| `kind` duplicates a built-in or custom key                                                  | Registry construction fails immediately |
| Operation uses an unregistered `kind`                                                       | Execution fails before applying it      |
| Operation fails its Definition schema                                                       | Schema validation fails                 |
| Operation contains functions or non-JSON values                                             | Serializability validation fails        |
| A custom reducer output declaration collides with a group key or another statistical output | Execution fails before the reducer runs |
| `outputModel` references a missing source field or disagrees with the actual field effect   | DataView advancement fails              |
| A compact mapping lacks a complete capability or output descriptor                          | Host field-mapping resolution fails     |

A Definition should implement only data-row and statistical semantics. Color, mark, layout, and other consumer-side semantics belong to the corresponding module extension point.

## API Reference

The following Definitions and helpers are exported from the `@retikz/data` package root.

### `TransformDefinition`

| Field           | Type                                                                                                 | Description                                                                 |
| --------------- | ---------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| `schema`        | `z.ZodType<TTransform>`                                                                              | Complete operation schema with a literal `kind`                             |
| `inputFields?`  | `(operation: TTransform, context: TransformContext) => Array<string>`                                | Returns source fields read by the operation                                 |
| `outputFields?` | `(operation: TTransform, context: TransformContext) => Array<string>`                                | Returns generated field names for strict-model and conflict checks          |
| `outputModel?`  | `(operation: TTransform, context: TransformContext) => DataTransformOutputModel \| undefined`        | Returns the complete field-type effect; omission discards old type evidence |
| `compact?`      | `DataTransformCompactCapability`                                                                     | Declares phase, binding class, and field effect for field mappings          |
| `apply`         | `(rows: Array<ExternalRow>, operation: TTransform, context: TransformContext) => Array<ExternalRow>` | Executes the transform purely and deterministically                         |

Use `defineTransform(definition)` to preserve the generic relationship among these fields.

### Output And Compact Contracts

| Type                             | Key fields                             | Responsibility                                                         |
| -------------------------------- | -------------------------------------- | ---------------------------------------------------------------------- |
| `DataTransformOutputDescriptor`  | `field`, `type`                        | Assigns a fixed output type or reuses an existing type with `{ from }` |
| `DataTransformOutputModel`       | `preserve.outputs` \| `replace.fields` | Extends the current field graph or replaces it with a complete list    |
| `DataTransformCompactCapability` | `phase`, `bindingClass`, `fieldEffect` | Lets a host decide whether the Definition can bind to a field slot     |

### `StatisticsReducerDefinition`

| Field           | Type                                                                                                 | Description                                                                                                      |
| --------------- | ---------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `schema`        | `z.ZodType<TReducerOperation>`                                                                       | Schema with a non-empty literal `kind`                                                                           |
| `inputFields?`  | `(operation: TReducerOperation) => Array<string>`                                                    | Returns source fields read by the reducer                                                                        |
| `outputFields?` | `(operation: TReducerOperation) => Array<string>`                                                    | Returns generated fields and drives dynamic conflict checks; it must declare every field that `reduce` may write |
| `outputs?`      | `(operation: TReducerOperation) => Array<DataTransformOutputDescriptor>`                             | Returns statically describable typed scalar outputs                                                              |
| `reduce`        | `(rows: Array<ExternalRow>, operation: TReducerOperation, context: TransformContext) => ExternalRow` | Returns the field fragment written to output                                                                     |

Use `defineStatisticsReducer(definition)` to define a reducer.

### `RowSelectorDefinition`

| Field          | Type                                                                               | Description                                        |
| -------------- | ---------------------------------------------------------------------------------- | -------------------------------------------------- |
| `schema`       | `z.ZodType<TSelectorOperation>`                                                    | Schema with a non-empty literal `kind`             |
| `inputFields?` | `(operation: TSelectorOperation) => Array<string>`                                 | Returns source fields read by the selector         |
| `select`       | `(rows: Array<ExternalRow>, operation: TSelectorOperation) => Array<RowSelection>` | Returns original rows and optional one-based ranks |

Use `defineRowSelector(definition)` to define a selector.

A custom selector can be used by `select` or by a host transform that explicitly supports it, such as Plot `relate`. Data `annotate` does not accept custom selectors.
