---
title: Extension Mechanisms
description: Define field formats, category orders, and runtime resolvers while keeping model configuration serializable.
---

Data-model extensions cover field parsing and category ordering. Reusable parsing rules become named formats, while one-off or source-specific rules use a runtime resolver. Neither form writes functions into serializable configuration.

## Applicability

Prefer built-in formats and field types. Register a `FieldFormatDefinition` only when a storage format must be reused across data sources; use `resolveField` for parsing branches local to the current source.

| Extension entry point | Responsibility                     | Stored configuration |
| --------------------- | ---------------------------------- | -------------------- |
| `defineFieldOrder`    | Custom category comparison         | `order` name         |
| `defineFieldFormat`   | Reusable field storage formats     | `format` name        |
| `resolveField`        | Temporary type and parser override | Nothing              |

`fieldMap` only maps logical fields to physical paths; it neither parses values nor registers an extension. Measurement types remain the closed set `continuous`, `temporal`, and `categorical`. Custom parsing must normalize values into one of those domains.

## Defining Field Formats

Use `defineFieldFormat` for formats that must be persisted and reused across data sources. `name` is the model lookup key, `impliedType` declares the canonical value type, and `parse` converts raw input to text, a finite number, or `undefined`.

The `wan` Definition below is injected through `<Plot formatDefinitions>`. The model stores only `format: 'wan'`, never the parsing function.

## Runtime Field Resolution

Use `resolveField` for one-off logic and source-specific branches. It returns an optional `type` and `parse` for each logical field and takes precedence over the model, named format, and default coercion. Returning `undefined` falls back to the standard intake path.

`resolveField` is a runtime escape hatch. It does not use a registry and cannot be serialized. Use a `FieldFormatDefinition` when a stable name, cross-host reuse, or persisted configuration is required.

## Defining Category Orders

Use `defineFieldOrder` for language-specific or business ordering. This example registers `labelLength`; select “Custom: label length” to sort labels by length.

A definition contains `name` and `compare(a, b, context)`. Return a finite number: negative places a first, zero keeps relative order, and positive places a last. `context.values` holds deduplicated effective categories in appearance order. Comparators must be pure, antisymmetric, and transitive, without modifying values or context.

Plot and Table accept arrays through runtime `fieldOrderDefinitions`: the same prop in React and runtime options in Vanilla or direct IR calls. The model stores only `order: 'labelLength'`. Table validates registration without reordering rows or columns. For standalone use, call `resolveFieldOrderRegistry(definitions)` and pass the registry to `resolveCategoryDomain(values, order, registry)`.

Names cannot be blank, duplicated, or override built-ins. Unknown names fail at intake. Thrown callbacks and nonfinite results produce `RetikzDataError`, preserving the original exception as `cause`. Definitions belong to the current request; receiving processes must supply their own implementation of stored names.

## Injecting A Host

The consuming host passes field-parsing capabilities into the intake pipeline. In Plot:

| Capability            | Injection entry point   | Model reference           |
| --------------------- | ----------------------- | ------------------------- |
| Named category orders | `fieldOrderDefinitions` | Field `order: name`       |
| Named field formats   | `formatDefinitions`     | Field `format: name`      |
| Temporary parsers     | `resolveField`          | None; resolved at runtime |

Other consumers can expose equivalent adapter entry points. The data model only consumes the format registry and resolver result.

## Execution

```text
field contract → look up named format → apply resolveField override → normalize field value
```

Named formats provide an initial field type and parser, then `resolveField` may override either value per field. When no custom rule matches, intake continues with the model declaration, inference result, and default coercion.

## Errors And Limits

| Condition                                 | Result                                                                          |
| ----------------------------------------- | ------------------------------------------------------------------------------- |
| Duplicate built-in/custom format name     | Registry construction fails immediately                                         |
| Model references an unknown format        | Intake fails before normalization                                               |
| `resolveField.parse` has no resolved type | Declare the type in the model or return `type` from the resolver                |
| Parser returns the wrong value type       | Invalid value handled by [Validation & Diagnostics](/viz/data/model/validation) |

Field parsing normalizes individual values. It does not reorder rows, change row counts, or produce statistical fields; those capabilities belong to [Data Transform Extensions](/viz/data/transform/extensions).

## API Reference

The following contracts are exported from the `@retikz/data` package root.

#### `FieldFormatDefinition`

`defineFieldFormat(definition)` accepts and returns the same `FieldFormatDefinition`.

| Field         | Type                                 | Description                                                               |
| ------------- | ------------------------------------ | ------------------------------------------------------------------------- |
| `name`        | `string`                             | Non-empty registry key that cannot collide with a built-in or custom name |
| `impliedType` | <ApiValues name="DataFieldType" />   | Measurement type used when the model omits `type`                         |
| `parse`       | `(raw: unknown) => ParsedFieldValue` | Converts a raw value to a canonical string, finite number, or `undefined` |

#### `ResolveField`

`ResolveField` is `(field: string, context: Parameters<ResolveField>[1]) => FieldResolution | undefined`. It returns an override for one logical field; `undefined` falls back to the standard path.

#### `FieldResolution`

`FieldResolution` is a runtime override for one field: `type?` supplies the final measurement type <ApiValues name="DataFieldType" />, and `parse?: (raw: unknown) => ParsedFieldValue` supplies a custom parser.
