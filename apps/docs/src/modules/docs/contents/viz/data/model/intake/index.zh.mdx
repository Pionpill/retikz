先在[字段类型](/viz/data/model/field-types)中约定逻辑字段，再把真实数据接入这份约定。字段映射负责“从哪里取值”，字段类型与格式负责“如何解释值”；例如把 `pricing.amount` 读成逻辑字段 `revenue`，再将 `'50%'` 解析为 `0.5`。接入后再选择跳过、抽样诊断或严格拒绝坏值。示例通过可视化展示 Data 的处理结果。

## 字段映射

数据源使用相同字段名与类型时，只需替换数据行；名字不同时，用 `fieldMap` 指定“逻辑字段名 → 物理路径”，消费方继续引用逻辑名。映射必须配合 `model`，且只能映射模型中已声明的字段。省略映射项时按逻辑字段名取值。

物理路径支持 `pricing.amount` 这样的点路径。读取时先查找完整名称对应的直接键，再逐段访问嵌套属性。数组不会自动展开；需要一条记录生成多行时，应先整理源数据。

切换下面的实际值、预测值和财务数据源：前两者只替换数据，财务数据额外使用路径映射，下游始终引用 `month` 与 `revenue`。

关键是根据数据源选择 `fieldMap`。下面省略数据选择和消费配置，仅保留映射逻辑：

```ts
const fieldMap = source === 'finance' ? { month: 'period', revenue: 'amount' } : undefined;
```

实际值和预测值都含有 `month`、`revenue`，因此不需要映射。财务数据使用 `period`、`amount`，由 `fieldMap` 对齐逻辑名。无论选择哪一组数据，`model` 和下游引用的逻辑字段都保持一致。

映射只改变取值路径，不转换值。映射到不同物理路径时，建议在模型中显式声明 `type` 或 `format`；不要依赖逻辑字段名对原始行进行的自动类型推断。

字段映射与真实数据都放在运行时，字段模型只保存字段约定。映射改变时，下游仍按同一组逻辑字段读取数据。

## 值解析

确定字段类型后，默认转换可把有限数值、安全整数 `bigint` 与严格数字串统一为连续值，把 `Date`、严格 ISO 字符串与 Unix 毫秒时间戳统一为时间值。数字串能否转换，与未声明类型时如何推断是两件事；推断规则见[测量类型](/viz/data/model/field-types#测量类型)。

默认转换不支持的存储格式通过字段 `format` 声明。格式名进入模型，内置或运行时注入的定义提供解析函数：

| `format`       | 类型         | 解析                           |
| -------------- | ------------ | ------------------------------ |
| `iso`          | `temporal`   | 严格 ISO，与默认时间解析等价   |
| `epochSeconds` | `temporal`   | Unix 时间戳秒转毫秒            |
| `epochMillis`  | `temporal`   | Unix 时间戳毫秒                |
| `slashDate`    | `temporal`   | 严格 `YYYY/MM/DD`，按 UTC 零点 |
| `numberString` | `continuous` | 容许空白与千分位逗号的数字串   |
| `percent`      | `continuous` | 百分比串 `'50%'` 转为 `0.5`    |

`format` 同时确定字段类型；与显式 `type` 冲突时会报错。有格式解析器时只使用该解析器，没有时才使用默认转换；解析失败不会再次尝试默认转换，而是交给[校验策略](/viz/data/model/intake#校验策略)处理。

## 分类顺序

`categorical` 字段默认按数据出现顺序形成分类域。需要 `S → M → L → XL` 这样的业务顺序时，在字段上写 `order`：

| `order`                                      | 效果                                              |
| -------------------------------------------- | ------------------------------------------------- |
| 不写 / `'appearance'`                        | 按数据出现序                                      |
| `'ascending'` / `'descending'`               | 全数值按数值比较，否则按字符串比较                |
| `'naturalAscending'` / `'naturalDescending'` | 按数字片段自然升序 / 降序排列，适合版本标签与编号 |
| 数组，如 `['S', 'M', 'L']`                   | 以数组为先，其余实际类别追加到末尾                |

`model.order` 排的是**分类域**，不会重排数据行。消费方可以复用这份类别顺序；要改变行的排列，请使用[数据变换里的排序](/viz/data/transform/operations#排序-sort)。

版本号应保留为字符串。`'10.2'` 和 `'10.18'` 按字母升序得到 `10.18 → 10.2`；使用 `order: 'naturalAscending'` 则得到 `10.2 → 10.18`。`naturalDescending` 按相反方向排列。

自然排序将连续 ASCII 数字按整数片段比较，其余文本按区分大小写的 UTF-16 顺序比较；数字片段在文本片段前，公共片段相同时较短标签在前。它不解析小数、负数或 SemVer，超长整数片段也不会因数值精度而混淆。`'v02'` 与 `'v2'` 比较等价，在自然升降序中都保持出现顺序，但仍是不同类别。

## 校验策略

示例的接入配置使用 `invalid: 'skip'` 作为默认策略：规范化保留数据行，不补造替代值，如何跳过不可用值由消费方决定。若整个字段都没有有效值，应通过抽样诊断定位问题。

`invalid` 决定是否严格拒绝坏值，只有 `skip` 和 `error` 两个取值；`validateData` 是独立的抽样诊断开关，不是第三种 `invalid` 策略。

| 属性           | 取值                            | 行为与用途                                                             |
| -------------- | ------------------------------- | ---------------------------------------------------------------------- |
| `invalid`      | `'skip'`（默认）                | 保留规范化行，由消费方跳过非法值，适合容忍少量坏点                     |
| `invalid`      | `'error'`                       | 全量检查参与字段，遇到非法或缺失值报错，适合数据准入与严格报表         |
| `validateData` | `false`（默认）                 | 关闭抽样诊断                                                           |
| `validateData` | `true` 或 `{ sampleRows: 100 }` | 每个参与字段在样本中至少有一个有效值，否则报错，适合排查空图与路径映射 |

`validateData: true` 默认检查前 100 行；传入对象可通过 `sampleRows` 调整抽样行数。抽样诊断允许样本中存在部分坏值，因此不能替代 `invalid: 'error'` 的逐值检查。

## 诊断信息

检查针对接入后的规范化值，在数据变换之前发生；错误中的字段名是逻辑字段名，行号是输入行的从零开始索引，不是排序或筛选后的序号。

| 错误信息                                  | 含义与排查方向                                                 |
| ----------------------------------------- | -------------------------------------------------------------- |
| `has no valid values in the sampled data` | 该字段在抽样范围内没有有效值；检查物理路径、字段类型与解析格式 |
| `missing or invalid at row 1`             | 第二条输入行的该字段不可用；检查原始值及解析结果               |
| 未注册格式或类型冲突                      | 配置本身不成立；先修正声明或注册定义，切换跳过策略无法绕过     |

抽样错误中的 `invalid` / `missing` 计数描述规范化结果，不一定保留原始值失败的原因。抽样通过也不保证其余行有效；`sampleRows: 0` 或空数据不会执行抽样检查。需要逐值保证时选择严格策略。

自定义解析返回不可用值后的处理也遵循上述策略。
