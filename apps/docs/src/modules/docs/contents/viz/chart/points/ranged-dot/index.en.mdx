Ranged Dot is fixed horizontally: `category` maps to y, while `start` and `end` share one x scale. If both endpoints declare an explicit scale binding, their names must match; one endpoint may declare the operation while the other references it. Use it when the two endpoint values and direction matter more than bar length.

## `RangedDotChart`

The root `recipe` uses Ranged Dot's exact slots. Component identity supplies the Point family and `chartType: 'ranged-dot'`:

```tsx
<RangedDotChart
  rows={rows}
  recipe={{
    encodings: { category: 'category', start: 'before', end: 'after', color: 'group' },
    properties: { range: { strokeWidth: 2 } },
  }}
/>
```

`RangedDotEncodings`, `RangedDotProperties`, and `RangedDotMark` are equivalent JSX sugar for the same recipe slots. Root-only authoring can omit `children`; different slots can mix, while two sources for one slot fail loudly.

## Atomic row semantics

One Ranged Dot semantic group emits one projected Relation operation. Plot projects both endpoints together and paints connector, start glyph, then end glyph. If either endpoint is missing, null, or unprojectable, the whole row is skipped without orphan geometry.

`start > end` never swaps roles. `start === end` retains a zero-length connector and two overlapping glyphs. Empty data is a valid empty result.

## Style precedence

`point` sets common constant appearance, then `startPoint` and `endPoint` override their endpoint. `range` affects only the connector. Optional field-bound `color` drives all three members and one categorical legend; member properties never create separate field scales.

When `color` and member color properties are omitted, the connector and both endpoints use the next default color from Plot's `palette.series` instead of falling back to CSS `currentColor`.

## API Reference

### `RangedDotEncodingsProps`

| Prop             | Type                                                                       | Default | Description                                  |
| ---------------- | -------------------------------------------------------------------------- | ------- | -------------------------------------------- |
| `category`       | Point position mapping                                                     | —       | Required category field fixed to y           |
| `start` / `end`  | Point position mapping                                                     | —       | Required endpoint fields sharing one x scale |
| `color?`         | Point color mapping                                                        | —       | Shared color and legend for all members      |
| `row` / `column` | `string`, `IRPlotPartitionDimension`, or `Array<IRPlotPartitionDimension>` | —       | Optional facet dimensions                    |
| `facet?`         | `IRPlotFacetOptions`                                                       | —       | Facet options; requires row or column        |

### `RangedDotPropertiesProps`

| Prop             | Type                                                                    | Default                       | Description                                                                               |
| ---------------- | ----------------------------------------------------------------------- | ----------------------------- | ----------------------------------------------------------------------------------------- |
| `point?`         | `IRRangedDotPointProperties`                                            | Point                         | Common constant appearance for both endpoints                                             |
| `startPoint?`    | `IRRangedDotPointProperties`                                            | inherited                     | Start endpoint override                                                                   |
| `endPoint?`      | `IRRangedDotPointProperties`                                            | inherited                     | End endpoint override                                                                     |
| `range?`         | `IRRangedDotRangeProperties`                                            | Path                          | Connector color, width, opacity, and style                                                |
| `domainPadding?` | `number` \| `{ kind?, default?, x?, y?, left?, right?, top?, bottom? }` | largest endpoint Point radius | Configures continuous x-scale range or explicit ratio padding; categorical y is unchanged |
| `autoPadding?` | `'max-radius'` \| `'point-aware'` \| `{ kind: 'max-radius' \| 'point-aware'; clearance?: number \| IRBoxSpacing }` | `'max-radius'` | Automatic padding policy; point-aware solves from individual positions and radii; explicit domainPadding wins |

`autoPadding` belongs to recipe properties. `point-aware` requires Cartesian2D, linear/time position scales, and no placement. Categorical axes, Polar, and jitter are unsupported. Fully explicit `domainPadding` bypasses point-aware solving. See [point-chart padding policies](/viz/chart/points#automatic-edge-padding).

Use `autoPadding: { kind: 'point-aware', clearance: 8 }` to reserve clearance between protected point extents and automatic plot-area edges. `clearance` is a nonnegative drawing-coordinate length, defaulting to `0`. Both strategies support it; explicitly configured `domainPadding` ends do not add clearance.

`clearance` also accepts the Kernel `IRBoxSpacing` object with nonnegative `default`, `x`, `y`, `top`, `right`, `bottom`, and `left` fields. Precedence is side → axis → `default` → `0`; `8` equals `{ default: 8 }`. For example, `{ default: 8, x: 12, top: 20, left: 0 }` gives top 20, bottom 8, left 0, and right 12. Explicit visual sides require Cartesian coordinates and retain their visual meaning with reversed axes.

### `RangedDotMarkProps`

| Prop          | Type                                                  | Default   | Description                                                      |
| ------------- | ----------------------------------------------------- | --------- | ---------------------------------------------------------------- |
| `override?`   | `boolean`                                             | `false`   | Replaces the complete ranged-dot group                           |
| `encodings?`  | `{ category?: string; start?: string; end?: string }` | inherited | Overrides direct fields, never color                             |
| `properties?` | `RangedDotMarkProps['properties']`                    | inherited | Merges member appearance and rejects recipe-only `domainPadding` |
