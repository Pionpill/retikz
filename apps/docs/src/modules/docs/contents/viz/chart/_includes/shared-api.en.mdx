## Chart authoring

`@retikz/chart` normalizes a complete Plot recipe and optional chart narrative metadata into `IRChart`. `IRChart` is the JSON-serializable canonical IR, and `ChartProvider` is its only composite provider. Applications normally author through the React or Vanilla adapters rather than assembling providers themselves.

| Entry                   | Use it when                                                                        | Result                                                             |
| ----------------------- | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| `Chart`                 | You already have a complete PlotSpec or need Plot JSX extensions in the chart body | Base Chart authoring                                               |
| `ScatterChart`          | You compare two continuous fields with points                                      | Built-in Scatter recipe with Plot extension entry points           |
| `BubbleChart`           | You encode a quantitative area in addition to two-dimensional position             | Built-in Bubble recipe with Plot extension entry points            |
| `ConnectedScatterChart` | You trace one ordered series through two-dimensional space                         | Built-in Connected Scatter recipe with Plot extension entry points |
| `resolvePointChartSpec` | You need framework-neutral Point typed authoring or JSON integration               | Resolves Point typed input to `IRChart` and a complete PlotSpec    |

The root entries retain only every-family base capability: import `Chart` and presentation markers from `@retikz/chart-react`, or `createChart` and `renderChart` from `@retikz/chart-vanilla`. Import Point typed API from the matching `/point` entry: `@retikz/chart/point` provides schemas and `resolvePointChartSpec`; `@retikz/chart-react/point` provides `ScatterChart`, `BubbleChart`, and `ConnectedScatterChart`; `@retikz/chart-vanilla/point` provides `createScatterChart`, `createBubbleChart`, and `createConnectedScatterChart`. Every `/point` entry also includes its base exports.

A typed Chart receives row-array `data`, recipe fields through `encoding`, and JSON-safe mark values such as `{ kind: 'constant', value: 10 }`. Additional axes, legends, marks, scales, or transforms continue to use Plot's public authoring capability.

## Presentation

`title`, `subtitle`, `source`, and `note` are Chart shorthands. Without markers, title and subtitle appear above the Plot, while note and source appear below it in their fixed shorthand order. Chart default tokens style them, and they share one Flex layout with the Plot.

| React marker    | Matching shorthand | Purpose                                                    |
| --------------- | ------------------ | ---------------------------------------------------------- |
| `ChartTitle`    | `title`            | Chart subject or observable conclusion                     |
| `ChartSubtitle` | `subtitle`         | Scope, year, sample, units, or method                      |
| `ChartSource`   | `source`           | Dataset and any transformation that affects interpretation |
| `ChartNote`     | `note`             | Reading constraint, definition, or supporting note         |

Place markers as direct children of `Chart` or `XxxChart`; transparent `Fragment` groups are allowed. A marker fully overrides the matching shorthand, and each preset can appear only once. Markers retain JSX order within their side of the Plot: `ChartSubtitle` followed by `ChartTitle` appears in that order above it, while `ChartSource` then `ChartNote` appears in that order below it.

Marker children currently accept only strings, transparent `Fragment`, and Core `Text`. Multiple `Text` children create lines and may each supply font, fill, or opacity. `position="top"` and `position="bottom"` only normalize the authoring location around the Plot; canonical `IRChart` retains only the final presentation-child order.

The three typed factories accept the same shorthands as React. For custom order or position, provide ordered plain `presentation` records. A record's `text` is a string or JSON-safe Core TextBlock, never a React object.

## Runtime styles

A named style needs same-named definitions from Core, Chart, and Plot. The static adapter in `<Layout>` passes its resolved Core Theme and inherited Core definitions to an embedded Chart, so recipe defaults match standalone authoring. `themeStyles` configures only the Layout created by a standalone Chart; an embedded Chart's named Core definition belongs on its parent `<Layout>`. Pass Chart- and Plot-owned definitions directly through `chartThemeStyles` and `plotThemeStyles`; a standalone subtree may instead inject them through `ChartThemeProvider` and `PlotThemeProvider`. Vanilla passes `theme` and `themeStyles` when calling `createChart()` or a typed factory; the returned authoring result retains them, and `renderChart()` consumes that result in one compile. Pass Core definitions or other compile options through `renderChart()`'s `compile` option; it does not accept a `compileDriver` that could produce extra layers or diagnostics. The base `createChart()` path keeps Plot definitions in `lowerOptions.plotThemeStyles` so it reuses the complete Plot runtime-options contract.

## Plot extensions

Chart owns closed recipes, chart narrative, and canonical composition. Plot continues to own coordinates, scales, axes, legends, marks, annotations, transforms, and interaction semantics. Therefore `Legend`, `Axis`, and additional marks can be typed Chart children alongside Chart markers, but they are not presentation items.

The adapter assembles `SurfaceProvider`, `FlexLayoutProvider`, the Plot provider, and `ChartProvider` into one contribution. Title, subtitle, Plot, source, and note can therefore lay out together while Plot preserves its own guide, lowering, and diagnostic path.
