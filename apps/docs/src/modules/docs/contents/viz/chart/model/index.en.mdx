Plot is a powerful low-level graphics grammar: it describes how data is drawn through marks, channels, scales, coordinates, and guides, but it also means that authors must assemble those grammar pieces themselves. When the goal is to express a complete graphic first, starting directly with Plot requires understanding a larger amount of low-level configuration.

Chart is the official higher-level graphic wrapper built on Plot. It answers a different question: “I want to start with a graphic type.”

- **A type-based graphic wrapper**: `ScatterChart`, `BubbleChart`, and other types express the graphic users want to draw, while Plot owns the lower-level drawing grammar. They operate at different abstraction levels.
- **Less configuration**: each `type` comes with its own default resolution logic, which can fill in the primary mark, scales, coordinates, and other semantics normally required by that type. Authors do not have to assemble a complete Plot from scratch.
- **Official higher-level capabilities**: these types are maintained through Retikz's official schemas, recipes, and resolution paths, providing an approachable entry point while converging on the base Chart used by compilation.

This makes type-based Chart wrappers easier to learn and easier for an LLM to understand and generate. When a graphic becomes more complex, you can still start from a Chart type and use its `plot` member to add axes, legends, additional marks, transforms, and other Plot capabilities. That requires learning Plot, but you keep the type semantics and default resolution that Chart already provides.

## Resolution pipeline

<ComponentPreview files="chart-model-pipeline" hideCode size="xs" />

Read the diagram as “input → type rules → shared graphic → output.” Each stage answers one question. The list below explains what each stage means to an author before introducing its implementation term:

1. **React / Vanilla: choose an authoring entry**
   React components and Vanilla factories are two author-facing ways to write a chart. They accept your data, type configuration, and presentation options without requiring you to work with the later compilation stages directly.
2. **Exact Source IR: keep the complete description of one type**
   Source IR is the chart's source description. It records the selected `type`, the configuration required by that type, its `plot`, and chart-wide presentation. `Exact` means that the description follows the selected type's precise structure instead of using one broad object for every Chart type.
3. **BoundChart: attach the type's defaults**
   The recipe reads the source description and attaches that type's default resolution logic, such as the primary mark, scales, and coordinates it normally requires. The intermediate result is called BoundChart; authors normally do not write it by hand.
4. **IRBaseChart: converge on one base graphic**
   `resolveChart` resolves the type-aware intermediate result into `IRBaseChart`. Whether the source started as Scatter, Bubble, or another Chart type, later compilation can now consume the same base graphic structure.
5. **Surface + Plot: enter compilation and drawing**
   Core consumes the unified `IRBaseChart` to create the Surface that carries the graphic, then Plot continues drawing data through marks, coordinates, and guides. Core therefore does not need separate knowledge of every higher-level Chart type.

## Responsibilities

| Topic                  | Responsibility                                                       | Read it when                                            |
| ---------------------- | -------------------------------------------------------------------- | ------------------------------------------------------- |
| Structure & Types      | Explains `namespace`, exact `type`, and field ownership              | Reading JSON, selecting a schema, or finding boundaries |
| Authoring & Resolution | Connects React, Vanilla, schemas, recipes, and `resolve`             | Comparing entry points or tracing canonicalization      |
| Presentation           | Organizes title, subtitle, Plot, note, and source                    | Controlling narrative order, text style, or layout      |
| Plot Integration       | Separates the chart shell from the drawing grammar and aligns themes | Adding axes, legends, marks, or runtime styles          |

All four topics share one boundary: Chart decides what graphic is being authored and how it becomes a complete chart, while Plot decides how data is drawn through the graphics grammar. Type folders and `/point` entries organize source and imports; they do not add another runtime layer.
