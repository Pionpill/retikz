## Chart 编写

所有 Chart 入口都遵循一致的字段布局，但不共享一个公开的 `ChartSchema` union。`BaseChartSchema` 与每个封装类型的精确 schema 都固定 `namespace: 'chart'`，用精确 `type` 表明解析逻辑；`plot` 保存 Plot 拥有的输入，封装类型的 `config` 保存该类型独有的配置，`presentation` 保存整图展示。

三个包按阶段划分职责：`@retikz/chart` 只拥有 Source IR、精确 schema、recipe、resolve 与 canonical presentation；plain `InputChart`、`normalizeChart`、展示记录和创建函数属于 `@retikz/chart-vanilla`；`@retikz/chart-react` 只把 JSX 与 props 转换为同一套 Vanilla Input，再复用对应 normalizer。React 与 Vanilla 因而不会各自维护一套 Source IR 组装规则。

精确 schema 解析后会绑定对应 recipe；所有 recipe 最终都由 `resolveChart` 产出 `IRBaseChart`，因此 Core 只消费 `chart.base`，不会按 Scatter、Bubble 等类型分裂执行入口。

| 入口                    | 适用场景                           | 对应 Chart `type`   |
| ----------------------- | ---------------------------------- | ------------------- |
| `Chart`                 | 显式描述完整 Plot                  | `base`              |
| `ScatterChart`          | 比较两个连续字段                   | `scatter`           |
| `BubbleChart`           | 在二维位置外再编码一个定量面积     | `bubble`            |
| `ConnectedScatterChart` | 观察同一有序序列在二维空间中的演变 | `connected-scatter` |

“点图”用于文档导航、源码归置和多入口导入。基础 Chart 能力从三个包各自的根入口导入；对应的 `/point` 公共入口只公开 Point typed contract，不转发根入口：`@retikz/chart/point` 完整导出各具体类型的 schema、IR、recipe 与 owned mark/component patch 契约，`@retikz/chart-react/point` 提供 `ScatterChart`、`BubbleChart` 与 `ConnectedScatterChart`，`@retikz/chart-vanilla/point` 提供精确的 `InputXxxChart`、`normalizeXxxChart` 与 `createXxxChart`。这个目录边界不形成 `PointChartSchema`、Point 专属解析器或适配主链；每个入口绑定自己的精确 schema，之后统一使用 `resolveChart` 与 Chart 适配契约。

封装类型把独有字段放在 `config` 中。例如 Scatter 的 `config.encoding` 提供 x/y，Bubble 再提供 size，Connected Scatter 再提供 order；主图元的局部调整也属于 `config`。数据、变换、比例尺、坐标、辅助元素与显式附加图元统一放在 `plot` 中，并继续沿用 Plot 的公开契约。

## 整图展示

`title`、`subtitle`、`source` 和 `note` 是 Chart 的简写。未使用标记时，标题和副标题出现在 Plot 上方，注记和来源出现在 Plot 下方；同一侧的简写采用固定默认顺序。它们由 Chart 默认主题令牌提供样式，并与 Plot 一起进入同一个 Flex 布局。

| React 标记      | 对应简写   | 作用                         |
| --------------- | ---------- | ---------------------------- |
| `ChartTitle`    | `title`    | 图表主题或可观察结论         |
| `ChartSubtitle` | `subtitle` | 范围、年份、样本、单位或方法 |
| `ChartSource`   | `source`   | 数据集与会影响理解的数据处理 |
| `ChartNote`     | `note`     | 读图限制、口径提示或补充说明 |

把标记作为 `Chart` 或 `XxxChart` 的直接子节点；透明 `Fragment` 可用于分组。一个标记覆盖同名简写，且每种预设最多出现一次。标记按 JSX 出现顺序布局：例如上方的 `ChartSubtitle` 再 `ChartTitle` 会先显示副标题，图后依次写 `ChartSource`、`ChartNote` 则会按来源、注记显示。

标记的子节点目前只接受字符串、透明 `Fragment` 和 Core `Text`。多个 `Text` 可形成多行，并可分别提供字体、填充色或透明度。`position="top"` 与 `position="bottom"` 只在编写阶段决定它位于 Plot 的哪一侧；归一后的 Base Chart 只保留最终的展示子节点顺序。

各类型创建函数接受与 React 相同的简写；需要自定义位置或顺序时，传入按顺序排列的普通 `presentation` 记录。记录的 `text` 是字符串或可 JSON 序列化的 Core `TextBlock`，不能传入 React 对象。

## 运行时样式

命名样式必须同时由 Core、Chart 与 Plot 提供同名定义。`<Layout>` 的静态适配层会把当前已解析的 Core 主题与继承的 Core 定义传给嵌入 Chart，因此独立与嵌入场景下的类型方案默认值一致。`themeStyles` 只配置独立 Chart 自行创建的 Layout；嵌入 Chart 的命名 Core 定义必须放在父 `<Layout>`。Chart 与 Plot 所属的定义可用 `chartThemeStyles`、`plotThemeStyles` 直接传给 Chart；独立子树也可用 `ChartThemeProvider` 与 `PlotThemeProvider` 注入。Vanilla 在调用 `createChart()` 或各类型创建函数时一并传入 `theme` 与 `themeStyles`；它们会随返回的编写结果保留，`renderChart()` 在一次编译中消费该结果。需要补充 Core 定义或其它编译选项时，传入 `renderChart()` 的 `compile`；它不接受会产生额外图层或诊断的 `compileDriver`。基础 `createChart()` 的 Plot 定义仍放在 `lowerOptions.plotThemeStyles`，以复用完整的 Plot 运行时选项。

## Plot extensions

Chart 负责按 `type` 解释 `config`、组织整图展示和完成 Chart 组合；Plot 继续负责坐标、比例尺、轴、图例、图元、标注、变换和交互语义。因此 `Legend`、`Axis` 或附加图元可以与 Chart 标记一起使用，但它们不是整图展示项。

适配层会把 `SurfaceProvider`、`FlexLayoutProvider`、Plot 提供者与 `ChartProvider` 作为一次依赖贡献组装。这样标题、副标题、Plot、来源和注记能共同布局，同时 Plot 仍保留自己的辅助元素、下沉与诊断路径。
