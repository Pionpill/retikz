Chart reuses Plot instead of wrapping a closed drawing result. A packaged type's recipe only supplies the Plot structure required by that type. Axes, legends, scales, transforms, additional marks, and annotations remain composable through public Plot contracts.

## Two owners, one complete graphic

<ComponentPreview files="chart-plot-ownership" hideCode size="md" />

| Chart owns                              | Plot owns                                                 |
| --------------------------------------- | --------------------------------------------------------- |
| `namespace`, exact `type`, and `config` | data, transforms, scales, and coordinates                 |
| title, subtitle, note, and source       | marks, axes, legends, and other guides                    |
| canvas, chart Surface, and Chart theme  | Plot theme, grammar resolution, lowering, and diagnostics |

When the Bubble recipe creates a primary Point mark from `config.encoding.size`, it is constructing Plot rather than implementing another Point system inside Chart. Axes, legends, and additional marks supplied through `plot` or React Plot children are still consumed by Plot schemas, providers, and pipelines. Base Chart supplies no recipe defaults and requires a complete explicit Plot.

## Which side should an extension use?

- Extend Plot when changing how data is drawn, such as adding a mark, channel, scale, coordinate, guide, or transform
- Extend a Chart type when packaging a reusable set of Plot semantics, keeping unique parameters in `config`
- Use Chart presentation for the complete graphic's subject, scope, source, or reading constraints
- Keep coordinate explanations, legends, and data annotations in Plot guides and annotation capabilities

This boundary prevents Chart types from copying the entire Plot API as the grammar grows, and prevents Plot from learning product-facing type names such as Scatter or Bubble.

## Runtime theme cooperation

Core, Chart, and Plot own separate Definition registries. A named style must be defined under all three owners when it affects all three; sharing the same name coordinates selection without merging ownership.

In React, a standalone Chart can receive `themeStyles`, `chartThemeStyles`, and `plotThemeStyles`. When embedded in `<Layout>`, Core definitions come from the parent Layout while Chart and Plot definitions are still contributed by their matching providers. Vanilla factories preserve the same runtime theme input, and `renderChart()` consumes it in one compilation. Base `createChart()` keeps Plot definitions under `lowerOptions.plotThemeStyles` to reuse the complete Plot runtime options.
