title: 与 Plot 协作

Chart 复用 Plot，而不是包住一份不可扩展的绘图结果。封装类型的 recipe 只补齐该类型默认需要的 Plot 结构；轴、图例、比例尺、变换、附加图元和标注仍沿 Plot 的公开契约继续组合。

## 两个 owner，一张完整图形

<ComponentPreview files="chart-plot-ownership" hideCode size="md" />

| Chart 拥有                           | Plot 拥有                                   |
| ------------------------------------ | ------------------------------------------- |
| `namespace`、精确 `type` 与 `config` | data、transform、scale 与 coordinate        |
| title、subtitle、note、source        | marks、axes、legends 与其它 guides          |
| 画布尺寸、整图 Surface 与 Chart 主题 | Plot theme、图形语法的解析、lowering 与诊断 |

当 Bubble recipe 根据 `config.encoding.size` 生成主 Point 图元时，它是在构造 Plot，不是在 Chart 中实现另一套 Point。用户通过 `plot` 或 React Plot 子组件添加 `Axis`、`Legend` 和附加 mark，仍由 Plot 的 schema、provider 与 pipeline 消费。Base Chart 则不提供 recipe 默认值，要求用户显式给出完整 Plot。

## 扩展应该落在哪一侧

- 改变“数据怎样被绘制”时扩展 Plot，例如新增 mark、channel、scale、coordinate、guide 或 transform
- 把一组 Plot 语义组织成可复用图形类型时扩展 Chart type，并把独有参数放入 `config`
- 说明整张图的主题、范围、来源或阅读限制时使用 Chart presentation
- 说明坐标、图例或数据图元时继续使用 Plot 的辅助元素与标注能力

这个边界避免 Chart 类型随着 Plot 能力增长而复制整套绘图 API，也避免 Plot 知道 Scatter、Bubble 等产品化类型名称。

## 运行时主题协作

Core、Chart 与 Plot 分别拥有自己的 Definition registry。使用命名 style 时，三个 owner 需要提供同名定义，当前 Chart 解析会分别从对应 registry 读取各自 token；同名只是选择协作，不合并 owner。

React 中，独立 Chart 可通过 `themeStyles`、`chartThemeStyles` 与 `plotThemeStyles` 提供三层定义；嵌入 `<Layout>` 时，Core 定义来自父 Layout，Chart 与 Plot 定义仍由对应 provider 贡献。Vanilla 创建函数同样保留运行时主题输入，`renderChart()` 在一次编译中消费它们。基础 `createChart()` 的 Plot 定义位于 `lowerOptions.plotThemeStyles`，与完整 Plot 运行时选项保持一致。
