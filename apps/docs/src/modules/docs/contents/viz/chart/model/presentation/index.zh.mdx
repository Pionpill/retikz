整图展示说明“这张图在讲什么、覆盖什么范围、数据来自哪里、阅读时要注意什么”。它属于 Chart，而不是某一种图形类型，也不是 Plot 的轴、图例或标注。

## 从编写顺序到 canonical 顺序

下面的 playground 使用真实 `Chart`，而不是用框图模拟布局。标题、副标题、Plot、注记和来源都会进入同一个 Surface；打开 Flex 辅助层后，可以看到 canonical 子项的 content、slot、allocation、padding、行区域与 gap。

`title`、`subtitle`、`note` 和 `source` 是常用简写。未提供展示标记或记录时，简写形成固定默认顺序：标题和副标题位于 Plot 上方，注记和来源位于 Plot 下方。

| React 标记      | 简写       | 默认位置 | 典型内容                     |
| --------------- | ---------- | -------- | ---------------------------- |
| `ChartTitle`    | `title`    | top      | 主题或主要结论               |
| `ChartSubtitle` | `subtitle` | top      | 范围、年份、样本、单位或方法 |
| `ChartNote`     | `note`     | bottom   | 读图限制、口径或补充说明     |
| `ChartSource`   | `source`   | bottom   | 数据集与会影响理解的数据处理 |

需要自定义文本样式、位置或顺序时，React 使用标记，Vanilla 使用按顺序排列的 `presentation` records。标记必须是 Chart 的直接子节点，透明 `Fragment` 可分组；同一种预设最多出现一次，并覆盖同名简写。标记的 authored order 会被保留，所以把 `ChartSubtitle` 写在 `ChartTitle` 前面也会改变最终顺序。

## 展示项都是可选子项

`title`、`subtitle`、`note` 或 `source` 未提供时，归一过程不会创建对应子项，Plot 与其余展示内容会按固定顺序补位。下面的四个开关可以独立比较每项存在或缺失时的 canonical 顺序。

## 编写态与 canonical 的边界

`position: 'top' | 'bottom'` 只存在于 Vanilla/React 编写态，用于把记录放到 Plot 占位之前或之后。`normalizeChartPresentation` 生成 canonical `presentation.children` 后，数组顺序已经表达布局，不再保留 `position`。

展示文本可以是字符串，也可以是可 JSON 序列化的 Core `TextBlock`。React 标记额外接受字符串、透明 `Fragment` 和 Core `Text` 子节点，并把它们收敛成相同的文本契约；普通 React 元素不会进入 IR。

解析阶段，Chart 使用 Standard `Surface` 作为整图容器，并通过 Flex 顺序放置展示文本和唯一的 Plot 占位。Chart 主题提供各预设的默认文本样式，Plot 仍负责自己的轴、图例和标注。
