Point charts use position to show observations. They help reveal distributions, relationships, clusters, and outliers, and can also show trajectories or before-and-after differences. Data typically has one observation per row, with numeric fields and optional category or ordering fields.

## What point charts reveal

Point charts preserve the position of each observation, helping you compare values while seeing individual differences. Instead of showing only totals or averages, they reveal whether a relationship is consistent, whether observations form distinct groups, and which observations stand apart.

For example, when comparing income per person and life expectancy across regions, position shows the relationship between the two measures and color can distinguish region categories. Bubble area can add population, bringing magnitude into the comparison. To follow one region over several years, preserve the year order and use a connected scatter chart.

## Choosing a chart

| Chart                                                    | When to use it                                                     | Suitable data                                        |
| -------------------------------------------------------- | ------------------------------------------------------------------ | ---------------------------------------------------- |
| [Scatter](/viz/chart/points/scatter)                     | Explore relationships between two variables, clusters, or outliers | Two numeric fields                                   |
| [Bubble](/viz/chart/points/bubble)                       | Compare magnitude alongside two variables                          | Three numeric fields, one representing magnitude     |
| [Regression](/viz/chart/points/regression)               | Examine overall or grouped trends                                  | Two numeric fields, optionally with a grouping field |
| [Connected scatter](/viz/chart/points/connected-scatter) | Follow observations along a trajectory                             | Two numeric fields and an explicit order             |
| [Ranged dot](/viz/chart/points/ranged-dot)               | Compare before-and-after values or two endpoints by category       | A category field and two numeric fields              |
| [Strip](/viz/chart/points/strip)                         | Compare observation distributions within categories                | A category field and one numeric field               |

## Preparing data and reading the chart

Decide what one point represents: a user, a measurement, a region, or an observation at a particular time. Values being compared should belong to the same observation; comparisons between groups also need a clear category field. An ordinary scatter chart does not depend on row order. An explicit sequence becomes necessary when connecting observations into a trajectory.

Read the overall distribution first, then compare groups and inspect individual outliers. An upward or downward trend can suggest association, but a chart alone does not establish causation. A regression line summarizes a trend and should not replace the original observations.

- **When points overlap:** try smaller points, lower opacity, or separate views for groups. Consider a strip chart when observations crowd together within categories. Visible point counts can underestimate the number of observations.
- **When bubbles represent magnitude:** read their area, rather than their diameter, and compare against the legend. Use the data table as well when you need exact values.

## Shared configuration

All six point chart types share edge-padding configuration. React accepts it through the corresponding properties component, such as `ScatterProperties`, or the root `recipe.properties` prop. The Vanilla API uses `properties`; direct IR uses `recipe.properties`. An individual mark can override the chart policy with `properties.autoPadding`; `domainPadding` remains a chart-level setting.

| Property        | Type                                                             | Description                                                                                                                                                |
| --------------- | ---------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `autoPadding`   | `false`, `'max-radius'`, `'point-aware'`, `{ kind; clearance? }` | Bubble defaults to point-aware, other point charts to maximum-radius padding. `false` disables a mark's automatic contribution; object form adds clearance |
| `domainPadding` | `number`, Directional padding object                             | Explicit position-domain padding takes precedence over automatic padding. Numeric `0` disables padding; objects configure individual directions            |

Keep the default policy for ordinary use. Bubble uses point-aware padding because its radii vary. See [PointMark edge padding](/viz/plot/mark/point#edge-padding) for calculation, precedence, and an interactive example. Points in `plotExtension` follow Plot defaults; set `domainPadding: 0` explicitly to keep a whole scale unpadded.

Size, color, and stroke are common concepts, but their inputs and semantics vary. Bubble requires a numeric size encoding; Connected Scatter styles points and paths separately; Ranged Dot distinguishes shared endpoint styles from start and end overrides. Each chart’s API retains these differences.
