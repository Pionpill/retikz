Chart-wide presentation explains what a graphic says, what scope it covers, where its data comes from, and what constraints affect interpretation. It belongs to Chart rather than one chart type, and it is distinct from Plot axes, legends, and annotations.

## Fixed slots and canonical order

This playground uses a real Point Chart instead of simulating layout with boxes. Title, subtitle, Plot, note, and source all enter one Surface. Enable the Flex overlay to inspect the content, slot, allocation, padding, line region, and gaps of the canonical children.

`title`, `subtitle`, `note`, and `source` are four fixed slots. Resolution always uses `title → subtitle → plot → note → source`; omitting a slot only removes that item and never moves the others across the Plot boundary.

| React marker    | Source slot | Default position | Typical content                             |
| --------------- | ----------- | ---------------- | ------------------------------------------- |
| `ChartTitle`    | `title`     | top              | Subject or primary conclusion               |
| `ChartSubtitle` | `subtitle`  | top              | Scope, year, sample, unit, or method        |
| `ChartNote`     | `note`      | bottom           | Reading constraints or methodology details  |
| `ChartSource`   | `source`    | bottom           | Dataset and processing that affects meaning |

React can provide the slots with the four markers; Vanilla and JSON use the `presentation` object directly. Markers must be direct Chart children, though transparent `Fragment` groups are accepted. Duplicating one marker fails loudly. Marker order, JSON property order, and Vanilla object construction order have no semantic meaning; free presentation order is not supported yet.

## Presentation items are optional

When `title`, `subtitle`, `note`, or `source` is absent, normalization creates no matching item. Plot and the remaining presentation content still use the fixed order. Use the four switches below to compare the canonical result with each item present or absent.

## Authoring versus canonical representation

Authoring exposes only the four slot values; it does not need a separate `position` field. Resolution inserts the Plot placeholder at its fixed position and produces the Surface / Flex content in canonical order.

Presentation text may be a string or a JSON-serializable Core `TextBlock`. React markers additionally accept strings, transparent `Fragment` groups, and Core `Text` children, then normalize them into the same text contract. Arbitrary React elements never enter Source.

During resolution, Chart uses a Standard `Surface` as the chart-wide container and Flex ordering for presentation text and the single Plot placeholder. Chart theme tokens style the slots, while Plot continues to own its own axes, legends, and annotations.
