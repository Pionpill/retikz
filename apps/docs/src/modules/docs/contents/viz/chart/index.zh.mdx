title: Chart
description: Chart 在 Plot 之上组织具体图形类型，并提供标题、来源、画布和主题等整图能力。
---

Chart 面向“完整图形”：根 `type` 是便于发现的 family，嵌套 `recipe.chartType` 选择具体 recipe。Chart 还提供标题、来源、画布与主题；Plot 持续拥有数据、图元、通道、比例尺、坐标、辅助元素与变换。Chart 不建立第二套图形语法。

| 层次  | 负责什么                                                     | 不负责什么                     |
| ----- | ------------------------------------------------------------ | ------------------------------ |
| Chart | family、chartType、Chart Source、整图展示、画布和 Theme      | 重新定义 Plot 的图元与编码语法 |
| Plot  | 数据、变换、图元、通道、比例尺、坐标、轴、图例和其它辅助元素 | Scatter 等图形类型产品语义     |

## 一个最小 Point Chart

具体图形使用 typed Chart 根，并通过 owner-scoped declaration 填充公共与私有 slot。下面的 `ScatterChart` 会产生 `type: 'point'`、`recipe.chartType: 'scatter'` 的 Source。

```tsx
import { ChartData, ChartLayout, ChartSource, ChartTitle } from '@retikz/chart-react';
import { ScatterChart, ScatterEncodings, ScatterProperties } from '@retikz/chart-react/point';

const rows = [
  { x: 1, y: 2 },
  { x: 2, y: 3 },
  { x: 3, y: 5 },
];

<ScatterChart>
  <ChartData data={rows} />
  <ChartLayout width={640} height={360} />
  <ScatterEncodings x="x" y="y" />
  <ScatterProperties size={8} />
  <ChartTitle>两个变量的关系</ChartTitle>
  <ChartSource>示例数据</ChartSource>
</ScatterChart>;
```

## 公共 declaration API

| Declaration                                                  | 基数       | 主要属性                          | 职责                                                                                   |
| ------------------------------------------------------------ | ---------- | --------------------------------- | -------------------------------------------------------------------------------------- |
| `ChartData`                                                  | 恰好 1     | `data`、`reference?`、`model?`    | 声明运行时数据行、Source 数据引用与字段模型；真实 rows 不进入 JSON Source              |
| `ChartLayout`                                                | 至多 1     | `width?`、`height?`、`layout?`    | 声明 standalone host dimensions 与 Source border-box；显式 `layout` 不和尺寸字段级合并 |
| `ChartExtension`                                             | 至多 1     | Plot extension props、`children?` | 隔离 axis、legend、transform、独立 Plot mark 等 Plot-owned 声明                        |
| `ChartTitle` / `ChartSubtitle` / `ChartNote` / `ChartSource` | 每类至多 1 | `children`                        | 写入固定 presentation slot；数组与 Fragment 只做透明分组                               |

Plot declaration 不能直接放在具体 Chart 根。`ChartExtension` 的 props 与 children 进入同一 Plot normalizer；props 中的 transform 先于 child transform，单值 slot 的双来源冲突继续由 Plot 报告。

具体 Chart 根只穿透数组与透明 Fragment，不穿透 DOM 或自定义 React 组件；被 wrapper 包住的 declaration 会 fail-loud。`ChartExtension` children 只接受 Plot declarations、数组、透明 Fragment 与空 slot，`Set` / generator 等普通 iterable 会被拒绝；Chart declaration 放入 extension、Plot declaration 放在 Chart 根也都会立即报错。

具体 Chart 根只保留所有类型共用的接线字段：`id?`、`theme?`、`panel?`、`themeDefinitions?`、`lowerOptions?` 与必需的 `children`。数据、layout、recipe 与 Plot extension 不再是根 props。

## React 宿主与嵌入

直接渲染具体 Chart 时会建立唯一一个 `Layout` / Scene host。`ChartLayout.width` 与 `height` 必须是有限正数，并配置该 host；若没有显式 `layout`，已声明的尺寸还会镜像到 Source。显式 `layout` 存在时保持独立，不与 host dimensions 合并。

放入已有 `<Layout>` 后，Chart 只贡献 Chart → Plot → Core 的 Scope/composite 并继承外层 effective Theme，不创建第二个 SVG。embedded `ChartLayout` 只能声明 `layout`；`width` / `height`（包括显式 `undefined`）会 fail-loud。CSS、renderer/runtime、动画和 compile callback 等高级宿主能力统一配置在外层 `<Layout>`。

如果已有符合精确 schema 的 JSON Source，应由应用层根据 `type` 与 `recipe.chartType` 选择具体入口或 compile adapter；Chart 不提供动态加载所有 family 的 generic `<Chart source={...}>`。Vanilla 与 JSON Source API 不受 React declaration 结构影响。
