title: Bubble chart
description: A bubble chart adds a third numeric variable through bubble size.
---

A bubble chart adds a required numeric `size` channel alongside the `x` and `y` position channels, allowing a data field to control bubble size. Each row produces one bubble, and `color` can distinguish categories.

## Using this topic

After [installation and first rendering](/viz/chart/get-start), choose one of the four equivalent inputs below. They share data and configuration.

100 earthquake records: depth on x, magnitude on y, and significance as size.

## Basic usage

### Bubble encodings

Encodings determine bubble positions, numeric size, and category colors.

<DocTabs defaultValue="react-jsx">
<DocTab value="react-jsx" label="React + JSX">

```tsx
<BubbleEncodings x="gdpPerCapita" y="lifeExpectancy" size="population" color="continent" />
```

</DocTab>
<DocTab value="vanilla-api" label="Vanilla API">

```ts
encodings: {
  x: 'gdpPerCapita',
  y: 'lifeExpectancy',
  size: 'population',
  color: 'continent',
},
```

</DocTab>
<DocTab value="direct-ir" label="IR">

```ts
recipe: {
  encodings: {
    x: 'gdpPerCapita',
    y: 'lifeExpectancy',
    size: 'population',
    color: 'continent',
  },
},
```

</DocTab>
</DocTabs>

This view uses 142 countries and territories from Gapminder 2007 to compare income, life expectancy, and population across continents.

- `x`: Map gdpPerCapita to a linear x-axis to compare numeric differences directly.
- `y`: Map lifeExpectancy to y.
- `size`: Use population for bubble size.
- `color`: Distinguish continents with continent.

Toggle category coloring to see how `color` distinguishes continents. Compare differently sized bubbles at similar positions to distinguish similar indicators from similar population sizes. The association does not control for other influencing factors.

### Bubble properties

Constant properties style bubbles without replacing the required numeric size encoding. Bubble sizes usually vary, so `autoPadding` defaults to `'point-aware'`, using each bubble’s actual position and radius. See [Point charts: automatic edge padding](/viz/plot/mark/point#edge-padding) for the strategies and a visual comparison.

In the same data, larger populations can obscure nearby countries. Appearance controls make overlaps easier to read while preserving positions and population encoding.

- `opacity.fill`: Set 0.35 to make overlapping regions easier to distinguish.
- `stroke`: Choose an outline color to separate nearby bubbles.
- `strokeWidth`: Set 1.5 to emphasize outlines; set 0 to compare bubbles without strokes.
- `shape`: Change the glyph shape without assigning a constant size.

Use the controls below to compare fill and stroke combinations. Use Scatter when every observation should have the same radius.

### Bubble marks

Marks append or replace bubbles while inheriting the chart’s numeric size encoding.

<DocTabs defaultValue="react-jsx">
<DocTab value="react-jsx" label="React + JSX">

```tsx
<BubbleMark
  override
  properties={{
    opacity: { fill: 0.15 },
    strokeWidth: 2,
  }}
/>
```

</DocTab>
<DocTab value="vanilla-api" label="Vanilla API">

```ts
marks: [
  {
    kind: 'bubble',
    override: true,
    properties: {
      opacity: { fill: 0.15 },
      strokeWidth: 2,
    },
  },
],
```

</DocTab>
<DocTab value="direct-ir" label="IR">

```ts
recipe: {
  marks: [
    {
      kind: 'bubble',
      override: true,
      properties: {
        opacity: { fill: 0.15 },
        strokeWidth: 2,
      },
    },
  ],
},
```

</DocTab>
</DocTabs>

This example retains income, longevity and population but replaces the primary bubbles with lighter fills and stronger outlines. Replacement does not add a second population layer.

- `override`: Set true to replace the primary mark in place.
- `properties.opacity.fill`: Use 0.15 to reduce occlusion.
- `properties.strokeWidth`: Use 2 for clearer outlines.

Size remains inherited from the recipe population field. Bubble marks deliberately have no size override, so the third numeric role is retained.

## Extended usage

### Logarithmic mapping

When income spans orders of magnitude, a linear axis compresses many countries. A logarithmic x-axis spreads out lower values, making income easier to compare across orders of magnitude.

Groups below are properties inside IR `recipe`; React and Vanilla use the corresponding inputs described above.

| Group        | Property       | Type             | Description                                 |
| ------------ | -------------- | ---------------- | ------------------------------------------- |
| `encodings`  | `x.scale`      | log scale object | GDP per capita must be positive             |
|              | `size`         | string           | Use population to represent population size |
|              | `color`        | string           | continent categories                        |
| `properties` | `opacity.fill` | number           | Reduce overlapping occlusion                |

Switch the x scale and inspect how horizontal distances change. Equal distances on a log axis are not equal dollar differences.

### Facet comparison

When color alone cannot separate dense regions, split panels by continent. Shared position and size scales support comparisons of income ranges and population sizes.

Groups below are properties inside IR `recipe`; React and Vanilla use the corresponding inputs described above.

| Group        | Property       | Type           | Description                                          |
| ------------ | -------------- | -------------- | ---------------------------------------------------- |
| `encodings`  | `x / y / size` | field mappings | Income, longevity and population                     |
|              | `row`          | string         | Create rows by continent                             |
|              | `facet`        | facet options  | Keep shared scales, show row headers and set spacing |
| `properties` | `opacity.fill` | number         | Use translucent fills                                |

Compare panels within the same x interval. The number of bubbles represents countries, not total population.

## Errors and limitations

- Size must come from a numeric field; `BubbleEncodings.size` cannot be removed through constant properties or a mark override.
- Named size scales must use sqrt. Exact area ratios also depend on domain, range and glyph shape.
- Facet options require row or column; binned position mappings cannot be combined with facets.

In React, supplying the same configuration field through both the root `recipe` and a child component raises an error.

Fully explicit `domainPadding` bypasses point-aware solving. See [shared point-chart configuration](/viz/chart/points#shared-configuration) for properties and precedence.

### Chart construction

Chart resolves a bubble mark to a Plot Point whose size comes from a numeric field. The table lists only bubble-specific conversions.

| Group      | `@retikz/chart`               | `@retikz/plot`                | Description                                                                       |
| ---------- | ----------------------------- | ----------------------------- | --------------------------------------------------------------------------------- |
| Encodings  | `size`                        | `size`                        | Maps the required numeric field to point size; the default size scale uses `sqrt` |
| Properties | `opacity.fill`, `strokeWidth` | `opacity.fill`, `strokeWidth` | Applies defaults of 0.7 and 1 before explicit properties override them            |
| Mark       | `BubbleChartMarkSchema`       | `PointMarkSchema`             | Resolves each bubble mark to one Plot Point                                       |
