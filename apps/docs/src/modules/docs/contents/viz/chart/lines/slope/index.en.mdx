---
title: Slope
description: Compare paired values across two stages with endpoint markers and entity labels.
---

A slope chart connects two values for each entity. An upward line indicates an increase; a downward line indicates a decrease. Both ends share one value scale. Each data row supplies a pair. Use [Line](/viz/chart/lines/line) for trends across more than two stages.

## Using this topic

After [installation and first render](/viz/chart/get-start), import from the Chart packages' `/line` entry. The four forms below use the same data. Points and labels are visible by default, with a line width of 2.

## Basic usage

### Slope encodings

Each row supplies an entity and its start/end values. Swapping the fields reverses the comparison; reordering rows preserves every pair.

<DocTabs defaultValue="react-jsx">
<DocTab value="react-jsx" label="React + JSX">

```tsx
<SlopeEncodings entity="entity" start="previous" end="current" />
```

</DocTab>
<DocTab value="vanilla-api" label="Vanilla API">

```ts
encodings: { entity: 'entity', start: 'previous', end: 'current' }
```

</DocTab>
<DocTab value="direct-ir" label="IR">

```json
{ "recipe": { "encodings": { "entity": "entity", "start": "previous", "end": "current" } } }
```

</DocTab>
</DocTabs>

| Property        | Type                         | Description                                                                     |
| --------------- | ---------------------------- | ------------------------------------------------------------------------------- |
| `entity`        | Field name or direct mapping | Required; endpoint names and default categorical color                          |
| `start` / `end` | Field name or direct mapping | Required paired values; may bind one shared scale, without implicit aggregation |
| `color`         | Field name or direct mapping | Optional categorical color; defaults to entity                                  |

Eight entities, A, B, C, E, F, G, H, and I, each occupy one row with previous and current observations.

- `entity`: binds entity to distinguish the eight comparisons.
- `start` / `end`: bind previous and current on the same value axis.

Swap stages to reverse the comparison. Shuffle rows to confirm that pairing remains unchanged.

### Slope properties

The default y scale uses `domainPadding: 32` to leave 32 drawing units at both ends for endpoint labels. An explicitly declared value scale uses its own padding configuration; set `domainPadding: 0` to disable it.

Configure points, labels, and lines independently. Hiding points can leave their entity labels visible.

Each endpoint has one label whose content comes from `entity`. Set `label: false` to hide it; `true` or an options object enables it. Without `position`, the start label faces left and the end label faces right; an explicit position applies to both. Label arrays and separate endpoint configurations are not supported.

<DocTabs defaultValue="react-jsx">
<DocTab value="react-jsx" label="React + JSX">

```tsx
<SlopeProperties point={{ size: 4 }} label={{ position: 'top', distance: 8 }} path={{ strokeWidth: 2 }} />
```

</DocTab>
<DocTab value="vanilla-api" label="Vanilla API">

```ts
properties: { point: { size: 4 }, label: { position: 'top', distance: 8 }, path: { strokeWidth: 2 } }
```

</DocTab>
<DocTab value="direct-ir" label="IR">

```json
{
  "recipe": {
    "properties": {
      "point": { "size": 4 },
      "label": { "position": "top", "distance": 8 },
      "path": { "strokeWidth": 2 }
    }
  }
}
```

</DocTab>
</DocTabs>

| Property | Type                    | Description                                                                               |
| -------- | ----------------------- | ----------------------------------------------------------------------------------------- |
| `stages` | Two strings             | Distinct left/right names; defaults to field names                                        |
| `point`  | Boolean or style object | Defaults to true; controls radius, shape, fill, stroke, and opacity                       |
| `label`  | Boolean or options      | Defaults to true; one entity label per endpoint, with position, distance, font, and color |
| `path`   | Stroke style object     | Width defaults to 2; a straight two-stage connection                                      |

The paired observations remain fixed while appearance changes.

- `point.size`: starts at 4; zero is a valid radius.
- `label`: enabled initially, using entity names, outward placement, and a distance of 8.
- `path.strokeWidth`: starts at 2.

Hide the points while retaining their labels; change label direction or distance to affect both endpoints, then reset.

Add a comparison group or replace the built-in line, points, and labels together.


</DocTab>
<DocTab value="vanilla-api" label="Vanilla API">

```ts

  slopeMark({
    properties: { path: { stroke: '#a855f7', strokeWidth: 2, dashPattern: [5, 4] }, point: false, label: false },
  }),
];
```

</DocTab>
<DocTab value="direct-ir" label="IR">

```json
{
  "recipe": {
    "marks": [
      {
        "kind": "slope",
        "properties": {
          "path": { "stroke": "#a855f7", "strokeWidth": 2, "dashPattern": [5, 4] },
          "point": false,
          "label": false
        }
      }
    ]
  }
}
```

</DocTab>
</DocTabs>

| Property     | Type                     | Description                                                 |
| ------------ | ------------------------ | ----------------------------------------------------------- |
| `override`   | Boolean                  | Appends by default; true replaces the entire built-in group |
| `encodings`  | Direct field overrides   | Overrides start/end, not entity or stage names              |
| `properties` | Sparse member properties | Inherits path/point/label fields; preserves false and zero  |

The purple dashed group uses the same pairs as the solid built-in lines.

- `path`: purple stroke, width 2, dash pattern [5, 4].
- `point` / `label`: disabled for the added group to avoid duplicate annotations.
- `override`: starts false.

Enable replacement to remove the original lines, points, and labels together. Enable added points to show the new group's endpoints.

## Extended usage

The encodings and properties groups below belong to recipe in the IR.

### Missing endpoints

A missing observation removes only that row's connection. The valid endpoint and its labels remain, without filling the gap with zero.

| Group        | Property        | Type       | Description                    |
| ------------ | --------------- | ---------- | ------------------------------ |
| `encodings`  | `start` / `end` | Field name | Read both stages from one row  |
| `properties` | `label`         | Boolean    | Show labels on valid endpoints |

B initially has no previous value; its current value of 62 remains visible. Restore the start to recover the connection.

Separate regions to reduce crossings without changing their paired observations.

| Group       | Property | Type       | Description                         |
| ----------- | -------- | ---------- | ----------------------------------- |
| `encodings` | `row`    | Field name | Split vertically by region          |
|             | `entity` | Field name | Retain names and categorical colors |

## Errors and limitations

- Input uses paired wide rows. Reshape long tables first. Repeated names remain independent rows, without deduplication or aggregation.
- Stage names must differ. Explicit endpoint scales must agree; independent value axes are not supported.
- Missing observations omit connections. Missing field declarations, invalid scale references, invalid constants, and coordinate projection errors still fail.
- Labels do not avoid collisions automatically. Filter data, adjust fonts, or facet dense comparisons.

### Chart construction

| Group      | `@retikz/chart`      | `@retikz/plot`                  | Description                                              |
| ---------- | -------------------- | ------------------------------- | -------------------------------------------------------- |
| Encodings  | start, end           | Path encodings.from/to          | One complete endpoint path per row                       |
|            | entity, color        | color, label                    | Names and colors do not determine pairing                |
| Properties | stages               | Point scale domain              | Fix the two stage positions                              |
|            | point, label         | Point properties, label         | Zero-size hosts can retain labels when points are hidden |
| Mark       | SlopeChartMarkSchema | PathMarkSchema, PointMarkSchema | A connection and two independent endpoints               |

Both ends use the same y scale. Plot skips the row's path when a field value cannot be mapped. The endpoint marks still consume the original rows, keeping the valid end visible.
