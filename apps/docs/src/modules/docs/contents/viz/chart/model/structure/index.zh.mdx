如果你只想描述“数据怎样映射成图形”，可以直接使用 Plot。当你已经知道要做散点图、气泡图或连接散点图时，Chart 提供带有默认语义的类型入口，减少需要记忆的配置，并统一处理标题、来源、画布与主题等整图能力。

基于 `type` 的 Chart 封装更加容易上手，也更容易被 LLM 理解。等你熟悉 Plot 后，还可以以某个 Chart 类型生成的图形为基础，通过 `plot` 成员添加 Plot 内容，构造更复杂的图形。下面先用一份 Source 建立整体印象，再展开字段职责和解析过程。

## 先看一份 Chart Source

下面用 Scatter 作为例子。代码只保留字段关系，数据和展示项的具体内容用省略号表示：

```ts
{
  namespace: 'chart',
  type: 'scatter',
  config: {
    encoding: {
      x: { field: 'height' },
      y: { field: 'weight' },
    },
  },
  plot: {
    data: { /* Plot data */ },
    // 这里还可以添加 Plot 的 transform、marks、guides 等内容
  },
  presentation: {
    children: [
      { kind: 'preset', preset: 'title', /* ... */ },
      { kind: 'plot', key: 'plot' },
      { kind: 'preset', preset: 'source', /* ... */ },
    ],
  },
}
```

这份输入表达的是：在 Chart 能力域中选择 `scatter`，用 `config` 说明 x/y 位置，再允许 `plot` 补充 Plot 侧内容；最后用 `presentation` 把生成的 Plot 放进一张有标题和来源的整图中。

## 字段布局：职责速览

先用这张表定位每个字段，下面的小节再说明它的行为和边界：

| 字段           | 主要职责                  | 典型承载内容                                                     |
| -------------- | ------------------------- | ---------------------------------------------------------------- |
| `namespace`    | 将输入路由到 Chart        | 固定值 `chart`                                                   |
| `type`         | 选择精确 schema 和 recipe | `scatter`、`bubble` 等类型标识                                   |
| `config`       | 表达类型专属意图          | x/y、size、order 以及类型允许的表现补丁                          |
| `plot`         | 复用 Plot 并继续扩展      | data、transform、scales、coordinate、marks、guides、theme 与尺寸 |
| `presentation` | 组织整图展示              | 标题、副标题、唯一的 Plot 占位、注释、来源及它们的顺序与布局     |

### `namespace`：声明能力域

`namespace: 'chart'` 是固定的判别字段。它告诉解析器：这不是直接交给 Plot 的输入，而是一份 Chart Source。它只负责选择能力域，不能代替 `type` 选择散点图或气泡图。

### `type`：选择类型和默认语义

`type` 是精确的判别值。它同时决定使用哪一个 schema 检查输入，以及使用哪一个 recipe 生成默认 Plot 语义。也就是说，`type` 不只是给结果起名字：

| `type`              | `config` 中的核心输入                  | Chart 会补出的默认语义                      |
| ------------------- | -------------------------------------- | ------------------------------------------- |
| `base`              | 没有类型专属 `config`                  | 不补主图元；`plot` 必须自行描述完整图形     |
| `scatter`           | x/y 位置，可选颜色、尺寸、透明度、形状 | Point 主图元、二维比例尺、坐标和默认 guides |
| `bubble`            | x/y 位置与必需的 size 字段             | 在 Point 语义上增加定量尺寸映射和尺寸图例   |
| `connected-scatter` | x/y 位置与必需的 order，可选 series    | 在 Point 语义上增加按顺序连接数据的路径     |

Chart 不用一个宽泛的公开 union schema 猜测类型。每个精确 `type` 都有自己的 schema 和 recipe；这样错误会在对应入口被发现，类型默认行为也能保持清晰。

### `config`：表达类型专属意图

`config` 只放当前 Chart 类型才有意义的输入。以 Point 类型为例，x/y 表达位置角色，颜色、尺寸、透明度和形状表达视觉通道；Bubble 的 `size` 是它独有的必需角色；Connected Scatter 的 `order` 决定连接路径的顺序，`series` 可以把数据分成多条独立路径。

因此，`config` 更像“我要画什么、关键字段是什么”，而不是一个可以放任意属性的样式对象。类型 recipe 会读取它，生成主 mark、比例尺、坐标和默认 guides。类型允许的 `mark` 或 `components` 补丁也属于 `config`，但仍必须遵守该类型的 schema。

### `plot`：复用 Plot 并保留扩展能力

`plot` 是 Plot owner 的字段。它承载数据、数据变换、比例尺、坐标或 composition、marks、guides、主题和尺寸等 Plot 内容。Chart 类型 recipe 先根据 `config` 生成默认 Plot 部分，再把作者写在 `plot` 中的内容合并进去：作者可以补充 marks，也可以按 Plot 的规则提供或覆盖相应的 Plot 配置。

这就是 Chart 和 Plot 的关系：Chart 提供易上手的类型默认值，Plot 仍然是表达复杂图形的底层能力。`plot` 不是绕过 Chart 的另一套输入；它是 Chart 允许作者向下扩展的 Plot 成员。

### `presentation`：组织整图展示

`presentation` 描述 Chart 的整图展示结构，而不是绘图语法。它的 `children` 按顺序放置标题、副标题、唯一的 Plot 占位、注释和来源；其中 Plot 占位告诉 Chart 把已经解析完成的图形放到哪里。标题、来源、画布间距和主题等能力因此可以由 Chart 统一管理，不需要每个 Plot 自己重复实现。

`presentation` 与 `plot` 的边界可以这样记：`plot` 决定“图形画什么”，`presentation` 决定“这张图怎样被阅读”。

除了这些核心字段，Source 还可以带有 `id` 和 Chart 主题 token 等共享元数据。它们用于标识实例或调整 Chart 外层样式，不改变 `namespace`、`type`、`config`、`plot` 和 `presentation` 的职责分工。

## 解析原理

图中的管线从用户输入开始，最后得到一份可以交给统一 Chart 外层消费的 Plot。先不需要记住 `Source`、`IRPlot` 或 `Base Chart` 这些名称，只要按下面的步骤理解它发生了什么：

<ComponentPreview files="chart-recipe-pipeline" hideCode size="sm" />

1. **收集一份具体类型的输入**：React 或 Vanilla 入口接收用户配置，形成一份 Chart Source。Source 就是“描述要画什么”的结构化输入，里面保留了 `type`、`config` 和作者提供的 `plot`。
2. **匹配类型并检查结构**：入口根据 `type` 找到对应的精确 schema 和 recipe，检查必需字段是否存在、字段形状是否正确。图中的 `match` 表示这一步。
3. **读取类型配置并生成默认 Plot**：类型 recipe 绑定这份 Source，读取 `config`，生成该类型需要的主 mark、比例尺、坐标和默认 guides。这里的 recipe 可以理解为“把类型输入翻译成 Plot 默认部分的规则”。
4. **合并作者的 Plot**：Chart 把类型默认部分和 `plot` 中作者声明的数据、变换、主题、尺寸及扩展图元合并。这样简单图形只需 `config`，复杂图形仍可通过 `plot` 继续表达。
5. **验证并交给统一外层**：合并结果通过 Plot schema 后，成为完整的 `IRPlot`。IR 只是内部可序列化的中间表示；随后它和 `presentation` 一起放进统一的 Base Chart（代码中的 `IRBaseChart`），由 Chart 的整图定义继续处理。

图中的 `Type Recipe`、`Plot Merge` 和 `IRPlot` 分别对应第 3、4、5 步。它们是解析过程中的内部角色，不是用户必须直接构造的另一套公开 API。所有具体 Chart 类型完成自己的 recipe 绑定后，都沿用同一条统一的 Chart 解析与下沉路径。
