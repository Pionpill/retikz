This page covers entries and constraints specific to this chart. See the [quick-start example](/viz/chart/get-start#the-first-result) for shared configuration using React components.

React uses `ScatterChart`, configured through its `recipe` prop or the dedicated child components below. The Vanilla API uses `scatterChart` with direct `encodings`, `properties`, and `marks` options. Direct IR places these fields inside `recipe` and sets `recipe.chartType: 'scatter'`. React and the Vanilla API supply the chart type automatically.

React can combine root props and child components for different configuration fields, but each field must be declared only once. For example, providing both `recipe.encodings` and `ScatterEncodings` raises an error. Root-only configuration requires no children.

These schemas are exported from `@retikz/chart/point` and describe persistable JSON IR. Nested root and shared configuration retain their type names. The recipe, encodings, properties, and mark contracts follow below. See the API reference for React and Vanilla authoring.

Use `ScatterMark` in React, `marks` in the Vanilla API, and `recipe.marks` in direct IR. React marks must be direct children of `ScatterChart`; Vanilla / IR marks declare `kind: 'scatter'`.

| Property     | Type                             | Description                                                                                      |
| ------------ | -------------------------------- | ------------------------------------------------------------------------------------------------ |
| `override`   | `boolean`                        | Appends when omitted; `true` replaces the default Scatter mark in place                          |
| `encodings`  | `ScatterChartMark['encodings']`  | Supports `x`, `y`, `color`, `size`, `opacity`, and `shape`; does not accept full mapping objects |
| `properties` | `ScatterChartMark['properties']` | Follows the properties above, excluding `autoPadding` and `domainPadding`                        |

Omitted mappings and properties inherit applicable chart settings. If replacement finds no target, the mark is appended and `onWarn` reports `CHART_MARK_OVERRIDE_TARGET_NOT_FOUND`. See the [mark schema](#scattermark--scatterchartmarkschema) for the full structure.
