  Scatter uses the exact `ScatterChartSchema`. The root `type` is `point` and `recipe.chartType` is `scatter`; data, layout, presentation, and Theme stay in the Source shell, while field bindings live in `recipe.encodings` and constant styles live in `recipe.properties`.

All examples on this page use `ScatterChart` from `@retikz/chart-react/point/scatter`. The recipe emits the built-in Scatter semantic mark, two-dimensional scales, and default Plot structure. A direct `ScatterMark` child injects an additional Chart-owned mark through `recipe.marks`, inheriting consumable encodings and properties.

`encodings` contain field names only; constants belong in `properties`. When both map to the same property, encoding wins. A mark's own `encodings` / `properties` override only that mark's inherited result and never mutate the recipe's built-in semantic mark. To add axes, legends, facets, tracks, or a completely independent Plot mark, write a Source `plotExtension` fragment; it does not inherit Chart context and is not an alias for `recipe.marks`.

## Shared Chart rules

Scatter shares family / chartType routing, exact schemas, the authoring pipeline, fixed presentation slots, and Theme owner slices with every other Chart type. Refer to [Chart Model](/viz/chart/model) for those rules; this page stays focused on Scatter's two-dimensional position, categorical encoding, and mark semantics.
