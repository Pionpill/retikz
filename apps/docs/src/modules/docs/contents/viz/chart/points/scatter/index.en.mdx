title: Scatter
description: Compare two continuous variables with points, and distinguish categories through color and shape encodings.
---

A scatter plot places each observation using two continuous variables. Use it to inspect relationships, distributions, and outliers. Color and shape distinguish categories; facets separate groups for comparison. Correlation alone does not establish causation.

## Using this topic

After [installation and first render](/viz/chart/get-start), choose one of the four entry points below. They share the same movie data and axis mappings. React and the Vanilla API assemble chart definitions automatically; direct IR supplies chart definitions and external data explicitly.

The example compares IMDb and Rotten Tomatoes ratings for 100 films. Each point represents one film.

The following tree lists all Scatter-specific children of `ScatterChart`: `ScatterEncodings` declares field mappings, `ScatterProperties` sets point appearance, and `ScatterMark` adds or overrides scatter marks. The latter two are optional; basic charts do not require an explicit `ScatterMark`.

```text
ScatterChart
├── ScatterEncodings
├── ScatterProperties
└── ScatterMark
```

This example reuses the movie data above. Child declarations are React-only.

```tsx
import { ChartData } from '@retikz/chart-react';
import { ScatterChart, ScatterEncodings } from '@retikz/chart-react/point';
import { scatterMinimalData } from './scatter-minimal.data';

export const Example = () => (
  <ScatterChart>
    <ChartData data={scatterMinimalData} />
    <ScatterEncodings x="imdbRating" y="rottenTomatoesRating" />
  </ScatterChart>
);
```

## Basic usage

### Scatter mappings

Mappings determine how data affects point position, color, shape, size, and opacity.

<DocTabs defaultValue="react-jsx">
<DocTab value="react-jsx" label="React + JSX">

```tsx
<ScatterEncodings x="fertilityRate" y="femaleLaborParticipation" color="incomeGroup" shape="incomeGroup" />
```

</DocTab>
<DocTab value="vanilla-api" label="Vanilla API">

```ts
encodings: {
  x: 'fertilityRate',
  y: 'femaleLaborParticipation',
  color: 'incomeGroup',
  shape: 'incomeGroup',
},
```

</DocTab>
<DocTab value="direct-ir" label="IR">

```ts
recipe: {
  encodings: {
    x: 'fertilityRate',
    y: 'femaleLaborParticipation',
    color: 'incomeGroup',
    shape: 'incomeGroup',
  },
},
```

</DocTab>
</DocTabs>

This example uses World Bank data for 186 economies in 2022. Each point represents an economy; fertility and female labor participation reveal the spread and overlap of income groups.

- `x`: Maps `fertilityRate` to the horizontal position.
- `y`: Maps `femaleLaborParticipation` to the vertical position.
- `color`: Maps `incomeGroup` to different colors.
- `shape`: Also maps `incomeGroup`, using shapes to help identify the same categories.

Color and shape provide two ways to identify income groups. Use the controls below to disable either mapping and compare how easily categories can still be distinguished; these changes do not move the points.

### Scatter properties

Constant properties style the whole point set; unspecified appearance follows the drawing defaults.

<DocTabs defaultValue="react-jsx">
<DocTab value="react-jsx" label="React + JSX">

```tsx
<ScatterProperties size={8} opacity={0.4} stroke="#475569" strokeWidth={1.5} />
```

</DocTab>
<DocTab value="vanilla-api" label="Vanilla API">

```ts
properties: {
  size: 8,
  opacity: 0.4,
  stroke: '#475569',
  strokeWidth: 1.5,
},
```

</DocTab>
<DocTab value="direct-ir" label="IR">

```ts
recipe: {
  properties: {
    size: 8,
    opacity: 0.4,
    stroke: '#475569',
    strokeWidth: 1.5,
  },
},
```

</DocTab>
</DocTabs>

This example retains the same economies, fertility and labor-participation axes, and income-group categories. Here the goal is to make observations easier to distinguish: economies with similar values produce overlapping points, so appearance affects how easily readers can judge dense regions and separate neighboring observations.

- `size`: Sets a uniform point radius of `8` in this example. Larger points stand out but increase overlap in dense regions.
- `opacity`: Sets uniform transparency to `0.4` in this example. Lower opacity makes underlying points more visible in overlapping areas.
- `stroke`, `strokeWidth`: Adds gray outlines of width `1.5` to distinguish neighboring points; set the width to `0` to hide outlines.

These constants apply to every point and do not encode a third numeric measure. Use the controls below to adjust these properties, comparing both dense regions and isolated points to choose a readable appearance.

This example replaces the default marks using IMDb and Rotten Tomatoes ratings for 100 films. The horizontal axis shows IMDb ratings and the vertical axis shows Rotten Tomatoes ratings. Each film receives one point.

The example uses `ScatterMark` to replace the default marks and adjust their appearance:

- `encodings`: Omitted to inherit the existing data and position mappings.
- `properties`: Sets `size: 3` and `opacity: 1` for smaller opaque points.
- `override`: Fixed at `true` to replace the default points.

Adjust the radius and opacity to compare point footprints and dense regions. In React, use `ScatterMark` as a direct child of `ScatterChart`.

## Extended usage

### Facet comparison

Separate categories into panels to compare their distributions. This example combines field mappings, facet layout, and point appearance. Mappings belong to `recipe.encodings` and appearance to `recipe.properties`; the corresponding React children provide the same configuration.

| Group        | Prop                     | Type                                             | Description                                                                              |
| ------------ | ------------------------ | ------------------------------------------------ | ---------------------------------------------------------------------------------------- |
| `encodings`  | `x`, `y`                 | Field name or mapping object                     | Map fertility and female labor participation with consistent axis meanings across panels |
|              | `column`                 | Field name, partition object, or partition array | Split columns by income group; `field` selects the field and `order` sets category order |
|              | `facet.header.column`    | `boolean` or text style object                   | Set to `true` here to display income-group column headers                                |
|              | `facet.spacing.panelGap` | `number`                                         | Set to `20` here to space the panels                                                     |
| `properties` | `size`                   | `number`                                         | A radius of `4` suits the narrower panels                                                |
|              | `opacity`                | `number`                                         | Set to `0.65` here to reduce overlap obscuring points                                    |

The example reuses World Bank 2022 economy data and splits `incomeGroup` into HIC, UMC, LMC, and LIC columns with shared position scales. Compare where each group concentrates, then inspect its internal spread. Faceting changes grouping, not individual values. Use `row` for vertical arrangement; `facet` options require `row` or `column`.

### Spatial coordinates

When fields contain positions on a playing field, a scatter chart can become an event distribution map. Alongside position and category mappings, this example combines point appearance, axis visibility, and a plot-area background. In IR, `encodings`, `properties`, and `guides` belong to `recipe`, while `plotExtension` belongs to the chart root. Property names in the table are relative to their group.

| Group           | Prop                        | Type                         | Description                                                    |
| --------------- | --------------------------- | ---------------------------- | -------------------------------------------------------------- |
| `encodings`     | `x`, `y`                    | Field name or mapping object | Bind shot-origin coordinates through `recipe.encodings`        |
|                 | `color`                     | Field name or mapping object | Bind `outcome` to distinguish shot results                     |
| `properties`    | `size`                      | `number`                     | Adjust the radius to distinguish nearby events                 |
|                 | `shape`                     | Shape name string            | Set a uniform shape for shot locations                         |
|                 | `stroke`                    | Color string or paint object | Optionally outline points to separate them from the background |
|                 | `opacity`                   | `number`                     | Adjust transparency to reveal overlapping locations            |
| `guides`        | `axis`                      | `boolean`                    | Set to `false` here to hide default axes                       |
| `plotExtension` | `defaultPlot.plotArea.fill` | Paint object                 | Configure a pitch image with `kind: 'image'` and `href`        |

This example uses StatsBomb shot data from the 2022 World Cup. Each point locates the origin of a Messi shot, and color identifies its outcome. Bind `x` and `y` to position fields and add the pitch background to view shot concentrations against a spatial reference. Use the controls below to adjust size, shape, stroke, and opacity and compare readability over the background. Read the axes as spatial positions, not a correlation between statistical measures. When replacing the data or background, check that coordinate ranges, directions, and proportions agree.

## Errors and limitations

- `jitter` must target the axis of its position channel: x for the `x` mapping and y for `y`.
- `series`, `detail`, `order`, `text`, and ordinary mapping arrays without a defined consumer are unsupported.

- `x` and `y` are required, and fields must match their scales.
- `facet` requires `row` or `column`; facets currently cannot be combined with x/y `bin` mappings.
- Providing the same configuration field through both root props and a child component, such as `recipe.encodings` and `ScatterEncodings`, raises an error.
- Scatter does not connect observations. Use [Connected scatter](/viz/chart/points/connected-scatter) when order and connections matter.
- Overlapping points may hide observations. Opacity improves visibility but does not ensure every point can be distinguished.

### Chart construction

Chart resolves a scatter mark to a Plot Point. The table shows how position and appearance reach that mark.

| Group      | `@retikz/chart`            | `@retikz/plot`             | Description                                                   |
| ---------- | -------------------------- | -------------------------- | ------------------------------------------------------------- |
| Encodings  | `x`, `y`                   | `encoding.x`, `encoding.y` | Maps the two fields to horizontal and vertical position       |
|            | `size`, `shape`, `opacity` | `size`, `shape`, `opacity` | Uses fields for point size, shape, and opacity                |
| Properties | `size`, `shape`, `opacity` | `size`, `shape`, `opacity` | Applies constant appearance; matching encodings take priority |
| Mark       | `ScatterChartMarkSchema`   | `PointMarkSchema`          | Resolves each scatter mark to one Plot Point                  |
