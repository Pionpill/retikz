title: Scatter
description: Compare two continuous variables with points, and distinguish categories through color and shape encodings.

A scatter plot places each observation using two continuous variables. Use it to inspect relationships, distributions, and outliers. Color and shape distinguish categories; facets separate groups for comparison. Correlation alone does not establish causation.

## Using this topic

After [installation and first render](/viz/chart/get-start), choose one of the four entry points below. They share the same movie data, axis mappings, and point appearance. React and the Vanilla API assemble chart definitions automatically; direct IR supplies chart definitions and external data explicitly.

The example compares IMDb and Rotten Tomatoes ratings for 100 films. Each point represents one film.

```tsx
import { scatterMinimalData } from './scatter-minimal.data';

export const Example = () => (
  <ScatterChart>
    <ChartData data={scatterMinimalData} />
    <ChartTitle text="IMDb and Rotten Tomatoes ratings move together" />
    <ScatterEncodings x="imdbRating" y="rottenTomatoesRating" />
    <ScatterProperties size={5} opacity={0.65} />
  </ScatterChart>
);
```

## Basic usage

### Scatter mappings

In React, declare field mappings with `ScatterEncodings`. The Vanilla API uses `encodings`, and direct IR uses `recipe.encodings`. These mappings control how data determines point position, color, shape, size, and opacity.

| Prop      | Type                                             | Description                                                                            |
| --------- | ------------------------------------------------ | -------------------------------------------------------------------------------------- |
| `x`       | `string` or mapping object                       | Required; Horizontal field; supports direct, aggregate, or derived mappings            |
| `y`       | `string` or mapping object                       | Required; Vertical field; supports direct, aggregate, or derived mappings              |
| `color`   | `string` or mapping object                       | Maps a field to color; supports direct or aggregate mappings                           |
| `shape`   | `string` or direct mapping object                | Distinguishes categories with point shapes                                             |
| `size`    | `string` or mapping object                       | Maps numeric values to point size; supports direct, aggregate, or derived mappings     |
| `opacity` | `string` or mapping object                       | Maps numeric values to opacity; supports direct, aggregate, or derived mappings        |
| `row`     | Field name, partition object, or partition array | Creates facet rows from a field name, partition object, or ordered array of partitions |
| `column`  | Field name, partition object, or partition array | Creates facet columns using the same input forms as `row`                              |
| `facet`   | Facet options object                             | Configures facet headers, spacing, and shared scales; requires `row` or `column`       |

This example uses World Bank data for 186 economies in 2022, with one point per economy. The horizontal axis shows births per woman, and the vertical axis shows labor-force participation among women aged 15 and older. Points farther right have higher fertility, while points higher up have greater participation. Nearby points have similar values on both measures, helping reveal the overall distribution, clusters, and observations away from the majority.

- `x`: Maps `fertilityRate` to the horizontal position.
- `y`: Maps `femaleLaborParticipation` to the vertical position.
- `color`: Maps `incomeGroup` to different colors.
- `shape`: Also maps `incomeGroup`, using shapes to help identify the same categories.

Color and shape provide two ways to identify income groups and compare their spread and overlap. Open the controls and disable color or shape independently to see whether the categories remain distinguishable; these changes do not move the points. The distribution shows relationships between measures, not evidence of causation.

### Scatter properties

In React, set uniform appearance with `ScatterProperties`. The Vanilla API uses `properties`, and direct IR uses `recipe.properties`. The table lists common props; default drawing configuration determines any appearance not explicitly set.

| Prop            | Type                              | Description                                                                                                                                                                      |
| --------------- | --------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `color`         | `string`                          | Sets a uniform color                                                                                                                                                             |
| `shape`         | `string`                          | Sets a uniform shape using a registered shape name                                                                                                                               |
| `size`          | `number`                          | Point radius; must be greater than or equal to `0`                                                                                                                               |
| `opacity`       | `number`                          | Overall opacity from `0` to `1`                                                                                                                                                  |
| `fill`          | Color string or paint object      | Fill color or paint configuration                                                                                                                                                |
| `stroke`        | Color string or paint object      | Stroke color or paint configuration                                                                                                                                              |
| `strokeWidth`   | `number`                          | Nonnegative stroke width                                                                                                                                                         |
| `fillOpacity`   | `number`                          | Fill opacity from `0` to `1`                                                                                                                                                     |
| `strokeOpacity` | `number`                          | Stroke opacity from `0` to `1`                                                                                                                                                   |
| `domainPadding` | Number or per-side padding object | A number or per-side configuration object; pads the position domain to prevent edge clipping; unconfigured ends follow `autoPadding`, which defaults to the maximum point radius |
| `autoPadding?`  | `'max-radius'` \| `'point-aware'` | Automatic padding policy; omitted means `max-radius`; `point-aware` solves from individual positions and radii; explicit `domainPadding` wins                                    |

This example retains the same economies, fertility and labor-participation axes, and income-group categories. Here the goal is to make observations easier to distinguish: economies with similar values produce overlapping points, so appearance affects how easily readers can judge dense regions and separate neighboring observations.

- `size`: Sets a uniform point radius. Larger points stand out but increase overlap in dense regions.
- `opacity`: Sets uniform transparency. Lower opacity makes underlying points more visible in overlapping areas.
- `stroke`: Optionally adds outlines to help distinguish neighboring point boundaries.

These constants apply to every point and do not encode a third numeric measure. Open the point controls and adjust these properties, comparing both dense regions and isolated points to choose a readable appearance.

### Scatter marks

In React, add or replace scatter marks with `ScatterMark`. The Vanilla API uses the `marks` array, and direct IR uses `recipe.marks`; scatter entries in either array require `kind: 'scatter'`. The chart generates points automatically, so ordinary charts need no explicit mark.

| Prop         | Type                    | Description                                                                                                                                                                                 |
| ------------ | ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `override`   | `boolean`               | Adds a mark by default; `true` replaces the default scatter mark                                                                                                                            |
| `encodings`  | Field mappings object   | Overrides this mark's fields; optional keys are `x`, `y`, `color`, `size`, `opacity`, and `shape`, each taking a field name string; unspecified fields inherit chart mappings               |
| `properties` | Point properties object | Overrides this mark's point appearance, such as `{ size: 3, opacity: 1 }`; excludes recipe-level `domainPadding` and `autoPadding`; unspecified entries retain inheritable chart appearance |

This example compares IMDb and Rotten Tomatoes ratings for 100 films. Each position represents one film, with IMDb ratings on the horizontal axis and Rotten Tomatoes ratings on the vertical axis. A distribution from the lower left toward the upper right helps show whether the ratings generally move together. Points with similar horizontal positions but different vertical positions represent films with similar IMDb ratings and different Rotten Tomatoes ratings.

The example first uses `ScatterProperties` to set the default point radius to `8` and opacity to `0.25`, then configures an additional `ScatterMark`:

- `encodings`: Omitted to inherit the existing data and position mappings, so both layers occupy the same positions.
- `properties`: Sets `size: 3` and `opacity: 1`, placing a small opaque point at the center of each larger translucent point.
- `override`: Omitted to use the default append behavior. Setting it to `true` replaces the default points, leaving only the small points.

The translucent outer area preserves the point footprint, while the opaque center identifies its precise position. Both layers represent the same films, not separate datasets. In React, use `ScatterMark` as a direct child of `ScatterChart`.

### Split categories into facets

Separate categories into panels to compare their distributions. This example combines field mappings, facet layout, and point appearance. Mappings belong to `recipe.encodings` and appearance to `recipe.properties`; the corresponding React children provide the same configuration.

### Use spatial coordinates

When fields contain positions on a playing field, a scatter chart can become an event distribution map. Alongside position and category mappings, this example combines point appearance, axis visibility, and a plot-area background.

| Group           | Prop                                       | Type                         | Description                                                    |
| --------------- | ------------------------------------------ | ---------------------------- | -------------------------------------------------------------- |
| `encodings`     | `x`, `y`                                   | Field name or mapping object | Bind shot-origin coordinates through `recipe.encodings`        |
|                 | `color`                                    | Field name or mapping object | Bind `outcome` to distinguish shot results                     |
| `properties`    | `size`                                     | `number`                     | Adjust the radius to distinguish nearby events                 |
|                 | `shape`                                    | Shape name string            | Set a uniform shape for shot locations                         |
|                 | `stroke`                                   | Color string or paint object | Optionally outline points to separate them from the background |
|                 | `opacity`                                  | `number`                     | Adjust transparency to reveal overlapping locations            |

| `plotExtension` | `plotExtension.plotDefaults.plotArea.fill` | Paint object                 | Configure a pitch image with `kind: 'image'` and `href`        |

This example uses StatsBomb shot data from the 2022 World Cup. Each point locates the origin of a Messi shot, and color identifies its outcome. Bind `x` and `y` to position fields and add the pitch background to view shot concentrations against a spatial reference. ## Errors and limitations

- `x` and `y` are required, and fields must match their scales.
- `facet` requires `row` or `column`; facets currently cannot be combined with x/y `bin` mappings.
- Providing a slot through both root configuration and a declaration, such as `recipe.encodings` and `ScatterEncodings`, raises an error.
- Scatter does not connect observations. Use [Connected scatter](/viz/chart/points/connected-scatter) when order and connections matter.
- Overlapping points may hide observations. Opacity improves visibility but does not ensure every point can be distinguished.

### Automatic edge padding

A point's position identifies its center. Mapping the data minimum and maximum directly to plot boundaries leaves the radius extending outside those boundaries. Scatter charts therefore supply `domainPadding` for continuous position scales that have no padding configured, leaving room inside the edges for point centers. The linear-coordinate illustration compares explicit `domainPadding: 0` with omitting the property. Overflow remains visible on the left to show the clipping risk.

<ComponentPreview files="scatter-padding-figure" hideCode type="illustration" size="lg" />

Both panels use the same data, point radius, and plot dimensions. Automatic padding changes the position-scale domain; it does not change data, shrink points, or enlarge the canvas. Each edge reserves one radius for extreme points in this illustration.

After default, appended, and replacement marks are determined, Chart reads the final point sizes and selects the largest radius. A constant `size` supplies the radius directly. A field-mapped size uses the maximum of the size scale's output range rather than scanning individual rows to estimate it. Without an explicit size, it uses the default point radius. This calculation covers the radius only; it does not measure additional stroke, shadow, or text extents, so it does not guarantee room for those effects.

Padding is supplied according to these rules:

- Omitted `domainPadding`: use `range` units and the maximum point radius on each side. These units measure drawing-coordinate lengths, not data values.
- Explicit number: apply that value to each side; `0` disables padding. Objects resolve each side from its specific direction, then `x` / `y`, then `default`. Unspecified sides use the automatic policy in `range` mode and to `0` in `ratio` mode.
- Explicit directions: `left`, `right`, `top`, and `bottom` require Cartesian coordinates. Chart maps visual directions to lower and upper domain ends according to the scale range direction.
- Configured scales: if a scale already has `domainPadding` or comes from `plotExtension.scales`, Chart preserves it without adding automatic padding.

The default `autoPadding: 'max-radius'` keeps the policy above without scanning individual rows. With `autoPadding: 'point-aware'`, Chart supplies the final point marks to Plot. Before generating geometry, Plot uses actual data views, positions, and radii to find compact padding. Space already available around large central points counts toward protection; large points near an edge also contribute, even when they are not position extrema.

Both charts below use identical data, size mappings, and canvas dimensions. The default reserves the maximum radius at every edge; point-aware padding uses existing space around the central point and adds the space needed at the edges.

<ComponentPreview files="scatter-auto-padding" hideCode type="illustration" size="lg" />

Both policies change position domains, not point sizes. Point-aware solving reuses numeric positions and sizes with bounded iterations and coordinates final plot-area dimensions. It never reads rendered geometry. Each solve pass is linear in the effective point count, so it costs more than the default mark-level calculation; strictly minimum padding is not guaranteed.

- Explicit `domainPadding` wins. Missing `range` ends use the selected policy; missing `ratio` ends remain `0`. Fully explicit padding bypasses point-aware solving.
- Point-aware mode currently requires Cartesian2D, linear/time position scales, and no placement. Unsupported combinations or infeasible drawing areas produce errors without falling back.
- Only effective points inside the baseline domain contribute size-radius constraints. Strokes, shadows, and text are excluded. Outside points retain Plot rendering and clipping semantics; domain expansion may bring some of them into view.
- Shared scales solve one domain across panels. Incompatible fixed pixel padding across differently sized panels produces an error.
- Chart references its final Point marks and Relation endpoints; `plotExtension.marks` are not included automatically. Authored scale padding and extension scales still take precedence.

Both `autoPadding` and `domainPadding` belong to recipe properties, not `ScatterMark.properties`.

## API reference

This page covers entries and constraints specific to this chart. See the [quick-start example](/viz/chart/get-start#the-first-result) for shared configuration using React components.

### Scatter configuration

`ScatterChart` fixes the Point family and Scatter recipe identity. Its root `recipe` directly uses Scatter's exact `encodings`, `properties`, and `marks` shape; component identity supplies `chartType: 'scatter'`:

```tsx
<ScatterChart
  rows={rows}
  data={{ reference: 'chart.data' }}
  recipe={{
    encodings: { x: 'fertility', y: 'work', color: 'incomeGroup' },
    properties: { size: 8 },
  }}
/>
```

The three declarations below are equivalent JSX sugar for those recipe slots. Root-only authoring can omit `children`; different slots can mix, while providing the same slot from both root and declaration fails loudly.

### Scatter mappings

`ScatterEncodingsProps` exactly reuses schema-derived `IRScatterChartEncodings`. Vanilla input and JSON Source keep the same encoding payload; React authors it as a separate declaration.

| Slot             | Supported Scatter mappings                                                            | Scatter-specific constraint                                                                       |
| ---------------- | ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| `x`              | `string`, direct, aggregate, derived (`bin`, `normalize`, `jitter`, custom transform) | Required; `jitter` can target only x; `bin` cannot be combined with a facet                       |
| `y`              | `string`, direct, aggregate, derived (`bin`, `normalize`, `jitter`, custom transform) | Required; `jitter` can target only y; `bin` cannot be combined with a facet                       |
| `color`          | `string`, direct, aggregate                                                           | Optional; binds Scatter's color consumer and accepts a compatible categorical or continuous scale |
| `size`           | `string`, direct, aggregate, derived (`normalize`, custom transform)                  | Optional; output must be continuous, and named scales currently accept only `sqrt`                |
| `opacity`        | `string`, direct, aggregate, derived (`normalize`, custom transform)                  | Optional; output must be continuous, and named scales currently accept only `linear`              |
| `shape`          | `string`, direct                                                                      | Optional; binds categorical shape and does not accept a named scale                               |
| `row` / `column` | `string`, `IRPlotPartitionDimension`, `Array<IRPlotPartitionDimension>`               | Optional; either dimension creates a facet, and an array expresses ordered facet hierarchy        |
| `facet`          | `IRPlotFacetOptions`                                                                  | Optional; configures `empty`, `header`, `resolve`, and `spacing`; requires `row` or `column`      |

Scatter rejects `series`, `detail`, `order`, `text`, and ordinary slot arrays without a defined consumer. Field types and scale compatibility are handled by the existing Data / Plot contracts and are not expanded here.

### Scatter properties

`ScatterProperties` declares recipe-level constants and does not accept field mappings; use `ScatterEncodings` for data-driven visual changes. `ScatterPropertiesProps` fields are grouped below.

| Fields                                                                                      | Values                                                                                                                                                                           |
| ------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `color`, `textColor`, `fill`, `stroke`, `shape`                                             | Colors, paints, or an extensible shape name                                                                                                                                      |
| `size`, `minimumSize`, `scale`, `rotate`, `dx`, `dy`, `padding`, `margin`, `cornerRadius`   | Finite numbers or the corresponding JSON-safe structures                                                                                                                         |
| `strokeWidth`, `fillOpacity`, `strokeOpacity`, `opacity`, `dashed`, `dotted`, `dashPattern` | Stroke, opacity, and dash constants                                                                                                                                              |
| `zIndex`, `align`, `lineHeight`, `maxTextWidth`, `font`, `label`                            | Drawing order, text, and label configuration                                                                                                                                     |
| `boundary`, `shadow`, `blendMode`                                                           | Boundary, shadow, and blend mode                                                                                                                                                 |
| `domainPadding?`                                                                            | `number` or `{ kind?, default?, x?, y?, left?, right?, top?, bottom? }`; defaults to range padding from the largest final Point radius                                           |
| `autoPadding?`                                                                              | `'max-radius'` \| `'point-aware'`; automatic padding policy; omitted means `max-radius`; `point-aware` solves from individual positions and radii; explicit `domainPadding` wins |

### Scatter marks

`ScatterMark` is Scatter's direct-child mark API. `ScatterMarkProps` is the props type exported by `@retikz/chart-react/point`; the component identity is fixed to Scatter, so callers do not provide `kind`. Shared Point mark nested fields are not repeated here.

| `ScatterMarkProps` property | Type                             | Scatter-specific behavior                                                                                                                                               |
| --------------------------- | -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `override?`                 | `boolean`                        | When `true`, replaces the implicit primary `scatter` mark in place; if no target exists, it appends and reports `CHART_MARK_OVERRIDE_TARGET_NOT_FOUND` through `onWarn` |
| `encodings?`                | `ScatterMarkProps['encodings']`  | Overrides inherited point field mappings from the current Scatter recipe; available fields follow the shared Point mark encoding contract                               |
| `properties?`               | `ScatterMarkProps['properties']` | Overrides inherited point styling from the current Scatter recipe; available fields follow the shared Point properties contract                                         |
