A connected scatter chart joins observations in an explicit order. Both axes can be measurements while time controls only the order. It reveals how two indicators evolve together and how trajectories differ between groups; its lines connect observations rather than fit trends.

## Using this topic

After [installation and first rendering](/viz/chart/get-start), choose one of the four equivalent inputs below. They share data and configuration.

## Basic usage

### Connected scatter encodings

Encodings determine observation positions, connection order, and trajectory groups.

<DocTabs defaultValue="react-jsx">
<DocTab value="react-jsx" label="React + JSX">

```tsx
<ConnectedScatterEncodings x="urbanization" y="lifeExpectancy" order="year" series="country" />
```

</DocTab>
<DocTab value="vanilla-api" label="Vanilla API">

```ts
encodings: {
  x: 'urbanization',
  y: 'lifeExpectancy',
  order: 'year',
  series: 'country',
},
```

</DocTab>
<DocTab value="direct-ir" label="IR">

```ts
recipe: {
  encodings: {
    x: 'urbanization',
    y: 'lifeExpectancy',
    order: 'year',
    series: 'country',
  },
},
```

</DocTab>
</DocTabs>

Each point is a country-year observation of urbanization and life expectancy. Six countries are sampled every five years from 1990 to 2020. Time is not on the x-axis, so connection order needs its own field.

- `x / y`: Bind urbanization and lifeExpectancy.
- `order`: Bind year to connect observations chronologically.
- `series`: Bind country to prevent connections between countries.

Follow each country's trajectory to read joint change. Time is represented by connection order, not the x-axis.

### Connected scatter properties

Properties style observations and paths separately and control how gaps are displayed.

<DocTabs defaultValue="react-jsx">
<DocTab value="react-jsx" label="React + JSX">

```tsx
<ConnectedScatterProperties
  colorMode="series"
  point={{ size: 4, opacity: 1 }}
  path={{ curve: 'linear', connectNulls: false, opacity: { stroke: 1 }, strokeWidth: 2 }}
/>
```

</DocTab>
<DocTab value="vanilla-api" label="Vanilla API">

```ts
properties: {
  colorMode: 'series',
  point: { size: 4, opacity: 1 },
  path: { curve: 'linear', connectNulls: false, opacity: { stroke: 1 }, strokeWidth: 2 },
},
```

</DocTab>
<DocTab value="direct-ir" label="IR">

```ts
recipe: {
  properties: {
    colorMode: 'series',
    point: { size: 4, opacity: 1 },
    path: { curve: 'linear', connectNulls: false, opacity: { stroke: 1 }, strokeWidth: 2 },
  },
},
```

</DocTab>
</DocTabs>

Dense trajectories contain both observations and connecting lines. Configure those layers separately while retaining their positions and order to emphasize either observations or the overall path.

- `point.size`: Adjust observation radius.
- `path.strokeWidth`: Adjust path width.
- `path.connectNulls`: Choose whether missing observations split or bridge the path.
- `path.curve`: Choose linear, stepped, or smooth connections; the default is `linear`. The “Connection curve” control changes only the path, preserving point positions and connection order. `basis` need not pass through intermediate observations. Monotone X/Y interpolation suits data monotonic along that axis and falls back to linear connections in polar coordinates, as in Plot.

South Africa 2005 is intentionally missing in this example. Bridging changes the line only; it does not create an observation.

`colorMode="mark"` gives each series point and path adjacent palette colors, with a matching two-color legend. The default `series` keeps their colors shared. `muted` uses the same series colors with 60% path opacity and unchanged points. An explicit `path.opacity.stroke` takes precedence.

### Connected scatter marks

Each mark contains both paths and observations; append and replace operations affect the complete group.

<DocTabs defaultValue="react-jsx">
<DocTab value="react-jsx" label="React + JSX">

```tsx
<ConnectedScatterMark
  override
  properties={{
    point: { opacity: { fill: 0.1 }, strokeWidth: 2 },
    path: { dashPattern: [6, 4] },
  }}
/>
```

</DocTab>
<DocTab value="vanilla-api" label="Vanilla API">

```ts
marks: [
  {
    kind: 'connected-scatter',
    override: true,
    properties: {
      point: { opacity: { fill: 0.1 }, strokeWidth: 2 },
      path: { dashPattern: [6, 4] },
    },
  },
],
```

</DocTab>
<DocTab value="direct-ir" label="IR">

```ts
recipe: {
  marks: [
    {
      kind: 'connected-scatter',
      override: true,
      properties: {
        point: { opacity: { fill: 0.1 }, strokeWidth: 2 },
        path: { dashPattern: [6, 4] },
      },
    },
  ],
},
```

</DocTab>
</DocTabs>

Outlined points and dashed paths replace the default trajectory appearance. Each country remains a complete path-and-observation group rather than a replaced line with an unrelated point layer.

- `override`: Set true to replace the complete group.
- `properties.point`: Reduce fill opacity and strengthen outlines.
- `properties.path`: Use dashPattern for the path.

Each group draws the path before its points so the line does not cover observations. The layers share a series color or default color unless `point.color`, `point.fill`, or `path.stroke` overrides it. Omitted member properties retain their recipe values. Use Plot when a path must be manipulated independently.

## Extended usage

### Missing-value connections

Country trajectories often contain missing years. Preserve series and chronological order before deciding whether to bridge gaps, so a data gap is not mistaken for no change.

Groups below are properties inside IR `recipe`; React and Vanilla use the corresponding inputs described above.

| Group        | Property                        | Type                     | Description                                                                |
| ------------ | ------------------------------- | ------------------------ | -------------------------------------------------------------------------- |
| `encodings`  | `x / y / order`                 | field mappings           | Indicator positions and year order                                         |
|              | `series`                        | string                   | country keeps paths independent                                            |
| `properties` | `path.connectNulls`             | boolean or stroke object | `true` or `{}` enables dashed bridges; object fields style only the bridge |
|              | `path.connectNulls.dashPattern` | `Array<number>`          | Bridge dash pattern, default [6, 4]; normal segments keep their style      |

Normal observations stay connected by solid lines; only missing spans use dashed bridges. The controls adjust bridge width, opacity, and dash length independently. Disabling connections leaves gaps. Consecutive missing rows form one gap; leading and trailing gaps are not extrapolated, and bridging creates no observations.

Compare South Africa with the segmented path in basic usage. Bridging is a display decision, not interpolation or imputation.

## Errors and limitations

- order is required; input row order is not a substitute. series belongs to the recipe only.
- Paths remain open; mark replacement targets the complete group, not a single member.
- Invalid observations emit no Point; connectNulls neither imputes nor cleans data.

In React, supplying the same configuration field through both the root `recipe` and a child component raises an error.

`point-aware` supports built-in continuous and categorical position scales in Cartesian2D and Polar2D coordinates. Fully explicit `domainPadding` bypasses point-aware solving. See [shared point-chart configuration](/viz/chart/points#shared-configuration) for properties and precedence.

### Chart construction

Chart resolves one connected-scatter mark to an open Plot Path and a Plot Point mark. The table lists conversions specific to this point-and-path group.

| Group      | `@retikz/chart`          | `@retikz/plot`                        | Description                                                  |
| ---------- | ------------------------ | ------------------------------------- | ------------------------------------------------------------ |
| Encodings  | `order`, `series`        | `order`, `series`                     | Writes order and group fields to Path to connect each series |
| Properties | `point`, `path`          | `Point` appearance, `Path` appearance | Applies member appearance; passes `connectNulls` to Path     |
|            | `colorMode`              | `color`, `stroke`, `opacity.stroke`   | Shares series colors, separates them, or mutes the path      |
| Mark       | `IRConnectedScatterMark` | `IRPlotPathMark`, `IRPlotPointMark`   | Produces an open Path and Point group from one Chart mark    |
