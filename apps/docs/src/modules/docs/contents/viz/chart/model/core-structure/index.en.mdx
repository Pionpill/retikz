In Chart Source, configuration for the drawing structure is concentrated in `recipe` and the optional `plotExtension`: the recipe selects the chart type and defines its data channels, properties, and Chart marks, while the extension adds lower-level Plot content and should rarely be needed for ordinary charts.

<ComponentAlert
  type="tip"
  title="Why keep plotExtension?"
  description="Chart is still in development. plotExtension can temporarily expose capabilities that Plot already supports but recipe does not yet encapsulate; common needs should move into recipe encodings, properties, and marks. The `data`, `coordinate`, `presentation`, `layout`, `background`, and `chartDefaults` fields in [General Structure](/viz/chart/model/general-structure) provide data, coordinates, and chart-wide presentation. Changing them does not switch the chartType or the recipe's mark composition, but it can still change plotted positions, coordinate behavior, and the final appearance.

Root `type` identifies a chart family for grouping and provider routing. Chart types in one family can reuse local logic, such as automatic edge padding for Point charts, but `type` does not determine how a specific chart is resolved. `recipe.chartType` determines two things:

- Functionally, which chart is drawn, such as scatter or bubble within the `point` family
- In implementation, which exact schema and recipe resolver apply: what `encodings` and `properties` accept, how `marks` inherit or override those values, and how default marks and scales are generated

```ts
recipe: {
  chartType: 'scatter',
  encodings: { x: 'weight', y: 'efficiency', color: 'group' },
  properties: { opacity: 0.82 },
  marks: [{ kind: 'scatter', override: true, properties: { size: 5 } }],
}
```

## Data channels: encodings

`recipe.encodings` binds fields from `data` to graphical channels. In this Scatter example, `weight`, `efficiency`, and `group` are data fields, while `x`, `y`, and `color` are channels. The category value bound to `color` passes through a scale before becoming a rendered color.

<ComponentPreview files="chart-encodings-map" hideCode type="illustration" size="sm" />

```ts
encodings: { x: 'weight', y: 'efficiency', color: 'group' }
```

Each `chartType` exposes its own channels. Beyond a direct field name, a channel can describe field mapping, transforms, scales, and related behavior; resolution produces the fields, transformations, and scales used by Plot. Field type, format, and categorical order belong to `data.model`, rather than a parallel Chart field model. If a field encoding and a constant property target the same channel, the encoding takes precedence. A recipe consumes only the channels its type declares; a configuration consumed by neither the recipe nor the authored overlay marks fails instead of being silently ignored.

## Chart properties: properties

`recipe.properties` sets constants and behavior specific to a chart type. `recipe.chartType` selects an exact schema, so the available properties vary: Strip uses `jitter` to spread points, while Regression uses `method` to choose a fitting method. Point charts also share common properties such as `opacity` and `size`.

<ComponentPreview files="chart-properties-map" hideCode type="illustration" size="lg" />

The type's resolver turns these properties into drawing details without requiring lower-level Plot configuration. Use `properties` for fixed appearance or type behavior; use the corresponding `encodings` channel when color, size, or another value should vary with each data row.

## Overlay marks: marks

`recipe.marks` adds Chart marks, in authored order, to the defaults generated by `chartType`. The figure uses Scatter points plus an overlaid Line to explain the composition: both use `x` and `y`, while the points use `color`, `size`, and `opacity`, and the line sets its own `stroke` and `strokeWidth`.

<ComponentPreview files="chart-overlay-marks" hideCode type="illustration" size="xxl" />

The Line is a conceptual overlay, not a currently accepted Scatter Chart mark: Scatter `recipe.marks` accepts only Scatter today. To draw points and a line with the current API, use [Connected Scatter](/viz/chart/points/connected-scatter).

Each mark has `{ kind, override?, encodings?, properties? }`. The `chartType` determines allowed kinds and which recipe channels and properties each kind may inherit. Values set on the mark take precedence over inherited values: an explicit property can replace an inherited encoding of the same name; if that mark explicitly sets both an encoding and a property for one slot, the encoding wins. Inheritance applies only when the mark is actually present in `marks`.

The default `override: false` appends a mark. Setting it to `true` replaces the entire built-in semantic group of the same kind in place, even if that group contains multiple Plot marks. If there is no group of that kind, the mark is still appended and `onWarn` reports the missing replacement target. Chart marks differ from independent `plotExtension.marks`, which do not inherit recipe channels or properties.

## Plot extension

`plotExtension` is a root Chart Source field, but its role is easiest to understand beside the recipe. The recipe generates the Plot content required by its chart type; authors can then provide an explicit lower-level Plot fragment through `plotExtension`. The generated Plot result is never written back into this field.

It can provide Plot `transform`, `scales`, `composition`, `marks`, `guides`, `plotDefaults`, `plotRules`, and `meta`. In particular, `plotExtension.marks` are independent Plot marks: they do not inherit `recipe.encodings` or `recipe.properties`, though they consume the same final encoding data view as Chart marks. Root `coordinate` cannot coexist with `plotExtension.composition`.

Use recipe encodings, properties, and marks for common chart configuration. When full control over the lower-level graphics grammar is needed, use Plot directly.
