title: Authoring & Resolution
description: Understand how React, Vanilla, and JSON produce exact Chart Source that a chartType recipe resolves consistently.
---

Chart separates convenient authoring from stable execution. React and Vanilla normalize their input forms into exact Chart Source. The parser first reads the family, then selects the unique recipe from `recipe.chartType`.

## One shared pipeline

<ComponentPreview files="chart-authoring-pipeline" hideCode size="sm" />

| Stage             | Owner                     | Result                                                        |
| ----------------- | ------------------------- | ------------------------------------------------------------- |
| React props / JSX | `@retikz/chart-react`     | Converts to Vanilla Input                                     |
| Plain input       | `@retikz/chart-vanilla`   | `normalizeXxxChart` produces exact Source                     |
| JSON              | Concrete chartType schema | Application selects a strict schema by family and `chartType` |
| recipe            | Active Chart provider     | Produces shared parts and the built-in mark                   |
| resolve           | Chart resolver            | Merges marks, Plot fragments, and Theme inputs                |

JSON is an alternate input, not a schema bypass. The application selects the concrete schema from `type` and `recipe.chartType`, and the active provider confirms that the recipe belongs to the root family. Unknown families, recipes, fields, and incompatible marks fail loudly. The parsed Source preserves author intent; recipe-generated coordinates, guides, and Plot marks only exist in later resolution stages.

## Three packages, one stage each

The root `@retikz/chart` entry exposes shared Chart Source schemas, constants, and the Theme contract. Each concrete chartType subpath exposes its exact schema and provider contribution. Recipe / mark Definitions and resolvers are package-internal implementation contracts, not third-party extension entry points. Plain types such as `InputScatterChart`, normalizers, and factory functions belong to `@retikz/chart-vanilla`. Typed React Charts interpret presentation markers and mark components before reusing the same normalizers, so React and Vanilla do not maintain parallel Source assembly rules. Dynamic family / chartType routing belongs to the application layer.

| Entry          | Root `type` | `recipe.chartType` | Import                              |
| -------------- | ----------- | ------------------ | ----------------------------------- |
| `ScatterChart` | `point`     | `scatter`          | `@retikz/chart-react/point/scatter` |

The Vanilla factory `createScatterChart` comes from `@retikz/chart-vanilla/point/scatter`. The concrete subpath loads only its chartType; the family root remains an explicit aggregate entry. It returns an authoring result that preserves runtime theme data while reusing the shared Chart adapter and resolution pipeline for rendering.
