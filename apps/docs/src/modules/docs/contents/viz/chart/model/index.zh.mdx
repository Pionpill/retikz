title: 图形模型

Plot 是强大的底层图形语法：它描述数据如何通过图元、通道、比例尺、坐标和辅助元素被绘制，但也意味着使用者需要自己组合这些语法部件。如果目标是先表达一种完整图形，直接从 Plot 开始往往需要理解较多底层配置。

Chart 是建立在 Plot 之上的官方上层图形封装，解决的是“我想先使用一种图形类型”的问题：

- **基于 `type` 的图形类型封装**：`ScatterChart`、`BubbleChart` 等类型直接表达用户想画的图形；Plot 则负责底层的图形语法，两者的抽象层级不同。
- **更少的配置**：每个 `type` 都带有自己的默认解析逻辑，会根据类型配置补齐通常需要的主图元、比例尺和坐标等语义，使用者不必从零组装完整 Plot。
- **官方提供的上层能力**：这些类型由 Retikz 官方 schema、recipe 和解析路径维护，既提供易用入口，也会统一收敛到基础 Chart 供后续编译。

因此，基于 `type` 的 Chart 封装更容易上手，也更容易让 LLM 理解和生成。等你需要更复杂的图形时，仍可以以某个 Chart 类型为基础，通过它的 `plot` 成员补充轴、图例、附加图元、变换等 Plot 能力；这要求你进一步了解 Plot，但不必放弃 Chart 已经提供的类型语义和默认解析。

## 解析原理

<ComponentPreview files="chart-model-pipeline" hideCode size="xs" />

这张图可以先按“输入 → 类型规则 → 统一图形 → 输出”来理解。管线中的每一步只解决一个问题，下面先解释它对使用者意味着什么，再补充对应的术语：

1. **React / Vanilla：选择编写入口**
   React 组件和 Vanilla 工厂是两种面向使用者的编写方式。它们负责接收你的数据、类型配置和展示选项，不要求你直接操作后面的编译阶段。
2. **Exact Source IR：保存一种类型的完整描述**
   Source IR 是图形的源描述，记录选定的 `type` 以及该类型需要的配置、`plot` 和整图展示内容。`Exact` 表示它使用当前类型自己的精确结构，而不是把所有 Chart 类型混成一个宽泛对象。
3. **BoundChart：接入类型默认规则**
   recipe 会读取这份源描述，并接入该类型自己的默认解析逻辑，例如补齐主图元、比例尺和坐标。这个中间结果叫 BoundChart，通常由系统产生，使用者不需要手动编写。
4. **IRBaseChart：收敛为统一的基础图形**
   `resolveChart` 会把带有类型规则的中间结果解析成 `IRBaseChart`。无论最初是 Scatter、Bubble 还是其它 Chart 类型，后续编译都可以使用同一种基础图形结构。
5. **Surface + Plot：交给编译与绘制阶段**
   Core 消费统一的 `IRBaseChart`，生成承载图形的 Surface，并继续交给 Plot 完成数据到图元、坐标和辅助元素的绘制。因此 Core 不需要分别认识每一种上层 Chart 类型。

## 职责一览

| 主题         | 负责什么                                           | 何时查阅                          |
| ------------ | -------------------------------------------------- | --------------------------------- |
| 结构与类型   | 解释 `namespace`、精确 `type` 及字段 owner         | 读写 JSON、选择 schema 或找边界   |
| 编写与解析   | 串起 React、Vanilla、schema、recipe 与 `resolve`   | 排查入口差异或理解 canonical 过程 |
| 整图展示     | 组织标题、副标题、Plot、注记与来源                 | 控制叙事顺序、文本样式或布局      |
| 与 Plot 协作 | 区分图形外壳和绘图语法，并说明主题 provider 的配合 | 添加轴、图例、图元或运行时样式    |

四个主题共享同一个边界：Chart 决定“这是什么图形、怎样形成完整整图”，Plot 决定“数据怎样通过图形语法被绘制”。类型目录和 `/point` 入口只组织源码与导入面，不新增运行时层级。
