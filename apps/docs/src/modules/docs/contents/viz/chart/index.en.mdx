---
title: Chart
description: Chart organizes concrete graphic types on top of Plot and adds chart-wide title, source, canvas, and theme capabilities.
---

Chart represents a complete graphic: the root `type` is a discoverable family, while nested `recipe.chartType` selects the concrete recipe. Chart also adds title, source, canvas, Theme behavior, and a high-frequency coordinate choice. Plot still owns coordinate operations, Definitions, registry lookup, resolution, and lowering. Chart does not introduce a second graphics grammar.

| Layer | Owns                                                                                | Does not own                                       |
| ----- | ----------------------------------------------------------------------------------- | -------------------------------------------------- |
| Chart | family, chartType, Chart Source, presentation, canvas, Theme, and coordinate choice | A replacement for Plot marks or coordinate grammar |
| Plot  | data, transforms, marks, channels, scales, coordinate contracts, axes, and legends  | Product semantics such as Scatter types            |

## A minimal Point Chart

Concrete graphics use a typed Chart root. Root props follow the Source `data`, `layout`, `coordinate`, `presentation`, `recipe`, and `plotExtension` groups, while component identity supplies `type: 'point'` and `recipe.chartType: 'scatter'`.

```tsx
import { ScatterChart } from '@retikz/chart-react/point';

const rows = [
  { x: 1, y: 2 },
  { x: 2, y: 3 },
  { x: 3, y: 5 },
];

<ScatterChart
  rows={rows}
  data={{ reference: 'chart.data' }}
  layout={{ width: 640, height: 360 }}
  presentation={{ title: 'Relationship between two variables', source: 'Example data' }}
  recipe={{ encodings: { x: 'x', y: 'y' }, properties: { size: 8 } }}
/>;
```

## Shared root prop and declaration API

| Entry                                                        | Cardinality    | Main props                                                                               | Responsibility                                                                                                          |
| ------------------------------------------------------------ | -------------- | ---------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| Concrete `XxxChart` root                                     | 1              | `rows?`, `data?`, `layout?`, `coordinate?`, `presentation?`, `recipe?`, `plotExtension?` | Complete IR-like entry; identity supplies family and chartType, while `rows` remains runtime-only                       |
| `ChartData`                                                  | At most 1      | `data`, `reference?`, `model?`                                                           | JSX sugar for the root data slot; mutually exclusive with root `rows` / `data`                                          |
| `ChartLayout`                                                | At most 1      | `width?`, `height?`, `layout?`                                                           | Declares standalone host dimensions and the Source border-box; an explicit `layout` is not field-merged with dimensions |
| `ChartCoordinate`                                            | At most 1      | `coordinate`                                                                             | Declarative alternative to the root prop; writes the same Source root `coordinate`                                      |
| `ChartExtension`                                             | At most 1      | Plot extension props, `children?`                                                        | Isolates Plot-owned axes, legends, transforms, and independent Plot marks                                               |
| `ChartTitle` / `ChartSubtitle` / `ChartNote` / `ChartSource` | At most 1 each | `children`                                                                               | Writes fixed presentation slots; arrays and Fragments are transparent grouping only                                     |
| `XxxEncodings` / `XxxProperties` / `XxxMark`                 | Per slot       | Exact props for the chartType                                                            | Maps to `recipe.encodings`, `recipe.properties`, and ordered `recipe.marks`                                             |

Plot declarations cannot be direct children of a concrete Chart. `ChartExtension` props and children enter the same Plot normalizer; prop transforms precede child transforms, while Plot reports duplicate sources for single-value slots.

Root props and declarations can mix across owner slots, such as root `recipe.encodings` with a child `XxxProperties`. The same slot has no override order: root `layout` plus `ChartLayout`, or root `recipe.properties` plus `XxxProperties`, fails loudly. An explicit `recipe.marks: []` still counts as an authored slot.

Use a coordinate name when no configuration is needed, and a full object otherwise. Vanilla normalization converts a string to `{ type }`; JSON Source always stores the object form:

```tsx
<ScatterChart coordinate="polar2D">{/* declarations */}</ScatterChart>
<BubbleChart coordinate={{ type: 'polar2D', innerRadius: 0.25, startAngle: -90 }}>
  {/* declarations */}
</BubbleChart>
```

You can instead place `<ChartCoordinate coordinate="polar2D" />` among the children to express the same slot. The root `coordinate` prop and `ChartCoordinate` cannot appear together. Either form can combine with recipe facet encodings and becomes the coordinate template for each panel, but neither can coexist with a Plot composition in `ChartExtension`, because both declare the spatial root.

A concrete Chart root traverses only arrays and transparent Fragments, never DOM or custom React components; wrapped declarations fail loudly. `ChartExtension` children accept only Plot declarations, arrays, transparent Fragments, and empty slots. Ordinary iterables such as `Set` or generators are rejected, as are Chart declarations inside the extension and Plot declarations at the Chart root.

Declarations are headless JSX sugar for the same owner slots, not a second grammar. `children` may be omitted for root-only authoring. Root-only, declaration-only, and cross-slot hybrid authoring all converge on one Vanilla Input and the same Source.

## React hosting and embedding

Rendering a concrete Chart directly creates exactly one `Layout` / Scene host. Without an authored `layout`, Cartesian coordinates default to `800 × 500` and Polar coordinates default to `400 × 500`. Root `layout.width` / `height` configure both Source and that implicit host; when only one dimension is provided, the other keeps the default for the active coordinate system. `ChartLayout.width` / `height` provide equivalent JSX sugar and mirror into Source when no explicit `layout` exists.

Inside an existing `<Layout>`, Chart contributes only its Chart-to-Plot-to-Core Scope/composite, inherits the outer effective Theme, and creates no second SVG. Root `layout` remains the Chart Source border-box. Embedded `ChartLayout` also accepts only `layout`; declaring `width` or `height`, including explicit `undefined`, fails loudly. Configure CSS, renderer/runtime, animation, and compile callbacks on the outer `<Layout>`.

When JSON Source already matches an exact schema, the application selects the concrete entry from `type` and `recipe.chartType`; Chart does not provide a generic `<Chart source={...}>` that dynamically loads every family. Vanilla and JSON Source APIs are unchanged by the React declaration structure.
