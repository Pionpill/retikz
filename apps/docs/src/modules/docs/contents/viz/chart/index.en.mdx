---
title: Chart
description: Chart organizes concrete graphic types on top of Plot and adds chart-wide title, source, canvas, and theme capabilities.
---

Chart represents a complete graphic: the root `type` is a discoverable family, while nested `recipe.chartType` selects the concrete recipe. Chart also adds title, source, canvas, and Theme behavior. Plot continues to own data, marks, channels, scales, coordinates, guides, and transforms. Chart does not introduce a second graphics grammar.

| Layer | Owns                                                                      | Does not own                                      |
| ----- | ------------------------------------------------------------------------- | ------------------------------------------------- |
| Chart | family, chartType, Chart Source, presentation, canvas, and Theme          | A replacement for Plot marks and encoding grammar |
| Plot  | data, transforms, marks, channels, scales, coordinates, axes, and legends | Product semantics such as Scatter types           |

## A minimal Point Chart

Concrete graphics use a typed Chart root and fill public and private slots through owner-scoped declarations. This `ScatterChart` produces Source with `type: 'point'` and `recipe.chartType: 'scatter'`.

```tsx
import { ChartData, ChartLayout, ChartSource, ChartTitle } from '@retikz/chart-react';
import { ScatterChart, ScatterEncodings, ScatterProperties } from '@retikz/chart-react/point/scatter';

const rows = [
  { x: 1, y: 2 },
  { x: 2, y: 3 },
  { x: 3, y: 5 },
];

<ScatterChart>
  <ChartData data={rows} />
  <ChartLayout width={640} height={360} />
  <ScatterEncodings x="x" y="y" />
  <ScatterProperties size={8} />
  <ChartTitle>Relationship between two variables</ChartTitle>
  <ChartSource>Example data</ChartSource>
</ScatterChart>;
```

## Shared declaration API

| Declaration                                                  | Cardinality    | Main props                        | Responsibility                                                                                                          |
| ------------------------------------------------------------ | -------------- | --------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `ChartData`                                                  | Exactly 1      | `data`, `reference?`, `model?`    | Declares runtime rows, the Source data reference, and field model; actual rows do not enter JSON Source                 |
| `ChartLayout`                                                | At most 1      | `width?`, `height?`, `layout?`    | Declares standalone host dimensions and the Source border-box; an explicit `layout` is not field-merged with dimensions |
| `ChartExtension`                                             | At most 1      | Plot extension props, `children?` | Isolates Plot-owned axes, legends, transforms, and independent Plot marks                                               |
| `ChartTitle` / `ChartSubtitle` / `ChartNote` / `ChartSource` | At most 1 each | `children`                        | Writes fixed presentation slots; arrays and Fragments are transparent grouping only                                     |

Plot declarations cannot be direct children of a concrete Chart. `ChartExtension` props and children enter the same Plot normalizer; prop transforms precede child transforms, while Plot reports duplicate sources for single-value slots.

A concrete Chart root traverses only arrays and transparent Fragments, never DOM or custom React components; wrapped declarations fail loudly. `ChartExtension` children accept only Plot declarations, arrays, transparent Fragments, and empty slots. Ordinary iterables such as `Set` or generators are rejected, as are Chart declarations inside the extension and Plot declarations at the Chart root.

The concrete Chart root keeps only wiring shared by all chart types: optional `id`, `theme`, `panel`, `themeDefinitions`, and `lowerOptions`, plus required `children`. Data, layout, recipe, and Plot extension values are no longer root props.

## React hosting and embedding

Rendering a concrete Chart directly creates exactly one `Layout` / Scene host. `ChartLayout.width` and `height` must be finite positive numbers and configure that host. Without an explicit `layout`, declared dimensions also mirror into Source. An explicit `layout` stays independent and is not merged with host dimensions.

Inside an existing `<Layout>`, Chart contributes only its Chart-to-Plot-to-Core Scope/composite, inherits the outer effective Theme, and creates no second SVG. Embedded `ChartLayout` accepts only `layout`; declaring `width` or `height`, including explicit `undefined`, fails loudly. Configure CSS, renderer/runtime, animation, and compile callbacks on the outer `<Layout>`.

When JSON Source already matches an exact schema, the application selects the concrete entry from `type` and `recipe.chartType`; Chart does not provide a generic `<Chart source={...}>` that dynamically loads every family. Vanilla and JSON Source APIs are unchanged by the React declaration structure.
