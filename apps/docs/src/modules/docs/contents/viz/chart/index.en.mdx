---
title: Chart
description: Chart organizes concrete graphic types on top of Plot and adds chart-wide title, source, canvas, and theme capabilities.
---

Chart represents a complete graphic: the root `type` is a discoverable family, while nested `recipe.chartType` selects the concrete recipe. Chart also adds title, source, canvas, and Theme behavior. Plot continues to own data, marks, channels, scales, coordinates, guides, and transforms. Chart does not introduce a second graphics grammar.

| Layer | Owns                                                                      | Does not own                                      |
| ----- | ------------------------------------------------------------------------- | ------------------------------------------------- |
| Chart | family, chartType, Chart Source, presentation, canvas, and Theme          | A replacement for Plot marks and encoding grammar |
| Plot  | data, transforms, marks, channels, scales, coordinates, axes, and legends | Product semantics such as Scatter types           |

## A minimal Point Chart

Concrete graphics use typed Chart entries. This `ScatterChart` produces Source with `type: 'point'` and `recipe.chartType: 'scatter'`; `encodings` bind fields and `properties` contain constants.

```tsx
import { ScatterChart } from '@retikz/chart-react/point/scatter';

const rows = [
  { x: 1, y: 2 },
  { x: 2, y: 3 },
  { x: 3, y: 5 },
];

<ScatterChart
  data={rows}
  encodings={{ x: 'x', y: 'y' }}
  properties={{ size: 8 }}
  title="Relationship between two variables"
  source="Example data"
  layout={{ width: 640, height: 360 }}
/>;
```

When you already have JSON Source that matches an exact schema, the application
should select the concrete entry from `type` and `recipe.chartType`. Chart does
not provide a generic `<Chart source={...}>` component that dynamically loads
every family. To compose axes, legends, or an independent Plot mark, write a
Source `plotExtension` fragment or use Plot directly.
