Chart Source 的根级字段描述整张图。先识别它属于哪个图形家族，再分别配置数据、展示内容、布局样式和坐标；具体图形类型由 `recipe` 决定。

## 数据变换与运行入口

所有 Chart 根支持 `transform: Array<IRDataTransformDeclaration>` 与 `dataExecution`；每条声明使用 `{ operation, dataExecution? }`。派生 encoding 同样将操作写入 operation，并可指定该阶段的执行配置。阶段顺序为根变换、派生 encoding，再到 recipe / 图元局部变换。执行优先级为声明 > Chart 根 > 执行器默认值 > builtin。

React 六类 Chart 接收 dataBindings、dataTransformExecutor 和 signal；原始 rows 与 dataBindings 互斥，Data Definition/Implementation 通过 lowerOptions 分别注入。独立客户端自动异步准备；嵌入外层 Layout 时开启 runtime.preparation 为 async。

Vanilla 图表工厂接收相同运行时输入。异步 SSR 使用 `renderChartAsync(input, { adapters: [当前图表Adapter], signal })`，返回 Promise 的 `{ svg, compileResult }`；同步 renderChart 与 React SSR 只接受本地同步计算。数据绑定和三模式说明见 [Data 扩展机制](/viz/data/transform/extensions)。

## 图形根结构

下面是一份 Point family 的 Scatter Source。它保存作者输入，不保存解析后生成的 Plot 图元、比例尺或辅助元素。

```ts
{
  namespace: 'chart',
  type: 'point',
  id: 'weight-efficiency',
  data: { reference: 'rows' },
  layout: { width: 640, height: 360 },
  recipe: {
    chartType: 'scatter',
    encodings: { x: 'weight', y: 'efficiency' },
  },
}
```

| 根字段      | 作用                                                              |
| ----------- | ----------------------------------------------------------------- |
| `namespace` | 固定为 `chart`，声明这份 Source 属于 Chart 能力域                 |
| `type`      | 图形家族，例如 `point`；与 `recipe.chartType` 一起选择精确 schema |
| `id`        | 可选的整图标识，用于在更大的绘图内容中识别这张 Chart              |

其余根字段按职责分为 `data`、`presentation`、`layout`、`background`、`chartDefaults` 和 `coordinate`。具体类型的 `recipe` 与底层 `plotExtension` 见[核心结构](/viz/chart/model/core-structure)。

## 数据入口

所有图形类型都从 `data` 指向的共享数据集读取字段，数据值保留在 Source 之外。

| 字段           | 子字段      | 作用                                         |
| -------------- | ----------- | -------------------------------------------- |
| `data`         | `reference` | 必填；引用调用方提供的数据集                 |
|                | `model`     | 可选；声明数据集的字段模型                   |
| `data.model[]` | `name`      | 必填；标识字段名或嵌套字段路径               |
|                | `type`      | 可选；声明字段类型，省略时从数据推断         |
|                | `format`    | 可选；指定字段值的解析格式                   |
|                | `order`     | 可选；指定分类顺序，省略时按数据出现顺序排列 |

`data.model` 声明 Chart 消费的逻辑字段及类型，运行时 `fieldMap` 把逻辑字段对应到数据源的原始字段。下图两份数据分别使用 `x/y` 与 `a/b`，但都向同一个 Chart 提供连续型的 `x/y`。

## 图形展示

根级 `presentation` 用以下四个槽位说明整张图，不包含 Plot 的轴、图例和数据标注。

| 子字段     | 作用                                   |
| ---------- | -------------------------------------- |
| `title`    | 可选；图形主题或主要结论               |
| `subtitle` | 可选；范围、时间、样本或单位等背景信息 |
| `note`     | 可选；读图限制或口径说明               |
| `source`   | 可选；数据来源及影响理解的处理说明     |

每个已提供的槽位都需要 `text`，还可用 `style` 和 `layout` 调整文本。

### 固定槽位与顺序

React 用 `ChartTitle`、`ChartSubtitle`、`ChartNote`、`ChartSource` 提供槽位，Vanilla 和 JSON 直接写 `presentation`。React 标记须是 Chart 的直接子节点，可用 `Fragment` 分组、不可重复；声明顺序不改变固定布局。解析时按 `title → subtitle → plot → note → source` 排列已有内容，未提供的槽位不会生成。下面通过展示开关比较各槽位的显隐，并开启 Inspect 观察布局。

## 布局与样式

`layout` 分配整张 Chart Surface 的外部尺寸，而非 Plot 内部绘图区。未指定尺寸时，笛卡尔坐标系默认使用 `800 × 500`，极坐标系默认使用 `400 × 500`；显式宽高逐字段覆盖默认值。标题、注记等展示文本占据自己的区域，Plot 填满扣除这些区域、内边距和间距后的剩余空间。

| 字段            | 子字段         | 作用                                              |
| --------------- | -------------- | ------------------------------------------------- |
| `layout`        | `width`        | 可选；整图 Surface 的外部宽度                     |
|                 | `height`       | 可选；整图 Surface 的外部高度                     |
|                 | `padding`      | 可选；展示区域与 Plot 内容周围的内边距            |
|                 | `gap`          | 可选；已有展示区域与 Plot 内容之间的间距          |
| `background`    | `fill`         | 提供 `background` 时必填；整图 Surface 的显式填充 |
|                 | `fillOpacity`  | 可选；背景填充的不透明度                          |
| `chartDefaults` | `background`   | 可选；整图背景的默认值，可被显式背景覆盖          |
|                 | `layout`       | 可选；`padding` 与 `gap` 的默认值                 |
|                 | `presentation` | 可选；已有展示槽位的 `style` 与 `layout` 默认值   |

根级 `background` 与 `chartDefaults.background` 都可省略；两者都省略时使用 Chart 主题背景。`chartDefaults.layout` 只接受 `padding`、`gap`，不设置外部宽高；`chartDefaults.presentation` 只为已有槽位设置 `style`、`layout`，不会创建新文本。具体图形类型的视觉属性仍由 `recipe.properties` 控制。

## 坐标配置

根级 `coordinate` 可显式选择 Plot 坐标配置，包含以下子字段；通常由具体 chartType 提供适合该图形的默认坐标。

| 子字段          | 作用                                                         |
| --------------- | ------------------------------------------------------------ |
| `type`          | 提供 `coordinate` 时必填；选择内置或已注册的自定义坐标       |
| `x`             | 可选；直角坐标的位置比例尺名称                               |
| `y`             | 可选；二维直角坐标的纵向比例尺名称                           |
| `angle`         | 可选；极坐标的角向比例尺名称                                 |
| `radius`        | 可选；二维极坐标的径向比例尺名称，或一维极坐标的圆周半径比例 |
| `startAngle`    | 可选；极坐标的起始角度                                       |
| `endAngle`      | 可选；极坐标的结束角度                                       |
| `innerRadius`   | 可选；二维极坐标的内半径比例                                 |
| `orientation`   | 可选；一维直角坐标的水平或垂直方向                           |
| `interpolation` | 可选；二维极坐标的连接插值方式                               |

内置 `type` 包括 `cartesian2D`、`polar2D`、`cartesian1D` 和 `polar1D`。除 `type` 外，可用的子字段取决于坐标类型；自定义坐标的字段由其 Definition 决定。`coordinate` 不代替 `recipe.encodings` 的字段映射。

`coordinate` 可以与 facet encoding 组合，但不能与 `plotExtension.composition` 同时写入。需要配置 Plot composition 时，参见[核心结构的 Plot 扩展](/viz/chart/model/core-structure)。
