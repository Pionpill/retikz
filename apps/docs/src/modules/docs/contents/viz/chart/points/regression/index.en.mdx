A regression chart overlays a fitted trend on original observations to summarize the relationship between two continuous variables. Each row supplies a pair; series can fit groups separately. A trend need not pass through every observation and does not establish causation or validated predictive power.

## Errors and limitations

See [Fitting methods](#fitting-methods) for equations, sample counts and domain requirements.

- Insufficient samples, rank deficiency or nonfinite predictions in any group fail the chart rather than silently reducing it to scatter.
- Nonfinite x/y pairs are filtered first; logarithmic, exponential and power methods still require valid positive domains.
- Custom methods must be injected into the current runtime registry, with no duplicate built-in or custom names.
- The default interpolating curve may overshoot between samples. It improves visual continuity without guaranteeing exact agreement with the fitted function between samples.

In React, supplying the same configuration field through both the root `recipe` and a child component raises an error.

`point-aware` supports built-in continuous and categorical position scales in Cartesian2D and Polar2D coordinates. Fully explicit `domainPadding` bypasses point-aware solving. See [shared point-chart configuration](/viz/chart/points#shared-configuration) for properties and precedence.

### Fitting methods

Regression fits trends through Plot’s `smooth` transform, independently for each facet and `series` group. It filters nonfinite x/y pairs, then fits the remaining $N$ observations $(x_i,y_i)$. The primary `method` and each `extraMethods` entry follow this process.

| Name                 | Method        | Equation                      | Valid sample and domain requirements                                      | Fitting time complexity |
| -------------------- | ------------- | ----------------------------- | ------------------------------------------------------------------------- | ----------------------- |
| Linear               | `linear`      | $\hat y=a+bx$                 | At least two pairs and two distinct x values                              | $O(N)$                  |
| Quadratic polynomial | `quadratic`   | $\hat y=a+bx+cx^2$            | At least three pairs, three distinct x values and full rank               | $O(N)$                  |
| Polynomial           | `polynomial`  | $\hat y=\sum_{k=0}^{n}c_kx^k$ | At least n + 1 pairs, n + 1 distinct x values and full rank               | $O(Nn^2+n^3)$           |
| Logarithmic          | `logarithmic` | $\hat y=a+b\ln x$             | At least two pairs with distinct x; positive x and prediction interval    | $O(N)$                  |
| Exponential          | `exponential` | $\hat y=ae^{bx}$              | At least two pairs with distinct x; positive y                            | $O(N)$                  |
| Power                | `power`       | $\hat y=ax^b$                 | At least two pairs with distinct x; positive x, y and prediction interval | $O(N)$                  |

Here $\hat y$ denotes a prediction. For `polynomial`, `order` sets the degree $n$: an integer from 2 to 6, defaulting to 3.

Complexities describe parameter fitting for one group and one model in the current implementation. $N$ is the valid sample count after filtering and $n$ is the polynomial degree. They assume fixed-precision arithmetic and exclude grouping, prediction sampling and rendering. Costs add across groups and fitting methods.

#### Linear fitting

`linear` finds the line that minimizes the sum of squared vertical residuals:

$$
\min_{a,b}\sum_{i=1}^{N}\left(y_i-a-bx_i\right)^2
$$

After computing the means $\bar x$ and $\bar y$, the slope and intercept are:

$$
b=\frac{\sum_{i=1}^{N}(x_i-\bar x)(y_i-\bar y)}{\sum_{i=1}^{N}(x_i-\bar x)^2},\qquad a=\bar y-b\bar x
$$

If all x values are identical, the denominator is zero and the slope cannot be determined, so fitting fails.

**Time complexity:** Means, variance and covariance take a constant number of passes over the samples, so parameter fitting is $O(N)$. Once fitted, a single prediction is $O(1)$.

#### Quadratic and polynomial fitting

`quadratic` fixes the degree at two; `polynomial` uses the specified degree. Both minimize squared residuals in the original y space. To reduce numerical problems from higher powers, the implementation first centers and scales x into $[-1,1]$:

$$
m=\frac{x_{\min}+x_{\max}}{2},\qquad s=\max_i\lvert x_i-m\rvert,\qquad z_i=\frac{x_i-m}{s}
$$

Row i of the design matrix $V$ contains $1,z_i,z_i^2,\ldots,z_i^n$. The coefficient vector $\boldsymbol\beta$ in these normalized coordinates solves:

$$
\min_{\boldsymbol\beta}\sum_{i=1}^{N}\left(y_i-\sum_{k=0}^{n}\beta_kz_i^k\right)^2,
\qquad
(V^{\mathsf T}V)\boldsymbol\beta=V^{\mathsf T}\mathbf y
$$

The implementation solves the normal equations with scaled pivot selection, Gaussian elimination and back substitution, then evaluates predictions with Horner’s method. Prediction inputs are also converted from x to z; normalization does not change the polynomial degree. Insufficient samples, too few distinct x values or numerical rank deficiency raise an error instead of automatically reducing the degree.

**Time complexity:** Accumulating the normal-equation matrix takes $O(Nn^2)$ and elimination takes $O(n^3)$, giving $O(Nn^2+n^3)$ overall. Horner evaluation takes $O(n)$ per prediction. Quadratic fitting fixes the degree at two, so fitting is $O(N)$ and each prediction is $O(1)$. Polynomial degrees are currently restricted to 2–6; at any fixed degree, fitting also grows linearly with sample count.

#### Logarithmic, exponential and power fitting

These methods transform the observations, reuse the linear slope and intercept calculation, then return predictions in the original y space:

| Method        | Data used for linear fitting  | Prediction in original coordinates |
| ------------- | ----------------------------- | ---------------------------------- |
| `logarithmic` | $(u_i,v_i)=(\ln x_i,y_i)$     | $\hat y=\alpha+\beta\ln x$         |
| `exponential` | $(u_i,v_i)=(x_i,\ln y_i)$     | $\hat y=\exp(\alpha+\beta x)$      |
| `power`       | $(u_i,v_i)=(\ln x_i,\ln y_i)$ | $\hat y=\exp(\alpha+\beta\ln x)$   |

For exponential and power models, $a=e^\alpha$ and $b=\beta$. They minimize squared residuals in log-y space, so results generally differ from nonlinear fitting that minimizes residuals in the original y space. Every log-transformed field must be positive. Setting an axis to a log scale alone does not change the fitting method.

**Time complexity:** The logarithmic transformation and subsequent linear fit each take $O(N)$, so each of these three methods fits in $O(N)$. A prediction uses a fixed number of arithmetic, logarithm and exponential operations, taking $O(1)$.

#### Sampling the fitted trend

After fitting the coefficients, `sampleCount` x values are spaced evenly over `extent` and evaluated with the fitted model. The default interval is the current group’s minimum and maximum valid x; the default sample count is 64. For an interval $[L,U]$ and $M$ samples:

$$
x_j=L+\frac{j}{M-1}(U-L),\qquad \hat y_j=f(x_j),\qquad j=0,\ldots,M-1
$$

The trend connects these predictions in x order using the default `catmullRom` interpolating curve, rendered as cubic Bézier segments. Set `trend.curve: 'linear'` for a polyline; other values reuse Plot Path connection modes. More samples refine the drawn curve without changing fitted coefficients or adding observations. An `extent` outside the observed range produces extrapolations whose reliability requires separate assessment.

All fitting methods retain the complete fixed sample sequence and selected connection mode. With linear coordinates, collinear predictions still appear as a straight line through the default interpolating curve. Nonlinear coordinates connect the projected samples using the same pipeline.

**Sampling time complexity:** Generating $M$ predictions takes $O(M)$ for linear, quadratic, logarithmic, exponential and power models, or $O(Mn)$ for a degree-n polynomial. Including parameter fitting, the former methods take $O(N+M)$ and polynomial fitting takes $O(Nn^2+n^3+Mn)$. These costs cover fitting and numerical sampling, not rendering the entire chart.

### Custom fitting

A custom method defines a parameter schema and `fit`. The schema uses a unique literal `kind` and owns parameter constraints and defaults. `fit(pairs, operation)` receives the current group's valid observations and parsed parameters, then returns a model with `predict(x)`. Data does not generate drawing paths: Plot samples the model using `extent` and `sampleCount`, then connects the predictions with `trend.curve`.

<ComponentPreview files="regression-fitting-flow" size="lg" hideCode type="flow" />

Define a method with `defineRegression` from `@retikz/data`, then inject it through `lowerOptions.regressionDefinitions`. Built-in and external methods share registration and execution. JSON stores only the method name and parameters, never callbacks.

This example implements a **fixed-slope fitting algorithm**: the caller supplies the slope, and the algorithm estimates the intercept that minimizes squared residuals. Use it when a prior relationship determines the slope and only an overall offset needs to be estimated.

Unlike built-in linear regression, which estimates both slope and intercept, this method fits only the intercept. The custom `slope` parameter defaults to `1` through its schema.

With a fixed slope $b$, only the intercept $a$ needs to be fitted:

$$
a=\frac{1}{N}\sum_{i=1}^{N}(y_i-bx_i),\qquad \hat y=a+bx
$$

Fitting takes $O(N)$ time and each prediction takes $O(1)$. For the three observations below and `slope: 2`, the intercept is $a=4/3$; predictions at $x=0,1,2$ are $4/3,10/3,16/3$. The caller fixes the slope while each group's data determines the intercept.

```ts
import { defineRegression, RetikzDataError } from '@retikz/data';
import { literal, number, strictObject } from 'zod';

export const fixedSlopeFit = defineRegression({
  schema: strictObject({
    kind: literal('fixed-slope'),
    slope: number().default(1),
  }),
  fit: (pairs, { slope }) => {
    if (pairs.length === 0) throw new RetikzDataError('fixed-slope requires at least one observation');
    const intercept = pairs.reduce((sum, pair) => sum + pair.y - slope * pair.x, 0) / pairs.length;
    return { predict: x => intercept + slope * x };
  },
});

export const lowerOptions = { regressionDefinitions: [fixedSlopeFit] };
export const rows = [
  { x: 0, y: 1 },
  { x: 1, y: 4 },
  { x: 2, y: 5 },
];
```

The demo below runs this algorithm. Points show observations and the orange line shows the fitted result. Changing the slope recomputes the intercept; the line always passes through the observation mean $(1,10/3)$.

## API reference

React uses `RegressionChart` with its `recipe` prop or dedicated child components. The Vanilla API uses `regressionChart` with direct `encodings`, `properties`, and `marks` options. Direct IR places these fields inside `recipe` and sets `recipe.chartType: 'regression'`. React and the Vanilla API supply the chart type automatically.

In React, each configuration field must be supplied through either root props or a child component, not both. Different fields may use different forms. For shared data, layout, presentation, and guides, see [Authoring](/viz/chart/model/authoring).

| `hidePoints` | `boolean`                           | Defaults to `false`; `true` omits this mark’s observation points while retaining the main and additional trends.                                  |
| `encodings`  | `RegressionChartMark['encodings']`  | Override direct fields in the same data; series cannot be overridden                                                                              |
| `properties` | `RegressionChartMark['properties']` | Replace method, sampleCount or extent; merge point/trend members; replace extraMethods as a whole, with [] clearing it; excludes padding policies |
