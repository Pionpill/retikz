Viz is the visualization capability group built on Kernel. It does not force every visualization into one “drawing grammar.” Instead, it separates stable problems into Data, Plot, and Table: a shared data foundation, independent chart and table semantics, and a common path into Kernel through Core IR.

## Three capabilities

| Capability          | Problem it solves                                                                          | Input and output                                                    | Does not own                                          |
| ------------------- | ------------------------------------------------------------------------------------------ | ------------------------------------------------------------------- | ----------------------------------------------------- |
| [Data](/viz/data)   | Field models, parsing, general transforms, statistics, provenance                          | External records + data contracts → canonical rows and lineage      | Channels, scales, marks, Cells, or rendering          |
| [Plot](/viz/plot)   | Channels, scales, coordinates, marks, and guides that map fields into charts               | Plot IR + datasets → Core IR contributions and runtime observations | General data algorithms, Core IR, Scene, or renderers |
| [Table](/viz/table) | Row / column structure, Cell semantics, presentation rules, and deterministic table layout | Table specs + data → Core IR contributions and manifests            | Plot grammar, general data processing, or renderers   |

Plot and Table are peer Tier 2 domain modules. Table is not a Plot mark, and Plot does not duplicate Table's row, column, or Cell model. Both can reuse Data's field and processing capabilities, then complete lowering inside their own boundary.

## Shared foundation

Data, Plot, and Table follow the same architectural constraints: IR remains JSON-serializable, built-in and custom capabilities share Definition / registry contracts, framework adapters own only authoring and runtime wiring, and domain semantics ultimately lower into Kernel Core IR.

Kernel then owns layout, reference resolution, Scene compilation, and renderer integration. Viz can therefore extend data and high-level expression without creating parallel geometry, Scene, or SVG / Canvas semantics. Read [Kernel Architecture](/kernel/concepts/design/principles) for the common lower-level pipeline.
