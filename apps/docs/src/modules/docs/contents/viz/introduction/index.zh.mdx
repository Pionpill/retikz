Viz 是建在 Kernel 之上的可视化能力组。它不把所有可视化都塞进一套“绘图语法”，而是按稳定问题拆成 Data、Plot 与 Table：共享数据底座，分别拥有图表和表格的高层语义，再通过 Core IR 接入统一的编译与渲染管线。

## 三块能力

| 能力                | 解决的问题                                             | 输入与输出                                               | 不负责什么                               |
| ------------------- | ------------------------------------------------------ | -------------------------------------------------------- | ---------------------------------------- |
| [Data](/viz/data)   | 字段模型、解析、通用变换、统计与来源追溯               | 外部记录 + 数据契约 → canonical 行与 lineage             | channel、scale、mark、Cell 或渲染        |
| [Plot](/viz/plot)   | 把数据字段映射成图表的通道、比例尺、坐标系、图元与辅助 | Plot IR + 数据集 → Core IR contribution 与运行时观测信息 | 通用数据算法、Core IR、Scene 或 renderer |
| [Table](/viz/table) | 表达行列结构、Cell 语义、呈现规则与确定性表格布局      | Table spec + 数据 → Core IR contribution 与 manifest     | Plot grammar、通用数据处理或 renderer    |

Plot 与 Table 是并列的 Tier 2 领域模块。Table 不是一种 Plot mark，Plot 也不复制 Table 的行列与 Cell 模型；二者都可复用 Data 的字段与数据处理能力，并在各自边界内完成 lowering。

## 共同底座

Data、Plot 与 Table 共享同一组架构约束：IR 必须可 JSON 序列化，内置与自定义能力复用 Definition / registry 契约，框架 adapter 只负责 authoring 与运行时接线，领域语义最终下沉到 Kernel 的 Core IR。

Kernel 随后统一处理布局、引用解析、Scene 编译与 renderer 接入。因此 Viz 可以扩展数据与高层表达力，却不需要另造平行几何、Scene 或 SVG / Canvas 语义。想理解这条共同底层管线，可继续阅读 [Kernel 架构](/kernel/concepts/design/principles)。
