title: Table
description: Table components organize external records or explicit Cells into fixed tracks and use the same TableSpec across React, Vanilla, and SSR.
---

Table is for two-dimensional row-and-column content. `DetailTable` maps each external record to a row, `ManualTable` declares rows, columns, and Cells directly, and `Table` consumes a complete spec. All three React entries share the same structure, layout, and lowering pipeline.

## Usage

```tsx
import { DetailTable } from '@retikz/table-react';
```

```tsx
<DetailTable
  dataRef="scores"
  data={rows}
  columns={[
    { id: 'name', field: 'name', header: 'Name' },
    { id: 'score', field: 'score', header: 'Score' },
  ]}
/>
```

Prefer `DetailTable` for record-per-row data, `ManualTable` for headers, summaries, or other explicit grids, and `Table` for a complete persisted or externally generated TableSpec.

## Examples

`DetailTable` reads each record in `columns` order. Header strings become value Cells automatically; records are injected through `data` at runtime and never enter the spec.

### Vanilla and SSR

The Vanilla API uses plain helpers instead of a fluent builder. `detailTable()` / `manualTable()` only construct a TableSpec; browser composition uses `embedTable()` + `createTableAdapter()`, while one-shot SSR uses `renderTable()`.

```ts
import { createTableAdapter, detailTable, embedTable, manualTable, renderTable } from '@retikz/table-vanilla';
import { figure, layer, mount } from '@retikz/vanilla';

const detailSpec = detailTable({
  id: 'scores',
  dataRef: 'scores',
  columns: [
    { id: 'name', field: 'name', header: 'Name' },
    { id: 'score', field: 'score', header: 'Score' },
  ],
});

const manualSpec = manualTable({
  rows: 1,
  columns: 1,
  cells: [{ address: { row: 0, column: 0 }, payload: { kind: 'value', value: 'Total' } }],
});

const adapter = createTableAdapter();
const view = mount(
  container,
  figure({ layers: [layer('content', [embedTable('scores-panel', detailSpec, { data: { scores: rows } })])] }),
  { adapters: [adapter] },
);

view.update(
  figure({ layers: [layer('content', [embedTable('scores-panel', detailSpec, { data: { scores: nextRows } })])] }),
);
const svg = renderTable(detailSpec, { data: { scores: rows } });
const { manifest } = renderTable(manualSpec, { artifacts: true });
```

## How it works

  type="tip"
  title="Optional for everyday use"
  description="Revisit when you compose several tables, inject custom definitions, or consume layout artifacts."
/>

### One spec, several entries

React sugar and Vanilla helpers both delegate to `@retikz/table`'s `createDetailTableSpec()` / `createManualTableSpec()`, producing a JSON-serializable TableSpec before entering the same lowering pipeline. External data, function-bearing custom definitions, and extra composites are runtime inputs and never enter the TableSpec.

| Entry                           | Construction result | Runtime host          |
| ------------------------------- | ------------------- | --------------------- |
| `DetailTable` / `detailTable()` | detail TableSpec    | React or Vanilla host |
| `ManualTable` / `manualTable()` | manual TableSpec    | React or Vanilla host |
| `Table`                         | existing TableSpec  | React host            |

A standalone React component may omit its TableSpec `id`; embedding inside a parent `Layout` requires one. Vanilla embedding instead requires a non-empty embed id in `embedTable(id, ...)`; the TableSpec itself may stay anonymous, in which case the lowered root id is `${embedId}/table`.

### Fixed tracks and manifests

alpha.1 uses uniform `columnWidth`, `rowHeight`, and optional `headerHeight`; Cell content does not resize columns or rows. Defaults are `120` for column width, `32` for body row height, and `0` for gaps. Content measurement, spans, and complete borders are later capabilities.

`onManifest` is standalone-only and notifies after layout content changes. SSR can call `renderTable(spec, { artifacts: true })` to receive both SVG and the matching layout manifest.

## API Reference

### Table

| Prop                      | Type                                           | Default | Description                                                    |
| ------------------------- | ---------------------------------------------- | ------- | -------------------------------------------------------------- |
| `spec`                    | `IRTableSpec`                                  | —       | Complete JSON-serializable Table spec                          |
| `data`                    | `ExternalDatasets`                             | `{}`    | External datasets indexed by spec reference                    |
| `structureDefinitions`    | `ReadonlyArray<AnyTableStructureDefinition>`   | `[]`    | Custom structure definitions                                   |
| `presentationDefinitions` | `ReadonlyArray<AnyCellPresentationDefinition>` | `[]`    | Custom Cell presentation definitions                           |
| `composites`              | `ReadonlyArray<CompositeDefinition>`           | `[]`    | Definitions required by Tier 2 Cell content                    |
| `onManifest`              | `(manifest: TableLayoutManifest) => void`      | —       | Standalone layout artifact callback; unsupported when embedded |
| `width` / `height`        | `number \| string`                             | —       | SVG or Canvas host size; does not change fixed tracks          |
| `renderer`                | `'svg' \| 'canvas'`                            | `'svg'` | Rendering backend                                              |
| `className` / `style`     | `string`<br />`CSSProperties`                  | —       | Passed to the rendering host                                   |
