`<Plot>` is the container component for the plot layer. It takes `data` (an array of raw rows) and a display size, collects `<PathMark>` / `<IntervalMark>` / `<Axis>` / `<Scale>` children, then assembles a PlotSpec and lowers it to core at compile time. Data never enters the IR; it is injected during lowering. `<Plot>` does not draw axes, grids, or legends by itself. Declare those guides explicitly. Scales are inferred unless overridden with `<Scale>`; the coordinate system defaults to `cartesian2D` and can be switched with `coordinate`.

## Usage

```tsx
import { Axis, IntervalMark, Plot } from '@retikz/plot-react';
```

```tsx
<Plot data={revenue} width={360} height={220}>
  <IntervalMark x="quarter" y="value" />
  <Axis dimension="x" />
  <Axis dimension="y" grid />
</Plot>
```

`width × height` is the full chart box, including the plot area, axes, and tick labels. Children declare field mappings and guides, not pixel coordinates; omit `<Axis>` / `<Legend>` guide children when you only want data marks.

## Examples

### Coordinates

`coordinate` decides how one `<Plot>` projects data internally. It defaults to `cartesian2D`; the same data can switch to `polar2D`, so the same field mappings are interpreted in another coordinate system.

<ComponentPreview name="plot-coordinate" sourceFiles={['plot-cartesian.data.ts']} size="md" />

<p className="text-sm text-muted-foreground">Left: cartesian bars; right: the same data as polar2D radial bars.</p>

`coordinate` accepts a string shorthand or an object, covering the coordinate family:

```tsx
<Plot coordinate="polar2D">                                    {/* polar (pie / radar / radial bars) */}
<Plot coordinate={{ type: 'polar2D', innerRadius: 0.5 }}>      {/* carve the center into a donut */}
<Plot coordinate="cartesian1D">                                {/* 1D line (rug / timeline) */}
<Plot coordinate="polar1D">                                    {/* 1D circle (cyclic data) */}
<Plot coordinate="ternary2D">                                  {/* ternary (barycentric) */}
```

See [Coordinates](/viz/grammar/coordinate) for each system's geometry options (polar's `innerRadius` / `startAngle` / `endAngle`, cartesian1D's `orientation`, polar1D's `radius`, …) and which marks / channels apply.

When one chart needs multiple coordinate regions, everyday JSX does not need a hand-written `composition` object. Dual axes use `<Axis id>` plus `xAxisId` / `yAxisId` on marks; facets and shared tracks use their containers to scope axes and marks. See [Coordinate Composition](/viz/grammar/coordinate/composition) for the full model.

```tsx
<Plot data={weather}>
  <PathMark x="day" y="temperature" />
  <IntervalMark x="day" y="rainfall" yAxisId="rain" />
  <Axis id="temp" dimension="y" placement={{ kind: 'side', side: 'left' }} title="Temperature" />
  <Axis id="rain" dimension="y" placement={{ kind: 'side', side: 'right' }} title="Rainfall" />
</Plot>
```

### Scales

Default scales come from field values and mark types: numbers use continuous axes, ordinary strings use categorical positions, and ISO dates use time axes. Inferred continuous positional domains leave 5% breathing room by default. To request log axes, square-root axes, a manual domain, or `domainPadding={0}`, add a `<Scale>` child to override the relevant dimension.

### Theme and palettes

`theme` controls visual defaults for one `<Plot>`: background, guide typography, axis / grid tokens, legend tokens, and palette. Prefer `theme.palette` for new code. The older `colors` prop remains a shorthand for categorical / series / sector palettes when those theme slots are omitted.

<ComponentPreview name="plot-colors" sourceFiles={['plot-cartesian.data.ts']} size="md" />

<p className="text-sm text-muted-foreground">Left: built-in palette and guide defaults; right: a local theme changes palette, background, grid, and axis label color.</p>

Theme merges only visual tokens. Scale domains, `domainPadding`, explicit tick values, tick formats, axis title text, and grid projection stay on `<Scale>`, `<Axis>`, or `<Legend>` rather than moving into theme.

```tsx
<Plot
  theme={{
    background: '#ffffff',
    palette: {
      categorical: ['#2563eb', '#dc2626', '#16a34a'],
      sequential: 'magma',
    },
    axis: {
      grid: { stroke: '#cbd5e1', drawOpacity: 0.45 },
      tickLabels: { textColor: '#475569' },
    },
    legend: {
      swatchSize: 12,
      label: { textColor: '#475569' },
    },
  }}
>
  <IntervalMark x="quarter" y="value" color="quarter" />
  <Axis dimension="y" grid />
  <Legend channel="color" />
</Plot>
```

### Data Models

Real data often uses field names that differ from the chart's logical names. `model` declares the logical fields and their types, while `fieldMap` maps those logical fields to actual data paths; marks always reference the logical names.

### Panel Composition

One parent `<Layout>` can contain several `<Plot>` panels. Each chart uses its own `width` / `height` for the outer box, then `x` / `y` or `transforms` positions that panel inside the parent canvas; the parent only carries and composes panels, without participating in each chart's scale inference.

<ComponentPreview name="plot-panels" sourceFiles={['plot-cartesian.data.ts']} size="md" />

<p className="text-sm text-muted-foreground">Left: a cartesian line chart; right: a cartesian bar chart inside the same Layout.</p>

`width` / `height` still describe each chart's own outer box; the parent `<Layout>` size only controls the combined canvas.

### Entry Forms

`<Plot>` has two entries, dispatched by whether `spec` is passed:

| Entry           | Required                                         | Use                                                      |
| --------------- | ------------------------------------------------ | -------------------------------------------------------- |
| Composition DSL | `data` (raw array) + `children`                  | Declare marks / guides / scales in JSX (the common case) |
| Spec entry      | `spec` (built PlotSpec) + `data` (dataset table) | Feed a persisted / externally generated spec directly    |

When chart configuration comes from persisted JSON or an external generator, pass `spec` directly. Data is still injected separately through the `data` table, not written into the PlotSpec.

## How it works

> Optional for everyday use; revisit when you want to understand how `<Plot>` is compiled, or when you write / generate the low-level IR directly.

`<Plot>` draws nothing on its own. The composition entry first assembles children (marks / guides / scales / coordinate) into a **PlotSpec**: a high-level Tier 2 IR (fully JSON-serializable; data is not part of it). At compile time, **lowering** turns that PlotSpec into `@retikz/core`'s Tier 1 IR (`<Scope>` / `<Node>` / `<Path>`), which core then compiles into a Scene for the renderer. The spec entry skips assembly and feeds a PlotSpec directly.

Lowering isn't private to `<Plot>`: it's registered as a **composite** in core's compile pipeline. Core expands any PlotSpec node through it, the same way it handles every high-level node — upper layers add no parallel rendering path.

### Each lowering step

Data enters lowering alongside the PlotSpec and becomes Tier 1 step by step:

| Step                         | Input                                               | Output                                                      |
| ---------------------------- | --------------------------------------------------- | ----------------------------------------------------------- |
| Resolve data                 | dataset via `data.reference` + `model` / `fieldMap` | normalized rows (type inference, renaming, transforms)      |
| Infer scales                 | fields bound to each channel + coordinate           | band / linear / time / log… scales and the projection frame |
| Mark → layer                 | each `<PathMark>` / `<IntervalMark>` …              | one core `<Scope>` layer (of `<Node>` / `<Path>`)           |
| Axis / grid / legend → layer | explicit `<Axis>` / `<Legend>`                      | grid, axis, and legend layers (each a `<Scope>`)            |
| Order z-index                | all layers above                                    | background `-1000` → grid `-300` → marks `0` → axis `200` → facet labels `300` → plot labels `400` → legend `500` |

Every layer is wrapped in one isolated-namespace `<Scope>`, so each chart's internal ids (datum / series) never collide. Use `layer={{ zIndex }}` on marks, `<Axis>`, `<Legend>`, `<TitleLabel>`, or `<CaptionLabel>` when you need to move a semantic layer; it overrides the outer scope's zIndex without changing datum order inside the layer.

### Composable panels

When the PlotSpec carries an `id` (spec entry or generated IR), lowering wraps an extra **externally visible** panel `<Scope>`: the panel bbox is registered as `<plotId>` and the drawing area as `<plotId>.plotArea`, both placed outside the isolated namespace. Sibling nodes can anchor to them to connect or annotate — letting you compose several charts into one figure.

## API

| Prop                 | Type                                         | Default            | Description                                                                                                                                                                                        |
| -------------------- | -------------------------------------------- | ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `data`               | `Array<Row>`                                 | —                  | Raw data rows (composition DSL entry); data never enters the IR                                                                                                                                    |
| `children`           | `ReactNode`                                  | —                  | Mark / guide / scale children (composition DSL entry)                                                                                                                                              |
| `model`              | `DataModel`                                  | —                  | Data model (field names + types): enables strict validation and type-driven scale / guide derivation; see [Data Model](/viz/data/model)                                                  |
| `fieldMap`           | `Record<string, string>`                     | —                  | Logical field name → actual path in the data (requires `model`); renames only, no value transform; see [Processing](/viz/data/processing)                                                |
| `coordinate`         | see [Coordinates](/viz/grammar/coordinate) | cartesian2D        | Coordinate system: `"polar2D"` / `"cartesian1D"` / `"polar1D"` / `"ternary2D"` shorthand or the matching object; cartesian2D by default                                                            |
| `composition`        | `PlotSpec['composition']`                    | —                  | Low-level coordinate composition config with `defaultView`, `views`, `arrangements`, `spacing`, and `resolve`. Mutually exclusive with `coordinate`; everyday JSX usually uses axis ids, `<Facet>`, and `<Scaffold>` sugar |
| `colors`             | `Array<string>`                              | `schemeCategory10` | Compatibility palette shorthand. Used for categorical / series / sector defaults only when the matching `theme.palette` slots are omitted                                                                 |
| `theme`              | `PlotSpec['theme']`                          | built-in theme      | JSON-safe visual defaults for background, typography, axis, legend, and palette. Local `<Axis>` / `<Legend>` fields override matching theme tokens; scale and tick semantics stay outside theme             |
| `id`                 | `string`                                     | —                  | Panel id: written to PlotSpec.id as an external anchor handle; in embedded DSL mode it is also the default dataset reference when `dataRef` is omitted                                             |
| `dataRef`            | `string`                                     | —                  | Dataset reference name for the DSL entry; set the same value on multiple plots to share one data source                                                                                            |
| `width`              | `number`                                     | —                  | Outer width (including axes and labels); also written as the PlotSpec intrinsic width                                                                                                              |
| `height`             | `number`                                     | —                  | Outer height (including axes and labels); also written as the PlotSpec intrinsic height                                                                                                            |
| `x` / `y`            | `number`                                     | —                  | Panel top-left position inside a parent `<Layout>`; converted to an outer `translate`                                                                                                              |
| `transforms`         | `Array<IRTransform>`                         | —                  | Panel-level transforms; can be combined with `x` / `y` for finer placement                                                                                                                         |
| `zIndex`             | `number`                                     | `0`                | Draw order for the panel inside its parent                                                                                                                                                         |
| `clip`               | `IRClipSpec`                                 | —                  | Panel-level clipping region                                                                                                                                                                        |
| `fontSize`           | `number?`                                    | —                  | Compatibility tick-label font size; prefer axis or theme tokens for new styling                                                                                                                    |
| `margin`             | `{ top?; right?; bottom?; left? }`           | —                  | Override the surrounding padding                                                                                                                                                                   |
| `channelDefinitions` | `Array<AnyChannelDefinition>`                | —                  | Runtime definitions for custom channels; used together with `encoding.channels` in a spec. See [Custom Channels](/viz/grammar/extend/channel)                                                    |
| `spec`               | `PlotSpec`                                   | —                  | Spec entry: a prebuilt Plot IR root (mutually exclusive with `children`)                                                                                                                           |

In addition, `renderer` / `className` / `style` pass through to the underlying `<Layout>` — picking the render backend, an extra class name, and inline styles respectively.
