---
title: ReferenceMark
description: ReferenceMark expresses reference constraints: constant or field values expanded into lines, one-axis bands, or coordinate regions.
---

`<ReferenceMark>` declares a reference constraint in data space. By default, bind `y` for a horizontal reference and bind `x` for a vertical reference; a lower bound alone becomes a line, while `xTo` / `yTo` turns it into a one-axis band. Set `kind="region"` and ReferenceMark builds a region from the roles consumed by the active coordinate: cartesian / polar use `x` / `xTo` plus `y` / `yTo`, while ternary also uses `z` / `zTo`. `number` means a constant, while `FieldName` means a data field name or field path and produces one reference per row.

It joins the same draw order as `<PointMark>` / `<IntervalMark>`, but it does not start from point, line, or interval dimensions. It first fixes one axis value, then expands along the opposite axis domain.

## Usage

```tsx
import { Plot, ReferenceMark } from '@retikz/plot-react';
```

```tsx
<Plot data={scores}>
  <ReferenceMark y={60} color="crimson" />
  <ReferenceMark y={60} yTo={80} color="#fde68a" />
</Plot>
```

For the default line / band form, exactly one of `x` / `y` is required. `xTo` only pairs with `x`, and `yTo` only pairs with `y`; partial spans along the opposite axis use `extentField` / `extentToField` together. The region form must explicitly set `kind="region"` and provide lower / upper bounds for every active coordinate role; for example, `ternary2D` needs `x` / `xTo`, `y` / `yTo`, and `z` / `zTo`.

## Presentation Layer

ReferenceMark is a low-level reference mark: it turns one fixed axis value into a line, a one-axis interval into a band, or two axis intervals into a region. What the presentation layer calls a threshold line, tolerance band, reference ring, sector wedge, or highlighted range is not a different mark; it is the same ReferenceMark under different coordinate and bound settings.

The bound axis decides orientation, and the optional upper bound decides the form:

| Presentation form         | Key props                                                 | Description                                         |
| ------------------------- | --------------------------------------------------------- | --------------------------------------------------- |
| Horizontal reference line | `y`                                                       | Fixed y value, spanning the x domain                |
| Vertical reference line   | `x`                                                       | Fixed x value, spanning the y domain                |
| Horizontal reference band | `y` / `yTo`                                               | Fixed y interval, filling `y∈[y,yTo]`               |
| Vertical reference band   | `x` / `xTo`                                               | Fixed x interval, filling `x∈[x,xTo]`               |
| Bounded 2D region         | `kind="region"` + `x` / `xTo` / `y` / `yTo`               | Fixed x and y intervals, filling their intersection |
| Ternary reference region  | `kind="region"` + `x` / `xTo` / `y` / `yTo` / `z` / `zTo` | Fixed component intervals clipped into the simplex  |

Under `polar2D`, the coordinate system reinterprets the same props: `y` is a constant-radius reference ring, `y` / `yTo` is an annular band, `x` is a radial reference line, `x` / `xTo` is a sector wedge, and `kind="region"` constrains both angle and radius to form an annular sector. Under `ternary2D`, `kind="region"` uses the three `x/y/z` component intervals and lets the ternary coordinate `projectCell` clip them into a contour.

## How It Works

`ReferenceMark` is a built-in registered mark. The React `<ReferenceMark>` component does not render DOM; `<Plot>` assembles the flat props into mark IR with `type: 'reference'`, puts `x` / `y` / `z` under `encoding`, and keeps `kind` / `xTo` / `yTo` / `zTo` / `extentField` / `extentToField` on the mark itself.

At compile time, `lowerMark` looks up `MARK_REGISTRY` by `mark.type`. `ReferenceMark` resolves to the `PlotMark.Reference` entry, which calls `lowerReferenceLayer`. The default line / band form accepts cartesian2D / polar2D; `kind="region"` follows the cell path and accepts any coordinate frame with `projectCell`. Lines lower into core `Path`, while bands / regions first build a coordinate-independent `Cell`, then use `frame.projectCell(...)` and lower into core `Node` geometry. `label` infers its host from the actual form: lines use geometry-label fields, while bands / regions use node-label fields, so users do not write `kind`.

For registration, focus on the `ReferenceMark` registry entry and the `lowerReferenceLayer` / `lowerReference` functions that perform the lowering:

```ts
[PlotMark.Reference]: { type: PlotMark.Reference, lower: lowerReferenceLayer },

const lowerReferenceLayer = (mark: Mark, rows: Array<ExternalRow>, frame: CoordinateFrame, channels: MarkChannels, markProvenance: MarkProvenance | undefined): IRChild | null => {
  if (mark.type !== PlotMark.Reference) return null;
  const shape = referenceShape(mark);
  if (shape.kind === 'region') {
    if (!hasProjectCell(frame)) throw new Error(failLoudMessage(mark.type, frame.type));
  } else if (frame.type !== PlotCoordinate.Cartesian2D && frame.type !== PlotCoordinate.Polar2D) {
    throw new Error(failLoudMessage(mark.type, frame.type));
  }
  const layer = lowerReference(mark, rows, frame, channels.colorOf, channels.defaultColor, markProvenance);
  return layer === null ? null : attachMarkLayer(layer, mark, markProvenance);
};

const lowerReference = (mark: ReferenceMark, rows: Array<ExternalRow>, frame: CoordinateFrame, colorOf: ColorOf | undefined, defaultColor: string | undefined, markProvenance: MarkProvenance | undefined): IRScope | null => {
  const shape = referenceShape(mark);
  const effectiveRows = referenceRows(mark, rows, shape, frame);

  if (shape.kind === 'region' || shape.band) {
    for (const row of effectiveRows) {
      const cell = referenceCell(mark, row, frame);
      if (!cell) continue;
      const geometry = frame.projectCell(cell);
      // band / region: cell geometry -> core Node layer
    }
    return cellLayer;
  }

  for (const row of effectiveRows) {
    const steps = referenceLineSteps(mark, row, frame, shape.orientation);
    if (!steps) continue;
    // line: reference steps -> core Path layer
  }
  return lineLayer;
};
```

The logic breaks down into four steps:

| Step              | Description                                                                                                                                                                              |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Orientation check | The default line / band form requires exactly one of `encoding.x` / `encoding.y`; `kind="region"` requires lower and upper bounds for every coordinate role consumed by the active frame |
| Form check        | The default form infers line / band from the upper bound; region goes straight to the cell path                                                                                          |
| Row iteration     | A fully constant reference produces one item; field axis values, field upper bounds, or extent fields produce one item per row                                                           |
| Core lowering     | A line becomes a core `Path`; a band / region uses coordinate `projectCell` to become fillable geometry in a Node                                                                        |

## API

`ReferenceMark` covers lines, bands, and regions, with props grouped as Position, Specific, Path, Node, Label, General, and Custom: position fields bind the reference axes, specific fields describe the span, path fields style reference lines, and node fields style reference bands / regions. `FieldName` means a field name or field path, such as `threshold` / `limits.lo`; `number` means an inline constant axis value. `label` does not carry `kind`; line / band / region form decides whether it uses core geometry-label fields or node-label fields.
