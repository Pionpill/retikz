---
title: PathMark
description: 'PathMark is a one-dimensional trajectory made from ordered points; lines, closed paths, multi-series lines, and radar outlines are presentation forms of the same mark.'
---

`<PathMark>` produces one 1D trajectory from a set of data rows. It projects each row into a point, sorts the points by `order`, and lowers the result into a core `Path`. Under cartesian2D it is usually a line; under polar2D it can become a polar path or a radar outline.

`x` / `y` bind position channels, `order` decides connection order, `series` decides whether to split into multiple paths, `curve` decides how adjacent points connect, and `closure` decides whether the path closes by baseline or by cycle. PathMark currently supports cartesian2D and polar2D.

## Usage

```tsx
import { PathMark, Plot } from '@retikz/plot-react';
```

```tsx
<Plot data={revenue}>
  <PathMark x="month" y="revenue" order="month" />
</Plot>
```

Set `order` explicitly. Otherwise PathMark follows data array order, so a different row order changes the path shape.

## Presentation Layer

PathMark is a low-level line mark: it only connects a set of ordered anchors into one 1D trajectory. It does not care whether the presentation layer calls that trajectory a line chart, trend line, outline, or radar outline; those are interpretations of the same PathMark.

The presentation form mainly changes through three groups of props: position channels decide where points come from, series channels decide how many paths are produced, and geometry props decide whether the path closes as a line or as a fillable area.

| Presentation form | Key props           | Behavior                                                                                                          |
| ----------------- | ------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Line              | `x` / `y` / `order` | Project each row into a point, then connect the points in order                                                   |
| Multi-series line | `series` / `color`  | Split rows by series first, then produce one path per group                                                       |
| Radar outline     | `polar2D`           | Polar paths close by default; set `closed={false}` for an open path                                               |
| Path area         | `closure` / `fill`  | Close the path by cycle, constant baseline, or per-row stacked baseline; set `fill` explicitly to fill the result |

### Connection Type

`curve` controls how adjacent points connect. The left side uses cartesian2D and the right side uses polar2D; when you switch the connection type, both sides update together. The polar plot does not set an inner radius, so PathMark projects angular and radial positions directly. Because `monotoneX` / `monotoneY` rely on monotonic projected screen x / y values, they fall back to `linear` under polar2D to avoid long control handles in closed areas.

<ComponentPreview files={['line-curve', 'line-curve.data.ts']} size="md" />

| Value        | Meaning                    | Behavior                                                                                                                   |
| ------------ | -------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `linear`     | Straight line              | Preserves the segment-by-segment relationship between neighboring points; useful when local changes should stay explicit   |
| `step`       | Midpoint step              | Switches the y value midway between two x positions; useful for state or inventory-like data                               |
| `stepBefore` | Before step                | Switches to the new value first, then moves along x; useful when a new value takes effect immediately                      |
| `stepAfter`  | After step                 | Keeps the old value until the next x position, then switches; useful when an old value remains valid until the next moment |
| `basis`      | Smooth spline              | Produces the softest curve, but does not guarantee passing through every middle point; useful for an overall trend         |
| `cardinal`   | Cardinal spline            | Passes through data points with a softer curve than straight lines, but local extrema may overshoot slightly               |
| `catmullRom` | Point-passing smooth curve | Passes through data points while preserving more local shape; useful as a general smooth line                              |
| `monotoneX`  | Monotone x                 | When x is monotonic, reduces y overshoot beyond neighboring extrema; prefer this for BI trend lines                        |
| `monotoneY`  | Monotone y                 | When y is monotonic, reduces x overshoot beyond neighboring extrema; useful for vertical trajectories                      |
| `natural`    | Natural spline             | Keeps the whole curve continuous with relaxed endpoints; useful when continuous curvature matters                          |

### Path Areas

`closure` only closes PathMark into a fillable path; it does not enable filling by itself. `stroke` is on by default, and `stroke="none"` removes the border line; `fill` is off by default, and a concrete color or paint enables filling. The left area effect is composed from two PathMark layers: one `baseline + fill + stroke="none"` layer for the area, and one normal path layer for the upper outline. The right side uses `cycle + fill` to fill a radar polygon. Use the top-left control to switch `curve`; the default is a straight line. Baseline and stack return edges use the same connection curve.

<ComponentPreview files={['line-closure', 'line-closure.data.ts']} controlsName="line-curve" size="md" />

When `baseline` is omitted, it follows the value axis: use 0 when 0 is inside the value-axis domain; if an explicit domain excludes 0, such as `[30, 80]`, use the nearest domain edge, 30. Pass `closure={{ kind: 'baseline', baseline: ... }}` when the lower edge should be pinned to another value.

For stacked areas, bind the upper boundary to `y` and pass the lower boundary field as `closure.baselineField`. The data can come from a stack transform or from precomputed `y0` / `y1` fields. The example uses the same fill-layer plus outline-layer composition for the area-chart effect. When `curve` is set, both boundaries use the same connection mode.

<ComponentPreview files={['line-stack-area', 'line-stack-area.data.ts']} controlsName="line-curve" size="md" />

### Interrupted Paths

When a row cannot project into a valid point, PathMark breaks there by default and lowers the surrounding runs into separate core `Path` elements. If the path also has `closure` and `fill`, the fill follows the same segments instead of spanning across the missing gap.

In this example, `Yasin` has no 2019 value, so both the outline and the filled area stop between 2018 and 2020. Set `connectNulls` explicitly when a chart should connect across gaps.

## How It Works

`PathMark` is a built-in registered mark. The React `<PathMark>` component does not render DOM; `<Plot>` collects it into mark IR with `type: 'path'` and records settings such as `x` / `y` / `order` / `series` / `closed` / `closure`.

At compile time, `lowerMark` looks up `MARK_REGISTRY` by `mark.type`. `PathMark` resolves to the `PlotMark.Path` entry, which calls `lowerPathLayer`. `lowerPathLayer` accepts only cartesian2D / polar2D, then calls `lowerPath`: it splits rows into series, splits each series into projectable continuous segments, and lowers each segment into a core `Path`.

For registration, focus on the `PathMark` registry entry and the `lowerPathLayer` / `lowerPath` functions that perform the lowering:

```ts
[PlotMark.Path]: { type: PlotMark.Path, lower: lowerPathLayer },

const lowerPathLayer = (mark: Mark, rows: Array<ExternalRow>, frame: CoordinateFrame, channels: MarkChannels, markProvenance: MarkProvenance | undefined): IRChild | null => {
  if (frame.type !== PlotCoordinate.Cartesian2D && frame.type !== PlotCoordinate.Polar2D) {
    throw new Error(failLoudMessage(mark.type, frame.type));
  }
  const layer = lowerPath(mark, rows, frame, channels.colorOf, channels.defaultColor, markProvenance);
  return layer === null ? null : attachMarkLayer(layer, mark, markProvenance);
};

const lowerPath = (mark: Mark, rows: Array<ExternalRow>, frame: CoordinateFrame, colorOf: ColorOf | undefined, defaultColor: string | undefined, markProvenance: MarkProvenance | undefined): IRScope | null => {
  if (mark.type !== PlotMark.Path) return null;
  const closure = mark.closure;
  const closed = mark.closed ?? isPolarCoordinateFrame(frame);
  const seriesField = pathSeriesField(mark, rows);
  const buildSegments = (segmentRows: Array<ExternalRow>) =>
    closure
      ? buildClosureStepSegments(mark, segmentRows, frame, closure, closed)
      : buildLineStepSegments(mark, segmentRows, frame, closed);
  if (seriesField) {
    const paths = buildSeriesPaths(mark, rows, seriesField, buildSegments, paintOfSeries, markProvenance);
    return paths.length === 0 ? null : { type: 'scope', pathDefault: { strokeWidth: LINE_STROKE_WIDTH }, children: paths };
  }
  const segments = buildSegments(rows);
  if (segments.length === 0) return null;
  const colorValue = mark.encoding.color?.value;
  const stroke = colorValue !== undefined ? String(colorValue) : defaultColor ?? DEFAULT_FILL;
  return {
    type: 'scope',
    pathDefault: { stroke, strokeWidth: LINE_STROKE_WIDTH },
    children: segments.map(segment => ({ type: 'path', children: segment.steps })),
  };
};
```

The logic has four parts:

| Step             | Behavior                                                                                                                                                                                                                    |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Coordinate check | PathMark needs 2D trajectory geometry; this release lowers it only under cartesian2D / polar2D                                                                                                                              |
| Sort and project | `orderRows` decides connection order, and `frame.project(...)` maps position channels into screen points                                                                                                                    |
| Series split     | Explicit `series` wins; without `series`, categorical `color` can implicitly split the rows                                                                                                                                 |
| Core lowering    | Each continuous segment inside each series becomes one core `Path`; `closed` appends a cycle for a line outline (`polar2D` closes by default), while `closure` builds a closed path and `fill` decides whether it is filled |

## API

`PathMark` props are grouped as Position, Specific, Path, Label, General, and Custom: position fields decide trajectory points, specific fields split series or close the path, and path fields lower onto the core `Path`. `FieldName` means a data field name or field path, such as `month` / `city`. Path labels use the core geometry-label host; `label` does not carry `kind`, because PathMark infers the host.

| Category | Prop                                         | Type                                                                                                                  | Default                                   | Description                                                                                                                                                      |
| -------- | -------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- | ----------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Position | `x` / `y`                                    | `FieldName`                                                                                                           | —                                         | Coordinate role fields; cartesian2D uses planar points, polar2D interprets them as angle / radius                                                                |
| Specific | `color`                                      | `FieldName?`                                                                                                          | `series`                                  | Color field; without explicit `series`, categorical color can split the rows                                                                                     |
|          | `order`                                      | `FieldName?`                                                                                                          | data order                                | Field bound to connection order                                                                                                                                  |
|          | `series`                                     | `FieldName?`                                                                                                          | —                                         | Split rows into multiple paths                                                                                                                                   |
|          | `curve`                                      | `PathCurveValue?`                                                                                                     | `linear`                                  | Connection curve between adjacent points; under polar2D, `monotoneX` / `monotoneY` fall back to `linear`                                                         |
|          | `closed`                                     | `boolean?`                                                                                                            | cartesian2D: `false`<br />polar2D: `true` | Connect the last point back to the first; set `false` under polar coordinates to keep an open path                                                               |
|          | `connectNulls`                               | `boolean?`                                                                                                            | `false`                                   | Whether to connect across missing or invalid points; by default the path breaks and lowers into multiple core `Path` elements                                    |
|          | `closure`                                    | `{ kind: 'cycle' }`<br />`{ kind: 'baseline'; baseline?: number }`<br />`{ kind: 'stack'; baselineField: FieldName }` | —                                         | Build a closed path; omitted `baseline` uses the value-axis baseline, explicit `baseline` pins a constant lower edge, and `stack` reads a per-row lower boundary |
| Path     | `stroke` / `fill`                            | `FieldName`<br />`IRPaintSpec`<br />`PointStrokeStyle?` / `PointFillStyle?`                                           | `currentColor` / —                        | Path stroke paint and closed-path fill paint; `stroke="none"` disables the border, while omitted `fill` keeps the path unfilled                                  |
|          | `strokeWidth`<br />`opacity` / `fillOpacity` | `PointNonnegativeNumberStyle?`<br />`PointOpacityStyle?`                                                              | —<br />—                                  | Path stroke width, whole-path opacity, and fill opacity                                                                                                          |
|          | `strokeOpacity`<br />`zIndex` / `rotate`     | `PointOpacityStyle?`<br />`PointZIndexStyle?`<br />`PointNumberStyle?`                                                | —<br />—<br />—                           | Stroke opacity, draw order, and rotation                                                                                                                         |
|          | `roundedCorners`                             | `MarkValueProp<number>`                                                                                               | —                                         | Rounded corners for path steps                                                                                                                                   |
|          | `lineCap` / `lineJoin`                       | `FieldName / LineCapValue`<br />`FieldName / LineJoinValue`                                                           | —<br />—                                  | Line cap and join style                                                                                                                                          |
|          | `scale`<br />`fillRule` / `thickness`        | `PathScaleStyle?`<br />`PathFillRuleStyle?`<br />`PathThicknessStyle?`                                                | —<br />—<br />—                           | Path scaling, fill rule, and thickness preset                                                                                                                    |
|          | `marks`                                      | `RelationPathSpecificOptions['marks']?`                                                                               | —                                         | Static core path marks, including endpoint arrows                                                                                                                |
|          | `dashPattern`<br />`shadow` / `blendMode`    | `NodeDashPatternStyle?`<br />`ShadowStyle?`<br />`BlendModeStyle?`                                                    | —<br />—<br />—                           | Dash pattern, shadow, and blend mode                                                                                                                             |
| Label    | `label`                                      | `MarkGeometryLabel`<br />`Array<MarkGeometryLabel>?`                                                                  | —                                         | Attach geometry labels to path segments; content lives in `content.field` / `content.value`, while `position`, `side`, and `distance` reuse core geometry labels |
|          | `resolveLabel`                               | `(row) => string?`                                                                                                    | —                                         | Runtime override for label content; requires `id` and is not stored in PlotSpec                                                                                  |
| General  | `id`                                         | `string?`                                                                                                             | —                                         | Optional mark handle for layer ids / runtime label resolution                                                                                                    |
|          | `transform`                                  | `Array<IRPlotTransform>?`                                                                                             | —                                         | Mark-local data transform; runs after the plot-level transform and only changes the rows seen by this layer                                                      |
| Custom   | `channels`                                   | `Record<string, Channel>`                                                                                             | —                                         | Custom channel bindings; resolved by registered channel definitions                                                                                              |
