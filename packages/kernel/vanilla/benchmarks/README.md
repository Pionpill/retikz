# Vanilla 性能基准

从仓库根目录串行执行：

```sh
pnpm bench --workspace packages/kernel/vanilla
pnpm --filter @retikz/vanilla bench:browser
```

浏览器入口需要 Playwright 对应版本的 Chromium；首次准备可运行 `pnpm --filter @retikz/vanilla exec playwright install chromium`。

- Node：normalize、无渲染目标的 runtime 与 LayerStack、IR 到完整 SVG 字符串。会话操作包含 Reconciler 和 Core 的实际工作，不是 Vanilla 独占耗时。
- Chromium：使用轻量后端验证 View 接线；使用真实 SVG / Canvas 测首次挂载与 batch 更新。完整 IR 替换不纳入常规性能矩阵，保留功能测试及历史报告。
- 浏览器指标截止在同步 API 返回，不包含下一帧的合成或屏幕呈现。短操作接近浏览器时钟精度时，P50 为零不表示操作免费。
- 被测实体规模小于 10000 时，预热 10 次、正式测量 100 次；达到或超过 10000 时，不预热、正式测量 10 次，总调用上限 10 次，不降为仅供参考的 3 次档。构造输入、准备上一帧、清理和结果验证不计时。两种环境各自生成报告，不比较 Node 与 Chromium 的绝对延迟，也不将源码加载的结果当作生产构建基线。

整图矩阵按操作和实际规模展示：

- Node、Path、Scope：各 100、1000、10000 个实体。被测实体均使用唯一 ID，不再按有无 ID 分组。Scope 平铺，每个包含一个匿名矩形节点，支撑节点计入报告标签。
- 混合：100/1000 Node 配 10/100 Path；另复用 Reconciler 两层流程图，报告列出实际 Node、Path、Scope 数量。
- 各档共用同一输入测全量编译（SSR 字符串）与增量编译初始帧（无宿主、SVG、Canvas）。增量测移动中间节点，规模为 100 Node + 99 Path 或 1000 Node + 999 Path，分别观测无宿主计算和真实后端提交。

整图 P50 黄 / 红预算按表中首项主体数量分档（ms）：≤100 为 8 / 16.6，101–500 为 25 / 50，501–1000 为 50 / 100，>1000（当前万级档）为 200 / 500。混合图以 Node 数计档，Scope 以容器数计档。真实 batch 按同一主体数单独分档（ms）：≤100 为 8 / 16.6，101–1000 为 16.6 / 33.3，>1000 为 33.3 / 50。按场景规模而非 batch 内指令数计档；采样轮次和整组执行时限不变。

## integration 的计时与归因

integration 测量的是 Vanilla 公开入口串起的 Kernel 全链路，不是 Vanilla 包的独占耗时。SSR 从已准备的 IR 到 SVG 字符串；浏览器从 IR 到真实 SVG / Canvas 增量会话初始帧或 batch 更新同步返回，不包含屏幕呈现。整图 replace 不等于增量 update。

每个集成场景的报告须在端到端耗时之外，分别列出同一次操作的三个互斥区间：

| 区间 | 包含的工作                                                                                                  | 首先核查                                           |
| ---- | ----------------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| 计算 | 从 IR 准备编译结果；包括协调器调度及调用的元素解析、几何计算和 Scene 组装，不含渲染目标提交                 | Reconciler、Core；按调用链继续到 Math、Foundation  |
| 渲染 | SSR 的 SVG 序列化；浏览器的渲染目标建立、帧与补丁准备、后端执行及提交                                       | Render 的 runtime 和对应 SVG / Canvas 后端         |
| 其他 | 本次端到端操作扣除上述两个区间的剩余时间，例如 Vanilla 宿主创建、尺寸同步和入树，以及未细分的接线与观测开销 | 按宿主和接线调用链核查；不能把差额全部算给 Vanilla |

逐个正式样本计算其他时间，再分别汇总端到端、计算、渲染和其他的 P50。不能用不同运行、不同输入或不同阶段的 P50 相减；各列 P50 也不保证相加等于总 P50。输入构造、准备上一帧和输出断言均不计时。旧报告缺少分段样本时标明“未采集”，不要回填估算值。

超预算时先指出场景、操作和超限的总耗时，再结合阶段数据、相关包的同负载基准或调用链说明责任包和证据。阶段占时最大不等于已定位缺陷；证据只到 Reconciler/Core 计算链或 Render 提交阶段时，写明已定位的区间、待区分的包和缺少的证据，不默认归责 Vanilla。

浏览器 batch 在常驻 SceneRuntime 上接真实 Render target；计时外复原，最终 SVG 几何或 Canvas 像素与独立挂载的目标帧核对。
