# Kernel 功能比较 Prompt

本文件维护本模块的比较 prompt、对象与维度，不保存比较结果。统一方法、能力状态、证据要求与报告格式遵循 [全仓功能比较方案](../../../../notes/feature-comparison.md)。

## 执行指令

> 请比较本模块当前实现与下列框架，按本文边界逐项核验，遵循全仓方案生成含分类均分和总均分的 10 分制表格与最多五条简要总结。结果写入 `notes/reports/feature-comparison/<YYYY-MM-DD>-kernel-<short-commit>.md`，不写回本文件；仅调研，不修改实现或自动执行性能测试。

## 输出格式

- 报告正文最前面（标题之后、基线信息和评分表之前）必须说明比较定位：“Retikz Kernel 在 JS 生态中缺少可直接对比的项目，因此本报告选择 TikZ/PGF 作为主要参考；其余对象为 JS 生态常见绘图库，仅作部分功能对比，不代表同层级产品的全面比较或综合排名。”
- 使用 10 分制，正文只保留评分表与最多五条简要总结；评分锚点与证据要求遵循全仓方案。
- 列顺序：分类、比较项、各外部框架分数、Retikz 现状、Retikz 规划、备注。外部框架列只放分数或 `—`，差异、依据与限制集中在最后的备注栏。
- 同一分类只在第一行填写分类名称，后续行留空；分类末尾增加“分类名 · 均分”，分类汇总后增加“总均分”，其下增加“能力完备性”，汇总值加粗并保留一位小数。
- 分类均分是该分类有效分数的算术平均；总均分是有效分类均分的等权平均，使用未舍入值计算后统一保留一位小数。`—` 不按零分处理；整类无有效分数时不参与总均分。
- 备注注明未评分项及总均分的有效分类数 / 全部分类数。覆盖范围不同的总均分仅供概览，不作严格排名；规划分仅评估 roadmap 与明确长期计划完成后的预期程度，备注列列出依据、前提和不确定性；不将规划当作已实现能力。
- 详细证据放折叠区或同目录 ignored 附件，生成结果不写回 prompt。

## 比较范围与对象

范围覆盖 packages/kernel 与 packages/library 两组的联合能力，名称为 Kernel 功能比较，不局限于 core 单包。Library 的 Extension、Layout、Standard 及其 adapter 均计入，但注明按需安装和注册要求；不纳入 Viz 或 Schematic 的领域能力。布局需区分 Flex / Grid / Overlay 排版、Standard 显式结构呈现和一般图算法布局。实际 owner 以当前源码为准，不能把可选能力当作尚未实现。比较对象不包含 Vega 和 Two.js。

| 比较对象                                   | 参考角色                       |
| ------------------------------------------ | ------------------------------ |
| [TikZ/PGF](https://tikz.dev/)              | 图元、锚点、路径语言与出版绘图 |
| [D3](https://d3js.org/)                    | 可编程几何、数据驱动与组合     |
| [Mermaid](https://mermaid.js.org/)         | 图解 DSL 与作者体验            |
| [React Flow](https://reactflow.dev/)       | 节点边交互与宿主集成           |
| [Excalidraw](https://docs.excalidraw.com/) | 场景持久化与编辑器集成         |

评估提示用于界定比较项，不作为额外列或分类。AI 和体验可基于可核验任务与 API 给出定性评分，但必须注明未做实测；不得声称已验证生成成功率或用户效率。性能中的多线程和并发模式可以评价机制完成度及有依据的规划，不能据此推断吞吐、延迟或加速比；性能、压力、基准和 LLM 测试仍须另获授权。WebGL、多 Worker 与 concurrent 的规划目标应追踪到 roadmap、长期计划，注明来源和未定前提；目标不足以支持数值判断时写 `—`。

规划评分口径：先核对源码，roadmap 中已实现的项目计入现状，不重复加分。规划分保留现状基线，仅按尚未交付且有明确目标的 roadmap / 长期计划调整；没有新增计划时与现状相同，目标过泛或无法判断时写 `—`。候选方向须标为条件性预期，不能当作确定承诺。现状和规划分别计算分类均分与总均分。

规划评分前必须实际阅读所属模块的 roadmap、相关架构设计及命中 ADR 全文，并核对当前源码；备注或证据区列出具体文档、状态、目标与未实现部分。不得仅凭标题、用户提到的方向、通用经验或理论可扩展性猜测规划能力和分数。文档缺失、目标不明确或旧设计与当前架构冲突且未解决时，对受影响规划项写 `—` 并说明缺口；没有新增目标且现状证据充分的项目可维持现状分。

在“总均分”下一行增加“能力完备性”，格式为 `已实现项数/全部比较项数 → x.x/10`，计算公式为已实现项数 ÷ 全部比较项数 × 10，各项等权。按证据逐项判断是否已有可用能力闭环，不按评分阈值或有无评分机械计数；能力已实现但缺性能实测分仍可计入。明确缺失、仅有理论可扩展性或需另行开发闭环的项目不计入；未核验项保留在分母、不计入分子，因此有未知项时须标明“已确认下限”，不能据此认定其余均不支持。规划列以已实现能力为基线，再并入有 roadmap 与架构设计依据的新增闭环，去重计数，标注为目标覆盖而非已交付。详细计数依据放折叠区。
