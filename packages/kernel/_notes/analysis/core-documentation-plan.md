## 一、文档归属

以职责边界决定页面归属，不以内容难度或讲解深度划分：

| 位置              | 职责                                     | 展开范围                                           |
| ----------------- | ---------------------------------------- | -------------------------------------------------- |
| Kernel 组件／进阶 | 横向串联多个 Kernel 包，必要时包含上层包 | 围绕完整任务解释各包输入输出、交接顺序和协作边界   |
| 开发包／Core      | 纵向讲解 Core 自身实现                   | 从 Core 输入到输出，解释阶段、数据结构、状态与算法 |

Core 页面可以介绍它如何消费 Runtime、Math 等依赖，但不展开依赖包内部实现。跨包专题链接各包原理，不重复完整包内处理链。

复杂度本身不是进入组件进阶的理由。例如极坐标解析属于 Core；只有讨论坐标怎样贯穿宿主、编译、渲染和空间查询时，才构成跨包专题。

组件自身的实现原理页保留解释局部行为所需的内容，完整编译过程由 Core 系列承接。公开 API 与 Schema 的参考仍保留唯一归属。

## 五、推进顺序与每批完成条件

建议顺序：C1 → C2 → C3 → C4 → C5 → C6 → C7 → C8；C0 随已完成正文整理。之后按 K1 → K2 → K3 → K4 → K5 串联跨包过程。可根据实际阅读问题调整下一篇，不并行铺开全部文章。

每批默认一篇或一个边界明确的主题，开始前确认：

1. 本篇回答的问题、前置知识、源码与测试阅读范围
2. 新增／改写／删除页面和导航的边界
3. 需要的流程图、数据变化示例与功能 demo
4. 验证范围及是否提交；agent 调度和提交必须另有明确授权

每篇按以下步骤推进：

- [ ] 沿一个具体案例阅读真实调用链，记录输入、中间结果、状态和输出
- [ ] 明确包内职责与跨包交接，区分当前实现、契约保证和未实现能力
- [ ] 先确认中文提纲与关键解释，再完成正文和英文同步
- [ ] 按篇幅和读者问题选择流程图、源码入口、示例，不按文件顺序翻译源码
- [ ] 同步本篇涉及的目录、导航、i18n 和旧链接
- [ ] 按文档规则完成格式、静态检查及所需页面核验；构建与运行时巡检另行确认
- [ ] 用户阅读后处理反馈，记录完成范围和下一篇入口

## 六、需要持续保持的事实边界

- 测量不等于读取 DOM：Core 消费注入的度量能力；具体提供方和更新接线需沿消费链核实
- 同次编译的子布局重放、单次布局的局部缓存、跨更新的增量计算必须分开解释
- 2026-10-11 阅读时，Core 增量快路径主要覆盖严格条件下单个根 Node 的无资源 fill 字符串变化；其他情况可能全量回退。写 C8 时必须重新核对，不把该快路径泛化成通用局部重算
- 笛卡尔几何不意味着所有点都展开成世界坐标：Scene 可保留局部几何与结构化分组变换
- 本计划不授权源码重构；阅读中发现问题时先单独记录和讨论，避免文档任务扩展为实现改造
