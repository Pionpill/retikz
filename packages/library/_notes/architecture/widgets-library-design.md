# Widgets · 图内交互部件规划

> **状态：已立项，待 Kernel 交互能力就绪后启动实现。** `@retikz/widgets` 规划为 Library 下与 Standard 平级的可选包，目前不创建 npm 包，不冻结组件 API，也不指定发布版本。

## 定位

Widgets 为绘图作者提供可直接放进 Retikz 场景的交互部件。例如，地图上的地点标记可以由图标和地名组成；指针从图标移到文字时，整个标记应保持高亮，点击任一部分都表示激活同一个地点。天气图上的观测站标注可以复用这个部件，而不需要理解地图的地点模型。

普通图元不因可点击就成为 widget。只想让一段地名悬浮变色、点击打开详情时，作者应能直接使用 Kernel 的交互能力，不依赖 Widgets。选择 `widgets` 这个名字，是为了强调包交付的是带有约定行为的现成部件，而不是所有 UI、所有绘图组件或一套 Web 设计系统。

## 职责边界

| 归属              | 以交互标注为例                                                                                                                           |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| Kernel            | 提供后端中立的目标识别、事件传递和呈现更新。增量渲染能更新画面，但不能单凭它判断某段文字和某个图标属于同一个操作目标。                   |
| Standard / Layout | 提供标注外观所需的绘图组合与排版；静态标注不必引入 Widgets。                                                                             |
| Widgets           | 组合图标、文字及其命中区域，定义整个标注何时高亮、何时激活，以及如何呈现外部给定的选中值。通过 Kernel 传达激活意图，不直接打开业务详情。 |
| 领域或宿主        | 决定选中哪个地点、是否打开详情、显示哪些天气数据，以及是否保存选择。画板外的工具栏、表单和编辑器命令不归 Widgets。                       |

部件描述与宿主回调分开：静态渲染和导出根据内容及显式给定的状态生成稳定画面；临时 hover、按压和焦点不写回绘图文档。部件消费 Kernel、Standard 和 Layout 的公开能力，不自建命中测试、事件路由或第二套渲染机制。

## 启动条件与首个场景

待 Kernel 能通过公开接口让普通图元完成下面的场景，再启动 Widgets。已有的[事件水合](../../../kernel/_notes/decisions/settled/runtime-interaction.md)是基础，不等于已经具备完整的[交互能力](../../../../notes/architecture/interaction-design.md)。

1. 以普通图元组成图标与文字，在 SVG 和 Canvas 上均可把两者的命中关联到同一语义目标；在两者之间移动不应触发整个标注的离开。
2. 悬浮时更新整个标注的外观，离开时恢复；激活时宿主只收到一次对应目标的意图。宿主更新选中值后，标注按新值绘制，不在部件内另存一份业务选择。
3. 首个部件封装上述重复工作，以地点标记和气象观测站验证复用。对可键盘操作的宿主，明确焦点、键盘激活与指针激活的对应关系；不把 Canvas 命中等同于已具备无障碍支持。

若普通图元还做不到前两项，缺口回到 Kernel，不为首个 widget 私设通道。后续是否加入 Toggle、Tabs 等部件，按真实场景另行判断；不以补齐 shadcn/ui 或 Ant Design 的目录为目标。更广泛的候选场景和持久化取舍见[画板交互控件讨论](../../../../notes/architecture/interactive-controls-design.md)。
